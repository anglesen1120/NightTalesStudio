## Resolved-path boundaries (QA D-1, D-2)
The pattern lists match the literal import specifier, so relative paths and `import()` escaped them. `eslint.config.js` wraps `@typescript-eslint/no-restricted-imports` (same options, same ruleId, no new dependency): every specifier of `import`/`export ... from`/`import x = require()`/`import('x')`/`typeof import('x')` is resolved against the importing file and, when it lands in `src/app/{core,shared,features}`, checked in its `@core|@shared|@features/...` alias form. Relative imports that stay inside the importer's own unit (`features/<f>/<layer>`, `core/<x>`, `shared/<x>`) are left as written. Non-literal `import(expr)` cannot be resolved statically and is not checked.

## Template scan (QA D-5, D-6)
`lint-forbidden-patterns.mjs` scans `*.html` and the inline `template:` strings of every `*.ts` (line numbers are those of the `.ts` file). `bind-innerHTML=` joins `[innerHTML]`. The `on*=` pattern uses an allow-list of real DOM event names, anchored at line start or after whitespace, a quote or `/`, so `ongoing=`, `online=`, `on-click=` and `(click)=` are not flagged while a column-0 `onclick=` and `<img/onerror=` are.

## Effective-rule deviation (task Failure-handling row 1)
Angular 22 made OnPush the implicit default. The installed `@angular-eslint/prefer-on-push-component-change-detection` (22.5.0) only reports an explicit `Eager`/`Default` opt-out (source: `dist/rules/prefer-on-push-component-change-detection.js`, `ChangeDetectionStrategy.d.ts` "NOTE: OnPush is enabled by default"). An omitted `changeDetection` is therefore enforced by the committed `no-restricted-syntax` fallback selector (`EXPLICIT_ONPUSH` in `eslint.config.js`); the angular-eslint rule stays on for `Eager`.
