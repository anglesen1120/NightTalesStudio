# Night Tales Studio — current app review

## Tóm tắt tiếng Việt

Giao diện hiện tại có nền tảng đúng: hỗ trợ tiếng Việt, token dark/light, các trạng thái lỗi và quy trình bảo mật khá đầy đủ trong source. Vấn đề không nằm ở việc thiếu thêm màu hay hình minh hoạ. Cách chia khối, độ ưu tiên và cách dùng component đang làm một bàn sản xuất riêng trông giống một tập hợp form quản trị.

Điểm tệ nhất nhìn thấy được: dashboard trống lặp ba empty state rồi thêm một khối onboarding; mobile cắt nhãn ngôn ngữ; trang đăng nhập dồn thông báo phiên, stepper và focus ring quanh tiêu đề trước tác vụ chính; danh sách series thiếu cấu trúc cột nên khó quét. Các token đã có nhưng Material và CSS riêng chưa tạo thành một hệ thống thống nhất.

Phase 1 giữ nhận diện xanh xám/teal hiện có, tái cấu trúc theo “cần bạn xem → đang thực hiện → sẵn sàng đăng”, làm rõ trạng thái và tạo bộ nền tảng để áp dụng vào Angular. Đây là prototype HTML/CSS; không kết nối tài khoản, không xác thực hoặc đăng video thật. Dữ liệu minh hoạ được ghi nhãn ngay trên dashboard.

## Cross-cutting findings grounded in code

1. **Medium — semantic colors collapse different meanings.** `_tokens.scss` maps warning to error and success to primary. `status-chip.ts` explicitly documents warn/error and info/success sharing appearances. Introduce separate warning and information token pairs. Eleven wire statuses plus unknown are demonstrated. Text and symbols carry meaning in addition to color.
2. **Medium — target sizing is conditional.** `_tokens.scss` uses 36px standard and 28px small controls, switching only for coarse pointers. Keyboard users at mobile sizes do not necessarily get coarse-pointer queries. Foundation sets actionable targets to at least 44px for all pointers; noninteractive chips may remain smaller.
3. **Medium — typography is functional but hierarchy is inconsistent.** Be Vietnam Pro is appropriate and already bundled. The 58px display size with 1.017 line-height in `_tokens.scss` is too tight as a general Vietnamese multiline default. No screenshot proves clipping, so this is a risk, not an observed defect. Use 40/1.3 showcase, 30/1.35 page, 22/1.4 section, 15/1.6 body; reserve display scale for system documentation only.
4. **Low — unnecessary repeated brand marks.** Auth uses a crosshair, shell uses two vertical strokes, and empty states add another target-like mark. These devices do not clarify different functions. Simplify to a typographic wordmark; spend visual emphasis on one production-track motif.
5. **Preserve existing good behavior.** Source has a skip link, inert mobile background, focus restoration hooks, error association, real-time reconnect/backoff/pause states, per-field validation, recovery-code gating, neutral unknown statuses and reduced-motion handling. Visual redesign must not delete these behaviors.

## Phase 1 acceptance boundaries

HTML/CSS specimens demonstrate visual states and native navigation, theme/language switches, details disclosure, state selection and recovery acknowledgement. They do not authenticate, publish, retry network requests, copy to clipboard, save settings or implement a focus-trapped modal. Session persistence and cross-page locale persistence require application logic and are intentionally left to Angular because this phase explicitly forbids JavaScript. Demo percentages are fixture data, never inferred from current production jobs.
