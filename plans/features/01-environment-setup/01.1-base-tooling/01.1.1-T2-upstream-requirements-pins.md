# 01.1.1-T2 — Upstream requirements → `worker-node/pins.env`

| Story | Size | Area | Depends on | Blocks | Gate |
|---|---|---|---|---|---|
| 01.1.1 | XS (0.25 d) | Ops | 01.1.1-T1 (uv), 01.1.2-T1 (`worker-node/` exists) | 01.1.2-T3, 01.2.1-T1, 01.2.2-T1, 01.2.3-T1, 01.3.3-T1 | 01-ready |

## Goal
`worker-node/pins.env` holds every D2 key. Code commits and model revisions are full 40-char SHAs resolved at the same moment. The Python version and lock status of each upstream repo are read **at the chosen SHA**, not from `main`.

## Inputs
- ✅ M1: MPT `harry0703/MoneyPrinterTurbo` `main` @ `3d5f4e421927d61f3eac729cf4b711ac0b69d688` (2026-09-21, v1.3.7). This is the candidate `MPT_COMMIT` (full SHA from `agent://MptFacts`).
- ✅ M7: MPT `requires-python >=3.11`, `.python-version` 3.11, install `uv sync --frozen`.
- ✅ V3/V4: VieNeu `pnnbao97/VieNeu-TTS`, `.python-version` 3.12, `requires-python >=3.10`, Mac install is plain `uv sync`. The SHA is chosen at install time (no candidate yet).
- ✅ V5: `pnnbao-ump/VieNeu-TTS-v3-Turbo` (subfolder `onnx_update`) and codec `OpenMOSS-Team/MOSS-Audio-Tokenizer-Nano`.
- ✅ W1: `mobiuslabsgmbh/faster-whisper-large-v3-turbo`.
- F18: `python` on PATH is not needed. D2 key names. D9 exit codes.

## Steps
1. **Code SHAs.** Resolve `main` to a full SHA without cloning:
   ```sh
   git ls-remote https://github.com/harry0703/MoneyPrinterTurbo.git refs/heads/main
   git ls-remote https://github.com/pnnbao97/VieNeu-TTS.git refs/heads/main
   ```
   - MPT: if `main` still equals `3d5f4e421927d61f3eac729cf4b711ac0b69d688`, use it (the facts in README §1 were read at this SHA). If `main` moved, **keep the candidate** unless the TL asks for the newer commit. Otherwise the M-facts would need re-verification at the new SHA. Confirm the candidate still exists: `git ls-remote https://github.com/harry0703/MoneyPrinterTurbo.git | grep -c 3d5f4e421927d61f3eac729cf4b711ac0b69d688` must be ≥ 1, or it must be reachable from `main` after bootstrap (`git merge-base --is-ancestor`).
   - VieNeu: take the `main` SHA returned now. Record the date and the SDK version read in step 2.
2. **Requirements at the SHA** (read-only, raw files at the exact commit; `<SHA>` = the value from step 1):
   ```sh
   curl -fsSL --max-time 30 https://raw.githubusercontent.com/harry0703/MoneyPrinterTurbo/<SHA>/.python-version
   curl -fsSL --max-time 30 https://raw.githubusercontent.com/harry0703/MoneyPrinterTurbo/<SHA>/pyproject.toml | grep -E '^(requires-python|version) *='
   curl -fsSIL --max-time 30 -o /dev/null -w '%{http_code}\n' https://raw.githubusercontent.com/harry0703/MoneyPrinterTurbo/<SHA>/uv.lock
   ```
   Run the same three commands for `pnnbao97/VieNeu-TTS/<SHA>`. Expected results:

   | Repo | `.python-version` | `requires-python` | `uv.lock` HTTP | Install command |
   |---|---|---|---|---|
   | MPT | `3.11` ✅ M7 | `>=3.11` ✅ | `200` ✅ [INFERENCE from `--frozen` in M7] | `uv sync --frozen` |
   | VieNeu | `3.12` ✅ V3 | `>=3.10` ✅ V4 | ⚠️ U3 | `200` → `uv sync --frozen`; `404` → plain `uv sync` (V3) and the generated lock is hashed (01.1.2-T3) |

   Set `MPT_PYTHON` and `VIENEU_PYTHON` to the **major.minor** from `.python-version`. If a value differs from D2 (`3.11` / `3.12`), stop and ask the TL: D2 fixes these values, so a change there comes first.
3. **Model revisions.** For each model repo, resolve `main` to a commit SHA **before** any download:
   ```sh
   for r in pnnbao-ump/VieNeu-TTS-v3-Turbo OpenMOSS-Team/MOSS-Audio-Tokenizer-Nano mobiuslabsgmbh/faster-whisper-large-v3-turbo; do
     printf '%s ' "$r"
     curl -fsSL --max-time 30 "https://huggingface.co/api/models/$r/revision/main" \
       | uv run --no-project --python 3.12 python -c 'import json,sys; print(json.load(sys.stdin)["sha"])'
   done
   ```
   ⚠️ U4: this assumes the endpoint returns the commit in field `sha`. Fallback (HF model repos are git repos [INFERENCE]):
   ```sh
   git ls-remote https://huggingface.co/<repo> refs/heads/main
   ```
   Every result MUST match `^[0-9a-f]{40}$`. If a repo is gated or private (auth needed), stop: no HF token is planned in D3. Escalate instead of adding a secret.
4. **Write `worker-node/pins.env`** (tracked, no secrets; format `KEY=value`, comments with `#`, no `export`, no quotes, no spaces around `=`; parsed by `load_pins` in `lib.sh` and by stdlib Python):
   ```sh
   # worker-node/pins.env — the only place versions live (README D2).
   # Resolved <YYYY-MM-DD> by <initials>; facts re-checked at these SHAs (01.1.1-T2).
   MPT_REPO=https://github.com/harry0703/MoneyPrinterTurbo.git
   MPT_COMMIT=3d5f4e421927d61f3eac729cf4b711ac0b69d688
   MPT_PYTHON=3.11
   VIENEU_REPO=https://github.com/pnnbao97/VieNeu-TTS.git
   VIENEU_COMMIT=<40-hex from step 1>
   VIENEU_PYTHON=3.12
   VIENEU_MODEL_REPO=pnnbao-ump/VieNeu-TTS-v3-Turbo
   VIENEU_MODEL_REVISION=<40-hex from step 3>
   VIENEU_CODEC_REPO=OpenMOSS-Team/MOSS-Audio-Tokenizer-Nano
   VIENEU_CODEC_REVISION=<40-hex from step 3>
   WHISPER_MODEL_REPO=mobiuslabsgmbh/faster-whisper-large-v3-turbo
   WHISPER_MODEL_REVISION=<40-hex from step 3>
   ```
   Only these 12 keys are allowed; `load_pins` rejects unknown keys (01.1.2-T2). The file is never committed with a `<…>` placeholder.
5. **Record the evidence** in `worker-node/README.md` § "Pins": a table per repo with the SHA, date resolved, `.python-version`, `requires-python`, `uv.lock` present (yes/no), and upstream version (`pyproject` `version`). Per-file `sha256` of model weights is **not** recorded here. 01.2.1-T1 (`worker-node/vieneu/weights.sha256`) and 01.2.3-T1 (`worker-node/mpt/whisper-large-v3-turbo.sha256`) do that, and 01.3.3-T1 copies it to `CARRY-OVER.md` (D2).
6. **Consumers must honour the pins.** Downstream tasks MUST download with the pinned revision. VieNeu's own `hf_hub_download` passes no revision (✅ V5), so 01.2.1-T1 verifies that `refs/main` equals `VIENEU_MODEL_REVISION` / `VIENEU_CODEC_REVISION` after the first fetch. A mismatch means **re-running this task's procedure** (a new commit with new values), never hand-editing a single value.

## Outputs
- Tracked: `worker-node/pins.env` (12 keys), `worker-node/README.md` § Pins.
- Recorded values: the SHAs, Python versions, and VieNeu lock status (input to 01.1.2-T3 step "sync mode").
- Commit: `pins.env` goes in a commit of its own (makes pin rollback a single `git revert`).

## Failure handling
| Failure | Action |
|---|---|
| MPT `main` moved past the candidate | Keep `3d5f4e42…`. If the TL wants the new commit, re-read M1–M11 at it first (diff `config.example.toml`, `material.py`, `subtitle.py`) |
| `.python-version` differs from D2 | Stop. Propose the D2 change to the TL (README first), then continue |
| VieNeu has no `uv.lock` at the SHA (U3) | Record `lock: no`. 01.1.2-T3 uses plain `uv sync` and hashes the generated lock. Flag reproducibility as ⚠️ in CARRY-OVER |
| HF API has no `sha` field (U4) | Use the `git ls-remote` fallback. Record which method was used |
| Model repo gated / needs a token | Stop. Escalate (a new secret would need a D3 change) |
| Rollback | `git revert` the pins commit |
