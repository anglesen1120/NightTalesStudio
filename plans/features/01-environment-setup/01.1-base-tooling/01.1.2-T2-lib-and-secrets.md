# 01.1.2-T2 — `worker-node/bin/lib.sh` + `worker-node/bin/secrets.sh`

| Story | Size | Area | Depends on | Blocks | Gate |
|---|---|---|---|---|---|
| 01.1.2 | XS (0.25 d) | Ops | 01.1.2-T1 | 01.1.2-T3, 01.2.1-T2 (VieNeu start), 01.2.2-T2/T4 (render, MPT start), 01.2.4-T2 (OpenAI keys), 04 proxy start | 01-ready |

## Goal
A single sourced library gives every script the same `$NTS_HOME`, pins, Keychain access, port guard and log format (D9). `secrets.sh` creates, lists and rotates the five D3 Keychain items without ever printing a value or putting an owner key into shell history.

## Inputs

- D1 (`NTS_HOME="${NTS_HOME:-$HOME/.nts}"`, internal disk), D2 (pins keys), D3 (5 services, account `$USER`), D4 (ports, exit 2 if busy), D9 (bash, `set -euo pipefail`, exit codes, `--help`, no `sudo`, no `set -x`), D13 (trusted execution location).
- ✅ E1: USB volume unencrypted → the `nts_home` guard.
- ✅ E2: ports 8000/8001/8002/8080/8501 are free today.
- F25 / D3: create Keychain items with `-T /usr/bin/security` so later reads do not pop a GUI prompt (⚠️ behaviour to confirm on macOS 27; not a verified fact, so no ✅).
- ⚠️ F26 / D13: the code that reads secrets (`worker-node/bin/*`) stays on `/Volumes/Project` (E1: Owners disabled) unless D13's trust check or export fallback is enforced. `secret()` is the single choke point that must refuse otherwise (security review NTS01-SEC-01).
- Agreed consumer contracts: OpenAiAccessPlan uses `secrets.sh set`, and VieneuPlan/MptPlan use `secret` and `require_port_free`.

## Steps
1. **`worker-node/bin/lib.sh`**: sourced only (no shebang execution). The first line guards against direct execution: `[[ "${BASH_SOURCE[0]}" != "$0" ]] || { echo "source me" >&2; exit 2; }`. It does not set shell options itself; callers set `set -euo pipefail`. Constants:
   - `NTS_REPO_ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/../.." && pwd)"`
   - `NTS_SERVICES=(nts.openai.story nts.openai.image nts.mpt.api_key nts.vieneu.api_key nts.proxy.api_key)`
   - `NTS_LOCAL_SERVICES=(nts.mpt.api_key nts.vieneu.api_key nts.proxy.api_key)`

   | Function | Contract |
   |---|---|
   | `log <msg…>` | Writes `YYYY-mm-ddTHH:MM:SSZ <script-name>: <msg>` to **stderr** (`date -u`). Never receives secret values (review rule). |
   | `die <code> <msg…>` | `log` + `exit <code>` (helper for D9 codes) |
   | `nts_home` | **Pure resolver, no side effects.** Resolves `NTS_HOME="${NTS_HOME:-$HOME/.nts}"`, exports it in the current shell, and prints it on stdout — nothing else. Guard → `die 2` if the path is under `/Volumes/` or under `$NTS_REPO_ROOT` (E1, F05). Does **not** create, `chmod`, or run `tmutil`; a caller that only needs the path (e.g. `env-versions.sh` reading `mpt_commit`) must not trigger mutation or print anything but the path. Callers that need `$NTS_HOME` as a shell variable use `NTS_HOME="$(nts_home)"` — because `nts_home` itself already exported it in-process, a caller sourcing `lib.sh` directly (not via `$(...)`) can also just read `$NTS_HOME` after calling `nts_home` with output discarded. |
   | `nts_home_init` | **Mutator, no stdout.** Calls `nts_home` internally (guard included), then if the directory is missing: `mkdir -p "$NTS_HOME"/{src,hf,logs,runs}`, `chmod 700`, `tmutil addexclusion` (log a WARN, not a failure, if tmutil fails, ⚠️ U7). If present with mode ≠ 700: `chmod 700` and log it. Idempotent. Called once by `01.1.2-T1` step 5 (manual first run) and by every script's startup (`nts_home_init` before `nts_home`'s guard is relied on elsewhere), so a fresh clone self-heals `$NTS_HOME` without operator steps. |
   | `load_pins` | Parses `$NTS_REPO_ROOT/worker-node/pins.env` line by line (**not** `source`, so no code runs). It skips blank lines and `#` comments. Each line must match `^[A-Z_]+=[^[:space:]]*$`, the key must be one of the 13 D2 keys (12 + `PROXY_PYTHON`, 04 CR-3), all 13 must be present, `*_COMMIT`/`*_REVISION` must match `^[0-9a-f]{40}$`, and `*_PYTHON` must match `^3\.[0-9]+$`. It exports each key. Any violation → `die 2 "pins.env: <key>: <reason>"`. |
   | `_nts_trusted_location` | **D13 check.** Private helper called only by `secret`. Reads the D13 mode recorded in `worker-node/README.md` (`internal` / `volume` / `export`, DEC-2: chosen on the implementation machine). For `internal`: `fdesetup status` is On and `$NTS_REPO_ROOT` is not under `/Volumes/`. For `volume`: runs `diskutil info` on the volume `$NTS_REPO_ROOT` sits on (resolved via `df -P`, never a hard-coded `/Volumes/Project`) and greps for `Owners: Enabled` and `Encrypted: Yes` (⚠️ exact label text, README D13). Returns 0 if both hold, **or** if `NTS_REPO_ROOT` itself is not on `/Volumes/*` (already trusted, e.g. a future non-USB checkout). Otherwise returns 1 unless the D13 export fallback is active: `$NTS_HOME/exec/<sha>/` exists and `${BASH_SOURCE[1]:-$0}` (the caller script) resolves under it. |
   | `secret <service>` | `<service>` must be in `NTS_SERVICES`, else `die 2 "unknown service: <service>"`. **D13 gate first**: `_nts_trusted_location \|\| die 2 "untrusted execution location (D13 mode <recorded mode>): see worker-node/README.md § Trusted execution location (internal disk, encrypted+owned volume, or \$NTS_HOME/exec/<sha> via bootstrap.sh --export)"`. Then runs `security find-generic-password -a "$USER" -s "$service" -w` with stderr captured (not discarded) to a variable. Exit 44 from `security` (`errSecItemNotFound`) → `die 2 "missing keychain item: <service> (run worker-node/bin/secrets.sh check)"`. Any other non-zero exit (e.g. `errSecInteractionNotAllowed` in a non-interactive session, SEC-07b) → `die 2 "keychain read failed for <service>: <captured stderr, first line only>"` — same D9 exit code 2 but a distinct message from "missing", so a locked session is never mistaken for an absent item. On success, prints **only the value** on stdout (the trailing newline `security -w` emits is part of the value's line, stripped with `$(...)` command substitution as usual). Use only as `VAR="$(secret nts.mpt.api_key)"`. Never `echo` the result, never pass it in argv; hand it to children as an env var (`NTS_MPT_API_KEY="$v" uv run …`) (D3). |
   | `require_port_free <port>` | `lsof -nP -iTCP:"$port" -sTCP:LISTEN -t >/dev/null` → if a listener exists: `die 2 "port <port> already in use"` (D4). Otherwise returns 0. |

   It also has one private helper `_nts_service_known <service>`.
2. **`worker-node/bin/secrets.sh`**: `#!/usr/bin/env bash`, `set -euo pipefail`, sources `lib.sh`, `umask 077`. Subcommands:

   | Subcommand | Behaviour | Exit |
   |---|---|---|
   | `set <service>` | `<service>` ∈ `NTS_SERVICES` (normally `nts.openai.story` / `nts.openai.image`). Requires a TTY (`[ -t 0 ]`, else exit 2). Prints which key is expected (e.g. "OpenAI key of project nts-trial-story"), then runs `security add-generic-password -U -a "$USER" -s "$service" -l "$service" -T /usr/bin/security -w` (`-T` = trusted-app ACL so later script reads do not pop a GUI prompt, README F25 ⚠️). With `-w` as the last argument and no value, `security` prompts, so the value never enters argv or history (D3; ⚠️ U6: it may prompt twice for confirmation). It confirms with `present` via `find-generic-password` (no `-w`). | 0 · 2 |
   | `init-local` | For each of `NTS_LOCAL_SERVICES`: if present → `unchanged`; else generate `v="$(openssl rand -hex 32)"` (64 hex chars = 32 random bytes) and store it (step 3), then `created`. It never touches OpenAI items. | 0 · 2 |
   | `check [--local] [--acl]` | For each service (or only the local ones), prints `<service> present` or `<service> missing` using `security find-generic-password -a "$USER" -s <svc> >/dev/null 2>&1` (**no `-w`** → no value is read). `--acl` (SEC-07) additionally parses `security dump-keychain -a` (**never `-d`**, so no secret data is dumped ⚠️ output format at macOS 27) and prints `<service> acl ok` when `/usr/bin/security` is a trusted application of the item, else `<service> acl missing`. | 0 all present (and ACL ok with `--acl`) · 1 any missing · 2 |
   | `rotate-local [<service>]` | Refuses (exit 2) if any of ports 8000/8001/8002/8080/8501 is listening (services must be stopped; uses `lsof`, like `require_port_free`). Regenerates the given local service, or all three. It prints the restart order: re-render MPT config (01.2.2-T2 renders on start), then restart VieNeu, the proxy and MPT. Never valid for `nts.openai.*` (owner rotates in the dashboard, 01.2.4-T3, then `set`). | 0 · 2 |
   | `--help` | Usage, service table (D3), exit codes | 0 |

3. **Storing a generated value** (argv trade-off, §8 of plan.md). Preferred: feed the command to `security -i` (interactive mode reads commands from stdin ⚠️ U6), so the value is never in any process's argv:
   ```sh
   printf 'add-generic-password -U -a %s -s %s -l %s -T /usr/bin/security -w %s\n' "$USER" "$svc" "$svc" "$v" | security -i >/dev/null
   ```
   `printf` is a bash builtin, so no process is spawned with the value in argv. **Verify after writing (SEC-06):** compare in-process, like with like: `[ "$(secret "$svc")" = "$v" ]`. Both sides come from command substitution or a variable, so a trailing newline from `security … -w` cannot cause a false mismatch. A mismatch is a **hard failure** (`die 1 "keychain verify failed: $svc"`, value never printed). It is never a reason to switch variants. **Fallback only if `security -i` itself exits non-zero:** `security add-generic-password -U -a "$USER" -s "$svc" -l "$svc" -T /usr/bin/security -w "$v"`. That call exposes the value in argv for the lifetime of the `security` process (visible to `ps` for the same user and root). It is accepted only for the three **local random** keys (same-user threat only, loopback services, rotatable with `rotate-local`), and only after the TL records the decision in the runbook. `unset v` right after.

   **ACL repair (SEC-07).** `-U` updates the value but does **not** change an existing item's trusted-app list. When `check --acl` reports `acl missing`: for local keys, `security delete-generic-password -a "$USER" -s <svc>` and then `init-local` (a new value, so re-render and restart); for OpenAI keys, delete and `set <svc>` again with the same key value from the owner (01.2.4-T2 flow).
4. **Hygiene rules** (both files):
   - Never `set -x` / `BASH_XTRACE`.
   - Never `echo "$v"`.
   - No `trap … DEBUG`.
   - Secrets never go to files except the MPT renderer's `config.toml` (01.2.2-T2).
   - `security` stderr is sent to `/dev/null` only where it would otherwise print item attributes (it never prints the password without `-w`).
5. Add runbook section `## Secrets` in `worker-node/README.md`: the D3 table, `secrets.sh set|init-local|check|rotate-local` usage, the argv variant in use, and the rule "never type a key after a command; always at the prompt".
6. Run `shellcheck worker-node/bin/lib.sh worker-node/bin/secrets.sh` at implementation time (D9).

## Failure handling
| Failure | Action |
|---|---|
| Keychain locked / GUI access prompt appears | Unlock the login keychain (`security unlock-keychain` prompts; never pass `-p`). A GUI prompt on a read means the item's ACL lacks `/usr/bin/security`: repair it with delete + re-add (step 3, SEC-07). Do not click "Always Allow" as a fix: it leaves the item inconsistent with `check --acl` |
| `security -i` exits non-zero on the piped command (U6) | Stop. The argv fallback is allowed only for the three local keys and only after the TL records it in the runbook (§8 trade-off, SEC-06). A verify mismatch is never a reason to switch |
| `set` prompts twice / confirms differently (U6) | Document the actual prompt in the runbook |
| `openssl` missing | macOS ships LibreSSL `openssl` ✅ [INFERENCE]. If absent: `head -c 32 /dev/urandom \| xxd -p -c 64` |
| `load_pins` rejects the file | Fix `pins.env` through the 01.1.1-T2 procedure. Never loosen the validation |
| Rollback | `for s in nts.mpt.api_key nts.vieneu.api_key nts.proxy.api_key; do security delete-generic-password -a "$USER" -s "$s" >/dev/null; done`; delete the two scripts |

## Notes
- ⚠️ U6: `security add-generic-password … -w` (last argument, no value) prompting behaviour, and `security -i` stdin syntax at macOS 27.
- ⚠️ U7: `tmutil` inside `nts_home`.
- Mode 644 for `lib.sh` is nominal on the USB volume (Owners disabled, E1), but it signals "sourced, not run".
- Threat note (SEC-07): the `-T /usr/bin/security` ACL means **any process running as this user** can read every `nts.*` item without a prompt, including the OpenAI keys. This is accepted for a single-user trial Mac; D13 limits which code can run as the reader, and the OpenAI keys are capped by the hard limits (D7).
- The `secret` contract (value only on stdout; exit 2 when missing or unreadable, told apart by the message; D9) was confirmed to OpenAiAccessPlan.
