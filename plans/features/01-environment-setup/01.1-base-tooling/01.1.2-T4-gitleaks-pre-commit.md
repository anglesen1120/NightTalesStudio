# 01.1.2-T4 — gitleaks pre-commit hook

| Story | Size | Area | Depends on | Blocks | Gate |
|---|---|---|---|---|---|
| 01.1.2 | XS (0.25 d) | Ops | 01.1.1-T1 (gitleaks, licence ok), 01.1.2-T1 (`.githooks/`, `.gitignore`) | the **first commit** of the repo; every later commit | 01-ready |

## Goal
A commit that stages a secret is blocked locally before it exists. The working tree is proven clean **before the first commit** (the repo has no commits yet, ✅ E2), so history starts secret-free.

## Inputs
- ✅ E2: gitleaks is not yet installed (01.1.1-T1 installs it); the repo has no commits.
- 01.1.1-T1 licence result (⚠️ U1, expected MIT).
- High-level plan 01 §8 (pre-commit secret scan) and NFR-01-1.
- D1 (`.githooks/pre-commit`), D3 (what counts as a secret), D9 (bash, exit codes).
- ⚠️ U2: the subcommand syntax depends on the installed gitleaks version. v8.19+ has `gitleaks git` / `gitleaks dir` / `gitleaks stdin`; older v8 has `gitleaks protect --staged` / `gitleaks detect --no-git`. Confirm with `gitleaks --help` and `gitleaks version`.

## Steps
1. **Confirm the syntax** at the installed version:
   ```sh
   gitleaks version
   gitleaks --help            # lists the available subcommands
   gitleaks git --help        # expect flags: --pre-commit, --staged, --redact, --no-banner (⚠️ U2)
   gitleaks dir --help        # expect: scans a directory without git
   ```
   Record the version and chosen commands in `worker-node/README.md` § Secret scanning. Steps below use the v8.19+ form. Mapping for an older build: `git --pre-commit --staged` → `protect --staged`, `dir <path>` → `detect --no-git --source <path>`, `git` (history) → `detect --source .`.
2. **Scan the working tree before the first commit.** At this point git history is empty, so a history scan finds nothing and only a directory scan is meaningful:
   ```sh
   mkdir -p "$HOME/.nts/logs"
   gitleaks dir . --redact --no-banner --report-format json \
     --report-path "$HOME/.nts/logs/gitleaks-initial-$(date +%Y%m%d-%H%M%S).json"
   echo "exit=$?"
   ```
   - Expected `exit=0`. Exit 1 means findings; see Failure handling.
   - The report lives in `$NTS_HOME/logs`, never in the repo. `--redact` keeps secret values out of the report and terminal.
   - Scope: the repo working tree, including ignored files. That is intended, because an ignored `config.toml` copy with a real key would be flagged, and that tells you where secrets sit on the USB volume (E1). Review but do not "fix" such hits by adding allow-list entries: move the file to `$NTS_HOME` or delete it.
3. **Hook file `.githooks/pre-commit`** (tracked, mode 755):
   ```bash
   #!/usr/bin/env bash
   # Blocks commits that stage secrets (NFR-01-1). Installed by: git config core.hooksPath .githooks
   set -euo pipefail
   if ! command -v gitleaks >/dev/null 2>&1; then
     echo "pre-commit: gitleaks not found; install it (brew install gitleaks) — commit blocked" >&2
     exit 1
   fi
   exec gitleaks git --pre-commit --staged --redact --no-banner --verbose
   ```
   - It fails closed: a missing gitleaks blocks the commit (a skipped scan must not look like a pass).
   - It scans only staged changes (fast; this is what enters history).
   - ⚠️ U2: the flag names above are to be confirmed at step 1. `--verbose` prints finding metadata (file, line, rule) with the value redacted.
3a. **Hook file `.githooks/pre-push`** (tracked, mode 755; SEC-12). `--no-verify`, a rebase, or a cherry-pick can put commits into history that the pre-commit hook never scanned. The pre-push hook scans exactly the range being pushed and fails closed:
   ```bash
   #!/usr/bin/env bash
   set -euo pipefail
   command -v gitleaks >/dev/null 2>&1 || { echo "pre-push: gitleaks not found — push blocked" >&2; exit 1; }
   z=0000000000000000000000000000000000000000
   while read -r lref lsha rref rsha; do
     [ "$lsha" = "$z" ] && continue                      # branch deletion: nothing to scan
     if [ "$rsha" = "$z" ]; then range="$lsha"; else range="$rsha..$lsha"; fi   # new branch: full history of lsha
     gitleaks git --redact --no-banner --log-opts="$range" || { echo "pre-push: secret in $lref ($range)" >&2; exit 1; }
   done
   ```
   ⚠️ U2: `--log-opts` spelling at the installed version.
4. **Activate** (per clone; the setting is not versioned, so the runbook and rehearsal check it):
   ```sh
   git config core.hooksPath .githooks
   git config --get core.hooksPath      # → .githooks
   ```
   On the USB volume the exec bit may not be enforced or stored as expected (E1: Owners disabled). Verify with `test -x .githooks/pre-commit && test -x .githooks/pre-push` and set `git update-index --chmod=+x .githooks/pre-commit .githooks/pre-push` after the first add, so the mode is recorded in git. A non-executable hook is skipped by git (with only a hint, not an error), so this check is what keeps SEC-12 from failing open.
5. **Prove the hook blocks, safely, in a throwaway repo** (never in the project repo, never with a real key):
   ```sh
   t="$(mktemp -d)"
   git -C "$t" init -q
   mkdir "$t/.githooks" && cp .githooks/pre-commit "$t/.githooks/" && chmod 755 "$t/.githooks/pre-commit"
   git -C "$t" config core.hooksPath .githooks
   git -C "$t" config user.email test@example.invalid && git -C "$t" config user.name test
   # fake AWS-style access key id, generated so no fixture string is stored anywhere
   printf 'aws_access_key_id = AKIA%s\n' "$(LC_ALL=C tr -dc 'A-Z2-7' </dev/urandom | head -c 16)" > "$t/leak.txt"
   git -C "$t" add leak.txt && git -C "$t" commit -qm leak; echo "blocked-exit=$?"     # expect ≠ 0
   git -C "$t" rm -q --cached leak.txt && rm "$t/leak.txt"
   echo 'hello' > "$t/ok.txt"
   git -C "$t" add ok.txt && git -C "$t" commit -qm ok; echo "clean-exit=$?"           # expect 0
   rm -rf -- "$t"
   ```
   The fake key matches gitleaks' default AWS rule [INFERENCE: default ruleset includes `aws-access-token` for `AKIA…` ids ⚠️]. If it is not detected, use a second generated pattern (for example a `-----BEGIN PRIVATE KEY-----` block with random base64) and record which one works. The fixture is generated at run time and deleted with the temp repo, so no secret-like string is ever committed to this repo.
6. **Allow-list policy** [DECISION proposal]:
   - Default: **no allow-list**. A finding is fixed by removing the secret, not by allowing it.
   - Real false positive (for example a SHA-256 in `weights.sha256` or a 40-hex pin mistaken for a token): add the finding's **fingerprint** (from the redacted report) to `.gitleaksignore`, one per line, with a preceding `# <file>:<line> <reason> <date> <initials>` comment. The same commit must contain the reason. The TL reviews every `.gitleaksignore` change.
   - Not allowed: path-wide or rule-wide exclusions in a custom `.gitleaks.toml`, and `git commit --no-verify` / `git push --no-verify`. If `--no-verify` was ever used, run a history scan right after (`gitleaks git --redact` ⚠️ U2) and note it in the run notes.
7. **First commit** only after steps 2–5 pass: stage explicit paths (never `git add -A` on the USB repo), commit, and the hook runs for real.
8. **History scans (SEC-12)**: run `gitleaks git --redact --no-banner` over the full history (⚠️ U2) → exit 0 at **gate 01-ready**, at **gate 01-closed**, and after any rebase, cherry-pick, or commit made with `--no-verify`. `smoke.sh` asserts `git config --get core.hooksPath` = `.githooks` (row `git.hooks`, FAIL otherwise; `env-versions.sh` keeps its 16-key contract), so a clone with the hooks switched off is visible.
9. Runbook section `## Secret scanning`: version, commands, activation, allow-list policy, the "what to do on a hit" table (Failure handling), and the reminder that a leaked real key must be **rotated** (01.2.4-T3 for OpenAI; `secrets.sh rotate-local` for local keys), not just removed from the commit.

## Outputs
- Tracked: `.githooks/pre-commit` and `.githooks/pre-push` (mode 755 recorded in git), `worker-node/README.md` § Secret scanning, `.gitleaksignore` only if a reviewed false positive exists.
- Local git config: `core.hooksPath=.githooks`.
- `$NTS_HOME/logs/gitleaks-initial-<YYYYmmdd-HHMMSS>.json` (redacted report, not tracked).

## Acceptance checks
- [ ] Initial scan: `gitleaks dir . --redact --no-banner; echo $?` → `0` (before the first commit)
- [ ] `git config --get core.hooksPath` → `.githooks`
- [ ] `test -x .githooks/pre-commit && test -x .githooks/pre-push && echo ok` → `ok`; after the first commit `git ls-files -s .githooks/` → both files mode `100755`
- [ ] Throwaway-repo proof (step 5): `blocked-exit` ≠ `0` and gitleaks prints a finding with `REDACTED` instead of the value; `clean-exit=0`
- [ ] Fail-closed: `PATH=/usr/bin:/bin .githooks/pre-commit; echo $?` → `1` with "gitleaks not found"
- [ ] SEC-12 pre-push proof in the throwaway repo (step 5 pattern): add a bare remote (`git init -q --bare "$t/remote.git"; git -C "$t" remote add origin "$t/remote.git"`), on top of the `ok` commit from step 5 commit the fake key with `--no-verify`, `git -C "$t" push -q origin HEAD` → exit ≠ `0` with `pre-push: secret in …`; after removing the commit (`git -C "$t" reset -q --hard HEAD~1`), the push → `0`
- [ ] SEC-12: `.githooks/pre-push` fails closed: `PATH=/usr/bin:/bin .githooks/pre-push </dev/null; echo $?` → `1`
- [ ] SEC-12: history scan logged at 01-ready (date and exit code in `worker-node/README.md` § Secret scanning)
- [ ] `git log --oneline | wc -l` ≥ 1 only after the checks above are ticked (first commit made through the hook)
- [ ] Before gate 01-closed: `gitleaks git --redact --no-banner; echo $?` → `0` (⚠️ U2 syntax)
- [ ] `test ! -e .gitleaks.toml` (no custom config weakening defaults), and `.gitleaksignore` absent or every line has a reason comment

## Failure handling
| Failure | Action |
|---|---|
| Initial scan finds a real secret in the working tree | Do not commit. Move it to the Keychain (`secrets.sh set`) or delete the file; if it is a real key, rotate it (it may have been copied or backed up). Re-scan until exit 0 |
| Finding in an ignored file (for example `config.toml` on the USB volume) | Not a commit risk, but a storage risk (E1): move it to `$NTS_HOME` or delete it, then rotate the key |
| Hook does not fire | `git config --get core.hooksPath`; `test -x .githooks/pre-commit`; check that a global `core.hooksPath` is not overriding (`git config --show-origin --get-all core.hooksPath`) |
| Subcommand/flag not recognised (U2) | Use the older-version mapping from step 1; update the hook and the runbook |
| Fake key not detected | Try the second generated pattern; if gitleaks detects nothing, stop and escalate (the scanner is not protecting anything) |
| Secret already committed | Stop pushing. Rotate the key first, then rewrite local history (before any push) with the TL; record the incident in `trial/runs/<run_id>/notes.md` or the runbook |
| Rollback | `git config --unset core.hooksPath`; delete `.githooks/pre-commit` |
