## Goal

A committed baseline `trial/baselines/vieneu-mac-<YYYYMMDD>.json` holds VieNeu's wall time, audio seconds, RTF, idle/peak RSS and cold start on vi/en fixtures; the **120 s gate** result (F01; informational, 04 CR-2) and the **watermark** behaviour (F10) are recorded; vi/en WAV samples are in `$NTS_HOME/runs/samples/` for 04.1.1.

## Inputs

- ✅ V1: one fp32 stream on CPU (`VIENEU_MAX_STREAMS=1`), `VIENEU_WATERMARK` on unless `0`, needs the `[watermark]` extra (resemble-perth → torch); behaviour without it ⚠️. `VIENEU_QUEUE_TIMEOUT` 10 s.
- ✅ V2: `/health` ready after load ≈ 19 s; WAV 48 kHz default. ✅ V3: ONNX threads = min(cpu/2, 8) = 5 on the 10-core M4, fixed.
- ✅ 04 NFR-04-2 / 04 R1: MPT kokoro timeout 120 s is an **idle** timeout (no bytes for 120 s), not a per-request total (04 CR-2); body ≤ 20,000 chars. ⚠️ whether MPT sends a whole script in one TTS request (`voice.py` not read; plan §2 Q6) → worst case assumed.
- ✅ 04 F3 / DECISIONS §8 item 6: WAV header length `0xFFFFFFFF` → audio seconds from decoded samples, not the header.
- ✅ 04 F4: VieNeu ignores `speed` → measured units/min is the real narration rate (input to plan 02).
- D1 paths, D3 key `nts.vieneu.api_key`, D9 conventions, D11 (no other heavy app; MPT and whisper not running).
- T2 `start-vieneu.sh` (`READY … after <n>s` line), T3 `voices.snapshot.json` (voice ids), T1 first-run log (`$NTS_HOME/logs/vieneu-firstrun-*.log`).

## Steps

1. **Fixtures** (tracked, `trial/fixtures/`, UTF-8 NFC, LF, plain prose, original text written for NTS, no real people/places — ghost-story register like the product; no markup, no numerals-heavy lines, sentences ≤ 30 words):

   | File | Language | Length rule | Purpose |
   |---|---|---|---|
   | `tts-vi-1000.txt` | vi | 1,000 ± 20 Unicode code points (`len(text.strip())` after NFC) | per-request RTF on a short chunk; sample for 04.1.1 |
   | `tts-en-1000.txt` | en | 1,000 ± 20 code points | same |
   | `tts-vi-5min.txt` | vi | **850 ± 25 syllables** (= whitespace-separated tokens; Vietnamese writes one syllable per token) | full 5-min story in one request (worst case, F01) |
   | `tts-en-5min.txt` | en | **750 ± 25 words** (whitespace-separated tokens) | same |

   Rates behind the 5-min sizes: vi ≈ 170 syllables/min, en ≈ 150 words/min [INFERENCE — typical narration rates, not measured]. The gate below normalises to 300 s of audio, so a wrong rate assumption changes the audio length, not the verdict. All four are far below the 20,000-char body limit (04 NFR-04-2). Count check (stdlib, D9):
   ```bash
   uv run --no-project --python 3.12 python - <<'PY'
   import unicodedata, pathlib
   for f in sorted(pathlib.Path("trial/fixtures").glob("tts-*.txt")):
       t = f.read_text(encoding="utf-8")
       assert t == unicodedata.normalize("NFC", t), f"{f} not NFC"
       print(f.name, "chars", len(t.strip()), "units", len(t.split()))
   PY
   ```

2. **Watermark: extra present?**
   ```bash
   cd "$NTS_HOME/src/vieneu"
   uv run --no-sync python -c 'import perth' ; echo "exit=$?"          # ⚠️ import name of resemble-perth; exit≠0 → extra absent (expected after plain sync)
   grep -n -i 'watermark\|perth' "$NTS_HOME"/logs/vieneu-firstrun-*.log "$NTS_HOME"/logs/vieneu-2*.log | head -n 20
   grep -rn -i 'watermark\|perth' apps/openai_speech.py src/vieneu/ | head -n 40   # read what happens on ImportError at the pin
   ```
   Classify into exactly one of: **A** server refuses to start (T2 never reached `READY`) · **B** starts, logs that watermarking is disabled/unavailable · **C** starts, no log line; code shows the watermark step is skipped on ImportError (silent off) · **D** extra present, watermark applied. Evidence = the log line (verbatim, it contains no secret) or `file:line` at the pin. Write `watermark.effective` = `off` for A-C, `on` for D, `unknown` if the code path cannot be determined.

3. **Baseline run (extra as installed).** Quit other heavy apps (D11; note what stays open). Port 8000 must be free (the bench starts its own server). Run:
   ```bash
   trial/tools/bench-vieneu.sh --voice-vi "Hải Đăng" --voice-en "<en voice id from voices.snapshot.json>"
   ```
   Specification of `trial/tools/bench-vieneu.sh` (Bash, D9; stdlib Python helper for JSON/stats via `uv run --no-project --python 3.12`; never `set -x`):

   | Phase | Action | Records |
   |---|---|---|
   | preflight | `worker-node/bin/start-vieneu.sh --check`; `require_port_free 8000`; fixtures exist; `ffprobe`, `ffmpeg` on PATH; `mkdir -p "$NTS_HOME/runs/samples/bench-$(date +%Y%m%d-%H%M)"` = `$OUT` | exit 2 on failure |
   | cold start × `--cold-starts` (default 2) | start `worker-node/bin/start-vieneu.sh` in background, wait for its `READY vieneu … after <n>s` line (timeout 300 s), then stop it (SIGINT) and wait for port 8000 to be free; the last start stays running for the next phases | `cold_start_s[]` = each `n` (first one after a reboot/purge is not required; note in `notes` whether file cache was warm) |
   | idle RSS | server PID = `lsof -tiTCP:8000 -sTCP:LISTEN`; wait 10 s after READY; 5 samples of `ps -o rss= -p $PID` 1 s apart | `idle_rss_mb` = median ÷ 1024 |
   | per request | for fixture in `tts-vi-1000`, `tts-en-1000`, `tts-vi-5min`, `tts-en-5min`; repeat `--repeats` (default 2; first 1000-char vi request is a discarded warm-up, logged as `repeat: 0`): start a background RSS sampler (`ps -o rss=` every 0.5 s → `$OUT/rss-<fixture>-<r>.csv`), send `POST /v1/audio/speech` `{"model":"vieneu-v3-turbo","input":<fixture text>,"voice":<vi/en voice>,"response_format":"wav"}` with `-H @<(printf 'Authorization: Bearer %s\n' "$KEY")`, `--max-time 900` (measure even if > 120 s), `-o $OUT/<fixture>-<r>.wav -w '%{http_code}\t%{time_starttransfer}\t%{time_total}\t%{size_download}'`; stop sampler | `http_status`, `ttfb_s`, `wall_s`, `bytes`, `peak_rss_mb` = max sample ÷ 1024 |
   | audio seconds | `ffmpeg -v error -i <wav> -f s16le -ac 1 -ar 48000 - \| wc -c` → samples = bytes ÷ 2 → `audio_s` = samples ÷ 48000 (decoded, not header; 04 F3). Also `ffprobe -v error -show_entries format=duration -of csv=p=0 <wav>` stored as `ffprobe_duration_s` for 04.1.1 comparison | `audio_s`, `rtf = wall_s / audio_s`, `units_per_min = units / (audio_s / 60)` |
   | health | `curl -s http://127.0.0.1:8000/health` before and after | `server.health` |
   | write | stop the server (SIGINT); stdlib helper writes `trial/baselines/vieneu-mac-$(date +%Y%m%d).json` (schema: plan.md §3; if the file exists, suffix `-2`, `-3`), medians per fixture in `summary`, and the `gate_120s` block with `result` but empty `decision` | baseline JSON |

   Environment recorded in the JSON: `sw_vers -productVersion`, `sysctl -n hw.ncpu`, `sysctl -n hw.memsize`, pins from `worker-node/pins.env`, `watermark` block from step 2, `extra_installed` from the import check.

   Why `ps` sampling and not `/usr/bin/time -l` alone: the server is a single process (no children, V3), so RSS of the PID is the whole footprint — unlike MPT (F04). `/usr/bin/time -l` would give only one lifetime peak; sampling gives idle vs per-request peak. Record `vm_stat` swap lines (`Swapins`/`Swapouts`) before/after in `notes` to flag memory-pressure artefacts.

4. **Watermark extra (only if step 2 = A, B or C).** Measure its cost so the owner can decide:
   ```bash
   cd "$NTS_HOME/src/vieneu"
   uv sync --frozen --extra watermark          # pulls torch (V1); record download size: du -sh .venv before/after
   uv run --no-sync python -c 'import perth; print("ok")'   # ⚠️ import name
   ```
   Re-run step 2 classification (expect **D**) and `trial/tools/bench-vieneu.sh --repeats 1 --tag watermark-extra …` (writes the same schema with `"tag": "watermark-extra"`). Compare `idle_rss_mb`, `peak_rss_mb`, `rtf` and `cold_start_s` with the plain run. Then **decide** [DECISION, owner + TL] and record in both JSONs `watermark.decision`:
   - **Keep extra on the Mac** → CR to 01.1.2-T3 (`bootstrap.sh vieneu` syncs with `--extra watermark`) and to 01.3.3 carry-over; the extra stays installed.
   - **Mac trial without watermark** (audio is never published in M0) → `uv sync --frozen` again (drops the extra; exact sync ⚠️ Q5), record that the worker (plan 11) MUST install `--extra watermark` and verify **D**; add to CARRY-OVER via 01.3.3-T1.
   - Neither acceptable (e.g. startup failure A without the extra and RAM too high with it) → escalate to TL before 05.5.2.

5. **120 s gate (F01) — informational capacity input (04 CR-2).**
   - `rtf_5min_max = max(summary["tts-vi-5min"].rtf_median, summary["tts-en-5min"].rtf_median)`; `projected_wall_s = rtf_5min_max × 300`.
   - `gate_120s.result` = `pass` if `projected_wall_s < 100` (RTF < 0.333), else `fail`; the result stays recorded but is **informational** (capacity input for 04 sizing), not a go/no-go: MPT's 120 s is an idle timeout (04 R1) and the proxy streams PCM → ffmpeg → MP3, so a slow RTF alone does not fail a 5-min request (04 CR-2).
   - No escalation branch: the "fail → chunking" option is withdrawn (owner-approved 2026-09-24, 04 O1). The pass/fail check is 04.1.2-T3: `ttfb_ms` < 30,000 and `max_gap_ms` < 60,000 on the 5-min fixtures through the proxy. `gate_120s.decision` records the result and the numbers sent to the plan 04 owner via hub (04 CR-2).
   - Also compute (INFO only, not gating): `rtf_1000` vs `rtf_5min` (linearity: > 20 % worse on 5-min → note possible length-dependent slowdown), `rtf_5min_max × 600` for the 10-minute question in 04 §10, and the measured vi syllables/min and en words/min for plan 02.
   - Fill `decided_by`, `decided_on`; **recording** the result (not passing it) is part of **01-ready** (README §7) (04 CR-2).

6. **WAV handoff to 04.1.1.** Copy one 1000-char and one 5-min WAV per language from `$OUT` to `$NTS_HOME/runs/samples/`:
   `vieneu-vi-1000.wav`, `vieneu-en-1000.wav`, `vieneu-vi-5min.wav`, `vieneu-en-5min.wav`. For each: `shasum -a 256`, RIFF size (bytes 4–7) and `data` chunk size as hex (`xxd -s 4 -l 4 -e`, and the 4 bytes after the `data` tag) → `samples[]` in the baseline (expect `ffffffff`, 04 F3); `ffmpeg -v error -i <wav> -f null -` exit code. Do **not** transcode to mp3 here — that is 04.1.1's check. Send the plan 04 owner the paths via hub.

7. **Commit** fixtures, `trial/tools/bench-vieneu.sh`, and the baseline JSON(s). Raw bench data (`$OUT`) stays in `$NTS_HOME`.

## Failure handling

| Failure | Action |
|---|---|
| A 5-min request exceeds 900 s or returns 429/5xx | record status; re-run once with nothing else running; persistent → record `result = "fail"` with the measured partial data (informational) and send it to the plan 04 owner as capacity input (04 CR-2) |
| RTF varies > 25 % between repeats | check `vm_stat` swap and other processes; add one more repeat; report median and spread |
| Memory pressure (swap-outs grow during the run) | record; note that RSS peak is then understated; re-run after closing apps |
| Step 2 = **A** (server does not start with `VIENEU_WATERMARK=1`) | no baseline possible without deciding: run step 4 first (install extra); if that is not acceptable, TL decides whether a Mac-only `VIENEU_WATERMARK=0` is allowed for M0 (would require changing the T2 guard and `env.example`; record as a deviation) |
| Watermark code path undecidable (`unknown`) | keep extra decision open, mark gate 01-ready **not** met for watermark; ask TL |
| `ffmpeg` cannot decode a sample | record exact stderr; this is the 04.1.1 PCM-fallback trigger (04 §4); do not work around it here |
| English voice id unknown (voice object has no language field) | use the default voice for en, record it, and let 04.2.1 pick en voices |
| Rollback | delete the baseline JSON(s) and re-run; if step 4 installed the extra and the decision is "without", `uv sync --frozen` in `$NTS_HOME/src/vieneu` and confirm the import check fails again |
