# 01.2.2-T4 — Start script: MPT API (no WebUI, D14)

| Story | Size | Area | Depends on | Blocks | Gate |
|---|---|---|---|---|---|

Size: XS holds after DEC-4 removed the WebUI script; SEC-04 (listener-ownership checks) is the only addition.

## Goal
One command per service (FR-01-1). `start-mpt-api.sh` renders and guards the config, verifies the upstream tap/proxy listeners it will send OpenAI/proxy keys to are owned by this user and are the expected process (SEC-04), then runs MPT on `127.0.0.1:8080` in the foreground with a teed log; it refuses to start whenever MPT would run with an open or LAN-bound config, or with an unverified upstream. The MPT WebUI is not used in M0 (D14).

## Inputs
- ✅ M2: `uv run python main.py`; `sh webui.sh` with `MPT_WEBUI_HOST` / `MPT_WEBUI_PORT`; the WebUI port drifts to 8502–8599 when busy. ✅ M7: `IMAGEIO_FFMPEG_EXE`. ✅ M8: a missing config is copied from the example; the WebUI rewrites the config. ✅ M11: startup warning `API key authentication is disabled; keep the API on a trusted network`. ✅ M3 + 01.2.3: `HF_HUB_OFFLINE=1`.
- D1 log path `$NTS_HOME/logs/<service>-<YYYYmmdd-HHMMSS>.log` with service name **`mpt-api`** (agreed with 01.3.1 and 01.2.3, which glob `mpt-api-*.log`). D3 Keychain services. D4 ports + `check-binds.sh`. D9 `lib.sh`: `nts_home`, `load_pins`, `secret`, `require_port_free` (exits 2), `log` (stderr, ISO UTC).

## Steps
1. **`worker-node/bin/start-mpt-api.sh`** (D9: `set -euo pipefail`, never `set -x`, `--help`):
   1. `source "$(dirname "$0")/lib.sh"`; `load_pins`; `H="$(nts_home)"`; `ROOT="$H/src/mpt"`; `REPO="$(cd "$(dirname "$0")/../.." && pwd)"`.
   2. Environment checks → exit 2: `git -C "$ROOT" rev-parse HEAD` == `$MPT_COMMIT`; `test -x /opt/homebrew/bin/ffmpeg`; `test -d "$ROOT/.venv"`; `mkdir -p "$H/logs"`.
   3. `require_port_free 8080` (exit 2 if something already listens).
   3a. **Upstream listener ownership (SEC-04).** MPT sends the OpenAI keys to `127.0.0.1:8002` and the proxy key to `127.0.0.1:8001`, so both listeners are verified before any secret is read:
      ```bash
      for p in 8002 8001; do
        rows="$(lsof -a -nP -iTCP:"$p" -sTCP:LISTEN -Fpcu 2>/dev/null)"   # p=pid c=command u=uid
        n="$(printf '%s\n' "$rows" | grep -c '^p')"
        [ "$n" = 1 ] || die 2 "port $p: expected exactly 1 listener, found $n"
        printf '%s\n' "$rows" | grep -qx "u$(id -u)" || die 2 "port $p: listener not owned by $(id -un)"
      done
      ```
      - 8002: `jq`-free check with `python3 -c` on `$H/tap.json`: `upstream == "${OPENAI_BASE_URL%/v1}"` (01 CR-15) and `pid` equals the 8002 listener pid (`tap.json` is written by `usage_tap.py` itself, 01.3.1-T2); the listener's `ps -o command= -p <pid>` contains `usage_tap.py`. Any mismatch → exit 2 (`tap not verified`).
      - 8001: the listener command contains the proxy entry point string `nts_vieneu_proxy` (`python -m nts_vieneu_proxy`, 04 D1) (04 CR-6). Until 04 lands, 8001 absent → WARN and continue only for runs that do not use `kokoro:` voices; T6 requires it.
      - `--no-tap` (test hook, never in measured runs) skips the 8002 check and requires the rendered base URLs to point at `OPENAI_BASE_URL` (01 CR-15) instead ⚠️ (renderer flag; otherwise refuse).
   4. `"$REPO/worker-node/bin/strip-bundled-music.sh" --check` → exit 1 on unlicensed audio (DECISIONS §5.5).
   5. Render (T2 step 3 pattern; the Keychain values exist only in the renderer's environment):
      ```bash
      NTS_MPT_API_KEY="$(secret nts.mpt.api_key)" NTS_OPENAI_STORY_KEY="$(secret nts.openai.story)" \
      NTS_OPENAI_IMAGE_KEY="$(secret nts.openai.image)" NTS_PROXY_API_KEY="$(secret nts.proxy.api_key)" \
        uv run --no-project --python 3.12 "$REPO/worker-node/bin/render-mpt-config.py" || exit 1
      ```
      Any `secret` failure (missing Keychain item) → exit 2 with the service name only.
   6. Refuse to start unless the rendered file is present and valid: `test -f "$ROOT/config.toml" && ! test -L "$ROOT/config.toml"` and `render-mpt-config.py --check` exit 0. Otherwise `log "refusing to start: config.toml missing/invalid (MPT would copy config.example.toml → auth off, 0.0.0.0; F07)"` and exit 1. MPT is never started without this.
   7. Launch in the foreground with a teed log. MPT reads its secrets from `config.toml` and gets no secret env var:
      ```bash
      LOG="$H/logs/mpt-api-$(date +%Y%m%d-%H%M%S).log"
      cd "$ROOT"
      env -u NTS_MPT_API_KEY -u NTS_OPENAI_STORY_KEY -u NTS_OPENAI_IMAGE_KEY -u NTS_PROXY_API_KEY \
          -u OPENAI_API_KEY \
          IMAGEIO_FFMPEG_EXE=/opt/homebrew/bin/ffmpeg HF_HUB_OFFLINE=1 PYTHONUNBUFFERED=1 \
          uv run python main.py 2>&1 | tee -a "$LOG" &
      ```
      Honour a caller-exported `HF_HUB_OFFLINE` (01.2.3 offline proof); the default is `1`. Use `${HF_HUB_OFFLINE:-1}`, and log a WARN if it is not `1`.
   8. Post-start assertions: poll ≤ 60 s until `lsof -nP -iTCP:8080 -sTCP:LISTEN` shows a listener, then:
      - `worker-node/bin/check-binds.sh` → exit 0 (no `*`, `0.0.0.0` or `::`), and the 8080 row shows `127.0.0.1:8080`.
      - `grep -q 'API key authentication is disabled' "$LOG"` → must **not** match.
      - Either failure → `log "FAIL …"`, kill the MPT process group (`kill -- -$PGID`, then `lsof -t -iTCP:8080 -sTCP:LISTEN | xargs kill`), exit 1.
      - On success print `mpt-api ready on 127.0.0.1:8080 log=$LOG`, then `wait` (foreground; Ctrl-C ends it; a `trap` on INT/TERM kills the child group).
2. **No WebUI in M0 (D14, owner DEC-4).** `start-mpt-webui.sh` is not written, and `sh webui.sh` is never run on the trial machine. `check-binds.sh` fails if anything listens on 8501–8599 (M2 port range), so an accidental WebUI start is caught by `smoke.sh`. If a UI is wanted later, the removed design (separate worktree `$NTS_HOME/src/mpt-webui`, dummy `webui-disabled-<hex>` keys, 30-min auto-stop) is the starting point for a new decision.
3. The script: `--help` prints usage and the exit codes; `--template PATH` (test hook) is passed through to `render-mpt-config.py --template`. Never echo `secret` output. Keep the `current_run` file untouched (01.3.1 owns it).

## Failure handling
- MPT exits during start (import error, ffmpeg check M7) → the script sees the pipe end, prints the last 30 log lines, exits 1.
- A listener on `*:8080` (e.g. `listen_host` ignored at the pin ⚠️) → killed by the post-start check; stop and investigate the M1 placement at the pin.
- `tee` hides MPT's exit status → use `set -o pipefail` and `wait "$PID"`.
- Rollback: Ctrl-C in the MPT terminal; `lsof -nP -iTCP:8080 -sTCP:LISTEN` → empty. Delete the rendered config per plan §11.
