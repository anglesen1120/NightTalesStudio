# 01.2.2-T5 — MPT smoke test

| Story | Size | Area | Depends on | Blocks | Gate |
|---|---|---|---|---|---|
| 01.2.2 | XS (0.25 d) | Worker | 01.2.2-T4 (API running), 01.2.2-T2 (`--check`, `--self-test`), `check-binds.sh` (D4) | 01.2.2-T6, gate 01-ready (`smoke.sh`), 04.1.2-T3 (04 CR-16), 05.4.1-T1 (05 CR-13) | 01-ready |

## Goal
`worker-node/bin/smoke-mpt.sh` proves against the running API that auth is on (401 without a key and with a wrong key, 200 with the right key), that foreign browser origins get 403, that MPT listens only on loopback, that the rendered config passes the guards, and that the renderer's negative cases fail. It exits 0 only when every check passes.

## Inputs
- ✅ M11: empty `api_key` → auth off with the startup warning `API key authentication is disabled; keep the API on a trusted network`; missing/wrong/duplicate `x-api-key` → 401 `invalid API key`; untrusted `Origin` → 403 `cross-origin browser request is not allowed`; body shape `{"status": <code>, "message": …}`. 05 §5.3: `GET /api/v1/tasks` exists.
- D3 `nts.mpt.api_key`; D4 `check-binds.sh`, port 8080; D9 conventions; T4 log `$NTS_HOME/logs/mpt-api-*.log`.
- Shared aggregator `worker-node/bin/smoke.sh` (proposed by 01.2.1, whoever lands first creates it): runs every `smoke-*.sh` in a fixed order, then `check-binds.sh`. Output lines are `PASS <check>` / `FAIL <check>: <detail>` / `WARN|INFO|SKIP <check>: <detail>`; exit 2 if any script exited 2, else 1 if any exited 1, else 0.

## Steps
1. Write `worker-node/bin/smoke-mpt.sh` (D9; `--help`; read-only against the service except for the renderer self-test in a temp dir):
   ```bash
   #!/usr/bin/env bash
   set -euo pipefail
   source "$(dirname "$0")/lib.sh"
   H="$(nts_home)"; REPO="$(cd "$(dirname "$0")/../.." && pwd)"
   BASE="http://127.0.0.1:8080/api/v1"
   KEY="$(secret nts.mpt.api_key)" || { echo "FAIL keychain: nts.mpt.api_key"; exit 2; }
   hdr() { printf 'x-api-key: %s\n' "$1"; }         # header via process substitution, never argv
   code() { curl -sS -o /dev/null -w '%{http_code}' --max-time 10 "$@"; }
   ```
   Checks, in order (each prints one `PASS`/`FAIL` line; failures are collected, exit at the end):

   | # | Check name | Command (shape) | Expected |
   |---|---|---|---|
   | 1 | `mpt.listening` | `lsof -nP -iTCP:8080 -sTCP:LISTEN` | a row with `127.0.0.1:8080`, else `FAIL` and exit 2 (service not started) |
   | 2 | `mpt.auth.no_key` | `code "$BASE/tasks"` | `401` |
   | 3 | `mpt.auth.wrong_key` | `code -H @<(hdr "$(openssl rand -hex 32)") "$BASE/tasks"` | `401` |
   | 4 | `mpt.auth.right_key` | `code -H @<(hdr "$KEY") "$BASE/tasks"` | `200` |
   | 5 | `mpt.auth.body` | `curl -sS "$BASE/tasks"` → JSON `message` | `invalid API key` (✅ M11; ⚠️ exact text at pin → `WARN` not `FAIL` if different but still 401) |
   | 6 | `mpt.origin.foreign` | `code -H @<(hdr "$KEY") -H 'Origin: https://evil.example.invalid' "$BASE/tasks"` | `403` |
   | 7 | `mpt.tasks_static.no_key` | `code "http://127.0.0.1:8080/tasks/"` | `401` (✅ M11 `/tasks` middleware; ⚠️ `404` possible if the static mount needs a file path → `WARN`) |
   | 8 | `mpt.log.auth_enabled` | newest `ls -t "$H"/logs/mpt-api-*.log \| head -1`; `grep -c 'API key authentication is disabled'` | `0` |
   | 9 | `mpt.lan_refused` | `ip=$(ipconfig getifaddr en0 \|\| ipconfig getifaddr en1)`; `curl -sS --max-time 3 "http://$ip:8080/" ; echo $?` | curl exit `7` (connection refused, F19); no IP → `SKIP` |
   | 10 | `mpt.binds` | `"$REPO/worker-node/bin/check-binds.sh"` | exit 0 |
   | 11 | `mpt.config.check` | `uv run --no-project --python 3.12 "$REPO/worker-node/bin/render-mpt-config.py" --check` | exit 0 |
   | 12 | `mpt.no_value_leak` (SEC-09) | **Fail closed:** first resolve all four values into shell variables, `k1="$(secret nts.mpt.api_key)" && k2="$(secret nts.openai.story)" && k3="$(secret nts.openai.image)" && k4="$(secret nts.proxy.api_key)" \|\| exit 2`; then check that each is non-empty and ≥ 16 chars (else exit 2). A `secret` failure inside `<(…)` would not propagate, and an empty pattern list makes `grep` report 0 matches = a false PASS. Only then: `grep -cFf <(printf '%s\n' "$k1" "$k2" "$k3" "$k4") <file>` per file (`$H/mpt-config.last.redacted.toml`, each `$H/logs/mpt-*.log`); `printf` is a builtin, so no value enters argv. `unset k1 k2 k3 k4` in the exit trap | `0` per file; lookup failure → exit 2 (never PASS) |
   | 13 | `mpt.webui_absent` (D14) | `lsof -nP -iTCP -sTCP:LISTEN \| awk '$9 ~ /:85(0[1-9]\|[1-9][0-9])$/'` and `test ! -e "$REPO/worker-node/bin/start-mpt-webui.sh"` | no listener on 8501–8599 and no WebUI script → PASS |
   | 14 | `mpt.config.mode` | `stat -f '%Lp %HT' "$H/src/mpt/config.toml"` | `600 Regular File` |
   | 15 | `mpt.renderer.selftest` | `… render-mpt-config.py --self-test` (dummy values; covers missing var, empty `api_key`, `listen_host = "0.0.0.0"`, bad chars, `/Volumes/` out) | exit 0 |
   | 16 | `mpt.music.check` | `"$REPO/worker-node/bin/strip-bundled-music.sh" --check` | exit 0 |

   Rules: `unset KEY` at exit (`trap`). Never print `$KEY`. `curl` output bodies go to `/dev/null` except check 5 (the 401 body contains no secret). The script does not create tasks and costs nothing.
2. Exit: `2` if check 1 failed or the Keychain lookup failed; else `1` if any `FAIL`; else `0`. `WARN`/`SKIP` do not fail.
3. Add `smoke-mpt.sh` to `smoke.sh` in the agreed order (`smoke-vieneu.sh`, `smoke-mpt.sh`, …). If `smoke.sh` does not exist yet, create it per the Inputs contract (the only file outside this feature's list that this task may create; coordinate with the 01.2.1 owner).

## Outputs
- Tracked: `worker-node/bin/smoke-mpt.sh` (and `worker-node/bin/smoke.sh` if this task lands first).
- Console output only; no files in `$NTS_HOME` (the self-test uses a temp dir).

## Acceptance checks
- [ ] With the API running (T4): `worker-node/bin/smoke-mpt.sh; echo $?` → 14 lines `PASS`/`SKIP`/`WARN` and `0`.
- [ ] With the API stopped: `smoke-mpt.sh; echo $?` → `FAIL mpt.listening` and `2`.
- [ ] Auth-off regression (throwaway, on a copy): render with a template copy whose `api_key` is `""` → the renderer refuses (exit 1), so an auth-off MPT cannot be produced through the scripts. The manual equivalent (not run on the real config) is documented as the reason checks 2/8 exist.
- [ ] `bash -x`-free: `grep -n 'set -x' worker-node/bin/smoke-mpt.sh` → nothing; `shellcheck worker-node/bin/smoke-mpt.sh` → clean.
- [ ] `grep -nE 'x-api-key: [0-9a-f]' worker-node/bin/smoke-mpt.sh` → nothing (no literal keys).
- [ ] `worker-node/bin/smoke.sh` runs `smoke-mpt.sh` and propagates its exit code.

## Failure handling
- 200 without a key → **stop everything** (auth off): Ctrl-C the API, check `config.toml` `api_key` (`--check`), and check the log for the auth-disabled warning. Never continue to T6.
- 404 on `/api/v1/tasks` → the prefix differs at the pin ⚠️ (05 §5.3 "prefix ⚠️"): find the route in `/docs` (`curl -sS http://127.0.0.1:8080/openapi.json | python3 -c 'import json,sys;print("\n".join(json.load(sys.stdin)["paths"]))'`), update `BASE`, and tell 05.4.
- 403 on right key without an Origin → a CORS env var (`CORS_ALLOWED_ORIGINS`, M8) is set in the shell; unset it.
- Origin check returns 200 → the MPT at the pin has no origin guard ⚠️; record it as `WARN` and inform 05.4 (the worker is private anyway).
- LAN check connects → `listen_host` is not applied; stop the API, investigate the M1 placement (T2).
