# 01.2.4-T1 — Org verification + billing guard

| Story | Size | Area | Depends on | Blocks | Gate |
|---|---|---|---|---|---|

## Goal
The OpenAI org can call GPT Image models (verification done or confirmed not needed). The org is prepaid with **auto-reload off** and an enforced **$30/month hard limit**. The usage tier and image rate limit are recorded.

## Inputs
- Facts: O1 (hard spend limit, 429 codes, not instant), O2 (prepaid, auto-reload on by default, `credit_balance_exhausted` not an instant cutoff), O5 ⚠️ (verification "may" be required), O8 (Tier 1 = 5 images/min, 100k TPM), M4 (retry 3× then skip keyword), F11.
- Decisions: D7 (org prepaid, auto-reload off, org hard limit $30 — amount is an owner proposal), DECISIONS §2 (spending limit in the dashboard).
- People: the **OpenAI org Owner** (dashboard billing/limits/verification need Owner rights; the developer may be a Reader/Member only).
- Nothing on the Mac is needed yet (no key is created in T1).

## Steps
All dashboard labels below are quoted from the docs and are ⚠️ (the UI may differ). When a label differs, write the real one in **Notes** of this file.

1. **Verification first (external wait).** Owner opens `https://platform.openai.com/settings/organization/general` ⚠️ → section "Organization Verification" / "Verify Organization" ⚠️ (O5, help 10910291).
   - Status already *Verified* → record `verified`.
   - Status unverified → start the verification flow (identity check via the provider shown ⚠️). Record `pending` + submission timestamp (UTC).
   - No verification section at all → record `not_shown` and treat as `unknown` until T3 C3 proves image access.
2. **Prepaid credit.** Owner → Settings → **Billing** ⚠️ (O2):
   1. Confirm the org is on prepaid billing (new API accounts are, O2).
   2. Buy credit. The amount is the owner's decision; proposal **$30** (= the D7 org limit; minimum purchase $5, O2). Credits expire after 1 year and are non-refundable except in listed cases (O2, DECISIONS §10.5), so do not over-buy.
   3. Open the auto-reload / "auto recharge" settings ⚠️ → **turn auto-reload off** (it is **on by default**, O2) → Save.
   4. Reload the Billing page → auto-reload shows off; the balance shows the purchase.
3. **Org hard spend limit.** Owner → `https://platform.openai.com/settings/organization/limits` → **Spend** → **Edit spend limit** → **Monthly spend limit** = `30` (USD) → toggle **Enforce a hard limit** on → Save (O1).
   - Do **not** leave it as a spend alert only: an alert only notifies and traffic continues (O1).
   - Optional: add a spend **alert** at $15 (50 %) so the owner gets an e-mail before the hard stop [INFERENCE: alert and hard limit can coexist ⚠️].
4. **Usage tier and rate limits.** On the same Limits page ⚠️, read:
   - usage tier (expected **Tier 1** for a new org, O8 ⚠️ for this org);
   - `gpt-image-2.5-flare` rate limit (Tier 1 = **5 images/min**, 100k TPM, O8);
   - `gpt-6-luna` RPM/TPM (record as shown);
   - the org's approved monthly usage limit (separate from the spend limit; exceeding it gives `organization_usage_limit_exceeded`, O1).
5. **Record** the values in a scratch note for T3, which writes them into `trial/baselines/openai-access-mac-<YYYYMMDD>.json` → `org{}`:
   `verification`, `verification_submitted_at` (if pending), `auto_reload` (`false`), `hard_limit_usd` (`30`), `credit_purchased_usd`, `usage_tier`, `image_rate_limit_ipm`, `story_rate_limit` (RPM/TPM as shown), `usage_limit_usd`.
   Do not record billing identity data (card, address, ID documents).
6. **Explain the rate-limit consequence** in the scratch note (it flows into 01.2.2-T6 and 01.3.1-T3):
   - MPT sends one image call per keyword. On 429/5xx it retries at +5, +15, +30 s, then logs `openai image generation failed` and **skips the keyword** with no error (M4).
   - At Tier 1 = 5 images/min, a burst of more than 5 calls/min plus ~50 s of retries can exhaust the retries → images silently missing. Whether MPT's calls are sequential is ⚠️ (observed in 01.2.2-T6 through the tap).
   - A spend-limit 429 (O1) or `credit_balance_exhausted` (O2) looks the same to MPT: the keyword is skipped. Only the tap's `error_code` (D6) tells them apart.
   - No tier upgrade in M0: trial numbers should reflect Tier 1.

## Failure handling
| Failure | Action |
|---|---|
| Developer lacks Owner/billing rights | Owner does steps 1–4 while the developer watches or reads back. Never share the owner's login |
| Verification pending for days | T2 + T3 story checks continue. Image checks, the tap end-to-end check and the wiring render wait. Report the external-wait lane in the weekly review (00 §13). Do **not** switch to another image model to bypass it (DECISIONS §3 fixes `gpt-image-2.5-flare`) |
| Verification rejected | Stop image work, escalate to the owner/TL. M0 cannot close without images (FR-01-2) |
| Hard-limit toggle not present (only alerts) | ⚠️ UI differs from O1. Set an alert at $30 plus keep auto-reload off and buy only $30 → the prepaid balance becomes the (delayed) ceiling (O2). Record "hard limit unavailable" as an open risk for the TL |
| Auto-reload cannot be turned off | Set the smallest monthly reload limit ⚠️ and a low threshold. Record the risk |
| Purchase fails | Retry with another payment method (owner). No further steps until the balance > 0 |

Rollback: raise or remove the spend limit, or re-enable auto-reload, in the same pages. Credits cannot be refunded (O2).
