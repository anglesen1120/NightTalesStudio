## Goal
Two OpenAI projects exist. Each has a one-model allow-list and an enforced hard limit. Each has one Restricted key, and the key value exists only in the Keychain services `nts.openai.story` / `nts.openai.image` on the Mac.

## Inputs
- Facts: O1 (project hard limit), O3 (Limits → Model Usage, **Owner only**), O4 (Restricted; Model capabilities = Request; List models = Read), M4/M5 (MPT uses `openai_image_api_keys` for images and `openai_api_key` for story), M1 (both keys in `[app]`).
- Decisions: D7 (project names, allow-lists, limits $5 / $25, key names, Restricted), D3 (Keychain service names, `secrets.sh`), D5 (renderer maps `nts.openai.story` → `${NTS_OPENAI_STORY_KEY}` → `openai_api_key`, `nts.openai.image` → `${NTS_OPENAI_IMAGE_KEY}` → `openai_image_api_keys`), DECISIONS §10.11 (separate image project).
- Tool contract from 01.1.2-T2 (confirmed by BaseToolingPlan): `secrets.sh set <service>` accepts only the 5 D3 names (else exit 2), needs a TTY (exit 2 without), runs `security add-generic-password -U -a "$USER" -s <service> -w` (security prompts for the value), exit 0 on success. `secrets.sh check` reports missing items. lib.sh `secret <service>` prints only the value, or prints `missing keychain item: <service> …` to stderr and exits 2.
- Key name month: `KEY_MONTH=$(date -u +%Y%m)` → e.g. `202609`.

## Steps
Dashboard labels are from the docs and are ⚠️. Write the real labels in **Notes** when they differ.

1. **Create project `nts-trial-story`.** Owner → org settings → **Projects** → Create project ⚠️ → name `nts-trial-story` exactly.
2. **Allow-list.** `nts-trial-story` → **Limits** → **Model Usage** (O3) → allow only `gpt-6-luna` → Save.
   - If the UI lists snapshots separately, allow the alias `gpt-6-luna` and its current snapshot(s) only. Record which ⚠️.
   - Do **not** allow `gpt-6-sol` now. It is added **temporarily** by the owner only for the 02.1.3-T1 A/B window and removed after 02.1.3-T2 (02 CR-17); a permanent upgrade (DECISIONS §3) is a later explicit change to this list.
3. **Project hard limit.** `nts-trial-story` → **Limits** → **Spend** → **Edit spend limit** → **Monthly spend limit** `5` → **Enforce a hard limit** on → Save (O1).
4. **Create project `nts-trial-image`**, then allow-list only `gpt-image-2.5-flare` (plus snapshot `gpt-image-2.5-flare-2026-09-08` if listed separately ⚠️). Set the hard limit to `25` with enforcement on.
5. **Check the sum:** $5 + $25 = $30 ≤ org limit $30 (T1). If the owner changes any amount, keep project sum ≤ org limit and update D7 via the TL (README change first).
6. **Create the story key** (owner, **sitting at the Mac**):
   1. On the Mac, the developer opens a terminal and runs `worker-node/bin/secrets.sh set nts.openai.story` (it waits at the security prompt). **Do not** run it with `bash -x`.
   2. Owner → `nts-trial-story` → **API keys** ⚠️ → Create new secret key ⚠️:
      - Name: `nts-trial-story-mac-<YYYYMM>` (e.g. `nts-trial-story-mac-202609`);
      - Owned by: the project/service account vs user ⚠️. Prefer a service account if offered [INFERENCE: survives a user leaving; confirm UI];
      - Permissions: **Restricted** → **Model capabilities: Request**; **List models: Read**; every other resource **None** (O4).
   3. Copy the key once (it is shown once ⚠️). Paste it only into the security prompt on the Mac. Press Enter and exit 0 is expected.
   4. Clear the clipboard right away: `pbcopy </dev/null`.
   5. Close the dashboard dialog. Never paste the key into chat, e-mail, notes, a file, the terminal command line, or a screenshot (DECISIONS §2, D3).
7. **Create the image key** the same way: `worker-node/bin/secrets.sh set nts.openai.image`; project `nts-trial-image`; name `nts-trial-image-mac-<YYYYMM>`; Restricted with the same two permissions; then `pbcopy </dev/null`.
8. **Presence check without printing values:**
   ```bash
   worker-node/bin/secrets.sh check
   security find-generic-password -a "$USER" -s nts.openai.story >/dev/null && echo story:present
   security find-generic-password -a "$USER" -s nts.openai.image >/dev/null && echo image:present
   ```
   (`find-generic-password` without `-w` prints only metadata; the redirect hides even that.)
9. **Shape check without printing values** (keys are distinct and non-empty; prints only lengths and a boolean):
   ```bash
   bash -c 'set -euo pipefail; . worker-node/bin/lib.sh
     s=$(secret nts.openai.story); i=$(secret nts.openai.image)
     printf "story_len=%d image_len=%d distinct=%s\n" "${#s}" "${#i}" "$([ "$s" != "$i" ] && echo yes || echo no)"'
   ```
10. **Record** for T3's access record (`projects{}`): for each project, the allow-list as shown, `hard_limit_usd`, `key_name`, `key_permission: "restricted"` and `key_owner` (service account/user). Key prefixes or last-4 are **not** recorded. The key name identifies the key in the dashboard.
11. **Shell history check** (defence in depth): `grep -c 'sk-' ~/.zsh_history ~/.bash_history 2>/dev/null || true` → expected `0` for each existing file. It prints counts only, never matches. [INFERENCE: OpenAI secret keys start with `sk-` ⚠️]

## Failure handling
| Failure | Action |
|---|---|
| Developer is not Owner → Model Usage/Limits greyed out | Owner does steps 1–5. The developer never gets the Owner role just for this |
| Owner cannot be at the Mac | Owner creates the key during a screen-share where the Mac terminal (not the dashboard) receives the paste, or reschedules. Never transfer the key by message. [DECISION: no remote key transfer] |
| `secrets.sh set` exits 2 "no TTY" | Run it from Terminal.app directly, not from a piped/IDE runner |
| Pasted wrong value / wrong service | Re-run `secrets.sh set <service>` (`-U` updates in place). If a key was pasted anywhere else (chat, a file, a command line), treat it as leaked → runbook rotation (T3) immediately |
| Model not listed in Model Usage | ⚠️ UI or name mismatch → record the exact list shown and stop. Do not allow "all models". Escalate to TL |
| Restricted permissions UI lacks "Model capabilities" | Record the real permission names. Choose the narrowest set that allows chat/images; T3 C6 proves the rest is denied |
| Key created in the wrong project | Revoke it in the dashboard, create it in the right one, `secrets.sh set` again |

Rollback: revoke the key(s) in the dashboard, then `security delete-generic-password -a "$USER" -s nts.openai.story` (and `.image`). Delete or archive the projects ⚠️.
