# 01.2.4-T3 — Access tests (positive/negative) + key-leak/rotation procedure

| Story | Size | Area | Depends on | Blocks | Gate |
|---|---|---|---|---|---|
| 01.2.4 | XS (0.25) | Ops / QA (developer; owner for dashboard read-back) | 01.2.4-T2; 01.2.4-T1 verification for C3; 01.1.2-T2 (`lib.sh`, `secrets.sh`); 01.1.1-T1 (`uv`) | 01.3.1-T2 end-to-end check, 01.2.2-T6, gate 01-ready | 01-ready |

## Goal
Direct API calls prove each key reaches only its own model and nothing else. The image key returns a `quality: low` image with the echoed quality and `usage` recorded. The dashboard limits are read back. A secret-free access record is committed, and the key-leak/rotation procedure text is specified for the runbook.

## Inputs
- Keychain: `nts.openai.story`, `nts.openai.image` (T2, D3). Read only through lib.sh `secret <service>` inside `$(…)` (it prints only the value; missing → stderr message, exit 2).
- Facts: O3 (allow-list), O4 (Restricted, Model capabilities = Request, List models = Read), O6 (`quality` echoed, default `auto`; `usage` fields, may be absent; set `model` explicitly), O8 (relay price for `gpt-image-2` resolved ✅ **184 VND/image** flat, owner 2026-09-28, 02 CR-27 — CRV-0928-5; official-API `gpt-image-2.5-flare` reference prices, superseded by `gpt-image-2`, 01 DEC-11: text in $5/1M, image out $30/1M; luna $0.10 / $0.50 per 1M), M4/M5 (which endpoint each key serves), DECISIONS §4 (1024×1024 low ≈ $0.006 official-API flare floor reference; relay ≈ $0.0072/image).
- T1/T2 scratch values (org + project settings) for the access record.
- The usage tap (01.3.1-T2, D6) is **not required**: all calls go direct to the pinned `OPENAI_BASE_URL` (`worker-node/pins.env`, today the relay `https://api.aixingialaire.shop/v1`; 01 CR-15, DEC-9) so T3 does not depend on the tap existing.

## Steps

### A. Write `worker-node/bin/openai-access-check.sh` (tracked, secret-free, D9)

Interface:

```
worker-node/bin/openai-access-check.sh [--only story|image|all] [--no-image-gen] [--help]
  --only story     run C0s, C1, C2, C6, C7 (usable while verification is pending)
  --only image     run C0i, C3, C4
  --no-image-gen   skip C3 (the only paid image call)
exit: 0 all executed checks pass · 1 a check failed · 2 usage/environment error (missing Keychain item, no curl/uv)
```

Behaviour:
1. `set -euo pipefail`; never `set -x` (the script aborts with exit 2 if `$-` contains `x`). `. "$(dirname "$0")/lib.sh"`; `NTS_HOME=$(nts_home)`.
2. `OUT="$NTS_HOME/runs/access-check-$(date -u +%Y%m%d-%H%M%S)"`; `mkdir -p "$OUT"`; `umask 077`.
3. One request helper. The key goes to curl only as a header file from a process substitution. `printf` is a bash builtin, so the key never appears in any process argv or in history:
   ```bash
   api() { # api <service> <id> <method> <path> [<json-body-file>]
     local svc=$1 id=$2 method=$3 path=$4 body=${5:-} key code
     key=$(secret "$svc")                       # exits 2 via lib.sh if missing
     local args=(-sS --max-time 120 -o "$OUT/$id.body" -w '%{http_code}' -X "$method"
                 -H 'Content-Type: application/json')
     [[ -n $body ]] && args+=(--data-binary "@$body")
     code=$(curl "${args[@]}" -H @<(printf 'Authorization: Bearer %s\n' "$key") \
            "$OPENAI_BASE_URL$path") || code=000   # load_pins first (01 CR-15)
     unset key
     printf '%s' "$code" > "$OUT/$id.status"
   }
   ```
   Request bodies are written by the script to `$OUT/<id>.req.json` (fixed strings, no secret) and passed with `--data-binary @file`.
4. Checks (bodies exactly as below; `model` always explicit, O6):

   | Id | Key | Call | Body | Pass condition |
   |---|---|---|---|---|
   | C0s / C0i | story / image | `GET /v1/models` | — | status 200 |
   | C1 | story | `POST /v1/chat/completions` | `{"model":"gpt-6-luna","messages":[{"role":"user","content":"Reply with OK."}],"max_completion_tokens":16,"reasoning_effort":"<OPENAI_EFFORT_CHAT>"}` (01 CR-16) | 200 and `usage.prompt_tokens`, `usage.completion_tokens` present |
   | C2 | story | `POST /v1/images/generations` | `{"model":"gpt-image-2","prompt":"A foggy empty village road at dusk, illustration","n":1,"size":"1024x1024","quality":"low"}` (flare superseded, 01 DEC-11) | status 4xx (denied). Status and `error.code`/`error.type` recorded |
   | C3 | image | `POST /v1/responses` when `OPENAI_IMAGE_API=responses` (else `/v1/images/generations`) | `{"model":"<OPENAI_IMAGE_HOST_MODEL>","input":"A foggy empty village road at dusk, illustration","reasoning":{"effort":"<OPENAI_EFFORT_IMAGE_HOST>"},"tools":[{"type":"image_generation","model":"gpt-image-2","size":"1024x1024","quality":"low"}],"tool_choice":{"type":"image_generation"}}` — one paid call, model from the template (`gpt-image-2`); no flare attempt (superseded, 01 DEC-11) | 200; a completed `image_generation_call` with `result` base64; `size`/`quality` echoed (advisory on the relay — `auto` forced, codex#28723); `usage` recorded or `"n/a:absent"` |
   | C4 | image | `POST /v1/chat/completions` | C1 body | status 4xx (denied). Recorded |
   | C6 | story | `GET /v1/files` | — | status 4xx (key is Restricted, Files = None). Recorded |
   | C7 | story | `POST /v1/chat/completions` | C1 body with `"model":"gpt-6-astra"` (not `gpt-6-sol`, which is temporarily allowed for 02.1.3-T1, 02 CR-17) | status 4xx (not in allow-list). Recorded |

   A 5xx or `000` (network) on any check → retry that check once after 10 s. Still failing → mark `pass: false, reason: "upstream"` (exit 1, not a security failure). **No retry on C3 when it returned 200** (one paid image only).
5. Post-processing with a stdlib Python block (`uv run --no-project --python 3.12 python - "$OUT" <<'PY' … PY`, D9) for each `<id>.body`:
   - Parse JSON. Keep `status`, `error.code`, `error.type`, `error.message` truncated to 200 chars (messages contain model names, not secrets ⚠️ confirm), `usage` (verbatim field names), and for C3 also `quality`, `size`, `output_format` if present (O6; in responses mode these live on the `image_generation_call` output item — advisory `auto` on the relay, codex#28723), plus `api` (`responses`|`images`, the `OPENAI_IMAGE_API` pin) and `reasoning_effort` (01 DEC-11).
   - C3: decode `data[0].b64_json` (responses mode: the `image_generation_call.result` of the translated reply) → `$OUT/C3.png`. Then **rewrite `$OUT/C3.body` without `data`** so no multi-MB base64 is kept next to the record. Estimate cost:
    `cost_usd_est = input_tokens_details.text_tokens × 5e-6 + input_tokens_details.image_tokens × 8e-6 + output_tokens × 30e-6` (O8 official-API `gpt-image-2.5-flare` reference rates, superseded — the relay price is flat **184 VND/image** ≈ $0.0072, owner 2026-09-28, 02 CR-27, CRV-0928-5, so on the relay `cost_usd_est = 184 / 25641 ≈ 0.0072` when `usage` carries no split; and responses-mode `usage` holds host-model tokens only → `n/a` fields, 01 DEC-11). If `usage` is absent → `"n/a:usage_absent"`.
   - C1: `cost_usd_est = prompt_tokens × 0.10e-6 + completion_tokens × 0.50e-6` (O8).
   - Write/merge `trial/baselines/openai-access-mac-$(date -u +%Y%m%d).json` (schema in `plan.md` §3):
     - `checks[]` is replaced on each run;
     - `org{}` and `projects{}` are created with every value `"unset"` if the file is new, and kept as they are if the operator already filled them.
   - Print one line per check to stdout, e.g. `C2 story images -> 403 <error.code> PASS(denied)`. **Never print the body of C1** (model output is harmless, but the policy is "no content in logs", D6 spirit).
6. The script never writes to `trial/runs/` (it is not a trial run) and never touches `$NTS_HOME/current_run`.

### B. Run it
1. `worker-node/bin/openai-access-check.sh --only story` → expect exit 0.
2. When T1 verification is `verified` (or unknown): `worker-node/bin/openai-access-check.sh --only image` → expect exit 0. Cost ≈ one image (requested 1024×1024 `low`; the relay ignores size/quality — advisory, codex#28723) ≈ **184 VND ≈ $0.0072** on the relay (owner 2026-09-28, 02 CR-27, CRV-0928-5; the ~$0.006 figure in DECISIONS §4 is the official-API `gpt-image-2.5-flare` floor reference, superseded 01 DEC-11) plus < $0.0001 of chat.
3. Open `$OUT/C3.png` once to confirm it is an image (Quick Look). It is not tracked.

### D. Runbook text (request to the owner of `worker-node/README.md`, 01.1.1-T3; BaseToolingPlan has agreed to copy it verbatim)

> #### OpenAI key leak / rotation (all secrets)
>
> **When:** a key value appeared anywhere other than the Keychain and `$NTS_HOME/src/mpt/config.toml` (repo, commit, push, chat, e-mail, screenshot, terminal command line, log, `run.json`, tap log), or gitleaks flagged it, or spend appears you cannot explain, or M0 closes.
>
> **Full-leak trigger (SEC-13):** `$NTS_HOME/src/mpt/config.toml`, or any part of `$NTS_HOME`, was copied, synced (iCloud, Dropbox, backup), attached, or shown on screen. `config.toml` holds **all four** secrets (`nts.openai.story`, `nts.openai.image`, `nts.mpt.api_key`, `nts.proxy.api_key`), and `$NTS_HOME` also reveals the VieNeu key through the process environment. So this trigger rotates **every** Keychain item, not only the OpenAI keys: steps 1–8 below for both OpenAI keys, then `worker-node/bin/secrets.sh rotate-local` (with all services stopped) for `nts.mpt.api_key`, `nts.vieneu.api_key` and `nts.proxy.api_key`.
>
> **Leak (do in this order; revoke first, investigate later):**
> 1. Owner: platform.openai.com → project (`nts-trial-story` or `nts-trial-image`) → API keys → **Revoke** the key named in `trial/baselines/openai-access-mac-*.json` (`nts-trial-<story|image>-mac-<YYYYMM>`). If unsure which key leaked, revoke both.
> 2. Stop MPT, the proxy, VieNeu and the usage tap (Ctrl-C in each terminal). Then `rm -f "$NTS_HOME/src/mpt/config.toml"`, so no rendered copy holds the leaked value. Calls already in flight fail with 401. MPT skips image keywords silently (M4), so do not trust a render that ran during rotation.
> 3. Owner: check the project and org usage for unexpected spend (daily buckets). Record the amount and time in `trial/runs/<run_id>/notes.md` or `worker-node/CARRY-OVER.md` (no key values).
> 4. If the value reached git: do not push. If already pushed, treat the key as public: revoking (step 1) is the fix. History rewriting is optional and never replaces revocation. Run `gitleaks detect` on the repo and remove the file from the index.
> 5. Create the replacement key: same project, name `nts-trial-<story|image>-mac-<YYYYMM>-r<n>` (n = 2, 3, …), Restricted, Model capabilities = Request, List models = Read.
> 6. On the Mac, at the terminal: `worker-node/bin/secrets.sh set nts.openai.<story|image>`, paste the key into the prompt only, then `pbcopy </dev/null`.
> 7. `worker-node/bin/openai-access-check.sh` → exit 0. Update `key_name` in the access record and commit it (secret-free).
> 8. Restart the tap and MPT with the normal start scripts (the config is re-rendered from the Keychain at start, D5).
>
> **Planned rotation (M0 close):** revoke both keys (step 1), then `security delete-generic-password -a "$USER" -s nts.openai.story` and `… -s nts.openai.image`, then `rm -f "$NTS_HOME/src/mpt/config.toml" "$NTS_HOME/mpt-config.last.redacted.toml"`. MPT can no longer start on this Mac (the renderer fails on the missing variable), which is intended. New keys for later work follow T2 with a new `<YYYYMM>`.
>
> **Detection (mandatory during the trial):** the org spend alert and one spend alert per project at 50 % of its hard limit (org $15, story $2.5, image $12.5; T1) stay on, and the owner checks each project's usage page once per calendar day (plan §7). An alert e-mail or an unexplained daily delta counts as a trigger for the **Leak** procedure.
>
> **Never:** paste a key into chat or a ticket, pass it as a command argument, `echo` it, run scripts with `bash -x`, or create an Admin key for the trial.

## Failure handling
| Result | Meaning | Action |
|---|---|---|
| C1 ≠ 200 with 401 | wrong/revoked key in `nts.openai.story` | Re-run `secrets.sh set nts.openai.story` (T2 step 6) |
| C1 ≠ 200 with 4xx model error | allow-list missing `gpt-6-luna` or wrong name | Fix Model Usage (T2 step 2) |
| C1 200 but empty content / `finish_reason: length` | 16 tokens spent on reasoning ⚠️ | Acceptable: the check needs 200 + `usage`, not text |
| C1 400 on `max_completion_tokens` | parameter not accepted ⚠️ | Use `max_tokens` in the body and note it (MPT sends neither, M5) |
| C2/C4/C7 → 200 | **allow-list not enforced** → a key can spend on the other budget | Stop. Revoke the key used, fix Model Usage, re-run. Do not proceed to 01.3.1-T2 until the check passes |
| C6 → 200 | key has permission "All" | Revoke, recreate as Restricted (T2), re-run |
| C3 403/4xx mentioning verification ⚠️ | O5 applies and is not done | Wait for T1 verification. Keep T3 open with `--only story` done |
| C3 429 `rate_limit_exceeded` ⚠️ / `*_spend_limit_exceeded` / `credit_balance_exhausted` | tier, limit or balance | Rate limit: wait 60 s and retry once manually. Spend or balance: re-check T1/T2 settings (limit set to 0? balance?) |
| C3 200 but `quality` ≠ `low` | API ignored/mapped the value | Record it. Raise with CR-3 (plan 03) |
| C3 200 without `usage` | O6 caveat | Record `"n/a:absent"`. Tell 01.3.1-T2/T3 that the tap must estimate from size/quality instead |
| gitleaks or `grep Bearer` hit | secret in a tracked file | Delete the file content, run the §D leak procedure (treat as leaked), fix the script |

Stop condition: all of C0–C7 pass → done. Do not run extra paid image calls to "double-check".
