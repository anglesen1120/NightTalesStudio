## Goal
A stdlib-only reverse proxy on `127.0.0.1:8002` forwards MPT's OpenAI calls to the pinned upstream `OPENAI_BASE_URL` (`worker-node/pins.env`, today `https://api.aixingialaire.shop/v1`; 01 CR-15, DEC-9) — byte-identical apart from the DEC-11 responses-translation and effort-injection rules below — and appends exactly one D6 JSON line per call to `trial/runs/<run_id>/openai_usage.jsonl`, without ever storing a header, key, prompt, message content or image bytes (F02, D6).

## Inputs
- ✅ D6 (fields, path, `run_id` rule, `TAP_IMAGE_QUALITY` off by default), D4 (port 8002, `127.0.0.1`), D9 (bash conventions, `lib.sh`: `nts_home`, `require_port_free`, `log`, `die`; Python stdlib via `uv run --no-project --python 3.12`), D1 (`$NTS_HOME`).
- ✅ M4: image body `{model, prompt, n: 1, size}`; MPT timeout (connect 30, read 300) s; MPT retries 429/500/502/503/504 3×; read timeouts not retried. ✅ M5: chat is non-streaming, SDK. ✅ M1: `openai_base_url`, `openai_image_base_url` in `[app]`.
- ✅ O6: image response `quality`, `size`, `usage` (`input_tokens`, `input_tokens_details{text_tokens,image_tokens}`, `output_tokens`, `total_tokens`, optional `output_tokens_details`), `usage` may be absent; error body `error.code` e.g. `moderation_blocked`. ✅ O1: hard-limit 429s carry an `error.code`.
- CR-3 (quality decision, 03) — injection stays off until decided. CR-4 — tap not carried to the worker.
- Keychain: none. The tap reads no secret; the stub test uses a fake key.
- 01.1.2-T1 `.gitignore` contains `trial/runs/no-run/` (requested from BaseToolingPlan).

## Steps
1. **`trial/tools/usage_tap.py`** (stdlib only, Python 3.12, one file, `--help`):
   - Config from env (read once at start; invalid → exit 2 with message, no value echoed for anything named `*KEY*`):

     | Var | Default | Rule |
     |---|---|---|
     | `TAP_LISTEN_HOST` | `127.0.0.1` | only `127.0.0.1` accepted (D4) |
     | `TAP_PORT` | `8002` | int |
     | `TAP_UPSTREAM` | origin of `OPENAI_BASE_URL` from `load_pins` (`${OPENAI_BASE_URL%/v1}`, today `https://api.aixingialaire.shop`; 01 CR-15) | exactly this value, or `http://127.0.0.1:<port>` (stub tests only); non-default → refused at startup unless `TAP_RUNS_DIR` resolves outside `<repo>/trial/runs` (NTS01-SEC-04) |
     | `TAP_UPSTREAM_TIMEOUT_S` | `610` | int ≥ 300 (✅ M4 read 300 s; ⚠️ OpenAI SDK default read timeout at the pinned `openai` version — MUST be ≤ this value, check in T4); values < 300 accepted only when `TAP_UPSTREAM` is the `127.0.0.1` stub (timeout test) |
     | `TAP_CONNECT_TIMEOUT_S` | `30` | int |
     | `TAP_MAX_BODY_BYTES` | `1048576` | request cap |
     | `TAP_MAX_RESPONSE_BYTES` | `67108864` | response cap (b64 1536×1024 PNG fits [INFERENCE]) |
     | `TAP_IMAGE_QUALITY` | unset | if set: one of `low\|medium\|high\|auto` (O6), else exit 2 |
     | `OPENAI_IMAGE_API` | `responses` | `images\|responses`; `responses` translates `/v1/images/generations` calls into `POST /v1/responses` (01 DEC-11, 01 CR-16) |
     | `OPENAI_IMAGE_HOST_MODEL` | `gpt-6-luna` | host model of the translated call |
     | `OPENAI_EFFORT_IMAGE_HOST` | `low` | `none\|minimal\|low\|medium\|high\|xhigh`; `reasoning.effort` of the translated call |
     | `OPENAI_EFFORT_CHAT` | `medium` (owner 2026-09-25: MPT `generate_script` writes the trial story via chat; `low` writes poorly) | same enum; injected into chat/responses bodies that lack an effort field |
     | `NTS_HOME` | via `nts_home` rule `${NTS_HOME:-$HOME/.nts}` | |
     | `TAP_RUNS_DIR` | `<repo>/trial/runs` (resolved from the script path) | tests point it at a temp dir; MUST be outside `<repo>/trial/runs` whenever `TAP_UPSTREAM` is non-default (NTS01-SEC-04) |
     | `TAP_MAX_CONCURRENCY` | `4` | int; bounds simultaneously handled requests (NTS01-SEC-10) |
   - Server: `http.server.ThreadingHTTPServer((host, port), Handler)`, `daemon_threads = True`, `protocol_version = "HTTP/1.1"`. Override `log_message` to write one line per request to stderr: `ts method endpoint status latency_ms` (no query string, no headers).
   - Startup guard (NTS01-SEC-04): if `TAP_UPSTREAM` ≠ the origin of the pinned `OPENAI_BASE_URL` (01 CR-15), resolve both `TAP_RUNS_DIR` and `<repo>/trial/runs` with `os.path.realpath`; if `TAP_RUNS_DIR` equals or is nested under the real `trial/runs`, exit 2 `tap_stub_upstream_forbidden` **before** opening the listening socket. This stops a tap started in stub/test mode — which forwards the real `Authorization` header in cleartext to an unverified local port — from ever writing into a real run's directory.
   - Startup, once bound (NTS01-SEC-04): `usage_tap.py` itself writes `$NTS_HOME/tap.json` (tmp file + `os.replace`, so `start-tap.sh` no longer writes it): `{"started_at","host","port","upstream","image_quality_injection","image_api","image_host_model","effort_image_host","effort_chat","timeout_s","pid"}` with `pid = os.getpid()`. A caller (e.g. `start_run.sh`, `run_manifest.py`) can then compare `tap.json.pid` against the actual `LISTEN` pid on 8002 to confirm the tap, not some other process, owns the port.
   - Methods: `do_GET`, `do_POST` forward; `do_PUT/DELETE/PATCH/HEAD/OPTIONS/CONNECT` → 405 `{"error":{"type":"tap_error","code":"tap_method_not_allowed","message":"…"}}`.
   - Path: must start with `/v1/` → else 404 `tap_path_not_allowed`. Upstream path = same path + query (the tap forwards the query unchanged; `endpoint` in JSONL = path without `/v1` and without query, e.g. `/images/generations`).
   - Request body: require `Content-Length` for POST (chunked or missing → 411 `tap_length_required`); > cap → 413 `tap_body_too_large` (body not read). Read exactly `Content-Length` bytes.
   - Headers forwarded: all incoming headers **except** hop-by-hop (`Connection`, `Keep-Alive`, `Proxy-Authenticate`, `Proxy-Authorization`, `TE`, `Trailer`, `Transfer-Encoding`, `Upgrade`, plus any named in `Connection`), `Host` (set to upstream host), `Content-Length` (recomputed), `Accept-Encoding` (set to `identity` so the tap can parse JSON). `Authorization` passed through **unchanged and unread** (never assigned to a variable other than the header list).
   - Optional injection (only when `TAP_IMAGE_QUALITY` set and endpoint is `/images/generations` and `Content-Type` is JSON): parse body, set `quality` only if absent, re-serialise; record in JSONL `request.quality` the injected value. Off → body bytes forwarded byte-identical. In `responses` mode the value is placed into the `image_generation` tool object instead (advisory on today's relay — it forces `auto`, codex#28723).
   - Responses translation (01 DEC-11, CR-16; only when `OPENAI_IMAGE_API=responses`, endpoint `/images/generations`, JSON body): `n` absent or `1` → upstream `POST /v1/responses` `{"model": OPENAI_IMAGE_HOST_MODEL, "input": <prompt>, "reasoning": {"effort": OPENAI_EFFORT_IMAGE_HOST}, "tools": [{"type":"image_generation","model":<model>,"size":<size>,"quality":<quality if present>}], "tool_choice": {"type":"image_generation"}}`. Upstream 200 with a completed `output[]` item `type = image_generation_call` → return 200 `{"created":<unix>,"data":[{"b64_json":<item.result>}],"size":<item.size>,"quality":<item.quality>,"usage":<upstream usage>}`. 200 without a completed image item → 502 `tap_image_missing`; any non-200 → passed through unchanged. `n > 1` → 400 `tap_image_n_unsupported`; missing JSON `model`/`prompt` → 400 `tap_image_request_invalid` (neither forwarded). `endpoint` stays `/images/generations`; the JSONL line gets `via = "responses"` and `request.reasoning_effort = OPENAI_EFFORT_IMAGE_HOST`.
   - Effort injection (01 DEC-11, CR-16): on `/chat/completions` bodies lacking `reasoning_effort` set `"reasoning_effort": OPENAI_EFFORT_CHAT`; on `/responses` bodies lacking `reasoning.effort` set it; already-set values are never overwritten; record `request.reasoning_effort` in JSONL.
   - Upstream: `http.client.HTTPSConnection(host, 443, timeout=TAP_UPSTREAM_TIMEOUT_S, context=ssl.create_default_context())` (no flag to disable verification); `HTTPConnection` only for the `127.0.0.1` stub. One new connection per request (no pooling; simple, MPT calls are sequential, D11). Connect timeout applied via `socket.create_connection` timeout on `conn.connect()` then `conn.sock.settimeout(TAP_UPSTREAM_TIMEOUT_S)` ⚠️ implementation detail, verify in the stub test.
   - Response: read the full body (cap → 502 `tap_upstream_too_large`); send upstream status + reason, upstream headers minus hop-by-hop, `Content-Length` = actual length, body **unchanged**. `Connection: close` on the downstream response (simple; ⚠️ confirm MPT's clients accept it — standard HTTP/1.1).
   - Tap-side upstream errors: `ssl.SSLError` → 502 `tap_upstream_tls`; `TimeoutError`/`socket.timeout` → 502 `tap_upstream_timeout` [DECISION: 502, not 504 — MPT treats it like an upstream gateway error and retries images (M4); the JSONL line makes a possible double billing visible]; `OSError` on connect → 502 `tap_upstream_connect`. Rejected requests (404/405/411/413/503) are answered by the tap and also logged as one JSONL line with their `tap_*` code.
   - Concurrency (NTS01-SEC-10): a process-wide `threading.Semaphore(TAP_MAX_CONCURRENCY)`, acquired non-blocking at the top of `do_GET`/`do_POST`. Not acquired → respond 503 `tap_busy` immediately (no upstream call), log the JSONL line, return (no `finally`-release needed since it was never acquired). Acquired → released in a `finally` after the JSONL line is written, so a slow call cannot starve the semaphore past its own request.
   - `Handler.timeout = 30` (class attribute; bounds reads from the **downstream** client — MPT/curl — not the upstream call, so a stalled or malicious local caller cannot hold a handler thread open indefinitely).
   - Catch-all (NTS01-SEC-10): the whole of `do_GET`/`do_POST` runs inside one `try/except Exception`. Anything not covered above (`RemoteDisconnected`, `IncompleteRead`, `InvalidURL`, a malformed header value raising in `putheader`, …) is caught, answered 502 `tap_internal`, logged to stderr as `type(e).__name__` only (never the message, never a traceback), and still produces one JSONL line (`http_status 502`, `error_code "tap_internal"`, `usage null`, `model`/`request`/`response` best-effort from whatever was parsed before the failure, else `null`). Override `BaseHTTPRequestHandler.log_error` (delegate to `log_message`, never call `format_exc`) and `socketserver.BaseServer.handle_error` (log `type(e).__name__` only) so a protocol-level exception outside the handler methods (bad request line, client hang-up mid-body) never writes a traceback into the teed `tap-<ts>.log`.
   - **No retries in the tap** (MPT and the SDK retry, M4/M5).

     | Field | Value |
     |---|---|
     | `ts` | request start, UTC ISO-8601 with ms + `Z` |

     | `http_status` | int status returned to MPT (upstream or tap 4xx/5xx) |

   - Parsing: `json.loads` only if `Content-Type` contains `json` and body ≤ cap; failures → fields `null` (never log the body, never log the exception message — only `type(e).__name__` to stderr).

## Failure handling
- MPT gets connection refused → tap not running; start it (rollout step 3). Never point MPT at OpenAI directly during a measured run without `start_run.sh --no-tap` (plan.md §11 rollback).
- TLS verify fails against the upstream host (01 CR-15) → stop; check system trust store / uv Python CA bundle ⚠️ (python.org builds may need `certifi`-like setup; uv-managed CPython uses system certs [INFERENCE]). Never add a no-verify option; if unresolvable use the lean option (README §9).
- Upstream 5xx/429 bursts → passed through; MPT retries (M4). Counted in `image_http_429_count`.
- Tap crash mid-run → MPT call fails, MPT skips that image (M4) → run gets issue `tap-crash`; re-run the render.
- JSONL write error (disk full, permissions) → response already sent; stderr line `jsonl_write_failed <type>`; the collector will under-count → mark run issue; fix and re-run.
- Response larger than cap → 502; raise `TAP_MAX_RESPONSE_BYTES` via env and restart.
- All handler threads busy (`TAP_MAX_CONCURRENCY` exhausted) → callers see 503 `tap_busy` (NTS01-SEC-10); D11 means MPT calls are sequential in practice, so this should not occur in a real run — repeated 503s in a run's JSONL is itself an issue to investigate (`tap-busy`, collector adds it, 01.3.1-T3).
