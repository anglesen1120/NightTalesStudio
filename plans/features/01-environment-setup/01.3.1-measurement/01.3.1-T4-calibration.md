## Steps
1. Before the render: tap running (`lsof -nP -iTCP:8002 -sTCP:LISTEN` → 127.0.0.1), no active run (`test ! -e "$NTS_HOME/current_run"`), D11 conditions noted (no other heavy app).
2. 01.2.2-T6 executes the render; note `RUN_ID` and the MPT `task_id`. **Quiesced-machine gate (performance review, 2026-09-26; 01 CR-21):** before starting, record in `notes.md` that `memory_pressure` reports `normal` and that `sysctl -n vm.swapusage` “used” is within ~128 MB of the idle reading taken with every other heavy app closed. If either fails, the run is **structural calibration only** (markers, windows, token columns) and its RAM/wall columns MUST NOT be used as a 05.5.2 / 03.3.1 baseline — re-run on a quiesced machine.
3. Dry run: `uv run --no-project --python 3.12 trial/tools/finish_run.py "$RUN_ID" --task-id "$TASK_ID" --dry-run`. Record every `n/a` it prints.
4. Confirm the parser against the real log (open `$NTS_HOME/logs/mpt-api-<ts>.log`, grep by task id; do not copy story text anywhere tracked):
   - Header regex matches every record (count header lines = count of `" | "` records) — adjust `LEVEL` padding if needed.
   - All 7 markers found once ✅ (resolved 2026-09-26, Q9): under plan02 `## generating video script` **is** logged when `video_script` is supplied — only its LLM call is skipped — so no exception is needed (01 CR-18).
   - **End-of-audio (Q1):** find the last audio-related line before `## generating subtitle` (e.g. audio file written / duration line) ⚠️; if a stable line exists, set `AUDIO_END_RE` and add it to the fixture; else keep `None` and write "audio window includes post-TTS work until subtitle marker" in `trial/schema.md`.
   - `task <id> finished` wording and `task failed … stage:` wording (compare with source `app/services/task.py` at `MPT_COMMIT` for the failure line, since a success run will not show it).
   - `image material rendered:` wording and count; `openai image generation failed` count.
   - whisper `detected language` / `complete, elapsed` lines.
   - Terms `completed:` list parses with `ast.literal_eval`.
5. Confirm file locations (Q2): `ls "$NTS_HOME/src/mpt/storage/tasks/$TASK_ID/"` → names of final video, audio, script file; update `finish_run.py` defaults.
6. Confirm tap data (Q3, Q4, Q5): in `trial/runs/$RUN_ID/openai_usage.jsonl` — chat `usage.prompt_tokens_details.cached_tokens` present?; image `response.quality`/`size` echoed?; any 200 image line without `usage`?; any 429/5xx lines (then check next day whether they were billed). ✅ **Observed 2026-09-26:** `prompt_tokens_details` is absent entirely → issue `cached-tokens-field-absent` (Q3); `response.quality`/`size` **are** echoed, but the relay forces quality `auto` **per call** (`low:3|medium:2`, `image_quality = low`) and one echoed size differed from the request (`1370x1148` vs `1536x1024`) (Q4 drift — what resolves `auto` to `low`/`medium` was not traced); the image `usage` carries `input_tokens_details.cached_tokens`, **not** the O6 `text_tokens`/`image_tokens` split → cols 43/44 `n/a:usage-split-absent`; 0 non-200 lines, so Q5 stays ⚠️ (01 CR-19 → 03 CR-3).
7. Confirm SDK timeout: at `MPT_COMMIT`, find the OpenAI client construction for the LLM (`app/services/llm.py` ✅ `llm.py:618`, no explicit timeout) and the pinned `openai` package default timeout in the MPT venv (`uv run --project "$NTS_HOME/src/mpt" python -c "import openai; print(openai.DEFAULT_TIMEOUT, openai.DEFAULT_MAX_RETRIES)"` ✅ `Timeout(connect=5, read=600, write=600, pool=600)` / `2`, confirmed 2026-09-26, Q7) → must be ≤ `TAP_UPSTREAM_TIMEOUT_S` (610); else raise it in `start-tap.sh` default.
8. Confirm proxy log (Q8): CR-1 lines present with `ts` inside the audio window → `sources.tts = proxy-log`; else record fallback used.
9. Check stage coverage: `jq '.coverage' trial/runs/$RUN_ID/stages.json` → `gaps_seconds` = 0; Σ window seconds = `total_seconds` (± 1 s rounding); first marker ≥ `run.json.started_at`; end ≤ `finished_at`.
10. Check sampler coverage: T4's rule divides the `rss_raw` rows by `stages.json total_seconds` ≈ (≥ 95 %) ✅ **263 samples / 276 s = 95.3 %** (262 = 94.9 % with end-exclusive windows — borderline, record which counting was used); the sampler-span density is separate (666 / 700 s = 95.1 %). Every stage window **with a non-zero width** has ≥ 1 sample (under plan02 `stage:script` is 0.0 s wide — the script and terms markers share one logged second — so its `rss.csv` row is `samples = 0`/`NA`; auxiliary file only, the sheet's RAM columns stay numeric) (01 CR-21); `ram_peak_whisper_mb` within ± 25 % of the 01.2.3-T2 peak (else explain in `notes.md`: model load vs cached).
11. Fix regexes/defaults found in steps 4–8 in `finish_run.py` + fixtures; rerun unit tests (`uv run --no-project --python 3.12 -m unittest discover -s trial/tools/tests -v`) → green; rerun `--dry-run` → only allowed n/a (`pending-dashboard`, `story-source-plan02` if 0 chat calls, justified others).
12. Real finish: `… finish_run.py "$RUN_ID" --task-id "$TASK_ID"` → row appended with `run_status = calibration`.
13. Write `trial/runs/$RUN_ID/notes.md`: D11 conditions, Q1–Q10 outcomes (confirmed / changed / still ⚠️), any regex changes (with `MARKER_SET` bump), plausibility notes.
14. **Next day (UTC day after the run):** OpenAI dashboard → Usage/Cost for projects `nts-trial-story` + `nts-trial-image`, day = run's UTC day ⚠️ (dashboard labels and timezone to confirm, Q10). Enter the sum: `… finish_run.py "$RUN_ID" --dashboard-cost <usd> --dashboard-day <YYYY-MM-DD>`. Delta ≤ 5 % → done. Delta > 5 % → investigate in this order: calls outside the tap (`no-run` lines, other tools using the keys), billed non-200 calls (Q5), wrong price entry, reasoning tokens not in `completion_tokens`; record in `notes.md`.
15. Send the Q outcomes to the plan owners via the README change list: Q1/Q9 → 05; Q4 → 03 (CR-3); Q8 → 04 (CR-1). Done 2026-09-26: **01 CR-18 → 05, CR-19 → 03, CR-20 → 04** (01 CR-21 covers the local T6/T4 text changes).

## Failure handling
- Render failed → finish with `--status failed` (row is data), fix via 01.2.2, repeat T6 + T4 with a new run id; the failed row stays.
- Parser cannot be fixed within the XS budget (e.g. markers absent at INFO level) → raise `log_level` in the template via 01.2.2-T2 or escalate to TL; 01-ready blocked.
- Dashboard shows no per-project split or no daily cost → compare org total for the day; record the limitation (O7).
- Delta > 5 % unexplained → keep 01-ready (row complete) but block use of prices in 05.5.2/12 until resolved.
