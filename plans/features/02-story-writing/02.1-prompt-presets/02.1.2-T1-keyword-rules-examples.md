## Goal

`prompts/shared/keyword-rules.v1.md` fixes the image-keyword contract for every preset (1–2 per segment, English, 3–12 words, a visual scene, never a real person's likeness, total within the `ceil(D × 6)` cap), and ≥ 10 good + ≥ 10 bad examples per topic make the rule checkable by a human author and by 03.2.2's linter.

## Inputs

- README: **F09** (uncontrolled totals blow the cap), **F37** (English is closed), **P5** (K = 6 images/min, `ceil(D × 6)`), **D3** (1–2 keywords per segment, validated), **D4** (segments ≈ `ceil(D × K ÷ 1.5)`, so keywords ≈ the cap), **D5** (`shared/keyword-rules.v1.md`, placeholders `{{keyword_rules}}`), **CR-5** (03.2.2 owns `KeywordRules` in Domain `Stories/Keywords/`).
- `../../../02-story-writing.md` story 02.1.2 (1–2 English keyword phrases per paragraph, a visual scene, never a real person's likeness) and `../../03-video-generation.md` FR-03-3 (English, 3–12 words, no names) + 03.2.1 (the cap).
- `../../../02-story-writing.md` M2 (MPT's own terms prompt makes 1–3-word stock terms — the reason our keywords must be explicit).
- 02.1.1-T0's spec; the three preset tasks reference this file by placeholder.

## Design

### File: `prompts/shared/keyword-rules.v1.md` (front-matter `role: shared`, `id: keyword-rules`, `version: v1`)

**Rules (numbered; the validator and the linter cite these numbers):**

| # | Rule | Notes |
|---|---|---|
| R1 | 1–2 keywords **per segment** (hook, each paragraph, ending) — never 0, never 3+ | D3 validator rule |
| R2 | **English only**, regardless of story language | F37, 03 FR-03-3 |
| R3 | 3–12 words, space-separated; no punctuation except hyphens inside a word | 03 FR-03-3 |
| R4 | Describe a **visual scene** a stock-image search can match: subject + place + light/time, optionally a mood word | image prompts work best in English |
| R5 | **Never** a real person's name or likeness; no "photo of X", no "man who looks like Y" | story 02.1.2 |
| R6 | No gore / injury / body / sexual / child-in-danger imagery — the tone line applies to keywords too | D3 + tone rules |
| R7 | No on-screen text, logos, watermarks, brand names, or UI | image generators render text badly and brands are a rights risk |
| R8 | No abstract nouns alone ("fear", "memory", "karma"): pair with a visible carrier ("empty altar in a small shrine at dawn") | otherwise the image is unrelated |
| R9 | Total keyword count per story ≈ `ceil(D × 6)` (K = 6/min, P5); the tier's segment count (D4) is chosen so the total lands at the cap | F09; the checker flags totals above the cap |
| R10 | Keywords follow the segment order; the hook and ending each get one keyword | D3 (hook/ending have keywords) |
| R11 | Prefer one strong scene over two weak ones; use the second keyword only when the segment has two distinct visual moments | pacing of images |

**Handling:** `{{keyword_rules}}` injects this file into every preset (D5 order). 02.2.1-T1 implements R1/R3/R5/R6 as validator checks; 03.2.2 adds the `fact_sources`-title name check at render (CR-5); R9's total is a checker advisory that becomes blocking above the cap.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| A preset restates the keyword rules instead of using `{{keyword_rules}}` | the duplication is the bug: the preset keeps only a one-line pointer; the file is the single source (D5) |
| The model returns 0 keywords for a segment | validator R1 blocking; the preset's output section and this file both state "every segment has at least one" |
| Keyword count exceeds the cap | R9 advisory → blocking above the cap; the fix is the D4 segment count, never dropping scenes silently (F09) |
| A keyword is a person's name the model invented | R5 blocking in the validator; 03.2.2's `fact_sources`-title check catches a *real* name at render (CR-5) |
| 3–12 word rule conflicts with a genuinely better 2-word keyword | the rule wins (03 FR-03-3 is fixed); a 2-word phrase is padded into a scene, not whitelisted |
| Rollback | revert the file + manifest entry |
