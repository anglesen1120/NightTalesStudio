# 02.1.2-T1 — Keyword rules + ≥ 10 good/bad examples per topic

| Story | Size | Area | Depends on | Blocks | Phase / flag |
|---|---|---|---|---|---|

## Goal

`prompts/shared/keyword-rules.v1.md` fixes the image-keyword contract for every preset (1–2 per segment, English, 3–12 words, a visual scene, never a real person's likeness, no real place identifier, no instruction or rendered text, total within the `ceil(D × 6)` cap), and ≥ 10 good + ≥ 10 bad examples per topic make the rule checkable by a human author and by `KeywordRules` (02.2.1-T1, reused by 03.2.2).

## Inputs

- README: **F09** (uncontrolled totals blow the cap), **F37** (English is closed), **P5** (K = 6 images/min, `ceil(D × 6)`), **D3** (1–2 keywords per segment, validated), **D4** (segments ≈ `ceil(D × K ÷ 1.5)`, so keywords ≈ the cap), **D5** (`shared/keyword-rules.v1.md`, placeholders `{{keyword_rules}}`), **CR-5** (**02.2.1-T1** builds `KeywordRules` in Domain `Stories/Keywords/`; **03.2.2** reuses it and adds the `fact_sources`-title name check at render).
- `../../../02-story-writing.md` story 02.1.2 (1–2 English keyword phrases per paragraph, a visual scene, never a real person's likeness) and `../../03-video-generation.md` FR-03-3 (English, 3–12 words, no names) + 03.2.1 (the cap).
- `../../../02-story-writing.md` M2 (MPT's own terms prompt makes 1–3-word stock terms — the reason our keywords must be explicit).
- 02.1.1-T0's spec; the three preset tasks reference this file by placeholder.

## Design

### File: `prompts/shared/keyword-rules.v1.md` (front-matter `role: shared`, `id: keyword-rules`, `version: v1`)

**Rules (R1–R13; numbered — the validator and the linter cite these numbers):**

| # | Rule | Notes |
|---|---|---|
| R1 | **1–2 keywords per segment** (the hook, each paragraph, the ending) — never 0, never 3 or more | D3 validator rule; zero keywords for a segment is a blocking defect |
| R2 | **English only**, regardless of the story language | F37, 03 FR-03-3: the image stack is English |
| R3 | **3–12 words**, space-separated; a hyphen inside a word and an apostrophe are allowed; no other punctuation (no commas, no periods) and no digits | 03 FR-03-3 |
| R4 | Describe a **visual scene** a stock-image search can match: subject + place, plus light/time or one mood word where it helps | image prompts work best as scene descriptions in English |
| R5 | **Never** a real person's name or likeness; no "photo of X", no "man who looks like Y", no invented human name | story 02.1.2 |
| R6 | No gore, blood, injury, corpse or dead body, weapon, self-harm or suicide (hanging, rope, noose), nudity or sexual content; no child or minor as the subject of a keyword — a child appears only through an object they left ("child's drawing"). The tone line applies to keywords too | D3 tone rules; the term list is `GoreTerms` in `KeywordRules` (built by 02.2.1-T1, reused by 03.2.2, CR-5) |
| R7 | No on-screen text, logos, watermarks, brand names, packaging or UI, and no object whose point is its text or face: signs, posters, newspapers, calendars, documents, files, labels, banknotes, screens | image generators render text badly and brands are a rights risk |
| R8 | No abstract noun alone ("fear", "memory", "karma") — pair it with a visible carrier ("empty altar in a small shrine at dawn") | otherwise the returned image is unrelated to the segment |
| R9 | Total keyword count per story ≈ `ceil(D × 6)` (K = 6 keywords/min, P5) and never above the cap; the tier's segment count (D4) is chosen so the total lands at the cap | F09. The count is an advisory in the 02.2.1-T1 validator and a total-cap advisory in `StoryQualityChecker` (02.3.4-T1) — never blocking |
| R10 | Keywords follow the segment order; the hook and the ending each get one keyword | D3 (the hook and the ending have keywords) |
| R11 | Prefer one strong scene over two weak ones; use the second keyword only when the segment holds two distinct visual moments | image pacing |
| R12 | **No real place identifier**: no address, house or plate number, street, village, school, shop or company name — describe the kind of place ("narrow alley in an old town at night") | privacy and defamation risk (03 FR-03-3) |
| R13 | A keyword is a **noun phrase describing what is in the frame**; never an instruction or words addressed to a model or about the image itself (ignore, instead, draw, render, generate, style, prompt, caption, text) | one bad example per topic in the tables below |

Rule count is **R1–R13** (**02 T76**–**T81**). `StoryDraftValidator` (02.2.1-T1) and `KeywordRules` (Domain `Stories/Keywords/`, built by 02.2.1-T1 and reused by 03.2.2, CR-5) cite these numbers.

**Handling — what is machine-checked (`KeywordRules`, built by 02.2.1-T1, reused by 03.2.2, CR-5):**

| Rule | Enforced by | Kind |
|---|---|---|
| R1 | 02.2.1-T1 `StoryDraftValidator` (1–2 per segment) | exact |
| R2 | `KeywordRules` alphabet `[A-Za-z' -]` after NFC | exact (the alphabet also rejects URLs, digits and punctuation) |
| R3 | `KeywordRules` word count 3–12 after whitespace split | exact |
| R4 | model only (no machine check) | — |
| R5 | partial heuristic: mid-phrase capitalisation + honorific list, **plus** a case-insensitive whole-token match against the run's bible character names and `fact_sources` person names | partial |
| R6 | `GoreTerms`, extended to cover the R6 categories (**02 T78**) | exact over its list |
| R7 | lexical list `logo, brand, trademark, sign, poster, headline, label, caption, reading, saying, written` (**02 T79**) | partial |
| R8 | model only | — |
| R9 | advisory in the 02.2.1-T1 validator; total-cap advisory in `StoryQualityChecker` (02.3.4-T1) | advisory |
| R10/R11 | model only | — |
| R12 | digit/street-word pattern (`street, road, lane, alley, ward, district`) + `fact_sources` place names (**02 T80**) | partial |
| R13 | meta-token list (`ignore, instead, draw, render, generate, style, prompt, caption, text`) (**02 T81**) | partial |

`{{keyword_rules}}` injects this file into every preset (D5 order); the file carries only model-facing text (**02 T83**).

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| A preset restates the keyword rules instead of using `{{keyword_rules}}` | the duplication is the bug: the preset keeps only a one-line pointer; the file is the single source (D5) |
| The model returns 0 keywords for a segment | validator R1 blocking; the preset's output section and this file both state "every segment has at least one" |
| Keyword count exceeds the cap | R9 advisory → blocking above the cap; the fix is the D4 segment count, never dropping scenes silently (F09) |
| A keyword is a person's name the model invented | R5 blocking in the validator; 03.2.2's `fact_sources`-title check catches a *real* name at render (CR-5) |
| 3–12 word rule conflicts with a genuinely better 2-word keyword | the rule wins (03 FR-03-3 is fixed); a 2-word phrase is padded into a scene, not whitelisted |
| A keyword carries a comma, a period or a digit | R3 blocking (**02 T76**); the keyword is rewritten, the alphabet is never widened (a comma also risks MPT splitting a term into paid fragment images, 03 F04) |
| A keyword names a real place ("12 tran phu street") | R12 blocking (**02 T80**); describe the kind of place instead |
| A keyword is an instruction to the model ("ignore the style and draw …") | R13 blocking (**02 T81**); it is a noun phrase or it fails |
| Rollback | revert the file + manifest entry |
