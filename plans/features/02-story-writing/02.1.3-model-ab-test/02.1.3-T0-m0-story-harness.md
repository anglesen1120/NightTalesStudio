## Goal

One command produces a schema-valid `story.v1` story from a real preset, through the 01 usage tap, with the key, tokens, latency and cost recorded — so the A/B test measures **our** presets and **our** schema instead of MPT's output format (F01).

## Design

### Files

- `trial/tools/story_harness.py` — the harness. Stdlib only: `argparse, json, os, re, ssl, socket, subprocess, sys, time, unicodedata, urllib.request, urllib.error, hashlib, statistics`.
- `trial/tools/story_validator.py` — throwaway validator (module + `__main__`). Deleted when 02.2.1-T1's `StoryDraftValidator` exists; it must not be imported by product code.
- `trial/tools/LENGTH.v1.json` — the D4 table transcribed (`{ "<tier>": { "vi": {min_tokens,max_tokens,min_segments,max_segments,writer_max_output}, "en": {…} } }`), so the numbers are data, not literals (`writer_max_output` = 2,500 for `short` — 02 T66). ⚠️ 02.1.1-T0 owns the authoritative length table; T0 diffs against it at T1 start and fails on mismatch.

### Fixtures authored here (T34: moved from 02.1.3-T1)

- `prompts/fixtures/briefs.vi.json` / `briefs.en.json` — 9 entries each, 3 per topic, **global** ids `b1..b9` (`b1–b3` ghost, `b4–b6` spiritual, `b7–b9` true crime), each `{id, topic, title, brief (2 sentences premise + 1 line atmosphere), tier:"standard", language, synthetic:true}`. The same nine ideas written natively in both languages (V1 — the vi set must read as spoken Vietnamese, not translated English). They live in T0 so preset acceptance (02.1.1-T1..T3) can run before the A/B harness batch exists. `b3` is the evening-shift teacher who vanished — **no minor is the subject of the harm** (QA-02D-16/D-B3); the ghost topic and `synthetic:true` are unchanged.
- `prompts/fixtures/fact-sheet.true_crime.v1.json` — a **synthetic** fact sheet for the three true-crime briefs (`{ "facts": [ { "id": "f1", "brief_id": "b7", "statement": "…", "sources": ["s1"] } ], "sources": [ { "alias": "s1", "title": "…" } ] }`), so a preset acceptance run can exercise the D6 `facts` path without 02.5.x. **Every fact carries a `brief_id`** so a cell only ever sees its own case (T92, QA-02D-4). No real person, incident, place or URL anywhere in it.
- The harness sends `facts: []` for ghost/spiritual cells and **only the facts whose `brief_id` is the cell's brief** for true-crime cells (the D6 object shape is unchanged); the count of fact ids/aliases in the fixture is the authority the 02.1.1-T3 acceptance text mirrors (T92). ⚠️ T25 still excludes `factual_care` from the D15 comparison in M0; the fixture makes the dimension *scorable* for preset acceptance, not decisive for the model choice (plan §10).

### CLI

```
uv run --no-project --python 3.12 trial/tools/story_harness.py --help
  --preset ghost|spiritual|true_crime        (required for a single run)
  --brief  "premise text"  |  --brief-id b1 | --brief-ids b1,b4,b7 --briefs-file prompts/fixtures/briefs.vi.json
  --lang   vi|en                             (optional filter only: a cell's language comes from its
                                              brief's own `language` field, never this flag — plan §3.1)
  --model  gpt-6-luna|gpt-6-sol              (default gpt-6-luna)
  --tier   short|standard|long               (default short)
  --out    trial/stories                     (default)
  --run-id <id>                              (default derived, §3.1; with > 1 cell → exit 2)
  --dry-run                                  assemble + write request.json, make no call
  --matrix                                   all presets × briefs × models from --briefs-file(s)
  --only-missing                             (default for --matrix) skip run dirs with a parseable metrics.json
  --retry-failed                             with --only-missing, rerun cells whose metrics.json is not outcome=ok
  --force                                    overwrite an existing run dir
  --max-usd  5.0                             stop before the next call if exceeded
  --sleep-ms 200                             pause between calls
  --timeout  240                             per-attempt socket timeout, seconds (T91; D7's product value is 90)
  --key-service nts.openai.story
  --tap-base-url http://127.0.0.1:8002/v1
  --facts <json>                             with --validate-only: the fact sheet whose ids the story may cite
  --validate-only <story.json>               run the validator and exit; without --facts it uses the fact ids of
                                             the --brief-id brief (true-crime stories validate without --facts)
```

Exit codes (01 D9): `0` ok · `1` a check failed (validator issues on `--validate-only`, budget exceeded) · `2` usage or environment error (missing key, tap down, missing preset/schema, unknown placeholder, bad `--model`, `--run-id` with more than one cell, an id failing the safe-component rule, a prompt file whose sha256 differs from `prompts/manifest.json`).

`substitute` accepts **only** `language_name, tier_minutes, token_range, segment_range, keyword_rules, ear_rules, overused_phrases, structure_vocab`; any other `{{name}}` is exit 2 — the same rule 02.2.3-T1 enforces at start-up, so a preset that passes here passes there.

### Prompt order (D5 + O9) and the data object (D6)

`system = writer.v1.md` (static, first) → `preset` → shared rules (`ear-rules`, `overused`, `keyword-rules`; `structure-vocab` is substituted into the enabled-list, not appended in full) — the three together are the cacheable head (≥ 1,024 tokens; `writer.v1.md` alone need not reach it, 02 T67). The user message is **exactly one** JSON object, `json.dumps(..., ensure_ascii=False, separators=(",", ":"))`:

```json
{"task":"write_story","brief":"…","length":{"tier":"standard","tokens":[1300,2080],"segments":[20,32],"units_per_segment":65},
 "bible":null,"facts":[],"avoid_plots":[],"structure_plan":null}
```

`bible`, `facts` and `structure_plan` are present and `null`/`[]` (schema shape stability, D6); no M0 cell supplies facts (02.5.x is M1). `length` carries **`units_per_segment`** (02 T97) = `round(min_tokens ÷ min_segments)` for the cell's tier and language — vi `standard` 1,300 ÷ 20 → 65, en `standard` 1,000 ÷ 20 → 50 — a **control key** the model follows; it is computed from `LENGTH.v1.json` and travels in the object, so no new placeholder joins the closed D5 list. Untrusted text is **only** ever inside this object — never substituted into a template.

### Request body (the D7 shape, applied)

The D7 field set, with the values the harness supplies (`input` = `[system, user]`, each `content` = `[{ "type": "input_text", "text": … }]`; the field *semantics* are D7):

| Field | Value |
|---|---|
| `model` | `--model` |
| `text.format` | name `story`, schema = `prompts/schemas/story.v1.json` verbatim, `strict: true` |
| `reasoning.effort` | `medium` (D7 `Writer` default, owner 2026-09-25; measured here) |
| `max_output_tokens` | `LENGTH.v1.json[tier].writer_max_output` — 6,000 for the T1 matrix's `standard` (2,500 `short` — 02 T66, 10,000 `long`); O4: includes reasoning |
| `store` | `false` (O5's default is `true`) |
| `safety_identifier` | `sha256("nts-m0-harness")` hex — one platform identity, no user id |
| `prompt_cache_key` | `write_story:<preset>` |
| header `X-Client-Request-Id` | `<run_id>:writer:<attempt>` |
| header `Authorization` | `Bearer <key from Keychain>`, in memory only |
| timeout | `--timeout`, default 240 s (T91); D7's product writer value is 90 s |

### Outcome mapping (D7)

| Condition | `outcome` | Retried? |
|---|---|---|
| JSON that passes `json.loads` **and** the strict schema (provider-enforced) | `ok` | — |
| `status` is `incomplete` with `incomplete_details.reason = max_output_tokens` | `invalid_output` | no (a bigger cap is a config change, not a retry) |
| a content part with `type: "refusal"`, or `incomplete_details.reason = "content_filter"` | `moderated` | no |
| HTTP 429 `*_spend_limit_exceeded` / `credit_balance_exhausted` | `funds_exhausted` | no |
| HTTP 429 (not a funds error) | `provider_error` | once, honouring `Retry-After`, then recorded |
| 3xx (redirect) | `provider_error` | no — redirects are not followed (SEC-02D-1) |
| other 4xx | `provider_error` | no |
| 5xx | `provider_unavailable` | once, honouring `Retry-After`, then recorded |
| transport timeout / status 0 | `provider_unavailable` | **no** — the upstream call is still in flight and is billed; it is recorded on the first occurrence (T91) |

`response.json` is written **whatever** the outcome (except a connection error with no body — then `response.json` holds `{"error":"transport","detail":"…"}`), so a failed cell is still evidence. `metrics.json.usage` copies every usage field the response carried — `input_tokens`, `cached_tokens` (`input_tokens_details.cached_tokens`), `cache_write_tokens`, `output_tokens` and `reasoning_tokens` (`output_tokens_details.reasoning_tokens`) — so the harness reports the cacheable head (02 T67) and the reasoning share of the `short` cap (02 T66).

### Harness robustness (phase-D gate findings, 02 T91–T96)

- **Attempts are all charged (T91).** `metrics.json` gains `attempts: [ { attempt, http_status, outcome, incomplete_reason, usage|null, cost_usd|null, cost_bound_usd } ]` and `timeout_s`; each attempt's cost (usage when the response carried it, else the conservative bound) is added to the `--max-usd` accumulator, so a retried 5xx does not vanish from `spent` (PERF-02D-1). A timed-out first attempt is charged from the bound.
- **`--timeout` (T91)** replaces the constant: default 240 s; the D7 product writer timeout stays 90 s.
- **Cell language comes from the brief (final review FR-1).** `_build_cells` takes each cell's language from its brief's `language` field; `--lang` (omitted by default) only filters a batch — a brief of the other language is skipped with a note, and exit 2 when no cell remains. Two `--briefs-file` inputs that repeat the ids yield distinct `vi-…`/`en-…` cells, each assembled from its own language's preset and shared blocks; `--brief-id`/`--brief-ids` resolve per file and language, never last-file-wins. Offline test: two briefs files + `--matrix --dry-run` → 36 distinct dirs, each `request.json` carrying that brief's `language`/`language_name`.
- **Safe run ids (T91/D-RUNID).** `--run-id` is rejected with exit 2 when the invocation produces more than one cell; every run id and brief id must match `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$` (`.`/`..` rejected) and the resolved run dir must stay under `--out` (SEC-02D-3).
- **No redirects (SEC-02D-1).** The opener adds a no-redirect handler (`redirect_request → None`) and the `Authorization` header is sent with `add_unredirected_header`; a 3xx becomes `provider_error`. Unit test: stub A answers 302 to stub B; B receives no request.
- **Pinned prompts (T96).** Every loaded prompt file is verified against `prompts/manifest.json` (exit 2 naming the file on a sha256 mismatch) and the per-file sha256 is recorded in `request.json` (QA-02D-14); the preset's front-matter is stripped like every other file before assembly (QA-02D-15).
- **Atomic metrics + resume (T0 `_cell_done`).** `metrics.json` is written via a temp file + `os.replace`, so it is never torn; a cell counts as **done** when its `metrics.json` parses and either records `outcome=ok` **or** `--retry-failed` was not passed — i.e. a recorded failure is left in place by default (it is evidence, not a gap); with `--retry-failed` it is not done and is rerun into `<run_id>-r2`. An unparseable/absent `metrics.json` is never done (QA-02D-10).
- **Malformed output cannot crash the batch (SEC-02D-2).** A shape check (`hook`/`ending` dicts, `paragraphs` a list of dicts, `keywords` a list of str) runs before `derive_body`/`derive_keywords`; a shape failure is `invalid_output` with reason `schema_shape`. `_safe_json`/`extract_story` catch `ValueError` **and** `RecursionError`, and a post-call failure still writes `metrics.json` (with `usage`/`cost`) and counts the spend.
- **Unpriced bound uses request bytes (PERF-02D-2).** For a cell with no price row, the input term of the conservative bound is the UTF-8 **byte count of the full request body** (the P6 rule: `input tokens ≤ UTF-8 bytes`), not the D4 word count; `head_tokens_estimate` stays the D4 story statistic only.
- **Lock acquisition (SEC-02D-4).** The first acquisition publishes via `os.link(tmp, path)`; `FileExistsError` → exit 2. `os.replace` is used only when the file already holds one of our ids (the language swap). Release removes the file only while it still holds our id.
- **Relay caveat (QA-02D-7).** The relay drops `max_output_tokens` and rewrites `safety_identifier`/`prompt_cache_key`, so a cap-cut (`incomplete_details.reason = max_output_tokens`) cannot be produced live; `classify` is unit-tested for it and T1's report states this.

### Validator (D3 rules; throwaway)

```python
def token_count(text: str, lang: str) -> int          # NFC normalise, split on Unicode whitespace, count non-empty
def validate(story: dict, tier: str, lang: str, limits: dict) -> list[dict]   # [{"rule","severity","segment","evidence"}]
```

Checks, with `severity` in the D3/D22 vocabulary (`blocking|advisory`) and `segment` addressing `title|hook|p:<i>|ending|meta`:

| Rule | Severity |
|---|---|
| `title_too_long` (> 100 chars), `title_has_angle_brackets` | blocking |
| `hook_too_long` (> 3 sentences) | blocking |
| `keyword_count_out_of_range` (not 1–2 per segment; exactly 1 at `short`, so the total ≤ `ceil(D × 6)` — 02 T65) | blocking |
| `keyword_too_short` / `keyword_too_long` (not 3–12 words), `keyword_not_english`, `keyword_person_name` | blocking |
| `segment_count_out_of_range` (outside D4 segments) | advisory (02 T99 — reported, not blocking, pending the post-A/B D4 calibration) |
| `short_beats_missing` (at `tier=short`, the required beats `setup`, `twist`, `reveal` are reported in order; `reveal` may fold into `ending`, and `build_up`/`clue`/`aftermath` are optional) | advisory — reported, not blocking; the D4 segment band is the objective check (02 T65) |
| `length_out_of_range` | **advisory** (02 T99 — inside and outside the D4 band alike; the >15 % branch keeps its evidence text, bands unchanged pending the post-A/B D4 calibration) |
| `markdown_or_bracket`, `url_in_text`, `list_marker` | blocking |
| `description_too_long` (> 1,000), `tags_too_many` (> 15), `tag_too_long` (> 30), `tag_total_too_long` (> 400) | blocking |
| `unknown_fact_ref` (`fact_refs` non-empty with no sheet) | blocking |
| `empty_segment`, `duplicate_paragraph` | advisory |

The validator **never** repairs and never blocks a paid call — it runs after the response and lands in `metrics.json.validator_issues`.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Tap not listening | exit 2 before any call; never fall back to the upstream `OPENAI_BASE_URL` directly (01 CR-15) (the trial's usage evidence lives in the tap) |
| Keychain read fails / item missing | exit 2 naming the service; never prompt interactively, never print the value |
| `gpt-6-sol` rejected by the project | `provider_error` recorded; the CR-17 allow-list window has closed or its entry is missing — restart the batch inside the window (a luna-only rerun is not an A/B) |
| `incomplete_details.reason = max_output_tokens` | `invalid_output`, raw body kept; a systematic pattern means the D4 cap or the preset is wrong |
| Refusal on a true-crime brief | `moderated`, recorded; T1 keeps the cell and reports the rate |
| 429 with `Retry-After: 30` | sleep, one retry, then record; `--sleep-ms` should prevent most |
| Budget exceeded mid-matrix | stop before the next call, print `spent=<x> cap=<y>`, exit 1; `--only-missing` resumes |
| Disk keeps a previous `run_id` | the **derived** id for an already-run cell is suffixed `-r2`, `-r3` (plan §3.1) so a rerun never overwrites; an **explicit** `--run-id` that already exists refuses and exits 2 unless `--force`. A torn/unparseable `metrics.json` never counts as done (QA-02D-9/10) |
| Transport timeout / status 0 | record `provider_unavailable` on the first occurrence — **no retry** (the upstream call is still in flight and billed); charge the attempt's bound and keep `attempts: [...]` (T91) |
| A prompt file's sha256 ≠ `prompts/manifest.json` | exit 2 naming the file before any call; a preset changed without re-hashing is a configuration error, not a batch failure (T96) |
| A model writes `other:` into `structure.*` | the M0 validator does not check structure (owner 02.2.1-T1); T1 hand-checks resolution in the vocabulary and records a model-emitted prefix (T71, QA-02D-12/13) |
| Rollback | delete `trial/tools/*` and `trial/stories/**`; nothing else changed |

## Notes

- [DECISION] The harness talks to the **tap**, not OpenAI, so spend and latency also land in the tap's JSONL (01 D6), not only in `metrics.json`. This is the point of F01's fix: the evidence chain is the trial's own.
  - The tap attributes a line only to a `current_run` matching the 01 D10 regex `^\d{8}-\d{4}-(vi|en)-(landscape|portrait)-\d{2}$`. The cell ids (`vi-ghost-b1-luna-standard`) do not match, so they are **never** written to `current_run`: the tap would log them as `no-run`.
  - Instead, a batch (T1) or a single run (T0) writes one D10 batch id per language to `$NTS_HOME/current_run`, for example `20261001-1030-vi-landscape-01`, and records it in each cell's `request.json` as `tap_run_id`.
  - Per-cell usage comes from the response `usage` (`metrics.json`).
  - Cross-check: the sum of the cells' `usage.input_tokens` / `output_tokens` for a batch equals the sum over the `/responses` lines of `trial/runs/<tap_run_id>/openai_usage.jsonl`, or the batch report names the difference (09 DoR finding, 2026-09-24). ⚠️ Until 01.3.1-T2 resolves the run dir at **request** time (CR-25), a timed-out/abandoned call is attributed when its response completes and can land in a later run's file, so for a batch containing a timeout the cell-vs-tap difference is expected and must be named, not asserted away (QA-02D-8/17).
- [DECISION] `store: false` on every call (O5's default is `true`) — a trial must not leave prompt/response retention behind.
