# 02.1.3-T1 — 36-story run + blind scoring

| Story | Size | Area | Depends on | Blocks | Phase / flag |
|---|---|---|---|---|---|
| 02.1.3 | M (1.0) | A/B run + human scoring | 02.1.3-T0, 02.1.2-T1, 02.1.5-T1 | 02.1.3-T2 | M0 · no flag |

## Goal

Produce the evidence for D15: 36 stories (6 presets × 3 briefs × 2 models), scored blind by 2 native raters per language against the D16 rubric, aggregated into a decision that can be re-derived from the CSV files alone.

## Inputs

- README: **D15** (decision rule), **D16** (seven dimensions, anchors 1/3/5, "the same dimensions are `review.v1`'s `scores` object"), D4 (length bands), D7 (`Writer` effort = `medium`, owner 2026-09-25), O3 (rates for the cost report), F10 (why 36 and 2 raters); §5.4 (the rubric in the high-level plan).
- 02.1.3-T0 (`story_harness.py` `--matrix`, `metrics.json`, `trial/tools/LENGTH.v1.json`, and the fixtures `prompts/fixtures/briefs.{vi,en}.json` + `prompts/fixtures/fact-sheet.true_crime.v1.json` — T34; consumed read-only here).
- Plan §3.2–3.4 (run ids, `key.csv`/`scores.csv`/`aggregate.csv`, the dimension keys), §3.5 (the brief fixture shape), §7 (budget arithmetic), §9 (T1 checks).
- 4 raters: 2 native Vietnamese, 2 native English (external people; the only human dependency in the whole story).

## Design

### 1. The matrix (36 cells, enumerated)

Per language 3 presets × 3 briefs × 2 models = 18; both languages = **36**. Tier **`standard` for all 36** (T24: pacing and length fit cannot be judged on 1-minute stories; writer `max_output_tokens` = 6,000, D4), `effort = medium` (D7 `Writer` default, owner 2026-09-25), `--sleep-ms 200`.

Each brief carries its own **`language`** (`vi`/`en`) and its own topic, and a cell's language comes from the brief it was built from — hence its `vi-…`/`en-…` run-id prefix. One `--matrix` over both briefs files therefore builds both columns with no `--lang`; the flag is only a filter (with `--lang vi` given, the `en` briefs are skipped with a note, exit 2 if nothing remains).

| | vi | en |
|---|---|---|
| `ghost` | `vi-ghost-b{1,2,3}-{luna,sol}-standard` | `en-ghost-b{1,2,3}-{luna,sol}-standard` |
| `spiritual` | `vi-spiritual-b{4,5,6}-{luna,sol}-standard` | `en-spiritual-b{4,5,6}-{luna,sol}-standard` |
| `true_crime` | `vi-true_crime-b{7,8,9}-{luna,sol}-standard` | `en-true_crime-b{7,8,9}-{luna,sol}-standard` |

Brief ids are **global** (`b1..b9`, §2): `b1–b3` = ghost, `b4–b6` = spiritual, `b7–b9` = true crime — the same nine ids in both languages, so a cell's topic is recoverable from its `briefId` alone.

36 distinct ids; a rerun of any cell gets a `-r2` suffix (T0 refuses to overwrite). The `--matrix` invocation is the single reproducible command (`--matrix` enumerates both models; `--model` restricts it):

```
uv run --no-project --python 3.12 trial/tools/story_harness.py \
  --matrix --briefs-file prompts/fixtures/briefs.vi.json --briefs-file prompts/fixtures/briefs.en.json \
  --tier standard --only-missing --max-usd 5.0 --sleep-ms 200 --timeout 240
```

The two repeated ids in the two files (`b1` is `vi`'s b1 **and** `en`'s b1) produce two cells each, `vi-…` and `en-…` — ids resolve per file and language, never last-file-wins — and each cell is assembled from its own language's preset and shared blocks. So this one command yields 36 distinct dirs: 18 `vi-…` + 18 `en-…`.

### 1b. Unrated per-tier sweep (12 cells, for D4 + 12.1.1) — accepted as T37

Gate 02-M0 requires "token/latency numbers **per tier**", and D4 is calibrated from 02.1.3 across its three tier rows — a `standard`-only matrix cannot supply that. One brief per topic (`b1` ghost, `b4` spiritual, `b7` true crime — ids are global, §2) × 2 tiers × 6 presets = **12 additional cells**, never scored, used only for tokens / latency / cost per tier:

```
vi-ghost-b1-luna-{short,long}        en-ghost-b1-luna-{short,long}
vi-spiritual-b4-luna-{short,long}    en-spiritual-b4-luna-{short,long}
vi-true_crime-b7-luna-{short,long}   en-true_crime-b7-luna-{short,long}
```
`--matrix --model gpt-6-luna --briefs-file prompts/fixtures/briefs.vi.json --briefs-file prompts/fixtures/briefs.en.json --brief-ids b1,b4,b7 --tier short` and the same with `--tier long` (two runs; `--matrix` defaults to both models unless `--model` restricts it). Each id resolves per file and language, so the three ids select six briefs — 3 `vi` + 3 `en` — and one run yields the 6 cells above. Total calls = 36 + 12 = **48**; the sweep's numbers fill `d4_calibration.tiers.{short,long}` (T2 §3) and 12.1.1's per-tier p50/p95. Accepted as T37; the per-tier numbers are handed on exactly as T2 §3 specifies (`d4_calibration.tiers` + `price_bounds_12_1_1.latency_ms`).

### 2. Brief fixtures (authored by 02.1.3-T0 — consumed here)

`prompts/fixtures/briefs.{vi,en}.json` (9 entries each) and `prompts/fixtures/fact-sheet.true_crime.v1.json` are authored in **02.1.3-T0** (T34), so preset acceptance (02.1.1-T1..T3) can run before this task exists. Ids are **global**: `b1–b3` = ghost, `b4–b6` = spiritual, `b7–b9` = true crime, the same nine in both languages. Each brief also carries its own **`language`** (`vi`/`en`), and that field — not `--lang` — is the cell's language and its `vi-…`/`en-…` run-id prefix, so the same id in the two files yields two distinct cells. This task consumes them read-only and verifies the allocation (§1/§1b) before the matrix runs. Each fact in the fact-sheet fixture carries a **`brief_id`**, and the harness sends only that brief's facts (README T92) — verify before the matrix that no true-crime cell can see another case's facts (a mixed sheet made 3 of 6 presets narrate the other case: QA-02D-4). The three true-crime briefs and their fact sheet are synthetic by construction (`synthetic:true`; no real person, incident, place or URL) — the A/B must never create material 02.8.2's real-person detector has to catch.

### 3. Rubric (`prompts/fixtures/rubric.md`) — D16 dimensions with written 1/3/5 anchors

Seven dimensions, 1–5 each. `factual_care` is `n/a` outside true crime and is excluded from those means (never scored 0). The same seven keys are `review.v1`'s `scores` object (D16), so this file is also the wording source for 02.6.1.

**`hook`** — 1: states a situation but gives nothing to wonder about; a listener would not stay. 3: raises a clear question within the first two sentences. 5: a concrete image plus an unresolved tension makes the next sentence unavoidable, in ≤ 2 sentences.

**`pacing`** — 1: uniform sentence length, the middle sags, the twist arrives without build-up. 3: beats in order (setup → build-up → clue → twist → reveal → aftermath) with at least one change of tempo. 5: every beat earns its place, tension rises, the reveal lands at the natural peak, aftermath ≤ 3 sentences.

**`atmosphere`** (without gore) — 1: fear is named ("it was scary") or bought with explicit gore. 3: atmosphere comes from concrete sensory detail; no explicit gore, no sexual content, no minor shown in danger (02 T73). 5: dread is built from the ordinary (sound, light, absence); the listener supplies the fear; nothing explicit is needed.

**`natural_language`** — 1: reads as translated English — wrong collocations, calques, stiff connectives; vi misuses or lacks diacritics. 3: native-sounding with occasional phrasing a native would not write. 5: reads as a native narrator writing for the ear — short spoken sentences, no brackets/lists/footnotes, numbers and dates said the way they are read aloud, one idea per sentence in tense moments.

**`originality`** — 1: a recognizable retelling of a known story; names, places or the twist match a well-known source. 3: familiar genre furniture, with at least one element (setting, mechanism or twist) that is not the default. 5: premise, mechanism and twist are each recognisably ours; no borrowed scene.

**`factual_care`** (true crime only; otherwise `n/a`) — 1: invented "facts" presented as true, or a real person/incident present. 3: claims are synthetic or match supplied material; no real person named. 5: every checkable claim is supplied or explicitly framed as unverified; no real-person and no real-incident signal, and internally consistent. ⚠️ M0 supplies no fact sheet (02.5.x is M1), so 5 here means "no real-person/real-incident signal + internally consistent", not source fidelity — accepted by T25, with `factual_care` excluded from the D15 comparison.

**`length_fit`** — 1: more than 15 % outside the tier token band, or the ending is cut off/padded. ⚠️ (02 T99) The band being scored is the **current** D4 band; if the owner recalibrates D4 after this A/B, `length_fit` must be re-read against the new band — the rater's 1/3/5 verdict stays, its meaning may shift, so quote the band in `REPORT.md` next to the means. 3: within ±15 % of the band and the ending resolves. 5: inside the band and the story uses the room without a padded middle.

### 4. Blind kit (`trial/tools/make_blind_kit.py`)

Input: the 36 completed **rated** run directories — the 12 sweep cells (§1b) are never scored and never enter the kit. Output: `trial/ab/r1/stories/<story_id>.md` (title + body only) + `trial/ab/r1/key.csv`. `story_id = S01…S36`, assigned by shuffling the 36 `run_id`s with a **recorded seed** (`--seed` printed and stored in `key.csv`), so the map is reproducible but not guessable from the kit. The kit file **must not** contain the model, preset, brief id, `run_id`, `prompt_version`, or any metric — the raters judge text, and the language is self-evident from the text. `key.csv` is never opened before `scores.csv` is complete; that is the masking procedure.

### 5. Scoring

One row per rater × story × dimension: `story_id,rater_id,rater_language,rater_native,dimension,score,notes,scored_at`. Each rater scores their own language's 18 stories × the 6 always-applicable dimensions + `factual_care` for the 6 true-crime stories = 114 rows per rater, ≈ **456 rows** total. Raters get `rubric.md` and the kit; they do not see the other model's story for the same brief side-by-side (A/B pairs are separated in the kit ordering, which is also why the kit is shuffled). At `standard` a story is ~1,000 tokens (≈ 6–8 min of narration), so budget **≈ 1 h per rater** — the cost T24 accepted in exchange for judgeable pacing and length fit.

### 6. Aggregation (`trial/tools/aggregate_scores.py`)

Joins `scores.csv` with `key.csv` (the only unblinding step, run after all scoring is filed) and produces:

- `aggregate.csv`: one row per `model,preset,language,dimension` with `n, mean_rating`, plus per-model `json_valid_rate` (from `metrics.json`), `tokens_mean`, `latency_p50_ms`, `latency_p95_ms`, `cost_usd_mean`.
- `REPORT.md`: the matrix summary (36 cells: outcome, `json_valid`, tokens, latency, cost), the per-dimension means (luna vs sol by language), the `n` per cell, the invalid/moderated cell list, and **the D15 test applied and printed**.

**D15 test, mechanically:**
```
mean(luna, lang) = mean of mean_rating over stories × the 6 dimensions scored everywhere
                   (factual_care is EXCLUDED from the D15 mean — T25: M0 has no fact sheet;
                    it is still scored and reported per true-crime story, never folded in)
mean(sol,  lang) = same
(a) luna_mean < sol_mean * 0.9                                    → sol for that language
(b) lang == vi and mean(natural_language, luna) < 3.5             → sol for vi
otherwise                                                         → luna stays default
```
Both languages are evaluated independently (D15 allows per-language model config). `n` is never folded: a cell with `n = 1` is printed as `n=1` and the affected mean is marked `†`; if a `†` mean decides condition (a) or (b), the report prints `DECISION NOT READY — rater missing` instead of a verdict (T25: an `n=1` cell that would decide D15 blocks the freeze; plan open item 1).

### 7. Cost and hygiene

`--max-usd 5.0` with a **hard stop, no paging in M0** (T25). Expected spend from the O3 arithmetic (plan §7) [INFERENCE]: rated matrix 18 luna `standard` ≈ $0.06 + 18 sol `standard` ≈ $1.3, plus the 12-cell sweep (6 luna `short` ≈ $0.02 + 6 luna `long` ≈ $0.1) → **≈ $1.5**, worst case ≈ $2.2 — inside both `--max-usd` and the 01 D7 `$5` project limit. Set `$NTS_HOME/current_run` to a campaign id so the tap's `openai_usage.jsonl` attributes the batch (01 D6); if the id shape does not fit 01 D10, accept `no-run` and rely on `metrics.json` ⚠️.

Two preconditions before the batch (README T91/T92, plan open items 5–6):
- **`trial/prices.json` must carry the `gpt-6-sol` row and the luna `cache_write` rate**, or `--matrix` exits 2 at the rates pre-flight and sol cells cannot be priced (QA-02D-18, CR-27) — an owner/01 change, not this task's.
- **`--timeout` is set from a measured relay tail, not the D7 90 s.** Phase-D measured a bimodal relay (17–58 s fast, 102–181 s slow, 3×502 at 154–181 s) and every client-aborted call was still billed (QA-02D-2); run at `--timeout 240` (T91) and record `attempts` per cell. The tap attribution is request-time only after CR-25, so do not assert cell-sum == tap-sum for a cell that timed out — print the per-run difference (plan open item 6).

## Steps

1. Verify T0's `briefs.{vi,en}.json` + `fact-sheet.true_crime.v1.json` match §2's global id allocation, then transcribe `prompts/fixtures/rubric.md` from Design §3.
2. Diff `trial/tools/LENGTH.v1.json` against 02.1.1-T0's length table; fix the harness data (not the presets) on mismatch.
3. Run the 36-cell `standard` matrix with `--only-missing` (§1), then the 12-cell per-tier sweep (§1b); keep both commands in `REPORT.md`.
4. `make_blind_kit.py` → `trial/ab/r1/{stories,key.csv}`; run the leak grep (Acceptance) before anyone scores.
5. Brief 4 raters on `rubric.md`; collect `trial/ab/r1/scores.csv` (one file, appended per rater; seal when `wc -l` reaches 456 + header).
6. `aggregate_scores.py` → `aggregate.csv`, `REPORT.md`; read the printed D15 verdict.
7. Record the run conditions (`tier`, `effort`, `--seed`, model, date, prompt `sha256`s) at the top of `REPORT.md` so a later `r2` is comparable.

## Tests

Throwaway scripts (no unit-test project for a spike; the checks are the observable contract):

- `aggregate_scores.py --selftest` over a 3-story fixture with hand-written scores → asserts the mean, the `n`, the `factual_care` exclusion and the `†` flag for a missing rater.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| A model rejects the call (sol entry missing/expired) | the cell is `provider_error`; **stop the batch** and resolve the CR-17 window — 18 missing cells is not a decision-usable matrix |
| A cell's recorded tier ≠ the tier it was requested with | invalid provenance: delete that run dir, rerun the cell (a mixed-tier matrix silently breaks T24's rationale and the D4 numbers) |
| > 3 invalid cells overall | still score, but the report leads with the validity rate; D15 cannot be applied from an incomplete matrix without saying so |
| A rater drops out mid-file | the cell keeps `n=1`; the mean is marked `†`; if a `†` mean decides, print `DECISION NOT READY` (never silently proceed) |
| A story is dominated by a refusal | score it 1 only if it produced no text; a refusal with no story is reported as `moderated` and excluded from means, counted in the rate |
| Both models score below 3.0 on a preset | the verdict is "presets need work", not "pick the model": T2 records it and the evidence goes to 02.1.1/02.1.2 for a rerun `r2` |
| The relay is in its slow tail (102–181 s) or returns 502 | the cell records `provider_unavailable` with `attempts: [...]` and is **still billed** (QA-02D-2); never retry a transport timeout (T91). Pause the batch, re-check the tail, and resume with `--only-missing` after raising `--timeout`; a failed cell is left in place as evidence, and `--retry-failed` decides whether a resumed batch reruns it (T0 `_cell_done`) |
| Scoring drifts between raters | report per-rater means; a rater whose mean differs from their partner's by > 1.0 on any dimension is flagged as "needs a second pass on that dimension", and their rows are not silently pooled |
| Kit regenerated after scoring started | forbidden: a new seed invalidates every filed score; rerun as `r2` with a new `trial/ab/r2/` |
| A rated run dir is partially populated (`metrics.json` ok but `story.json`/`video_script.txt` missing, or `metrics.json` unparseable) | `make_blind_kit.py` exits **2** naming every such dir and the missing file(s) — never a traceback, never a partial kit (02 T100, QA AbTooling D1) |
| A `scores.csv` row is non-numeric, outside the rubric range 1–5, a dimension typo, or a row/header that does not match the columns | `aggregate_scores.py` exits **2** naming file, line and offending value; a blank `score` stays an unrated row and is skipped (02 T100, QA AbTooling D3/D4) |
| Rollback | delete `trial/ab/**`; the 36 raw runs stay regenerable |

## Notes

- [DECISION] Tier **`standard`** for all 36 rated cells (T24) — pacing and length fit are not judgeable on 1-minute stories; `short`/`long` are measured only by the unrated 12-cell sweep (§1b).
- [DECISION] `n` is never hidden. F10's whole point is that one sample per cell is noise; the report must therefore expose `n`, the `†` flag and the per-rater spread, or the decision is not reproducible. T25 confirms an `n=1` cell that would decide D15 blocks the freeze.
- ⚠️ True-crime scoring in M0 measures tone and length, not source fidelity (no fact sheet exists yet) — accepted by T25, with `factual_care` excluded from the D15 comparison. The dimension is still anchored so `review.v1` (02.6.1) inherits the wording.
- [OPEN] Rater availability is the only human dependency; at `standard` it is 456 scored rows ≈ 1 h of reading **per rater** (≈ 4 h across the 4 raters), and there is no fallback in the contract (plan open item 1).
- ⚠️ **Structure values are hand-checked in M0.** The M0 validator does not implement T71's `structure_text_invalid` (that rule's owner is 02.2.1-T1), so the acceptance criterion "`structure.*` resolves in the topic vocabulary or falls back to `other:<text>`" is checked by a script or by hand in `REPORT.md`, not by the harness (QA-02D-13). The `other:` prefix is the validator/mapper's, never the model's (T71) — with no check, watch for a model-emitted `other:` that would double up (QA-02D-12).
