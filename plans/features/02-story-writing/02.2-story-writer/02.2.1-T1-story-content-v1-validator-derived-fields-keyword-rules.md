# 02.2.1-T1 — `StoryContentV1` + `StoryDraftValidator` + derived fields + `KeywordRules`

| Story | Size | Area | Depends on | Blocks | Phase / flag |

## Goal

The `story.v1` output contract as pure Domain code: `StoryContentV1` mirrors D3 exactly, `StoryDraftValidator` returns **blocking/advisory** issues with stable rule ids (never throwing, never truncating), `DerivedStoryFields` computes `body`/`keywords`/`word_count` on every save, and `KeywordRules` implements 03 FR-03-3 once and is shared with the render linter (CR-5).

## Inputs

- README **D3** (the schema, the validator list, the derived fields, "the model never outputs URLs or source ids"), **D4** (length targets + the token rule + the 15 % band), **D22** (segment addressing `title|hook|p:<i>|ending|meta`), **F08** (schema has no structure tags / no `schema_version`), **F36** (metadata limits tied to 06.2.1), **P5** (keywords English, 3–12 words, cap `ceil(D × K)`).
- **CR-5:** `KeywordRules` lives in Domain `Stories/Keywords/` and is shared — 02 uses it in the validator/hints, 03.2.2 adds the `fact_sources`-title name check at render.
- **D21** step 2: `ValidationResult Validate(StoryContentV1, StoryRules)`.
- 02.1.1-T0 owns `prompts/schemas/story.v1.json` and `prompts/shared/structure-vocab.v1.json` (the file contents); this task owns the C# side.
- `PriceLimits` (Domain `Usage/`) is declared by 02.2.4-T1 and consumed here by `LengthTargetResolver.Resolve(LengthTier, Language, PriceLimits)` (D21). If this task lands first, it adds that one record and 02.2.4-T1 consumes it — the type is a trivial rates/limits holder either way.

## Design

### Records (`src/NightTales.Domain/Stories/Content/`)

```csharp
public sealed record StoryContentV1(
    string Title, StorySegmentV1 Hook, IReadOnlyList<StorySegmentV1> Paragraphs,
    StorySegmentV1 Ending, string Description, IReadOnlyList<string> Tags,
    IReadOnlyList<string> ContentWarnings, StoryStructureV1 Structure);

public sealed record StorySegmentV1(
    string Text, IReadOnlyList<string> Keywords, IReadOnlyList<string> FactRefs,
    string? Beat = null);                    // Beat non-null on paragraphs only (D3)

public sealed record StoryStructureV1(
    string SubGenre, string Setting, string Opening, string TwistType, string NarratorMode);

public static class StoryEnums   // the D3 enums, as string constants + valid sets
{
    public static readonly IReadOnlySet<string> Beats =
        new HashSet<string> { "setup", "build_up", "clue", "twist", "reveal", "aftermath" };
    public static readonly IReadOnlySet<string> ContentWarnings =
        new HashSet<string> { "violence", "death", "crime", "supernatural", "self_harm_mention", "disturbing" };
    public static readonly IReadOnlySet<string> NarratorModes = new HashSet<string> { "first_person", "third_person" };
}
```

- `schema_version: "story.v1"` and `fact_sources: [{ source_id, title, url }]` are **not** part of the model contract: the persistence layer (02.2.2-T1) adds them to `story_versions.content` after validation (D3). This task's types stay model-shaped.
- `StoryRules` (`Stories/Content/StoryRules.cs`): `TitleMaxChars = 100`, `HookMaxSentences = 3`, `MinKeywordsPerSegment = 1`, `MaxKeywordsPerSegment = 2`, `DescriptionMaxChars = 1_000`, `MaxTags = 15`, `TagMaxChars = 30`, `TagsTotalMaxChars = 400`, `LengthTarget Length`, `Language Language`, `IReadOnlySet<string> AllowedFactRefs`, `IReadOnlySet<string> StructureVocab` (sub_genre/opening/twist_type entries). Built by the job from the run's `price_version.limits` (via `LengthTargetResolver`, D21) + the approved fact sheet + `structure-vocab.v1.json`.
- `LengthTarget` / `LengthTargetResolver` are reproduced **verbatim from D21**: `LengthTarget(int MinTokens, int MaxTokens, int MinSegments, int MaxSegments, int WriterMaxOutput, int ReviewMaxOutput, int RevisionMaxOutput)` and `LengthTarget Resolve(LengthTier tier, Language lang, PriceLimits limits)` (Domain `Stories/Length/`). `PriceLimits` is declared by 02.2.4-T1 (see Inputs).

### Rule ids, severity and kind

| Rule id | Severity | Kind | Check |
|---|---|---|---|
| `title_too_long` | blocking | objective | > 100 chars |
| `title_has_markup` | blocking | objective | contains `<` or `>` |
| `hook_too_long` | blocking | objective | > 3 sentences |
| `keyword_invalid` | blocking | objective | a keyword fails `KeywordRules` |
| `keyword_count_out_of_range` | blocking | objective | a segment has 0 or > 2 keywords |
| `segment_count_out_of_range` | blocking | objective | outside `Length.MinSegments..MaxSegments` |
| `length_out_of_range` | blocking | objective | tokens > 15 % outside `Length.MinTokens..MaxTokens` |
| `length_advisory` | advisory | objective | tokens within 15 % of the band edge |
| `text_has_markup` | blocking | objective | markdown/brackets/list markers/URLs/backticks in any `text` |
| `description_too_long` | blocking | objective | > 1,000 chars |
| `tags_invalid` | blocking | objective | > 15 tags, any tag > 30 chars, or total > 400 chars (F36) |
| `fact_ref_unknown` | blocking | objective | a `fact_ref` not in `AllowedFactRefs` (and non-empty when the sheet is absent) |
| `beat_invalid` | blocking | objective | a paragraph `Beat` outside `StoryEnums.Beats` |
| `narrator_mode_invalid` | blocking | objective | `NarratorMode` outside the enum |
| `warning_invalid` | blocking | objective | a `ContentWarnings` entry outside the enum |
| `structure_vocab_unknown` | advisory | objective | `SubGenre`/`Opening`/`TwistType` not in the vocabulary → mapped to `other:<text>` |

- `Segment` on each issue uses the D22 addressing (`title`, `hook`, `p:<0-based index>`, `ending`, `meta`), because the same addressing drives the editor (10.5.10), the review and similarity.
- `ValidationResult(IReadOnlyList<ValidationIssue> Issues)` with `bool IsValid => Issues.All(i => i.Severity != Blocking)` and `IReadOnlyList<string> BlockingRuleIds`. The **job** (02.2.2-T3) maps "no valid draft" to `TextCallResult.InvalidOutput` and owns the retry; the validator never decides that (D21, D7).
- **Never truncates [DECISION]:** the validator reports; it does not fix. A 130-char title is an issue, not a rewrite — the corrective note (02.2.3-T2) tells the model which rules it broke.

### Algorithms (deterministic, documented in the code)

- **Tokens (D4):** `NFC`-normalise, split on Unicode whitespace, count non-empty tokens. vi token = syllable (V1). One static `StoryText.Tokenize(string)` used by the validator, `DerivedStoryFields` and the cost estimator's output bound.
- **Sentences:** count runs of text terminated by `.`, `!`, `?`, `…` (and their Vietnamese equivalents); a trailing unterminated run counts as one sentence. `"Chào. Bạn khỏe?"` = 2.
- **Markup:** reject `*`, `_`, `#`, `` ` ``, `>`, `<`, `[`, `]`, a line starting with `- ` or `N. `, and any `http://`/`https://`/`www.` occurrence.
- **15 % band (D4):** `minTol = MinTokens * 0.85`, `maxTol = MaxTokens * 1.15`; outside `[minTol, maxTol]` → `length_out_of_range`; inside the band but outside `[MinTokens, MaxTokens]` → `length_advisory`.
- **`KeywordRules`** (`Stories/Keywords/KeywordRules.cs`): `Check(string) → KeywordViolation` covering (a) word count 3–12 after whitespace split, (b) English only — reject any character outside `[A-Za-z0-9' -]` after NFC (this rejects Vietnamese diacritics, 03 FR-03-3), (c) person-name heuristic: reject when any token after the first is capitalised mid-phrase or when the phrase contains a title/honorific from the small list (`mr`, `mrs`, `ms`, `dr`, `sir`, `lady`, `captain`, `detective`, `officer`, `professor`, `saint`), (d) gore list: reject when the phrase contains any entry of `GoreTerms` (`blood`, `bloody`, `guts`, `corpse`, `decapitated`, `mutilated`, `dismembered`, `gore`, `entrails`, `severed`) — ⚠️ the list is a proposal, owner-editable, and 03.2.2 consumes the same set.
- **`DerivedStoryFields.From(StoryContentV1)`:** `Body` = `Hook.Text` + `"\n\n"` + paragraph texts joined by `"\n\n"` + `"\n\n"` + `Ending.Text`; `Keywords` = hook ++ paragraphs ++ ending, in order, deduplicated only when adjacent-identical? **No** — concatenated verbatim in order (D3); `WordCount` = `StoryText.Tokenize(Body).Count`. The 03.2.1 cap `ceil(D × K)` is **not** enforced here (it is a hint/checker concern, F09) — but `StoryQualityChecker` (02.3.4-T1) reuses `StoryText.Tokenize`.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| `Paragraphs` empty | `segment_count_out_of_range` (blocking) — a draft with no body is never valid. |
| `Text` null/empty in a segment | Treated as 0 tokens; the length and segment checks catch it; no exception (records are non-nullable, so `""`). |
| Duplicate keywords across segments | Allowed (D3 does not dedupe); the 03.2.1 cap is a checker/hint concern (F09). |
| `fact_refs` non-empty on a fiction topic | `fact_ref_unknown` — the approved set is empty for fiction. |
| Unknown structure term | Mapped to `other:<text>`, advisory only — the variety guard (02.8.4) must not fail a run on vocabulary. |
| A single 500-char token (no whitespace) | Counts as 1 token; the length band is the only guard. |
| Rollback | Pure Domain types; reverting the assembly reverts behaviour (no migration, no config). |

## Notes

- [DECISION] The validator reports, never repairs, and never mutates the draft: the corrective note (02.2.3-T2) + the job's single retry (02.2.2-T3) are the repair path, so `story_versions` never stores a silently edited draft.
- [DECISION] The 15 % band is objective (blocking outside, advisory inside) exactly as D4 states; a widening of the band is a D4 change, not a validator change.
- [OPEN] The person-name heuristic is deliberately conservative (mid-phrase capitalisation + honorific list). It will miss some names and will not reject a fully capitalised phrase like `SILENT HOUSE`; 03.2.2 adds the `fact_sources`-title check at render. If the TL wants a stronger rule, a name list is a data file, not code.
- ⚠️ `GoreTerms` is a proposal (10 terms); the owner may extend it. It is one `IReadOnlySet<string>` so the change is data-only.
- ⚠️ `StoryText` is also used by 02.5.6 (shingles) and 03.2.2 — keep it dependency-free so both can reference it without pulling in EF.
