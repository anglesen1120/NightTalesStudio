# 02.2.1-T2 — `OpenAiTextClient` + `OpenAiStoryWriter.WriteAsync`

## Goal

One adapter — `OpenAiTextClient : ITextClient` — makes every OpenAI call on the Responses API with a strict JSON schema, a single retry layer, and the D7 outcome mapping returned as data (`TextCallResult<T>`), never as a control-flow exception. `OpenAiStoryWriter.WriteAsync` is the writer step: assemble the prompt (02.2.3-T2), call, return the draft or the mapped outcome.

## Design

### `OpenAiTextClient` (`src/NightTales.Infrastructure/OpenAI/`)

```csharp
public sealed class OpenAiTextClient(OpenAIClient client, IOptionsMonitor<OpenAiOptions> options,
    ResiliencePipelineProvider<string> pipelines, ILogger<OpenAiTextClient> log) : ITextClient
{
    public async ValueTask<TextCallResult<T>> CallAsync<T>(TextCallRequest req, CancellationToken ct)
        where T : class;
}
```

- **Request** — `CreateResponseOptions { Model = options.Models[req.Step], MaxOutputTokens = req.MaxOutputTokens, Store = false, SafetyIdentifier = Sha256Hex(req.Run.UserId), PromptCacheKey = req.PromptCacheKey, Reasoning = new ReasoningOptions { Effort = options.Effort[req.Step] } }`; input items `[ CreateSystemMessageItem(req.SystemPrompt), CreateUserMessageItem(req.UserDataJson) ]`; text format `ResponseTextFormat.CreateJsonSchemaFormat(req.SchemaName, req.Schema, jsonSchemaIsStrict: true)` (O2). System prompt first, user data last, matching the O9 cache prefix.
- **Funds-exhausted gate (12 CR-20):** one line at the top of `CallAsync`, before any request is built — `if (flags.IsEnabledAsync("provider_funds_exhausted", ct)) return TextCallResult<T>.ProviderFundsExhausted(requestId: null);` — reusing the existing D7 outcome, no new case, no retry attempted; 12.8.3-T2 owns the flag and its circuit-breaker logic and asserts 02's existing Polly non-retry policy for this outcome by test (not re-implemented here).
- **SDK retries off** — the `OpenAIClient` is constructed with a policy that performs **zero** internal retries (⚠️ in 2.14.0 this is `OpenAIClientOptions { RetryPolicy = new ClientRetryPolicy(maxRetries: 0) }`; confirm the exact member at implementation). One `Microsoft.Extensions.Http.Resilience` pipeline per call is then the only retry: `pipelines.GetPipeline($"openai-{req.Step}")` with a per-step timeout (writer 90 s, review 45 s, facts 60 s, others 30 s), 2 attempts on 429/5xx/timeout, jittered backoff honouring `Retry-After` (F23, D7).
- **Correlation header** — `CreateResponseOptions` carries no headers, so `ClientRequestIdHandler : DelegatingHandler` on the named `"openai"` `HttpClient` reads `TextCallScope.Current` (an `AsyncLocal<string>`) and sets `X-Client-Request-Id = "<generation_run_id>:<step>:<attempt>"`. The client wraps each call in `using var scope = TextCallScope.Push(...)`.
- **Response → result** (`x-request-id` read from the raw response, O8 ⚠️):

```csharp
var result = await client.Responses.CreateResponseAsync(options, ct);
var requestId = TryGetHeader(result.GetRawResponse(), "x-request-id");
```

| Condition | `TextCallResult<T>` |
|---|---|
| text parses as `T` and no refusal part | `Ok(draft, usage, requestId)` |
| `incomplete_details.reason == "max_output_tokens"` | `InvalidOutput(usage, requestId, ["max_output_tokens_exceeded"])` |
| JSON deserialisation fails, or a schema-required property is missing | `InvalidOutput(usage, requestId, ["schema_invalid"])` |
| a content part of kind `Refusal` (`ResponseContentPartKind.Refusal`) | `Moderated(usage, requestId, categories)` (categories from the content-filter results when present, else empty) |
| `incomplete_details.reason == "content_filter"` | `Moderated(usage, requestId, categories)` |
| 429 with code `*_spend_limit_exceeded` or `credit_balance_exhausted` | `ProviderFundsExhausted(requestId)` |
| any other 4xx (`ClientResultException.Status`) | `ProviderError(status, requestId)` |
| 5xx or timeout after the retry budget | `ProviderUnavailable(requestId)` |

- **Never throws for control flow:** the whole mapping is `try/catch (ClientResultException) / (TaskCanceledException) / (JsonException)`; an unexpected exception type is logged and mapped to `ProviderError` — `TextCallResult` is the only contract (D7).
- **`TokenUsage`** (`Application/Abstractions/Text/TokenUsage.cs`): `InputTokens`, `CachedInputTokens`, `CacheWriteTokens`, `OutputTokens`, `ReasoningTokens` (O4). Usage is attached to **every** result that carried it, including failures (D14); when the response has no usage the result carries `null` and `IUsageMeter` marks the row `estimated`.
- **Logging (D19):** one structured line per call — `step`, `attempt`, `model`, `generation_run_id`, `prompt_version`, `prompt_cache_key`, input/cached/output/reasoning tokens, latency, `request_id`, and on failure the mapped kind + status. **No prompt, no data object, no draft text, ever.**
- DI: `AddHttpClient("openai")` + `AddResilienceHandler` for each step key + `OpenAiTextClient` as the `ITextClient` singleton.

### `OpenAiStoryWriter` (`src/NightTales.Application/Features/Stories/Writing/OpenAiStoryWriter.cs`)

```csharp
public sealed class OpenAiStoryWriter(IPromptAssembler assembler, ITextClient client,
    IPromptCatalog catalog, IUsageMeter meter) : IStoryWriter
{
    public async ValueTask<TextCallResult<StoryContentV1>> WriteAsync(StoryWriteRequest req, CancellationToken ct)
    {
        var prompt = assembler.Assemble(req, new AssemblerContext(req.Series.Topic, req.Series.Language,
            req.Series.StoryPresetKey, req.Length.WriterMaxOutput));
        var call = new TextCallRequest(req.Run, TextStep.Writer, prompt.SystemPrompt, prompt.UserDataJson,
            SchemaName: "story.v1", Schema: catalog.GetSchema("story.v1"),
            MaxOutputTokens: req.Length.WriterMaxOutput, PromptCacheKey: prompt.PromptCacheKey,
            PromptVersion: prompt.PromptVersion);
        var result = await client.CallAsync<StoryContentV1>(call, ct);
        await meter.RecordAsync(UsageItem.From(req.Run, TextStep.Writer, result, "story"), ct);   // own transaction (D14)
        return result;
    }

    // ReviewAsync / ReviseAsync: declared by D21, implemented by 02.6.1 / 02.6.2 — not registered here.
    public ValueTask<TextCallResult<StoryReviewV1>>  ReviewAsync(StoryReviewRequest r, CancellationToken ct)
        => throw new NotSupportedException("IStoryWriter.ReviewAsync is implemented by 02.6.1-T1.");
}
```

- The writer does **not** validate (the job calls `StoryDraftValidator`, D21 step 2), does **not** retry (the job owns the single invalid-output retry, `plan.md` §4), and does **not** persist. On that retry the corrective note carries **validator rule ids only** — the invalid draft text is never echoed back into the prompt (D6 marks it untrusted, and echoing it wastes tokens).
- `IUsageMeter.RecordAsync` runs for every outcome, including `InvalidOutput`/`Moderated`/`ProviderError`, so a failed generation keeps its cost (D14, D2 `counts_toward_limit`).
- `MeteringOnlyCreditLedger` / `IBudgetGuard` (D1) are **not** called here — reservation happens in the command handler (02.2.2-T2) before dispatch.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Timeout after the retry budget | `ProviderUnavailable` → job maps to `story_generation_failed`, `counts_toward_limit = false` (D2, D7). |
| 429 without a spend-limit code | Treated as transient → retried; still 429 after the budget → `ProviderUnavailable`. |
| Response with no `usage` | `null` usage; `IUsageMeter` writes `estimated = true` with the D1 bound. |
| `store` accidentally true | Impossible by construction (set on every request); a test asserts the field. |
| Model returns valid JSON of the wrong shape (e.g. extra property) | Strict mode rejects it server-side; if it still arrives, deserialisation into `StoryContentV1` drops unknown members — the validator then judges the content (D3 lengths are not schema features, F08). |
| `OPENAI_API_KEY` missing | Fail at start-up (secret manager validation), not on the first call. |
| Rollback | Swap `ITextClient` for the TestKit `FakeTextClient` via DI/config; no data migration. |

## Notes

- [DECISION] The SDK's internal retry is disabled and Polly is the single retry layer, exactly as F23 requires; the test asserting **2** HTTP attempts is the proof (a lingering SDK retry would produce 4).
- [DECISION] `TextCallResult` is the only failure channel; no `throw` for provider outcomes. Unexpected exceptions are logged and mapped to `ProviderError` so a job never dies on an unmodelled response.
- [OPEN] ⚠️ The exact 2.14.0 member that disables SDK retries (`ClientRetryPolicy(maxRetries: 0)` vs an `OpenAIClientOptions` property) is unverified; also ⚠️ the `x-request-id` accessor (`ClientResult.GetRawResponse().Headers`) is a System.ClientModel pattern not shown in the OpenAI docs — if unavailable, `provider_request_id` is best-effort `null`.
- [OPEN] `reasoning.effort = none` with strict JSON schema on `gpt-6-luna` is unverified; the `Writer` default is `medium` (owner, 2026-09-25; D7) and the other steps stay `low` until 02.1.3 measures it.
- [OPEN] `IStoryWriter.ReviewAsync`/`ReviseAsync` are declared but unregistered until 02.6.1/02.6.2; a DI resolution of those steps fails at build/registration time, never mid-run.
