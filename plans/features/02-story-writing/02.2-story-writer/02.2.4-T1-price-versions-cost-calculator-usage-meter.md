## Goal

Rates and output limits are **versioned, immutable rows** (`price_versions`) selected by the run's queue time; `TextCostCalculator` computes the exact USD cost from the rates that were active at reserve time; `IUsageMeter` writes one `usage_records` row per provider call **in its own transaction** so a failed job keeps its cost; `IStoryCostEstimator` returns the worst-case bound the budget guard reserves before dispatch.

## Design

### `price_versions` (P subset) — EF mapping

| Column | Type | Constraints |
|---|---|---|
| `version` | `int` | PK, monotonic, assigned as `max(version) + 1` on insert |
| `active_from` | `timestamptz` | NOT NULL, indexed `(active_from DESC)` |
| `rates` | `jsonb` | NOT NULL — `{ "<model>": { "in": 0.10, "cached": 0.01, "cache_write": 0.125, "out": 0.50 } }` per 1M tokens; plus `"image": { "gpt-image-2": { "unit": "per_image", "per_image_usd": 0.007176 } }` — the relay price is **184 VND/image flat** (owner 2026-09-28, 02 CR-27; `trial/prices.json` `unit: per_image`, `trial/schema.md` col 17 branch `Σ n × per_image` ÷ `fx_vnd_per_usd`), converted at the SBV 25,641 VND/USD of 2026-09-25. The earlier token-priced shape was measured on `gpt-image-2.5-flare` and is superseded (01 DEC-11); `image_cost_usd = n × 184 / fx` |
| `limits` | `jsonb` | NOT NULL — `{ "story": { "short": { "writer": 1500, "review": 1200, "revision": 1500 }, "standard": {…}, "long": {…} } }` (D4) |
| `config_hash` | `text` | NOT NULL, unique — sha256 of the seed config block |
| `created_at` | `timestamptz` | NOT NULL, `now()` default |

- **Immutable:** no update path; a rate change inserts a **new** row. A historical `usage_records.price_version` must stay resolvable forever (D14), so an update would silently rewrite history.
- **Seed** (`PriceVersionSeeder : ISeeder`, order 40, run by the 09.2.5-T1 `SeedRunner`: Development auto-seed and `nts-seed`; **not** its own `IHostedService`, because a hosted service also starts inside the build-time OpenAPI generator's boot, where `price_versions` does not exist): read config `OpenAi:Pricing`, compute `config_hash`; if no row has that hash, insert one with `active_from = now()`; if a row has it, do nothing. Rates default to O3 (`gpt-6-luna` `0.10 / 0.01 / 0.125 / 0.50`, `gpt-6-sol` `2 / 0.20 / 2.50 / 10`); `limits` default to the D4 table.
- `PriceCatalog` (`src/NightTales.Infrastructure/Persistence/Queries/PriceCatalog.cs`) implements `IPriceCatalog.GetActive(DateTimeOffset queuedAt) → PriceVersion`: newest row with `active_from <= queuedAt`, cached in memory keyed by `version` (the table is tiny and append-only). `PriceVersion`/`PriceRates`/`PriceLimits` are Domain records (`src/NightTales.Domain/Usage/`).
- Migration `02_PriceVersions` creates the table + the `active_from` index + the `config_hash` unique index. `usage_records` columns are added by 09's own migration (CR-4) — this task only writes them.

### `TextCostCalculator` (`src/NightTales.Domain/Usage/TextCostCalculator.cs`) — pure, no I/O

```
cost = (input − cached) × r_in + cached × r_cached + cache_write × r_write + output × r_out   // all rates per 1M tokens
```

- `SurchargeThresholdTokens = 272_000` (⚠️ configured constant `OpenAi:Pricing:SurchargeThresholdTokens`; O3 says "> 272K input tokens cost 2× input and 1.5× output"): when `input > threshold`, `r_in` and `r_write` are doubled and `r_out` is multiplied by 1.5 — applied to the **whole** request, matching the provider's pricing note.
- Result is `decimal`, rounded to **6** decimals (`MidpointRounding.AwayFromZero`) to match `numeric(12,6)`.
- Unknown model in `rates` → `PriceRates` lookup throws `UnknownModelPricingException` **at estimate time** (before dispatch), never mid-calculation after a paid call.
- `Compute` returns `decimal?` — `null` when `usage` is `null` (the caller then records `estimated = true` with the D1 bound).

**Worked examples** (asserted verbatim by `TextCostCalculatorTests`; the test names carry the expected value):

| # | Model | input | cached | cache_write | output | Arithmetic | Cost |
|---|---|---|---|---|---|---|---|
| A | `gpt-6-luna` | 12,000 | 0 | 0 | 3,000 | `(12000×0.10 + 3000×0.50)/1e6` = `(1200 + 1500)/1e6` | **$0.002700** |
| B | `gpt-6-luna` | 20,000 | 15,000 | 0 | 2,500 | `(5000×0.10 + 15000×0.01 + 2500×0.50)/1e6` = `(500 + 150 + 1250)/1e6` | **$0.001900** |
| C | `gpt-6-sol` | 30,000 | 0 | 10,000 | 4,000 | `(30000×2 + 10000×2.50 + 4000×10)/1e6` = `(60000 + 25000 + 40000)/1e6` | **$0.125000** |
| D (guard) | `gpt-6-luna` | 300,000 | 0 | 0 | 5,000 | rates ×2 / ×1.5 → `(300000×0.20 + 5000×0.75)/1e6` = `(60000 + 3750)/1e6` | **$0.063750** |

- B is the cached-token case (O9): 15,000 cached tokens cost 0.1× and dominate the saving.
- C is the cache-**write** case: the write premium (1.25× input) is charged on top of the normal input rate.
- D proves the 272K guard fires on the whole request, not per segment.

### `IUsageMeter` (`src/NightTales.Application/Abstractions/Usage/`)

```csharp
public sealed record UsageItem(string Provider, string Operation, string Model,
    int? InputTokens, int? CachedInputTokens, int? CacheWriteTokens, int? OutputTokens,
    Guid? ReservationId, Guid? EpisodeId, bool Estimated, decimal? CostUsd,
    string PriceVersion, string? ProviderRequestId); -- (12 CR-17)

Task RecordAsync(UsageItem item, CancellationToken ct);
```

- `UsageMeter` (`src/NightTales.Infrastructure/Persistence/Usage/UsageMeter.cs`) resolves a **fresh scope / `IDbContextFactory` context** per call and commits in **its own transaction** (D14): a job that later fails or is cancelled still has its cost on record.
- `UsageItem.From(RunContext run, TextStep step, TextCallResult result, string operation)` maps: `provider = "openai"`, `operation` from the D14 list (`story`, `story_review`, `story_revision`, `fact_sheet`, `bible_proposal`, `idea`, `source_find`, `moderation`), `model` from config, the five token fields (O4 — reasoning tokens are **logged only**, not stored separately), `reservation_id`/`episode_id` from the run, `price_version` from `run.PriceVersion`, `provider_request_id` from the result (O8), and `cost_usd = TextCostCalculator.Compute(ratesOf(run.PriceVersion), usage)`.
- `estimated = true` when the result carried no usage → `cost_usd` = the D1 bound for that step (never `0`, never `null`: an unmetered call must not look free).
- `UsageMeter` is the **only** writer of `usage_records`; the job never inserts directly (D14).

### `IStoryCostEstimator` (`src/NightTales.Application/Abstractions/Usage/`)

```csharp
Task<UsageBound> WorstCaseAsync(LengthTier tier, Language language, CancellationToken ct);
public sealed record UsageBound(decimal WorstCaseUsd, int MaxInputTokens, int MaxOutputTokens);
```

- **Worst case = the full pipeline (CR-6 / T46):** `WorstCaseUsd` sums `TextCostCalculator.Compute` over **four paid calls** — writer, review, revision and **review #2** — each at its own `max_output_tokens` from the active `price_versions.limits` (`story[tier].writer|review|revision`; review #2 reuses the `review` value), with the byte-counted input at the active rates and the surcharge branch applied to each. **Plus two moderation calls at cost 0** (O7: `omni-moderation-latest` is free) — included so the call count is explicit, contributing `0` to the total.
- `MaxOutputTokens` = `story[tier].writer` (the largest single step, exposed on `UsageBound`); `MaxInputTokens` = the reserve upper bound of P6 — the UTF-8 **byte** length of the assembled system prompt + data object for that tier/language (cached per `(tier, language)`, invalidated when the prompt `release` changes), because bytes ≥ tokens for UTF-8 text.
- `IBudgetGuard` (D1) compares `spent today + open bounds + worstCaseUsd` against `Budget:MaxPlatformCostUsdPerDay` ($3) and per month ($40); `ICreditLedger.ReserveAsync` takes the same bound.
- ⚠️ Deliberately an **upper** bound (bytes for tokens, every step at max output, worst-case surcharge): an underestimate would let a run slip past the cap. This **supersedes 02 §5.7's "writer + review + one revision" price bound** (CR-6, F16).

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Config rate changed between reserve and settle | The run settles with the **reserved** version's rates (`RunContext.PriceVersion`), so a mid-run rate change cannot retroactively change a settled cost. |
| `price_versions` empty at start-up | The seeder inserts the config row before the Api/Worker accepts work; `GetActive` before the first row throws `PriceCatalogEmptyException` and the host fails start-up. |
| `active_from` in the future (hand-seeded row) | `GetActive` skips it; the newest past row is used. |
| `cached_input_tokens > input_tokens` (provider bug) | `TextCostCalculator` throws rather than producing a negative cost; the caller records `estimated = true` with the bound. |
| Job cancelled mid-call | `UsageMeter` already committed in its own transaction if the response arrived; if not, the run is not counted (D2) and the sweeper (02.2.2-T3) closes it. |
| Prompt release changes (02.1.3-T2) | The estimator's cached input bound is invalidated by the `release` value from `IPromptCatalog`; the next estimate recomputes. |
| Rollback | `price_versions` rows are immutable, so rollback = insert a new row with the old rates; no code revert needed. |

## Notes

- [DECISION] `price_versions` rows are **append-only**. Updating a rate in place would rewrite the cost of every historical `usage_records` row that references it (D14 requires resolvability).
- [DECISION] `estimated = true` always carries a non-zero bound, never `0`: an unmetered call that looks free is the failure mode this field exists to prevent.
- [DECISION] The estimator is an upper bound on purpose (UTF-8 bytes for tokens, max output, surcharge applied) — the platform caps in D1 depend on never underestimating.
- [OPEN] **`IPriceCatalog` ownership:** D21 references `IPriceCatalog.GetActive(queuedAt)` but no feature plan declares its owner. This task creates it in 02.2 (`Infrastructure/Persistence/Queries/PriceCatalog.cs`); if 12.1.2 claims it at M2, the port moves and the P implementation stays here.
- [DECISION] **Credit ledger DI switch at M2 (12 CR-5):** the P registration `ICreditLedger → MeteringOnlyCreditLedger` (02.2.2-T2) is swapped for `ICreditLedger → CreditService` at M2; `ICreditLedger` gains `GrantAsync`, `ExpireAsync`, `VoidPaymentLotsAsync`, `GetOpenReservationAsync` (12 README D2). Callers compiled against the port — including this task's `IUsageMeter`/cost-recording path — do not change.
- ⚠️ `SurchargeThresholdTokens = 272_000` and "applies to the whole request" are read from O3's wording ("> 272K input tokens cost 2× input and 1.5× output"); the exact provider rule for a partially-cached request above the threshold should be re-checked against the pricing page at implementation time — the guard is a **safety** multiplier, so an over-estimate is acceptable and an under-estimate is not.
- ⚠️ `usage_records` column list is owned by 09's migration (CR-4 adds the new `operation` values); this task writes but does not create the table.
