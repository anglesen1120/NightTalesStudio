## Goal

Every generated draft and every brief is checked with the free moderation endpoint before the expensive path completes: a refusal or a `content_filter` stop becomes `story_moderated` with a `moderation_events` row, a brief flag fails the run **before any paid call**, and a blocking category on the final draft is recorded and blocks approval — with the flagged text never echoed to the client or the log.

## Design

### Port

```csharp
// src/NightTales.Application/Abstractions/Moderation/IContentModerator.cs  (D12)
public interface IContentModerator
{
    ValueTask<ModerationResult> CheckAsync(IReadOnlyList<string> texts, ModerationStage stage, CancellationToken ct);
}
public sealed record ModerationResult(bool Flagged, IReadOnlyList<string> Categories, IReadOnlyDictionary<string, double> Scores);
public enum ModerationStage { Brief, Draft, AutopilotGate, BibleProposal, Ideas, FindSources }
```

`ModerationStage` extends D12's three stages with the TL-ruling values (`bible_proposal`, `ideas`, `find_sources`) so series-level runs can record a refusal with `stage = <kind>` (D8). `AutopilotGate` stays owned by 02.8.2.

### Adapter

```csharp
// src/NightTales.Infrastructure/OpenAI/OpenAiContentModerator.cs
internal sealed class OpenAiContentModerator(ModerationClient client, IUsageMeter meter, ModerationOptions options) : IContentModerator;
```

`POST /v1/moderations`, model `omni-moderation-latest` (O7, **free**). Each text is chunked to ≤ 8,000 chars ⚠️ (no documented limit); a text longer than the cap is split and the **union** of the flagged categories is returned (a chunked flag is still a flag). One `usage_records` row per call with `provider = openai`, `operation = moderation`, `cost_usd = 0`, `estimated = true` (the endpoint returns no usage). Config `OpenAi:Moderation:Model` (default `omni-moderation-latest`), `OpenAi:Moderation:MaxCharsPerChunk` (default `8000`), `OpenAi:Moderation:TimeoutSeconds` (default `15`, TL T21).

### Stage behaviour

| Stage | Called from | Texts | On `flagged` |
|---|---|---|---|
| `Brief` | `GenerateStoryJob` step 0b (02.2.2-T3) | `episode.Brief`, `episode.Title` | the run fails `story_moderated` **before** any paid call, refund, `counts_toward_limit = true`; `moderation_events.stage = 'brief'` |
| `Draft` | `GenerateStoryJob` step 3 | final `title`, `body`, `description`, `tags` | run **succeeds**; `audit.v1.moderation = { flagged: true, categories }`; a blocking category blocks approval downstream (02.3.2/02.3.3 read it); any category writes a row |
| `BibleProposal` / `Ideas` / `FindSources` | the series-level jobs (02.6.3 / 02.8.1 / 02.7) | that kind's output text | the run fails `<kind>_moderated`; a `moderation_events` row with `stage = <kind>` |
| `AutopilotGate` | 02.8.2-T2 | narration, metadata, scene prompts | 02.8.2's thresholds (not this task) |

### Refusal / `content_filter` mapping (D7, O6)

| Signal | Detected as | Result | Run / events |
|---|---|---|---|
| Refusal | a content part `ResponseContentPartKind.Refusal` (O6) | `TextCallResult.Moderated(categories?)` | `story_moderated` + `moderation_events(source = openai_text, stage = draft)`; refund; **counted** |
| Content filtering | `incomplete_details.reason == "content_filter"` (O6) | `TextCallResult.Moderated(categories?)` | as above |
| Blocked **input** | no documented error code ⚠️ (O6) | falls through to `ProviderError` (other 4xx) → `story_generation_failed` | not counted, refunded |

The refusal/`content_filter` branch lives in 02.2.1-T2's `OpenAiTextClient` outcome mapping; this task owns the moderator port, the brief/draft checks and the `moderation_events` write. The mapping is driven by the outcome, **never** by an error code (O6's ⚠️).

### `moderation_events` row (D12)

Columns used: `user_id`, `episode_id` (null for series-level kinds), `source = 'openai_text'`, `stage`, `categories text[]`, `excerpt` (≤ 300 chars of the flagged segment), plus the house `id`/`created_at`. `excerpt` comes from **our own** brief or draft, never from a source text or a stored version (D19/D22). Retention: deleted with the episode (00 §6 L287 + 13).

### Blocking categories on the draft (human path, D12)

`sexual/minors`, `self-harm/instructions`, `illicit/violent`, `hate/threatening` are **blocking** — they land in `audit.v1.moderation` as objective issues that block approval. Every other category is an advisory hint only. The run still succeeds in both cases.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Moderation endpoint 5xx/timeout after the retry budget | **fail closed** → `story_generation_failed` (never a silent pass) |
| Text longer than the chunk cap | split; a flag in any chunk flags the whole text |
| Moderation returns no usage | `estimated = true`, `cost_usd = 0` (the endpoint is free) |
| Blocked input with no documented error code (O6 ⚠️) | falls through to `ProviderError` → `story_generation_failed` (not counted) |
| Series-level run flagged | run fails `<kind>_moderated`, `moderation_events.stage = <kind>`, no episode touched |
| `IModerationEventWriter` DB failure | logged; the run outcome is unchanged (the event row is evidence, not control flow) |
| Rollback | remove the DI registration; the job's 0b/3 calls are behind the same port |
