# 02.4.2-T1 — Rolling-24 h generation limit, `Retry-After` and the episode row lock

| Story | Size | Area | Depends on | Blocks | Phase / flag |

## Goal

FR-02-7 is enforced as a **rolling 24 h** window over counted generation runs: a sixth user-triggered story generation for an episode inside the window returns `429 story_generation_limit` with an accurate `Retry-After`, and the count, the limit check and the run insert cannot interleave because they share one transaction on the episode row lock.

## Design

### The check

```csharp
// src/NightTales.Application/Features/Stories/Generation/IGenerationLimitGuard.cs
public interface IGenerationLimitGuard
{
    ValueTask<ErrorOr<Success>> CheckAsync(Guid episodeId, Guid userId, CancellationToken ct);
}
// src/NightTales.Infrastructure/Persistence/Queries/GenerationLimitGuard.cs
internal sealed class GenerationLimitGuard(IAppDbContext db, GenerationLimitOptions options, IClock clock) : IGenerationLimitGuard;
```

One round trip, two aggregates (plan §4 U6):

```sql
SELECT COUNT(*) AS counted, MIN(queued_at) AS oldest
FROM generation_runs
WHERE episode_id = @episodeId
  AND kind       = 'story'
  AND trigger    = 'user'
  AND counts_toward_limit
  AND queued_at  > now() - make_interval(hours => @windowHours);   -- Story:LimitWindowHours, default 24
```

`counted >= Story:DailyGenerationLimit` (default **5**, FR-02-7) → error `story_generation_limit` (429).

`Retry-After` = the seconds until the **oldest** counted run leaves the window, floored at 1:

```text
Retry-After = max(1, ceil(extract(epoch from oldest + make_interval(hours => @windowHours) - now())))
```

The status is 429 and the body is ProblemDetails with `code = story_generation_limit` plus the same `Retry-After` header (D8 L255). The count is per **episode** and per user-triggered story run — not per series and not per account.

### Race safety (owned here, used by T2)

The count and the run insert happen in **one transaction**, and the transaction takes the episode row lock **first**:

```sql
SELECT id FROM episodes WHERE id = @episodeId FOR UPDATE;
```

`IAppDbContext.LockEpisodeForUpdateAsync(Guid episodeId, CancellationToken ct)` (Infrastructure, raw `FromSqlInterpolated`) is called as step 1 of the `GenerateStoryCommand` handler — *before* the state check, so the status read and the count see one consistent snapshot. Two concurrent generate calls for one episode serialise on the row; the loser then fails T2's step 6 with `story_generation_in_progress`. The partial unique index `ux_generation_runs_active_episode` is the second backstop. Serialisable isolation is **not** required.

### Counting table (D2, the authority for the tests)

| Outcome | `status` | `error_code` | `counts_toward_limit` |
|---|---|---|---|
| saved a version | `succeeded` | — | **true** |
| refusal / `content_filter` / brief flagged | `failed` | `story_moderated` | **true** |
| invalid output twice | `failed` | `story_invalid_output` | false (platform) |
| 5xx / timeout / other 4xx after the retry budget | `failed` | `story_generation_failed` | false (platform) |
| `provider_funds_exhausted` / over a spend cap | `queued` → `cancelled` | pause reason in `error_detail` | false |
| sweeper timeout / stuck `queued` > 12 h | `failed` / `cancelled` | kind's `*_generation_failed` | false |
| cancelled (admin / account deletion) | `cancelled` | — | **true** |

Autopilot runs (`trigger = autopilot`) are **not** counted here — D17's per-run caps (≤ 2 story generations) govern them.

| Config key | Default | Meaning |
|---|---|---|
| `Story:DailyGenerationLimit` | `5` | FR-02-7, per episode per rolling 24 h |
| `Story:LimitWindowHours` | `24` | the window length (a config so the rule is testable without clock games) |

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Exactly at the limit (`counted == 5`) | the 6th is rejected; the 5th was accepted |
| The oldest counted run is a moderated run | it counts, so it can be the one that gates the window (correct: the user's content caused it) |
| All counted runs are older than the window | `counted = 0`, `oldest = NULL` → success; `Retry-After` is never computed from `NULL` |
| Clock skew between app and DB | the window is computed **in SQL** (`now()`), so one clock rules |
| A platform failure inside the window | not counted → does not consume the user's budget |
| Rollback | remove step 5; the runs stay in the table and the rule is off |
