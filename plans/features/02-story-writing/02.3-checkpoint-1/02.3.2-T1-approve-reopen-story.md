## Goal

`POST /api/v1/episodes/{id}/story/approve` locks the exact reviewed version (`episodes.approved_story_version_id` + `story_approved`) behind an `If-Match` precondition and a fixed, observable precondition order, `POST …/story/reopen` returns the episode to `story_review`, both raise their D21 domain event, and the render path reads the approved text through a single port.

## Design

### Commands

`src/NightTales.Application/Features/Stories/Commands/ApproveStory/`, `…/ReopenStory/`

```csharp
public sealed record ApproveStoryCommand(Guid EpisodeId, string IfMatch, AttestationInput? Attestation,
    ApprovalSource Source = ApprovalSource.User) : IRequest<ErrorOr<ApprovedStoryDto>>;

public sealed record AttestationInput(bool Accepted, string TextVersion);   // defined here, validated by 02.3.3

public sealed record ReopenStoryCommand(Guid EpisodeId, string IfMatch) : IRequest<ErrorOr<EpisodeStoryStateDto>>;

public sealed record ApprovedStoryDto(Guid EpisodeId, Guid StoryVersionId, string Etag, string Status,
    DateTimeOffset ApprovedAt);
```

`AttestationInput`/`ApprovalSource` live here so 02.8.2's autopilot path can call the same command with `Source = ApprovalSource.Autopilot` without a second route.

### Approve precondition order (fixed; each check is asserted before the next)

Rows 3–6 **are** the sub-checks of `IStoryApprovalGate.ValidateAsync(episode, version, attestation, ct)` — numbered 3a–3e in 02.3.3-T1 (3a is the topic switch; 3d, similarity, runs for every topic) — while rows 1–2 and 7–8 stay in the handler. The gate returns the accepted attestation text version (null for fiction) so the handler can audit it.

| # | Check | Failure |
|---|---|---|
| 1 | load the episode; `status == StoryReview` → proceed. `status == StoryApproved` **and** `If-Match` matches `approved_story_version_id` → 200 no-op (idempotent re-approve, no audit, no event). Otherwise | 409 `episode_invalid_state` |
| 2 | `StoryEtag.RequireAndMatch(ifMatch, episode.CurrentStoryVersionId)` | 428 `if_match_required` / 412 `story_version_conflict` |
| 3 | **true-crime only** (`topic = true_crime`): fact sheet current, via the fixed port `IFactSheetGuard.EnsureApprovedAsync(episodeId, topic, ct)` [02.5.3, D21] — no new port | 409 `story_fact_sheet_outdated` |
| 4 | **true-crime only**: ≥ 2 cited fetched sources (F13) | 409 `story_sources_required` |
| 5 | **any topic, whenever the episode has url sources** (02 §5.9 "only true-crime and sourced episodes are checked"; FR-02-10): `SimilarityApprovalGuard.Classify(score, options)` (Domain, 02.5.6-T1) must not be `Block`, recomputing the score first when it is null (**T31**: `IsScorable` → `Score(...).Score` over the **sources corpus only**, the same corpus D21 stage 6 scores and 02.5.6-T2 calibrates against) | 409 `story_too_similar_to_source` |
| 6 | **true-crime only**: attestation accepted with the current text version | 400 `story_attestation_required` |
| 7 | `version.AuditReport.Moderation` has no blocking category (D12: `sexual/minors`, `self-harm/instructions`, `illicit/violent`, `hate/threatening`). When the block is absent or `stale = true` (an edit during a moderation outage kept the previous verdict, 02.3.1-T1), re-run the **free** `IContentModerator` check once, apply the fresh verdict and **write it back** with `stale = false`; the kept verdict's categories still gate in the meantime | 409 `story_moderated` (D8 HTTP table, ✅ T30) |
| 8 | commit | — |

Rationale for the order: 1–2 are cheap and idempotent; 3–5 are deterministic server-side checks (fact sheet, sources, similarity) and run **before** the human action, so the attestation tick (6) is only ever requested for an approval that can actually proceed; the moderation verdict is refreshed last (7), once, before the commit.

On success (single transaction): `episode.ApproveStory(currentStoryVersionId)` → `approved_story_version_id = current_story_version_id`, `status = StoryApproved`, `approved_at = now`; `audit.LogAsync("episode.story_approved", data: new { episode_id, story_version_id, approval_source })`; for true crime also `audit.LogAsync("episode.true_crime_attested", data: new { story_version_id, text_version })` (the gate returns the accepted text version); `outbox.Add(new StoryApproved(episodeId, seriesId, userId, storyVersionId, command.Source))`. `EpisodeUpdated` follows from the outbox projection (09.5.3), so the UI needs no second event (README §10 T2 precedent).

### Reopen

`story_approved` only; `StoryEtag.RequireAndMatch(ifMatch, episode.ApprovedStoryVersionId ?? episode.CurrentStoryVersionId)`; sets `status = StoryReview`, `approved_story_version_id = null` [DECISION — an approval must not survive a reopen, or a render could pick up a version the user just unlocked], `approved_at = null`; audit `episode.story_reopened` (`data { episode_id, story_version_id }`); `outbox.Add(new StoryReopened(...))`. From `rendering` → 409 `episode_invalid_state` (D9's ETag stays valid; the status check fails first).

### Render hand-off port

`src/NightTales.Application/Abstractions/Stories/IStoryRenderInputProvider.cs`

```csharp
public sealed record StoryRenderInput(Guid StoryVersionId, string Body, IReadOnlyList<string> Keywords,
    string Title, string Language, LengthTier Tier,
    IReadOnlyList<SegmentKeywords> Segments);   // 03 CR-13: (segment address hook|p:<i>|ending, keywords) in story order

public interface IStoryRenderInputProvider
{
    ValueTask<ErrorOr<StoryRenderInput>> GetAsync(Guid storyVersionId, CancellationToken ct);   // T28 / CR-18
}
```

Implementation `StoryRenderInputProvider` (Application `Features/Stories/Render/`): takes the **approved** version id (09.6.1 resolves `episodes.approved_story_version_id` and passes it in — T28/CR-18, never `current_story_version_id`), loads that version and projects `Body` (D3) + `Keywords` (ordered, D3) + `Title` + `Language` (series) + `Tier` (episode `length_tier`) + `Segments` (D22 address + keywords per segment, story order; `SegmentKeywords` is Domain `Stories/Keywords/`, 03 CR-13); unknown id → `Error.NotFound`, and the caller treats a missing approved version as `episode_invalid_state`. 05.5.1 passes `Body` → MPT `video_script`; `video_terms` are built from `Segments` by 03 `RenderImagePlanner` + `ScenePromptBuilder` (03 D3/D4, 03 CR-13). After a reopen `approved_story_version_id` is null, so the port cannot return a version the user just unlocked.

### Routes

`src/NightTales.Api/Endpoints/StoryEndpoints.cs` — `MapPost("…/story/approve")`, `MapPost("…/story/reopen")`; both owner-authorized, both read `Request.Headers.IfMatch`, both return the new `ETag` header (`sv-` of the approved/current version). Approve accepts `{ "attestation": { "accepted": true, "textVersion": "ta.v1" } }` and ignores it entirely for non-true-crime topics.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| A revision (02.6.2) lands between view and click | `current_story_version_id` moved → 412, the user re-reads and re-approves (F11) |
| Two tabs approve at once | one wins; the loser gets 412 or 409, never a second `approved` transition |
| Approve without `attestation` on true crime | 400 `story_attestation_required` (gate, not a null deref) |
| `audit_report` absent on the version | moderation check is skipped as unknown; the UI shows a hint; approve proceeds (only D12's blocking categories are a gate, and an absent report means they were never evaluated) |
| Episode has no `series_id` (should be impossible) | `episode_invalid_state` with a warning log — never a null-reference in the event payload |
| Renderer calls `GetAsync` mid-approval | reads a committed snapshot: either the old approved version or the new one, never a mix |
| Rollback | status transitions are additive; reverting leaves `story_approved` rows that the render port still reads correctly |
