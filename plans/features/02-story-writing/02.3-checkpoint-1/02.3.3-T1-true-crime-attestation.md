# 02.3.3-T1 — True-crime guard + attestation (`ta.v1`)

| Story | Size | Area | Depends on | Blocks | Phase / flag |

## Goal

A `true_crime` episode cannot be generated without an approved fact sheet, and cannot be approved without ≥ 2 distinct fetched sources that are each cited by a kept fact, without a current fact sheet, and without an explicit attestation tick against the current attestation text version; the tick is recorded in `audit_logs` with the story version id. This task also owns the **source-similarity block**, which is *not* topic-scoped: by 02 §5.9 it applies to any episode with url sources, fiction included (sub-step 3d).

## Design

### Attestation text: version `ta.v1`, two languages

Embedded resources, loaded through `PromptCatalog`'s manifest (D5):

```
prompts/shared/attestation.ta.v1.vi.md
prompts/shared/attestation.ta.v1.en.md
```

`manifest.json` entries keyed **relative to `prompts/`** (README §10 T27, matching `LinkBase="Prompts"`): `"shared/attestation.ta.v1.vi.md"` and `"shared/attestation.ta.v1.en.md"`, each `{ "version": "ta.v1", "sha256": "…" }`; the existing start-up check covers them (a missing file or a hash mismatch fails boot). Content covers the three clauses of story 02.3.3:

1. every fact in this script is supported by the listed sources;
2. no private person is accused of anything the sources do not establish;
3. victims are treated respectfully.

`Story:TrueCrime:AttestationVersion` (default `ta.v1`) is the single accepted value. A tick whose `TextVersion` differs → `story_attestation_required`, so a wording change invalidates every stored tick. The text is exposed to the UI as `currentStory.attestation { required, textVersion, text, acceptedAt }` (CR-7 extension; alternative route in the plan's §10 open item).

### Guard on generate (`draft → story_generating`, P3)

Already wired by 02.2.2-T2/T3; this task owns the true-crime branch and its tests:

```csharp
// 02.2.2-T2 handler, before dispatch
var sheet = await factSheetGuard.EnsureApprovedAsync(episode.Id, episode.Topic, ct);
if (sheet.IsError) return sheet.Errors;                    // 409 fact_sheet_required
run.Facts = sheet.Value.Facts; run.FactSheetId = sheet.Value.FactSheetId;
```

`ApprovedFactSheet.None` (fiction) is a success with no facts. The job re-checks at start: if the approved sheet id changed since the command, the run fails `story_generation_failed` with detail `fact_sheet_outdated` and `counts_toward_limit = false` (D21/D2) — a platform reason, not a user error.

### Approval gate (`IStoryApprovalGate`, replaces `NullStoryApprovalGate`)

`src/NightTales.Application/Features/Stories/Approval/StoryApprovalGate.cs`

```csharp
public sealed class StoryApprovalGate(
    IFactSheetGuard factSheets, IStorySourceRepository sources, IFactRepository facts,
    IOptions<StoryOptions> story, IOptions<SimilarityOptions> similarity) : IStoryApprovalGate
{
    public async ValueTask<ErrorOr<string?>> ValidateAsync(
        Episode episode, StoryVersion version, AttestationInput? attestation, CancellationToken ct);
}
```

Returns `ErrorOr<string?>` where the value is the accepted text version (null for fiction) so the handler can audit `episode.true_crime_attested` without re-reading config.

Sub-order (fixed by 02.3.2-T1's table):

| Sub-step | Rule | Failure |
|---|---|---|
| 3a | `episode.Topic != Topic.TrueCrime` → skip 3b, 3c and 3e (fiction has no fact sheet and no attestation); **3d still runs** because similarity is source-scoped, not topic-scoped (02 §5.9) | — |
| 3b | `version.FactSheetId == (await factSheets.EnsureApprovedAsync(...)).FactSheetId` (F12) | 409 `story_fact_sheet_outdated` |
| 3c | F13: `sources.Count(IsQualifying) ≥ 2` where `IsQualifying(s) = s.Kind == Url && s.Status == Fetched && s.ContentSha256 is not null && facts.Any(f => f.Kept && f.SourceIds.Contains(s.Id))`, and the qualifying set has ≥ 2 distinct `ContentSha256` | 409 `story_sources_required` |
| 3d | **Not topic-scoped** — runs for any episode with url sources (02 §5.9): `SimilarityApprovalGuard.Classify(version.SimilarityScore, similarity.Value)` (Domain, 02.5.6-T1) is not `Block`. By **T31** a null score is recomputed when the episode has url sources: `if (!SimilarityScorer.IsScorable(story, corpus, opt)) score = null; else score = Score(story, corpus, opt).Score;` then `Classify(score, options)` (`Score` is non-nullable; `IsScorable` is false for an empty corpus or a story under `Similarity:MinTokens` = 50, so the score legitimately stays null and `Classify` returns `Pass`) | 409 `story_too_similar_to_source` |
| 3e | `attestation is { Accepted: true }` and `attestation.TextVersion == story.Value.TrueCrime.AttestationVersion` | 400 `story_attestation_required` |

The F13 query is one round trip: `SELECT s.*, count(f.id) FILTER (WHERE f.kept) FROM story_sources s LEFT JOIN fact_sources …` — or, since `IFactSheetGuard` already returns `AliasToSourceId`, evaluate in memory over the approved sheet's facts joined to the episode's `story_sources` (preferred: no new query, and it is exactly the "kept fact" semantics of F13). Domain diversity is **not** checked (F13: advisory hint only, owned by 02.3.4-T1).

### Audit

Handler, after the gate succeeds and the episode transitions (02.3.2-T1 step 5):

```csharp
await audit.LogAsync("episode.story_approved", Category.Episodes, Visibility.User,
    data: new { episode_id, story_version_id, approval_source });
if (acceptedTextVersion is not null)
    await audit.LogAsync("episode.true_crime_attested", Category.Episodes, Visibility.User,
        data: new { story_version_id, text_version = acceptedTextVersion });
```

`data` carries ids, versions and codes only (D13) — never the clause text or the story body.

### Config

```jsonc
{ "Story": { "TrueCrime": { "AttestationVersion": "ta.v1", "MinCitedSources": 2 } } }
```

`MinCitedSources` default 2; validated at start-up (`1 ≤ MinCitedSources ≤ 10`, matching the per-episode source cap).

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| A fact sheet is re-approved while the story sits in `story_review` | `fact_sheet_id` differs → 409 `story_fact_sheet_outdated`; the UI offers "regenerate from the new sheet" or reopen (F12) |
| Fact ids are not stable across sheet versions | never compared across versions: only `fact_sheet_id` is compared (F12) |
| Source rows were deleted after the story was written | the citation join returns fewer qualifying sources → 409 `story_sources_required`; the message names the missing count, never the URLs (D19) |
| `similarity_score` is null (scoring skipped) | ✅ **T31:** recompute it (pure, local) when the episode has url sources, then classify; with no corpus it stays null, `Classify` returns `Pass` and the UI shows no similarity hint. A null score never blocks by itself |
| Attestation text changed (`ta.v1` → `ta.v2`) with episodes mid-review | their tick version is stale → 400; the dialog re-renders the new text |
| Attestation tick sent for a fiction episode | ignored (no row, no error) |
| Two sources on the same registrable domain | qualifies — F13's domain diversity is advisory only |
| Rollback | disabling the gate is not an option (liability control); revert the deploy |
