# 02.3.4-T1 — `StoryQualityChecker` rules

| Story | Size | Area | Depends on | Blocks | Phase / flag |

## Goal

One pure Domain service turns a `story.v1` draft plus its context into a deterministic, ordered list of quality issues — each with a stable rule id, a severity, an objective/taste kind, a D22 segment address, a config-driven threshold and a bilingual message key — so the editor can warn before approve and the review model can receive the same objective issues.

## Inputs

- README: **D3** (validator rules, derived fields, metadata limits), **D4** (length bands, token rule, segment ranges, ±15 % objective boundary, `K = 6` keywords/min), **D12** (`audit_report.moderation` blocking categories), **D21** (`StoryQualityChecker.Check(StoryContentV1, StoryCheckContext) → QualityReport`; Domain `Stories/Quality/`), **D22** (`audit.v1.local.issues` layout, segment addressing, `evidence` ≤ 200 chars of our own draft), **F07** (length is per tier × language), **F09** (keyword totals vs `ceil(D × K)`), **F38** (Domain folder `Stories/Quality/`), **CR-5** (`KeywordRules` lives in Domain `Stories/Keywords/` and is shared with 03.2.2).
- 02.1.2-T1: `KeywordRules` (English, 3–12 words, person-name heuristics, gore list).
- 02.2.1-T1: `StoryDraftValidator` (owns the hard, save-blocking rules — this checker must not duplicate a rule that the validator already enforces as a hard error, except where the story requires a *hint*).
- 02.2.3-T1: `TextNormalizer`/tokenizer (D4 token rule) — reused, never re-implemented.
- 02.5.6-T1: `SimilarityApprovalGuard.Classify(double?, SimilarityOptions) → { Pass, Warn, Block }` (the only similarity boundary; `Q-SIM-01`/`Q-SIM-02` read its verdicts) and `Shingler`/`TextNormalizer` for the internal-repetition rule.

## Design

### Types (`src/NightTales.Domain/Stories/Quality/`)

```csharp
public enum QualitySeverity { Advisory, Blocking }
public enum QualityKind { Objective, Taste }
public enum QualitySegmentKind { Title, Hook, Paragraph, Ending, Meta }

public sealed record QualityIssue(string RuleId, QualitySeverity Severity, QualityKind Kind,
    string Segment,            // D22 addressing: "title" | "hook" | "p:3" | "ending" | "meta"
    string MessageKey,
    string Evidence,           // ≤ 200 chars of OUR draft only (D22)
    string? RepairDirection,   // short imperative, e.g. "cut to 1-2 keywords"
    decimal? Measured, decimal? Threshold);

public sealed record QualityCounters(int Tokens, int Segments, int Keywords, int Paragraphs,
    double? SimilarityScore, double? InternalShingleShare);

public sealed record QualityReport(IReadOnlyList<QualityIssue> Issues, QualityCounters Counters)
{
    public bool HasBlocking => Issues.Any(i => i.Severity == QualitySeverity.Blocking);
    public IReadOnlyList<QualityIssue> Hints => Issues;   // the DTO projection sorts objective-first
}

public sealed record StoryCheckContext(EpisodeSnapshot Episode, LengthTarget Length, StoryRules Rules,
    Language Language, IReadOnlyList<FactForWriter>? Facts, IReadOnlyList<FactSourceRef> FactSources,
    double? SimilarityScore, ModerationResult? Moderation, bool ModelReviewStale,
    IReadOnlyList<string>? FactSheetTitles,
    NameCorpus Names, RenderImagePlan? Plan);   // 03 CR-14: render linter issues + scene-budget hints (03.2.2-T2)

public sealed class StoryQualityChecker
{
    public QualityReport Check(StoryContentV1 content, StoryCheckContext ctx);
}
```

Purity contract: no I/O, no clock, no randomness; issues are emitted in a fixed order (`RuleId` ordinal, then segment index) so `audit_report.local.issues` is stable and diffable; the report never contains source text, fact statements or URLs.

### Rule table (the deliverable)

`K = ceil(D × 6)` where `D` = the tier's target minutes (D4); `D4` = the tier row of the D4 table; segments are `hook + paragraphs + ending`.

| Rule id | Severity | Kind | Segment | Algorithm | Threshold (config key · default) | Message key |
|---|---|---|---|---|---|---|
| `Q-LEN-01` | Blocking | Objective | `meta` | token count (D4 rule) > 15 % outside `[MinTokens, MaxTokens]` | D4 table (`Story:Length:Rate:{lang}`) | `quality.length_far_out_of_range` |
| `Q-LEN-02` | Advisory | Objective | `meta` | token count inside the 15 % band but outside the target range | `Story:Quality:LengthTolerance` · `0.15` | `quality.length_out_of_range` |
| `Q-SEG-01` | Blocking | Objective | `meta` | segment count outside `[MinSegments, MaxSegments]` | D4 table | `quality.segment_count_out_of_range` |
| `Q-HOOK-01` | Blocking | Objective | `hook` | `hook.text` empty or < 3 tokens | `Story:Quality:MinHookTokens` · `3` | `quality.hook_missing` |
| `Q-HOOK-02` | Advisory | Objective | `hook` | sentence count > `MaxHookSentences` | `Story:Quality:MaxHookSentences` · `3` | `quality.hook_too_long` |
| `Q-KW-01` | Advisory | Objective | each of `hook`,`p:<i>`,`ending` | keyword count outside `[1, 2]` per segment | `Story:Quality:KeywordsPerSegment` · `[1,2]` | `quality.keyword_count_per_segment` |
| `Q-KW-02` | Advisory | Objective | `meta` | total keywords > `ceil(D × KeywordsPerMinute)` (F09) | `Story:Quality:KeywordsPerMinute` · `6` | `quality.keyword_total_above_cap` |
| `Q-KW-03` | Advisory | Objective | the segment | any keyword fails `KeywordRules` (CR-5: English, 3–12 words, no person names, no gore) | `KeywordRules` (02.1.2) | `quality.keyword_invalid` |
| `Q-KW-04` | Advisory | Objective | `meta` | duplicate keywords across segments (case-insensitive, NFC) | — | `quality.keyword_duplicate` |
| `Q-REP-01` | Advisory | Objective | later of the two segments | two sentences equal after normalisation and ≥ `RepeatedSentenceMinTokens` tokens | `Story:Quality:RepeatedSentenceMinTokens` · `12` | `quality.repeated_sentence` |
| `Q-REP-02` | Advisory | Objective | the segment | internal 8-token shingle share of the draft > `MaxInternalShingleShare` | `Story:Quality:MaxInternalShingleShare` · `0.25` | `quality.repetitive_phrasing` |
| `Q-NAME-01` | Advisory | Taste | the segment | true crime only: a capitalised token pair not present in any `FactSheetTitles`/`FactSources` title (person-name heuristic, F31-style, never a claim) | `Story:Quality:NameHeuristic` · `true` | `quality.possible_real_name` |
| `Q-FACT-01` | Advisory | Objective | each `p:<i>` | true crime only: paragraph with `beat ≠ setup` and `fact_refs = []` while the story has ≥ 1 fact — fires **unconditionally**, no config gate (✅ **T32**), never blocking | — | `quality.fact_refs_missing` |
| `Q-META-01` | Blocking | Objective | `meta` | title ≤ 100 no `<`/`>`; description ≤ 1,000; tags ≤ 15 × ≤ 30, total ≤ 400 (D3) | D3 limits | `quality.metadata_invalid` |
| `Q-MD-01` | Blocking | Objective | the segment | markdown, brackets, list markers or a URL in `text` (D3) | — | `quality.formatting_invalid` |
| `Q-MOD-01` | Blocking | Objective | `meta` | `ctx.Moderation` flagged with a D12 blocking category | D12 list | `quality.moderation_blocked` |
| `Q-SIM-01` | Advisory | Objective | `meta` | `SimilarityApprovalGuard.Classify(ctx.SimilarityScore, options)` = `Warn` (the verdict owns the thresholds; ✅ T31: a null score never warns) | `Similarity:WarnAbove` (02.5.6) | `quality.similarity_warn` |
| `Q-SIM-02` | Blocking | Objective | `meta` | **any topic with url sources** (02 §5.9): `SimilarityApprovalGuard.Classify(...)` = `Block` (the same verdict the approve gate acts on — one boundary, 02.5.6-T1) | `Similarity:BlockAbove` · `0.97` (calibrated by 02.5.6-T2; was `0.15`) | `quality.similarity_blocked` |
| `Q-REVIEW-01` | Advisory | Taste | `meta` | `ctx.ModelReviewStale` (F25) — the review no longer describes this text | — | `quality.model_review_stale` |
| `Q-TIER-01` | Advisory | Objective | `meta` | the episode has no `length_tier`, so length cannot be judged | — | `quality.length_tier_missing` |

`Q-LEN-01`/`Q-SEG-01`/`Q-META-01`/`Q-MD-01`/`Q-MOD-01`/`Q-SIM-02` are `Blocking` because each is already enforced somewhere else (validator at save, D12 gate, true-crime gate). [DECISION] **The checker itself never gates approve**: `ApproveStoryCommand` reads `audit_report.moderation` (02.3.2-T1 step 4) and the true-crime gates, and the UI shows blocking hints as warnings but does **not** disable approve for them; approve is disabled only by the conditions in `../../10-web-ui/README.md` §10 WR6 (moderation block, true-crime precondition, keyword-linter flags that the server enforces with 409 `keywords_flagged`, unsaved draft) (10 CR-11). This keeps one authority per rule and prevents a hint-only rule from silently blocking a save the validator accepted.

### Config and validation

```jsonc
{ "Story": { "Quality": {
  "LengthTolerance": 0.15, "MinHookTokens": 3, "MaxHookSentences": 3,
  "KeywordsPerSegment": [1, 2], "KeywordsPerMinute": 6,
  "RepeatedSentenceMinTokens": 12, "MaxInternalShingleShare": 0.25,
  "NameHeuristic": true } } }
```

`StoryQualityOptionsValidator : IValidateOptions<StoryQualityOptions>` + `ValidateOnStart()`: `KeywordsPerSegment[0] ≤ [1]` and both in `[0, 5]`; `KeywordsPerMinute ∈ [1, 20]`; `LengthTolerance ∈ [0, 0.5]`; `MaxInternalShingleShare ∈ (0, 1)`; `RepeatedSentenceMinTokens ≥ 4`; every threshold used by a rule is present (a missing key fails boot, not the check).

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| No `length_tier` on the episode | `Q-TIER-01` only; length rules are skipped (never a guessed tier) |
| `ctx.Length` null (tier unknown) | length/segment rules skipped, everything else still runs |
| Empty draft (all segments empty) | `Q-HOOK-01`, `Q-SEG-01`, `Q-LEN-01` together; the checker never throws |
| Vietnamese text | the token rule (D4) counts syllables; sentence splitting must handle `!?…` and `\n` |
| Very long draft | rules are O(n) over tokens; the internal-shingle rule is O(n) with a rolling hash |
| `similarity_score` null | no similarity issue (02.3.3-T1 documents the same choice for the gate) |
| Threshold changed between the job and the edit | the edit recomputes; old issues are replaced, never merged |
| A rule throws on malformed content | the checker must not throw on data the validator rejected: every rule guards its inputs and the checker is called only after `StoryDraftValidator` passed |
| Rollback | the checker is read-only; reverting leaves previously written `audit_report.local` blocks readable |

## Notes

- (03 CR-14) The checker appends `RenderKeywordLinter.Lint(segments, ctx.Names)` issues (`keyword_name_detected`, blocking objective) and `ctx.Plan.HintCodes` (`scenes_trimmed`, `scenes_sparse`, advisory, segment `meta`). Callers load `Names` through `INameCorpusProvider` (`NameCorpus.Empty` for fiction) and pass the plan from `RenderImagePlanner` (03.2.1-T1); owner of the wiring: 03.2.2-T2.

- [DECISION] The checker emits hints; it never blocks. Blocking authority stays with `StoryDraftValidator` (save), D12's moderation gate and the true-crime gates (02.3.2-T1 step 4, 02.3.3-T1).
- [DECISION] `Q-SIM-02` reads the **same** `SimilarityApprovalGuard.Classify` verdict the approve gate acts on (02.5.6-T1), so the UI can explain a 409 with exactly the number that caused it — the boundary exists once.
- ✅ **T32 (resolved):** the fact-ref hint fires for true crime whenever `beat ≠ setup` and `fact_refs = []` — no config flag gates it (the key is removed, not defaulted) and it is never blocking, because D3 permits `fact_refs = []` on any segment.
- ⚠️ The person-name heuristic (`Q-NAME-01`) is a lexicon + capitalisation heuristic, not named-entity recognition (README F31/T15). It must never be phrased as an accusation.
