## Design

### `currentStory` block (added to the episode detail DTO)

```jsonc
"currentStory": {
  "versionId": "9d4e77ab-…", "version": 4, "source": "edited",
  "etag": "\"sv-9d4e77ab-…\"",
  "status": "story_review",              // episode status, so the editor needs no second field
  "content": { /* story.v1 + backend-added fact_sources (D3) */ },
  "body": "…", "keywords": ["…"], "wordCount": 903,
  "qualityHints": [ { "ruleId": "Q-KW-01", "severity": "advisory", "kind": "objective",
                      "segment": "p:3", "messageKey": "quality.keyword_count_per_segment",
                      "evidence": "0 keywords", "repairDirection": "add 1-2 keywords", "measured": 0, "threshold": 1 } ],
  "auditReport": { /* audit.v1 verbatim (D22) */ },
  "similarityScore": 0.021,
  "factSheetId": "1a2b…",
  "approvedStoryVersionId": "9d4e77ab-…", // null unless approved
  "attestation": { "required": true, "textVersion": "ta.v1", "text": "…", "acceptedAt": null }
}
```

`currentStory` is `null` when the episode has no story version (status `draft`). `qualityHints` is the flattened, objective-first projection of `auditReport.local.issues` ++ `auditReport.model_review.issues`; the client renders `auditReport` in the expanded "why" panel only (no recomputation, no second call). `attestation` extends CR-7 (plan §10 open item: extension vs own route).

### New routes

| Method | Route | Response |
|---|---|---|
| GET | `/api/v1/episodes/{id}/story/versions` | `StoryVersionSummaryDto[]` — `{ versionId, version, source, createdAt, wordCount, etag, similarityScore, approved, isCurrent }`, ordered `version DESC` |
| GET | `/api/v1/episodes/{id}/story/versions/{versionId}` | `StoryVersionDetailDto` — `{ versionId, version, source, createdAt, createdBy, etag, content, body, keywords, wordCount, qualityHints[], auditReport, similarityScore, factSheetId }` |

Both are owner-authorized, 404 for a foreign episode **and** for a `versionId` that belongs to another episode (never 403), and both are `AsNoTracking` projections with `content`/`audit_report` deserialised through the existing `StoryContentV1`/`AuditReportV1` converters — no new serialisation path.

`GET …/versions/{versionId}` is the CR-12 route (confirmed here, ✅ T33); the list route is already in 00 §8 (✅ T33) — no CR needed for it.

### Queries

`src/NightTales.Application/Features/Stories/Queries/`

```csharp
public sealed record GetStoryVersionsQuery(Guid EpisodeId) : IRequest<ErrorOr<IReadOnlyList<StoryVersionSummaryDto>>>;
public sealed record GetStoryVersionQuery(Guid EpisodeId, Guid VersionId) : IRequest<ErrorOr<StoryVersionDetailDto>>;
public sealed record GetCurrentStoryQuery(Guid EpisodeId) : IRequest<ErrorOr<CurrentStoryDto?>>;   // used by the episode detail handler
```

`GetStoryVersionsQuery` selects only the summary columns (no `content`, no `audit_report`) — the history list must not pull megabytes of JSON per row. `GetCurrentStoryQuery` loads one row plus the attestation text and the episode's approval state.

### Wire-up

`src/NightTales.Api/Endpoints/StoryEndpoints.cs`: `MapGet("…/story/versions")`, `MapGet("…/story/versions/{versionId:guid}")`. The episode detail handler (09.5.3, CR-7) calls `GetCurrentStoryQuery` and embeds the block; no extra HTTP round trip for the editor.

- [ ] `curl -s /api/v1/episodes/{id} | jq '.currentStory | {versionId, version, source, etag, wordCount, similarityScore, factSheetId}'` returns the current version's values and `etag` is exactly `"sv-<versionId>"`.
- [ ] `curl -s /api/v1/episodes/{id} | jq '.currentStory.qualityHints[0] | keys'` returns `ruleId, severity, kind, segment, messageKey, evidence, repairDirection, measured, threshold`; the first element is objective before any taste hint.
- [ ] On a `draft` episode with no story version, `currentStory` is `null` and the episode detail is still 200.
- [ ] `curl -s /api/v1/episodes/{id}/story/versions | jq 'length, .[0].version'` returns the count and the highest version; the payload contains no `content`/`auditReport` field.
- [ ] `curl -s /api/v1/episodes/{id}/story/versions/{versionId} | jq '.content.title, .auditReport.schema_version'` returns the version's title and `"audit.v1"`.
- [ ] `GET …/story/versions/{versionIdOfAnotherEpisode}` → 404; another user's episode → 404.
- [ ] After an edit, `isCurrent` is true only for the new version and `approved` is true only for `episodes.approved_story_version_id`.
- [ ] The detail route sets the same `ETag` header value as the PUT/approve routes for that version.
- [ ] No response body contains a source URL outside `content.fact_sources` (which is the D3 contract) and none contains another episode's data.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Version row with a `content` JSON that fails deserialisation (older schema) | 500 is unacceptable: return the summary fields and `content: null` with a warning log; the history list stays usable ⚠️ |
| `audit_report` absent | `auditReport: null`, `qualityHints: []`; the editor shows "no checks recorded" |
| Episode mid-generation (`story_generating`) | `currentStory` = the previous version (if any) plus `generation { … }` from CR-7; the editor is read-only |
| Episode reopened | `approvedStoryVersionId: null` and `attestation.acceptedAt` still shows the last tick time — the UI must treat "approved = false" as authoritative, not the attestation date |
| Large `content` (Long tier) | the detail route is one row by primary key; the list route never loads it |
| `fact_sources` in `content` | returned as stored (D3); never re-resolved from `story_sources`, so a deleted source does not break the view |
| Rollback | both routes are read-only; removing them leaves the episode detail block (CR-7) working if 09 keeps it |
