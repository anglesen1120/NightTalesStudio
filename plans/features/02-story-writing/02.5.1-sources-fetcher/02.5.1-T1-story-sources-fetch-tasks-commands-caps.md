## Goal

An episode in `draft` or `story_review` accepts up to 10 sources — pasted URLs or the user's own notes — each producing a `story_sources` row and, for a URL, exactly one `fetch_tasks` row in the same transaction; the two volume caps (30 url sources per user per rolling 24 h, 10 per episode) and the domain blocklist are enforced at the API with the D8 codes; the user can list, remove and retry sources.

## Design

### Domain (`src/NightTales.Domain/Research/`)

New: `StorySource.cs`, `StorySourceKind.cs` (`Url`, `UserNote`), `StorySourceStatus.cs` (`Pending`, `Fetched`, `Failed`, `Rejected`), `SourceUrl.cs`, `IPublicSuffixList.cs`, `DomainBlocklist.cs`, `SourceErrors.cs`, `FetchTask.cs`, `FetchTaskKind.cs`, `FetchTaskStatus.cs`, `Events/SourceFetched.cs`, `Events/SourceRemoved.cs`.

`SourceUrl.Parse(string input, IPublicSuffixList psl) → ErrorOr<SourceUrl>` — the single place URL syntax is decided (rules in `plan.md` §3.1). It rejects with `SourceErrors.SourceUrlInvalid` for: scheme ∉ {http, https}; an explicit port ∉ {80, 443}; any userinfo; length > 2,048; a host that is an IP literal in **any** notation (dotted-quad, decimal `2130706433`, octal `0177.0.0.1`, hex `0x7f.0.0.1`, bracketed IPv6, IPv4-mapped IPv6) — detection is `Uri.CheckHostName(host) == UriHostNameType.IPv4/IPv6` **after** the decimal/octal/hex forms are canonicalised by `Uri`, plus an explicit regex for the bare-integer form `^[0-9]{1,10}$` because `Uri` accepts it as a host name; empty host; a host with no registrable domain (`localhost`, single-label, bare TLD); unparsable. Normalisation: IDNA/punycode via `IdnMapping.GetAscii`, lowercase, strip **one** trailing dot (then re-run the single-label check), drop the fragment, drop a default port, empty path → `/`.

```csharp
public sealed record SourceUrl
{
    public string Value { get; init; }              // "https://example.com/a?b=1"
    public string Host { get; init; }               // "example.com" (punycode, no trailing dot)
    public string RegistrableDomain { get; init; }  // "example.com"
    public bool IsHttps { get; init; }
}
public interface IPublicSuffixList { string? GetRegistrableDomain(string host); }
```

`IPublicSuffixList` is a Domain port; the implementation is `Infrastructure/Research/PublicSuffixListProvider.cs` (§Steps 6). `DomainBlocklist` takes `IReadOnlySet<string>` of registrable domains and matches the **registrable domain only** (the caller passes the registrable domain of the host, so `m.youtube.com` → `youtube.com` → hit). This is deliberately simpler than suffix matching on the raw host and is equivalent given `SourceUrl` already reduced the host to its registrable domain; the raw-host suffix walk is the T1 (`SafeHttpSourceFetcher`) responsibility for redirect targets, which may be non-registrable in exotic cases.

`StorySource` — the aggregate child described in `plan.md` §3.1. Invariants enforced in the factory methods: `Kind == Url` ⇒ `Url`/`NormalizedUrl`/`RegistrableDomain` set and `NoteText` null; `Kind == UserNote` ⇒ `NoteText` set (≤ 3,000 chars after `Trim()`, non-empty) and `Url` null. `MarkFetched` requires a 64-char lowercase hex `sha256` and `textChars ≥ 0`.

[DECISION] A `user_note` row is created **`Fetched`** (not `Pending`) with `ContentSha256 = sha256(UTF8(NFC(NoteText)))`, `TextChars = NoteText.Length`, `ExtractedTextKey = null`, `FetchedAt = now`. Rationale: it has no fetch to wait for, and 02.5.3-T1 can then treat every source uniformly (text from the column when `ExtractedTextKey` is null). FR-02-4's "≥ 2 fetched **url** sources" is enforced by 02.5.4-T1 counting `kind = 'url'` only. Recorded as [OPEN] 4 in `./plan.md` §10.

`FetchTask` — `plan.md` §3.1. `Lease` throws if not `Queued`; `Heartbeat`/`Complete`/`Fail` require `Status == Leased`; `Requeue` requires `IsLeaseExpired(now)`; `Attempts` increments on `Lease`.

```csharp
public sealed record AddSourceCommand(Guid EpisodeId, string? Url, string? NoteText) : ICommand<SourceDto>;
public sealed record RemoveSourceCommand(Guid EpisodeId, Guid SourceId) : ICommand<Deleted>;
public sealed record RetrySourceCommand(Guid EpisodeId, Guid SourceId) : ICommand<SourceDto>;

    string? RegistrableDomain, string? NoteText, StorySourceStatus Status, string? ErrorCode,
```

`AddSourceValidator` (FluentValidation): exactly one of `Url`/`NoteText` non-empty; `NoteText` length ≤ `Sources:MaxNoteChars` (raw length check — the Domain re-checks after trim); `Url` length ≤ 2,048 (so an over-long URL is a validation error, not a 500). Every other URL rule is in `SourceUrl.Parse` so the API and the fetcher cannot diverge.

`AddSourceHandler` — exact order, because the codes are asserted in the acceptance checks:

1. Load the episode tracked through `IAppDbContext` (must belong to `ICurrentUser`; 404 otherwise — never 403, to avoid confirming existence).
2. State gate: `episode.Status` ∈ {`Draft`, `StoryReview`} else `ErrorOr` `episode_invalid_state` (409). `StoryApproved`, `Rendering`, `VideoReview`, `VideoApproved`, `Published` are all rejected (F26 precedent). [DECISION] Also rejected while a `story` or `fact_sheet` generation run is `queued`/`running` for the episode? **No** — adding a source during generation is harmless and blocking it would surprise the user; only 02.5.4's fact-sheet edit is state-gated.
3. `Url` branch: `SourceUrl.Parse(url, psl)` → `source_url_invalid` (400). Then `blocklist.IsBlocked(sourceUrl.RegistrableDomain)` → `source_domain_not_allowed` (400) with the message "Paste an article or record page; video and social platforms cannot be used as sources." The rejected source is **not** persisted (no `rejected` row is written on add — the code is returned in the ProblemDetails and the UI shows the message; a persisted `Rejected` row is only produced by a redirect-hop rejection inside the fetcher, where there is no HTTP response to carry the code).
4. Episode cap: `count(story_sources where episode_id = @id) >= Sources:MaxPerEpisode` → `source_limit_reached` (409). Counted over both kinds (a note consumes a slot).
5. 24 h cap (counts **creations**, not rows — F15, `(02 CR-31)`): `count(source_creations where user_id = @u and created_at > now - 24h) >= Sources:MaxUrlSourcesPerUserPerDay` → `source_fetch_limit_reached` (429). `source_creations` is an append-only ledger `(id uuidv7, user_id, created_at)` with index `(user_id, created_at)`, no URL/note/episode/source column (D13/D19) and no FK to either, so deleting a source or an episode frees no quota. The error carries `retryAfterSeconds = ceil((oldest creation in the window + 24 h) − now)`; the endpoint sets `Retry-After`. Notes are excluded (they write no ledger row). A purge of rows older than 24 h is optional (correctness never needs it); the 13.3.1 deletion engine deletes a user's rows by `user_id`.
6. Duplicate: for the URL branch, `normalized_url` already on the episode → `source_duplicate` (409). A note has no duplicate rule (the user may legitimately record two notes).
7. Insert `story_sources`; for the URL branch also insert `fetch_tasks` (`kind = FetchSource`, `status = Queued`, `url = normalizedUrl.Value`, `registrable_domain = sourceUrl.RegistrableDomain`, `not_before = now`, `attempts = 0`). Both through `IAppDbContext` in one `SaveChangesAsync` — the `UnitOfWork` behaviour wraps the command, so it is one transaction.
8. `[Audited("episode.source_added", Category.Episodes, Visibility.User)]` with `data = { sourceId, kind, registrableDomain, status }` — no URL, no note text (D13: ids, versions, scores and codes only). The ids exist only after the handler ran, so the command implements `IAuditDataFromResponse<ErrorOr<SourceDto>>` (an `IAuditData` extension: `AuditBehavior` calls `ToAuditData(response)` after a successful handler) `(02 CR-31)`; `registrableDomain` is omitted for a note.
9. Return `SourceDto`. The `Idempotency-Key` behaviour (09.4) is inherited from the command pipeline; a replayed POST returns the stored response and does **not** create a second row (tested).

`RemoveSourceHandler`: load the episode tracked, state gate as above, find the source on the episode (404 if absent or owned by another user), `Remove`, `SaveChanges` (the `fetch_tasks` FK cascade deletes a `queued`/`leased` row — [DECISION] a `leased` task is cancelled by cascade deletion rather than a status update, so a fetcher that posts a result for it gets `404 task_not_found` and drops the work; simpler than a `cancelled` status transition and the sweeper never sees it). `[Audited("episode.source_removed", …)]`.

`RetrySourceHandler`: only `status == Failed` (409 `episode_invalid_state` otherwise); state gate; re-apply the 24 h cap (429); `source.Retry(now)` → `Pending`; insert a new `fetch_tasks` row (`attempts = 0`); the partial unique index guarantees at most one live task. `[Audited("episode.source_added", …, data: { retry: true })`] — [DECISION] reuse the add action with a `retry` flag rather than adding an action key D13 does not list.

`ListSourcesHandler`: `IReadDb` no-tracking projection to `SourceListItemDto` + the `limits` block computed from the two counts — the live rows of the episode and the user's `source_creations` in the window (so the UI never guesses). `SourceListItemDto` = `SourceDto` minus `NormalizedUrl`/`ContentSha256` plus `IsCited` (false until 02.5.4-T1 fills it) and `ErrorMessageKey` (the UI copy key for the code). The extracted text is **not** returned.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Two parallel POSTs at the 9th/10th slot | the episode row lock serialises them; the loser gets 409 |
| URL with a Unicode host that maps to a single-label punycode name | `source_url_invalid` |
| URL whose host is a public suffix only (`https://co.uk/`) | `source_url_invalid` (`GetRegistrableDomain` returns null) |
| `public_suffix_list.dat` has no entry for an unknown TLD | fall back to the last two labels (the standard "unlisted TLD" rule) and log at debug; never throw |
| `NoteText` is only whitespace | validation error (400) before the Domain factory |
| Remove while a task is `leased` | cascade delete; the fetcher's result POST gets 404 and drops the work |
| Remove the last source while a fact sheet exists | allowed; 02.5.4-T1 decides what a stale sheet means (the sheet keeps its aliases) |
| Episode deleted mid-command | the FK cascade removes everything; the command returns 404 on the next load |
| `Retry-After` mapping missing in 09's mapper | it is not missing (T43/CR-20); if a future refactor drops it, the endpoint falls back to setting the header from the same `retryAfterSeconds` metadata — a 5-line change in this task, never a change in 09 |
| Migration rollback | `Down()` drops both tables; additive only, so `episodes` and existing rows are untouched |
| Public-suffix package rejected at implementation time (license/maintenance) | vendor `public_suffix_list.dat` as an embedded resource + ~60 lines of longest-match code; the port keeps the swap invisible |

## Notes

- [DECISION] The blocklist is checked **before** the caps, so a blocked domain always yields the specific 400 message rather than a cap error — the message is the user-facing explanation ("video and social platforms cannot be used as sources").
- [DECISION] A note is created `Fetched` with a content hash (see Design). If the TL prefers a distinct `Note` status, only `StorySourceStatus`, the UI chip map and 02.5.3's text lookup change — no schema change beyond a check constraint.
- [DECISION] `Rejected` rows are written only by the fetcher (a redirect hop), never by the add command: the add failure has an HTTP response to carry the code, and persisting a rejected row for every blocked paste would clutter the list.
- [DECISION T43] The `Retry-After` header for the 429 comes from 09's `ProblemDetails` mapper (CR-20), driven by the `retryAfterSeconds` metadata key this task emits. No local header setting; no change to 09 from this folder.
- ⚠️ `Nager.PublicSuffix` license/maintenance must be checked at implementation time; the vendored-list fallback is already specified so the task cannot be blocked by it.
- [DECISION SEC-5] `source_creations` rows only have to outlive the 24 h cap window. An optional retention sweep may delete ledger rows older than a few days (e.g. 7); it is not required for correctness and is not part of this task. Account erasure must cover the table: its `users` FK is `RESTRICT`, so 13.3.2 deletes the rows explicitly (13.3.1 plan §8 note).
