## Goal

Two questions the rest of 02.5.2 must not guess at are closed with measurements: **(1)** which main-text extractor we ship (in-process .NET vs a Python sidecar), decided by running both over a fixed 20-page corpus and comparing title/text quality, Vietnamese handling, license and deployment cost; **(2)** how we honour robots.txt, decided by rejecting the stale `TurnerSoftware.RobotsExclusionTools` (E4, last release 2022-08-09, predates RFC 9309 ⚠️) and writing a small, testable in-house RFC 9309 **subset spec** that 02.5.2-T1 implements.

## Inputs

- README: E1 (SmartReader 0.11.1, Apache-2.0, Readability port for netstandard2.0/2.1, depends on AngleSharp ≥ 1.5.2 ✅), E2 (trafilatura 2.2.0, Apache-2.0 since v1.8.0, Python ≥ 3.10 ✅), E3 (AngleSharp 1.8.2 MIT; NReadability abandoned → rejected), E4 (RobotsExclusionTools 0.9.1 MIT, last release 2022-08-09, predates RFC 9309 ⚠️ unmaintained); D10 (the fetcher host has no DB/storage/OpenAI — a sidecar must fit inside a container whose entire value is a minimal surface); D11 (robots semantics: token `NightTalesStudioBot`, 4xx → allow, 5xx/unreachable → disallow, 24 h per-host cache); F14 (the SSRF/abuse gaps this spike must not reopen — e.g. a robots fetch is itself an outbound request subject to every D11 rule); F19 (the precedent that a Python sidecar needs a written exception to DECISIONS §10.13).
- 02 §4 story 02.5.2 last bullet ("a main-text extraction library is chosen with a commercial-safe license and recent maintenance … decision recorded in DECISIONS.md"); 02 §5.7 ("respect robots.txt; per-domain rate limit 1 request/s").
- Plan `./plan.md` §2 (facts table), §3.1 (`IArticleExtractor` consumers), §7.2 (why the container's surface matters), §9 (the 10-page manual extraction check this spike seeds), §10 [OPEN] 7 and 8 (Crawl-delay; the `source_no_text` threshold).

## Design

### Deliverable 1 — extractor decision (measurement, not preference)

Harness: a throwaway console under `tools/extract-spike/` (⚠️ 00 §5.2 lists only `tools/mock-mpt/`; this spike's tool is deleted after the decision — see Cleanup). It takes the corpus manifest, runs each candidate, and writes `spike-report.md` + a per-page JSON.

```jsonc
// tools/extract-spike/corpus.json   — 20 pages, fixed at spike time (URLs + sha256 of the saved HTML)
[
  { "id": "vi-news-01", "lang": "vi", "url": "https://vnexpress.net/…", "htmlSha256": "…", "expectedTitleContains": "…", "expectedTextCharsMin": 800 },
  { "id": "en-news-01", "lang": "en", "url": "https://www.bbc.com/…", "htmlSha256": "…", "expectedTitleContains": "…", "expectedTextCharsMin": 1200 }
]
```

Corpus composition (20 pages): **8 Vietnamese news** (2 each from vnexpress.net, tuoitre.vn, thanhnien.vn, dantri.com.vn), **2 Vietnamese long-form/blog** (one WordPress, one with heavy inline JS), **6 English news** (bbc.com, reuters.com, apnews.com, nytimes.com, theguardian.com, npr.org), **1 Wikipedia article**, **1 government/PDF-adjacent HTML page**, **1 SPA with no server-rendered text** (expected `source_no_text` for both candidates), **1 paywalled page** (expected partial text). The saved HTML is committed to the spike folder so the comparison is reproducible without re-fetching (and so it does not depend on robots.txt or the live pages still existing).

Metrics per candidate, per page (recorded in a table in `spike-report.md`):

| Metric | How |
|---|---|
| title correct | the extracted title contains `expectedTitleContains` |
| text length | chars after whitespace normalisation, vs `expectedTextCharsMin` |
| boilerplate leakage | count of lines matching a nav/footer/cookie regex list (`cookie`, `Đăng nhập`, `Subscribe`, `Related`, `Chia sẻ`, `Quảng cáo`) |
| main-text recall | manual 5-point sample: does the text include the article's first and last paragraph |
| Vietnamese diacritics intact | NFC round-trip of the extracted text equals the input's (no mojibake, no stripped diacritics) |
| latency | p50/p95 over 5 runs per page |
| memory | peak RSS during the 20-page run |
| failure behaviour | what it returns on the SPA page and the paywall (empty? exception? a nav-only string?) |

Decision rule (recorded in `DECISIONS.md` §3 by this task, ⚠️ the TL owns the file — the task supplies the text):

- **Choose SmartReader (in-process)** unless it fails at least one of: Vietnamese diacritics intact on ≥ 19/20 pages; main-text recall on ≥ 18/20; boilerplate leakage below 10 % of extracted chars on ≥ 18/20. This is the default because it adds **zero** processes, zero runtimes and zero IPC to a container whose contract (D10) is "no DB, no storage, no OpenAI, minimal surface".
- **Choose trafilatura (sidecar)** only if SmartReader fails a rule above **and** trafilatura passes all three, **and** the TL signs the Python exception (F19 precedent: DECISIONS §10.13 says background work is C#). A sidecar also means: a second base image (or a two-stage image), a localhost HTTP contract, its own health check, its own CVE stream, and the robots/SSRF rules applied inside a runtime we do not control — all of which must be spelled out in the decision record if chosen.
- Tie-break: if both pass, SmartReader wins on deployment cost; if both fail, the fallback is **SmartReader + a `source_no_text` outcome** (we would rather fail a page than ship a second runtime) and the corpus's failures become known limitations in the report.
- ⚠️ Whichever wins, verify the licence **at spike time** (E1/E2 are stated as Apache-2.0 in the README's facts table, but vendor licenses move) and record the exact version + license + release date in the decision record.

`IArticleExtractor` (the port 02.5.2-T1 depends on — frozen here so T1 is not blocked by the outcome):

```csharp
// src/NightTales.Domain/Research/IArticleExtractor.cs   (Domain: no HTTP, no HTML dependency)
public interface IArticleExtractor
{
    ArticleExtraction Extract(string html, Uri url, string? contentType, CancellationToken ct);
}
public sealed record ArticleExtraction(string? Title, string Text, int TextChars, bool IsMainTextFound);
```

`ArticleExtraction.Text` is whitespace-normalised NFC, no HTML, no markdown. `IsMainTextFound == false` (or `TextChars < SourceNoTextThreshold`) → the caller maps to `source_no_text`. The implementation for SmartReader is `Infrastructure/Research/Extraction/SmartReaderArticleExtractor.cs` (02.5.2-T1 owns it; the spike only proves the choice).

⚠️ `source_no_text` threshold: `plan.md` §10 [OPEN] 8 proposes 200 chars. The spike's corpus is the calibration input — record the extracted length of the **shortest genuinely-article** page and set the threshold to ~60 % of it (so a nav-only extraction falls below and a short real article does not).

### Deliverable 2 — robots.txt RFC 9309 subset spec

`spike-report.md` contains a normative, implementable spec (this is what 02.5.2-T1 codes and what the T4 suite asserts). `TurnerSoftware.RobotsExclusionTools` is rejected because it predates RFC 9309 (E4) — the `Allow` directive and the longest-match rule are the parts we actually depend on, so an unmaintained pre-9309 parser is a correctness risk, not just a maintenance smell. The spec:

| Aspect | Rule |
|---|---|
| Fetch | `GET https://{host}/robots.txt`, subject to **every** D11 rule (scheme, port, no IP literals, global-unicast check, `ConnectCallback` re-check, no proxy, no cookies, ≤ 3 redirects, decompressed cap, `text/plain` or `text/html`). Timeout 5 s (`Fetcher:RobotsTimeoutSeconds`). Its own size cap: 512 KiB decompressed; larger → treat as disallow |
| Cache | in-memory, keyed by `scheme://host:port` (a robots file is per-origin), TTL 24 h (`Fetcher:RobotsCacheHours`), LRU 1,000 origins; a `Disallow` verdict is cached too (a 5xx host must not be retried on every page) |
| Encoding | UTF-8; a BOM is stripped; invalid UTF-8 → decode with replacement and parse (never throw) |
| Line handling | split on `\n` (a trailing `\r` is stripped); ignore blank lines; `#` starts a comment (only outside a value, i.e. everything from the first `#` to end-of-line is dropped); a line without `:` is ignored; the field name is lowercased and trimmed, the value is trimmed of leading whitespace only (trailing spaces are significant in a path) |
| Groups | consecutive `user-agent` lines form one group; a new `user-agent` after a non-`user-agent` line starts a new group; `allow`/`disallow` lines attach to the **current** group; directives before any `user-agent` are ignored |
| Group selection | exact, case-insensitive match on the token `nighttalesstudiobot` (the UA token is the part before `/`) wins; otherwise the `*` group; if neither exists → allow all |
| Rule matching | path = the percent-decoded path + query of the request URI; a rule value is a path prefix; `*` matches any run of characters; a trailing `$` anchors the end; the **longest** matching rule value wins (counting the pattern's length, not the matched span); on equal length `allow` wins over `disallow`; an empty `disallow` value matches nothing (allow all); a rule value without a leading `/` is treated as if it had one |
| Directives we ignore | `sitemap`, `host`, `request-rate`, `visit-time`, and every unknown field. **`crawl-delay` is honoured** [DECISION T43]: the per-host interval becomes `max(1 s, crawlDelay)`, capped at **10 s** — a `crawl-delay` above 10 s means the host wants less traffic than our own page budget allows, so the fetch is refused with `source_blocked_by_robots` rather than waiting. Config `Fetcher:CrawlDelayMaxSeconds = 10`. A malformed or negative `crawl-delay` is ignored (treated as absent, so the 1 s floor applies) |
| Limits | ≤ 1,000 rules per selected group; beyond that the extra rules are dropped and the file is treated as allow-all for the dropped part — a deliberately permissive degradation with a `robots_rule_limit_exceeded` log |
| Failure semantics (D11) | `2xx` → parse. `3xx` → follow ≤ 3 redirects (each re-checked) then parse; more → disallow. `4xx` (incl. 404) → **allow all**. `5xx`, timeout, connection failure, or unparsable-after-1 MiB of garbage → **disallow all** with `source_blocked_by_robots`. A robots fetch failure is **never** retried within the same task |
| UA token | `nighttalesstudiobot` — the lowercased first token of `Fetcher:UserAgent` (`NightTalesStudioBot/0.1.0 (+https://…/bot)`), derived at start-up, not hard-coded |

Worked examples that become the T1 unit tests (in the spec, one line each, so the implementation has an oracle): exact-group-beats-wildcard; `Disallow: /` + `Allow: /a` → `/a` allowed, `/b` denied; `Disallow: /*.pdf$` → `/x.pdf` denied, `/x.pdf?y=1` allowed; `Disallow:` (empty) → allow; two equal-length rules, one allow → allow; a group for another bot does not apply.

## Steps

1. Create `tools/extract-spike/` (throwaway): a console that downloads and **saves** the 20 corpus pages (using the spike's own simple HTTP client — do not wait for 02.5.2-T1), writes `corpus.json` with each page's `htmlSha256`, and prints the manifest for review.
2. Run candidate A: add `SmartReader 0.11.1` + `AngleSharp 1.8.2`, implement a 40-line adapter, run the corpus, dump per-page JSON (title, text, chars, latency, memory).
3. Run candidate B: `pipx`/`uv` a Python 3.10+ env with `trafilatura 2.2.0`, run the same 20 saved HTML files (no re-fetch), dump the same JSON shape.
4. Fill the comparison table and apply the decision rule; write `spike-report.md` §1 (decision + numbers + license/version/date + the `source_no_text` threshold recommendation) and §2 (the robots spec tables above).
5. Write the `DECISIONS.md` §3 text (the TL applies it — this folder never edits files outside itself): extractor, version, license, the 20-page numbers, the rejected candidates and why, and the robots decision with the E4 reason.
6. Hand `IArticleExtractor` + the robots spec + the threshold to 02.5.2-T1 (they are T1's Inputs).
7. Cleanup: keep `spike-report.md` and `corpus.json` (with the saved HTML) under the feature folder as the evidence; delete the console project and the Python env (the report says so).

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| A corpus page is unreachable at spike time | substitute the closest page from the same site and note the swap; the manifest is the record of what was actually tested |
| A site returns a paywall/consent wall to the spike's simple client | keep the page (it is a legitimate "partial text" case) and mark it in the manifest; do not spend time defeating the wall |
| SmartReader returns `IsReadable = false` on a Vietnamese page | that is a measurement, not an error — it feeds the decision rule and, if it becomes the chosen extractor, the `source_no_text` path |
| trafilatura's output differs run to run (it has internal heuristics/threading) | run each page 5 times; record the modal output; if the output is unstable, record that as a strike against it |
| Both candidates fail the rule | choose SmartReader + `source_no_text` and list the failing pages as known limitations (see the decision rule) |
| The license of a candidate changed since the README's facts table | record the actual license; a non-permissive license removes the candidate regardless of quality |
| The spike's HTML snapshots are large (20 pages) | **applied 2026-09-26:** the 20 pages total 8,205,055 B > 5 MiB, so the snapshots are **not** committed: `trial/research/corpus/html/` is gitignored and `corpus.json` + `corpus.sha256` are the reproducible input (`sha256sum -c` = 20/20; the fetch command is in `spike-report.md`). The report's numbers stay the evidence (02 T102) |

## Notes

- [DECISION] The spike saves HTML and compares offline. Re-fetching during comparison would (a) break reproducibility, (b) make the comparison depend on robots.txt and rate limits, and (c) hide latency in the network rather than in extraction.
- [DECISION] `IArticleExtractor` lives in **Domain** (`Research/`) so 02.5.2-T1's fetcher can depend on it without Infrastructure, and the `NightTales.Fetcher.Core` library (**accepted**, T40 — see `plan.md` §10 item 3) can reference Domain only.
- [DECISION] A sidecar is a **last resort** and needs a written Python exception (F19 precedent). The report must say so explicitly if it recommends one.
- [DECISION T43] `crawl-delay` **is** honoured as `max(1 s, crawlDelay)` with a 10 s ceiling; above the ceiling the fetch is refused (`source_blocked_by_robots`) instead of waiting. `Sitemap` stays ignored. This makes the per-host limiter take the robots rules as an input, so 02.5.2-T1's `IRobotsPolicy` must return the resolved interval alongside the allow/deny verdict (the spec above is the contract).
- ⚠️ The corpus must be re-checked if the chosen extractor is upgraded; the report records the version it was measured with.
