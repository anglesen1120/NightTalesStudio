## Goal

One class fetches a user-supplied URL and returns either the extracted article text or a D8 error code, with every D11 rule enforced in the order the rules must be enforced — syntax, blocklist, DNS, connect-time address re-check, manual redirects, robots, rate limit, decompressed size, content type, extraction — and with no bypass path: a caller cannot obtain a `Stream` to a non-global-unicast address, cannot follow an unchecked redirect, and cannot exceed the byte or time budget.

`ISourceFetcher` returns `ErrorOr<FetchedSource>` — a fetch failure is **data** (`SourceFetchError` in the error), never an exception, because the caller (02.5.2-T3) maps it to a result POST. Exceptions are reserved for bugs and cancellation.

### The address rule (D11 "global unicast only"), written out

`GlobalUnicastAddressValidator : IAddressValidator` (`src/NightTales.Infrastructure/Research/Http/`). Implementation: normalise, then consult a CIDR block table (default **allow**, because the IANA special-purpose registry is a closed list and every non-global entry is in the table — this is what "global unicast only" means in practice; a default-deny table would require the whole `2000::/3` allocation space).

Normalisation before any check:

1. `IPAddress.IsIPv4MappedToIPv6` → `MapToIPv4()` (covers `::ffff:a.b.c.d`).
2. IPv4-**compatible** (`::/96` with the low 32 bits non-zero, e.g. `::127.0.0.1`) → take the low 32 bits as IPv4.
3. An IPv6 address with a non-zero `ScopeId` → reject outright (a scoped address is link-local by construction).
4. `2002::/16` (6to4) and `2001::/32` (Teredo) are **not** unwrapped — they are rejected as blocked (D11 names them explicitly), because unwrapping would let an attacker embed a private IPv4 inside a routable-looking v6 literal.

Block table (v4) — reject if the address is in any of:

| CIDR | What |
|---|---|
| `0.0.0.0/8` | "this network" |
| `10.0.0.0/8` | RFC 1918 |
| `100.64.0.0/10` | CGNAT |
| `127.0.0.0/8` | loopback |
| `169.254.0.0/16` | link-local, incl. `169.254.169.254` metadata |
| `172.16.0.0/12` | RFC 1918 |
| `192.0.0.0/24` | IETF protocol assignments |
| `192.0.2.0/24` | TEST-NET-1 |
| `192.88.99.0/24` | 6to4 relay anycast |
| `192.168.0.0/16` | RFC 1918 |
| `198.18.0.0/15` | benchmarking |
| `198.51.100.0/24` | TEST-NET-2 |
| `203.0.113.0/24` | TEST-NET-3 |
| `224.0.0.0/4` | multicast |
| `240.0.0.0/4` | reserved (incl. `255.255.255.255`) |

Block table (v6) — reject if in any of:

| CIDR | What |
|---|---|
| `::/128` | unspecified |
| `::1/128` | loopback |
| `::/96` | IPv4-compatible (after normalisation, a remainder is rejected) |
| `64:ff9b::/96`, `64:ff9b:1::/48` | NAT64 well-known / local-use |
| `100::/64` | discard-only |
| `2001::/32` | Teredo |
| `2001:1::1/128`, `2001:1::2/128` | protocol assignments |
| `2001:2::/48` | benchmarking |
| `2001:3::/32`, `2001:4:112::/48`, `2001:20::/28`, `2001:30::/28` | AMT / AS112 / ORCHIDv2 / Drone Remote ID |
| `2001:db8::/32` | documentation |
| `2002::/16` | 6to4 |
| `2620:4f:8000::/48` | AS112 direct delegation |
| `3fff::/20` | documentation |
| `5f00::/16` | segment routing SIDs |
| `fc00::/7` | ULA |
| `fe80::/10` | link-local |
| `fec0::/10` | deprecated site-local |
| `ff00::/8` | multicast |

`IsAllowed` returns `false` + a reason for a blocked address, and `true` for everything else (a public v4 or a global v6 in `2000::/3` outside the table). The reason string is used for metrics/logs only (never returned to the user; the user sees `source_url_invalid`). `LoopbackAllowingAddressValidator` (test-only, `tests/NightTales.TestKit/`) allows exactly `IPAddress.Loopback`/`::1` and delegates otherwise — and an architecture test asserts the production DI graphs never resolve it (D20).

### `SafeHttpSourceFetcher` (`src/NightTales.Infrastructure/Research/SafeHttpSourceFetcher.cs`)

Constructor: `SafeHttpSourceFetcher(HttpClient http, IArticleExtractor extractor, IRobotsPolicy robots, IAddressValidator addresses, IDnsResolver dns, IHostRateLimiter limiter, DomainBlocklist blocklist, IPublicSuffixList psl, IOptions<FetcherOptions> opt, ILogger<SafeHttpSourceFetcher> log)`.

`HttpClient` is built by a factory with exactly these handler settings (a unit test asserts each one, because each is a security control):

```csharp
new SocketsHttpHandler
{
    AllowAutoRedirect = false,          // D11: manual redirects, the URL is re-checked at every hop
    UseProxy = false,                   // D11: no environment proxy can reroute the connection
    UseCookies = false,                 // D11: no cookie jar exists to leak or replay
    AutomaticDecompression = DecompressionMethods.None,  // we decompress ourselves to count bytes
    ConnectTimeout = TimeSpan.FromSeconds(5),
    PooledConnectionLifetime = TimeSpan.FromMinutes(2),
    ConnectCallback = (ctx, ct) => ConnectAsync(ctx, ct),
}
```

and `HttpClient.Timeout = Timeout.InfiniteTimeSpan` (the 10 s budget is enforced by a `CancellationTokenSource` per request, so the timeout covers robots + DNS + redirects as one budget — `plan.md` §3.3 `Fetcher:TotalTimeoutSeconds`).

`ConnectAsync` — the anti-rebinding core. **The control is resolve-then-connect-to-IP**: the resolution happens *here*, the address is validated, and the socket is connected to that `IPAddress` — `HttpClient` never re-resolves the host name, so the address that was checked is the address that is connected to. (D20: no loopback bypass in production; the test server is reachable only because the test validator allows it.)

```csharp
private async ValueTask<Stream> ConnectAsync(SocketsHttpConnectionContext ctx, CancellationToken ct)
{
    var host = ctx.DnsEndPoint.Host;
    var port = ctx.DnsEndPoint.Port;

    if (port is not (80 or 443)) throw new SourceFetchException(SourceErrors.SourceUrlInvalid);
    if (IPAddress.TryParse(host, out _)) throw new SourceFetchException(SourceErrors.SourceUrlInvalid); // belt-and-braces; SourceUrl already rejected it

    var addresses = await _dns.ResolveAsync(host, ct);           // FakeDnsResolver in tests
    if (addresses.Count == 0) throw new SourceFetchException(SourceErrors.SourceUnreachable);

    // A new Socket per attempt: on Linux a socket cannot be reused after a failed connect
    // (PlatformNotSupportedException "Sockets on this platform are invalid for use after a failed connection attempt").
    Socket? socket = null;
    try
    {
        foreach (var ip in addresses)
        {
            if (!_addresses.IsAllowed(ip, out var reason)) { _log.LogDebug("fetch address blocked: {Reason}", reason); continue; }
            var attempt = new Socket(ip.AddressFamily, SocketType.Stream, ProtocolType.Tcp) { NoDelay = true };
            try { await attempt.ConnectAsync(new IPEndPoint(ip, port), ct); socket = attempt; break; }
            catch (SocketException) { attempt.Dispose(); /* try the next address */ }
        }
        if (socket is null) throw new SourceFetchException(SourceErrors.SourceUnreachable);

        // Defence in depth only: the address connected to is already the validated one (we resolved here and
        // never let HttpClient re-resolve), so this can only fire if the socket API ever returns a peer that
        // differs from the endpoint we asked for. It is not the rebinding control.
        if (socket.RemoteEndPoint is IPEndPoint peer && !_addresses.IsAllowed(peer.Address, out _))
            throw new SourceFetchException(SourceErrors.SourceUrlInvalid);

        return new NetworkStream(socket, ownsSocket: true);
    }
    catch { socket?.Dispose(); throw; }
}
```

Note the two deliberate details: the address check happens **inside** the loop (a host with one blocked and one public address connects to the public one, and a host with only blocked addresses fails closed), and TLS/SNI is unaffected because the handler still uses the request URI's host for the handshake.

`FetchAsync` — the pipeline, in this exact order:

1. **Syntax + blocklist** on `request.Url` (defence in depth: `SourceUrl.Parse` runs again here, so a caller that constructs a request by hand cannot skip it) → `source_url_invalid`; `blocklist.IsBlocked(request.RegistrableDomain)` → `source_domain_not_allowed`.
2. **Budget**: `using var cts = CancellationTokenSource.CreateLinkedTokenSource(ct); cts.CancelAfter(TotalTimeoutSeconds)`. Any `OperationCanceledException` where `ct` is not cancelled → `source_unreachable` (the 10 s timeout, D11).
3. **robots** for the hop's origin (D11 + the T0 spec): `IRobotsPolicy.IsAllowedAsync` → `false` → `source_blocked_by_robots`. The robots fetch itself goes through the same handler (same address rules) and its own 5 s budget.
4. **rate limit**: `IHostRateLimiter.WaitAsync(registrableDomain)` — 1 req/s per registrable domain, in-memory, a `SemaphoreSlim(1)` + a last-request timestamp per key; the limiter is shared across all in-flight tasks of the process.
5. **request**: `HttpMethod.Get`, `Version = HttpVersion.Version20`, `VersionPolicy = RequestVersionOrLower`, headers `User-Agent` (the D11 UA), `Accept: text/html,application/xhtml+xml,text/plain;q=0.9`, `Accept-Encoding: gzip, br`, `Accept-Language: <series language>` [DECISION: send the episode language so a multilingual site serves the right text; it is not a tracking vector and it is not a credential], no `Authorization`, no `Cookie`, no `Referer`. `HttpCompletionOption.ResponseHeadersRead`.
6. **redirect** (manual, ≤ 3): `301/302/303/307/308` → resolve `Location` against the current URI (relative allowed) → `SourceUrl.Parse` the **absolute** result → `source_url_invalid` if it fails, `source_domain_not_allowed` if its registrable domain is blocked → **then** re-run steps 2–5 for the new hop (the 10 s budget is shared across hops — [DECISION] one budget for the whole fetch, matching D11's "10 s total per page"). A 4th redirect → `source_unreachable`. `Location` missing or unparsable → `source_unreachable`. A redirect from https to http is allowed (D11 does not forbid it) but is logged at information level.
7. **status**: `2xx` → continue; `4xx`/`5xx` → `source_unreachable` with the status kept for the row (`SourceFetchError.Code`, `HttpStatus`).
8. **content type**: read `Content-Type`; the media type must be `text/html`, `application/xhtml+xml` [DECISION: treated as html — it is the same parser and D11's intent is "not a binary"], or `text/plain`, else `source_unsupported_type`. Then **sniff** the first 512 bytes: a NUL byte, or a byte sequence invalid under the declared charset (defaulting to UTF-8), → `source_unsupported_type` (closes the "declared html, actually a zip" confusion).
9. **decompressed size**: wrap the response stream (`Content-Encoding: gzip` → `GZipStream`, `br` → `BrotliStream`, else as-is) in `CountingStream` with a 2 MiB limit; exceeding it throws `SourceTooLargeException` → `source_too_large`. The compressed length is never used as the check.
10. **charset**: `Content-Type; charset=` → the HTML `<meta charset>`/`<meta http-equiv>` in the first 4 KiB → UTF-8. Decode with `Encoding.GetEncoding(name, EncoderFallback.ReplacementFallback, DecoderFallback.ReplacementFallback)` so a mis-declared page degrades instead of throwing. Vietnamese pages are the reason this step exists (windows-1258/cp1258 still appears on older sites) ⚠️ verify against the T0 corpus; if any corpus page is cp1258, keep this step, otherwise it stays as cheap insurance.
11. **extract**: `text/plain` → the decoded body, whitespace-normalised; html → `IArticleExtractor.Extract`. `IsMainTextFound == false` or `TextChars < SourceNoTextThreshold` (T0's number 1,275, config `Fetcher:MinTextChars`, 02 T104) → `source_no_text`; the SmartReader adapter sets `IsMainTextFound = IsReadable && TextChars ≥ MinTextChars`, never on non-empty text alone (T104). **Extract-phase bounds (T105, SEC-0928-1):** the parse is synchronous and outside the 10 s request budget, so before SmartReader touches the decoded HTML a **pre-parse guard** runs on it — a streaming tokenizer counts elements and nesting depth without building a DOM, and > `Fetcher:ExtractMaxElements` (50,000) or depth > `Fetcher:ExtractMaxDepth` (512) → `source_too_large`; the depth check must run **before** AngleSharp builds the DOM because a `StackOverflowException` cannot be caught (⚠️[INFERENCE] AngleSharp 1.8.2 exposes no depth limit — the guard is ours). `Extract` itself runs on a **dedicated worker** with a watchdog at `Fetcher:ExtractTimeoutSeconds` = **5 s**: on timeout the result is `source_no_text` (log reason `extract_timeout`, no page text kept) and the fetch ends so the lease is released. `TextChars > Fetcher:MaxTextChars` (300,000) → `source_too_large` (D11 stores at most that; a longer article is a failure, not a silent truncation, so the fact sheet is never built on half an article). The 2 MiB / 300,000-char caps bound **bytes**, not parse cost — they do not bound a runaway parse; the guard and the watchdog do (T105).
12. **hash + result**: `Sha256 = hex(SHA256(UTF8(text)))`, return `FetchedSource(finalUrl, title, contentType, sha256, text, textChars, httpStatus)`. The raw HTML is dropped here and never leaves the method (D11: "raw HTML is never stored").

Every exit path passes through one `catch` that maps `SourceFetchException` → `ErrorOr` and everything else → `source_unreachable` with the exception type logged (never the message, which may contain the URL — D19).

### Robots (`src/NightTales.Infrastructure/Research/Http/RobotsTxtPolicy.cs`, `RobotsRules.cs`)

`RobotsRules.Parse(string content, string userAgentToken)` and `RobotsRules.IsAllowed(string pathAndQuery)` implement the T0 spec exactly (groups, exact-token-over-wildcard selection, longest-match, allow-wins-ties, `*`/`$`, empty-`disallow`-allows, unknown directives ignored, the 1,000-rule cap, and **`crawl-delay` honoured** as `max(1 s, crawlDelay)` capped at `Fetcher:CrawlDelayMaxSeconds` = 10 s — above the cap the decision is deny with `source_blocked_by_robots` [T43]). `RobotsTxtPolicy` owns the fetch (through the same safety pipeline, 5 s, 512 KiB, `text/plain`) and the 24 h per-origin cache (`ConcurrentDictionary<string, CacheEntry>` + LRU trim at 1,000 origins). Failure semantics per D11: 2xx parse; 3xx follow ≤ 3; 4xx allow; 5xx/timeout/unparsable disallow.

### Rate limiter (`src/NightTales.Infrastructure/Research/Http/HostRateLimiter.cs`)

`IHostRateLimiter` — per registrable domain: `SemaphoreSlim(1,1)` + `lastRequestAt`; a request waits until `lastRequestAt + minInterval`, where `minInterval` is the value the robots decision returned (the 1 s floor, or the host's `crawl-delay` when it is larger), then records `now`. Bounded to 10,000 keys with an idle sweep (a key with no request for 10 min is dropped). [DECISION] One instance per process (singleton); the server-side 1-lease-per-domain rule (02.5.2-T2) is the cross-process guarantee, so the in-memory limiter only has to be correct within one fetcher.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| DNS returns both a blocked and a public address | connect to the public one; only if none is allowed → `source_unreachable` |
| DNS returns no records | `source_unreachable` |
| The robots.txt fetch cannot connect: the host resolves only to blocked addresses, refuses the connection or fails in transport | D11 "unreachable → disallow" applies to robots: `RobotsTxtPolicy` caches a deny-all verdict (`robots_unreachable`, the failure type logged) and the fetch returns `source_blocked_by_robots`, not `source_unreachable`. Nothing is dialled to a blocked address, so the SSRF control holds. This includes a first hop whose host only resolves to blocked addresses (02.5.2-T1 review F7) |
| `Location` is an absolute URL with credentials | `source_url_invalid` (the `SourceUrl.Parse` re-run on the hop) |
| A redirect loop (A → B → A) | the hop budget (3) exhausts → `source_unreachable`; no loop detection needed |
| Response has `Content-Encoding: zstd` (unexpected) | not in the accepted set → the body is read as-is and fails the sniff → `source_unsupported_type` (we advertise only gzip/br) |
| Charset declared as something .NET does not know | UTF-8 fallback with replacement, then extraction; if the result is < `MinTextChars` → `source_no_text` |
| Page is larger than 2 MiB compressed but small decompressed | allowed (the cap is on decompressed bytes, per D11) |
| Page returns 200 with an empty body | `source_no_text` |
| robots.txt is enormous (a 100 MB file) | the 512 KiB robots cap → disallow + `robots_rule_limit_exceeded` log |
| The fetch is cancelled by shutdown | `OperationCanceledException` propagates (not mapped to an error code); the lease expires and the sweeper requeues |
| An unexpected exception (a bug in the extractor) | caught → `source_unreachable`, the exception **type** logged (never the message, which may embed the URL); the task still returns a result so the row does not hang `pending` |
| Extract exceeds `Fetcher:ExtractTimeoutSeconds` (a pathological document) | the watchdog ends the worker → `source_no_text` with reason `extract_timeout`, no page text, and the fetch completes so the lease is released (T105) |
| HTML exceeds the element/depth pre-parse guard | `source_too_large` — the streaming tokenizer rejects it before AngleSharp builds a DOM, so an uncatchable `StackOverflowException` never happens (T105) |
| The chosen extractor throws on a malformed document | same as above, and the page id is added to the T0 report's known-failures list |
| Rollback | the class is not yet wired into a host until 02.5.2-T3, so removing the DI registration is a complete rollback |

## Notes

- [DECISION] The 10 s budget is **shared** across robots + DNS + all redirect hops, per D11's "10 s total per page (robots included in its own 5 s)". This means a slow robots file eats the page's budget — accepted, because the alternative (per-hop budgets) makes the worst case `10 × 4` seconds and lets a redirect chain stall the lease.
- [DECISION] Default-allow in the address validator with a closed block table (see the Design rationale). A reviewer who prefers default-deny must supply the `2000::/3` allocation list; the block table is the IANA special-purpose registry's non-global subset.
- [DECISION] `application/xhtml+xml` is treated as html; D11 says "text/html or text/plain (sniff-checked)" — XHTML is the same parser and the sniff still runs.
- [DECISION] A `meta refresh` is not followed: it is page-scripted navigation, and following it would need a parser-level redirect that D11 does not authorise.
- [DECISION] `Accept-Language` is sent from the episode language. If the TL objects to any per-request header beyond the UA, dropping it only affects multilingual sites (the extracted text is the site's default language).
- ⚠️ `Fetcher:MinTextChars` (T0's threshold, **1,275**, 02 T104) is the one tunable that can cause a silent `source_no_text`; the T0 corpus numbers set it and the T4 suite pins the boundary.
- ⚠️ cp1258/windows-1258 handling is unverified against the T0 corpus; the charset step stays either way.
