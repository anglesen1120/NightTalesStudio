## Goal

The Api exposes a narrow, token-authenticated lease API on port `8081` that a fetcher with **no database access** can pull work from: `lease` hands out at most 4 tasks platform-wide and 1 per registrable domain under `FOR UPDATE SKIP LOCKED`, `heartbeat` extends a lease to `now + 60 s` (never earlier than its current end and never past `leased_at + Fetcher:MaxLeaseTotalSeconds`, 300 s), `result` validates the posted text, stores it in object storage, updates `story_sources` and raises `SourceFetched`; `FetchLeaseSweeperJob` (Worker, every 60 s) requeues leases older than 90 s and fails a task after its second expiry.

## Design

### `fetch_tasks` lease SQL (the heart of the task)

`FetchTaskLeaseStore` (`src/NightTales.Infrastructure/Persistence/Queries/FetchTaskLeaseStore.cs`) — raw SQL through `IAppDbContext.Database`, because this is a queue claim that EF cannot express:

```sql
-- LeaseFetchTasks(@workerId text, @max int, @room int, @leaseSeconds int) → setof (id, kind, url, attempt, lease_until, registrable_domain)
-- As built (FetchTaskLeaseStore.cs:65-100, called from LeaseAsync :137-194). [DECISION T42] The call runs in one transaction
-- whose first statements are:
--   SELECT pg_try_advisory_xact_lock(<constant>);        -- polled every 20 ms for at most 2 s, else 503 service_unavailable (:146-149, :364-385)
--   SELECT count(*)::int FROM fetch_tasks WHERE status = 'leased';   -- leasedNow, exact under the lock (:152, :352-357)
-- At leasedNow >= Fetcher:MaxLeasesPlatformWide the call answers [] and the statement below is skipped (:153-156);
-- otherwise @room = MaxLeasesPlatformWide - leasedNow (:162).
WITH domain_busy AS (
    SELECT DISTINCT registrable_domain FROM fetch_tasks
    WHERE status = 'leased' AND registrable_domain IS NOT NULL
),
eligible AS (
    SELECT t.id, t.registrable_domain, t.not_before, t.created_at  -- `ranked` orders by these (without them PG 42703)
    FROM fetch_tasks t
    WHERE t.status = 'queued'
      AND t.not_before <= now()
      AND (t.registrable_domain IS NULL OR t.registrable_domain NOT IN (SELECT registrable_domain FROM domain_busy))
      AND NOT (t.kind = 'find_sources' AND t.generation_run_id IS NULL)   -- QA-6: the fetcher could not act on it
),
-- Rank *within the batch* so a single statement can never lease two tasks of the same domain.
-- (Postgres rejects FOR UPDATE together with DISTINCT ON / window functions, hence the two nested CTEs.)
ranked AS (
    SELECT id,
           row_number() OVER (PARTITION BY registrable_domain ORDER BY not_before, created_at) AS rn
    FROM eligible
),
candidates AS (
    SELECT id
    FROM fetch_tasks
    WHERE id IN (SELECT id FROM ranked WHERE rn = 1)
    ORDER BY not_before, created_at
    FOR UPDATE SKIP LOCKED
    LIMIT LEAST(@max, @room)
)
UPDATE fetch_tasks t
SET status = 'leased',
    leased_by = @workerId,
    leased_at = now(),
    lease_until = now() + make_interval(secs => @leaseSeconds),
    attempts = t.attempts + 1
FROM candidates c
WHERE t.id = c.id
RETURNING t.id, t.kind, t.url, t.attempts, t.lease_until, t.registrable_domain;
```

Heartbeat statement (`FetchTaskLeaseStore.cs:102-110`, run by `HeartbeatAsync` `:197-229`). It extends the lease to `min(max(lease_until, now + HeartbeatSeconds), leased_at + MaxLeaseTotalSeconds)`: a heartbeat never shortens a lease, and the `WHERE` short-circuits once `now() >= leased_at + MaxLeaseTotalSeconds`, so no row changes and the answer is `409 fetch_lease_lost` (`:219-221`):

```sql
-- HeartbeatFetchTask(@id uuid, @workerId text, @heartbeatSeconds int, @maxTotalSeconds int)
UPDATE fetch_tasks
SET lease_until = LEAST(
    GREATEST(lease_until, now() + make_interval(secs => @heartbeatSeconds)),
    leased_at + make_interval(secs => @maxTotalSeconds))
WHERE id = @id AND status = 'leased' AND leased_by = @workerId AND lease_until > now()
  AND leased_at IS NOT NULL AND now() < leased_at + make_interval(secs => @maxTotalSeconds)
RETURNING lease_until;
```

Notes that matter:

- `FOR UPDATE SKIP LOCKED` is what makes two fetcher replicas safe: each row is locked by exactly one claimer and the other skips it instead of blocking.
- The `ranked` CTE is what makes the **1-lease-per-domain** rule hold inside one batch: without it, three queued tasks on `example.com` with `@max = 4` would all be leased by the same statement, because `domain_busy` only sees domains leased by *earlier* statements. `row_number() … PARTITION BY registrable_domain` keeps exactly one row per domain per call. (`PARTITION BY` groups NULLs together, so at most **one** `find_sources` task (NULL domain) is leased per call. That is intended: option B runs one browser task at a time per call. The `eligible` filter never blocks NULL domains through `domain_busy`.)
- The platform cap is applied through `@room = MaxLeasesPlatformWide - leasedNow` (`LIMIT LEAST(@max, @room)`), with `leasedNow` counted by a separate statement before the lease statement and the call short-circuiting to `[]` when `leasedNow >= MaxLeasesPlatformWide` (`FetchTaskLeaseStore.cs:152-162`); **[DECISION T42]** the whole call runs in one transaction that first takes the advisory lock `pg_try_advisory_xact_lock(<constant>)` (polled every 20 ms, at most 2 s, then `503 service_unavailable`, `FetchTaskLeaseStore.cs:61-63,364-385`; SEC-2.3), so both `leasedNow` and `domain_busy` are read under mutual exclusion and two concurrent lease calls cannot land at 5 or hand out two leases for one domain. Both reads are unlocked in themselves; the advisory lock is precisely what makes them exact, so it is a correctness requirement, not a tuning knob — do not drop it when "one replica is enough" (a rolling restart briefly runs two).
- `find_sources` tasks with a NULL `generation_run_id` are never eligible (`NOT (kind = 'find_sources' AND generation_run_id IS NULL)`, `FetchTaskLeaseStore.cs:75`; QA-6): the fetcher could not act on them.
- `attempts` increments on lease (not on failure), so a task that is leased and then expires twice reaches `attempts = 2` and the sweeper fails it — exactly D10's rule. `leased_at` is set here so `fetch_duration_seconds` can measure fetch time rather than queue time.
- Index `(status, not_before)` (from 02.5.1-T1) serves the scan; `(status, registrable_domain) WHERE status='leased'` serves `domain_busy`.

### Internal API (`src/NightTales.Api/Endpoints/Internal/FetcherEndpoints.cs` + `Security/FetcherTokenAuthenticationHandler.cs`)

A **second Kestrel endpoint** on `8081` (`options.Listen(IPAddress.Parse(Fetcher:Internal:ListenAddress), 8081)` gated by `Fetcher:Internal:Enabled`; `ListenAddress` defaults to `127.0.0.1` and is `0.0.0.0` only in the container env (compose, staging, prod). A code-configured endpoint makes Kestrel ignore `ASPNETCORE_URLS`, so the public listener is declared the same way from `Kestrel:Endpoints` config and never disappears when the internal one is enabled (11 CR-16)), its own minimal middleware pipeline: no `UseAuthentication` for users, no `UseRateLimiter` from the public policy, no OpenAPI document, no SignalR. The public listener (`8080`) never maps these routes — asserted by a test (`GET localhost:8080/internal/fetcher/v1/tasks/lease` → 404).

```csharp
// Security/FetcherTokenAuthenticationHandler.cs
// scheme "FetcherToken"; the only principal it produces is "fetcher:<instanceId>".
// The token is read once at start-up from IConfiguration["FETCHER_API_TOKEN"] (runtime secret manager,
// 11.5.2) into a byte[]; comparison is CryptographicOperations.FixedTimeEquals on SHA-256 of the
// presented value vs SHA-256 of the stored value (hashing first makes the comparison length-independent).
// No token configured → the handler rejects everything AND start-up logs a fatal warning; the listener
// is only enabled when a token exists, so a misconfigured deployment cannot expose an open lease API.
```

Routes (all require the scheme; all return `ProblemDetails` on failure):

| Route | Request | Response | Failures |
|---|---|---|---|
| `POST /internal/fetcher/v1/tasks/lease` | `{ "workerId": "fetcher-1", "max": 4 }` | `200 [ { taskId, kind, url, attempt, leaseUntil, userAgent, finderRequest? } ]` | `400` (`max` ∉ [1,4] or missing `workerId`), `401` (token), `429` (rate limit) |
| `POST /internal/fetcher/v1/tasks/{taskId}/heartbeat` | `{ "workerId": "fetcher-1" }` | `200 { "leaseUntil": "…" }` | `401`, `404` (`fetch_task_not_found`), `409` (`fetch_lease_lost`) |
| `POST /internal/fetcher/v1/tasks/{taskId}/result` | the fetch result **or** the finder result (below) | `200 { "taskId": "…", "status": "done" }` | `400` (validation, with a D8 code), `401`, `404`, `409` (`fetch_lease_lost`) |

`fetch_task_not_found` and `fetch_lease_lost` are **internal-only** codes: they are never shown to a user, never appear in `story_sources.error_code`, and are therefore not part of D8's public catalogue — **[DECISION T43] accepted as-is** (the TL ruled the two codes stay; they are documented here and nowhere else).

`lease` maps each row to a response item, and for `find_sources` re-derives the requester payload from the `generation_runs` row of that run (D2: `kind = 'find_sources'`), joined by the task's `generation_run_id` — **[DECISION T38]** that column is now part of `fetch_tasks` (`uuid NULL`, addition 3), so the finder payload is re-derivable without duplicating brief text into a table the fetcher can see. `fetch_tasks.episode_id` is **NOT NULL** (T38: a `find_sources` task is episode-level), so every task is deleted with its episode.

```jsonc
// finderRequest (kind = find_sources only)
{ "topic": "true_crime", "language": "vi", "seriesTitle": "…", "brief": "…",
  "allowList": ["vnexpress.net", "tuoitre.vn"], "maxCandidates": 10 }
// allowList comes from the 02.7.2-T1 allow-list table/option; when 02.7 has not shipped, no find_sources
// task exists, so this branch is exercised only by the T4 stub.
```

`result` validation, in order, each failure returning `400` with the code and **leaving the task `leased`** (it will expire and be swept — the fetcher's `409`/`400` handling decides whether to abandon or retry, and 02.5.2-T3 abandons on any `400`):

1. Lease ownership: `status = 'leased' AND leased_by = @workerId AND lease_until > now()` else `409 fetch_lease_lost`.
2. `fetch_source` + `status: "done"` [T39]: `text` non-empty and ≤ `Fetcher:MaxTextChars` (300,000) else `400 source_no_text` / `400 source_too_large`; `textSha256` present and equal to `hex(SHA256(UTF8(text)))` else `400 source_no_text` (a mismatch is corruption — never store it); `finalUrl` parses through `SourceUrl.Parse` and its registrable domain is not blocked else `400 source_domain_not_allowed`; `contentType` ∈ the accepted set (defence in depth: the fetcher already checked) else `400 source_unsupported_type`.
2b. `find_sources` + `status: "done"` [T39]: `candidates` present (≤ 50); see item 4.
3. `fetch_source` + `status: "failed"`: `errorCode` ∈ the D8 job-code set, else coerced to `source_unreachable` (never store an unknown code).
4. `find_sources` candidates: entries whose `url` fails `SourceUrl.Parse` are **dropped silently**; the rest are handed to the 02.7.2-T3 `CandidateExtractor` (D11 + allow-list + dedupe + cap 10) and inserted into **`source_candidates`** (02.7 plan §3, README §10 T59) with the task's `generation_run_id`; the run is then completed as in 02.7.2-T3 steps 5–7. Nothing is stored on `generation_runs` (D2 has no result column).

On a valid `fetch_source` result, in one transaction: write the object (§Storage), `source.MarkFetched(...)` / `MarkFailed(...)`, `task.Complete(now)` / `Fail(code, now)`, raise `SourceFetched` through `episode.RaiseSourceFetched(source.Id, now)` (`CompleteFetchTaskHandler.cs:138`), which keeps the event's four existing fields `SourceId, EpisodeId, UserId, OccurredAt` (`SourceFetched.cs:14`; see the [DECISION] on SourceFetched in §Notes: consumers re-read the episode, so no `SeriesId/Status/ErrorCode/RegistrableDomain` payload), write the outbox row (the outbox dispatcher turns it into `EpisodeUpdated`; no new SignalR event type — CR-7). Metrics: `fetch_tasks_total{status,error_code}` and `fetch_duration_seconds`, measured **lease → result** from `leased_at` (set by the lease statement, cleared on requeue), never from `created_at` — otherwise the histogram measures queue time and is useless.

### `FetchLeaseSweeperJob` (`src/NightTales.Application/Features/Research/Jobs/FetchLeaseSweeperJob.cs`, registered by `src/NightTales.Worker/Jobs/FetchLeaseSweeperRegistration.cs`)

Recurring Hangfire job, id `fetch-lease-sweeper`, `Cron.Minutely()` (D10: every 1 min). One SQL statement per run:

```sql
-- RequeueExpiredLeases(@maxAttempts int, @backoffSeconds int)
UPDATE fetch_tasks
SET status = CASE WHEN attempts >= @maxAttempts THEN 'failed' ELSE 'queued' END,
    error_code = CASE WHEN attempts >= @maxAttempts THEN 'source_unreachable' ELSE NULL END,
    leased_by = NULL,
    lease_until = NULL,
    leased_at = NULL,
    not_before = CASE WHEN attempts >= @maxAttempts THEN not_before ELSE now() + make_interval(secs => @backoffSeconds) END,
    finished_at = CASE WHEN attempts >= @maxAttempts THEN now() ELSE NULL END
WHERE status = 'leased' AND lease_until < now()
RETURNING id, source_id, episode_id, attempts, status;
```

Then, for each returned row that became `failed` with a `source_id`, the job calls `StorySource.MarkFailed("source_unreachable", null, now)` and raises `SourceFetched` on the episode (`FetchLeaseSweeperJob.cs:203,209`) so the UI shows a failed source rather than a task that silently vanished. Each pass also reconciles failed-task/pending-source pairs a crashed earlier pass left behind (`ListFailedTasksWithPendingSourceAsync`, lookback 24 h, `FetchLeaseSweeperJob.cs:59,123`; `FetchLeaseSweepStore.cs:170-182`) and then refreshes the `fetch_leases_active` gauge (`:109,147-157`). [DECISION] The sweeper is idempotent and single-instance-safe (the `WHERE status='leased' AND lease_until < now()` is the guard), so no distributed lock is needed even if two Workers run it; ⚠️ Hangfire recurring jobs are per-server, so in a multi-Worker deployment the job must be registered with a `DisableConcurrentExecution`-style lock or the query alone must be trusted — the query alone **is** safe (each row is updated once because the status flips), so no lock is required; note it in the job's XML doc.

Metrics: `fetch_tasks_total{status="requeued"}` / `{status="failed",error_code="source_unreachable"}`; a log line per run with the counts only.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| The fetcher posts a result for a task the sweeper already requeued | `409 fetch_lease_lost` (the row is no longer `leased` by that worker); the fetcher drops the work |
| The fetcher posts twice (retry after a timeout on a `200`) | the first result wins (`status='done'` → the second gets `409 fetch_lease_lost`); the object write is content-addressed so a duplicate write is harmless |
| The object write succeeds and the transaction fails | an orphan object under `research/…`; cleaned by 13.3's sweep; the row stays `pending` and the next lease retries |
| The transaction commits and the outbox dispatch fails | the outbox retries (09); `EpisodeUpdated` is delayed, not lost |
| `story_sources` row deleted while its task is leased | the FK cascade deletes the task; the result POST gets `404 fetch_task_not_found` and the fetcher drops it |
| The Api restarts while 4 tasks are leased | the leases expire in ≤ 90 s; the sweeper (in the Worker, a separate process) requeues them |
| Two Workers run the sweeper concurrently | safe: the `WHERE status='leased' AND lease_until < now()` guard means each row flips once; the second run finds nothing |
| The Api's internal listener is accidentally exposed | the token is mandatory (start-up fails without it) and the network ACL is 11.2.2-T2's job; this task's test asserts the route is absent from the public listener |
| `max` > 4 requested | clamped to the platform cap minus leased, never an error (the client is trusted but the cap is absolute) — [DECISION] `400` only for `max` ∉ [1, 4] so a buggy client is visible; the effective count is `min(max, cap − leased)` |
| `lease_until` is in the past on read (clock skew) | `heartbeat`/`result` return `409`; the sweeper requeues; the clock source is `IClock` (UTC) |
| Rollback | disable `Fetcher:Internal:Enabled` (listener gone, fetcher logs 404s and retries) then redeploy; `fetch_tasks` rows keep their status and the sweeper keeps working |

## Notes

- [DECISION] `lease` clamps rather than errors above the cap, so a fetcher that asks for 4 while 3 are leased gets 1 without special-casing — but `max > 4` is a `400` because no caller should ever ask for more than the platform cap.
- [DECISION T38] The four column additions to D10's `fetch_tasks` list are **accepted**: `url`, `registrable_domain`, `generation_run_id`, `leased_at`; `episode_id` is **NOT NULL** (a `find_sources` task is episode-level). All four go into CR-4's bullet and are in `plan.md` §3.2.
- [DECISION T39] Every result body carries `status: "done" | "failed"`; the field is mandatory (`400` when absent).
- [DECISION T42] The lease statement takes a `pg_advisory_xact_lock` on a constant, so the platform cap (4) and the per-domain cap (1) are exact, not best-effort. The advisory lock is a correctness requirement — a rolling restart briefly runs two fetchers, so "one replica is enough" is not a reason to drop it.
- [DECISION] `fetch_task_not_found` / `fetch_lease_lost` are internal-only codes, deliberately outside D8 (which is a user-facing catalogue) — confirmed by T43.
- [DECISION] A task is never retried more than twice: D10's `attempts = 2` → `source_unreachable`. A user who wants another try uses `POST …/sources/{id}/retry` (02.5.1-T1), which counts against the 24 h cap — this keeps retries a user decision, not a background loop.
- ⚠️ Still to confirm with 13.3: that 13.3.1-T1's deletion sweep covers the `research/` storage prefix (the Api writes those objects; the rows cascade with the episode, the objects do not).
- [DECISION] **No migration.** `generation_run_id` and `leased_at` already exist in `20261003140736_02_SourcesAndFetchTasks` (02.5.1-T1), so this task adds none and the migration chain is unchanged (Step 1's "fold them into that migration" case did not arise).
- [DECISION] **`find_sources` results answer `400 fetch_task_kind_unsupported` until 02.7.2-T3.** The body is still validated (≤ 50 candidates, entries with an invalid URL dropped) and a `failed` body is also refused, then the Api answers `400 fetch_task_kind_unsupported`, leaves the task `leased` (it expires and is swept) and persists nothing: candidate persistence and the domain allow-list belong to 02.7.2-T3. - [DECISION] **`Fetcher:Internal:Enabled` is committed `false`** (`src/NightTales.Api/appsettings.json`, `Fetcher:Internal`). A deployment or dev environment enables it together with `FETCHER_API_TOKEN` (≥ 32 chars, never in a settings file); enabled without a usable token the Api fails start-up (`FetcherInternalOptionsValidator`). `tools/dev/up.sh` and the compose `api` service enable it with a generated throwaway token; `docs/dev-setup.md` § Host boot contexts documents it.

- [DECISION] **Global limiter constants** are fixed in code, not configuration: 8 concurrent internal requests and 300 requests per minute across all workers (`FetcherRateLimiter.cs:22,25`), in addition to the per-worker `MaxRequestsPerMinutePerWorker`.
- **Frozen hand-off for 02.5.2-T3 and 02.7.2-T2 (wire contract as built; derived from the code, cited file:line).** Every path is under `/internal/fetcher/v1/tasks` (`FetcherEndpoints.cs:38`), served only on the internal port; all three are `POST`, bodies are JSON objects, property names are camelCase as serialized (`JsonSerializerDefaults.Web`, `FetcherEndpoints.cs:51-56`), a `null` member of a response is **omitted** (`WhenWritingNull`, `:55`) and timestamps are ISO-8601 `DateTimeOffset`. Every request carries exactly one `Authorization: Bearer <FETCHER_API_TOKEN>` header (≤ 512 chars; `FetcherTokenAuthenticationHandler.cs:76-93`).
  - **Encoding (MUST).** Send UTF-8 JSON **with relaxed escaping** — .NET `JavaScriptEncoder.UnsafeRelaxedJsonEscaping` or the equivalent in the fetcher's language (no `\uXXXX` for non-ASCII): the body cap is **1 048 576 bytes** (`FetcherInternalOptions.cs:36`, enforced on `Content-Length` and while streaming, `FetcherEndpoints.cs:273-295`, answer `413`), and a 300 000-character Vietnamese text is up to 3 bytes per character in UTF-8 but 6 bytes per character as `\uXXXX`, so the escaped form can exceed the cap while the raw form fits.
  - **`POST /lease`** (`FetcherEndpoints.cs:143-165`). Request `{"workerId": "fetcher-1", "max": 4}`: `workerId` 1–64 characters of `[A-Za-z0-9._:-]` (`WorkerIdRules.cs:20-27`, `FetchResultLimits.cs:14`), `max` an integer 1–4 (`LeaseFetchTasksValidator.cs:13`, `LeaseFetchTasksCommand.cs:24`). `200` body is a **top-level JSON array** (empty when nothing is leasable) of `LeaseDto` (`LeaseDto.cs:14-21`): `{"taskId": "<guid>", "kind": "fetch_source" | "find_sources", "url": "<string>" (omitted for find_sources), "attempt": <int, 1-based>, "leaseUntil": "<ISO-8601>", "userAgent": "<string>", "finderRequest": {…} (omitted for fetch_source)}`. `finderRequest` is `{"topic": "<snake_case>", "language": "<code>", "seriesTitle": "<string>", "brief": "<string>", "allowList": [] , "maxCandidates": 10}` (`LeaseDto.cs:33-39`; `allowList`/`maxCandidates` constants at `FetchTaskLeaseStore.cs:305`, see the decision above). The array is ordered by `taskId` (`FetchTaskLeaseStore.cs:154`).
  - **`POST /{taskId}/heartbeat`** (`FetcherEndpoints.cs:167-191`; `taskId` in `D` GUID format, not `Guid.Empty`, `:255`). Request `{"workerId": "fetcher-1"}`. `200` body `{"leaseUntil": "<ISO-8601>"}` = `min(max(lease_until, now + Fetcher:HeartbeatSeconds (60)), leased_at + Fetcher:MaxLeaseTotalSeconds (300))` (`FetchTaskLeaseStore.cs:102-110`; `FetcherEndpoints.cs:206`); once past the total ceiling no row changes and the answer is `409 fetch_lease_lost` (`FetchTaskLeaseStore.cs:219-221`). `409 fetch_lease_lost` when the worker no longer holds a live lease, `404 fetch_task_not_found` when the task is gone (`FetchTaskLeaseStore.cs:193-196`).
  - **`POST /{taskId}/result`** (`FetcherEndpoints.cs:193-213`). Request `FetchResultRequest` (`FetchTaskResult.cs:18-28`): `{"workerId": "<as above>", "status": "done" | "failed" (mandatory, `FetchTaskResultValidator.cs:68-71`), "httpStatus": <int> (kept only when 100–599, `:74`), "finalUrl": "<string>", "title": "<string>", "contentType": "<string>", "text": "<string>", "textSha256": "<hex>", "errorCode": "<string>", "candidates": [{"url": "<string>", "title": "<string>", "site": "<string>"}]}` (`FetchCandidateRequest`, `FetchTaskResult.cs:34`). All members except `workerId` and `status` are optional at bind time; which are required depends on kind and status:
    - `fetch_source` + `done` (`FetchTaskResultValidator.cs:85-129`): `text` non-empty else `400 source_no_text`; `text.Length` (UTF-16 code units) ≤ `Fetcher:MaxTextChars` (300 000) else `400 source_too_large`; no NUL/C0 control other than TAB, LF, CR, nor DEL else `400 source_no_text` (`:105-108`, `:258-290`; the validator's own lone-surrogate guard is defence in depth); a lone surrogate on the wire never reaches this check: a lone `\uD800`-style escape cannot be transcoded, so the body fails to bind and answers `400 validation_failed` on member `body` (`FetcherEndpoints.cs:355-365`; test `Result_TextWithLoneSurrogate_Returns400_NeverA500`, `FetchResultValidationTests.cs:185`); `textSha256` = lowercase hex SHA-256 of the UTF-8 bytes of `text` (compared case-insensitively) else `400 source_no_text` (`:110-114`); `finalUrl` must parse as a source URL and not be a blocked domain else `400 source_domain_not_allowed` (`:116-120`); `contentType` media type (parameters stripped, lowercased) must be `text/html` or `text/plain` else `400 source_unsupported_type` (`:43-47,122-126`). Success: `200 {"taskId": "<guid>", "status": "done"}` (`CompleteFetchTaskCommand.cs:11`, `CompleteFetchTaskHandler.cs:148`).
    - `fetch_source` + `failed`: `errorCode` is one of `source_unreachable`, `source_too_large`, `source_blocked_by_robots`, `source_unsupported_type`, `source_no_text`, `source_domain_not_allowed`; anything else (or absent) is stored as `source_unreachable` (`:31-40,162-163`). Answer is the same `200 {"taskId": …, "status": "done"}` — a `failed` body completes the lease (`CompleteFetchTaskCommand.cs:9-10`).
    - `find_sources` (either status): `done` requires `candidates` (else `400 validation_failed`, field `candidates`), at most 50 entries (`FetchResultLimits.cs:11`, `:131-143`), entries whose `url` does not parse are dropped silently, `title`/`site` are cleaned and capped at 300 characters (`FetchResultLimits.cs:17`); then **every** find_sources body gets `400 fetch_task_kind_unsupported` and the task stays `leased` (`CompleteFetchTaskHandler.cs:69-74`).
    - Order of checks: rate limit (`FetcherEndpoints.cs:202`) → owner lookup (`404 fetch_task_not_found`, `FetcherResultRunner.cs:43-46`) → `workerId` shape (`400 validation_failed`, `CompleteFetchTaskValidator.cs:15`) → lease ownership `409 fetch_lease_lost` (`FetchTaskLeaseStore.cs:222-225`, also when the source is no longer `pending`, `CompleteFetchTaskHandler.cs:87-90`) → body validation above. **Any `400` leaves the task `leased`**; 02.5.2-T3 abandons on any `400` (see the Design).
  - **Errors.** Failure bodies are `application/problem+json` `{"type", "title", "status", "code", "traceId", "errors"}` where `errors` is `null` when there are none: the job-code bodies pass `null` (`FetcherProblem.cs:45-50`) and the problem record has no ignore-null attribute (`FetcherProblem.cs:54-60`; `ProblemDetailsWriter.cs:111,244`); branch on the HTTP status and `code`, never on `title`. Codes: `400 validation_failed` (malformed JSON, a lone surrogate escape, a number where a string belongs — numbers must be JSON numbers and strings JSON strings, `JsonNumberHandling.Strict`, `FetcherEndpoints.cs:58` — a numeric or unknown `status`: `FetcherEndpoints.cs:337-365`, `FetchTaskResultValidator.cs:68-71`; `errors` maps member → messages), `400` job codes `source_no_text` / `source_too_large` / `source_unsupported_type` (`FetcherProblem.cs:18-23`) and `source_domain_not_allowed` / `fetch_task_kind_unsupported` (own codes, catalogued 400 in `ErrorCatalogue.cs:80,86`), `404 fetch_task_not_found`, `409 fetch_lease_lost` (`FetcherErrors.cs:13-22`, `ErrorCatalogue.cs:123,127`), `429 rate_limited` with `Retry-After` seconds once a `workerId` exceeds `Fetcher:Internal:MaxRequestsPerMinutePerWorker` (60/min, `FetcherEndpoints.cs:231-246`) or the global limiter refuses: more than 8 requests in flight or 300 requests per minute across all workers, fixed constants, no config keys (`FetcherRateLimiter.cs:22,25,52,57`), `503 service_unavailable` (database or storage deadline/transient failure, `FetcherEndpoints.cs:83`, `FetchTaskLeaseStore.cs:408`; a contended platform lease lock after 2 s, `FetchTaskLeaseStore.cs:61,378`; the object `PUT` exceeding `TextWriteDeadline` of 15 s, `FetcherResultRunner.cs:47,165-176`), `500 internal_error` (`:81-92`). Bodiless answers: `401` (missing/wrong/user-JWT token, `FetcherTokenAuthenticationHandler.cs:104-109`), `404` (unknown path, `:105-110`), `405` with `Allow: POST` (`:112-118`), `413` (body over `Fetcher:Internal:MaxBodyBytes`, `FetcherEndpoints.cs:140,328`).
  - **Write order and token (as built).** `result` writes the text object **before** the short claim transaction (`FetcherResultRunner.cs:33,58-154`), so a lease lost after the write leaves an orphan object (same key for the same text; cleaned by 13.3). The bearer token is trimmed on both sides, configured and presented (`FetcherInternalOptions.cs:26`, `FetcherTokenAuthenticationHandler.cs:89`).
