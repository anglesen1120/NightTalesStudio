## Goal

The Api exposes a narrow, token-authenticated lease API on port `8081` that a fetcher with **no database access** can pull work from: `lease` hands out at most 4 tasks platform-wide and 1 per registrable domain under `FOR UPDATE SKIP LOCKED`, `heartbeat` extends a lease by 60 s, `result` validates the posted text, stores it in object storage, updates `story_sources` and raises `SourceFetched`; `FetchLeaseSweeperJob` (Worker, every 60 s) requeues leases older than 90 s and fails a task after its second expiry.

## Design

### `fetch_tasks` lease SQL (the heart of the task)

`FetchTaskLeaseStore` (`src/NightTales.Infrastructure/Persistence/Queries/FetchTaskLeaseStore.cs`) — raw SQL through `IAppDbContext.Database`, because this is a queue claim that EF cannot express:

```sql
-- LeaseFetchTasks(@workerId text, @max int, @leaseSeconds int) → setof (id, kind, url, attempt, lease_until, registrable_domain)
-- [DECISION T42] The whole statement runs inside one transaction that first takes
--   SELECT pg_advisory_xact_lock(<constant>);
-- so the caps are exact, not best-effort (see the notes below the query).
WITH leased_now AS (
    SELECT count(*) AS n FROM fetch_tasks WHERE status = 'leased'
),
domain_busy AS (
    SELECT DISTINCT registrable_domain FROM fetch_tasks
    WHERE status = 'leased' AND registrable_domain IS NOT NULL
),
eligible AS (
    SELECT t.id, t.registrable_domain
    FROM fetch_tasks t
    WHERE t.status = 'queued'
      AND t.not_before <= now()
      AND (t.registrable_domain IS NULL OR t.registrable_domain NOT IN (SELECT registrable_domain FROM domain_busy))
),
-- Rank *within the batch* so a single statement can never lease two tasks of the same domain.
-- (Postgres rejects FOR UPDATE together with DISTINCT ON / window functions, hence the two nested CTEs.)
ranked AS (
    SELECT id,
           row_number() OVER (PARTITION BY registrable_domain ORDER BY not_before, created_at) AS rn
    FROM eligible
),
candidates AS (
    SELECT id
    FROM fetch_tasks
    WHERE id IN (SELECT id FROM ranked WHERE rn = 1)
    ORDER BY not_before, created_at
    FOR UPDATE SKIP LOCKED
    LIMIT LEAST(@max, GREATEST(0, @platformCap - (SELECT n FROM leased_now)))
)
UPDATE fetch_tasks t
SET status = 'leased',
    leased_by = @workerId,
    leased_at = now(),
    lease_until = now() + make_interval(secs => @leaseSeconds),
    attempts = t.attempts + 1
FROM candidates c
WHERE t.id = c.id
RETURNING t.id, t.kind, t.url, t.attempts, t.lease_until, t.registrable_domain;
```

Notes that matter:

- `FOR UPDATE SKIP LOCKED` is what makes two fetcher replicas safe: each row is locked by exactly one claimer and the other skips it instead of blocking.
- The `ranked` CTE is what makes the **1-lease-per-domain** rule hold inside one batch: without it, three queued tasks on `example.com` with `@max = 4` would all be leased by the same statement, because `domain_busy` only sees domains leased by *earlier* statements. `row_number() … PARTITION BY registrable_domain` keeps exactly one row per domain per call. (`PARTITION BY` groups NULLs together, so at most **one** `find_sources` task (NULL domain) is leased per call. That is intended: option B runs one browser task at a time per call. The `eligible` filter never blocks NULL domains through `domain_busy`.)
- The platform cap is enforced inside the same statement (`@platformCap - count(leased)`), and **[DECISION T42]** the whole statement is wrapped in `pg_advisory_xact_lock(<constant>)` so both `leased_now` and `domain_busy` are read under mutual exclusion and two concurrent lease calls cannot land at 5 or hand out two leases for one domain. Both reads are unlocked in themselves; the advisory lock is precisely what makes them exact, so it is a correctness requirement, not a tuning knob — do not drop it when "one replica is enough" (a rolling restart briefly runs two).
- `attempts` increments on lease (not on failure), so a task that is leased and then expires twice reaches `attempts = 2` and the sweeper fails it — exactly D10's rule. `leased_at` is set here so `fetch_duration_seconds` can measure fetch time rather than queue time.
- Index `(status, not_before)` (from 02.5.1-T1) serves the scan; `(status, registrable_domain) WHERE status='leased'` serves `domain_busy`.

### Internal API (`src/NightTales.Api/Endpoints/Internal/FetcherEndpoints.cs` + `Security/FetcherTokenAuthenticationHandler.cs`)

A **second Kestrel endpoint** on `8081` (`options.Listen(IPAddress.Parse(Fetcher:Internal:ListenAddress), 8081)` gated by `Fetcher:Internal:Enabled`; `ListenAddress` defaults to `127.0.0.1` and is `0.0.0.0` only in the container env (compose, staging, prod). A code-configured endpoint makes Kestrel ignore `ASPNETCORE_URLS`, so the public listener is declared the same way from `Kestrel:Endpoints` config and never disappears when the internal one is enabled (11 CR-16)), its own minimal middleware pipeline: no `UseAuthentication` for users, no `UseRateLimiter` from the public policy, no OpenAPI document, no SignalR. The public listener (`8080`) never maps these routes — asserted by a test (`GET localhost:8080/internal/fetcher/v1/tasks/lease` → 404).

```csharp
// Security/FetcherTokenAuthenticationHandler.cs
// scheme "FetcherToken"; the only principal it produces is "fetcher:<instanceId>".
// The token is read once at start-up from IConfiguration["FETCHER_API_TOKEN"] (runtime secret manager,
// 11.5.2) into a byte[]; comparison is CryptographicOperations.FixedTimeEquals on SHA-256 of the
// presented value vs SHA-256 of the stored value (hashing first makes the comparison length-independent).
// No token configured → the handler rejects everything AND start-up logs a fatal warning; the listener
// is only enabled when a token exists, so a misconfigured deployment cannot expose an open lease API.
```

Routes (all require the scheme; all return `ProblemDetails` on failure):

| Route | Request | Response | Failures |
|---|---|---|---|
| `POST /internal/fetcher/v1/tasks/lease` | `{ "workerId": "fetcher-1", "max": 4 }` | `200 [ { taskId, kind, url, attempt, leaseUntil, userAgent, finderRequest? } ]` | `400` (`max` ∉ [1,4] or missing `workerId`), `401` (token), `429` (rate limit) |
| `POST /internal/fetcher/v1/tasks/{taskId}/heartbeat` | `{ "workerId": "fetcher-1" }` | `200 { "leaseUntil": "…" }` | `401`, `404` (`fetch_task_not_found`), `409` (`fetch_lease_lost`) |
| `POST /internal/fetcher/v1/tasks/{taskId}/result` | the fetch result **or** the finder result (below) | `200 { "taskId": "…", "status": "done" }` | `400` (validation, with a D8 code), `401`, `404`, `409` (`fetch_lease_lost`) |

`fetch_task_not_found` and `fetch_lease_lost` are **internal-only** codes: they are never shown to a user, never appear in `story_sources.error_code`, and are therefore not part of D8's public catalogue — **[DECISION T43] accepted as-is** (the TL ruled the two codes stay; they are documented here and nowhere else).

`lease` maps each row to a response item, and for `find_sources` re-derives the requester payload from the `generation_runs` row of that run (D2: `kind = 'find_sources'`), joined by the task's `generation_run_id` — **[DECISION T38]** that column is now part of `fetch_tasks` (`uuid NULL`, addition 3), so the finder payload is re-derivable without duplicating brief text into a table the fetcher can see. `fetch_tasks.episode_id` is **NOT NULL** (T38: a `find_sources` task is episode-level), so every task is deleted with its episode.

```jsonc
// finderRequest (kind = find_sources only)
{ "topic": "true_crime", "language": "vi", "seriesTitle": "…", "brief": "…",
  "allowList": ["vnexpress.net", "tuoitre.vn"], "maxCandidates": 10 }
// allowList comes from the 02.7.2-T1 allow-list table/option; when 02.7 has not shipped, no find_sources
// task exists, so this branch is exercised only by the T4 stub.
```

`result` validation, in order, each failure returning `400` with the code and **leaving the task `leased`** (it will expire and be swept — the fetcher's `409`/`400` handling decides whether to abandon or retry, and 02.5.2-T3 abandons on any `400`):

1. Lease ownership: `status = 'leased' AND leased_by = @workerId AND lease_until > now()` else `409 fetch_lease_lost`.
2. `fetch_source` + `status: "done"` [T39]: `text` non-empty and ≤ `Fetcher:MaxTextChars` (300,000) else `400 source_no_text` / `400 source_too_large`; `textSha256` present and equal to `hex(SHA256(UTF8(text)))` else `400 source_no_text` (a mismatch is corruption — never store it); `finalUrl` parses through `SourceUrl.Parse` and its registrable domain is not blocked else `400 source_domain_not_allowed`; `contentType` ∈ the accepted set (defence in depth: the fetcher already checked) else `400 source_unsupported_type`.
2b. `find_sources` + `status: "done"` [T39]: `candidates` present (≤ 50); see item 4.
3. `fetch_source` + `status: "failed"`: `errorCode` ∈ the D8 job-code set, else coerced to `source_unreachable` (never store an unknown code).
4. `find_sources` candidates: entries whose `url` fails `SourceUrl.Parse` are **dropped silently**; the rest are handed to the 02.7.2-T3 `CandidateExtractor` (D11 + allow-list + dedupe + cap 10) and inserted into **`source_candidates`** (02.7 plan §3, README §10 T59) with the task's `generation_run_id`; the run is then completed as in 02.7.2-T3 steps 5–7. Nothing is stored on `generation_runs` (D2 has no result column).

On a valid `fetch_source` result, in one transaction: write the object (§Storage), `source.MarkFetched(...)` / `MarkFailed(...)`, `task.Complete(now)` / `Fail(code, now)`, raise `SourceFetched { EpisodeId, SeriesId, UserId, SourceId, Status, ErrorCode, RegistrableDomain }`, write the outbox row (the outbox dispatcher turns it into `EpisodeUpdated`; no new SignalR event type — CR-7). Metrics: `fetch_tasks_total{status,error_code}` and `fetch_duration_seconds`, measured **lease → result** from `leased_at` (set by the lease statement, cleared on requeue), never from `created_at` — otherwise the histogram measures queue time and is useless.

### Storage (`src/NightTales.Infrastructure/Storage/ExtractedTextStore.cs`)

`IExtractedTextStore.WriteAsync(Guid userId, Guid episodeId, Guid sourceId, string sha256, string text, ct) → string key` and `ReadAsync(string key, ct) → string`. Key `research/{userId}/{episodeId}/{sourceId}/{sha256}.txt` (content-addressed, so a retry that yields the same text overwrites the same object and a changed text writes a new one). Written **before** the row update: a crash between them leaves an orphan object (cleaned by 13.3's deletion sweep) and never a row whose `extracted_text_key` points at nothing. ⚠️ Confirm with 13.3.1-T1 that the deletion sweep includes the `research/` prefix — this plan's [OPEN] 9.

### `FetchLeaseSweeperJob` (`src/NightTales.Worker/Jobs/FetchLeaseSweeperJob.cs`)

Recurring Hangfire job, id `fetch-lease-sweeper`, `Cron.Minutely()` (D10: every 1 min). One SQL statement per run:

```sql
-- RequeueExpiredLeases(@maxAttempts int, @backoffSeconds int)
UPDATE fetch_tasks
SET status = CASE WHEN attempts >= @maxAttempts THEN 'failed' ELSE 'queued' END,
    error_code = CASE WHEN attempts >= @maxAttempts THEN 'source_unreachable' ELSE NULL END,
    leased_by = NULL,
    lease_until = NULL,
    leased_at = NULL,
    not_before = CASE WHEN attempts >= @maxAttempts THEN not_before ELSE now() + make_interval(secs => @backoffSeconds) END,
    finished_at = CASE WHEN attempts >= @maxAttempts THEN now() ELSE NULL END
WHERE status = 'leased' AND lease_until < now()
RETURNING id, source_id, episode_id, attempts, status;
```

Then, for each returned row that became `failed` with a `source_id`, the job calls `StorySource.MarkFailed("source_unreachable", null, now)` so the UI shows a failed source rather than a task that silently vanished. [DECISION] The sweeper is idempotent and single-instance-safe (the `WHERE status='leased' AND lease_until < now()` is the guard), so no distributed lock is needed even if two Workers run it; ⚠️ Hangfire recurring jobs are per-server, so in a multi-Worker deployment the job must be registered with a `DisableConcurrentExecution`-style lock or the query alone must be trusted — the query alone **is** safe (each row is updated once because the status flips), so no lock is required; note it in the job's XML doc.

Metrics: `fetch_tasks_total{status="requeued"}` / `{status="failed",error_code="source_unreachable"}`; a log line per run with the counts only.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| The fetcher posts a result for a task the sweeper already requeued | `409 fetch_lease_lost` (the row is no longer `leased` by that worker); the fetcher drops the work |
| The fetcher posts twice (retry after a timeout on a `200`) | the first result wins (`status='done'` → the second gets `409 fetch_lease_lost`); the object write is content-addressed so a duplicate write is harmless |
| The object write succeeds and the transaction fails | an orphan object under `research/…`; cleaned by 13.3's sweep; the row stays `pending` and the next lease retries |
| The transaction commits and the outbox dispatch fails | the outbox retries (09); `EpisodeUpdated` is delayed, not lost |
| `story_sources` row deleted while its task is leased | the FK cascade deletes the task; the result POST gets `404 fetch_task_not_found` and the fetcher drops it |
| The Api restarts while 4 tasks are leased | the leases expire in ≤ 90 s; the sweeper (in the Worker, a separate process) requeues them |
| Two Workers run the sweeper concurrently | safe: the `WHERE status='leased' AND lease_until < now()` guard means each row flips once; the second run finds nothing |
| The Api's internal listener is accidentally exposed | the token is mandatory (start-up fails without it) and the network ACL is 11.2.2-T2's job; this task's test asserts the route is absent from the public listener |
| `max` > 4 requested | clamped to the platform cap minus leased, never an error (the client is trusted but the cap is absolute) — [DECISION] `400` only for `max` ∉ [1, 4] so a buggy client is visible; the effective count is `min(max, cap − leased)` |
| `lease_until` is in the past on read (clock skew) | `heartbeat`/`result` return `409`; the sweeper requeues; the clock source is `IClock` (UTC) |
| Rollback | disable `Fetcher:Internal:Enabled` (listener gone, fetcher logs 404s and retries) then redeploy; `fetch_tasks` rows keep their status and the sweeper keeps working |

## Notes

- [DECISION] `lease` clamps rather than errors above the cap, so a fetcher that asks for 4 while 3 are leased gets 1 without special-casing — but `max > 4` is a `400` because no caller should ever ask for more than the platform cap.
- [DECISION T38] The four column additions to D10's `fetch_tasks` list are **accepted**: `url`, `registrable_domain`, `generation_run_id`, `leased_at`; `episode_id` is **NOT NULL** (a `find_sources` task is episode-level). All four go into CR-4's bullet and are in `plan.md` §3.2.
- [DECISION T39] Every result body carries `status: "done" | "failed"`; the field is mandatory (`400` when absent).
- [DECISION T42] The lease statement takes a `pg_advisory_xact_lock` on a constant, so the platform cap (4) and the per-domain cap (1) are exact, not best-effort. The advisory lock is a correctness requirement — a rolling restart briefly runs two fetchers, so "one replica is enough" is not a reason to drop it.
- [DECISION] `fetch_task_not_found` / `fetch_lease_lost` are internal-only codes, deliberately outside D8 (which is a user-facing catalogue) — confirmed by T43.
- [DECISION] A task is never retried more than twice: D10's `attempts = 2` → `source_unreachable`. A user who wants another try uses `POST …/sources/{id}/retry` (02.5.1-T1), which counts against the 24 h cap — this keeps retries a user decision, not a background loop.
