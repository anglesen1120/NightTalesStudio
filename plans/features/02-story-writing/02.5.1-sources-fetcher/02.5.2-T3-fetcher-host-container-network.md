## Goal

A new .NET 10 host `src/NightTales.Fetcher/` runs a `BackgroundService` that leases tasks from the internal API, fetches and extracts them under the D11 rules, heartbeats while working, posts results, and holds **only** `FETCHER_API_TOKEN` + the internal base URL as configuration — no database, no object storage, no OpenAI, no Hangfire, no MPT, no listening port; and this task states the exact container/network requirements that 11.2.2-T2 implements and tests.

### Host (`Program.cs`)

```csharp
var builder = Host.CreateApplicationBuilder(args);

       .Validate(o => !string.IsNullOrWhiteSpace(o.BaseUrl), "Fetcher:Internal:BaseUrl is required")
       .ValidateOnStart();
builder.Services.AddSingleton<IAddressValidator, GlobalUnicastAddressValidator>();   // D20: the production one only
builder.Services.AddSingleton<IDnsResolver, SocketDnsResolver>();
builder.Services.AddSingleton<IRobotsPolicy, RobotsTxtPolicy>();
builder.Services.AddSingleton<IHostRateLimiter, HostRateLimiter>();
builder.Services.AddSingleton<IArticleExtractor, SmartReaderArticleExtractor>();
builder.Services.AddSingleton<ISourceFetcher, SafeHttpSourceFetcher>();
builder.Services.AddHttpClient<FetcherApiClient>(c => { c.BaseAddress = new Uri(baseUrl); c.Timeout = TimeSpan.FromSeconds(15); })
       .ConfigurePrimaryHttpMessageHandler(() => new SocketsHttpHandler { UseProxy = false, UseCookies = false });
builder.Services.AddHostedService<FetcherLoop>();
builder.Services.AddHostedService<FetcherHealthService>();     // /healthz on :8080 internal-only? NO — see below
builder.Services.AddSerilog(...);                               // D19 field allow-list
builder.Services.AddOpenTelemetry().WithMetrics(...);
```

**No listening socket at all** — not even a health endpoint. [DECISION T43] Liveness is proven by the lease loop itself: a fetcher that cannot lease logs a warning and exits non-zero after `Fetcher:ConsecutiveFailuresBeforeExit = 5`, and the supervisor restarts it. This keeps the ingress rule at "none" (11.2.2-T2) and removes a port that could be probed from the internet.

Token handling: `FetcherApiOptions.Token` is read from `FETCHER_API_TOKEN` (the same runtime secret the Api verifies, 11.5.2). Missing/empty → **exit 1 at start-up** with a clear message; the client never sends an empty `Authorization`. The token is never logged, never put in a URL, and never included in an exception message (`FetcherApiClient` strips the header from any thrown `HttpRequestException` context).

### `FetcherLoop` (`BackgroundService`)

```csharp
protected override async Task ExecuteAsync(CancellationToken stoppingToken)
{
    var inFlight = new Dictionary<Guid, Task>();          // taskId → running work
    var consecutiveFailures = 0;
    while (!stoppingToken.IsCancellationRequested)
    {
        // 1. Reap finished work.
        foreach (var (id, task) in inFlight.Where(p => p.Value.IsCompleted).ToList())
        {
            if (task.Exception is not null) _log.LogWarning(task.Exception, "fetch task faulted: {TaskId}", id);
            inFlight.Remove(id);
        }

        // 2. Lease only what we can run: the client cap is an optimisation, the server cap is the truth (F15).
        var want = _opt.Value.MaxLeasesPlatformWide - inFlight.Count;
        if (want <= 0) { await Task.Delay(TimeSpan.FromMilliseconds(500), stoppingToken); continue; }

        var leased = await _api.LeaseAsync(_instanceId, want, stoppingToken);   // 401 → fatal; 5xx → backoff
        consecutiveFailures = leased.IsError && leased.FirstError.Type is ErrorType.Unexpected ? consecutiveFailures + 1 : 0;
        if (consecutiveFailures >= _opt.Value.ConsecutiveFailuresBeforeExit)
        { _log.LogError("fetcher cannot reach the internal API; exiting for a supervisor restart"); Environment.Exit(1); }

        foreach (var item in leased.Value) inFlight[item.TaskId] = RunTaskAsync(item, stoppingToken);

        if (leased.Value.Count == 0) await Task.Delay(_opt.Value.IdlePollMilliseconds, stoppingToken);  // 2 s default
    }

    // 3. Shutdown: stop leasing, cancel in-flight work (their leases expire in ≤ 90 s and the sweeper requeues).
    await Task.WhenAll(inFlight.Values.Select(t => t.ContinueWith(_ => { })));
}
```

`RunTaskAsync(item, ct)`:

1. `using var heartbeat = new TaskHeartbeat(_api, item.TaskId, _instanceId, _opt.HeartbeatSeconds)` — a `PeriodicTimer` that POSTs a heartbeat every 60 s and sets a flag on a `409 fetch_lease_lost`; the fetch's own `CancellationTokenSource` is linked to that flag so a lost lease aborts the work instead of finishing it and being rejected. **T105 (SEC-0928-1):** for a `fetch_source` task the heartbeat self-disposes after `TotalTimeoutSeconds + ExtractTimeoutSeconds` (~15 s) — a hostile page that stalls a fetch must not pin one of the ≤ 4 lease slots forever; past that bound the work is cancelled, the lease is released (it expires in ≤ 90 s and the sweeper requeues/fails it), and no result POST is attempted. Only `find_sources` (02.7.2-T3, its own duration) heartbeats past it.
2. `fetch_source`: build `SourceFetchRequest` (parse `item.Url` again locally — defence in depth) and call `ISourceFetcher.FetchAsync`; map `FetchedSource` → the T2 `FetchedResult` body, or the error code → `FailedResult`.
3. `find_sources`: call `ISourceFinderRunner` (02.7.2-T3 owns it; this host only routes). When the flag/runner is absent, fail the task with `find_sources_generation_failed` — no such task is created before 02.7 lands, so this path exists only for the T4 stub.
4. POST the result. On `200` → done. On `409 fetch_lease_lost` → drop silently (the sweeper owns it, no retry). On `400` → log the code and **do not retry** (a validation failure is deterministic). On `5xx`/timeout → retry the **result POST** up to 3 times with jittered backoff (the work is done and the lease may still be alive; the POST is idempotent because the task's status flips to `done` once). On a 3rd failure → give up; the lease expires and the sweeper requeues, which re-does the fetch once (attempts = 2) and then fails it — accepted, because losing a completed fetch to a transient API blip is worse.
5. Never throws: every failure is a result POST or a log line, so one bad URL cannot kill the loop.

### Container requirements (the text 11.2.2-T2 implements)

| Aspect | Requirement |
|---|---|
| Image | same hardened base as Api/Worker, non-root user, read-only root filesystem, no shell/curl/wget in the final layer, no build tools |
| Processes | one (the .NET host); no sidecar, no Chrome, no Python **unless** 02.5.2-T0 chose trafilatura and the TL signed the exception |
| Listening ports | **none** (see the [DECISION] above) |
| Egress allowed | `0.0.0.0/0:80` and `0.0.0.0/0:443`; the Api internal listener `api:8081`; the configured DNS resolver |
| Egress denied | PostgreSQL, the object-storage endpoint, the render subnet, the `mpt-adapter` port, `169.254.169.254` and the whole `169.254.0.0/16`, the app subnet except `api:8081` |
| Ingress | none from anywhere |
| Secrets | `FETCHER_API_TOKEN` only |
| Config | `Fetcher:Internal:BaseUrl`, `Fetcher:UserAgent`, `Fetcher:PublicHost`, the caps, `Fetcher:BlockedDomains` |
| Storage/DB mounts | none (no volumes except the read-only rootfs and a `/tmp` tmpfs with a 64 MiB limit) |
| Egress test (11.2.2-T2 owns it) | from the fetcher's network namespace (a debug sidecar sharing it, because the image has no shell; 11 T14, 11 CR-10): `api:8081` reachable; `https://example.com` reachable; `postgres:5432`, the storage endpoint, a render node address and `169.254.169.254` all fail; a connect to the app subnet on any port other than 8081 fails |
| Scale | 1 replica in P; the lease API's 4-lease cap makes a second replica safe but pointless at this volume [DECISION] |
| Resource limits | CPU 0.5, memory 512 MiB, pids 128. ⚠️ Corrected (T105, SEC-0928-1): the 2 MiB / 300,000-char caps bound **response bytes**, not parse cost — a runaway SmartReader/AngleSharp parse is bounded by the extract pre-parse guard (elements/depth) + `ExtractTimeoutSeconds` watchdog (02.5.2-T1); these container limits are the backstop for everything else |

### Observability

Metrics: `fetch_tasks_total{status,error_code}`, `fetch_duration_seconds`, `fetch_leases_active` (gauge, the in-flight count), `fetch_robots_cache_entries`, `fetch_api_errors_total{operation,kind}` (lease/heartbeat/result × 4xx/5xx), `fetch_process_working_set_bytes`. Logs: task id, source id, kind, attempt, status, error code, http status, duration, registrable domain — never the URL path/query, title or text (D19). Alerts (08.2, owned there, listed here for completeness): failure rate > 30 % over 15 min; `fetch_leases_active == 0` for 10 min while the API reports queued tasks; more than 3 restarts in an hour.

## Acceptance checks

- [ ] `dotnet run --project src/NightTales.Fetcher` with a valid token and one queued task fetches it, posts the result, and the source becomes `fetched` in `psql` — with no DB connection string anywhere in the fetcher's config (`grep -r "ConnectionStrings" src/NightTales.Fetcher/` → 0).
- [ ] With `FETCHER_API_TOKEN` unset the process exits non-zero within 2 s with a message that does not contain a token value.
- [ ] With the internal API stopped, the process logs warnings and exits non-zero after 5 consecutive failures (the supervisor-restart contract), rather than spinning silently.
- [ ] `dotnet list src/NightTales.Fetcher package` and `dotnet list src/NightTales.Fetcher.Core package` show no EF Core, no `OpenAI`, no `Hangfire`, no AWS/S3 client; the architecture test fails if one is added.
- [ ] With 6 queued tasks the process runs at most 4 concurrently (`fetch_leases_active` peaks at 4; `psql -c "select count(*) from fetch_tasks where status='leased'"` never exceeds 4).
- [ ] Two tasks on the same registrable domain are not both in flight (the server refuses the second lease; the log shows the second task leased only after the first finished).
- [ ] A `fetch_source` task that would outlive `TotalTimeoutSeconds + ExtractTimeoutSeconds` stops heartbeating (no >60 s heartbeat run holds the lease), is cancelled, and the lease is released so the sweeper requeues it — a hostile slow-parse page cannot pin the ≤ 4 lease slots (T105).
- [ ] Deleting the source mid-fetch: the result POST returns `404` and the loop logs and continues (no crash, no retry storm).
- [ ] Simulating `409 fetch_lease_lost` mid-fetch (sweeper forced to run early) aborts the fetch within one heartbeat and drops the result without a retry.
- [ ] Killing the process mid-fetch: within ~2 min the sweeper requeues the task and the restarted fetcher completes it (attempt 2).
- [ ] `docker compose --profile fetcher up fetcher` starts the container with a read-only rootfs and no volumes; `docker exec fetcher sh -c 'wget -qO- http://169.254.169.254/'` fails (no tool, or no route) — the authoritative version of this check is 11.2.2-T2's egress test.
- [ ] No log line or trace attribute contains a source URL path/query, title or text (`grep` the captured logs for the test page's path → only the registrable domain appears; the OTel trace has no `url.full` for the fetcher client).
- [ ] The fetcher's process list contains exactly one dotnet process and no browser/Python (unless T0 chose the sidecar, in which case the decision record says so).

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| The internal API returns `401` | fatal: log + exit non-zero (a wrong/rotated token must not be retried forever). This is the rotation window described in `plan.md` §11 |
| The internal API is down at start-up | warn + retry with backoff; exit after 5 consecutive failures so the supervisor restarts with fresh DNS |
| The DNS resolver is unreachable | `SocketDnsResolver` throws → `source_unreachable` per task; the loop survives |
| Clock skew between fetcher and Api | leases are server-timed; the fetcher only counts its own heartbeat interval, so skew shortens or lengthens nothing on the server side |
| A result POST succeeds but the response is lost | the task is `done`; the retry gets `409 fetch_lease_lost` and is dropped (idempotent by status) |
| A task's URL is malformed (a bug upstream) | the fetcher's local re-parse fails → posts `failed source_url_invalid`… ⚠️ that code is a **400 user** code, not a job code; [DECISION] the fetcher posts `source_unreachable` in this case (the row must never carry a user-facing 400 code), and logs the anomaly |
| The container is OOM-killed mid-fetch | the supervisor restarts it; the lease expires; the sweeper requeues; attempt 2 completes or fails |
| Two replicas run | safe: the server's 4-lease cap and the domain cap hold; the client cap is per process, so the pair can hold 4 total, not 8 (the server is the truth) |
| The `Fetcher:BlockedDomains` config drifts between the Api and the fetcher | the fetcher's copy is a defence-in-depth re-check; a stale copy can only *block* more, never less, because the Api already rejected the task at creation — [DECISION] the fetcher logs a start-up warning if its blocklist hash differs from a `Fetcher:BlocklistHash` config value the Api also has (cheap drift detection, no shared config store) |
| Rollback | stop the container; queued tasks wait, leases expire, the sweeper requeues, nothing is lost; the Api keeps serving sources with `pending` rows and the UI shows them as waiting |

## Notes

- [DECISION T40] `NightTales.Fetcher.Core` (Domain only) is **accepted**; 00 §5.2 gains the layout row and `NightTales.Infrastructure` references Core instead of owning the fetcher classes. This is the only structural change this task proposes outside its own folder.
- [DECISION T43] No health endpoint: liveness = "can lease". The container keeps the ingress rule at **none** and adds no probeable port; the host exits non-zero after 5 consecutive internal-API failures so the supervisor restarts it.
- [DECISION T43] The fetcher has **no** storage egress — the Api writes the extracted-text object (see 02.5.2-T2 §Storage). The egress table above is therefore final, and 11.2.2-T2's egress test must assert the storage endpoint is unreachable from the container.
- [DECISION T43] The 429 `Retry-After` header for `source_fetch_limit_reached` is produced by 09's `ProblemDetails` mapper (CR-20), so nothing in this feature sets it locally.
- [DECISION] A malformed URL from the server is reported as `source_unreachable`, never as a 400 user code — `story_sources.error_code` must stay inside the D8 job-code set.
- [DECISION] One replica in P. A second replica is safe by construction but adds an operator surface for no throughput gain at 4 leases.
- [DECISION] The result POST is retried (idempotent) but a `400` is not (deterministic) and a `409` is not (the sweeper owns the task).
