## Design

### Harness

`tests/NightTales.TestKit/Fetching/` (started by 02.5.2-T1, completed here):

| Piece | Purpose |
|---|---|
| `HttpTestServer` | an in-process Kestrel on `127.0.0.1:{ephemeral}`, routes registered per test: `/ok`, `/redirect?to=`, `/gzip-bomb`, `/pdf`, `/binary-as-html`, `/robots-disallow`, `/robots-500`, `/robots-404`, `/slow?ms=`, `/cookie-setter`, `/set-cookie-then-check`, `/spa`, `/short-text`, `/long-text`, `/deep-nested`, `/many-elements`, plus a request log (method, path, headers, count) for assertions |
| `LoopbackAllowingAddressValidator` | allows `127.0.0.1`/`::1` and delegates to `GlobalUnicastAddressValidator` otherwise (D20) |
| `FakeDnsResolver` | scripted answers per host: `public-then-private`, `private-only`, `empty`, `single-label`; a `FlipAfterFirstResolve(host)` helper for the rebinding case |
| `StubFetcherApi` | the 02.5.2-T2 handlers hosted in-process, so the loop tests do not need a second process |
| `SourceSeed` | inserts an episode + source + `fetch_tasks` row through `IAppDbContext` (D20 builders) |

The suite is split in two files so the failure output is readable:

- `tests/NightTales.Api.IntegrationTests/Features/Research/FetcherSsrfSuiteTests.cs` — cases 1–20 (the fetcher's own behaviour, `ISourceFetcher` called directly, one test per threat-table row group).
- `tests/NightTales.Api.IntegrationTests/Features/Research/FetcherAbuseAndCapsTests.cs` — cases 21–34 (+ 23b, 23c, 23d) (end-to-end through the lease API + the loop, plus the volume caps).

Every test asserts on the **D8 code** (or the observable row state), never on an exception type, and each carries the threat-table row number in a comment so the gate review can walk the table.

### Cross-cutting assertions (in every test, via a fixture)

- **No loopback bypass in production** (D20): the suite runs twice over a representative subset — once with `LoopbackAllowingAddressValidator` (the abuse cases must still be blocked by the *other* rules) and once with `GlobalUnicastAddressValidator` (the test server is unreachable, proving the production graph has no bypass). A test that only passes with the test validator is a finding, not a pass.
- **No leakage** (D19): the captured Serilog output and the OTel trace for each case are scanned for the source URL's path, its query string, the page title and the extracted text; only the registrable domain may appear.
- **No raw HTML persisted**: after each case, `story_sources.extracted_text_key` (when set) points at an object whose content contains no `<` tag and equals the posted text; a failed case writes no object.
- **Error codes stay inside the catalogue**: every `story_sources.error_code` produced by the suite is a member of the D8 job-code set (a reflection assertion over the set, so a new code cannot be invented by accident).
- **Determinism**: no test depends on the public internet; `example.com` appears only as a *name* in fake-DNS answers, never as a real request (a test asserts the suite's HTTP client is never used with a public address by checking the fake resolver's resolution log).

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| A test needs a real public host (none should) | it is rewritten with the fake resolver; the suite must never depend on the internet (a CI without egress must pass) |
| Kestrel's ephemeral port collides | the harness binds port 0 and reads the assigned port; no fixed ports anywhere |
| The loopback server is unreachable with the production validator | that is the point of the second run — the test asserts the fetch fails and the server sees nothing |
| The sweeper test needs ~2 min of wall time | use `IClock`/a forced sweeper invocation (`FetchLeaseSweeperJob.ExecuteAsync()` called directly with a `FakeClock` set 91 s ahead) instead of sleeping — the suite stays under 3 min |
| The gzip bomb is expensive to generate | a 3 MiB zero-filled payload compresses to a few KiB and expands past the cap in milliseconds; generate it once per run in a fixture |
| A blocked case fails because the request *did* reach the server | a real finding: the case must not be weakened to pass; escalate to 02.5.2-T1 |
| A case is flaky on a loaded CI machine (timing: rate limit, timeout) | widen the assertion to an inequality with a margin (e.g. ≥ 0.9 s rather than ≥ 1.0 s) but never remove it; a timing case that cannot be made stable is moved to a manual check with a note |
| The error-code reflection assertion fails after a new code is added | add the code to the D8 set in the test **and** flag it to the TL (the catalogue is a contract, D8/F29) |
| The suite is green but a threat-table row has no test | the evidence file's table must have no empty "test name" cell; the gate review reads that file, not the test list |
| Rollback | none needed (tests only) |

## Notes

- [DECISION] The suite asserts on the D8 code and on the *observable* server-side request log, never on internal call counts or exception types. "The request never happened" is the assertion that matters for SSRF; "an error was returned" is not.
- [DECISION] Two validator runs for the representative subset, because D20's test-only loopback allowlist is exactly the kind of thing that can silently become a production bypass; the second run is the regression guard.
- [DECISION] `ssrf-suite-evidence.md` is a mapping table, not prose: the gate reviewer walks threat-table row → test name → observed result. It is the `02-M1-research` gate artefact for the app side; 11.2.2-T2's egress test is the container side.
- ⚠️ Cases 5, 11 and 17 depend on `System.Uri`'s parsing of exotic host forms (decimal/octal/hex, IDN, shorteners). If `Uri` normalises a form differently than assumed, the assertion is adjusted to the observed normalisation **only after** confirming the address validator still blocks the resulting IP — the security property is "no request to a non-global address", not "this exact string is rejected".
- ⚠️ The suite is the acceptance evidence for F14 and the mitigation for the §8 risk row "Fetcher abused for SSRF"; it must be run on every PR touching 02.5.2.
