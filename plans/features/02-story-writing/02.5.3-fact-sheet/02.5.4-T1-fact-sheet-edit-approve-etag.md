# 02.5.4-T1 — Fact-sheet edit/approve with `fs-` ETag, fact-id stability, F13/F26 rules

| Story | Size | Area | Depends on | Blocks | Phase / flag |

## Goal

The owner can correct a draft sheet (edit / delete / add facts) and approve it under optimistic concurrency, with fact ids that stay stable and are never reused, and with approve refused until the source-diversity rule (F13) holds.

## Inputs

Decisions D1, D8, D9, D13, D21; findings F12, F13, F26, F29; 02 §4 02.5.4. Outputs of 02.5.3-T2 (`fact_sheets` incl. `source_aliases`, `FactSheetValidator`, `FactSheetDto`, the `Superseded` status and its migration), 02.5.1 (`story_sources`, `user_note` kind with `note_text`).

## Design

**Routes** — plan.md §5: `GET /episodes/{id}/fact-sheet` (200 + `ETag: "fs-<id>"`), `PUT /episodes/{id}/fact-sheet` (`If-Match`), `POST /episodes/{id}/fact-sheet/approve` (`If-Match`). Missing `If-Match` → 428 `if_match_required`; mismatch → 412 `fact_sheet_conflict` (D9, D8).

**`UpdateFactSheetCommand(Guid EpisodeId, string IfMatch, FactSheetContentDto Content)`** — Application `Features/Research/UpdateFactSheet/`:

- Episode status gate (F26): allowed in `draft` / `story_review`; in `story_approved` → 409 `episode_invalid_state` (UI offers reopen, 02.3.2); `rendering` → 409 `episode_invalid_state` always.
- Id reconciliation (`FactIdAllocator`, Domain `Research/`): a non-null `Id` present in the current version is **kept verbatim** (order as given); an unknown or duplicated input id → 400; `null` `Id` → `f{++maxFactId}` in input order. `maxFactId` starts at `max(version.max_fact_id)` so ids from **any** prior version are never reused, even after deletions (F12). Deleted facts vanish from the new version; their ids are retired forever.
- Every input fact requires ≥ 1 `SourceIds`; each id must belong to the episode's `story_sources` (a `user_note` source is allowed and is labelled "your note" / "ghi chú của bạn" — 02 §4). Unknown source id → 400 `fact_sheet_invalid_content` (T51).
- Statement re-validated with the same rules as 02.5.3-T2 step 2 (NFC, non-empty, ≤ 600 chars); failure → 400 `fact_sheet_invalid_content` with field errors in `errors` (T51).
- **`confidence` (T53) is preserved, never dropped by an edit**: for an existing `Id`, a null input `Confidence` keeps the stored value and an explicit value overrides it; a **new** fact defaults to `High` (the user asserts it) unless the body says otherwise. The response always carries the effective value.
- Persist a **new row**: `version = max(version) + 1`, `status = draft`, `generation_run_id = null`, `prompt_version = "user"`, `created_by = userId`, `max_fact_id`, `source_aliases` (alias→id map for the kept/added facts, CR-4), recomputed `content_sha256`. Never mutate the previous version (D9 — the ETag is the row id).
- `[Audited("episode.fact_sheet_saved", Category.Episodes, Visibility.User)]`; outbox `EpisodeUpdated` with ids only (`{ episodeId, seriesId }` — the sheet id, status, version and ETag travel in the response/DTO the client refetches); `FactSheetSaved` domain event. Response: 200 `FactSheetSummaryDto` + new `ETag`.

**`ApproveFactSheetCommand(Guid EpisodeId, string IfMatch)`**:

- Same ETag rules; target row must be `status = draft` (re-approving an approved row → 412 `fact_sheet_conflict`, the ETag points at the draft).
- **F13 gate**: among `Facts`, collect distinct `SourceIds` where the source is `kind = url`, `fetch_status = fetched`; require ≥ 2 such sources **each cited by ≥ 1 kept fact** with distinct `content_sha256`; else 409 `story_sources_required`. Fewer than 5 facts (`F13SourceDiversityCheck.MinFacts`) → 409 `fact_sheet_sources_insufficient`.
- Sets `status = approved`, `approved_by/at`; `[Audited("episode.fact_sheet_approved", …)]`; outbox `EpisodeUpdated` (ids only) + `FactSheetApproved`. **Does not** touch the story: staleness is detected at story approve via `story.fact_sheet_id` (F12, 02.5.5-T1).

**`GetFactSheetQuery`** returns the latest version (draft or approved) with resolved `FactSourceRefDto` (title, url, alias, `IsUserNote`) and the `fs-` ETag.

**Concurrency** — partial unique `(episode_id) WHERE status = 1` means approving a new draft while an older approved row exists must first supersede it: the approve handler marks any existing approved row `Superseded` in the same transaction **and flushes that UPDATE before the draft becomes `Approved`** (EF may reorder two statements of one save, so the demotion is its own `SaveChanges`). `FactSheetStatus.Superseded = 2` **already exists** — shipped by 02.5.3-T2 (#184) with the partial unique index; the `[OPEN]` in plan.md §10 (alternative: deleting the old row, rejected to keep the audit trail) is therefore closed by that task and nothing is added to the enum here.

## Tests

- ETag: 428 without `If-Match`, 412 on stale, F26 state gates, new row per edit with the previous version untouched.
- Ids: kept ids preserved, new facts get `MaxFactId+1`, retired ids never reused, duplicate/unknown ids and unknown sources → 400 `fact_sheet_invalid_content` (`PutFactSheet_InvalidBody_Returns400FactSheetInvalidContent`), `user_note` allowed and labelled.
- Approve: F13 diversity (1 cited source, same `content_sha256`, unfetched source, zero facts → 409), success sets approved + new ETag, previous approved row superseded.

## Failure handling and edge cases

- Two tabs edit the same draft → the second gets 412; no merge, no partial write.
- Approve while a generate run is active → the draft ETag still governs; approving the previous draft is allowed and the in-flight run's new version will be a fresh draft (the user must re-approve). Document in the UI copy.
- A fact whose only source was deleted from the episode → `UpdateFactSheet` rejects the body (unknown source id) and the UI must offer to remove that fact; approve's F13 check ignores deleted sources.
- `user_note` sources never count toward F13 diversity (they are not `fetched` url sources).
- Adding a fact to an **approved** sheet is not allowed directly: the first edit creates a new draft version (02 §4).

### Choices made while implementing (02.5.4-T1, 2026-10-14)

1. **`GET` without a sheet is 404 `fact_sheet_not_found`.** The read has no separate episode lookup: the tenant-filtered *sheet* lookup answers for the unknown, the foreign and the sheet-less episode alike, so no request can tell them apart (decision 9). New code `fact_sheet_not_found` added to `ErrorCodes` + `ErrorCatalogue` (404) + `web/src/assets/i18n/errors/{en,vi}.json`.
2. **Check order (decision 8) is: lock → episode/current-version load (404) → `If-Match` (428/412) → F26 state (409) → body (400).** The PUT answers 400 only after the route can actually save, so an invalid body never hides a 409/412. The approve route adds its two steps after the state gate: target must be `draft` (else 412, the tag no longer names the current row) and then F13 (409).
3. **A user note's title is the neutral key-free `note`** (`FactSheetWire.UserNoteTitle`), with `IsUserNote = true` and `Url = null`; the SPA localises it (`"ghi chú của bạn"` / `"your note"`). A **deleted source** renders `unavailable` (`FactSheetWire.MissingSourceTitle`) with `Url = null`, so a `GET` after a source deletion still answers 200 with the citation kept — the version is not rewritten. A fetched URL source with no title of its own falls back to its final URL, then its URL, then `unavailable`.
4. **Minimum 5 facts is `F13SourceDiversityCheck.MinFacts` at approve, not at save.** An edit may store fewer than 5 (or zero) facts; approve refuses them with 409 `fact_sheet_sources_insufficient`.
5. **`Confidence` (T53) is preserved.** Omitted in the body → a kept fact keeps its stored value and a new fact defaults to `high`; present → it overrides. A fact whose statement **and** source list are unchanged is copied verbatim (its `Origin` and `SourceOverlap` survive); any other change stores `Origin = user` and drops the stale overlap score.
6. **Duplicates are answered per fact: one error entry per failing group**, with `metadata.field = facts[i].statement|sourceIds` and `metadata.limit` where a cap applies. Unknown, duplicate and retired ids come from `FactIdAllocator` in the same 400 shape. Facts are capped at `FactSheetExtractionOptions.MaxMaxFacts` (mirrors the `facts.v1` extraction ceiling) and sources per fact at `FactInputLimits.MaxSourcesCeiling` (10 — the alias scheme is `s1…s10`).
7. **A unique refusal at flush is 412 only on the two fact-sheet indexes.** The Application layer cannot reference Npgsql, so the provider's error is read through the BCL — `DbException.SqlState` plus the `ConstraintName` entry Npgsql records in `Exception.Data` — and `DbUpdateException` with SQLSTATE 23505 **on `ux_fact_sheets_episode_version` or `ux_fact_sheets_episode_approved`** is mapped to `fact_sheet_conflict` by the one shared `FactSheetFlushConflict.IsFactSheetUniqueViolation` (the same answer a lost race deserves, and the reason `Supersede()` is flushed separately before the approval UPDATE). **Any other 23505 is rethrown and stays a 500**: it is not this contract's race, and hiding it would report a defect as a client conflict.
8. **`UpdateFactSheetCommand`/`ApproveFactSheetCommand` carry no `Idempotency-Key`** and the routes declare none: the ETag is the concurrency token, so a replay is a 412 (same as `PUT /episodes/{id}/story`). Both routes use `RequireIfMatch()`, so a missing header is 428 before the handler; the handlers also check the value themselves (the story *approve* route documents the header instead of filtering it — that deviation is deliberate there and not copied here, per the S35 contract's explicit `RequireIfMatch()` on both routes).
9. **Free routes carry no rate-limit policy** — the same accepted residual as the story read/edit/approve routes; no new policy was invented.
10. **The `fs-` ETag is emitted from the DTO** (`IHasETag`), not re-read after commit: it names the version row's id and no commit can change it (unlike `xmin`-based tags). The body is bound as `FactSheetContentDto` with the host's camelCase policy; an unknown `confidence` string is refused by the `JsonStringEnumConverter` before the handler runs.
11. **`FactStatementRules` is shared with the extraction**, so an edit accepts exactly the statements the model could have produced (same NFC normalisation, control-character and length rules) — no second set of rules.
12. **Realtime:** `FactSheetSaved`/`FactSheetApproved` are consumed by two new `IOutboxHandler`s that send `RealtimeEventName.EpisodeUpdated` with ids only (no new event type), registered in the Worker's DI next to the two 02.5.3-T2 fact-sheet handlers.
13. **plan §5 realtime payload (R5).** plan.md §5 now states what the shipped handlers send: `EpisodeUpdated` with **ids only** (`{ episodeId, seriesId }`, NOTIFY `data: null`), never `change`/`factSheetId`/`status`/`version` (contract decision 22; `FactSheetRealtimeHandlers.cs` builds `RealtimeIds(EpisodeId, SeriesId)` for `FactSheetGenerated`, `FactSheetSaved` and `FactSheetApproved`). The client reads the sheet id, status and version from the fact-sheet DTO it refetches.
14. **Accepted residual S2 — owner: TL.** `FactStatementRules` rejects only C0 controls, DEL, the SEC-6 bidi controls and lone surrogates, so it still **accepts** C1 controls `U+0080–U+009F`, zero-width/format characters (e.g. `U+200B` ZWSP, `U+00AD` soft hyphen, `U+FEFF`) and Unicode tag characters `U+E0000–U+E007F`. The same rules are shared with the extraction validator shipped in #184; fix in `FactStatementRules` for **both** paths (extraction via `FactSheetValidator` and edit via `UpdateFactSheetCommandHandler`), with a test row per character class.
15. **Accepted residual S3 — owner: the 02.5.6 task.** A user-edited fact skips the F18 copy/overlap guard (`SourceOverlap = null`) until 02.5.6 scoring exists; the story-level similarity check at story approve is the backstop.
16. **A version cites at most ten distinct sources (`s1…s10`).** `FactSheetSourceAliases.MaxAliasNumber` is the scheme's ceiling (README F12) and `Reconcile` throws on an eleventh source, so `UpdateFactSheetCommandHandler` refuses a body whose facts cite more than ten distinct sources **before** the alias map is built: 400 `fact_sheet_invalid_content`, `metadata.field = facts` (`PutFactSheet_ElevenDistinctCitedSources_Returns400WithTheFactsField`, and `PutFactSheet_TenDistinctCitedSources_SavesTheVersion` for the ceiling itself). Per fact the cap is `FactInputLimits.MaxSourcesCeiling` (10, decision 6) — the two are separate limits: ten sources on one fact, or ten across ten facts, are both legal.
17. **Source aliases are recycled.** An alias whose source is no longer cited becomes free for a new source (`FactSheetSourceAliases.Reconcile`); a still-cited source always keeps its alias, so the scheme stays within `s1…s10` (review finding R3, 2026-10-14). Accepted P3 test gaps (delta review): no unit test pins "any other 23505 is rethrown" in `FactSheetFlushConflict` (the two real-Postgres race tests prove the positive path); `FactSheetChangeTrackingTests.PutAndApprove_…` cannot see a spurious `facts` rewrite on the approve path (`LoadedFactSheet_WithNoEdit` covers the comparer itself); `CopyFacts` throws on a fact whose inner lists are null, which stored documents never contain.
