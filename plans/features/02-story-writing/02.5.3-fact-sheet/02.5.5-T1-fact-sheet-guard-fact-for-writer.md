## Goal

The story pipeline can only run on the currently approved sheet: a fiction episode passes through with no facts, a true-crime episode without an approved sheet is refused (409 `fact_sheet_required`), the writer receives facts only (never raw source text), and `fact_sources` in the stored story is built by the backend from `story_sources`.

## Inputs

Decisions D3, D6, D8, D21; findings F12, F18, F26; 02 §4 02.5.5. Outputs of 02.5.4-T1 (`fact_sheets` approved state, `fs-` ETag), 02.2.1 (`IStoryWriter`, `StoryWriteRequest`), 02.2.2-T3 (`GenerateStoryJob`), 02.5.6 (`ScoreFact`/corpus, not used here).

## Design

**Ports (D21 — exact shapes, do not rename)**

```csharp
// src/NightTales.Application/Abstractions/Research/IFactSheetGuard.cs
public interface IFactSheetGuard { Task<ErrorOr<ApprovedFactSheet>> EnsureApprovedAsync(Guid episodeId, Topic topic, CancellationToken ct); }

public sealed record ApprovedFactSheet(Guid? FactSheetId, int? Version, IReadOnlyList<FactForWriter> Facts, IReadOnlyDictionary<string, Guid> AliasToSourceId)
{
    public static ApprovedFactSheet None { get; } = new(null, null, [], new Dictionary<string, Guid>());
}
public sealed record FactForWriter(string Id, string Statement, IReadOnlyList<string> SourceAliases);
```

`FactForWriter` deliberately carries **no** `SourceIds`, no URL, no title (D6: the writer sees aliases only). It is what the writer prompt serialises into `facts[]`.

**`FactSheetGuard`** — `src/NightTales.Application/Features/Research/FactSheetGuard.cs`: a fiction topic (`topic.IsFiction()`: `Ghost`, `Spiritual`; 09 README D16) → `ApprovedFactSheet.None` (success; fiction needs no sheet). `Topic.TrueCrime`: no `status = approved` row → `Error.Conflict(code: ErrorCodes.FactSheetRequired)` → 409 `fact_sheet_required` (D8; status from the 09 catalogue by code, 09 README D7) (09 CR-9); an approved row with `Facts.Count == 0` → 409 `fact_sheet_required` (an empty sheet is not usable); otherwise `ApprovedFactSheet(row.Id, row.Version, facts as FactForWriter, aliasMap)`. The alias map is read from the persisted **`fact_sheets.source_aliases`** column (CR-4/D21) — not re-derived from the live `story_sources`, so editing sources after generation cannot corrupt `AliasToSourceId`. Read-only, no side effects, scoped.

**`FactSourcesBuilder`** — Domain `Stories/Facts/FactSourcesBuilder.cs` (D3: the backend adds `fact_sources` to `story_versions.content`):

```csharp
public static IReadOnlyList<FactSourceRef> Build(StoryContentV1 content, ApprovedFactSheet sheet, IReadOnlyDictionary<Guid, SourceMetadata> sources);
public sealed record FactSourceRef(Guid SourceId, string Title, string Url);
```

Rules: collect every `fact_ref` in `hook`, `paragraphs[]` and `ending` (D3); resolve ref → `FactForWriter` → `SourceAliases` → `AliasToSourceId` → `SourceId`; a ref absent from the approved sheet is unresolvable and is returned in `UnknownRefs` for the self-review to flag as a blocking objective issue (02 §4, owner 02.6.1-T2); output is de-duplicated by `SourceId`, ordered by first use, and **never** derived from anything the model wrote (F12); a ref with no source rows (deleted source) is skipped and reported. For a `kind = user_note` source the `FactSourceRef` carries the note label ("your note" / "ghi chú của bạn") as `Title` and a null/empty `Url` — the writer never receives the note text as a URL.

**Staleness (F12, D21, T54)** — the story link is `story_versions.fact_sheet_id`. (1) `GenerateStoryCommand` calls the guard before reserving; error → 409 `fact_sheet_required`. (2) `GenerateStoryJob` start re-runs the guard and compares `FactSheetId` to the `fact_sheet_id` captured at run creation; changed → run fails `story_generation_failed`, `error_detail = "fact_sheet_outdated"`, `counts_toward_limit = false` (D2). (3) The approve-side check (409 `story_fact_sheet_outdated`) lives in **02.3.2-T1 / 02.3.3-T1** and calls this same guard; this task only provides it.

**Writer wiring** — `GenerateStoryJob` step 1 (D21) passes `ApprovedFactSheet.Facts` into `StoryWriteRequest.Facts`; `IStoryWriter` serialises them as `"facts":[{"id":"f1","statement":"…","sources":["s1"]}]` inside the single JSON data object (D6). Raw `extracted_text` is **never** placed in the writer request.

## Tests

- Guard: fiction → `None`; true crime without an approved (or with an empty, or only superseded) sheet → 409 `fact_sheet_required`; approved → facts carry ids + aliases only; alias map rebuilt from stored aliases/ids.
- Builder: refs collected from hook/paragraphs/ending; de-dupe by `SourceId` in first-use order; unknown ref reported not built; deleted source skipped and reported; output never contains model-written URLs/ids.
- Job/command: `GenerateStoryCommand` gate; mid-run sheet change fails the run with `fact_sheet_outdated` and `counts_toward_limit = false`; writer receives facts, never raw source text.
- E2E (02 §7): sources → sheet → approve → story; `story_versions.content.fact_sources` holds the cited `story_sources` titles/urls.

## Failure handling and edge cases

- Sheet approved **after** the run was created → run fails at start (staleness re-check), no paid call, not counted.
- A source cited by a fact is deleted after approval → the guard still succeeds; `FactSourcesBuilder` skips the missing source and reports it; the self-review flags the affected `fact_ref` (severity owned by 02.6.1-T2).
- Fiction episode → `ApprovedFactSheet.None`; a non-empty `fact_refs` on fiction is a `StoryDraftValidator` error (D3), not this task's.
- Story approve with an outdated sheet → 409 `story_fact_sheet_outdated` (call site 02.3.2).
- `Topic` enum source of truth is 02.1/09 domain; if the name differs (`SeriesTopic`), adapt the call site only.
