## Goal

When the review holds ≥ 1 `blocking` + `objective` issue, **exactly one** revision call fixes those issues, the result becomes a new `story_versions` row (`source = revised`, `parent_version_id`), steps 2–4 re-run once (validator + checker + moderation + **review #2** for hints only), a segment-drift check adds an advisory `revision_drift`, and both extra calls are metered without counting toward the FR-02-7 daily limit.

## Inputs

- README: D21 step 5 (`IStoryWriter.ReviseAsync`, `TextStep.Revision`, `RevisionMaxOutput`) + "steps 2–4 run once more, no further revision"; D22 (`revision { applied, fixed_issue_ids, parent_version_id, review_after }`); D7 (timeout 90 s, outcome mapping); D14 (`operation = story_revision`); D2 (`counts_toward_limit` rule); F16/CR-6 (the reserve must include review #2).
- Story 02.6.2 (L153–156): only blocking + objective issues are fixed; taste issues are hints; a `revised` row becomes current; metered `story_review`/`story_revision`, priced inside the story generation price, not counted toward the daily limit.
- 02.6.1-T1 (`ReviewAsync`, `ReviewIssueV1`, `RevisionPolicy` inputs, the `revision_drift` type), 02.2.1-T1 (`StoryDraftValidator`), 02.3.4-T1 (`StoryQualityChecker`), 02.4.1-T1 (`IContentModerator`).

## Design

**Prompt `prompts/revise/v1.md`** (static system prompt): fix **only** the listed issues, preserve everything else (segment order, beats, keywords, `fact_refs`, structure tags), return the **full** `story.v1` object in the same schema, invent no new facts, claims, names or URLs, and do not restructure the story to satisfy a style preference. Placeholders from the D5 closed list: `{{language_name}} {{tier_minutes}} {{token_range}} {{segment_range}} {{ear_rules}}`.

**User message** (one JSON object, D6): `{"task":"revise_story","language","tier","length":{"tokens":[min,max],"segments":[min,max]},"issues":[{"id","type","segment","evidence","repair_direction"}],"story":<story.v1>,"facts":[{"id","statement"}] ([] for fiction),"bible":{entities[],summaries[]}}` — `issues` carries **only** blocking + objective issues; taste/advisory issues are never sent.

**Types.**

```csharp
public sealed record StoryRevisionRequest(StoryContentV1 Draft, StoryReviewV1 Review,
    IReadOnlyList<ReviewIssueV1> Issues, Language Language, LengthTier Tier, LengthTarget Length,
    Topic Topic, IReadOnlyList<FactForWriter> Facts, BibleSnapshot? Bible, string PresetKey);
```

`IStoryWriter` gains the D21 member verbatim — no `RunContext` parameter:

```csharp
ValueTask<TextCallResult<StoryContentV1>> ReviseAsync(StoryRevisionRequest req, CancellationToken ct);
```

Implemented in the partial `src/NightTales.Infrastructure/OpenAI/OpenAiStoryWriter.Revise.cs` (`TextStep.Revision`, `req.Length.RevisionMaxOutput`, `promptCacheKey = $"revision:{req.PresetKey}"`, `schemaName = "story.v1"`).

Domain `src/NightTales.Domain/Stories/Review/`:

- `RevisionPolicy.ShouldRevise(StoryReviewV1 review, int maxRevisions, bool revisionAlreadyApplied) → bool` and `BlockingObjectiveIssues(review)` — revise iff `!revisionAlreadyApplied && maxRevisions > 0 && BlockingObjectiveIssues(review).Count > 0`.
- `SegmentDriftDetector.Detect(StoryContentV1 original, StoryContentV1 revised, IReadOnlyCollection<string> addressedSegments, double minSimilarity) → RevisionDrift { SegmentCountChanged, ChangedSegments[], AddedFindings[] }` — pure, reuses `TextNormalizer` (D21). Flags: segment count changed; a segment **not** in `addressedSegments` whose token-set similarity < `minSimilarity`; a `beat` changed on an untouched segment; a new blocking finding from the local checker that was absent in the original audit.
- `AuditReportBuilder.MergeRevision(...)` writes `revision { applied, fixed_issue_ids, parent_version_id, review_after { scores, issues } }` (D22) and appends the drift as an issue `{ type: "revision_drift", severity: "advisory", kind: "objective", segment, evidence, impact, repair_direction }` plus the additive `revision.drift { segment_count_changed, changed_segments[], added_findings[] }` (⚠️ plan §10 item 2).

**Flow** (owned by `GenerateStoryJob`, 02.2.2-T3; this task supplies steps and the decision):

1. `reviewing` done → ask `RevisionPolicy`. Not revising ⇒ save the generated row; blocking/taste issues stay as hints; episode → `story_review`.
2. Revising ⇒ `IBudgetGuard.CheckAsync` → `ReviseAsync` → `StoryDraftValidator` → `StoryQualityChecker` → `IContentModerator` → `ReviewAsync` (review #2) → `SegmentDriftDetector` → `Episode.CompleteStoryGeneration` saves the `revised` row (`parent_version_id` = generated row) and sets it current.
3. Review #2 **never** triggers another revision (D21); its remaining blocking issues are hints for the human and inputs for the 02.8.2 gate.
4. Revision output invalid after its retry ⇒ keep the original draft: `audit.revision = { applied:false, reason:"revision_invalid_output" }`, the run still succeeds, only the generated row exists.

**Config** (`Story:Revision`), validated at start-up (fail boot, like 02.8.2's gate validator): `Enabled=true`, `MaxRevisions=1` (must be `0` or `1`, D21), `MinTextSimilarity=0.6`; plus `OpenAi:Models:Revision=gpt-6-luna`, `OpenAi:Effort:revision=low`.

**Metering.** `IUsageMeter.RecordAsync` per call: `operation = story_revision` (the revision) and `story_review` (review #2), both with the run's `reservation_id` and `price_version`; both summed into `generation_runs.cost_usd`. `counts_toward_limit` is **not** changed by review/revision (D2: only `kind=story`, `trigger=user`, rolling 24 h). The worst-case reserve must include review #2 (F16/CR-6, owner 02.2).

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Revision output invalid after the retry | Original draft saved; `revision.applied=false`, `reason=revision_invalid_output`; run succeeds |
| Review #2 still has blocking objective issues | Saved as-is, hints only; 02.8.2 gates see them; no second revision (D21) |
| Revision returns fewer/more segments | Allowed only for the addressed issues; otherwise `SegmentCountChanged` drift is recorded (advisory) |
| Revision drops a `fact_ref` or invents a fact | `StoryDraftValidator` fails it → treated as invalid output (original kept) |
| Revision `Moderated` | Run `story_moderated` + `moderation_events`; no version row |
| Budget cap between review and revision | `spend_cap_reached`; the generated row is saved, `revision.applied=false`, `reason=spend_cap_reached` |
| `Story:Revision:Enabled=false` | No revision even with blocking issues; the review hints still show |
| Prompt change to `revise/v1.md` | sha256 manifest check fails at start-up until the manifest is updated (D5) |
| Rollback | Set `Story:Revision:Enabled=false`; `revised` rows already stored stay current and readable |
