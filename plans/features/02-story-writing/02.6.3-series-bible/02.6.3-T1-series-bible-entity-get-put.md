## Goal

A series owns exactly one `series_bibles` row, created with the series, whose `bible.v1` content is readable and replaceable through `GET/PUT /api/v1/series/{id}/bible` under a required `If-Match` (`"sb-<version>"`, D9), with the content limits of the plan §3.2 enforced as 400 `bible_invalid_content`.

## Design

### Domain (`src/NightTales.Domain/Series/Bible/`)

```csharp
public sealed class SeriesBible : Entity, IUserOwned
{
    public Guid UserId { get; private set; }
    public Guid SeriesId { get; private set; }
    public int Version { get; private set; }
    public SeriesBibleContent Content { get; private set; }
    public BibleProposal? ProposedContent { get; private set; }
    public Guid? ProposedFromEpisodeId { get; private set; }

    public static SeriesBible CreateDefault(Guid seriesId, Guid userId, IClock clock);
    public void ReplaceContent(SeriesBibleContent content, BibleLimits limits, IClock clock); // validates, Version++, UpdatedAt
    public void SetProposal(BibleProposal proposal, Guid fromEpisodeId, IClock clock);        // no Version change
    public void ClearProposal(IClock clock);
    public IReadOnlyList<BibleOp> ApplyProposal(IClock clock);                                // T2 uses it; defined here
}
```

`SeriesBibleContent` (record) and the item records are in `SeriesBibleContent.cs` exactly as plan §3.1. `BibleLimits` is a record bound from `IOptions<BibleOptions>` (`src/NightTales.Infrastructure/SeriesBible/BibleOptions.cs`, section `Bible`):

```jsonc
// appsettings.json
"Bible": {
  "Limits": { "NarratorNameChars": 80, "NarratorPersonaChars": 1000, "VoiceNotesChars": 1000,
              "MaxCharacters": 30, "MaxPlaces": 30, "MaxRules": 30, "NameChars": 60, "DescriptionChars": 300,
              "RuleChars": 300, "SummaryTitleChars": 100, "SummaryChars": 200, "MaxContentBytes": 65536 },
  "Proposal": { "Enabled": true, "MaxOps": 10, "MaxCharacterOps": 3, "MaxPlaceOps": 3, "MaxRuleOps": 2, "MaxStoryChars": 24000 },
  "Prompt": { "MaxSummaries": 50, "MaxChars": 24000 }
}
```

`NameChars` (60) caps `recurring_characters[].name` and `places[].name` — added so 02.6.3-T3's writer-snapshot budget has a provable upper bound on every field (see that task's convergence proof); `narrator.name` keeps its own `NarratorNameChars` (80).

`BibleContentValidator.Validate(content, limits, IReadOnlySet<Guid> approvedEpisodeIds) → IReadOnlyList<BibleFieldError>` — pure, no I/O. `approvedEpisodeIds` is loaded by the handler (one query on `episodes` of the series with `approved_story_version_id IS NOT NULL`); the Domain only compares.

`BibleErrors` factories: `InvalidContent(IReadOnlyList<BibleFieldError>)`, `Conflict()`, `ProposalNotPending()`, `IfMatchRequired()`, `Missing()`. Codes are the D8 strings (`bible_invalid_content`, `bible_conflict`, `bible_proposal_not_pending`, `if_match_required`).

`If-Match` handling is a shared concern (09.1): the endpoint reads the header, and a small `ETagComparer.IsMatch(string? ifMatch, string current, bool required)` in `src/NightTales.Application/Abstractions/Concurrency/ETagComparer.cs` is used by this command and by the fact-sheet/story commands (CR-5-style sharing; if 02.2.2-T2 already created one, reuse it — do not add a second). ### Api (`src/NightTales.Api/Endpoints/SeriesBibleEndpoints.cs`)

```csharp
var group = app.MapGroup("/api/v1/series/{id:guid}/bible").RequireAuthorization().WithTags("SeriesBible");

group.MapGet("/", async (Guid id, ISender sender, HttpContext http, CancellationToken ct) =>
{
    var result = await sender.Send(new GetBibleQuery(id), ct);
    return result.Match(dto => { http.Response.Headers.ETag = ETagComparer.Quote(dto.ETag); return Results.Ok(dto); },
                        errors => errors.ToProblemDetails());
});

group.MapPut("/", async (Guid id, UpdateBibleRequest body, ISender sender, HttpContext http, CancellationToken ct) =>
{
    var ifMatch = http.Request.Headers.IfMatch.ToString();
    var result = await sender.Send(new UpdateBibleCommand(id, body.Content.ToDomain(), ifMatch), ct);
    return result.Match(r => { http.Response.Headers.ETag = ETagComparer.Quote(r.ETag); return Results.Ok(new { r.Version, r.ETag }); },
                        errors => errors.ToProblemDetails());
});
```

`ProblemDetails` for validation carries `errors` as `Dictionary<string, string[]>` from `BibleFieldError` (`bible_invalid_content` + `errors[]`, plan §5). `ToProblemDetails()` is the shared mapper of 09.1.2/09 §5.4 (CR-8 merges D8); this task adds the bible rows only.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| `series_bibles` row missing for an existing series (hook not landed / data drift) | GET → 500 `series_bible_missing` + alert metric `bible_missing_total`; never auto-create in a query (CQRS rule, plan §4 U1) |
| `If-Match: *` | refused like the fact-sheet route → 412 `bible_conflict` (owner decision 2026-10-15; `*` is not a match on any NTS resource, `ETags.Matches`) |
| `If-Match: W/"sb-2"` | rejected as not a strong match → 412 `bible_conflict` |
| Client sends `schema_version` | ignored; the backend always writes `bible.v1` |
| Client sends `structure`/`approved_at` inside a summary | ignored, re-derived |
| Client removes a summary whose episode is approved | allowed (a wrong summary must be fixable); the next approval of that episode re-adds it (T2 dedupe) |
| PUT while a proposal is pending | allowed; the proposal is kept and still applies append-only (plan §4 U2) |
| PUT on an archived series | allowed (the owner may tidy it; 00 §6 keeps the row) |
| Content > 65,536 bytes after a valid PUT | 400 `too_long` on the root path — protects the D6 data-object budget |
| `updated_at` clock | `IClock` from DI (09.1), never `DateTimeOffset.UtcNow` |
| Rollback | drop the endpoint group + `Bible:Proposal:Enabled=false`; the table stays (additive) |
