# 02.7.1-T1 — Spike: link finder, option A (Responses `web_search`) vs option B (jev-ultrafast)

| Story | Size | Area | Depends on | Blocks | Phase / flag |
|---|---|---|---|---|---|
| 02.7.1 | M (1.0) | BE spike (throwaway) | 02.7.2-T1 (≥ 3 approved sites per language), 01.2.4 story key (Keychain `nts.openai.story`) | 02.7.2-T3, DECISIONS §10.10, 02.8.3 true-crime research branch | P · `source_finder` off |

## Goal
A recorded go/no-go and an A/B verdict per README D18. The evidence is 10 fixed research cases run through both options, with success rate, precision, cost per search and latency. Nothing from the spike ships.

## Inputs
- README W1, W2 (`filters.allowed_domains` ≤ 100, `include: ["web_search_call.action.sources"]`), W3 ⚠️, W4 ⚠️, J1, J2, D18, F19, F33.
- Approved allow-list `config/source-finder/allowed-sites.v1.json` (02.7.2-T1).
- DECISIONS §10.10 (jev-ultrafast allowed only for research on allow-listed sites), §10.13 (C#-only backend).

## Design
**Cases** (`trial/source-finder/cases.v1.json`, tracked). Each case has `id`, `language`, `topic`, `query` and `expected_kinds` (what a relevant source looks like):

| id | lang | topic | Query (short) | A relevant hit is |
|---|---|---|---|---|
| c1 | vi | true_crime | vụ án đã xét xử công khai, bản án được đăng trên cổng thông tin tòa án | court judgment page or news report of the verdict |
| c2 | vi | true_crime | vụ án lịch sử trước 1975 được báo chí tường thuật | newspaper archive or encyclopedia article |
| c3 | vi | ghost | truyền thuyết dân gian về ma ở một địa danh cụ thể | folklore article, encyclopedia, local-culture page |
| c4 | vi | spiritual | phong tục tâm linh ngày rằm tháng bảy | encyclopedia or culture article |
| c5 | vi | true_crime | vụ mất tích được công an thông báo và báo chí đưa tin | official notice or mainstream news |
| c6 | en | true_crime | a closed 19th-century murder case with a public trial record | archive, encyclopedia, trial transcript page |
| c7 | en | true_crime | a solved case covered by a national newspaper | news article |
| c8 | en | ghost | folklore of a named haunted building | encyclopedia or heritage page |
| c9 | en | spiritual | origin of a named folk ritual | encyclopedia or academic page |
| c10 | en | true_crime | appeal ruling published by a court | court website |

Queries name only public cases already covered by the press. No private persons are added by us.

**Option A harness** `trial/tools/finder_spike_a.py` (stdlib, `uv run --no-project --python 3.12`, 01 D9 conventions). It calls Responses `POST /v1/responses` through the 01 usage tap with:
- `model: gpt-6-luna`, `reasoning.effort: low`, `store: false`, `tool_choice: auto`
- `tools: [{ type: "web_search", filters: { allowed_domains: [...] } }]`
- `include: ["web_search_call.action.sources"]`
- the draft `prompts/finder/v1.md` text

It records citations, sources, the `web_search_call` count, usage and latency. It also tries the same request with a strict `text.format` JSON schema to answer W4, and checks whether the .NET SDK can express `filters`/`include` (W3; read the SDK source for `WebSearchTool`).

**Option B harness**: run jev-ultrafast locally per its README (J1) against a signed-out Chrome profile created for the spike, with navigation limited to the allow-list. Record whether it runs headless in a container (J1 ⚠️), whether it works with an OpenAI text model (`TEXT_MODEL_API_KEY`), the TypeSafe tokens used, and latency. Read TypeSafe legal terms (J2 ⚠️) and quote the automated-use / commercial clause.

**Scoring** (`trial/source-finder/results.csv`): `case_id, option, candidates, relevant, allow_listed, blocked_hit, cost_usd, latency_s, notes`.
- Success = ≥ 2 relevant, allow-listed candidates.
- Precision = relevant ÷ candidates.
- Scoring is done by the owner reading each link (no automation).

**Decision rule (D18)**:
- **Go-A** if A success ≥ 6/10, A success ≥ B − 1 case (10 points), and mean A cost ≤ $0.05.
- **Go-B** only if B beats A by more than 1 case **and** §10.13 exception + TypeSafe terms are accepted by the owner in writing.
- **No-go** if neither option reaches 6/10.

## Steps
1. Freeze `cases.v1.json` and the approved allow-list snapshot (hash in the report).
2. Run option A for all 10 cases (≤ $1 total, [INFERENCE] from W1 rates); save raw JSON under `$NTS_HOME/runs/finder-spike/` (untracked).
3. Try the strict-schema variant for 3 cases (W4) and note the result.
4. Check the .NET SDK surface for `filters`/`include` (W3); note the class/method or "raw JSON needed".
5. Set up option B (≤ 2 h timebox). If it cannot run within the timebox, record "B not operable" (that counts as a B loss).
6. Run B for the 10 cases if operable.
7. Owner scores every candidate link; fill `results.csv`.
8. Apply the decision rule; write DECISIONS §10.10 entry (verdict, numbers, W3/W4 answers, TypeSafe clause or "not read").
9. Update 02.7.2-T3 size (M for A, L for B) and plan §10.

## Outputs
- Tracked: `trial/source-finder/cases.v1.json`, `trial/source-finder/results.csv`, `trial/source-finder/REPORT.md`, `trial/tools/finder_spike_a.py`, DECISIONS §10.10 entry.
- Untracked: raw responses in `$NTS_HOME/runs/finder-spike/`.

## Acceptance checks
- [ ] `results.csv` has 20 rows (10 cases × 2 options) or 10 rows + "B not operable" with the reason.
- [ ] No candidate in any A run is on a D11 blocked domain (`blocked_hit = 0` for all rows); any non-zero is a no-go for that option.
- [ ] REPORT.md states the D18 verdict computed from the table, the mean cost per search per option and W3/W4 answers.
- [ ] DECISIONS §10.10 updated with the verdict and date.
- [ ] Spike code is not referenced by any `src/` project.

## Tests
None permanent (throwaway spike). The harness has a `--dry-run` that prints the request body without the key, used once to check no brief/fact text leaks into the request (only the query).

## Failure handling and edge cases
| Case | Action |
|---|---|
| `allowed_domains` rejected by the API or ignored (results outside the list) | Record it; extraction in T3 discards non-allow-listed URLs anyway. If > 30 % of citations are outside the list, cost/precision suffer → note in the verdict |
| A web_search returns 0 citations but sources exist | Count sources as candidates (T3 fallback); note it |
| Model performs > 3 searches | Record the count; T3 caps `SourceFinder:MaxSearchCalls` |
| B needs a signed-in Google/other account | Stop B: disallowed (DECISIONS §10.10) → B loses |
| TypeSafe terms forbid commercial or automated use | B is no-go regardless of scores |

## Notes
- ⚠️ W3/W4 are the only API unknowns; neither blocks A (raw JSON and annotation parsing are enough).
- Cost reference: A ≈ $0.01 per web search call (W1) + tokens; B ≈ TypeSafe input tokens × $0.042/1M + text-model tokens (J2).
