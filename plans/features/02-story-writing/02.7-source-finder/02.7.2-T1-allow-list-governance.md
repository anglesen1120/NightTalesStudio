# 02.7.2-T1 — Allow-list governance for research sites

| Story | Size | Area | Depends on | Blocks | Phase / flag |
|---|---|---|---|---|---|
| 02.7.2 | S (0.5) | BE + owner review | 02.5.1-T1 (`DomainBlocklist`, PSL helper) | 02.7.1-T1, 02.7.2-T3 | P · `source_finder` |

## Goal
A tracked, reviewed allow-list of research sites. It is loaded and validated at start-up. The finder may only search approved sites, and approval requires a recorded basis that automated access is permitted.

## Inputs
- README D11 (blocked domains, registrable-domain matching), W2 (≤ 100 `allowed_domains`, no scheme), DECISIONS §10.10 ("allow-listed sites whose terms permit automated access").
- 02.5.1-T1: `UrlNormalizer`, `RegistrableDomain.Of(host)`, `DomainBlocklist.IsBlocked(host)`.

## Design
**File** `config/source-finder/allowed-sites.v1.json`, copied into the Worker image and embedded as a resource like the prompts (D5 style, no runtime disk reads):

```json
{
  "version": 1,
  "sites": [
    { "domain": "vi.wikipedia.org", "name": "Wikipedia tiếng Việt", "language": "vi", "category": "encyclopedia",
      "terms_url": "https://foundation.wikimedia.org/wiki/Policy:Terms_of_Use", "robots_checked": false,
      "automated_access_basis": null, "status": "candidate", "reviewed_at": null, "reviewer": null }
  ]
}
```

Fields:
- `domain`: host without scheme/path, lowercase, punycode.
- `language`: `vi` | `en` | `any`.
- `category`: `encyclopedia` | `news` | `court` | `archive` | `government` | `culture`.
- `status`: `candidate` | `approved` | `rejected`.
- `automated_access_basis`: quoted clause + URL, or "official API/bulk-data permission" + URL.
- `reviewed_at`: ISO date. `reviewer`: name.

**Initial candidates** (all `status = candidate`; none is approved by this plan): vi.wikipedia.org, en.wikipedia.org, vnexpress.net, tuoitre.vn, thanhnien.vn, nhandan.vn, congbobanan.toaan.gov.vn (published judgments portal), bbc.com, apnews.com, reuters.com, theguardian.com, loc.gov (chroniclingamerica), archives.gov, courtlistener.com. ⚠️ Each one's terms and robots.txt must be read and quoted before approval. News sites often forbid automated collection. Option A sends queries to OpenAI's search index rather than crawling the sites, but the later page fetch (02.5.2) is our own request. So the basis must cover **fetching a single article page on a user's request, with robots respected**.

**Types** (`src/NightTales.Application/Features/Research/SourceFinder/`):

```csharp
public sealed record AllowedSite(string Domain, string Name, string Language, string Category, string Status);
public interface IResearchAllowList
{
    IReadOnlyList<AllowedSite> Approved(Language lang);   // language == lang or "any"
    bool IsAllowed(string registrableOrHost);              // exact host or subdomain of an approved domain
    string Hash { get; }                                   // sha256 of the file, logged at start-up
}
```

Implementation `EmbeddedResearchAllowList` (Infrastructure/Research). Start-up validation (`IValidateOptions` + hosted check, fail start):

| Rule id | Rule |
|---|---|
| AL1 | JSON parses; `version = 1` |
| AL2 | `domain` has no scheme, path, port or trailing dot, and is lowercase punycode |
| AL3 | No entry's registrable domain or host matches `DomainBlocklist` (D11) |
| AL4 | `approved` entries have non-empty `automated_access_basis`, `reviewed_at`, `reviewer` |
| AL5 | ≤ 100 approved entries (W2) |
| AL6 | No duplicate domains |

**Review procedure** (in the file's PR template section and `docs/runbooks/source-finder-allow-list.md`):
1. Open `terms_url` and the site's robots.txt.
2. Quote the clause that permits (or does not forbid) fetching single pages automatically for research. If the terms forbid scraping or automated access → `rejected` with the quote.
3. Set `robots_checked = true` when `NightTalesStudioBot` / `*` is not disallowed for article paths.
4. The owner approves in the PR. Every change to `status` is a PR reviewed by the owner.

## Failure handling and edge cases
| Case | Behaviour |
|---|---|
| Zero approved entries | Start-up succeeds but `FindSourcesCommand` returns 404 `feature_disabled` (the flag is effectively off); logged warning |
| A site changes its terms | Owner sets `rejected` via PR; the next deploy stops using it. Existing candidates stay as history |
| Domain moves (redirects to a new host) | Only the listed host is allowed; the new host needs its own entry |

## Notes
- Never mark a site `approved` from memory or this plan: approval requires the quoted clause (DECISIONS §10.10).
- The blocklist wins over the allow-list at every level (AL3 at start, D11 at extraction and at fetch).

## Delivery notes (Session 47)
- (a) `gov.uk` is listed as `www.gov.uk`: gov.uk is a public suffix and AL2 rejects public-suffix entries.
- (b) loc.gov robots sets Crawl-Delay 5 (cap `CrawlDelayMaxSeconds=10`); its free-to-use page covers image sets only.
- (c) `AllowedSite.Language` is a string (`any` is not in the Language enum). `Approved(Language)` takes the enum and includes `any` entries.
- (d) Wiring is in the Api only. The Worker has no `Fetcher:BlockedDomains`; 02.7.2-T3 wires it (hand-over in T3 Notes, AL-S47-2).
- (e) `IsAllowed` accepts canonical ASCII/punycode only (callers pass SourceUrl.Host), stops at 255 chars, strips one trailing dot, lets the blocklist win, and matches the listed host plus label-boundary subdomains.
- (f) AL2 also rejects public-suffix, IP-literal and reserved-suffix entries (beyond the task text).
- (g) Zero approved entries: this task only logs a warning; the 404 `feature_disabled` belongs to 02.7.2-T2 (hand-over in T2 Notes, AL-S47-1).
- (h) Open items recorded in STATUS §Open tasks as AL-S47-3 to AL-S47-7.
