## Goal
A user or the autopilot can request a source search for an episode. The result is a list of candidate links that can be added (through the normal source path) or dismissed. Nothing is ever added automatically by the run itself.

## Inputs
- Plan §3–§5; README D1, D2 (`kind = find_sources`, episode-level per T17), D8, D9 (no ETag needed: candidates are append/flag only), D13, D19; §10 T17, T59.

## Design
**Entity** `src/NightTales.Domain/Research/SourceCandidate.cs` (`IUserOwned`):

```csharp
public sealed class SourceCandidate : Entity, IUserOwned
{
    public Guid UserId { get; private set; }  public Guid EpisodeId { get; private set; }
    public Guid GenerationRunId { get; private set; }
    public string Url { get; private set; } = "";  public string NormalizedUrl { get; private set; } = "";
    public string RegistrableDomain { get; private set; } = "";  public string? Title { get; private set; }
    public string SiteName { get; private set; } = "";  public short Rank { get; private set; }
    public SourceCandidateStatus Status { get; private set; }  public Guid? SourceId { get; private set; }
    public ErrorOr<Success> MarkAdded(Guid sourceId);   // Proposed → Added; else source_candidate_not_proposed
    public ErrorOr<Success> Dismiss();                  // Proposed → Dismissed; Dismissed → no-op; Added → error
}
public enum SourceCandidateStatus { Proposed = 0, Added = 1, Dismissed = 2 }
```

EF `SourceCandidateConfiguration`: table `source_candidates`, columns per plan §3, `status` as text with CHECK, unique `ux_source_candidates_episode_url (episode_id, normalized_url)`, index `(episode_id, status, rank)`, FK cascade on episode. Migration `AddSourceCandidates`.

**Command** `src/NightTales.Application/Features/Research/Commands/FindSources/`:

```csharp
public sealed record FindSourcesCommand(Guid EpisodeId, string? Query, GenerationTrigger Trigger)
    : ICommand<ErrorOr<FindSourcesAccepted>>, IIdempotentCommand;
public sealed record FindSourcesAccepted(Guid GenerationRunId);
```

Handler order:
1. Flag `source_finder` on and `IResearchAllowList.Approved(lang).Count > 0`, else `feature_disabled` (404).
2. Load the episode (tenant filter → `not_found`). State `draft` | `story_review`, else `episode_invalid_state`.
3. Validator: `Query` ≤ 300 chars after trim; control characters stripped.
4. Active run check: an existing `generation_runs` row `(episode_id, kind = find_sources, status in queued|running)` → `find_sources_in_progress` (409). The partial unique index (D2) is the backstop.
5. `worst = IStoryCostEstimator`-style bound for `source_find` = `MaxSearchCalls × web_search_call rate + bytes(prompt) × r_in + limits.finder × r_out`. Then `IBudgetGuard.CheckAsync(worst)` → `spend_cap_reached`.
6. `ICreditLedger.ReserveAsync(userId, CreditOperation.SourceFind, runId, bound)`.
7. Insert `generation_runs` (`kind = find_sources`, `trigger`, `episode_id`, `series_id`, `worst_case_usd`).
8. Raise `SourceFindRequested { GenerationRunId, EpisodeId, UserId, Query? }` → outbox (query only in the outbox payload, plan §3).
9. `[Audited("episode.sources_find_requested", Category.Episodes, Visibility.User)]`.

Other slices:
- `ListSourceCandidatesQuery(EpisodeId)` → `IReadDb` projection `SourceCandidateDto(Guid Id, string Url, string? Title, string SiteName, short Rank, string Status, Guid? SourceId, DateTimeOffset CreatedAt)`, ordered by `created_at desc, rank`.
- `AddSourceCandidateCommand(EpisodeId, CandidateId)`: loads the candidate (`Proposed`), sends `AddSourceCommand(EpisodeId, candidate.Url)` **inside the same UnitOfWork**. On success it calls `MarkAdded(sourceId)`; on error it returns the 02.5.1 error unchanged and the candidate stays `Proposed`. Audited `episode.source_candidate_added`.
- `DismissSourceCandidateCommand(EpisodeId, CandidateId)` → 204. Audited `episode.source_candidate_dismissed`.

**Endpoints** (`src/NightTales.Api/Endpoints/SourceFinderEndpoints.cs`) per plan §5.

## Acceptance checks
- [ ] `POST /episodes/{id}/sources/find` with flag off → 404 `feature_disabled` (`FindSources_FlagOff_Returns404FeatureDisabled`).
- [ ] Second call while a run is active → 409 `find_sources_in_progress`.
- [ ] Same `Idempotency-Key` twice → same `generationRunId`, one `generation_runs` row.
- [ ] Budget guard denies → 429 `spend_cap_reached`, no run row.
- [ ] Add of a candidate when the episode already has 10 sources → 409 `source_limit_reached` and the candidate stays `proposed` (`AddCandidate_AppliesSourceCaps`).
- [ ] Add twice → second call 409 `source_candidate_not_proposed`.
- [ ] User B's candidate id → 404 (`Candidates_OtherUser_Returns404`).
- [ ] No Hangfire argument or log line contains the query (`FindSources_QueryNotInJobArgsOrLogs`).

## Tests
Integration (real PostgreSQL 17, `PostgresFixture` + FakeBudgetGuard): the acceptance checks above. Unit: `SourceCandidate_MarkAdded_FromDismissed_Fails`, `Dismiss_Twice_NoOp`, `FindSourcesValidator_QueryOver300_Fails`.

## Failure handling and edge cases
| Case | Behaviour |
|---|---|
| Episode moves to `story_approved` while candidates exist | Add → 409 `episode_invalid_state` from `AddSourceCommand` (02.5.1 allowed states) |
| Same URL proposed by a later run | Unique index; the runner skips it (T3) |
| Candidate URL added manually meanwhile | `AddSourceCommand` returns `source_duplicate`; UI shows it; candidate can be dismissed |
| Run crashed | `StaleGenerationSweeperJob` fails it (`find_sources_generation_failed`), the reservation is refunded, a new find is allowed |
