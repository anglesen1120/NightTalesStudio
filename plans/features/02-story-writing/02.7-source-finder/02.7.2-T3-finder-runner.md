## Goal
A `find_sources` run turns a query into ≤ 10 allow-listed, D11-safe candidate links taken only from search citations. It meters the cost and ends the run with a D8 outcome. The runner never adds a source.

## Inputs
- Plan §7; README W1, W2, W3 ⚠️, W4 ⚠️, D6, D7, D11, D12, D14, D19, D21 (`ITextClient`, `TextStep.Finder`); §10 T12/T56 (`limits.finder` = 2,000), T55 (`OpenAi:Pricing`), T39.
- 02.7.1-T1 verdict. If **no-go**, this task is not built.

## Design
**Port** (Application/Abstractions/Research):

```csharp
public interface ISourceFinder
{
    ValueTask<SourceFinderResult> FindAsync(SourceFinderRequest req, CancellationToken ct);
}
public sealed record SourceFinderRequest(RunContext Run, Language Language, Topic Topic, string Query,
                                         IReadOnlyList<string> AllowedDomains);
public abstract record SourceFinderResult
{
    public sealed record Ok(IReadOnlyList<FoundLink> Links, UsageItem Usage, int SearchCalls) : SourceFinderResult;
    public sealed record Failed(string ErrorCode, UsageItem? Usage, IReadOnlyList<string>? ModerationCategories) : SourceFinderResult;
}
public sealed record FoundLink(string Url, string? Title, int Order, LinkOrigin Origin); // Citation | Source
```

**Option A — `OpenAiSourceFinder`** (Infrastructure/OpenAI):
- Builds a `TextCallRequest` with `Step = TextStep.Finder`, the system prompt `finder/v1.md` and the data object `{ "task": "find_sources", "language": "vi", "topic": "true_crime", "query": "…" }` (D6). `MaxOutputTokens = limits.finder`, `store = false`.
- Adds tool `web_search` with `filters.allowed_domains = req.AllowedDomains` and `include: ["web_search_call.action.sources"]`. If the SDK cannot express these (W3), it posts the raw JSON body through the protocol method (`CreateResponse(BinaryContent)`) — the same client, retry and timeout pipeline (D7).
- Parses output items: counts `web_search_call` items; collects `url_citation` annotations in order (`Origin = Citation`); if none, collects `web_search_call.action.sources` (`Origin = Source`).
- **Never** parses URLs from the model's text.
- `SearchCalls > SourceFinder:MaxSearchCalls` (3) → `Failed("find_sources_generation_failed")` with usage still recorded.
- Refusal / `content_filter` → `Failed("find_sources_generation_failed", categories)`; the job writes `moderation_events(stage = find_sources)`.
- `finder.v1.json` strict schema is used only if W4 proves compatible: it holds `{ "notes": string }` for the log. The candidates never come from it.

**Job** `FindSourcesJob.RunAsync(Guid generationRunId)` (Application/Features/Research/Jobs):
1. Load the run (`queued`), the episode and the `SourceFindRequested` query (outbox payload; else title + brief first 300 chars). Mark `running`, stage `writing`.
2. `IBudgetGuard.CheckAsync` again (dispatch-time, D1). If denied → `pause_reason = spend_cap_reached`, stays `queued`.
3. `ISourceFinder.FindAsync(...)` with `IResearchAllowList.Approved(lang)` domains.
4. `CandidateExtractor.Extract(links, allowList, blocklist, existing)` (Domain, pure):
   - `UrlNormalizer` (02.5.1) → invalid → drop
   - `DomainBlocklist.IsBlocked` → drop
   - `!allowList.IsAllowed` → drop
   - already a `story_sources.normalized_url` or `source_candidates.normalized_url` on the episode → drop
   - dedupe, keep order, cap 10
   - `Title` trimmed to 300 chars
5. Insert `source_candidates` (`Proposed`, rank = order). `ON CONFLICT (episode_id, normalized_url) DO NOTHING`.
6. `IUsageMeter.RecordAsync(operation = source_find, cost = tokens + SearchCalls × rates.web_search_call)` in its own transaction (D14).
7. Run `succeeded` (also with 0 candidates), settle the reservation, outbox `EpisodeUpdated`. On `Failed` → run `failed` with the code, refund.

Hangfire retry 0; the sweeper recovers crashes (D2/T21). Timeout `OpenAi:RequestTimeout:Finder` 60 s.

**Option B — `SidecarSourceFinder`** (built only on Go-B):
- `FindAsync` inserts a `fetch_tasks` row (`kind = find_sources`, `generation_run_id`, `episode_id`) and returns `Pending`. The job completes when the lease API receives `{ status: done, candidates[] }` (T39); the Api then runs steps 4–7.
- The sidecar (Python, next to `NightTales.Fetcher`, same subnet and egress rules, no DB/storage/OpenAI app credentials) runs jev-ultrafast with:
  - a fresh signed-out Chromium profile per task, deleted afterwards
  - a navigation interceptor allowing only allow-listed hosts
  - D11 hosts refused; form POSTs, logins, downloads and pop-ups refused
  - a 90 s task timeout
- TypeSafe and text-model keys live only in the sidecar's secret store.

## Steps
1. Port + result types + `CandidateExtractor` (pure) with unit tests.
2. Option A adapter; spike findings W3/W4 applied.
3. `FindSourcesJob` + outbox handler `SourceFindRequested → IJobScheduler.Enqueue<FindSourcesJob>(runId)`.

5. Seed `price_versions.rates.web_search_call = 0.01` and `limits.finder = 2000` (02.2.4-T1 config).

## Tests
Unit (Domain): the extractor cases. Application (FakeTextClient, D20): job outcomes, budget pause, sweeper interplay. Integration: end-to-end with a fake `ISourceFinder` returning fixed links → candidates visible via `GET …/candidates`.

## Failure handling and edge cases
| Case | Behaviour |
|---|---|
| Allow-list changed between command and job | Job uses the list at run time; candidates always re-checked |
| All links filtered out | Run `succeeded` with 0 candidates; UI shows `sources.find.empty`; autopilot → `waiting_owner` "add sources" (F33) |
| `allowed_domains` ignored by the API | Extraction filter still guarantees allow-list-only candidates |
| Provider funds exhausted | `pause_reason = provider_funds_exhausted` (D2), no candidates |
