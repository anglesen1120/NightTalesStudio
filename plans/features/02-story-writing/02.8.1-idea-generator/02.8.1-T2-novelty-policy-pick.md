## Goal

Every candidate idea is measured against past episodes and pending ideas (lexical shingles plus one judge call for the batch) and against the content policy, then scored so exactly one candidate is `picked` and the rest are `rejected` with a reason the run log can show.

## Design

### Novelty — `IIdeaNoveltyChecker` (Application `Features/Autopilot/Ideas/Abstractions`)

```csharp
ValueTask<ErrorOr<NoveltyBatchResult>> CheckAsync(IReadOnlyList<(Guid IdeaId, IdeaCandidate Candidate)> batch,
                                                  NoveltyCorpus corpus, Language lang, RunContext run, CancellationToken ct);
public sealed record NoveltyCorpus(IReadOnlyList<CorpusEpisode> Episodes, IReadOnlyList<CorpusIdea> PendingIdeas);
public sealed record CorpusEpisode(Guid EpisodeId, string Title, string Summary);   // newest 100 approved
public sealed record CorpusIdea(Guid IdeaId, string Title, string Logline);         // status proposed|picked
public sealed record NoveltyBatchResult(IReadOnlyDictionary<Guid, NoveltySignals> ByIdeaId, bool JudgeUsed);
public sealed record NoveltySignals(decimal LexicalScore, Guid? LexicalOverlapId, NoveltyJudge? Judge);
public sealed record NoveltyJudge(decimal Score, decimal Fit, decimal HookStrength, Guid? MaxOverlapEpisodeId, string Reason);
```

- Corpus provider `IIdeaCorpusProvider` (Infrastructure): (a) the newest `Autopilot:Ideas:Novelty:CorpusEpisodes` (100) approved episodes of the series — `story_versions.title` + `content.description` truncated to 200 chars, joined through `episodes.approved_story_version_id`, ordered by `story_versions.created_at DESC`; (b) `episode_ideas` of the series with `status IN ('proposed','picked')` (excludes this batch's own rows by id, which are `proposed` too — pass the batch ids to exclude). Reuse the bible summaries when the bible is newer than the corpus? **No**: one source (approved story versions) keeps the scoring honest and independent of bible edits.
- Lexical (`IdeaNoveltyLexical`, Domain, pure): normalise `title + " " + logline + " " + setting`; `n = SimilarityOptions.NFor(lang)` (vi 10, en 8); Jaccard = `|A∩B| / |A∪B|` against each corpus entry; keep the max and its id. An empty shingle set (text shorter than `n` tokens) scores 0 (no overlap claim). Cost 0.
- Judge (one call per batch): `prompts/ideas/novelty.v1.md` + `prompts/schemas/novelty.v1.json` (strict):

```json
{ "type": "object", "additionalProperties": false, "required": ["scores"],
  "properties": { "scores": { "type": "array", "minItems": 1, "maxItems": 10,
    "items": { "type": "object", "additionalProperties": false,
      "required": ["index", "max_overlap_episode_id", "score", "fit", "hook_strength", "reason"],
      "properties": { "index": { "type": "integer", "minimum": 0 },
                      "max_overlap_episode_id": { "type": ["string", "null"] },
                      "score": { "type": "number", "minimum": 0, "maximum": 1 },
                      "fit": { "type": "number", "minimum": 0, "maximum": 1 },
                      "hook_strength": { "type": "number", "minimum": 0, "maximum": 1 },
                      "reason": { "type": "string" } } } } } }
```

  Data object: `{ "task": "score_ideas", "language": "vi", "topic": "ghost", "ideas": [ { "index", "title", "logline", "hook", "setting" } ], "past_episodes": [ { "index", "title", "summary" } ] }` — `past_episodes` = the newest 100 corpus episodes (title + ≤ 200-char summary, **no ids**, D6/D19). Call fields: `TextStep.Novelty`, model `OpenAi:Models:Novelty` (default `gpt-6-luna`), effort `OpenAi:Effort:Novelty` (default `low`), `max_output_tokens` = `price_versions.limits.novelty.max_output_tokens` (fallback 400), `store = false`, `prompt_cache_key = "ideas:novelty"`, header `X-Client-Request-Id = {generationRunId}:novelty:{attempt}`, timeout 30 s, 2 attempts.
  [DECISION] One call for the batch (not per idea): cheaper, consistent, and the model sees the candidates together so it cannot call two similar candidates both fresh. `fit` and `hook_strength` come from the same call so no extra cost (plan §3.4).
  The judge sees `max_overlap_episode_id` as a **1-based index** into `past_episodes` (models garble UUIDs, D6/F12 principle) → the server maps the index back to the episode id; an out-of-range index → `null`.
- Degradation: judge `InvalidOutput` after one retry, `ProviderError` or `ProviderUnavailable` → `JudgeUsed = false`, `Judge = null`; the scorer then uses `noveltyComponent = 1 − LexicalScore`, `Fit = 1.0`, `HookStrength = 0.5` and the run continues (a scoring helper must not fail the run). `Moderated` → the same degradation **plus** one `moderation_events` row (`source = openai_text`, `stage = "ideas"` — TL ruling #3, 2026-09-24: a refusal on the run's own paid call writes an event with `stage = kind`, distinct from the per-candidate `stage = brief` pre-check below). `ProviderFundsExhausted` → propagate as an error (the caller pauses the series).
- Thresholds: `Autopilot:Ideas:Novelty:{LexicalMax=0.35, JudgeMax=0.70}` ⚠️ (calibrate in the 02.8.2-T3 dry run). Raw scores decide rejection, never the weighted score.

### Policy — `IIdeaPolicyChecker` (Application)

```csharp
ValueTask<PolicyBatchResult> CheckAsync(IReadOnlyList<(Guid IdeaId, IdeaCandidate Candidate)> batch,
                                        IdeaPolicyContext ctx, RunContext run, CancellationToken ct);
public sealed record PolicyBatchResult(IReadOnlyDictionary<Guid, PolicyVerdict> ByIdeaId);
public sealed record PolicyVerdict(string? RejectReason, bool RequiresResearch, IReadOnlyList<string> MatchedBannedThemes);
```

1. **Banned themes** (deterministic, free): normalise the theme (NFC + invariant lower, diacritics kept) and the candidate text (`title + " " + logline + " " + hook + " " + setting`), then whole-word sequence containment → `policy_banned_theme`. ⚠️ Substring matching is a backstop; the prompt forbids the themes too.
2. **Moderation**: `IContentModerator.CheckAsync([logline, hook], ModerationStage.Brief, ct)` per candidate (free, O7); `flagged` → `policy_moderated` + one `moderation_events` row per flagged candidate (`source = openai_text`, `stage = brief`, `categories`, `excerpt` ≤ 300 chars of the flagged text). Usage recorded with `operation = moderation`, `cost_usd = 0` (D12/D14).
3. **True-crime framing** (F31/F33): when `topic = true_crime`, a candidate matching the framing lexicon (vi "câu chuyện có thật"/"dựa trên sự thật", en "based on a true story"/"true crime") or the dated-incident pattern (`\b(19|20)\d{2}\b` within 40 chars of a crime noun from a small config list) → `RequiresResearch = true` (no rejection at idea level; the story gate and the owner's fact-sheet approval are the real control).
4. Skipped entirely when the batch is empty or when `Autopilot:Ideas:Policy:ModerationEnabled = false` (default true; the banned-theme check still runs).

### Scoring and pick

`IdeaScorer.Score(IdeaSignals, IdeaWeights) → decimal` (Domain, pure, plan §3.4):

```
noveltyComponent = 1 − max(LexicalScore, Judge?.Score ?? 0)
score = clamp01( w.Novelty*noveltyComponent + w.Fit*(Judge?.Fit ?? 1.0m) + w.Hook*(Judge?.HookStrength ?? 0.5m)
                 − w.Variety*(VarietyPenalty) )
```

Weights `Autopilot:Ideas:Weights:{Novelty=0.45, Fit=0.30, Hook=0.25, Variety=0.35}`. `VarietyPenalty` and a hard-block `RejectReason` come from 02.8.4-T1's `VarietyGuard.Evaluate`. Ties break by the candidate's batch index. A hard-blocked candidate is `rejected` before scoring.

Pick order inside `IdeaPlanner.ProposeAndPickAsync` (T1's skeleton + these steps): novelty → policy → variety → score → `MarkPicked(score)` for the winner, `MarkRejected(reason)` for the rest (`not_best` when they only lost the ranking), `SetSignals(score, similarity, noveltyDetail)` on every row where `similarity = max(LexicalScore, Judge?.Score ?? 0)`.

Rejection reasons (one source of truth, `IdeaRejectionReason`): `novelty_lexical`, `novelty_judge`, `policy_banned_theme`, `policy_moderated`, `variety_triple_repeat`, `variety_template_repeat`, `not_best`, `invalid`, `duplicate`.

`NoIdea`: every candidate rejected → `ErrorOr` error `IdeaErrors.NoIdea(reason)` where `reason` is the most common rejection reason in the batch (deterministic: highest count, then alphabetical) so 02.8.3 can record and alert on it.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Judge returns fewer scores than candidates | missing indices → `Judge = null` for those candidates (lexical only), the run continues |
| Judge returns an id/index that is not in the corpus | `MaxOverlapEpisodeId = null`, the score is still used |
| Corpus is empty (the series' first episode) | lexical 0 for every candidate; the judge still runs (it sees no past episodes) and `fit`/`hook_strength` drive the pick |
| Every candidate is lexically blocked | the judge call is skipped (`JudgeUsed = false`) and `NoIdea(novelty_lexical)` is returned — saves a paid call |
| Moderation endpoint unreachable (5xx) | treat as "not flagged" but log `moderation_unavailable_total` and set `Autopilot:Ideas:Policy:FailClosed` (default false) — when true, candidates are rejected `policy_moderated` instead (configurable, since the endpoint is free and usually up) |
| Banned-theme false positive (a theme word inside another word) | whole-word matching prevents it; the list is data and can be edited without a deploy |
| `novelty` jsonb exceeds a sane size | it holds ≤ 5 scores and reasons; cap `reason` at 300 chars on write |
| Two runs race on the same series (two slots) | each run scores its own batch; a `picked` idea from the other run is in the corpus (status `picked`), so the second run avoids it — the partial unique index on `(series_id, kind) WHERE episode_id IS NULL` prevents two concurrent idea runs for the same series anyway |
| Rollback | set `LexicalMax`/`JudgeMax` to 1.0 and `Weights.Variety` to 0 → the pipeline degenerates to "pick the first valid candidate" without a code change |

## Notes

- ⚠️ `LexicalMax = 0.35` and `JudgeMax = 0.70` are first guesses (F32 marks the threshold as uncalibrated). Calibrate against the first ~50 real runs in the 02.8.2-T3 dry run and record the numbers in `DECISIONS.md` §3 (D15-style).
- [DECISION] The judge is **one call per batch** (plan §4 U2); the schema returns per-index scores, which is a faithful extension of F32's per-idea shape.
- [DECISION] Judge failure degrades to lexical-only; it never fails the run. `Moderated` also writes a `moderation_events` row (`stage = "ideas"`, TL ruling #3) before degrading. `ProviderFundsExhausted` is the only judge outcome that propagates.
- The judge call is metered with `operation = idea` (the only text operation for this feature); `moderation` is separate with cost 0. If the TL wants a distinct `idea_novelty` operation, D14 needs the value (not requested — one operation is enough to see the cost).
- The judge sees episode **indices**, never UUIDs (D6/F12 principle).
- `TextNormalizer`/`Shingler` are owned by 02.5.6-T1: reuse, never reimplement (a second normaliser would make idea novelty disagree with source similarity).
- Do not log idea text, the judge reason or episode titles (D19).
- [OPEN] Hand-overs from 02.8.1-T1 (Session 52, PR #TBD): IDEA-S52-2 add `ErrorCodes.IdeaInvalidState` + its 409 catalogue row and align `MarkPicked` (throws on a repeat) with `MarkRejected` (no-op); `MarkUsedAsync` answers `idea_invalid_state` on a `proposed` pick until you call `MarkPicked`. IDEA-S52-3 `MarkUsed` has no `xmin` guard (concurrent calls with different episodes both succeed): single-flight per slot or add an `xmin` token with a snapshot change. IDEA-S52-4 `IEpisodeStructureHistory` already parses the tags of the 50 newest approved versions; reuse it, and if T1's title-only fallback is all you need, split a titles-only read. `IdeaPick.Score`/`Similarity` are 0 and `RequiresResearch = topic == true_crime` is already set by T1 (IDEA-S52-6). The planner is Worker-only; `ProposeAndPickAsync` must run with no open transaction on the scope and the retry is guarded by `IBudgetGuard` (`excludingRunId` = the run).
