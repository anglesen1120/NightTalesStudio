## Goal

An idea whose structure repeats a recent episode's template, or whose tag triple repeats within the last 10 episodes, is rejected before any story money is spent; the writer is steered with `required_tags`/`forbidden_tags`; and a written story is verified against the plan so the 02.8.2 gate can fail a forbidden tag.

## Inputs

- Contract: README D3 (`story.v1.structure` = `{ sub_genre, setting, opening, twist_type, narrator_mode }`, free strings mapped to the vocab of `prompts/shared/structure-vocab.v1.json`, `other:<text>` when unmapped; beats enum `setup|build_up|clue|twist|reveal|aftermath`; `narrator_mode` is an enum), D6 (the `structure_plan` data-object key), D21 (`StoryWriteRequest` carries the plan), F32; DECISIONS §6 + §10.12 (the mass-produced policy and why the guard exists); story 02.8.4 ("autopilot rotates settings, sub-genres, openings and scene styles, and blocks an idea whose structure repeats a recent episode's template").

Structure)` and serialises `StructurePlan` under the `structure_plan` key (omitted when null); the writer system prompt states `required` is a must and `forbidden` is a must-not (PresetsM0Plan lists the key in the writer prompt rules); GenerateJobPlan's message: the **02.8.2 gate** calls `VarietyGuard.VerifyWritten`, not the generate job.

## Design

public sealed record StructurePlan(StructureRequirements Required, StructureForbidden Forbidden)

    public static readonly StructurePlan Empty = new(StructureRequirements.None, StructureForbidden.None);
    public bool IsEmpty => Required == StructureRequirements.None && Forbidden.IsEmpty;

Values are **vocab ids** (snake_case ASCII, e.g. `haunted_house`), never free text; the mapper that turns a model string into a vocab id (or `other:<text>`) is 02.2.1-T1's and is reused.

### Rules (plan §3.5, repeated here as the contract)

| Rule | Definition | Effect |
|---|---|---|
| R1 triple repeat | candidate `(sub_genre, opening, twist_type)` equals that of any of the last `WindowK` = 10 episodes | hard block → `RejectReason = variety_triple_repeat` |
| R2 tag share cap | adding the candidate pushes a tag value above `TagShareMax` = 40 % of the window (5 of 11 when the window is full at 10) | soft → `Penalty = 0.5`, `SoftViolations += "<dimension>:<value>"`, value added to `Forbidden` for the batch |
| R3 template repeat | candidate `beat_signature` **and** `opening` **and** `twist_type` all equal those of any of the last `TemplateWindowK` = 5 episodes | hard block → `variety_template_repeat` |
| R4 rotation | per dimension, the least-used value in the window with count < `RotationMinCount` = 3 becomes `Required` (tie-break: lowest count, then ordinal) | steering only |
| R5 cold start | fewer than 2 history entries with a structure | no requirements, no rejections |
| — | `narrator_mode` is never a dimension (it follows the preset) | — |

`Penalty` combines R2 hits: `0.5` for one soft violation, `0.75` for two or more (capped at 0.75 so a soft violation can never equal a hard block). A candidate with a `RejectReason` is rejected before scoring (02.8.1-T2 §3.4).

`VerifyWritten(written, plan)`:

| Rule | Condition | Issue |
|---|---|---|
| forbidden used | `written.<dimension>` ∈ `plan.Forbidden.<dimension>` | `structure_plan_forbidden_used` (the gate **fails**) |
| required missing | `plan.Required.<dimension>` is set and `written.<dimension> != required` | `structure_plan_missing` (advisory: the model maps free strings to vocab ids and may land on `other:<text>`) |
| narrator mode | ignored | — |

### History read port

```csharp
// src/NightTales.Application/Features/Autopilot/Ideas/Abstractions/IEpisodeStructureHistory.cs
ValueTask<IReadOnlyList<EpisodeStructureRef>> GetRecentAsync(Guid seriesId, int max, CancellationToken ct);
```

Implementation `src/NightTales.Infrastructure/Autopilot/EpisodeStructureHistory.cs`, one no-tracking projection:

```sql
SELECT e.id AS episode_id, sv.title, sv.created_at, sv.content
FROM episodes e
JOIN story_versions sv ON sv.id = e.approved_story_version_id
WHERE e.series_id = @seriesId AND e.approved_story_version_id IS NOT NULL
ORDER BY sv.created_at DESC
LIMIT @max;
```

- `max` = `max(WindowK, TemplateWindowK, CorpusNeeds)` = 10 for the guard (02.8.1-T2 has its own 100-row corpus provider; do not merge them — different limits and shapes).
- `Structure` = `sv.content -> 'structure'` mapped to `StoryStructureTags` (reuse the D3 reader); `BeatSignature` = the paragraph `beat` values in order joined with `>` (computed in memory from `content.paragraphs[].beat`, ≤ 10 rows).
- ⚠️ `sv.created_at` is a proxy for the approval time; a version can only be approved while current, so the newest-first order is right in practice. The exact approval timestamp would need `audit_logs`, which is not a read model.
- A story with no paragraphs (impossible per D3) or an unmapped structure yields an empty signature → R3 cannot match for that episode (fail-open, never fail-closed on missing data).

### Steering and verification wiring

- **Steering (before the writer):** `IdeaPlanner` (02.8.1-T1/T2) computes `AssessBatch` once, passes `SuggestedRequired`/`SuggestedForbidden` into the idea prompt (`required_tags`/`forbidden_tags`), then per candidate `Evaluate`; `ToPlan(batch, decision)` produces the `StructurePlan` stored with the picked idea? **No**: the plan is derived from the *history at generation time*, and the writer runs later. [DECISION] `ToPlan` is called again by `IStructurePlanProvider` (02.6.3-T3 / StoryWriterPlan contract) at story-generation time from the **current** history (the history may have grown between the idea and the story), merged with the picked idea's own `structure` as an additional `Required` when the guard's suggestion is empty. This keeps the plan fresh without persisting a stale one on the idea.
- **Verification (after the writer):** the 02.8.2 gate calls `VerifyWritten(story.Content.Structure, plan)`; `structure_plan_forbidden_used` → gate failure (the run stays in `story_review` and the owner is notified, 02.8.2); `structure_plan_missing` → advisory, recorded in `autopilot_runs.gate_results` and the audit `data` (counts only, D13).
- No change to `story.v1`: the written `structure` is already there (D3).

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Fewer than 2 history entries | R5: nothing is required or rejected (a new series must not be blocked) |
| History has an unmapped tag (`other:<text>`) | compared as-is; `other:` values are never suggested as `Required` (they are not stable) |
| A story has no `beats` (all paragraphs mapped to one beat) | signature = that single beat; R3 needs an exact match, so it rarely fires — fail-open |
| Every candidate is blocked | `IdeaPlanner` returns `NoIdea(variety_template_repeat|variety_triple_repeat)`; 02.8.3 records the run outcome (no retry inside the run) |
| The guard blocks too much during the first weeks (small history) | `Autopilot:Variety:Enabled=false` (steering only) or raise `RotationMinCount`/lower `TagShareMax`; all config, no deploy |
| The written story's tags differ from the plan (model mapped to `other:*`) | `structure_plan_missing` advisory, not a gate failure — otherwise a soft constraint would burn a whole generation |
| A user (non-autopilot) episode | `IStructurePlanProvider` returns `null`; no steering, no verification, no rejection — the variety guard is an autopilot rule only |
| History query slow | one indexed query with `LIMIT 10` on `(series_id, approved_story_version_id)`; `episodes` has an index on `series_id` (09.2.2) |
| Rollback | `Autopilot:Variety:Enabled=false` (hot-reload, 09.10.3) |
