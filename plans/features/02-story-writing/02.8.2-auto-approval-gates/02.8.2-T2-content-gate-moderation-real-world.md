## Goal

Before the story gate may pass, the generated content is checked twice: `omni-moderation-latest` runs over the final narration, the title/description/tags **and** the expanded scene prompts (style template × keywords) with per-category thresholds, and a real-world-framing detector looks for "this really happened" signals in the same text plus the review model's `real_world_claims[]`. Any flag or hit routes the episode to the owner — never to a silent pass and never to an automatic block.

Application — `src/NightTales.Application/Features/Autopilot/Gates/`:

```csharp
public interface IAutopilotContentGate
{
    ValueTask<ErrorOr<ModerationGateOutcome>> CheckAsync(AutopilotContentGateRequest req, CancellationToken ct);
}
public sealed record AutopilotContentGateRequest(Guid EpisodeId, Guid StoryVersionId, string Language,
                                                 StoryTextSegments Segments, IReadOnlyList<string> ExpandedScenePrompts,
                                                 string StyleTemplateName, AutopilotGateProfile Profile);
public sealed record ModerationGateOutcome(bool Flagged, IReadOnlyList<string> Categories,
                                           IReadOnlyDictionary<string, double> Scores, string? UnavailableDetail);
```

- `AutopilotModerationGate : IAutopilotContentGate` — `…/Gates/AutopilotModerationGate.cs`:
  1. builds the text list: `[narration, title, description, string.Join('\n', tags), each expanded scene prompt]` (scene prompts as **one** chunk each, so a flagged scene prompt names the scene);
  2. chunks every text to ≤ 8,000 chars on a paragraph boundary (never mid-word), keeping the segment id for each chunk (D22);
  3. calls `IContentModerator.CheckAsync(texts, ModerationStage.AutopilotGate, ct)` (D12);
  4. evaluates the verdict: `flagged = categories.Any(c => profile.Moderation.BlockedCategories.Contains(c)) || scores.Any(kv => kv.Value > profile.Moderation.MaxScore[kv.Key])` — a category with a score above its threshold counts even when `flagged = false`, which is what makes the thresholds meaningful;
  5. writes one `moderation_events` row per flagged chunk (`source = openai_text`, `stage = autopilot_gate`, `categories`, `excerpt` = ≤ 300 chars of that chunk) and records usage (`operation = moderation`, cost 0, D14);
  6. on a 5xx/timeout after the D7 retry budget → `UnavailableDetail = "moderator_unavailable"` and `Flagged = true` (**fail closed**, plan §7).
- `RealWorldSignalService : IRealWorldSignalService` — `…/Gates/RealWorldSignalService.cs`. Assembles the inputs (segments from `story_versions.content` + metadata, the lexicon for the series language, the `model_review.real_world_claims[]` from `audit.v1`) and calls the Domain detector. Registered as `IRealWorldSignalService` in `src/NightTales.Application/Abstractions/`.
- `RealWorldLexiconProvider` — `src/NightTales.Infrastructure/Prompts/RealWorldLexiconProvider.cs`. Reads `Prompts/shared/real-world-framing.vi.txt` / `.en.txt` from the embedded prompt resources (D5) into `IReadOnlyList<string>`, trimmed, lowercased, comment lines (`#`) skipped, cached for the process lifetime. It is loaded at start-up by `PromptCatalog` so a missing file fails start-up (D5), not the first gate.

`IAutoApprovalGate` (02.8.2-T1) consumes both: check 6 = `moderation_draft` (already stored), check 7 = `moderation_gate` (this task), check 8 = `real_world_signal` (this task).

### Scene-prompt expansion

```csharp
// 03 feature D1 — one shared builder (03 CR-3); moderate the text without the platform negative clause
var prompts = story.Keywords
    .Select(k => ScenePromptBuilder.Build(styleTemplate, k).ModerationText)
    .ToArray();
```

- `style_templates.template` is read once per evaluation through the existing read path (09.4.2-T1 `GET /style-templates` uses the same rows); the negative clause ("no gore, no text, no logos, no real person likeness") is **not** part of the template: `ScenePromptBuilder` appends it, and `ModerationText` leaves it out, so a clause that scores on `violence`-adjacent categories can never fail every episode by itself. No strip setting exists (03 CR-3).
- Scene prompts are checked in the **series language** for vi series, but the keywords are English (03 FR-03-3). Both are sent as-is: the moderator handles mixed text ⚠️ (T3 measures the false-positive rate on vi series).

### Real-world detection (F31: three signals, no named-entity claim)

| Signal | Rule | Example hit |
|---|---|---|
| `FramingLexicon` | a phrase from `real-world-framing.{vi\|en}.txt` appears in a segment (case- and diacritic-insensitive, word-boundary match, NFC-normalised) | vi "dựa trên sự kiện có thật"; en "based on real events" |
| `DatedIncident` | a **date pattern** and an **incident word** occur in the **same segment** (`RequireIncidentCoOccurrence = true`) | vi "ngày 12/3/2019 … vụ án"; en "In March 2019 … the murder case" |
| `ModelClaim` | `audit_report.model_review.real_world_claims[]` is non-empty (D16/D22) | the reviewer says "this reads as a real 2018 incident" |

- **Deliberate non-signal:** character, place and person names. F31: a fiction detector cannot separate an invented name from a real one, and a named-entity list would both miss real people and block every ordinary name. Not implemented, documented here and in the run-log copy (`autopilot.gate.failed.real_world_signal`).
- `Evidence` is ≤ 200 chars of **our own draft** around the match (D22 rule) and never source text; the lexicon phrase itself is the `MatchedPhrase`.
- Segment addressing is the D22 one, so the owner can jump to the exact place in the editor (10.5.10).
- Every hit → check 8 fails → owner review (UC6). No automatic rewrite, no automatic block of the idea.

Dated-incident patterns (compiled with `[GeneratedRegex]`, `RegexOptions.IgnoreCase`; no backtracking constructs so `RegexOptions.NonBacktracking` is possible ⚠️ verify with the chosen patterns):

| Language | Pattern (essence) |
|---|---|
| vi numeric | `\b(?:ngày\s+)?\d{1,2}[/-]\d{1,2}[/-](?:19\|20)\d{2}\b` |
| vi long | `\bngày\s+\d{1,2}\s+tháng\s+\d{1,2}(?:\s+năm\s+(?:19\|20)\d{2})?\b` |
| vi year | `\bnăm\s+(?:19\|20)\d{2}\b` |
| en month | `\b(?:Jan(?:uary)?\|Feb(?:ruary)?\|Mar(?:ch)?\|Apr(?:il)?\|May\|Jun(?:e)?\|Jul(?:y)?\|Aug(?:ust)?\|Sep(?:tember)?\|Oct(?:ober)?\|Nov(?:ember)?\|Dec(?:ember)?)\s+\d{1,2},?\s+(?:19\|20)\d{2}\b` |
| en day-month | `\b\d{1,2}\s+(?:Jan…\|Dec…)\s+(?:19\|20)\d{2}\b` |
| en numeric | `\b\d{1,2}[/-]\d{1,2}[/-](?:19\|20)\d{2}\b` |

Incident words (same segment, `Autopilot:Gates:RealWorld:IncidentWords`, configurable, data not code):
- vi: `vụ án`, `vụ thảm sát`, `án mạng`, `giết người`, `tai nạn`, `vụ nổ`, `bắt giữ`, `kết án`, `tù chung thân`, `tử hình`, `mất tích`, `tự tử`
- en: `murder case`, `homicide`, `massacre`, `shooting`, `arrested`, `convicted`, `sentenced`, `life sentence`, `death penalty`, `went missing`, `suicide`

`YearOnly` alone (e.g. "năm 2020") is **not** a hit: it co-occurs with ordinary fiction dates. It counts only with an incident word in the same segment. This is the main false-positive control and T3 measures it.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Moderator 5xx/timeout after retries | fail closed (`moderator_unavailable`), owner review, no `moderation_events` row (nothing was classified) |
| Text longer than the chunk limit | chunked on a paragraph boundary; a single paragraph longer than the limit is hard-split at the limit (⚠️ D12 has no documented limit; T3 records the real behaviour) |
| Lexicon file missing at runtime | start-up fails (D5); never an empty lexicon silently passing everything |
| Style template has no `{term}` | `ScenePromptExpander` sends the raw keyword (03 FR-03-1 expects `{term}`; a template without it is a 03-side data error) and logs a warning |
| Keyword list empty | no scene prompts to check; narration and metadata are still checked |
| Detector hits in a `user_note` or a fact statement | never — the detector only sees generated content (`story_versions.content` + metadata), never the owner's inputs |
| Story edited after generation | the gate re-runs both checks on the edited version (T1 §Notes); the previous verdict is overwritten in the same `gate_results` object with a higher `attempt` |
| False positive on ordinary fiction | the co-occurrence rule (date **and** incident word in one segment) keeps single years/dates out; residual false positives are a cost, not a safety hole (owner review), and T3 tunes the incident-word list |
| Rollback | the two checks fail closed if their services are removed; there is no flag to disable them individually — disabling is done by `Autopilot:Gates:DryRun = true` |

## Notes
