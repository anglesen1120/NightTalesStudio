## Goal

Every gate threshold has a validated default, the gate runs in **dry-run** mode (evaluate and record, never auto-approve) until the owner has reviewed a calibration report over the first `N = 10` autopilot episodes, and the owner can decide the final numbers from measured pass/fail data instead of guessing.

## Design

### Configuration surface (owned here)

```jsonc
{
  "Autopilot": {
    "Gates": {
      "DryRun": true,
      "DryRunMaxEpisodes": 10,
      "Profiles": {
        "default": {
          "Story": {
            "MinMeanReviewScore": 3.5, "MinDimensionScore": 3.0, "MaxRevisions": 1,
            "MaxSourceSimilarity": 0.05, "MaxPastEpisodeSimilarity": 0.10,
            "AllowedContentWarnings": ["violence", "death", "crime", "supernatural", "disturbing"]
          },
          "Moderation": {
            "BlockedCategories": ["sexual/minors", "self-harm/instructions", "illicit/violent", "hate/threatening"],
            "MaxScore": { "harassment": 0.5, "hate": 0.3, "illicit": 0.5, "self-harm": 0.3,
                          "sexual": 0.5, "violence": 0.6, "violence/graphic": 0.3 }
          },
          "RealWorld": { "RequireIncidentCoOccurrence": true, "IncidentWords": { "vi": ["…"], "en": ["…"] } },
          "Video": { "MaxDurationDeviation": 0.05, "LoudnessLufs": [-16.0, -14.0], "RequireSubtitlesWhenEnabled": true }
        },
        "strict": {
          "Story": { "MinMeanReviewScore": 4.0, "MinDimensionScore": 3.5, "MaxSourceSimilarity": 0.03, "MaxPastEpisodeSimilarity": 0.05 }
        }
      }
    }
  }
}
```

- `strict` is a partial overlay: any key it omits inherits from `default` (`AutopilotGateProfile.Merge(default)`).
- `Video` moves the 05.5.1 numbers into the gate profile so the gate can be stricter than the render check if the owner wants (default: identical).
- `series.autopilot_settings.gate_thresholds_ref` selects `"default"` or `"strict"`. A missing/unknown profile → `default` + a warning log (never a disabled gate).

### Validation (`AutopilotGateOptionsValidator : IValidateOptions<AutopilotGateOptions>`)

Fail start-up (not the run) on any of these — a gate with a nonsense threshold must never run:

| Rule | Reason |
|---|---|
| every profile key is a known path under `Story`/`Moderation`/`RealWorld`/`Video` | a typo silently disabling a check |
| `1 ≤ MinMeanReviewScore, MinDimensionScore ≤ 5` | D16 scale |
| `0 ≤ MaxSourceSimilarity ≤ Similarity:BlockAbove` (0.97 after the 02.5.6-T2 calibration; was 0.15) and `0 ≤ MaxPastEpisodeSimilarity ≤ 1` | an autopilot threshold looser than the human block is a contradiction |
| `MaxRevisions ∈ {0, 1}` | D21 allows at most one revision |
| `AllowedContentWarnings ⊆` the D3 `content_warnings` enum | an unknown warning never matches |
| `BlockedCategories ⊆` the 13 O7 categories; `MaxScore` keys ⊆ the same set; values ∈ [0, 1] | a category name typo would silently pass everything |
| `DryRunMaxEpisodes ≥ 1`; `LoudnessLufs[0] < LoudnessLufs[1]` | sanity |
| at least one `Profiles` entry named `default` | the fallback target |

`ValidateOnStart()` is used so the failure is at boot, matching D5's prompt-catalog behaviour.

### Dry-run mode

```csharp
public sealed class GateModeResolver(IOptionsMonitor<AutopilotGateOptions> options, IGateCalibrationCounter counter)
{
    public async ValueTask<GateMode> ResolveAsync(Guid seriesId, CancellationToken ct);
    public async ValueTask<GateCalibrationStatus> StatusAsync(Guid seriesId, CancellationToken ct); // Evaluated, Remaining
}
```

- `mode = options.CurrentValue.DryRun ? GateMode.DryRun : GateMode.Live`. **The flag is authoritative and never flips itself.** `DryRunMaxEpisodes` only drives the readiness signal, so a bug or a stuck counter can never enable live gates.
- `IGateCalibrationCounter.CountEvaluatedAsync(seriesId, ct)` counts the series' runs whose `gate_results` is non-null and whose `mode = 'dry_run'`:

```sql
SELECT count(*) FROM autopilot_runs
WHERE series_id = @seriesId AND gate_results->>'mode' = 'dry_run';
```

  (no new column, no migration; index `(series_id, slot_at DESC)` from 02.8.3-T1 covers the scan).
- In dry run: `GateResultWriter` stores `mode = "dry_run"`, `AutoApproved = false`, `Reason = DryRun`, and the owner is notified for **every** episode (UC6 with `CopyKey = autopilot.gate.dry_run_review`). The pipeline therefore behaves exactly like a fully manual channel — the safest possible first 10 episodes.
- `GET /series/{id}/autopilot/runs` (02.8.3-T2) exposes `gatesDryRun: true|false` and `gatesDryRunRemaining: n` so the UI can show the banner without a new route.

### Calibration report (read model — no new binary, no new route)

`GateCalibrationReportBuilder` (Application `Features/Autopilot/Gates/GateCalibrationReportBuilder.cs`), a pure aggregation over rows already loaded for the run log — **not** a CLI (00 §5.2 lists only `tools/mock-mpt/`; `nts`/`nts-admin` in DECISIONS.md is the host-operator break-glass tool, not a reporting surface):

```csharp
public interface IGateCalibrationReportBuilder
{
    GateCalibrationReportDto Build(IReadOnlyList<AutopilotRunGateRow> runs, IReadOnlyList<OwnerVerdictRow> ownerVerdicts, int target);
}
public sealed record GateCalibrationReportDto(int Evaluated, int Target, bool Ready,
    IReadOnlyList<CheckStatDto> CheckStats, HistogramDto ReviewScoreHistogram, HistogramDto SimilarityHistogram,
    double FalseBlockRate, double PotentialFalseApproveRate, int NoOwnerVerdictCount,
    IReadOnlyList<string> RecommendationLines);
public sealed record CheckStatDto(string CheckId, int Evaluations, int Passes, double PassRate,
    decimal? Min, decimal? P50, decimal? Max, decimal? Threshold, decimal? ClosestFailureMargin);
```

- `AutopilotRunGateRow` = the dry-run subset of `autopilot_runs` for the series (`gate_results->>'mode' = 'dry_run'`, already the query 02.8.3-T2's `ListAutopilotRunsQuery` loads for the run log — no second round trip for the common case).
- `OwnerVerdictRow` = one extra query over `audit_logs` (D13, CR-3) for `episode.story_approved` / `episode.story_version_saved` / `episode.story_reopened` / video reject rows on the series' episodes in the calibration window, joined by `episode_id`.
- **Consumed by `GET /series/{id}/autopilot/runs`** (02.8.3-T2, `ListAutopilotRunsQuery`): when the series has at least one `mode = dry_run` run, the response adds an optional `calibrationReport: GateCalibrationReportDto` field — no new route, no new project. 10.4.3-T1's run log renders it as a summary panel above the per-run list; the per-run verdicts are the existing list items (the "verdict table" of the original design).
- The report's six elements: **(1)** the run list itself (verdict table); **(2)** `checkStats`; **(3)** `reviewScoreHistogram`/`similarityHistogram`; **(4)** `falseBlockRate`/`potentialFalseApproveRate`/`noOwnerVerdictCount`; **(5)** `recommendationLines` (deterministic: pass rate < 50 % / > 95 % with no near-misses / one category dominates — see the decision table below); **(6)** `evaluated`/`target`/`ready`.

### Calibration procedure (owner-facing, repeated at M1 exit and after any threshold change)

1. Enable autopilot for the series with `DryRun = true` (default). The planner produces the first `N` episodes; the owner approves each one by hand in the UI as usual.
2. After the `N`-th run reaches a terminal state: open the series' Autopilot tab → run log (10.4.3-T1). The calibration panel (from `GET …/autopilot/runs`'s `calibrationReport` field) shows the six elements and the readiness line (`Evaluated N/N`).
3. Read the false-block / potential-false-approve rates. Any **false block** is the expensive error: it means the owner's taste is looser than the threshold. Any **potential false approve** means a real defect slipped through and the threshold must be tightened.
4. Apply the recommendation lines **one check at a time** — a single config change per calibration round, so the next 10 episodes attribute the effect. Record the before/after numbers in `DECISIONS.md` §3 if the change is material (D15 precedent).
5. Set `Autopilot:Gates:DryRun = false`. From that run on, every verdict carries `mode = "live"`, so "when did gates go live" is answerable from `autopilot_runs`.
6. Re-run the procedure after any material prompt/preset change (02.1.3-T2) or model change (D15), and whenever 02.8.3-T4 pauses the series for two gate failures in a row (the pause is the trigger for a calibration round, not a reason to loosen everything).

### Threshold decision table (what to change for which symptom)

| Symptom in the report | Likely cause | Change |
|---|---|---|
| `self_review_mean_score` fails > 50 % | the review model scores harshly in this language, or the writer is weak for the tier | lower `MinMeanReviewScore` by 0.25 **or** raise the writer model per language (D15); never lower `MinDimensionScore` below 3.0 |
| `similarity_past_episodes` fails often on a small series | the past-episode corpus is tiny and near-duplicate openings dominate | raise `MaxPastEpisodeSimilarity` to 0.15 (still at the human warn level) — but see 02.8.4 variety, which should fix the cause |
| `length_in_range` fails often | D4 rate/token band not calibrated for the language | fix the D4 numbers (F07), do not widen the gate |
| `moderation_gate` fails often, categories are `violence`/`violence/graphic` | horror content legitimately scores here | raise `MaxScore.violence` (0.6 → 0.7) after checking the excerpts; **never** raise `sexual/minors`, `self-harm/instructions`, `illicit/violent`, `hate/threatening` — they stay blocking |
| `real_world_signal` fails often with `DatedIncident` | the incident-word list is too broad for the genre | trim `RealWorld.IncidentWords`; keep the co-occurrence rule |
| `real_world_signal` never fires | the lexicon is too small or the folding is broken | add phrases; verify the diacritic fold with a fixture |
| `video_failed_scenes` fires | MPT skipped scenes (blocked or failed images); `quality_report.images.skipped` names them (03 D7) | not a gate problem — the owner edits the scenes; if one template causes most blocks, retire it (03 §8); keep the check (03 CR-3) |
| every check passes and the owner still edits | the gate cannot see taste | that is expected; do not loosen deterministic checks to chase it |

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Fewer than `N` runs available | report prints `Evaluated 4/10` and still shows every statistic; readiness stays "not ready" |
| A run has `gate_results = null` (pre-gate run, e.g. an older row) | skipped by the counter and shown as `n/a` in the verdict table |
| `audit_logs` has no owner action for an episode (owner never touched it) | excluded from both rates, counted separately as `no_owner_verdict` |
| Owner changes `DryRun` mid-flight | allowed; `mode` is per verdict, so both phases are visible in one report |
| Threshold change without re-calibration | allowed but discouraged by the procedure; the report's "since last change" column shows it |
| The ground-truth query times out or errors | the run list itself still returns; `calibrationReport` is omitted and the run log shows "calibration data unavailable" rather than failing the whole response |
| Rollback | set `DryRun = true`; the report stays readable and every past verdict keeps its own `mode` |
