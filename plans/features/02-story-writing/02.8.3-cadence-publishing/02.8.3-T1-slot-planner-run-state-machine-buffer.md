## Goal

One recurring tick (`AutopilotPlanJob`, every 15 min, D17) turns each enabled, unpaused series' cadence into `autopilot_runs` rows — exactly one per slot, `UNIQUE (series_id, slot_at)` — and advances every due run through a single explicit state machine, calling the same commands a user would call, under `SystemContext(ownerId)` with `trigger = autopilot`. A fiction run reaches `published` without the owner; a true-crime run stops for the owner at the fact sheet and again at the story; every step is idempotent by `autopilot:{seriesId}:{slotAt:O}:{step}`.

### Ready buffer (exact semantics)

- `buffer_days` (1..7) is both the **planning horizon** and the **ready-buffer depth**: `start_at = min(slot_at − buffer_days, story_start_at)` (§3.4), so with `buffer_days = 2` the episode is normally `ready` about 1.5 days before its publication is created.
- The buffer is realised by *when* the run starts, because only one run per series may be in a **producing** state (`IsProducing`: `planned`…`publication_created`). Once a run reaches `veto_window` (its production is finished and its publication exists), the next slot's run may start — that is what keeps a daily cadence fed.
- `Autopilot:MaxProducingRunsPerSeries` = 1 (config, validated ≥ 1); a second producing run would be a bug, so the orchestrator asserts it and logs `autopilot_concurrency_violation_total`.
- Horizon: `horizonDays = buffer_days + max(cadence interval in days, 1)` (§3.2).

### Per-run caps (D17)

| Cap | Where enforced | On exceed |
|---|---|---|
| ≤ 1 idea pick | `PlanIdeaStep` (`step = "idea"`) | a second attempt is impossible: the step key is the slot's idea key |
| ≤ 2 story generations | `AutopilotRun.Attempt` + step `story` / `story2` | `StoryGateStep` on a failing gate with `Attempt = 2` → `gate_failed` |
| ≤ 1 render | `AutopilotRun.RenderAttempts` + step `render` | a render failure → `failed` (`render_failed`), no retry in the run |

### True-crime path (F33)

`PlanIdeaStep` → `ResearchStep` when `series.topic = true_crime`:
1. If the `source_finder` flag is on **and** 02.7.1 recorded a go: `generation_runs` row (`kind = find_sources`, `trigger = autopilot`, key `…:find_sources`), `FindSourcesCommand` → candidate links → `AddSourceCommand` for the selected ones → `GenerateFactSheetCommand` (`kind = fact_sheet`, key `…:fact_sheet`) → `waiting_owner` (`waiting_for = fact_sheet`).
2. Otherwise (F33): `waiting_owner` with `waiting_for = sources`, and the alert copy `autopilot.true_crime.add_sources` tells the owner to paste links. No finder call is attempted.
3. From either branch the run only continues on `FactSheetApproved` (user) → `story_generating` → `story_gate` → the gate's true-crime hold → `waiting_owner` (`waiting_for = story`) → continues on `StoryApproved` (user, `ApprovalSource.User`) → `rendering`.
4. `waiting_owner` expiry (`Autopilot:WaitingOwner:ExpiryHours` = 48) → `failed` with reason `owner_approval_expired`; the episode stays in its review state for the owner to finish by hand, and the slot is skipped. Expiry does **not** pause the series (a true-crime series legitimately waits).

### Idempotency

Every step key is `autopilot:{seriesId}:{slotAt:O}:{step}` with `step ∈ {idea, story, story2, story_gate, render, video_gate, publication, consent, go_live, find_sources, fact_sheet, sources_required}`:
- `generation_runs.idempotency_key` carries it for the paid steps (D2), so a duplicated tick cannot pay twice;
- `autopilot_runs.step` is the local guard: a step is executed only when `step` is strictly behind it;
- the episode state machine is the final guard (e.g. `story_review → story_approved` twice is rejected by the domain, 00 §7);
- the slot insert is `ON CONFLICT (series_id, slot_at) DO NOTHING`;
- all outbox handlers are safe to run twice because they only call `AdvanceAsync`, which compare-and-sets.

### SystemContext

`AutopilotRunOrchestrator` opens a scope per run: `SystemContext.For(run.UserId)` (09.2.3) — `ICurrentUser.Id = run.UserId`, tenant filters **on**, actor `system`. A run whose `user_id` does not resolve fails the step and logs (never runs unfiltered). `IgnoreQueryFilters` is not used anywhere in this feature; the tick's cross-series scan is the allow-listed `(id, user_id)` system query (09.2.3, architecture test).

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Tick overlaps itself (previous tick still running) | Hangfire's `DisableConcurrentExecution`-equivalent via `IJobScheduler` ⚠️ confirm the port supports it; otherwise the compare-and-set on `(state, step)` makes the overlap harmless |
| No valid authorization | runs → `awaiting_authorization`; the series is not paused; the UI shows the re-accept banner |
| Channel connection not `active` | the planner still creates runs (the owner may fix the channel before the slot), but `PlanIdeaStep` refuses and pauses (T4 trigger 6) |
| Budget refusal at any paid dispatch | step → `failed` (`spend_cap_reached`); T4 pauses |
| Outbox message lost | the tick's time-based fallback advances the run (plan §7.2) |
| Worker restart mid-step | the step is re-entered; the paid steps are guarded by `generation_runs.idempotency_key`, the local ones by `step` |
| `slot_at` in the past at planning time (a series enabled after its publish time) | the slot is skipped (`autopilot_slot_skipped_total{reason="in_past"}`); the next slot is used |
| Two series share a channel and both want the same local day | the daily cap is per channel; the second series' slot is skipped that day (logged, no run row) |
| `start_at` already in the past when the run is created | the run is planned and advanced in the same tick (catch-up), which is why `start_at` may be earlier than `now` |
| DST gap/overlap | resolved once in `SlotCalculator` (§3.2), logged, stored — never re-resolved later |
| Rollback | unregister the recurring job (one line); existing runs stop advancing, publications continue through 06. No data migration needed |
