## Goal

The owner can read and change a series' autopilot settings, accept a **versioned authorization text** (bound by a hash of the exact rendered text), revoke it, pause/resume and list runs — with the topic locked while autopilot is on, a re-auth requirement for the two consent-bearing actions, and any change to a field the text covers revoking the authorization until it is accepted again.

### Authorization text

Template `prompts/shared/autopilot-authorization.{vi|en}.v1.md`, embedded and hashed at start-up like the prompt catalog (D5). Placeholders: `{{series_title}}`, `{{topic_label}}`, `{{channel_title}}`, `{{days_of_week}}`, `{{publish_time}}`, `{{time_zone}}`, `{{daily_cap}}`, `{{privacy_label}}`, `{{veto_window_hours}}`, `{{pre_audit_note}}`. `text_hash = sha256(NFC(rendered text), UTF-8, lowercase hex)`.

**en (`autopilot-authorization.en.v1.md`):**

> I authorize NightTalesStudio to upload **each autopilot episode of the series "{{series_title}}"** (topic: {{topic_label}}) to the YouTube channel **{{channel_title}}** on this cadence: **{{days_of_week}} at {{publish_time}} ({{time_zone}})**, at most **{{daily_cap}}** video(s) per day, with privacy **{{privacy_label}}**. Every episode is shown to me before it is uploaded and I can edit or cancel it during the veto window of **{{veto_window_hours}} hours**; if I do nothing, the upload proceeds. {{pre_audit_note}} I understand the videos are synthetic media and are flagged as such, and that I can turn this off at any time, which stops future uploads.

**vi (`autopilot-authorization.vi.v1.md`):**

> Tôi cho phép NightTalesStudio tự động tải lên **mỗi tập của series "{{series_title}}"** (chủ đề: {{topic_label}}) lên kênh YouTube **{{channel_title}}** theo lịch: **{{days_of_week}} lúc {{publish_time}} ({{time_zone}})**, tối đa **{{daily_cap}}** video mỗi ngày, chế độ hiển thị **{{privacy_label}}**. Mỗi tập đều được hiển thị cho tôi trước khi tải lên và tôi có thể sửa hoặc huỷ trong thời gian chờ **{{veto_window_hours}} giờ**; nếu tôi không làm gì, video sẽ được tải lên. {{pre_audit_note}} Tôi hiểu video là nội dung tổng hợp (synthetic media) và được gắn nhãn như vậy, và tôi có thể tắt bất cứ lúc nào — việc tắt sẽ dừng các lần tải lên tiếp theo.

`{{pre_audit_note}}` (only when `youtube_audit_status = pending`):
- en: "Until the YouTube API audit is approved, uploads stay **private** and are not published publicly."
- vi: "Cho đến khi YouTube duyệt API, các video chỉ ở chế độ **riêng tư** và không được công khai."

`{{privacy_label}}` maps `public|unlisted|private` to "public (everyone)" / "unlisted (link only)" / "private" and "công khai" / "không công khai (chỉ có link)" / "riêng tư". `{{topic_label}}` maps `ghost|spiritual|true_crime` to "ghost stories" / "spiritual stories" / "true crime (real people, always reviewed by me)" and "truyện ma" / "truyện tâm linh" / "true crime (người thật, luôn do tôi duyệt)".

`AuthorizationTextRenderer` (Application) is the single place that renders the text, used by GET (to show it), by accept (to re-render and compare the hash) and by 06.2.2-T3 (it stores `consent_text_version`, not the text).

### Accept / revoke rules

- Accept: re-render from the **stored** settings + series + channel + audit status; require `textVersion` and `textHash` to match exactly; on mismatch → 409 `autopilot_authorization_required` with `errors["textHash"] = "stale_text"`. On success: insert `series_autopilot_authorizations` (`version = previous + 1`, `cadence` = the settings snapshot, `topic`, `channel_connection_id`, `privacy`, `accepted_at = now`), set `series.current_autopilot_authorization_id`, write `autopilot.authorization_accepted`, and emit the outbox event `AutopilotAuthorizationAccepted`.
- Revoke (automatic): a change to any **covered** field revokes — `series.topic`, `series.default_channel_id`, `cadence.*`, `daily_cap`, `privacy`, `veto_window_hours`, `pre_audit_mode`; so does disabling autopilot (`revoked_reason = disabled`), accepting a new version (`superseded`) and `DELETE …/authorization` (`owner_revoked`). Revocation sets `revoked_at` + `revoked_reason`, clears `series.current_autopilot_authorization_id`, writes `autopilot.authorization_revoked`, and moves the series' non-terminal runs to `awaiting_authorization` (via T1's orchestrator, one call per run).
- Not covered (no revocation): `tone`, `banned_themes`, `gate_thresholds_ref`, `render_lead_minutes`, `story_lead_minutes`, `series.title` (plan §3.7 [DECISION]).
- The covered-field check is an **explicit field-by-field comparison** against the authorization's stored `cadence` snapshot (00 §6) — not a diff of the rendered text, because the text also carries `series.title` (confirmed by the TL, README §10 T10: the authorization names the series by id, a rename does not revoke). Adding a new covered field is a code change in the comparator, listed once here and in plan §3.7.

### Enable/disable and re-auth

- `PUT /series/{id}/autopilot` with `enabled = true` requires, in order: (0) the owner's current legal acceptance (`ILegalAcceptance.EnsureCurrentAsync`, else 409 `legal_acceptance_required`; 13.2.1-T1, 13 CR-2); (1) re-auth within 5 min (`POST /auth/reauth`), else 401 `reauth_required` (09.3.2 pattern — enabling authorizes future uploads without per-video consent); (2) valid settings; (3) a current authorization whose hash matches the rendered text for the **new** settings, else 409 `autopilot_authorization_required`; (4) an `active` channel connection on `series.default_channel_id`, else 409 `channel_reauth_required`, and that connection's `platform` is not `tiktok`, else 409 `autopilot_channel_unsupported` (07 CR-5 — TikTok Direct Post has no scheduling parameter and requires a per-post manual privacy choice); (5) topic unchanged while it was enabled, else 409 `autopilot_topic_locked`.
- `enabled = false` → revoke (`disabled`) + `autopilot.disabled`. No re-auth (it reduces risk).
- Settings-only change while enabled: apply, then run the covered-field diff → revoke + move runs to `awaiting_authorization` if a covered field changed.
- `PATCH /series/{id}` with a topic change while `autopilot_enabled` → 409 `autopilot_topic_locked` (guard supplied to 09.4.1-T1; the guard reads `series.autopilot_enabled` inside the same transaction). `DELETE /series/{id}` (archive) with autopilot on → implicitly disables + revokes in the same transaction ([DECISION], CR to 09.4.1-T1).
- `If-Match` on the series aggregate: `"sa-<series.xmin>"` ⚠️ (plan §10 open item 7); stale → 412 `series_conflict`.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Owner accepts from a page rendered with older settings | 409 `stale_text`; the UI reloads the text |
| Two tabs accept different texts | the second accept compares against the **stored** settings (single source), so only one of them matches; the other gets `stale_text` |
| Settings invalid **and** the authorization would change | 400 first (the text cannot be rendered from invalid settings) |
| No channel connected | 409 `channel_reauth_required` on enable; the settings can still be saved with `enabled = false` |
| `youtube_audit_status` flips pending→approved | the rendered text changes (the pre-audit note disappears) → the covered-field diff revokes, and the owner re-accepts. [DECISION] This is intended: the accepted text said "private until the audit", so a public cadence needs a new acceptance |
| Series archived while enabled | disabled + revoked in the same transaction; episodes stay |
| Run list for a series with no runs | 200 with `items: []` (not 404) |
| `gate_results` absent on an old run | `Gates = null` in the DTO, never an error |
| Rollback | disable the series (revokes); the routes can be hidden by the `youtube_publish` flag without a migration |
