## Goal

A pure, deterministic plan for the images of one render: how long each image stays on screen, how many images the narration needs, which keywords are sent (in story order, capped with a few spares), which hints the user sees — and the worst-case image cost that the budget guard checks before anything is paid.

## Inputs

- README **D3** (formulas, trim rule, hints), **D4** (`video_clip_duration`, array terms), **D8** (worst case, placeholder 6,000 tokens), **F03**, **F17**.
- `plan.md` §3.1 (types), §3.2 (`image_plan` jsonb), §4 (callers).
- I7/I8: MPT stops once the audio is covered and loops short material, so terms beyond `NeededImages` are unpaid spares.
- 02 D4 rates and tiers; 02 D3/D22 segment order and addresses.

## Design

### Algorithm (`RenderImagePlanner.Plan`)

```text
rate            = lang == vi ? RateVi : RateEn                     // tokens per minute
estSeconds      = ScriptTokens / rate * 60
needed          = max(1, ceil(estSeconds / ClipSeconds))
tierMaxMinutes  = { short: 1, standard: 8, long: 15 }[Tier]
tierCap         = ceil(tierMaxMinutes * 60 / ClipSeconds)
maxTerms        = min(ceil(needed * (1 + SpareShare)), tierCap)

terms           = flatten(Segments)  // (segment, index-in-segment, keyword), story order
if terms.Count > maxTerms:
    drop index-1 keywords, walking segments from the last to the first, until Count == maxTerms
    if still > maxTerms: drop index-0 keywords from the last segment backwards until Count == maxTerms
    hints += "scenes_trimmed"
if terms.Count < ceil(needed * SparseShare): hints += "scenes_sparse"
slots           = 0..terms.Count-1 in story order
```

- Default options: `ClipSeconds = 10`, `SpareShare = 0.15`, `SparseShare = 0.7`, `RateVi = 260`, `RateEn = 200` (config `Images:ClipSeconds`, `Images:SpareShare`, `Images:SparseShare`, `Story:Length:Rate:{lang}`; 02 T103 — vi 260 syllables/min, en 200 words/min, superseding the 160/145 defaults).
- Worked example (Standard vi, 1,560 tokens, 26 segments × 1.5 keywords = 39 keywords): est = 1,560 ÷ 260 × 60 = 360 s → needed = ceil(360 ÷ 10) = 36 → maxTerms = min(ceil(36 × 1.15), ceil(8 × 60 ÷ 10)) = min(42, 48) = 42 → nothing trimmed (02 T103).
- Worked example (Short en, 170 tokens, 5 segments × 2 = 10 keywords): est = 170 ÷ 200 × 60 = 51 s → needed = ceil(51 ÷ 10) = 6 → maxTerms = min(ceil(6 × 1.15), ceil(1 × 60 ÷ 10)) = min(7, 6) = 6 → trim 4 second keywords (from the last segment backwards) → hint `scenes_trimmed` (02 T103).
- The planner never reorders and never edits a keyword.

### `ImageCostEstimator : IImageCostEstimator` (Application/Features/Rendering)

```csharp
public CostBound WorstCase(Aspect aspect, int maxTerms, int priceVersion)
{
    var r = priceCatalog.Get(priceVersion).Rates.Image[options.Model];      // D8 shape
    var cell = $"{aspect.ToWire()}:{options.QualityOrAuto}";
    var tokens = r.TokensPerImageP95.GetValueOrDefault(cell, options.PlaceholderTokensPerImage); // 6,000 ⚠️
    var perImage = tokens * r.ImageOutPer1M / 1e6m + 200 * r.TextInPer1M / 1e6m;
    return new CostBound(maxTerms * perImage);
}
```

- `options.QualityOrAuto` = `ImageRelay:Quality` mirrored in the backend config `Images:Quality` (unset → `auto`, D9).
- `CostBound` is the 02 D1 type used by `IBudgetGuard.CheckAsync`.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| No keywords at all (validator should prevent it) | plan with 0 terms + `scenes_sparse`; 09.6.1 refuses to render with 409 `keywords_flagged` rule `no_scenes` (03.2.2-T2) — MPT would fail at stage `terms` (I11) |
| Measured speaking rate differs from the default | only `needed` moves; spares absorb ±15 %. A narration longer than all terms can cover loops images (I8); that is not a skip (D6 `failed` stays empty), so the video gate passes and only the `scenes_sparse` hint (if raised at plan time) tells the user |
| Price version has no image block yet (before 03.3.1-T2) | placeholder tokens (6,000 ⚠️) → a high but safe bound |
| `Images:ClipSeconds` changed | affects new renders only; K in the story prompts (02 D4) should change with it — documented in the config comment |
| Rollback | config only; the planner has no state |
