## Goal

Keywords that name a real person from the episode's own research (source titles and approved facts) are flagged before any image is paid for, in both languages, on top of the general `KeywordRules` from plan 02.

## Design

### Folding (`NameCorpus.Fold`)

1. NFD normalise; drop every char in Unicode category `Mn` (combining marks).
2. Map `đ` → `d`, `Đ` → `D` (not decomposed by NFD).
3. Split on any char that is not a letter or digit; keep the original casing for run detection, then lower-case for storage.

`"Vụ án Nguyễn Văn An ở Đà Lạt"` → tokens `Vu an Nguyen Van An o Da Lat` → runs `Nguyen Van An`, `Da Lat` → stored `["nguyen","van","an"]`, `["da","lat"]`.

### Run extraction (`NameCorpus.From`)

- A run = ≥ 2 consecutive tokens whose first letter is upper case.
- The first token of a run is skipped while it is in the stop list (folded, case-insensitive): `the, a, this, that, in, on, at, of, police, court, case, vu, toa, cong` — then the rest of the run is re-evaluated (still needs ≥ 2 tokens). `an` is **not** in the list: it is both an English article and a common Vietnamese given name (`An`), and folded `án` ("case") would otherwise drop a real first name.
- **Title Case guard (03 CR-18a; applies to source titles only, 03 CR-18d):** a text where ≥ 60 % of the tokens with ≥ 3 letters start upper case (typical English headlines, "The Night The Lights Went Out") is skipped, because every word pair would become a "name". With the two-argument `NameCorpus.From(titles, statements)` the guard runs on the source titles only: fact statements are sentences and skip it (they are the main name source), and Vietnamese titles are sentence case in practice ⚠️ (checked on the first 10 true-crime episodes).
- Sentence-initial words are handled by the stop list only; a sentence starting with a real surname still yields its run [DECISION: accept more false positives over missed names].
- Place names (`Da Lat`) are also caught. That is acceptable: keywords should describe scenes generically ("mountain town at night"), and a place name plus a real case is identifying (G4) [DECISION].

### Match (`NameCorpus.Matches(keyword)`)

- Fold the keyword the same way, lower-case, tokenise.
- Flag when any 2 consecutive tokens of any run appear as 2 consecutive tokens of the keyword (`van an` matches `nguyen van an`).
- Complexity: runs are stored as a `HashSet<(string, string)>` of bigrams → O(keyword tokens).

### Provider (`NameCorpusProvider : INameCorpusProvider`, Infrastructure/Rendering)

- Loads, through `IReadDb` under the episode's tenant filter: titles of `story_sources` with `kind = url` and `status = fetched`; statements of the episode's `fact_sheets` row with `status = approved` (if any). Builds the corpus with `NameCorpus.From(titles, statements)`, so the Title Case guard applies to the titles only (03 CR-18d).
- Returns `NameCorpus.Empty` when `Images:Linter:NameCorpusEnabled = false` or the series topic is not `true_crime` [DECISION: fiction has no real-person corpus].

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| A place name blocks a scene the user wants ("Da Lat pine forest") | expected (G4); the hint copy tells the user to describe the place generically |
| A name split across tokens differently in the keyword (`NguyenVanAn`) | not matched (no bigram); residual; `KeywordRules` capitalisation heuristic may still catch it |
| Very long fact sheets | corpus is built once per call from ≤ 100 facts (02 fact sheet limits) — negligible cost |
| Fact sheet approved after the story was approved | the render-time lint (03.2.2-T2) catches it → 409 `keywords_flagged`, user reopens |
| Rollback | `Images:Linter:NameCorpusEnabled = false`; `KeywordRules` stay on |
