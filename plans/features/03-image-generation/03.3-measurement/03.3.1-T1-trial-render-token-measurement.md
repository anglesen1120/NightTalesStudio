# 03.3.1-T1 — Trial renders token measurement (3 per aspect) + token report

| Story | Size | Area | Depends on | Blocks | Phase / flag |
|---|---|---|---|---|---|
| 03.3.1 | S (0.5) | Worker | 03.4.1-T1 (submit fields proven), 05.5.2-T1 (two landscape trial renders: L1 vi + L2 en, or a second vi story when en is not launched, 05 T14) (05 CR-7), 01.3.1-T3 (collector, `finish_run.py`), 03.3.2-T1 (chosen quality for the confirmation runs) | 03.3.1-T2 | P · M0 · `TAP_IMAGE_QUALITY` for runs L3/P3 only |

## Goal

Measured output tokens and cost per image for landscape and portrait, from real MPT renders that use the D4 submit fields (10-s clips, sequential order, array terms), both for what MPT does today (`auto`) and for the quality chosen on the contact sheet (injected by the tap) — plus proof that images per minute ≈ 6.

## Inputs

- README **D3** (clip 10 s → 6 images/min), **D4** (submit fields), **D13** (M0: global template per run, tap), **I7** (billed images ≤ `ceil(audio ÷ clip)`).
- `plan.md` §3 (`tokens-per-image.csv`), §7 (budget).
- 01 D6 tap JSONL, D8 sheet (schema v2 image columns, Q3), D10 run ids; 01.3.1-T3 `finish_run.py`.
- 05.5.2: renders `L1` (vi) and `L2` (en), 5-min ghost stories, landscape.
- 03.1.1-T1 step 5: M0 global template strings (`dark-folklore-ink` vi, `foggy-cinematic` en).

## Design

### Run plan (6 renders)

| Run | Lang | Aspect | Length | Quality | Source |
|---|---|---|---|---|---|
| L1 | vi | landscape | 5 min | `auto` (no injection) | 05.5.2 |
| L2 | en | landscape | 5 min | `auto` | 05.5.2 |
| L3 | en | landscape | 3 min | chosen (tap `TAP_IMAGE_QUALITY`) | this task |
| P1 | vi | portrait | 1 min | `auto` | this task |
| P2 | en | portrait | 1 min | `auto` | this task |
| P3 | vi | portrait | 1 min | chosen (tap) | this task |

Expected images (D3): 30 + 30 + 18 + 6 + 6 + 6 = **96**. Stories for L3/P1–P3 come from the 02.1.3-T0 harness output (Short tier for P-runs), keywords as a JSON list.

### Submit body fields for every run (D4 subset valid on the Mac)

`video_source = "openai_image"`, `video_terms` = JSON array (plain keywords; the style is in MPT's global template, D13), `video_clip_duration = 10`, `video_concat_mode = "sequential"`, `match_materials_to_script = true`, `video_count = 1`, `video_aspect` per run. 05.5.2 must use the same fields for L1/L2 (hand-over note to 05; CR-5).

### Token report `trial/tools/image_tokens_report.py` (stdlib)

- Input: run ids; reads `trial/runs/<id>/openai_usage.jsonl`, keeps `endpoint = /images/generations` and `http_status = 200`.
- Groups by `(aspect from run id, response.quality or "unknown")`; computes `n`, `n_no_usage`, mean/p50/p95/max of `usage.output_tokens`, mean of `usage.input_tokens_details.text_tokens`, mean cost with O8 rates.
- Writes `trial/images/tokens-per-image.csv` (plan §3) with `source = render`, and appends the contact-sheet rows (`source = contact`) from `contact-sheet-results.csv` so one file holds both.
- Also prints `images_per_audio_minute` per run = `image_count ÷ (tts audio seconds ÷ 60)` from the sheet row.

## Steps

1. Confirm 05.5.2 used the D4 fields for L1/L2 (check `$NTS_HOME/runs/<id>/submit-response.json` / the submit body saved by 05); if not, re-run one of them with the fields (budget allows one).
2. Render L3, P1, P2, P3 with the standard 01 run procedure (`start_run.sh` → submit → `finish_run.py`); for L3/P3 restart the tap with `TAP_IMAGE_QUALITY=<chosen>` and restart it without the variable afterwards.
3. Run `image_tokens_report.py L1 L2 L3 P1 P2 P3`.
4. Check per run: `image_failed_count = 0`, `moderation_blocked_count = 0`, `image_http_429_count` noted; a run with any skipped image is **invalid** for token averages (01 F24 rule) but its tokens still count in the p95 (billed images).
5. Write `trial/images/REPORT.md` §Trial renders: run table (id, aspect, quality echoed, images, tokens mean/p95, cost/image, image-stage minutes from `stages.json`, 429s), and the images-per-minute check.
6. Hand the numbers to 03.3.1-T2.

## Tests

- `image_tokens_report.py --self-test` on a fixture JSONL (3 aspects/qualities, one line without `usage`, one 429): p95, `n_no_usage`, 429 excluded.
- Manual: watch each render once (owner, ≈ 15 min total).

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| A run skips images (429 at Tier 1) | mark the run invalid for averages, keep its billed tokens; if 2 runs skip, raise pacing to 03.4.3 before M1 (G7) |
| `response.quality` absent | group as `unknown`; the decision then relies on the contact-sheet rows for that quality |
| Images per minute ≠ 6 | `video_clip_duration` was not applied → stop, fix the submit body (05 hand-over), re-run |
| Budget pressure | drop P3 first (portrait chosen-quality data then comes from the contact sheet only) |
| Rollback | none; measurements only |
