## Goal

The two open change requests from plan 01 are closed with evidence: the image quality the platform pays for (CR-3 → D9 value) and how production image usage is metered (CR-4 → D8, relay), and the measured tokens per image become the seed of `price_versions.rates.image` and the new DECISIONS §4 numbers.

## Design

### Decision record (`trial/images/REPORT.md` §Decision and DECISIONS §4)

| Item | Content |
|---|---|
| Quality | chosen `q` per the 03.3.2-T1 rule, same value for both aspects unless the rule gives different ones (then per aspect: `ImageRelay:QualityByAspect`) |
| Why not `auto` | echoed quality/tokens of the `auto` cells and renders; variance (p95 ÷ mean) |
| CR-3 | option (b) relay injection — confirmed, or (a) accept `auto` if `auto` echoed = `q` in ≥ 95 % of calls and costs the same [DECISION rule] |
| CR-4 | relay metering (D5/D8) — confirmed; fallback = estimates (`estimated = true`) only when a report is missing |
| Tokens per image | table `aspect × quality` mean and p95 (render rows preferred when `n ≥ 6`, else contact rows) |
| Cost per video | per tier: `NeededImages(tier max) × mean cost/image` and `MaxTerms × p95 cost/image` (D3) → handed to 12.1.1 and to the 02 D1 daily/monthly caps |
| Tier 1 impact | image-stage minutes per 5-min video; the tier-increase request (README §10 O4) |

### Config seed (`appsettings.json`, block `OpenAi:Pricing:Image`, 02 T55)

```json
"OpenAi": { "Pricing": { "Image": { "gpt-image-2": {   // 01 DEC-11 (was gpt-image-2.5-flare, superseded; values priced on flare → re-measure)
  "text_in_per_1m": 5, "image_in_per_1m": 8, "image_out_per_1m": 30,
  "tokens_per_image":     { "landscape:medium": 0, "portrait:medium": 0, "landscape:high": 0, "portrait:high": 0, "landscape:low": 0, "portrait:low": 0 },
  "tokens_per_image_p95": { "landscape:medium": 0, "portrait:medium": 0, "landscape:high": 0, "portrait:high": 0, "landscape:low": 0, "portrait:low": 0 }
} } } }
```

`0` values are replaced with the measured numbers (rounded up to the next 10). 02.2.4-T1 writes a new `price_versions` row when the config hash changes (02 D14), so the numbers become active without code changes (CR-4).
- ✅ Resolved 2026-09-28 (02 CR-27): the DEC-9 relay bills `gpt-image-2` flat **184 VND/image** ≈ $0.0072 (fx 25,641 VND/USD, SBV 2026-09-25; `trial/prices.json` `unit: per_image`), so the cost-per-video row = `NeededImages(tier max) / MaxTerms` × 184 VND ÷ fx — Short 6 → 1,104 VND ≈ $0.04, Standard 48 → 8,832 VND ≈ $0.34, Long 90 → 16,560 VND ≈ $0.65, and one Standard video/day ≈ $0.34 stays far under the 02 D1 $3/day cap. The superseded 5/8/30 token rates remain only as the measurement reference for `tokens_per_image`; responses-mode `usage` reports no image tokens, so the `tokens_per_image` cells may stay estimates until the relay reports image usage.

### Other values set here

- `ImageRelay:Quality` (node) and `Images:Quality` (backend estimator) = chosen `q`.
- `Images:PlaceholderTokensPerImage` stays 6,000 but is no longer used once the cells exist.

## Steps

1. Apply the 03.3.2-T1 rule to the ratings; write the table and the chosen quality.
2. Fill the tokens tables from `tokens-per-image.csv`.
3. Compute cost per video per tier (Short 1 min portrait, Standard 8 min, Long 15 min) with D3 counts.
4. Write the decision into `trial/images/REPORT.md` §Decision.
5. Update DECISIONS §4 (CR-12): replace "medium ~$0.013 (assumption)" with the measured table, the chosen quality and the date; §5.2 note on `moderation_blocked` handling via the relay.
6. Update 03 high-level §10: CR-3 and CR-4 closed, pointing to this README D8/D9 (CR-10).
7. Put the measured values in `appsettings.json` `OpenAi:Pricing:Image` (or hand them to 02.2.4-T1 if it is not built yet).
8. Send the cost-per-tier table to the 12.1.1 owner and re-check the 02 D1 caps ($3/day, $40/month) against one Standard video/day.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| No quality passes the rule | choose `high`, note it, and ask the owner whether a template change should be tried first |
| Portrait data too thin (n < 6 per cell) | use the landscape ratio × portrait contact rows, marked ⚠️ in DECISIONS |
| One Standard video per day exceeds the $3/day cap | escalate to the owner with the number; do not change the cap in code |
| Rollback | a new config version (new `price_versions` row); DECISIONS gets a dated correction |
