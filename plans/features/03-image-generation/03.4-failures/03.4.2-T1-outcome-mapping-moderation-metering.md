## Goal

When a render ends, the backend turns the adapter's `images.v1` report into one clear outcome: the video is kept and reviewed (with the blocked or missing scenes listed), or the render fails with `image_moderated` / `image_generation_failed` — never auto-retrying a moderated render — while every billed image is metered, every blocked scene is recorded, and a funds problem pauses new work.

## Design

### Classifier (`Domain/Rendering/Images/ImageOutcomeClassifier`)

```csharp
public static ImageOutcome Classify(MptTerminal terminal, ImageReportV1? r, IReadOnlyList<string> slotSegments, ImagePolicy p)
{
    if (r is null)
        return terminal == MptTerminal.Succeeded
            ? ImageOutcome.OkUnknown()                                    // no report: ingest, estimate usage, alert
            : ImageOutcome.Failed("image_generation_failed", "upstream_error", retryable: true);   // row 8

    var skipped   = r.Failed.Select(f => new SkippedScene(f.Slot, SegmentAt(slotSegments, f.Slot), ReasonOf(f))).ToList();
    var moderated = skipped.Count(s => s.Reason == "moderated");
    var funds     = r.Failed.Any(f => p.FundsCodes.Contains(f.ErrorCode ?? ""));
    var share     = (double)skipped.Count / Math.Max(1, r.Needed ?? r.Planned);

    if (terminal == MptTerminal.FailedMaterials)
        return funds     ? ImageOutcome.Failed("image_generation_failed", "provider_funds_exhausted", false, skipped, moderated, fundsExhausted: true) // row 7
             : moderated > 0 ? ImageOutcome.Failed("image_moderated", null, false, skipped, moderated)                                              // row 6
             : ImageOutcome.Failed("image_generation_failed", "upstream_error", true, skipped, 0);                                                   // row 8
    if (skipped.Count == 0) return ImageOutcome.Ok();                                                                                               // row 1
    if (share <= p.MaxSkippedShare) return ImageOutcome.OkWithSkips(skipped, moderated);                                                            // rows 2, 3
    return moderated == skipped.Count
        ? ImageOutcome.Failed("image_moderated", null, false, skipped, moderated)                                                                    // row 4
        : ImageOutcome.Failed("image_generation_failed", "images_incomplete", true, skipped, moderated);                                            // row 5
}
```

- `ReasonOf`: `moderation_blocked` → `moderated`; 429 `rate_limit_exceeded` / `relay_rate_limited` → `rate_limited`; `relay_*` → `relay_rejected`; timeouts (status 0/504) → `timeout`; else `upstream_error`.
- `FundsCodes` = `insufficient_quota`, `billing_hard_limit_reached`, `project_spend_limit_exceeded`, `credit_balance_exhausted` (config `Images:FundsCodes`).
- `Needed` comes from `render_jobs.params.image_plan.needed` (the relay sends `null`, 03.4.3-T1); the job fills it into the report before classifying.
- A "succeeded" task with `funds` failures but share ≤ 10 % stays OK with skips **and** raises the funds signal (the next render would fail anyway).
- `MptTerminal` other than succeeded/failed-materials (e.g. failed at `audio`, `subtitle`) → not an image outcome; the classifier is not called and 05/09 map the code.

### Job integration (code in 09.6.3 files)

`PollRenderJob`, on a terminal adapter state, in this order:
1. Parse `images` → `ImageReportV1` (lenient: unknown fields ignored; schema mismatch → treated as `null` + metric `image_report_invalid_total`).
2. `RecordImageUsage.ExecuteAsync(renderJob, report, ct)` — own transaction (02 D14); skipped if image rows already exist for the render job (idempotent on job retries).
3. `Classify(...)`.
4. `Failed` → `renderJob.Fail(code, detail)`; `episode.RenderFailed()` (→ `story_approved`); `ImageModerationRecorder` when `moderated > 0`; `ICreditLedger.RefundAsync`; schedule a retry only when `Retryable` and `attempt < 2` (the retry reuses the same `image_plan`; 09.6.3 creates the new attempt); `FundsExhausted` → publish `ProviderFundsExhausted { Source = "image" }` to the 12.8.3 P-subset handler.
5. `Ok*` → store the outcome in `renderJob.params.image_outcome` (kind + skipped list) and enqueue ingest as today.
6. Adapter cleanup is requested only after steps 2–5 committed (F15).

`IngestRenderOutputJob` writes `quality_report.images` (plan §3.3) from the stored outcome, then `ImageModerationRecorder` for rows 2 (moderated slots of a kept video), then `RenderSucceeded`.

### Moderation events (`ImageModerationRecorder`)

- One row per moderated slot: `user_id`, `episode_id`, `source = openai_image`, `stage = render_image`, `categories = []`, `excerpt` = the **keyword** of that slot, read from the approved story version through `IStoryRenderInputProvider` (never the full prompt; ≤ 300 chars).
- Idempotent per render job: the recorder writes nothing when `moderation_events` rows with `source = openai_image`, `stage = render_image` already exist for this episode created after the render job's `started_at` (no new column; one render job per episode is active at a time, 09.6.1).

### Usage rows (`RecordImageUsage`)

- One `usage_records` row per `usage[]` entry (D8 field list), `cost_usd` from `ImageCostCalculator.Compute(entry, rates)`; `estimated = true` rows use `tokens_per_image[aspect:quality]`.
- Report missing on a succeeded task → the real count is unknown → write **one** row with `estimated = true`, `image_count = image_plan.needed`, cost = needed × estimated per-image cost, and raise `image_report_missing_total`.

### Read model and UI (hand-over)

- `GET /episodes/{id}` → `latestRenderJob.images { needed, succeeded, skipped: [ { segment, reason } ] }` (09.5.3 read model).
- 10.5: video review shows the skipped banner and highlights segments; `image_moderated` failure shows the "Edit scenes" flow (P10); copy keys in `plan.md` §6 (CR-7).
- 02.8.2-T1 check 7 reads `quality_report.images.skipped.length == 0` and `moderated_count == 0` (CR-3); `VideoGateInput.ImageModerationEvents` = `moderated_count`.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Report says a slot outside `slot_segments` | segment `unknown`, logged as `image_report_slot_out_of_range`; outcome still computed |
| Story version changed between render and poll (reopen) | keywords for excerpts are read from the render job's `story_version_id`, not the current version |
| Usage transaction fails | job retries the step (idempotent); classification waits until usage is written (F15) |
| Owner rejects D7 rows 4–5 (README §10 O2) | set `Images:MaxSkippedShare = 1.0` → every succeeded task goes to review with its skipped list |
| Rollback | revert the job wiring; classifier/calculator are pure and harmless |
