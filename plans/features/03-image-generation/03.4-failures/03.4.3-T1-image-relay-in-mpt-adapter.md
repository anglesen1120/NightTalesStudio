## Goal

Every OpenAI image call MPT makes on a render node goes through a loopback relay inside `mpt-adapter` that holds the image key, sets the chosen quality, paces calls to the account's rate limit, refuses prompts that were not planned by the backend, and records each call's outcome and token usage against the render task — so the adapter status can return a complete `images.v1` report.

## Design

### Placement

- Same process as `mpt-adapter`, a second listener bound to `127.0.0.1:${ImageRelay:Port}` (8091). The adapter's Worker-facing listener is unchanged.
- The adapter is .NET 10 (11 D3, owner O1; 11 CR-5). The relay lives in `src/NightTales.MptAdapter/ImageRelay/`, reads `ImageRelay__*` and `NODE_OPENAI_IMAGE_KEY` from `/etc/nts/adapter.env`, and is bound to the server core through `IImagePlanSink` (`Register` at submit, `Release` at cancel/delete, `BuildReport` for terminal statuses; 11 D5). The adapter may not reference Domain (11 D3), so the negative clause comes from config with the startup hash check against `seed/style-templates.md` (03.1.1-T2 fallback path). `ImageReportV1` is created here in `src/NightTales.RenderNode.Contract/` and consumed by 03.4.2-T1 (11 CR-5).

### Components

| Component | Responsibility |
|---|---|
| `ImagePlanRegistry` | `Register(taskId, ImagePlan{ MaxImages, PromptSha256[] })` at submit; `TryClaim(sha256) → (taskId, slot) \| unknown \| capReached`; `Release(taskId)` at cleanup; persisted to `${DataDir}/plans/<taskId>.json` so a restart can rebuild it |
| `PromptGuard` | the D5 request checks, in order: size ≤ 64 KB → JSON → `model` → `n = 1` → ends with `ImageRelay:NegativeClause` → hash claim → cap |
| `TokenBucket` | `ImagesPerMinute` tokens per 60 s, burst 1; `WaitAsync(min(MaxWaitSeconds, deadline left))`; injected clock for tests |
| `UpstreamClient` | `HttpClient` to `https://api.openai.com/v1/images/generations`, connect 10 s, read `min(UpstreamReadSeconds 180, deadline left)`, no automatic redirects, `Authorization: Bearer <NODE_OPENAI_IMAGE_KEY>`, retries only 429 `rate_limit_exceeded` ≤ 2 honouring `Retry-After` ≤ 30 s, each retry takes a bucket token and runs only if `Retry-After + 60 s` fits the request deadline (`RequestDeadlineSeconds` 270, README D5, DoR DR-1) |
| `CallLog` | appends one D5 line per final outcome (and per relay rejection) to `${DataDir}/<taskId>.jsonl`, fsync |
| `ImageReportBuilder` | builds `images.v1` from the plan + JSONL + MPT's terminal state when the adapter status is asked for a terminal task |

### Request flow

```text
MPT POST /v1/images/generations
  → PromptGuard (reject → 400 {"error":{"code":"relay_…"}} + CallLog line, no upstream call)
  → TokenBucket.WaitAsync (timeout → 429 relay_rate_limited + CallLog)
  → body: set quality (if configured), moderation; forward
  → UpstreamClient (429 rate → retry; quota codes/5xx/4xx → pass through)
  → CallLog { slot, http_status, error_code, quality_sent, quality_echoed, size, usage (numeric leaves), request_id (x-request-id), latency_ms, relay_wait_ms, attempt }
  → return upstream status + body unchanged to MPT
```

- A claimed slot stays claimed even when the call fails (MPT does not retry a 400; a 429/5xx retry by MPT sends the **same** prompt → same hash → `TryClaim` returns the same slot while it is marked `in_flight/failed_retryable`, not a new slot). Rule: a slot is `open → claimed → done | failed_final`; a retryable failure (429/5xx) sets it back to `claimed_retryable`, and the next identical hash reuses it.
- Cap: `calls` counts upstream attempts that reached OpenAI (reported only); the cap check is `distinct slots claimed ≤ MaxImages`, so MPT's own 3 attempts on one slot never hit the cap (README D5, DoR DR-2).

### Status extension (adapter → Worker)

`GET /tasks/{id}` (11.3.5 route) adds for terminal tasks:

```json
{ "state": "complete", "percent": 100,
  "images": { "schema": "images.v1", "planned": 34, "needed": null, "called": 31, "succeeded": 30,
              "failed": [ { "slot": 7, "http_status": 400, "error_code": "moderation_blocked" } ],
              "unattempted": 3, "quality_sent": "medium", "quality_echoed": ["medium"],
              "size": "1536x1024", "model": "gpt-image-2.5-flare",
              "usage": [ { "slot": 0, "request_id": "req_…", "text_tokens": 92, "image_tokens": 0, "output_tokens": 1056, "estimated": false } ],
              "relay_rejections": { "relay_prompt_unstyled": 0, "relay_unknown_prompt": 0, "relay_image_cap_reached": 0, "relay_rate_limited": 0 } } }
```

- `needed` is filled by the backend (it knows the plan); the relay returns `null`.
- `failed` = slots whose final state is `failed_final` (last attempt's status/code). `unattempted` = `planned − distinct claimed slots`.
- Non-terminal tasks: `images` is omitted (keeps polling cheap).

### Node config (CR-5, CR-6)

- MPT `config.toml`: D4 image block (`openai_image_base_url = "http://127.0.0.1:8091/v1"`, `openai_image_api_keys = []`, `openai_image_prompt_template = ""`, `twelvelabs_rerank_terms = false`); 11.3.1 guards reject any other value.
- Adapter settings: `ImageRelay:{Enabled, Port, Model, Quality, Moderation, ImagesPerMinute, MaxWaitSeconds, UpstreamReadSeconds, RequestDeadlineSeconds, DataDir, NegativeClause}`; secret `NODE_OPENAI_IMAGE_KEY` (node secret store, 11.3.2).
- Startup checks: key present; `NegativeClause` sha256 equals the value published in `seed/style-templates.md` (03.1.1-T2); port free and loopback; `DataDir` writable. Any failure → adapter health `image_relay.ok = false` and the Worker stops dispatching to the node (11.3.3 uses health).

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Relay down / port closed | MPT gets connection refused → connect error is retried by MPT (I5), then skipped; health `image_relay.ok = false` stops new dispatch; running task ends with many failures → D7 rows 5/8 |
| Key revoked (401) | passed through; MPT does not retry with one key (I4); every image fails → task fails `materials`; report codes `invalid_api_key` → D7 row 8 + alert |
| Plan not registered (adapter restart lost it and no file) | all calls `relay_unknown_prompt` → task fails; the Worker's retry resubmits with a fresh plan |
| Disk full for JSONL | the call is still forwarded (never lose a paid image); `CallLog` failure metric; report marks `usage` entries `estimated = true` for missing lines |
| Upstream response without `usage` | usage entry with `estimated = true`, tokens `null` (D8 estimates) |
| `ImageRelay:Enabled = false` | adapter starts without the listener; node config must then point MPT at OpenAI (emergency profile); status omits `images` |
| Rollback | disable the flag + emergency MPT profile; no data migration |
