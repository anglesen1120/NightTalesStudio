## Design

**D6 mapping (`errors.py`).** One table `CODES: dict[str, int]` with every D6 code and its HTTP status; `ProxyError` refuses an unknown code (`assert code in CODES`). `map_upstream_status(up)` before commit:

| Upstream | Proxy |
|---|---|
| 400 | 400 `upstream_rejected`, message = `up.error_message()[:200]` or `"upstream rejected request"` |
| 401 / 403 | 502 `upstream_auth_failed` |
| 429 | not mapped here → admission retry (below) |
| 5xx, other ≠ 200 | 502 `upstream_unavailable` |
| `httpx.ConnectError`, `ConnectTimeout`, `ReadTimeout` before headers | 502 `upstream_unavailable` |

**Admission (`SpeechPipeline.admit` + upstream open loop).**

```python
budget_end = t0 + admission_wait_s
try:
    await wait_for(slots.acquire(), timeout=max(0, budget_end - now()))
except TimeoutError:
    raise ProxyError("proxy_busy", 429, "proxy busy", retry_after=5)
while True:
    up = await stack.enter_async_context(vieneu.speech_stream(body))
    if up.status != 429: break
    await stack.aclose_last()                       # close that upstream response
    wait = min(parse_retry_after(up.headers) or 2, 5, budget_end - now())
    if wait <= 0: raise ProxyError("upstream_busy", 429, "upstream busy", retry_after=5)
    await asyncio.sleep(wait)
log.admission_wait_ms = ms(now() - t0) at first 200
```

`parse_retry_after`: integer seconds only (VieNeu sends `1` or `2`, V3); HTTP-date or garbage → `None`. Budget math: worst case admission = 60 s; first-audio deadline 90 s from arrival leaves ≥ 30 s for VieNeu's first PCM; MPT's idle timeout 120 s is never reached before the commit (D4). A late slot release (F17, from SPIKE row d) is absorbed as long as it is < 60 s. The response always carries `Retry-After: 5` for both 429 codes (MPT ignores it, M2; kept for other clients).

**D3 limits.** Step 1: `read_body(request, limit=262_144)` iterates `request.stream()`, counts bytes, and raises 413 `body_too_large` as soon as the count exceeds the limit (stops reading; a declared `Content-Length` > limit is rejected before reading). Step 3: `len(input) > 20_000` → 413 `input_too_long` (code points, V1). Order is D3's: body size → JSON → input → format → voice.

**D2 allow-list.** `app.py` registers only the three D2 routes. A pure ASGI middleware `RouteGate` runs first: path not in the D2 set → 404 `route_not_found`; known path, other method → 405 `method_not_allowed` with `Allow: POST` or `Allow: GET`; both log one D7 line with `route: "other"` (404) or the route name (405) and never reach any handler or `VieneuClient`. FastAPI's own 404/405/422 handlers are replaced by `error_body` responses. Auth runs in the route before `read_body`, so a 401 never reads the body.

## Failure handling and edge cases

- Upstream 429 without `Retry-After` → 2 s wait.
- 429 on the last retry with 0.3 s budget left → sleep 0.3 s, retry once more, then `upstream_busy`.
- Semaphore granted late with no budget left for upstream → attempt once (budget checks only between retries).
- Client sends `Transfer-Encoding: chunked` without `Content-Length` → counting limit still applies.
- `Expect: 100-continue` from other clients → uvicorn handles it; 401 is still returned without reading.
- Wire tests flaky on slow CI → all timeouts derive from one `WIRE_SCALE` factor (default 1.0).
