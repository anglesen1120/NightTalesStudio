## Goal

`GET /health` (no auth, loopback only) reports the exact `proxy-health.v1` schema — VieNeu reachability, ffmpeg/libmp3lame presence, catalog validity against the live upstream voice set, and proxy self-info — with 200 only when every check passes, else 503 with the specific reason codes, so the node adapter (11.3.5, hand-over) can gate dispatch on it.

- README **D9** (`catalog_voice_missing` = catalog ids not canonical upstream names, aliases excluded).
- README **D13** (env var table: `CATALOG_CHECK_INTERVAL_S`; `FFMPEG_PATH` "resolved on PATH at startup").
- README **F10** (backend never talks to the proxy directly; health reaches it only via the adapter, CR-8/CR-12), **F22** (loopback everywhere), **F12** (ffmpeg PCM decode check is speech-path, not health; health only probes the encoder's presence).

- `04.1.3-T1`'s `UpstreamVoiceCache` (`app.state.voice_cache`) and `VieneuClient.voices()` — reused here, not re-implemented.

## Design

### `upstream.py` addition

```python
async def health(self) -> dict:
    """VieNeu GET /health (no auth) → { status, backend, max_streams, active, waiting, sample_rate }
    (V7). Timeout fixed at 2 s (D8). Raises ProxyError(upstream_unavailable) on connect/timeout/
    non-200/invalid JSON; the caller (health.py) turns that into reason `vieneu_unreachable`."""
```

Separate from `voices()`'s timeout: health must fail fast (2 s) so `/health` itself stays responsive under load, independent of `UPSTREAM_CONNECT_TIMEOUT_S`.

### Startup ffmpeg probe (added to `__main__.py`, 04.1.2-T1's file — this task specifies the exact probe and populates `app.state.ffmpeg_probe`)

```python
@dataclass(frozen=True)
class FfmpegProbe:
    ok: bool
    version: str | None
    libmp3lame: bool
```

Run once at process start: `ffmpeg_path -hide_banner -encoders` (subprocess, 5 s timeout). `libmp3lame = "libmp3lame" in stdout`. Version parsed from `ffmpeg_path -version` first line (`ffmpeg version X.Y.Z ...` → `X.Y.Z`; parse failure → `version = None`, does not fail the probe on its own). `ok` = binary found (`Settings.ffmpeg_path` not `None`) **and** return code 0; `libmp3lame` is judged separately. A missing binary → `ok=False, version=None, libmp3lame=False`. The probe never crashes startup (README D8/D13: a missing ffmpeg is not a config error) — the process still starts and reports `ffmpeg_missing`/`libmp3lame_missing` via `/health`.

### `health.py`

```python
async def build_health(state) -> tuple[int, dict]:
    reasons: list[str] = []
    vieneu_ok = True
    try:
        v = await state.vieneu.health()            # VieNeu /health needs no key (V7): it can only prove reachability
    except ProxyError:
        vieneu_ok = False
        reasons.append("vieneu_unreachable")
        v = None
    else:
        if v.get("status") != "ok":
            vieneu_ok = False
            reasons.append("vieneu_unhealthy")

    probe = state.ffmpeg_probe
    if not probe.ok:
        reasons.append("ffmpeg_missing")
    elif not probe.libmp3lame:
        reasons.append("libmp3lame_missing")

    cache = state.voice_cache
    upstream_names = await cache.names()           # cached set; the background loop refreshes it every CATALOG_CHECK_INTERVAL_S
    # The LATEST refresh decides, even if older names are still cached (README D8): a stale cache never masks a failure.
    if cache.last_error == "upstream_auth_failed":
        reasons.append("vieneu_auth_failed")       # the only proof of VIENEU_API_KEY
    elif cache.last_error is not None and "vieneu_unreachable" not in reasons:
        reasons.append("vieneu_unreachable")
    missing = sorted(vid for vid in state.catalog.ids if vid not in upstream_names) if cache.ever_succeeded else []
    if missing:
        reasons.append("catalog_voice_missing")   # active or not (README D8)
    catalog_ok = cache.ever_succeeded and cache.last_error is None and not missing

    body = {
        "schema": "proxy-health.v1", "status": "ok" if not reasons else "error", "reasons": reasons,
        "vieneu": {"ok": vieneu_ok, **({"backend": v["backend"], "max_streams": v["max_streams"],
                    "active": v["active"], "waiting": v["waiting"]} if v else {})},
        "ffmpeg": {"ok": probe.ok, "version": probe.version, "libmp3lame": probe.libmp3lame},
        "catalog": {"ok": catalog_ok, "revision": state.catalog.revision, "voices": len(state.catalog.ids),
                    "missing_upstream": missing},
        "proxy": {"version": PROXY_VERSION, "started_at": state.started_at.isoformat(), "in_flight": state.in_flight},
    }
    return (200 if not reasons else 503), body
```

(D8 fixes the body `status` to `"ok"` (HTTP 200, `reasons: []`) or `"error"` (HTTP 503, ≥ 1 reason); consumers still key off the HTTP status and `reasons`.)

### Route

```python
@router.get("/health")
async def health(request: Request) -> JSONResponse:
    status_code, body = await build_health(request.app.state)
    return JSONResponse(body, status_code=status_code)
```

No `require_bearer` call (D2: "none (loopback only …)").

## Tests

- `test_health_ok_returns_200_and_empty_reasons` — every subsystem healthy → 200, `reasons: []`, `status: "ok"`.
- `test_health_vieneu_unreachable_reason_and_503` — `VieneuClient.health` raises `ProxyError(upstream_unavailable)` → `"vieneu_unreachable"` in `reasons`, 503.
- `test_health_voice_refresh_401_reports_vieneu_auth_failed` — fake VieNeu answers `GET /v1/voices` with 401 (its `/health` stays 200) → `"vieneu_auth_failed"`, 503.
- `test_health_auth_failure_after_good_refresh_not_masked_by_stale_cache` — first refresh 200 (names cached), key then rejected (401) on the next refresh → `"vieneu_auth_failed"`, 503, although `names()` still returns the old set.
- `test_health_vieneu_unhealthy_reason` — VieNeu responds 200 with `status != "ok"` → `"vieneu_unhealthy"`.
- `test_health_ffmpeg_missing_reason` — `FfmpegProbe(ok=False, ...)` injected → `"ffmpeg_missing"`.
- `test_health_libmp3lame_missing_reason` — `FfmpegProbe(ok=True, libmp3lame=False)` → `"libmp3lame_missing"`.
- `test_health_voice_list_never_fetched_reports_unreachable_not_catalog_invalid` — every refresh fails with a connect error → `"vieneu_unreachable"`, no `"catalog_voice_missing"`, no `"catalog_invalid"`, `catalog.ok = false`.
- `test_health_catalog_voice_missing_reason_lists_ids` — one active catalog id absent from `UpstreamVoiceCache.names()` → `"catalog_voice_missing"` in `reasons`, that id present in `catalog.missing_upstream`.
- `test_health_catalog_voice_missing_ignores_aliases` — an alias-only upstream match does not clear `missing_upstream` for the real id (reuses `04.1.3-T1`'s cache semantics).
- `test_health_multiple_reasons_combine` — VieNeu down **and** ffmpeg missing → both codes present, still one 503.
- `test_health_body_schema_field_exact` — `schema == "proxy-health.v1"` literal string.
- `test_health_never_requires_bearer` — request without `Authorization` header still returns a body (not 401).
- `test_health_response_never_contains_api_keys_or_input_text` — serialized body grepped for the test's `PROXY_API_KEY`/`VIENEU_API_KEY` fixture values → 0 matches.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| VieNeu times out (not a connect failure) at 2 s | `vieneu_unreachable` (timeout is a form of unreachable in this contract; D8 does not distinguish "slow" from "down") |
| ffmpeg probe itself hangs | 5 s subprocess timeout kills it; treated as `ok=False` |
| `UpstreamVoiceCache` never had a successful refresh (cold-start race, see 04.1.3-T1) | `vieneu_auth_failed` or `vieneu_unreachable` by `last_error`; `catalog_voice_missing` is not evaluated until one refresh has succeeded; `catalog.ok = false`. `catalog_invalid` is never a health reason (an invalid file stops the process at startup, README D8/D9) |
| Health called before `app.state.ffmpeg_probe` exists (should not happen post-04.1.2-T1 wiring) | Not handled defensively here — an `AttributeError` would be a startup-ordering bug in `__main__.py`, out of this task's scope to guard against |
| `state.in_flight` under concurrent speech requests | Read-only snapshot of a counter maintained by the speech pipeline (04.1.2-T1); no lock needed for a read |

## Notes

- The adapter (11.3.5-T1, hand-over CR-12) embeds this body **unchanged** under the key `tts_proxy` in its own health response, and gates dispatch on `tts_proxy.status == "ok"`. This task does not implement the adapter; it only guarantees the byte-for-byte contract the adapter can rely on.
- `status` is `"ok"` or `"error"` (README D8, TL ruling T5). Consumers (`11.3.5-T1`, `smoke-proxy.sh`) check the HTTP status and `reasons: []`, not the literal string.
