## Goal

Write `worker-node/proxy/FALLBACK-voxcpm.md`: a decision-ready note on switching MPT from the `kokoro` slot (this plan's design, VieNeu PCM streaming) to the `voxcpm` slot (WAV + SSE), so that if VieNeu becomes blocked or unacceptable, the Tech Lead has the triggers, the exact proxy changes, and the consequences written down in advance — without actually building or enabling it.

## Inputs

- `DECISIONS.md` §5.3 (locked, not reopened): the two-option comparison table — option A (`kokoro`, chosen) vs option B (`voxcpm`, fallback); the MPT `voxcpm` facts (`response_format: "wav"`, `stream: true`, requires an `api_key`, parses SSE `speech.audio.delta`/`speech.audio.done`, one voice per config via `voice_id`).
- README **CR-15** ("§5.3: the proxy streams PCM → MP3 (not '~30 lines, wav → mp3'); §8 item 6: ffmpeg decodes the unknown-length WAV (X1; re-confirmed at the pin by 04.1.1-T1), pydub (option B) still unverified").
- README **F12** (raw PCM chosen over WAV specifically to avoid trusting ffmpeg's stderr-noisy WAV decode; relevant because option B's own proxy would face the same WAV question from the MPT side, but from VieNeu's SSE audio deltas instead).

## Design

### Structure of `FALLBACK-voxcpm.md`

1. **When to switch** — concrete triggers, not vague language:
   - VieNeu upstream is unmaintained/abandoned for > 2 weeks with an open security issue (owner-level trigger, not automatic).
   - The chosen VieNeu presets fail the English-narration bar (README O2 outcome "(c) reopen the locked TTS decision") — DECISIONS §3 is locked and only the owner can reopen it.
   - A VieNeu-specific defect blocks M0/M1 with no workaround inside this plan's design (e.g. streaming PCM output is removed upstream, or the pinned commit's decode breaks and no other pin fixes it).
   - Explicitly **not** a trigger: normal 429/5xx operational noise (handled by D5 admission), or a single bad voice rating (handled by 04.2.1-T1's per-voice re-audition).
2. **MPT `[voxcpm]` facts** (verbatim from DECISIONS §5.3, cited, not re-derived): body `{"response_format":"wav","stream":true}`, `api_key` required, SSE frames `speech.audio.delta` (base64 audio chunks) / `speech.audio.done`, **one voice per config** (`voice_id`, `voice.py:324-337`).
3. **What the proxy would change** (relative to this plan's `kokoro`-slot design, by D-name so a future implementer can diff against the current contract):
   - `D2` route stays `/v1/audio/speech`, but the **upstream** request body gains `stream_format: "sse"` and drops the `stream_format: "audio"` / `stream: true` distinction MPT would send is irrelevant — the proxy still speaks to VieNeu, not to MPT's expectations of voxcpm's own upstream; the mapping is: MPT → proxy (unchanged `mp3` request, M1) → proxy → VieNeu with `stream_format: "sse"` instead of `D3`'s `"audio"`.
   - Response parsing changes from raw PCM framing (`D4`) to SSE event parsing: accumulate base64 chunks from `speech.audio.delta` events, decode, feed to the same ffmpeg pipeline (`D4`'s ffmpeg command is reusable unchanged, since it still receives raw PCM after base64-decoding each delta) until `speech.audio.done`.
   - `D9`'s catalog `voices.v1` schema is unaffected (it already carries one canonical id per voice); what changes is `D10` — MPT's `[voxcpm]` block would need `voice_id` set to **one** voice, because voxcpm exposes only one voice per config, unlike `kokoro`'s catalog-driven multi-voice list.
   - `D6` error codes are reusable as-is; only the upstream-parsing internals (`upstream.py`'s `speech_stream`) change, not the public contract to MPT.
4. **Consequences**:
   - One voice per config (§5.3) means the node would need **one MPT config per language** (a `[voxcpm]` block can select only one `voice_id`), unlike the current single `[kokoro]` block with a catalog-driven list — this multiplies node MPT config profiles by language count and complicates `01.2.2-T2`/`05.1.1`/`11.3.1` templates.
   - The voice catalog (`D9`) would lose its "one config, many voices" simplicity: switching narrators would require redeploying MPT config, not just adding a catalog row.
   - `04.2-voice-catalog`'s preview/audition work (D11, D12) stays reusable (voices are still VieNeu presets either way) — only the MPT-side selection mechanism changes.
5. **What stays unverified**:
   - pydub's ability to decode a WAV of *unknown declared length* streamed via SSE deltas (the WAV header question is separate from the SSE parsing question) — DECISIONS §8 item 6 marks this ⚠️; `04.1.1-T1` only confirmed **ffmpeg** decodes VieNeu's unknown-length WAV header (X1), not pydub, and not through an SSE-reassembled stream.
   - Whether VieNeu's SSE mode (`stream_format: "sse"`) has the same admission/429/abort semantics as its PCM/audio mode (V3–V5) — not measured by `04.1.1-T1`, which tested `"audio"` mode only.
   - Whether MPT's voxcpm client-side timeout/retry behaviour (parallel to `M2`/`M3` for kokoro) matches the 120 s-idle assumption this plan relies on for `kokoro` — not read from MPT source for this note (out of scope; would need its own spike if option B is ever pursued).

|---|---|
