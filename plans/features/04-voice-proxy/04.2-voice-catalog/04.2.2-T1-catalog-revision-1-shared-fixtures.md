## Design

### Revision 1 content

```json
{ "schema": "voices.v1", "revision": 1, "vieneuCommit": "<VIENEU_COMMIT from worker-node/pins.env>",
  "voices": [
    { "id": "<preset name, NFC>", "slug": "<slugify(id)>", "displayName": "<id>", "language": "vi|en",
      "gender": "<snapshot gender>", "tags": ["<style>", "<region, vi only>", "<rater tag>…"], "active": true,
      "previewStorageKey": null } ] }
```

- `id` = canonical preset name copied from the snapshot's `data[].id` (never an alias, never retyped — copy bytes).
- `slug` computed by `nts_vieneu_proxy.catalog.slugify` (not by hand); `displayName` = `id` (O4); `gender` from the snapshot.
- `previewStorageKey` = `null` for every entry until 04.2.3-T1 verifies the upload.
- Revision 0's entries that 04.2.1-T1 did not select stay in revision 1 with `active: false` [DECISION]: the seeder never deletes rows and deactivation is file-driven (09.2.5-T1 edge case "renames a voice id"), so Development databases and any dev series using them keep working (F14). They still pass every D9 rule; D9's "≥ 1 active voice per language" counts only active entries.
- Order: by language (`vi` first), then selection rank, inactive entries last. Written UTF-8, NFC, 2-space indent, `ensure_ascii=False`, trailing newline.

### MPT voice-name hazard check (M5)

For every revision-1 id, with MPT's own interpreter and code (`$NTS_HOME/src/mpt/.venv/bin/python`, cwd = the MPT checkout): `parse_voice_name("kokoro:"+id) == "kokoro:"+id`, `not is_azure_v2_voice("kokoro:"+id)` (it returns `""`, not `False`, for a name without the `-V2` suffix — assert falsiness), and `("kokoro:"+id).split(":", 1)[1].strip() == id` (the kokoro-branch split, M5 [INFERENCE: re-implemented from the L692 description; replace with a call if the branch is a function]; the M5 functions live in MPT `app/services/voice.py`, L371 `parse_voice_name` / L379 `is_azure_v2_voice`). This proves the D9 rules on the real MPT code, not only on our copy of them. (04 T16)

## Steps

1. Build revision 1 from the 04.2.1-T1 selection with a one-off snippet (not tracked) that copies ids from the snapshot and calls `slugify`; write `seed/voices.v1.json`.
2. Validate: `uv run --project worker-node/proxy python -c 'from nts_vieneu_proxy.catalog import load_catalog as l;c=l("seed/voices.v1.json");print(c.revision,len(c.voices))'` → `1 <n>`, exit 0.
3. Every id is canonical upstream: `python3 -c 'import json;s={v["id"] for v in json.load(open("worker-node/vieneu/voices.snapshot.json"))["data"]};c=json.load(open("seed/voices.v1.json"));m=[v["id"] for v in c["voices"] if v["id"] not in s];print(m);raise SystemExit(bool(m))'` → `[]`.
4. M5 hazard check (above) → one `PASS m5 <id>` line per id.
5. Write the fixtures, `expected.json` and `seed/fixtures/voices/README.md`; run the proxy's catalog tests over them: `uv run --project worker-node/proxy pytest -q worker-node/proxy/tests/test_catalog_fixtures.py`.
6. Restart the proxy on revision 1: stop the foreground `worker-node/bin/start-proxy.sh`, start it again (04.1.5-T1); `worker-node/bin/smoke-proxy.sh` → all `PASS`.
7. Health: `curl -s http://127.0.0.1:8001/health | python3 -c 'import json,sys;c=json.load(sys.stdin)["catalog"];print(c);raise SystemExit(not(c["ok"] and c["revision"]==1 and c["missing_upstream"]==[]))'` → exit 0.
8. One speech call per id through the proxy: `for id in …; do curl -sS -o /dev/null -w '%{http_code} %{content_type}\n' --max-time 120 -H @<(printf 'Authorization: Bearer %s\n' "$(secret nts.proxy.api_key)") -H 'Content-Type: application/json' --data "$(python3 -c 'import json,sys;print(json.dumps({"input":"Đêm nay trăng sáng.","voice":sys.argv[1]}))' "$id")" http://127.0.0.1:8001/v1/audio/speech; done` → `200 audio/mpeg` each.
9. Tell 01.2.2-T6 which id is the first active `en` voice (CR-6) and 05.5.2 the vi/en set.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| A selected id fails a D9 rule (would only happen with a hand-typed id) | fix the copy from the snapshot; never rename a preset |
| M5 check fails for a real preset name | drop the voice from the selection (take the next-ranked one from 04.2.1-T1) and note it in its README |
| Health shows `missing_upstream` non-empty | the running VieNeu is not at `vieneuCommit`; re-pin or re-snapshot (01.2.1-T3) before continuing |
| O2 answered (b) "postpone en" | Not blocked (README §10 T6): the best-rated en voice stays active; in P only the owner creates series, so "postpone en" means no en series are created |
| 04.1.5-T1 not yet done | steps 1–5 still run; steps 6–8 wait (soft dependency, plan.md §10) |
