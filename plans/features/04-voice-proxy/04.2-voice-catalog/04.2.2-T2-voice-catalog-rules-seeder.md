## Goal

The backend loads the **same** `seed/voices.v1.json` the proxy loads, in every environment, rejects it with exactly the D9 codes the proxy uses (proven on the shared fixtures), and upserts the `voices` table including `preview_storage_key` — so series validation (09.4.1-T1) and `GET /voices` (09.4.2-T1) see the curated catalog, not placeholders (CR-9).

## Design

### Domain (`src/NightTales.Domain/Catalog/`, file-scoped namespace `NightTales.Domain.Catalog`)

```csharp
public sealed record VoiceCatalogEntry(
    string Id, string Slug, string DisplayName, string Language, string Gender,
    IReadOnlyList<string> Tags, bool Active, string? PreviewStorageKey);

public sealed record VoiceCatalogFile(
    string Schema, int Revision, string VieneuCommit, IReadOnlyList<VoiceCatalogEntry> Voices);

public static class VoiceCatalogRules
{
    public const string VoiceIdInvalid = "voice_id_invalid";
    public const string VoiceSlugMismatch = "voice_slug_mismatch";
    public const string CatalogInvalid = "catalog_invalid";
    public static readonly IReadOnlySet<string> Tags = /* D9 closed list, 11 values */;

    public static ErrorOr<Success> ValidateEntry(VoiceCatalogEntry e);
    public static ErrorOr<Success> ValidateFile(VoiceCatalogFile f);
    public static string Slugify(string id);
}
```

- Raw strings in the records (not enums) so an invalid `language`/`gender` is reported as a rule failure, not a parse exception. Errors are `Error.Validation(code, description, metadata: { ["voiceId"] = id or null })`; the description never contains more than the id.
- `ValidateEntry` order (first failure wins): id → slug → displayName → language → gender → tags → previewStorageKey.
  - **id** (`voice_id_invalid`): `id.IsNormalized(NormalizationForm.FormC)`; `id == id.Trim()`; 1–64 **Runes** (not UTF-16 units; Python counts code points); first Rune is a Unicode letter or number (`Rune.GetUnicodeCategory` ∈ L\*, N\*), the rest letter/number or one of `_ . -` and space; no `-Female`, `-Male`, `:` (ordinal); not `EndsWith("-V2", Ordinal)`. The pattern is implemented explicitly, **not** with .NET `\w` — .NET's `\w` includes `Mn`/`Pc` and excludes `No`, Python's `re` `\w` does the opposite (README D9 regex; Python semantics are normative, plan.md §10).
  - **slug** (`voice_slug_mismatch`): `e.Slug == Slugify(e.Id)`.
  - Others (`catalog_invalid`): displayName 1–40 chars after trim; language ∈ {`vi`,`en`}; gender ∈ {`female`,`male`,`neutral`}; tags ⊆ `Tags`, 0–4, distinct; previewStorageKey null or `^voice-previews/<slug>\.v[1-9][0-9]*\.mp3$` with the entry's own slug.
- `ValidateFile` order: `schema == "voices.v1"` → `revision ≥ 0` → `vieneuCommit` matches `^[0-9a-f]{40}$` → each entry (`ValidateEntry`, file order) → ids unique (ordinal) → slugs unique → when `revision ≥ 1`, ≥ 1 active entry per language. File-level errors carry `voiceId = null`; a duplicate reports the **later** entry's id.
- `Slugify` (D9): `id.Normalize(FormD)` → drop `UnicodeCategory.NonSpacingMark` → `đ/Đ → d` → `ToLowerInvariant()` → runs of `[^a-z0-9]` → `-` → trim `-`. `"Hải Đăng" → "hai-dang"`.
- CR-10 hand-over: 09's `VoiceId` value object calls `VoiceCatalogRules` for its id check (one implementation).

### Infrastructure

- `Infrastructure/Persistence/Seeding/VoiceCatalogFileReader.cs`: `public static class VoiceCatalogFileReader { public static ErrorOr<VoiceCatalogFile> Parse(ReadOnlySpan<byte> utf8Json); }` — `System.Text.Json` (`JsonDocument`, camelCase, no reflection-based options), malformed JSON or a file-level missing/wrongly typed/unknown property → `catalog_invalid`, `voiceId = null`; an entry-level missing/wrongly typed/unknown property → `catalog_invalid` with that entry's `id` (README D9, T8). Checks follow the D9 check order (T14).
- `VoiceSeeder` (changed): `sealed class VoiceSeeder(IAppDbContext db, IClock clock, IOptions<SeedOptions> options, IHostEnvironment env) : ISeeder`.
  1. Read `Seed:VoiceCatalogFile` (default `seed/voices.v1.json`, resolved against the content root; missing file → Development: warning + skip, as 09.2.5-T1; elsewhere: fail).
  2. `Parse` → `ValidateFile`; `revision == 0 && !env.IsDevelopment()` → fail `catalog_invalid` ("revision 0 is Development-only").
  3. Any failure → `SeedReport` failed with message `seed_voice_invalid:<id>:<code>` (`<id>` = `-` when `voiceId` is null) and **no** row written.
  4. Upsert by `id` in one `SaveChangesAsync(ct)`: insert via `Voice.Create(id, displayName, language, gender, tags, active, previewStorageKey)`, update `display_name`, `language`, `gender`, `tags`, `active`, `preview_storage_key` (CR-9); rows absent from the file untouched (09.2.5-T1); `slug`/`schema`/`vieneuCommit` are not stored.
- `SeedOptions` gains `VoiceCatalogFile`; `appsettings.json` `"Seed": { "VoiceCatalogFile": "seed/voices.v1.json", … }`.
- `seed/catalog.dev.json`: the `voices` block is removed (CR-9); `CatalogFile` keeps whatever else it holds (⚠️ if nothing remains, 09.2.5 owner removes file and setting).
- Container/node images copy `seed/voices.v1.json` (same file as the proxy bundle, CR-12).

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| File invalid in Development at startup | `SeedHostedService` logs the failed report, startup continues (09.2.5-T1); `voices` keeps its previous rows |
| File invalid on `nts-seed` elsewhere | exit 1, nothing written |
| Voice language changed between revisions while series use it | upsert applies; 09.4.1-T1 keeps existing series (P6); owner catalog migration (F08) |
| C# and Python disagree on a fixture | fix the side that differs from D9; never edit `expected.json` to match code |
| Preview key present but object missing | not checked here (04.2.3-T1 writes keys only after HEAD 200) |
