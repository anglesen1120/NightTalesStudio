## Goal

Every active catalog voice has one static, loudness-matched ≈ 10 s MP3 preview produced by the real proxy pipeline, tracked in a manifest; at M1 each preview is uploaded under an immutable versioned key and only then written into the catalog as `previewStorageKey`, so `GET /voices` returns a working `previewUrl` and nobody spends credits to hear a voice.

- Static; no per-user generation.

## Design

### Texts

`preview.vi.txt` ≈ 28 syllables, `preview.en.txt` ≈ 25 words (≈ 10 s at ≈ 170 syllables/min / ≈ 150 wpm [INFERENCE]; use the 01.2.1-T4 rates). UTF-8 NFC, one sentence, no trailing newline issues (the tool strips one final `\n` before hashing and sending). `text_sha256` = sha256 of the exact UTF-8 bytes sent.

### Tool `worker-node/proxy/tools/make_previews.py`

Runs in the proxy venv so it can import `nts_vieneu_proxy.catalog.load_catalog` (otherwise stdlib only): `UV_PROJECT_ENVIRONMENT="$NTS_HOME/src/proxy-venv" uv run --frozen --project worker-node/proxy python worker-node/proxy/tools/make_previews.py --generate|--upload [options]`. Exit 0 ok · 1 a voice failed · 2 usage/config. Key from env `PROXY_API_KEY` (never argv, never logged).

`--generate [--catalog seed/voices.v1.json] [--out "$NTS_HOME/runs/voice-previews"] [--bump <id>…]`:
1. Load the catalog; take **active** entries [DECISION: pickers only show active voices].
2. Version per voice: manifest row with the same `id` and `text_sha256` and no `--bump` → keep `n`, skip generation if the local file's sha256 matches; otherwise `n = previous n + 1` (first time `n = 1`). `--bump <id>` covers "changed voice" (e.g. a new `vieneuCommit`).
3. POST `http://127.0.0.1:8001/v1/audio/speech` `{ "input": <text>, "voice": <id> }` (MP3 by default, D3) → `<out>/raw/<slug>.mp3`; status must be 200 and `Content-Type: audio/mpeg`.
4. Encode: `ffmpeg -hide_banner -loglevel error -i <out>/raw/<slug>.mp3 -af loudnorm=I=-16:TP=-1.5:LRA=11 -ac 1 -ar 48000 -c:a libmp3lame -b:a 128k -y <out>/<slug>.v<n>.mp3` (argv list, no shell; `FFMPEG_PATH` honoured).
5. Checks: `ffprobe -v error -show_entries format=duration -of csv=p=0` ≤ 12.0 s; size ≤ 200,000 bytes [DECISION: 200 KB = 200,000]; measured integrated loudness (second pass `-af loudnorm=print_format=json -f null -`, `input_i`) within −16 ± 1.5 LUFS [DECISION].
6. Write the manifest row; `catalog_revision` = the catalog `revision` read in step 1.

Manifest `worker-node/proxy/previews.manifest.json`: JSON array sorted by `slug`, one row per voice (the latest version), keys exactly:

```json
[ { "id": "Thiện Minh", "slug": "thien-minh", "key": "voice-previews/thien-minh.v1.mp3",
    "sha256": "<64 hex>", "bytes": 162816, "duration_s": 9.84, "text_sha256": "<64 hex>", "catalog_revision": 1 } ]
```

`--upload --env <env>… [--catalog seed/voices.v1.json]` (M1, after 11.4.1):
1. For each manifest row whose `key` ≠ the catalog entry's `previewStorageKey`, for **each** listed env bucket `nt-public-<env>`:
   - HEAD the key: 404 → PUT; 200 with the same length → skip; 200 with a different length → exit 1 `refusing to overwrite <key>` (never overwrite, D12).
   - PUT with `Content-Type: audio/mpeg`, `Cache-Control: public, max-age=31536000, immutable`, body = the local file (sha256 re-checked against the manifest first).
   - HEAD again → 200 and `Content-Length == bytes` (D12), and `Content-Type: audio/mpeg`.
2. Only when every env passed for that key: set the entry's `previewStorageKey = key`.
3. If any entry changed: `revision += 1` (once per run), write the catalog (same formatting as 04.2.2-T1), then `load_catalog` must succeed; else exit 1 and restore the previous file.
- Storage access goes through two functions, `put_object(bucket, key, path, content_type, cache_control)` and `head_object(bucket, key) -> (status, length, content_type)`, implemented with the S3-compatible CLI 11.4.1 names ⚠️ (not fixed; the contract above is). Credentials via that CLI's environment/profile, never argv. The public URL check `curl -sI <11.4.1 public base>/<key>` → 200 is an acceptance step, not tool logic.
- One catalog file serves every environment (D9), so a key is written only after it exists in **all** env buckets named in the run [DECISION; plan.md §10].

### Versioning rule

`v<n>`: n starts at 1, increments on a new preview text (`text_sha256` changes) or a changed voice (`--bump`); an existing key is never re-uploaded with different bytes. Old versions stay in the bucket (cache safety); cleanup is not in P.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Proxy not running / 401 | exit 2 before any voice (`/health` probe + one authenticated call first) |
| Proxy 4xx/5xx for one voice | that voice fails, others continue; exit 1; manifest keeps the previous row |
| Preview > 12 s or > 200,000 bytes | file deleted, voice failed; shorten the text (new `text_sha256` → n + 1) |
| Loudness outside tolerance | voice failed (loudnorm single-pass drift); re-run, else note in the manifest commit |
| Upload fails mid-run | keys already verified in every env are written, others stay null; re-run is idempotent (HEAD skip) |
| Bucket already holds different bytes under the key | exit 1, never overwrite; bump that voice |
| 11.4.1 not ready at M0 | generation only; catalog keys stay `null`; picker shows no play button (CR-11) |
