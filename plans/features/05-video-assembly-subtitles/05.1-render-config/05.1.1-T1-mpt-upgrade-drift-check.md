# 05.1.1-T1 — MPT upgrade drift check: config, `VideoParams`, routes

| Story | Size | Area | Depends on | Blocks | Phase / flag |
|---|---|---|---|---|---|
| 05.1.1 | S (0.5) | Worker | 01.2.2-T1 (pinned `config.example.pinned.toml`), 05.4.1-T1 (S1 snapshots `worker-node/contract/mpt-videoparams.pinned.json`, `mpt-routes.pinned.json`) | 05-M0 gate (the node deploy runs the diff as a text hand-over, no edge; 11 CR-4) | P · M0 · none |

## Goal

One stdlib tool, `worker-node/bin/mpt-upgrade-diff.py`, that compares a **candidate** MPT checkout against the three pinned baselines and answers one question before an `MPT_COMMIT` bump: did anything D2, D3 or D4 depends on change? It fails closed (exit 1) on a change to a config key the node/Mac profiles use, to a `VideoParams` field, or to a route the adapter uses, and stays quiet (exit 0 + advisory lines) on everything else. The task also writes down the upgrade procedure, because a green diff is only step 3 of six.

## Inputs

- README **D1** (ownership), **D2** (node config rows), **D3** (submit fields), **D4** (MPT-side route usage), **C1**, **C5**, **C7**, **C20**, **C22**, **F09**, **F10**, **F12**, **F22**, **P1**, **CR-7**.
- `worker-node/mpt/config.example.pinned.toml` (01.2.2-T1; default `--baseline-config`) ⚠️ filename — see Notes.
- `worker-node/contract/mpt-videoparams.pinned.json`, `worker-node/contract/mpt-routes.pinned.json` (05.4.1-T1 S1; D1 gives this task ownership of both).
- A candidate worktree with its own venv: `$NTS_HOME/src/mpt-candidate` at the proposed `MPT_COMMIT`, `uv sync` already run there (so `<candidate>/.venv/bin/python` exists).
- `worker-node/pins.env` (`MPT_COMMIT`, 01 D2) — read for the report only, never written; `uv` on PATH; `UV_PROJECT_ENVIRONMENT` under `$NTS_HOME` for any `uv run --project` in the runbook (D14).

## Design

**File.** `worker-node/bin/mpt-upgrade-diff.py`, Python 3.12 stdlib only (`tomllib`, `json`, `subprocess`, `hashlib`, `argparse`, `tempfile`, `pathlib`, `re`); no network. Run as `uv run --no-project --python 3.12 python worker-node/bin/mpt-upgrade-diff.py …` (01 D9).

**CLI (exact).**

```
mpt-upgrade-diff.py --candidate DIR
                    [--baseline-config worker-node/mpt/config.example.pinned.toml]
                    [--baseline-params worker-node/contract/mpt-videoparams.pinned.json]
                    [--baseline-routes worker-node/contract/mpt-routes.pinned.json]
                    [--json]
                    [--self-test]
```

Exit codes (01 D9): `0` no blocking change · `1` at least one blocking change · `2` usage or environment (missing `--candidate`, missing/unreadable baseline, missing `<candidate>/.venv/bin/python`, unparsable candidate file). `--self-test` runs the synthetic cases and ignores the other arguments.

**Diff (a) — config keys/sections/defaults.** Parse both TOML files with `tomllib` and flatten to dotted keys (`app.api_key`, `whisper.model_size`, …); a key that exists only as a comment in the baseline counts as absent, so a present candidate key is an **addition**. Three sets:

| Set | Content | Severity |
|---|---|---|
| `used` | every D2 node row + every key 01.2.2-T2's Mac template sets: `log_level`, `listen_host`, `listen_port`, `app.api_key`, `video_source`, `pexels_api_keys`, `pixabay_api_keys`, `openai_image_base_url`, `openai_image_api_keys`, `openai_image_model`, `openai_image_size`, `openai_image_prompt_template`, `material_directory`, `endpoint`, `twelvelabs_rerank_terms`, `llm_provider`, `openai_api_key`, `openai_base_url`, `subtitle_provider`, `enable_redis`, `max_concurrent_tasks`, `max_queued_tasks`, `video_codec`, `upload_post_enabled`, `upload_post_auto_upload`, `upload_post_api_key`, `whisper.model_size`, `whisper.device`, `whisper.compute_type`, `whisper.initial_prompt`, `kokoro.base_url`, `kokoro.api_key`, `kokoro.model_id`, `kokoro.voices` | addition / removal / default change → **BLOCKING** |
| `other` | any other key in either file | advisory line |
| `missing` | a `used` key **present in the baseline** and absent from the candidate. Keys that are only comments in both files (`video_codec` L440, `whisper.initial_prompt` L511 at the snapshot, C20) are compared as comment lines instead: the commented form disappearing is advisory (T5) | **BLOCKING** (the profile would no longer render) |

Types are compared too (D2): `max_queued_tasks` stays an integer `0`; `pexels_api_keys`, `pixabay_api_keys`, `openai_image_api_keys`, `kokoro.voices` stay arrays; `upload_post_enabled`, `upload_post_auto_upload`, `twelvelabs_rerank_terms`, `enable_redis` stay booleans.

**Diff (b) — `VideoParams` JSON schema.** Run the candidate's **own** interpreter:

```bash
"$CAND/.venv/bin/python" -c 'import json; from app.models.schema import VideoParams; print(json.dumps(VideoParams.model_json_schema(), sort_keys=True))'
```

Flatten to `field → {type, default, enum}` (walk `properties`; resolve `$ref` through `$defs`; `anyOf` becomes the sorted type list, e.g. `bool|str` for `text_background_color`, C22). Against the pinned snapshot:

- a D3 field whose **name**, **type** or **enum** changed → **BLOCKING**;
- a D3 field **absent** from the candidate → **BLOCKING** (C5: unknown fields are ignored, so an absence degrades silently — F10);
- a field D3 does not send, added or changed → advisory;
- a `default` change on a D3 field → advisory, because D3 always sends an explicit value ("fixed values"); the report prints which rule applied.
- a change to a D3 field's `required` membership, constraint bounds (`minimum`, `maximum`, `exclusiveMinimum`, `exclusiveMaximum`, `minLength`, `maxLength`, `pattern`, `minItems`, `maxItems`) or nested `items`/`$defs` shape → **BLOCKING**; the same change on another field → advisory; any field that becomes `required` → **BLOCKING**; a `$ref` cycle or more than 10 000 schema nodes → exit 2 (T72).

**Diff (c) — routes.**

```bash
"$CAND/.venv/bin/python" -c 'import json, app.asgi as a; print(json.dumps({p: sorted(m.lower() for m in d) for p, d in a.app.openapi()["paths"].items()}, sort_keys=True))'
```

Compare the `path → sorted methods` map with the pinned snapshot. **BLOCKING:** any change to `POST /api/v1/videos`, `GET /api/v1/tasks/{task_id}`, `DELETE /api/v1/tasks/{task_id}`, `GET /api/v1/download/{file_path}`, `GET /ping` (D4's MPT-side usage; `/ping` is the liveness probe). **Advisory:** `GET /api/v1/tasks`, `POST /api/v1/subtitle`, `POST /api/v1/audio`, `GET|POST /api/v1/musics`, `GET|POST /api/v1/video_materials`, `GET /api/v1/stream/{file_path}`, the three LLM routes, and the presence of `/docs`, `/redoc`, `/openapi.json` (F12: the node binds `127.0.0.1`, so exposure is not the concern). The `verify_token` dependency (C1) is checked structurally per **(method, path)** on the four D4 MPT-side pairs (`POST /api/v1/videos`, `GET` and `DELETE /api/v1/tasks/{task_id}`, `GET /api/v1/download/{file_path}`): its disappearance on any pair is **BLOCKING**; `GET /ping` is info only (T72).

**Diff (d) — progress constants (warn only).** `re.findall(r"\bprogress=(\d+)", …)` over the candidate `app/services/task.py` compared with the literal set `{5, 10, 20, 30, 40, 50, 100}` (C7), **plus** the computed step: `re.search(r"_progress\s*\+=\s*50\s*/\s*params\.video_count\s*/\s*2", …)` must still match twice (it yields 75 for `video_count = 1`; L965, L1023 at the snapshot). The unanchored `_progress = 50` initialiser is not counted (T6). A change is a **warning**, never blocking: D4's `stage` mapping degrades (F09) but the wire contract does not break. The report prints old → new with line numbers.

**Report.** Human text: one `## config`, `## params`, `## routes`, `## progress` block, each line `BLOCKING|advisory|info  <key>  <baseline> -> <candidate>`, then `BLOCKING: <n> change(s)` or `OK: no blocking change`. `--json`: `{"schema":"mpt-upgrade-diff.report.v1","candidate":"<dir>","mpt_commit":"<sha or null>","blocking":[{"kind":"config|params|routes","key":"…","baseline":"…","candidate":"…"}],"advisory":[…],"warnings":[…],"baselines":{"config":"<sha256>","params":"<sha256>","routes":"<sha256>"},"ok":false}`. Values are key names, types and route paths — a D2 secret key appears as `<changed>` / `<set>` / `<empty>`, never its value.

**Upgrade procedure** (into the tool's `--help` epilogue and 01.3.3-T1's CARRY-OVER):

1. Bump `MPT_COMMIT` in `worker-node/pins.env` in its **own** commit (01 D2).
2. `git -C "$NTS_HOME/src/mpt" fetch && git -C "$NTS_HOME/src/mpt" worktree add "$NTS_HOME/src/mpt-candidate" "$MPT_COMMIT"`, then `cd "$NTS_HOME/src/mpt-candidate" && uv sync`.
3. `mpt-upgrade-diff.py --candidate "$NTS_HOME/src/mpt-candidate"` → **exit 0 required** before anything else.
4. Re-run the 05.4.1-T1 scenario subset **S0, S3, S5, S12** (pin check, route/OpenAPI inventory, validation, restart mid-task) against the candidate; record in `worker-node/contract/mpt-api.md`.
5. Refresh the three pinned snapshots **in the same commit as the bump** and re-run the diff — exit 0 against the refreshed baselines.
6. A confirmed BLOCKING change is escalated to the TL, not patched here: D2/D3/D4, `MptSubmitFields`, the D14 fixtures (05.4.1-T2), the adapter (11.3.5-T1) and mock-mpt (11.1.2-T1) move together. If the change is unacceptable, keep the old `MPT_COMMIT` and revert the bump commit.

## Steps

0. Confirm the baselines exist and hash them; read `MPT_COMMIT` from `pins.env`; require `<candidate>/.venv/bin/python` (else exit 2 with the exact `uv sync` hint). If the candidate has git metadata, HEAD must equal `MPT_COMMIT`, else exit 2; with no git metadata, record `"mpt_commit": null` plus a warning ⚠️ (the 05 README's snapshot has no git metadata either). A dirty worktree (tracked modifications or untracked files) is a warning plus `"dirty": true` and never fails, since the pin checkout is dirty by design (T73).
1. `flatten_toml()` + diff (a), with the `used` set as a module-level tuple so `--self-test` can assert on it.
2. `extract(cand)`: **one** subprocess (`params+routes`), list argv, `text=True`, `stdin` closed, its own session and a throwaway `HOME`; a 90 s whole-run deadline (child ≤ 60 s, git ≤ 10 s); stdout capped at 16 MiB; exactly one sentinel line, or exit 2. Child stderr goes to a 0600 log under `$NTS_HOME/logs/`, never into the report; the check restores the candidate's `config.toml`, `resource/` and `storage/` to their pre-run state (T74).
3. `flatten_schema()` + the diff (b) rules.
4. Diff (c) including the `verify_token` structural check.
5. Diff (d), then the human and `--json` reports.
6. `--self-test` (see Tests).
7. Run against the pin: `--candidate "$NTS_HOME/src/mpt"` with the pinned baselines must exit 0; record the run in the hand-over note.

## Outputs

- `worker-node/bin/mpt-upgrade-diff.py` (tracked, executable).
- The three baselines stay where D1 puts them; this task consumes them (the snapshots are 05.4.1-T1 S1).
- A `mpt-upgrade-diff.report.v1` JSON object for CI/ops, the human report for the runbook, and the step list above in `--help` (referenced by 01.3.3-T1's CARRY-OVER).

## Acceptance checks

- [ ] `uv run --no-project --python 3.12 python worker-node/bin/mpt-upgrade-diff.py --candidate "$NTS_HOME/src/mpt" --json` exits 0 with `"ok": true` and `"blocking": []`.
- [ ] `… --self-test` exits 0 and prints one line per synthetic case (`<case>: <exit> expected <exit> OK`).
- [ ] Removing `max_queued_tasks` from a copy of the pinned config and passing it as `--baseline-config` exits 1 with a `config` entry naming `max_queued_tasks`.
- [ ] A synthetic routes JSON with `GET /api/v1/download/{file_path}` → `POST` exits 1; one with `GET /api/v1/stream/{file_path}` changed exits 0 with one advisory.
- [ ] `--candidate /nonexistent` exits 2 with the path/`uv sync` hint; `--baseline-params /nonexistent` exits 2.
- [ ] No secret in the output: with a candidate whose `app.api_key` is non-empty, the printed value is `<changed>`/`<set>`, never the string.
- [ ] `--json` output parses with `uv run --no-project --python 3.12 python -c 'import json,sys; json.load(sys.stdin)'`.

## Tests

`--self-test` writes synthetic pairs into a `tempfile.TemporaryDirectory()` (nothing tracked):

| Case | Expect |
|---|---|
| identical TOML + JSON | 0, `blocking: []` |
| `used` key removed / default changed (`max_queued_tasks 0 → 5`) / becomes the string `"0"` | 1, kind `config` (type change too) |
| non-`used` key changed (`[app] some_new_option`) | 0, one advisory |
| D3 field type changed (`voice_volume: number → string`) / D3 field removed (`subtitle_display_mode`) | 1, kind `params` |
| non-D3 field added | 0, one advisory |
| D4 route method changed (`GET /api/v1/tasks/{task_id}` → `POST`) / D4 route removed (`DELETE …`) / `verify_token` dropped | 1, kind `routes` |
| `/stream` method changed | 0, one advisory |
| progress set changed (`50 → 55`) | 0, one warning |
| missing baseline file | 2 |

No permanent test framework: the tool is stdlib and its self-test is the regression suite (05-M0 gate row "`mpt-upgrade-diff.py` green against the pin").

## Failure handling and edge cases

- Candidate venv missing → exit 2 with `cd <candidate> && uv sync`; never create it silently (a wrong interpreter yields a false schema).
- Candidate import fails (renamed module, broken dependency) → exit 2, and print `params+routes extraction failed (exit N): <exception class>` plus the path of the 0600 stderr log (T74); never treat it as "no change".
- Baseline missing or unparsable (invalid or non-UTF-8 TOML, JSON of the wrong shape) → exit 2 (fail closed), one line, no traceback; never fall back to "no baseline = nothing to compare".
- The candidate's `config.example.toml` is missing, non-UTF-8 or invalid TOML → diff (a) is skipped with a warning, the other two still run, and the overall exit is 2.
- `app/services/task.py` renamed upstream → `progress constants: source not found` as a warning, not blocking.
- A D3 field absent at the candidate **and** absent from the pinned snapshot → BLOCKING; the fix is refreshing the snapshots in the upgrade commit, not relaxing the rule.
- An unresolved `$ref` in the schema → reported as `unresolved: <name>` and BLOCKING (a schema that cannot be read is a schema that cannot be trusted).
- A 60 s subprocess timeout → exit 2 with the command echoed; never compare a partial schema as if complete.
