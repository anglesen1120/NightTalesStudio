# 05.1.1-T2 — Node config profile + guards

## Goal

Give `render-mpt-config.py` a third profile, `node`, that renders MPT's config for a GPU worker from `worker-node/mpt/config.node.template.toml`, with every D2 row enforced as a guard: a mismatch exits 1 and writes nothing. The node profile differs from `mac` in the bind address, the queue depth, the codec, whisper's device/compute type, and the loopback TTS proxy — all of which are load-bearing for F07/F12/F16 and 04 D10.

## Inputs

- README **D2** (the guard table), **D7** (`BeVietnamPro-Bold.ttf`), **D14**, **C2**, **C14**, **C19**, **F07**, **F12**, **F16**, **P1**, **CR-4**, **CR-5**; 01 D5 (`log_level`), 01 CR-9 (no `h264_videotoolbox` on the node), 01 D9 (exit codes), 03 D4/D5, 04 D10.
- `worker-node/bin/render-mpt-config.py` + `worker-node/mpt/config.template.toml` (01.2.2-T2, signed) ✅ — extended, never forked; its atomic write, mode 0600 and secret-free drift diff stay as they are.
- `worker-node/bin/check-fonts.sh` / `worker-node/fonts/FONTS.csv` (05.2.2-T1) — the profile only *points at* the font (`font_name` guard is D6's job); the health check runs `check-fonts.sh` (11.3.1-T1).
- The node environment file written by 11.3.2 (⚠️ path unnamed — open item in `plan.md` §10) or the process environment.

**Renderer extension.** `render-mpt-config.py --profile node [--env-file FILE] --out FILE` renders the template; `--check --profile node [--env-file FILE] FILE` validates an existing file against the same table and writes nothing. Values come from the process environment, or from `--env-file` (KEY=VALUE lines, `0600`, never tracked) when given — the node environment file is 11.3.2's artefact (open item). The out path comes from `--out`; the node's path is ⚠️ fixed by 11.3.1-T1 (the Mac profile's default stays `$NTS_HOME/src/mpt/config.toml`).

**`string.Template` is textual** — that is the one trap in this task. `max_concurrent_tasks = ${NTS_MPT_MAX_CONCURRENT}` must be written **unquoted** in the template so the rendered TOML is an integer, and the raw value must be validated `^[1-8]$` *before* substitution; every other placeholder renders inside double quotes. The rendered file is parsed with `tomllib` before the atomic rename, so a syntax error can never be written.

**Guards, in order** (first failure group reported, then all failing keys): (1) required env keys present and non-empty (`NTS_MPT_API_KEY`, `NTS_PROXY_API_KEY`, `NTS_MPT_MAX_CONCURRENT`, `NTS_MPT_VIDEO_CODEC`, `NTS_WHISPER_DEVICE`, `NTS_WHISPER_COMPUTE`); (2) enumerated value sets (`NTS_MPT_MAX_CONCURRENT` `^[1-8]$`, `NTS_MPT_VIDEO_CODEC ∈ {libx264, h264_nvenc}`, `NTS_WHISPER_DEVICE ∈ {cuda, cpu}`, `NTS_WHISPER_COMPUTE ∈ {float16, int8_float16, int8}`, `NTS_MPT_API_KEY` length ≥ 32); (3) the rendered TOML parses and every D2 row equals its guard value with the right type; (4) `[whisper] initial_prompt` absent; (5) the `/Volumes/` path check inherited from 01.2.2-T2 is unchanged for the `node` profile (the node's config is outside the repo, so the check only applies to `--out` inside the repo). Secret values are never printed: a failing secret key prints `<set>` / `<empty>` / `<too short>`, and the drift diff prints key names and `<changed>` only (01.2.2-T2's SEC rules apply unchanged).

**`spike` profile — cross-reference, not implemented here.** 05.4.1-T1 adds `[kokoro] base_url = "http://127.0.0.1:18004/v1"` (the TTS stub) to the `spike` profile created by 03.4.1-T1; that value is allowed **in `spike` only** and the `node` guard rejects it (D2 requires `:8001`). Do not add it to the node template.

## Steps

1. Write `worker-node/mpt/config.node.template.toml` with every D2 row and the six placeholders; `max_concurrent_tasks` unquoted, `[whisper] initial_prompt` absent (commented text is fine).
2. Extend `render-mpt-config.py` with the `node` profile: a `PROFILES` entry (template path, guard table, out-path default, env keys) and a `check_profile()` that takes rendered TOML + the raw env values. Keep the `mac` and `spike` paths untouched.
3. Add `--check --profile node FILE` and `--env-file FILE`; keep the existing exit codes (`0` ok, `1` guard failure, `2` usage/env) and the 01 D9 conventions.
4. Add the self-test cases (see Tests) to the renderer's existing self-test entry point, or a `--self-test --profile node` branch if 01.2.2-T2 has no self-test (⚠️ check on disk first).
5. Run `--check --profile node` on a rendered file and confirm the integer type of `max_concurrent_tasks` and `max_queued_tasks` via `tomllib`.

## Failure handling and edge cases

- Missing env key → exit 2 when `--env-file` is unreadable, exit 1 when a required key is absent from an otherwise readable environment (usage vs guard, 01 D9); the message names the key, never the value.
- `max_concurrent_tasks` would render as a quoted string (the template was edited to add quotes) → the TOML type guard fails → exit 1; do not silently coerce.
- A guard table row whose key is absent from the rendered file (template edited) → exit 1 with `missing: <key>`; a *new* unknown key in the template is advisory only (it is the renderer's own file).
- `--out` inside `/Volumes/` → the inherited 01.2.2-T2 path check still applies; the node path is outside the repo, so the check does not fire there.
- `--check` on a file rendered by another profile → exit 1 (the guard table is profile-specific); never auto-detect the profile.
- The node has no `whisper` model downloaded → not this task's failure; 11.3.1-T1 provisions it (01.2.3-T1) and the adapter's health reports `mpt_unreachable` (D4).
- `h264_nvenc` on a node without the driver → the codec guard passes (it is a D2 value) and MPT falls back to `libx264` (C14); 11.3.1-T1 verifies the fallback in provisioning, not here.
