## Goal

One place that turns a render request into (a) the non-content `render-params.v1` stored on the job (D11) and (b) the exact `render-submit.v1` body the adapter accepts (D3/D4) — so no other class composes an MPT field, and a field D3 fixes can never be left to a default (F10). Golden tests pin the wire against the D14 fixtures.

**`SubtitlePresetCatalog.Load` validation** (D6, an `ErrorOr` error, never a throw): `schema != "subtitle-presets.v1"`; `revision < 1`; either aspect missing; `fontName != "BeVietnamPro-Bold.ttf"` (D7); `fontSize ∉ [24,160]`; `strokeWidth ∉ [0,10]`; a colour not matching `^#[0-9A-F]{6}$`; `subtitlePosition ∉ {bottom, top, center, two_thirds_bottom, custom}` (C16); `customPosition ∉ [0,100]`; `maxCharsPerLine ≤ 0`; `maxLines ≤ 0`. `maxCharsPerLine`/`maxLines` are **not** MPT fields and never enter `MptSubmitFields` (D6).

**`BuildParams` rules** (D11): `MapperVersion = 1`; `StoryVersionId`, `VoiceId`, `StyleTemplateId`, `StylePromptVersion`, `ClipSeconds` copied from the input (`ClipSeconds = 10`, 03 D3); `Subtitles.Preset = $"{aspect}@{catalog.Revision}"`; `Music` = `MusicParams(choice.TrackId, choice.BgmVolume)` or `null`; `ImagePlan` = the input summary. No I/O, no clock, deterministic.

**`BuildSubmit` mapping** (D3):

| MPT field | Rule |
|---|---|
| `video_subject` | `story.Title`, 1–200 chars (else `render.subject_invalid`) |
| `video_script` | `story.Body` normalised to NFC; `Rune` count ≤ 20,000, else `Error.Validation("render.script_too_long", …)` (04 V1, CR-3) |
| `video_terms` | `plan.Prompts[i].Text` in order; 1–200 strings, each 1–1,000 chars (03 D4) |
| `video_aspect` | `p.Aspect == "landscape"` → `"16:9"`; `"portrait"` → `"9:16"`; anything else → `render.aspect_invalid` (C14) |
| `video_language` | `p.Language` (`"vi"`\|`"en"`) |
| `voice_name` | `"kokoro:" + p.VoiceId` (04 D10) |
| `bgm_type` / `bgm_file` / `bgm_volume` | `p.Music` non-null → `"custom"` / `track!.File` / `p.Music.BgmVolume`; null → `""` / `""` / `0` (D8, F13, C18) |
| `subtitle_enabled` | `p.Subtitles.Enabled` (P: `true`) |
| subtitle fields | `font_name` ← `preset.FontName` (the catalog's `FontName`, D7); `subtitle_position` ← `preset.SubtitlePosition`; `custom_position` ← `preset.CustomPosition`; `font_size`, `stroke_color`, `stroke_width`, `text_fore_color`, `text_background_color`, `rounded_subtitle_background` ← the preset (camelCase → snake_case) |
| fixed literals | `video_fit_mode "cover"`, `video_concat_mode "sequential"`, `video_transition_mode null`, `video_clip_duration 10`, `video_clip_speed 1.0`, `match_materials_to_script true`, `video_count 1`, `video_source "openai_image"`, `video_materials null`, `custom_audio_file null`, `voice_volume 1.0`, `voice_rate 1.0`, `video_music_prompt ""`, `sonilo_bgm_prompt ""`, `subtitle_display_mode "sentence"` (F01), `subtitle_animation "none"`, `paragraph_number 1`, `video_script_prompt ""`, `custom_system_prompt ""` |
| `n_threads` | **never set here** — the adapter injects `ADAPTER_MPT_THREADS` (F22); the property does not exist on `MptSubmitFields` |

`image_plan` = `{ max_images, prompt_sha256 }` copied from `plan` (03 D4); the adapter strips it before MPT (D4). `render_job_id` = the argument. `schema` = `"render-submit.v1"`.

**Canonical serialization** (the golden rule): `JsonSerializerOptions(JsonSerializerDefaults.Web) { WriteIndented = true }` with `\n` newlines and declaration-order properties; the fixtures are pretty-printed the same way with a trailing newline. The test compares bytes, and deserializes each fixture with `JsonUnmappedMemberHandling.Disallow` (D14) so a new or renamed field on either side fails.

**No DB and no HTTP.** 09.6.1-T1 stores `BuildParams` output verbatim in `render_jobs.params` and pre-checks the 20,000-code-point limit (CR-3); 09.6.2-T1 calls `BuildSubmit` per attempt and owns the client, retries and idempotency. This task adds no `DbContext`, no `HttpClient`, no migration.

## Failure handling and edge cases

- `p.Aspect` is neither `landscape` nor `portrait` → `render.aspect_invalid`; never a silent `"16:9"` default.
- `p.Music` is non-null but `track` is null, or `p.Music.TrackId != track.Id` → `ArgumentException` (a programming error, not a user error); no new error code is introduced.
- `p.Music` is null while `track` is non-null → `""`/`""`/`0` wins (the stored params are the record of what was rendered, D11).
- `plan.Prompts` is empty or has > 200 entries → `render.terms_invalid` (D3 requires 1–200); the planner guarantees ≥ 1 (03 D4), so this is a programming error surfaced early.
- A prompt text longer than 1,000 chars → `render.terms_invalid` (D3).
- NFC normalisation can change the rune count (a decomposed sequence collapses); the limit is checked **after** normalisation, and the same normalised text is what MPT receives.
- `seed/subtitle-presets.v1.json` is missing from the embedded resources → `Load` returns an error at startup (fail fast, never a null catalog).
- A fixture whose JSON uses a key the DTO does not have → the golden test fails by design (D14 `Disallow`); fix the DTO or the fixture in 05.4.1-T2, never by adding a lenient option.

- `RenderParamsInput` and `ImagePlanSummary` are [INFERENCE] names: the README fixes the JSON shapes (D11, 03 D4) and the two method signatures, not these two type names. If 03.2.1-T1 already exposes a projection of `RenderImagePlan`, reuse it instead of `ImagePlanSummary`.
- `n_threads` (F22) and `video_codec` (D2) are node-side; the mapper must not learn about them.
- Why the fixture comparison is byte-exact: F10 — a renamed or missing key is silently ignored by MPT (C5), so only a byte comparison catches it before the adapter does.
- The preset values themselves are 05.2.3-T1's (owner O4); this task validates and transports them.
