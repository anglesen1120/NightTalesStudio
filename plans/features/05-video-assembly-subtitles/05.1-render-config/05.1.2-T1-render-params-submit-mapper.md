## Goal

One place that turns a render request into (a) the non-content `render-params.v1` stored on the job (D11) and (b) the exact `render-submit.v1` body the adapter accepts (D3/D4) — so no other class composes an MPT field, and a field D3 fixes can never be left to a default (F10). Golden tests pin the wire against the D14 fixtures.

**`SubtitlePresetCatalog.Load` validation** (D6, an `ErrorOr` error, never a throw): `schema != "subtitle-presets.v1"`; `revision < 1`; either aspect missing; `fontName != "BeVietnamPro-Bold.ttf"` (D7); `fontSize ∉ [24,160]`; `strokeWidth ∉ [0,10]`; a colour not matching `^#[0-9A-F]{6}$`; `subtitlePosition ∉ {bottom, top, center, two_thirds_bottom, custom}` (C16); `customPosition ∉ [0,100]`; `maxCharsPerLine ≤ 0`; `maxLines ≤ 0`. `maxCharsPerLine`/`maxLines` are **not** MPT fields and never enter `MptSubmitFields` (D6).

**`BuildParams` rules** (D11): `MapperVersion = 1`; `StoryVersionId`, `VoiceId`, `StyleTemplateId`, `StylePromptVersion`, `Subtitles.Preset`, `ClipSeconds` copied from the input (`ClipSeconds = 10`, 03 D3; `Preset` = `<aspect>@<revision>` composed by the caller 09.6.1-T1 from `SubtitlePresetCatalog.Revision`, 05 CR-14); `Music` = `MusicParams(choice.TrackId, choice.BgmVolume, input.MusicAttribution)` or `null`; `ImagePlan` = the input summary. **`BuildSubmit` mapping** (D3):

| MPT field | Rule |
|---|---|
| `video_subject` | `story.Title`, 1–200 chars (else `render.subject_invalid`) |
| `video_script` | `story.Body` normalised to NFC; `Rune` count 1–20,000, else `Error.Validation("render.script_too_long", …)` (04 V1, CR-3); an empty script returns the same code — D3's range has no separate one (05 CR-14) |
| `video_terms` | `prompts[i].Text` in order (the `prompts` argument, never a member of `plan`); 1–200 strings, each 1–1,000 chars (03 D4, 05 CR-14) |
| `video_aspect` | `p.Aspect == "landscape"` → `"16:9"`; `"portrait"` → `"9:16"`; anything else → `render.aspect_invalid` (C14) |
| `video_language` | `p.Language` (`"vi"`\|`"en"`) |

| `subtitle_enabled` | `p.Subtitles.Enabled` (P: `true`) |
| subtitle fields | `font_name` ← `preset.FontName` (the catalog's `FontName` on the preset, D7, 05 CR-14); `subtitle_position` ← `preset.SubtitlePosition`; `custom_position` ← `preset.CustomPosition`; `font_size`, `stroke_color`, `stroke_width`, `text_fore_color`, `text_background_color`, `rounded_subtitle_background` ← the preset (camelCase → snake_case) |

| `n_threads` | **never set here** — the adapter injects `ADAPTER_MPT_THREADS` (F22); `MptSubmitFields` has no such member and no such JSON name (05 CR-14) |

`image_plan` = `{ max_images = plan.MaxTerms, prompt_sha256 = prompts[i].Sha256 }` built from the prepared prompts, never copied from `plan` — 03.2's `RenderImagePlan` carries no prompts or hashes (05 CR-14); `prompts.Count != plan.Terms.Count` → `ArgumentException`. The adapter strips `image_plan` before MPT (D4). `render_job_id` = the argument. `schema` = `"render-submit.v1"`.

**Canonical serialization** (the golden rule): `JsonSerializerOptions(JsonSerializerDefaults.Web) { WriteIndented = true }` with `\n` newlines and declaration-order properties; the fixtures are pretty-printed the same way with a trailing newline. The test compares bytes, and deserializes each fixture with `JsonUnmappedMemberHandling.Disallow` (D14) so a new or renamed field on either side fails.

**No DB and no HTTP.** 09.6.1-T1 stores `BuildParams` output verbatim in `render_jobs.params` and pre-checks the 20,000-code-point limit (CR-3); 09.6.2-T1 and 09.6.3-T1 call `BuildPrompts(plan, style)` first and then `BuildSubmit(...)` per attempt (05 CR-14) and own the client, retries and idempotency. This task adds no `DbContext`, no `HttpClient`, no migration.

## Failure handling and edge cases

- `p.Aspect` is neither `landscape` nor `portrait` → `render.aspect_invalid`; never a silent `"16:9"` default.
- An empty `story.Body` (0 runes) → `render.script_too_long`: D3's 1–20,000 rune range has no separate code for it (05 CR-14). 09.6.1-T1 maps that code to `validation_failed` field `script` before the mapper runs.
- `p.Music` is non-null but `track` is null, or `p.Music.TrackId != track.Id` → `ArgumentException` (a programming error, not a user error); no new error code is introduced.
- `p.Music` is null while `track` is non-null → `""`/`""`/`0` wins (the stored params are the record of what was rendered, D11).
- The `prompts` argument (built by `BuildPrompts`) is empty or has > 200 entries → `render.terms_invalid` (D3 requires 1–200); its count must equal `plan.Terms.Count` (05 CR-14); `RenderImagePlan` guarantees ≥ 1 term (03 D4), so this is a programming error surfaced early.
- A prompt text empty or longer than 1,000 chars → `render.terms_invalid` (D3).
- NFC normalisation can change the rune count (a decomposed sequence collapses); the limit is checked **after** normalisation, and the same normalised text is what MPT receives. A body longer than 120,000 UTF-16 units (`6 × 20,000`: NFC merges at most 3 code points into 1, each at most 2 units) cannot normalise to ≤ 20,000 runes, so it is rejected with `render.script_too_long` before normalising, which bounds the allocation (05 CR-14).
- `seed/subtitle-presets.v1.json` is missing from the embedded resources → `Load` returns an error at startup (fail fast, never a null catalog).
- A fixture whose JSON uses a key the DTO does not have → the golden test fails by design (D14 `Disallow`); fix the DTO or the fixture in 05.4.1-T2, never by adding a lenient option.
