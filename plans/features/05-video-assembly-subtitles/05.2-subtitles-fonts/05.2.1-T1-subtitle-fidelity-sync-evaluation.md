# 05.2.1-T1 — Subtitle fidelity and sync evaluation (6 videos) + threshold calibration

| Story | Size | Area | Depends on | Blocks | Phase / flag |
|---|---|---|---|---|---|
| 05.2.1 | M (1.0) | BA | 05.5.2-T1 (trial videos L1/L2), 05.5.1-T1 (`render_check.py`), 05.4.1-T1 (`mpt_client.py`) | 05.5.1-T2 (calibrated thresholds), 05-M0 gate | P · M0 · none |

## Goal

Prove with measurements that the burned-in subtitles of six M0 videos carry exactly the script text and land on the spoken words, then calibrate the SRT heuristics of `render-check.v1` (D9 ✅) against human labels so 05.5.1-T2 can fix the `RenderQuality:*` thresholds (D10 ✅) before M1. Output: `trial/subtitle-eval/results.csv` (6 rows) + `README.md` with the numbers proposed as a TL ruling — this replaces the withdrawn word-error-rate test (F01 ✅).

## Inputs

- Contract `../README.md`: C15, C16, D3, D6, D7, D9 (SRT), D10, D12, D13, X1, X2, F01, F02, F15, F16, F23, F24, O4, O5.
- L1 (`vi`, landscape 5 min) and L2 (`en`, landscape 5 min) task dirs from 05.5.2-T1 in `$NTS_HOME/runs/<run_id>/` with `final-1.mp4`, `subtitle.srt`, `audio.mp3`, `script.json` (downloaded by `mpt_client.py`, T2) and `render-check.json` (C13 ✅).
- `worker-node/checks/render_check.py` + `render-check.v1` (05.5.1-T1) and the D14 fixtures `render-check.v1.{ok,zero-cues,no-subtitles}.json`; `trial/tools/mpt_client.py`, `tts_stub.py`, `image_stub.py` (05.4.1-T1, 03.4.1-T1) with the `spike` MPT profile (stubs on `127.0.0.1:18003` / `18004`, D12 ✅).
- The MPT task log for the whisper language line (C15 ✅, 01.3.1 col 51). Tools are stdlib: `uv run --no-project --python 3.12` (D14 ✅).

## Design

### Six videos

| id | source | lang | aspect | script / fixture | produced by |
|---|---|---|---|---|---|
| `L1-vi-landscape-5m` | 05.5.2-T1 | vi | landscape | trial L1, 5 min | 05.5.2-T1 (F24 ✅) |
| `L2-en-landscape-5m` | 05.5.2-T1 | en | landscape | trial L2, 5 min | 05.5.2-T1; en only if 04 O2 launches en, else 05.5.2-T1's second vi story (`source = substitute`, T14) |
| `E1-vi-portrait` | here | vi | portrait | first ≈ 60–90 s of L1 | `mpt_client.py` + stubs |
| `E2-en-portrait` | here | en (or vi) | portrait | L2 (or L1) | `mpt_client.py` + stubs |
| `E3-vi-landscape-names` | here | vi | landscape | `subtitle-eval-vi-names.txt` (names, diacritics) | `mpt_client.py` + stubs |
| `E4-en-landscape-longclause` | here | en | landscape | one clause > 84 chars (forces a 3-line cue, F15 ✅) | `mpt_client.py` + stubs |

The four short renders use the TTS and image stubs (no spend) and are submitted one at a time (`mpt_client.py` never submits a second task while one runs, D2 ✅).

### Measurements

| # | Measure | Method | Criterion |
|---|---|---|---|
| a | cue-text fidelity | `render-check.v1.subtitles.text_matches_script` (D9 ✅) on all six | `true` on all six; any `false` = bug → record the diff, escalate, never patch the check |
| b | sync | a reviewer labels 20 random cues per video `on_time` (start within ± 0.5 s of the spoken onset), `early`, `late` or `wrong_window` (`subtitle_sample.py --srt … --n 20 --seed <run_id>`) | `on_time_share ≥ 0.95` per video |
| c | heuristics | tabulate `zero_duration`, `coverage_share`, `cps_p95`, `sync_suspect`, `long_cues` per video against the labels of (b) | calibrated parameters proposed (below) |
| d | whisper language | detected language + probability from the MPT log line (C15 ✅) | recorded per video; empty when the line is absent, never guessed |
| e | readability | the native reviewer (vi and en) checks phone and desktop rendering incl. diacritics | `readability_vi` / `readability_en` ≥ 4/5, no clipped line |

### Threshold calibration

`render-check.v1` measures only (D9 ✅); the numbers are proposed here and fixed by 05.5.1-T2 in `RenderQuality:*` (D10 ✅). Starting parameters: `sync_suspect` per cue = `chars ÷ (end − start) > 25` **or** `(end − start) > 12 s` (report `sync_suspect` = count, `render-quality.v1` hint at share > 0.10); `subtitles_present` = `cues ≥ 1` ∧ `zero_duration = 0` ∧ `coverage_share ≥ 0.50`; `long_cues` = cues longer than `maxCharsPerLine × maxLines` of D6 (42×2 / 28×2) and stay an advisory hint in P (O5 ✅).

Method: build the confusion against the labels of (b) for the chosen pair and its ± 20 % neighbours and report precision/recall; with fewer than five positive cues overall, keep the pair as a [target] with the evidence attached.

## Steps

1. `set -euo pipefail`; `export NTS_HOME="${NTS_HOME:-$HOME/.nts}"`; `RUNS="$NTS_HOME/runs/subtitle-eval"`; `mkdir -p "$RUNS" trial/subtitle-eval`. No key is printed (the stub profile needs none, C19 ✅).
2. Write `trial/fixtures/subtitle-eval-vi-names.txt` (60–90 s: names such as `Nguyễn Thị Ánh Tuyết`, `Lý Thường Kiệt`, temple/ghost vocabulary, tone marks on every vowel) and `trial/tools/subtitle_sample.py`:
   `subtitle_sample.py --srt FILE --n 20 --seed <run_id> [--csv FILE]` — parses `HH:MM:SS,mmm --> HH:MM:SS,mmm` (UTF-8), prints `cue_id, start, end, duration, chars, text`, picks `random.Random(seed).sample(range(len(cues)), min(n, len(cues)))` sorted; exit 0 / 1 unreadable SRT / 2 usage.
3. Collect L1/L2 from the 05.5.2-T1 run dirs (verify the five files: `final-1.mp4`, `subtitle.srt`, `audio.mp3`, `script.json`, `render-check.json`); if en was not launched, L2 from 05.5.2-T1 is already the second vi story (T14): use it and set `source = substitute`; E2 (en portrait) then becomes vi as the task table says.
4. Render E1–E4 one at a time: `uv run --no-project --python 3.12 trial/tools/mpt_client.py run --spec "$RUNS/<id>.spec.json" --run-dir "$RUNS/<id>"` (≈ 60–90 s each; the status must reach `succeeded` with a non-null `output.subtitles`, D4/D9 ✅).
5. Check all six: `uv run --no-project --python 3.12 worker-node/checks/render_check.py run --task-dir "$RUNS/<id>" --aspect <landscape|portrait> --subtitles on --out "$RUNS/<id>/render-check.json"` — exit 0 expected; exit 1 = unreadable input (report still written, record it).
6. Label: `subtitle_sample.py --srt "$RUNS/<id>/subtitle.srt" --n 20 --seed "$run_id" --csv "$RUNS/<id>/sample.csv"`, then play the video at those timestamps and record one of the four labels per cue — never filled from the heuristics.
7. Record the whisper language + probability from the MPT log (C15 ✅, 01.3.1 col 51) by fixed line prefix; nothing else is copied out of the log (C4 ✅).
8. Tabulate `results.csv` (exact header below): automatic columns verbatim from the report, human columns from step 6, `on_time_share = on_time ÷ sampled_cues` to 4 decimals.
9. Write `trial/subtitle-eval/README.md`: machine + pins, the six rows, the confusion table, the proposed `sync_suspect` pair and `coverage_share` floor with evidence, the language observations, the readability verdict, and one line marking the numbers as a proposal for a TL ruling (D10 ✅). No audio, video or frame is committed (D12/D14 ✅).

## Tests

- **Sampler determinism:** same `--seed` on the same SRT → identical cue ids (`diff` empty); different seeds differ on a 200-cue SRT.
- **Heuristic plumbing (negative):** a task dir whose SRT has a zero-length cue makes `render_check.py` report `zero_duration > 0` and the `results.csv` row carries the same number (the CSV copies the report).

## Failure handling and edge cases

- `text_matches_script = false` → real bug (C15 ✅): record cue id, script chunk and cue text, mark the row, escalate; never "fix" the check or the fixture.
- A render fails → take the outcome code from the status (D5 ✅: `tts_failed`, `render_assembly_failed`, `render_node_error`, `render_lost`, `render_timeout`) and retry once when transient; never count a failed video as a row, never hand-edit the CSV to hide it.
- `on_time_share < 0.95` → keep the row, add the label breakdown and escalate; a systematic early/late pattern is a D9/D10 finding, not a reason to re-label.
- en not launched (04 O2) → L2 is 05.5.2-T1's second vi story (`source = substitute`, T14); en subtitle evidence then comes from E2/E4 only (stub TTS).
- Whisper line absent → leave `whisper_language`/`whisper_probability` empty; never infer the language from the script.
- `render_check.py` exit 1 (e.g. truncated MP4, X5-style) → keep the report, set `notes = container_invalid` and exclude that video from the ≥ 95 % target.
- Stub port already in use (18003/18004) → stop and report; never start a second stub. All media stays under `$NTS_HOME/runs/`.
