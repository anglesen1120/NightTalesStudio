# 05.3.1-T1 — `check-music.sh` build check (no unlicensed audio, catalog present on the node)

| Story | Size | Area | Depends on | Blocks | Phase / flag |
|---|---|---|---|---|---|
| 05.3.1 | XS (0.25) | Worker | 01.2.2-T3 (`strip-bundled-music.sh`, `install-music.sh`, `LICENSES.csv`) | 05.3.2-T2, 11.3.1-T2, 11.3.5-T4 (11 CR-4), 05-M0 gate | P · M0 · none |

## Goal

One read-only command that proves a node cannot serve a render with audio it has no licence for and cannot serve a render with music the catalog expects but the node is missing: `worker-node/bin/check-music.sh` runs 01.2.2-T3's strip check, then verifies every **active** catalog track exists in `resource/songs` with the catalog's sha256, then runs `check_catalog.py` (05.3.2-T1) for catalog self-consistency. It is the M0 gate item (README §7) and the source of the adapter's `assets.music_missing` / `assets.music_revision` health values (D4 ✅).

## Inputs

- README **D8** (catalog schema, sha256, active), **D4** (`assets.music_missing`, `assets.music_revision`, reason `music_missing`), **C18** (MPT resolves `bgm_file` in `storage/bgm` then `resource/songs`), **P1**/**CR-7**, **M12** (audio never in the repo).
- 01.2.2-T3 (read ✅): `strip-bundled-music.sh [--check] [--mpt-root DIR]`, exit 0 ok / 1 audio remains / 2 env; default root `$(nts_home)/src/mpt`; the allow-list is the `sha256` column of `worker-node/music/LICENSES.csv`; `install-music.sh` copies CSV rows into `resource/songs`.
- 05.3.2-T1 (sibling, not a dependency): `seed/music-tracks.v1.json` revision 1 and `worker-node/music/tools/check_catalog.py`.
- 01 D9 conventions: `set -euo pipefail`, `--help`, idempotent, shellcheck clean, `lib.sh` (`nts_home`, `die`), stdlib Python via `uv run --no-project --python 3.12` (never `jq`).

## Design

```
check-music.sh [--mpt-root DIR] [--catalog FILE] [--json] [--help]
```

- `REPO_ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/../.." && pwd)"`; default `--catalog "$REPO_ROOT/seed/music-tracks.v1.json"`; default `--mpt-root "$(nts_home)/src/mpt"` (01.2.2-T3 default, same root semantics).
- **Read-only, always.** It never deletes and never calls `strip-bundled-music.sh` without `--check`. No forked strip logic: the allow-list scan, the extension list and the `storage/bgm` rule stay in 01.2.2-T3 (CR-7 ✅). If MPT at the pin reads music from another dir or a different extension list, both scripts change together (01.2.2-T3 failure note).
- Three groups, run in this order; a group 1 failure prints and exits **1** at once (foreign audio is the worse condition, and the later groups read a tree that must be trusted):

| # | Group | Command | Failure |
|---|---|---|---|
| 1 | No unlicensed audio | `strip-bundled-music.sh --check --mpt-root "$MPT_ROOT"` | propagate its **1** (`offenders` list), its **2** → our **2** |
| 2 | Catalog files present with the right hash | stdlib Python reads `--catalog`, prints `id<TAB>file<TAB>sha256` for `active = true` rows; bash checks `resource/songs/<file>` exists and `shasum -a 256` equals the row | print one `music_missing <id>` line per bad track, continue to group 3, exit **1** |
| 3 | Catalog self-consistent | `uv run --no-project --python 3.12 "$REPO_ROOT/worker-node/music/tools/check_catalog.py" --catalog "$CATALOG"` | propagate its **1** (rule/JSON↔CSV failure); its **2** → our **2** |

- Exit code = worst outcome: **2** only for usage/environment (missing `--catalog` file, missing `check_catalog.py`, no `uv`, `--mpt-root` without `main.py` or `resource/`), otherwise **1** if any group failed, else **0**.
- `--json` prints exactly one line on stdout for the adapter and sends the human output to stderr:

```json
{ "ok": false, "catalog_revision": 1, "music_missing": ["temple-02"], "unlicensed": [], "catalog_errors": 0 }
```

  `music_revision` for `render-node-health.v1.assets` is `catalog_revision`; `assets.ok` is `ok`; a non-ok result adds the `music_missing` reason (D4 ✅). `unlicensed` carries the offending relative paths from group 1 (≤ 20, then `…`). On an exit-2 usage/environment failure the `--json` line is best-effort — `ok=false`, `catalog_revision=null`, the lists empty — so the adapter must use the exit code, not `ok` alone, to tell an env failure from a rule failure (05 T53).
- The catalog is read with the stdlib (`json`), so a catalog that is unparseable or has no `tracks` array is reported by group 2 as `catalog_unreadable`, and group 3 still runs: `check_catalog.py` treats an unreadable catalog and a wrong/absent `schema` (and an unreadable CSV header) as usage/environment errors and exits **2** (05.3.2-T1), so the check exits **2** as well (2 > 1), with group 2's `catalog_unreadable` line printed first. A parseable, schema-valid catalog that breaks a D8/CSV rule is group 3's **1**.
- `--catalog` pointing at an absent file → exit **2**: the build check requires a catalog (README §7 makes revision 1 a gate item). 05.3.1-T1's own tests therefore write a temporary catalog; the real one is validated by 05.3.2-T1.

## Steps

1. Add `worker-node/bin/check-music.sh` (D9 header: shebang, `set -euo pipefail`, usage, `--help`, `source "$(dirname "$0")/lib.sh"`), with the three groups and the `--json` shape above. Keep every command an argument list; quote all paths.
2. Group 2's catalog reader as an inline stdlib snippet (no `jq`, no Python file): `uv run --no-project --python 3.12 python -c 'import json,sys; d=json.load(open(sys.argv[1])); print(d["revision"]); [print(t["id"], t["file"], t["sha256"], sep="\t") for t in d["tracks"] if t.get("active")]' "$CATALOG"` — first line is the revision, the rest are the rows.
3. Hash compare with `shasum -a 256` and a `case`-free string compare; a file that exists with the wrong hash reports `music_missing <id> (sha256)`.
4. Wire the exit-code precedence (2 > 1 > 0) and the `--json` single-line output; make the human summary start with `music: ok (revision 1, 24 active tracks)` or `music: FAILED (<n> problems)`.
5. Add `worker-node/bin/tests/check-music.test.sh` (D9 test style: temp `$NTS_HOME/runs/check-music-<pid>/` tree, no network, `trap` cleanup) with the named cases in §Tests.
6. Run it on the Mac against a temp catalog, then against `seed/music-tracks.v1.json` once 05.3.2-T1 has written it. Record the command and the output in the 05-M0 gate evidence.

## Failure handling and edge cases

- `strip-bundled-music.sh` absent (older checkout) → exit 2 with a hint to 01.2.2-T3; do not inline a replacement (CR-7 ✅).
- `uv` missing or offline → exit 2; the check never downloads anything (`uv run --no-project` uses the local interpreter).
- MPT root has `resource/` but no `resource/songs` → treat as an empty tree, not an error: `mkdir -p` is **not** done by this script (it is read-only); every active track is reported `music_missing` and the exit is 1. 11.3.1-T1 runs `install-music.sh` before this check.
- A catalog with zero active tracks → exit 0 and `catalog_revision` printed; the M0 gate separately requires 20–30 tracks (README §7), so the gate command also asserts the count via `--json`.
- Duplicate `file` in the catalog → reported by group 3 (`check_catalog.py`), not here.
- `.m4a` tracks: the hash compare is extension-agnostic; group 1's extension list stays 01.2.2-T3's.
- A node with Redis/other MPT copies of `resource/songs` ⚠️: out of scope — one MPT root per node.
- Never print the contents of `LICENSES.csv` rows beyond `id`/`file`/`sha256`; never print a key or a URL with credentials.
