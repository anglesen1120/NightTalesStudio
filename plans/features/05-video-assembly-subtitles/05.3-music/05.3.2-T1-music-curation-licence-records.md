# 05.3.2-T1 — Curation of 20–30 tracks, licence records, gain and `seed/music-tracks.v1.json`

## Goal

A small, legally clean, measured catalog the backend can select from without touching audio: `seed/music-tracks.v1.json` revision 1 (D8 schema) + the appended `LICENSES.csv` rows + `worker-node/music/tools/check_catalog.py`, which proves the JSON obeys every D8 rule and agrees with the CSV. Installed with `install-music.sh` and proven by `check-music.sh` (05.3.1-T1) — all three are 05-M0 gate items (README §7 ✅).

## Inputs

- README **D8** ✅ (schema, id rule, licence enum, attribution rule, scope rule, mood vocabulary, `durationSec ≥ 60`, gain formula with `MusicBedLufs = −34`, topic → moods), **L2** ✅, **O2** ⚠️ (owner decision pending), **C17** (mix, 3 s fade, loop), **C18** (MPT picks by extension from `resource/songs`), **P1**/**CR-5** ✅ (CSV columns appended, never renamed), **CR-7** ✅.
- 01.2.2-T3 (read ✅): the CSV header `file,title,artist,source_url,license,license_url,attribution,mood_tags,sha256,duration_s,loudness_lufs,added_at`, its CC0 placeholder row, `install-music.sh`, and the QA commands (`shasum -a 256`, `ffprobe`, `ffmpeg -af loudnorm`).
- 01 D9 conventions: stdlib Python via `uv run --no-project --python 3.12`, no `jq`, `set -euo pipefail`.
- `seed/fixtures/music/*.json` + `expected.json` — written **by this task**, because 05.3.2-T3's C# tests read them.

## Design

### Source policy (O2 recommendation (a) ⚠️ owner decision pending)

1. **YouTube Audio Library first**, filter "Attribution not required" (standard licence, no Content ID claim, monetisable in YPP, L2 ✅) → `platformScope = "youtube"`.
2. **YouTube Audio Library CC-BY** second, the exact credit text in `attribution` (required in the description, L2 ✅) → `platformScope = "any"`.
3. **CC0 sources** third, `platformScope = "any"`, `attribution = null` — with the ⚠️ Content ID note (§Notes).
4. Per track: the licence is read **on the source page**; `evidence_url` records that exact page, `retrieved_at` the ISO-8601 UTC date, and the page (PDF print or screenshot) is saved to `$NTS_HOME/music-evidence/<track_id>/`. Third-party evidence is **never committed** (M12 ✅); the repo keeps metadata only.

### Content rules

- 20–30 tracks, **≥ 4 per topic mood set** (D8 ✅): `ghost` {`dark_ambient`, `suspense`} · `spiritual` {`temple`, `meditation`, `calm`} · `true_crime` {`noir`, `suspense`}; every one of the six moods covered by ≥ 4 tracks; 1–3 moods per track.
- Instrumental only, no vocals/lyrics (narration sits on top); ≥ 60 s, prefer ≥ 120 s; loop-friendly (no hard ending — C17 loops the bed with a 3 s fade-out); `.mp3`/`.m4a` only; files live in `$NTS_HOME/music/` (never the repo, M12 ✅).

### Per-track QA (all four, per track)

```bash
f="$NTS_HOME/music/<file>"
shasum -a 256 "$f"                                                                  # → sha256, lowercase hex, 64
ffprobe -v error -show_entries format=duration:stream=codec_name,sample_rate,channels,bit_rate -of json "$f"
ffmpeg -hide_banner -nostats -i "$f" -af loudnorm=print_format=json -f null - 2>&1  # → input_i = integrated LUFS
```
- The loudness JSON block is the last `{ … }` on stderr; parse it with `uv run --no-project --python 3.12 python -c` (no `jq`). `input_i = "-inf"` → reject (silence). Two measurements > 1 LU apart → reject, never average.
- Gain: `bgmVolume = round(clamp(10^((MusicBedLufs − loudnessLufs) ÷ 20), 0.03, 0.40), 3)` with `MusicBedLufs = −34` [target, D8 ✅], e.g. `-17.3 → 0.146`:
  `uv run --no-project --python 3.12 python -c 'import sys;print(round(min(max(10**((-34-float(sys.argv[1]))/20),0.03),0.40),3))' -17.3`
- Listening check (headphones + speakers, first and last 10 s): no clipping, no abrupt end, no speech, no recognisable melody from a known song (a Content ID magnet).

### `check_catalog.py` (stdlib; the machine-checkable half of the rules)

```
check_catalog.py --catalog FILE [--licenses FILE] [--json] [--self-test]
```

- Default `--licenses worker-node/music/LICENSES.csv` (repo-relative). No network.
- JSON rules, each with a stable code: `revision_not_positive`, `track_id_format`, `track_id_not_file_stem`, `track_id_duplicate`, `file_duplicate`, `file_extension`, `license_unknown`, `attribution_required` (`CC-BY-4.0` without a non-empty `attribution`), `attribution_not_allowed` (non-CC-BY with one), `scope_unknown`, `scope_license_mismatch`, `moods_unknown`, `moods_count`, `duration_below_minimum` (< 60), `loudness_missing`, `sha256_format`, `bgm_volume_range`, `bgm_volume_formula_mismatch` (must equal the D8 formula to 3 dp), `active_missing`.
- CSV consistency: every JSON track needs a row with the same `file`, `sha256`, `license`, `track_id`, `platform_scope`, a non-empty `evidence_url`, an ISO-8601 `retrieved_at`, and `mood_tags` (`;`-separated) equal to the JSON `moods` set → `csv_row_missing`, `csv_field_mismatch`, `csv_moods_mismatch`, `csv_evidence_missing`. A row with an empty `track_id` (the 01.2.2-T3 placeholder) is allowed and needs no JSON track.
- `--json` prints one line: `{ "ok": true, "revision": 1, "tracks": 24, "active": 24, "moods": { "dark_ambient": 5, … }, "errors": [] }` — the mood histogram is what the M0 gate reads for "≥ 4 per topic mood set".
- Exits **0** ok · **1** any rule/consistency error (all listed, not just the first) · **2** usage/env (missing file, unreadable CSV header).
- `--self-test` writes only inside a temp dir: the fixtures vs `expected.json`, boundary cases generated in memory (id length 40/41, charset, gain clamps at `−34`/`−80`, `durationSec` 59.9/60.0, uppercase sha256), and a synthetic JSON↔CSV mismatch pair (missing row, wrong sha256, wrong mood tags, empty evidence URL).

### Output files

- `seed/music-tracks.v1.json` — D8 schema, `"revision": 1`, tracks sorted by `id` (ordinal), gain from the formula (never by hand).
- `worker-node/music/LICENSES.csv` — 01.2.2-T3 header **byte-identical**, four columns appended in this order: `track_id,platform_scope,evidence_url,retrieved_at` (CR-5 ✅). Rows are appended with an inline stdlib `csv` snippet (quoted commas safe); `check_catalog.py` stays read-only, so each file has exactly one writer.
- `seed/fixtures/music/`: `valid-catalog.json` (3 tracks, revision 1) · `invalid-id.json` · `invalid-license.json` · `invalid-attribution.json` · `invalid-scope.json` · `invalid-moods.json` · `invalid-duration.json` · `invalid-sha256.json` · `invalid-duplicate-file.json` · `invalid-revision.json` · `expected.json` (`{ "<fixture>": { "ok": false, "code": "attribution_required" } }`, the exact codes above).

## Steps

1. Fix the source list per §Source policy; open each source page, read the licence, record `platformScope` and the credit text; save the evidence page to `$NTS_HOME/music-evidence/<track_id>/`; download the file to `$NTS_HOME/music/<file>`.
2. Run the §Per-track QA on every file; drop failures; keep the measurements (id, file, sha256, duration, loudness, gain, moods, scope, evidence) in a scratch table.
3. Check mood coverage (≥ 4 per topic mood set and per mood); top up from the source list where thin.
4. Write `seed/music-tracks.v1.json` (revision 1, sorted by `id`) and append the CSV rows with the four extra columns, leaving the 01.2.2-T3 placeholder row untouched.
5. Write `check_catalog.py` and the eleven fixtures + `expected.json`.
6. `check_catalog.py --self-test` → 0; `check_catalog.py --catalog seed/music-tracks.v1.json` → 0 with the mood histogram.
7. `install-music.sh --mpt-root "$(nts_home)/src/mpt"` → 0; `check-music.sh --mpt-root "$(nts_home)/src/mpt"` → 0 and `--json` shows `music_missing: []`, `catalog_revision: 1`.
8. Owner listening session (1 slot): ~8 tracks (≥ 2 per topic mood set), 30 s each, approve/swap recorded. A swap before 05-M0 keeps `revision` 1; after M0 any change bumps it (D8 ✅).
9. Record in the 05-M0 evidence: the two exit-0 commands, the mood histogram, the licence source per track and where the evidence files are.

## Failure handling and edge cases

- No suitable track for a mood after the source pass → prefer a second CC0 source over lowering coverage; if still short, record the gap in the 05-M0 evidence and ask the TL before shipping revision 1 (the D8 selector degrades to `null` → no music, hint `music_none`, which is legal but not the story's intent).
- Owner swaps a track after the session → replace the file and the row; `revision` stays 1 until 05-M0, then any change is `revision + 1` (D8 ✅) and 05.3.2-T2 re-syncs nodes.
- A source page changes or disappears → the saved evidence in `$NTS_HOME/music-evidence/` is the record; update `retrieved_at` when re-verified.
- A track is later claimed through Content ID (CC0 ⚠️) → set `active = false` (content change, revision bump) and replace it; the row is kept (the seeder never deletes, 05.3.2-T3).
- `LICENSES.csv` with an unbalanced quote → `check_catalog.py` exits 2 (unreadable CSV header) instead of reporting a rule error; fix the CSV.
- The 01.2.2-T3 placeholder row must keep working: empty `track_id`, no JSON track required.

## Notes

- ⚠️ **Content ID risk for CC0**: a CC0 file can be registered by a third party and claimed on YouTube; the mitigation is preferring the YouTube Audio Library "attribution not required" filter for `youtube`-scope tracks, not a guarantee.
- ⚠️ **O2 is an owner decision** (`plan.md` §10): this task follows recommendation (a). With option (b) (CC0 only) the catalog shrinks; no code or schema change.
- The audio files are the only artefacts that cannot be committed; `seed/music-tracks.v1.json` + `LICENSES.csv` are the committed truth (M12 ✅). `MusicBedLufs = −34` is a [target] (D8 ✅), tuned in 05.5.2-T1; a change re-computes every `bgmVolume` and bumps the revision.
