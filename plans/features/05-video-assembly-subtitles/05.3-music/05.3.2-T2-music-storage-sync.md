# 05.3.2-T2 — Music storage sync (`upload_music.py`, `sync-music.sh`)

| Story | Size | Area | Depends on | Blocks | Phase / flag |
|---|---|---|---|---|---|
| 05.3.2 | S (0.5) | Worker | 05.3.2-T1 (catalog file), 05.3.1-T1 (`check-music.sh`), 11.4.1-T1 (buckets) | 11.3.1-T2 (11 CR-4) | P · M1 · none |

## Goal

Get the licensed catalog onto every node without shipping audio through the repo: the operator uploads `$NTS_HOME/music/<file>` to `music/<file>` in the private assets bucket, and a node pulls the files it is missing (or whose hash changed), verifies each sha256, installs them into MPT's `resource/songs` and re-runs the strip check. Idempotent, safe at every provisioning and after every catalog revision change (D8 ✅, M11 ✅).

## Inputs

- README **D8** ✅ (key `music/<file>`, read-only `music/`-scoped credential, sha256 check, then install + strip check, M0 copies by hand), **D4** (`assets.music_revision`/`music_missing` — how a failed sync shows up), **C18** (MPT reads `resource/songs`).
- 05.3.2-T1: `seed/music-tracks.v1.json` (`revision`, `tracks[].file`, `tracks[].sha256`, `active`).
- 05.3.1-T1 `worker-node/bin/check-music.sh`; 01.2.2-T3 `install-music.sh [--mpt-root DIR] [--source DIR]`, `strip-bundled-music.sh [--check] [--mpt-root DIR]`.
- ⚠️ 11.4.1-T1 bucket name; ⚠️ 11.3.2 node credential (read-only, prefix `music/`) and node env keys; ⚠️ 11 FR egress already allows the storage endpoint.
- 01 D9 conventions: `set -euo pipefail`, `--help`, `lib.sh`, stdlib Python via `uv run --no-project --python 3.12`, no `jq`, no `set -x`.

## Design

```
worker-node/music/tools/upload_music.py --catalog FILE [--source DIR] [--bucket NAME] [--prefix music/] [--dry-run]
worker-node/bin/sync-music.sh [--catalog FILE] [--dest DIR] [--mpt-root DIR] [--force] [--help]
```

**`upload_music.py`** (operator, on the Mac): stdlib + `curl`, no `boto3` assumption. It also copies `$NTS_HOME/music-evidence/<track_id>/*` to the private prefix `music-evidence/<track_id>/` (never public; T24), because `$NTS_HOME` is excluded from backups (01 D1). Per `LICENSES.csv` row (every catalog track, active or not, **and** the 01.2.2-T3 placeholder; T4) — the local `sha256` must equal the catalog value (else exit 1 `hash mismatch <file>`); `HEAD` the object and skip when `Content-Length` and `x-amz-meta-sha256` already match (idempotent); otherwise `PUT` with `-H "x-amz-meta-sha256: <hash>"` and the right `Content-Type`. Signing without leaking the key (D15 S7): `upload_music.py` reads the **operator write key** from the Keychain (`nts.music.write` → `NTS_MUSIC_WRITE_KEY`/`NTS_MUSIC_WRITE_SECRET`) and runs `curl --aws-sigv4 "aws:amz:<region>:s3" --config -` with `user = "<key>:<secret>"` written to curl's **stdin** (`subprocess.run(..., input=…)`) — never argv, never `<(…)`. `sync-music.sh` uses the node **read-only** key `NTS_MUSIC_READ_KEY`/`NTS_MUSIC_READ_SECRET` (prefix `music/` only; `music-evidence/` is not readable from nodes) the same way: `printf 'user = "%s:%s"\n' … | curl --config - …`. `--dry-run` prints the PUT/skip plan. Exits 0 ok · 1 hash mismatch or failed PUT · 2 usage/env (missing bucket env, catalog, `curl`, or `--aws-sigv4` support).

**`sync-music.sh`** (node): defaults `--catalog "$REPO_ROOT/seed/music-tracks.v1.json"`, `--dest "$(nts_home)/music"`, `--mpt-root "$(nts_home)/src/mpt"`.

1. Fast path — `$DEST/.catalog-revision` equals the catalog `revision` and every `LICENSES.csv` row's file sha256 matches → skip the downloads (still run the install + strip tail). `--force` bypasses it.
2. Per `LICENSES.csv` row (active and inactive tracks and the placeholder — `install-music.sh` requires a source file for **every** CSV row, 01.2.2-T3 step 5; T4): missing or hash-different `$DEST/<file>` → download to `$DEST/.tmp/<file>.part` with `curl --fail --connect-timeout 10 --max-time 600 --retry 2 --retry-delay 5 --max-filesize 52428800` (D15 P7), verify the sha256 in 1 MiB chunks of the received bytes, then `mv` into place (atomic; a corrupt download never replaces a good file).
3. Then unconditionally: `install-music.sh --source "$DEST" --mpt-root "$MPT_ROOT"` and `strip-bundled-music.sh --check --mpt-root "$MPT_ROOT"`, propagating a non-zero; write `$DEST/.catalog-revision` **only** after both exit 0.
4. Credential: **read-only, prefix-scoped to `music/`** (11.3.2 ⚠️), from the node env file; never printed, never in argv, never in the repo or a log line. Two client options, in preference order: **(A) node read-only credential (recommended)** — `curl --aws-sigv4 … --config <(…)` per file or a 0600 `curl` config under `$NTS_HOME`, so provisioning and revision changes need no operator; **(B) presigned GET URLs minted by an operator step** — the node holds no secret at all, each sync needs an operator; the URL is treated as a secret and never logged. No AWS CLI assumption in either ⚠️.
5. Exits 0 ok · 1 download/install/strip failure (missing track, hash mismatch, unlicensed audio left) · 2 usage/env (catalog, `curl`, bucket/credential env, `install-music.sh`).
6. After a successful sync the node health must show `assets.music_revision` = the catalog revision and `music_missing: []` (D4 ✅) — 11.3.5-T1 maps `check-music.sh --json` to that.

**Mac M0: not used.** Files are copied by hand to `$NTS_HOME/music/` and installed with `install-music.sh` (D8 ✅, M11 ✅). This task is M1 only.

## Steps

1. Write `upload_music.py` with the pre-upload hash check, the HEAD-skip and `--dry-run`; log `put music/<file> <bytes> sha256=<hash>` or `skip music/<file> (present, same sha256)`.
2. `upload_music.py --catalog seed/music-tracks.v1.json --dry-run` → review → run for real → exit 0; `HEAD` every object and compare `Content-Length` + `x-amz-meta-sha256` with the catalog.
3. Write `sync-music.sh` with the fast path, temp+`mv` download, install + strip tail and the revision marker.
4. Wire it into 11.3.1-T1 provisioning after the bucket exists and before `check-music.sh`; note that a catalog revision change re-runs it.
5. Test with the local fixture server (§Tests), then once against the real bucket (or a documented ⚠️ emulator run).
6. Record in the 05-M1 evidence: the upload log, the sync log (first run downloads N, second 0), `check-music.sh --json` with `music_missing: []`.

## Acceptance checks

- [ ] `upload_music.py … --dry-run` → exit 0, one plan line per active track, no write; running it twice → the second run prints `skip` for every file (idempotent).
- [ ] A tampered local file (one byte appended) → exit 1 `hash mismatch <file>`, nothing uploaded.
- [ ] `bash worker-node/bin/tests/sync-music.test.sh` → all cases pass, exit 0.
- [ ] Against the fixture server: first `sync-music.sh` downloads N files, the second downloads 0 and exits 0, and `$NTS_HOME/music/.catalog-revision` equals the catalog revision.
- [ ] Corrupt the served body of one track → exit 1 `hash mismatch <file>` and the previously good `$DEST/<file>` unchanged (`shasum -a 256` identical); delete one installed file from `$MPT_ROOT/resource/songs` → exit 0 and `check-music.sh` → exit 0.
- [ ] `sync-music.sh --catalog <absent>` → 2; with no credential env → 2 with a hint to 11.3.2; a bumped test revision skips the fast path, and reverting the marker restores it.
- [ ] Secret hygiene: `grep -F "$NTS_MUSIC_READ_SECRET" <any log from the test>` exits 1; a `PUT` with the node read-only key → 403 and a `GET music-evidence/…` with it → 403 (D15 S7); `grep -c 'set -x' worker-node/bin/sync-music.sh` = 0; `shellcheck worker-node/bin/sync-music.sh` → 0.
- [ ] Node end to end (M1, once the bucket exists): `sync-music.sh` → 0, `check-music.sh --json` → `music_missing: []`, `catalog_revision` = 1.

- `t_missing_catalog_exit_2` · `t_no_credential_exit_2` · `t_missing_install_script_exit_2` · `t_secret_never_logged` (a marker secret absent from stdout, stderr and every temp file the script writes).
- `upload_music.py`: `t_dry_run_no_write` · `t_second_upload_skips` · `t_hash_mismatch_exit_1` (pure stdlib checks against the fixture server; the SigV4 path is one manual run against the real bucket ⚠️).

## Failure handling and edge cases

- Bucket name or credential missing → exit 2 with a hint to 11.4.1-T1 / 11.3.2; never fall back to an anonymous or public read.
- `curl` without `--aws-sigv4` ⚠️ → exit 2 and record the version; option (B) is the fallback.
- Network failure mid-download → the `.part` file stays in `$DEST/.tmp/` (cleaned at the next run) and the good file is untouched; exit 1.
- The catalog lists a file the bucket does not have → `404` → exit 1 `music_missing <id>`; health then reports `music_missing` and the dispatcher skips the node (D4 ✅) — never a silent failure.
- A track set `active = false` stays downloaded and installed (its CSV row still exists, and `install-music.sh` needs every CSV row's file, 01.2.2-T3 step 5); the backend simply never selects it (D8). Retiring a file for good = remove its CSV row **and** its catalog entry in one commit; `strip-bundled-music.sh` then deletes it from `resource/songs` at the next run (T4).
- Bucket object deleted but present on the node → the fast path hides it; `--force` or a revision bump re-checks, and `check-music.sh` still passes (the node has the file), which is correct.
- M0 never runs this script (manual copy, D8 ✅); do not add it to the Mac bootstrap. Never print a presigned URL, an `Authorization` header or a credential, and never write the credential into the node env file from this script (11.3.2 owns that file).
