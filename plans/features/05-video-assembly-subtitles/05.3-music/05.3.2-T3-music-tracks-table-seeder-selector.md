## Design

### Table `music_tracks` — global catalog, **not** tenant-owned

| Column | Type | Rule |
|---|---|---|
| `id` | `uuid` PK | UUIDv7 (`Guid.CreateVersion7()`) |
| `track_id` | `text` UNIQUE | D8 id rule: `^[a-z0-9]+(-[a-z0-9]+)*$`, ≤ 40, = `file_name` stem |
| `file_name` | `text` | `.mp3` / `.m4a` |
| `title`, `artist`, `source_url` | `text` | non-null |
| `license` | `text` | CHECK ∈ {`CC0-1.0`, `CC-BY-4.0`, `YouTube-Audio-Library`} |
| `attribution` | `text` NULL | CHECK: non-empty iff `license = CC-BY-4.0` |
| `platform_scope` | `text` | CHECK ∈ {`any`, `youtube`}; CHECK `YouTube-Audio-Library` ⇒ `youtube` |
| `moods` | `text[]` | CHECK `moods <@ {dark_ambient,suspense,temple,meditation,noir,calm}` and `array_length` 1–3 |
| `duration_sec` | `numeric(7,1)` | CHECK ≥ 60 |
| `loudness_lufs` | `numeric(5,1)` | measured integrated |
| `bgm_volume` | `numeric(4,3)` | CHECK 0.03–0.40 and equal to the D8 formula at 3 dp |
| `sha256` | `char(64)` | CHECK `^[0-9a-f]{64}$` |
| `storage_key` | `text` | `music/<file>` |
| `catalog_revision` | `int` | the file's revision |
| `active` | `bool` | default true |
| `created_at`, `updated_at` | `timestamptz` | default `now()` |

- **No `user_id`, no tenant filter**: the catalog is global and identical for every tenant, so `MusicTrack` must be listed as intentionally unfiltered in the 09.2.3 conventions ⚠️ (`plan.md` §10); otherwise a global query filter breaks selection silently (`null` → `music_none`).
- EF configuration in Infrastructure (`MusicTrackConfiguration`): unique index on `track_id`, the CHECKs via `ToTable(t => t.HasCheckConstraint(…))`, `moods` as `text[]` (Npgsql), `bgm_volume`/`duration_sec`/`loudness_lufs` as `decimal`, `sha256` as `char(64)` (⚠️ folder/naming per the 09.2.2 convention).
- Migration **`AddMusicTracks`** (up: table + constraints + unique index; down: drop), in the 09.2.2 bundle so the CI migration check (09.2.2-T2) runs up/down on an empty database.

### Domain (`Domain/Rendering/Music/`, no EF)

Signatures (sealed records, file-scoped namespaces, `ErrorOr`, no EF reference):

- `MusicTrack(Guid Id, string TrackId, string FileName, string Title, string Artist, string SourceUrl, MusicLicense License, string? Attribution, MusicPlatformScope PlatformScope, IReadOnlyList<string> Moods, decimal DurationSec, decimal LoudnessLufs, decimal BgmVolume, string Sha256, string StorageKey, int CatalogRevision, bool Active)`
- `enum MusicLicense { Cc0 = 1, CcBy = 2, YouTubeAudioLibrary = 3 }` · `enum MusicPlatformScope { Any = 1, YouTube = 2 }`
- `MusicTrackCandidate(string TrackId, string FileName, MusicLicense License, string? Attribution, MusicPlatformScope PlatformScope, IReadOnlyList<string> Moods, decimal DurationSec, decimal LoudnessLufs, decimal BgmVolume, string Sha256, bool Active)`
- `MusicTrackRules.Validate(MusicTrackCandidate candidate) → ErrorOr<Success>` — every D8 rule, with the **same error codes** `check_catalog.py` prints (`track_id_format`, `track_id_not_file_stem`, `license_unknown`, `attribution_required`, `attribution_not_allowed`, `scope_license_mismatch`, `moods_unknown`, `moods_count`, `duration_below_minimum`, `sha256_format`, `bgm_volume_range`, `bgm_volume_formula_mismatch`), all violations collected into one `ErrorOr`
- `MusicTrackRules.ComputeBgmVolume(decimal loudnessLufs, decimal musicBedLufs = -34m) → ErrorOr<decimal>` — the D8 formula, shared by the seeder's re-check and the fixture parity

### `MusicSelector` (Domain, pure)

`MusicSelectionInput(SeriesTopic Topic, IReadOnlyList<string> RecentTrackIds, Guid EpisodeId)` · `MusicChoice(string TrackId, string File, decimal BgmVolume)` · `MusicSelector.Pick(MusicSelectionInput input, IReadOnlyList<MusicTrack> active, int avoidRecent = 3) → MusicChoice?`.

Exactly D8 ✅ (M7): candidates = `active` ∧ `moods ∩ topicMoods ≠ ∅` (`ghost` {`dark_ambient`, `suspense`}, `spiritual` {`temple`, `meditation`, `calm`}, `true_crime` {`noir`, `suspense`}) ∧ scope allowed (`any` or `youtube`; 07 enforces the platform rule, CR-8 ✅) → drop the last `avoidRecent` (3) `RecentTrackIds`, keep them if that empties the set → order by `TrackId` with `StringComparer.Ordinal` → index `BinaryPrimitives.ReadUInt32BigEndian(SHA256.HashData(EpisodeId.ToByteArray())[..4]) % count` → `MusicChoice(track.TrackId, track.FileName, track.BgmVolume)`. No candidate → `null` (no music, hint `music_none`, D10 ✅). `avoidRecent` comes from backend config `Music:AvoidRecent` (default 3), read by 05.1.2-T1, not here.

### `IRecentMusicQuery` (port; implementation waits for 09.6.1)

`Nts.Application.Abstractions.Rendering.IRecentMusicQuery` with `Task<IReadOnlyList<string>> GetRecentTrackIdsAsync(Guid seriesId, int take, CancellationToken ct)`. Contract: the last 3 `render_jobs.params->'music'->>'track_id'` of the series, newest first —

```sql
select params->'music'->>'track_id' as track_id from render_jobs
where series_id = @series_id and params->'music' is not null
order by created_at desc limit @take;
```

`render_jobs` is created by 09.6.1 (M1), so this task ships **only the port + `NullRecentMusicQuery`** (empty list); the Infrastructure implementation lands with 09.6.1-T1 (raw `SqlQuery<string>` / `FromSqlInterpolated` ⚠️ exact shape is 09.6.1's). Selection is deterministic with an empty recent list until then.

### `MusicTrackSeeder` (Infrastructure; 09.2.5-T1 pattern ⚠️ exact abstraction name)

- Reads `seed/music-tracks.v1.json` (embedded resource) when the catalog seed runs: auto-seeded in Development, via an explicit `nts-seed` elsewhere after the migration bundle and before a render submit is accepted (05 README §10 T85, 09.2.5 plan §1).
- Upsert by `track_id`: existing row → update all catalog fields + `updated_at`; new row → insert with `Guid.CreateVersion7()`. **Never deletes.**
- A row whose `track_id` is absent from the file → `active = false` (kept, so an old `params.music.track_id` still resolves to its `platform_scope`; the attribution itself is frozen in `params.music.attribution`, T9 / 06 CR-5).
- `revision < 1` outside Development → refuse, table untouched (in Development: warn and continue). Any `Validate` failure → the whole file is rejected, no partial seed.
- Idempotent: a second run changes nothing and never rewrites `id`.

## Failure handling and edge cases

- Catalog absent/unreadable (or over 1 MiB) when the seed runs → log an error, leave the table untouched, do not fail the host (the render path degrades to `null` → no music, `music_none`, D10 ✅). ⚠️ Flag to the TL if Production should fail hard instead.
- `revision < 1` outside Development → refuse, no rows changed; in Development → warn and continue. A track removed from the JSON → `active = false`, never deleted.
- A catalog with an empty `tracks` array, a duplicate JSON property, a loudness with more than 2 decimals, a `durationSec` above 3600, a blank `title`/`artist`, or a `sourceUrl` that is not an absolute `https` URL is rejected whole (`seed_music_invalid`), so a broken file can never deactivate the catalog (05 §10 T85 gate fixes SEC-1..4, CR-2..4).
- Two seeds racing → the unique index on `track_id` plus upsert keeps one row per track; a concurrent insert may raise a unique violation, retried once ⚠️ (09.2.5-T1's pattern governs).
- `moods` empty array → rejected by the CHECK (and earlier by `moods_count`); `bgm_volume > 0.999` does not fit `numeric(4,3)`, and the 0.03–0.40 CHECK keeps the range.
- `EpisodeId` hashing must be SHA-256 over the 16 UUID bytes — never `GetHashCode` (process-randomised).
- If the 09.2.3 conventions apply a global `user_id` filter to every entity, `MusicTrack` must be exempted (⚠️ `plan.md` §10); the failure mode is an empty candidate set and silent `music_none` hints.
