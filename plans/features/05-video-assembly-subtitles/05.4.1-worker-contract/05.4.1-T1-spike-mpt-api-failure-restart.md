## Design

### `trial/tools/tts_stub.py` (new, stdlib only)

- `ThreadingHTTPServer` on `127.0.0.1:18004`; only `POST /v1/audio/speech` (OpenAI speech shape; only `input` is read); else 404 JSON. `--require-key`/`NTS_TTS_STUB_KEY` → 401 unless the Bearer matches; default off (MPT sends no key with `[kokoro] api_key = ""`, D2).
- Modes via `--script FILE` (the image stub's JSON shape: `default`, `by_call`, `by_input_contains`), D12: `ok` 200 `audio/mpeg` whole fixture · `e500` 500 `{"error":{"code":"server_error"}}` · `abort` 200 with the fixture's `Content-Length`, 4096 bytes then socket closed (04 X2) · `empty` 200 `Content-Length: 0` · `sine` 200 a 440 Hz tone MP3 (no speech) · `slow` 200 first byte after 130 s (`--slow-delay` overrides; self-test uses 1).
- Fixtures `--fixtures DIR` (default `$NTS_HOME/runs/spike-05/fixtures/`): `speech-en.mp3`, `speech-vi.mp3`, `sine-60s.mp3`, made on the Mac with `say` + `ffmpeg -c:a libmp3lame -b:a 192k -ar 44100`; **never committed** (D12); a missing fixture → exit 2 printing the exact commands.
- `--calls-file` (default `tts-stub-calls.jsonl`): `{ n, ts, input_sha256, input_len, mode, status, bytes_written, aborted }` — hash and length, never the text. `--self-test`: per-mode status/byte count, an MPEG sync word (`0xFF 0xFB`/`0xF3`) on every fixture, unknown route 404; exit 0/1/2.

### `trial/tools/mpt_client.py` (new, stdlib only)

`--base-url` (default `http://127.0.0.1:8080`); key from the Keychain via the 01 `secret` helper into the environment, sent as the single `x-api-key` header (C2).

- `submit --spec FILE [--run-dir DIR]` → build the D3 body (written to `DIR/submit-body.json`; default `DIR` is under `$NTS_HOME/runs`, gitignored even when `$NTS_HOME` is the default `<repo>/.nts`; an explicit `--run-dir` inside the repo exits 2 — the body holds the script), `POST /api/v1/videos` with `x-task-id: <run_id>` (C3); print `{"task_id": …}`; non-200 → print the body, exit 1.
- `poll --task-id ID [--interval 5] [--timeout 3600] [--trace FILE]` → `GET /api/v1/tasks/{id}` (C6); map per the table below; print a `render-status.v1`-shaped JSON on every change; `--trace` appends `{ts, state, progress, failed_stage}` per tick (S3: `--interval 1`); 404 after a submit → `failed`/`render_lost` (F06); timeout → exit 1 with the last status, `state: "running"` and `"poll_timeout": true` — not a failure: resume with `poll`, never re-submit while MPT reports `state 4` (D15 P7).
- `download --task-id ID --dest DIR` → `GET /api/v1/download/{id}/final-1.mp4`, `…/subtitle.srt`, `…/audio.mp3` and `…/script.json` (C12, C13) — the four files `render_check.py` reads (D9; T2); a 404 on the SRT is not an error when subtitles are off; write `DIR/manifest.json` = `{file, bytes, sha256, content_type}`.
- `run --spec FILE --run-dir DIR` → submit → poll (5 s) → download → when `render_check.py` exists, `render_check.py run --task-dir DIR --aspect <spec aspect> --subtitles on --normalize`; print the final D4-shaped status. Exit 0 success · 1 failure/lost · 2 usage/env.

Run spec (tracked, `trial/fixtures/spike-render-spec.json`): `{ run_id, story_file, terms_file, aspect, language, voice_id, preset_file|null, music_track|null }`. Body = the D3 key set: `video_subject` = first line of `story_file` (≤ 200 chars), `video_script` = the body NFC, `video_terms` = the `terms_file` array, `video_aspect` = `16:9`|`9:16`, `video_language`, `voice_name = "kokoro:" + voice_id`, subtitle fields from `preset_file` else the D6 defaults inline, music from `music_track` or none; `n_threads` never sent (F22). The client never prints the key nor writes script/prompt text.

Mapping (D4/D5), implemented once here and reused by the adapter:

| MPT | `state` | `stage` | outcome |
|---|---|---|---|
| `4`, progress 0 | `queued` | `queued` | — |
| `4`, 5–29 / 30–39 / 40–49 / 50–99 | `running` | `voice` / `subtitles` / `images` / `assembling` | — |
| `1` | `succeeded` | `done` | — |
| `-1`, `failed_stage` `audio` / `materials` / `video` / `preflight, script, terms, pipeline` | `failed` | `voice` / `images` / `assembling` / last reached | `tts_failed` / `image_generation_failed` / `render_assembly_failed` / `render_node_error` |
| 404 after a submit | `failed` | — | `render_lost` |

### Spike profile addition and sampler

2. Start the stubs and the spike profile (the key is never on argv and never printed):

```bash

worker-node/bin/render-mpt-config.py --profile spike && worker-node/bin/start-mpt-api.sh --profile spike
```
3. Write `tts_stub.py` + `--self-test`; make the three fixtures; extend `redact_prompts.py` with the `video_script`/`script.json` rule (+ self-test case).
4. Write `mpt_client.py` + `--self-test` (body builder, mapping table, no network); write the fixtures (`spike-story-en.txt`, `spike-story-vi.txt`, `spike-terms.json`, `tts-stub-script.json`, `spike-render-spec.json`).

Stop the stubs; `start-mpt-api.sh --profile normal` (the "mac" profile nickname used in prose means exactly this normal render); `smoke.sh` green (proves the swap was undone).

## Failure handling and edge cases

| Case | Action |
|---|---|
| Pin differs / a C fact changed | record in S0, `NO-GO` for the dependent D3/D4 item, escalate to the TL |
| MPT refuses the spike profile | the 03.4.1-T1 guard fired — re-render; never edit `config.toml` by hand |
| `render_check.py` absent (05.5.1-T1 not landed) | `run` prints `check: null` and fills `output` from the download manifest (video/subtitles bytes+sha256, `narration_seconds: null` until 05.5.1-T1 lands) (D9); measure loudness with `ffmpeg -i final-1.mp4 -af ebur128=peak=true -f null -` |
| Key not in Keychain | `die 2` with the `security add-generic-password -s nts.mpt.api_key …` hint; never type the key on the command line |
