## Goal

Freeze the language-neutral render-node contract as files a .NET, Python or other implementation can build from without asking questions — routes, auth, error envelope, submit validation order, status/stage mapping with the **observed** progress values, outcome codes, lost rule, capacity, cancel, cleanup, health reasons, idempotency — plus the D14 golden fixtures and the hand-over to the three gated consumers.

## Design

### `worker-node/contract/render-node.v1.md` (new, tracked)

One file, no JSON-Schema companion (D14); sections in order, each citing its README id:

1. Scope/owners (11.3.5-T1 serves, 11.1.2-T1 mocks, 09.6.2-T1 calls) · transport `https://<node private address>:8090` with a pinned certificate fingerprint (D15 S1; port ⚠️ final in 11.3.5-T1), JSON UTF-8, ISO-8601 UTC `Z` · auth (one `x-api-key`, constant-time, every route → 401 `adapter_unauthorized`) · error envelope `{"error":{"code","message" (≤ 200 chars, no content),"errors":[ … ]}}` · unknown path → 404 `adapter_route_not_found`.
2. Routes: the D4 table, all 7 with request/success/error codes — `POST /v1/renders`, `GET /v1/renders/{task_id}`, `…/video`, `…/subtitles`, `POST …/cancel`, `DELETE …`, `GET /v1/health`; **plus one 8th, probe-only route (12 CR-19, contract only — 11.3.5-T1 implements):** `POST /v1/probe-image` — same auth (`x-api-key`) and cert pinning as every other route; request `{}` (no body fields — it exercises the node's own configured OpenAI project/key, not a caller-supplied prompt); terminal result synchronously or via one status poll: `200 {"funded": true}` or `200 {"funded": false, "reason"}` — the adapter internally drives **exactly one cheapest image** through its own relay-backed path (`images.v1`, 03 D5/D6), excluded from `capacity` accounting; `reason` is a **closed enum** `{credit_balance_exhausted, key_invalid, project_unfunded, rate_limited, upstream_unavailable, timeout}`; single-flight; result cached 60 s funded / 300 s unfunded; 10 s upstream timeout; error `503 adapter_probe_unavailable` (route not yet implemented by 11.3.5-T1 — the 12.8.3-T3 caller that had to treat this as fail-closed, never a fabricated pass, was dropped by DEC 10.14, so the route has no consumer today), `429 adapter_probe_throttled` + `Retry-After`; no probe fixture is shipped (contract-only, request `{}`). This route proves funding by burning one cheapest image, not a full render job (F-avoidance of a wasted GPU render just to test a key; §10 T67).
3. `render-submit.v1`: envelope, the D3 (`mpt-submit.v1`) field table, adapter-added `n_threads` (F22), `x-task-id` → MPT `request_id` (C3), validation order — (1) key set exactly D3 minus `n_threads`, (2) types/ranges, (3) fixed values; first failing group → 400 `adapter_contract_violation` `errors:[{field,rule}]` (F10).
4. `render-status.v1`: example; `state` ∈ `queued|running|succeeded|failed|cancelled`; the `stage` table **with the observed S3 boundaries** (`queued` 0, `voice` 5–29, `subtitles` 30–39, `images` 40–49, `assembling` 50–99, `checking`, `done`) citing the trace sample; `percent` non-decreasing, 100 only terminal; terminal `output`/`check`/`images` shapes; the never-in-a-status list (F11) · lost rule (F06/C9) · capacity 429 `adapter_capacity_full` + `Retry-After: 30` (F07/C10) · cancel + cleanup (204 / 409 `adapter_task_busy`, image-plan release, 03 D5/D12) (F08/C11) · idempotency (`render_job_id` + body sha256 → 202/200/409 `adapter_idempotency_conflict`; `task_id` UUIDv7 by the adapter) · `render-node-health.v1` example, `reasons` ⊆ {`mpt_unreachable`, `mpt_unauthorized`, `tts_proxy_not_ok`, `image_relay_not_ok`, `font_missing`, `music_missing`, `disk_low`, `config_mismatch`}, liveness (`/ping` + an authenticated `GET /api/v1/tasks?page=1&page_size=1`), 503 blocks new submits.
5. Outcome table D5 verbatim + the mock mode mapping incl. the new `assembly_failed`, `node_error`, `quality:<check>` (P7/CR-4) · `images` = `images.v1` (03 D5/D6, relay on `127.0.0.1:8091`) and `tts_proxy` = `proxy-health.v1` (04 D8) by reference · `check` = `render-check.v1` (D9), `render-quality.v1` (D10) is the Worker's — the adapter measures, the backend decides (F20).

### `worker-node/contract/README.md` (new, tracked)

Index (`render-node.v1.md`, `mpt-api.md`, `images.md` by pointer, `samples/mpt/`, `fixtures/`, `tools/check_fixtures.py`, the two pinned JSONs) with one owner line per file. **Versioning:** a breaking change (route removed, field removed/retyped, code renamed) → `render-node.v2`, **both** served during migration (11.3.5-T1) with a deprecation note; additive changes stay in v1 with a changelog row. **Changelog:** `date | change | README §10 ruling | fixtures touched` — any D3/D4/D5 change found by the spike becomes a TL ruling in README §10 **first**, then the fixtures, and `render-node.v1.md` cites the ruling id next to the changed line. **Fixture table:** file → what it proves → derived from.

### D14 golden fixtures (24, tracked, in `fixtures/`)

`render-submit.v1.{landscape-vi,portrait-en,no-music}.json` · `render-status.v1.{queued,running-voice,running-images,checking,succeeded,failed-tts,failed-materials,failed-assembly,lost,cancelled}.json` · `render-node-health.v1.{ok,proxy-down,disk-low}.json` · `render-check.v1.{ok,loud,silent,no-subtitles,zero-cues,truncated}.json` · `render-quality.v1.{pass,fail-loudness}.json`.

Values from the T1 samples (S3 succeeded + trace, S5 `failed-tts`, S12 `lost`); the rest derived from D4/D9/D10 and marked in the fixture table. Submit fixtures carry the placeholder `NTS_FIXTURE_SCRIPT` in `mpt.video_script` (never the spike text); hashes are fake but self-consistent.

### `worker-node/contract/tools/check_fixtures.py` (new, stdlib)

Per fixture: parse; `schema` matches the filename prefix; the top-level key set equals the D4/D9/D10 key set **exactly**; enum membership (`state`, `stage`, `outcome.code`, `reasons`); no forbidden content (`video_script` except the placeholder, `terms`, `prompt`, `audio_file`, `subtitle_path`, `materials`, `/Users/`, `/storage/`, `http://` inside a status fixture). `--coverage`: one line per route/code/field named in `render-node.v1.md` with the fixture carrying it, exit 1 on a gap. `--self-test`: a mutated copy must fail. Exit 0 pass · 1 failure (`file: key`) · 2 usage.

## Failure handling and edge cases

| Case | Action |
|---|---|
| The spike contradicts D4/D5 | README §10 ruling **first**, then the fixtures; a renamed code other plans already use goes into the update requests — never renamed silently |
| A fixture cannot be filled from a sample (`checking`, `cancelled`) | derive from D4 + the D9 shape, record the derivation in the fixture table; never add extra keys to explain it |
| mock-mpt still on `mock_contract_violation` | CR-4 not applied → mock-mpt is not gate-ready; note it in the hand-over |
