## Goal

Turn a measured `render-check.v1` into the stored verdict `render_jobs.quality_report` = `render-quality.v1` (D10): the blocking checks in D10's order, the advisory hints, and the exact top-level names 02.8.2's video gate reads (P2, CR-6). Pure Domain code — no DB, no HTTP, no media access (F20). `quality_report.images` is **not** produced here (03.4.2-T1, P3).

## Inputs

- README **D10** (names, check ids/order, thresholds, hints, config prefix), **D5** (`render_quality_failed`, no auto-retry), **D9** (the check object), **P2**, **P3**, **D14** (fixtures, `JsonUnmappedMemberHandling.Disallow`).
- `worker-node/contract/fixtures/render-check.v1.{ok,loud,silent,no-subtitles,zero-cues,truncated}.json` and `render-quality.v1.{pass,fail-loudness}.json` (05.4.1-T2).
- `RenderCheckV1` field semantics from 05.5.1-T1; the `Aspect` enum from 05.1.2-T1 (`render-params.v1`) ⚠️ confirm the type name; 09.1.1-T1's solution layout ⚠️ (paths below are relative to it).

## Design

**Types.**

Images` |
| `Domain/Rendering/Quality/RenderQualityPolicy.cs` | `sealed record RenderQualityPolicy` + `IValidateOptions<RenderQualityPolicy>`: `MaxDurationDrift 0.05`, `MinLufs -16`, `MaxLufs -14`, `MaxTruePeakDbtp -1.0`, `MaxLongestSilenceSeconds 10`, `MinSubtitleCoverage 0.50`, `MinCues 1`, `SyncSuspectHintShare 0.10`, `PolicyVersion 1` — bound from config section `RenderQuality`; ranges validated at startup |
| `Domain/Rendering/Quality/RenderExpectations.cs` | `sealed record RenderExpectations(Aspect Aspect, bool SubtitlesEnabled, bool MusicSelected)` (`MusicSelected` = `render-params.v1.music != null`, T12) |
| `Domain/Rendering/Quality/QualityCheck.cs` | `sealed record QualityCheck(string Id, double? Value, double? Threshold, bool Pass)` |
| `Domain/Rendering/Quality/RenderQualitySubtitles.cs` | `sealed record RenderQualitySubtitles(int Cues, double CoverageShare, double SyncSuspectShare, int LongCues, bool? TextMatchesScript)` |
| `Domain/Rendering/Quality/RenderQualityEvaluator.cs` | `public static class RenderQualityEvaluator` with `public static RenderQualityReportV1 Evaluate(RenderCheckV1? check, RenderExpectations expect, RenderQualityPolicy policy)` |

Pure and total: a `null` check, a missing `output`, or a `null` metric never throws — the affected check is `pass = false` (fail closed, P2). No `CancellationToken`, no `ErrorOr`: nothing async or fallible by design (Domain has no EF).

**Flat fields (D10):** `DurationSec = check.Container.DurationS`, `TtsDurationSec = check.Narration.DurationS`, `IntegratedLufs = check.Loudness.After?.IntegratedLufs ?? check.Loudness.Before.IntegratedLufs` ([INFERENCE]: with `--normalize` the after-value is the verdict), `TruePeakDbtp` likewise, `Width/Height = check.Video.Width/Height`, `SubtitlesPresent = check.Subtitles.Present`, `Sha256 = check.Output?.Sha256 ?? check.Input.Sha256`, `Normalized = check.Output?.Normalized ?? false`. `Subtitles.SyncSuspectShare = SyncSuspect ÷ Max(Cues, 1)`; `TextMatchesScript` nullable (`null` when 05.5.1-T1 wrote `script_missing`).

**Checks, in D10's order** (each returns `QualityCheck(id, value, threshold, pass)`; a skipped check is `pass = true`, `value = null`):

| id | value | threshold | fails when |
|---|---|---|---|
| `container_valid` | `errors.Count` | 0 | any `errors` (incl. `container_invalid`, `audio_silent`, timeouts) |
| `streams` | codec pair | `h264` + `aac` | either codec differs or a stream is missing |
| `resolution` | `"{width}x{height}"` | `1920x1080` landscape / `1080x1920` portrait | mismatch |
| `duration` | `Abs(duration_sec − tts_duration_sec) ÷ tts_duration_sec` | `MaxDurationDrift` 0.05 | value > threshold **or** `tts_duration_sec` null (F17) |
| `loudness` | `IntegratedLufs` | `[MinLufs, MaxLufs]` | value < −16 or > −14 (both ends inclusive pass) |
| `true_peak` | `TruePeakDbtp` | `MaxTruePeakDbtp` −1.0 | value > threshold, or null |
| `silence` | `Silence.LongestS` | 10 s | value > threshold |
| `subtitles_present` | `cues` | `MinCues` 1 + `zero_duration == 0` + `coverage_share ≥ 0.50` | any of the three, or `Present == false`; **skipped** when subtitles are off |
| `subtitle_text` | `TextMatchesScript` | `true` | `false` or `null`; **skipped** when subtitles are off |

`Pass = checks.All(c => c.Pass)`. `hints`, in order: `subtitle_sync_suspect` when `SyncSuspectShare > SyncSuspectHintShare`, `subtitle_cues_long` when `LongCues ≥ 1`, `loudnorm_dynamic` when the check's `warnings` contains it, `music_none` when `MusicSelected = false` (T12).

**`images` merge (P3, CR-3).** The evaluator returns `Images = null`. 09.6.3-T2's ingest (the only writer; 09 W2 CR-12) sets it from 03.4.2-T1's `images.v1` **in the same transaction** that writes `quality_report`. 05.5.1 never writes `quality_report.images`.

**Outcome mapping (D5, CR-3).** `pass = false` → the ingest ends the job `failed` with `error_code = render_quality_failed`, **no** auto-retry (a deterministic output fails again); `pass = true` continues to the normal success path. This task owns the verdict; 09.6.3-T2 owns the state transition (09 W2 CR-12).

**Contract notes.** CR-3: 09.6.3-T2 calls `Evaluate` and stores the result (09 W2 CR-12). CR-6: 02.8.2's `plan.md` §3.2 field names are confirmed against this DTO; its new check 10 (`subtitle_sync`) reads our `subtitle_sync_suspect` hint.

## Steps

1. Add the DTOs (`JsonNamingPolicy.SnakeCaseLower`, `JsonUnmappedMemberHandling.Disallow`); make the two `render-quality.v1.*` fixtures round-trip first — they pin the names.
2. Add `RenderQualityPolicy` and its options-validation test.
3. Implement the nine checks in D10 order as private static helpers, then `Evaluate` assembling the report.
4. Implement the hints in order; round-trip every `render-check.v1.*` fixture and assert the `ok` → pass, `loud` → fail-`loudness` verdicts.
5. Wire `AddOptions<RenderQualityPolicy>().BindConfiguration("RenderQuality")` + validation in 09.1.1-T1's DI extension ⚠️; no EF, no HTTP.
6. Post the `Evaluate` signature and the check-id list on `hub` for 09.6.3-T1 and 02.8.2-T1 (CR-3, CR-6).

## Failure handling and edge cases

- Missing `check` (adapter never returned one) → `Evaluate(null, …)` → `Pass = false`, every check `pass = false, value = null`, `hints = []` (fail closed, P2).
- `check.Narration.DurationS == null` (05.5.1-T1's `audio_missing`) → `duration` check fails, never divides by zero.
- `Subtitles.TextMatchesScript == null` (`script_missing` warning) → `subtitle_text` fails, not skipped (only `SubtitlesEnabled == false` skips it) — [DECISION] here, since D10 does not name this case explicitly.
- A future `errors` code not yet in D9's list still fails `container_valid` (the check counts `errors.Count`, not a fixed set).
- `Images` stays `null` if 09.6.3-T1 never sets it — the field is nullable by design, not an evaluator bug.
- A policy config outside its declared range (e.g. `MinLufs > MaxLufs`) fails DI validation at startup, never at evaluation time.

## Notes

- `RenderQuality:*` key names are [INFERENCE] beyond the `RenderQuality` prefix README gives; renaming here is free before 09's config binding lands.
- Thresholds marked [target] in D10 (loudness band, silence, coverage, sync-suspect share) come back from 05.2.1-T1 / 05.5.2-T1 as a config change, not a code change — that is the point of keeping them in `RenderQualityPolicy`.
- Implementation notes (2026-10-01, 05.5.1-T2):
  - **Placement deviates from the Design table, with a reason.** The Domain assembly may reference
    `ErrorOr` only (09.1.2-T1 allow-list, `Domain_ReferencesOnlyErrorOr`), so `RenderQualityPolicy`,
    `RenderExpectations`, `QualityCheck`, `RenderQualitySubtitles` and `RenderQualityEvaluator` live in
    `src/NightTales.Application/Rendering/Quality/`; `RenderQualityReportV1` stays at the specified
    `Application/Abstractions/Rendering/`. `RenderCheckV1` is **11.3.5-T1's** file (11 README D4 gives
    the contract project to it and lists 05.5.1-T2 as the type's owner): this branch carries a
    byte-identical copy of `RenderCheckV1.cs`, `RenderNodeJson.cs` and
    `UtcDateTimeOffsetJsonConverter.cs` from that branch and reads/writes every render document through
    `RenderNodeJson.Strict` — there is no separate options type here. `RenderQualityPolicyValidator`
    (`IValidateOptions<…>`) and the `RenderQuality` binding live in
    `src/NightTales.Infrastructure/DependencyInjection/` + the Worker root, because
    `Microsoft.Extensions.Options`/`IConfiguration` are not in the Application allow-list either.
  - **Encoded check values follow the D14 fixtures, not the value column of the Design table.** The
    fixtures are the contract artefacts and the acceptance requires `Assert.Equivalent` reproduction:
    `container_valid`/`streams`/`resolution` encode their verdict as `1`/`0` against a threshold of `1`,
    `subtitles_present` carries the cue count, `subtitle_text` the boolean, `loudness` the integrated
    value against the band's top. `duration`'s drift is stored rounded to 4 decimals and
    `subtitles.sync_suspect_share` to 3, which is what `render-quality.v1.*` contains.
  - **`render-check.v1.loud` vs `render-quality.v1.fail-loudness`.** The loud fixture gained the D9
    `loudnorm_dynamic` warning on 2026-09-27 (contract changelog), after the pinned report was written;
    D10 turns that warning into one more advisory hint, so `Loud_fixture_fails_loudness_only` compares
    every field against the pinned report with that one hint added.
- QA rework (2026-10-02, fixes D1–D6): non-finite `RenderQuality:*` doubles now fail startup validation by key (D1), `"warnings": null` no longer throws and raises no hint (D2), a report whose input and output both lack a sha256 fails closed (D3), the sync-suspect hint compares the raw quotient while the stored share stays rounded to 3 (D4), a non-finite measure is read as `null` so `RenderNodeJson.Strict` always serialises (D5), and the dead `Microsoft.Extensions.Options` using in `RenderQualityPolicy.cs` is deleted (D6).
