## Goal

Two real trial renders — **L1** (vi ghost story, 5 min, landscape) and **L2** (en ghost story when 04 O2 has launched en, otherwise a second vi ghost story; 5 min, landscape; T14) — measured end to end (check + policy + ratings + wall time), so that Gate 1's M0 exit criterion (README §7) and 03.3.1-T1's token measurement (F24) have real renders to work from. This task does **not** design the SRT thresholds (05.2.1-T1) or the checker's C# policy (05.5.1-T2) — it applies D10 **by hand** with a stdlib mirror and records where the numbers land.

## Design

**Run plan (2 renders, F24-compliant).**

| Run | Lang | Aspect | Length | Story source | Voice | Preset | Music |
|---|---|---|---|---|---|---|---|
| L1 | vi | landscape | 5 min | 02.1.3-T0 harness (ghost) | 04.2.2-T1 vi pick | `landscape@1` (D6) | D8 rule, by hand |
| L2 | en | landscape | 5 min | 02.1.3-T0 harness (ghost, en) | best-rated en id (04 O2) | `landscape@1` | D8 rule, by hand |

L2 is en **only if** 04 O2's launch condition holds: best en voice mean naturalness ≥ 3.0 (measured in 04.2.1-T1). If not, L2 becomes a **second vi ghost story** (5 min, landscape, another harness story, same voice rules), the decision is recorded (`en-skipped: naturalness <3.0, see 04.2.1-T1`), and 03.3.1-T1 still gets two landscape runs (T14). The en subtitle rating then does not apply.

**Submit fields.** Exactly D3's `mpt-submit.v1` object, built by hand for `mpt_client.py`'s run spec (JSON: story text, terms list, aspect, voice, preset, music); same fields 03.3.1-T1 needs for L1/L2 (`video_clip_duration=10`, `video_concat_mode=sequential`, `match_materials_to_script=true`, `video_source=openai_image`) — this is the hand-over CR-5 in the 03 plan names.

**Music choice (D8, by hand).** Ghost topic → moods `{dark_ambient, suspense}`; pick one `active` track from `seed/music-tracks.v1.json` whose moods intersect and whose `platformScope` allows `youtube`/`any`; `bgm_type=custom`, `bgm_file=<file>`, `bgm_volume=<track.bgmVolume>` (or `bgm_type=""` for "no music" as a deliberate variant if the owner wants to compare). Record the chosen `track_id` in `run.json` (there is no sheet column for it — see plan.md §10 open items).

**Post-render pipeline.**

1. `RUN_ID="$(trial/tools/start_run.sh <lang> landscape "<ghost topic>" 5 --status trial --voice "<voice_id>" --story-source plan02)"` (the 01.3.1-T3 CLI as recorded in 01.2.2-T6: positional `<lang> <aspect> "<topic>" <target_minutes>`) writes `$NTS_HOME/current_run`, starts the RSS sampler and prints only the run id; the usage tap (01.3.1-T2) must already be running.
2. `mpt_client.py submit --spec <run-spec.json>` posts the D3 body, saves the submit body to `$NTS_HOME/runs/<run_id>/submit-body.json` (05.4.1-T1; never under the tracked `trial/runs/`, it holds the script; T11).
3. `mpt_client.py poll --task-id <id> --timeout 3600 --trace "$NTS_HOME/runs/<run_id>/trace.jsonl"` until terminal (a `poll_timeout` is resumed with the same command, never re-submitted, D15 P7); `mpt_client.py download` fetches `final-1.mp4`, `subtitle.srt`, `audio.mp3`, `script.json` into `$NTS_HOME/runs/<run_id>/` (T2).
4. `uv run --no-project --python 3.12 worker-node/checks/render_check.py run --task-dir "$NTS_HOME/runs/<run_id>" --aspect landscape --subtitles on --normalize --out "$NTS_HOME/runs/<run_id>/render-check.json"`; record its wall time (NFR-05-1 input, `render_check` wall time separate from MPT wall time).
5. `trial/tools/apply_quality_policy.py --check "$NTS_HOME/runs/<run_id>/render-check.json" --aspect landscape --subtitles-enabled` — a small **stdlib mirror** of D10 (same nine checks, same thresholds, same hint rules) that prints the `render-quality.v1`-shaped verdict to `$NTS_HOME/runs/<run_id>/render-quality.json`. [DECISION here] This script is a manual mirror only; the **C# `RenderQualityEvaluator` (05.5.1-T2) is normative** — any discrepancy found later is a TL ruling, not a silent fix to this script.
6. `finish_run.py --run-id <run_id>` appends the sheet row (01 D8: 58 columns, incl. `subtitle_detected_language` col 51, `total_wall_seconds` col 23) and closes the tap window.

**Native ratings (owner action, not automated).** vi: the owner **and** one other native speaker each watch L1 once on a phone and once on a desktop, rate voice naturalness and subtitle readability **1–5** independently; **≥ 4/5 required on both axes, both viewers, both devices** for the gate. en (only if L2 exists): one fluent listener rates en subtitles ≥ 4/5. Ratings are written to `trial/m0-trial/ratings.csv` (`run_id, rater, device, axis, score, note`; `rater` is a pseudonymous id `R1`, `R2`, … — the name mapping stays in `$NTS_HOME/m0-trial/raters.csv`, D15 S8), not the 58-column sheet (ratings are not per-column facts, they are per-viewing).

**Measurements recorded (beyond the sheet).** NFR-05-1 input = **Mac** wall time only (`total_wall_seconds`, col 23) plus the per-stage split per output minute from the `--trace` ticks (voice, subtitles, images, assembling) — the GPU figure belongs to plan 11 (D15 P7). `render_check` wall time and `--normalize` wall time (from 05.5.1-T1's own step 6) go into `trial/runs/<run_id>/metadata.json` (no sheet column exists, plan.md §10 open item). Loudness before/after (from `render-check.json`) and the chosen `bgmVolume`/`MusicBedLufs` (by-ear tuning: play the render, judge whether the music masks or disappears under narration; a ± 3 dB adjustment to `MusicBedLufs` is a **TL ruling**, not a silent config change, since it touches every track's `bgmVolume`, D8). Detected language comes straight from sheet col 51.

**Artefacts.** `trial/runs/<run_id>/` (metadata, `render-check.json`, `render-quality.json` — **no media, no submit body, no script**; `final-1.mp4`, `subtitle.srt`, `submit-body.json` stay in `$NTS_HOME/runs/<run_id>/`, T11). `trial/m0-trial/ratings.csv` (tracked). `trial/m0-trial/README.md`: one page for Gate 1 — run table (id, lang, cost, wall time, quality verdict pass/fail per check, rating scores), open issues, the L2 skip decision if applicable.

**Hand-over to 03.3.1-T1.** Post the two (or one) run ids on `hub`, plus confirmation that the submit body used D3's fields (03.3.1-T1's step 1 checks this). 03.3.1-T1 reads the same `trial/runs/<run_id>/openai_usage.jsonl` (tap) for token rows and skipped-image counts — nothing new is written for it here beyond the run existing and being tagged `trial`.

## Steps

1. Confirm 04 O2's en gate result from 04.2.1-T1 (naturalness ≥ 3.0?) and decide whether L2 is en or a second vi story (T14) before spending anything.
2. Pick the vi voice (and en voice if applicable) from 04.2.2-T1's catalog rev 1; pick the music track by the D8 mood rule; write the run spec JSON for L1 (and L2).
3. Write `trial/tools/apply_quality_policy.py` (stdlib, mirrors D10) and self-test it against the `render-check.v1.*` fixtures from 05.4.1-T2, asserting the same verdicts as `render-quality.v1.{pass,fail-loudness}`.
4. Run the L1 pipeline (steps 1–6 of §Design); watch and rate it (owner + 1 native, 2 devices, 2 axes).
5. If L2 applies, repeat step 4 for en with 1 fluent-listener rating on subtitles.
6. Fill `trial/m0-trial/README.md` and `trial/m0-trial/ratings.csv`; record NFR-05-1's Mac wall-time input and the render-check timings.
7. Post the run ids to `hub` for `Plan05QualityTrial`'s own downstream note and for 03.3.1-T1 / 05.2.1-T1 to pick up.

## Tests

No permanent automated tests — this is a one-off measurement task. The only reusable artefact is `apply_quality_policy.py`, whose `--self-test` (against the D14 fixtures) **is** its test and is run again by anyone reusing it before M1's C# evaluator supersedes it.

## Failure handling and edge cases

- `render-quality.json.pass = false` on a check → **fix the cause and re-render** (wrong preset, wrong music gain, a real whisper failure) and count the attempt in the README table; never hand-edit `render-check.json`/`render-quality.json`/the sheet row.
- MPT task fails outright (`failed_stage`) → record it as a `run_status = failed` sheet row (01 D8's `run_status` enum) and re-run with the same spec; do not silently retry more than twice without a TL note.
- Native rater unavailable → block this task's rating-dependent acceptance checks (`todo block`), keep the render and its measured numbers, resume when a rater is found; do not substitute a lower rater count.
- en naturalness borderline (close to 3.0, ⚠️ on 04.2.1-T1's own confidence) → L2 = second vi story, record the exact number and flag it for the TL as a possible re-check after more en voice data.
- Tap not running when the run started → the run id is unattributed (01 D10); abort and restart the run with the tap up — a trial run with no tap coverage cannot feed 03.3.1-T1 or the cost columns.
- Music track with no candidate for the topic's moods → `MusicSelector`'s null case (D8): use `bgm_type=""` and record `music_none` in the README, do not force an unrelated track.
