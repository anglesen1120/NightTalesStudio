## Goal

`POST /api/v1/channels/youtube/connect` mints a single-use `state` + PKCE verifier (10 min, bound to the caller's session family and the active OAuth client) and returns Google's authorization URL; `GET /api/v1/channels/youtube/callback?code&state` authenticates **without any bearer token** — by atomically claiming that state row — exchanges the code with the client pinned to the state, and answers a `302` to one of two fixed relative paths. Both routes are behind `RequireFeature("youtube_publish")`; connect additionally requires a ≤ 5 min re-auth and a current legal acceptance.

**`ConnectYouTubeHandler`** (order = UC1 in `plan.md` §4, each failure before any write):

```csharp
public async Task<ErrorOr<ConnectYouTubeResponse>> Handle(ConnectYouTubeCommand cmd, CancellationToken ct)
{
    // 1. Platform.TryParse(cmd.Platform)            → Error.NotFound("not_found")           (404)
    // 2. IReauthGuard.RequireRecentAsync(TimeSpan.FromMinutes(5), ct)                       (401 reauth_required)
    // 3. ILegalAcceptance.EnsureCurrentAsync(_currentUser.UserId, ct)                       (409 legal_acceptance_required)
    // 4. _resolver.ResolveAsync(_resolver.ActiveClientId, ct)                               (503 oauth_client_secret_unavailable)
    // 5. purge: DELETE FROM oauth_states WHERE user_id = @u AND (used_at IS NOT NULL OR expires_at <= now)
    // 6. state    = WebEncoders.Base64UrlEncode(RandomNumberGenerator.GetBytes(32));
    //    verifier = WebEncoders.Base64UrlEncode(RandomNumberGenerator.GetBytes(32));        // 43 chars
    //    nonce    = WebEncoders.Base64UrlEncode(RandomNumberGenerator.GetBytes(32));        // YR10
    //    error = OAuthState.Create(..., _tokenIssuer.HashToken(state), _protector.Protect("oauth.v1", verifier),
    //                              _tokenIssuer.HashToken(nonce), client.ClientId, _currentUser.SessionId,
    //                              now, TimeSpan.FromMinutes(o.OAuthStateMinutes));
    // 7. _db.Add(state); await _uow.SaveChangesAsync(ct);
    // 8. url = _youTube.BuildAuthorizationUrl(client, new(o.RedirectUri, o.Pkce), state, PkceChallenge(verifier));
    //           → https://accounts.google.com/o/oauth2/v2/auth?client_id&redirect_uri&response_type=code
    //             &scope=<two URIs, space-joined>&access_type=offline&prompt=consent
    //             &include_granted_scopes=false&state&code_challenge&code_challenge_method=S256
    // 9. return new ConnectYouTubeResponse(url, state.ExpiresAt, nonce);   // endpoint sets the cookie, body drops it
}
```
The `state` and `verifier` exist only in local variables and in the response URL; the log line carries `userId`, `oauthClientId`, `expiresAt` (`{state:redacted}` is unnecessary because nothing logs the query). `PkceChallenge` = `WebEncoders.Base64UrlEncode(SHA256.HashData(Encoding.ASCII.GetBytes(verifier)))` (RFC 7636 S256). With `Pkce = false` (the F12 fallback) steps 6/8 omit the verifier column write and the two PKCE parameters — the switch exists so the fallback is a config change, not a code edit.

**`CompleteYouTubeConnectHandler`** — **two `IUnitOfWork` boundaries and a success-typed outcome** (the 09.3.2-T1 `ReauthOutcome.Failed` / WT29 pattern: a handler-level `ErrorOr` error rolls the whole transaction back on 09 D5, which would undo the claim). The command therefore never returns an error; the endpoint maps the outcome to the fixed 302.

*Unit of work #1 — the claim (must commit on its own).* Raw SQL, atomic, no tracked entity (the 09.3.2-T1 rotation precedent, `09.3.2-T1-login-refresh-logout.md:116-124`):

```sql
UPDATE oauth_states SET used_at = @now
WHERE state_hash = @hash AND used_at IS NULL AND expires_at > @now
RETURNING id, user_id, platform, code_verifier_protected, oauth_client_id, refresh_family_id;
```
`await _uow.SaveChangesAsync(ct)` commits it **before** any Google call, so a replay of the same callback can never claim the row again, whatever happens next. A crash between the two units burns the state and creates nothing: the user restarts the connect (a burned state is harmless, a replayable one is not).

*Unit of work #2 — the connect (rolled back as a whole on any failure).*
1. No claimed row, **or no `__Host-nts_oauth` cookie on the request** (YR10) → `StateInvalid` — one outcome for unknown/expired/already-used/foreign states and for a callback from another browser.
2. The cookie value hashed with `ITokenIssuer.HashToken` must equal the row's `browser_nonce_hash`, compared with `CryptographicOperations.FixedTimeEquals` (09 BD16) → mismatch (the user started the connect in another browser/tab profile) → `StateInvalid`; the row is already claimed, so the state is spent (YR10).
3. `error=access_denied` (Google denied, no `code`) → `Denied`; the claim has already burned the state.
4. Family liveness by **reuse of the signed port**: `_refreshTokens.GetReauthStateAsync(row.refresh_family_id, ct)` (`IRefreshTokenService`, `09.3.2-T1-login-refresh-logout.md:65,67`; `ReauthState(DateTimeOffset? ReauthenticatedAt, int ReauthAttempts, bool Revoked)`) → `Revoked == true` → `StateInvalid`. Residual: that member carries no `expires_at`, so a family that *expired* (absolute/idle) without a revoke still reads `Revoked == false`; the state's own 10-minute TTL plus the ≤ 5-minute re-auth at connect bound the window, and no second session read/table access is added (Notes).
5. `_protector.TryUnprotect("oauth.v1", row.code_verifier_protected, out var verifier)` → false → `StateInvalid` (never a stack trace, A4).
6. `_resolver.ResolveAsync(row.oauth_client_id)` — the **state's** client, never `ActiveClientId` (D5/F19) → failure → `ExchangeFailed`.
7. `_youTube.ExchangeCodeAsync(client, code, verifier, redirectUri, ct)` → failure → `ExchangeFailed`; a missing `refresh_token` in the response → `ExchangeFailed` (offline access is required, D2).
8. `_youTube.GetMyChannelAsync(tokens.AccessToken, ct)` → no channel → `ExchangeFailed`.
9. 06.1.2-T2's `IConnectChannelConnection.ConnectAsync(...)` joins **this** unit: it loads the row `FOR UPDATE` first, inserts or `Reconnect`s (protecting the tokens under the **existing** connection id and re-pinning `oauth_client_id` to the state's client — YR11), `last_verified_at = now`; `23505` on `ux_channel_connections_account` → `ChannelAlreadyConnected` (its own unit rolls back, the victim row is untouched).
10. On `Connected` only: `IAuditWriter.Write(...)` — action `publishing.channel_connected`, `subject_user_id = actor_user_id = row.user_id`, `data = { platform, oauthClientId, externalAccountId, reconnected }`, `ip`/`user_agent` from the request (the 09.7.2-T1 precedent for an anonymous GET that writes its own audit row, `09.7-video-review-storage/plan.md:235`); then the outbox row `channel_connection_changed.v1`; then `IEmailSender.QueueAsync` (06.1.2-T2 owns the template; `[NotAudited]` on the command is deliberate — a pipeline audit would fire on the failure outcomes too).
11. Any failure inside unit #2 rolls it back **entirely** — no connection row, no audit row, no outbox row, no `email_messages` row — while unit #1 stays committed, so the state is `used_at NOT NULL` and the code is never retried. Endpoint mapping: `Connected` → `302 /channels?connected=youtube`; the four other outcomes → `302 /channels?error=<wire>`; both targets are constants and no outcome text reaches the `Location` header. The endpoint clears the cookie (`__Host-nts_oauth=; Max-Age=0; Path=/; Secure; HttpOnly; SameSite=Lax`) on **every** outcome, before the redirect (YR10).

### Endpoints (`src/NightTales.Api/Http/PublishingEndpoints.cs`, group `/api/v1`, 09 D14)

```csharp
channels.MapPost("/channels/{platform}/connect", ConnectYouTube)
    .RequireAuthorization().RequireRateLimiting("auth").RequireFeature("youtube_publish");
channels.MapGet("/channels/{platform}/callback", CompleteYouTubeConnect)
    .AllowAnonymous().RequireRateLimiting("auth").RequireFeature("youtube_publish");

// connect: the endpoint maps the handler's BrowserNonce to the cookie and serialises the wire body WITHOUT it
static void SetOAuthNonce(HttpResponse r, string nonce) => r.Cookies.Append("__Host-nts_oauth", nonce, new CookieOptions
{ HttpOnly = true, Secure = true, SameSite = SameSiteMode.Lax, Path = "/", MaxAge = TimeSpan.FromMinutes(10) });
static string? ReadOAuthNonce(HttpRequest r) => r.Cookies["__Host-nts_oauth"];
```
- Filter order: flag → authorization → rate limit → (`connect` only) `RequireReauth(TimeSpan.FromMinutes(5))` (A5, a thin filter over `IReauthGuard`) — the legal gate is the handler's step 3 so its 409 body carries `errors.documents`.
- The callback sets `Cache-Control: no-store` and `Referrer-Policy: no-referrer` on **both** the 302 and the failure redirects, and uses `Results.Redirect(path)` with a relative path built from a constant — the `code`/`state`/`error` values are never interpolated into `Location`.
- Rate policy `auth` (09 D14) bounds state minting and callback probing; a 429 is a JSON ProblemDetails here even though the route is anonymous.
- Both routes log the query string redacted (`code`/`state` dropped by the 09.9.3-T2 processors); if the processors' key allow-list does not cover `state`, the endpoints must not enable query logging at all — asserted by a test (§Tests). **YR23:** the LB access log for `/api/v1/channels/*/callback` additionally drops the query string at the edge (11.2.2-T1 note, **06 CR-10**) — recorded here as the second, independent line; this folder owns neither the LB config nor the processors.

### Performance (README D18)

- **Connect**: one insert on `oauth_states` plus a bounded purge of the caller's **own** finished rows (`DELETE … WHERE user_id = @u AND (used_at IS NOT NULL OR expires_at <= now())`, served by `ix_oauth_states_user_created`) — no table scan, no unbounded delete, no per-user job.
- **Callback**: the claiming UPDATE is an index probe on `ux_oauth_states_state_hash`; then exactly one token POST, one `channels.list`, one upsert on `ux_channel_connections_account`, one audit insert, one outbox insert and one e-mail insert. No loop over channels, no per-publication work, no N+1; nothing is buffered (the token and channel responses are a few hundred bytes).
- **No lock across the network**: the transaction holds no `FOR UPDATE` while the Google calls are in flight — the state's single-use claim is the concurrency control, and the row-level UPDATE commits as part of the same short transaction. Two Api instances cannot both exchange the same code (the loser sees no row).
- The named `HttpClient` is a singleton with `Timeout = YouTube:Http:TimeoutSeconds` (15), so a stuck Google endpoint cannot pin a request thread past the timeout; the callback performs **no** retry (the code is single-use), which also bounds the work to one attempt.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| `state` unknown / expired / already used / belongs to another user or family | one code, 302 `?error=oauth_state_invalid`, nothing written, response body empty (no oracle) |
| `TryUnprotect` false (wrong purpose, tampered cipher, rotated key ring) | same `oauth_state_invalid`; the protector logs the purpose at `Warning`, never the value (A4) |
| Google returns no `refresh_token` (a silent prior grant) | `oauth_exchange_failed`; D2 sends `prompt=consent` + `access_type=offline` so this should not happen — the check exists because a missing refresh token would silently make the connection unusable after 1 h |
| Google token endpoint 500 / timeout (15 s) | no automatic retry (the code is single-use) → `oauth_exchange_failed`; the user restarts the flow; the state is spent so no replay is possible |
| Google accepts the PKCE parameters but the .NET client sends `code_challenge` with padding | `WebEncoders.Base64UrlEncode` never pads; the PKCE observation in step 9 catches a rejection (F12) |
| `channels.list` 401 right after a successful exchange | `oauth_exchange_failed` (no row): a wrong scope set or an unverified-project channel restriction shows up here, and the staging check from 06.1.1-T1 is the diagnostic |
| The channel fetch returns two channels | take the first and log a warning with ids only — `mine=true` returns the authenticated account's channel, a second one means a Brand Account; a later S-phase settings field chooses (out of P scope) |
| The client secret is unreadable (secret manager down, `ActiveClientId` unset) | 503 `service_unavailable` on connect, `oauth_exchange_failed` redirect on the callback; nothing is logged but the client id |
| Callback reached with `code` but no `state` | `oauth_state_invalid` (the claiming UPDATE cannot match a null hash) — never a 400 that leaks the parameter set |
| Flag turned off while a connect is open | the callback answers 404 `feature_disabled` (the row expires in ≤ 10 min); the user restarts after the flag is on — recorded in `plan.md` §11 |
| Two Api instances claim the same state | the row-level UPDATE is atomic; the loser sees no row → `oauth_state_invalid`; the winner proceeds (the test covers it) |
| The callback arrives in another browser (no cookie, or a cookie from a different connect) | `?error=oauth_state_invalid`, nothing written; the row is already claimed so the state stays spent — the user restarts the connect in the browser they will finish in (YR10; the check is constant-time and one code, no oracle) |
| `__Host-nts_oauth` set over plain `http://localhost` in Development | browsers apply the secure-context exemption to `localhost` and accept the `Secure` cookie ⚠️ unverified per browser; if a browser rejects it, run the connect on the staging https origin rather than weakening `Secure`/`__Host-` (the prefix requires both `Secure` and `Path=/`) |
| The state purge meets a row created in the same millisecond | the purge predicate only removes `used_at IS NOT NULL OR expires_at <= now`, so it can never delete a live state the user just received |

## Notes

- **Family liveness uses an existing port member — no CR.** `IRefreshTokenService.GetReauthStateAsync(Guid familyId, ct) → ReauthState(DateTimeOffset? ReauthenticatedAt, int ReauthAttempts, bool Revoked)` (`09.3.2-T1-login-refresh-logout.md:65,67`) is the read; the callback consumes `Revoked`. No new interface, no raw SQL against `refresh_tokens` and no second session mechanism. Residual (documented, not a defect to fix here): the member has no `expires_at`, so an expired-but-unrevoked family reads `Revoked == false`; the 10-minute state TTL and the ≤ 5-minute re-auth at connect bound that window. If 09 later exposes expiry (or a revocation-on-expiry), this caller switches to it without a contract change.
- [OPEN] The secret-resolution port name (`ISecretStore`/`ISecretProvider` — not pinned anywhere in 09/11; only the `…SecretRef` convention is, `11-worker-deployment/README.md:226`, 09.2.6-T3:109). `ConfigOAuthClientResolver` takes it as a constructor dependency; the name lands in README §10 items.
- **Redirect codes are not catalogue codes (YR5).** `oauth_denied` and `oauth_exchange_failed` exist **only** as the callback's `error` query values (a closed set the UI maps); they are registered in **06 CR-9**, so this folder no longer asks `plans/09-backend-api.md` §5.4 for rows for them. `oauth_state_invalid` and `channel_already_connected` remain the two codes of this folder that are already catalogued (README C6).
- **Browser binding (YR10).** The nonce is 32 random bytes, hashed with `ITokenIssuer.HashToken` (the repo's one hashing helper, A9) and compared with `CryptographicOperations.FixedTimeEquals` (09 BD16) — never `==`. `SameSite=Lax` is required, not cosmetic: the callback is a cross-site top-level GET carrying the cookie, and `Strict` would drop it; `__Host-` additionally requires `Secure` + `Path=/` + no `Domain`. The nonce is independent of the authorization URL and is never serialised.
- **Edge log hygiene (YR23).** The LB access log for `/api/v1/channels/*/callback` drops the query string (11.2.2-T1 note, **06 CR-10**), independent of the app-side 09.9.3-T2 redaction; both are needed because the LB logs before the app ever sees the request.
- [DECISION] No retry on code exchange: an authorization code is single-use and Google's own guidance is to restart the flow; retrying would turn a transient 500 into a burned code.
- **Order matters and is tested**: flag → bearer → rate → re-auth → legal → client resolution. Swapping re-auth and legal would answer 401 where D3 mandates 409, and the SPA's dialog chain depends on it.
- **`IYouTubeClient` is declared once, here, in full** (README D9: one port for every Google call in plan 06). `RevokeAsync(string token, ct) → ErrorOr<RevokeOutcome>` is this task's declaration; `RevokeOutcome { Revoked, AlreadyRevoked }` exists so 06.4.1-T1's retry-with-backoff disconnect can treat a `4xx invalid_token` reply as success (idempotent revoke) without a second interface. **06.4.1-T1 implements the method body inside `src/NightTales.Infrastructure/Publishing/GoogleYouTubeClient.cs` — the class *this task* creates (Outputs above), not 06.1.2-T2 — and must not re-declare the port member.** If its task file still shows its own `IYouTubeClient`/`RevokeAsync` signature or a `Publishing/Google/` subfolder path for the class, that is the stale copy to drop; this file (path and signature) is authoritative. 06.2.3-T1 adds only the upload-half members to the same interface (its own Notes already says "Adopted from 06.1.2-T1, not redeclared").
- `[INFERENCE]` names: `IConnectChannelConnection` (the T1→T2 hand-off port), `PublishingEndpoints`, `PublishingServiceCollectionExtensions`, `YouTube:Http:TimeoutSeconds`, `YouTube:Pkce`, `YouTube:OAuthStateMinutes`, `oauth_client_unknown`/`oauth_client_secret_unavailable`, the `FakeGoogleOptions` shape.
