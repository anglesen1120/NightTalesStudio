## Goal

A `ready` episode with an `active` YouTube connection can be turned into a `Publication` in `awaiting_consent` through `POST /episodes/{id}/publications`, with metadata that YouTube will accept: title ≤ 100 characters, description ≤ 5,000 UTF-8 bytes **after** the render's music attribution is appended, tags counted the way YouTube counts them (commas and implicit quotes), `publishAt` at least the publish lead time ahead. The row carries the ETag `"pu-<xmin>"` that every later consent/cancel/PATCH must echo. The episode detail endpoint stops returning `publications: null` and reports the aggregated publication state from one indexed query.

`Create` sets `Status = AwaitingConsent`, `ContainsSyntheticMedia = true`, `VetoEndsAt = vetoEndsAt`, `AutopilotAuthorizationId`; it does **not** touch the episode (the `ready → scheduled` call is `Episode.MarkScheduled` inside 06.2.2-T1 after consent, D12/F15).

### Value object — `YouTubeMetadataRules`

```csharp
public const int TitleMaxChars = 100, DescriptionMaxBytes = 5000,
                 TagsMaxLength = 500, TagsMaxCount = 15, TagMaxChars = 30;

public static void AppendAttribution(ref string description, string? attribution);
// attribution null/empty → unchanged; else description + "\n\nMusic: " + attribution   (C8, ruling T9)

public static ErrorOr<Success> Validate(string title, string description, IReadOnlyList<string> tags,
    string privacy, DateTimeOffset? publishAt, DateTimeOffset now, int publishLeadMinutes);

public static int TagsLength(IReadOnlyList<string> tags);
// Σ (len(tag) + (tag.Contains(' ') ? 2 : 0)) + (tags.Count - 1)   // G4: commas and implicit quotes count
```

`Validate` (all violations `Error.Validation` with `metadata["field"]`, so 09.1.4-T1's writer produces 400 `validation_failed` + `errors`): title 1–100 chars and no `<`/`>`; description 1–5000 **UTF-8 bytes** (`Encoding.UTF8.GetByteCount`, measured after `AppendAttribution`) and no `<`/`>`; `tags.Count ≤ 15`, each tag ≤ 30 chars, `TagsLength ≤ 500`; `privacy ∈ {public, unlisted, private}` (G6); `publishAt` null or `≥ now + PublishLeadMinutes` (D6). The byte/char mix is the whole point of F08/F09 — the generated-description cap of 1,000 chars (02 D3) is 02's rule and is not re-implemented here.

### YR1 — veto window for autopilot publications

When `AutopilotAuthorizationId is not null`, `Create` receives
`vetoEndsAt = min(now + series.autopilot_settings.veto_window_hours, (publishAt ?? now) − YouTubeOptions.PublishLeadMinutes)`
(02.8.3 creates late videos with a shortened veto, `02.8.3-cadence-publishing/plan.md:146`; `veto_window_hours` 2..48, default 12, `02.8.3/plan.md:56-63`). If that instant is `< now + YouTubeOptions.MinVetoWindowHours`, the command returns 400 `validation_failed` field `publishAt` and writes no row (defence in depth; 02 already treats the slot as missed). Manual publications have `VetoEndsAt = null`. `veto_ends_at` is immutable after create (06.2.2-T3 enforces the same on PATCH).

Handler steps (single UnitOfWork transaction, no external call):

1. `db.Query<Episode>()` owner-scoped (tenant filter) → 404 `not_found` when absent.
2. `Episode.Status == Ready` else 409 `episode_invalid_state` (09.1.4-T1's `ErrorCodes.EpisodeInvalidState`).
3. `db.Query<Connection>()` → `Status == Active` else 409 `channel_not_active` (row must also be the user's own — the filter gives 404).
4. Latest render job: `db.Query<RenderJob>().Where(j => j.EpisodeId == id).OrderByDescending(j => j.Id)` (WT49: no `created_at`), read `params.music.attribution`.
5. `YouTubeMetadataRules.AppendAttribution(ref description, attribution)` **then** `Validate(...)` → 400 `validation_failed` (field keys `title`/`description`/`tags`/`privacy`/`publishAt`) — validation runs against the **submitted** privacy, before any pre-audit override.
6. Autopilot branch: read `series.autopilot_settings.veto_window_hours` (02-owned table, read-only) and apply YR1 → veto window or 400 `validation_failed` field `publishAt`.
7. **Pre-audit branch (D12/C4, advisor-fixed 2026-09-25):** read `YouTubeOptions.AuditStatus` (`IOptionsMonitor<YouTubeOptions>`, D11 — already required for step 6's `PublishLeadMinutes`/`MinVetoWindowHours`, no new dependency). When `AuditStatus != Approved`: stamp `platform_payload.preAudit = true` and `platform_payload.requestedPrivacy = <submitted privacy>`, and store the row's `Privacy` as `"private"` — the enforced/effective value D12 describes ("ends `published` with `privacy = private`") — regardless of what was submitted. When `Approved`: `Privacy` = the submitted value, no stamp written. Deciding this **at create**, not later, is what makes the veto notice (06.2.2-T2, queued moments later in the same request) and the summary/list DTOs agree with the enforced value from the very first read — the original bug was leaving this decision for a later "upload planner" that would run after the notice had already gone out with the wrong preview.
8. `Publication.Create(...)`, `db.Publications.Add`, `await db.SaveChangesAsync` (UnitOfWork opens the transaction in the pipeline; a partial-unique violation is **not** caught here — it surfaces as `DbUpdateException`, which the handler translates to 409 `publication_invalid_state` after checking the index name, so the orchestrator retry is deterministic instead of a 500).
9. `[Audited("publishing.publication_created", data: ids only)]`.
10. Domain event `PublicationUpdated` → outbox `publication_updated.v1 { publicationId, episodeId, userId, status, errorCode: null }` (D13).

public sealed record PublicationsSummary(int Published, int Scheduled, DateTimeOffset? LastPublishedAt);

var summary = await db.Query<Publication>().Where(p => p.EpisodeId == id)
    .GroupBy(_ => 1)
    .Select(g => new PublicationsSummary(
        g.Count(p => p.Status == PublicationStatus.Published),
        g.Count(p => p.Status == PublicationStatus.Scheduled),

## Failure handling and edge cases

- Episode has no render job (or `params` without `music`): attribution is `null`, the description is stored as sent — no error (05 README:332-336).
- `music.attribution` is an empty string: treated as absent (no `Music: ` tail with no value).
- `episodes` row deleted between the read and the insert: FK violation → 404 `not_found` (mapped by the UnitOfWork), not a 500.
- Duplicate create racing two workers: the partial unique is the arbiter; the loser returns 409 `publication_invalid_state` and writes no audit row (the plan maps the exception before the audit step).
- `autopilotAuthorizationId` pointing at a revoked authorization: rejected here with 400 `validation_failed` field `autopilotAuthorizationId` [INFERENCE: 02.8.3-T4's own check is authoritative; this is defence in depth] — the authorization-status read is a 02-owned table read-only lookup.
- Autopilot publication whose `publishAt` is in the past by more than the lead time (late video): the veto collapses to its floor and the create is refused when below `MinVetoWindowHours` (YR1) — the orchestrator records a missed slot, it does not get a silent immediate publish.
- `publishAt` exactly `now + PublishLeadMinutes`: accepted (`>=`).
- Time zone: every comparison uses `IClock` (UTC instants only); no PT-day logic exists in this task (that is `IQuotaLedger`, D10).
- Concurrency: two clients create for two different episodes concurrently — no shared lock, both succeed; the xmin ETag is read after commit via `ToCreatedResult`.
- Migration on a database where `series_autopilot_authorizations` does not exist yet: the FK is declared, so `_06_Publications` must run after 02.8.3-T1's migration (documented ordering in the plan §11).
