## Goal

One port carries every Google call the publishing feature makes, and one implementation talks to Google: `IYouTubeClient` (Application) with `GoogleYouTubeClient` on `Google.Apis.YouTube.v3` 1.76.0.4262 + `Google.Apis.Auth` 1.76.0 (G8, Apache-2.0). The upload half of the port is a **resumable session**: a session URI is created without any content, chunks are streamed from `IBlobStore.OpenReadAsync` in multiples of 256 KB except the last (G7), a probe answers `Complete | Partial(nextByte) | Expired`, and a `404` restarts the session. Access tokens are supplied by the caller (the connection owns them); this task never reads a token from the database. `FakeGoogleServer` gains the matching upload surface so every later task tests against a real HTTP stack instead of a mock.

### Implementation — `src/NightTales.Infrastructure/Publishing/GoogleYouTubeClient.cs`

One service object per call, an `HttpClient` from `IHttpClientFactory` with the per-call timeout from `YouTubeUploadOptions`, and an `AccessTokenInitializer : IConfigurableHttpClientInitializer` that adds `Authorization: Bearer <token>` (the credentials are handed in as a string; nothing is read from storage here).

- `StartUploadAsync`: `length` is the caller's total (`assets.size_bytes`; the nullable `BlobObject.Length` is a cross-check only — F14/CR-18). Create the session **without content**, sending the `VideoInsertRequest` as `snippet,status` with `status.containsSyntheticMedia` and `status.selfDeclaredMadeForKids`, `status.privacyStatus` and `status.publishAt` when non-null (G3/G5), and `Content-Range: bytes 0-0/<total>` so the session knows the size; return the `Location` header as the session URI (G7). ⚠️ the SDK member that creates a session without a content stream is unverified (`InsertMediaUpload.InitiateSessionAsync` per G8's file, not proven); **step 1 spikes it**, and if the SDK cannot do it, this method talks the documented raw protocol on `HttpClient` (`POST {UploadBaseUrl}videos?uploadType=resumable&part=snippet,status`) — the port and every consumer stay identical.
- `ResumeUploadAsync` **contract:** the caller passes the stream already positioned at the resume offset (`UploadStreamPositioning.EnsureAtAsync`, below) and `length` = the object's total; the client reads **from the current position** and its first `Content-Range` starts exactly there (step 1 verifies against the fake that the SDK honours the stream position; if it does not, the raw-protocol path sets it explicitly — G7). Implementation: `ResumableUpload.CreateFromUploadUri(sessionUri, content, uploadOptions)` (G8) with `ChunkSize = ChunkSizeBytes`, `MinimumChunkSize = 256 KB`; `ResumeAsync()` drives the chunk loop, reads the stream **only in chunk-sized reads** and reports `IProgress<long>` with the bytes sent; the returned `VideoId` is parsed from the final JSON body. A `404` on any chunk → `ErrorOr` `SessionExpired`. Transport failure after `MaxChunkRetries` (1/2/4 s + jitter) → `Transport`.
- `UploadStreamPositioning.EnsureAtAsync(Stream stream, long offset, CancellationToken ct)` (`src/NightTales.Application/Features/Publishing/Upload/UploadStreamPositioning.cs`, shipped here, called by 06.2.3-T2): `stream.Seek(offset, Begin)` when `CanSeek`, otherwise discard `offset` bytes in a reused 256 KB buffer (constant memory, no full buffer; AWSSDK.S3 response streams are not reliably seekable — CR-17 requests a byte-range read to remove the discard). A stream that ends before `offset` → `ErrorOr` `SessionExpired` (the object shrank).
- `ProbeUploadAsync`: an empty `PUT` with `Content-Range: bytes */<total>` (G7) — `308` with `Range: bytes=0-N` → `Partial(N + 1)`; `200/201` with a JSON body → `Complete(videoId)`; `404` → `Expired`; anything else → `Transport`.
- `GetVideosAsync`: `videos.list?part=status&id=<csv>`; **the caller batches** (≤ 50 ids, D18: 1 unit per call); maps to `YouTubeVideoStatus`.
- `RefreshAsync`: form POST to `TokenUrl` (`grant_type=refresh_token`, `client_id`, `client_secret`); a body `{"error":"invalid_grant"}` → `ReauthRequired`; `invalid_client`/`unauthorized_client` → `ClientBroken`; `5xx`/timeout → `Transport`.
- `RevokeAsync`: **implemented by 06.1.2-T1** (form POST to `RevokeUrl?token=…`, G9, mapping to `RevokeOutcome.Revoked`/`AlreadyRevoked` for 06.4.1-T1's idempotent disconnect) — listed here only because `GoogleYouTubeClient` is the one shared class; this task adds nothing to this member.
- Every failure builds `YouTubeFailure(reason, status, isTransport)` from the parsed Google error body and returns the matching `YouTubeErrorCodes` constant — the classifier in 06.2.3-T3 turns those into outcomes.
- **Logging:** method name, HTTP status, Google `reason`, elapsed ms, bytes; never the token, the session URI, the title, the description or the response body. The `Location` header is the only header ever read.

## Failure handling and edge cases

- **SDK cannot create a session without content or probe without a stream** → implement `StartUploadAsync`/`ProbeUploadAsync` on the raw documented protocol (G7) over `HttpClient`; the port, the fakes and every consumer are unchanged. Recorded in Notes (step 1).
- **Session URI returned by Google without an `id` (Drive-style `upload_id`)** → the URI is used verbatim (`new Uri(location)`); no assumption about its shape is made anywhere (the URI is opaque to this layer and to 06.2.3-T2, which only encrypts it).
- **Chunk smaller than 256 KB but not the last** → the SDK raises; the client maps it to `Transport` and the job retries the same session, which re-sends the chunk at the stored offset instead of corrupting the video.
- **Stream shorter than `length`** (the asset row disagrees with the object) → the fake's final response carries no `id`; the client returns `Transport` with `bytesSent < length` logged. 06.2.3-T2 fails the publication with `youtube_upload_failed` (a short upload is unrecoverable).
- **`403` with reason `uploadLimitExceeded`** → same branch as `quotaExceeded` (D9 treats both as the daily-limit case; the daily 100-call limit and the 10 000-unit bucket both need the reschedule).
- **HTTP 401 with an expired token** (not a revoked grant) → `ReauthRequired` is **not** returned blindly: the body's reason decides (`invalid_grant`/`unauthorized` → `ReauthRequired`; a plain 401 with no reason → `Transport` so the job retries once instead of marking the connection expired). The classifier (06.2.3-T3) documents the same rule.
- **Clock/expiry** → `OAuthTokens.ExpiresAt` is built from the response's `expires_in` and the injected `IClock`, never from the process clock directly.
- **Huge video (e.g. 2 GB)** → chunking is streamed; `length` is a `long` on every member; no `int` cast exists in the file (asserted by review).
- **`FakeGoogleServer` port already in use** → the fixture binds port 0 and injects the chosen base URL into options (D19), so parallel test classes never collide.
- **Rollback** → the port and the client are additive; deleting the registration leaves the rest of the build intact. No data change, no migration.
