# 06.2.4-T1 — Lead time, `publishAt`, pre-audit mode (omit `publishAt`)

| Story | Size | Area | Depends on | Blocks | Phase / flag |
|---|---|---|---|---|---|
| 06.2.4 | S (0.5) | BE | 06.2.3-T2 | 02.8.3-T3 | P · M1 |

## Goal

Decide the exact `privacyStatus`/`publishAt` that `PublishYouTubeJob` sends to `videos.insert`, from a consented publication's already-fixed `Privacy`/`PreAudit`/`PublishAt`, and persist that decision so the upload job only executes it. This is a **pure, options-free decision** (README ruling **YR3** moved the queue-time/lead-time arithmetic to 06.2.2-T1's `PublicationQueueTime.For`, invoked by 06.2.3-T2's Worker-side outbox handler — not this task): G3 requires `privacyStatus = private` whenever a `publishAt` is sent, so a `publishAt` is included **only** for `Privacy == "public"`, non-pre-audit rows; every other combination (pre-audit, an owner-intended `private` row, catch-up) uploads `private` and omits `publishAt`, and no go-live job is ever scheduled for it ✅ G3, D12, YR2.

## Design

**1. `YouTubeOptions` — not read by this task at all.**
`YouTubeOptions`/`YouTubeOptionsValidator` (`src/NightTales.Application/Abstractions/Publishing/YouTubeOptions.cs`) are **06.1.2-T1's** — they declare `PublishLeadMinutes`, `Poll:*`, `GoLive:*`, etc. This task's decision needs none of them: it only compares `Publication.Privacy` to `"public"` and reads `Payload.PreAudit`/`Publication.PublishAt`. `YouTubeOptions.PublishLeadMinutes` is consumed by 06.2.2-T1's `PublicationQueueTime.For` (YR3) — a different file, a different task.

**2. The pure decision — a Domain function, no interface, no Application-layer port.**
`src/NightTales.Domain/Publishing/Publication.Schedule.cs` (partial; `Publication.cs` is 06.2.1-T1's):

```csharp
public sealed record PublicationUploadPlan(string PrivacyStatus, DateTimeOffset? PublishAt);

public static ErrorOr<PublicationUploadPlan> PlanUpload(PublicationMetadata m, PublicationPayload payload, DateTimeOffset now);
public ErrorOr<Success> ApplyUploadPlan(PublicationUploadPlan plan, DateTimeOffset now);   // CAS on status ∈ {awaiting_consent → scheduled, scheduled}; writes platform_payload.upload only
public bool IsPreAudit => Payload.PreAudit;   // exposed for 06.2.5-T1's go-live gate; never written here
```

```csharp
// PlanUpload's body — pure, no I/O, no options:
if (ConsentAt is null) return Error.Conflict(ErrorCodes.PublicationConsentRequired);   // 409, C6 — existing code (06.2.1-T1)
if (Payload.PreAudit)
    return new(PrivacyStatus: "private", PublishAt: null);                             // D12/YR20: forced at create, permanently read-only here
var wanted = PublishAt;                                                                // the row's own value (YR2: never null just because of pre-audit — pre-audit already handled above)
if (wanted is null || wanted.Value <= now.AddMinutes(1))                               // catch-up / immediate: nothing to schedule
    return new(PrivacyStatus: Privacy, PublishAt: null);                               // send the row's real intended privacy directly
if (Privacy == "unlisted") return Error.Validation(ErrorCodes.ValidationFailed, "publishAt");   // G3 cannot express it — reject (§Notes item 2)
if (Privacy == "private") return new(PrivacyStatus: "private", PublishAt: null);       // TL-fixed: an owner-intended-private row NEVER gets publishAt —
                                                                                        // sending it would let YouTube auto-publish a video marked private
return new(PrivacyStatus: "private", PublishAt: wanted);                               // only Privacy == "public" reaches here: G3 requires private+publishAt;
                                                                                        // YouTube itself promotes it to public at that instant
```

`ApplyUploadPlan` writes **only** `platform_payload.upload = { privacyStatus: plan.PrivacyStatus, publishAt: plan.PublishAt, preAudit: Payload.PreAudit }` through 06.2.3-T2's `PublicationPayload.With(...)` helper (CR-15, additive keys only) — `upload.preAudit` is a plain copy of the already-immutable top-level `Payload.PreAudit`, kept because 06.2.3-T2's own acceptance test builds and reads `upload = { privacyStatus, preAudit }` together (`06.2.3-T2:160`); it is never a second writer of the canonical flag. `ApplyUploadPlan` never touches `Privacy`, `requestedPrivacy` or the top-level `preAudit` itself (06.2.1-T1's create-time stamp). It still touches `updated_at` (the D7 ETag `"pu-<xmin>"` — CR-2 — must move, so 10.4.3-T2 can never consent to a plan it did not read). No new column, no migration (D20 keeps `_06_Publications` with 06.2.1-T1). `PublishYouTubeJob` reads `platform_payload.upload` **verbatim** to build `VideoInsertRequest` — it never re-derives `PrivacyStatus`.

**3. Sticky for the row, recomputed (not corrected) for the request.** `Privacy`/`requestedPrivacy`/top-level `preAudit` never change after create, so this decision and `PublishYouTubeJob` naturally never publish an unaudited or owner-marked-private slot regardless of when they run. `upload.PrivacyStatus`/`PublishAt` **are** recomputed each time `PlanUpload` runs, but from the same immutable inputs every time — a re-plan of the same row (e.g. after a `PATCH`, which per YR20 is blocked from touching `Privacy` on a pre-audit row anyway) yields the same output for the same `Privacy`/`PreAudit`/`PublishAt`, so nothing is ever "corrected", only recomputed consistently.

**4. No wiring, no scheduler call — `IPublishScheduler` never shipped (YR3).** An earlier draft of this task assumed an `IPublishScheduler.EnqueueAtAsync` port existed and that this task would call it. It does not exist: the Api never enqueues (its `IJobScheduler` registration throws); the actual mechanism is 06.2.3-T2's Worker-side `PublicationScheduledForUploadHandler`, an `IOutboxHandler<PublicationUpdated>` that reacts to the **ordinary** `publication_updated.v1` event on a transition to `scheduled` (already fired by 06.2.2-T1's/06.2.2-T3's consent command, D13 — no new field), re-reads the row, and calls `IJobScheduler.Enqueue`/`Schedule<PublishYouTubeJob>` at `06.2.2-T1`'s `PublicationQueueTime.For(publishAt, PublishLeadMinutes, now)`. This task's only integration point is: whichever consent command transitions the publication to `scheduled` must call `PlanUpload` + `ApplyUploadPlan` **in the same transaction**, before that transaction commits (so `platform_payload.upload` is populated by the time `PublishYouTubeJob` — or its precursor handler — reads the row). No forward edit into 06.2.2-T1's file is needed for scheduling; only for calling `PlanUpload`/`ApplyUploadPlan`, coordinated with its owner (§Notes).

## Steps

1. Add the `upload` key (`{ privacyStatus, publishAt, preAudit }`, three fields — `preAudit` a copy of the top-level flag, per 06.2.3-T2's verbatim-read contract) to 06.2.3-T2's `PublicationPayload.With(...)` helper and its JSON mapping in `PublicationConfiguration.cs` (additive, one writer); assert the round-trip with a persisted row in an integration test. `Privacy`/`requestedPrivacy`/top-level `preAudit` are 06.2.1-T1's create-time keys — not touched here.
2. Add `Publication.Schedule.cs` (`PlanUpload`, `ApplyUploadPlan`, `IsPreAudit`) — pure Domain, no `IOptionsMonitor`, no interface — with the CAS transition `awaiting_consent|scheduled → scheduled`.
3. Coordinate with `06.2.2-T1`'s owner: its consent/`PATCH` handler calls `PlanUpload` + `ApplyUploadPlan` in the same transaction as the `scheduled` write (before the transaction's `publication_updated.v1` fires); no scheduler call is added there or here (YR3).
4. Tests (below) + one `psql` check on a plan row.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| `publishAt` in the past (worker downtime, catch-up) | `PublishAt = null` in the request, `PrivacyStatus = Privacy` (no scheduling needed); the poller resolves the status (06.2.5-T1); no go-live job |
| `publishAt` exactly `now + 1 min` | same catch-up branch: an upload takes minutes, so an "early" lead of ≤ 1 min is meaningless |
| no `publishAt` at all (immediate publish) | `PrivacyStatus = Privacy`, `PublishAt = null`, no go-live job |
| `Privacy == "public"`, `publishAt` in the future, not pre-audit | `PrivacyStatus = "private"`, `PublishAt = publishAt` (G3: scheduling requires private); YouTube itself flips it to public at that instant |
| `Privacy == "private"`, `publishAt` in the future | `PrivacyStatus = "private"`, `PublishAt = null` (TL-fixed): the request never carries the `publishAt`, so YouTube can never auto-publish a video the owner marked private; no go-live job is scheduled for this row (06.2.5-T1 keys off `upload.publishAt`, not the raw row value) |
| audit not approved at create time (pending/rejected) | row already `Privacy = private`, top-level `preAudit = true` — **06.2.1-T1's stamp** (YR20); this task's plan sends `PrivacyStatus = "private"`, omits `publishAt`, and never re-checks `AuditStatus` |
| `AuditStatus` flips to `approved` after create, before or during upload | **no effect on the row** — `Privacy`/`requestedPrivacy`/top-level `preAudit` are permanently read-only after create (D12, `02.8.3-T3:156`, YR20); `upload.PrivacyStatus`/`PublishAt` are recomputed on the next `PlanUpload` call from the same immutable inputs, so they do not change either |
| `unlisted` + future `publishAt` | `validation_failed`, field `publishAt` ([OPEN] §Notes item 2); G3 cannot express it |
| no `consent_at` | `publication_consent_required` (M1, C6, existing code) — the upload job also refuses, defence in depth |
| re-planning a `scheduled` publication | `ApplyUploadPlan`'s status CAS makes a repeated call a no-op; there is no scheduler call from this task to duplicate (YR3) |
| `PATCH` attempts to change `Privacy` on a pre-audit row | 409 `publication_privacy_locked` (YR20/YR5) — 06.2.2-T1's validation, not this task's |
| quota exhausted at plan time | not this task: 06.3.1-T1 returns 429 `youtube_quota_exhausted`; the publication stays `scheduled` with `next_attempt_at` = next PT midnight (D10, 06 CR-4) |
| `platform_payload` growth | the `upload` key is two short scalars; `UploadSessionEnc` (06.2.3-T2) is the only large member and is never logged |
| clock skew / DST | all instants are `DateTimeOffset`/`timestamptz` in UTC; this task performs no local-time arithmetic (it has none — the PT day is 06.3.1-T1's, the lead time is 06.2.2-T1's) |

## Notes

- **[OPEN] 1 — how 02 learns `preAudit` at run-outcome time:** `publication_updated.v1` carries ids only (D13), so 02 either keeps the flag on its own run row or reads it from `PublicationDto` — per 06.2.1-T1's Notes, `PublicationDto` now exposes `PreAudit`/`RequestedPrivacy` read straight off `platform_payload` (06 CR-10, peer-confirmed). Not decided or implemented in this folder.
- **[OPEN] 2 — `unlisted` + future `publishAt`:** G3 allows `publishAt` only with `private`, and YouTube publishes at that instant, so a scheduled *unlisted* slot cannot be expressed with one insert. This task rejects it (`validation_failed`, field `publishAt`). The alternative is uploading `private`/no `publishAt` and flipping `privacyStatus` to `unlisted` at `publish_at` with `videos.update` — extra scope (write quota, a new job branch) that the TL must accept or drop. The high-level 06.2.4 text does not mention the case.
- **Resolved by ruling YR2, not open anymore:** the pre-audit `publish_at`-on-the-row question. `02.8.3-T3` and `06.2.1-T1` always keep `publish_at = run.SlotAt` on the row; only this task's plan/request omits `publishAt`. `PlanUpload` already reads `PublishAt` as the row's value and branches on `Payload.PreAudit` first, so this ruling requires no code change here.
- **Resolved by ruling YR3, not open anymore:** the earlier `IPublishScheduler`/wiring question. That port never shipped. The Api never enqueues; the Worker's `PublicationScheduledForUploadHandler` (06.2.3-T2) does the actual scheduling via 06.2.2-T1's `PublicationQueueTime.For`. This task has no scheduler dependency, no `YouTubeOptions` dependency, and no forward edit into 06.2.2-T1's scheduling code — only a coordination note that its consent handler must call `PlanUpload`/`ApplyUploadPlan`.
- **Defect fixed (TL review):** an earlier draft of this task sent `publishAt` for **any** future-dated row regardless of `Privacy`, including `Privacy == "private"` — YouTube would then auto-publish a video the owner explicitly marked private. Fixed: `publishAt` is included only for `Privacy == "public"` rows (invariant 1 / §Design 2).
- Reuse, never fork: `YouTubeOptions` is 06.1.2-T1's single instance — this task never reads it; `platform_payload.upload` is additive to 06.2.3-T2's `PublicationPayload.With(...)`; error codes are 09's closed `ErrorCodes` class — no local factory.
- No new audit action from this task specifically; `publishing.publication_updated` (YR21) is 06.2.5-T1's/the consent command's concern for the transitions they write.
