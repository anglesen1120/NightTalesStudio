## Goal

The operator can never exceed the project's daily upload quota and can see when the next upload slot is available. `platform_quota_usage` holds one row per Pacific calendar day; `IQuotaLedger.TryReserveAsync` takes exactly one unit with a single conditional `UPDATE` (no over-reservation under concurrency), `ReleaseAsync` returns a unit when YouTube never received the insert, and `GET /publishing/youtube/eta` answers `{ available, nextSlotAt }`. The gauge `youtube_quota_used` feeds the 11.6.2-T1 alert.

## Design

**Table (new, this task's migration).** §3.2 of the plan is the spec: composite PK `(platform, quota_day)`, `units_used int NOT NULL DEFAULT 0 CHECK (units_used >= 0)`, `units_limit int NOT NULL CHECK (units_limit > 0)`, `platform text NOT NULL CHECK (platform IN ('youtube'))`, `created_at`/`updated_at timestamptz NOT NULL`. No `id` column (platform counter — not an aggregate, not `IUserOwned`, no `xmin`, no tenant filter), no secondary index: every statement filters on the full PK.

**Domain / Application / Infrastructure.**

```csharp
// src/NightTales.Domain/Publishing/PlatformQuotaUsage.cs  — shell only (the ledger drives it with SQL)
public sealed class PlatformQuotaUsage                       // PK (Platform, Day)
{
    public string Platform { get; private set; } = "youtube";
    public DateOnly QuotaDay { get; private set; }
    public int UnitsUsed { get; private set; }
    public int UnitsLimit { get; private set; }
    public DateTimeOffset CreatedAt { get; private set; }
    public DateTimeOffset UpdatedAt { get; private set; }
    private PlatformQuotaUsage() { }
}

// src/NightTales.Application/Abstractions/Publishing/IQuotaLedger.cs
public interface IQuotaLedger
{
    Task<ErrorOr<QuotaReservation>> TryReserveAsync(string platform, DateTimeOffset now, CancellationToken ct = default);
    Task<ErrorOr<Success>> ReleaseAsync(QuotaReservation reservation, CancellationToken ct = default);
}

// src/NightTales.Application/Abstractions/Publishing/QuotaReservation.cs
public readonly record struct QuotaReservation(string Platform, DateOnly Day);

// src/NightTales.Application/Publishing/Quota/PacificQuotaDay.cs  — the single PT-day implementation (Q4)
public static class PacificQuotaDay
{
    private static readonly TimeZoneInfo Zone = TimeZoneInfo.FindSystemTimeZoneById("America/Los_Angeles");
    public static DateOnly Day(DateTimeOffset utc);            // Pacific calendar date of `utc`
    public static DateTimeOffset NextResetAt(DateTimeOffset utc); // next Pacific midnight (DST-safe, ICU zone)
}

// src/NightTales.Application/Publishing/Quota/GetYouTubeEtaQuery.cs
public sealed record GetYouTubeEtaQuery : IQuery<YouTubeEtaDto>;
public sealed record YouTubeEtaDto(int Available, DateTimeOffset? NextSlotAt);
```

`NextResetAt` must be DST-safe: take the Pacific local date of `utc` + 1 day, build local midnight and convert back with that day's offset (`Zone.GetUtcOffset` for the instant — never a fixed `−07:00`), so the March/November transitions give 07:00Z and 08:00Z respectively.

**Infrastructure `YouTubeQuotaLedger`** (`src/NightTales.Infrastructure/Publishing/YouTubeQuotaLedger.cs`): constructor takes `IAppDbContext db`, `IOptionsMonitor<YouTubeOptions> options`, `NightTalesMetrics metrics`. `TryReserveAsync`:

```csharp
var day  = PacificQuotaDay.Day(now);
var limit = options.CurrentValue.Quota.UnitsPerDay;            // 100 (D11, F22)
// 1. seed (idempotent; concurrent seeds are no-ops, never errors):
await db.Database.ExecuteSqlInterpolatedAsync(
    $"INSERT INTO platform_quota_usage (platform, quota_day, units_used, units_limit, created_at, updated_at) " +
    $"VALUES ({platform}, {day}, 0, {limit}, now(), now()) ON CONFLICT (platform, quota_day) DO NOTHING", ct);
// 2. one atomic statement; the row lock serialises contenders:
var rows = await db.PlatformQuotaUsage
    .Where(r => r.Platform == platform && r.QuotaDay == day && r.UnitsUsed < r.UnitsLimit)
    .ExecuteUpdateAsync(s => s
        .SetProperty(r => r.UnitsUsed, r => r.UnitsUsed + 1)
        .SetProperty(r => r.UpdatedAt, _ => now), ct);
if (rows == 1) { PublishGauge(day, platform); return new QuotaReservation(platform, day); }
var retryAfter = (int)Math.Ceiling((PacificQuotaDay.NextResetAt(now) - now).TotalSeconds);
return Error.TooManyRequests(code: ErrorCodes.YouTubeQuotaExhausted,
                             metadata: new() { ["retryAfterSeconds"] = retryAfter });
```

`ReleaseAsync` is one statement — `UPDATE … SET units_used = units_used - 1, updated_at = now() WHERE platform = @p AND quota_day = @d AND units_used > 0` — and returns `Result.Success` whether or not it touched a row (Q5). `PublishGauge` reads the row (single `SELECT`, no tracking) and calls `metrics.SetYoutubeQuotaUsed(limit == 0 ? 0 : (double)used / limit)` inside a try/catch that only logs: a metric failure must not fail the reservation.

**Registration.** `IQuotaLedger → YouTubeQuotaLedger` **scoped** (it takes the scoped `IAppDbContext`, same reasoning as 09 README D4 for handlers). `IAppDbContext`/`AppDbContext` gain `DbSet<PlatformQuotaUsage> PlatformQuotaUsage`. `PlatformQuotaUsageConfiguration`: `ToTable("platform_quota_usage")`, `HasKey(r => new { r.Platform, r.QuotaDay })`, both properties `ValueGeneratedNever()`, `ToTable(t => { t.HasCheckConstraint(...) })` for the three CHECKs, no `HasQueryFilter` (not user-owned — 09.2.3's filter must not add a user predicate).

**Endpoint** (`src/NightTales.Api/Endpoints/Publishing/YouTubeEtaEndpoints.cs`): `MapGet("/publishing/youtube/eta", …)` in the existing `/api/v1` publishing group, bearer policy + `RequireFeature("youtube_publish")` (404 `feature_disabled`), zero request parameters, `GetYouTubeEtaQuery` through `ISender`, `ToHttpResult()`. Handler: one `SELECT` for today's PT row (as-no-tracking); no row → `Available = options.Quota.UnitsPerDay, NextSlotAt = null`. No `Idempotency-Key`, no `If-Match`, no ETag, no outbox event (plan §5).

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Row missing at reserve | seeded in the same call (step 1); concurrent seeds are `ON CONFLICT DO NOTHING` no-ops |
| Two workers race for the last unit | one `UPDATE` returns 1 row, the other 0 → the loser gets 429 `youtube_quota_exhausted`, never an over-reservation |
| Release on a zero/missing row | success, no-op, no row created |
| Double release (retry after a crash) | impossible by construction: the release commits in the same unit of work as the `scheduled`/`failed` state change it belongs to; a rolled-back transaction rolls both back |
| `units_limit` changed mid-day | applies to the next day's row (the limit is read at seed time); documented in the runbook note |
| Clock skew Api ↔ Worker | both use `PacificQuotaDay` (one helper), so at most one unit can be mis-bucketed inside the skew window |
| Day row absent when the ETA is read | reports the full configured limit (no row written by a read) |
| Metric recorder throws | caught and logged; the reservation result is unaffected |
| DST spring-forward (23:00 → 01:00 local) | `NextResetAt` never returns a non-existent local midnight; it uses the next local date's offset |
| `YouTube:Quota:UnitsPerDay` = 0 | startup validation of `YouTubeOptions` (D11) rejects it; the CHECK `units_limit > 0` is the second line of defence |
