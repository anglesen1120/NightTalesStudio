## Goal

One owner-initiated `DELETE /channels/{id}` that (1) revokes the grant at Google immediately, (2) wipes the stored tokens whatever Google answers, (3) cancels every publication that has not started uploading and releases a quota unit **only where one was actually reserved**, (4) opens the 7-day `data_deletion_requests` row through 13.3.1-T1's engine, and (5) records outbox + audit. Idempotent, bearer-authenticated, tenant-scoped, no `If-Match` (README D15).

## Design

**Domain — nothing added.** `ChannelConnection.Revoke(now)` already exists (06.1.2-T2); this handler simply calls it.

**Infrastructure — method body only.** `src/NightTales.Infrastructure/Publishing/GoogleYouTubeClient.cs` (existing file, created by 06.1.2-T1) gains the `RevokeAsync` implementation:

```csharp
public async Task<ErrorOr<RevokeOutcome>> RevokeAsync(string token, CancellationToken ct)
// POST {options.RevokeEndpoint}   Content-Type: application/x-www-form-urlencoded
// body: token=<token>   (never a query string)
// 200 -> Revoked ; 4xx with {"error":"invalid_token"} -> AlreadyRevoked ;
// transport/5xx -> Error (the caller's retry loop applies, this method makes one attempt)
```
The port signature (`RevokeAsync(string token, ct) → ErrorOr<RevokeOutcome>`) and the `RevokeOutcome` enum are **06.1.2-T1's declaration** — this task must not re-declare either.

**Application command** — `src/NightTales.Application/Features/Publishing/Channels/DisconnectChannel/{DisconnectChannelCommand.cs,DisconnectChannelHandler.cs}`:

```csharp
public sealed record DisconnectChannelCommand(Guid ChannelId) : ICommand<Success>;
```

Handler order (all inside one `IUnitOfWork` transaction; the Google HTTP call happens **inside** the transaction but is not itself transactional — the DB state only lands at commit, plan §3.3 invariant 2):

1. load `ChannelConnection` under the tenant filter (`ChannelConnection : IUserOwned`) with a **`SELECT … FOR UPDATE` row lock** (YR11: "disconnect also locks the row", the same discipline as `Reconnect`'s) → missing = `not_found`;
2. already `revoked` → `CreateAsync(..., Channel, connectionId, InAppRevoke)` (idempotent) and return `Success` (no Google call, no outbox, no audit);
3. `TryUnprotect(connectionId.ToString(), RefreshTokenEnc) ?? TryUnprotect(connectionId.ToString(), AccessTokenEnc)` — both unreadable ⇒ skip the Google call (`googleRevoke = "skipped"`, log with the connection id) and continue at 5;
4. `IYouTubeClient.RevokeAsync(token, ct)` — **no client resolution, no `IOAuthClientResolver` call**; retry loop 3 attempts, delays 250 ms / 1 s / 4 s, each + 0–20 % jitter, only on a transport/5xx `Error`; `AlreadyRevoked` counts as success; exhausted ⇒ increment `youtube_channel_revoke_failed_total`, log `{ connectionId, attempt: 3 }`, set `googleRevoke = "failed"` and continue (D15);
5. `connection.Revoke(now)`;
6. cascade: `db.Publications.Where(p => p.ChannelConnectionId == connection.Id && (p.Status == AwaitingConsent || p.Status == Scheduled))` with a row lock, then per row `Publication.Cancel(now)`; **read `platform_payload.quotaReservedDay` first** — call `IQuotaLedger.ReleaseAsync(reservation)` only when that key is present on the row (invariant 4/R16: a `scheduled` row `PublishYouTubeJob` never picked up holds no reservation, and releasing unconditionally would corrupt `units_used`);
7. `IDeletionRequests.CreateAsync(userId, DeletionScope.Channel, targetId: connection.Id, DeletionReason.InAppRevoke, ct)` — `due_at` is the engine's (`now + 7 d`), never computed here;
8. outbox `channel_connection_changed.v1 { connectionId, userId, status: "revoked" }`;
9. audit `publishing.channel_disconnected`, `data = { platform, oauthClientId, externalAccountId, publicationsCancelled, quotaUnitsReleased, googleRevoke }` (no title, no token);
10. return `Success` → endpoint answers `204`.

**Endpoint** — extend the channels group created by 06.1.2-T1 (`MapDelete("/{id:guid}", ...)`), inside the same `RequireFeature("youtube_publish")` + bearer group, with `[Audited("publishing.channel_disconnected")]`, so the route table stays one group and one flag check (no second registration path).

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Google unreachable / 5xx after 3 attempts | tokens wiped anyway, request created, metric + audit `failed`, log with ids |
| `AlreadyRevoked` (already revoked at Google) | treated as success — the desired end state holds |
| Unprotectable token ciphertext (key rotated away) | Google call skipped, everything else proceeds; `googleRevoke = "skipped"` + warning |
| A cancelled publication has no `quotaReservedDay` key | no `ReleaseAsync` call for that row — never decrement below 0 |
| Crash between the Google call and the commit | the transaction rolls back: the row stays `active` with tokens, no request — the user retries; Google may have already revoked, in which case the retry's refresh/upload fails later and 06.4.2-T1/06.2.3-T2 handle it |
| Disconnect while an upload job is streaming | the cascade ignores `uploading`/`processing`; the job's next Google call fails after the revoke → that publication ends `failed` `channel_reauth_required` (06.2.3-T2's map) |
| Concurrent `POST /channels/youtube/connect` for the same channel | serialised by the row lock; the reconnect either precedes (disconnect revokes the new tokens) or follows (a new `active` row) |
| Connection already `revoked` and its request already `completed_at` | no second request: the partial unique covers **open** rows only |
