## Goal

The operator answers "how much of today's upload budget is left, how long is the queue, and who is consuming it" with one admin request — no SQL, no Hangfire dashboard. The per-user daily cap and the publish-form ETA banner are P (`06.3.1-T1`) and 06.3.2-T1 respectively; this task is only the admin read that makes both visible.

## Design

**Query.** `GetAdminQuotaQuery() : IQuery<AdminQuotaDto>` (tagged `[NotAudited]` — an admin read is not audited; if the 09.3.6-T1 arch test requires one of the three attributes on the query type, this is the value), handler `GetAdminQuotaQueryHandler` in `src/NightTales.Api/Features/Admin/YouTube/`.

```csharp
public sealed record AdminQuotaDto(DateOnly QuotaDay, int Used, int Limit, int Available,
    DateTimeOffset NextResetAt, int QueueLength, IReadOnlyList<AdminQuotaUserDto> Users);
public sealed record AdminQuotaUserDto(Guid UserId, string DisplayName, int UploadsToday, int UploadsLimit,
    bool Overridden, DateTimeOffset? EarliestScheduledAt);
```

**Three statements, no more (F30):**

1. `platform_quota_usage` day row: `SELECT units_used, units_limit FROM platform_quota_usage WHERE platform = 'youtube' AND quota_day = @day` where `@day = PacificQuotaDay.Day(now)`; missing → `Used = 0`, `Limit = YouTubeOptions.Quota.UnitsPerDay` (the `06.3.1-T1:152` rule). `Available = max(0, Limit − Used)`, `NextResetAt = PacificQuotaDay.NextResetAt(now)`.
2. `QueueLength`: `SELECT COUNT(*) FROM publications WHERE status = 'scheduled'` (`AsNoTracking`, `IgnoreQueryFilters` in `Features/Admin`, uses the P index `(status, next_attempt_at)`).
3. Per-user top 20: one statement over `platform_user_quota_usage u` (`quota_day = @day`) ⋈ `users` (`display_name`), with a correlated `EXISTS (SELECT 1 FROM platform_user_quota_limits l WHERE l.user_id = u.user_id)` for `Overridden` and a windowed join for `EarliestScheduledAt` = `MIN(p.next_attempt_at)` over that user's `scheduled` publications (`LEFT JOIN LATERAL (SELECT MIN(next_attempt_at) … WHERE p.user_id = u.user_id AND p.status = 'scheduled')`), `ORDER BY uploads_used DESC, user_id ASC LIMIT 20`. A user with no row today is absent (not zero-filled) — the view is "who is using today's budget", not a user directory.

**Route.** `GET /api/v1/admin/quota` → `AdminQuotaDto`; admin/owner policy + MFA; also behind `RequireFeature("youtube_publish")` (Part A D1), so a disabled feature 404s for everyone. No rate-limit policy of its own (admin traffic is already rate-limited; nothing here is expensive). Registered from `src/NightTales.Api/Endpoints/Admin/AdminQuotaEndpoints.cs`.

**Privacy (F24).** Counts + `display_name` only: no titles, episode ids, channel names/ids, tokens, or e-mail. An `admin` sees the top 20 ids of a cohort that is already visible through 09.9.1's `GET /admin/users`.

## Acceptance checks

- [ ] `GET /api/v1/admin/quota` on a day with one uploaded publication and a limit of 100 answers `used = 1`, `limit = 100`, `available = 99`, `queueLength` equal to a manual `COUNT(*)` over `scheduled` publications, `nextResetAt` equal to `PacificQuotaDay.NextResetAt(now)`.
- [ ] A day with no `platform_quota_usage` row answers `used = 0`, `limit = YouTube:Quota:UnitsPerDay`, `quotaDay` = today's PT date (the P missing-row rule).
- [ ] `queueLength` changes as soon as a publication moves out of `scheduled`, and includes every user's rows (cross-tenant read happens only in `Features/Admin`).
- [ ] `users[]` is ordered by `uploadsToday` descending, ties by `userId`, capped at 20; `uploadsLimit` reflects a `platform_user_quota_limits` override and `overridden` is true exactly then.
- [ ] `earliestScheduledAt` is the earliest `next_attempt_at` of that user's `scheduled` publications and null when the user has none.
- [ ] Exactly three SQL commands are executed for one request (no N+1), asserted by the command counter; each statement is `AsNoTracking`.
- [ ] A `user`-role token gets 404 (09's admin policy); an admin without a fresh MFA step is refused; with `youtube_publish` off the route answers 404 `feature_disabled`.
- [ ] The JSON contains no field beyond the DTO's (a snapshot test guards the field list) and no title/episode/channel/token/e-mail value (F24).
- [ ] The response is culture-invariant: `quotaDay` as `yyyy-MM-dd`, timestamps ISO-8601 with `Z`/offset — no localized text (the vi+en copy is CR-19/10 S).
- [ ] No migration, no new index and no `platform_quota_usage` write is introduced by this task.

## Tests

- **Unit:** statement 3's projection logic over an in-memory context (override flag, `earliestScheduledAt`, top-20 order and tie-break).
- **Integration (Testcontainers):** three seeded scenarios (empty day, mid-day with two users + one override, day where a user's rows are all deferred with `user_upload_limit_reached`) asserting the DTO numbers; the three-command counter; `pg_indexes` shows the queue count used `(status, next_attempt_at)`.
- **API:** 200 shape snapshot; 404 for `user`; 404 `feature_disabled`; MFA gate.
- **Not tested:** the 10 S admin UI rendering (its own tests), `PacificQuotaDay` internals (P), the ETA endpoint (P).

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| No day row yet (first request of a PT day) | `used = 0`, `limit` from options, `nextResetAt` = next PT midnight (the `06.3.1-T1:152` rule) |
| `platform_user_quota_usage` empty but publications are queued | `users[]` is empty, `queueLength` > 0 — correct: the cohort has not uploaded yet today |
| A user's `display_name` was purged | joined row still resolves (the column is not nullable in P); if it were null the DTO would carry an empty string |
| More than 20 users used the budget | only the top 20 by `uploadsToday`; the count is not a completeness claim (the sum is not exposed as a total) |
| Day boundary during the request | `@day` is captured once per request, so the three statements agree even across the PT midnight instant |
| A capped user with a deferred row | appears with `earliestScheduledAt` = the next PT midnight + jitter (the fairness deferral), which is exactly the operator's cue |
| Stale-read pressure from a dashboard polling | no server-side polling; the 10 S UI decides (CR-19); the query is index-only for the queue count |
