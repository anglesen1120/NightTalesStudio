# 07.1.1-T1 — TikTok app registration, `video.publish` scope, PULL_FROM_URL ownership and OAuth error taxonomy

| Story | Size | Area | Depends on | Blocks | Phase / flag |
|---|---|---|---|---|---|
| 07.1.1 | S (0.5) | Ops/BA | 13.1.1-T1 (soft), 13.1.2-T1 (soft) | 07.1.2-T1 | P · R2 |

## Goal

Two TikTok developer apps (staging, prod) in one developer account with Login Kit + Content Posting API enabled, each with exactly one static `https` redirect URI `https://<env origin>/api/v1/channels/tiktok/callback`, the privacy-policy and terms URLs from 13.1.1-T1/13.1.2-T1, the requested scope **`video.publish` only**, and a **DNS-verified `PULL_FROM_URL` domain/URL prefix** for our object-storage host; `docs/ops/tiktok-oauth-setup.md` records every per-env value 07.1.2-T1/T2 need at runtime (client key, secret ref, redirect URI, scopes, audit status, claimed volume) plus the **real** `oauth/token` / `oauth/revoke` error taxonomy and rate limits, and `tools/ops/tiktok-oauth-check.py` proves the round trip on staging.

## Inputs

- `../README.md` §1 K13 (authorize/token/revoke shapes, `expires_in` 86400, `refresh_expires_in` 31536000, `code_verifier` mobile/desktop only, rotation), K14 (redirect rules), K15 (scopes, subset grant), K16 (`PULL_FROM_URL`, verified domain, "do not use `FILE_UPLOAD`"), K17, K10/K11 (caps, intended use) ✅; §3 D12 (scope), D14 (secret name), D19 (`TikTokOptions` keys), D6/D13 (⚠️ token/revoke limits — this task makes them facts); §10 **TT4**; §7 gate `07-connect`; §11 DoR condition (1); §4 CR-4 (presigned URL this gate unblocks), CR-8 (`MonthlyActiveCreators` = the volume filed with 13.4.3-T1).
- 13.1.1-T1 / 13.1.2-T1 (legal pages — soft: drafts exist, versions may change); 11 (env config, `nts/<env>/api/…` secret naming; the exact store CLI is 11.2.2-T1's ⚠️).
- Precedent to mirror, not re-invent: `06.1-connect/06.1.1-T1-google-cloud-oauth-clients.md` → `docs/ops/youtube-oauth-setup.md` + `tools/ops/youtube-oauth-check.py`.

## Design

Console work + two repo artifacts + evidence. **No product code, no migration, no route**; the recorded values are read by 07.1.2-T1/T2 as configuration.

**`docs/ops/tiktok-oauth-setup.md`** — one section per env:

| Item | staging | prod |
|---|---|---|
| App name/id; Login Kit + Content Posting API on | recorded | recorded |
| Client key (**public**) | recorded | recorded |
| Secret ref (name only) | `nts/staging/api/TIKTOK_CLIENT_SECRET` | `nts/prod/api/TIKTOK_CLIENT_SECRET` |
| Redirect URI (exactly one) | `https://<staging origin>/api/v1/channels/tiktok/callback` | `https://<prod origin>/api/v1/channels/tiktok/callback` |
| Requested / granted scopes | `video.publish` / observed list | same |
| Privacy-policy + terms URLs and versions | recorded | recorded |
| `PULL_FROM_URL` verified domain + URL prefix + DNS TXT name/value | recorded | recorded |
| `TikTok:ActiveClientId`, `TikTok:Clients:<clientId>:SecretName` | recorded | recorded |
| `TikTokOptions.AuditStatus` | `pending` | `pending` |
| Claimed 24-h active-creator volume `MonthlyActiveCreators` | recorded | recorded |

**Error-taxonomy section — the contract for 07.1.2-T2's classifier (TT4).** One row per probe actually run: `endpoint (token \| token-refresh \| revoke) | probe | TikTok error | error_description | HTTP | classification | source`. Classification rules: a code naming the grant/token ⇒ that connection `expired` + `tiktok_reauth_required` (only after the D10 ladder); anything else ⇒ **platform incident**. Unobservable rows are ⚠️ + [OPEN] and stay "incident" until proven.

**Rate-limit section.** The two endpoints' documented limits; until sourced, `RateLimits:TokenPerMinute` / `:RevokePerMinute` = 10 stay ⚠️ [INFERENCE] (D6).

**`tools/ops/tiktok-oauth-check.py`** (new, executable; the `chmod +x` is recorded in the doc — `/Volumes/Project` has Owners disabled, so the bit only matters on the clone that runs it). Reads `TIKTOK_CLIENT_KEY` / `TIKTOK_CLIENT_SECRET` from the env, never prints a secret: (1) prints the authorize URL with `scope=video.publish&response_type=code&disable_auto_auth=1&state=<random>` and **no `code_verifier`** (K13); (2) exchanges a pasted `code`; (3) asserts `expires_in == 86400`, `refresh_expires_in == 31536000`, `scope` contains `video.publish`, prints only the **length** of `open_id`; (4) one `creator_info` call → nickname + `privacy_level_options` (private unaudited account ⇒ `SELF_ONLY`, K9); (5) one refresh, printing whether a **new** refresh token came back; (6) revoke. Five HTTPS calls, no retries.

**Evidence** (07.4.1-T1 / 13.4.3-T1 inputs): portal screenshots (app config, scope request, URL-properties verification) + script transcripts; binaries in `~/.nts/compliance/evidence-<yyyy-mm-dd>/` with rows in the 07.4.1-T1 pack index — **binaries never enter the repo** (13 D14); synthetic tenant `demo+<n>@invalid`; no real e-mail/token/key/content.

## Steps

1. Register the developer account and both apps (staging first, prod after staging is green).
2. Add **exactly one** redirect URI per env, byte-identical to `https://<env origin>/api/v1/channels/tiktok/callback` (no trailing slash/query/fragment, ≤ 512 chars, K14).
3. Paste the 13.1.1-T1 / 13.1.2-T1 URLs; record the versions.
4. Request **`video.publish` only** — no `user.info.basic` (F13/O5); screenshot the request and the consent screen's granted list.
5. Register the storage host's domain/URL prefix for `PULL_FROM_URL`, complete the DNS TXT verification, record name/value + verified status (K16) — the gate for 07.3's presigned URL (CR-4).
6. Create `nts/<env>/api/TIKTOK_CLIENT_SECRET` per env through 11's runbook (⚠️ command is 11.2.2-T1's; record the command, never the value).
7. Write the doc + the check script; run it against staging with the owner's **private** test account, then the negative cases (invalid code, dead-token refresh, second revoke, declined scope).
8. Fill the taxonomy + rate-limit sections from the real runs; mark unobservable rows ⚠️ + [OPEN].
9. Hand over to 07.1.2-T1 (`TikTok:ActiveClientId`, `TikTok:Clients:<clientId>:SecretName`, redirect URIs, the taxonomy) and to 13.4.3-T1 the claimed `MonthlyActiveCreators` (CR-8).

## Acceptance checks

- Given the portal, When each app's redirect URIs are listed, Then exactly one per env, byte-identical to `https://<env origin>/api/v1/channels/tiktok/callback`, `https`, static, ≤ 512 chars (K14).
- Given the scope screen, Then only `video.publish` was requested and the granted list equals `{video.publish}` (K15, O5).
- Given the storage host, Then the URL-prefix verification shows verified with the DNS TXT name/value recorded (K16) — before any presigned URL is issued.
- Given a staging run, Then the script exits 0 and the transcript shows 86400 / 31536000, whether a rotated refresh token came back, and a successful revoke; a replay of the same `code` fails with the recorded code.
- Given the doc, Then every taxonomy row names endpoint + TikTok code + classification, and `grep -nE "(client_secret|access_token|refresh_token)"` finds no **value**.
- Given DoR condition (1), Then the rate limits carry a source ✅ or the explicit ⚠️ [INFERENCE] marker.
- Given the evidence folder, Then no binary is tracked by git and the pack index lists each artefact id, location and visibility.

## Tests

No product test (no code under test). Proof = the script's two runs (positive + negative) and the portal captures, recorded in the doc and the pack. The recorded code names/HTTP shapes become the fixtures for 07.1.2-T2 and must be mirrored by `FakeTikTokServer` (D17) — a fake invented from memory would make the classifier tests tautological ⚠️.

## Failure handling and edge cases

| Situation | Handling |
|---|---|
| Portal rejects the redirect URI (query/fragment/length/duplicate) | fix the app config; the path is fixed by the 06/07 routes — never register a different one to satisfy the portal |
| Scope request needs a justification | write the intended-use statement once (K11: authentic creators posting their own content to accounts they run — **not** an internal utility tool) and reuse it verbatim in 13.4.3-T1 |
| DNS TXT verification incomplete | block 07.3.1-T1 and gate `07-connect`; re-issue the record; never fall back to `FILE_UPLOAD` (K16/D2) |
| Refresh returns no new refresh token | record the observed behaviour ⚠️; the classifier still stores whatever pair came back (D13) |
| An error code outside K1/K13 | add a ⚠️ row, classify as an incident (TT4), raise it with TikTok support before the flag leaves owner-only |
| Secret-store command differs per env | record the command; the value never leaves the store or reaches the repo |
| The owner's test account is public | the observed option set is larger than `SELF_ONLY`; record both cases — 07.2.2-T1's intersection still wins (D4) |
