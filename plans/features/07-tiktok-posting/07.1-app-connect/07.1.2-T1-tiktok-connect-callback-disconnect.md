## Goal

`POST /channels/tiktok/connect` returns an authorize URL carrying `client_key`, `scope=video.publish`, `response_type=code`, `redirect_uri`, `state`, `disable_auto_auth=1` (no PKCE, K13) and persists a single-use `oauth_states` row bound to the caller's browser nonce; the anonymous `GET /channels/tiktok/callback` claims that row, exchanges the code with the **client bound to the state**, gates on the granted scope list, reads the creator nickname once and upserts an `active` `channel_connections` row with tokens protected under `tokens.v1/{connectionId}` and the client pinned; reconnect keeps the same row under `FOR UPDATE`; `DELETE /channels/{id}` revokes at TikTok, wipes the tokens, cancels the not-yet-uploaded publications and files the 7-day deletion request. A callback **never** answers JSON — every failure is `302 /channels?error=<code>`.

## Design

**Routes** (C4; all behind `RequireFeature("tiktok_publish")`).

| Route | Policy | Result |
|---|---|---|
| `POST /channels/tiktok/connect` | bearer + `IReauthGuard.RequireRecentAsync(5 min)` + `ILegalAcceptance.EnsureCurrentAsync`; `Idempotency-Key` required | 200 `ConnectChannelResponse(string AuthorizationUrl)`; 401 `reauth_required`; 409 `legal_acceptance_required`; 404 `feature_disabled`; 400 `validation_failed` |
| `GET /channels/tiktok/callback?code&state` | **anonymous**, policy `auth`, `[AllowAnonymousRequest]`, never JSON | `302 /channels?connected=tiktok` \| `302 /channels?error=<code>` |
| `DELETE /channels/{id}` | bearer, tenant-filtered | 204; 404 `not_found` |

**Commands** (one file triple each, exactly one audit attribute — 09.3.6-T1):
- `CreateTikTokOAuthStateCommand(Guid UserId, string IdempotencyKey) → ErrorOr<ConnectChannelResponse>` — `[NotAudited]`: the connect *attempt* is not a connection event; `publishing.channel_connected` is audited by the upsert (D14).
- `CompleteTikTokConnectionCommand(string? Code, string State, string? BrowserNonce, string? Error, string? ErrorDescription) → ErrorOr<Uri>` — `[AllowAnonymousRequest]`; the endpoint maps `Error.Code` into `?error=<code>` (06 YR5 pattern).
- `DisconnectTikTokChannelCommand(Guid ConnectionId) → ErrorOr<Deleted>` — `[Audited("publishing.channel_disconnected")]`.

**Ports/infrastructure (one HTTP client, no parallel convention — TT11 spirit):**
- `ITikTokApiClient` (Application port, Infrastructure impl over `HttpClient`, base URLs from options): `BuildAuthorizeUrl(string clientKey, string redirectUri, string state)`; `ExchangeCodeAsync(string clientKey, string clientSecret, string code, string redirectUri, CancellationToken ct) → ErrorOr<TikTokTokenResponse(string OpenId, string Scope, string AccessToken, int ExpiresIn, string RefreshToken, int RefreshExpiresIn)>`; `GetCreatorInfoAsync(string accessToken, CancellationToken ct) → ErrorOr<TikTokCreatorInfo(string Nickname, string AvatarUrl, IReadOnlyList<string> PrivacyLevelOptions, bool CommentDisabled, bool DuetDisabled, bool StitchDisabled, int MaxVideoPostDurationSec, string? BlockReason)>`; `RevokeAsync(string clientKey, string clientSecret, string token, CancellationToken ct) → ErrorOr<Success>`. Every `clientKey` is the pinned `OAuthClient.ClientId` (06 D5) sent as TikTok's `client_key`; it is the state row's client for the exchange and `connection.oauth_client_id` for everything later. 07.2.1-T1 (`IExternalLookup`) and 07.3.1-T1 extend **this** interface. `GetCreatorInfoAsync`'s result maps 1:1 onto D11's `TikTokCreatorInfoDto` names (`nickname`, `avatarUrl`, `privacyLevelOptions`, `commentDisabled`, `duetDisabled`, `stitchDisabled`, `maxVideoPostDurationSec`, `blockReason`); `canPost` is derived from `error.code` by 07.2.1-T1.
- `TikTokOptions` (D19, declared here if 07.1.1-T1 has not) + `IValidateOptions`/`ValidateOnStart`.
- **Rate limiting (D6, key defined).** `ITikTokRateLimiter.TryAcquireAsync(Guid connectionId, TikTokEndpoint endpoint, ct)` is unchanged and keys `tt:rl:{connectionId}:{endpoint}` — it covers the **post-connection** endpoints (`init`, `creator_info`, `status`, `token`, `revoke`). The callback runs before any connection exists, so it does **not** touch the bucket; it is bounded instead by (a) the `auth` rate policy on the route and (b) **at most one live TikTok state row per user** — a new connect marks the caller's previous unused TikTok row `used_at = now()`, so a single user cannot fan out callbacks. The first bucket-keyed call is 07.2.1-T1's `creator_info` keyed by the connection id. ⚠️ If the state table ever allows concurrent live attempts per user, the callback needs a user-keyed bucket — recorded as a contract note, not invented here.

**Callback (no DB transaction held across HTTP):**
1. `UPDATE oauth_states SET used_at = now() WHERE state_hash = @h AND platform = 'tiktok' AND used_at IS NULL AND expires_at > now() RETURNING id, user_id, oauth_client_id, refresh_family_id, browser_nonce_hash;` — 0 rows ⇒ `oauth_state_invalid`; committed on its own so a lost response cannot replay.
2. `CryptographicOperations.FixedTimeEquals(SHA256(BrowserNonce), row.BrowserNonceHash)` (06 YR10); mismatch ⇒ `oauth_state_invalid`, no row, cookie deleted either way.
3. The bound refresh family must still be live (06 D3).
4. Outbound, no transaction open: resolve the state's client (06 D5) → `ExchangeCodeAsync` → the granted `scope` list must contain `video.publish` (`tiktok_scope_missing`, no row, no alert — F25) → **one** `GetCreatorInfoAsync` for `creator_nickname` only.
5. `UpsertTikTokConnectionCommand`, one UnitOfWork:
```sql
SELECT * FROM channel_connections
 WHERE platform = 'tiktok' AND external_account_id = @openId AND status <> 'revoked'
 FOR UPDATE;   -- 0 rows ⇒ insert; 1 row, same user ⇒ reconnect; 1 row, other user ⇒ channel_already_connected
```
   insert/update `display_name = nickname`, `scopes = { 'video.publish' }`, both ciphertexts `ITokenProtector.Protect(id.ToString(), …)` with the UUIDv7 generated **before** protection (06 D4), `token_expires_at = now + ExpiresIn`, `status = 'active'`, `oauth_client_id` = the state's client (re-pin per YR11), `last_verified_at = now`; then audit, `QueueAsync` the `channel_connected` e-mail **in the same transaction** (a queueing failure fails the command, 06 D3) and outbox. The partial unique index `(platform, external_account_id) WHERE status <> 'revoked'` is the concurrency backstop; 23505 ⇒ `channel_already_connected`. The avatar is **not** persisted (no column in C1 ⚠️) — 07.2.1-T1 serves it live.

**Disconnect.** Tenant-filtered load (foreign id ⇒ 404 `not_found`); `SELECT … FOR UPDATE` (YR11); `RevokeAsync` with the pinned client, 3 attempts, backoff 200 ms / 700 ms / 2000 ms ⚠️[INFERENCE]; whatever the outcome, one UnitOfWork: tokens NULL, `status = 'revoked'`, `revoked_at = now`, `Publication.Cancel(now)` for the connection's `awaiting_consent|scheduled` publications, one `data_deletion_requests(scope = 'channel', target_id = id, reason = 'in_app_revoke', due_at = now + 7 d)`, outbox + audit. The **channel** scope nulls tokens and drops the account identifiers; the `platform_payload` purge belongs to the **publication** scope (that column is on `publications`, 00 §6:291 — the channel handler cannot purge it). A revoke failure logs `tiktok.revoke.failed` and needs the D18-CR counter (§7 of `plan.md`); it is never a 5xx. A repeat `DELETE` is 204 with no second deletion row (partial unique, 06 YR13).

**Errors:** `reauth_required` 401, `legal_acceptance_required` 409, `feature_disabled` 404, `not_found` 404, `validation_failed` 400; callback query values `oauth_state_invalid`, `oauth_denied`, `oauth_exchange_failed`, `tiktok_scope_missing`, `channel_already_connected` ⚠️ (D12 states 409 on the connect path; a callback cannot return JSON, so the redirect form is used and the 409 stays reserved for a future bearer re-check — F25 rule).

## Steps

1. Declare `TikTokOptions` (+ validator) and `ITikTokApiClient` (auth members), wired from options with one named `HttpClient`.
2. `CreateTikTokOAuthStateCommand`: build the authorize URL, mark the caller's previous unused TikTok state row used, insert the new one (`platform='tiktok'`, `code_verifier_protected = NULL`, `oauth_client_id` = `ActiveClientId`, `refresh_family_id` = the caller's `sid`), set `__Host-nts_oauth` (HttpOnly/Secure/SameSite=Lax/Path=/ 10 min) and store its SHA-256; idempotent on `Idempotency-Key`.
3. Add the connect endpoint with the re-auth/legal/flag guards.
4. `CompleteTikTokConnectionCommand` per §Design (claim → nonce → family → exchange → scope gate → one `creator_info` → upsert); map every failure to a callback query value.
5. Add the anonymous callback endpoint (policy `auth`) that always redirects, clears the nonce cookie, and keeps the query string out of logs (CR-10).
6. `DisconnectTikTokChannelCommand` + the 13.3.1-T1 request call.
7. Extend the `GET /channels` projection so a `tiktok` row appears with the 06 D4 DTO shape (and `status = 'expired'` is visible for 10.7.1/10.7.3).
8. Tests per §Tests; confirm 09.3.6-T1 arch tests pass.

## Acceptance checks

- Given an owner with the flag, re-auth ≤ 5 min and current legal acceptance, When `POST /channels/tiktok/connect` runs, Then the URL query is exactly `client_key`, `scope=video.publish`, `response_type=code`, `redirect_uri`, `state`, `disable_auto_auth=1` with **no** `code_verifier`, and one `oauth_states` row exists (`code_verifier_protected IS NULL`, `expires_at ≈ now+10 min`, `used_at IS NULL`, `browser_nonce_hash` = SHA-256 of the cookie); the caller's previous unused TikTok row is now `used_at`-stamped.
- Given the happy callback, Then `/channels?connected=tiktok`, one row with `platform='tiktok'`, `external_account_id = open_id`, `display_name = creator_nickname`, `scopes = {video.publish}`, `status='active'`, `token_expires_at ≈ now + 86400 s`, the pinned `oauth_client_id`, both ciphertexts decryptable under `tokens.v1/{connectionId}`, plus exactly one audit row, one `channel_connected` e-mail row and one outbox row.
- Given a replayed state, a state completed in another browser, or an expired row, Then `302 /channels?error=oauth_state_invalid`, no connection, no audit, no alert.
- Given the granted scope list lacks `video.publish` (or TikTok returns `error=access_denied`), Then `302 /channels?error=tiktok_scope_missing`, **no** row, no incident, no alert (F25).
- Given user B resolves A's `open_id`, Then `302 /channels?error=channel_already_connected`, A's row untouched, one connection total.
- Given the same user reconnects, Then the same connection id, both ciphertexts changed, `oauth_client_id` re-pinned, `last_verified_at` advanced, no second row.
- Given `DELETE` on an owned connection, Then TikTok revoke called once with the pinned `client_key`, tokens NULL, `revoked`, `revoked_at` set, the connection's `awaiting_consent|scheduled` publications `cancelled`, one deletion row with `due_at ≈ now + 7 d`, outbox + audit, 204; a second call is 204 with no new deletion row.
- Given the revoke endpoint returns 500 three times, Then still 204 with tokens NULL, one warning log and no fourth attempt.
- Given another user's id, Then 404 `not_found`; with the flag off, all three routes → 404 `feature_disabled`.

## Failure handling and edge cases

| Situation | Handling |
|---|---|
| Token endpoint 5xx / transport error | `oauth_exchange_failed` (302), no row, no incident — the user retries |
| Unknown `error` code on exchange | 302 `oauth_exchange_failed`, logged with `log_id`; the classifier decides `expired` vs incident for **later** calls only |
| State claimed but the flow never finishes | the 10-min expiry is the bound; no sweep job |
| Two callbacks race on one state | the `UPDATE … WHERE used_at IS NULL` claim arbitrates; the loser gets 0 rows ⇒ `oauth_state_invalid` |
| Two users race on one `open_id` | `FOR UPDATE` + partial unique; the loser gets `channel_already_connected`, never a 500 |
| The row was `revoked` mid-flight | the upsert's `status <> 'revoked'` predicate excludes it ⇒ a new row; the old keeps its revocation + deletion request |
| E-mail queueing fails inside the transaction | the whole command fails (`oauth_exchange_failed`), nothing is written (06 D3) |
| `creator_info` fails in the callback | `oauth_exchange_failed`; no half-populated connection (the nickname is mandatory for `display_name`) |
| Revoke returns a named grant error (already revoked) | treated as success: tokens are wiped anyway (D12) |
| Disconnect while `PublishTikTokJob` runs | the job sees `status='revoked'` and stops; the publication is `cancelled` by the disconnect transaction |
