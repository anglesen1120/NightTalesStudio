## Goal

Give the post screen (10.7.3-T1) the live TikTok creator state on **every render** of `/episodes/:id/publish/tiktok`: nickname, the account's real `privacy_level_options`, the interaction flags, `max_video_post_duration_sec`, and `canPost`/`blockReason` that is `false` whenever TikTok says the creator cannot post now — including its **HTTP-200 error** case. Nothing is persisted, nothing is cached across users, and the outbound call is rate-limited per connection.

## Design

```csharp
public sealed record TikTokCreatorInfoDto(        // D11 field list, verbatim
    Guid ChannelId, string Nickname, string AvatarUrl, IReadOnlyList<string> PrivacyLevelOptions,
    bool CommentDisabled, bool DuetDisabled, bool StitchDisabled, int MaxVideoPostDurationSec,
    bool CanPost, string? BlockReason);
public sealed record GetTikTokCreatorInfoQuery(Guid ChannelId) : IRequest<ErrorOr<TikTokCreatorInfoDto>>;

// [DECISION] TT11: check 09 first — extend `IExternalLookup` if it exists; never declare a second interface.
public interface IExternalLookup {
    Task<ErrorOr<TikTokCreatorInfo>> GetTikTokCreatorInfoAsync(Guid connectionId, CancellationToken ct); }
public sealed record TikTokCreatorInfo(string Nickname, string AvatarUrl, IReadOnlyList<string> PrivacyLevelOptions,
    bool CommentDisabled, bool DuetDisabled, bool StitchDisabled, int MaxVideoPostDurationSec,
    bool CanPost, TikTokBlockReason? BlockReason, string? PlatformLogId);          // [INFERENCE] name; never persisted
public enum TikTokBlockReason { CannotPostNow, ActiveUserCap, CreatorBanned }
```

**Handler** (`GetTikTokCreatorInfoQueryHandler`, ≤ 80 lines, `[NotAudited]`): (1) load the connection through `db.Query<ChannelConnection>()` — tenant-filtered, so another user's id and a non-TikTok id both answer 404 `not_found`; (2) `status != active` → **200** with `canPost = false`, `blockReason = errors.tiktok.reauthRequired` [DECISION: a re-consent prompt is a screen state, and D11 already carries the pair — no new code]; (3) `ITikTokRateLimiter.TryAcquireAsync(connectionId, TikTokEndpoint.CreatorInfo, ct)`; denied → 429 `tiktok_rate_limited` + `Retry-After` (D10's only 429); (4) access token via `ITokenService`; (5) `IExternalLookup` call → map to the DTO with `ChannelId` from the route.

**Infrastructure `TikTokClient`.** `POST {ApiBaseUrl}/v2/post/publish/creator_info/query/`, scope `video.publish` (K2). **HTTP 200 with a non-`ok` `error.code` is a result, not an exception** (F12): `spam_risk_too_many_posts`/`spam_risk_user_banned_from_posting`/`spam_risk*` → `CannotPostNow`; `reached_active_user_cap` → `ActiveUserCap`; an unknown code → `CannotPostNow` + a log carrying TikTok's `log_id` (never a silent success). Non-200: 401 → one forced refresh + one retry in the same command (D10 ladder), then `canPost = false` + `reauthRequired`; 429 `rate_limit_exceeded` → the 429 result; 5xx/timeout → the catalogue's `503` (`ErrorCodes` constant looked up, never created — `06.3.1-T1:159`'s reuse rule) and **no** incident (a read never raises one). Field mapping verbatim from K2: `creator_nickname`, `creator_avatar_url` (2 h TTL, passed through), `privacy_level_options[]`, `comment_disabled`, `duet_disabled`, `stitch_disabled`, `max_video_post_duration_sec`.

**Limiter** ([OPEN] O-1, `./plan.md` §11): this task declares `ITikTokRateLimiter.TryAcquireAsync(Guid connectionId, TikTokEndpoint endpoint, CancellationToken ct) → ErrorOr<Success>`, `enum TikTokEndpoint { Init, CreatorInfo, Status, Token, Revoke }`, and ships the in-memory token-bucket implementation keyed `tt:rl:{connectionId}:{endpoint}` with `TikTokOptions.RateLimits:CreatorInfoPerMinute` = 20 (D6); 07.3.1-T1 consumes the other endpoints and owns the job-deferral rule.

**Endpoint.** `src/NightTales.Api/Endpoints/Channels/TikTokCreatorInfoEndpoints.cs` on the channels group: `RequireFeature("tiktok_publish")` → `RequireAuthorization()` → `paid` → bind → `sender.Send` → `ToHttpResult`. No token, `open_id`, `creator_username`, scope list or client id appears in the DTO or the problem details.

## Acceptance checks

- **Given** an active TikTok connection of the caller **when** the route runs **then** `200` with `nickname`, `avatarUrl`, the exact `privacy_level_options`, the three flags, `maxVideoPostDurationSec`, `canPost = true`, `blockReason = null` — and no token/`open_id`/`creator_username` in the body or the logs.
- **Given** `FakeTikTokServer` answering **HTTP 200** with `error.code = spam_risk_too_many_posts` **then** `200` with `canPost = false` and `blockReason = errors.tiktok.cannotPostNow` (F12) — never a success-shaped DTO with an empty option list.
- **Given** another user's channel, or a non-TikTok channel id **then** `404 not_found` and the fake's counter is unchanged (no outbound call).
- **Given** the flag off **then** `403 feature_disabled`, no outbound call; **given** a drained bucket **then** `429 tiktok_rate_limited` + `Retry-After`, no outbound call (D6).
- **Given** the fake answers 401 twice **then** exactly one refresh ran, the answer is `canPost = false` + `errors.tiktok.reauthRequired`, and **no** `platform_incident` row exists (D10 ladder).
- **Given** two consecutive renders **then** the fake's counter is 2, `SaveChanges` was never called, and no `publications`/`audit_logs` row and no cache entry appeared (F15).
- **Given** a vi and an en caller **then** every `blockReason` has a copy key in both locales (D18).

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| HTTP 200, `error.code = ok`, empty `privacy_level_options` | `canPost = false` + `errors.tiktok.cannotPostNow`; the screen can never build a default-less dropdown (U5) — logged, never an empty-option success |
| `max_video_post_duration_sec` absent/0 | Mapped to `0`: the duration rule then refuses every video instead of guessing a limit; the ambiguity is logged |
| TikTok 5xx or socket timeout | `503` from the catalogue, no incident, no in-request retry (the screen re-renders) |
| Two renders race the bucket | One wins; the loser gets 429 + `Retry-After` (in-flight = 1 per connection, D6) |
| Refresh happens mid-call | The retry uses the new token; the connection row is written only by `ITokenService` under its own `FOR UPDATE` (D13), never here |
| Connection deleted between read and call | `canPost = false` + `reauthRequired`; never a 500 |
| Locale missing | `en` fallback + a fallback log line |

## Notes

- **Security.** Tenant filter only, 404 for everything not the caller's, no `IgnoreQueryFilters`; `paid` because this is an authenticated outbound call per render (F15); `[NotAudited]` because it persists nothing — its trace is the log line and the endpoint's HTTP metrics.
- **Performance.** One outbound call per render, cached nowhere by design; `TikTokOptions` via `IOptionsMonitor`; the bucket is O(1) per acquire with one key string allocation and a per-connection `SemaphoreSlim`.
- **Observability.** One line per lookup: `channelId`, `outcome ∈ ok|200_error|unauthorized|throttled|transient`, `durationMs`, TikTok `log_id?` — never nickname, avatar or option list (D14/D18). No new instrument (07.3 owns `tiktok_*`).
- **i18n.** `blockReason` is a copy key (`errors.tiktok.*`), never a TikTok string.
- **[OPEN] O-1** (`./plan.md` §11): if the TL rules that 07.3.1-T1 owns `ITikTokRateLimiter` end-to-end, step 4's implementation half moves there and this task consumes the TestKit limiter — the endpoint contract and every test above stay identical.
- Consumers: 07.2.2-T1 (validator re-checks creator info through the same port), 10.7.3-T1 (U1/U2/U5/U6/U13), 07.3.3-T1 (job-time caps reuse the `blockReason` vocabulary).
