# 07.2.2-T1 — TikTok publication create, validator matrix and variant-bound consent

| Story | Size | Area | Depends on | Blocks | Phase / flag |

## Goal

Create a TikTok publication row that can only hold settings TikTok would accept, and bind the consent to the **exact declaration variant** the disclosure selection implies. A tampered client (privacy outside the live option set, an interaction the creator disabled, branded content that is private, a caption over 2200 UTF-16 units, a video over the creator's limit, a stale consent version, `description`/`tags`/`publishAt` on a platform that has none) is refused server-side with the D10 code; while the client is unaudited, `SELF_ONLY` is the only accepted privacy.

## Design

**Domain (`Publishing/TikTok/`, pure).** `TikTokPostSettings { PrivacyLevel, DisableComment, DisableDuet, DisableStitch, DisclosureEnabled, BrandOrganic, BrandedContent }` (D5 verbatim); `TikTokMetadataRules.CaptionUtf16Units(string)` counts **UTF-16 code units** (a vi tone-mark pair or an emoji counts 2, K3) + `ValidateCaption`/`ValidateDisclosure`; `TikTokConsentVariants { Music = "tt.v1.music", Branded = "tt.v1.branded" }.For(settings)` → `Branded` iff `BrandedContent` (TT9). `Publication.CreateTikTok(episodeId, channelConnectionId, caption, settings, now)` sets `Platform = "tiktok"`, `Status = AwaitingConsent`, `Privacy = settings.PrivacyLevel` (wire enum verbatim), `Title = caption`, `Description = Tags = PublishAt = NULL`, `ContainsSyntheticMedia = true`, no veto fields, and is the **only** writer of `platform_payload.tiktok` = `{ privacyLevel, disableComment, disableDuet, disableStitch, brandContentToggle, brandOrganicToggle, isAigc: true }` (D8); `publishId`/`videoUrlExpiresAt` are 07.3.1-T1's. [OPEN] O-2: it extends a 06-owned file.

**Create path.** `CreateTikTokPublicationCommand(EpisodeId, ChannelConnectionId, Caption, TikTokPostSettings Settings, string? ConsentTextVersion)` (D3 verbatim) + the optional `tiktok` object on the create body (`disableComment`, `disableDuet`, `disableStitch`, `disclosureEnabled`, `brandOrganic`, `brandedContent`, CR-2). The existing 06 route/handler/validator is **extended**, not duplicated (a `platform = 'tiktok'` connection runs the TikTok branch). `ConsentTextVersion` is the text the client rendered and must equal the derived variant (TT9) — a client that never fetched the variant cannot create the row. `Idempotency-Key` required (same key/body → same `201` + `ETag: "pu-<xmin>"`, no second row; same key/different body → 409 `idempotency_conflict`). One `IUnitOfWork` transaction: the row + `Episode.MarkScheduled` (06 D12) + `publication_updated.v1 { publicationId, episodeId, userId, status: "awaiting_consent", errorCode: null }` + the `publishing.publication_created` audit row (`[Audited]`, ids/codes only).

**Validator matrix** (the server is the authority, UC-6; creator facts from one `IExternalLookup` call under the 20/min bucket).

| # | Rule | On violation |
|---|---|---|
| V1 | `description`, `tags`, `publishAt` all null/absent for TikTok | 400 `validation_failed` (fields named) |
| V2 | Connection exists, is the caller's, `platform = 'tiktok'`, `status = active` | 404 `not_found` / 400 `validation_failed` |
| V3 | `privacyLevel` present and non-empty (no default, U5/TT7) | 400 `tiktok_invalid_post_settings` |
| V4 | `privacyLevel ∈ allowed options` = `creator_info.privacy_level_options`, or its intersection with `{ SELF_ONLY }` while `AuditStatus ≠ approved` (D4/U13) | 400 `tiktok_invalid_post_settings` |
| V4b | While `AuditStatus ≠ approved`, `creator_info.privacy_level_options` must not contain `PUBLIC_TO_EVERYONE` — a public account cannot post for an unaudited client (K9, D4, 07 CR-14) | 409 `tiktok_account_not_private` |
| V5 | `BrandedContent ⇒ privacyLevel ≠ SELF_ONLY` (U8) | 400 `tiktok_invalid_post_settings` |
| V6 | `DisclosureEnabled = false ⇒ !BrandOrganic ∧ !BrandedContent`; `true ⇒ BrandOrganic ∨ BrandedContent` (U7); `brand_content_toggle` still sent, `false` when off (K3) | 400 `tiktok_invalid_post_settings` |
| V7 | `disableComment`/`disableDuet`/`disableStitch` false only when the matching creator flag is false (U6) | 400 `tiktok_invalid_post_settings` |
| V8 | caption 1…`TikTokOptions.CaptionMaxUtf16Units` (2200) UTF-16 code units (U4) | 400 `tiktok_invalid_post_settings` |
| V9 | `assets.duration_sec` of `episodes.final_video_asset_id` ≤ `creator_info.max_video_post_duration_sec` (U3) | 400 `tiktok_video_too_long` |
| V10 | `creator_info.canPost = true` at create (U2; the screen blocks earlier, the server re-checks) | 409 `tiktok_cannot_post_now` |
| V11 | Episode in a publishable state (06.2.1-T1's precondition) | 409 `episode_invalid_state` |

V1/V3/V5–V8 are pure and collected together; V4/V4b/V7/V9/V10 use the single creator-info call, taken after V1/V2 and before any write. `PrivacyLevel` is a closed wire enum ([INFERENCE] `TikTokPrivacyLevel`, the D8/F17 list) so no free text reaches `platform_payload`.

**Consent path** (extends 06.2.2-T1's `ConsentPublicationCommand`). For `platform = 'tiktok'` the expected version is the variant derived from the **stored** `platform_payload.tiktok` selection (never the request, TT9); mismatch → 400 `consent_text_outdated`; then 06's `Publication.Consent(textVersion)` runs unchanged (`→ scheduled`, `consent_source = user`) **plus** `PublishAt = now` (consent instant, D3/TT6), `Episode.MarkScheduled`, the `publishing.consented` audit row and `publication_updated.v1` (`"scheduled"`). `If-Match` required (428 `if_match_required`); the `xmin` token makes a concurrent consent/cancel a 409 `concurrency_conflict` loser. No veto window, no cancel-by-link (TT10). 07.2.2-T2's e-mail call goes **before** the handler's single `SaveChangesAsync`.

**Texts, query, errors.** `Templates/Consent/tt.v1.music.<locale>.md` (never-commercial / "Your brand" → TikTok's Music Usage Confirmation) and `tt.v1.branded.<locale>.md` ("Branded content" alone or with "Your brand" → the Branded Content Policy + Music Usage Confirmation, U9); vi + en, embedded, boot-validated (every variant × locale present, non-empty). `GetConsentTextQuery(Locale, Variant?)` → `ConsentTextDto(Version, Text)`: `branded` → `tt.v1.branded`, `music` → `tt.v1.music`, absent → `music` [DECISION: the never-commercial text is the safe superset; 10.7.3 always sends the selection-derived value]; unknown variant → 400 `validation_failed` (field `variant`). `ErrorCodes`/`ErrorCatalogue` (plan §2 F-12): `tiktok_invalid_post_settings` 400, `tiktok_video_too_long` 400, `tiktok_cannot_post_now` 409, `tiktok_account_not_private` 409 (07 CR-14), `tiktok_rate_limited` 429, `consent_text_outdated` 400, `validation_failed` 400, `idempotency_key_required` 400, `if_match_required` 428, `not_found` 404, `feature_disabled` 403; Domain `PublicationErrorCodes` gains `tiktok_cannot_post_now` (TT3, the rest of CR-3 is 07.3's). CR-3 must land the statuses in `plans/09-backend-api.md` §5.4 ([OPEN] O-4).

## Steps

1. Domain: settings record, rules, variant helper, `Publication.CreateTikTok`; `PublicationErrorCodes` + `ErrorCodes`/`ErrorCatalogue` entries.
2. Application: command + validator (V1–V11) + handler; extend the create route contract with the `tiktok` object and the platform branch (one route, one DTO).
3. Application: the TikTok branch of the shared consent handler (stored-payload variant, `PublishAt = now`).
4. Application: consent-text query + the two variant × locale texts + boot validation + vi/en copy.
5. Endpoint wiring (`RequireFeature("tiktok_publish")`, `paid`/`auth`, `RequireIfMatch()`, `RequireIdempotencyKey()`), then the tests of `## Tests`.

## Acceptance checks

- **Given** `AuditStatus = pending` and a creator with public options **when** the body asks `privacy = PUBLIC_TO_EVERYONE` **then** 400 `tiktok_invalid_post_settings`, no row, no outbox row, no audit row (U13); **given** `AuditStatus = pending`, a public account (`privacy_level_options` contains `PUBLIC_TO_EVERYONE`) and `privacy = SELF_ONLY` **then** 409 `tiktok_account_not_private`, no row (K9, 07 CR-14); **given** `approved` and a privacy **inside** the set **then** the row is created with that wire enum stored verbatim (D8/F17).
- **Given** `brandedContent = true` with `privacy = SELF_ONLY` **then** 400 (U8); `disclosureEnabled = false` with `brandOrganic = true` **then** 400 (U7); `disclosureEnabled = true` with neither flag **then** 400 (U7); a missing `privacyLevel` **then** 400 (TT7).
- **Given** the creator has `comment_disabled = true` **when** the body sends `disableComment = false` **then** 400; with `disableComment = true` the row is created (U6) — both polarities asserted.
- **Given** a caption of 2200 UTF-16 units **then** accepted; 2201 (or 1101 emoji) **then** 400 (U4/K3); **given** `assets.duration_sec` over the creator's limit **then** 400 `tiktok_video_too_long` (U3), equal to it accepted. **Given** `description`/`tags`/`publishAt` present **then** 400 `validation_failed` and `publish_at` stays null (CR-2/TT6).
- **Given** a valid create **then** 201 + `ETag: "pu-<xmin>"`, `awaiting_consent`, `platform_payload.tiktok.isAigc = true`, `contains_synthetic_media = true`, one `publication_updated.v1`, one `publishing.publication_created` row (ids/codes only), the episode already `scheduled`; the replayed `Idempotency-Key` returns the identical body with no second row.
- **Given** a consent whose `consentTextVersion` disagrees with the stored selection **then** 400 `consent_text_outdated`; with the right one **then** `scheduled`, `consent_source = user`, `consent_at` set, `consent_text_version` = the variant, `publish_at = consent_at`, episode `scheduled`, one `publishing.consented` row; without `If-Match` **then** 428 `if_match_required`. **Given** `consent-text?locale=vi&variant=branded` **then** `{ version: "tt.v1.branded", text: <vi, citing the Branded Content Policy + Music Usage Confirmation> }`, `variant=music` cites the Music Usage Confirmation only, both exist in vi and en (U9).

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| No `final_video_asset_id`, or `duration_sec` null | V9 unevaluable → 409 `episode_invalid_state`; never "unknown ⇒ allow" |
| Creator-info fails (5xx/timeout) inside create | The create fails with the catalogue's `503`; no row — never a publication against an unverified option set |
| Creator became unable to post between render and "Post" | V10 → 409 `tiktok_cannot_post_now`, no row, the screen shows the `blockReason` copy (U2) |
| `AuditStatus` flips to `approved` between create and consent | The stored `privacy` stays what create accepted; nothing is re-derived |
| The account flips **public** between connect and create (unaudited) | V4b → 409 `tiktok_account_not_private`, no row; the user switches the account private and re-posts (07 CR-14) |
| Same `Idempotency-Key`, different body | 409 `idempotency_conflict`; the first row is untouched |
| Concurrent consent and `DELETE /publications/{id}` | `xmin` makes the loser throw `DbUpdateConcurrencyException` → 409 `concurrency_conflict`; no half-applied episode transition |
| Consent on a row not `awaiting_consent` | 409 `publication_invalid_state` (06's); a repeat is the same 409, not a silent no-op |
| A consent text missing at boot | Boot template validation fails (a config error, never a runtime 500) |
| Unknown `variant`, unparseable `locale` | 400 `validation_failed` naming the field |

## Notes

- **Security.** Tenant filter on every read (404 across users); the whole matrix is re-run server-side because the screen is a convenience, not a control (UC-6); audit rows carry ids/codes only — the caption length is logged as a number, never the text; `platform_payload.tiktok` holds no token and no presigned URL.
- **Authorization.** `RequireFeature("tiktok_publish")` (owner-only until 07.4.1-T2, CR-6) → `RequireAuthorization()` → `paid` on create (it calls TikTok), `auth` on consent-text; `RequireIdempotencyKey()`/`RequireIfMatch()` as above.
- **Performance.** One creator-info call per create (the same 20/min bucket as the screen), one `assets (episode_id)` lookup, one transaction with the outbound call outside it; the pure rules only count lengths and test membership.
- **Observability / i18n.** `event = tiktok_validation_rejected` (`code` + field names + `channelId`); consent success logs `publicationId`, variant id, `consent_at`; two variants × vi/en plus one copy key per emitted code, `en` fallback with a log line.
- **[OPEN]** O-2 (the 06 aggregate/handler seam), O-4 (CR-3 to 09 §5.4) — `./plan.md` §11. The duration source (plan §2 F-12) is an [INFERENCE] on the 09.6.3-T2 ingest mapping; either way V9 is a hard bound.
- Consumers: 07.2.2-T2 (the e-mail fires in the same transaction), 07.3.1-T1 (init builds `post_info` from the stored payload), 10.7.3-T1 (buttons and the rendered variant).
