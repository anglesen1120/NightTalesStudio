## Goal

One read model behind the weekly review: `GET /admin/kpis?window=7|30` returns `KpiSnapshotDto` with the 15 pinned keys (D7), each carrying value, unit, target, status and source, computed read-only from existing tables, so no KPI is ever ad-hoc SQL again (F11, F15, F17).

## Inputs

- Contract `../README.md` §B3 D7 (route, DTO, keys, statuses, sources) and §B1 K22/K23/K24.
- `../../../00-overview.md` §6: preamble `:262` (`id`, `created_at`, `updated_at` on every table), `users:266`, `episodes:280`, `render_jobs:287`, `usage_records:294`, `platform_quota_usage:292`, `data_deletion_requests:306`, `payments:300`.
- Targets: `../../../08-90-day-operations.md` §5.1.
- 09.9.1-T1's `/api/v1/admin` group + `AdminPolicy`; 09.9.3-T1's telemetry conventions; 12.5.2-T1's `IMarginQuery`.
- CR-11 (`users.email_verified_at`); the cost window uses 00 §6's `usage_records (created_at, operation)` (09 W3 CR-39).

## Design

**Route.** Registered on 09.9.1-T1's group in `Api/Endpoints/AdminEndpoints.cs` with `AdminPolicy` and `[Audited("kpis_view", Category.Support, Visibility.Internal)]` — no second `/admin` group, no own policy (K23). `window ∉ {7, 30}` → `400 invalid_window`; not admin/owner → `404 not_found`.

**Handler.** `Features/Admin/Kpis/GetKpiSnapshotQuery : IQuery<ErrorOr<KpiSnapshotDto>>` (Mediator), `AsNoTracking`, `IgnoreQueryFilters` only because it is under `Features/Admin` (09.2.3-T1 arch test). Nine blocks, one statement each, ≤ 10 statements total; the snapshot is memoised 60 s in-process (F15).

**DTO.** `KpiSnapshotDto (string Window, DateTimeOffset From, DateTimeOffset To, DateTimeOffset GeneratedAt, KpiBlockDto Acquisition, Activation, Retention, Reliability, Cost, Capacity, Compliance, Support, Flagship)`; `KpiBlockDto (KpiMetricDto[] Metrics)`; `KpiMetricDto (string Key, decimal? Value, string Unit, decimal? Target, string Status, string Source, string? DocsRef, string? Link)`; `Status ∈ {ok, warn, breach, unknown}`; `Source ∈ {db, metric, manual}`.

**Keys → source (D7).** `signups` = `count(users)` where `created_at` in window; `verified_email_rate` = share of those with `email_verified_at` not null; `first_video_within_7d_rate` and `second_episode_within_30d_rate` per the pinned definitions (F17 — success is `render_jobs.status = succeeded`, never `publications.publish_at`, K24); `render_success_rate` and `render_p95_seconds` from `render_jobs` terminal rows (`percentile_cont`); `cost_per_episode_usd` from `usage_records.cost_usd` over the window (`render` rows, episode-level), `margin_percent` from `IMarginQuery` (12.5.2-T1 — never recomputed here); `youtube_quota_used_percent` from the newest `platform_quota_usage` row for the current `quota_day`; `deletion_on_time_rate` from `data_deletion_requests` (`completed_at ≤ due_at`); `gpu_utilisation_percent` = `metric` with the 11.6.2-T1 node board link; `flagship_*` and `support_*` = `manual` with `Value = null`, `Status = unknown`, `DocsRef` to `docs/ops/flagship/kpi.md` / `docs/support/sla/YYYY-WW.md`.

**Targets.** One static `KpiTargets` table: `key → (target, unit, direction)`; `lower_is_better` for `render_p95_seconds`; `warn` at 90 % of the target on the good side, `breach` beyond it; a key without a target is `unknown` with the target null. Never inline per branch.

**Window.** `To = now` (FakeClock-able), `From = To - window days`; the quota day uses `platform_quota_usage.quota_day` (YouTube's day), not UTC.

## Steps

1. Add `KpiSnapshotDto`/`KpiBlockDto`/`KpiMetricDto` and the `KpiTargets` table in `Features/Admin/Kpis/` (contract file, no EF entity).
2. Implement the nine block queries in one `KpiQuery` helper; assert each uses `AsNoTracking` and no per-user loop.
3. Wire the Mediator handler with `ErrorOr`, mapping `window` failure to `invalid_window`.
4. Register the endpoint on 09.9.1-T1's admin group with `AdminPolicy` and the audit attribute.
5. Add the 60 s memo keyed by `(window)`.
6. Add the OpenAPI description (keys, units, statuses, `manual` semantics).
7. Unit-test `KpiTargets` status mapping for all 15 keys; integration-test the window boundaries, empty DB, boundary-day rows and the activation definition.
8. Add the arch test (handler under `Features/Admin`) and the audit assertion.

## Acceptance checks

- [ ] `GET /admin/kpis?window=7` and `?window=30` return 200 with all 15 keys, each with the documented `Source`.
- [ ] `window=15` → `400 invalid_window`; a user/admin mismatch token → `404 not_found`; the audit row carries action `kpis_view`.
- [ ] `db` keys are computed for a seeded week and match hand-computed values; `manual` keys return null value + `unknown` + the right `DocsRef`; `gpu_utilisation_percent` carries the 11.6.2-T1 link.
- [ ] Activation uses the first succeeded render and ignores failed renders; a `publications` row with `publish_at` set but another status changes nothing (K24/F17).
- [ ] The response contains no e-mail, title, user id or episode id.
- [ ] The handler is under `Features/Admin` and the endpoint is on the shared group (arch test green).

## Tests

- Unit: all 15 keys × (ok, warn, breach, unknown) and both directions; `lower_is_better` only for `render_p95_seconds`.
- Integration: rows exactly at `From` and `To`; empty DB; user verified 7 d + 1 s before the first success (not activated) vs exactly at the boundary (activated); two successes → one activation; `quota_day` rollover.
- Contract: the DTO's key set equals §B3 D7 (fails on rename).
- Route/security: statuses above; no per-user data (assert the serialised payload for a seeded user never contains its e-mail).

## Failure handling and edge cases

- Empty database → zeros for `db` keys, `unknown` for `manual` keys (never null-as-zero).
- `users.email_verified_at` null (pre-CR-11 rows) → excluded from the activation denominator and counted in a `data_gap` note on the block.
- `render_jobs` with no terminal rows in the window → `unknown` for reliability, not 0 %.
- `IMarginQuery` unavailable → `margin_percent` `unknown` with a log warning; the rest of the snapshot still returns.
- `platform_quota_usage` missing today's row → `youtube_quota_used_percent` `unknown`.
- A slow query (> 1 s) → log with the block name; the endpoint never times out the whole snapshot for one block (each block guarded, worst case `unknown`).
- Clock: everything through `IClock` so tests can pin `now`.

## Notes

- Never group by `publications.publish_at` (K24); no download event exists (F17) — do not add one here.
- Do not re-implement margin (12.5.2-T1) or provider money (`GET /admin/funding`, 12.8.1-T1).
- The 60 s memo is process-local and must be invalidated by nothing else; it exists only to serve the page and its refresh button.
- CR-11 is a precondition: without `users.email_verified_at` the activation block is `unknown`; the 30-day cost window relies on `usage_records (created_at, operation)` (00 §6:296, 09 W3 CR-39).
