## Goal

The owner-facing Angular page at `/admin/kpis` that renders the snapshot against its targets — nine blocks, status as text, links out for the metric/manual values — inside 10's admin shell (D7, K21).

## Inputs

- 08.1.1-T1's `KpiSnapshotDto` and the pinned key list (§B3 D7).
- 10's admin UI design `10.9.1-T0` and shell `10.9.1-T1` (`ADMIN_NAV_ITEMS` in `features/admin/nav/admin-nav.ts`: `{ path, labelKey, icon, roles, feature? }`).
- Shared components `PageHeader`, `StatusChip`, `LoadingState`, `EmptyState`, `ErrorState` (10.1.3-T1) and `core/http` helpers (10 README §6).
- `admin` Transloco scope (vi + en); 10.10.1-T1's axe pass; 11.6.2-T1's board URL.

## Design

`features/admin/kpis/` — `kpis.page.ts` (route component), `kpis.store.ts` (signal store), `kpis.service.ts` (HTTP), `kpi-targets.ts` (label/unit keys only; values come from the API). Route `/admin/kpis`, guarded by the shell's `roleGuard` (admin/owner).

- Nav: append `{ path: '/admin/kpis', labelKey: 'admin.nav.kpis', roles: ['admin', 'owner'] }` to `ADMIN_NAV_ITEMS`; label keys `admin.nav.kpis` + per-block/per-key labels in the `admin` scope, vi + en.
- Window selector writes `?window=7|30` into the URL so a snapshot link is shareable; the default is 30.
- Each block renders a table (`<caption>`, `scope="col"`) of `metric | value | target | status | source`; status via `StatusChip` as **text** (never colour-only); `manual` rows show "manual — see the doc" with the `DocsRef` link; `gpu_utilisation_percent` shows the 11.6.2-T1 board link.
- `LoadingState` / `EmptyState` ("no data for this window yet") / `ErrorState` with retry; a 404 (not admin) falls through to the shell's 404 page, a 401 `reauth_required` opens the shared `ReauthDialog` (10.3.3-T3).
- No charts: tables are the accessible default, and any future sparkline must ship a table equivalent.

## Steps

1. Scaffold `features/admin/kpis/` following the wave-1 feature layout (page/store/service).
2. Add the `ADMIN_NAV_ITEMS` entry and the label keys in the `admin` scope (vi + en).
3. Bind the snapshot: blocks as tables, status chips, manual/metric links, window selector synced to the query string.
4. Wire loading/empty/error states and the re-auth dialog.
5. Component tests with an HTTP fake (both windows, a `manual`-only block, an empty block, an API error).
6. Add the Playwright spec (owner project) with the axe check and the nav entry assertion.

## Acceptance checks

- [ ] Signed in as admin or owner, `/admin/kpis?window=7` loads and shows all nine block headings; as a normal user the route is refused by `roleGuard`.
- [ ] Every block's rows show value, target, status and source; `manual` rows render the doc link and no number; `gpu_utilisation_percent` links to the metric board.
- [ ] Switching the window updates the URL and refetches; the page passes `@axe-core/playwright` with the WCAG 2.1 AA tag set.
- [ ] Labels switch with the UI locale (vi and en) with no missing key.
- [ ] No user identifier or e-mail is rendered anywhere on the page.
- [ ] Errors and empty windows show their states, never a blank table.

## Tests

- Component (Vitest/TestBed): window switch triggers one call; `manual` keys render the link; a null value renders "manual"/"—" not "0"; the error path renders `ErrorState` with retry.
- E2E (Playwright, owner project, `workers: 1`): login through the UI, navigate via the nav entry, assert block headings, run axe, switch to 7 days and assert the URL.
- i18n: a missing-key check in the existing web test setup (both scopes complete).
- No source-text or snapshot-of-template tests; assertions are on rendered semantics.

## Failure handling and edge cases

- API 404 (wrong role) → shell 404; 401 `reauth_required` → re-auth dialog, then retry.
- `Status = unknown` → chip labelled "unknown" with a tooltip naming the reason (`Source = manual` or a data gap), never silently blank.
- Very long numbers → formatted with the shared pipes; units are shown per key (%, USD, hours, count).
- Mobile width → blocks stack; each table scrolls horizontally without breaking the caption/header association.
- Stale snapshot → the page shows `GeneratedAt` and a manual refresh button; it never polls.
