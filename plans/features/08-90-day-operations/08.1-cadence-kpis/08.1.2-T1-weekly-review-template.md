# 08.1.2-T1 — Weekly review template and money routine

## Goal

`docs/ops/weekly/YYYY-WW.md` — the fixed 30-minute review template (KPI snapshot → incidents → costs/margin → quota → support themes → policy news → top 3 backlog changes) plus the 15-minute weekly money routine and the SaaS-checkpoint countdown row (FR-08-1, D13).

## Inputs

- `../../../08-90-day-operations.md` §4 (08.1.2 agenda), §5.3 ("Weekly money routine (owner, 15 min, part of 08.1.2)").
- §B3 D7 (the KPI key names the template records) and D13 (the checkpoint countdown).
- `/admin/funding` (12.8.1-T1) and the margin-per-package view (12.8.4-T1) for the money routine.
- `../08.4-flagship-channel/08.4.3-T1-weekly-kpi-sheet.md` (P) — the flagship sheet is linked, not duplicated.
- `../../../08-90-day-operations.md` §5.2 (the alerts the incidents section lists) and §5.4 (support targets).

## Design

**File.** One file per ISO week, `docs/ops/weekly/YYYY-WW.md`, created from `docs/ops/weekly/TEMPLATE.md`; `docs/ops/weekly/README.md` indexes the weeks and links the previous/next file. Nothing is generated automatically (D13): the template is filled by hand from `/admin/kpis`, 11.6.2-T1's boards, `/admin/funding` and the support SLA log.

**Sections (fixed order, fixed headings).**
1. `## Snapshot` — one row per D7 key (`key | value | target | status`), copied from `/admin/kpis?window=30`, plus the 7-day delta.
2. `## Incidents` — every page/warn fired that week (rule id, when, runbook followed, follow-up), plus anything that should have fired and did not.
3. `## Costs and margin` — provider spend, `cost_per_episode_usd`, `margin_percent`, the set-aside gap.
4. `## Quota` — YouTube quota use vs the alert line, any pending extension request.
5. `## Support themes` — top themes with ticket counts from `docs/support/sla/YYYY-WW.md` (08.3.1-T1) and the SLA breaches.
6. `## Policy news` — monthly YouTube/TikTok policy check when due (08 §8 risk row).
7. `## Top 3 backlog changes` — from `docs/ops/backlog.md` (08.3.2-T1) with the evidence count.
8. `## Money routine (15 min)` — open `/admin/funding`; runway ≥ 14 days?; top up by the set-aside gap (12.8.2-T1); record the top-up and the new balance snapshot; check margin per package.
9. `## Checkpoints` — the countdown line: next SaaS checkpoint (day 30/60/90), days remaining, the metric keys it will read (`docs/ops/saas-checkpoints.md`, 08.5.1-T2) — this is the reminder mechanism (D13).
10. `## Decisions and follow-ups` — owner, date, item; also the quarantine list for flaky tests (09.1.5-T1:99) and any applied CR diff.

**Rules.** Time box 30 minutes; if a number is missing it is recorded as "no data — owner, method", never estimated; the file is written even in a quiet week (one line per empty section).

## Steps

1. Write `docs/ops/weekly/TEMPLATE.md` with the ten headings, the D7 key list in `## Snapshot`, and inline prompts.
2. Write `docs/ops/weekly/README.md` (index + how to create a week: copy the template, name it by ISO week).
3. Add the money-routine checklist verbatim from §5.3 (five steps) and the checkpoint countdown line.
4. Fill the first real week and link it from the index.

## Outputs

- `docs/ops/weekly/TEMPLATE.md`, `docs/ops/weekly/README.md`, and the first `docs/ops/weekly/YYYY-WW.md`.

## Acceptance checks

- [ ] The template contains all ten sections with the exact headings above, and the `## Snapshot` key list matches §B3 D7 names character for character.
- [ ] The money routine lists the five steps from §5.3 including the ≥ 14-day runway check and the balance-snapshot record.
- [ ] The countdown row names the next SaaS checkpoint and points at `docs/ops/saas-checkpoints.md`.
- [ ] The first week's file is filled, the index links it, and the review took ≤ 30 minutes (noted).

## Tests

- Review (no automation): a reviewer checks the template's headings, the D7 key names and the money-routine steps against §5.3; the first filled week is read for "no data" honesty instead of estimates.
- Nothing is asserted by CI: this is a BA artifact, and a doc-parity CI test would be source-text testing.

## Failure handling and edge cases

- Missed week → the file is created late with the missing-week reason in `## Decisions and follow-ups`; the index shows the gap rather than hiding it.
- No users yet → all `## Snapshot` rows are "no data" (zeros from the API are still recorded) and the incidents section is the main content.
- Provider outage → the money routine records the affected step and the follow-up owner.
- If the weekly review grows past 30 minutes twice in a row, that is a finding for the next backlog review (recorded, not silently tolerated).

## Notes

- Do not duplicate the flagship sheet (08.4.3-T1) or the support SLA log: both are linked from their sections.
- The template is the artifact the weekly discipline is audited against after 12 weeks.
