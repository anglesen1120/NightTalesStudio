# 08.4.3-T1 — Weekly channel + production KPI sheet (manual Studio export + platform metrics)

## Goal

Create the channel's single weekly scoreboard — `docs/ops/flagship/kpi.md`, one row per ISO week — and the read-only SQL snippet file `docs/ops/flagship/queries.sql` that produces its platform half from existing tables. The sheet is the Channel phase's evidence base: the Gate 2 checkpoints (08.5.1-T1) read it, and it is where the K1 measurements (cost per video, owner time per episode) become numbers.

Deliverable is a document plus SQL: no code, no endpoint, no new table or view, no scheduler, no YouTube API call (K5).

## Inputs

- `docs/ops/flagship/weekly/YYYY-WW.md` (08.4.2-T1) — owner touch minutes per activity, published count, pauses/incidents, veto seen/edited/cancelled.
- `docs/ops/flagship/calendar.md` (08.4.1-T1) — planned slots per week, the denominator for "slots published".
- 11.6.2-T1 — the dashboards and alert rules whose numbers this sheet cross-checks (quota %, render failure share, alert counts); this task adds no rule and no metric.
- YouTube Studio → Analytics export (manual CSV), K5 [DECISION].
- `../../00-overview.md` §6 — the columns available to the snippets (K14): `usage_records`, `render_jobs`, `publications`, `autopilot_runs`, `platform_incidents`, `audit_logs`.
- 02.8.2 `plan.md` §3.4 — `gates.v1` in `autopilot_runs.gate_results` (`story.pass`, `video.pass`, `checks[]`).
- 02.8.3-T4 — the pause reason code enum (the sheet's pause column is a breakdown by reason code).
- `../README.md` D3 (the column set), K4 (YPP thresholds, tracked not required), K5, F5.

## Design

**1. The sheet.** `docs/ops/flagship/kpi.md`, one row per ISO week, fixed column order so weeks are comparable:

```markdown
# Flagship channel — weekly KPIs
Source key: S = YouTube Studio manual export (K5) · Q = queries.sql snippet · A = alert board (11.6.2-T1) · W = weekly/<week>.md

| Week | Dates | Slots planned | Slots published | Studio export date | Views (S) | Impressions (S) | CTR % (S) | Avg view duration (S) | Subscribers gained / total (S) | Watch hours (S) | Videos published (Q1) | Private-only published (Q1) | Veto seen / edited / cancelled (W) | Autopilot consent share (Q5) | Story gate pass share (Q4) | Video gate pass share (Q4) | Render success share (Q3) | p95 render minutes (Q3) | Render quality failures (Q3) | Cost this week USD (Q2) | Cost per published video USD (Q2÷Q1) | Cost per episode USD (Q2) | Estimated-cost share (Q2) | Pauses (Q4, by reason) | Alerts (A) | Incidents (Q6) | Owner touch minutes (W) | Touch min / episode (W) | Notes |
```

Rules for filling it:

- **Every cell carries its source letter.** An unmeasured cell is `n/a` plus the reason in `Notes` (e.g. `n/a — no Studio export this week`); never a guess, never a carried-forward value without saying so.
- `Slots planned` comes from `calendar.md`; `Slots published` from Q1. A gap between them is the F4/checkpoint metric "slots published without manual rescue" — record why in `Notes`.
- `Cost per published video` = the week's Q2 total ÷ Q1 published count; `Cost per episode` = the same total grouped per episode (an episode produced but not yet published still has cost — say so in `Notes`).
- **YPP column** (K4): subscribers total and watch hours are transcribed every week; the threshold comparison (1,000 subs + 4,000 watch hours / 12 months) is stated once in a `## Monetization thresholds (K4)` block under the table as *tracked, not required* (D4). Mass-produced content is not monetizable (K4) — the note says so, so nobody reads the column as a commitment.
- **Currency.** The sheet is USD-only (`usage_records.cost_usd`) and converts nothing, so exactly one place in the phase applies a rate: Gate 2 criterion C1's VND form (08.5.1-T1) is derived at checkpoint time from the price version in force (`price_versions.credit_usd`/`fx_buffer`, 00 §6, 12 §5.7) plus the owner's stated conversion, and `docs/ops/gate-2.md` names that source. A weekly VND cell would be added here as `Cost this week VND (Q2 x fx)` with the named rate + date — never a floating rate inside a cell.
- Weeks whose output is pre-audit `private` (K8) are marked in `Notes` and do not count toward the 12 public weeks (F4); they are still recorded (the cost/render data is what D1's `long`-tier decision needs).

**2. `docs/ops/flagship/queries.sql`** — seven labelled, **read-only** snippets, each with a one-line comment stating the KPI it produces and the bind parameters. Final text (column names from 00 §6, K14; a name that drifted is fixed here, never invented):

```sql
-- Q1 episodes/videos published per ISO week (§KPI: Videos published, Private-only published)
SELECT to_char(date_trunc('week', p.publish_at), 'IYYY-"W"IW') AS iso_week,  -- NOTE: `publications` has publish_at (00 §6), no published_at (06 CR-1 proposes it; switch when it lands)
       count(*)                                                 AS published_count,
       count(*) FILTER (WHERE p.privacy = 'private')             AS private_only_count
FROM publications p
JOIN episodes e ON e.id = p.episode_id
WHERE e.series_id = :'series_id'::uuid AND p.status = 'published'
GROUP BY 1 ORDER BY 1;

-- Q2 cost per episode and per operation (§KPI: cost this week, cost/episode, cost/video, estimated share)
SELECT u.episode_id,
       round(sum(u.cost_usd), 4)                                        AS cost_usd,
       round(sum(u.cost_usd) FILTER (WHERE u.operation = 'render'), 4)   AS render_cost_usd,
       round(sum(u.cost_usd) FILTER (WHERE u.estimated), 4)              AS estimated_cost_usd,
       round(sum(u.gpu_seconds), 1)                                      AS gpu_seconds,
       bool_or(u.estimated)                                              AS estimated
FROM usage_records u
WHERE u.user_id = :'owner_id'::uuid AND u.created_at >= :'week_start'::timestamptz AND u.created_at < :'week_end'::timestamptz
GROUP BY 1 ORDER BY 2 DESC;

-- Q2b cost by operation and model for the week
SELECT u.operation, u.provider, u.model,
       count(*) AS calls, round(sum(u.cost_usd), 4) AS cost_usd, sum(u.estimated::int) AS estimated_rows
FROM usage_records u
WHERE u.user_id = :'owner_id'::uuid AND u.created_at >= :'week_start'::timestamptz AND u.created_at < :'week_end'::timestamptz
GROUP BY 1,2,3 ORDER BY 4 DESC;

-- Q3 render reliability (§KPI: render success share, p95 render minutes, render quality failures)
SELECT to_char(date_trunc('week', r.submitted_at), 'IYYY-"W"IW') AS iso_week,
       count(*)                                                                        AS renders,
       round(count(*) FILTER (WHERE r.status = 'succeeded')::numeric / nullif(count(*), 0), 3) AS success_share,
       round((percentile_cont(0.95) WITHIN GROUP (
                ORDER BY EXTRACT(EPOCH FROM (r.finished_at - r.started_at)) / 60.0))::numeric, 1) AS p95_minutes,
       count(*) FILTER (WHERE r.status = 'failed' AND r.error_code = 'render_quality_failed') AS quality_failures
FROM render_jobs r
WHERE r.user_id = :'owner_id'::uuid AND r.submitted_at >= :'week_start'::timestamptz AND r.submitted_at < :'week_end'::timestamptz
GROUP BY 1 ORDER BY 1;

-- Q4 autopilot outcomes and gate pass shares (§KPI: pauses by reason, gate pass shares)
SELECT to_char(date_trunc('week', a.slot_at), 'IYYY-"W"IW') AS iso_week,
       count(*)                                                                    AS runs,
       count(*) FILTER (WHERE a.outcome IS NULL)                                    AS still_producing,
       count(*) FILTER (WHERE a.pause_reason IS NOT NULL)                           AS paused_runs,
       coalesce(a.pause_reason, '-')                                                AS pause_reason,
       round(count(*) FILTER (WHERE (a.gate_results -> 'story' ->> 'pass') = 'true')::numeric
             / nullif(count(*) FILTER (WHERE a.gate_results -> 'story' IS NOT NULL), 0), 3) AS story_pass_share,
       round(count(*) FILTER (WHERE (a.gate_results -> 'video' ->> 'pass') = 'true')::numeric
             / nullif(count(*) FILTER (WHERE a.gate_results -> 'video' IS NOT NULL), 0), 3) AS video_pass_share
FROM autopilot_runs a
WHERE a.series_id = :'series_id'::uuid AND a.slot_at >= :'week_start'::timestamptz AND a.slot_at < :'week_end'::timestamptz
GROUP BY 1, 5 ORDER BY 1, 5;

-- Q5 consent source and veto-window usage (§KPI: autopilot consent share, veto acted on)
SELECT to_char(date_trunc('week', p.created_at), 'IYYY-"W"IW') AS iso_week,
       count(*) FILTER (WHERE p.consent_source = 'autopilot') AS consent_autopilot,
       count(*) FILTER (WHERE p.consent_source = 'user')      AS consent_user,
       count(*) FILTER (WHERE p.consent_at IS NOT NULL)        AS consented,
       count(*) FILTER (WHERE p.consent_at IS NOT NULL
                          AND p.consent_at < p.veto_notice_sent_at) AS consented_before_notice
FROM publications p
JOIN episodes e ON e.id = p.episode_id
WHERE e.series_id = :'series_id'::uuid AND p.created_at >= :'week_start'::timestamptz AND p.created_at < :'week_end'::timestamptz
GROUP BY 1 ORDER BY 1;

-- Q6 platform incidents in the week (§KPI: incidents)
SELECT i.platform, i.error_code, i.raised_at, i.cleared_at
FROM platform_incidents i
WHERE i.raised_at >= :'week_start'::timestamptz - interval '7 days' AND i.raised_at < :'week_end'::timestamptz
ORDER BY i.raised_at;

-- Q7 audit cross-check of pause/resume/enable events (§KPI: cross-check of the weekly narrative)
-- NOTE: `audit_logs` has `created_at` (00 §6: actor_user_id, …, created_at; index (subject_user_id, created_at)), no `occurred_at`.
SELECT al.action, al.created_at, al.data
FROM audit_logs al
WHERE al.actor_user_id = :'owner_id'::uuid
  AND al.created_at >= :'week_start'::timestamptz AND al.created_at < :'week_end'::timestamptz
  AND al.action IN ('autopilot.enabled','autopilot.disabled','autopilot.authorization_accepted',
                    'autopilot.authorization_revoked','autopilot.paused','autopilot.resumed')
ORDER BY al.created_at;
```

Snippet rules: read-only (no DDL/DML); run against staging or a replica; every statement is safe to re-run; the `:'week_start'::timestamptz`/`:'week_end'::timestamptz` bounds are half-open ISO weeks (`date_trunc('week', …)` Monday) and always passed explicitly rather than derived from `now()`; `:'owner_id'::uuid` and `:'series_id'::uuid` are bound (K15 — the plan's snippets never assume a single row). The `:'var'` form is mandatory: psql splices a bare `:var` into the SQL raw, so a raw UUID lands unquoted and `>= 2026-09-21` degrades into integer arithmetic; `:'var'` inserts the value as a properly quoted literal.

**3. Studio export procedure (manual, K5).** Once a week, after the routine: YouTube Studio → Analytics → Advanced mode → set the range to the ISO week → export CSV → transcribe the five columns (views, impressions, CTR, average view duration, subscribers gained/total, watch hours) → record `Studio export date` in the row. The CSV itself is **not** committed to the repository (K5: nothing YouTube-derived is stored by our code; the transcription is a plain number set in our own ops doc).

**4. Reconciliation duty.** Before a row is final, the platform columns are re-derived from the run log by hand for at least one metric (08.4.3-T1's V6): a mismatch between the sheet and the log is a finding in the weekly file, not a silent correction.

## Steps

1. Write `docs/ops/flagship/kpi.md` with the header block, the source key, the column row of §Design 1 and an empty `## Monetization thresholds (K4)` block; fill the first row from the rehearsal week.
2. Write `docs/ops/flagship/queries.sql` exactly as §Design 2 (seven snippets labelled Q1–Q7 with their KPI comment and bind parameters).
3. Run each snippet against staging data (or a staging copy) with the week's bounds bound; capture the command and the returned row count for each in the file's header comment; fix any column name that does not exist, and record the correction there (never invent a column).
4. Fill the first KPI row completely from the rehearsal week's data: five Studio columns, the Q-derived platform columns, the touch-time column from 08.4.2-T1's file.
5. Reconcile: recompute `Videos published` and `Pauses` by hand from the Autopilot tab's run log and compare with Q1/Q4; record the reconciliation result in the row's `Notes`.
6. Add the derived columns' formula notes (cost per published video = Q2 total ÷ Q1; touch min/episode = §5 of the weekly file ÷ its published count) so a later operator computes them identically.
7. Confirm the K4 block states "tracked, not required" and repeats that mass-produced content is not monetizable.
8. Hand the sheet to the checkpoint owner (08.5.1-T1) as the week-4/8/12 evidence source.

## Outputs

- `docs/ops/flagship/kpi.md` (new; header + column row + first filled week + K4 block + formula notes).
- `docs/ops/flagship/queries.sql` (new; Q1–Q7 + Q2b, each with a KPI comment and bind parameters, verified to run).
- No code, view, materialized view, scheduled query, dashboard or alert.

## Tests

BA dry runs and document checks:

1. **V4 snippets run** — execute `queries.sql` statement by statement against staging; every statement returns without error; a zero-row week returns header-only (not an error); record the run for each. Negative check: bind `:'series_id'::uuid` to an unknown series id → zero rows, no error (proves the filter is real and the snippets are safe to re-run).
2. **V6 sheet reconciles** — re-derive `Videos published` and `Pauses` by hand from the Autopilot tab; both must equal Q1/Q4 for the same week.
3. **Cost arithmetic check** — recompute `Cost per published video` and `Touch min / episode` from the raw cells with a calculator; both must equal the sheet's derived cells (catches a stale formula).
4. **Estimated-cost sanity** — Q2's `estimated_cost_usd` share is compared with the 12 price-version expectation for the week; a large share is called out in `Notes` rather than silently averaged into the cost numbers.
5. **ISO-week boundary check** — run Q1/Q3 for a week containing a month boundary and confirm the `IYYY-"W"IW` values group Monday–Sunday as the sheet claims (a wrong week key silently mis-aligns the whole trend).
6. **No-export week check** — simulate a week with no Studio export: the channel cells read `n/a` + reason, the platform columns are still filled from Q's, and the row is not skipped.

## Failure handling and edge cases

| Case | Handling |
|---|---|
| No Studio export that week | Channel cells `n/a` + reason in `Notes`; the platform half is still filled (it does not depend on Studio). Never carry last week's numbers forward silently. |
| A snippet fails on an unknown column | The migration drifted from 00 §6: fix the column in `queries.sql`, note the corrected name in the file header, and continue; never substitute a differently-meaning column. |
| `publications` has no `published_at` | Confirmed, not open: 00 §6 lists `privacy`, `publish_at`, `consent_at`, `veto_notice_sent_at`, `external_post_id` and no `published_at` (that column is 06 CR-1's proposal, 06.2.1-T1:141). Q1 keys the week on `publish_at` — an approximation, since a retry or a pre-audit hold can publish in a later week than its slot — and says so in the snippet comment; when `published_at` lands, Q1 switches to it and the note is deleted. `privacy` needs no hedge: it exists. |
| A week with zero published videos | Row is still written: `Slots published = 0`, `Cost per published video = n/a (no published video)`, the cost columns filled (cost happened) and the reason in `Notes` (paused? pre-audit? gate failures?). |
| An episode has cost but is not published (failed render, cancelled slot) | Q2 groups per episode regardless of state; the sheet's cost cells include it and `Notes` says which episode(s) are unattributed — this is exactly the cost per video Gate 2 must not understate. |
| Duplicate rows from a re-run of a snippet | Expected (read-only, re-runnable); the sheet records a snapshot date-hour and treats a later re-run as a corrected snapshot only when the week is still open. |
| Alert count and the weekly file disagree | The alert board (A) is the authority for alerts, the weekly file for causes; record the difference rather than editing the weekly file to match. |
| The K4 comparison reads as a target | Re-state "tracked, not required" in the K4 block; the Gate 2 criteria live in `docs/ops/gate-2.md`, not in this sheet (D4). |

## Notes

- This sheet is a **manual** artefact by decision (K5): the cost of not storing YouTube analytics through the API is a weekly human transcription. Do not automate it later without revisiting the stored-data duty.
- The column set is D3's; adding a column is a document change (a diff in git), not a code change — keep the order stable so week-over-week reading stays mechanical.
- `p95` render time and render success share come from `render_jobs`, whose `submitted_at`/`started_at`/`finished_at` are 00 §6 columns; a render with `started_at IS NULL` is excluded by the percentile and must show up as a non-`succeeded` row in the success share — the two numbers are read together.
- [INFERENCE] the exact Studio export UI path (`Analytics → Advanced mode → Export`) is the current console flow; if it changes, the procedure is updated here and the export date is the real contract.
- [OPEN] the `publications` projection for `published_at`/`privacy` (see the failure table) is the only genuinely uncertain column pair; the snippet file records the resolution when the migrations land.
