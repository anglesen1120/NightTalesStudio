## Goal

Homebrew `postgresql@17` on `127.0.0.1:5432` gives every developer the same local PostgreSQL 17 **without Docker**, and `tools/dev/db-init.sh` creates (idempotently) the role and database named in `.env`. The Api and Worker find it through configuration that is never committed. The `docker-compose.yml` `postgres` service stays available for e2e and image smoke runs but is **never required** for daily development (owner 2026-09-28, 00 §5.1; 09 W3 CR-35).

## Design

**Native server (the daily path).**

```bash
brew install postgresql@17            # keg-only: binaries under $(brew --prefix postgresql@17)/bin
brew services start postgresql@17     # data dir $(brew --prefix)/var/postgresql@17 ⚠️ confirm at implementation
```

- `listen_addresses = '127.0.0.1'`, `port = 5432`: `db-init.sh` runs `ALTER SYSTEM SET listen_addresses = '127.0.0.1'` when `SHOW listen_addresses` differs, then `brew services restart postgresql@17` once (Homebrew's stock value is `localhost`, which also binds `[::1]`); the acceptance check proves the listener is loopback-only (09 W3 CR-35).
- The versioned formula's `psql`/`pg_isready` are not on `PATH` by default (keg-only) — `tools/dev/db-init.sh` resolves them through `$(brew --prefix postgresql@17)/bin` and `docs/dev-setup.md` shows the same `PATH` line.

**`tools/dev/db-init.sh`** (new, idempotent, bash 3.2, `set -euo pipefail`; 09 W3 CR-35):

- Reads `POSTGRES_DB` / `POSTGRES_USER` from `.env` (falling back to the `.env.example` defaults) and `POSTGRES_PASSWORD` from `.env` only; a missing password or the `.env.example` value exits 2. Quoted values must close their quote (only blanks or a comment may follow), else exit 2. Connects to the maintenance database `postgres` on `127.0.0.1:5432` and exits 1 before any change or password transfer unless `server_version_num` is 17.x and `data_directory` is `$(brew --prefix)/var/postgresql@17`; `brew --prefix postgresql@17` failing exits 2; the identity check repeats after the `listen_addresses` restart; every failing mutation exits 1; `--user-secrets` stores `ConnectionStrings:Postgres` for Api and Worker from the parsed values (JSON on stdin) (09 W3 CR-36).
- `CREATE ROLE … LOGIN PASSWORD …` guarded by `SELECT 1 FROM pg_roles WHERE rolname = …`; `ALTER ROLE … PASSWORD …` when the role exists (so a re-run converges).
- `CREATE DATABASE … OWNER …` guarded by `SELECT 1 FROM pg_database WHERE datname = …`.
- `ALTER ROLE … CREATEDB` — 09.2.1-T2's `PostgresFixture` runs as this role and creates `nts_template` plus one database per test class, so the role needs `CREATEDB` on the dev server.
- Refuses `postgres` and `pg_*` as `POSTGRES_USER` and `postgres`/`template0`/`template1` as `POSTGRES_DB` (exit 2), and any existing role with SUPERUSER, CREATEROLE, REPLICATION or BYPASSRLS (exit 1), so a re-run never rewrites an admin role's password; an existing database owned by another role gets `ALTER DATABASE ... OWNER TO` (09 W3 CR-36). Second run creates nothing and exits 0; the password is passed through a shell variable, never in the argv of an external `env`/`psql` call (12 §security).

**`.env` / `.env.example`** (committed example, git-ignored `.env`, 09.1.1-T1; `.gitignore` carries `!.env.example` after `.env*`, 09 W3 CR-36): `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD=change-me-local`. 11.1.1-T1 grows this same file with the app rows.

**Connection string.** `ConnectionStrings:Postgres`, set with `dotnet user-secrets set` for Api and Worker, or with the env var `ConnectionStrings__Postgres`. Nothing goes into `appsettings*.json`. The test connection string `NTS_TEST_PG` (09.2.1-T2, D13) points at this same server.

**Optional compose service (e2e / image smoke).** (09 W3 CR-35) `docker-compose.yml` (repo root) defines the `postgres` service 11.1.1-T1 extends; daily dev does not start it:

```yaml
name: nighttales
services:
  postgres:
    image: postgres:17-alpine     # unchanged for the compose path (11.1.1-T1 extends this service)
    environment:
      POSTGRES_DB: ${POSTGRES_DB:-nighttales}
      POSTGRES_USER: ${POSTGRES_USER:-nighttales}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:?set POSTGRES_PASSWORD in .env}
    ports: ["127.0.0.1:5432:5432"]
    volumes: ["pgdata:/var/lib/postgresql/data"]
    healthcheck:
      test: ["CMD-SHELL", "PGPASSWORD=\"$${POSTGRES_PASSWORD}\" psql -X -At -h 127.0.0.1 -U \"$${POSTGRES_USER}\" -d \"$${POSTGRES_DB}\" -c 'SELECT 1'"]   # password login (09 W3 CR-36)
      interval: 5s
      timeout: 3s
      retries: 20
volumes:
  pgdata: {}
```

- `docs/dev-setup.md` section "Database": the daily commands (`cp .env.example .env`, `brew install postgresql@17`, `brew services start postgresql@17`, `tools/dev/db-init.sh`, then set user-secrets) plus one paragraph on the optional compose path.

## Acceptance checks

- [ ] (09 W3 CR-35) `brew services list | grep postgresql@17` → `started`; `lsof -nP -iTCP:5432 -sTCP:LISTEN` → one listener on `127.0.0.1`, not `*`.
- [ ] `psql "host=127.0.0.1 port=5432 user=nighttales dbname=nighttales" -c 'select version()'` → PostgreSQL 17.x (role and database from `.env`).
- [ ] `tools/dev/db-init.sh` run twice → exit 0 both times; the second run creates nothing (idempotent); `bash -n tools/dev/db-init.sh` and `shellcheck tools/dev/db-init.sh` are clean under bash 3.2.
- [ ] `psql … -c "select rolcreatedb from pg_roles where rolname='nighttales'"` → `t` (`CREATEDB` for the 09.2.1-T2 fixture).
- [ ] From another host on the LAN, port 5432 is not reachable (bound to 127.0.0.1).
- [ ] `git grep -n "POSTGRES_PASSWORD=" -- ':!plans'` → only `.env.example` (the plan text quotes the key itself; 09 W3 CR-36).
- [ ] (optional compose path) `docker compose config` → valid; without `POSTGRES_PASSWORD` it fails with "set POSTGRES_PASSWORD in .env"; `docker compose up -d postgres && docker compose ps` → `healthy` within 100 s.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Port 5432 already used by another Homebrew PostgreSQL major | the native server refuses to start → stop the other cluster (`brew services stop postgresql@<major>`) or set a different `port` in both `postgresql.conf` and the connection string |
| The native server is not running | `tools/dev/db-init.sh` fails fast with the hint `brew services start postgresql@17` |
| The role exists with an unknown password | the script runs `ALTER ROLE … PASSWORD` so a re-run converges to `.env` |
| Compose service started next to the native server | both bind 5432 → set `ports: ["127.0.0.1:5433:5432"]` in a `docker-compose.override.yml` (git-ignored) and the matching connection string, or stop the native service |
| The compose path is used with an old volume | the container starts with the old credentials and the healthcheck (a password login, not `pg_isready`) stays unhealthy → `docker compose down -v` (compose data is disposable; the native dev database is the durable one; 09 W3 CR-36) |
| Apple Silicon | Homebrew installs an arm64 build; the optional `postgres:17-alpine` compose image is multi-arch; no platform override needed |
