| Story | Size | Area | Depends on | Blocks | Phase / flag |

## Goal

`NightTales.Architecture.Tests` fails the build on any violation of the D1 reference table and of the D4, D10, D11 and D12 conventions. It is proven once with deliberate violations.

## Inputs

- README D1 (allow-lists), D2, D4 (handlers), D10 (`IUserOwned`, `IgnoreQueryFilters` allow-list), D11 (`[OutboxEvent]`), D12 (ids-only jobs, Hangfire confinement), F18, N10.
- 09 §4 09.1.2 (L61–64), §7; 02 CR-19 (Fetcher); 09.2.1 plan (no pooling).

## Design

**Assembly reference rules** (`AssemblyReferenceRules.cs`, via `Assembly.GetReferencedAssemblies()` so that unused references count too):

| Assembly | Allowed references (plus `System.*`, `Microsoft.Extensions.*.Abstractions`, `netstandard`) |
|---|---|
| `NightTales.Domain` | `ErrorOr` |
| `NightTales.Application` | Domain, `Mediator.Abstractions`, `FluentValidation*`, `ErrorOr`, `Microsoft.EntityFrameworkCore` (**not** `.Relational`, not `Npgsql*`, not `Microsoft.AspNetCore*`, not `Hangfire*`) |
| `NightTales.Fetcher.Core` | Domain (02 CR-19) |
| `NightTales.Fetcher` | Fetcher.Core, `Microsoft.Extensions.*` |

**Layer rules** (`LayerRules.cs`, ArchUnitNET):
- `Types().That().ResideInAssembly(Api|Worker).And().DoNotHaveNameMatching("Program|.*ServiceCollectionExtensions")` must not depend on types in `NightTales.Infrastructure.Persistence*`.
- Types in `Hangfire*` namespaces may be used only by `NightTales.Infrastructure.Jobs*`, `NightTales.Worker` and `NightTales.Api` (the dashboard, 09.2.6-T2).

**Convention rules** (`ConventionRules.cs`):

| Test | Rule |
|---|---|
| `Handlers_AreSealed_AndLiveInFeatureFolders` | every implementer of `ICommandHandler<,>` / `IQueryHandler<,>` is `sealed` and its namespace matches `NightTales.Application.Features.*.(Commands|Queries).*` |
| `EachRequestFolder_HasOneRequestAndOneHandler` | per leaf namespace: exactly one `ICommand<>`/`IQuery<>` and one handler; at most one `AbstractValidator<>` |
| `DomainEvents_HaveOutboxEventAttribute` | every `IDomainEvent` implementer has `[OutboxEvent(name)]`, names are unique and match `^[a-z_]+\.v[0-9]+$` |
| `Jobs_TakeIdsOnly` | every public method on an `IBackgroundJob` implementer takes only `Guid`, `int`, `long`, enums, `DateTimeOffset`, `CancellationToken`, or `string` named `idempotencyKey` / `recurringId` |
| `EpisodeOrSeriesChildren_AreUserOwned` | every type with a `Guid EpisodeId` or `Guid SeriesId` property, deriving from `Entity`, implements `IUserOwned` |
| `Endpoints_DoNotReferenceDbContexts` | `NightTales.Api.Endpoints*` types do not depend on `IAppDbContext` / `IReadDb` |

**Call-site rules** (`CallSiteRules.cs`): an IL scan with `System.Reflection.Metadata` of every method body in `src` assemblies for `call`/`callvirt` to:
- `EntityFrameworkQueryableExtensions.IgnoreQueryFilters` → the declaring type must be in `Application.Features.Admin.*` or in `AllowLists.IgnoreQueryFiltersTypes` (`RetentionSweepJob`, `DataDeletionJob`, `CreditReconciliationJob`, `SystemWorkQuery`) (D10);
- `EntityFrameworkServiceCollectionExtensions.AddDbContextPool` → none allowed.

Lambdas compile to compiler-generated nested types, so the scan attributes a hit to the outermost declaring type.

## Steps

1. Load the architecture once (`ArchitectureModel`) and write the allow-lists.
2. Implement the assembly reference rules.
3. Implement the layer and convention rules with ArchUnitNET.
4. Spike (≤ 1 h): can ArchUnitNET see the `IgnoreQueryFilters` call inside a lambda? If not, implement `CallSiteRules` with the IL scan.
5. Negative proof on a scratch branch: add one violation per family (Npgsql in Application; an unsealed handler; a job with `string text`; an event without the attribute; `IgnoreQueryFilters` in a Series handler), confirm that each test fails, then delete the branch.
6. Add CODEOWNERS for `tests/NightTales.Architecture.Tests/AllowLists.cs` (TL) [DECISION].

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| A rule matches nothing yet (no jobs, no events) | the rule passes. ArchUnitNET's "should exist" check is disabled for these rules (`WithoutRequiringPositiveResults()`) ⚠️ API name to confirm |
| The Mediator source generator emits types into the Api/Worker assemblies | exclude the `Mediator` namespace from the layer rules |
| Compiler-generated closure types | attributed to the declaring type (IL scan) |
| A legitimate new exception | edit `AllowLists.cs` in the same PR, with TL review via CODEOWNERS |
