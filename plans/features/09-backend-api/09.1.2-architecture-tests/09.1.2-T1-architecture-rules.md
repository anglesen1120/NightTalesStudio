## Goal

`NightTales.Architecture.Tests` fails the build on any violation of the D1 reference table and of the D4, D10, D11 and D12 conventions. It is proven once with deliberate violations.

## Inputs

- README D1 (allow-lists), D2, D4 (handlers), D10 (`IUserOwned`, `IgnoreQueryFilters` allow-list), D11 (`[OutboxEvent]`), D12 (ids-only jobs, Hangfire confinement), F18, N10.
- 09 §4 09.1.2 (L61–64), §7; 02 CR-19 (Fetcher); 09.2.1 plan (no pooling).

## Design

**Assembly reference rules** (`AssemblyReferenceRules.cs`, via `Assembly.GetReferencedAssemblies()` so that unused references count too):

| Assembly | Allowed references (plus `System.*`, `Microsoft.Extensions.*.Abstractions`, `netstandard`) |
|---|---|
| `NightTales.Domain` | `ErrorOr` |
| `NightTales.Application` | Domain, `Mediator.Abstractions`, `FluentValidation*`, `ErrorOr`, `Microsoft.EntityFrameworkCore` (**not** `.Relational`, not `Npgsql*`, not `Microsoft.AspNetCore*`, not `Hangfire*`) |
| `NightTales.Fetcher.Core` | Domain (02 CR-19) |
| `NightTales.Fetcher` | Fetcher.Core, `Microsoft.Extensions.*` |

**Layer rules** (`LayerRules.cs`, ArchUnitNET):
- `Types().That().ResideInAssembly(Api|Worker).And().DoNotHaveNameMatching("Program|.*ServiceCollectionExtensions")` must not depend on types in `NightTales.Infrastructure.Persistence*`.
- Types in `Hangfire*` namespaces may be used only by `NightTales.Infrastructure.Jobs*`, `NightTales.Worker` and `NightTales.Api` (the dashboard, 09.2.6-T2).

**Convention rules** (`ConventionRules.cs`):

| Test | Rule |
|---|---|
| `Handlers_AreSealed_AndLiveInFeatureFolders` | every implementer of `ICommandHandler<,>` / `IQueryHandler<,>` is `sealed` and its namespace matches `NightTales.Application.Features.*.(Commands|Queries).*` |
| `EachRequestFolder_HasOneRequestAndOneHandler` | per leaf namespace: exactly one `ICommand<>`/`IQuery<>` and one handler; at most one `AbstractValidator<>` |
| `DomainEvents_HaveOutboxEventAttribute` | every `IDomainEvent` implementer has `[OutboxEvent(name)]`, names are unique and match `^[a-z_]+\.v[0-9]+$` |
| `Jobs_TakeIdsOnly` | every public method on an `IBackgroundJob` implementer takes only `Guid`, `int`, `long`, enums, `DateTimeOffset`, `CancellationToken`, or `string` named `idempotencyKey` / `recurringId` |
| `EpisodeOrSeriesChildren_AreUserOwned` | every type with a `Guid EpisodeId` or `Guid SeriesId` property, deriving from `Entity`, implements `IUserOwned` |
| `Endpoints_DoNotReferenceDbContexts` | `NightTales.Api.Endpoints*` types do not depend on `IAppDbContext` / `IReadDb` |

**Call-site rules** (`CallSiteRules.cs`): an IL scan with `System.Reflection.Metadata` of every method body in `src` assemblies for `call`/`callvirt` to:
- `EntityFrameworkQueryableExtensions.IgnoreQueryFilters` → the declaring type must be in `Application.Features.Admin.*` or in `AllowLists.IgnoreQueryFiltersTypes` (`RetentionSweepJob`, `DataDeletionJob`, `CreditReconciliationJob`, `SystemWorkQuery`) (D10);
- `EntityFrameworkServiceCollectionExtensions.AddDbContextPool` → none allowed.

Lambdas compile to compiler-generated nested types, so the scan attributes a hit to the outermost declaring type.

## Steps

1. Load the architecture once (`ArchitectureModel`) and write the allow-lists.
2. Implement the assembly reference rules.
3. Implement the layer and convention rules with ArchUnitNET.
4. Spike (≤ 1 h): can ArchUnitNET see the `IgnoreQueryFilters` call inside a lambda? If not, implement `CallSiteRules` with the IL scan.
5. Negative proof on a scratch branch: add one violation per family (Npgsql in Application; an unsealed handler; a job with `string text`; an event without the attribute; `IgnoreQueryFilters` in a Series handler), confirm that each test fails, then delete the branch.
6. Add CODEOWNERS for `tests/NightTales.Architecture.Tests/AllowLists.cs` (TL) [DECISION].

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| A rule matches nothing yet (no jobs, no events) | the rule passes. ArchUnitNET's "should exist" check is disabled for these rules (`WithoutRequiringPositiveResults()` — **confirmed in 0.13.4**, `ArchUnitNET.Fluent.ArchRule\`1.WithoutRequiringPositiveResults()`) |
| The Mediator source generator emits types into the Api/Worker assemblies | exclude the `Mediator` namespace from the layer rules |
| Compiler-generated closure types | attributed to the declaring type (IL scan) |
| A legitimate new exception | edit `AllowLists.cs` in the same PR, with TL review via CODEOWNERS |

### Implementation record (2026-09-29)

Shipped: `tests/NightTales.Architecture.Tests/{ArchitectureModel,AllowLists,AssemblyReferenceRules,LayerRules,ConventionRules,CallSiteRules}.cs` + `.github/CODEOWNERS` (new file; entry for `AllowLists.cs`, owner `@anglesen1120`). 13 tests. `dotnet test tests/NightTales.Architecture.Tests -c Release` → 13/13 green, 0.6 s, no Docker.

**Step 4 spike — can ArchUnitNET see `IgnoreQueryFilters` inside a lambda? ✅ Yes.** A scratch `IgnoreQueryFilters()` call inside a `Func<IQueryable<object>>` lambda compiled into `ScratchSeriesHandler.<Handle>b__0_0` was reported by an ArchUnitNET rule over the Application assembly as
`NightTales.Application.Features.Series.Commands.ScratchSeriesCommand.ScratchSeriesHandler does depend on "Microsoft.EntityFrameworkCore.EntityFrameworkQueryableExtensions"`
— i.e. ArchUnitNET resolves the `MethodCallDependency` and attributes it to the **outermost declaring type**, not to the compiler-generated closure. `CallSiteRules` (the IL scan with `System.Reflection.Metadata`) is nevertheless kept, as specified by this task: it gives the explicit allow-list semantics (namespace prefix plus the four named system types) and names the exact method and target in the failure message. Two IL gotchas found while building it: an instantiated generic call carries a **`MethodSpec` token (0x2B)**, not `MemberRef` — the spec must be unwrapped before reading the member; and operand lengths must come from the runtime `OpCodes` table (`OpCode.Size`/`OperandType`), with `InlineSwitch` special-cased.

**Step 5 negative proof (local; there is no CI yet).** Five scratch violations were added on the worktree, each named test failed, then every scratch file, the temporary `Npgsql.EntityFrameworkCore.PostgreSQL` reference and the touched lock files were reverted and the suite re-run green (13/13). **Defect the proof caught in the rules themselves.** The first draft compared `Type.GetInterfaces()[i].FullName` with `Mediator.ICommandHandler\`2`; a *constructed* generic interface has a full name that includes its type arguments, so every handler rule silently matched nothing (violations 2 and 3 stayed green). Fixed by comparing `GetGenericTypeDefinition().FullName` for generic interfaces. Evidence that the failure messages name the offending type and rule: the table above.

**Same-assembly call tokens (defensive, proved 2026-09-29).** A `call` to a member of the *same* assembly carries a `MethodDef` token (0x06), not `MemberRef`. Proved with a scratch internal shim `TenantShim.IgnoreQueryFilters<T>` inside Application called from a Series handler — `IgnoreQueryFilters_OnlyInAllowList` went red with `IgnoreQueryFilters called from …ShimProbe.ShimProbeHandler.Handle (target NightTales.Application.Features.Series.Commands.ShimProbe.TenantShim)`, then the shim was deleted and the suite re-run green. So an internal shim cannot be used to bypass the D10 rule.

**Deviations from this task's Design table (09.1.2 CR-1, CR-2).**
- **CR-1** — `AllowLists.ApplicationAllowedReferences` also permits `NightTales.RenderNode.Contract`. This task's Design table omits it; README D1 (11 CR-3) includes it, and the README is the contract.
- **CR-2** — the allow-list lists the assembly name **`Mediator`**, not only the package id `Mediator.Abstractions`. The `Mediator.Abstractions` 3.0.2 package ships `lib/{net8.0,netstandard2.0}/Mediator.dll`, so the compiled reference is `Mediator`; the rule matches assembly names. This was found by negative proof #1 (the first run reported both `Mediator` and `Npgsql`) and re-proved after the fix (`["Npgsql"]` only). The package id is kept in the set for traceability.

**Other decisions.** `IUserOwned`/`IDomainEvent`/`Entity`/`IBackgroundJob` are matched by **name + namespace prefix** (`NightTales.Domain*`, `NightTales.Application*`) because those markers do not exist yet in every worktree; the rules therefore pass on an empty set and stay correct once 09.1.3 adds them. Layer rules use `WithoutRequiringPositiveResults()`. `Endpoints_DoNotReferenceDbContexts` is an ArchUnitNET rule over `NightTales.Api.Endpoints*` (`NotDependOnAnyTypesThat().HaveNameMatching("^IAppDbContext$|^IReadDb$")`). `tests/Directory.Build.props` gained `<NoWarn>$(NoWarn);CA1707</NoWarn>` because warnings are errors and the task's Test table uses `Subject_Behaviour_Expected` names. The test project references `NightTales.Fetcher(.Core)` through `Condition="Exists(...)"`, so `Fetcher_ReferencesOnlyDomainAndCore` cannot pass vacuously once 02.5.2-T3 creates those projects; the lock files are unchanged today.
