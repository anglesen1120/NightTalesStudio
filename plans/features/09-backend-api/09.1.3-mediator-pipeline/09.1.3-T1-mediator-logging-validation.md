## Goal

Api and Worker send messages through a Scoped, source-generated Mediator. Every message passes the ordered pipeline, and a validation failure returns `validation_failed` errors without reaching the handler.

## Inputs

- README N1, N2, F03, D4 (list and markers), D7 (`validation_failed`).
- 09 §4 09.1.3 (L66–69).

## Design

```csharp
// Application/Behaviors/MediatorPipeline.cs
public static class MediatorPipeline
{
    public static readonly Type[] Behaviors =
    [
        typeof(LoggingBehavior<,>), typeof(AuthorizationBehavior<,>), typeof(ValidationBehavior<,>),
        typeof(UnitOfWorkBehavior<,>), typeof(IdempotencyBehavior<,>), typeof(AuditBehavior<,>),
    ];
}

// Api/Program.cs and Worker/Program.cs
services.AddMediator((MediatorOptions o) =>
{
    o.ServiceLifetime = ServiceLifetime.Scoped;
    o.Assemblies = [typeof(ApplicationAssemblyMarker)];
    o.PipelineBehaviors = MediatorPipeline.Behaviors;   // ⚠️ must be an inline array if the generator needs literals
});

public sealed class LoggingBehavior<TMessage, TResponse>(ILogger<LoggingBehavior<TMessage, TResponse>> log)
    : IPipelineBehavior<TMessage, TResponse> where TMessage : IMessage where TResponse : IErrorOr;

public sealed class ValidationBehavior<TMessage, TResponse>(IEnumerable<IValidator<TMessage>> validators)
    : IPipelineBehavior<TMessage, TResponse> where TMessage : IMessage where TResponse : IErrorOr;

// Common/Errors/ErrorOrFactory.cs — cached compiled conversion List<Error> → TResponse
public static class ErrorOrFactory<TResponse> where TResponse : IErrorOr
{
    public static TResponse From(List<Error> errors);
}

public interface IIdempotentCommand { string? IdempotencyKey { get; } }
public interface IRequireRole { PlatformRole RequiredRole { get; } }
[AttributeUsage(AttributeTargets.Class)] public sealed class AllowAnonymousRequestAttribute : Attribute;
```

- T1 ships `AuthorizationBehavior`, `UnitOfWorkBehavior`, `IdempotencyBehavior` and `AuditBehavior` as **pass-through** classes, so the list compiles. T2 and 09.3.6-T1 replace their bodies. [DECISION] This is intentional scaffolding inside one wave. They are replaced before any feature command lands (gate `09-skeleton`).
- `ValidationBehavior`:
  - runs every validator with `ValidateAsync`;
  - maps each failure to `Error.Validation(code: ErrorCodes.ValidationFailed, description: failure.ErrorMessage, metadata: { "field": camelCase(PropertyName) })`;
  - returns all of them together.
- Validators are registered with `AddValidatorsFromAssemblyContaining<ApplicationAssemblyMarker>(ServiceLifetime.Scoped)`.
- `LoggingBehavior`:
  - uses the `Stopwatch.GetTimestamp` delta;
  - logs `Information` for ok and `Warning` for errors;
  - logs only the message type name and `result.FirstError.Code`, never property values.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| A validator throws | the exception propagates (a bug, not a validation error); the Api maps it to 500 (09.1.4) |
| A message without a validator | passes through |
| `TResponse` not `IErrorOr` | not allowed: the behaviours constrain it; a handler returning a raw type fails compilation of the generated pipeline ⚠️ confirm the generator's diagnostics |
