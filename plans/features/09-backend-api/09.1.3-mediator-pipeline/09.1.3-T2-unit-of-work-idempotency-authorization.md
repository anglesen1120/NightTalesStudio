## Goal

Every command runs in one transaction that opens before its handler. Its effects, outbox rows and idempotency record commit or roll back together. A replayed or racing idempotent command executes exactly once, and unauthenticated requests are refused by default.

## Design

```csharp
// Application/Abstractions/Persistence/IUnitOfWork.cs
public interface IUnitOfWork
{
    Task BeginAsync(CancellationToken ct);                       // ReadCommitted, on the scoped AppDbContext connection
    Task<ErrorOr<Success>> CommitAsync(CancellationToken ct);    // SaveChangesAsync + commit; maps concurrency/transient errors
    Task RollbackAsync(CancellationToken ct);
}

// Application/Abstractions/Idempotency/IIdempotencyStore.cs
public interface IIdempotencyStore
{
    Task<IdempotencyClaim> ClaimAsync(Guid userId, string key, string requestHash, DateTimeOffset now, CancellationToken ct);
    Task CompleteAsync(Guid claimId, string responseType, string responseJson, CancellationToken ct);
}
public abstract record IdempotencyClaim
{
    public sealed record New(Guid ClaimId) : IdempotencyClaim;
    public sealed record Replay(string ResponseType, string ResponseJson) : IdempotencyClaim;
    public sealed record Mismatch : IdempotencyClaim;          // → 422 idempotency_key_reused
}
```

`UnitOfWorkBehavior<TMessage,TResponse> where TMessage : IBaseCommand`:
1. `BeginAsync`.
2. `var r = await next(m, ct)`.
3. If `r.IsError` → `RollbackAsync` and return `r`.
4. Otherwise `CommitAsync`:
   - `DbUpdateConcurrencyException` → rollback, return `concurrency_conflict`;
   - `NpgsqlException { IsTransient: true }` → rollback, return `service_unavailable`.
5. Return `r`.

Exceptions from the handler roll back and rethrow.

`IdempotencyBehavior<TMessage,TResponse> where TMessage : IIdempotentCommand` runs inside the transaction:
1. A null or empty key passes through (the endpoint filter already enforces the key where it is required, 09.1.4).
2. `requestHash = SHA256(typeof(TMessage).FullName + "\n" + JsonSerializer.Serialize(m with key cleared, canonical options))`. The canonical options are: sorted properties, camelCase, no indentation.
3. `ClaimAsync` SQL:
   ```sql
   INSERT INTO idempotency_keys (id, user_id, key, request_hash, created_at, expires_at)
   VALUES (@id, @user, @key, @hash, @now, @now + interval '24 hours')
   ON CONFLICT (user_id, key) DO NOTHING
   RETURNING id;
   -- no row → SELECT id, request_hash, response_type, response, expires_at FROM idempotency_keys WHERE user_id=@user AND key=@key FOR UPDATE;
   --   expires_at < @now → UPDATE … SET request_hash=@hash, response=NULL, response_type=NULL, created_at=@now, expires_at=@now+24h → New
   --   request_hash <> @hash → Mismatch; response IS NULL → cannot happen after the twin committed (it would have rolled back) → treat as New
   --   else → Replay
   ```
4. `Replay` → deserialize to the success value type and wrap it as `TResponse`; the handler does not run.
5. `New` → `next`; on success `CompleteAsync` in the same transaction, then return.

`AuthorizationBehavior`:
- If the message has `[AllowAnonymousRequest]` → pass.
- `!currentUser.IsAuthenticated` → `Error.Unauthorized(code: ErrorCodes.Unauthorized)` (401).
- `IRequireRole` and the role is lower than required → `ErrorCodes.NotFound` (404; admin/owner surfaces are not revealed, 09 §5.4 `not_found`).
- `Actor == system` passes role checks only for `PlatformRole.User` requirements [DECISION]. System jobs never perform admin actions.

The Infrastructure `EfUnitOfWork` uses `AppDbContext.Database.BeginTransactionAsync(IsolationLevel.ReadCommitted)` and `IDbContextTransaction`. `IdempotencyStore` uses raw SQL on the same connection and transaction.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| The client retries while the first request is still running | the twin blocks on the unique index (P4) until the first commits, then replays |
| The first request fails (error result) | rollback removes the claim; the twin inserts and executes |
| The sweep meets a row a twin is renewing | the renewal wins: the batch re-tests `expires_at` on the row itself, which is the only qualifier `ReadCommitted` re-evaluates (EvalPlanQual) after the claim commits; the claim stays. The reverse direction is covered too — a reuse whose row the sweep took reports 0 rows and the claim is taken afresh |
| The response type was renamed between deploy and replay | deserialization fails → treat as `Mismatch` with 422 and log a warning [DECISION]; keys live 24 h, so this only occurs across a deploy |
| A long handler holds a transaction during an external call | forbidden by 09 T5: commands never call external APIs (00 §5.2); jobs do |
| Idempotency on a query | not possible: the constraint is `IIdempotentCommand` |
