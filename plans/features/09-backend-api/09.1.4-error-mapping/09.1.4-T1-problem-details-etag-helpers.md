## Goal

Any `ErrorOr` result maps to the right status and a uniform ProblemDetails body. Paid POSTs without a key and D9/D15 routes without `If-Match` are rejected at the endpoint.

## Inputs

- README D7, D14, D15, D17; 09 §5.4 (catalogue); 02 README D8 (02 codes), D9 (ETags); 02 CR-20.

Mapping rules:
- If any error has `Type == Validation` → 400 `validation_failed`, with `errors` grouped by `metadata["field"]`.
- Otherwise the first error's code → `ErrorCatalogue.Status`. An unknown code → 500 `internal_error`, and the error is logged as a bug.
- A 429 with `metadata["retryAfterSeconds"]` sets the `Retry-After` header.
- `ETag`: `ToCreatedResult` / `ToHttpResult` set the `ETag` header when the value implements `IHasETag { string ETag { get; } }`.

Filters:
- `RequireIdempotencyKey()`: the `Idempotency-Key` header must be present, 1–128 chars, printable ASCII `0x21–0x7E`. Otherwise 400 `idempotency_key_required`.
- `RequireIfMatch()`: the `If-Match` header must be present. Otherwise 428 `if_match_required`.
- Binder: `[FromHeader(Name = "If-Match")] string? ifMatch`, passed into the command.

Exceptions: `app.UseExceptionHandler` + `AddProblemDetails` customisation → 500 `internal_error`, with the `traceId` from `Activity.Current`.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Several non-validation errors | the first determines the status; all are listed under `errors` only if they are validation errors |
| A 202 body code returned as an error by mistake | `AcceptedBodyCodes` is excluded from `Status`; the unit test fails if a code appears in both |
| A client sends `If-Match: *` | not matched → 412 with the resource code [DECISION]; clients must send the exact ETag |
