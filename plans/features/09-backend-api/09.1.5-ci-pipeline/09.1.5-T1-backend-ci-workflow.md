## Goal

Every PR and every push to `main` builds, format-checks and tests the backend, including the PostgreSQL integration tests, and publishes `openapi.json`. A formatting error or a failing test turns the run red.

## Inputs

- 09.1.1-T1 (`RestorePackagesWithLockFile`, committed `packages.lock.json`), README D2 (`NightTales.ci.slnf`), D13 (`PostgresFixture` on `NTS_TEST_PG`; 09 W3 CR-35), D14 (openapi path), O2; 09.1.1-T2 (dev database), 09.2.1-T2 (harness).
- 09 §4 09.1.5 (L75–76); 11.5.1 (owns the rest of the pipeline).

## Design

`.github/workflows/backend.yml`:

```yaml
name: backend
on:
  pull_request:
  push: { branches: [main] }
permissions: { contents: read }
concurrency: { group: backend-${{ github.ref }}, cancel-in-progress: true }
env: { DOTNET_NOLOGO: "1", DOTNET_CLI_TELEMETRY_OPTOUT: "1",
       ConnectionStrings__Postgres: "Host=127.0.0.1;Database=nighttales;Username=nighttales;Password=ci-openapi-document-generation-placeholder" }   # (09 W3 CR-37): the build-time OpenAPI generator boots the Api
jobs:
  build-test:
    runs-on: ubuntu-24.04
    steps:
      - uses: actions/checkout@<sha>
      - uses: actions/setup-dotnet@<sha>          # reads global.json
        with: { global-json-file: global.json }
      - run: dotnet restore NightTales.ci.slnf --locked-mode
      - run: dotnet build NightTales.ci.slnf -c Release --no-restore
      - run: dotnet format NightTales.ci.slnf --verify-no-changes --no-restore
      - name: Unit tests (no database)
        shell: bash          # `set -o pipefail`: without it the `tee` pipeline would mask the test exit code
        run: |
          set -o pipefail
          dotnet test NightTales.ci.slnf -c Release --no-build \
            --filter "Category!=Integration" --minimum-expected-tests 1 2>&1 | tee unit-tests.log   # (09 W3 CR-37)
      - uses: actions/upload-artifact@<sha>
        if: always()         # the document comes out of the build step, so a red format/test step must not drop it
        with: { name: openapi, path: src/NightTales.Api/openapi.json, if-no-files-found: error, retention-days: 14 }   # (QA-L) 14 days = plan §4 UC2
      - uses: actions/upload-artifact@<sha>
        if: always()
        with: { name: test-results-unit, path: unit-tests.log, if-no-files-found: warn, retention-days: 14 }   # console log, not trx (09 W3 CR-37)
  integration:
    needs: build-test
    runs-on: ubuntu-24.04
    services:
      postgres:
        image: postgres:17
        env: { POSTGRES_PASSWORD: postgres }
        ports: ["5432:5432"]
        options: >-
          --health-cmd "pg_isready -U postgres"
          --health-interval 5s
          --health-timeout 3s
          --health-retries 20
    env:
      NTS_TEST_PG: "Host=127.0.0.1;Port=5432;Database=postgres;Username=postgres;Password=postgres"
    steps:
      - uses: actions/checkout@<sha>
      - uses: actions/setup-dotnet@<sha>
        with: { global-json-file: global.json }
      - run: dotnet restore NightTales.ci.slnf --locked-mode
      - name: Integration tests (PostgreSQL 17 service)
        shell: bash          # `set -o pipefail`: without it the `tee` pipeline would mask the test exit code
        run: |
          set -o pipefail
          dotnet test NightTales.ci.slnf -c Release --no-restore \
            --filter "Category=Integration" --minimum-expected-tests 1 2>&1 | tee integration-tests.log   # (09 W3 CR-37)
      - uses: actions/upload-artifact@<sha>
        if: always()
        with: { name: test-results-integration, path: integration-tests.log, if-no-files-found: warn, retention-days: 14 }   # console log, not trx (09 W3 CR-37)
```

The snippet above is `.github/workflows/backend.yml` with the action SHAs replaced by `<sha>`: the two `dotnet test` steps are `shell: bash` + literal block + `set -o pipefail` (a folded `>` scalar would have run the pipeline without `pipefail`, so a failing `dotnet test` piped into `tee` would have reported `tee`'s exit code, 0). Every `actions/upload-artifact` step sets `retention-days: 14` (plan §4 UC2), and the `openapi` upload carries `if: always()` because the document is produced by the build step.

- (09 W3 CR-35) The `integration` job runs against a runner-provided `postgres:17` service container (health-gated with `pg_isready`) and sets `NTS_TEST_PG` to it; `PostgresFixture` (09.2.1-T2) creates `nts_template` and one database per test class on that server. **No Docker-in-the-runner step**: the job never calls `docker`, so tests need no daemon of their own.
- Integration tests carry `[Trait("Category", "Integration")]` [DECISION], set once on a base class in TestKit (`IntegrationTest`) and inherited by every derived class (verified). **(09 W3 CR-37)** The four DB-dependent classes in `tests/NightTales.Infrastructure.UnitTests/Persistence/` (`AppDbContextTests`, `JsonColumnSpikeTests`, `ModelConstraintTests`, `ReadDbContextDatabaseTests`, still on the local `PostgresTestFixture` because converging them needs TestKit's probe model, which 09.1.5-T1 does not own) carry the same trait, so the integration job runs the whole solution filter — 13 more tests than `NightTales.Api.IntegrationTests` alone. Verified split: unit job 35 tests, integration job 23.
- **(09 W3 CR-37) `--minimum-expected-tests 1` is part of both test steps.** `tests/Directory.Build.props` passes `--ignore-exit-code 8`, so a filter that matches nothing prints `total: 0` and still exits 0 — a typo would leave the job vacuously green. Verified on this toolchain: zero-match → `Test run summary: Minimum expected tests policy violation, tests ran 0, minimum expected 1`, exit 9 (8 is the ignored code, 9 is not); both real filters → exit 0.
- **(09 W3 CR-37) No `--logger trx` / `--report-trx`.** Verified 2026-09-29: they turn the run into `Zero tests ran` with exit 5 under this xunit.v3/MTP setup, so both jobs write their console output to `unit-tests.log` / `integration-tests.log` and upload that. The Tests table's "the trx artifact is uploaded" is therefore "the console-log artifact is uploaded".
- **(09 W3 CR-37) `openapi.json` recipe (verified, .NET SDK 10.0.401).** `Microsoft.Extensions.ApiDescription.Server` **10.0.12** (matches `Microsoft.AspNetCore.OpenApi`) with `IncludeAssets=runtime;build;native;contentfiles;analyzers;buildtransitive`, `PrivateAssets=all`; `<OpenApiGenerateDocuments>true</OpenApiGenerateDocuments>`; the tool writes `$(MSBuildProjectName).json` into `$(OpenApiDocumentsDirectory)` (set to `obj/openapi`), and a `Copy` target `AfterTargets="GenerateOpenApiDocuments"` produces `src/NightTales.Api/openapi.json` (git-ignored). `Program.cs` needs `builder.Services.AddOpenApi()` (without it the build fails with "Unable to find service type 'Microsoft.Extensions.ApiDescription.IDocumentProvider'"), and because the generator **boots the app** every build step needs a parseable `ConnectionStrings__Postgres` — the workflow-level constant placeholder, never a real secret. Verified document: `openapi: 3.1.1`, path `/health/live`. The `--generate-openapi` fallback [DECISION] is **not** used.
- Actions are pinned by full commit SHA and bumped by Dependabot (config `.github/dependabot.yml`, `github-actions` + `nuget`, weekly; the NuGet updates are grouped into one PR — see the failure-handling table). Verified 2026-09-29: the pins in the file are `actions/checkout` **v7.0.1**, `actions/setup-dotnet` **v6.0.0**, `actions/upload-artifact` **v7.0.1**.

## Steps

1. Tag the integration base class with the trait (TestKit, done by 09.2.1-T2). **(09 W3 CR-37)** Tag the four DB-dependent `tests/NightTales.Infrastructure.UnitTests/Persistence/` classes as well, so the unit job no longer needs a database; converging them onto the TestKit harness is out of scope here (it needs the probe model inside TestKit, which another task owns).
2. Confirm the `postgres` service block and the `NTS_TEST_PG` env value against `PostgresFixture`'s expected connection string (maintenance database, superuser so `CREATE DATABASE` is allowed).
3. **(09 W3 CR-37)** Enable build-time OpenAPI generation: `Microsoft.Extensions.ApiDescription.Server` 10.0.12 in `Directory.Packages.props` + the `NightTales.Api.csproj` reference/target recipe above, `builder.Services.AddOpenApi()` in `Program.cs`, `.gitignore` the generated file, refresh `src/NightTales.Api/packages.lock.json`, then confirm `openapi.json` (3.1.1) appears after `dotnet build` **with** `ConnectionStrings__Postgres` set.
4. Write `backend.yml` and `dependabot.yml`; both test steps carry `--minimum-expected-tests 1` and no trx logger.
5. Negative proof on a scratch PR: a misformatted file → `build-test` red; a failing integration test → `integration` red. (Local, verified here: the zero-match filter with `--minimum-expected-tests 1` exits 9.)
6. Record in `docs/dev-setup.md` how to run the same commands locally, including `NTS_TEST_PG` pointing at the 09.1.1-T2 dev server and the `ConnectionStrings__Postgres` requirement of the build step.

## Acceptance checks

- [ ] A PR with no changes → both jobs green in < 10 min.
- [ ] The step-5 scratch PR shows `build-test` red on the format error and `integration` red on the failing test.
- [ ] The artifact `openapi` contains a valid OpenAPI document — verified locally on 2026-09-29 with `python3 -c "import json;print(json.load(open('src/NightTales.Api/openapi.json'))['openapi'])"` → `3.1.1` (the `jq .openapi` form of this check is equivalent; ⚠️ resolved).
- [ ] `grep -n "uses:" .github/workflows/backend.yml` → every action pinned by a 40-char SHA (verified 2026-09-29: `actionlint` reports no findings).
- [ ] `grep -n "docker" .github/workflows/backend.yml` → no hit in the `integration` job (the `postgres` service is the only database dependency; no Docker-in-runner step; 09 W3 CR-35).
- [ ] Unsetting `NTS_TEST_PG` locally makes `PostgresFixture` fail with its named error, never skip (09.2.1-T2; `PostgresFixtureGuardTests`).
- [ ] **(09 W3 CR-37)** Both test steps carry `--minimum-expected-tests 1`: on a filter that matches nothing the run exits **9** with `Minimum expected tests policy violation, tests ran 0, minimum expected 1`, so the unit job cannot be vacuously green.
- [ ] **(09 W3 CR-37)** `env -u NTS_TEST_PG dotnet test NightTales.ci.slnf -c Release --no-build --filter "Category!=Integration" --minimum-expected-tests 1` → green, 35 tests, no database; with `NTS_TEST_PG` exported `--filter "Category=Integration"` → green, 23 tests.

## Tests

| Name | Kind | Asserts |
|---|---|---|
| Scratch PR: format error | CI run | `dotnet format --verify-no-changes` fails the job |
| Scratch PR: failing integration test | CI run | the `integration` job fails; the console-log artifact is uploaded (09 W3 CR-37: trx does not work under MTP) |
| Scratch PR: zero-match filter | CI run | `--minimum-expected-tests 1` turns a filter that matches nothing red (exit 9, 09 W3 CR-37) |
| `OpenApi_DocumentIsGeneratedAtBuild` | CI step | the file exists after `dotnet build` and reports `openapi: 3.1.1` |
| `integration` job, `NTS_TEST_PG` unset | CI run | the fixture fails the job with its named message instead of skipping (09 W3 CR-35) |

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| (09 W3 CR-35) Docker Hub rate limit when pulling the `postgres:17` service image | [DECISION] mirror through `ghcr.io` or log in with a read-only Docker Hub token as a repo secret (owner action) if it happens |
| The service container is not ready when the test step starts | the `options` health gate (`pg_isready`, 20 retries) holds the job until the server accepts connections |
| The `postgres` service configured the wrong database | `NTS_TEST_PG` must name the maintenance database (`postgres`) as superuser, because `PostgresFixture` runs `CREATE DATABASE` (09 W3 CR-35) |
| A flaky integration test | fix or quarantine it with `[Trait("Category","Quarantine")]`, excluded and listed in the weekly review (08.1.2); never retry-until-green |
| Lock file out of date | `--locked-mode` fails → the developer runs `dotnet restore` and commits |
| **(09.1.5-T1 review)** A Dependabot NuGet PR is red with `NU1004` | expected on bot PRs today. With central package management the bot bumps `Directory.Packages.props` but regenerates only the lock files of the projects it resolved, missing projects reached only through a `<ProjectReference>` (dependabot/dependabot-core#13950 — open, checked 2026-09-29); `dotnet restore --locked-mode` then fails. The maintainer runs an **unlocked** `dotnet restore NightTales.ci.slnf` and commits **every** changed `packages.lock.json` before the PR can go green. NuGet updates are therefore grouped into one PR (`.github/dependabot.yml` `groups`), so this repair happens at most once per week. CI owns no auto-repair workflow for this |
