## Goal

An owner's integration values live in one place, `system_settings`, with non-secret values readable in plain JSON and secret values encrypted, purpose-bound, hint-only on read, and never logged, audited, exported or returned. Every change appends a version row. This task creates the storage primitives and seeds the §5.6 catalog (plus the new `captcha` row); it does not expose the admin API (09.10.2-T1) or the node/purpose-key details (09.10.1-T2, D6).

## Design

Implements §C3 **D6**.

```csharp
// Domain/Settings/SystemSetting.cs — NOT IUserOwned (Part A D10)
public sealed class SystemSetting
{
    public string Integration { get; private set; } = default!;
    public string Key { get; private set; } = default!;
    public bool IsSecret { get; private set; }
    public JsonDocument? Value { get; private set; }          // null when IsSecret
    public byte[]? SecretCiphertext { get; private set; }      // null when !IsSecret
    public string? SecretHint { get; private set; }            // last 4 chars
    public int Version { get; private set; }
    public string? UpdatedBy { get; private set; }
    public DateTimeOffset UpdatedAt { get; private set; }
    public Guid? WorkerNodeId { get; private set; }             // set only for mpt node-key rows (09.10.1-T2)

    public void ApplyValue(JsonDocument value, string updatedBy, DateTimeOffset now) { /* version++, Value=value, SecretCiphertext=null */ }
    public void ApplySecret(byte[] ciphertext, string hint, string updatedBy, DateTimeOffset now) { /* version++, SecretCiphertext=ciphertext, SecretHint=hint, Value=null */ }
}

// Application/Abstractions/Secrets/SecretString.cs
public readonly record struct SecretString
{
    private readonly string? _value;
    public SecretString(string? value) => _value = value;
    public string? Reveal() => _value;                 // called only inside the encryption boundary
    public override string ToString() => "***";          // never the value
}
```

`SecretString` has **no** implicit conversion from `string` and is registered with a Serilog `IDestructuringPolicy` (in the 09.9.3-T2 pipeline) that renders it as `"***"` in every sink. `ISettingsEncryptor` wraps `IDataProtectionProvider`:

```csharp
public interface ISettingsEncryptor
{
    byte[] Protect(string integration, string key, SecretString value, Guid? nodeId = null);
    SecretString Unprotect(string integration, string key, byte[] ciphertext, Guid? nodeId = null);
}
// purpose chain: "settings.v1/{integration}/{key}" or "settings.v1/mpt/api_key/{nodeId}" for node rows
// CreateProtector(purposeChain) per call — purpose binds ciphertext to its row, so a copy to another row throws.
```

`secret_hint` is computed as `value.Length <= 4 ? value : value[^4..]` before encryption, stored in plaintext (it is not sensitive).

**Catalog seed.** A one-shot idempotent seeder (run from a migration, not from application code) inserts every §5.6 row plus `captcha` (W3 CR-2):

## Steps

1. Add `SystemSetting`, `SystemSettingVersion` (append-only projection) domain types and the `SettingsDbContext` mapping (`UseSnakeCaseNamingConvention`, unique `(integration, key)`, no `IUserOwned`/tenant filter — Part A D10).
2. Implement `SecretString`, its Serilog `IDestructuringPolicy`, and `ISettingsEncryptor`/`DataProtectionSettingsEncryptor` over 09.9.4-T1's key ring.
3. Write the idempotent catalog-seed migration (SQL above), covering every §5.6 integration plus `captcha` (W3 CR-2); assert `ON CONFLICT DO NOTHING` so re-running on a populated environment changes nothing.
4. Add the read-side query object `GetSettingsCatalogQuery` returning non-secret `value` or `secretHint` per key (never `secret_ciphertext`) — used by 09.10.2-T1, not exposed by an endpoint here.
5. Add the write-side internal command `ApplySettingValueCommand`/`ApplySettingSecretCommand` (called by 09.10.2-T1, not routed here) that appends a `system_setting_versions` row in the same transaction.
6. Wire `[NotAudited]` on the internal read query and leave the write commands' `[Audited]` attribute to 09.10.2-T1 (this task only supplies the persistence primitives, per D2's one-writer-per-artefact rule — the HTTP surface is 09.10.2-T1's).
7. Add the log-scan test harness hook: a fixture that seeds one known secret value per integration and exposes it to the shared log-scan assertion (09.10.2-T1/T2 extend it; this task proves the harness itself catches a deliberately-logged secret in a throwaway repro).

## Acceptance checks

1. Given the migration runs on an empty DB, When it completes, Then every §5.6 integration/key pair exists in `system_settings`, secret keys have `value = NULL, is_secret = true, version = 0`, and re-running the migration changes zero rows.
2. Given a secret is encrypted for `(openai, api_key)`, When its ciphertext bytes are copied into the row `(email, smtp_password)` and decryption is attempted with that row's purpose, Then `ISettingsEncryptor.Unprotect` throws (purpose mismatch) — never returns a wrong-but-valid value.
3. Given a `SecretString` instance, When it passes through `ToString()`, `JsonSerializer.Serialize`, or a Serilog log call, Then the output is `"***"` in every case, never the underlying value.
4. Given `GetSettingsCatalogQuery` runs, Then its projection never selects `secret_ciphertext`, only `secret_hint` for secret keys.
5. Given the catalog seed, Then no `mpt` row and no `vieneu_proxy` row are inserted (mpt rows belong to worker-node CRUD in 09.10.2-T1; `vieneu_proxy` does not exist per 04 CR-8).

## Failure handling and edge cases

| Case | Handling |
|---|---|
| Migration re-run on a DB where an owner already changed `openai.base_url` | `ON CONFLICT DO NOTHING` — the owner's value and version are untouched |
| `Unprotect` called with a ciphertext from a different node's `mpt` key | Purpose chain includes `nodeId`; throws `CryptographicException`, never returns a plausible wrong key |
| `ApplySettingValueCommand` racing two writers on the same `(integration, key)` | Optimistic: `version` is checked by 09.10.2-T1's `If-Match`; this task's persistence layer itself is not concurrency-aware beyond the unique key (409 handling is 09.10.2-T1's) |
| KEK missing at startup (09.9.4-T1's key ring cannot initialize) | Out of this task's scope; degraded-start behavior is **09.10.3-T1** |
| A secret value logged accidentally by a future call site | Caught by the log-scan harness this task establishes; a bare `string` secret passed instead of `SecretString` is a code-review/architecture-test concern, not runtime-detectable here |
