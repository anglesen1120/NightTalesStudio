## Goal

Every `mpt` worker-node adapter key is bound to its own node by the encryption purpose chain, so a leaked or misrouted ciphertext can never decrypt against the wrong node; and old secret history ages out automatically — `SettingSecretPurgeJob` nulls `secret_ciphertext` in `system_setting_versions` rows older than 7 days while the **live** setting in `system_settings` is never touched (F12).

## Inputs

- README §C3 **D6** (purpose chains), F12 (purge must never touch the live row).
- `plans/09-backend-api.md:369` — `SettingSecretPurgeJob`: daily, argument = version id with `secret_ciphertext` not null and older than 7 days (S5).
- `plans/09-backend-api.md:483,485` — adapter key rotation runbook context (`ADAPTER_API_KEY`/`ADAPTER_API_KEY_NEXT`), backups contain only ciphertext.

## Design

Implements §C3 **D6** node-key purposes + F12's purge predicate.

```csharp
public interface ISettingsEncryptor
{
    // extended by this task: the nodeId overload is the *only* one used for mpt api_key rows
    byte[] Protect(string integration, string key, SecretString value, Guid? nodeId = null);
    SecretString Unprotect(string integration, string key, byte[] ciphertext, Guid? nodeId = null);
}
// purpose = nodeId is null ? $"settings.v1/{integration}/{key}" : $"settings.v1/mpt/api_key/{nodeId}"
```

`SystemSetting.WorkerNodeId` (added in 09.10.1-T1's model) is set only for rows created by 09.10.2-T1's node CRUD; this task adds the **validation** that a non-null `WorkerNodeId` is only ever paired with `integration = "mpt", key = "api_key"` (an architecture/domain invariant, checked in the setter and in an architecture test).

```csharp
[JobPolicy(Retries = 0)]
public sealed class SettingSecretPurgeJob(ISystemWorkQuery work, TimeProvider clock, ILogger<SettingSecretPurgeJob> log)
{
    // recurring: daily, "0 3 * * *"
    public async Task RunAsync(CancellationToken ct)
    {
        var cutoff = clock.GetUtcNow().AddDays(-7);
        int total = 0;
        while (true)
        {
            var batch = await work.PendingSecretVersionIdsAsync(cutoff, limit: 5000, ct); // ids only
            if (batch.Count == 0) break;
            await work.NullSecretCiphertextAsync(batch, ct);   // UPDATE system_setting_versions SET secret_ciphertext = NULL WHERE id = ANY(@ids)
            total += batch.Count;
            if (batch.Count < 5000) break;
        }
        log.LogInformation("settings.purge.completed count={Count}", total);   // count only, never an id list at Information
    }
}
```

The predicate is scoped **exclusively** to `system_setting_versions`: `WHERE secret_ciphertext IS NOT NULL AND changed_at < @cutoff`; it never references `system_settings`. `secret_hint` is left in place on the version row so a future audit can still show "the value that was active then started with `…1234`" without being able to restore it.

## Steps

1. Extend `ISettingsEncryptor`'s implementation with the `nodeId` purpose-chain branch and add the domain invariant `WorkerNodeId != null ⇒ Integration == "mpt" && Key == "api_key"` (throw `InvalidOperationException` in the setter otherwise).
2. Add `ISystemWorkQuery.PendingSecretVersionIdsAsync(DateTimeOffset cutoff, int limit, CancellationToken ct)` and `NullSecretCiphertextAsync(IReadOnlyList<Guid> ids, CancellationToken ct)` — ids-only, batched (Part A D12).
3. Implement `SettingSecretPurgeJob`, register it in 09.2.6-T1's recurring job list at `"0 3 * * *"` (daily, off-peak), `[JobPolicy(Retries = 0)]` (a missed day is caught by the next run; no retry storm).
4. Add an architecture test asserting the job's SQL/LINQ predicate touches only `system_setting_versions` (grep-style compile-time check over the query's `DbSet<T>` — reuse the pattern from another ids-only job's arch test if one exists, else a reflection-based check that the handler's only `DbSet` access is `Set<SystemSettingVersion>()`).
5. Add the "restore" read helper `GetVersionsForRollbackQuery` output field `SecretReentryRequired: bool` per key — `true` whenever that version's `secret_ciphertext` is null (purged) **and** `is_secret` — consumed by 09.10.2-T1's rollback response.

## Acceptance checks

1. Given a node key is encrypted for node A, When decryption is attempted with node B's id, Then `Unprotect` throws — a key never silently decrypts for the wrong node.
2. Given `system_setting_versions` rows 6 and 8 days old with a non-null `secret_ciphertext`, When `SettingSecretPurgeJob` runs, Then the 8-day row's `secret_ciphertext` is null and `secret_hint` unchanged, and the 6-day row is untouched.
3. Given the purge job has run, When the corresponding **live** `system_settings` row is read, Then it still decrypts and a `…/test` call against it still succeeds (F12 — the live value is never touched).
4. Given a rollback target version whose secret was purged, Then `GetVersionsForRollbackQuery` marks that key `SecretReentryRequired = true` and never attempts to decrypt a null ciphertext.
5. Given an attempt to set `WorkerNodeId` on a row whose `(integration, key)` is not `(mpt, api_key)`, Then the domain throws before any persistence.

## Failure handling and edge cases

| Case | Handling |
|---|---|
| Purge job crashes mid-batch | Each batch's `UPDATE` is one transaction; a crash after batch N leaves batches ≤ N nulled and the rest untouched; next day's run picks up the remainder (idempotent predicate) |
| A version row is exactly 7 days old at run time | `changed_at < cutoff` (strict `<`) — a row from exactly `now() - 7d` is kept one more day, never a boundary flap |
| Two nodes share a base URL but different keys | Purpose chain keys on `nodeId`, not on `base_url`, so this is safe by construction |
| `WorkerNodeId` set for a deleted node | Out of scope here — node lifecycle is 09.10.2-T1's; this task's invariant only checks the `(integration, key)` pairing |
