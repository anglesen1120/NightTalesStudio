# 09.10.2-T3 — Connect-time egress IP re-validation

## Goal

Every outbound call this wave makes to a configured host — the settings test call, `openai`, `payment`, `email`, `mpt` adapter, `youtube`/`tiktok` OAuth — re-validates the **resolved IP at connect time, on every call**, not only when the URL was saved, so DNS rebinding cannot move a previously-approved host onto a blocked or internal address after the fact. One factory is used by every typed client and by `POST …/test`.

## Inputs

- README §C3 **D6** egress rule (loopback/link-local/metadata/`0.0.0.0/8`/IPv4-mapped-or-compatible IPv6 always blocked, also inside an allow-listed name; `mpt` additionally restricted to the render subnet CIDR).
- `plans/09-backend-api.md:483` — exact block list and the `SocketsHttpHandler.ConnectCallback` mechanism, `UseProxy = false`, resolved-and-dialled-IP invariant.
- README §C5 security review row "Secrets at egress (SSRF)" — one `ConnectCallback` factory shared by the settings test client, HIBP client and Turnstile siteverify client (09.3.3-T2 consumes this task's factory soft).
- Reused: named `HttpClient`s registered by 09.3.5-T1 (`pwnedpasswords`, `turnstile`) — this task supplies the callback they attach, not new clients; 09.10.2-T1's `ISettingsCatalog.RuleFor(...).TestProbe` calls through a client built here.

## Design

Implements §C3 **D6**'s egress half.

```csharp
public interface IEgressGuard
{
    // Throws SocketException("egress_blocked") if the candidate endpoint fails any check.
    ValueTask ValidateAsync(string integration, IPEndPoint candidate, CancellationToken ct);
}

public sealed class EgressGuard(IOptionsMonitor<SettingsOptions> options) : IEgressGuard
{
    private static readonly IReadOnlyList<(IPNetwork Net, string Label)> BlockedRanges = new[]
    {
        (IPNetwork.Parse("127.0.0.0/8"), "loopback"), (IPNetwork.Parse("::1/128"), "loopback"),
        (IPNetwork.Parse("169.254.0.0/16"), "link_local"), (IPNetwork.Parse("fe80::/10"), "link_local"),
        (IPNetwork.Parse("0.0.0.0/8"), "unspecified"),
        // IPv4-mapped/-compatible IPv6 normalized to their IPv4 form before the checks above run again
    };

    public ValueTask ValidateAsync(string integration, IPEndPoint candidate, CancellationToken ct)
    {
        var ip = NormalizeMappedOrCompatible(candidate.Address);          // ::ffff:127.0.0.1 -> 127.0.0.1
        foreach (var (net, label) in BlockedRanges)
            if (net.Contains(ip)) throw new EgressBlockedException(integration, label);
        if (integration == "mpt" && !options.CurrentValue.RenderSubnetCidr.Contains(ip))
            throw new EgressBlockedException(integration, "outside_render_subnet");
        return ValueTask.CompletedTask;
    }
}

public static class EgressHttpClientFactory
{
    public static SocketsHttpHandler Build(string integration, IEgressGuard guard) => new()
    {
        UseProxy = false,
        AllowAutoRedirect = false,
        ConnectCallback = async (context, ct) =>
        {
            var entry = await Dns.GetHostEntryAsync(context.DnsEndPoint.Host, ct);
            var chosen = entry.AddressList[0];                              // deterministic pick
            var endpoint = new IPEndPoint(chosen, context.DnsEndPoint.Port);
            await guard.ValidateAsync(integration, endpoint, ct);            // re-validate...
            var socket = new Socket(SocketType.Stream, ProtocolType.Tcp);
            await socket.ConnectAsync(endpoint, ct);                          // ...then dial the SAME endpoint
            return new NetworkStream(socket, ownsSocket: true);
        }
    };
}
```

The same resolved `IPEndPoint` that passes validation is the one dialled (no re-resolve between check and connect) — this closes the classic TOCTOU rebinding gap. `EgressHttpClientFactory.Build` is called once per named `HttpClient` registration (`settings-test`, and the callback attached to 09.3.5-T1's `pwnedpasswords`/`turnstile` clients via `ConfigurePrimaryHttpMessageHandler`).

## Steps

1. Implement `IEgressGuard`/`EgressGuard` with the exact blocked-range table (loopback, link-local incl. `169.254.169.254`, `0.0.0.0/8`, IPv4-mapped/compatible IPv6 normalized first) plus the `mpt`-only render-subnet-CIDR check from `SettingsOptions.RenderSubnetCidr` (env-only per S12).
2. Implement `EgressHttpClientFactory.Build` and register `EgressConnectCallbackFilter : IHttpMessageHandlerBuilderFilter` (keyed by `HttpMessageHandlerBuilder.Name` → integration) as the **single** DI hook that attaches the `ConnectCallback` to **every** settings-backed named `HttpClient` resolved through `IHttpClientFactory` — `settings-test`, `pwnedpasswords`/`turnstile` (09.3.5-T1), `openai` (02.2.1-T2, 09 W3 CR-29), `mpt` (09.6.2-T1's `MptRenderClient`, 09 W3 CR-29), `youtube-oauth`/`tiktok` OAuth token clients (06.1.2-T1/07.1.2-T1, 09 W3 CR-29) and the payment-provider client (plan 12, 09 W3 CR-29) — transparently, with **no code change required in any of those tasks' own client registration** (the filter decorates by name at the point each names its `AddHttpClient(name)`). Add an architecture test enumerating every named `HttpClient` registered across the Api/Worker hosts and asserting each name is either in the guarded-integration map or on an explicit, reviewed allow-list of purely-internal/no-egress clients.
3. Wire 09.10.2-T1's `TestSettingCommandHandler` to resolve its probe `HttpClient` through this factory keyed by `integration`.
4. Add a `EgressBlockedException → setting_test_failed` (502) mapping for the settings-test path specifically (other consumers map it to their own codes, e.g. `captcha_unavailable`, per their own tasks).
5. Add the IPv4-mapped/compatible normalization helper (`::ffff:a.b.c.d` → `a.b.c.d`; `::a.b.c.d` compatible form → `a.b.c.d`) as a small pure function with its own unit tests (a common bypass vector).
6. For the `email` integration (MailKit `SmtpClient`, not `IHttpClientFactory`): before `ConnectAsync(host, port, options)`, resolve the host via `Dns.GetHostEntryAsync` and run the chosen `IPEndPoint` through the **same** `IEgressGuard.ValidateAsync("email", ...)`, then call the MailKit overload that connects to the validated `IPAddress` directly (never the hostname again), so no second DNS lookup can race a rebind between validation and connect — implemented in 09.2.6-T3's SMTP client wrapper (09 W3 CR-29, signed task, cited here, not edited by this folder).

## Acceptance checks

1. Given a hostname that resolves to `127.0.0.1`, When any guarded client connects, Then the connection is refused before any bytes are sent and the caller sees its own mapped error (`setting_test_failed` for the settings-test path).
2. Given a hostname that resolves to `169.254.169.254` (cloud metadata), Then refused, even if the integration's allow-list contains that hostname literally.
3. Given `::ffff:127.0.0.1` (IPv4-mapped) or `::7f00:1`-style compatible form, Then refused after normalization — the raw-bytes check alone would have missed it.
4. Given a DNS-rebinding host that resolves to a public IP at validation time and to `127.0.0.1` a moment later, Then the connection dials the **validated** IP (no re-resolve between check and connect), so the rebind cannot redirect the actual TCP connection.
5. Given `integration = "mpt"` and a resolved IP outside `SettingsOptions.RenderSubnetCidr`, Then refused even if it is a routable public IP.
6. Given `integration = "openai"` and a resolved IP inside the render subnet CIDR but outside `openai`'s own allow-list, Then the CIDR check does not apply (it is `mpt`-only) but the allow-list check (09.10.2-T1's `ISettingsCatalog`) still refuses it.
7. Given the architecture test that enumerates every named `HttpClient` in both hosts, Then `openai`, `payment`, `mpt`, `youtube-oauth` and `tiktok` all resolve to a guarded integration — none is on the internal-only allow-list.
8. Given the `email` integration (MailKit), When the configured SMTP host resolves to `127.0.0.1` or `169.254.169.254` at connect time, Then the connect is refused before `SendEmailJob` transmits any message.

## Failure handling and edge cases

| Case | Handling |
|---|---|
| DNS returns multiple A/AAAA records, some blocked and some not | `EgressHttpClientFactory` uses `entry.AddressList[0]` deterministically and validates only that one — the chosen record is what is dialled, so there is no smuggling through a later record |
| IPv6-only host for an `mpt` node | CIDR check must support IPv6 `IPNetwork` if the render subnet is ever IPv6 (documented; current render subnet is IPv4 per 11 — `[INFERENCE]` no IPv6 render subnet exists yet, guard still type-checks IPv6 forms for safety) |
| `Dns.GetHostEntryAsync` throws (NXDOMAIN) | Propagates as a connection failure, mapped by the caller to its own unreachable/`*_unavailable` code, not swallowed silently |
| A future integration is added to §5.6 without updating the CIDR/allow-list branch | Caught by 09.10.2-T1's `ISettingsCatalog.RuleFor` needing an explicit entry per integration — an unmapped integration has no rule and the endpoint 404s rather than falling through with no validation |

## Notes

One guard, one factory, shared by every egress-capable client in this wave (D6, §C5). No new package (`System.Net.Sockets`/`IPNetwork` are BCL, .NET 10). This task has no i18n surface (internal-only exception mapping); the user-facing codes (`setting_test_failed`, `captcha_unavailable`) belong to the consuming tasks.
