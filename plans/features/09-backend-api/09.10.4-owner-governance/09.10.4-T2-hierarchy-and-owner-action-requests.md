## Design

```csharp
// src/NightTales.Domain/OwnerGovernance/OwnerActionRequest.cs
public enum OwnerActionKind { MfaReset, Demote, Suspend, Promote }
public enum OwnerActionStatus { Pending, Disputed, Applied, Cancelled }

public sealed class OwnerActionRequest : AggregateRoot, IUserOwned
{
    public OwnerActionKind Action { get; private set; }
    public Guid TargetUserId { get; private set; }
    public Guid UserId => TargetUserId;                       // IUserOwned marker only
    public string Reason { get; private set; } = default!;
    public Guid? RequestedByUserId { get; private set; }
    public OwnerActionStatus Status { get; private set; }
    public DateTimeOffset ApplyAfter { get; private set; }
    public Guid? ApprovedByUserId { get; private set; }
    public Guid? CancelledByUserId { get; private set; }
    public string? CancelReason { get; private set; }
    public DateTimeOffset? AppliedAt { get; private set; }

    public static ErrorOr<OwnerActionRequest> Request(
        OwnerActionKind action, Guid targetUserId, string reason, Guid? requestedByUserId,
        DateTimeOffset now, OwnerGovernanceOptions options)
    {
        if (string.IsNullOrWhiteSpace(reason) || reason.Length > 500)
            return Error.Validation(ErrorCodes.ValidationFailed);
        return new OwnerActionRequest
        {
            Id = Guid.CreateVersion7(), Action = action, TargetUserId = targetUserId, Reason = reason,
            RequestedByUserId = requestedByUserId, Status = OwnerActionStatus.Pending,
            ApplyAfter = now + TimeSpan.FromHours(options.TimeLockHours)
        };
    }

    public ErrorOr<Success> Approve(Guid approverId, bool isThirdOwnerReauth, DateTimeOffset now)
    {
        if (Status == OwnerActionStatus.Disputed)   // 09 W3 CR-22 (D8, finding NTS-W3-OWNER-APPROVE-GUARDS)
        {
            if (approverId == RequestedByUserId || approverId == TargetUserId)
                return Error.Conflict(ErrorCodes.OwnerActionDisputed);   // requester/counter-filer/target may not approve their own dispute
            if (!isThirdOwnerReauth) return Result.Success;   // a non-qualifying third owner is a silent no-op, same as Pending
            ApprovedByUserId = approverId;
            return Apply(now);
        }
        if (Status != OwnerActionStatus.Pending) return Error.NotFound(ErrorCodes.NotFound);
        if (!isThirdOwnerReauth) return Result.Success;   // documented no-op: stays pending until the time-lock or a real third owner
        ApprovedByUserId = approverId;
        return Apply(now);
    }

    public ErrorOr<Success> Cancel(Guid cancellerId, bool cancellerIsTarget, string reason, DateTimeOffset now,
        int cancelsUsedByCanceller, OwnerGovernanceOptions options)
    {
        if (Status == OwnerActionStatus.Disputed) return Error.Conflict(ErrorCodes.OwnerActionDisputed);
        if (Status != OwnerActionStatus.Pending) return Error.NotFound(ErrorCodes.NotFound);
        var cap = cancellerIsTarget ? options.TargetCancelCapPer30Days : options.CancelCapPer30Days;
        if (cancelsUsedByCanceller >= cap) return Error.Conflict(ErrorCodes.CancelLimitReached);
        Status = OwnerActionStatus.Cancelled; CancelledByUserId = cancellerId; CancelReason = reason;
        return Result.Success;
    }

    public ErrorOr<Success> Apply(DateTimeOffset now)
    {
        if (Status is OwnerActionStatus.Applied or OwnerActionStatus.Cancelled) return Result.Success; // idempotent no-op
        if (Status == OwnerActionStatus.Disputed) return Error.Conflict(ErrorCodes.OwnerActionDisputed);
        Status = OwnerActionStatus.Applied; AppliedAt = now;
        return Result.Success;
    }
}
```

- **Hierarchy check** (`Application/Features/Admin/RoleHierarchy.cs`, reused by `09.10.5-T1`): `static bool ActorOutranks(PlatformRole actor, PlatformRole target, OwnerActionKind? action = null) => actor > target || (actor == PlatformRole.Owner && target == PlatformRole.Owner && action is OwnerActionKind.MfaReset or OwnerActionKind.Demote or OwnerActionKind.Suspend);` (ordinal compare per README:323 declaration order `User < Admin < Owner`, §2 [INFERENCE]; the owner-on-owner exception is 09 W3 CR-22, D8) — every user-management command calls this first, passing the action it is about to perform; `false` → `Error.NotFound(ErrorCodes.NotFound)` (never 403, D5). The exception never covers `delete`/`promote` — a caller must not pass those expecting the gate to widen; owner-on-owner `delete` stays 404 here.
- **Port** (`Application/Abstractions/OwnerGovernance/IOwnerActionRequester.cs`): `Task<ErrorOr<Guid>> RequestAsync(OwnerActionKind action, Guid targetUserId, string reason, Guid? requestedByUserId, CancellationToken ct)` — writes a `Request(...)` row via `EfUnitOfWork`; `09.10.5-T1` and `09.10.7-T1` call this instead of touching the table (D2 one-writer rule). In the same transaction, for every active owner **except the target** (and never for a `system`, i.e. `requestedByUserId is null`, row — no recipient exists to receive a cancel link for that branch), queues `EmailMessage(owner.Id, "approval_cancel", owner.UiLocale, new Dictionary<string,string> { ["displayName"] = owner.DisplayName, ["requestKind"] = "owner_action", ["reason"] = reason, ["deadline"] = applyAfter.ToString("O"), ["requestId"] = id.ToString() })` via the signed `IEmailSender.QueueAsync` (09 W3 CR-23) — 09.10.8-T1's `SendEmailJob`-time minter mints each recipient's token.
- **`ApproveOwnerActionCommand(Guid RequestId)` handler:** `[Audited("owner_action.approved", Category.AccountSecurity, Visibility.User)]`. Loads the row, computes `isThirdOwnerReauth = ` (caller is owner, caller.Id ≠ `RequestedByUserId`, **caller.Id ≠ `TargetUserId`, `RequestedByUserId is not null`** (09 W3 CR-22: a `system` row is never eligible for a synchronous approve by any caller — 09.10.4-T4 gives it its own `objection_recorded` branch instead), caller's `PromotedAt` ≤ `now - ApproverMinOwnerAgeDays`, `IReauthGuard.RequireRecentAsync(ReauthWindowSeconds)` succeeded), calls `Approve`; on success with an actual apply, performs the same side effect + `RotateStampAsync` as the job (§Steps 4) inside the same transaction (so a caller who *is* the qualifying third owner gets a synchronous 200, not a 202 waiting for the next job tick). A `Disputed` row is now approvable by a qualifying third owner who is neither the requester, the counter-filer nor the target (`Approve`'s own party check above); the requester, counter-filer or target attempting to act on a `Disputed` row gets 409 `owner_action_disputed`.
- **`CancelOwnerActionCommand(Guid RequestId, string Reason)` handler:** `[Audited("owner_action.cancelled", ...)]`. `cancelsUsedByCanceller` = `COUNT(*) FROM owner_action_requests WHERE (action, target_user_id) = (@action, @target) AND cancelled_by = @caller AND cancelled_at > now() - interval '30 days'` (`cancelled_at`, 09 W3 CR-24 to `00-overview.md` §6).
- **`OwnerActionApplyJob`** (`Infrastructure/Jobs/OwnerActionApplyJob.cs`, `[JobPolicy(Retries = 0)]`, recurring `"*/1 * * * *"`): `SELECT id FROM owner_action_requests WHERE status = 'pending' AND apply_after <= now() ORDER BY apply_after LIMIT 50 FOR UPDATE SKIP LOCKED` (own transaction per row, `IsolationLevel.Serializable`, `SET LOCAL lock_timeout = 3s`); per row: re-lock target (+ co-owner set for `demote`/`suspend`/`promote`, `ORDER BY id`), re-check role/`owner_dispute_freeze_until`/`last_owner`/owner-count, `Apply(now)`, side effect, `RotateStampAsync` where applicable, `SaveChangesAsync`. Sets gauge `owner_actions_pending = COUNT(*) WHERE status = 'pending'` at the end of each tick.

## Acceptance checks

- Given an admin, When `PATCH /admin/users/{id}/role` targets `owner`, Then the hierarchy check rejects with 404 before `IOwnerActionRequester` is even called (verified via `09.10.5-T1`'s integration test, this task only proves `ActorOutranks(Admin, Owner) == false`).
- Given an owner, When they promote a user, Then `IOwnerActionRequester.RequestAsync` returns a new id and a row exists with `status = 'pending'`, `apply_after = now + 24h`.
- Given a `pending` row and a second owner promoted 45 days ago who has re-authenticated in the last 5 minutes, When `POST /admin/owner-actions/{id}/approve`, Then the response is 200 and `owner_action_requests.status = 'applied'` in the same request (not waiting for the job).
- Given a `system` (`requested_by IS NULL`) row, When any owner calls approve, Then it is a no-op 200/202 with the row still `pending` (never a qualifying approve).
- Given a `pending` row, When the target itself calls approve, Then it is a no-op with the row unchanged (`caller.Id == TargetUserId` excludes it from `isThirdOwnerReauth`).
- Given a `disputed` row, When a qualifying third owner (neither requester, counter-filer nor target) calls approve, Then it applies (200); When the requester, the counter-filer or the target calls approve, Then 409 `owner_action_disputed` and the row is unchanged.
- Given an owner acting on another owner, When the action is `mfa_reset`, `demote` (via `PATCH .../role`) or `suspend`, Then `ActorOutranks` admits the call and a `pending` `owner_action_requests` row is created (202), never a 404; When the action is `delete`, Then 404/400 and no row is created.
- Given the same row and a caller who is the original requester, When they call approve, Then it is a no-op 200 with the row still `pending` (not a qualifying third owner).
- Given a `pending` row, When the target cancels once, Then 204 and `cancelled_by` = target; a second cancel of the *same* row → 404 (already terminal, not `cancel_limit_reached` — that cap applies across different requests of the same `(action, target)` pair, tested in T4).
- Given `OwnerActionApplyJob` ticks with two Api/Worker instances racing the same due row, When both attempt the claim, Then exactly one applies (`SKIP LOCKED`) and `owner_actions_pending` reflects the post-tick count.

## Failure handling and edge cases

| Condition | Behavior | Code |
|---|---|---|
| Caller role not strictly above target | Reject before any row is read/written | 404 `not_found` |
| Approve on a non-`pending` row | No-op, row unchanged | 404 `not_found` |
| Cancel on a `disputed` row | Reject, row unchanged | 409 `owner_action_disputed` |
| Cancel exceeds the caller's 30-day cap | Reject, row unchanged | 409 `cancel_limit_reached` |
| Apply-time re-check finds `owner_dispute_freeze_until` in the future | Row stays `pending`, retried next tick | (no HTTP response — job-internal) |
| Apply-time re-check finds `last_owner` | Row → `cancelled`, `cancel_reason = "last_owner"` | (no HTTP response — job-internal) |
| Two job ticks race the same due row | `SKIP LOCKED` yields the row to exactly one | — |
| Missing `X-Reauth` recency on approve/cancel | Reject before the row is touched | 401 `reauth_required` |
