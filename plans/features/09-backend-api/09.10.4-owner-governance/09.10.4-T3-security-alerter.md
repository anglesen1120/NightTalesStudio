# 09.10.4-T3 — Security alerter: e-mail fan-out through the signed pipeline

| Story | Size | Area | Depends on | Blocks | Phase / flag |
|---|---|---|---|---|---|
| 09.10.4 | S (0.5) | BE | 09.10.4-T1, 11.6.2-T1 | 09.10.7-T1, 09.10.3-T1, 08.2.1-T2 | S · M2 |

## Goal

Implement the **S** side of the signed `ISecurityAlerter` interface (`09.10.4-T1`): for every `SecurityEvent`, queue one templated e-mail per active owner through the already-signed `IEmailSender`/`SendEmailJob` pipeline (09.2.6-T3), never inline SMTP, and rely on that pipeline's existing `email_messages.status`/failure tracking — consumed by 08.2's `security_email_failed` db_check — as the P1 backstop (D17, W3-TL3). No new alert-channel port is invented.

## Design

Implements the e-mail half of §C3 D17/plan-08's D9; the "11.6.2 alert pipeline" half is a metric emission, not a call.

```csharp
// src/NightTales.Application/Features/OwnerGovernance/Security/SecurityEventCatalog.cs
public static class SecurityEventCatalog
{
    // Kind -> the already-catalogued (or CR-pending) template name; no second payload type, no new interface.
    public static readonly IReadOnlyDictionary<string, string> TemplateByKind = new Dictionary<string, string>
    {
        // 09 W3 CR-28: keys are exactly the frozen `security.*` SecurityEvent.Kind values (§C3.3), never the §C3.4 action/audit vocabulary
        ["security.owner_action_pending"] = "owner_action_pending",   // request created; this folder's row, §C3.5 (CR below)
        ["security.role_changed"]         = "security_alert",         // an owner-action apply that demotes/promotes
        ["security.mfa_changed"]          = "security_alert",         // an owner-action apply that resets MFA
        ["security.break_glass_recovery"] = "security_alert",         // consumed by 09.10.7-T1 (recover AND restore, out of folder)
    };
}

// src/NightTales.Infrastructure/Security/EmailFanOutSecurityAlerter.cs
public sealed class EmailFanOutSecurityAlerter(
    IEmailSender emails, IOwnerLookup owners, IMeter meter) : ISecurityAlerter
{
    public async Task AlertAsync(SecurityEvent evt, CancellationToken ct)
    {
        meter.SecurityEventsTotal.Add(1, new("kind", evt.Kind));   // the "11.6.2 pipeline" half — a metric, not a call (§C6/09-backend-api.md:278)
        if (!SecurityEventCatalog.TemplateByKind.TryGetValue(evt.Kind, out var template)) return;
        foreach (var owner in await owners.GetActiveOwnersAsync(ct))
        {
            var message = new EmailMessage(owner.Id, template, owner.UiLocale, BuildParams(evt, template));
            await emails.QueueAsync(message, ct);   // signed, queue-only; SendEmailJob owns delivery/retry/failure recording
        }
    }

    private static IReadOnlyDictionary<string, string> BuildParams(SecurityEvent evt, string template) => template switch
    {
        "security_alert" => new Dictionary<string, string> { ["event"] = evt.Kind, ["severity"] = "P1", ["at"] = DateTimeOffset.UtcNow.ToString("O"), ["dataSummary"] = Summarize(evt.Detail) },
        "owner_action_pending" => new Dictionary<string, string> { /* action/targetDisplayName/reason/applyAfter filled by the caller-supplied Detail — see Notes on the SecurityEvent payload gap */ },
        _ => new Dictionary<string, string>()
    };

    private static string Summarize(string? detail) => string.IsNullOrEmpty(detail) ? "" : detail.Length > 200 ? detail[..200] : detail;
}
```

- **The "11.6.2 alert pipeline" half is a metric, not a channel call.** `plans/09-backend-api.md`:278 requires the event to reach "the 11.6.2 alert pipeline (not configurable from the app)" — since 11.6.2-T1 has no application-callable port (it is OTel export + a repository rule file + dashboards, `11.6.2-T1-telemetry-dashboards-and-alerts.md`:20-52, consumed passively), this is satisfied by emitting the counter metric `security_events_total{kind}` and letting 11.6.2-T1's rule file watch it — **this metric name is not yet in §C3.3's frozen list; proposed as a CR below**, since it did not exist when §C3.3 was written.
- **E-mail delivery is fully delegated** to the signed pipeline: `QueueAsync` writes one `email_messages` row + the outbox event `email_requested.v1` inside the caller's own transaction (09.2.6-T3:39); `SendEmailJob` renders/sends/records `Sent`/`Failed` asynchronously. A failed send leaves `email_messages.status = 'failed'`, which is exactly what 08.2.1-T1's `security_email_failed` db_check already reads (consumed) — **this task raises no alert itself**.
- **[OPEN] contract gap, F14's "pre-change config" requirement:** `plans/09-backend-api.md`:278 says an `email`-integration change must notify "through both the old and the new configuration". The signed `09.2.6-T3` pipeline has **no dynamic, admin-editable e-mail configuration** — `Email:Smtp:*` are static `appsettings`/secret-manager keys (09.2.6-T3 Config section), and no task in `09.10-settings/` currently makes `email` a `system_settings` integration (D6/D7 name only `payment.*`, `youtube.*`, `tiktok.*` as critical integrations; `email` is not among them). **This task cannot implement "notify through both configurations" as literally written** because there is no second configuration to read. Reported to Main as a contract gap between `09-backend-api.md`:278 (P, high-level) and the signed `09.2.6-T3`/`09.10-settings` scope (neither of which this folder may edit). This task implements the reachable half — reliable e-mail delivery to every owner through the one, current configuration — and flags the "old vs new config" clause as unimplementable until a CR makes `email` a dynamic settings integration.
- **Params allow-list:** `BuildParams` never passes `SecurityEvent.Detail` verbatim into a template param beyond a length-capped, non-identifying summary (`dataSummary`, ≤ 200 chars) — no raw PII, token, or address (D17).

## Acceptance checks

- Given a `security.owner_action_pending` event, When `AlertAsync` runs, Then one `EmailMessage(ownerId, "owner_action_pending", owner.UiLocale, params)` is queued per active owner via `IEmailSender.QueueAsync` — verified by a fake `IEmailSender` recording one call per owner, zero inline SMTP calls.
- Given `SendEmailJob` (signed, consumed) later fails all attempts for one of those messages, When 08.2's `OpsAlertSweepJob` (consumed) runs its `security_email_failed` db_check, Then it finds the `email_messages` row with `status = 'failed'` and `template = 'owner_action_pending'` — this task's test only proves the row exists in that state; it does not re-implement or call the sweep job.
- Given `SecurityEvent.Kind` is not in `SecurityEventCatalog.TemplateByKind`, When `AlertAsync` runs, Then the `security_events_total{kind}` metric still increments but no e-mail is queued and no exception is thrown.
- Given `evt.Detail` contains more than 200 characters, When `BuildParams` runs for `security_alert`, Then `dataSummary` is truncated to 200 characters — never the raw value.

## Failure handling and edge cases

| Condition | Behavior | Code |
|---|---|---|
| `SecurityEvent.Kind` not in the catalog | Metric increments, no e-mail queued, no throw | — |
| No active owners exist | No e-mail queued (nothing to send); metric still increments | — |
| `IEmailSender.QueueAsync` itself fails (DB error) | Propagates to the caller — the caller's own transaction rolls back (this alerter never swallows an infrastructure failure of the queue write) | 503 `service_unavailable` (Part A D5 default) |
| The actual SMTP send later fails (`SendEmailJob`, out of folder) | `email_messages.status = 'failed'`; observed by 08.2's `security_email_failed` db_check — this task takes no further action | — |

- **`09.10.8-T1`'s cancel-link e-mail is a separate template** (`approval_cancel`, already reserved in the signed `EmailTemplateCatalog` since wave 2, `09.2.6-T3`:90 — owner comment `// 09.10.8`) and is queued/minted by that task's own `IEmailTokenMinter`, not by this alerter; `SecurityEventCatalog` here never maps to `approval_cancel`.

This is a naming/ownership duplication in the wave-3 proposal, reported to Main — `09.10.8-T1`'s task file in this folder uses the **already-signed** `approval_cancel` name, not the unsigned `cancel_link` proposal.
- **[OPEN]** the `SecurityEvent(string Kind, Guid? SubjectUserId, string?
