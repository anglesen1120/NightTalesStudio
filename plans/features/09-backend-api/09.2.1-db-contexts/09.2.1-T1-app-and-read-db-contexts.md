## Goal

Commands get a tracked `IAppDbContext` and queries get a no-tracking `IReadDb`. Both share one model with snake_case names, UTC `timestamptz`, enum `CHECK`s and `xmin` concurrency. The JSON mapping strategy for every later feature is fixed by a spike.

## Design

```csharp
// Application/Abstractions/Persistence/
public interface IAppDbContext
{
    DatabaseFacade Database { get; }
    Task<int> SaveChangesAsync(CancellationToken ct);   // called only by UnitOfWork (D5) and seeders
    // DbSet<T> properties are added by each owning task (09.2.2-T1: Series, Episodes, …)
}
public interface IReadDb { IQueryable<T> Query<T>() where T : class; }

// Infrastructure/Persistence/
public sealed class AppDbContext(DbContextOptions<AppDbContext> options, ICurrentUser currentUser)
    : IdentityDbContext<AppUser, AppRole, Guid>(options), IAppDbContext
{
    internal Guid? CurrentUserId { get; } = currentUser.Id;       // read by the "tenant" filter (09.2.3-T1)
    protected override void OnModelCreating(ModelBuilder b) { base.OnModelCreating(b); b.ApplyNightTalesConventions(this); }
}
public sealed class ReadDbContext(DbContextOptions<ReadDbContext> options, ICurrentUser currentUser) : DbContext(options), IReadDb
{
    public override int SaveChanges() => throw new InvalidOperationException("read-only context");
    // + SaveChanges(bool), SaveChangesAsync(CancellationToken), SaveChangesAsync(bool, CancellationToken)
}
public sealed class AppUser : IdentityUser<Guid> { /* 00 §6 users columns; mapped in 09.2.2-T1 */ }
public sealed class AppRole : IdentityRole<Guid>;
```

`ReadDbContext` maps the same entity types as `AppDbContext`, including the Identity types (`AppUser` is mapped explicitly with `ToTable("users")`), so that queries can join users. It has no migrations assembly: `MigrationsAssembly` is set only for `AppDbContext`, and `ReadDbContext` never runs `Migrate`.

`AddPersistence`:

```csharp
services.AddOptions<PersistenceOptions>().BindConfiguration("Persistence").ValidateOnStart();
services.AddDbContext<AppDbContext>(o => o.UseNpgsql(cs, n => n.CommandTimeout(t).MigrationsAssembly(infra))
                                          .UseSnakeCaseNamingConvention());
services.AddDbContext<ReadDbContext>(o => o.UseNpgsql(cs, n => n.CommandTimeout(t))
                                           .UseSnakeCaseNamingConvention()
                                           .UseQueryTrackingBehavior(QueryTrackingBehavior.NoTracking));
services.AddScoped<IAppDbContext>(sp => sp.GetRequiredService<AppDbContext>());
services.AddScoped<IReadDb>(sp => sp.GetRequiredService<ReadDbContext>());
```

Conventions (`Persistence/Conventions/`):
- `EnumCheckConvention` (from `HasEnumCheck<TEnum>()` annotations) adds `ck_<table>_<column>` with the snake_case values of the enum.
- `AggregateRootConvention` gives every `AggregateRoot` a `Version` mapped with `IsRowVersion()` (N8).
- Enum value converter: `EnumToSnakeCaseStringConverter<TEnum>` (uses `JsonNamingPolicy.SnakeCaseLower.ConvertName`).

**Spike (≤ 2 h), recorded in Notes:** a test entity with a complex property `ToJson()` containing a nested list, on PostgreSQL 17 (the `NTS_TEST_PG` server; 09 W3 CR-35). It must round-trip, it must query into a JSON property, and `ExecuteUpdate` must set a JSON property.
- **Pass** → structured `jsonb` uses complex types.
- **Fail** → structured `jsonb` uses `string` + `HasColumnType("jsonb")` + typed accessors in the entity (System.Text.Json).

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Probe entities for tests | live in `tests/NightTales.Infrastructure.UnitTests`/TestKit and are added through a test-only `IEntityTypeConfiguration` assembly; never in `src` |
| Identity model and snake_case together | apply the renames after `base.OnModelCreating` |
| `ReadDbContext` used inside a command | allowed for reads, but it does not see uncommitted writes of the command; commands read through `IAppDbContext` (00 §5.2) |
