## Goal

Every integration test gets an isolated, migrated PostgreSQL 17 database in well under a second, against the **real server** named by `NTS_TEST_PG` (Homebrew `postgresql@17` on this Mac, a `postgres:17` service container in CI) — no container is started by the tests, and no Docker is needed. It can call the Api as any test user and run Worker code in-process, without sleeps.

## Design

```csharp
// tests/NightTales.TestKit/Database/PostgresFixture.cs  (xunit.v3 assembly fixture)
public sealed class PostgresFixture : IAsyncLifetime
{
    // ctor reads NTS_TEST_PG (Npgsql connection string, Database = maintenance db "postgres").
    // No container start. Fails fast, never skips:
    //   missing/blank NTS_TEST_PG        -> InvalidOperationException("NTS_TEST_PG is required for integration tests …")
    //   server_version_num / 10000 != 17 -> InvalidOperationException("NTS_TEST_PG must point at PostgreSQL 17 (found …)")
    // once per run: DROP DATABASE IF EXISTS nts_template WITH (FORCE); CREATE DATABASE nts_template; migrate it
    public Task<TestDatabase> CreateDatabaseAsync(string name, CancellationToken ct);   // CREATE DATABASE "<name>" TEMPLATE nts_template
}
public sealed class TestDatabase : IAsyncDisposable { public string ConnectionString { get; } }  // DROP DATABASE … WITH (FORCE) on dispose
// TestDatabase.ConnectionString = NTS_TEST_PG with Database=<name>, so credentials come from the same env var

// tests/NightTales.TestKit/Api/ApiFactory.cs
public sealed class ApiFactory(TestDatabase db, FakeClock clock) : WebApplicationFactory<Program>
{
    // ConfigureWebHost: ConnectionStrings:Postgres = db.ConnectionString; replace IClock with clock;

    public HttpClient ClientFor(Guid userId, PlatformRole role = PlatformRole.User);  // sets X-Test-User / X-Test-Role
    public HttpClient AnonymousClient();
}

// tests/NightTales.TestKit/Api/TestAuthHandler.cs — reads X-Test-User (Guid) and X-Test-Role; no header → NoResult
// tests/NightTales.TestKit/Worker/WorkerHost.cs
public sealed class WorkerHost(TestDatabase db, FakeClock clock) : IAsyncDisposable
{
    public InlineJobScheduler Jobs { get; }                      // records Enqueue/Schedule calls; RunPendingAsync() executes them
    public Task<int> RunOutboxOnceAsync(CancellationToken ct);   // one OutboxDispatcher iteration (09.2.4-T1)
    public IServiceScope CreateScope();
}
// tests/NightTales.TestKit/Time/FakeClock.cs
public sealed class FakeClock(DateTimeOffset start) : IClock { public DateTimeOffset UtcNow { get; private set; } public void Advance(TimeSpan by); public void Set(DateTimeOffset at); }
// tests/NightTales.TestKit/Builders/{SeriesBuilder,EpisodeBuilder,UserBuilder}.cs — insert rows directly through AppDbContext under ISystemContext
// tests/NightTales.TestKit/IntegrationTest.cs — [Trait("Category","Integration")] base class; creates the class database
```

- `NTS_TEST_PG` is the connection string of a PostgreSQL **17** server that the test role may create databases on (`CREATEDB`). Dev: the Homebrew server prepared by `tools/dev/db-init.sh` (09.1.1-T2); CI: the `postgres:17` service of the `integration` job (09.1.5-T1). The same variable is used by `dotnet test` on a developer machine and in CI, so the two paths run identical code.
- The fixture rebuilds `nts_template` once per run (drop + create + migrate) rather than assuming a pristine container, because the dev server is long-lived.
- The test users are real `users` rows, created by `UserBuilder`, so that FKs hold. The claims come from `TestAuthHandler`.
- `WorkerHost` builds the Worker's service collection (the same `AddWorkerServices` extension as `Worker/Program.cs`), minus the Hangfire server and `OutboxDispatcher`'s timer loop.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| `NTS_TEST_PG` unset or blank | the fixture fails fast at construction with `NTS_TEST_PG is required for integration tests: set it to the PostgreSQL 17 connection string (see docs/dev-setup.md)` — a named error, never a silent skip |
| `NTS_TEST_PG` points at a server that is not PostgreSQL 17 | the fixture fails fast with `NTS_TEST_PG must point at PostgreSQL 17 (found <server_version>)` before creating any database |
| The test role lacks `CREATEDB` | `CREATE DATABASE … TEMPLATE` fails with SQLSTATE 42501 and the message points at `tools/dev/db-init.sh` (09.1.1-T2) |
| The dev server is down | connection failure at fixture construction, with the `NTS_TEST_PG` value (password masked) in the message |
| A test class leaks connections, so `DROP DATABASE` fails | `WITH (FORCE)` (PostgreSQL 13+) terminates them |
| A migration is added while a stale `nts_template` exists in the same run | impossible: the template is dropped and rebuilt once at run start from the compiled migrations |
| Parallel test classes | each has its own database on the shared server; xunit.v3 parallelism stays on |
| Another process uses the same `nts_template` database | the rebuild's `DROP DATABASE … WITH (FORCE)` terminates its connections; a second concurrent test run on one server is not supported (CI isolates per job) |

## Notes

- `TestAuthHandler` is the auth scheme for 02 development until 09.3.2 lands (CR-10).
- The builders insert through `AppDbContext` inside `ISystemContext.For(userId)`, so the tenant filter and `user_id` rules are exercised, not bypassed.
- **Deferred to 09.2.6-T1: `WorkerHost` and `InlineJobScheduler`.** That task owns the D12 ports `IBackgroundJob` / `IJobScheduler` (`Application/Abstractions/Jobs/*`), the outbox dispatcher and the Worker composition root; until they exist there is no Worker service to host and no job type to schedule, so a `WorkerHost` here would only be a guess. The `Test`-scheme half of this task (09.2.1-T2) ships without it, and 09.2.6-T1 adds `Threading/WorkerHost.cs` + `Threading/InlineJobScheduler.cs` with the ports it defines.
- **Deferred to 09.2.2-T1: `SeriesBuilder` / `EpisodeBuilder`.** Those builders need the `Series` / `Episode` entities, which 09.2.2-T1 (with `InitialCore` in 09.2.2-T2) defines; `UserBuilder` ships now because the `users` table is Identity's.
- **Implements `ISystemContext` nowhere.** It does not exist and is 09.2.3-T1's (D10); the TestKit fake is `Auth/TestCurrentUser.cs`, a settable `ICurrentUser`.
- **[DEVIATION] `Program` is not nameable from a test assembly**: both hosts declare a top-level `Program`, so `WebApplicationFactory<Program>` is ambiguous (CS0433) for any project that sees both. `NightTales.TestKit.csproj` therefore references the Worker with `Aliases="NightTalesWorkerHost"` (09.2.6-T1 reaches Worker types through `extern alias`), and `ApiFactory.ProductionHost(...)` returns the plain host so a test project never names `Program` either.
- **[DEVIATION] Template build in the zero-migration window.** `PostgresFixture.RebuildTemplateAsync` calls `MigrateAsync` when the context compiles at least one migration and `EnsureCreatedAsync` otherwise: with zero migrations (today, until 09.2.2-T2 lands `InitialCore`) `Migrate` is a documented no-op, so the template would carry no schema and neither `UserBuilder` nor any later integration test could write a row. The branch is dead from the first migration on.
- **[DEVIATION] The fixture is a `Lazy` singleton, not `[assembly: AssemblyFixture]`.** xUnit v3 instantiates and initializes every registered assembly fixture for any run with at least one test, whether or not a test uses it — the unit job runs without `NTS_TEST_PG`, so a registered fixture would fail it. `PostgresFixture.Shared` (created on first use by `IntegrationTest`) keeps the work lazy *and* once per run.
- **[DEVIATION] The Api probe reports the `ClaimsPrincipal`, not `ICurrentUser.Id`.** Until 09.2.3-T1 registers `HttpCurrentUser`, `AddPersistence` registers `AnonymousCurrentUser`, so a probe endpoint that resolved `ICurrentUser` would report anonymity for every request; the probe therefore asserts the claims the `Test` scheme produced (`sub`, `role`).
