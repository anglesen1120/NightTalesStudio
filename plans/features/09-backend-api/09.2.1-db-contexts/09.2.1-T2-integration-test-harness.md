## Goal

Every integration test gets an isolated, migrated PostgreSQL 17 database in well under a second, against the **real server** named by `NTS_TEST_PG` (Homebrew `postgresql@17` on this Mac, a `postgres:17` service container in CI) — no container is started by the tests, and no Docker is needed. It can call the Api as any test user and run Worker code in-process, without sleeps.

## Design

```csharp
// tests/NightTales.TestKit/Database/PostgresFixture.cs  (xunit.v3 assembly fixture)
public sealed class PostgresFixture : IAsyncLifetime
{
    // ctor reads NTS_TEST_PG (Npgsql connection string). Its Database= is only where the fixture
    // runs its own DDL (CREATE/DROP DATABASE, catalog queries); any database the role can connect to
    // works and the dev value is the .env database, `nighttales`.
    // No container start. Fails fast, never skips:
    //   missing/blank NTS_TEST_PG        -> InvalidOperationException("NTS_TEST_PG is required for integration tests …")
    //   server_version_num / 10000 != 17 -> InvalidOperationException("NTS_TEST_PG must point at PostgreSQL 17 (found …)")
    // once per run: DROP DATABASE IF EXISTS nts_template WITH (FORCE); CREATE DATABASE nts_template; migrate it
    public Task<TestDatabase> CreateDatabaseAsync(string name, CancellationToken ct);   // CREATE DATABASE "<name>" TEMPLATE nts_template
}
public sealed class TestDatabase : IAsyncDisposable { public string ConnectionString { get; } }  // DROP DATABASE … WITH (FORCE) on dispose
// TestDatabase.ConnectionString = NTS_TEST_PG with Database=<name>, so credentials come from the same env var

// tests/NightTales.TestKit/Api/ApiFactory.cs
public sealed class ApiFactory(TestDatabase db, FakeClock clock) : WebApplicationFactory<Program>
{
    // ConfigureWebHost: ConnectionStrings:Postgres = db.ConnectionString; replace IClock with clock;
    // AddAuthentication("Test").AddScheme<AuthenticationSchemeOptions, TestAuthHandler>("Test", _ => {});
    public HttpClient ClientFor(Guid userId, PlatformRole role = PlatformRole.User);  // sets X-Test-User / X-Test-Role
    public HttpClient AnonymousClient();
}

// tests/NightTales.TestKit/Api/TestAuthHandler.cs — reads X-Test-User (Guid) and X-Test-Role; no header → NoResult
// tests/NightTales.TestKit/Worker/WorkerHost.cs
public sealed class WorkerHost(TestDatabase db, FakeClock clock) : IAsyncDisposable
{
    public InlineJobScheduler Jobs { get; }                      // records Enqueue/Schedule calls; RunPendingAsync() executes them
    public Task<int> RunOutboxOnceAsync(CancellationToken ct);   // one OutboxDispatcher iteration (09.2.4-T1)
    public IServiceScope CreateScope();
}
// tests/NightTales.TestKit/Time/FakeClock.cs
public sealed class FakeClock(DateTimeOffset start) : IClock { public DateTimeOffset UtcNow { get; private set; } public void Advance(TimeSpan by); public void Set(DateTimeOffset at); }
// tests/NightTales.TestKit/Builders/{SeriesBuilder,EpisodeBuilder,UserBuilder}.cs — insert rows directly through AppDbContext under ISystemContext
// tests/NightTales.TestKit/IntegrationTest.cs — [Trait("Category","Integration")] base class; creates the class database
```

- `NTS_TEST_PG` is the connection string of a PostgreSQL **17** server that the test role may create databases on (`CREATEDB`). Dev: the Homebrew server prepared by `tools/dev/db-init.sh` (09.1.1-T2); CI: the `postgres:17` service of the `integration` job (09.1.5-T1). The same variable is used by `dotnet test` on a developer machine and in CI, so the two paths run identical code. Its `Database=` entry is only where the fixture runs its own DDL (`CREATE DATABASE`, `DROP DATABASE`, catalog queries) — no test ever writes there — so any database the role can connect to works; the dev value is `nighttales` (`POSTGRES_DB` in `.env`). The fixture enforces two boundaries before any DDL: every database it creates or drops must carry the reserved prefix `nts_`, and the server must be loopback unless `NTS_TEST_PG_ALLOW_REMOTE_DDL=1` is set (the CI service container is reached at `127.0.0.1`, so CI never sets it).
- The fixture rebuilds `nts_template` once per run (drop + create + migrate) rather than assuming a pristine container, because the dev server is long-lived.
- The test users are real `users` rows, created by `UserBuilder`, so that FKs hold. The claims come from `TestAuthHandler`.
- `WorkerHost` builds the Worker's service collection (the same `AddWorkerServices` extension as `Worker/Program.cs`), minus the Hangfire server and `OutboxDispatcher`'s timer loop.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| `NTS_TEST_PG` unset or blank | the fixture fails fast at construction with `NTS_TEST_PG is required for integration tests: set it to the PostgreSQL 17 connection string (see docs/dev-setup.md)` — a named error, never a silent skip |
| `NTS_TEST_PG` points at a server that is not PostgreSQL 17 | the fixture fails fast with `NTS_TEST_PG must point at PostgreSQL 17 (found <server_version>)` before creating any database |
| The test role lacks `CREATEDB` | `CREATE DATABASE … TEMPLATE` fails with SQLSTATE 42501, which the fixture maps to `InvalidOperationException("… the test role may not run CREATE DATABASE … run tools/dev/db-init.sh (09.1.1-T2) …")`; any other SQLSTATE keeps the original `PostgresException` |
| The test role does not own `nts_template` | `DROP DATABASE nts_template` fails with SQLSTATE 42501 (`must be owner of database nts_template`) and the same named error names the failing statement and `tools/dev/db-init.sh` |
| A database name without the `nts_` prefix would be created or dropped | refused before any DDL with `InvalidOperationException("Refusing destructive DDL on database '<name>': … reserved prefix 'nts_' …")`; the template name is checked in the fixture constructor too |
| `NTS_TEST_PG` points at a non-loopback host | refused with `InvalidOperationException("NTS_TEST_PG points at '<host>', which is not a loopback host. …")` unless `NTS_TEST_PG_ALLOW_REMOTE_DDL=1`; the message states that the fixture drops and creates databases and that the override must never target a shared or production cluster. CI needs no override: the service container is reached at `127.0.0.1` |
| The dev server is down | connection failure at fixture construction, with the `NTS_TEST_PG` value (password masked) in the message |
| A test class leaks connections, so `DROP DATABASE` fails | `WITH (FORCE)` (PostgreSQL 13+) terminates them |
| A migration is added while a stale `nts_template` exists in the same run | impossible: the template is dropped and rebuilt once at run start from the compiled migrations |
| Parallel test classes | each has its own database on the shared server; xunit.v3 parallelism stays on |
| Another process uses the same `nts_template` database | the rebuild's `DROP DATABASE … WITH (FORCE)` terminates its connections; a second concurrent test run on one server is not supported (CI isolates per job) |

## Notes

- `TestAuthHandler` is the auth scheme for 02 development until 09.3.2 lands (CR-10).
- The builders insert through `AppDbContext` inside `ISystemContext.For(userId)`, so the tenant filter and `user_id` rules are exercised, not bypassed.
- **Deferred to 09.2.6-T1: `WorkerHost` and `InlineJobScheduler`.** That task owns the D12 ports `IBackgroundJob` / `IJobScheduler` (`Application/Abstractions/Jobs/*`), the outbox dispatcher and the Worker composition root; until they exist there is no Worker service to host and no job type to schedule, so a `WorkerHost` here would only be a guess. The `Test`-scheme half of this task (09.2.1-T2) ships without it, and 09.2.6-T1 adds `Threading/WorkerHost.cs` + `Threading/InlineJobScheduler.cs` with the ports it defines.
- **Deferred to 09.2.2-T1: `SeriesBuilder` / `EpisodeBuilder`.** Those builders need the `Series` / `Episode` entities, which 09.2.2-T1 (with `InitialCore` in 09.2.2-T2) defines; `UserBuilder` ships now because the `users` table is Identity's.
- **Implements `ISystemContext` nowhere.** It does not exist and is 09.2.3-T1's (D10); the TestKit fake is `Auth/TestCurrentUser.cs`, a settable `ICurrentUser`.
- **[DEVIATION] `Program` is not nameable from a test assembly**: both hosts declare a top-level `Program`, so `WebApplicationFactory<Program>` is ambiguous (CS0433) for any project that sees both. `NightTales.TestKit.csproj` therefore references the Worker with `Aliases="NightTalesWorkerHost"` (09.2.6-T1 reaches Worker types through `extern alias`), and `ApiFactory.ProductionHost(...)` returns the plain host so a test project never names `Program` either.
- **[DEVIATION] Template build in the zero-migration window.** `PostgresFixture.RebuildTemplateAsync` calls `MigrateAsync` when the context compiles at least one migration and `EnsureCreatedAsync` otherwise: with zero migrations (today, until 09.2.2-T2 lands `InitialCore`) `Migrate` is a documented no-op, so the template would carry no schema and neither `UserBuilder` nor any later integration test could write a row. The branch is dead from the first migration on.
- **[DEVIATION] The fixture is a `Lazy` singleton, not `[assembly: AssemblyFixture]`.** xUnit v3 instantiates and initializes every registered assembly fixture for any run with at least one test, whether or not a test uses it — the unit job runs without `NTS_TEST_PG`, so a registered fixture would fail it. `PostgresFixture.Shared` (created on first use by `IntegrationTest`) keeps the work lazy *and* once per run.
- **[DEVIATION] The Api probe reports the `ClaimsPrincipal`, not `ICurrentUser.Id`.** Until 09.2.3-T1 registers `HttpCurrentUser`, `AddPersistence` registers `AnonymousCurrentUser`, so a probe endpoint that resolved `ICurrentUser` would report anonymity for every request; the probe therefore asserts the claims the `Test` scheme produced (`sub`, `role`). `ICurrentUser.Id` becomes assertable through the harness when 09.2.3-T1 lands.
- **Privilege failures are named errors, not raw `PostgresException`s (2026-09-29 fix wave, SEC).** Every DDL statement the fixture runs (`CreateDatabaseAsync`, `DropDatabaseAsync`) goes through one mapper, `PostgresFixture.DescribeDdlFailure(sqlState, statement)`, which turns SQLSTATE `42501` into an `InvalidOperationException` naming `NTS_TEST_PG`, the statement kind (`CREATE DATABASE` / `DROP DATABASE`) and the remedy `tools/dev/db-init.sh` (09.1.1-T2), keeping the original `PostgresException` as the inner exception; every other SQLSTATE is rethrown unchanged. Verified live against the local server as a `NOCREATEDB`, non-owner role: `42501: must be owner of database nts_template` and `42501: permission denied to create database` both produced the named error.
- **Destructive-DDL boundary (2026-09-29 fix wave, SEC).** Two controls, both enforced before any DDL reaches the server: managed names must carry the reserved prefix `nts_` (`RequireManagedDatabaseName`, applied to the template name in the fixture constructor and inside `QuoteIdentifier`, the DDL renderer), and the `NTS_TEST_PG` host must be loopback unless `NTS_TEST_PG_ALLOW_REMOTE_DDL=1` (`EnsureDdlTargetIsLoopback`; accepted are `127.0.0.0/8`, `::1`, `localhost` and Unix-socket paths). An unspecified host is accepted because Npgsql resolves it locally. The dev and CI values are both loopback (`127.0.0.1`), so **no run needs the override**; `docs/dev-setup.md` states that the override must never target a shared or production cluster.
- **Test-auth headers are a closed, single-valued grammar (2026-09-29 fix wave, SEC).** `TestAuthHandler` no longer uses `Enum.TryParse` for the role (which accepts `X-Test-Role: 2` as `PlatformRole.Owner` and comma-joined values); `TryParseRole` matches only the case-insensitive `PlatformRole` names, and each of `X-Test-User` / `X-Test-Role` must be sent at most once, so duplicated headers fail authentication instead of silently picking a value.
- **Teardown clears the per-database pool first (2026-09-29 fix wave, PERF).** `TestDatabase.DisposeAsync` calls `NpgsqlConnection.ClearPool` for exactly its own connection string before `DROP DATABASE … WITH (FORCE)`, so the drop does not wait for PostgreSQL to terminate idle pooled backends. Measured on this Mac with a pooled connection left behind on each used database (open + close one `NpgsqlConnection` on `database.ConnectionString`, then time the sequential `DisposeAsync` calls): single teardown 169–398 ms → 10.9–12.5 ms (first, cold: 398 → 114 ms); 20 databases in a row 5652 ms → 1237 ms (282.6 ms → 61.8 ms average). `TestDatabase.ConnectionString` is computed once per instance instead of rebuilding an `NpgsqlConnectionStringBuilder` on every getter call: `GC.GetAllocatedBytesForCurrentThread()` over 10 000 reads gives 0 B/call cached versus 8097 B/call on the old getter path (`PostgresFixture.ConnectionStringFor`). No raw connection string is compared in an assertion any more (`PostgresDatabaseTests` compares the masked values and the parsed `Database` names), so a failing assertion cannot print the password.
- **Delta re-review residuals fixed (2026-09-29, second wave).** (1) The loopback guard accepts Npgsql's per-host port syntax — `127.0.0.1:5432`, `[::1]:5432`, `localhost:5432`, and multi-host lists with ports — because a port never changes where the connection goes; a `:` suffix that is not a plain port number (`127.0.0.1:notaport`, `127.0.0.1:`) and a remote host with a port (`10.0.0.5:5432`) are still refused unless the override is set (`SplitHostAndPort` + `PostgresFixture_LoopbackHostWithPort_IsAccepted`; mutation-checked: removing the split makes that test red). (2) The raw server-level statement runner is now `private` — the only public DDL paths are `CreateDatabaseAsync` / `DropDatabaseAsync`, which enforce the `nts_` prefix and map the privilege failure — and every per-database helper goes through `HelperConnectionString` / `ConnectionStringFor`, which validate the prefix too, so no public member can run SQL against a database the harness does not own (`PostgresFixture_NonManagedDatabase_RawSqlHelpers_AreRefused`). `ExecuteAsync`/`QueryStringsAsync`/`TableNamesAsync`/`AppliedMigrationsAsync` stay public because tests must create markers and read catalogs inside their own managed database, and `DatabaseExistsAsync`/`DatabaseOidAsync` stay name-agnostic because they are read-only, parameterized catalog probes on the maintenance connection, not a SQL entry point. The staleness test now uses the guarded helpers instead of raw server SQL.
- `TestKit_ContainsNoTaskDelayOrSleep` (plan §9) is a **grep acceptance check, not a test**: there is no test method of that name.
