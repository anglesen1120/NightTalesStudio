## Goal

Every core-set table in plan §3 has a Domain (or Infrastructure, for `AppUser`) type and an `IEntityTypeConfiguration`. From these, EF generates exactly the columns, `CHECK`s, FKs and indexes of plan §3.

Every entity implements `ICreatedAt`; entities of mutable tables (both `created_at` and `updated_at` above) implement `IAuditable`, while immutable/append-only ones (`story_versions`, `usage_records`) stop at `ICreatedAt`. `ICreatedAt { DateTimeOffset CreatedAt }` and `IAuditable : ICreatedAt { DateTimeOffset UpdatedAt }` are new Domain/Common interfaces owned by this task (09 W3 CR-38); one convention maps `created_at` for every `ICreatedAt` and `updated_at` only for `IAuditable`, and the columns are stamped by `AuditableSaveChangesInterceptor` (Infrastructure, registered before `OutboxSaveChangesInterceptor` — 09.2.4-T1), never by hand-written configuration.

Configuration pattern (`Infrastructure/Persistence/Configurations/<Type>Configuration.cs`):

```csharp
internal sealed class EpisodeConfiguration : IEntityTypeConfiguration<Episode>
{
    public void Configure(EntityTypeBuilder<Episode> b)
    {
        b.ToTable("episodes");
        b.HasKey(e => e.Id); b.Property(e => e.Id).ValueGeneratedNever();
        b.Property(e => e.Brief).HasMaxLength(1000).IsRequired();
        b.Property(e => e.Title).HasMaxLength(120);
        b.Property(e => e.LengthTier).HasEnumCheck();
        b.Property(e => e.Status).HasEnumCheck();
        b.HasOne<Series>().WithMany().HasForeignKey(e => e.SeriesId).OnDelete(DeleteBehavior.Restrict);
        b.HasOne<StoryVersion>().WithMany().HasForeignKey(e => e.CurrentStoryVersionId).OnDelete(DeleteBehavior.NoAction);
        b.HasIndex(e => new { e.UserId, e.CreatedAt, e.Id }).IsDescending(false, true, true);
        b.HasIndex(e => new { e.UserId, e.Status, e.CreatedAt, e.Id }).IsDescending(false, false, true, true);
        b.HasIndex(e => new { e.SeriesId, e.CreatedAt, e.Id }).IsDescending(false, true, true);
    }
}
```

- Partial indexes use `HasFilter("…")`.
- `CHECK`s that are not enums (`style_templates.template` contains `{term}`) use `ToTable(t => t.HasCheckConstraint(...))`.
- Every `IUserOwned` entity: `HasOne<AppUser>().WithMany().HasForeignKey(e => e.UserId).OnDelete(DeleteBehavior.Restrict)`.
- JSON columns of this task start as `string` + `HasColumnType("jsonb")` — the five structured columns `autopilot_settings`, `content`, `audit_report`, `gate_results` and `rules` keep the `jsonb` column type but stay opaque strings here (**09 W3 CR-44**; the reason is reproduced: their typed shapes belong to the tasks that own each document, EF rejects an empty complex type, a `JsonElement` member NREs on save, and a single-string shell writes `{"Json":…}`, which also breaks `feature_flags.rules` DEFAULT `'{}'`). The task that owns the persisted document type switches its column to `ComplexProperty(…, b => b.ToJson())` in its own PR — 02.8.3-T1 `autopilot_settings` and `gate_results` (it defines `AutopilotSettings`, `GateResultsV1` and `AutopilotRunConfiguration`; 02.8.2-T1 writes the `gates.v1` content with no migration), 02.2.2-T1 `content` and `audit_report` (it owns `StoryVersionConfiguration` and adds `schema_version`/`fact_sources` to `content`; 02.2.1-T1 only defines the pure Domain `StoryContentV1`). `feature_flags.rules` is exempt and stays `string` + `jsonb` permanently: 06.5.2-T1 keeps the flag schema unchanged and parses `rulesJson` as text, and DEFAULT `'{}'` survives. The 09.2.1-T1 spike still governs every column whose document type already exists (README D8:211), and the opaque outbox `payload` stays `string` + `HasColumnType("jsonb")` (D8, 09 W3 CR-41).
- Placeholder FK columns whose target table does not exist yet (`default_channel_id`, `channel_connection_id`, `idea_id`, `render_job_id`, `generation_run_id`) are plain `Guid?`. The owning feature's migration adds the FK constraint.
- `AppUser`: the configuration (or `ModelBuilderExtensions.ApplyIdentityModel`) must **replace** the non-unique `email_index` on `normalized_email` (`src/NightTales.Infrastructure/Persistence/ModelBuilderExtensions.cs`:41-42) with the unique `ux_users_normalized_email` — do not add a second index beside it (09 W3 CR-41), and the constraint test asserts `email_index` is absent.
- `AssetConfiguration` owns the column types of the `assets` table, including `StorageKey` (`HasMaxLength(512)`) and `Sha256` (`HasMaxLength(64)`); it adds **no** retention index — `ix_assets_retention_due` is 09.7.3-T1's (09 W3 CR-40).
- `AuditableSaveChangesInterceptor` (Infrastructure `Persistence/`) is registered on `AppDbContext` **before** `OutboxSaveChangesInterceptor` and stamps `CreatedAt` from `IClock` for every `ICreatedAt` entity (only while still `default`) and `UpdatedAt` for every `IAuditable` entity (09 W3 CR-38).
- `SeriesBuilder` and `EpisodeBuilder` (`tests/NightTales.TestKit/Builders/`) move here from 09.2.1-T2, which deferred them until the `Series`/`Episode` entities exist (09 W3 CR-41).

## Steps

1. Write the enums, the `ICreatedAt`/`IAuditable` interfaces and the entity shells (the D3 base classes come from 09.2.1-T1); every entity implements `ICreatedAt`, and every entity with both timestamps implements `IAuditable`.
2. Add `AuditableSaveChangesInterceptor` and register it on `AppDbContext` **before** `OutboxSaveChangesInterceptor` (09.2.4-T1); map the two timestamps through one convention, not per configuration (09 W3 CR-38).
3. Write one configuration per table, following plan §3 column by column; replace Identity's non-unique `email_index` with the unique `ux_users_normalized_email` (09 W3 CR-41).
4. Add the `DbSet<T>` properties to `IAppDbContext` and `AppDbContext` for Series, Episodes, StoryVersions, AutopilotRuns, SeriesAutopilotAuthorizations, ModerationEvents, UsageRecords, Assets, Voices, StyleTemplates, FeatureFlags. `OutboxMessage` and `IdempotencyKey` are Infrastructure-only sets on `AppDbContext`.
5. Generate a throwaway migration and read the SQL (`dotnet ef migrations script`) against plan §3. Fix any drift, then delete the throwaway (T2 generates the real one).
6. Add `SeriesBuilder` and `EpisodeBuilder` to `tests/NightTales.TestKit/Builders/` (deferred here by 09.2.1-T2).
7. Write the constraint tests.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Circular FK `episodes` ↔ `story_versions` | the FK from `episodes` is added after both tables exist, in the same migration (EF orders it); NO ACTION lets an episode delete cascade its versions within one statement |
| `series.current_autopilot_authorization_id` ↔ `series_autopilot_authorizations.series_id` | same pattern; SET NULL on the series side |
| A later feature needs a column on a core table | it adds an expand-only migration; this configuration file gets the property in that feature's PR |
