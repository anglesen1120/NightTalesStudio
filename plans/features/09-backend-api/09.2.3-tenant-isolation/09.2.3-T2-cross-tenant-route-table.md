# 09.2.3-T2 — Cross-tenant route table generated from `openapi.json`

| Story | Size | Area | Depends on | Blocks | Phase / flag |
|---|---|---|---|---|---|
| 09.2.3 | M (1.0) | BE (tests) | 09.2.3-T1, 09.9.5-T1 | M2 gate; 09.9.1-T1 (09 W3 CR-17), 06.1.2-T3 | S · none |

## Goal

Every route with an `{id}`-style path parameter, on every verb, is called by user A against resources of user B, and must answer 404. A new route that the table does not cover fails the build.

## Inputs

- 09 L95 (the requirement), §7; README D10, D13, D14 (`openapi.json` path); 09.9.5-T1 (the published document).

## Design

- `tests/NightTales.Api.IntegrationTests/CrossTenant/RouteTableGenerator.cs` reads `src/NightTales.Api/openapi.json` and yields `(method, template)` for every path whose template contains `{…}` other than `{platform}`/`{provider}` (non-resource parameters, on the allow-list `CrossTenantAllowList.NonResourceParams`).
- `CrossTenantSeed` (TestKit) creates, for user B, one of each resource type: series, episode, story version, source, fact sheet, bible, publication, and so on. Each feature registers its seeder through `ICrossTenantSeeder` (`string ParamName`, `Task<Guid> SeedAsync(Guid ownerId)`), so this test grows with the features.
- `CrossTenantTests.EveryIdRoute_ForOtherTenant_Returns404` is a theory over the generated table:
  1. Substitute B's ids by parameter name through the seeders.
  2. Send a minimal valid body, from an `ICrossTenantSeeder.SampleBody(method, template)` or `{}` as fallback, with the `Idempotency-Key` and `If-Match` headers set.
  3. Assert 404.
- `CrossTenantTests.EveryIdParameter_HasASeeder` fails if a parameter name has no seeder, so a new route type must bring its seeder.

## Steps

1. Implement the generator and the allow-list.
2. Add `ICrossTenantSeeder` and implement the seeders for the P resources that exist (series, episode, and the 02 resources).
3. Write the two tests; run them in the `integration` CI job.

## Outputs

- New: `tests/NightTales.Api.IntegrationTests/CrossTenant/*.cs`, `tests/NightTales.TestKit/CrossTenant/ICrossTenantSeeder.cs` and the seeders.

## Acceptance checks

- [ ] `EveryIdRoute_ForOtherTenant_Returns404` green for all routes in `openapi.json`.
- [ ] A scratch route `GET /api/v1/widgets/{widgetId}` without a seeder → `EveryIdParameter_HasASeeder` red.
- [ ] A scratch handler that skips the tenant check (`IgnoreQueryFilters` placed on the allow-list for the experiment) → the theory row for that route red.

## Tests

| Name | Kind | Asserts |
|---|---|---|
| `EveryIdRoute_ForOtherTenant_Returns404` | integration theory | 404 for each `(method, template)` |
| `EveryIdParameter_HasASeeder` | integration | coverage of parameter names |
| `RouteTableGenerator_ReadsAllIdRoutes` | unit | a fixture `openapi.json` yields the expected rows |

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| A route validates the body before loading the resource (400 before 404) | the handler order is wrong for this rule: authorization/tenant lookup must happen before content validation [DECISION]; exception: FluentValidation shape errors, which is why the seeders provide valid sample bodies |
| Public routes with ids (cancel links, 09.10.8) | on `CrossTenantAllowList.PublicRoutes` with a reason |
| Admin routes | called as a non-admin: 404 (09.9.1), covered by the same assertion |
