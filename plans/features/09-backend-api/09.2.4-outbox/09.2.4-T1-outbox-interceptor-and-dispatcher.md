## Goal

Domain events commit atomically with their aggregate. The Worker delivers each one at least once to every registered handler, as the event's user, and poison messages end in a visible dead letter instead of blocking the queue.

## Inputs

- Plan §3, §4, §7; README D11, D10, D5, D12, D13; 09.2.2 plan §3 (`outbox_messages` columns).

## Design

```csharp
[AttributeUsage(AttributeTargets.Class)] public sealed class OutboxEventAttribute(string name) : Attribute { public string Name { get; } = name; }
[AttributeUsage(AttributeTargets.Class)] public sealed class PlatformEventAttribute : Attribute;   // allowed to have no user_id

public interface IOutboxHandler<in TEvent> where TEvent : IDomainEvent
{ ValueTask HandleAsync(TEvent e, OutboxContext ctx, CancellationToken ct); }
public sealed record OutboxContext(Guid MessageId, Guid? UserId, int Attempt, DateTimeOffset OccurredAt);

public static IServiceCollection AddOutboxHandler<TEvent, THandler>(this IServiceCollection s)
    where TEvent : IDomainEvent where THandler : class, IOutboxHandler<TEvent>;   // Scoped; order = registration order
```

Interceptor (`SavingChangesAsync`):
1. For each tracked `AggregateRoot` with `DomainEvents.Count > 0`, and for each event:
   - `type = registry.NameOf(e.GetType())`;
   - `user_id = (aggregate as IUserOwned)?.UserId`. If it is null and the event is not `[PlatformEvent]` → throw `InvalidOperationException` (a bug; the command fails).
   - `payload = JsonSerializer.SerializeToDocument(e, e.GetType(), OutboxJson.Options)`;
   - `occurred_at = e.OccurredAt`, `next_attempt_at = e.OccurredAt`, `trace_parent = Activity.Current?.Id`.
2. Add the `OutboxMessage` entities and `ClearDomainEvents()`.

The interceptor is registered on `AppDbContext` only.

Dispatcher loop (`ExecuteAsync`):

```sql
-- claim (own short transaction)
WITH due AS (
  SELECT id FROM outbox_messages
  WHERE processed_at IS NULL AND failed_at IS NULL AND next_attempt_at <= @now
  ORDER BY occurred_at LIMIT @batch FOR UPDATE SKIP LOCKED)
UPDATE outbox_messages o SET next_attempt_at = @now + make_interval(mins => @lease)
FROM due WHERE o.id = due.id
RETURNING o.id, o.type, o.payload, o.user_id, o.attempts, o.occurred_at, o.trace_parent;
```

For each claimed row:
1. `using var scope = sp.CreateAsyncScope()`.
2. If `user_id` is not null → `scope.ISystemContext.For(user_id)`.
3. Start `Activity("outbox.handle")` with parent `trace_parent`.
4. Resolve the registered `IOutboxHandler<T>` list for `registry.TypeOf(type)` and call them in order.
5. Success → `UPDATE … SET processed_at = @now, error = NULL`.
6. Exception → `attempts = attempts + 1`, `next_attempt_at = @now + least(2^attempts, 300) s`, `error = left(ex.GetType().Name + ": " + ex.Message, 2000)`. When `attempts + 1 >= 10` → `failed_at = @now` and increment `outbox_dead_letters_total`.

Other rules:
- An unknown type, or a null `user_id` on a non-platform type → `failed_at` at once.
- Between batches, sleep `PollInterval` via `Task.Delay(…, clock-independent, stoppingToken)` only when the batch was empty. A full batch loops immediately.
- The dispatcher uses `IClock` for `@now`, so tests control it.

`WorkerHost.RunOutboxOnceAsync` (TestKit) calls the same `ProcessBatchAsync(ct)` method that the loop calls.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| A handler takes longer than the lease | it can be claimed twice; handlers are idempotent (O4). A lease of 5 min is above the expected handler time (enqueue or one short command) |
| A long outage leaves many rows due | batches of 20 loop without delay until drained; lag metric alerts |
| The Worker stops (SIGTERM) | `stoppingToken` stops after the current message; the claimed but unprocessed rows re-run after the lease |
| Payload schema change | new `vN` name; the old handler stays for one release |
| The user was deleted before dispatch | the handler finds nothing and returns (success) |
