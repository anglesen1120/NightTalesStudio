## Goal

A fresh Development database has voices, style templates and all publishing flags off as soon as the Api or the Worker starts. `nts-seed` does the same on demand elsewhere, and a reseed never deletes rows or flips a flag.

## Inputs

- Plan §3 (types, semantics, config, content), §7; README D8, D9, D10 (catalogs are not user-owned).
- 00 §6 rows `voices`, `style_templates`, `feature_flags`; 02 flag `source_finder`.

## Design

- Types per plan §3.1: `ISeeder`, `SeedReport`, `SeedRunner`, `VoiceSeeder`, `StyleTemplateSeeder`, `FeatureFlagSeeder` in `Infrastructure/Persistence/Seeding/`.
- Content file `seed/catalog.dev.json` (repo root, committed):

```json
{ "voices": [ { "id": "<vieneu-vi-1>", "displayName": "…", "language": "vi", "gender": "female", "tags": ["narrator"] } ],
  "featureFlags": [ "youtube_publish", "tiktok_publish", "source_finder" ] }
```

- Style templates come from **`seed/style-templates.v1.json`** (owner plan 03, 03.1.1-T1: 7 templates, `negativeClauseVersion`), loaded by `StyleTemplateSeeder` in **every** environment, not from `catalog.dev.json` (03 CR-1). Each row is validated with `StyleTemplateRules.Validate` (03.1.1-T2) and the file's `negativeClauseVersion` must equal `NegativeClause.Version`; any failure aborts the seed with `seed_style_template_invalid:<name>:<code>`.
- Upsert rules (plan §3.2):
  - voices: by `id`, updating `display_name`, `language`, `gender`, `tags`, `active`;
  - style templates: by `name`, updating `template`, `topic_hint`, `preview_storage_key`, `active` (03 CR-1);
  - flags: insert-only (`enabled = false`, `rules = {}`).
  - Rows missing from the file are left alone.
- `SeedHostedService : IHostedService` in both hosts: runs `SeedRunner` in `StartAsync` when `IsDevelopment() && Seed:Enabled != false`. A failure is logged, and startup continues.
- `nts-seed`: `Program.cs` in Api and Worker checks `args.Contains("--seed")` → builds the host, runs `SeedRunner`, exits 0 or 1. Usage: `dotnet run --project src/NightTales.Api -- --seed` against the native dev database (compose variant: `docker compose run --rm api --seed`) (09 W3 CR-35).
- Validation before writing: every `template` contains `{term}`; languages and genders parse to the enums; duplicate keys in the file → the seed fails with the key named.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Api and Worker seed at the same time | both upsert; the natural-key unique indexes make one insert win, and the other catches `23505` and retries the row as an update [DECISION] |
| Plan 04 renames a voice id | a new row is inserted; the old one stays and is deactivated by editing the file (`active: false`) |
| The catalog file is missing in Development | log a warning, skip the catalogs, still seed flags |
