## Goal

On a system with no owner, `nts-seed` (or the Development auto-seed) creates exactly one owner from environment variables. It never logs the password, and it does nothing once an owner exists.

## Inputs

- Plan §3.1 (`OwnerSeeder`), §8; README F22, D9 (`users.role` authoritative); 09 L102; 09.10.4-T1 (MFA enrolment forced at first login).

## Design

```csharp
public sealed class OwnerSeeder(UserManager<AppUser> users, AppDbContext db, IOptions<SeedOptions> options, IClock clock) : ISeeder
{
    public string Name => "owner"; public int Order => 100;
    // 1. if db.Users.Any(u => u.Role == PlatformRole.Owner) → Skipped
    // 2. email/password from Seed:Owner:Email / Seed:Owner:Password; either empty → Skipped + warning "owner seed not configured"
    // 3. users.CreateAsync(new AppUser { Email, UserName = Email, EmailConfirmed = true, Role = Owner, Status = Active,
    //    DisplayName = "Owner", UiLocale = Vi, CreatedAt = now }, password); Identity password policy applies (≥ 12 chars, 09.3.1)
    // 4. failure → throw with Identity error codes only (never the password)
}
```

- The MFA requirement comes from 09.10.4-T1 (an owner without TOTP must enrol at first login). This seeder sets nothing MFA-related.
- The password is used once and never stored in options logs: `SeedOptions.Owner` is excluded from the options dump, and its `ToString()` is overridden to `"***"`.
