## Goal

The Worker runs background jobs from PostgreSQL-backed Hangfire on named queues. Application code schedules them only through `IJobScheduler`, a job's retry policy comes from `[JobPolicy]`, and recurring jobs are kept in sync with the code at every start.

## Inputs

- Plan §3, §7; README D12 (port signatures, queues, rules), D1, N5, N6, H3.

## Design

```csharp
// Application/Abstractions/Jobs/
public interface IBackgroundJob;                                   // marker; job classes are sealed, resolved from DI
public enum JobQueue { Default, Render, Publish, Email }
[AttributeUsage(AttributeTargets.Class)]
public sealed class JobPolicyAttribute : Attribute { public JobQueue Queue { get; init; } = JobQueue.Default; public int Retries { get; init; } }
public interface IJobScheduler
{
    string Enqueue<TJob>(Expression<Func<TJob, CancellationToken, Task>> call) where TJob : class, IBackgroundJob;
    string Schedule<TJob>(Expression<Func<TJob, CancellationToken, Task>> call, TimeSpan delay) where TJob : class, IBackgroundJob;
    void AddOrUpdateRecurring<TJob>(string id, string cron, Expression<Func<TJob, CancellationToken, Task>> call) where TJob : class, IBackgroundJob;
    void RemoveRecurringIfExists(string id);
}
public interface IRecurringJobRegistration { string Id { get; } void Register(IJobScheduler scheduler); }
```

- `HangfireJobScheduler` rewrites `(j, ct) => j.RunAsync(id, ct)` into Hangfire's `Expression<Func<TJob, Task>>` by substituting `ct` with `CancellationToken.None` (H3). It then calls `IBackgroundJobClient.Enqueue(queue, expr)`, with the queue read from `[JobPolicy]` on `TJob` (lowercase name).
- `JobPolicyFilterProvider : IJobFilterProvider` returns `new AutomaticRetryAttribute { Attempts = policy.Retries, OnAttemptsExceeded = AttemptsExceededAction.Fail }` for the job type. It is registered via `GlobalJobFilters`/`JobFilterProviders.Providers.Add(...)` ⚠️ confirm the API. The global default `AutomaticRetryAttribute` (10 attempts) is **removed**, so the default is 0.
- `RecurringJobRegistrar.StartAsync`:
  1. Register every `IRecurringJobRegistration`.
  2. Read the current recurring ids from `JobStorage.Current.GetConnection().GetRecurringJobs()`.
  3. Remove those not registered, except those with the prefix `manual:` [DECISION].
  4. Cron is UTC.
- Storage: `UsePostgreSqlStorage(o => o.UseNpgsqlConnection(cs), new PostgreSqlStorageOptions { SchemaName = "hangfire", PrepareSchemaIfNecessary = true, QueuePollInterval = TimeSpan.FromSeconds(Jobs:QueuePollSeconds) })`.
- Server: `AddHangfireServer(o => { o.Queues = ["default","render","publish","email"]; o.WorkerCount = sum(Jobs:Workers:*) })`. [DECISION] One server with all queues in P. Per-queue servers come when a queue needs isolation (render, 09.6).
- Api: registers `IJobScheduler` **only** with a throwing implementation ("the Api schedules through the outbox", H4). An accidental Api use fails fast in tests.
- Worker `Program.cs` (in order): Serilog; `AddPersistence`; `AddMediator` (Scoped); `AddJobs`; `AddHostedService<OutboxDispatcher>()` (09.2.4-T1); health on `Worker:HealthPort`.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Two Workers start together | Hangfire's schema install takes a lock ⚠️; recurring upserts are idempotent |
| A job class is not registered in DI | Hangfire fails the job at activation; a start-time check resolves every `IBackgroundJob` type found in Application and fails the Worker boot if one is missing [DECISION] |
| A long job during shutdown | the server's cancellation token fires; jobs must honour `ct`; Hangfire requeues aborted jobs |
| Spike fails (H2) | see the plan's open items; the port and tests stay unchanged |
