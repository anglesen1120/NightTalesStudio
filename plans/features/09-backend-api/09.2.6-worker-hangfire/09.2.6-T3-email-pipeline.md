## Goal

Every e-mail the platform sends has one owner: a feature queues a typed message through `IEmailSender`, the outbox event `email_requested.v1` carries it to the Worker, `SendEmailJob` renders the `vi`/`en` template pair, sends it over SMTP with MailKit and records the outcome in `email_messages`, so callers that must know the delivery state (06.2.2-T3 veto notice, 02.8.2/02.8.3 alerts) read `IEmailDeliveryStatus`. Wave-2 addition to this signed folder (09 W2 CR-7, README BD9).

## Design

```csharp
// Application/Abstractions/Email/
public sealed record EmailMessage(Guid UserId, string Template, Language Locale, IReadOnlyDictionary<string, string> Params);

public interface IEmailSender                                              // queue only, never sends inline
{ Task<ErrorOr<Guid>> QueueAsync(EmailMessage message, CancellationToken ct); }   // returns email_messages.id

public enum EmailStatus { Queued, Sent, Failed }
public sealed record EmailDelivery(Guid Id, EmailStatus Status, int Attempts, string? LastErrorCode,
                                   DateTimeOffset? SentAt, DateTimeOffset CreatedAt);
public interface IEmailDeliveryStatus { Task<ErrorOr<EmailDelivery>> GetAsync(Guid emailMessageId, CancellationToken ct); }

public interface ISmtpEmailSender { Task<ErrorOr<string>> SendAsync(MimeMessage message, CancellationToken ct); }  // Infrastructure detail, faked in TestKit

public interface IEmailTokenMinter                                            // one per token-bearing template; WT17
{ Task<ErrorOr<IReadOnlyDictionary<string, string>>> MintAsync(Guid userId, string template, IReadOnlyDictionary<string, string> parameters, CancellationToken ct); }   // creates the single-use row, returns the render values it owns (the link)
```

**Token-bearing e-mails ("[RULED — README §B10 WT17, WT30]).** The link token is minted **at send time, inside `SendEmailJob`**, by a per-template `IEmailTokenMinter` — P ships `PasswordResetTokenMinter` (template `password_reset`), which calls 09.3.3-T1's `IUserActionTokenService.IssueAsync` to create the `user_action_tokens` row and 09.3.3-T1's `AuthLinks` to build the `#`-fragment link; the S-phase `email_verify` minter belongs to 09.3.1-T3. Consequences: outbox payloads and `email_messages.params` **never** hold a token, `link` is **not** an allow-listed `params` key, and `params jsonb` keeps only allow-listed token-free values and is set to `null` once `sent`. Two key sets therefore exist per template: the **producer allow-list** in `EmailTemplateCatalog.Keys` (excludes `link`) which `QueueAsync` enforces, and the template placeholders, which the renderer satisfies from the producer params **plus** the minter's values at send time — so `{{link}}` renders without ever travelling through `params`.

`QueueAsync` (Application, `EmailSender`): resolve the template in `EmailTemplateCatalog` (unknown → `Error.Validation("email_template_unknown")`); reject a param key outside the template's allow-list (`email_template_keys`); compute `toHash = SHA-256(lowercase(trim(user.email)) + pepper)`; add the aggregate — the outbox interceptor (D11) writes `email_requested.v1` in the same `SaveChanges`. All producers are command or outbox handlers, so it always joins an existing UnitOfWork.

**The row owns the render input.** `outbox_messages.payload` is not a usable source on a retry: `OutboxCleanupJob` deletes rows with `processed_at < now − 7 d` (09.2.4 plan L49), while a Hangfire retry can run later than that — so `params jsonb` must live on `email_messages`. That makes `params jsonb` a required addition to 00 §6's `email_messages` row (currently `user_id, template, locale, to_hash, status, attempts, provider_message_id, last_error_code, created_at, sent_at`, 00 §6 L270): **CR requested of 00 §6, as a follow-up to 09 W2 CR-1**; the alternative (keep the outbox row authoritative and pass its id) fails on exactly the retries that need it. `outbox_message_id` is deliberately **not** added: the message id is the idempotency guard, and the row is its own audit trail. (Open items.)

No `to_address` column: the job resolves the current address from `users.email` by `user_id`, so the address exists once in the database. No FK to `users` — rows outlive the account (13 §5.4).

**Job.**

```csharp
// Application/Features/Email/Jobs/SendEmailJob.cs
[JobPolicy(Queue = JobQueue.Email, Retries = 5)]
public sealed class SendEmailJob : IBackgroundJob { public async Task RunAsync(Guid emailMessageId, CancellationToken ct); }
```

Steps: `ISystemWorkQuery.PendingAsync<EmailMessage>(m => m.Id == emailMessageId, 1, ct)` (the wave-1 pinned member, 09.2.3-T1 L36 — no port widening) → no pair → log `email_message_missing` and return; `using var scope = systemContext.For(userId)`; load the row (the tenant filter now applies, so `EmailMessage : IUserOwned` is what makes this safe) — already `Sent` → return (idempotency guard, `09 §5.3`); `Sending()`; mint the template's token values (`IEmailTokenMinter`, [RULED — README §B10 WT17, WT30]) and commit that single-use token row in this step; read `users.email` (`status = deleted` or null → `Failed("email_user_gone")`, return, never retry); render with the minted values (never persisted); build the `MimeMessage` with `MessageId = "<{emailMessageId}@nighttales.app>"` (deterministic, so a retry cannot produce two distinguishable messages), `From` from `Email:From`, `To` = the address read now; `ISmtpEmailSender.SendAsync` → `Sent(providerMessageId)`; on any exception → `Failed(code)` + rethrow so Hangfire applies the 5-attempt policy. The job owns its scope and calls `SaveChangesAsync` itself (D5's "handlers never call `SaveChanges`" applies to Mediator handlers).

**Config (defaults).** `Email:From:Address` (required), `Email:From:Name` = `NightTales`, `Email:Smtp:Host` = `127.0.0.1` (Development = Mailpit), `Email:Smtp:Port` = `1025`, `Email:Smtp:Security` = `None` (Development only) | `StartTls` | `StartTlsWhenAvailable` | `SslOnConnect`, `Email:Smtp:Username`, `Email:Smtp:PasswordSecretRef` = `nts/<env>/api/SMTP_PASSWORD`, `Email:Smtp:TimeoutSeconds` = 30, `Email:AddressHashPepperSecretRef` = `nts/<env>/api/EMAIL_ADDRESS_PEPPER` (no default). `EmailOptionsValidator` fails boot when the environment is not `Development` and security is `None`, a credential is missing, or the pepper is unset. Links are built at send time from `App:PublicOrigin` by the minter ([RULED — README §B10 WT17]).

**Metrics.** `email_queued_total{template}`, `email_sent_total{template}`, `email_failed_total{template,code}`, `email_send_seconds`.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| SMTP down | exception → `Failed(code)`, up to 5 Hangfire attempts with backoff, then the job is `Failed` and `email_failed_total` increments; the row stays `failed` and an operator can retry it (dashboard, 09.2.6-T2) |
| The address changed between queue and send | the job reads the current address; the old `to_hash` stays for correlation. For `password_reset` the new address is acceptable (the token belongs to the user) [DECISION] |
| User deleted or suspended | `email_user_gone`, no send, no retry |
| Two Workers take the same job | Hangfire's per-job lock serialises them; the `Sent` guard makes a second delivery attempt impossible after the first commit |
| Templates and catalog drift | boot fails; both ship in one build |
| A single-use token (reset/verify/cancel link) | [RULED — README §B10 WT17, WT30] it is minted inside `SendEmailJob` by the template's `IEmailTokenMinter` and exists only in the rendered SMTP body: never in `email_messages.params`, never in `outbox_messages.payload`, never logged (redacted by the 09.9.3-T2 processors), and `params` is `null` on `sent` |
| MailKit's licence (MIT ⚠️) is rejected at implementation | re-implement `ISmtpEmailSender` on another SMTP client; port, job and tests unchanged (W2-O4) |
| One recipient accepted, another refused | one `email_messages` row per recipient; a 550 is permanent → `failed`, no retry storm [DECISION] |

## Notes

- BD9 is the contract (queue `email`, 5 retries, `{{key}}`, MailKit + TLS, `email_messages` + `IEmailDeliveryStatus`, the template file pattern); deviations are listed in the plan's Open items, not invented here.
- `EmailMessage : IUserOwned`, so D10's tenant filter applies to every read: the job resolves the owner through the pinned `ISystemWorkQuery.PendingAsync` member and then runs under `ISystemContext.For`, and `IEmailDeliveryStatus.GetAsync` reads through the filtered context — another user's message is a 404 with no hand-rolled predicate.
- [RULED — README §B10 WT17, WT30] Token-bearing templates (`password_reset`, and the S-phase `email_verify`) get their link from an `IEmailTokenMinter` executed inside `SendEmailJob`, which also creates the single-use `user_action_tokens` row; nothing token-bearing is ever queued or persisted.
- [INFERENCE] the template path, the six template names, the `Email:*` keys, the metric names, `EMAIL_ADDRESS_PEPPER`, `ISmtpEmailSender` — see the plan's Open items.
- [OPEN] CR to 00 §6: add `params jsonb` to the `email_messages` row (09 W2 CR-1 follow-up). Required, not cosmetic: outbox payloads are purged after 7 d (`OutboxCleanupJob`, 09.2.4 plan L49) while a Hangfire retry can run later, so the row must own its render input.
