# 09.3.1-T2 — Breached-password check and registration hardening

## Goal

Make a breached password unusable at every password-setting entry point, and close the registration hardening gaps that the signed 09.3.1-T3 leaves open — without adding a second register handler or a second register path (F01, W3 CR-4). Deliverable: `IBreachedPasswordChecker` over the HIBP Pwned Passwords **range** API with a bundled top-N seed and fail-open (§C3 D3), the disposable-domain and `email_not_verified` hardening asserted on the signed flow, and the CAPTCHA/rate-limit wiring of `POST /auth/register` (`captchaToken`, `anon` policy).

## Design

**Port and implementation (D3).**

```csharp
// Application/Abstractions/Identity/IBreachedPasswordChecker.cs
public sealed record BreachCheckResult(long Count, bool FromBundledSeed, bool RemoteUnavailable);
public interface IBreachedPasswordChecker { Task<ErrorOr<BreachCheckResult>> CheckAsync(string password, CancellationToken ct); }

// Infrastructure/Identity/PwnedPasswordsChecker.cs
public sealed class PwnedPasswordsChecker(
    IHttpClientFactory clients, IMemoryCache cache, IPwnedSeedProvider seed,
    IOptions<PwnedPasswordsOptions> options, ISecurityAlerter alerter,
    IAuditWriter audit, ILogger<PwnedPasswordsChecker> log) : IBreachedPasswordChecker
{
    public async Task<ErrorOr<BreachCheckResult>> CheckAsync(string password, CancellationToken ct)
    {
        var full = Convert.ToHexString(SHA1.HashData(Encoding.UTF8.GetBytes(password))); // in memory only, never persisted/logged
        var prefix = full[..5]; var suffix = full[5..];
        if (options.Value.BundledSeedEnabled && seed.Contains(full)) return new BreachCheckResult(1, true, false);
        if (cache.TryGetValue<HashSet<string>>($"pwned:{prefix}", out var hit)) return FromCache(hit, suffix);
        var req = new HttpRequestMessage(HttpMethod.Get, $"range/{prefix}")
                  { Headers = { { "Add-Padding", "true" }, { "User-Agent", "nts-api/" + Version } } };
        try
        {
            using var res = await clients.CreateClient(HttpClients.PwnedPasswords).SendAsync(req, ct);
            if (!res.IsSuccessStatusCode) return await UnavailableAsync(ct);
            var set = Parse(await res.Content.ReadAsStringAsync(ct));       // "SUFFIX:count" lines, count 0 = padding
            cache.Set($"pwned:{prefix}", set, new MemoryCacheEntryOptions { Size = 1, AbsoluteExpirationRelativeToNow = TimeSpan.FromMinutes(options.Value.CacheMinutes) });
            return FromCache(set, suffix);
        }
        catch (Exception ex) when (ex is HttpRequestException or TaskCanceledException) { log.LogWarning("breach_check_unavailable {Kind}", ex.GetType().Name); return await UnavailableAsync(ct); }
    }
}
```

- `IPwnedSeedProvider` loads the bundled `pwned-top-100000` seed once (embedded resource of SHA-1 hex hashes, `Lazy<HashSet<string>>`, `StringComparer.OrdinalIgnoreCase`) — no filesystem read per request, no network.
- `IMemoryCache` for the range responses is registered with `SizeLimit = PwnedPasswordsOptions.CacheSizeLimit` (2,000) so the cache is bounded; the key is the 5-char prefix only.
- Settlement: suffix membership is decided with `CryptographicOperations.FixedTimeEquals` over the UTF-8 bytes of the two suffixes (constant-time membership rather than `HashSet.Contains`) so the comparison does not leak which suffix matched.
- **Fail-open** (`FailOpen true`): transport error, timeout (`TimeoutSeconds 5`), 5xx or an unparseable body returns `BreachCheckResult(0, false, true)`; a *successful* `200` that contains the suffix → `Count ≥ 1`. `RemoteUnavailable = true` **never** blocks the flow, and the same code path writes one `security.breach_check_unavailable` audit row (`Category.AccountSecurity`, `Visibility.Internal`, `data = {"kind":"hibp"}`) + the `breached_password_check_total{outcome="unavailable"}` metric + one alert through `ISecurityAlerter` throttled by `CaptchaOptions.AlertThrottleMinutes`… throttle state is the alerter's (09.10.4-T3), this task only calls it.
- The outbound call is bounded: named client `pwnedpasswords` (W3 CR-7: attempt 5 s / total 8 s, ≤ 1 transport retry, **no retry on 4xx**), and a successful login/registration on the bundled seed makes **zero** outbound calls (§C6).

**Call sites (no second register path).** `ModeAwareRegistrationFlow` (09.3.1-T3) calls `CheckAsync` after `RegisterValidator` shape validation and **before** the account lookup, so an existing and a new e-mail take the same path and the same timing budget; a `Count ≥ 1` result returns 400 `breached_password` and **no** `users`/`user_consents` row is written (the check runs inside the handler's UnitOfWork, before the aggregate is added). `ResetPasswordCommand` (09.3.3-T1) and the change-password handler keep their own call site through the same port and keep their existing 400 `breached_password` mapping — this task changes neither handler body.

**Hardening (F01).** The disposable-domain rule stays 09.3.1-T3's (`IRegistrationPolicyProvider.Current.DisposableDomains`, evaluated before the account lookup, 400 `validation_failed` field `email` with the generic address message); this task (a) adds the acceptance/timing test that proves it is not an enumeration oracle, (b) validates the `registration.disposable_domains` array shape where it is read (lowercase, IDN-normalized, no wildcards, ≤ 200 entries — the settings write side and its 400 `setting_invalid` are 09.10.6-T1's), and (c) asserts the `RequireVerifiedEmailFilter` → 403 `email_not_verified` gate on a protected route.

**CAPTCHA and rate-limit wiring (W3 CR-9/CR-7, soft on 09.3.3-T2).** `RegisterCommand` gains `string? CaptchaToken` (CR-9); the register endpoint consumes it through 09.3.3-T2's `ICaptchaVerifier`/gate when the pair's counter says `captcha_required` (mode `open` always calls the gate), and the route is mounted on the `anon` policy (60 req/min per resolved IP, `Retry-After` in `OnRejected`, defined by 09.3.5-T1). One line in `Api/Endpoints/AuthEndpoints.cs` attaches the policy; the gate itself is 09.3.3-T2's step, called from the same flow.

## Acceptance checks

- [ ] Given a password whose SHA-1 prefix+suffix exists in the remote range, When `POST /auth/register` is called with it, Then 400 `breached_password`, no `users` row, no `user_consents` row, and the response body/timing is indistinguishable from the existing-e-mail path.
- [ ] Given a password in the bundled seed **and** the remote client unreachable, When register is called, Then 400 `breached_password` with **zero** outbound HTTP calls (`FakeHttpMessageHandler.CallCount == 0`).
- [ ] Given the range endpoint times out or answers 500, When register is called with a password unknown to the seed, Then the registration proceeds, exactly one `security.breach_check_unavailable` audit row (`category = account_security`, `visibility = internal`) exists, `breached_password_check_total{outcome="unavailable"}` incremented, and one alert was handed to `ISecurityAlerter`.
- [ ] Given two identical registrations inside `CacheMinutes`, Then the second one performs **no** second range request (cache hit) and at most `CacheSizeLimit` prefixes are ever cached.
- [ ] Given captured logs/traces/audit rows of the whole suite, Then no password, no SHA-1 hash, no 5-char prefix and no `pwnedpasswords` request URI appears (§C5, §C8).
- [ ] Given `registration.disposable_domains` contains `mailinator.com`, When `A@Mailinator.com` registers, Then 400 `validation_failed` with field `email` and the generic message, and the account lookup never ran (timing envelope equal to a fresh address).
- [ ] Given a malformed `registration.disposable_domains` value (wildcard, uppercase with a dot-suffix mismatch, 201 entries), Then it is rejected as 400 `setting_invalid` at the settings write side and the register flow never sees it (09.10.6-T1 owns the write; asserted here as a read-side guard).
- [ ] Given an unverified account calling a `RequireVerifiedEmailFilter` route, Then 403 `email_not_verified` and the DB row is unchanged.
- [ ] Given the pair's counter is at 3 failures, When register is called without `captchaToken` in mode `open`, Then 400 `captcha_required`; with a valid token the registration succeeds; with an invalid token 400 `captcha_invalid` (gate = 09.3.3-T2, asserted on this route).
- [ ] 11 register attempts in one minute from one IP → the 11th answers 429 `rate_limited` with `Retry-After` and never reaches the flow (the `anon` policy).
- [ ] `grep` finds exactly one `IRegistrationFlow` implementation and exactly one `/auth/register` route mapping (no second register path).

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| HIBP 5xx / timeout / DNS failure | Fail-open: registration continues, one audit row + metric `unavailable` + throttled alert; never a 5xx to the caller (D3) |
| HIBP answers 200 with a malformed body | Treated as unavailable (fail-open) + `LogWarning` with the status code only, never the body |
| Bundled seed file missing/corrupt at startup | Host fails fast at startup (the seed is a build artefact), logged without any hash content |
| Password longer than 128 chars | `RegisterValidator` already rejects it before the checker (09.3.1-T3:39) — the checker is never reached |
| Two concurrent registrations of the same prefix | Both may issue one request; the cache is bounded and idempotent, no lock needed |
| HIBP reachable but slow (> 8 s total) | The resilience pipeline cancels → fail-open; `breached_password_check_total{outcome="unavailable"}` |
| `CaptchaOptions.Enabled = false` or a Turnstile outage | The gate degrades per D4 (fail-open + delay) on login; on `/auth/register` the flow answers 503 `captcha_unavailable` (09.3.3-T2) |
| Mode `closed` | 403 `registration_closed` from the signed flow, before the breach check |
| Cache eviction under memory pressure | A later request re-fetches the prefix; no correctness impact |
