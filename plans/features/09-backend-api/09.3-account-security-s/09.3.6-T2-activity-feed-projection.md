# 09.3.6-T2 — Activity feed projection

| Story | Size | Area | Depends on | Blocks | Phase / flag |
|---|---|---|---|---|---|
| 09.3.6-T2 | S (0.5) | BE | 09.3.6-T1; 09.5.1-T1 soft | 09.10.5-T1 soft, 10.8.5-T1 (W3 CR-14) | S · M2 |

## Goal

Let a user see their own history without ever leaking staff identity, IP addresses or raw payloads: `GET /me/activity` and `GET /episodes/{id}/activity`, both cursor-paginated projections of `audit_logs` restricted to the frozen `messageKey` allow-list (§C3.4), reusing the two indexes 09.3.6-T1 already created.

## Inputs

- README §C0 brief 1, §C3 **D11** (feed ordering context), D18 (i18n), §C3.1 (both routes), **§C3.4** (the frozen allow-list — authoritative for this task), §C6 (query plan), §C7 (`messageKey` freezing), F10.
- Reuse (never re-implement): `AuditLog`/`Category`/`Visibility`/`ActorType` and the three existing indexes `ix_audit_logs_subject_created (subject_user_id, created_at DESC)`, `ix_audit_logs_entity (entity_type, entity_id) WHERE entity_id IS NOT NULL`, `ix_audit_logs_created_id (created_at, id)` (09.3.6-T1:41-50 / plan.md:41-51); `Cursor`/`Page<T>` keyset helper (`readonly record struct Cursor(DateTimeOffset CreatedAt, Guid Id)` + `Page<T>(IReadOnlyList<T> Items, string? NextCursor)`, defined in `09.4.1-T1-series-aggregate-commands-endpoints.md:39-41` and reused the same way 09.5.1-T1 reuses it); `ICurrentUser` (09.2.3-T1:18); `IReadDb`.
- `audit_logs` is **not** `IUserOwned` (it carries both `subject_user_id` and `actor_user_id` — one tenant filter cannot express it, 09.3.6-T1 plan.md:56) — every query here uses an **explicit** `subject_user_id = @me` predicate (D10's documented explicit-predicate path for non-aggregate rows), never `IgnoreQueryFilters`.
- `action` **is** the frozen wire `messageKey` (09.3.6-T1:133, W3-TL2); the allow-list this task projects from is §C3.4 verbatim — copied here, not re-derived.

## Design

**Allow-list (verbatim from §C3.4, the single source of truth for `params`).**

| `action` | Category | `params` built |
|---|---|---|
| `account.registered`, `account.email_verified`, `account.logout`, `account.password_changed`, `account.password_reset_requested`, `account.password_reset`, `account.mfa_enabled`, `account.mfa_disabled`, `account.mfa_reset`, `account.mfa_failed`, `account.refresh_reuse_detected` | account_security | `{}` |
| `account.sessions_revoked_all` | account_security | `{count}` |
| `account.login_succeeded`, `account.login_failed`, `account.captcha_challenged` | account_security | `{device}` + `ip`/`device` columns |
| `account.progressive_delay` | account_security | `{seconds}` |
| `account.mfa_locked` | account_security | `{until}` |
| `account.session_revoked` | account_security | `{device, via}` (`via ∈ self\|admin\|stamp`) |
| `account.suspended`, `account.unsuspended` | account_security | `{reason?}` |
| `account.role_changed` | account_security | `{from, to}` (**no** actor id) |
| `support.action_taken` | support | `{action, reason}`, `actorLabel = "Support team"` |
| `owner_action.requested`, `owner_action.approved`, `owner_action.cancelled`, `owner_action.applied` | account_security | `{action, targetDisplayName}` (**no** owner e-mail/id) |

`settings.*`, `flag.changed`, `admin.user_viewed`, `content_viewed` (category `support`, visibility `internal`) are **never** projected to `/me/activity` — excluded by the `visibility = 'user'` predicate below, not by a second allow-list.

**Query (`GetActivityQuery`).**

```csharp
public sealed record GetActivityQuery(string? Category, DateTimeOffset? From, DateTimeOffset? To, string? Cursor, int Limit = 20)
    : IQuery<ErrorOr<Page<ActivityItemDto>>>;
public sealed record GetEpisodeActivityQuery(Guid EpisodeId, string? Cursor, int Limit = 20)
    : IQuery<ErrorOr<Page<ActivityItemDto>>>;
public sealed record ActivityItemDto(DateTimeOffset OccurredAt, string Category, string MessageKey,
    IReadOnlyDictionary<string, string> Params, string? TargetType, Guid? TargetId,
    string ActorLabel, string? Reason, string? Ip, string? Device);   // §C3.1 verbatim (09 §4.3.6)
```

```csharp
// Application/Features/Activity/GetActivityHandler.cs
var rows = await db.AuditLogs
    .Where(a => a.SubjectUserId == currentUser.Id && a.Visibility == Visibility.User)
    .Where(a => AllowListedActions.Contains(a.Action))                       // §C3.4 set, compiled to a SQL IN(...)
    .WhereIf(category is not null, a => a.Category == category)
    .WhereIf(from is not null, a => a.OccurredAt >= from)
    .WhereIf(to is not null, a => a.OccurredAt <= to)
    .OrderByDescending(a => a.CreatedAt).ThenByDescending(a => a.Id)         // matches ix_audit_logs_subject_created
    .Where(cursor is not null ? Cursor.KeysetPredicate(cursor) : _ => true)
    .Take(limit + 1)
    .Select(a => new { a.OccurredAt, a.Category, a.Action, a.Data, a.EntityType, a.EntityId, a.ActorType,
                       Ip = a.Category == Category.AccountSecurity ? a.Ip : null,
                       Device = a.Category == Category.AccountSecurity ? a.UserAgent : null })
    .ToListAsync(ct);
```

Projection to `ActivityItemDto` happens **in memory** after the query (never `SELECT data`-as-is): `Params` is rebuilt key-by-key from the row's `DataJson` restricted to §C3.4's declared keys for that `action` — an unlisted key in `data` is dropped, never forwarded; `ActorLabel` is `"Support team"` when `ActorType == Admin` (or the row's action is `support.action_taken`), else the caller's own display name is **not** needed (the row is already theirs); `Ip`/`Device` are populated only when `Category == AccountSecurity` **and** the row's `SubjectUserId == @me` (already guaranteed by the outer predicate) — the projection never reads `a.Data` as a raw pass-through and never returns the actor's id.

**Episode variant.** `GetEpisodeActivityQuery` adds `entity_type = 'episode' AND entity_id = @episodeId` to the same predicate set (reusing `ix_audit_logs_entity`, a partial index that already exists) — **and keeps** `subject_user_id = @me`, so another user's episode-id guess still returns an empty allow-listed page that the handler maps to 404 `not_found` (existence is checked via 09.5.1-T1's episode read port, not by inferring 404 from an empty activity page, to avoid a timing oracle between "no activity yet" and "not your episode").

**Cursor and paging.** Reuses the shared `Cursor`/`Page<T>` struct verbatim (no `CursorPageDto`/`CursorCodec` — those names do not exist anywhere in this plan set, confirmed by grep); `limit` defaults 20, max 100 (mirroring 09.5.1-T1's own `limit` bound pattern) — `limit ≤ 0` or `> 100` → 400 `validation_failed` field `limit`; an invalid cursor → 400 `validation_failed` field `cursor` (same shape as 09.5.1-T1:106-107).

## Steps

1. Add `GetActivityQuery`/`GetEpisodeActivityQuery`, `ActivityItemDto`, `AllowListedActions` (a `static readonly FrozenSet<string>` built from the §C3.4 table above — one array literal, not a config file, since the set is frozen at release per W3-TL2).
2. Add the handlers; wire the in-memory allow-listed `Params` rebuild per action (a small `IReadOnlyDictionary<string, Func<AuditDataRow, IReadOnlyDictionary<string,string>>>` keyed by `action`, one entry per row of the §C3.4 table).
3. Map `GET /me/activity` and `GET /episodes/{id}/activity` (the latter behind the existing episode tenant check via 09.5.1-T1's read port for the 404 case).
4. Add the i18n keys `activity.<action>` for every §C3.4 row in vi and en.
5. Write the tests; verify the query plan (`EXPLAIN`) uses the two named indexes, not a sequential scan.

## Acceptance checks

- [ ] Given a user with mixed `account_security`/`support`/`internal` rows, When `GET /me/activity` is called, Then only `visibility = user` rows on the §C3.4 allow-list are returned, in `messageKey`/`category`/`params` shape exactly as documented, and `data` never appears verbatim in the response.
- [ ] Given a `support.action_taken` row where an admin acted, Then `actorLabel = "Support team"` and no admin id/e-mail appears anywhere in the item.
- [ ] Given another user's `subject_user_id`, Then their rows never appear in the caller's page (tenant isolation via the explicit predicate, not `IgnoreQueryFilters`).
- [ ] Given `GET /episodes/{id}/activity` for an episode that belongs to another user, Then 404 `not_found` (via the episode read port's own 404, not an empty-page inference).
- [ ] Given `category`/`from`/`to`/`cursor`/`limit` filters, Then each narrows the result set correctly and an invalid `cursor` or a `limit` outside `1..100` returns 400 `validation_failed` on the matching field.
- [ ] Given the query's `EXPLAIN (ANALYZE)` output, Then it uses `ix_audit_logs_subject_created` (or `ix_audit_logs_entity` for the episode variant) — never a sequential scan on `audit_logs`.
- [ ] Given every `action` in §C3.4, Then a corresponding `activity.<action>` key exists in both `vi` and `en` resource files (build-time or test-time check).
- [ ] Given a row whose `action` is **not** in `AllowListedActions` (e.g. `settings.changed`), Then it never reaches the response even if some future bug tries to write it with `visibility = user`.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| `entity_id` null on a non-episode row reaching the episode query | Excluded by the partial index predicate itself (`WHERE entity_id IS NOT NULL`) — never a candidate row |
| A future writer adds a new `action` without updating `AllowListedActions`/i18n | The row exists in `audit_logs` but never surfaces on `/me/activity` until both are added — fails closed, not open (W3-TL2's "cannot merge without" rule is enforced by the allow-list being the only path to the response, not by a separate lint) |
| `category` filter value outside the four enum names | 400 `validation_failed` field `category` |
| `from > to` | 400 `validation_failed` (both fields named) |
| A row's `Data` JSON is missing a key the allow-list expects (defensive) | The builder omits that key from `Params` rather than throwing (a malformed historical row must not 500 the whole page) |
| 100+ rows requested in one page | Capped at 100; `limit = 101` → 400, matching 09.5.1-T1's own bound (consistency across list endpoints) |
