# 09.3.4-T1 — `GET /me` and `PATCH /me`: display name, UI locale, read-only e-mail, MFA state

## Goal

An authenticated user reads and edits his own account: `GET /me` returns the profile the UI needs, `PATCH /me` changes `display_name` and `ui_locale` only. The address, the role and the MFA state are visible but not writable here, and every request acts on `ICurrentUser.Id` — there is no user id in the route.

## Design

```csharp
// Application/Features/Me/
public sealed record MeDto(Guid Id, string DisplayName, string Email, Language UiLocale, PlatformRole Role,
                           bool MfaEnabled, DateTimeOffset? LastLoginAt,
                           IReadOnlyList<string> Features);   // 10 CR-10: enabled keys of MeFeatureAllowList

public sealed record GetMeQuery : IQuery<ErrorOr<MeDto>>;

[Audited("account.profile_updated", Category.AccountSecurity, Visibility.User)]
public sealed record UpdateMeCommand(string? DisplayName, Language? UiLocale) : ICommand<ErrorOr<MeDto>>, IAuditData
{
    internal Dictionary<string, string> Summary { get; } = [];                    // the handler writes the delta here
    public AuditData ToAuditData() => new(SubjectUserId: null, EntityType: "user", EntityId: null, Summary);  // SubjectUserId filled from ICurrentUser
}

public sealed class UpdateMeCommandValidator : AbstractValidator<UpdateMeCommand>
{
    public UpdateMeCommandValidator()
    {
        RuleFor(c => c).Must(c => c.DisplayName is not null || c.UiLocale is not null).WithErrorCode("required");
        RuleFor(c => c.DisplayName).Length(1, 80).Must(v => v is null || v == v.Trim()).When(c => c.DisplayName is not null);
        RuleFor(c => c.DisplayName).Must(v => v is null || !v.Any(char.IsControl)).When(c => c.DisplayName is not null);
    }
}
```

- Endpoint group `Api/Endpoints/MeEndpoints.cs : IEndpointGroup` (`Api/Endpoints/` [INFERENCE: folder name, D14 fixes `Api/Endpoints/<Feature>Endpoints.cs`]), mapped at `/api/v1/me` with `.RequireAuthorization()`; no rate-limit policy (plan §5) and no `If-Match`/`ETag` (D15 lists episodes/series only).
- `GetMeQueryHandler`: read with `IReadDb` (no tracking, D8) by `ICurrentUser.Id!.Value`, project directly into `MeDto` in SQL (no entity materialisation, no N+1). `UiLocale`/`Role` are enums serialised snake_case by the global converter (D14) → `"vi"`, `"user"`. `MfaEnabled` = `users.two_factor_enabled` (00 §6; the enrolment transitions belong to 09.10.4-T1). `LastLoginAt` = `users.last_login_at`. `MeDto` deliberately carries **no** `createdAt`: `users` has no such column (G7).
- `Features` (10 CR-10): `MeFeatureAllowList = ["source_finder", "youtube_publish"]` (Application constant); the handler asks `IFeatureFlags.IsEnabledAsync(key, ct)` (09.9.2-T2, cached 30 s) for each key and returns the enabled ones in allow-list order; until 09.9.2-T2 lands the list is empty (soft edge). Only allow-listed keys are ever exposed (no flag enumeration). `PATCH /me` returns the same field.
- `UpdateMeCommandHandler`: load the tracked user `await db.Users.FirstOrDefaultAsync(u => u.Id == currentUser.Id!.Value, ct)`; `null` or `status = deleted` → 401 `unauthenticated` (the token outlived the account) [DECISION]; otherwise set `DisplayName` when non-null and `UiLocale` when non-null, fill `Summary` (`"uiLocale" = "en->vi"`, `"displayName" = "changed"` — never the name text, BD16), and return the updated `MeDto`. The handler **never** calls `SaveChangesAsync` or opens a transaction (D5): the UnitOfWork behaviour commits the tracked change and the audit row together.
- Over-posting: `UpdateMeRequest { string? DisplayName, Language? UiLocale }` is closed. [RULED — README §B10 WT18, WT44] Unknown JSON members are rejected by a **per-endpoint strict binding filter attached to `PATCH /me` only** — **not** by a global serializer change (`JsonUnmappedMemberHandling.Disallow` API-wide would alter every other endpoint's contract) — so `email`, `role`, `mfaEnabled` or any typo becomes 400 `validation_failed` instead of a silent no-op, and `email` stays read-only by construction.
- `Language` (D16) is reused for `ui_locale`; no `UiLocale` enum is introduced (plan §3).
- Route/DTO table: 200 `MeDto` on both verbs; 400 `validation_failed` (FluentValidation → D7 field grouping, camelCase `uiLocale`); 401 `unauthenticated`; 503 `service_unavailable` on a transient DB failure (D5). No 404: the row is the caller's.

## Acceptance checks

- [ ] `curl -s localhost:5000/api/v1/me -H "X-Test-User: <seeded owner>"` → 200 with `displayName`, `email`, `uiLocale`, `role`, `mfaEnabled`, `lastLoginAt`; the body contains no `securityStamp`, `passwordHash` or `lastTotpStep`.
- [ ] `curl -X PATCH … -d '{"uiLocale":"vi"}'` → 200 with `"uiLocale":"vi"`; a following `GET /me` returns the same value (read from the DB, not from the token).
- [ ] `curl -X PATCH … -d '{"email":"x@y.z"}'` → 400 `validation_failed` and the DB row is unchanged.
- [ ] `curl -X PATCH … -d '{"displayName":"   "}'` → 400 `validation_failed` with field `displayName`.
- [ ] After the PATCH, `SELECT count(*) FROM audit_logs WHERE action = 'account.profile_updated'` increased by exactly 1 and the row's `data` holds `{"fields":["uiLocale"],"uiLocale":{"from":"en","to":"vi"}}`.
- [ ] A failed PATCH (UC3) adds no audit row.
- [ ] An unauthenticated `GET /me` → 401.
- [ ] `PATCH /me` with an unknown member → 400 `validation_failed` through the per-endpoint filter, while a control endpoint with a JSON body still ignores unknown members — proving the strictness is not a global serializer change ([RULED — README §B10 WT18, WT44]).

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Token valid, user deleted/suspended | 401 `unauthenticated` (`deleted`), no write. Suspended: in P the only enforcement is at refresh (09.3.2-T1 L162), so a live access token still reaches `/me` until it expires; the per-request refusal (`IStampValidator` → 401 `session_revoked`, 09 README D9) is not part of P: its phase-S task is dropped by DEC 10.14 |
| Concurrent PATCH of the same field | last write wins; no `xmin` ETag on `/me` (D15), so no 412 — acceptable for a single-user profile |
| `uiLocale` sent as `"VI"` | 400 `validation_failed` (the converter matches exact snake_case, D14) |
| Unknown JSON member | 400 `validation_failed` via the per-endpoint strict binding filter on `PATCH /me` (closed DTO; [RULED — README §B10 WT18, WT44]) — never silently ignored, and no global serializer behaviour changes |
| `AppUser` is not Application-visible | `[INFERENCE]` the handler reads `IAppDbContext.Users` (`DbSet<AppUser>`, D8). If 09.3.1-T1 keeps `AppUser` inside Infrastructure, the handler switches to an Application port `IUserProfileReader`/`IUserProfileWriter` — the endpoint, DTO, validator and tests are unchanged |
| Audit write fails | the command returns 503 `service_unavailable` and the profile change rolls back with it (D5/D7) |
