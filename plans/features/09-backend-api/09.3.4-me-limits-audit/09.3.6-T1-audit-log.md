## Goal

Every state-changing command leaves exactly one `audit_logs` row, written by the Mediator `AuditBehavior` **inside** the command's transaction from an `[Audited(action, category, visibility)]` attribute and an `IAuditData` projection, or is explicitly exempted with `[NotAudited(reason)]` — enforced by an architecture test. Auth handlers, jobs and CLI verbs write through `IAuditWriter`, and 09.7.3-T1 deletes rows through one ordered retention rule list.

## Design

Full type list, the pipeline contract and the retention list are in `plan.md` §3; this section fixes the mechanism and the SQL.

```csharp
// Application/Abstractions/Audit/
[AttributeUsage(AttributeTargets.Class, Inherited = false)]
public sealed class AuditedAttribute(string action, Category category, Visibility visibility) : Attribute;
[AttributeUsage(AttributeTargets.Class, Inherited = false)]
public sealed class NotAuditedAttribute(string reason) : Attribute;

public interface IAuditData { AuditData ToAuditData(); }
public sealed record AuditData(Guid? SubjectUserId, string? EntityType, Guid? EntityId, IReadOnlyDictionary<string, string> Summary);

public sealed record AuditEntry(Guid? ActorUserId, ActorType ActorType, Guid? SubjectUserId, string Action, Category Category,
                               Visibility Visibility, string? EntityType, Guid? EntityId, string DataJson,
                               IPAddress? Ip, string? UserAgent, string? ActorLabel, DateTimeOffset OccurredAt);
public interface IAuditWriter { Task WriteAsync(AuditEntry entry, CancellationToken ct); }   // joins the ambient transaction; never commits
```

```csharp
// Application/Behaviors/AuditBehavior.cs — D4 slot 6 (Logging 1 … UnitOfWork 4 → Idempotency 5 → Audit 6)
public sealed class AuditBehavior<TRequest, TResponse>(IAuditWriter writer, ICurrentUser user, IAuditContext context,
    AuditMetadataCache metadata, IClock clock) : IPipelineBehavior<TRequest, TResponse>
    where TRequest : notnull where TResponse : IErrorOr
{
    public async ValueTask<TResponse> Handle(TRequest request, MessageHandlerDelegate<TRequest, TResponse> next, CancellationToken ct)
    {
        var response = await next(request, ct);
        if (!response.IsError && request is IAuditData data && metadata.TryGet<TRequest>(out var attribute))
            await writer.WriteAsync(ToEntry(attribute, data, user, context, clock.UtcNow), ct);
        return response;
    }
}
```

Because slot 6 sits inside the UnitOfWork's transaction (D4/G6) and `EfAuditWriter` only adds the row to `AppDbContext`, the row commits with the change; an error response writes nothing; and an idempotent replay short-circuits in slot 5 — outside Audit — so a replay never duplicates a row. `ActorType` is derived (plan §3): `User` when `ICurrentUser.Id == SubjectUserId`, `Admin` when the role is admin/owner and the subject differs, else `System`. `Ip`/`UserAgent` are filled only for security events, which are written by the auth handlers through `IAuditWriter` (the behaviour leaves them null). `[INFERENCE]` `AuditMetadataCache` (attribute lookup per closed request type) and `IAuditContext` implement `HttpContext` IP/user-agent in the Api and nulls in the Worker.

Migration `<yyyyMMddHHmm>_09.3.6T1_AuditLogs`: the DDL and indexes are in `plan.md` §3 (00 §6 columns, `CHECK` via `HasEnumCheck`, nullable `actor_user_id`/`subject_user_id` plus `ck_audit_logs_user_visible_has_subject`, no FK to `users`, index `(subject_user_id, created_at DESC)` + the `(entity_type, entity_id)` partial index for 09.3.6-T2 + the **`(created_at, id)` sweep index** ([RULED — README §B10 WT47], added to `plan.md` §3). `EfAuditWriter` is the only writer of the table; nothing reads it in P except the retention sweep.

Non-Mediator callers: auth handlers (09.3.2-T1/T3, 09.3.3-T1, 09.10.4-T1 — login success/failure, CAPTCHA challenge, progressive delay, logout, password change/reset, MFA on/off, refresh-token reuse, session revoked by security stamp), Worker outbox handlers/jobs (story generated/failed, render done/failed, publication published/failed, credits expired, refunds), CLI verbs (`nts-worker flags set` → `actor_type = system`, `data.actor = "system:operator"`, category `support`, visibility `internal`, BD13), 11.3.3-T1 (`render_node.state_changed`, T5) and 09.7.2-T1 (`episode.video_url_issued` — a query, so it opens `IUnitOfWork` explicitly). Each of those calls `IAuditWriter.WriteAsync` and relies on its own transaction: an outbox handler that already uses a command needs no change; a bare job or verb must `BeginAsync`/`CommitAsync` itself.

Architecture test (`tests/NightTales.Architecture.Tests/AuditAttributeTests.cs`, ArchUnitNET 0.13.4, D1/D2): every type implementing `Mediator`'s `ICommand<…>` in `NightTales.Application` has **exactly one** of the two attributes; `NotAuditedAttribute.Reason` is non-empty and ≤ 200 chars; `AuditedAttribute.Action` matches `^[a-z][a-z0-9_]*(\.[a-z0-9_]+)+$` and is unique; `Category`/`Visibility` are explicit attribute arguments (no defaults). A probe command that lives in the **test** assembly deliberately violates the rule, proving it fires (the slot-ordering check is 09.1.3-T2's test).

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| The audit insert fails (constraint, DB down) | the whole command rolls back and returns 503 `service_unavailable` (D5) — a change is never recorded without its audit row [DECISION] |
| A command is `[NotAudited]` by accident | the reason text is reviewable and short; the architecture test forces the author to write it |
| Failed login or CAPTCHA challenge on an unknown e-mail | `subject_user_id = null`, `visibility = internal`, `actor_type = system`/`user`, and the attempted address is stored **hashed** in `data` (never plain, like `email_messages.to_hash`); the `CHECK` forbids a null subject on a `user`-visible row. A failure on a **known** account writes that user as subject with `visibility = user`, so it shows in `GET /me/activity` (09 §4 L145) |
| A legacy/02 command already shipped an `[Audited]` attribute with the pre-BD15 signature | the attribute arity changed (action, category, visibility all required); a missing visibility is a compile error, not a silent internal default [DECISION] |
| `[Audited]` on a query | ignored by the behaviour (slot 6 is commands-only, D4); the arch test flags the attribute on a non-command as an error |
| 09.7.2-T1's `GET /episodes/{id}/video-url` writes a row inside a read | explicit `IUnitOfWork` per WF16; the guard in `EfAuditWriter` throws if no transaction is ambient, so the mistake fails in tests |
| Account deletion (13 §5.4) | no FK, no cascade; the sweep writes `subject_user_id`'s hash and keeps security/staff rows — this task only guarantees the row survives |
| Row growth | one insert per command, no update path, no cascade; 09.7.3-T1 deletes through the ordered rules, batches newest-first |
| A Worker job writes as `system` with no HTTP context | `ICurrentUser` is `ScopedCurrentUser` (`ISystemContext`, D10) and the Worker `IAuditContext` returns nulls; `ActorLabel` is required to be set for operator verbs (test `IAuditWriter_OperatorVerb_RecordsSystemOperatorLabel`) |
