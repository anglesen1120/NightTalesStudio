## Goal

A user can create, list, read, patch (with `If-Match`) and archive their own series. Invalid voice or style combinations are refused, and other users' series are invisible (404).

Handler rules:
- `CreateSeriesHandler`:
  1. Load the voice and the template through `IAppDbContext` (platform tables).
  2. Missing or inactive → `validation_failed` (field `voiceId` / `styleTemplateId`); language mismatch → `voice_language_mismatch`; `StyleTopicPolicy.IsAllowed(topic, template.TopicHint)` false (a `true_crime` series needs a `true_crime` template; fiction may not use one) → `validation_failed` field `styleTemplateId` (03 CR-2). `UpdateSeriesHandler` re-checks the policy when the topic or the template changes.
  3. `Series.Create(currentUser.Id!.Value, …, clock.UtcNow)`, then `db.Series.Add`.
  4. Return the id. [DECISION] `xmin` is assigned by PostgreSQL at commit, and the handler returns before UnitOfWork saves (D5), so the handler cannot know the ETag. The endpoint gets it with a post-commit read (`IReadDb`, `select xmin`) inside the `ToCreatedResult` etag delegate.
- `UpdateSeriesHandler`: load → `ETags.Matches(cmd.IfMatch, ETags.Series(s.Version))` or return `series_conflict` → `s.Update(...)` → the new ETag comes from the same post-commit read in the endpoint.
- `ListSeriesHandler`: keyset `WHERE (created_at, id) < (@c, @i) ORDER BY created_at DESC, id DESC LIMIT @limit + 1`; `nextCursor` comes from the extra row.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Same title twice | allowed (no uniqueness) |
| Voice deactivated after series creation | existing series keep it; a PATCH to another inactive voice is refused |
| `limit` > 100 | 400 `validation_failed` (field `limit`) |
| Concurrent PATCHes with the same ETag | one wins; the other gets 412 (check) or 409 `concurrency_conflict` (race after the check) |
