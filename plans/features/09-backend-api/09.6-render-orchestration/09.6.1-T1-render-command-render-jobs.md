### Migration + EF configuration

Migration `<ts>_09_RenderJobs` (D9 `<yyyyMMddHHmm>_09_RenderJobs`, expand-only) creates `render_jobs` from 00 §6 L287 + W2 CR-1 (`stage`, `percent`, `submitted_at`, `next_poll_at`, `cancel_requested_at`, `images_needed`) + `reservation_id uuid NOT NULL` (the `ReserveAsync` result; NOT NULL is safe because the table is created empty) [RULED — README §B10 WT50]:

```csharp
// src/NightTales.Infrastructure/Persistence/Configurations/RenderJobConfiguration.cs
public sealed class RenderJobConfiguration : IEntityTypeConfiguration<RenderJob>
{
    public void Configure(EntityTypeBuilder<RenderJob> b)
    {
        b.ToTable("render_jobs");
        b.HasKey(x => x.Id);
        b.Property(x => x.Id).ValueGeneratedNever();                     // UUIDv7 (D8)
        b.Property(x => x.Status).HasConversion<string>().HasMaxLength(16)
            .HasEnumCheck<RenderJobStatus>("status");                    // D8 snake_case + CHECK
        b.Property(x => x.Stage).HasMaxLength(32).IsRequired();
        b.Property(x => x.Percent).HasColumnType("smallint");
        b.Property(x => x.ErrorCode).HasMaxLength(64);
        b.Property(x => x.ErrorMessage).HasMaxLength(2000);               // safe text, never content
        b.Property(x => x.ReservationId).IsRequired();                   // uuid NOT NULL: the ReserveAsync result [RULED — README §B10 WT50]
        b.Property(x => x.Params).HasColumnType("jsonb");                       // render-params.v1 (05 D11)
        b.Property(x => x.QualityReport).HasColumnType("jsonb");                // render-quality.v1 (05 D10)
        b.Property(x => x.Version).IsRowVersion();                        // xmin (N8)
        b.HasIndex(x => new { x.Status, x.NextPollAt })
            .HasFilter("status IN ('submitted','running')");              // BD5 poller index
        b.HasIndex(x => x.EpisodeId).IsUnique()
            .HasFilter("status IN ('queued','submitted','running','ingesting')"); // one active render
        b.HasIndex(x => new { x.UserId, x.EpisodeId });                   // tenant-scoped lookups
        // No created_at index: render_jobs has no created_at column; "latest job" reads order by the primary key `id DESC`
        // (UUIDv7) and no created_at index is claimed [RULED — README §B10 WT49].
        b.HasQueryFilter("tenant", x => x.UserId == _currentUserId);       // D10 named filter
    }
}
```

`params`/`quality_report` mapping is the ⚠️ N9 choice: EF complex type with `ToJson()` where Npgsql supports it, otherwise `string` + `HasColumnType("jsonb")` with an explicit serializer (D8; decision recorded by 09.2.1-T1's spike). Either way the column is `jsonb` and the JSON is exactly `render-params.v1` / `render-quality.v1`.

### `IRecentMusicQuery` implementation (for 05.3.2-T3)

```csharp
// src/NightTales.Infrastructure/Rendering/RecentMusicQuery.cs
internal sealed class RecentMusicQuery : IRecentMusicQuery
{
    private readonly IReadDb _db;
    public async Task<IReadOnlyList<string>> GetRecentTrackIdsAsync(Guid seriesId, int take, CancellationToken ct) =>
        await (from r in _db.Query<RenderJob>()                       // no tracking (IReadDb, D8)
               join e in _db.Query<Episode>() on r.EpisodeId equals e.Id
               where e.SeriesId == seriesId && r.Params.Music != null
               orderby r.Id descending                                // UUIDv7 ⇒ creation order
               select r.Params.Music!.TrackId).Take(take).ToListAsync(ct);
}
```

- Contract: the last 3 non-null `params->'music'->>'track_id'` of the series, newest first (05.3.2-T3 L61–67).
- `series_id` is **not** a `render_jobs` column (00 §6 L287) → the join through `episodes.SeriesId` is required; `take` = 3 comes from `MusicSelector`.
- Newest-first uses `id DESC`, because UUIDv7 is time-ordered (D8) and `render_jobs` has no `created_at` column — and **no `created_at` index is claimed** ([RULED — README §B10 WT49]; the plan §10 note is thereby closed).
- DI: replace the M1 registration of `NullRecentMusicQuery` with `RecentMusicQuery` (05.3.2-T3 L83/L106); the unused null type is deleted (Session 44: nothing referenced it, the tests use their own recording fakes). Tenant filter applies (the caller is the authenticated user's scope), so no `IgnoreQueryFilters`.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| `approved_story_version_id` is null (reopen race) | step 1 fails with 409 `episode_invalid_state`; `IStoryRenderInputProvider` is never called (02.3.2-T1 L115) |
| Two concurrent requests with the same key | the second blocks on `idempotency_keys`' unique index, then replays the stored response (D6) |
| Two concurrent requests, different keys, same episode | the partial unique index rejects the second insert → `DbUpdateConcurrencyException` → 409 `concurrency_conflict` (D5) |
| Advisory lock timeout in step 7 | 429 `spend_cap_reached` only when the guard refuses; a lock timeout surfaces as 409 `concurrency_conflict`, never a 500 |
| `MusicSelector` returns null | `params.music = null` (05 D11); the render proceeds and the evaluator later adds the `music_none` hint |
| Reserve succeeds, insert fails | single transaction (D5) → both roll back; no orphan reservation |
| Price catalogue has no `price_versions` row | 429 `spend_cap_reached` is wrong here — the estimator returns an error mapped to 503 `service_unavailable` (fail closed, no render) |
| Rollback | drop the endpoint group + handler registration; the migration leaves an inert table; no other feature reads `render_jobs` yet |

### Delivery notes (Session 44)

1. `RenderJob.Create` takes the id first. The handler generates `Guid.CreateVersion7()` before `ReserveAsync`, so the ledger `referenceId` and the `render_jobs` row share it (Acceptance 7).
2. `keywords_flagged` `errors[]` is implemented here (Acceptance 6). The wire uses `Errors.KeywordsFlagged` / `Errors.NoScenes`; `ProblemBody.Errors` is `JsonElement?` with a 100-row cap. `no_scenes` row: `{segment:"meta", index:0, rule:"no_scenes"}`. Keyword violations use the rule `keyword_invalid`.
3. `no_scenes` fires on `plan.Terms.Count == 0`. The task's `MaxTerms == 0` case is unreachable: `RenderImagePlanner` never returns `MaxTerms` 0.
4. Price catalogue error → 503 `service_unavailable` (fail closed).
5. Check order: 404 → 409 state → 412 If-Match, with the episode row lock taken first.
6. Reserve bound = `UsageBound(worstCaseUsd, plan.MaxTerms * tokens, images.PlaceholderTokensPerImage)`.
7. `quality_report` is plain jsonb. `RenderJob.UpdateProgress` rejects a decreasing or out-of-range percent. `Fail` accepts only the ten D5 codes.
8. `RecentMusicQuery` SQL adds `AND r.params->'music'->>'track_id' IS NOT NULL`, because a jsonb `null` music is not SQL NULL. This amends the 05.3.2-T3 SQL.
9. FK `story_version` is CASCADE. A missing style template → 409 `episode_invalid_state` (an inactive template still renders). No `LockSeriesForShareAsync`, no archived-series gate.
