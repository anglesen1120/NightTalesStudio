## 3. Domain and data

**Aggregate (BD5, exact names).** `RenderJob : AggregateRoot, IUserOwned` in `src/NightTales.Domain/Rendering/RenderJob.cs`:

- `Create(Guid userId, Guid episodeId, Guid storyVersionId, Guid reservationId, RenderParamsV1 @params, int attempt, DateTimeOffset now) → ErrorOr<RenderJob>` (status `queued`, `stage = "queued"`, `percent = 0`); `ReservationId` is `NOT NULL` and stores the `ReserveAsync` result [RULED — README §B10 WT50].
- `MarkSubmitted(string adapterTaskId, Guid nodeId, DateTimeOffset now)` — `queued → submitted`, sets `submitted_at` (BD7 sets `next_poll_at = now + 10 s`).
- `UpdateProgress(string stage, short percent, DateTimeOffset now)` — `submitted/running`, **never decreasing** percent, no-op when unchanged (BD7 pushes `RenderProgress` only on change).
- `MarkIngesting(DateTimeOffset now)`, `Succeed(DateTimeOffset now)`, `Fail(string code, DateTimeOffset now)`, `RequestCancel(DateTimeOffset now)`, `Cancel(DateTimeOffset now)`; transitions 00 §7 (L340).
- `RenderJobStatus { Queued, Submitted, Running, Ingesting, Succeeded, Failed, Cancelled }` [INFERENCE: enum name; values fixed by BD5's index predicate + 00 §7 L340], stored snake_case text with `HasEnumCheck<RenderJobStatus>("status")` (D8).

**Episode partial (owner 09.5.1).** `src/NightTales.Domain/Episodes/Episode.Render.cs`: `RequestRender(DateTimeOffset now)` (`story_approved → rendering`), `RenderFailed(DateTimeOffset now)` (`rendering → story_approved`, used by failure, timeout and cancel), `RenderSucceeded(DateTimeOffset now)` (`rendering → video_review`) [INFERENCE: the last two names — `RenderFailed` is the name 03.4.2-T1 already calls; 09.5.1 keeps `Episode.cs`].

**Migration `<ts>_09_RenderJobs`** (D9 naming; expand-only, apply before the Worker rollout): 00 §6 L287 columns + the W2 CR-1 additions + `reservation_id uuid NOT NULL` (`ReserveAsync` result — safe to add NOT NULL because the table is created empty here) [RULED — README §B10 WT50], plus:

- no `created_at` index is added — WT49: latest-job reads order by `id DESC` (UUIDv7) and no `created_at` index is claimed [RULED — README §B10 WT49];
- index `(status, next_poll_at) WHERE status IN ('submitted','running')` — the poller's claim predicate (BD5);
- unique partial index `(episode_id) WHERE status IN ('queued','submitted','running','ingesting')` — one active render per episode; a retry row (`attempt + 1`) is allowed because the previous row is `failed`;
- tenant filter through `IUserOwned` (D10) — `render_jobs` is in the D10 allow-list for `IgnoreQueryFilters` only in `Application/Features/Admin/**`;
- `params`/`quality_report` as `jsonb` (EF complex type with `ToJson()` where Npgsql supports it, ⚠️ N9 spike 09.2.1-T1; fallback `string` + `HasColumnType("jsonb")`, D8).

**Bounds.** Script length ≤ 20,000 code points, checked on the NFC-normalised text (BD5; 05 CR-3) → `validation_failed` field `script`. `images_needed` comes from `params.image_plan.needed` (03.4.2-T1) so the ingest needs no extra read.

## 5. API and events

**`POST /api/v1/episodes/{id}/render`** — filters `RequireIdempotencyKey()` (400 `idempotency_key_required`) + `RequireIfMatch()` (428 `if_match_required`); ETag `"ep-<episodes.xmin>"` (D15), mismatch → 412 `episode_conflict`; command `RenderEpisodeCommand(Guid EpisodeId, string? IfMatch, string IdempotencyKey)`; 202 via `ToAcceptedResult(location)` with `Location: /render-jobs/{id}`; idempotent replay returns the stored response (D6), a different body under the same key → 422 `idempotency_key_reused`.

| Condition | Code / status |
|---|---|
| episode not `story_approved` | 409 `episode_invalid_state` |
| script > 20,000 code points | 400 `validation_failed`, field `script` |
| linter blocking issue / zero planned terms | 409 `keywords_flagged`, `errors[] { segment, index, rule }` (`rule = no_scenes` when the plan is empty) |
| budget guard | 429 `spend_cap_reached` (02 D1) with `Retry-After` (02 CR-20) |
| no node capacity (Worker side) | `render_worker_unavailable` — metric + reschedule, never this endpoint's response [OPEN] |

**`DELETE /api/v1/render-jobs/{id}`** — `CancelRenderCommand(Guid RenderJobId)`; 204 on cancel, 409 `episode_invalid_state` while `ingesting`, 404 `not_found` for another user's job (D10), 409 `concurrency_conflict` on a lost `xmin` race.

**Outbox / realtime.** `RenderRequested { RenderJobId, EpisodeId, UserId }` → `render_requested.v1` (09.6.1-T1); `RenderSucceeded { EpisodeId, RenderJobId }` → `render_succeeded.v1` (02 CR-23, 09.6.3-T2); `RenderFailed { EpisodeId, RenderJobId, ErrorCode, Attempt, Final }` → `render_failed.v1`, raised by 09.6.3-T1/T2 when a job ends `failed` and `Final = true` means no automatic retry follows [RULED — README §B10 WT28]; `video_rejected.v1` with `Target = re_render` is consumed by the Worker's `VideoReRenderHandler`, which sends `RenderEpisodeCommand` with idempotency key `video-reject-rerender:{messageId}` **outside** the reject transaction [RULED — README §B10 WT3]; realtime `RenderProgress` is `RealtimeEvent(RealtimeEventName.RenderProgress, RealtimeIds(episodeId, renderJobId), RealtimeData(Stage, Percent))` through `IRealtimeNotifier.NotifyAsync(userId, e, ct)` inside the poller's transaction, only when stage/percent changed, and `RealtimeData` carries **only** `stage` (enum) and `percent` (0–100) with the NOTIFY body ≤ 8 KB [RULED — README §B10 WT54].

## 8. Security and privacy

- **Least privilege / tenancy:** every `render_jobs` read is the D10 tenant filter; another user's job answers 404 `not_found` (never 403); `IgnoreQueryFilters(["tenant"])` is allowed only in `Application/Features/Admin/**`; the poller uses `ISystemContext.For(userId)` with ids-only jobs (D10, D12).
- **Secrets:** the node `x-api-key` lives in `worker_nodes.api_key_ciphertext` (11.3.3-T1) and is injected per request by `RenderNodeConnectionFactory`; it is never logged, never in an exception message, never in a job argument; TLS is validated against `worker_nodes.tls_cert_sha256`.
- **Data minimisation:** `render_jobs.params` holds counts/hashes/settings only (05 D11, 09 §4 L181–184) — never `video_script`, `video_terms` or prompts; Hangfire arguments are ids only (D12); `Error` descriptions are fixed sentences without content (D7, 05 D4 S4); logs carry hashed `userId`, `episodeId` and codes (BD16, 11.6.2-T1 L40).
- **Integrity:** downloads are streamed with incremental SHA-256 and compared with `output.video.sha256`, redirects disabled, size/type caps enforced → `render_output_invalid`; the download URL is built from the registered `base_url` + `adapter_task_id`, never from a response body (09 §4 L196).
- **Rate/size:** submit bodies ≤ 2 MiB at the adapter (05 D4 S2); the API's `MaxRequestBodySize` stays 1 MiB (BD12); the render route is on the `paid` rate-limit policy (BD14).
- **Retention:** temp files are removed in `finally`; the adapter `DELETE` removes the node task dir after commit (03 D12); secrets never appear in the `assets`/`quality_report` payloads.
