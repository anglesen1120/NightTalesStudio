## Goal

Any feature that has just committed a change can push it to the owner's open page: `IRealtimeNotifier.NotifyAsync(userId, event, ct)` writes `pg_notify('realtime', <ids-only JSON ≤ 8 KB>)` inside the caller's transaction; one `RealtimeListenerService` per Api instance `LISTEN`s and forwards each message to that instance's local sockets in group `user:{id}`. The hub accepts WebSockets only and never carries the JWT in a URL.

`PgNotifyRealtimeNotifier` — one SQL round trip, ambient transaction, no writes:

```csharp
public sealed class PgNotifyRealtimeNotifier(AppDbContext db) : IRealtimeNotifier
{
    public const int MaxPayloadBytes = 8_000;             // BD11/BD16
    public async Task NotifyAsync(Guid userId, RealtimeEvent e, CancellationToken ct)
    {
        var json = JsonSerializer.Serialize(new { userId, @event = e.Name.ToWireName(), ids = e.Ids, data = e.Data }, JsonOptions);
        if (Encoding.UTF8.GetByteCount(json) > MaxPayloadBytes)
        { Metrics.RealtimeNotifyDropped.Add(1, new("event", e.Name.ToWireName())); return; }   // drop, never truncate
        await db.Database.ExecuteSqlRawAsync("SELECT pg_notify('realtime', {0})", [json], ct);
    }
}
```

[DECISION] `ExecuteSqlRawAsync` on the caller's `AppDbContext` joins the transaction opened by `UnitOfWorkBehavior` (D5), so PostgreSQL delivers **at commit** and discards on rollback; with no ambient transaction (an outbox handler, D11) delivery is immediate. The notifier never opens a transaction, never calls `SaveChanges`, and never writes a row.

`EpisodeHub` — group from the principal only:

```csharp
[Authorize(AuthenticationSchemes = "HubTicket")]
public sealed class EpisodeHub(RealtimeConnectionRegistry registry) : Hub
{
    public override async Task OnConnectedAsync()
    {
        var userId = Context.UserIdentifier
            ?? throw new HubException("hub connection without a subject");       // never a client-supplied group
        await Groups.AddToGroupAsync(Context.ConnectionId, RealtimeGroups.User(userId));
        registry.Add(userId, Context);
        await base.OnConnectedAsync();
    }
    public override Task OnDisconnectedAsync(Exception? e)
    { registry.Remove(Context.ConnectionId); return base.OnDisconnectedAsync(e); }
}
public static class RealtimeGroups { public static string User(Guid id) => $"user:{id}"; }
```

Mapping: `app.MapHub<EpisodeHub>("/hubs/episodes")` with `HttpTransportType.WebSockets` only (client `skipNegotiation`, BD11 ✅); `AddSignalR()` in the Api composition root only; no sticky session is required, a WebSockets-capable load balancer is assumed (11.2.2-T3).

`HubTicketAuthenticationHandler : AuthenticationHandler<AuthenticationSchemeOptions>` (scheme `HubTicket`): reads `ticket` from the query string, calls `IHubTicketValidator.ClaimAsync`, and on success builds a principal with `sub` (and the role/stamp it reads live) — a missing/expired/used/tampered ticket and a missing validator registration all end in `401 hub_ticket_invalid` (or a fail-fast throw for the unregistered-validator case, below). The handler never logs the ticket value.

**Seam with 09.8.1-T2 [DECISION].** This task depends on 09.8.1-T2 *for its table* but B8.1 orders T1 first, so: T1 ships the hub, the scheme, the port and the notifier; the **production** `IHubTicketValidator` registration (`NpgsqlHubTicketValidator`) is added by 09.8.1-T2 together with `hub_tickets`. Until T2 lands a connect attempt fails fast with an explicit `InvalidOperationException("IHubTicketValidator is not registered")` — **no permissive fallback and no production stub**; T1's integration tests register `FakeHubTicketValidator` (hand-written, `NightTales.TestKit`, D13) so group joins and fan-out are testable in isolation.

`RealtimeListenerService : BackgroundService` (Api) — one connection per instance, two channels:

```csharp
// own long-lived Npgsql connection; never an EF DbContext
await conn.ExecuteAsync("LISTEN realtime; LISTEN security;");
while (!ct.IsCancellationRequested)
{
    var note = await conn.WaitAsync(TimeSpan.FromSeconds(30), ct);       // heartbeat, no busy loop
    if (note is null) { await BackstopAsync(ct); continue; }             // 60 s stamp/status/token-expiry sweep
    if (note.Channel == "realtime") await hub.Clients.Group(RealtimeGroups.User(note.UserId))
                                        .SendAsync(note.EventName, note.Payload, ct);
    else                            registry.AbortUser(note.UserId);      // channel "security": user id only
}
```

- Backoff on a dropped connection: `1, 2, 4, 8, 16, 30` s (`Realtime:ListenerBackoffSeconds`, BD11 ✅), then a reconnect; on reconnect nothing is replayed — clients refetch (BD11 ✅).
- [DECISION] the listener re-checks that a `realtime` message's `userId` equals the group it targets (defence in depth), and it ignores an unknown `event` name with a warning instead of forwarding it.
- Backstop every `Realtime:RevalidateSeconds` (60): `Abort()` a connection once `Hubs:MaxConnectionMinutes` for its **role** has elapsed (owner/admin 5, user 15) — **no stamp/status cache is read in P** ([RULED — README §B10 WT37]).
- `RealtimeConnectionRegistry` — in-memory `userId → (connectionId, HubCallerContext, connectedAt, maxConnectionMinutes)`; `maxConnectionMinutes` is the **role's** cap (`Hubs:MaxConnectionMinutes`: owner/admin 5, user 15 — WT37); `AbortUser(userId)` aborts only that user's connections **on this instance** (open item 7); entries are removed on disconnect (no leak).

Config and metrics: see plan §7 (`Realtime:TicketTtlSeconds`/`TicketCleanupRetentionHours` are 09.8.1-T2's keys, `ListenerBackoffSeconds`, `Hubs:MaxConnectionMinutes` (per role, WT37), `RevalidateSeconds`, `MaxPayloadBytes`); metrics `realtime_notify_total`, `realtime_notify_dropped_total`, `realtime_listener_reconnects_total`, `realtime_listener_messages_total`, `realtime_connections_active` [INFERENCE: names].

Producers (not this task): 02/06/09.6.3 call `IRealtimeNotifier` from a command or an outbox handler; `PollRenderJob` calls it for `RenderProgress` only when stage/percent changed (BD7 ✅) — always with the user id from their own `ICurrentUser`/`ISystemContext`, never a client-supplied id (D10).

## Acceptance checks

- [ ] `NotifyAsync` executes exactly one `SELECT pg_notify('realtime', …)` on the caller's `AppDbContext` and never `SaveChanges`/`BEGIN`.
- [ ] The payload contains `userId`, `event`, `ids` and — for `RenderProgress` **only** — `data` with `stage` + `percent` (0–100) and no other member ([RULED — README §B10 WT54]); a synthetic payload over 8,000 bytes is dropped and counted (`realtime_notify_dropped_total`), never truncated, and no error propagates to the caller's command.
- [ ] `NotifyAsync` inside a rolled-back command transaction delivers **nothing** to a listening connection; inside a committed one it delivers exactly once.
- [ ] `/hubs/episodes` accepts WebSockets only; a non-WebSocket transport is rejected; a client cannot join a group other than `user:{sub}`.
- [ ] A connection with a valid ticket joins `user:{id}`; the same event raised for another user is not delivered to it.
- [ ] A missing/expired/used ticket → `401 hub_ticket_invalid`; an unregistered `IHubTicketValidator` fails fast with an explicit error (no permissive fallback).
- [ ] The listener holds **one** connection per Api instance, listening on `realtime` **and** `security`; a dropped connection reconnects with 1, 2, 4, 8, 16, 30 s backoff and forwards nothing during the outage.
- [ ] A `security` message aborts only that user's connections on the receiving instance; the backstop closes a connection once `Hubs:MaxConnectionMinutes` for its **role** has elapsed (owner/admin 5, user 15) and reads **no** stamp/status cache ([RULED — README §B10 WT37]).
- [ ] No log line, metric label or exception message contains the ticket, the hash, the connection string or any token; the access log has no `ticket` query parameter.
- [ ] `RealtimeProgress` producers can build the event without referencing Infrastructure (Application-only types); the arch test still passes.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| PostgreSQL down when a producer notifies | The exception propagates inside the caller's transaction → the command fails and rolls back (D5) — a change is never committed without its notification |
| Payload > 8 KB | Dropped + `realtime_notify_dropped_total` + one error log (with the event name, no ids) — never truncated, never an exception to the caller |
| Listener connection dropped / DB restarted | Backoff 1→30 s, `realtime_listener_reconnects_total`, one warning per attempt; clients refetch on their own reconnect |
| `IHubTicketValidator` not registered (T1 before T2) | Connect fails fast with `InvalidOperationException("IHubTicketValidator is not registered — delivered by 09.8.1-T2")`; never an anonymous or permissive connect |
| Ticket replayed after use | The claim returns 0 rows → `401 hub_ticket_invalid` (09.8.1-T2) |
| Client sends a stale/expired access token | Nothing happens here: the ticket, not the token, authenticates the socket; the backstop closes the connection at `Hubs:MaxConnectionMinutes` for the connection's **role** (owner/admin 5, user 15) — [RULED — README §B10 WT37] |
| Access revoked elsewhere (family revocation) | every revocation sends `NOTIFY security` (user id) → the receiving instance `AbortUser`s that user's live connections; no stamp cache is consulted in P (WT37) |
| `security` message arrives on an instance without that user's socket | No-op on that instance; the owning instance aborts its own connection (open item 7) |
| Unknown event name in a `realtime` message | Ignored + warning; the client never receives an unsubscribed method |
| Two instances both `LISTEN` | Both receive the message; each forwards only to its own local group members, so no duplicate delivery to one socket |
| Slow socket / back-pressure | `SendAsync` is per-connection and non-blocking for the loop (SignalR buffers per connection); the loop never awaits a client beyond that call |
