## Goal

An admin searches/lists users, opens a detail bundle (profile, sessions, channels, balance, moderation/reports, admin audit trail) and acts on a user (suspend, unsuspend, revoke sessions, resend verification, force password reset, MFA reset, role change, delete) — the user-management half of the admin surface (D13 split from 09.9.1-T1's group/platform-ops half, F03).

## Inputs

- `../README.md` §C3 **D13** (this task owns `/admin/users*`; 09.9.1-T1 owns the group/policy/pagination it runs on), **D8** (role hierarchy: actor role strictly above target's else 404; `mfa/reset`/`role`/`delete` are `OwnerPolicy` + `IReauthGuard` and may time-lock via `owner_action_requests`), **D9** (`ISecurityEventWriter.RotateStampAsync` — the **one** writer for stamp rotation; this task calls it, never rotates the stamp itself).
- §C3.1 routes: `GET /admin/users`, `GET /admin/users/{id}`, `POST /admin/users/{id}/suspend|unsuspend|sessions/revoke|resend-verification|force-password-reset|mfa/reset|delete`, `PATCH /admin/users/{id}/role`.
- §C6 "`/admin/users`": keyset pagination on `(created_at, id)`, no `COUNT(*)` per row for `hasPayments` — one projection query with `EXISTS`/`LATERAL`.
- §C3.2 index: `users (status, role, created_at DESC, id)` (W3 CR-1) backs the keyset list.
- §C3.7 `Lead12`: `creditBalance` in the list/detail reads plan 12's `GetBalanceQuery { UserId }` (12.2.2-T1) — the **same** query, no second read port; §C3.7 `Lead13S`: `POST /admin/users/{id}/delete` reuses 13.3.2-T1's account-scope command (soft).
- Reused: `09.9.1-T1`'s `/api/v1/admin` group + `AdminPageDto<T>` + cursor codec; `09.3.2-T2`'s `ISecurityEventWriter.RotateStampAsync(userId, reason, ct)`; `09.10.4-T2`'s `owner_action_requests` + 202 `owner_action_pending` contract for `role`/`delete`/`mfa/reset`; `09.3.6-T2`'s activity actions (`account.suspended`/`account.role_changed` are user-visible, written by this task's handlers); `09.3.7-T1`'s session-revoke shape (`DELETE /me/sessions/{id}` pattern reused server-side for the admin "sessions/revoke" action).

## Design

```csharp
// Application/Features/Admin/Users/AdminListUsersQuery.cs
public sealed record AdminListUsersQuery(string? Query, string? Status, string? Role, bool? Verified,
    bool? HasPayments, string? Cursor, int Limit = 20) : IQuery<ErrorOr<AdminPageDto<AdminUserListItemDto>>>;
public sealed record AdminUserListItemDto(Guid Id, string Email, string? DisplayName, string Role, string Status,
    bool EmailConfirmed, bool MfaEnabled, DateTimeOffset CreatedAt, DateTimeOffset? LastLoginAt, decimal CreditBalance);

public sealed record AdminGetUserQuery(Guid UserId) : IQuery<ErrorOr<AdminUserDetailDto>>;
// AdminUserDetailDto: profile, verification, MFA on/off, last login, active-session summary (count, lastIp, userAgent),
// channels (platform + status, never tokens), series/episode counts, balance + recent ledger (12's read port),
// payments, refunds, moderation events, reports, admin audit trail for that user — §C3.1 verbatim field list.

[Audited("account.suspended", Category.AccountSecurity, Visibility.User)]
public sealed record AdminSuspendUserCommand(Guid UserId, string Reason) : ICommand<ErrorOr<AdminActionResult>>;
[Audited("account.unsuspended", Category.AccountSecurity, Visibility.User)]
public sealed record AdminUnsuspendUserCommand(Guid UserId, string Reason) : ICommand<ErrorOr<AdminActionResult>>;
[Audited("account.session_revoked", Category.AccountSecurity, Visibility.User)]   // params { device: "all", via: "admin" }
public sealed record AdminRevokeUserSessionsCommand(Guid UserId, string Reason) : ICommand<ErrorOr<AdminActionResult>>;
[Audited("support.action_taken", Category.Support, Visibility.User)]   // §C3.4's generic row: { action, reason }, actorLabel "Support team"
public sealed record AdminResendVerificationCommand(Guid UserId, string Reason) : ICommand<ErrorOr<AdminActionResult>>;
[Audited("support.action_taken", Category.Support, Visibility.User)]
public sealed record AdminForcePasswordResetCommand(Guid UserId, string Reason) : ICommand<ErrorOr<AdminActionResult>>;
public sealed record AdminActionResult(bool Applied, Guid? OwnerActionRequestId);

// mfa/reset, role, delete need OwnerPolicy + IReauthGuard and may time-lock:
public sealed record AdminMfaResetCommand(Guid UserId, string Reason) : ICommand<ErrorOr<AdminActionResult>>;
public sealed record AdminChangeRoleCommand(Guid UserId, string NewRole, string Reason) : ICommand<ErrorOr<AdminActionResult>>;
public sealed record AdminDeleteUserCommand(Guid UserId, string Reason) : ICommand<ErrorOr<AdminActionResult>>;
```

Handler rules:
- **List:** `IReadDb.Query<User>().IgnoreQueryFilters(["tenant"])`, filters on `Status`/`Role`/`Verified`/free-text `Query` (email/display-name `ILIKE`), keyset on `(created_at DESC, id)` (W3 CR-1 index), `hasPayments` via `EXISTS (SELECT 1 FROM payments WHERE user_id = u.id)` in the projection (no per-row subquery cost beyond the plan, §C6 fix), `creditBalance` via one batched call to `GetBalanceQuery` per page (not per row) — a single `WHERE user_id = ANY(@ids)` variant of 12's read port, or `Task.WhenAll` over the page if 12 exposes only a single-id overload [OPEN: confirm with `Lead12` whether a batched overload exists; falls back to N calls bounded by page size ≤ 100].
- **Detail:** role-above-target check first (actor role strictly higher, else 404, D8); assembles the bundle from existing read ports only — no new query logic duplicating `09.3.7-T1` (sessions), `09.3.6-T2` (activity, not shown here — this is the admin's own trail from `audit_logs` filtered `subject_user_id = @id`).
- **Suspend:** revokes every `refresh_tokens` family (calls `09.3.7-T1`'s revoke-all path server-side, not the user route), `ISecurityEventWriter.RotateStampAsync(userId, "admin_suspend", ct)` (stamp + `UserSecurityChanged` + SignalR abort, one call — D9), cancels queued render jobs with refund (`09.6.4-T1`'s `CancelRenderCommand` per active job, `ISystemContext.For(userId)`), pauses scheduled publications (06's domain method, soft dependency) — all in one transaction; writes the **single** `account.suspended` audit row (§C3.4 — `audit_logs.action` is the one wire `messageKey`, W3-TL2; no separate internal row).
- **Unsuspend / sessions_revoke:** thin calls into the existing owning handler under `ISystemContext.For(userId)`, each writing its own frozen §C3.4 action (`account.unsuspended`, `account.session_revoked` with `via = admin`).
- **resend_verification / force_password_reset:** thin calls into `09.3.1-T3`'s verification-token minter / `09.3.3-T1`'s password-reset minter respectively — this task never re-implements either minter. §C3.4 has no dedicated action for these two admin verbs, so both use the generic frozen `support.action_taken` row (`{ action: "resend_verification"|"force_password_reset", reason }`, `actorLabel = "Support team"`) — the only §C3.4 row built for exactly this case.
- **mfa/reset, role, delete:** `OwnerPolicy` + `IReauthGuard.RequireRecentAsync(5 min)`; role-above-target check (D8, `RoleHierarchy.ActorOutranks` extended by 09 W3 CR-22 to admit owner→owner `mfa_reset`/`demote`/`suspend`). For a target who is **not** an owner, the actor already outranks them and the handler applies the change directly (HL:272 — owners act on admins/users with no time-lock). For an **owner** target (`mfa/reset`, a `role` PATCH that demotes, `suspend`), or whenever the action is `promote` (any target), this handler **always** calls `IOwnerActionRequester.RequestAsync(...)` and returns 202 `owner_action_pending` with the request id — it **never** applies inline, regardless of the requester's own re-auth recency or tenure; the only path to an immediate apply is a **different**, qualifying owner calling **09.10.4-T2**'s `ApproveOwnerActionCommand`. `delete` calls 13.3.2-T1's account-scope command (soft) for a non-owner target; an owner-on-owner `delete` is never created (400/404, D8). The last active owner cannot be demoted/suspended/deleted → 409 `last_owner` (D8), checked before any write.

## Acceptance checks

- Given an admin, When it calls `GET /admin/users?status=active&cursor=`, Then the response is keyset-paginated, `creditBalance` is populated via 12's `GetBalanceQuery` and the query plan shows no per-row `COUNT(*)`.
- Given an admin acting on a user with an equal or higher role, When any action route is called, Then the response is 404 `not_found` (D8), before any state change.
- Given an admin, When it calls `POST /admin/users/{id}/suspend`, Then within the same transaction: every `refresh_tokens` family for that user is revoked, `UserSecurityChanged` is raised exactly once, all that user's active SignalR connections are aborted, all queued render jobs are cancelled with exactly one refund each, and exactly one `account.suspended` audit row exists.
- Given the last active owner, When `PATCH /admin/users/{id}/role` or `.../delete` targets them, Then the response is 409 `last_owner` and nothing is written.
- Given an owner without a recent re-auth, When it calls `.../mfa/reset`, Then the response is 401 `reauth_required`.
- Given a re-auth'd owner promoted more than 30 days ago (eligible by tenure), When they call `PATCH .../role` to promote a user, Then the response is 202 `owner_action_pending` with a new `owner_action_requests` row in `pending` state and `users.role` is **unchanged** — the requester's own eligibility never applies a `promote`/owner-target action inline; only a different owner's approval via 09.10.4-T2 does.

## Failure handling and edge cases

| Case | Handling |
|---|---|
| Suspend called twice on an already-suspended user | Idempotent: 200/204, no second `UserSecurityChanged`, no double refund (guarded by job status, mirrors `09.6.4-T1`'s idempotency) |
| `role` change to the same role | 200 no-op, `account.role_changed` audit row still written only if the role actually differs (else skipped) |
| `mfa/reset` on a user with no MFA enrolled | 409 `episode_invalid_state`-shaped equivalent — [INFERENCE] a dedicated `mfa_not_enrolled` 409, since §C3.1 does not list a specific code for this branch |
| `GetBalanceQuery` unavailable (12's service down) | List/detail still return with `creditBalance: null` and a partial-data flag — never fail the whole admin page for a billing read [INFERENCE, no code specifies fallback] |
| Delete request racing an in-flight suspend for the same user | Both originate distinct `owner_action_requests`/actions; 09.10.4-T2's serializable apply-time re-check (D8) is the single source of truth, not this task |
