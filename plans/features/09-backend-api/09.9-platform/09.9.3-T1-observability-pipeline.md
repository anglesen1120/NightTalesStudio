# 09.9.3-T1 — Serilog + OpenTelemetry (Npgsql instrumentation, no EF instrumentation) + health + custom metrics

## Goal

Every Api request and every Worker job is diagnosable from one trace: Serilog emits compact JSON to stdout and forwards to OTLP, OpenTelemetry traces/metrics cover ASP.NET Core, HttpClient and PostgreSQL (via `Npgsql.OpenTelemetry`), Hangfire jobs produce spans, `/health/live` and `/health/ready` answer orchestrators, and the five custom metrics frozen for 11.6.2-T1 are exported. A secret or a piece of story text never appears in a log or a span.

## Design

### Packages (additive only)

`Directory.Packages.props`: `Serilog.Sinks.OpenTelemetry` **4.2.0**, `Serilog.Formatting.Compact` **3.0.0** (W4); `OpenTelemetry.Extensions.Hosting` **1.19.1**, `OpenTelemetry.Exporter.OpenTelemetryProtocol` **1.19.1**, `OpenTelemetry.Instrumentation.AspNetCore` **1.19.0**, `OpenTelemetry.Instrumentation.Http` **1.19.0** (W2); `Npgsql.OpenTelemetry` **10.0.3** (W3). **No** `OpenTelemetry.Instrumentation.EntityFrameworkCore` (WF09) — asserted by a test so a later dependency bump cannot sneak it in.

### Shared wiring, used by Api **and** Worker

```csharp
// Infrastructure/Telemetry/TelemetryRegistration.cs   [INFERENCE: file/type names]
public static class TelemetryRegistration
{
    public static IHostApplicationBuilder AddNtsTelemetry(this IHostApplicationBuilder b, string serviceName);
    // Serilog:  CompactJsonFormatter to stdout (W4) + WriteTo.OpenTelemetry (endpoint, protocol, resource attributes)
    // OTel:     AddOpenTelemetry()
    //             .ConfigureResource(r => r.AddService(serviceName, serviceVersion: InformationalVersion)
    //                                      .AddAttributes(new { deployment.environment = env, instance = host+pid }))
    //             .WithTracing(t => t.SetSampler(new ParentBasedSampler(new TraceIdRatioBasedSampler(ratio)))
    //                                .AddAspNetCoreInstrumentation()
    //                                .AddHttpClientInstrumentation()
    //                                .AddNpgsql()                       // W3 — DB spans, no EF package (WF09)
    //                                .AddSource(JobTelemetry.ActivitySourceName))
    //             .WithMetrics(m => m.AddAspNetCoreInstrumentation().AddHttpClientInstrumentation()
    //                                .AddMeter(NightTalesMetrics.MeterName))
    //             .UseOtlpExporter();                                // 11 D17 collector
}
```

`Program.cs` (Api) and the Worker host both call `AddNtsTelemetry("nts-api" | "nts-worker")`. Bootstrap logger: file-less, console JSON, so a startup crash before DI is still a JSON line.

### Log enrichment

- `UseSerilogRequestLogging` with `EnrichDiagnosticContext`: `route` (endpoint template, not the raw path), `statusCode`, `durationMs`, `episodeId` (route value when present), `traceId`/`spanId` from `Activity.Current`.
- `UserHashEnricher` **[INFERENCE]** adds `userId` = base64url(`HMACSHA256(Logging:UserHashSalt, sub)`) truncated to 16 chars — stable across instances for correlation, not reversible, never the raw id or the e-mail. The salt is a secret (`nts/<env>/shared/LOG_SALT`); a missing salt is a **startup failure** in every environment except `Development` (where a fixed dev value is used and a warning is logged).
- The Api never configures `LoggingBehavior` here (D4 owns it); this task only makes its `traceId` land in the same trace.
- Story text, secrets and tokens stay out by rule: 09.9.3-T2 owns the redaction set; `SecretString` masking belongs to the settings store, whose phase-S task is dropped by DEC 10.14.

### Health endpoints

```csharp
// Api/Endpoints/HealthEndpoints.cs  [INFERENCE: type name] — IEndpointGroup (D14), mapped by discovery
services.AddHealthChecks()
    .AddCheck<AppDbContextHealthCheck>("db", tags: ["ready", "db"], failureStatus: HealthStatus.Unhealthy)
    .AddCheck<BlobStoreHealthCheck>("storage", tags: ["ready", "storage"], failureStatus: HealthStatus.Degraded)
    .AddCheck<NodeRegistryHealthCheck>("nodes", tags: ["ready", "nodes"], failureStatus: HealthStatus.Degraded);
```

| Route | Auth | 200 | 503 | Notes |
|---|---|---|---|---|
| `GET /health/live` | anonymous | always | — | token liveness only; no dependency touched |
| `GET /health/ready` | anonymous | `Healthy`, or `Degraded` when only storage/nodes fail | database unreachable | `Cache-Control: no-store`, `HealthReport` JSON |

- `AppDbContextHealthCheck` = `AppDbContext.Database.CanConnectAsync` with a 5 s timeout.
- `BlobStoreHealthCheck` = `IBlobStore.ExistsAsync(bucket, Storage:HealthMarkerKey, ct)` — a cached assets job result, **never** a per-request hashing or listing operation.
- `NodeRegistryHealthCheck` = `INodeHealthCache` only (no HTTP to a node): at least one node `active`.
- Bodies carry check name + status + duration; no exception text, no connection string, no host name. **[DECISION 09.9-D2]** (from `plan.md`): only the DB is a hard failure.

### Metrics

`Application/Telemetry/NightTalesMetrics.cs` **[INFERENCE: class name]** — one `Meter` named `NightTales` **[INFERENCE]**, instruments created once, registered as a singleton and injected by 02/03/06/09.6.3 (they never reference the OTel SDK).

| Metric | Type / unit | Tags | Recorded by |
|---|---|---|---|
| `render_jobs_active` | `ObservableGauge<long>` / `{job}` | — | Worker refresh loop |
| `render_duration_seconds` | `Histogram<double>` / `s` | `stage`, `outcome` | 09.6.3-T1/T2, 03/05 stages |
| `openai_cost_usd_total` | `Counter<double>` / `USD` | `operation` | 02 (story), 03 (image) usage writers |
| `youtube_quota_used` | `ObservableGauge<double>` / `1` (0..1) | — | 06 quota reader |
| `outbox_lag_seconds` | `ObservableGauge<double>` / `s` | — | `OutboxDispatcher` (D11) |
| `outbox_dead_letters_total` | `Counter<long>` / `{message}` | — | `OutboxDispatcher` (D11) |

`RenderMetricsRefresher` **[INFERENCE name]** (Worker `BackgroundService`, 30 s tick, `pg_try_advisory_lock(hashtext('render_metrics'))`): counts `render_jobs` in `queued|submitted|running|ingesting` and calls `ResetRenderJobsActive`. The count is a platform-wide read issued by `RenderMetricsQuery`, which joins the Part A **D10** `IgnoreQueryFilters` allow-list (a dedicated metrics reader, one entry) and returns **counts only — never rows** **[RULED — README §B10 WT14]**. HTTP latency/5xx for the 11.6.2-T1 board come from the AspNetCore instrumentation; no custom instrument is added for them. Cardinality is bounded: tag sets are closed enums/strings (`stage`, `outcome`, `operation`), never ids.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Collector unreachable / slow | the batch exporter drops after its bounded queue; the app never blocks a request on export; a warning is logged once per minute (no per-record flood) |
| `LoggingBehavior` trace missing | the request span still carries `traceId`; the log line falls back to the current `Activity` (no null trace) |
| `INodeHealthCache` cold (no poller tick yet) | node check reports `Degraded` with `unhealthy: no data` — never `Unhealthy` |
| Storage marker missing | `Degraded`; the marker is created by 09.7.2-T1's deploy step; readiness must not write it |
| `render_jobs_active` query slow | the refresher runs every 30 s outside the request path with the advisory lock; a failure logs and keeps the previous value |
| Duplicate spans (retry) | job spans are per attempt; `job.attempt` is a tag, so retries are distinguishable |
| Clock/timezone | all durations are `TimeSpan`/`long` ms from `Activity`/`Stopwatch`; `FakeClock` is never used for measurement |
| Serilog outage (stdout writes) | Serilog's own failure is swallowed by the async sink configuration; the app keeps serving |

Rollback: set `Otlp:Enabled=false` (or remove the sink) without redeploying business code; health endpoints are additive and can be left mapped while the orchestrator stops probing them.
