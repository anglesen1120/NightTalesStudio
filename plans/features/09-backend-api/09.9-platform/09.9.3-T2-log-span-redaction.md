# 09.9.3-T2 — Query-string redaction (`access_token`, `ticket`, `token`, `code`, `state`) in logs/spans + capture test

| Story | Size | Area | Depends on | Blocks | Phase / flag |

## Goal

No raw `access_token`, `ticket`, `token`, `code` or `state` value ever leaves the process — not in a log line (stdout JSON or the OTLP log sink), not in a span attribute (`url.query`, `url.full`, exception messages) — proven by a capture test over the hub-connect and reset-link paths.

## Inputs

- README Part B: **BD12** (10.5, redaction processors), BD16 (no token in logs), BD3 (reset links carry the token in the URL **fragment**, the SPA posts it), BD11 + **09.8.1-T2** (hub ticket in the WebSocket URL).
- `plans/09-backend-api.md:233` — the epic sentence: request logs, OTel `url.query`/`url.full` attributes and load-balancer access logs must not contain the raw values; an integration test asserts a hub connect and a reset link leave no raw value in captured logs or spans.
- `plans/09-backend-api.md:249` — the same rule stated for the whole suite (secrets never appear in any response/log/trace/audit/export/exception).
- **09.9.3-T1** — the Serilog/OTel pipeline this processor plugs into; **09.8.1-T2** — `POST /hubs/ticket` and the WebSocket URL that carries `ticket`.
- Part A **D4** (`LoggingBehavior`'s `mediator.request` line must not carry the query), **D7** (ProblemDetails never echoes a query value), BD16 (frozen redaction list).

## Design

### One list, two writers (Serilog + OTel)

```csharp
// Infrastructure/Telemetry/Redaction/RedactionOptions.cs  [INFERENCE: type names]
public sealed class RedactionOptions
{
    public string[] QueryKeys { get; init; } =
        ["access_token", "ticket", "token", "code", "state"];                 // BD12 — frozen default
    public string[] Headers { get; init; } = ["authorization", "cookie", "set-cookie"];   // [INFERENCE] extension
    public const string Mask = "<redacted>";                                  // [INFERENCE]
}
// bound from Logging:RedactionQueryKeys / Logging:RedactionHeaders
```

```csharp
// Infrastructure/Telemetry/Redaction/QueryStringRedactor.cs
public static class QueryStringRedactor
{
    // Single pass, allocation-light: split on '&' then on the FIRST '='.
    // Key match is case-insensitive (ordinal-ignore-case) on the decoded key.
    // No key matches → return the input instance unchanged (no allocation).
    // Parse failure or an undecodable '%' sequence → return "?" + Mask for the whole query (fail-closed), never the raw text.
    public static string Redact(string? queryString, IReadOnlySet<string> keys);
}
```

- **Serilog**: `QueryStringRedactionEnricher` rewrites `RequestPath`/`QueryString` (request-logging properties), the properties `url.query`/`url.full` when present, `http.url`, and the `Headers` list (`authorization`, `cookie`, `set-cookie` → `<redacted>`). Registered **before** the OTel sink so the forwarded log event is already clean (`Serilog.Sinks.OpenTelemetry` serialises the enricher output).
- **OTel**: one `RedactingActivityProcessor : BaseProcessor<Activity>` rewrites, on `OnEnd`, the attributes whose key is in `{ url.query, url.full, http.url, http.target, query.string, request.query }` and, if an attribute value is an exception message/stack, applies the same query redactor to it. Registered with `AddProcessor(...)` in `TelemetryRegistration` (09.9.3-T1) so it also covers the `Npgsql` and HttpClient activities.

Order matters: the processor runs for **every** activity regardless of sampler outcome, and it is registered even when `Otlp:Enabled=false` (stdout JSON is also a log sink).

### Coverage of the two named paths

| Path | Where the raw value appears | Redacted by |
|---|---|---|
| Hub connect `GET /hubs/episodes?ticket=<raw>` (09.8.1-T2) and the WebSocket upgrade request | ASP.NET Core request log `QueryString`, span `url.query`/`url.full`, the `LoggingBehavior` line | enricher + activity processor |
| Reset / verify link `POST /api/v1/auth/reset-password` (`token` in the body per BD3, but a dev/proxy URL may use a query) and any `?token=`/`?code=`/`?state=` OAuth callback (06) | request log `QueryString`, span attributes, exception messages | same |
| `access_token` on a hub or media URL | `url.query`, `url.full` | same |

Load-balancer access logs are outside the process; the plan records the requirement (09:233) and 11's reverse-proxy config must strip query strings on the two auth/hub paths — **Open item** for the TL/11 (`plan.md` §10).

### Performance

- Per log event / activity: one set lookup per query key plus one string build only when a redaction actually happens. No regex, no LINQ, no unbounded allocation; URLs are bounded by the request line limit already enforced by Kestrel.
- The key set is materialised once at startup into a `HashSet<string>(StringComparer.OrdinalIgnoreCase)` and captured by the enricher/processor (no per-event config reads).
- The processor never mutates an attribute concurrently (activity attributes are written under the SDK's enumerator lock); it must skip activities already processed (`activity.GetTagItem("nts.redacted") is not null` guard **[INFERENCE]**) so double registration cannot loop.

### Tests are the acceptance

The capture test builds a real request through `ApiFactory` with a `TestLogSink` (a hand-written `ILogEventSink` preserving Serilog's structured properties, i.e. pre-render) plus an `ActivityListener` capturing `url.query`/`url.full`; the assertion is on the **raw** seeded values (`TokenFixtures.ResetToken`, `TokenFixtures.HubTicket`), not on the log text shape.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Unknown/extra query key added later | not redacted → the positive-control test keeps the list honest; adding a key is a one-line config change (no code) |
| Value appears in a path segment (`/reset/<token>`) | out of scope of the query redactor; the reset flow uses a fragment + POST body (BD3). Any path-embedded token is a new finding — raise it, do not silently extend the list |
| Raw value in a request **body** | never logged (D4 logs the route template + duration only); a body-logging call site must fail review |
| Double registration of the processor | guard flag prevents re-processing; the test asserts the value is masked exactly once |
| `ILogEventSink` sees the un-enriched event | the enricher is registered before the sink; the test asserts on the sink's *received* properties, so a wrong order fails the test |
| OTLP export disabled | processor still registered (stdout JSON is a sink) |
| Collector-side redaction | explicitly **not** relied on: the value must not leave the process |

Rollback: never disable the enricher/processor in production (plan §11). A defect is fixed forward; the previous image is the only rollback. Reverting the whole 09.9.3-T2 means reverting 09.9.3-T1's registration — do not ship a build where the redaction list is empty (a startup assertion rejects an empty `Logging:RedactionQueryKeys`).
