## Goal

`openapi.json` is published by CI, and a **breaking** contract change fails the PR unless it is versioned: additive changes stay inside `/api/v1`, a breaking change must introduce a new `/api/v2` prefix while `/api/v1` keeps working. The document carries a `ProblemDetails` schema component so generated clients (`10.1.4`) get a typed error model.

## Design

### The `contract` job (additive to `backend.yml`)

```yaml
  contract:
    needs: build-test
    if: github.event_name == 'pull_request'
    runs-on: ubuntu-24.04
    permissions: { contents: read }
    steps:
      - uses: actions/checkout@<sha>                     # head of the PR
      - uses: actions/download-artifact@<sha>            # same run — no cross-run API
        with: { name: openapi, path: head }
      - uses: actions/checkout@<sha>                     # the merge base of authority: main
        with: { ref: main, path: base }
      - uses: actions/setup-dotnet@<sha>
        with: { global-json-file: base/global.json }
      - run: dotnet restore base/NightTales.ci.slnf --locked-mode
      - run: dotnet build base/src/NightTales.Api -c Release --no-restore
      - run: dotnet run --project base/src/NightTales.Api -c Release --no-build -- --generate-openapi base/openapi.json
      - run: tools/ci/install-oasdiff.sh                 # pinned version + SHA-256 verify (W11, Apache-2.0)
      - run: oasdiff breaking --fail-on ERR base/openapi.json head/openapi.json | tee findings.txt
      - run: python3 tools/ci/check-version-rule.py findings.txt base/openapi.json head/openapi.json
      - run: jq -e '.components.schemas.ProblemDetails' head/openapi.json
      - name: summary
        if: always()
        run: python3 tools/ci/summarize-contract.py findings.txt >> "$GITHUB_STEP_SUMMARY"
```

- `download-artifact` with the default (same-run) scope is the reason the job lives **inside** `backend.yml` rather than in a separate workflow: a cross-run artifact download needs an API token and a run id, which is more moving parts for no benefit. **[DECISION 09.9-D3]**
- The base spec is generated from `main` by building it in the same job — deterministic, no stored baseline to go stale. Cost is one extra `dotnet build` of the Api project on PR runs only.
- oasdiff is pinned by **version and SHA-256** in `tools/ci/install-oasdiff.sh` (constants filled at implementation; W11 fixes the project, not the release). A download failure fails the job — never a silent skip.
- `--fail-on ERR` fails on errors and above; warnings (`info`) are reported in the job summary but do not fail (so a description-only change does not block a PR).

### The versioning rule (09.9.5-D4, extends BD12)

```python
# tools/ci/check-version-rule.py   — exit 0 unless a breaking change is unversioned
# 1. parse findings.txt: any finding of level ERR means the head changed the contract incompatibly.
# 2. if there are ERR findings:
#      - every path in base.openapi.json's `paths` must still exist, unchanged, in the head document
#        (a removed/renamed/retyped operation inside /api/v1 is never acceptable), AND
#      - the head document must contain a new top-level prefix that base does not have
#        (e.g. /api/v2/...) AND `info.version`'s major must be greater than base's.
#    Otherwise: print "unversioned breaking change" + the finding list, exit 1.
# 3. additive-only change (no ERR findings): always pass.
```

- `info.version` is set at build from the CI build metadata: `<major>.<minor>.<run_number>`; the major is the API version and only changes with a new prefix.
- Rationale: the 10.x client is generated from the head document, so an operation that was silently removed or retyped breaks shipped apps; the rule forces an explicit, additive-in-old-version path for anything a client can observe.

### `ProblemDetails` schema component

- 09.1.4-T1's error mapping registers one `ProblemDetails` schema (the same type used for every error response) in the Api's OpenAPI document; this task asserts the component exists and that **every** error response in the document references it (a unit test iterating the document), so generated clients get a typed error body with `code`, `title`, `status`, `type`, `traceId` (D7).
- The `jq -e` step is a cheap belt-and-braces check in CI; the unit test is the real gate (it can assert the property list, not just presence).

### Published artifacts

- The already-existing artifact `openapi` (`src/NightTales.Api/openapi.json`) is the head input for this job and for 10.1.4's client generation; retention follows the repository default (11.5.1 owns pipeline retention).
- The `contract` job writes `findings.txt` + a summary table into the run's step summary (operator-facing surface, `plan.md` §6).

## Steps

1. Add the `contract` job to `.github/workflows/backend.yml` with pinned action SHAs (same style as `build-test`), `needs: build-test`, `if: pull_request`, `permissions: { contents: read }`.
2. Add `tools/ci/install-oasdiff.sh` (pinned version + SHA-256 + `set -euo pipefail`).
3. Add `tools/ci/check-version-rule.py` implementing the rule above; unit-test it with fixtures.
4. Add `tools/ci/summarize-contract.py` (findings table + the remediation hint).
5. Add the `ProblemDetails` component assertion in the Api tests (`OpenApiDocumentTests`) and make the document generation part of the normal build (already 09.1.5-T1's C3 / `--generate-openapi` fallback).
6. Add the fixture specs under `tests/fixtures/openapi/` (one breaking, one additive, one versioned-breaking) and wire them into the python tests.
7. Update the feature README of 09 (§10/§12 tables) with the new gate; note in `plans/features/README.md` only if the index requires it (do not edit other plans).

## Acceptance checks

- [ ] On a PR that adds a property to a response DTO, `contract` passes and the summary lists no ERR finding.
- [ ] On a PR that removes a path or a response property, `contract` **fails** with the finding list and `check-version-rule.py` prints "unversioned breaking change".
- [ ] On a PR that adds `/api/v2/...` with a major `info.version` bump while `/api/v1` is untouched, `contract` passes (the fixture pair proves the rule, not just the tool).
- [ ] On `push` to `main`, the `contract` job does not run (`if: pull_request`), and `build-test` still publishes the `openapi` artifact.
- [ ] `jq -e '.components.schemas.ProblemDetails' head/openapi.json` succeeds, and the unit test asserts every error response references it with the five D7 properties.
- [ ] A failed oasdiff download or a failed base build fails the job with a distinct message (never "no findings").
- [ ] `oasdiff` runs from a SHA-256-verified, version-pinned binary whose archive hash is committed in the script; no floating `latest` URL.
- [ ] The job uses only `contents: read` and pinned action SHAs.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| `openapi` artifact missing (build broke earlier) | `needs: build-test` already failed → the job never starts; if the artifact alone is missing, `download-artifact` fails the job (fail-closed) |
| `main` does not build (broken trunk) | distinct failure message ("base build failed") so it is not confused with a contract break; the job stays red until trunk is green |
| Spec generation flaky (`--generate-openapi` starts the app) | run with `--no-build`, no database required at generation time; a failure is reported as a generation failure, not as a diff |
| First PR after the gate lands | `main` already publishes a spec (09.1.5-T1), so a base always exists; if a file is absent the script exits non-zero (fail-closed) |
| Breaking change that is genuinely wanted | add the new prefix, bump the major in `info.version`, keep `/api/v1` — the same PR passes |
| Warning-level findings | reported in the summary, never blocking |
| oasdiff release unavailable | pinned hash mismatch → job fails; the fix is a reviewed bump of the version+hash constants |
| A PR edits `.github/workflows/backend.yml` in the same PR | out of scope: branch protection must mark `contract` required (repository setting; 11.5.1 owns pipeline policy) |

Rollback: remove `contract` from the required checks in branch protection (instant), or revert the job; the artifact and the document generation stay (10.1.4 depends on them).
