## Goal

`openapi.json` is published by CI, and a **breaking** contract change fails the PR unless it is versioned: additive changes stay inside `/api/v1`, a breaking change must introduce a new `/api/v2` prefix while `/api/v1` keeps working. The document carries a `ProblemDetails` schema component so generated clients (`10.1.4`) get a typed error model.

## Design

### The `contract` job (additive to `backend.yml`)

```yaml
  contract:
    needs: build-test
    if: github.event_name == 'pull_request'
    runs-on: ubuntu-24.04
    permissions: { contents: read }
    steps:
      - uses: actions/checkout@<sha>                     # head of the PR
      - uses: actions/download-artifact@<sha>            # same run — no cross-run API
        with: { name: openapi, path: head }
      - uses: actions/checkout@<sha>                     # the PR base (`develop` today; BD12 says "main")
        with: { ref: ${{ github.event.pull_request.base.sha }}, path: base }
      - uses: actions/setup-dotnet@<sha>
        with: { global-json-file: base/global.json }
      - run: dotnet restore base/NightTales.ci.slnf --locked-mode
      - run: dotnet build base/src/NightTales.Api -c Release --no-restore
      - run: dotnet run --project base/src/NightTales.Api -c Release --no-build -- --generate-openapi base/openapi.json
      - run: tools/ci/install-oasdiff.sh                 # pinned version + SHA-256 verify (W11, Apache-2.0)
      - run: oasdiff breaking --fail-on ERR base/openapi.json head/openapi.json | tee findings.txt
      - run: python3 tools/ci/check-version-rule.py findings.txt base/openapi.json head/openapi.json
      - run: jq -e '.components.schemas.ProblemDetails' head/openapi.json
      - name: summary
        if: always()
        run: python3 tools/ci/summarize-contract.py findings.txt >> "$GITHUB_STEP_SUMMARY"
```

- `download-artifact` with the default (same-run) scope is the reason the job lives **inside** `backend.yml` rather than in a separate workflow: a cross-run artifact download needs an API token and a run id, which is more moving parts for no benefit. **[DECISION 09.9-D3]**
- The base spec is generated from the **PR base commit** (`github.event.pull_request.base.sha` — `develop` today, fixed for the run) by building it in the same job — deterministic, no stored baseline to go stale. Cost is one extra `dotnet build` of the Api project on PR runs only.
- oasdiff is pinned by **version and SHA-256** in `tools/ci/install-oasdiff.sh` (constants filled at implementation; W11 fixes the project, not the release). A download failure fails the job — never a silent skip.
- `--fail-on ERR` fails on errors and above; warnings (`info`) are reported in the job summary but do not fail (so a description-only change does not block a PR).

### As built (2026-10-01)

Three details of the snippet above changed while implementing it, and the `ProblemDetails` component
needed one addition the design assumed was already there:

- **The base document is not generated with `--generate-openapi`.** `09.1.5-T1-backend-ci-workflow.md:88`
  settled that the fallback is **not** used: `Microsoft.Extensions.ApiDescription.Server` writes the
  document during `dotnet build`, through the Api project's own `CopyOpenApiDocument` target. The
  `dotnet run … -- --generate-openapi base/openapi.json` line of the snippet would in fact start the web
  server and hang the job — `Program.cs` handles no such argument. The job therefore builds
  `base/src/NightTales.Api` and diffs `base/src/NightTales.Api/openapi.json`, the same path the head
  artifact is published from, so both documents are produced by the same generation.
- **The findings file is oasdiff's `--format json`, named `findings.json`, and `--fail-on ERR` is not
  used.** `--fail-on ERR` fails the step before the rule runs, and then a *versioned* breaking change —
  which must pass (acceptance check 3) — could never pass. The rule is the arbiter: oasdiff runs
  without `--fail-on`, its JSON findings are the file, and `check-version-rule.py` decides the exit
  code. A spec oasdiff cannot read still fails its own step, with its own message.
- **The head document's path is resolved, not assumed.** `actions/download-artifact` roots a
  single-file artifact at the file's directory, so it lands at `head/openapi.json`; the job resolves it
  with `find` so a change in that layout fails with a message that names the artifact instead of a
  confusing diff error.
- **The base of the comparison is the PR base commit, not `main`** (QA defect D1). `main` in this
  repository is frozen at the initial commit (no `src/`, no `NightTales.ci.slnf`) and every PR targets
  `develop`, so `ref: main` made the job die at "Restore the base" on every PR and measured against a
  document that does not exist. The job now checks out
  `${{ github.event.pull_request.base.sha }}` — the commit the PR is based on, `develop` today, fixed
  for the run — and the step is named "Check out the PR base". BD12's wording ("against `main`") is
  therefore read as "against the PR's trunk" (see the Notes tag line).
- **`ProblemDetailsSchemaTransformer` was added** (`src/NightTales.Api/Http/`, registered in
  `Program.cs`). The generated `ProblemDetails` component is built from
  `Microsoft.AspNetCore.Mvc.ProblemDetails`, whose members stop at `detail`/`instance`: the `code` and
  `traceId` members of D7 that `ProblemDetailsWriter` always writes were missing from the published
  document, so the acceptance check ("every error response references it **with the five D7
  properties**") could not hold without it. The transformer adds both as required strings.

### The versioning rule (09.9.5-D4, extends BD12)

```python
# tools/ci/check-version-rule.py   — exit 0 unless a breaking change is unversioned
# 1. parse findings.txt: any finding of level ERR means the head changed the contract incompatibly.
# 2. if there are ERR findings:
#      - every path in base.openapi.json's `paths` must still exist, unchanged, in the head document
#        (a removed/renamed/retyped operation inside /api/v1 is never acceptable), AND
#      - the head document must contain a new top-level prefix that base does not have
#        (e.g. /api/v2/...) AND `info.version`'s major must be greater than base's.
#    Otherwise: print "unversioned breaking change" + the finding list, exit 1.
# 3. additive-only change (no ERR findings): always pass.
```

- `info.version` is set at build from the CI build metadata: `<major>.<minor>.<run_number>`; the major is the API version and only changes with a new prefix.
- Rationale: the 10.x client is generated from the head document, so an operation that was silently removed or retyped breaks shipped apps; the rule forces an explicit, additive-in-old-version path for anything a client can observe.

### `ProblemDetails` schema component

- 09.1.4-T1's error mapping registers one `ProblemDetails` schema (the same type used for every error response) in the Api's OpenAPI document; this task asserts the component exists and that **every** error response in the document references it (a unit test iterating the document), so generated clients get a typed error body with `code`, `title`, `status`, `type`, `traceId` (D7).
- **As built:** the framework generates that component from `Microsoft.AspNetCore.Mvc.ProblemDetails`, which carries only `type`, `title`, `status`, `detail` and `instance`. The two D7 members `ProblemDetailsWriter` always writes — `code` and `traceId` — are therefore added by `ProblemDetailsSchemaTransformer` (`src/NightTales.Api/Http/`, registered in `Program.cs` with `AddOpenApi(options => options.AddSchemaTransformer<…>())`), as required strings. The component's `required` list is the two added members; the framework's own members stay as generated.
- The `jq -e` step is a cheap belt-and-braces check in CI; the unit test is the real gate (it can assert the property list, not just presence).

### Published artifacts

- The already-existing artifact `openapi` (`src/NightTales.Api/openapi.json`) is the head input for this job and for 10.1.4's client generation; retention follows the repository default (11.5.1 owns pipeline retention).
- The `contract` job writes `findings.json` (oasdiff's `--format json`, as built) + a summary table into the run's step summary (operator-facing surface, `plan.md` §6).

- [x] On a PR that removes a path or a response property, `contract` **fails** with the finding list and `check-version-rule.py` prints "unversioned breaking change". — **verified** end to end on the `breaking` fixture (exit 1, finding list + remediation); a removed *path* is verified by `removed_path_fails_even_with_a_new_prefix`.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| `openapi` artifact missing (build broke earlier) | `needs: build-test` already failed → the job never starts; if the artifact alone is missing, `download-artifact` fails the job (fail-closed) |
| The PR base does not build (broken trunk) | distinct failure message ("base build failed") so it is not confused with a contract break; the job stays red until the trunk is green |
| Spec generation flaky (the generator boots the app in-process) | the base document is written by `dotnet build` of the Api (09.1.5-T1's target, **not** a `--generate-openapi` run), so a failure is reported as a build failure, not as a diff. No database is needed: the generator boots the host with the placeholder connection string of the workflow `env` |
| First PR after the gate lands | the PR base already publishes a spec (09.1.5-T1; `develop` carries it), so a base always exists; if a file is absent the script exits non-zero (fail-closed) |
| Breaking change that is genuinely wanted | add the new prefix, bump the major in `info.version`, keep `/api/v1` — the same PR passes |
| Warning-level findings | reported in the summary, never blocking |
| oasdiff release unavailable | pinned hash mismatch → job fails; the fix is a reviewed bump of the version+hash constants |
| A PR edits `.github/workflows/backend.yml` in the same PR | out of scope: branch protection must mark `contract` required (repository setting; 11.5.1 owns pipeline policy) |

Rollback: remove `contract` from the required checks in branch protection (instant), or revert the job; the artifact and the document generation stay (10.1.4 depends on them).
