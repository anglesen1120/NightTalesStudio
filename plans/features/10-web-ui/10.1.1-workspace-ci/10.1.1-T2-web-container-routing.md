## Goal

Give the SPA a production-shaped container and one origin in every mode: a digest-pinned, non-root, read-only-rootfs nginx image serving `dist/web/browser` on **8080** with the D3 caching rules, `GET /healthz` for the container health and the deploy gate, the D4 header set, and a **hard 404 for `/api/*`, `/hubs/*`, `/health/*`** so the SPA can never answer an API path with HTML; plus the dev proxy that makes `ng serve` talk to the local API. **Dev is native (owner 2026-09-28, `plans/00-overview.md` §5.1; 10 CR-43):** the daily path is `npm start` = `ng serve` + `web/proxy.conf.json` on macOS, no Docker; this Dockerfile and the compose `web` profile exist for the **deploy image** (CI build + smoke, staging, production) and for e2e / image smoke only, never as a daily-dev requirement. Behaviour is identical through `http://localhost:4200` in dev and through the LB in staging/prod.

| `web/nginx/templates/default.conf.template` | `server { listen 8080; server_tokens off; root /usr/share/nginx/html; autoindex off; location = /.git { return 404; }` … `}` — the image's entrypoint envsubst's this file into `conf.d/default.conf` |
| `web/nginx/templates/security-headers.conf.template` | **all D4 headers except CSP** (WR2/WR13), owned here and **envsubst'ed at start-up** into `/etc/nginx/conf.d/security-headers.conf`: `add_header Referrer-Policy "no-referrer" always;`, `add_header X-Content-Type-Options "nosniff" always;`, `add_header Permissions-Policy "camera=(), microphone=(), geolocation=(), payment=()" always;`, `add_header Cross-Origin-Opener-Policy "same-origin" always;` and `add_header Strict-Transport-Security "$NTS_HSTS" always;`. **HSTS mechanism (stated explicitly):** nginx does **not** pass a header whose value is the empty string, so `NTS_HSTS=""` (dev/compose default) emits no HSTS while staging/prod set `max-age=31536000; includeSubDomains` — no `if` block (which would break `add_header` inheritance) and no `$NTS_HSTS`-conditioned duplicate file |
| `web/docker-entrypoint.d/15-nts-validate-env.sh` | **start-up validation (WR13)** — refuses to start (`exit 1`, message names the variable and the offending token) when: `NTS_CSP_MEDIA_ORIGINS` contains `;`, `"`, `'`, `<`, `>`, `(`, `)`, `\`, a control character or a whitespace-separated token not matching `^https?://[A-Za-z0-9.-]+(:[0-9]{1,5})?$`; `NTS_HSTS` is non-empty and does not match `^max-age=[0-9]+(; includeSubDomains)?$`; `NTS_SPA_FALLBACK` does not match `^[a-zA-Z0-9._-]+$`. Empty values are allowed; the script never echoes a value into the log beyond the variable name and the rejected token |
| `web/nginx/templates/includes/.gitkeep` | the template directory that receives the generated `csp-headers.conf.template` at image build time; the file itself is never committed |
| `web/nginx/guards/api-proxy.conf.template` | `location /api/ { proxy_pass ${NTS_API_UPSTREAM}; proxy_http_version 1.1; proxy_set_header Host $host; proxy_set_header X-Forwarded-Proto $scheme; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; }` + the same for `/health/` + `location /hubs/ { proxy_pass ${NTS_API_UPSTREAM}; proxy_http_version 1.1; proxy_set_header Upgrade $http_upgrade; proxy_set_header Connection $connection_upgrade; proxy_set_header Host $host; proxy_read_timeout 3600s; proxy_send_timeout 3600s; access_log /dev/stdout nts_noquery; }` (dev only) |
| `web/nginx/guards/api-guard-404.conf` | `location ~ ^/(api\|hubs\|health)/ { return 404; }` — the **prod/default** guard: an API path that reaches the web container is a routing bug and must fail fast, never return HTML |
| `web/nginx/templates/00-nts-map.conf.template` | `map $http_upgrade $connection_upgrade { default upgrade; '' close; }` (http context) + `log_format nts_noquery '$remote_addr - $remote_user [$time_local] "$request_method $uri $server_protocol" $status $body_bytes_sent "$http_referer" "$http_user_agent"';` — the format uses `$uri` (path only, **no query string**) so the single-use hub ticket in `/hubs/*?ticket=…` never reaches the log (D8/WR13) |
| `web/docker-entrypoint.d/17-nts-api-guard.sh` | if `NTS_API_UPSTREAM` is non-empty → `envsubst` `guards/api-proxy.conf.template` → `/etc/nginx/conf.d/nts-api-guard.conf`; else copy `guards/api-guard-404.conf` there; prints which mode was chosen. Runs before the image's `20-envsubst-on-templates.sh`; no other behaviour |
| `web/proxy.conf.json` | dev (`ng serve`): `/api` and `/health` → `"target": "http://127.0.0.1:5000"`, `"secure": false`, `"changeOrigin": false`, `"logLevel": "warn"`; `/hubs` → the same target with `"ws": true`. Same-origin host `localhost`, so no cookie rewriting and no CORS |
| `web/.dockerignore` | `node_modules`, `dist`, `.angular`, `e2e-results`, `playwright-report`, `test-results`, `.git` |
| `web/tools/web/container-smoke.sh` | the executable checklist of the acceptance below (curl + `docker run --read-only`), `npm run container:smoke`; exit non-zero on the first failed assertion and print the observed status/header |

**nginx behaviour (exact)**

- **`add_header` inheritance gotcha (WR2, must be stated in the config comments):** an `add_header` inside a `location` **cancels every inherited `add_header`** from the server level. Therefore every location that sets headers `include /etc/nginx/conf.d/security-headers.conf;` (the envsubst output of `templates/security-headers.conf.template`), and the HTML-serving locations **additionally** `include /etc/nginx/conf.d/includes/csp-headers.conf;` (the generator's template, envsubst'ed at start). CSP is sent on HTML responses only — never on assets or JSON.
- `location / { try_files $uri $uri/index.html /$NTS_SPA_FALLBACK; include /etc/nginx/conf.d/security-headers.conf; include /etc/nginx/conf.d/includes/csp-headers.conf; add_header Cache-Control "no-cache"; }` — **WR13**: the `try_files`/fallback HTML hits carry `no-cache` too, not only the explicit `.html` matches; prerendered documents are served as real files (deep link `/vi/privacy` → the directory index), everything else gets the client fallback HTML so the router can handle it.
- `location ~* \.html$ { include /etc/nginx/conf.d/security-headers.conf; include /etc/nginx/conf.d/includes/csp-headers.conf; add_header Cache-Control "no-cache"; }` — the explicit HTML location repeats both includes for the same inheritance reason.
- `location ~* -[A-Za-z0-9]{8}\.(?:js|css|woff2)$ { include /etc/nginx/conf.d/security-headers.conf; add_header Cache-Control "public, max-age=31536000, immutable"; }` (hash length ⚠️ confirmed against the built names; if Angular emits a different length the pattern is adjusted in the same PR and recorded). **No CSP here** (WR2).
- `location /assets/ { include /etc/nginx/conf.d/security-headers.conf; add_header Cache-Control "public, max-age=3600, must-revalidate"; }` — i18n JSON and images are not content-hashed (D3/D10).
- `/hubs/` (dev proxy only) additionally sets `access_log /dev/stdout nts_noquery;` — query strings (the hub ticket) are never logged (D8/WR13).
- `location = /healthz { access_log off; add_header Content-Type text/plain; add_header Cache-Control "no-store"; return 200 "ok\n"; }` — container health and the 11.5.1-T1 rollout gate; it never touches the SPA and reveals nothing.
- `gzip on; gzip_types text/html text/css application/javascript application/json image/svg+xml; gzip_min_length 1024;` — brotli-static is used if the image supports it ⚠️, otherwise gzip is the contract minimum.
- The API-guard include is placed **before** `location /` so `/api/...` can never fall through to `try_files`.

**Cross-check for the cookie fact (ruling).** `__Secure-` prefixed cookies are accepted by Chromium over `http://localhost` (localhost is a potentially trustworthy origin); Firefox is stricter. This task records the observed result for both browsers as PR evidence (devtools → Application → Cookies → `localhost` shows `__Secure-nts_rt`, and `POST /api/v1/auth/refresh` carries it), and the automated regression is added to the Playwright smoke spec (10.1.5-T1, CR in `plan.md` §10) so the acceptance is re-checked by `e2e.yml`'s compose job (11.5.1-T1:22) on every PR touching `web/**`.

**Copy keys.** None — the container serves static files and returns plain text for `/healthz` and 404s (no user-visible string, no i18n key). Any HTML the container generates on its own would be a bug, which the guard prevents.

**a11y (D16).** No UI is created here; the task must not break the baseline: no `Content-Security-Policy` directive that blocks the app's own scripts or the Material runtime `style-src 'unsafe-inline'`, and no `X-Frame-Options`/`frame-ancestors` value that blocks the app. Response headers are the contract (D4) and the e2e axe run (10.1.5-T1) proves the pages still work.

**Performance (NFR-10-1/2).** Immutable hashed assets make repeat visits cheap; `no-cache` HTML guarantees a new deploy is picked up; gzip is on; there is no per-request work in nginx (no `if`, no `rewrite`, no hashing at request time — the CSP file is generated at image build and the media origins are substituted once at start-up, D4/WR2).

**Security.** Runtime image is non-root (uid 101), read-only rootfs, no shell tooling added, `server_tokens off`, `autoindex off`, dotfiles 404, no source maps, no `.env`, no secret in the image or the Dockerfile; the four env vars (`NTS_SPA_FALLBACK`, `NTS_CSP_MEDIA_ORIGINS`, `NTS_API_UPSTREAM`, `NTS_HSTS`) are non-secret configuration; access logs contain request lines only and no token ever appears in a URL (D8).

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| `nginxinc/nginx-unprivileged` digest cannot be resolved / licence is not the expected Apache-2.0 (verified 2026-10-04 on the pinned `1.29-alpine` image label + upstream LICENSE; 10 CR-44) | stop and escalate in the PR; do **not** silently switch to the root `nginx` image — the non-root requirement (D3) is part of the gate |
| Read-only rootfs breaks nginx's temp paths | the unprivileged image already points pid/cache/temp at writable `/tmp`; if a path is still needed, mount a `tmpfs` at that path in the run/compose command and record it — never drop `--read-only` |
| Angular's output hash is not 8 characters | adjust the immutable-asset location pattern in the same PR and record the actual pattern in the PR body |
| `NTS_SPA_FALLBACK` set to a non-existent file | `try_files` ends in a 404 for unknown deep links; the smoke script asserts the fallback file exists in the image (`[ -f /usr/share/nginx/html/$NTS_SPA_FALLBACK ]`) |
| API upstream set to an unreachable host in dev | nginx returns `502` for `/api/**`; that is correct dev behaviour and the client maps it to `network_error` (10.2.2-T1) |
| Firefox refuses `__Secure-nts_rt` over `http://localhost` | acceptable and recorded: P's e2e is Chromium-only (ruling); the finding is handed to 09.3.2's cookie attributes review via the PR body, and the dev-only workaround is running the prod-shaped HTTPS origin (`https://staging.<domain>`) |
| `csp:gen` not landed yet (10.1.6-T1) | `docker build` fails at that builder step **by design** (never ship an image without the CSP include); `ng serve` is the interim dev path (no CSP locally), and the container acceptance runs once 10.1.6-T1 lands in the same wave — the PR records which state was verified, never a silent `RUN npm run build` that ships no CSP |
| The image's envsubst does not recurse into `templates/includes/` ⚠️ | place the generated template at `/etc/nginx/templates/csp-headers.conf.template` (same flow, one level up) and keep the include path `/etc/nginx/conf.d/csp-headers.conf`; record the actual output path in the PR body |
| 10.1.6-T1 renames or moves its generated file | align this folder's COPY target and include path to the new name in that PR (the include contract is: one `add_header Content-Security-Policy …always;` line, HTML responses only) and record it as a CR in `plan.md` §10 — never declare CSP in `security-headers.conf` as a shortcut |
