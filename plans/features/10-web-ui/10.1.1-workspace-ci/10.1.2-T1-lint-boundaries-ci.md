# 10.1.2-T1 — ESLint, boundary rules, CI lint

| Story | Size | Area | Depends on | Blocks | Phase / flag |
|---|---|---|---|---|---|
| 10.1.2 | S (0.5) | FE | 10.1.1-T1 | 10.1.4-T1, 10.1.6-T1 | P · M1 |

## Goal

Make the D2 architecture rules and the security bans **mechanically unbreakable**: one flat ESLint config that fails when `domain` imports framework code, when a `ui` component injects a store/repository/`HttpClient`, when a file outside `data-access` imports `@shared/api`, when a feature deep-imports another feature, when `any` appears, when a component is not `OnPush`, when a component calls `.subscribe(`, or when the code uses `bypassSecurityTrust*`/`eval`/`document.write`/storage outside `core/prefs` — plus a template/HTML scan for what ESLint cannot express, and negative fixtures that prove each rule actually fires.

## Inputs

- ✅ `../README.md` §3 **D2** (the exact rule list and the layout), **D5** (generated `@shared/api` is excluded from lint), **D6** (`localStorage` only in `core/prefs`), **D13** (OnPush everywhere, `track`, `@defer`), **D16** (a11y baseline), **D15** (CI runs lint).
- ✅ `plans/10-web-ui.md:58-62` story 10.1.2 ("boundary plugin ⚠️ license check", rules for `any`, OnPush, subscriptions) and `:47` NFR-10-6.
- ✅ `plans/00-overview.md` §5.4 (layer responsibilities: `domain` pure, `data-access` implements the port, `application` orchestrates, `ui` presentational).
- ⚠️ `@angular-eslint` rule names in the installed major (`prefer-on-push-component-change-detection`, the template `innerHTML` rule, the accessibility rule set); whether a boundary plugin (e.g. `eslint-plugin-boundaries`) is worth its dependency — **not used here** (see Design).

## Design

**Decision — no boundary plugin.** The D2 rules are expressible with `@typescript-eslint/no-restricted-imports` (glob-scoped overrides) and `no-restricted-syntax`, both already in the toolchain; adding a graph plugin would be a new dependency with its own licence and config surface for no extra coverage (the high-level 10.1.2 mentioned one with a ⚠️ licence check). If a richer cross-module graph rule is wanted later, `eslint-plugin-boundaries` (⚠️ licence to verify) is the candidate — recorded as [OPEN] in `plan.md` §10, not adopted silently.

**Files created**

| File | Content |
|---|---|
| `web/eslint.config.js` | flat config, ESM: `angular-eslint` recommended TS + template sets, `typescript-eslint` recommended-type-checked as the base, then the overrides below; `ignores: ['dist/**', '.angular/**', 'node_modules/**', 'src/app/shared/api/**', 'tools/lint-fixtures/**']` (`src/app/shared/api` is generated and formatted by 10.1.4-T1, D5) |
| `web/tools/web/lint-forbidden-patterns.mjs` | scans `src/**/*.html` (any other template suffix used) for `[innerHTML`, `javascript:`, inline `on*=` handlers, `srcdoc=`, `<iframe`, `document.write`, `eval(`, `new Function`; prints `file:line: <pattern>` and exits 1. Reason: the CSP generator (10.1.6-T1) also fails on inline handlers, but lint must fail **before** the build so the author sees it in the editor/PR, and Angular templates are not fully covered by the TS rules |
| `web/tools/web/check-lint-fixtures.mjs` | runs `npx eslint --no-ignore --format json <fixture>` for each fixture, compares the reported `ruleId` list with `web/tools/lint-fixtures/expected.json`, prints a PASS/FAIL table, exits non-zero on any mismatch (`--no-ignore` is required because the fixtures are in the config's `ignores`) |
| `web/tools/lint-fixtures/**` + `expected.json` | one directory per rule with a minimal violating file, e.g. `domain-imports-angular/episode-summary.ts`, `ui-injects-httpclient/episode-list.component.ts`, `any/cursor-page.ts`, `no-onpush/widget.component.ts`, `component-subscribe/episode-list.component.ts`, `bypass-security-trust/xss.ts`, `storage-outside-prefs/sidebar.component.ts`, `cross-feature-deep-import/series-page.ts`, `inline-handler/template.html` |

**Rule blocks (exact, per glob)**

| Glob | Rule | Value / message |
|---|---|---|
| `src/app/features/*/domain/**/*.ts` | `@typescript-eslint/no-restricted-imports` | forbid `@angular/*`, `rxjs`, `rxjs/*`, `@core/*`, `@features/*`, `@shared/api`, `@shared/ui/*`, `../data-access/*`, `../application/*`, `../ui/*`; message: "domain imports only its own files and @shared/util (D2)" |
| `src/app/**/ui/**/*.ts`, `src/app/**/*.component.ts` | `@typescript-eslint/no-restricted-imports` | forbid `@angular/common/http`, `@shared/api`, `**/data-access/**`, `**/application/**`; message: "ui takes inputs/outputs only (D2)" |
| same globs | `no-restricted-syntax` | `CallExpression[callee.name='inject'][arguments.0.name=/^(HttpClient\|.*Repository\|.*Store)$/]` → "ui must not inject a store/repository/HttpClient (D2)" |
| every file outside `src/app/**/data-access/**` and `src/app/core/**/data-access/**` | `@typescript-eslint/no-restricted-imports` | forbid `@shared/api`, `@shared/api/*`; message: "only data-access imports the generated client (D2/D5)" |
| per-feature blocks generated by a loop over `['public','auth','dashboard','series','episodes']` inside `src/app/features/<f>/**` | `@typescript-eslint/no-restricted-imports` | forbid `@features/<other>` deep paths (`@features/<other>/*`) for every other feature; the bare `@features/<other>` (its `index.ts`) stays allowed — "a feature imports another only through its index.ts (D2)" |
| all `src/**/*.ts` | `@typescript-eslint/no-explicit-any` (error), `@typescript-eslint/no-unsafe-*` (recommended-type-checked), `no-console` `['error', { allow: ['warn','error'] }]` | `any` is banned; the only allowed console methods are `warn`/`error` (dev diagnostics, D9) |
| all components | `@angular-eslint/prefer-on-push-component-change-detection` ⚠️; fallback selector `Decorator[expression.callee.name="Component"]:not(:has(ObjectExpression > Property[key.name="changeDetection"]))` under `no-restricted-syntax` | every component is `OnPush` (D2/D13) |
| components/`ui` | `no-restricted-syntax` → `CallExpression[callee.property.name='subscribe']` | "use `toSignal()` or `takeUntilDestroyed()` (D2)" |
| all `src/**/*.ts` | `no-restricted-syntax` → `MemberExpression[property.name=/^bypassSecurityTrust/]`, `Identifier[name=/^(eval|Function)$/]`, `CallExpression[callee.object.name='document'][callee.property.name='write']` | security bans (D2/D4) |
| all `src/**/*.ts` except `src/app/core/prefs/**` | `no-restricted-syntax` → `Identifier[name=/^(localStorage\|sessionStorage)$/]` | "browser storage only in core/prefs (D2/D6)" |
| all templates (`*.html`) via the angular-eslint template config | the **accessibility rule set** ⚠️ (alt text, form label association, `click` without keyboard handler, no positive `tabindex`) + `@angular-eslint/template/no-any`-style rules available in the installed major | D16 baseline basics fail lint, not review |
| `src/app/**/*.ts` where `track` matters | `@angular-eslint/template/forbid-... `? ⚠️ no such rule | **not expressible**: `@for` without `track` is caught by the compiler itself (Angular requires an explicit `track`) → no rule needed; recorded so nobody adds a fake one |

**Scripts** (`web/package.json`): `lint` = `ng lint && node tools/web/lint-forbidden-patterns.mjs && node tools/web/check-lint-fixtures.mjs` — one command, three checks, matching the single `lint` step the CI ruling prescribes; `lint:app` = `ng lint`; `lint:forbidden` = the HTML scan; `lint:fixtures` = the fixture matrix (all three are also individually runnable).

**CI.** `web.yml` (10.1.5-T1) runs `npm run lint`; nothing else changes there (the D15 step list is fixed by the ruling). `@typescript-eslint` requires type information: the flat config sets `languageOptions.parserOptions.projectService: true` (⚠️ or `project: ['tsconfig.app.json','tsconfig.spec.json']` for the installed version).

**Copy keys.** None — this task adds no UI. It does, however, gate the copy contract indirectly: none of its rules may be relaxed to accommodate a translation remark (D10 forbids hard-coded user-visible strings, and `no-console` keeps debug text out of the UI); any literal user-visible string in a template is caught by 10.2.5-T1's `i18n:check`, not here.

**a11y (D16).** This task is where the a11y baseline becomes enforceable: the template accessibility rule set fires on missing alt text, a form control without an associated label, a `click` without a keyboard handler and a positive `tabindex` — the same checks the axe run repeats at runtime (10.1.5-T1). Focus visibility, contrast and target size are theme/visual concerns (10.1.3-T1 + axe), and the `aria-live` requirement is review-level (no lint rule exists for "this progress region is announced").

**Performance.** Nothing runs at runtime; the guard is the boundary itself (a `ui` component cannot import the HTTP client, so an accidental request from a presentational component is impossible by construction). The fixtures are excluded from the app build (`tools/` is not part of `tsconfig.app.json`), so they add no bundle weight. The HTML scan is O(files) with no build step.

**Security.** The bans are the security surface of D2/D4: no `bypassSecurityTrust*`, no `[innerHTML]` in any template, no `eval`/`new Function`/`document.write`, no storage outside `core/prefs`, and `no-console` prevents dumping response payloads (D9's rule is "no content in logs"). The rule set must not be weakened by an inline `// eslint-disable` — the config sets `reportUnusedDisableDirectives: 'error'` and `linterOptions.noInlineConfig` is **not** enabled (a reviewed, justified disable must stay possible), so a disable comment is allowed but must be justified in review and turns up in the PR diff.

## Steps

1. Add the dev dependencies (`eslint`, `angular-eslint`, `typescript-eslint` — versions pinned exactly like the rest of the workspace) and write `web/eslint.config.js` with the blocks above; set `angular.json`'s `lint` target (`@angular-eslint/builder:lint`, `lintFilePatterns: ["src/**/*.ts","src/**/*.html"]`).
2. Run `npm run lint:app` on the clean workspace; fix every finding in 10.1.1-T1's code (expected: none, or a missing `track`/`OnPush` at most).
3. Write `tools/web/lint-forbidden-patterns.mjs` and run it against `src/**/*.html`.
4. Create the fixtures + `expected.json` and write `tools/web/check-lint-fixtures.mjs`; run `npm run lint:fixtures` and confirm each fixture fires exactly one rule (and that a clean control file fires none).
5. Add the three scripts to `package.json` and the combined `lint`; run the combined command twice (results identical — the fixture script is idempotent).
6. Record the directive list in the PR body (glob → rules) so 10.1.4-T1/10.1.6-T1 know which paths they must satisfy, and confirm `src/app/shared/api/**` is ignored before that code exists (add the generated directory to `.prettierignore`-free tooling? no: only `eslint.config.js` `ignores` + `angular.json` `lintFilePatterns` exclude it).

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| `@angular-eslint` rule name differs in the installed major | use the `no-restricted-syntax` fallback selector committed in the same file (documented next to the rule) and record the effective rule in the PR body |
| `projectService: true` unsupported by the installed `typescript-eslint` | fall back to `parserOptions.project: ['tsconfig.app.json','tsconfig.spec.json']`; if a file is not covered by either project, add it to `tsconfig.spec.json`'s `include` instead of disabling type-aware rules |
| A legitimate `.subscribe(` in a store | stores are exempt (only components/`ui` are banned); if a store needs a raw subscription, it uses `takeUntilDestroyed` from its own `DestroyRef` and the rule does not fire |
| A future shared helper needs `document`/storage | it must move to `core/prefs` or `core/dom` (a sibling `core` service) — the rule's message names `core/prefs`; changing the allow-list is a contract change (record it as a CR, do not edit the glob ad hoc) |
| `@shared/api` generated code violates the base rules | by design: the directory is ignored (D5); 10.1.4-T1 formats it and never hand-edits it |
| Fixture file accidentally included in the app build | fixtures live under `tools/`, outside `tsconfig.app.json`; the acceptance proves `dist` does not contain them |
| Lint becomes slow (> 2 min) | the fixtures are linted by an explicit file list, not by a directory glob, and type-aware rules run only over `src/**`; record the measured runtime in the PR |
