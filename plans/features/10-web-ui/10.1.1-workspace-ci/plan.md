## 3. Domain and data

No database, no server state, no HTTP in this folder. Client-side models/ports/signals:

- **No content model and no feature code here.** The `LegalDocument`/`LegalBlock` models, the build-time content pipeline and the public routes belong to **10.3.1-T1** (D12, TL ruling WR1) and are deliberately absent from this folder.
- **Preferences (the only persistence, D2/D6)** — `web/src/app/core/prefs/preferences.store.ts`: `PreferencesStore` (`@Injectable({ providedIn: 'root' })`) with signals `uiLanguage = signal<UiLanguage>('vi')` and `theme = signal<ThemePreference>('dark')`, methods `read(): void` (boot), `setLanguage(lang)`, `setTheme(theme)`; storage key `nts.prefs.v1` (JSON `{ uiLanguage, theme }`), read/write guarded by `try/catch` and by a `typeof localStorage !== 'undefined'` check (safe in any non-browser context). No content, no identifiers, no tokens.
- **No stores or repositories otherwise.** The first `data-access` port/repository pair arrives with 10.1.4-T1 (generated client) and 10.2.x.
- **Signal conventions pinned here** (so later tasks do not diverge): stores expose `readonly` signals + `computed`, async use cases return `Promise<Result<T>>`, no NgRx (D13); `AppError` never lives here (10.2.2-T1).
- **Build-time contracts produced here**: npm script names (§5 table), the nginx env list (`NTS_CSP_MEDIA_ORIGINS`, `NTS_API_UPSTREAM`, `NTS_HSTS`, `NTS_SPA_FALLBACK`), `web/nginx/templates/security-headers.conf.template` (all D4 headers except CSP; `NTS_HSTS` empty in dev → the header is omitted) with its start-up validator `web/docker-entrypoint.d/15-nts-validate-env.sh`, and the include contract for the generated CSP template (`dist/nginx/csp-headers.conf` → `/etc/nginx/templates/includes/csp-headers.conf.template` → `/etc/nginx/conf.d/includes/csp-headers.conf`, HTML locations only, WR2).

## 8. Security and privacy

- **Tokens**: none in this folder; D6 keeps the access token in a `SessionStore` signal (memory only) and the refresh cookie HttpOnly. Nothing here writes to `localStorage`/`sessionStorage` except `PreferencesStore` (`uiLanguage`, `theme` — no PII, no content, D6). No token, ticket or body may be logged (D5/D8) — the web server logs request lines only, and no token ever appears in a URL.
- **XSS / CSP / Trusted Types**: the built HTML must contain **no inline event handlers, no `javascript:` URLs and no unhashed inline `<script>`**; the nginx header set is D4's (`default-src 'none'`, `object-src 'none'`, `base-uri 'none'`, `frame-ancestors 'none'`, `require-trusted-types-for 'script'`, `trusted-types angular angular#bundler nts-sanitizer`, `angular#unsafe-bypass` **not** allowed); the generator that enforces this (`gen-csp`) and the e2e violation fixture are 10.1.6-T1's; templates render text only (`[innerHTML]` banned by lint).
- **Open redirect / navigation**: no redirect logic here; `returnUrl` validation is 10.2.1-T1.
- **Idempotency / ETag / caching**: no mutating call from this folder (idempotency keys 10.2.3-T1, `If-Match` 10.2.3/10.3.x); HTTP caching is limited to immutable hashed assets, and HTML is `no-cache` so a new deploy is picked up (D3).
- **Container hardening**: non-root (uid 101 from nginx-unprivileged), read-only root filesystem + no writable mounts, `autoindex off`, dotfiles denied, no `node_modules`/source maps/source in the runtime stage, no secret in the image or the Dockerfile (the four env vars are non-secret and injected at run time), no `nginx` `server_tokens` version leak (`server_tokens off`).
