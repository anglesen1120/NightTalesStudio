# 10.1.4-T1 — Generated API client (`npm run api:gen`) + import rule

| Story | Size | Area | Depends on | Blocks | Phase / flag |
|---|---|---|---|---|---|
| 10.1.4 | S (0.5) | FE | 10.1.1-T1, 10.1.2-T1, 09.1.5-T1, 09.9.5-T1 (soft) | 10.2.2-T1, 10.2.1-T1 | P · M1 |

## Goal

Make the frontend contract mechanically identical to the backend contract: `ng-openapi-gen` generates `web/src/app/shared/api/**` from the pinned CI artifact `openapi.json`, the generated tree is committed and excluded from lint, a CI step fails when regeneration produces a diff, an `openapi` guard test mirrors the backend's `ProblemDetails` gate, and an ESLint boundary keeps the generated client reachable only from `data-access` so no component can call an HTTP operation directly.

## Design

**Pinned spec + provenance.**

- `web/openapi.json` — the vendored copy of the 09.1.5-T1 `openapi` artifact, committed. Never hand-edited; when the artifact changes, it is replaced by `npm run api:gen:local -- <path>` and the regenerated tree is reviewed in the same PR.
- `web/tools/web/openapi.lock.json` — `{ "source": "artifact openapi (09.1.5-T1)", "specVersion": "<info.version>", "sha256": "<sha256 of openapi.json>" }`. The contract test recomputes the hash, so a silent edit of the spec (or of the lock) fails locally and in CI. ⚠️ `info.version` is asserted only for presence, not a specific value: 09.9.5-T1 tracks it.

**Generator config — `web/api-gen.config.json`**

```json
{
  "$schema": "node_modules/ng-openapi-gen/ng-openapi-gen-schema.json",
  "input": "openapi.json",
  "output": "src/app/shared/api",
  "indexFile": true,
  "services": true,
  "promises": false,
  "module": false,
  "serviceSuffix": "Client",
  "modelIndex": true,
  "enumStyle": "alias",
  "ignoreUnusedModels": false
}
```

The exact 1.1.0 schema supports these options; `templates` is a string custom-template directory, not a boolean, so it is omitted. Evidence: [ng-openapi-gen 1.1.0 README](https://raw.githubusercontent.com/cyclosproject/ng-openapi-gen/1.1.0/README.md) and [1.1.0 JSON schema](https://raw.githubusercontent.com/cyclosproject/ng-openapi-gen/1.1.0/ng-openapi-gen-schema.json). `services: true` preserves the generated tag-service surface; `promises: false` preserves Observable methods, and each data-access adapter uses `firstValueFrom` at its Promise port. `module: false` preserves standalone Angular output.

**Package scripts (`web/package.json`).**

```json
"api:gen": "ng-openapi-gen --config api-gen.config.json",
"api:gen:local": "ng-openapi-gen --config api-gen.config.json --input",
"api:check": "node tools/web/check-api-drift.mjs"
```

`api:gen:local -- <path>` regenerates from a local spec file (used to adopt a new artifact); `api:gen` regenerates from the committed `web/openapi.json`; `api:check` proves the committed tree matches the pinned spec.

**Drift + guard script — `web/tools/web/check-api-drift.mjs`** (no dependencies, Node 26, ESM) (10 CR-43):

1. Regenerates into a temp directory (`os.tmpdir()`), never touching the working tree.
2. Byte-compares every file against `web/src/app/shared/api/**`, reporting added/removed/changed files with the first differing line; exit 1 on any difference.
3. **Absolute-URL guard:** fails if any generated file contains an `http(s)://` literal (the SPA is same-origin, D3) — a spec whose `servers` would bake an origin must be fixed in 09.9.5-T1, not worked around here.
4. **Shape guard:** fails if `index.ts` does not export a `ProblemDetails` model (the type 10.2.2-T1's `AppErrorMapper` consumes).
5. Prints a one-line summary (`ok: N files` / `drift: M files`) so the `web.yml` log says which of the three checks failed.

**ESLint entries added to 10.1.2-T1's `web/eslint.config.js`** (additive; the file is 10.1.2-T1's, see `CR-2`):

- `ignores: ['src/app/shared/api/**']` — generated code is neither formatted nor linted by hand (D5) and is never patched.
- Boundary: only `features/*/data-access/**` and `core/**/data-access/**` may import `@shared/api` (message: "HTTP DTOs and clients are only reachable from data-access; map to a domain model and expose it through the domain port (D5)"). Test files are exempt (`**/*.spec.ts`) because specs are not part of the shipped bundle and must be able to assert the generated types.
- No other rule is relaxed: `any` stays banned everywhere outside the generated tree, and the Trusted Types bans include `bypassSecurityTrustResourceUrl` (**WR12**: it is what a `MatIconRegistry` SVG set would need, and the kit uses inline `<svg>` instead). The generated client adds **no DOM surface, no inline script and no icon registry**, so it cannot affect `csp:gen` or the TT allow-list (`angular`, `angular#bundler`, `nts-sanitizer` only).

**Generated surface.**

```
web/src/app/shared/api/
  models/            # ProblemDetails, EpisodeDetailDto, EpisodeListItemDto, … (C8, C14)
  services/          # <Tag>Client, one per OpenAPI tag, methods per operationId
  index.ts           # barrel: models + services
```

Generated code is committed, reformatted only by the generator, and never contains a token, an origin or an environment value. Base paths come from the spec (relative, `/api/v1/...`), and the Angular `HttpClient` is injected by the client — which is exactly why only `data-access` may touch it (D2).

**Deliberately not built here (no duplication, D5).** `If-Match`/ETag plumbing (`withIfMatch(etag)`, `readEtag(response)`) and the idempotency-key helper belong to `core/http/` and are owned by 10.2.1-T1 / 10.2.3-T1; this task only guarantees the generated types those helpers read (the ETag-bearing DTOs of C8/C14) are exported. Generated code holds no token, no cookie, no absolute origin and no environment value, and nothing in it is logged.

**Consumers.** 10.2.2-T1 (`AppErrorMapper` maps `ProblemDetails` → `AppError`), 10.2.1-T1 (`SessionStore`/interceptor use the auth clients), then every feature's `data-access` implementing its domain port. Domain ports are abstract classes; DTO ↔ model mapping is an explicit function per feature (00 §5.4) — **this task writes no mapper**.

## Steps

1. Add `ng-openapi-gen` pinned as a devDependency; run `npm ci` and confirm the published version matches FE12 (`../README.md:44`).
2. Vendor the artifact as `web/openapi.json` (download the `openapi` artifact, or produce it locally with the `--generate-openapi` fallback of 09.1.5-T1 `:63`), then write `web/tools/web/openapi.lock.json` with its SHA-256 and `info.version`.
3. Write `web/api-gen.config.json` and the four `package.json` scripts.
4. Run `npm run api:gen`; commit `web/src/app/shared/api/**` unchanged from the generator output.
5. Write `web/tools/web/check-api-drift.mjs` (regenerate-to-temp, byte compare, absolute-URL guard, `ProblemDetails` export guard, one-line summary).
6. Add the lint `ignores`, the `@shared/api` boundary and the spec-file exemption to `web/eslint.config.js` (CR-2), and add a fixture the boundary rule can be proven against (`web/tools/web/lint-fixtures/api-boundary/`, used by the lint script, not by the unit builder).
7. Write `web/src/app/shared/api-contract.spec.ts` — the compile-then-run smoke importing the barrel types this repo's other folders depend on.
8. Write `web/tools/web/check-api-drift.test.mjs` and `web/tools/web/openapi-contract.test.mjs` (see Tests).
9. Grep the whole `web/` tree for `@shared/api` and confirm every non-generated hit is inside a `data-access` folder or a `*.spec.ts` file; fix any other hit by moving the call into the feature's `data-access` (this is the migration step, not a follow-up).
10. Document in `web/README.md`: how to adopt a new artifact (`api:gen:local -- <path>` + review the diff), what `api:check` does, and that `src/app/shared/api/**` is generated and must never be edited by hand.
11. Verify the eager/lazy contract from the emitted build graph: the initial graph may contain only the minimal auth/session bootstrap client operations required by `SessionStore` restore (the explicit allowlist is `ApiConfiguration`, auth/refresh tag service and its DTOs, interceptor/session bootstrap); it must not contain unrelated feature tag services/operations, feature pages, SignalR, or heavy UI. Use Angular build stats/metafile import/chunk edges and the initial chunk list, not operation-name grep in minified output.

## Acceptance checks

- [ ] `npm run api:gen` on a clean checkout leaves `git status` clean (the committed tree equals the generator output for the pinned spec).
- [ ] `npm run api:check` exits 0 on the committed state and exits non-zero with a file-level diff summary when any generated file is mutated (proved by the drift test).
- [ ] `npm run api:check` fails with the absolute-URL message when a generated file contains `http(s)://`, and with the `ProblemDetails` message when the barrel stops exporting that model.
- [ ] `web/tools/web/openapi-contract.test.mjs` proves `.components.schemas.ProblemDetails` exists with `type`, `title`, `status`, `code`, `traceId` and optional `errors`, that every error response in the document references it (mirroring 09.9.5-T1 `:44,74`), and that the SHA-256 in `openapi.lock.json` matches `web/openapi.json`.
- [ ] `npm run lint` fails with the boundary message when a fixture component imports `@shared/api`, and passes for the same import from a `data-access` file and from a `*.spec.ts` file.
- [ ] `grep -rn "@shared/api" web/src --include=*.ts` returns hits only under `**/data-access/**` and `*.spec.ts` (plus the generated tree itself).
- [ ] The generated client is not blanket-absent from the initial graph: only the documented auth/session bootstrap allowlist is reachable eagerly; all unrelated feature operations/pages, optional SignalR, and heavy UI are behind named lazy boundaries. The check consumes emitted stats/metafile import/chunk edges and compares initial versus lazy entries; it does not rely on minified symbol names.
- [ ] The tag-service/Observable contract is observable: generated tag services are present, generated methods return `Observable`, and a data-access adapter proves `firstValueFrom` produces the domain `Promise` without exposing generated DTOs. `module: false` is confirmed in the generated output.
- [ ] Generator options are schema-validated against the pinned 1.1.0 sources above; unsupported options fail the config check rather than being silently ignored.
- [ ] `web/src/app/shared/api/**` is not linted or formatted by hand (`ignores` present) and no file in it carries a hand-written edit — the drift check is the proof.
- [ ] No generated file contains a token, a cookie name, an absolute origin or an environment host; the only base path is the relative `/api/v1/...` from the spec.
- [ ] No user-visible surface, therefore **no copy keys**: the drift script's output is developer-facing English and never rendered in the app; the `core`/`auth`/… i18n files are untouched by this task.
- [ ] No a11y impact: the generated tree renders nothing and adds no DOM; axe results on the existing routes are unchanged.

## Tests

`web/tools/web/check-api-drift.test.mjs` (Vitest, node env) — temp-dir fixtures: (a) identical trees → 0, no output diff; (b) one byte changed in a model → non-zero + that file reported; (c) one file removed → reported; (d) a fixture containing `https://api.example` → the absolute-URL guard fires; (e) an `index.ts` without `ProblemDetails` → the shape guard fires.

`web/tools/web/openapi-contract.test.mjs` — parses `web/openapi.json`: `openapi` starts with `3.1` (⚠️ version confirmed at implementation per 09.1.5-T1 `:83`), `.components.schemas.ProblemDetails` present with the five required properties and `errors` optional, every `4xx`/`5xx` response references `#/components/schemas/ProblemDetails`, every `$ref` resolves, and the lock hash matches.

`web/src/app/shared/api-contract.spec.ts` — imports `ProblemDetails` and the episode DTO types named in C8/C14 from the generated barrel and asserts the properties the wave-1 folders map (`status`, `etag`, `nextActions`, `renderJob`, `code`, `traceId`); this is the only test over generated code and its job is to fail loudly if a regeneration renames the import path the rest of the app relies on. It lives outside `shared/api/` on purpose — regenerating the output directory must not delete a hand-written spec.

**Deliberately not tested:** the generator's internals, generated method bodies, or the exact service method names (they change with the spec and are not part of our contract); the backend's `ProblemDetails` registration (09.9.5-T1 owns it).

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| `web/openapi.json` missing or unparsable | `api:check` exits non-zero before generating, naming the path; CI fails; no partially regenerated tree is left behind (work always happens in a temp dir) |
| The artifact lacks `ProblemDetails` (backend regression) | `api:check` shape guard + the contract test fail; the fix is in 09.9.5-T1/09.1.4-T1, never a locally patched spec |
| The spec carries an absolute `servers` URL | Absolute-URL guard fails and names the file; the SPA stays same-origin (D3) instead of silently switching origins |
| Generated diff is huge after an upgrade | Adopt it as one reviewed PR (spec + generated tree + lock together); reviewers check `ProblemDetails` and the DTOs the wave-1 screens map |
| A developer edits the generated tree by hand | The next `api:check` fails with the exact file and line; the fix is to fix the spec or the generator config |
| A spec imports `@shared/api` | Allowed by the spec-file exemption — otherwise every contract assertion would have to live in production code |
| Generator renames a model (e.g. a suffix change) | `api-contract.spec.ts` fails at compile time; the rename is adopted with the spec bump in one PR (the alternative — a hand-maintained type alias layer — is rejected: it re-introduces drift, F10) |
| Node 26 ESM/temp-dir behaviour differs on CI (10 CR-43) | The script uses only `node:fs/promises` and `os.tmpdir()` and is exercised by its own test, which runs in the same unit step as everything else in `web.yml` |
