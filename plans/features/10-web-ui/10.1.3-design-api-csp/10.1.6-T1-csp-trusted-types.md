## Goal

Make one XSS useless. After `ng build`, a build step hashes every executable inline script and writes **one** nginx header file for the CSP (WR2: nothing else, nothing committed), so the SPA is served with `default-src 'none'`, a hash-pinned `script-src 'self'`, `object-src 'none'`, `base-uri 'none'`, `frame-ancestors 'none'`, `connect-src 'self'` and `require-trusted-types-for 'script'`; the build **fails** on an inline event handler or a `javascript:` URL. Trusted Types are enforced with exactly one custom policy (`nts-sanitizer`, whose input is a closed block model, never user HTML), `bypassSecurityTrust*`/`[innerHTML]`/`eval` are lint-banned outside that one reviewed module, every Playwright spec installs a fixture that fails on any CSP or Trusted Types violation (the one deliberate-violation control uses its own `cspProbe` test, which opts out), and download names coming from the server are sanitised before they reach the filesystem.

## Design

**Header CSP emitted by the build (D4, normative — the string in the file is the contract):**

```
default-src 'none'; script-src 'self' 'sha256-…' 'sha256-…'; style-src 'self' 'unsafe-inline';
img-src 'self' data: ${NTS_CSP_MEDIA_ORIGINS}; media-src 'self' ${NTS_CSP_MEDIA_ORIGINS};
font-src 'self'; connect-src 'self'; manifest-src 'self'; worker-src 'self'; object-src 'none';
base-uri 'none'; form-action 'self'; frame-ancestors 'none';
require-trusted-types-for 'script'; trusted-types angular angular#bundler nts-sanitizer
```

This policy is the **only** thing the generated file contains: one `add_header Content-Security-Policy "…" always;` line (WR2.2). `${NTS_CSP_MEDIA_ORIGINS}` stays literal in the file so the image's envsubst fills it at container start. The four other D4 headers (`Referrer-Policy: no-referrer`, `X-Content-Type-Options: nosniff`, `Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=()`, `Cross-Origin-Opener-Policy: same-origin`) live in 10.1.1-T2's `web/nginx/security-headers.conf`, and because a `location`-level `add_header` cancels **every** inherited server-level one, each location that sets headers must `include` that file (HTML locations also the CSP template) — the container check asserts all headers on `/`, a deep client route and a hashed asset; the prerendered legal page is 10.3.1-T1's assertion (WR1) and lands with it. HSTS stays with the LB/API rule (09.9.4-T1) and is additionally set by nginx in Staging/Production — never duplicated into a location that would fight it. `web.yml` runs `build` + `csp:gen` for **validation only**; the artefact produced there is discarded (the image builds its own).

**`web/tools/web/gen-csp.mjs`** (Node 26, ESM, zero dependencies, deterministic) (10 CR-43):

1. Input root `dist/web/browser`; walk every `**/*.html`.
2. For each `<script>` **without** `src` and **without** `type="application/json"`: SHA-256 of the exact byte range, base64 → `'sha256-<hash>'`. Hashes are collected into a sorted set so re-running produces byte-identical output.
3. **Hard failures:** any `on[a-z]+=` attribute in an HTML file, any `javascript:` URL in `href`/`src`/`action`/`formaction`, or a `<script src>` that is not same-origin. Message names file + line + the offending snippet. No bypass flag exists.
4. Leaves `${NTS_CSP_MEDIA_ORIGINS}` **literal** in `img-src`/`media-src` (envsubst fills it in the container) and asserts the placeholder occurs exactly once per directive — the generator does **not** read the env var, because envsubst runs at container start, not at build time (WR2.1).
5. Writes **exactly one** file: `web/dist/nginx/csp-headers.conf`, i.e. outside the served `dist/web/browser` tree, containing the single line `add_header Content-Security-Policy "<policy>" always;`. No manifest, no second file, nothing committed (WR2.1).
6. Guards the produced file: fails if it holds more than one `add_header`, if it contains `unsafe-eval`, if `script-src` contains `unsafe-inline`, if it lacks `require-trusted-types-for 'script'` or any of the D4 directives, or if the CSP value exceeds 8 000 characters (proxy header limits); warns above 2 000.

**`web/src/app/core/security/nts-sanitizer.ts`** — `NtsSanitizer`, `@Injectable({ providedIn: 'root' })`:

```ts
export type LegalBlock = { kind: 'heading' | 'paragraph' | 'list' | 'quote'; text?: string; items?: readonly string[]; level?: number };

@Injectable({ providedIn: 'root' })
export class NtsSanitizer {
  toTrustedHtml(blocks: readonly LegalBlock[]): TrustedHTML;   // closed templates + escapeHtml on every field
  static readonly POLICY_NAME = 'nts-sanitizer';
}
```

The policy is created lazily through `window.trustedTypes.createPolicy(NtsSanitizer.POLICY_NAME, { createHTML })` and only when `trustedTypes` exists (jsdom in unit tests does not implement it — the spec injects a fake). There is deliberately **no** method that accepts a string of HTML: the only input is the closed block model produced by `tools/web/legal-to-json.mjs` (D12). It is unused in P (D4 `:129`) and exists so a future need has exactly one reviewed place; the escaping and the closed-template behaviour are unit-tested now.

**`web/src/app/shared/util/safe-filename.ts`** (D4 `:129`):

```ts

// NFC → drop quotes, /, \ and ".." sequences → drop C0/C1 control chars → collapse whitespace →

```

**`web/src/app/shared/util/download-blob.ts`** — `downloadBlob(blob: Blob, filename: string): void`: `URL.createObjectURL` → `a.download = safeFilename(filename)` → click → `URL.revokeObjectURL` in a `finally`. The only download path in the app; wave-2 download endpoints and any blob export must use it.

**Playwright fixture — `web/e2e/fixtures/csp.fixture.ts`** (composed with 10.1.5-T1's base fixture):

- The fixture installs a context-level listener before any page exists and attaches it to every current and newly created page (including pages opened by popups); it pushes only sanitized `{ violatedDirective, effectiveDirective, disposition, route, lineNumber }` records onto `window.__ntsCsp`. It never stores `blockedURI`, `sourceFile`, `sample`, raw URLs, query strings, fragments, userinfo, request bodies, or page text.
- A console listener records only CSP/Trusted Types diagnostics (not arbitrary console errors), sanitizing messages to a fixed category and route; `pageerror` is recorded only for a Trusted Types category. The afterEach failure contains directive/category/route/line only, with no token, cookie, body, URL, source path, sample, or secret-bearing console text.
- Deliberate violations run only in an isolated `cspProbe` test/context with the normal auto-fail fixture disabled for that probe; the positive probe serves an isolated response containing an inline `<script>` (not an undispatched `onclick`) and asserts one sanitized violation. Ordinary route specs never intentionally violate CSP.
- Exported as `test`/`expect` so `web/e2e/**` imports the instrumented test; the listener remains active across every existing and newly created page/context used by the suite.

**`web/e2e/security/routes.ts`** — `export const CSP_ROUTES: readonly string[]` — the shared route list each later feature appends to. It starts with the routes the container serves at this task's time (the shell/client fallback; the prerendered legal routes join when 10.3.1-T1 lands, login when 10.3.3-T1 lands). Because the fixture is attached to **every** spec, the runtime proof grows automatically with the app: the first page that renders Material or opens the hub is verified by construction, which is exactly how the `§8` risk "Trusted Types breaks a third-party library" is retired (D4 `:131`).

**Specs.** `web/e2e/security/csp.spec.ts` — for each route in `CSP_ROUTES`: assert the `Content-Security-Policy` response header contains `default-src 'none'`, `object-src 'none'`, `base-uri 'none'`, `frame-ancestors 'none'`, `connect-src 'self'`, `form-action 'self'`, `require-trusted-types-for 'script'` and `trusted-types angular angular#bundler nts-sanitizer`; assert it contains no `unsafe-eval` and no `unsafe-inline` inside `script-src`; assert the other four D4 headers are present **and are inherited in each location that sets one** (checked on `/`, a deep client route, and a hashed asset (the prerendered legal page joins with 10.3.1-T1, WR1), the asset without CSP); assert every inline `<script>` in the served document is covered by a hash in the header, the served header contains **no unresolved `${`** and no literal `NTS_CSP_MEDIA_ORIGINS` (an unset container env would otherwise leave the placeholder and silently drop every media origin), and `img-src` equals `'self' data:` + the configured origins (`document.querySelectorAll('script:not([src])')` count vs the hash count from the response header); run `@axe-core/playwright` with the WCAG 2.1 AA tags. `web/e2e/security/csp-negative.spec.ts` is the **positive control for the detector** — `page.route()` fulfils `/__csp-probe` with the real CSP header and a body containing a raw `onclick=` handler, and the spec asserts the fixture collected a violation (a second probe with a clean body collects none), so a dead listener fails the suite instead of passing silently. `web/e2e/security/trusted-types.spec.ts` — assert `window.trustedTypes !== undefined`, `trustedTypes.defaultPolicy === null` (nobody silently installed a default policy), that the allow-list is exactly `angular`, `angular#bundler`, `nts-sanitizer` (`policyNames()`), and that `nts-sanitizer` can be created and used once — the policy-creation probe runs in a scratch `page.evaluate` that does not keep state; assert `createPolicy('angular#unsafe-bypass')` and `createPolicy('angular#unsafe-jit')` **throw** (WR12), so an unsafe policy can never be reached. `web/e2e/security/csp-negative.spec.ts` — the detector's positive control, exported as its **own `cspProbe` test** (raw `@playwright/test`) that does **not** install the fixture's auto-fail `afterEach` (otherwise the deliberate violation would fail the spec proving the detector works; the fixture may alternatively expose an `expectViolations: true` mode). It fulfils `/__csp-probe` through `page.route()` with the real CSP header copied from the app response plus a body containing an **inline `<script>`** (blocked at parse time — a raw `onclick=` is not used as the trigger because Chromium enforces inline handlers only on dispatch, so a never-clicked probe would report nothing and the control would look dead), and asserts `window.__ntsCsp.length > 0` for the violating probe vs `0` for a clean probe with the same header.

**ESLint entries (additive, in 10.1.2-T1's config; CR-2 in `plan.md` §10).** `no-restricted-syntax` / `no-restricted-globals` for `document.write`, `eval`, `new Function`, `any`-argument `bypassSecurityTrust*` calls and any `[innerHTML]`/`[outerHTML]`/`[srcdoc]` binding, with the single `overrides` exemption for `src/app/core/security/nts-sanitizer.ts`. Proof lives in `web/tools/web/lint-fixtures/` (two files: one that must fail, one exempt that must pass) and is exercised by the lint run.

**Copy keys / a11y.** No user-visible surface: this task adds no copy key (nothing renders), no DOM and no interactive control, so the D16 baseline is unaffected — the CSP spec still runs axe on every visited route so a regression caused by the header set would be visible. The only user-visible artefact is the sanitised download filename, which is data (from `Content-Disposition`), not copy.

The isolated Playwright probe, not this node fixture set, proves runtime violation detection.

`web/e2e/security/csp.spec.ts` + `trusted-types.spec.ts` (Playwright, run by 11.5.1-T1's `e2e.yml` job `e2e` on `web/**`, **not** by `web.yml`) — header assertions per route, axe WCAG 2.1 AA, fixture silent, no `defaultPolicy`, policy probe; plus the header/inheritance assertions on the surfaces that exist, the no-unresolved-placeholder and `img-src` equality assertions, and the permanent **positive control** in `csp-negative.spec.ts` (its own `cspProbe` test without the auto-fail `afterEach`, `page.route()` serving `/__csp-probe` with the real CSP header plus an inline `<script>`, asserting the detector recorded a violation while a clean probe records none) — the control lives in the suite instead of a one-off PR note precisely because a detector-only spec passes when the listener is dead.

**Not tested here:** the nginx server block itself (10.1.1-T2), the API's own headers (09.9.4-T1 covers HSTS/nosniff/Referrer-Policy/VsFO on the API side), and any user-visible screen (none exists at this point).

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| A legitimate inline script appears in the output (e.g. a future analytics bootstrap) | The build hashes it automatically; if it is third-party, it must be self-hosted and hashed — never whitelisted with `unsafe-inline` or a CDN origin |
| An inline event handler or `javascript:` URL appears | Build fails with file + line; the fix is in the template; there is no bypass flag |
| `style-src 'unsafe-inline'` questioned again | Recorded risk (D4 `:127`): Material/Angular inject `<style>` at runtime and a static cached page cannot carry a nonce; markup injection is blocked by Trusted Types + the sanitizer ban. Revisit only if Angular ships hash-based style CSP for static output |
| A third-party library needs the `angular#unsafe-bypass` policy | Not allowed (D4 `:129`). The fix is to call the library without string HTML or to drop it; the fixture fails the run until then |
| Material or SignalR logs a Trusted Types violation on first use | The CSP fixture fails the owning spec immediately — before feature work continues (the point of landing this task first) |
| A new media origin is needed (e.g. the object store for playback) | Add it to `NTS_CSP_MEDIA_ORIGINS` in the container env; never widen `img-src`/`media-src` to `*` |
| The hub fails to connect under `connect-src 'self'` (D4 ⚠️ `:127`) | Add `wss://<host>` (the same origin) to `connect-src`; `connect-src` is never set to `*`. The container e2e is the proof |
| jsdom has no `trustedTypes` | `NtsSanitizer` creates the policy lazily and the spec injects a fake; production code never assumes the API exists, but the CSP still enforces it in the browser |
| The CSP header grows past proxy limits | The 8 000-character guard fails the build; the fix is fewer inline scripts (prefer external), not a shorter policy |
| A dev runs `ng serve` (no nginx, no CSP) and sees no violation | Expected and documented: the CSP is a container/header feature; the runtime proof is the container e2e, never a dev-only `meta` tag |
| `NTS_CSP_MEDIA_ORIGINS` is malformed by hand in a compose file | The generator only asserts the literal placeholder; envsubst cannot validate, so **10.1.1-T2's entrypoint** rejects a value containing `;`, `"`, `'` or inner whitespace at start (CR-1d/WR13) — otherwise a `;` would inject a directive into the header |
| `NTS_CSP_MEDIA_ORIGINS` is **unset** in the container env | `Dockerfile`/compose define `ENV NTS_CSP_MEDIA_ORIGINS=""` (WR13). An unset variable is not substituted by envsubst, so the literal `${NTS_CSP_MEDIA_ORIGINS}` survives and nginx dies with `unknown "nts_csp_media_origins" variable` (or the header ships a placeholder token) — the entrypoint fails fast with an actionable message instead, and the empty case is asserted (`img-src 'self' data:`) |
| Someone moves HSTS or the four non-CSP headers into the CSP file or the CSP file is expected to carry them | HSTS lives in 10.1.1-T2's templated `security-headers.conf` (`NTS_HSTS`, empty in Development) and the four other headers live in the same file (WR13/WR2.2); the generated file has exactly one `add_header` and the four-surface curl check catches a duplication or a loss |
| `optimization.styles.inlineCritical` is turned on by a later change | The injected `onload` handler makes `csp:gen` fail the build (WR12/CR-5) — a loud failure by design, fixed in `angular.json`, never by whitelisting inline handlers |
| A location shows the CSP but loses `nosniff`/`Referrer-Policy` | Location-level `add_header` cancelled the inherited server-level ones (WR2.3): that location must `include` `web/nginx/security-headers.conf` too; the four-surface curl check is what makes this visible |
| The template path in the Dockerfile is wrong or the file is not copied | The image starts but serves HTML with no CSP; the four-surface e2e fails on the missing header — never on a silent pass, because the header is asserted positively |
| `csp:gen` is run only after the image build | The image would ship without the CSP: `csp:gen` belongs to the builder stage before the image layer is created (WR2.1); `web.yml`'s independent `build` + `csp:gen` run is validation, not the artefact source |

## Notes

- **Produces:** the CSP generator + the single nginx CSP artefact, the sanitizer module, the download-name utilities, the instrumented Playwright fixture, the `cspProbe` control and the two security specs. **Consumes:** 10.1.1-T2's nginx server block/templates (container, `include` points, `NTS_HSTS`, env default and validation), 10.1.2-T1's ESLint config, 10.1.5-T1's Playwright config/base fixture and `web.yml`. **Blocks:** 10.3.1-T1 (legal-page header assertion lands with it) and 10.3.3-T3 (`safeFilename` consumer — **WR5**).
- **Reuse:** `safeFilename`/`downloadBlob` are the single download path for wave 2 and S; `nts-sanitizer` is the single reviewed HTML-producing module for D12's legal blocks; the CSP fixture is shared by every spec instead of each spec re-implementing violation detection.
- **Cross-file needs:** `CR-1` (WR2: builder-stage `csp:gen`, template copy + envsubst, per-location includes, malformed-env rejection, the four-surface check) in `plan.md` §10; `CR-2` (ban entries + the one exemption) with 10.1.2-T1; `CR-4` (`e2e.yml` **must trigger on `web/**`** and runs the suite; the deploy workflow must not add a separate `csp:gen` step) with 11.5.1-T1; `CR-5` (`optimization.styles.inlineCritical: false` in `angular.json`) with 10.1.1-T1.
- **Open items carried from `plan.md` §10:** `O-A` the CAPTCHA provider's script origin — if 10.3.3-T1 needs a remote vendor script, that is a separate reviewed exception to `script-src`/`trusted-types` (never `unsafe-inline`); `O-F` the `connect-src 'self'` + `wss://` proof, closed by this task's container run.
- **CI ownership:** `web.yml` (10.1.5-T1) runs `build` + `csp:gen` for **validation only** and does not start compose or run Playwright; the runtime proof is 11.5.1-T1's `e2e.yml` job `e2e`, whose path filter must include `web/**` or the check never runs on a web-only PR.
- **Ownership:** this task does **not** create `web/playwright.config.ts` or the base fixture (10.1.5-T1), does not touch the nginx server block or the Dockerfile (10.1.1-T2 — CR-1), and does not add a `web.yml` step list of its own (10.1.5-T1 owns the file).
- **Probe design note.** The control deliberately does *not* reuse the auto-fail fixture: a spec that installs it and then provokes a violation would fail itself, so `csp-negative.spec.ts` exports its own `cspProbe` test (or uses the fixture's `expectViolations: true` mode) and triggers the block with an inline `<script>` rather than `onclick=` — Chromium enforces inline handlers only on dispatch.
- **Deliberate omissions:** the prerendered legal page's header assertion is 10.3.1-T1's (it owns those routes, WR1) and lands with it; nothing generated is committed and there is no drift check for it (WR2.1 — it is build output, unlike the API client of 10.1.4-T1); no nonce plumbing (impossible on static prerendered output, F01), no SSR server, no CSP report endpoint in P (the fixture is the detector; a `report-uri` would need a collector owned by 12), no dev-only `meta` CSP.
- **QA fixes (2026-10-04).** D1: `ng serve` ignores `deployUrl`, so with no `<base>` the SPA did not boot on nested routes in dev; the `development` build configuration now sets `baseHref: "/"` (dev sends no CSP; the production document still has no `<base>`), proven by `e2e/deep-link.spec.ts` on both targets. L3: the static scan decodes entities and strips tab/newline before the `javascript:` check and also rejects external `<link rel=stylesheet|modulepreload>` and `<meta http-equiv=refresh>` with `javascript:`.
