## 3. Domain and data

Client-only: this folder owns three small client-side models plus one generated type surface. Nothing here persists server state, and nothing here may touch `localStorage`/`sessionStorage` outside `core/prefs` (D2).

**Theme model.** Tokens are CSS custom properties defined once in `web/src/app/shared/ui/theme/`:
- `_tokens.scss` → `:root, [data-theme='dark']` and `[data-theme='light']`; groups `--nts-color-{bg,surface,surface-variant,on-surface,primary,on-primary,outline,error,warn,success,focus}`, `--nts-space-{1..8}` (4 px base), `--nts-radius-{sm,md,lg}`, `--nts-elevation-{1,2,3}`, `--nts-font-{sans,mono}`, `--nts-type-{display,title,body,label,caption}-{size,line,weight}`.
- `_theme.scss` → builds the Angular Material M3 theme from those values (`mat.theme(...)`/`define-theme` ⚠️ exact SCSS API of Material 22.2 to confirm at implementation), dark as the default `$type`, light emitted under `[data-theme='light']`.
- `_typography.scss` → `@font-face` from `@fontsource/be-vietnam-pro` (400/500/600, subsets `latin`, `latin-ext`, `vietnamese`, `font-display: swap`, `font-family: 'Be Vietnam Pro'`); **no** Google Fonts/CDN request (D11), which is why `style-src` may stay `'self' 'unsafe-inline'` and `font-src 'self'`.
- `web/src/styles.scss` imports the three partials in that order.

**Theme state (port).** `web/src/app/core/prefs/theme.store.ts` — `ThemeStore` (`@Injectable({ providedIn: 'root' })`), signal `theme: Signal<'dark' | 'light'>` (default `'dark'`), `init()` (in `provideAppInitializer`) reading the persisted preference and applying `document.documentElement.dataset['theme']`, `setTheme(t)` writing the preference through the `core/prefs` storage port only. The kit components read tokens through CSS, never through a `.ts` colour table, so a theme switch needs no component re-render beyond the attribute.

**Generated API surface.** `web/src/app/shared/api/` (generated, committed, lint-ignored, D5): one client per tag, `ProblemDetails` and every DTO as a class/interface, barrel `index.ts`. `web/openapi.json` is the pinned vendored artifact of the 09.1.5-T1 `openapi` artifact; its provenance (`specVersion` + SHA-256) lives in `web/tools/web/openapi.lock.json`, re-checked by the contract test so a hand-edited spec fails locally and in CI. **This folder writes no mapper**: `features/*/data-access/**` owns DTO ↔ domain mapping (D5, 00 §5.4).

**Sanitizer port.** `web/src/app/core/security/nts-sanitizer.ts` — `NtsSanitizer` (`@Injectable({ providedIn: 'root' })`), `toTrustedHtml(blocks: readonly LegalBlock[]): TrustedHTML` where `LegalBlock = { kind: 'heading' | 'paragraph' | 'list' | 'quote'; text?: string; items?: readonly string[]; level?: number }` (the D12/`legal-to-json.mjs` block shape). Implementation: a closed set of templates, every text field through a local `escapeHtml()`, then `trustedTypes.createPolicy('nts-sanitizer', { createHTML })`. **User text never becomes HTML**: there is no `innerHTML` API on this service. Currently unused (D4 `../README.md:129`); it exists so a future need has exactly one reviewed place, and it is unit-tested now.

**Pure util.** `web/src/app/shared/util/safe-filename.ts` — `safeFilename(raw: string, fallback?: string): string` (D4 `:129`): NFC-normalise, drop `"`/`'`/`/`/`\`/`..`, drop C0/C1 control characters (0x00–0x1F, 0x7F), collapse whitespace to a single space, trim, truncate to **100** characters, fall back to `fallback ?? 'download'` when the result is empty or only dots. Companion `web/src/app/shared/util/download-blob.ts` — `downloadBlob(blob: Blob, filename: string): void` (createObjectURL → `a.download = safeFilename(filename)` → click → revoke), the only download path in the app.

**Signals summary.** `ThemeStore.theme` (root, session-independent); no other signal store in this folder. The kit is presentational: inputs/outputs only, no injected store, no `HttpClient` (D2 `:110`).

## 4. Use cases

**U1 — Render any screen's shell states (10.1.3).** *As a developer I want one kit so that 10 screens do not invent 10 empty states.*
- Given a feature page, When it renders `PageHeader` + one of `LoadingState`/`EmptyState`/`ErrorState`, Then the visual and a11y behaviour is identical everywhere; the page passes only inputs (title key, message key, action label) and handles one output.
- API calls: none. States: `loading` (skeleton rows, `aria-busy="true"`), `empty` (title + body + optional action), `error` (title + body + `Retry` action + `traceId` line when the caller passes one), `ready` (content projected).
- Errors: `ErrorState` renders only already-mapped copy (`errors.<code>` from D9/10.2.2-T1); it never receives raw `ProblemDetails.detail` (D9 `:159`).

**U2 — Confirm a destructive action, in both languages (10.1.3).**
- Given `ConfirmDialog.confirm({ titleKey, bodyKey, confirmLabelKey, destructive })`, When the user opens it, Then focus moves into the dialog, `Escape` cancels, focus returns to the trigger, and the confirm button is the only primary action; the `cost-line` slot is projected when the S caller provides one and is absent in P (D14).
- States: idle → open → confirmed/cancelled; while an async confirm is pending the confirm button shows a spinner and is disabled (no double submit).

**U3 — Regenerate and verify the typed client (10.1.4).**
- Given the pinned `web/openapi.json`, When `npm run api:gen` runs, Then `web/src/app/shared/api/**` is rewritten in place and `git diff` is either empty (up to date) or a reviewable change; `npm run api:check` (re-generate into a temp dir + byte compare) fails with a diff summary when the committed tree is stale.
- Given a feature developer, When a file outside `data-access` imports `@shared/api`, Then `npm run lint` fails with the boundary message (D2/D5).
- Errors: missing `web/openapi.json` → non-zero exit with an actionable message; the pinned spec lacking `.components.schemas.ProblemDetails` → the contract test fails (mirrors the 09.9.5-T1 `jq -e` gate).

**U4 — Build, serve and prove the page cannot run injected script (10.1.6).**
- Given `npm run build` then `npm run csp:gen` in the builder stage, When the container serves an HTML response, Then the CSP from D4 is present as a **header** (never a meta tag: `frame-ancestors`/`base-uri` are ignored in `meta`), `require-trusted-types-for 'script'` is active, the allow-list is exactly `angular`, `angular#bundler`, `nts-sanitizer` (WR12 — `angular#unsafe-bypass`/`angular#unsafe-jit` must not be creatable), and the non-CSP headers are still inherited in every location that sets one (WR2.3); a Playwright run fails if any page logs a `securitypolicyviolation` event or a console CSP/Trusted Types error (fixture owned here), and a positive-control spec fails if the detector is dead.
- Given `dist/web/browser/**/*.html` containing an inline `onclick=` attribute or a `javascript:` URL, When `gen-csp.mjs` runs, Then the build fails with the file and line.
- Given a download whose server filename is `../"hack\n.mp4`, When the client saves it, Then the name is sanitised by `safeFilename` (no separators, no quotes, no control characters, ≤ 100 chars) — unit-tested in P; the download screens are wave 2.

## 5. API and events

**Routes consumed by this folder: none.** U3 consumes a build artifact (`openapi.json`), not HTTP. The generated client exposes the API surface for other folders; this folder calls nothing.

**Artifact consumed.** `openapi` (09.1.5-T1 `:41-42`) → vendored as `web/openapi.json`; the `ProblemDetails` component (`type, title, status, code, traceId, errors?`) must be present (09.9.5-T1 `:9,44,74`).

**Events: none subscribed, none emitted.** No SignalR, no polling, no timers in this folder.

**Constraints this folder imposes on the consumers (checked by its tests, D4/F02/C6).**
- All app HTTP is same-origin and relative (`/api/v1/...`, `/hubs/episodes`) because `connect-src 'self'` — a future absolute base URL breaks the app, not just the CSP.
- `connect-src 'self'` is expected to cover the hub over `wss://<same host>` ⚠️ (D4 `:127`); the CSP e2e asserts a hub-served page connects with no violation; if a browser refuses, the fix is adding `wss://<host>` to `connect-src`, never dropping `connect-src` to `*`.
- Third-party media comes only from `NTS_CSP_MEDIA_ORIGINS` (container env) in `img-src`/`media-src`; the SPA never inlines remote scripts.
- `form-action 'self'` — no form may post to an external origin.
- No vendor script on any wave-1 page (media/playback is wave 2, D12 forbids third-party assets on legal pages). ⚠️ [OPEN] the CAPTCHA provider (10.3.3-T1, only after `captcha_required`) may need a `script-src` origin + a TT allowance; that is a separate reviewed exception, tracked in §10.

## 7. Jobs and integrations

**No runtime jobs, no realtime, no polling, no timers** (D17 `:190` lists the only two pollers in wave 1, neither here).

**Build steps owned here** (npm scripts added to `web/package.json` / `package-lock.json`; the file is 10.1.1-T1's, this folder adds only the scripts).
1. `npm run api:gen` → `ng-openapi-gen --config api-gen.config.json` (input `web/openapi.json`, output `src/app/shared/api`, committed).
2. `npm run api:check` → `node tools/web/check-api-drift.mjs` (generate to a temp dir, byte-compare against the committed tree and against the `specVersion`/SHA-256 recorded in `web/tools/web/openapi.lock.json`, print the first differing file).
3. `npm run build` → `ng build` (10.1.1-T1 owns `angular.json`).
4. `npm run csp:gen` → `node tools/web/gen-csp.mjs` (**WR2**; tool name from D4, npm script name from the ruling): run in the web image **builder stage right after the build** (`npm run build && npm run csp:gen`). It hashes every executable inline `<script>` in `dist/web/browser/**/*.html` (SHA-256, base64) skipping `type="application/json"` blocks, **fails** on an inline `on*=` handler attribute or a `javascript:` URL, and writes **exactly one** file — `web/dist/nginx/csp-headers.conf`, i.e. **outside** the served `dist/web/browser` tree — containing exactly one line: `add_header Content-Security-Policy "<policy>" always;` with `${NTS_CSP_MEDIA_ORIGINS}` left **literal** for the image's envsubst at container start. The runtime stage copies it to `/etc/nginx/templates/includes/csp-headers.conf.template`. Nothing generated is committed and no drift check exists for it (it is build output). `csp-hashes.conf` is dropped: no consumer.
5. `npm run e2e` → Playwright (config + base fixture from 10.1.5-T1; the CSP fixture from this folder).

**CI wiring (TL ruling 2026-09-24, `../README.md` D15 `:182`).** `web.yml` (10.1.5-T1) runs: `npm ci` → lint → i18n key-set check → `api:check` (drift) → unit tests → `npm run build` → gzip budget → `npm run csp:gen`. There, `build` + `csp:gen` are **validation only** (they fail on an inline handler or a `javascript:` URL); the artefact produced in CI is discarded. **`web.yml` does not start compose and does not run Playwright.** The Playwright suite lives in `web/e2e/` and is executed by 11.5.1-T1's `e2e.yml` job `e2e` (trigger `web/**`), which starts the compose stack. This folder's `csp:gen` step is therefore the last gate `web.yml` can enforce alone; the CSP/Trusted Types *runtime* proof is the container run in `e2e.yml`, whose path filter **must include `web/**`** or the check never runs on a web-only PR (CR-4).

**nginx `add_header` inheritance (WR2.3, stated explicitly because it silently drops headers).** An `add_header` inside a `location` cancels **every** inherited server-level `add_header`. Therefore each location that sets headers must `include` `web/nginx/security-headers.conf` (10.1.1-T2's file, the four non-CSP headers), and each HTML-serving location must additionally `include` the CSP template. The container check asserts **all** D4 headers on `/` (client fallback), a deep client route and a hashed asset (the asset gets the non-CSP headers but **no** CSP — assets are not HTML). The **prerendered legal page** joins that list only once 10.3.1-T1 lands (it owns those routes, WR1) and 10.3.1-T1 adds that assertion with its own check — no prerendered route exists at 10.1.6-T1 completion.

**Dev/prod parity.** Header injection is done by nginx in the container (10.1.1-T2); `ng serve` (10.1.1-T1) has no CSP, so a violation is only observable through the container/e2e path — stated in the task's failure table rather than worked around with a dev-only meta tag.

## 8. Security and privacy

- **CSP (D4 `:124`, [DECISION] O4; artefact flow per WR2).** Emitted as one `add_header Content-Security-Policy "<policy>" always;` line in `web/dist/nginx/csp-headers.conf` → `/etc/nginx/templates/includes/csp-headers.conf.template` in the image, with `${NTS_CSP_MEDIA_ORIGINS}` filled by envsubst at container start. The policy on every HTML response: `default-src 'none'; script-src 'self' <hashes>; style-src 'self' 'unsafe-inline'; img-src 'self' data: ${NTS_CSP_MEDIA_ORIGINS}; media-src 'self' ${NTS_CSP_MEDIA_ORIGINS}; font-src 'self'; connect-src 'self'; manifest-src 'self'; worker-src 'self'; object-src 'none'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'; require-trusted-types-for 'script'; trusted-types angular angular#bundler nts-sanitizer`. Hash-based, not nonce-based, because public pages are prerendered and cached (F01, FE7). `style-src 'unsafe-inline'` is an accepted risk: Material/Angular inject `<style>` at runtime and a static cached HTML cannot carry a nonce; CSS injection requires markup injection, which Trusted Types + the sanitizer ban block. Inline **styles** are therefore never hashed (O4); inline **scripts** always are. envsubst cannot validate its input, so the media-origin value must be rejected by the container when malformed (`;`, `"`, `'` or inner whitespace) — CR-1, because a `;` there would inject a directive. Revisit if Angular ships hash-based style CSP for static output.
- **Trusted Types.** `angular#unsafe-bypass` is **not** allow-listed; `bypassSecurityTrust*` is lint-banned outside `core/security/nts-sanitizer.ts`; the allow-list is exactly `angular`, `angular#bundler`, `nts-sanitizer` (**WR12**), the only custom policy is `nts-sanitizer` (closed block model, never user HTML), and the spec asserts `angular#unsafe-bypass` and `angular#unsafe-jit` **cannot be created** — no `MatIconRegistry` SVG set is used anywhere (it needs `bypassSecurityTrustResourceUrl`), because every icon is an inline-`<svg>` component from 10.1.3-T1.
- **Other web headers (D4 `:130`, WR2.2).** `Referrer-Policy: no-referrer`, `X-Content-Type-Options: nosniff`, `Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=()`, `Cross-Origin-Opener-Policy: same-origin` — all four live in 10.1.1-T2's `web/nginx/security-headers.conf`, **not** in the generated CSP file (one `add_header` source each); HSTS is set by 10.1.1-T2's `security-headers.conf`, which is a **template** carrying `NTS_HSTS` (empty in Development) — **WR13**; the API side keeps its own HSTS rule (09.9.4-T1 `:86,147`). `X-Frame-Options: DENY` is 09.9.4-T1's on the API side; the SPA's equivalent is `frame-ancestors 'none'`.
- **Tokens.** Nothing in this folder stores, logs or places a token in a URL (C1); the generated client carries no `withCredentials` (same origin, D6) and no token value. The client must never be constructed with a token baked into a base URL string that ends up in a log or a shareable link.
- **XSS surface.** Story/legal text is rendered by interpolation and `@for` (D12/D18), keywords are plain chips, and the editor never uses Markdown. `innerHTML`, `document.write`, `eval`, `new Function` are lint-banned (D2 `:113`).
- **Downloads.** `Content-Disposition` names arriving from the server are treated as untrusted: `safeFilename` before `a.download`, which stops header/name injection, path traversal and control characters (D4 `:129`). The util is the single implementation; a second download path is a review failure.
- **Privacy / no content in storage or logs.** No story text, legal text, token, `ProblemDetails` body or personal data in `localStorage`/`sessionStorage` (D2/D18, F25) — the kit persists nothing but the theme preference through `core/prefs`; no `console.log` of API payloads; `traceId` is displayed, not logged with the body.
- **Open redirect.** Not applicable here (no navigation from untrusted input); the theme preference is a closed enum, validated on read.
