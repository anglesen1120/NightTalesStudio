**Specs** (`web/e2e/a11y/`, picked up by the existing `testDir: './e2e'`; no `playwright.config.ts` change):
1. `axe-matrix.spec.ts` — AE-1: for each `auth: 'none'|'owner'` row, vi+en, dark+light, `expectA11yClean(page, { tags: WCAG22_TAGS, label: row.name })`; CSP fixture installed; `<html lang>` asserted.
2. `keyboard.spec.ts` — AE-2 (UC-2): skip link first on authenticated pages; a recorded tab path per route that reaches every control in `states`; dialogs trap + `Escape` restores focus to the invoker; focus never lands on `document.body`; every table header toggles `aria-sort`.
3. `states.spec.ts` — AE-3 (UC-3): `page.route` stubs for the codes above; each renders its `errors.<code>` copy inside a live region; `unknown_error` shows `traceId`; focus is never moved by a toast/poll update.
4. `zoom-motion.spec.ts` — AE-4 (UC-5): 200 % zoom (640×512 CSS px, `deviceScaleFactor: 2`), `page.emulateMedia({ reducedMotion: 'reduce' })`, 360 px, no clipping, no obscured focused control, no horizonal scroll (`document.scrollingElement.scrollWidth <= clientWidth` at 360 px).
5. `axe-error-copy` unit spec — AU-1 under `web/src/app/core/errors/a11y-error-copy.spec.ts`, Vitest + jsdom, reading `web/src/assets/i18n/errors/{vi,en}.json` directly (no TestBed tree; `ZONELESS_TEST_PROVIDERS` not needed).

**Manual script (`a11y-manual-matrix.md`, new, in this folder)** — one block per route row with the SD12 criteria as columns (UC-4/UC-5/UC-7), the SR tool + version, and `Verified by/date`. Screen reader (name/role/value), dragging alternatives, redundant entry and 24 px target size are **manual-only** because axe cannot cover them (FC9); the CAPTCHA iframe interior is manual-only (FC16) with the fallback path recorded if the vendor widget is not keyboard-usable (`[OPEN]` A10-2).

**Copy.** No new key is introduced by this task. The unit spec enumerates the codes from `../README.md:613-634` plus SD13 (`:679`) — `captcha_required`, `captcha_invalid`, `breached_password`, `forbidden`, `reauth_required`, `legal_acceptance_required`, `rate_limited`, `unknown_error`, `insufficient_credits`, `spend_cap_reached`, `promo_invalid`, `promo_expired`, `promo_exhausted`, `promo_already_used`, `refund_not_eligible`, `payment_invalid_state`, `payment_expired`, `account_under_review`, `age_attestation_required`, `setting_change_pending`, `owner_action_pending`, `setting_change_not_pending` — and asserts `errors.<code>` exists in **both** vi and en; a missing key is reported against SD13's owner, never added here.

**a11y of the audit itself.** The specs contain no product DOM; the canary that proves `expectA11yClean` still detects a violation stays the wave-1 `setContent` self-proof. No `disableRules`, no `exclude` unless the wave-1 fixture already excluded that subtree and the exclusion is documented in the matrix row.

**i18n.** vi is asserted first (default locale) and `en` second for every row; the matrix records both columns, and a string that overflows its control at 1280 px in either language is a finding against the screen's owner.

3. Append the new routes to `CSP_ROUTES` (`web/e2e/security/routes.ts`) via `CSP_ROUTES_EXTRA`; confirm the existing CSP spec covers them without a config change.
4. Write `axe-matrix.spec.ts`, `keyboard.spec.ts`, `states.spec.ts`, `zoom-motion.spec.ts` with `test.describe.serial`, `workers: 1` inherited from the config, and `test.use({ trace: 'off', video: 'off' })` on authenticated specs (WR14).
5. Write `web/src/app/core/errors/a11y-error-copy.spec.ts` (AU-1) and run it under Vitest.
6. Open `a11y-manual-matrix.md` and fill the T1 blocks by hand against the running stack in dark+light, vi+en, 360/768/1280.
7. Run the whole folder green, then every recorded finding: `[OPEN]` row (rule id, route, node, owning task) or fixed by its owner.
8. Re-run after each owner fix; the red row must flip without touching a screen here.

## Acceptance checks

- **Given** the compose stack, **when** `npm run e2e -- a11y` runs, **then** every `auth: 'none'|'owner'` matrix row passes axe with `wcag2a, wcag2aa, wcag21a, wcag21aa, wcag22aa` in vi and en, dark and light, and the CSP fixture reports no violation on any of them.
- **Given** any of those pages, **when** only the keyboard is used, **then** the first `Tab` on an authenticated page focuses the skip link, every control in that row's `states` is reachable and operable, dialogs trap and restore focus, and no dialog leaves focus on `document.body`.
- **Given** `captcha_required`, `breached_password`, `rate_limited` and `unknown_error`, **when** they are provoked, **then** each renders its `errors.<code>` copy inside `aria-live="polite"`/`role="status"`, `traceId` appears on `unknown_error`, and the widget is revealed only for `captcha_required`.
- **Given** 200 % zoom, 360 px width, `prefers-reduced-motion: reduce` and both themes, **when** each page renders, **then** no content is clipped, no focused control is obscured, no horizontal scrollbar appears, and no non-essential animation plays.
- **Given** the vitest spec, **when** it runs, **then** every code listed in `## Design` resolves to a key in both `web/src/assets/i18n/errors/vi.json` and `en.json` (or the missing key is reported against SD13's owner).
- **Given** the wave-1 and wave-2 suites, **when** they run after the fixture change, **then** they are unchanged and still green (the default tag set did not move).
- **Given** `a11y-manual-matrix.md`, **when** the audit closes, **then** every T1 row has a `Verified by/date` entry or an `[OPEN]` row with an owning task id.

## Failure handling and edge cases

| Case | Handling |
|---|---|
| A page needs the CAPTCHA iframe audited inside | Out of axe's reach (cross-origin, FC16): the row gets `manualOnly: ['captcha-iframe']`, the container's accessible name + `aria-live` countdown + fallback path are asserted in `states.spec.ts`, and the interior is a manual matrix entry — never an `exclude` that silently hides a real violation. |
| The vendor widget is not keyboard-usable | Record the documented fallback (the API's e-mail/OTP-free path, SD15/`[OPEN]` A10-2) in the matrix and report it to ST-2's decision owner — do not patch the vendor from here. |
| A route is unreachable without a role the fixture lacks (admin-only path inside a T1 route) | T1 does not add an admin fixture; the row is `auth: 'none'|'owner'` only and the admin-side check belongs to T2. |
| Prerendered pages have no live API | The rows run against the served prerendered HTML with hydration; states that need an API are stubbed with `page.route` — never by disabling hydration. |
| A violation's fix would change a screen | Report `[OPEN]` with the owning task id; the screen's owner fixes it. This task never edits a product component, style or copy key. |
| axe version bump changes rules | `package-lock.json` pin (10.1.1-T1); a new rule that fires is a finding, never a `disableRules` entry. |
| Flaky focus assertions | Assert on `document.activeElement`'s role/name (not on a CSS class), and use `expect.poll` on the focus assertion instead of a timeout; `waitForTimeout` stays banned (WR14). |
| `en` strings overflow a control at 1280 px | Finding against the screen's owner, recorded with the overflowing key; not fixed by shrinking from here. |
