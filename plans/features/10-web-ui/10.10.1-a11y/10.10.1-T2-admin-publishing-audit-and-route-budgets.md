## Goal

## Design

**1. Audit rows (append to T1's artifacts).** `route-matrix.ts` gains the `admin` and `publishing` scopes from SD1/SD10 (`../README.md:657-666`) — `/admin`, `/admin/users`, `/admin/users/:id`, `/admin/render-jobs`, `/admin/usage`, `/admin/moderation`, `/admin/quota`, `/admin/reports`, `/admin/deletion-requests`, `/admin/flags`, `/admin/kpis`, `/admin/billing/{packages,promos,payments,refunds,funding}`, `/admin/settings`, `/admin/settings/nodes`, `/admin/approvals`, `/channels`, `/channels/:platform/callback`, `/episodes/:id/publish/youtube`, `/episodes/:id/publish/tiktok` (flag `tiktok_publish`), `/publications/cancel`, `/publications/approve` — each with its SD1 state list, `auth: 'admin'` or `'owner+reauth'` (T2 adds the admin fixture; T1's fixture set stays as written), and the `manualOnly` criteria.

**2. Table-specific a11y (FC16 — the reason this task exists).** An admin data table must satisfy, per table: a `<caption>` or `aria-label` naming the table; `<th scope="col">` on every header; `aria-sort="ascending|descending|none"` on the **one** sorted column; sort buttons that are keyboard reachable with an accessible name (`admin.<table>.sortBy`); a filter form whose controls are labelled and whose "clear filters" is reachable; row actions with an accessible name that includes the row identity; loading announced via `aria-live`/`role="status"` and not by an overlay that traps focus; the filtered-empty state distinct from the loading state; and paging via `cursor-page.ts` with a keyboard-reachable "load more"/next control. The spec asserts each of those and the manual matrix re-checks them by screen reader, because axe only sees the first two.

**3. Budget script (`web/tools/web/check-gzip-budget.mjs`).** Keep the existing CLI and behaviour and add a `--routes` mode:

```js
export const ROUTE_BUDGETS = [
  { route: 'initial',            match: null,                               budget: 256000 },
  { route: '/admin/**',          match: ['features/admin/'],                budget: 300000 },
  { route: '/admin/settings/**', match: ['features/admin/settings/'],       budget: 120000 },
  { route: '/billing/**',        match: ['features/billing/'],              budget: 260000 },
  { route: '/account/**',        match: ['features/account/'],              budget: 180000 },
  { route: '/channels,/episodes/:id/publish/**', match: ['features/publishing/'], budget: 240000 },
  { route: 'tiktok',             match: ['features/publishing/tiktok/'],    budget: 140000 },
];
export const INITIAL_MUST_NOT_REFERENCE = ['features/admin/', 'features/billing/', 'features/publishing/tiktok/'];
```

- **Attribution** `[OPEN]` A10-1: a chunk is attributed to a route by the `sources[]` of its sibling `.js.map` (the build used by the budget step sets `sourceMap.scripts: true`); if the pinned `@angular/build` output cannot be attributed that way, fall back to a committed `web/tools/web/route-chunk-prefixes.json` mapping and record the deviation in this file's `## Notes` and in the matrix. No other vendor API is assumed.
- **Initial-exclusion assertion:** starting from the HTML references, follow only **static** import specifiers inside the initial JS; stop at `import(` (dynamic). Any reachable chunk whose attributed sources match `INITIAL_MUST_NOT_REFERENCE` fails with `initial bundle references <chunk> (<route>)`.
- **Output:** the existing `file raw gzip` rows plus one `route raw gzip budget status` row per entry; a route with **no** chunk discovered fails (`route <x> matched no chunk — table is stale`), mirroring the existing "missing directory fails loudly" rule (A4) so the table cannot rot silently.
- **Numbers** `[DECISION]` (`plan.md` §3): ceilings, not targets — T2 measures each chunk after the wave-3 screens land, writes the measured value into the table and keeps each ceiling at measured + 15 %; the initial entry stays exactly 256000 (250 kB, D13/NFR-10-2).

**4. Tests (`check-gzip-budget.test.mjs` extended, Node `--test`).** Temp-fixture builds proving: under/over a **route** ceiling → exit 0/1 with the route named; a chunk matching an admin/billing matcher reachable from the initial HTML → exit 1 with the "initial bundle references" message; a dynamic-import-only reference → exit 0 (no false positive); an entry matching no chunk → exit 1; existing initial-budget cases unchanged.

**5. i18n.** Admin/publishing failures use the screens' own keys — `errors.*` for codes (`reauth_required`, `forbidden`, `self_grant_forbidden`, `grant_target_forbidden`, `setting_change_pending`, `owner_action_pending`, `owner_action_disputed`, `grant_requires_approval`, `setting_change_not_pending`, `owner_action_not_pending`, `rate_limited`, `feature_disabled`) and the `admin.*`/`tiktok.*` scope keys the screens define (SD13 `:679`). T2 adds **no** key; a missing one is reported against the owning folder. Accessible names of admin controls are asserted to come from keys, never from server text.

## Acceptance checks

- **Given** an owner and an admin session on the compose stack, **when** `npm run e2e -- a11y` runs, **then** every admin/publishing row passes axe with `wcag2a, wcag2aa, wcag21a, wcag21aa, wcag22aa` in vi and en, dark and light, with the CSP fixture reporting nothing.
- **Given** any admin table, **when** it is sorted, filtered, paged or emptied, **then** `aria-sort` sits on exactly one column, the sort and filter controls are keyboard reachable and named from `admin.*` keys, loading is announced politely, the filtered-empty state is distinguishable from loading, and row actions carry the row identity in their accessible name.
- **Given** any admin dialog, **when** it opens and closes, **then** focus moves in, is trapped, and returns to the invoking control; `Escape` closes it; and a 202 `setting_change_pending`/`owner_action_pending`/`grant_requires_approval` response renders as a pending banner (announced), not as an error.
- **Given** `feature_disabled` on `/admin/quota` (flag off), **when** the route is opened, **then** the screen is hidden with an explanation and no axe violation.
- **Given** a production build, **when** `node web/tools/web/check-gzip-budget.mjs --dir dist/web/browser --budget 256000 --routes` runs, **then** it prints a row per route, exits 0 inside every ceiling, and exits 1 if any admin/billing/TikTok chunk is reachable from the initial bundle.
- **Given** a deliberately inflated admin chunk, **when** the gate runs, **then** it fails naming `/admin/**`; **given** the inflation is reverted, **then** it is green again (self-proof recorded in this file's `## Notes`).
- **Given** the public `/publications/cancel` and `/cancel-request` pages, **when** opened logged out at 360 px, **then** they are fully keyboard-operable and axe-clean with the fragment-only token never in a query string or a log.
- **Given** `a11y-manual-matrix.md`, **when** the pass closes, **then** every T2 row has a `Verified by/date` entry or an `[OPEN]` row with an owning task id.

## Failure handling and edge cases

| Case | Handling |
|---|---|
| Attribution of chunks cannot be derived from sourcemaps (`[OPEN]` A10-1) | Use the committed `route-chunk-prefixes.json` mapping, record the deviation here and in the matrix; the initial-exclusion assertion and the ceilings are unaffected. |
| A route's chunks legitimately exceed a ceiling | Raise the ceiling **once** with the measured value + 15 % written down and the reason in `## Notes`; never by removing the entry, and never by relaxing the initial 250 kB. |
| A route matches no chunk (renamed folder, `@defer` split) | The script fails loudly (`table is stale`); fix the matcher, do not skip the entry. |
| Chunk is reachable from the initial bundle via a `@defer` boundary | `@defer` emits a dynamic import, so it is **not** followed and must not fail the assertion; if it does, the walk has a bug — fix the walk, not the assertion. |
| Admin screen unreachable in CI because MFA is not enrolled for the fixture | Fixture enrols TOTP on first run through the UI (existing `loginAsOwner` pattern) or an admin seed row is used; if neither is possible, the row is marked `[OPEN]` with the reason — never audited with a weakened guard. |
| `logrocket`/table virtualisation hides rows from axe | Audit with the accessible list rendered (no virtualisation in the e2e build) or exclude the virtualised container **with a manual matrix entry** for the rows it hides; never a silent `exclude`. |
| Third-party iframe (CAPTCHA) inside an admin flow | Same rule as T1: container-level assertions + a manual entry (FC16). |
| A red axe row blocks the M2 exit | The row stays red and named; the owning task fixes it. This task does not edit product screens, styles or copy keys. |
