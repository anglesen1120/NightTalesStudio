## Goal

Prove the **whole product** works for its owner, through the browser, against the real local stack: eight Playwright journeys under `web/e2e/journeys/` that log in (MFA), create a series and an episode, generate text, edit and approve a story, render a video through `mock-mpt`, review and approve it, walk the true-crime path (sources → fact sheet → attestation), survive a real story-ETag conflict and a `keywords_flagged` block, enable and watch autopilot, publish up to `scheduled` with a real consent step, and open both veto e-mail pages — in Vietnamese and English, with axe (WCAG 2.1 AA) and the D4 CSP fixture clean on every page visited.

Because three dependencies cannot exist in CI as-is, this task also owns the three assets that make the journeys deterministic **without** weakening them: the mock OpenAI service of **WT-W1** (`web/e2e/stubs/openai-stub.mjs` + its compose service, declared in a new `web/e2e/docker-compose.e2e.yml` override so `11.1.1-T1`'s compose file is never edited), the journey harness (`web/e2e/journeys/fixtures.ts`, `journey.ts`, `route-fixtures.ts`), and a **stack preflight** that fails a journey by name when the stack is incomplete — so a green run always means the real stack was driven, and a missing piece is never a silent skip.

**Imports from the app that the journeys assert but never import.** No test file imports `web/src/**`; the only app module whose behaviour is asserted indirectly is `web/src/app/features/publishing/domain/youtube-metadata-rules.ts` (10.7.2-T1's single implementation of the title/description/tags/privacy rules) — the publish journey asserts it through the rendered form (byte counter, `≤ 500`/`≤ 15 × 30` tags, privacy disabled when `preAudit`), and `web/src/app/shared/util/safe-filename.ts` (10.1.6-T1, D4/WR4) through the download attribute. Nothing in `web/src/app/…` changes.

**Journey mechanics.** One independent test/file = one journey = one owner login; named `test.step` sections carry sanitized step/route/assertion evidence. Run each file alone with run-unique data; serial scheduling never chains mutable tests. Real API/DB/Worker/mock-mpt acceptance retains the explicitly approved exceptions: P-J1 text through `openai-stub` (WT-W1); P-J2 real seeded active channel (WT-W4), scheduled + cancel only (WT-W2), OAuth target contract owned by 10.7.1-T1 (C20); P-J3 fetched source presentation intercepted on `GET /api/v1/episodes/{id}/sources` (C13/D15, no production SSRF bypass). WR14 allows only the documented keywords_flagged/story_version_conflict presentation intercepts; real J4 conflict is still a real 412. Synthetic states do not replace server acceptance.

Use `getByRole`/`getByLabel` for user actions and names in the selected locale; retain C19 testids for stable technical observations, not blanket action selection ([Playwright best practices](https://playwright.dev/docs/best-practices)).

The shared 10.1.6-T1 CSP fixture is installed at **context creation before navigation**, with init script and listeners on existing/new pages, the J4 second tab and J7 fresh anonymous context. Axe is checked after each meaningful settled page/state and triggered lazy/defer path under production headers. Intentional forbidden-policy/canary probes run in isolated explicit probe mode and assert the detector catches the expected violation; they are not positive zero-violation journey tests. Report only sanitized origin/path/route/directive, no raw console text, URL query/fragment or sink sample. Chromium is required for TT enforcement; OPTIONAL other-browser smoke checks unsupported-TT graceful behavior, not enforcement.

**Timing.** Each file sets its own `test.setTimeout` (180 s for the pipeline files) and `test.describe.configure({ mode: 'serial' })`, so `playwright.config.ts` (10.1.5-T1) is untouched: the suite is picked up by the existing `npm run e2e` inside 11.5.1-T1's `e2e` job (WR3/C1). App timers are advanced with `page.clock` (`install`, `fastForward`) — the run-log poll (30 s), the veto tick (1 min), the video-URL refresh (`expiresAt − 60 s`); the TOTP step boundary stays a real wall-clock wait. Server-side transitions are waited on with `expect.poll`, never faked.

**Preflight (`journeyStack()`).** Before step 1: `GET /__stub/state`; `GET /health/ready` through the web origin; for the publish file, `GET /me`'s `features[]` contains `youtube_publish`. A failure throws with the exact remediation text and the journey **fails** (never `test.skip`): "compose-up must pass `-f web/e2e/docker-compose.e2e.yml --profile e2e`", "`nts-worker flags set youtube_publish on`". The function takes its base URLs as parameters so its negative control is unit-testable.

**Performance (of the suite).** One stack start, `workers: 1`, one login per file, `MOCK_RENDER_SECONDS=6`, run-unique titles and bounded web-first assertions/`expect.poll`; no `waitForTimeout` loop. Sensitive/auth-bearing files have trace/video off even on failure, with sanitized diagnostics only. Application LCP/interactivity evidence uses the cold-cache protocol in `plan.md` §9, never suite duration or bundle size as a substitute.

**Security.** No token, hub ticket, signed URL, TOTP secret or cookie value may reach a trace, video, attachment or console: auth-bearing files disable trace/video (WR14); journeys assert the `/hubs/*` URL carries only the single-use ticket, that the video URL never appears in a console call or in `localStorage`/`sessionStorage`, and that the OAuth step navigates only to the API-returned URL with origin exactly `https://accounts.google.com` (WD10) before aborting it. The TOTP secret lives only in `web/e2e/.auth/owner-totp.json` (0600, git-ignored, deleted in global teardown). No `storageState` is ever written or read (F08); the second session in J4 is a second **tab** in the same context (WR10). The cancel page's fragment token is removed with `history.replaceState` before any request and the journey asserts no request carries it in a query string. `openai-stub` and its `/__stub/*` surface are separate containers, reachable only from the compose network and absent from `deploy.yml`'s image set.

**Reuse (D11/WR4 owners — nothing is re-implemented).** `loginAsOwner`/`totp()`/`expectA11yClean`/the CSP fixture/`global-teardown.ts` → 10.1.5-T1/10.1.6-T1; `ConfirmDialog` (approve/reject/cancel confirmations, empty `cost-line` per D14) → 10.1.3-T1; `ConflictDialog` → 10.2.2-T1; `ReauthDialog` → 10.3.3-T3; `StatusChip`/`LoadingState`/`EmptyState`/`ErrorState`/`RetryCountdown`/`CharCounter`/`Stepper` → 10.1.3-T1/10.2.2-T1; `keywordFlags`/`setKeywordFlags` → 10.5.10-T1 (WR6); `visible-poll` → 10.2.6-T1; `SegmentChips`/`segment-address.ts` → 10.5.3-T1; `youtube-metadata-rules.ts` → 10.7.2-T1; `safe-filename.ts` → 10.1.6-T1. **a11y (D16).** Every visited page gets the axe run (WCAG 2.1 AA tags) plus the CSP/TT assertion (D4); beyond axe the journeys assert what axe cannot — focus moved into and restored out of each modal (approve, conflict, re-auth, authorization), the `aria-live` progress/"saved" regions on the timeline and editor, the `aria-describedby` link between the blocked-gate alert and the disabled button, the keyboard-only path on the anonymous cancel page, the 360 px editor without horizontal scroll, and that the failure chips carry an icon + text (no colour-only information). **Copy keys (vi + en).** The journeys assert the screens' own keys: `errors.<code>` for every provoked failure, `realtime.paused`, `quality.*`/`render.*` (02.3.4-T1, 10.6.1-T1, 10.6.2-T1), `episodes.research.*`/`factSheet.*` (10.5.5-T1), `core.nav.*`/`core.app.name` (10.2.6-T1), `series.style.<name>.label/.hint`, `series.style.trueCrimeNotice`, `voices.tag.<tag>` (03/04 hand-overs). ## Failure handling and edge cases

| Case | Handling |
|---|---|
| The stack was started without the override file, or `youtube_publish` is off | `journeyStack()` fails the file with the exact remediation (`-f web/e2e/docker-compose.e2e.yml --profile e2e`; `nts-worker flags set youtube_publish on`) — never `test.skip`, so an incomplete stack cannot look green |
| The stub is up but an OpenAI path is missing | The stub 404s JSON without logging the body; the Api logs its own failure; the journey fails at the generate step and the log names the path (O-W5's discovery mechanism) |
| The keyword injector form does not cover `quality:<check>` ([INFERENCE], C6 of `plan.md`) | Fall back to a stack started with `MOCK_FAIL_MODE` (O-W4(d)); the report records which form ran, and the journey's assertions do not change |
| The render takes longer than the timeout on a loaded runner | `MOCK_RENDER_SECONDS=6` in the override, a 180 s file timeout, and `expect.poll` intervals tuned to the mock's tick; never a bare `waitForTimeout` |
| The video URL expires mid-playback (the WD4 refresh path) | The journey invalidates it deliberately (a `page.clock` fast-forward past `expiresAt − 60 s`) and asserts the refresh: a new `GET …/video-url`, playback continues, and no request is issued while the document is hidden |
| TOTP step collision (`invalid_mfa_code`) | 10.1.5-T1's helper retries; a journey never computes a second code in the same step, and the first-run enrolment file is written once per run (WR14) |
| The two-tab refresh rotates the cookie and revokes the family | The second session is a **tab in the same context** (one cookie jar, `navigator.locks` — WR10); the journey asserts both tabs stay signed in after the second save |
| A run on a laptop stack with data already present | Run-unique titles (`e2e-journey-<file>-<UTC>`) and no assumption of an empty DB; the report says the journey leaves its rows (no cleanup through a non-existent SPA API) |
| A `page.route` handler masks a real server bug | Handlers exist only for the four documented states, are listed in the report with their route pattern, and are removed in `afterEach`; the happy path is unstubbed and the preflight proves the real stack is answering |
| The `en` pass finds an untranslated key | The journey fails on the key-pattern assertion (10.2.5-T1's rule); the fix belongs to the owning screen's i18n file, not to the journey |
| The channel cannot be connected in CI (C20) | **WT-W4** resolves it: the stack is seeded with one `active` connection (`seed/youtube-channel.sql`, token columns NULL) before the publish/veto files, so those journeys drive the real path. Failure modes are explicit: no `docker compose`/wrong working directory → the seeder resolves the file set and project name from the repo root (never a bare relative path) and fails with the compose/psql error naming the file; a missing or renamed column → `psql -v ON_ERROR_STOP=1` aborts the whole seed; an invisible row (wrong `user_id`) is impossible by construction because the id is a subselect on `NTS_E2E_OWNER_EMAIL`, and the preflight's `GET /channels` assertion catches it anyway. State drift is handled, not assumed: 10.7.1-T1's spec revokes the seeded row for real and `ux_channel_connections_account` excludes `revoked` rows, so the seeder's `WHERE NOT EXISTS (… status='active')` guard re-inserts an active row in the next file's `beforeAll` (file order irrelevant) and never duplicates; the connect/disconnect walkthrough itself stays manual evidence for 06.5.1-T1/13.4.2-T1 |
| No veto e-mail in Mailpit (⚠️ O-W11: perhaps only an autopilot-created row mints a link) | J7 first tries the link of the autopilot-driven row from J5 on the same stack; if no message exists at all, it asserts the garbage-token path (a real API round trip) plus the page's UX with `page.route` on the cancel-by-link route, and the report states which mode ran |
| A media-origin/CSP misconfiguration (WT-W11) blocks the player | The fixture's `securitypolicyviolation` report names the blocked origin; the fix is the override's `NTS_CSP_MEDIA_ORIGINS` (and `Storage__PublicServiceUrl`), never a relaxed CSP header. Missing `Storage__PublicServiceUrl` instead shows as an unresolvable source URL in the player's `error` event. Both fail the journey with the origin in the message, so the reader cannot mistake a configuration error for a product bug |
| Teardown after a failure | `global-teardown.ts` (10.1.5-T1) deletes `web/e2e/.auth/`; `e2e.yml`'s `teardown` job drops the volumes `if: always()` — the journeys add no cleanup of their own |
