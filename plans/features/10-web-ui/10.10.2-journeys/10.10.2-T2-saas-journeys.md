## Design

Files (all new, under `web/e2e/journeys/`, following `10.10.2-T1`'s one-spec-per-journey convention):

- `saas-onboarding.spec.ts` (+ `.en.spec.ts`) — J-S1: register → real mail verify → legal/18+ → packages → real checkout → sandbox provider verification/webhook through the approved **server-side provider adapter** → real `/billing/return` polling to `paid` → render to `queued`. Browser redirect HTML may be fake external presentation only; it must not mock payment API, grant credits or prove paid. Reuse existing shared journey helpers, not a second harness.
- `saas-admin-actions.spec.ts` — J-S2: `loginAsOwner` (or a seeded `admin` fixture account, reusing `09.2.5-T2`'s owner-seed pattern if a second seed is needed — `[OPEN]`, flagged to the TL, not invented here) → suspend a seeded user (`POST /admin/users/{id}/suspend`) → approve a seeded `pending_approval` credit-grant request (`10.9.4-T2`) → toggle a feature flag through `ReauthDialog` step-up (`PATCH /admin/feature-flags/{key}`, 401 `reauth_required` → dialog → retry once).
- CAPTCHA: use [documented Turnstile dummy keys](https://developers.cloudflare.com/turnstile/troubleshooting/testing/) with the matching API test secret via the existing e2e env override, never production credentials or real challenges. These keys still contact vendor origins; allow only the reviewed 10.3.3-T2/10.1.6-T1 CSP delta. Add always-fail and duplicate-token negatives, asserting real server rejection and no registration/payment side effect.
- No new library or unauthorised stub/service. Payment seam approval/readiness is a prerequisite with plan 12 owners (12.3.2-T1 checkout, 12.7.4-T1 return); if the server sandbox adapter cannot verify/webhook paid, mark integration OPEN and fail preflight, never browser-mock a grant. At snapshot `00e7d5d5415579c7df55a66dc2177cbc2e31eb78`, billing routes/producers are planned, not shipped.

## Acceptance checks

- **Given** a fresh e-mail, **When** onboarding runs, **Then** real register answers 202, mail verify completes, legal/18+ is accepted once, server sandbox verification/webhook makes payment paid and ledger credits visible on refetch, and render reaches queued. Browser-only redirect HTML cannot satisfy paid; failed/replayed verification cannot grant twice.
- **Given** CAPTCHA dummy sitekey and matching API test secret, **When** pass/fail/duplicate-token modes run, **Then** no production credentials/real challenge is used, real API rejects fail/replay without side effects, and vendor requests stay within reviewed CSP origins; do not assert absence of vendor network.
- **Given** a seeded user, **When** the admin journey suspends it, **Then** the user row shows `suspended` and a second suspend attempt is rejected per the existing admin contract.
- **Given** a seeded `pending_approval` credit-grant request, **When** the admin approves it, **Then** the request's status becomes resolved and the grant is reflected on a refetch (server state, no client arithmetic, A10).
- **Given** the feature-flag toggle, **When** `reauth_required` is returned, **Then** `ReauthDialog` succeeds and the toggle retries once, landing the new `enabled` value.
- **Given** every terminal screen in both journeys, **When** axe runs, **Then** `expectA11yClean` reports zero violations (10.10.1-T1's matrix rows for these screens are the manual-audit counterpart, not duplicated here).

## Failure handling and edge cases

| Case | Handling |
|---|---|
| Sandbox/fake provider return page never resolves to a terminal status | Journey fails loudly at the polling timeout (`10.8.1-T1`'s `expiresAt` → `failed`/`payment_expired`), not a silent skip |
| CAPTCHA test key rejected (misconfigured secret) | Preflight fails by name (mirrors `10.10.2-T1`'s WT-W1 preflight precedent), never a silent fallback to a token-less submit |
| Credit-grant request already resolved by another actor before the approve step | Journey asserts the 409 `grant_request_not_pending` path explicitly rather than treating it as flaky |
| Feature-flag toggle's re-auth dialog times out | Journey fails with the re-auth timeout surfaced, not retried indefinitely (single retry only, per the shared `ReauthDialog` contract) |
| `10.10.1-T1`'s extended a11y fixture not yet landed (soft dependency) | This task's own `expectA11yClean` calls use the harness already shipped by `10.10.2-T1`; no functional dependency on `10.10.1-T1`'s matrix file |
