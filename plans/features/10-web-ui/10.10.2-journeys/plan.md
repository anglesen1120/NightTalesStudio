## 1. Scope

**In scope (2 tasks, 3.0 d raw).** `10.10.2-T1` (P, L, 2.0 d) — the owner journey suite: eight Playwright specs under `web/e2e/journeys/` that walk the product through the browser against the compose stack (api, worker, postgres, storage, mail, `mock-mpt`, `web` profile), plus the three assets this folder owns because they exist only for e2e: (1) the mock OpenAI service of **WT-W1** — `web/e2e/stubs/openai-stub.mjs` and its compose service `openai-stub` (profile `e2e`), declared in a **new override file** `web/e2e/docker-compose.e2e.yml` so `11.1.1-T1`'s file is not edited (kept, **CI-only** — e2e; 10 CR-43); (2) the journey harness `web/e2e/journeys/{fixtures,journey,route-fixtures}.ts`; (3) the failure matrix driven through `mock-mpt`'s documented injectors (WD8's "success, `image_moderated`, `render_quality" and further mock-mpt scenarios). `10.10.2-T2` (S, M, 1.0 d, **10 CR-40**) — the S-slice SaaS journeys added once the S screens ship (register → verify → legal/18+ → sandbox billing → render; admin actions): reuses this folder's harness/stub/fixtures verbatim, adds specs only.

**Out of scope (owned elsewhere).** `playwright.config.ts`, `web/e2e/fixtures/{axe,auth,csp}.ts`, `global-teardown.ts`, `smoke.spec.ts`, `web.yml` → **10.1.5-T1** (WR3: `web.yml` has no compose/e2e); the CSP fixture and `nts-sanitizer` → **10.1.6-T1**; the stack/`.env.example` → **11.1.1-T1/T2**; `tools/mock-mpt` + its env parsing → **11.1.2-T1/T2**; the `images.v1` generator → **03.4.3-T2**; `e2e.yml` → **11.5.1-T1** (this folder asks it for four things, §10 O-W4, and owns none); the enrolment/MFA/re-auth screens → **10.3.3-T3** (its specs assert them; journeys only *use* them); all per-screen specs stay flat in `web/e2e/` and keep their own scenarios — journeys assert **transitions across screens** and reference, never duplicate, a page-level behaviour; every S item (`10.10.2-T2`, WB7), credit/pricing copy (D14), TikTok (10.7.3).

**Explicitly not built in P.** No SPA source change, no new API route, no new `mock-mpt` behaviour. No Google call from the stack (WT-W2): the publishing journey stops at `scheduled` + cancel. No real OpenAI call (WT-W1). No real outbound source fetch — see P-J3 in §3 for why and its `[OPEN]` fallback.

**Phase / flag.** P · M1. No flag of its own; the publishing journeys need `youtube_publish` on for the stack (WT-W2; the CLI is `nts-worker flags set <key> on|off`, ✅ `09.9.2-T2:88-89`) and the preflight **fails by name** if it is off (no silent skip, §7). **Order:** last task of plan 10 (§B8.1: depends on 10.6.2-T1, 10.7.4-T2, 10.5.6-T1, 10.4.3-T2, 10.1.5-T1, 11.5.1-T1; blocks nothing); inside it harness → stub → happy/failure journeys → publish pair.

## 7. Jobs and integrations

Realtime and timers.

- **Realtime.** No timer or subscription of this folder's own; the hub is exercised for real (§5). A journey that needs a close forces it with `context.setOffline(true/false)` (the wave-1 pattern, `realtime.spec.ts:89`) instead of waiting the 5 min token close; the reconnect assertions are request-count based (one ticket per attempt, no refetch storm — D8/F07).
- **Timers.** App-side timers — the 30 s run-log poll, the 1 min veto tick, the video-URL refresh at `expiresAt − 60 s` — are advanced with `page.clock` (WR14/WR16/C18). Server-side timers are never faked: journeys wait on real server transitions with `expect.poll`, so no cross-clock assumption can pass.
- **CI wiring.** Existing `npm run e2e`/11.5.1-T1 job and config ownership unchanged. Each journey is one independent `test` with `test.step` sections, one file-local login and run-unique data; serial scheduling is not cross-test state dependence. Sensitive/auth/billing/admin-bearing files disable trace/video even on failure; upload only redacted safe diagnostics.
- **Stack preflight** (`journeyStack()`): before the first step of every journey — `GET /__stub/state` (WT-W1), `GET /health/ready` through the web origin, and (publishing file) that `GET /me`'s `features[]` contains `youtube_publish` (D14/C17). A missing piece **fails the file by name** with the exact remediation ("compose-up must pass `-f web/e2e/docker-compose.e2e.yml --profile e2e`"; "`nts-worker flags set youtube_publish on`"). Never a silent skip — a skipped journey is an untested journey (§10 O-W4).
- **Timing knobs.** `MOCK_RENDER_SECONDS=6` on the e2e stack (override default) keeps a real `queued → running(voice…assembling) → checking → succeeded` walk inside the timeout; `MOCK_VIDEO_SECONDS` stays at its default (the canned MP4 must be long enough for the player assertions) ⚠️ confirmed on the first run (O-W8).

## 8. Security and privacy

- **Nothing sensitive in an artefact.** No token, hub ticket, signed URL, TOTP secret or cookie value in a trace, video, report, attachment or console. Auth-bearing files set `trace/video: 'off'` (C3/WR14). Journeys assert the rules directly: `/hubs/*` URLs carry only the single-use ticket and no token (`page.on('request')` scans every hub URL); the video URL never appears in a console call or in `localStorage`/`sessionStorage` (a storage + console probe); the OAuth step navigates only to the API-returned URL and only when its origin is exactly `https://accounts.google.com` (WD10), then aborts it.
- **The TOTP secret** lives only in `web/e2e/.auth/owner-totp.json` (0600, git-ignored, deleted by `global-teardown.ts` even on failure, C3); this folder never logs or attaches it and never turns it into a `storageState`.
- **No `storageState`.** One UI login per file — replaying the rotating refresh cookie revokes the family (F08/C3). A second session is a second **tab** in the same context (J4), the supported `navigator.locks` path (WR10), never a second cookie jar.
- **No in-app hooks** (WR14). `page.route`/`page.clock` act from outside the SPA; `openai-stub` and its `/__stub/*` surface are separate containers reachable only from the compose network and are **never** in a production image (`deploy.yml`'s image set excludes it — C1/§3).
- **Cancel page**: the token is read from the fragment and removed with `history.replaceState` **before** any request (WD7/WD10); the journey asserts the removal and that no request carries the token in a query string.
- **Deny-by-default on stubs.** A handler is registered per test and removed in `afterEach`; the preflight asserts the real stack is up and the report lists every intercepted route, so a stub cannot mask a broken server.
- **Secrets:** none needed (C1); owner credentials come from `NTS_E2E_OWNER_EMAIL`/`NTS_E2E_OWNER_PASSWORD` as non-secret dev values in CI (C3). Nothing in this folder writes a credential to disk.
**Media origin (WT-W11).** The override sets `NTS_CSP_MEDIA_ORIGINS` **and** `Storage__PublicServiceUrl` to the host-reachable storage origin. Both are load-bearing for J1/J3: the first extends D4's `media-src`/`img-src` (without it the CSP blocks the presigned video URL and the player assertions fail with a `securitypolicyviolation` rather than a product bug), the second makes the API hand out a URL the browser can actually resolve. A failure here is a configuration error and must be diagnosed as such (the fixture's violation report names the blocked origin), never worked around by relaxing the header.
