## Goal

The SPA holds the access token in memory, restores the session once on boot with the `HttpOnly` refresh cookie,
refreshes exactly once for any number of concurrent 401s (a second parallel refresh is reported by the server as
token theft), retries the failed request once, ends the session cleanly on `session_revoked` / `refresh_token_reused`
/ logout while resetting every session-scoped store, and never refreshes on behalf of a background activity while the
user is idle.

## Design

Files (all new unless noted):
- `web/src/app/core/session/token-pair.ts` — `interface TokenPair { accessToken: string; expiresAt: number }`,
  `interface SessionUser { role: PlatformRole; amr: readonly string[] }`,
  `type PlatformRole = 'user' | 'admin' | 'owner'` (JWT role is snake_case, `09.3.2-T1:46`),
  `const FRESHNESS_MARGIN_MS = 30_000` (matches `Auth:Access:ClockSkewSeconds` 30, `09.3-auth/plan.md:127`).
- `web/src/app/core/session/me-summary.ts` — `interface MeSummary { uiLocale: 'vi' | 'en'; role: PlatformRole;
  features: readonly string[]; displayName: string; email: string }` — the in-memory view of `GET /me`
  (09.3.4-T1-me-endpoints.md:22-24 — `displayName`, `email`, `uiLocale`, `role`, `features` are the DTO's own
  field names, `Language` serialised as `"vi"`/`"en"`); the shell (10.2.6-T1) maps `MeDto` from `@shared/api`
  into it and calls `SessionStore.setMe()` (agreed seam with 10.2.4/10.2.5/10.2.6, 2026-09-24).
- `web/src/app/core/session/session.api.ts` — `abstract class SessionApi { abstract refresh(): Promise<TokenPair>;
  abstract logout(): Promise<void>; }` (domain port; no Angular imports).
- `web/src/app/core/session/data-access/session.repository.ts` — `@Injectable() class HttpSessionRepository
  implements SessionApi`; the only file here importing `@shared/api` (D5); maps ISO `expiresAt` → epoch ms via
  `Date.parse`, uses `firstValueFrom`, never returns `HttpResponse`.
- `web/src/app/core/session/session-store.ts` — `@Injectable({providedIn: 'root'}) class SessionStore`.
  Private writable signals hold `accessToken`, `expiresAt`, `role`, `amr`, `me`, `enrolmentToken`,
  `endReason`, `restoreSettled`; same-named public views use `.asReadonly()`. Arrays/objects are immutable
  snapshots replaced on update. Keep private `refreshInFlight: Promise<string|null>|null` and
  `restorePromise: Promise<void>|null`. Public `generation: Signal<number>` exposes the private session counter.
  Computed: `status = computed<'anonymous'|'restoring'|'authenticated'|'refreshing'|'ended'>(…)`,
  `mode = computed<'full'|'enrolment'>(() => enrolmentToken() ? 'enrolment' : 'full')`, `isAuthenticated`,
  `isOwnerOrAdmin` (WR8: the `status` union is unchanged; in enrolment mode `status` is never `'authenticated'`). Consumer contract (pinned with 10.2.4-T1, 2026-09-24): react by stopping on
  `'anonymous'`/`'ended'` and starting on `'authenticated'`; `'restoring'`/`'refreshing'` are transient and are
  never a sign-out.
  Methods: `restore(): Promise<void>` (idempotent, one call), `ensureFreshAccessToken(opts?: { userAction?: boolean }):
  Promise<string|null>`, `authHeader(): string | null` (the enrolment token wins while it exists), `signIn(tokens: TokenPair, role: PlatformRole, amr: readonly string[]): void`,
  `setMe(summary: MeSummary | null): void`, `hasFeature(key: string): boolean` (reads `me()?.features ?? []`),
  `beginEnrolment(token: string): void`, `logout(): Promise<void>`,
  `signOut(reason: SessionEndReason): void`, `reset(): void` (implements `SessionScoped`).
  `ensureFreshAccessToken` rules (WR10, WR11): if a token exists and `expiresAt - Date.now() > FRESHNESS_MARGIN_MS`
  → return it. Otherwise a refresh is allowed only while `opts?.userAction === true ||
  ActivityTracker.isActive()`; when it is not, return `null` **without** a call and let the caller pause (realtime
  stays paused, polling stops; D7). When allowed, the whole refresh runs inside
  `RefreshLock.run(...)`: re-check `refreshInFlight` and the token **after** acquiring the lock (a tab that refreshed
  first returns the fresh token instead of presenting the rotating cookie again — C1 reuse detection, `09.3.2-T1:136`)
  and clear `refreshInFlight` in a `finally`.
  `signOut(reason)`: sets `endReason`, clears `accessToken`/`expiresAt`/`enrolmentToken`/`me`, iterates
  `SESSION_SCOPED` (injected array) calling `reset()` inside a try/catch that logs nothing but a dev-console code,
  then `Router.navigate(['/login'], { queryParams: { returnUrl: sanitizeReturnUrl(router.url) } })` unless already
  on `/login`. `logout()` is the explicit user action (WR8): `await SessionApi.logout()` (204, a 401 is treated as
  already logged out) then `signOut('logout')` with **no** `returnUrl`. `beginEnrolment(token)` stores the
  enrolment-only token in memory (cleared by `signIn`, `signOut` and `reset`) and keeps `status` out of
  `'authenticated'`.
  Bump generation before `signIn`, `beginEnrolment`, `signOut` or `reset` replaces identity. Every restore/refresh
  captures it before awaiting; stale success/failure cannot commit state or sign out a newer user. A stale restore
  still settles its Promise. `finally` clears a flight only if that field still references its own Promise.
  The shell owns generation checks around `/me` before the synchronous `setMe` call.
- `web/src/app/core/session/session-scope.ts` — `interface SessionScoped { reset(): void }` +
  `const SESSION_SCOPED = new InjectionToken<readonly SessionScoped[]>('SESSION_SCOPED')`.
- `web/src/app/core/session/session-end.ts` — `type SessionEndReason = 'logout'|'expired'|'revoked'|'reused'|
  'restore_failed'`.
- `web/src/app/core/session/return-url.ts` — `sanitizeReturnUrl(raw: string | null): string`; accepts only
  `^/(?![/\\])[^\s]*$` and rejects the auth pages (`/login`, `/forgot-password`, `/reset-password`,
  `/verify-email`); anything else → `/dashboard`.
- `web/src/app/core/session/activity.ts` — `@Injectable({providedIn: 'root'}) class ActivityTracker`;
  Private writable lastInputAt/tick/isVisible with same-named readonly views (10 s tick interval solely for
  computed isActive); visibility initialized from document, `idleWindowMs = computed(() => role() === 'user' ?
  ACTIVITY_WINDOWS.user : ACTIVITY_WINDOWS.admin)`, `isActive = computed(() => tick() >= 0 && Date.now() -
  lastInputAt() < idleWindowMs())`; `start()` registers `pointerdown`, `keydown`, `wheel`, `touchstart` (passive)
  and `visibilitychange`, throttled to one `lastInputAt.set` per `ACTIVITY_THROTTLE_MS = 100`; `stop()` removes them
  and clears the interval; both are wired through `DestroyRef`. Constants `ACTIVITY_WINDOWS = { admin: 25 * 60_000,
  user: 13 * 86_400_000 }` (README.md:148-152).
- `web/src/app/core/session/refresh-lock.ts` — `const REFRESH_LOCK_NAME = 'nts-refresh'` and
  `class RefreshLock { run<T>(fn: () => Promise<T>): Promise<T> }`: uses
  `navigator.locks.request(REFRESH_LOCK_NAME, { mode: 'exclusive' }, fn)` when `'locks' in navigator`, otherwise an
  in-process mutex of the same shape (documented fallback for jsdom and lock-less engines) so WR10's cross-tab
  guarantee never disappears silently.
- `web/src/app/core/session/session.interceptor.ts` — `export const sessionInterceptor: HttpInterceptorFn`:
  1. skip everything outside `/api/v1/**` and the four auth routes (`/auth/login`, `/auth/login/mfa`,
     `/auth/refresh`, `/auth/forgot-password`, `/auth/reset-password`) for the `Bearer` header; the refresh route is
     additionally `SILENT` (never refreshed recursively, never retried);
  2. for the remaining requests: `const token = await store.ensureFreshAccessToken({ userAction:
     req.context.get(USER_ACTION) })`; if `null` because the refresh was idle-gated, the request goes out without a
     header and the WR9 matrix below decides (no sign-out here); else clone with
     `setHeaders({ Authorization: 'Bearer ' + (token ?? store.authHeader()) })`;
  3. 401 policy (WR9), decided by `retryable401(res)`: `res.status === 401 && !isAuthRoute(req.url)` **and** the body
     code is null/empty, `unauthorized` (the App-layer 401 the expired access token actually carries,
     `09.1.4-T1:21`, `plans/09-backend-api.md:72`), `unauthenticated`, **or** the response carries an invalid-token
     challenge (`WWW-Authenticate: Bearer error="invalid_token"`). 09 configures no `OnChallenge`/`JwtBearerEvents`
     (nothing under `plans/features/09-backend-api`), so the bodiless and challenge forms are tolerated but never
     assumed. Then:
     a. refresh once — `store.ensureFreshAccessToken({ userAction: req.context.get(USER_ACTION) })` — and replay the
        **original** request exactly once, marked with the `RETRIED` context flag (a context token, so a clone keeps
        it; a replay of a replay is impossible);
     b. `fresh === null` because the refresh was **idle-gated** (WR11: no `USER_ACTION`, `isActive()` false) →
        rethrow the 401 and **keep the session** (`status()` stays `'authenticated'`; realtime/polling stay paused
        and the user's next action refreshes normally — an idle tab must never be logged out by a poll);
     c. `fresh === null` because the refresh **failed**, or the replay 401s again → `store.signOut('revoked')` and
        rethrow — this is the explicit terminal owner for `session_revoked`-style expiry;
  4. **pass-through (never replayed, WR9)**: `reauth_required`, `invalid_credentials`, `invalid_mfa_code`,
     `mfa_token_invalid`, `mfa_enrolment_required`, `hub_ticket_invalid`, `refresh_token_reused`, `session_revoked`
     reach the caller unchanged, with two session effects only: `session_revoked` → `signOut('revoked')` and
     `refresh_token_reused` → `signOut('reused')` (the response is still returned). `hub_ticket_invalid`
     (10.2.4-T1 takes a new ticket), `mfa_enrolment_required` (10.3.3-T1 calls `beginEnrolment`) and
     `reauth_required` (10.3.3-T3 `ReauthDialog` re-runs the **store-level** user action) do **not** end the session
     here;
  5. `/auth/*` is never replayed — the four login/reset routes plus `/auth/refresh`, which is `SILENT` and never
     refreshed recursively; a 401 there goes straight to the screen;
  6. refresh failure handling: a network failure surfaces `network_error` to the caller and keeps the session until
     the token expires (D9, offline-friendly); refresh 403 `forbidden` (Origin) → dev-console line, `unknown_error`
     to the caller, **no** sign-out (§2 ⚠️).
- `web/src/app/core/session/auth.guard.ts` — `authGuard: CanActivateFn` and
  `authChildGuard: CanActivateChildFn` share the full-session decision: inject store/Router synchronously at
  guard entry, then await the memoized `store.restore(): Promise<void>` and inspect current mode/status.

  `mfaEnrolmentGuard: CanActivateFn` guards `/account/security/mfa-setup` outside the full-session shell: await

Full-session users must be able to enrol, including an unenrolled admin redirected by `adminGuard`; do not bounce them to dashboard. Enrolment mode never bootstraps `/me` or the full shell (10.3.3-T3 owns the setup flow).
  `anonymousGuard` also awaits restore and redirects authenticated full/enrolment sessions to dashboard/setup.
- `web/src/app/core/session/provide-session.ts` — `export function provideSession(): EnvironmentProviders`

## Steps

1. Models, port and repository; assert `expiresAt` parsing from the ISO string the API returns.
2. `SessionStore` (signals + `restore` + `ensureFreshAccessToken` + `signIn` + `beginEnrolment` + `logout` +
   `signOut` + `reset`) with `RefreshLock`, the single-flight promise and the `SESSION_SCOPED` fan-out (WR8, WR10).
3. `ActivityTracker` with the four listeners, the 1/10 s throttle, the role-aware window and `DestroyRef` cleanup.
4. `sessionInterceptor` + `sanitizeReturnUrl`; wire the skip list and the retry-once rule.
5. `authGuard` / `mfaEnrolmentGuard` / `anonymousGuard` + `provideSession()`; register in `app.config.ts`. The unit
   spec injects `RefreshLock`, so it stubs `navigator.locks` with a `FakeLock` and runs one case without the API
   (jsdom never has Web Locks) to prove the in-process fallback.
6. `core` scope `session.*` keys in vi + en; leave the parity check to 10.2.5-T1.
7. Capture `private readonly injector = inject(Injector)` at store construction, then resolve
   `this.injector.get(Router)` in `signOut` if deferred resolution is necessary to avoid a cycle.
   `inject(Router)` inside a method called by an async action/interceptor is forbidden (NG0203).

      `reauth_required`, `invalid_credentials`, `invalid_mfa_code`, `mfa_token_invalid`, `mfa_enrolment_required` or

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Boot refresh times out / offline | anonymous, `restoreSettled` still true, no redirect loop; the next user action retries naturally |
| Refresh 403 `forbidden` (Origin misconfig) | not a session end; dev-console line + `unknown_error`; documented so it is not mistaken for `session_revoked` |
| Two browser tabs (WR10) | both refreshes serialise on `navigator.locks` (`nts-refresh`) and re-check the token after acquiring it, so only one presents the rotating cookie; a tab that still sends a stale cookie (restored from bfcache) gets `refresh_token_reused` → that tab signs out with the reuse banner (server theft detection, `09.3.2-T1:136`) |
| `navigator.locks` unavailable (jsdom, lock-less engine) | `RefreshLock` falls back to an in-process mutex so the in-process single flight still holds; the cross-tab guarantee is degraded and documented (no silent loss) |
| Clock skew / suspended laptop | the 30 s margin plus the `USER_ACTION` flag on a user action (WR11); a stale token after resume just 401s and follows the WR9 matrix |
| `expiresAt` missing/unparsable in the body | treat the token as stale (`expiresAt = 0`) so the next request refreshes; dev-console line |
| `signOut` triggered from a navigation guard | guard returns `false` and lets `signOut` navigate; no double `UrlTree` |
| Realtime `onclose` after the session ended | 10.2.4-T1 checks `status`; `ensureFreshAccessToken` returns `null` once `endReason` is set, so no refresh loop |
| `reset()` throwing in a feature store | caught per scope, remaining stores still reset, dev-console line only |
| Enrolment-only session (WR8) | `mode() === 'enrolment'` and `status()` is not `'authenticated'`, so realtime and `GET /me` never start; `anonymousGuard` keeps the user on `/account/security/mfa-setup`; `signIn()` after enrolment clears `enrolmentToken` |
| 401 that must not be replayed (WR9) | `reauth_required` → the screen opens `ReauthDialog` and re-runs the store action; `hub_ticket_invalid` → 10.2.4-T1 takes a new ticket; `mfa_enrolment_required` → `beginEnrolment`; none of them replays the request |

  second parallel refresh of the same cookie as reuse and revokes the whole family (`09.3.2-T1:136-138`, `:201:238`).

  client `markReauthenticated`), WR9 (401 retry matrix), WR10 (`RefreshLock` + `navigator.locks` + re-check),
  WR11 (`USER_ACTION` flag + `isActive()` gate).

  feature store, `sanitizeReturnUrl` for 10.3.3-T1, `provideSession` for the shell.

  (10 CR-46). Unit specs (Router harness, `FakeSessionApi`, `HttpTestingController`) cover every other Acceptance bullet.
- As built (QA L1): cross-tab, a tab waiting on `nts-refresh` cannot learn the other tab's in-memory token (no
  BroadcastChannel, out of scope), so it presents the already-rotated cookie after the lock — a legitimate serial
  rotation, never a parallel presentation. The in-lock re-check covers same-tab only.
- No client-side timeout on the boot refresh (QA L2): aborting a refresh after the server rotated the cookie could
  lose the new cookie and turn the next refresh into `refresh_token_reused` (family revoked); the browser's fetch
  limit applies.
- Refresh 403 `email_not_verified` (09 `RefreshSessionService`) → boot `restore_failed`, mid-session `unknown_error`
  without sign-out; 10.3.3-T1 owns any verify-email UX.
- As built (QA D1): the backend answers a refresh without a cookie with 401 `session_revoked` (WT21) and the SPA
  cannot see the HttpOnly cookie, so at boot any 401 except `refresh_token_reused` settles anonymous (no banner, no
  scope reset); `refresh_token_reused` → `reused`; network/5xx/403/other → `restore_failed`, and a later
  `ensureFreshAccessToken({ userAction: true })` retries the refresh (success commits, failure re-applies this
  classification, no navigation). Mid-session `session_revoked` still signs out as `revoked`.
- As built (review): (1) logout needs cookie AND `Bearer` (`LogoutCommand` is not anonymous): `SessionApi.logout(accessToken | null)`;
  `SessionStore.logout()` takes a fresh token (failure → `null`, never blocks), signs out locally at once (no
  returnUrl) and only then POSTs with an explicit header, which the interceptor passes through (still no auto-Bearer,
  refresh or replay); 204 and 401 `session_revoked` resolve, a null token resolves on any outcome, any other failure
  rejects without restoring anything. (2) A refresh answering a different `sub` than the held session is not adopted:
  `signOut('expired')`, flight resolves `null`; restore and `restore_failed` retries commit normally. (3) The
  interceptor binds every request to `store.generation()` (also passed as `ensureFreshAccessToken({ generation })`,
  which resolves `null` for a replaced session): a late 401 of an old session neither replays nor signs out the new
  one. (4) Refresh-401 `signOut('revoked')` only while the store still holds a full session. (5) Network is detected by
  `code`/`kind`, so a store `unknown_error` reaches the caller as a non-HTTP error. (6) HTTP-surfaced refresh failures
  carry `code`, `Retry-After` and `traceId` so the caller's mapper reads the same `AppError`.
