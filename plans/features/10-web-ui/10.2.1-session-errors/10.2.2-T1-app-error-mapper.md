## Goal

One place turns any HTTP failure into a typed `AppError`, and one helper binds its field errors to the typed reactive
form that caused it, so every wave-1 screen shows the code-specific i18n message (vi + en), never `detail`, and knows
whether the answer is a validation error, a conflict, a rate limit, a client bug or an unknown server error.

## Design

Files (all new):
- `web/src/app/core/errors/app-error.ts` — `interface AppError { code: string; status: number; kind: AppErrorKind;
  fieldErrors: Record<string, string[]>; retryAfterSec?: number; traceId?: string; problem?: ProblemDetails }`;
  `type AppErrorKind = 'validation' | 'auth' | 'conflict' | 'precondition' | 'rate_limit' | 'not_found' |
  'feature_disabled' | 'client_bug' | 'network' | 'server' | 'unknown'`; guards `isValidation`, `isConflict`,
  `isRateLimited`, `isClientBug`.
- `web/src/app/core/errors/error-code.ts` — `ERROR_CODES` (as const, one entry per catalogue row reachable in
  wave 1, plus the alias `unauthenticated` → `errors.session_revoked`), `type KnownErrorCode`,
  `isKnownCode(code)`, `kindFor(code: string, status: number): AppErrorKind`.
- `web/src/app/core/errors/app-error-mapper.ts` — `@Injectable({providedIn: 'root'}) class AppErrorMapper`:
  `from(error: unknown): AppError` (accepts `HttpErrorResponse`, `Error`, anything else),
  `fromProblem(problem: ProblemDetails | null, status: number, retryAfter: number | null): AppError`,
  `messageKey(error: AppError): string` → `errors.<code>` (or `errors.unknown_error`),
  `fieldMessageKey(error: AppError, ptr: string): string`, `traceFooter(error)`, all pure apart from the injected
  `isDevMode()` flag.
- `web/src/app/core/errors/bind-field-errors.ts` — `bindFieldErrors(form: AbstractControl, error: AppError, opts?:
  { pointerSeparator?: '.'; markTouched?: boolean }): string[]`; maps `fieldErrors` keys to controls by
  `control.get(path.split('.'))`, sets `{ [key]: messageKey }` on them, marks them touched, returns the keys that had
  no control (caller shows them in `FormErrorAlert`).
- `web/src/app/core/errors/index.ts` — barrel re-exporting the four modules.
- `web/src/app/shared/ui/form-error-alert/form-error-alert.component.{ts,html,scss}` —
  `inputs: error = input<AppError | null>(null)`, `unmappedKeys = input<readonly string[]>([])`,
  `showTrace = input(true)`; OnPush; renders nothing when `error() === null`.
- No `FormFieldError` component is built: D11 (`README.md:168`) and WR4 (`README.md:347`) list neither it nor a
  owner for it, so each consuming page renders the first message key `bindFieldErrors` wrote into a control's
  `errors` inside its own `mat-error` (id bound to `aria-describedby`). Adding a shared component here would need
  TL sign-off.
- `web/src/app/shared/ui/retry-countdown/retry-countdown.component.{ts,html,scss}` —
  `inputs: seconds = input.required<number>()`, `messageKey = input<string | null>(null)`;
  `output: elapsed = output<void>()`; internal `remaining = signal(seconds())`, one 1 s `setInterval` cleared in
  `DestroyRef.onDestroy`; re-arms when `seconds()` changes (immediate first render, `@if (remaining() > 0)`).
- `web/src/app/shared/ui/conflict-dialog/conflict-dialog.component.{ts,html,scss}` — Material `MatDialog`
  wrapper with `data: { messageKey: string; detailKeys?: readonly string[]; saveAsNewLabel?: string }`;
  `outputs: reload`, `saveAsNew`, `cancel`; ESC = cancel; focus trap + focus restore (Material default), and
  returns `'reload' | 'saveAsNew' | 'cancel'` from `afterClosed()` for callers using the service form.
- `web/src/app/shared/ui/index.ts` — add the three components to the existing barrel (10.1.3-T1 file, one export
  line each; note it in Outputs).
- `web/src/assets/i18n/errors/vi.json`, `web/src/assets/i18n/errors/en.json` — new scope, keys as listed in plan
  §6 (one leaf per catalogue code + `errors.form.*`, `errors.action.*`, `errors.retryIn`, `errors.retryNow`,
  `errors.conflict.*`).

Contract:
- Copy text is looked up by key only; `problem.detail`, `title` and `type` are never rendered (D9); `traceId`, when
  present, is rendered in the alert footer through `errors.unknown.trace` with `{{traceId}}`.
- 428 `if_match_required`, 400 `idempotency_key_required`, 422 `idempotency_key_reused` → `kind: 'client_bug'`:
  the user sees `errors.<code>` and, in dev (`isDevMode()`), a single console line `code/status/traceId` with no
  body.
- Status mapping when the body is missing a `code`: 0 → `network_error` (also for a bare `ProgressEvent` error),
  400 → `validation_failed`, 401 → `unauthenticated` (see the next bullet) else `unauthorized`, 403 →
  `forbidden`, 404 → `not_found`, 409 →
  `concurrency_conflict`, 412 → `concurrency_conflict`, 413 → `payload_too_large`, 422 →
  `idempotency_key_reused`, 428 → `if_match_required`, 429 → `rate_limited`, 5xx → `internal_error`; anything
  else → `unknown_error`. An unknown non-empty `code` wins over the status and maps to `unknown_error`.
- `retryAfterSec` is read from the `Retry-After` header (integer seconds; an HTTP-date is ignored and treated as
  absent, `[INFERENCE]` the API only sends seconds).
- 401 in practice (WR9): the mapper receives exactly the 401s the interceptor does **not** replay — `reauth_required`,
  `invalid_credentials`, `invalid_mfa_code`, `mfa_token_invalid`, `mfa_enrolment_required`, `hub_ticket_invalid`,
  `refresh_token_reused`, `session_revoked`, plus any 401 on `/auth/*`. Only the first form (no code,
  `unauthorized`, `unauthenticated`, or an `invalid_token` challenge) is refreshed and replayed once; a replay that
  401s again, or an idle-gated refusal, is decided by the interceptor (WR11 keeps the session). `GET/PATCH /me` answers 401 `unauthenticated` when the token outlived the
  account (`09.3.4-T1-me-endpoints.md:49`, `:52`, `:100`); because that code is missing from the 09 §5.4 catalogue
  and `ErrorCodes`, the mapper maps it to `errors.session_revoked` ([OPEN] cross-plan gap, plan §10) so it can never
  render `errors.unknown_error`.
- `keywords_flagged` (02/03 D10) keeps its structured payload: `AppError.fieldErrors['keywords_flagged']` is not a
  field map — the mapper puts the raw entries on `problem` and screens render them as rows
  (`segment`, `index`, `rule` → `errors.keywords_flagged.rules.<rule>`).

## Steps

1. `app-error.ts` + `error-code.ts` (codes copied from `plans/09-backend-api.md` §5.4 and 02 D8; no invented code).
2. `app-error-mapper.ts` with the status/code table above; `from()` reads `status`, `statusText`, the parsed body
   (guarding non-JSON), and the `Retry-After` header; never copies `detail` into a message.
3. `bind-field-errors.ts` — path → `AbstractControl.get()`, `setErrors({ [messageKey]: true })`, `markAsTouched()`,
   return the unmapped pointers (deduplicated, in payload order).
4. The three shared components + their specs; OnPush, `input()`/`output()` only, no store/`HttpClient` injection (D2).
5. The `errors` i18n scope in both languages; register the scope in the Transloco loader config (10.2.5-T1's file —
   additive line, recorded in Outputs); leave the parity check to 10.2.5-T1.
6. Export through `core/errors/index.ts` and add the three components to `shared/ui/index.ts`.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Body is HTML (proxy/LB error page) or empty | fall back to the status table; no parse error surfaces |
| `Retry-After` missing on 429 | `retryAfterSec` undefined, the action stays disabled until the user retries manually (no invented countdown) |
| `errors` payload has an array of objects (`keywords_flagged`) | the mapper keeps them on `problem`; the screen renders rows, not a field map |
| Several non-validation errors | first code wins for `code`/`status` (server rule, `09.1.4-T1`); the mapper does not merge them |
| Validation payload for a control not yet in the form (segment added later) | key returned as unmapped; the screen may re-bind after the control exists — `bindFieldErrors` is idempotent |
| 202 body codes (`grant_requires_approval`, `setting_change_pending`, `objection_recorded`) | never arrive as errors; if one does, it maps to `unknown_error` (client bug) |
| Text direction/very long `traceId` | the footer wraps and truncates with `text-overflow: ellipsis`, never breaks the 360 px layout |
