## Goal

One root service owns exactly one hub connection for the signed-in user: it exchanges the access token for a 60-second single-use ticket, connects WebSockets-only to `/hubs/episodes`, and treats **every** close identically — backoff, fresh token, fresh ticket, connect, then a single `resync` that lets only stores with a live subscription refetch (coalesced within 250 ms). When the user has been idle past the role's window the service stops reconnecting and shows a paused state a user action can resume. No access token ever reaches a URL, no ticket is ever logged or stored, and a routine 401 refresh never tears the socket down.

### `RealtimeService` API

```ts
@Injectable({ providedIn: 'root' })
export class RealtimeService {
  private readonly tickets = inject(HubTicketRepository);
  private readonly connectionFactory = inject(HUB_CONNECTION_FACTORY);
  private readonly session = inject(SessionStore);
  private readonly activity = inject(ActivityTracker);
  private readonly errors = inject(AppErrorMapper);

  private readonly _state = signal<RealtimeState>('idle');
  readonly state = this._state.asReadonly();
  readonly connected = computed(() => this.state() === 'connected');
  readonly paused = computed(() => this.state() === 'paused');
  private readonly _resync = signal(0);
  readonly resync = this._resync.asReadonly();
  private readonly _progress = signal<ReadonlyMap<string, RenderProgress>>(new Map());
  readonly progress = this._progress.asReadonly();

  start(): void;                       // idempotent; no-op unless SessionStore.mode === 'full' && SessionStore.status() === 'authenticated' (WR8)
  stop(): void;                        // hub.stop(), clear subscriptions, detach listeners, state='stopped'
  reset(): void;                       // the SESSION_SCOPED entry point: stop() + progress.set(new Map()) + state='idle'; safe to call twice
  pause(): void;                       // state='paused'; nothing is scheduled
  resume(): void;                      // user action → refresh → ticket → connect → resync
  on<E extends RealtimeEventName>(name: E, ids?: Partial<RealtimeIds>): Observable<RealtimeEventOf<E>>;
  subscribeEpisode(episodeId: string, handler: () => void): RealtimeSubscription;   // ref-counted, coalesced
}
```

* `connect()` (single-flight, guarded by `connecting`): `await session.ensureFreshAccessToken()` → `await tickets.issue()` → `connectionFactory().start('/hubs/episodes?ticket=' + encodeURIComponent(ticket))` → `state='connected'`, `attempt=0`, `resync.update(n => n + 1)`. The URL string is a local: it is passed to `start()` and never stored on the service, never logged, never put in an error message.
* `onClose()` (one path for backstop abort, family revocation, network drop): if `stopped` → ignore; if `!activity.isActive()` → `pause()` (no ticket request at all, D7); else `state='backoff'`, `delay = nextDelayMs(attempt++, rng)`, `setTimeout` registered with `DestroyRef`; on fire → `connect()`.
* Ticket errors (via `AppErrorMapper`): `401` → exactly one extra `ensureFreshAccessToken()` + one retry of the ticket (then backoff); `429 rate_limited` → `delay = max(delay, retryAfterSec * 1000)` and no attempt reset; `503` → backoff.
* `ensureFreshAccessToken()` rejection → `stop()` and no reconnect (the session flow of 10.2.1-T1 routes to `/login`).
* `visibilitychange → visible` while `connected` → `resync` +1 (missed events), no reconnection.
* Event dispatch: the socket handler looks the incoming name up in **`WIRE_TO_NAME`** — the four canonical PascalCase client names (`EpisodeUpdated`, `RenderProgress`, `PublicationUpdated`, `CreditBalanceChanged`, 00 §8) plus their snake_case aliases (the internal NOTIFY `event` values the Api listener maps before `SendAsync`, e.g. `render_progress`) — and a name that is not a key is dropped **before** the payload is parsed: ids are never touched, never logged. `RenderProgress` → clamp `percent` to `0…100`, ignore an unknown `stage` string, store in `progress` **without** HTTP; a stage change resets the stored `percent`; every other mapped event → `subscriptions.notify(matchingKey)` where the matching key is the event's `episodeId` (and `seriesId` when present).
* `effect()` on `session.status()`: start only when `session.mode() === 'full' && status() === 'authenticated'`; `'anonymous'`/`'ended'` → `reset()`; the transient `'restoring'`/`'refreshing'` are ignored, so a routine 401 refresh never tears the socket down (WR8). In enrolment mode no socket and no `GET /me` ever start, because `status` is not `'authenticated'` there.
* `reset()` is registered with the `SESSION_SCOPED` fan-out of 10.2.1-T1 and builds on `stop()`: hub `stop()`, subscriptions cleared, **the per-user `progress` map replaced by a new empty map**, `state='idle'`, timers cleared. A bare `stop()` (refresh failure, teardown) keeps `state='stopped'`; only a session end resets to `'idle'`, so nothing per-user survives a sign-out and a second user on the same device can never receive the first user's progress.
* Background refetches: the refetch a subscriber performs in response to `resync`/`EpisodeUpdated` is issued **without** the `HttpContext` `USER_ACTION` flag (WR11), so a 401 on it refreshes only while `ActivityTracker.isActive()` — an idle tab cannot keep an owner session alive through event-driven traffic.
* `subscriptions.notify(key)`: one `setTimeout(250)` window per key; all subscribers of that key are called once per window, in registration order; a refetch that throws is caught (the store owns its error state) and never breaks the window.
* `subscribeEpisode` registers a **local** id filter and refetch callback; the server auto-joins `user:{id}`.
  It never invokes a join/leave episode RPC (none exists). Unsubscribe removes this local registration/window.
* Connect attempts capture both session generation and a private connection generation. `stop/reset/pause`
  invalidates the latter; check both after token/ticket/start awaits and in socket callbacks. Close any late
  socket and discard stale ticket/state/progress/resync/error completions; old cleanup cannot clear a newer flight.
  Progress updates clone the Map and replace the immutable entry before `_progress.set(next)`; no in-place Map
  mutation. Socket callbacks notify consumed signals directly, without NgZone or forced change detection.
* Snapshot readiness (`00e7d5d5415579c7df55a66dc2177cbc2e31eb78`, 2026-10-02): transport/ticket are implemented
  by 09.8.1-T1/T2; `RealtimeEvent` forwards data only for RenderProgress, other events are ids-only.
  Render producer workflows await 09.6.1-T1/09.6.2-T1/09.6.3-T1/T2; publication workflow awaits 06.2.1-T1;
  CreditBalanceChanged awaits plan 12 (S). Transport smoke is not proof those producers or MFA UI login exist.

### Performance, security, reuse, a11y, copy

* **Performance**: exactly one ticket per connect attempt (never per event, no N+1); one connection for the whole app; `progress` and `state` are signals so change detection runs only where a signal is read; coalescing caps refetch storms at one call per key per 250 ms; backoff tops out at 30 s so an idle server cannot produce a busy loop; all timers are `DestroyRef`-scoped and cleared by `stop()`.
* **Security**: access token only in the `Authorization` header (10.2.1-T1 interceptor) — never in the hub URL; the ticket is single-use, 60 s, kept in a local variable, never logged (no `console.*` with the URL, dev included) and never persisted; unknown events never hit the DOM; no `[innerHTML]`; the service exposes no data of its own beyond ids/progress (D14: never renders content).
* **Reuse**: produces `HubConnectionPort` + `HUB_CONNECTION_FACTORY` + `RealtimeService.subscribeEpisode` (consumed by 10.4.3-T2 and 10.5.2-T1), `progress` (consumed by wave-2 10.6.1-T1). Reuses `SessionStore`, `ActivityTracker`, `AppErrorMapper`, the D5 generated client, `DestroyRef` cleanup. `visible-poll` (D17) is **not** used — the hub is event-driven.
* **a11y**: no UI in this task; the paused/backoff/paused states are surfaced by `RealtimeStatusComponent` (10.2.6-T1) with `aria-live="polite"` and the copy keys `shell.realtime.{connected,reconnecting,paused,continue}` (D16).
* **Copy keys (vi+en)**: this task authors **no** user-visible string. It consumes `shell.realtime.*` (vi: `Đã kết nối trực tiếp` / `Đang kết nối lại…` / `Cập nhật trực tiếp đang tạm dừng` / `Tiếp tục`; en: `Live updates on` / `Reconnecting…` / `Live updates paused` / `Continue`) from the `core` scope (10.2.6-T1) and `errors.rate_limited` / `errors.network_error` / `errors.unknown_error` from the `errors` scope (10.2.2-T1). `hub_ticket_invalid` deliberately has **no** copy key: it is never shown, only retried once.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Server aborts after `Hubs:MaxConnectionMinutes` (owner 5 min, user 15 min) | Indistinguishable from any other close → one refresh + ticket + connect; the client never hard-codes the cap |
| Family revocation while connected | Client-side close (server abort) → same path; the refresh that follows fails with `session_revoked` → `stop()` + login |
| Network offline | `onClose` → backoff ladder; `start()` rejects → treated as a close (no tight loop); `visibilitychange` while offline still only emits `resync` when connected |
| 429 on the ticket route (policy `hub` 10/min) | `Retry-After` becomes the delay, ladder intact; a legitimate reconnect cadence (≥ 5 min) never reaches the limit |
| 503 on the ticket route | Backoff, no user-facing error (the app stays usable without live updates) |
| Two tabs open | Each tab has its own connection and its own ticket (single use per row, 09.8.1-T2) — no shared state, no interference |
| Event arrives for an unknown episode / after unsubscribe | Dropped by the registry (no key match) |
| Duplicate/out-of-order `RenderProgress` | Last event wins within a stage; a stage change resets `percent` [INFERENCE: the server emits one event per change in order] |
| `stop()` while a connect is in flight | The pending `start()` resolution is discarded (`stopped` guard) and the connection is closed, so no socket leaks |
| `visibilitychange` listener and timers | All registered through `DestroyRef`; `stop()` detaches them (no leaks in a long SPA session) |
| A client method name renamed upstream (e.g. `RenderProgress` → `RenderProgressV2`) | The event is dropped by `WIRE_TO_NAME` (no crash, no log with ids); only that event's live behaviour is lost — the integration smoke that asserts one `EpisodeUpdated` reaches a store fails in the same PR as the backend rename |
| Enrolment-only session | `status` is not `'authenticated'` → `start()` no-ops, no ticket, no socket; the MFA enrolment screen owns the UI (WR8) |
| `reset()` called twice (logout + explicit stop) | Idempotent: the second call sees no connection, an empty registry and an empty `progress` map, and leaves `state='idle'` |
| Background refetch hits a 401 while the user is idle | No `USER_ACTION` flag → the refresh runs only when `isActive()`; otherwise realtime pauses and the bar offers Continue (WR11 + D7), so an abandoned tab cannot renew an owner session |
| Refresh succeeds but the ticket is stale (issued > 60 s ago) | Claim fails → `401 hub_ticket_invalid` → one new ticket (the ticket is fetched immediately before `start()`, so this is a rare race) |
