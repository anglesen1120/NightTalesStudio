## Goal

Every wave-1 screen can be written in `vi` (default) and `en` with one mechanical rule: a feature route declares a Transloco scope, the scope's two JSON files live under `web/src/assets/i18n/<scope>/<lang>.json`, and CI fails when the two files drift apart or when a key used in code has no translation. Locale-coupled values (dates, numbers, schedule times) are formatted through one service so no screen calls `Intl` directly, and the language the user picks is applied everywhere (Transloco, `<html lang>`, `Intl`, later the API via `PATCH /me`).

### `LocaleService` behaviour

* `resolveInitial(profile, pref, browserLangs)`: first defined of `profile` (from `SessionStore.me()?.uiLocale`) → `pref` (`core/prefs`, storage key `nts.prefs.v1`, field `uiLanguage`) → first browser tag whose primary subtag is `vi`/`en` → `'vi'`.
* `resolveStartup(profile)`: what the app-config initializer calls. Browser platform: `resolveInitial(profile, savedUiLanguage, navigator.languages)`. Server platform (prerender): `resolveInitial(profile, null, [])` — never `navigator` (Node defines one that mirrors the build host's locale) and never storage, so a prerendered page cannot get its language from the CI runner.
* `activate(locale, { persist }): void`: synchronous local operation, sets Transloco active language and
  document lang, then private `_locale.set(locale)`; public `locale = _locale.asReadonly()`. Persist writes only
  `uiLanguage` of `nts.prefs.v1` through core/prefs. No await, profile request or writable public signal.
* Locale persistence lives in the **shell store** (10.2.6-T1), not here: `activate()` does local work only, so a root singleton never depends on a route-provided repository. `ShellStore.changeLocale` calls `LocaleService.activate(...)` and then, when authenticated, `MeRepository.updateUiLocale(...)` + `SessionStore.setMe(...)`. There is no `LocaleService.setLocale`.
* Formatting: `vi` → `vi-VN`, `en` → `en-US`; `formatDateTime` uses the caller's options; `formatInZone(instant, timeZoneId)` renders `dd/MM/yyyy HH:mm`-style output **plus** the zone id (D10 requires an explicit zone wherever the value is a schedule — the autopilot screen of 10.4.3-T1 consumes it).
* Material date locale: `MAT_DATE_LOCALE` is provided at bootstrap from the effective locale ([DECISION] in-task): a language change updates `Intl` immediately and Material's date formats on the next load; wave 1 has no Material date input outside the autopilot tab, which formats through `formatInZone`.
* Route scopes provide their loader/provider at the lazy route. Templates consume Transloco's notified loading
  bridge and readonly locale, not an unobserved subscription variable. DestroyRef scopes any imperative
  subscription/effect; no root service injects a route repository. Late responses may populate a language-keyed
  cache but cannot restore the old active language or patch destroyed route state. Explicitly retain fallback
  semantics below; do not silently display vi content as a successful en load.

## Steps

1. Add the two exact dependency versions + the three npm scripts; commit the updated `package-lock.json`.
2. Add `web/tools/web/i18n-keys.mjs` (`flattenKeys`, `diffKeySets`, `findDuplicateLeaves`, `matchesPattern`, `checkUsedKeys`, `HANDED_OVER_KEYS`) and `web/tools/web/check-i18n.mjs` + `web/.translocorc.json` (for `i18n:find`); run the CLI on an empty assets tree, on a hand-made broken tree (one-sided key, duplicate leaf, non-string leaf) and on a tree with a template key that has no JSON entry, proving all five failure exits and the green exit.
3. Create `web/src/assets/i18n/core/{vi,en}.json` with the `common.*` keys above (identical key sets; no `session.*`, no `errors` — those are 10.2.1-T1/10.2.2-T1) and add `provideTransloco` + the loader to the app config.
4. Implement `TranslocoHttpLoader` (per-scope, successes cached, failures evicted and rethrown, scope/language validated, prerender-safe branch) and `bundled-translations.ts` with `core` (the map is data-driven and `PRERENDER_SAFE_SCOPES` is derived from it: a scope absent from it has no bundle and the loader takes its error path).
5. Implement `locale.model.ts` + `LocaleService` (resolution, activate, four format methods, `formatInZone`).
6. Wire `body[lang]`-free plumbing: keep `<html lang="vi">` as the static default in `index.html` (prerender-safe) and let `activate()` own it at runtime; add `Transloco` `missingHandler` with `useFallbackTranslation: false` (dev: `console.warn('missing key', key, lang)` once per key and language + return `key`; prod: return `key`). No fallback value is shown: a lazy route loads only the active language's file of its scope (acceptance 104), so a fallback language would cost every route a second file and display untranslated text as if it were translated; CI parity (`i18n:check`) keeps both files equal, so the key path is the visible-bug path.
7. Document the key style in `web/README.md` (one short section: scope → file, `scope.area.item`, camelCase leaves, no sentence fragments outside a scope, handed-over keys verbatim).
8. Run `npm run i18n:check` + `npm run lint` + `npm test` locally; add the i18n e2e spec (owner of the config: 10.1.5-T1 — the spec file lives in `web/e2e/i18n.spec.ts` and uses the shared login helper).

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Scope JSON missing for a language | Check fails in CI (`missing language file`); at runtime this is the "HTTP error" row below (a 404 is a failed load: not cached, retried on the next activation); keys render as the key path while the other language's file loads (visible bug, never the other language's text) |
| Key present in one language only | CI fails (both directions); at runtime the active language's file is authoritative: the key renders as its key path, never the other language's text (`useFallbackTranslation: false` — a lazy route loads only the active language's file, a fallback would load a second file per route and show untranslated text as translated) |
| Key missing everywhere | dev: warn once per key and language + key path; prod: key path (no `en` fallback value, same reason as above). Never `undefined`/empty |
| Translation value is `null`/number/array | `check-i18n.mjs` rejects non-string leaves (`scope: non-string leaf`) |
| HTTP error / offline while loading a scope | The loader evicts its own cache entry and **throws**; a failure is never stored as `{}` (`failedRetries: 0` stays: the retry is the next activation, not a hidden loop). Observed with Transloco 8.4.0, `fallbackLang: 'en'`, specs in `transloco-loader.spec.ts` ("Transloco service with a failing scope"): (1) `load('quality/vi')` fails → Transloco fetches `quality/en.json` once; if that loads, nothing rejects, the active language stays `vi`, nothing is stored for `quality/vi` and keys render as the key path (`quality.<key>`); (2) if the fallback fails too, `load` rejects with `TranslationLoadError` and each failed file logs once in dev; [INFERENCE from Transloco 8.4 source, not exercised: a template pipe/directive subscribes without an error handler, so the error reaches the global error handler/console and that binding shows empty text rather than the key path until it is re-activated]; (3) in both cases the next `load('quality/vi')` (route re-entry, language switch back) issues a **new** request and, on success, stores the real JSON — nothing is cached for the app's lifetime. No retry loop, no spinner lock (the loader never blocks a route) |
| Browser language unsupported (`fr`) | `vi` (default), no warning |
| Prerender of a public page | the language is never taken from the build host (`LocaleService.resolveStartup` skips `navigator` and storage on the server platform: `vi` unless the route activates its own language, D12); `bundledFor` path only — no HTTP during prerender (D12/F18); a scope not in `PRERENDER_SAFE_SCOPES` (derived from the bundled map, `core` today) must not be used by a prerendered route: its load fails like any other and is not cached |
| Scope or language that is not well-formed (`../..`, `x/../y`, `__proto__`, `fr`, …) | `getTranslation` returns `{}` with no request and no cache entry (dev log `i18n scope rejected`); bundle lookups use own-property checks, so prototype keys never resolve |
| Language switch while `PATCH /me` fails (offline, 5xx, 400) | Local locale stays switched, snackbar `shell.language.saveFailed` (10.2.6-T1); the server value wins on the next `GET /me` |
| Duplicate leaf in one JSON file | Check fails (`duplicate leaf`) — JSON's last-wins would silently drop a translation |
| Key added by a developer but not used | `npm run i18n:find` reports it; washing unused keys is a review step, not a CI failure (avoid false failures in feature branches) |

## Notes

* Produces (reuse): `LocaleService` (consumed by 10.2.6-T1 and by the autopilot schedule display of 10.4.3-T1/10.4.3-T2), `flattenKeys`/`diffKeySets` (consumed by `tools/web/check-i18n.mjs` **and** `i18n-keys.spec.ts` — one implementation), `PRERENDER_SAFE_SCOPES`/`bundledFor` (consumed by 10.3.1-T1), the `i18n:check` npm script (run by 10.1.5-T1's `web.yml`, D15).
* Reuses: `core/prefs` (D6, the only storage writer), the `HttpClient` configuration of 10.1.4-T1, the Vitest builder of 10.1.5-T1, `@fontsource/be-vietnam-pro` + theme tokens of 10.1.3-T1 (`vi` glyph coverage — D11), no D11 shared component is modified by this task.
* Hand-overs: 10.3.1-T1 adds its `public` JSONs to `bundled-translations.ts` (one line per language) because it prerenders; 10.2.2-T1 owns `errors/*` and 10.2.1-T1 owns `session.*` inside `core/{vi,en}.json` — the scaffold created here must not be edited by them outside their own branch (no key collision, verified by `i18n:check`); the `quality` scope (WR15, `web/src/assets/i18n/quality/{vi,en}.json`) is authored by the hints work (10.5.10-T1 / 02 copy) and is picked up by the same check once the directory exists.
* Lint seam: any ESLint rule about hard-coded user-visible template strings belongs to **10.1.2-T1** (the workspace eslint config); this task enforces D10's CI requirements (per-scope key parity **and** every used key defined) in `npm run i18n:check` and deliberately adds no template-literal lint of its own, so the two owners cannot drift into two different key checks.
* Security/privacy (D1–D18): no user data, token or content in any JSON or in prefs; translations render through interpolation only (no `[innerHTML]`, no `bypassSecurityTrust*`); no third-party font/CDN is contacted, so D4's `font-src 'self'` and `script-src 'self'` stay intact.
* Performance (D13): the `core` scope is part of the initial bundle by design and is the only scope that is; every other scope is loaded by its lazy route; the loader memoises per `scope+lang`; no `Intl` object is constructed per render (one formatter per tag cached in the service).
* a11y (D16): `<html lang>` follows the active locale (screen-reader pronunciation), the language control is labelled, and the e2e axe run covers both languages; `vi` strings are longer than `en` — the shell's 360 px check (10.2.6-T1) is run in `vi`.
