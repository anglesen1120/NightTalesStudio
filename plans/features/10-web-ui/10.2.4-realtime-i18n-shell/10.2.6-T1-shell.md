## Goal

One authenticated layout wraps every wave-1 screen: a top bar (product name, page title, `header-end` slot, language switch, user menu), a side navigation with the three P destinations (Dashboard, Series, Episodes) and `aria-current`, a skip link, a `<main>` outlet, and a realtime status strip that shows "paused — Continue" when the hub is asleep. The shell also loads `/me` once into `SessionStore` (name, e-mail, role, `features[]`, `uiLocale`) and owns the language switch: it applies the locale locally at once and, when signed in, persists it with `PATCH /me { uiLocale }` without ever blocking or reverting the UI on failure.

### `ShellStore` API

```ts
@Injectable()
export class ShellStore {
  private readonly me = inject(MeRepository);
  private readonly session = inject(SessionStore);        // me/setMe/hasFeature/status/mode/logout
  private readonly locale = inject(LocaleService);
  private readonly realtime = inject(RealtimeService);
  private readonly snack = inject(MatSnackBar);
  private readonly title = inject(Title);

  readonly summary = computed(() => this.session.me());
  readonly navItems = computed(() => NAV_ITEMS.filter(i => i.visible()));
  readonly realtimeState = computed(() => this.realtime.state());
  readonly pageTitle = signal('');                        // from route data.titleKey through Transloco

  loadMe(): Promise<void>;          // once, only when session.mode() === 'full' && session.status() === 'authenticated' && session.me() === null → me.get() → session.setMe(mapped)
  changeLocale(locale: AppLocale): Promise<void>;
  logOut(): void;                   // session.logout() (POST /auth/logout, no returnUrl) — the redirect is 10.2.1-T1's job (WR8)
  resumeRealtime(): void;           // realtime.resume()
}
```

* `loadMe()`: guarded by an in-flight promise, by `session.me() === null`, and by `session.mode() === 'full' && session.status() === 'authenticated'` — so a re-render, a navigation or a second shell mount performs **one** `GET /me`, and the enrolment-only session never calls it (WR8). A `401` is left to the interceptor (session flow); any other `AppError` shows `ErrorState` inside the shell body only for the profile block — the navigation stays usable (a profile failure must not lock the app). The mapping is defensive: `features` is read as `me.features ?? []` and unknown keys are dropped, so a deploy skew or an older API build that returns a `MeDto` without `Features` still renders (10 CR-10 **is** applied upstream — `MeDto.Features`, `09.3.4-T1:22-24`) — in that degraded case every flag-gated block simply stays hidden.
* `changeLocale(locale)`: `await localeService.activate(locale, { persist: true })` (immediate: Transloco + `<html lang>` + prefs) → if `session.status() === 'authenticated'` → `me.updateUiLocale(locale)` → `session.setMe(mapped)`; a failure shows `shell.language.saveFailed` in a snackbar and **keeps** the local choice (the server value wins on the next `GET /me`). One call per user action: a re-entrant click while a request is in flight is ignored.
* `pageTitle`: on `NavigationEnd`, `titleKey` (route `data`) → `transloco.translate(key)` → `Title.setTitle()`; re-applied on a locale change so the browser tab matches the language.
* Navigation uses `RouterLink` + `RouterLinkActive`; the active item renders `aria-current="page"`; below 600 px `SideNavComponent` gets `mode="over"` and the top bar shows a hamburger with `aria-expanded` and focus restore on close.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| `GET /me` fails (non-401) | Profile block shows `ErrorState` with `common.retry`; navigation, outlet and realtime stay usable — the shell never blocks the whole app on a profile read |
| `GET /me` returns `features: []` | `hasFeature` is `false` for every flag; flag-gated blocks hide themselves (D14) and the shell shows no empty slot |
| `hasFeature` flips off mid-session (404 `feature_disabled`) | The owning block hides and refetches `/me` (D14) — the shell re-renders because `SessionStore.me` changed; no shell change is needed |
| `me` is still `null` while the shell renders (slow `/me`) | Top bar shows the product name only, the user menu trigger renders `shell.menu.triggerLabel`, and the nav is fully functional |
| Language switch while a route is loading | Locale applies immediately; the scope JSON of the new language is fetched by the loader (10.2.5-T1); one pending switch wins (last click) and issues one `PATCH` |
| Language switch while offline | Local locale switches; `PATCH` fails → snackbar; the next session's `GET /me` restores the server value |
| Session ends while the user menu is open | `SessionStore.status → 'ended'` clears `me`; the menu closes (binding on `null`) and the router leaves the shell |
| 360 px with the overlay nav open and the status bar visible | The status bar stays inside the viewport, the overlay covers the nav only, focus stays in the overlay until Escape/selection |
| Very long display name or e-mail | Truncated with `text-overflow: ellipsis` in the trigger, full value available as the `mat-menu` header text (no tooltip-only information) |
| Role label unknown to the client | Falls back to `shell.menu.role.user` (defensive; the API enum is `user`/`admin`/`owner`) |
| Icon component missing/undrawable | Each nav item keeps its visible text label, so no information is lost (icons are decorative with `aria-hidden`); the inline SVG cannot fail to load like a sprite could |
| `MeDto` without `features` (deploy skew / an older API build) | `features: []` → `hasFeature` is always false → flag-gated blocks stay hidden; nothing crashes and the shell ships |
| Enrolment-only session | The shell is not shown for enrolment routes (10.2.1-T1's `mfaEnrolmentGuard` owns the redirect); if it ever mounts, `loadMe()` no-ops and `RealtimeService.start()` no-ops because `mode !== 'full'` |
| Empty `NAV_ITEMS` right after this task merges | The nav renders nothing (no error, no dead link); the first screen PR fills it. Reviewers must not accept a temporary hard-coded item |

* Performance (D13): the shell is the only eagerly loaded UI chunk; leaf components are OnPush and driven by signals; `@for` over `items` uses `track item.id`; icons are inline SVG (no icon-font download, no `MatIconRegistry` policy cost — WR12); `cursor-list` never issues a request without `loadMore()` and `visible-poll` never overlaps itself; one `/me` request per session (guarded), zero shell timers, no polling in the shell.
* Security (D1–D18): display name/e-mail live in memory only (never persisted — `core/prefs` holds the UI language and nothing else); the token is never rendered or stored; no `[innerHTML]`; the sign-out path clears `me` and the hub subscription (F22); navigation uses static relative routes only (no `returnUrl` construction, F21); no third-party origin is contacted, keeping D4's CSP tight.
* a11y (D16): landmarks, skip link, `aria-current`, labelled controls, trapped-and-restored focus for the overlay menu, `aria-live="polite"` on the realtime strip, contrast in both themes, ≥ 24 px targets, 360 px without horizontal scroll, reduced-motion honoured, axe in the e2e spec.
