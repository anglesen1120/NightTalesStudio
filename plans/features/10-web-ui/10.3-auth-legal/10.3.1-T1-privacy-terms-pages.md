## Design

Files under `web/src/app/features/public/` (D2 layout: `domain`, `data-access`, `application`, `ui`, `feature`, `index.ts`):

- `domain/legal.model.ts` — `LegalDoc`, `LegalRun`, `LegalBlock { id, kind: 'heading'|'paragraph'|'list'|'quote', level?, runs?, items? }`,
  `LegalDocument { doc, lang, version, effectiveDate, blocks }` (see `plan.md` §3.3).
- `domain/legal.port.ts` — `export abstract class LegalRepository { abstract get(doc: LegalDoc, lang: 'vi'|'en'): LegalDocument; }`
  **synchronous** because the content is a build-time module (no loading state, no HTTP during prerender).
- `data-access/legal.repository.ts` — `GeneratedLegalRepository implements LegalRepository`, reads the committed generated module
  `data-access/legal-content.generated.ts`; throws a build-time-style error (`legal_content_missing`) if a doc/lang pair is absent —
  the generator already fails the build, so this is belt-and-braces for a hand-edited checkout.
- `data-access/legal-content.generated.ts` — **generated, committed, lint-excluded** (same treatment as `shared/api`), header comment
  naming the generator and the manifest version.
- `application/public-seo.service.ts` — `apply(doc: LegalDocument, alternates: Record<'vi'|'en', string>)` sets `Title`, `Meta`
  (`description`, `og:title`, `og:description`, `og:type=article`, `og:locale`), and appends `<link rel="canonical">` +
  `<link rel="alternate" hreflang="vi|en|x-default">` to `DOCUMENT.head` (idempotent: it removes the elements it owns first).
  Head writes are DOM-based (no `innerHTML`), so they land in the prerendered HTML.
- `ui/legal-document-page/legal-document-page.ts` — standalone, OnPush, `input.required<LegalDoc>()`, `input.required<'vi'|'en'>()`;
  `computed` picks the document from the repository; renders `PageHeader` + a table of contents (`@for (b of toc(); track b.id)`)
  + the blocks (`@for (b of doc().blocks; track b.id)`), and at the end the language switch (`<a [routerLink]>` to the sibling route
  with `hreflang`) and `EmptyState` when `blocks.length === 0`.
- `public.routes.ts` — `privacy`/`terms` redirect to `/vi/...` (default language, D10) [INFERENCE]; the four leaf routes use
  `loadComponent` (D13) and resolve the document through a `legalResolver`.
- `app.routes.server.ts` — the four legal paths are `RenderMode.Prerender`; every other route already falls back to
  `RenderMode.Client` (D1). 10.1.1-T1 owns that file; this task adds exactly these four entries.
- `tools/web/legal-to-json.mjs` — Node ESM, no dependency. Reads `web/src/content/legal/manifest.json`
  (`{ "<doc>": { "version", "effectiveDate" } }`, authored by the 13 tasks) and, per doc/lang,
  `web/src/content/legal/<prefix>.<version>.<lang>.md` (manifest key -> file prefix: `tos -> terms`,
  `privacy -> privacy`; 13 CR-34); parses the Markdown subset `h2|h3`, paragraph, `-`/`1.` list, `>` quote,
  inline `**emphasis**`, `[text](href)`; rejects raw HTML (`<...>`), an unsupported construct, an unknown link scheme (allowed:
  `https://`, `mailto:`, `/`) and a missing/`vi`≠`en` version; emits `legal-content.generated.ts` (stable ids `block-<n>`,
  blocks in document order). `--out <path>` for tests; exit code ≠ 0 on any rejection, printing the file and line.
- `web/src/content/legal/manifest.json` + the four `*.md` files are authored by the 13 tasks (13.1.1-T1 / 13.1.2-T1); this task's
  fixture uses a tiny sample under `tools/web/__fixtures__/legal/` for the generator test and does not invent policy text.

Copy keys (D10, both languages): `public.legal.toc`, `public.legal.version`, `public.legal.updated`,
`public.legal.otherLanguage`, `public.legal.backHome`, `public.legal.empty`, `public.nav.privacy`, `public.nav.terms`, and
`errors.<code>` for every code this page can surface (only `not_found` is reachable, still added for the shared key set, D9).

No extra legal visual state is required (the deck is approved; see the T0 record).

`LegalDocumentPage` is a standalone public-route container outside the authenticated shell. It resolves `{doc, lang}` and supplies an immutable `LegalDocumentViewModel` to a presentational legal body; the only intents are anchor navigation and a normal `<a>` language switch. The build contract is `manifest.json` plus four versioned Markdown inputs → a committed readonly generated block module; missing locale/version/unsupported syntax fails the build. The emitted HTML must contain the full content, TOC, language links and head metadata and remain readable/navigable with JavaScript disabled. There is no runtime HTTP repository, loading spinner, hydration-dependent content or consent write in this task. Runtime legal acceptance belongs to `13.2.1-T1` and is not inferred from these static pages. Shared ownership and evidence rules are linked from [implementation-roadmap.md §2–§3](../implementation-roadmap.md) and [integration-readiness.md §2](../integration-readiness.md); no new shared component is introduced.

**Task-local acceptance delta:** disable JavaScript and block `/api/**`, then load all four built routes directly: legal body, TOC anchors, version/effective date, canonical/hreflang and the sibling-language link remain present and usable. This is independent of the static design-frame review and of the future legal-acceptance API.

## Failure handling and edge cases

- **Missing/blank content for a language**: the generator fails the build (never a runtime empty page); at runtime the repository
  throws `legal_content_missing` and the route renders `EmptyState` with `public.legal.empty`.
- **Version skew** (`manifest.json` bumped by 13 but a file not updated): build failure naming the expected file; this is the guard
  that keeps the shown version equal to `user_consents` (C11).
- **Unsupported Markdown** (tables, images, footnotes, nested lists): build failure, not a silent drop — the 13 drafts must stay in
  the subset; the error lists the construct and line.
- **Link schemes**: only `https://`, `mailto:` and site-relative `/`; anything else (`http:`, `javascript:`, `data:`) fails the
  build and therefore can never reach a rendered `href`.
- **Prerender environment**: no `window`/`navigator`/`localStorage` access outside `isPlatformBrowser`; head writes go through
  `Title`/`Meta`/`DOCUMENT` so they work in the prerender pass.
- **No API, no cache risk**: the page has no runtime data, so it stays correct under the D3 HTML `no-cache` rule and the immutable
  hashed-asset rule; content changes are a new deploy, never a stale fetch.
- **Language switch keeps the document**: `/vi/privacy` ↔ `/en/privacy`, never to the landing page; the redirects
  `/privacy` → `/vi/privacy` and `/terms` → `/vi/terms` preserve the 13 contract ("published at `/privacy`").
- **Bounded work**: one synchronous lookup per route, O(blocks) render, no N+1 calls, no client-side cache beyond the page store.
