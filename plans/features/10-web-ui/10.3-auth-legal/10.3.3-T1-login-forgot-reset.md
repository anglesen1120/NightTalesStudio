## Goal

Ship the three unauthenticated entry screens: `/login` (password step only — the MFA step is 10.3.3-T3), `/forgot-password`
(always the same "sent" panel, no account enumeration) and `/reset-password` (token read from the URL **fragment** and removed from
the address bar before the POST). Deliver the `auth` feature skeleton, its domain port, `LoginStore` with the password step and the
`step` signal T3 widens, the `returnUrl` hand-off into `SessionStore`, and the `429 retry_after` countdown.

## Design

Files under `web/src/app/features/auth/` (D2); `auth.routes.ts` exports the lazy routes.

- `domain/auth.model.ts` — `Session`, `AuthRole`, `LoginOutcome` (`ok | mfa | enrolment`), `LoginStep = 'password'`,
  `AuthRepository` abstract class with `login(email, password)`, `forgotPassword(email)`, `resetPassword(token, password)`,
  `logout()`; `loginMfa` is **declared by T3** (T1 leaves the port without it).
- `data-access/auth.repository.ts` — `AuthApiRepository implements AuthRepository`: calls `@shared/api`, maps the DTO to `Session`,
  maps `ProblemDetails` through `AppErrorMapper` and — because `mfa_required`/`mfa_enrolment_required` are 401s carrying data —
  returns `Result.ok({ kind: 'mfa', mfaToken })` / `{ kind: 'enrolment', token }` instead of an error (documented in the file).
  `login` is annotated `Idempotency`-free: auth routes require no `Idempotency-Key` (`09.3.3-T1-…:126`).
- `data-access/reset-token.ts` — `readTokenFromHash(hash: string): string | null` (matches `/^#t=([A-Za-z0-9_-]+)$/`) and
  `stripHash(): void` (`history.replaceState(null, '', location.pathname + location.search)`), both `isPlatformBrowser`-guarded.
- `application/login.store.ts` — `@Injectable()` (route-provided, OnPush page): signals `step = signal<LoginStep>('password')`,
  `submitting`, `error`, `mfaToken: signal<string|null>(null)` (memory only), `rateLimitedUntil: signal<number|null>(null)`,
  `enrolmentRedirect = signal(false)`, `formError = signal<string|null>(null)`; `computed canSubmit`. Methods `submitPassword(email,
  password)` (in-flight guard; on `ok` → `SessionStore.signIn(session)` + navigate to the sanitised `returnUrl` [WR8]; on `mfa` →
  set `mfaToken`, `step.set('mfa')`; on `enrolment` → `SessionStore.beginEnrolment(token)` + navigate to
  `/account/security/mfa-setup`; on `rate_limited` → store `retryAfterSec`), `backToPassword()` (clears `mfaToken`).
  **T3 widens `LoginStep` to `'password' | 'mfa'` and adds `submitMfa`/`useRecoveryMode` in the same file.**
- `application/forgot-password.store.ts` — `submitting`, `sent`, `error`; `submit(email)`: a 202 or a `validation_failed` sets
  `sent` only for 202; the panel copy is identical for a known and an unknown address (C4).
- `application/reset-password.store.ts` — `token: string|null` (filled from the constructor's `readTokenFromHash`), `hasToken`,
  `submitting`, `error`, `done`; `submit(password, confirm)` validates `password === confirm` client-side
  (`auth.reset.mismatch`) then calls the port; success → `done` and the page offers `/login`.
- `ui/login-page/`, `ui/forgot-password-page/`, `ui/reset-password-page/` — standalone, OnPush, typed Reactive Forms with Material
  (D13; **not** Signal Forms), error text bound from `bindFieldErrors(form, error)` (10.2.2-T1), the non-field error in a
  `role="alert"` block, `RetryCountdown` fed by `retryAfterSec` disabling submit until 0.
- `auth.routes.ts` — `/login`, `/forgot-password`, `/reset-password`, all `loadComponent`, all behind `anonymousGuard`
  (10.2.1-T1) so an authenticated user is sent to `/dashboard`; `/login` accepts `?returnUrl=`.
- `testing/fake-auth.repository.ts` — hand-written fake implementing the port with settable scripted outcomes (D15: no mocking
  library): `willReturn(outcome)`, `willFail(error)`, `calls: Array<{method, args}>`.

The deck is the approved design (recorded 2026-10-02).

The routed containers own `LoginStore`, `ForgotPasswordStore` and `ResetPasswordStore` plus typed forms; presentational auth surfaces consume readonly task-specific view models and emit `submitPassword`, `requestReset`, `resetPassword`, `retryAfterElapsed` and navigation intents only. Programmatic `setErrors`, `patchValue`, enable/disable and countdown completion cross a zoneless form-state bridge read by the template and cleaned through `DestroyRef`. Route destruction aborts/ignores pending results; a session-generation change or successful boot restore invalidates anonymous-page continuations; leaving login clears the in-memory challenge.

The snapshot currently has password session/refresh/logout routes, but this task is not complete owner sign-in: the MFA challenge payload/sign-in route belongs to `09.3.2-T3`, and forgot/reset routes belong to `09.3.3-T1`. Adapter fixtures may drive component work, but real-system acceptance remains blocked until those owners merge and the generated client is regenerated from their OpenAPI SHA. This task sends no idempotency key; duplicate submits are prevented in the route store. See [implementation-roadmap.md §2–§3](../implementation-roadmap.md) and [integration-readiness.md §2–§3](../integration-readiness.md).

**Task-local acceptance delta:** after an async server response, field errors, form-level alert, disabled state and countdown must become visible under zoneless `whenStable` without a manual `detectChanges`; a response that completes after navigation/session generation changes must not paint the old route or sign a new user in.

## Failure handling and edge cases

- **Unknown e-mail vs wrong password**: both surface `auth.login.invalidCredentials`; the store never branches on the message, so
  enumeration is impossible by copy, status or render path.
- **`403 email_not_verified`** (S path, mapped anyway): shows `auth.login.emailNotVerified`; no registration link is rendered in P.
- **`403 registration_closed`**: unreachable from this UI (C5); the `errors.registration_closed` key exists so the mapper never
  shows raw text if a stray 403 arrives.
- **`429`** on any of the three screens: `RetryCountdown` from `Retry-After`, submit disabled, no automatic retry; a second 429
  restarts the countdown (never stacks timers).
- **Network failure**: `network_error` alert with a manual retry button; no retry loop, no request replay on navigation.
- **Double submit / rapid Enter**: one in-flight guard per store; the button is `disabled` while submitting.
- **Boot refresh race**: the `provideAppInitializer` refresh (D6) can resolve while `/login` is open; the page subscribes to
  `SessionStore.isAuthenticated` and navigates to `/dashboard` at most once, and the `anonymousGuard` prevents the flash.
- **Session end** (`SessionStore.logout()`, or the interceptor ending the session — D6/[WR8]): `LoginStore` clears
  `mfaToken`/`error` and returns to `step === 'password'`.
- **Fragment absent, malformed (`#t=`) or with an extra param**: `readTokenFromHash` returns `null` → missing-token state; the page
  never falls back to `location.search` (F03: only the fragment is a legal channel).
- **`history.replaceState` unavailable** (unlikely, mocked environment): the page falls back to leaving the URL untouched but
  still clears the input value and never re-reads the hash; covered by a unit test.
- **Bounded work**: one HTTP request per user action; login page bundle stays inside the D13 budget because Material dialogs,
  `DiffView`, CDK drag-drop and the hub are not imported by this feature.
