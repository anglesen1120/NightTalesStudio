## Goal

Produce the approved UI design for every screen and state this folder ships: the prerendered landing and pricing pages, the `/` language redirect, `/register` (all server-mode and CAPTCHA states), `/verify-email` (all four outcomes) and the shared `CaptchaWidget`. The deliverable is a design link recorded in `plan.md` §6 plus the owner's approval record; it is a **hard gate** — no implementation task in this folder starts before it (SD11, owner rule 2026-09-25, C7 design gate).

## Inputs

- `plan.md` §6 (screen × state inventory) and §2 F1–F28; `../README.md` §C0:552, §C3 SD1/SD2/SD3/SD4/SD5/SD11/SD12/SD13/SD14/SD15, §C7 design gate, §C10 S-O1/S-O3/S-O4, ST-1/ST-2.
- D11 design system (`../README.md:168`): Angular Material M3, dark default + light option, tokens once in `shared/ui/theme/`, font Be Vietnam Pro self-hosted (`@fontsource/be-vietnam-pro`, weights 400/500/600, subsets latin + latin-ext + vietnamese, OFL-1.1, FE14); no third-party font/CDN request.
- The theme + UI kit **must exist first**: 10.1.3-T1 owns `PageHeader`, `EmptyState`, `ErrorState`, `LoadingState`, `StatusChip`, `ConfirmDialog` (+`cost-line`), `Stepper`, `CharCounter`, `CopyableCode` and the icon components (WR4).
- Legal texts: 13.1.1-T1 (privacy) and 13.1.2-T1 (terms) deliver `web/src/content/legal/<prefix>.<version>.<lang>.md` (manifest key -> file prefix: `tos -> terms`, `privacy -> privacy`; 13 CR-34); the register design shows the three consent checkboxes incl. the 18+ attestation (13.2.3-T1) with version strings from that content (SC16).
- Pricing content shape: `web/src/content/pricing/<lang>.json` (ST-1); **the owner supplies any figures** — the design uses placeholders until then.
- Ruling context the design must reflect: no third-party asset on any public page; the CAPTCHA is the single allowed third-party widget (S-O3/ST-2); pricing shows no live prices (S-O4/ST-1).

## Design

Artifacts in the project design tool (Figma or equivalent), one page per route:

- **`/<lang>/` landing** — hero (headline, subhead, primary CTA → `/register`, secondary → `/<lang>/pricing`), value props, footer with language switcher + legal links (`/<lang>/privacy`, `/<lang>/terms`). No loading/empty/error state (prerendered, no fetch).
- **`/<lang>/pricing`** — tier cards (`PricingTier[]`: name, feature list, price placeholder, CTA `/register`; signed-in variant CTA `/billing`), comparison table, note line; no live package call.
- **`/register`** — field set: e-mail, password, confirm, three consent checkboxes, `inviteCode` (only when `registration.mode = invite`), `CaptchaWidget`. States: idle, captcha hidden, captcha visible (`captcha_required`), submitting, `captcha_invalid` (reset), `captcha_unavailable` (fail-closed on register — retry/`RetryCountdown`, no token-less submit, 09 W3 CR-34), `breached_password` (field-bound), `registration_closed`, `rate_limited` (countdown), success → neutral "check your e-mail".
- **`/verify-email`** — verified, expired, invalid, resent.
- **`CaptchaWidget`** — idle, loading, ready, expired, error, unavailable; annotation for iframe `title`, `aria-live` countdown, keyboard path, and the documented fallback if the vendor widget is not keyboard-usable (FC16).
- **`/` redirect** — no visible screen; annotated as prerendered.

Annotations required per screen: breakpoints **360 / 768 / 1280**, both themes (dark default + light), vi + en text at real lengths (vi is default), focus order, keyboard path, `aria-live` regions, target size ≥ 24 px, contrast pairs, and the D11 components/tokens used.

## Steps

1. Confirm 10.1.3-T1's theme + UI kit and the D11 component inventory exist; open the design file from that library.
2. Draft wireframes (lo-fi) for the four screens + widget in the five state families; walk the flows UC-1…UC-7 (`plan.md` §4).
3. Build hi-fi mockups from D11 tokens/components at 360/768/1280, dark + light, vi + en.
4. Annotate focus order, keyboard path, `aria-live` regions, target sizes, contrast, reduced-motion behaviour, and the CAPTCHA widget's cross-origin constraints.
5. Show the pricing page with placeholders and a note that the owner supplies figures (ST-1); show the register page in `open`, `invite` and `closed` modes.
6. Record the screen × state inventory as a table and link each row to the mockup frame.
7. Present to the owner; record approval (name + date + link) in `plan.md` §6 and in `## Outputs` below.

- **Given** approval is absent, **When** any implementation task is attempted, **Then** it is blocked (hard dependency, C7 design gate).

## Tests

No code tests (design task). Verification is the review checklist above plus:
- a frame-per-row coverage check against the `plan.md` §6 table;
- a breakpoint/theme/language matrix check (4 screens + widget × 3 × 2 × 2);
- a token/component conformance check against the 10.1.3-T1 UI kit.

## Failure handling and edge cases

| Case | Handling |
|---|---|
| 10.1.3-T1 theme/kit not ready | Design task waits (hard dependency); do not invent a second component set |
| 13.1.1-T1/13.1.2-T1 legal texts missing | Consent checkbox copy uses the agreed labels with a version placeholder; record as `[OPEN]` in `plan.md` |
| Owner has no figures for pricing | Placeholders stay; the page ships without live prices (ST-1) |
| Turnstile widget not keyboard-usable (ST-2 re-opens) | Document the fallback path in the design; the implementation task consumes that annotation |
| Owner requests changes | Re-approve and update the record + link; implementation tasks stay blocked until then |
