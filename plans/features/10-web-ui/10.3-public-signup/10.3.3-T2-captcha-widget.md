## Goal

Ship the provider-agnostic CAPTCHA layer and its CSP delta: the `CaptchaProvider` port, the Cloudflare Turnstile implementation, the `CaptchaWidget` shared component, the public runtime config (`captchaSiteKey`), the `gen-csp.mjs` `CAPTCHA_ORIGINS` widening, and the progressive-delay countdown on `captcha_required`/`rate_limited` plus the `breached_password` field error. The widget is reused by login/MFA (10.3.3-T1/T3) and by 13.3.4-T1's report page.

## Design

Files:

- `web/src/app/core/security/captcha-provider.ts` — `interface CaptchaProvider { readonly siteKey: string; render(el: HTMLElement, opts): Promise<{ token: string }>; reset(): void }` (verbatim SD4).
- `web/src/app/core/security/turnstile-loader.ts` — `loadTurnstileScript(): Promise<void>`, idempotent; injects `<script src="https://challenges.cloudflare.com/turnstile/v0/api.js" async defer>` through a Trusted-Types policy scoped to exactly that URL, called **only** from `CaptchaWidget`'s first mount on the CAPTCHA-bearing routes (register/login/MFA/forgot/reauth/report) — never from `index.html`, so `/cancel-request` never requests it (09 W3 CR-34).
- `web/src/app/core/security/turnstile.provider.ts` — Cloudflare Turnstile implementation; awaits `turnstile-loader`, then reads `window.turnstile`.
- `web/src/app/core/config/runtime-config.ts` — reads `assets/runtime-config.json` **once at boot**; exposes `captchaSiteKey` (public value only).
- `web/src/app/shared/ui/captcha-widget.ts` — OnPush, inputs/outputs-only: inputs `siteKey`/`visible`/`resetKey`, outputs `token`/`expired`/`error`/`heightChange`; **no store, no `HttpClient`**; exported from `@shared/ui` (SD4); calls `turnstile-loader` on first mount only.
- `tools/web/gen-csp.mjs` — `CAPTCHA_ORIGINS` constant → `script-src` += `https://challenges.cloudflare.com`, add `frame-src https://challenges.cloudflare.com`, `style-src` += same origin; pre-clearance off (`connect-src` unchanged) (F9). The header still allows the origin shell-wide (one static CSP for the SPA), but the script is only ever **requested** on the CAPTCHA-bearing routes — `/cancel-request` never calls `turnstile-loader`, so no network request to `challenges.cloudflare.com` happens there even though the header would permit it (09 W3 CR-34).
- Reused, **not produced** (WR4 owns it in 10.2.2-T1): `RetryCountdown` for the progressive delay on `captcha_required`/`rate_limited`.
- Container entrypoint writes `assets/runtime-config.json` (`{ captchaSiteKey }`, `no-store`) from `NTS_CAPTCHA_SITE_KEY` (F10).

i18n: `errors.captcha_required`, `errors.captcha_invalid`, `errors.captcha_unavailable`, `errors.breached_password` (+ `errors.rate_limited`) in vi + en (F16/F20).

## Steps

1. Declare `CaptchaProvider` and implement `turnstile.provider.ts` (render/reset; no script injection).
2. Implement `turnstile-loader.ts` (Trusted-Types-compatible, idempotent, on-demand) and wire it into `CaptchaWidget`'s first mount — never a static tag in `index.html` (09 W3 CR-34).
3. Implement `runtime-config.ts` + the container entrypoint write of `assets/runtime-config.json` from `NTS_CAPTCHA_SITE_KEY` (F10, ST-7).
4. Build `captcha-widget.ts` from the 10.3.1-T0 design: OnPush, inputs `siteKey`/`visible`/`resetKey`, outputs `token`/`expired`/`error`/`heightChange`; `reset()` clears the token; iframe `title` + `aria-live` countdown (F7, F23).
5. Add `CAPTCHA_ORIGINS` to `gen-csp.mjs` and update the D4 header generation; do **not** touch `require-trusted-types-for`/`trusted-types` (F9, ST-2).
6. Add register + login specs to the 10.1.6-T1 CSP fixture asserting zero `securitypolicyviolation` with the widget mounted (F25).
7. Wire the progressive-delay countdown (`RetryCountdown`) on `captcha_required`/`rate_limited` and the `breached_password` field error into the consuming pages.
8. Add axe specs (WCAG 2.2 tags) for the widget states; document the fallback if the vendor widget is not keyboard-usable (F23).

## Acceptance checks

- **Given** the register page with the widget mounted, **When** the CSP fixture runs, **Then** no `securitypolicyviolation` is fired and the widget renders (F25).
- **Given** the CSP header, **When** inspected, **Then** `script-src`/`frame-src`/`style-src` contain exactly `https://challenges.cloudflare.com` and `connect-src` is unchanged; `require-trusted-types-for 'script'` and the `trusted-types` allow-list are unchanged (F9, ST-2).
- **Given** a 400 `captcha_invalid`, **When** received, **Then** the widget resets and the token field clears; **given** 503 `captcha_unavailable` on register, **Then** the form shows `RetryCountdown` and blocks submission until a token is available — **no token-less submit on register** (D4, 09 W3 CR-34); the fail-open token-less path applies only to login/forgot/reauth (10.3.3-T1).
- **Given** a third consecutive failure, **When** `captcha_required` arrives, **Then** the widget appears and the progressive-delay countdown is announced via `aria-live` (F15, F23).
- **Given** `runtime-config.json`, **When** fetched, **Then** it is `no-store` and contains only `captchaSiteKey` (no secret) (F10).
- **Given** the widget, **When** axe runs with `wcag2a,wcag2aa,wcag21a,wcag21aa,wcag22aa`, **Then** the iframe has a `title`, the countdown is `aria-live`, and the keyboard path is operable — or the documented fallback is in place (F23).
- **Given** the login/MFA and report pages, **When** they mount the widget, **Then** they pass `captchaToken` through the same port and component.
- **Given** `/cancel-request` is visited, **When** the network trace is inspected, **Then** no request to `challenges.cloudflare.com` occurs (09 W3 CR-34) — `turnstile-loader` is never invoked outside the CAPTCHA-bearing routes.

## Failure handling and edge cases

| Case | Handling |
|---|---|
| Turnstile blocked by Trusted Types (ST-2) | Re-open the vendor with 09; **never** relax the TT header or `bypassSecurityTrust*` |
| `window.turnstile` unavailable at boot | Provider renders only on demand; show the `error`/`unavailable` state; on **register** this blocks submission with a retry (D4, no token-less submit), on login/forgot/reauth it allows a token-less submit (503 path) |
| `captchaSiteKey` missing from runtime config | Widget shows `unavailable`; register blocks submission with a retry (no token-less register submit, D4); log a warning without the key |
| Token expires (>300 s) | Widget emits `expired`; user re-solves before submit (tokens are single-use) |
| Vendor widget not keyboard-usable | Use the documented fallback (offer the API-allowed path); record as `[OPEN]` (FC16) |
| Owner licence/privacy note absent | Task is blocked at start (ST-2/S-O3 gate) |
