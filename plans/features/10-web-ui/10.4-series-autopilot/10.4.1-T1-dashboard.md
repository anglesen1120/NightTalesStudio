## Goal

`/dashboard` is the creator's overview: three status groups rendered as approved ruled rows, each driven by the scalar-status episode list API with one primary next action. It contains **no** credit balance, quote or buy button in P; the S-only balance visible in the artifact chrome is never copied.

## Design

**Files produced.**
- `web/src/app/features/dashboard/application/dashboard.store.ts` — `DashboardStore`, `@Injectable()` provided by the routed page:
  ```ts
  type Group = 'needsReview' | 'inProgress' | 'ready';
  readonly needsReview = signal<readonly EpisodeSummary[]>([]);
  readonly inProgress = signal<readonly EpisodeSummary[]>([]);
  readonly ready      = signal<readonly EpisodeSummary[]>([]);
  readonly loading    = signal(false);
  readonly error      = signal<AppError | null>(null);
  readonly refreshing = signal(false);          // focus refresh: keeps the current cards on screen
  readonly lastRefreshedAt = signal<number | null>(null);
  readonly isOwner = computed(...);             // from SessionStore, controls the idle-window copy only
  load(): Promise<void>;                        // 5 scalar-status calls in Promise.all; one AppError if any fails
  refresh(): Promise<void>;                     // coalesced: ignored while `refreshing()` is true
  ```
  Queries are `story_review`, `video_review`, `story_generating`, `rendering`, and `ready`; the store merges them into the three view groups by id and sorts by `updatedAt`. Requests are parallel, never chained, and no comma-separated status is sent.
- `web/src/app/features/dashboard/feature/dashboard-page.ts` — the page: `PageHeader` (`dashboard.title`) + three `<section>`s; each section renders `LoadingState` skeletons while `loading()`, an inline `EmptyState` when its list is empty, and a ruled `<ul>` of `NextActionRow`s otherwise. A whole-page failure renders `ErrorState` with Retry; a focus refresh keeps the last good rows and shows `dashboard.partialRefreshFailed` if any request fails.
- `web/src/app/features/dashboard/ui/next-action-row.ts` — `NextActionRow`, OnPush, consumes immutable `NextActionRowViewModel { episode, group, primaryAction }` and emits `open` or `primaryAction` intent. It is a semantic `<li>` with the approved ruled-row treatment, not a Material card; the container decides navigation.
- `web/src/app/features/dashboard/dashboard.routes.ts` + `index.ts` — `authGuard` + `loadComponent`; the shell nav entry is 10.2.6-T1's.
- `web/src/app/features/dashboard/testing/fake-episode.repository.ts` — thin re-export/wrapper of the episodes feature's fake with a canned fixture per status and a call log; kept here so the dashboard store test does not depend on the episodes tests' fixtures.

**Reuse rule (D2).** `EpisodeSummary`, `EpisodeRepository` and the status presentation come from `@features/episodes` (`features/episodes/index.ts` is the only legal import path). This task must **not** copy `episode-status.ts`; if a status label is missing there, it is added in the episodes feature by 10.5.1-T1's file, not here [OPEN-3: coordination item with 10.5.1-T1 — this task's `## Notes` records the request; no file outside this folder is edited].

**Focus refresh.** `dashboard-page.ts` registers `afterNextRender` + a `focus`/`visibilitychange` listener (throttled to at most one `refresh()` per 10 s, coalesced by the store's `refreshing` guard) so returning to the tab shows current data without polling. Cleanup through `DestroyRef`. No `setInterval` (D17).

**Copy keys (scope `dashboard`, vi + en).** `dashboard.title`, `dashboard.refresh`, `dashboard.needsReview|inProgress|ready`, `dashboard.<group>.empty`, `dashboard.partialRefreshFailed`, `dashboard.card.action.reviewStory|reviewVideo|open|publish`, `dashboard.card.updated` (relative time is produced by `Intl`, the key is only the fallback label), `dashboard.updatedJustNow`; plus `errors.network_error|rate_limited|unknown_error` (D9). Cross-plan keys used verbatim: the episode status labels from 10.5.1-T1 (e.g. `episode.status.story_review`) — not re-authored here.

**A11y (D16).** Each group is `<section aria-labelledby>` with a heading and text count; refresh announces counts once via `aria-live="polite"`; each ruled row action is a button/link whose accessible name includes the episode title; `StatusChip` has icon + text; skeleton sections expose `aria-busy`; rows stack at 360 px; reduced motion disables shimmer.

**Performance.** Exactly 5 scalar-status HTTP calls per `load()` (asserted with the fake's call log), 0 calls while hidden, ≤ 1 coalesced refresh per 10 s on refocus, `track episode.id`, no images or heavy defer target.

**Security.** No mutation on this page (navigation only) → no `If-Match`/idempotency concerns; no token in storage (D6); episode/series titles are ordinary interpolated text (no `innerHTML`, D2/D4); nothing logged; the store is provided by the routed page and therefore dropped on navigation, so no stale data survives a logout (D6 `SESSION_SCOPED` is not needed for a page-provided store, but the router guard re-runs `load()` after a new login).

**Approved design handoff (2026-10-02).** Use [`03-dashboard-series.html`](../../../../design/ui/screens/03-dashboard-series.html), frames `f-dash-loading`, `f-dash-data`, `f-dash-group-empty`, `f-dash-empty`, `f-dash-error`. The frames establish base visuals; rate-limit/focus-refresh behavior is runtime acceptance. Screen-03 balance is S-only reference: P leaves shell `header-end` empty and renders no credit UI.

`DashboardPage` is the route container; `NextActionRow` is presentational through the typed view model/intent seam above. The route store owns request generation, rejects late completion after route/session teardown, and removes focus/visibility listeners through `DestroyRef`. There is no ETag or idempotency key on this read-only task. The current episode list API is present and scalar-status only; acceptance uses its real five-request contract. Shared/error ownership and notification rules are linked from [implementation-roadmap.md §2–§3](../implementation-roadmap.md) and readiness from [integration-readiness.md §1](../integration-readiness.md).

**Task-local acceptance delta:** prove exactly five scalar-status requests, stable de-duplicated grouping, no stale update after leaving the route/session, ruled-row markup matching `f-dash-data`, and no balance/credit node despite the S-only artifact chrome.

## Failure handling and edge cases

| Case | Handling |
|---|---|
| One group failing (e.g. a 500 on `status=ready`) | `load()` reports one `AppError`; the page shows `ErrorState` with Retry and keeps nothing stale (a partial render would be misleading). The focus `refresh()` instead keeps the last good data and shows `dashboard.partialRefreshFailed`. |
| 429 on any of the 5 calls | `RetryCountdown` from `Retry-After`; Retry disabled until 0; all fresh result sets are discarded to keep the view consistent. |
| No episodes at all (new account) | Three empty states + a primary "Create series" link (the dashboard links; it does not duplicate the flow). |
| Scalar status filter | Always send one allowed status per request. A comma-separated status is never sent or feature-detected. |
| Episode status drifts between the 5 calls | De-duplicate by id and prefer the most advanced known status so an episode appears in exactly one group. |
| Session ends while loading | The interceptor's `SessionEnded` navigates to `/login?returnUrl=/dashboard` (D6); no error state is painted. |
| Unknown/new status value from the wire | Ignored (it belongs to no group) — never rendered as an unknown chip; the count reflects only known statuses. |
| Deep link while unauthenticated | `authGuard` → login with `returnUrl=/dashboard` (validated per D6). |
| Rollback | Remove the route entry + the lazy chunk; nothing else in the app depends on the dashboard. |
