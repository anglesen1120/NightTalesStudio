## Goal

The series editor's voice step is a real picker: the user sees the voices for the chosen language (display name, gender, tags as translated keys), can listen to a preview when the backend supplies one, and cannot change the speaking rate (04 CR-11 — the rate is fixed in P). The component and its data path are reusable by the series editor and by any later screen that selects a voice.

## Design

**Files produced.**
- `web/src/app/features/series/domain/voice.model.ts` — `Voice`, `VoiceTag` (the 11-value union, comment-linking 04 README L213), `Language`.
- `web/src/app/features/series/domain/catalog.repository.ts` — `abstract class CatalogRepository { voices(language: Language): Promise<readonly Voice[]>; styleTemplates(topic?: Topic): Promise<readonly StyleTemplate[]> }` (the style half is implemented by 10.4.2-T1; this task ships the port and the voices implementation).
- `web/src/app/features/series/data-access/catalog.http-repository.ts` — implements `CatalogRepository` over the generated `@shared/api` client. `voices()` maps the DTO (`displayName` → `displayName`, `tags` → `VoiceTag[]`) with an explicit mapper function, checks the response `ETag` through `readEtag()` and stores nothing outside the store; a 304 reuses the last list held by the store (the browser's HTTP cache already serves it). Unknown tag values from the wire are **dropped** (a new tag needs a key in both locales; showing a raw key would be a bug).
- `web/src/app/features/series/testing/fake-catalog.repository.ts` — hand-written fake with a call log (`voicedCalls: Language[]`), a canned list (one `vi` voice without a preview, one with, one `en` voice, one `central`-tagged voice) and `failWith(AppError)`.
- `web/src/app/features/series/ui/voice-picker.ts` — `VoicePicker`, standalone, `ChangeDetectionStrategy.OnPush`, no injected store:
  ```ts
  @Input({ required: true }) voices: readonly Voice[] = [];
  @Input() selectedId: string | null = null;
  @Input() disabled = false;
  @Output() readonly selected = output<string>();
  ```
  Renders a `role="radiogroup"` (`fieldset` + `legend`, legend text `series.field.voice`): one row per voice with the display name, the gender text (`series.voice.gender.<value>`), tag chips and a play control.
- `web/src/app/features/series/ui/audio-preview-button.ts` — `AudioPreviewButton`, `OnPush` (produced for reuse by wave 2, WR4):
  ```ts
  @Input({ required: true }) previewUrl: string | null = null;
  @Input() label = '';                       // accessible name: `${label} — ${displayName}`
  @Output() readonly started = output<void>(); // the parent stops any other player
  ```
  Uses a native `<audio preload="none" controls>` wrapped in `@defer (on interaction)` (D13/F12) so no media request happens until the user asks; when `previewUrl === null` the component renders a disabled button with the tooltip `series.voice.previewUnavailable` and **no** `<audio>` element at all (never a request to a missing asset).
- `web/src/app/features/series/application/voice-step.store.ts` — `VoiceStepStore`, `@Injectable()` provided by the editor page (10.4.2-T1 imports it; this task defines the contract so the editor can be written against it):
  ```ts
  readonly language = signal<Language>('vi');
  readonly voices = signal<readonly Voice[]>([]);
  readonly loading = signal(false);
  readonly error = signal<AppError | null>(null);
  readonly selectedId = signal<string | null>(null);
  readonly selected = computed(() => this.voices().find(v => v.id === this.selectedId()) ?? null);
  readonly compatible = computed(() => this.selected() === null || this.selected()!.language === this.language());
  async load(language: Language): Promise<void>;   // single-flight per language, no N+1
  select(id: string): void;                        // ignores a voice whose language differs from `language()` after the last load
  clear(): void;                                   // used by the language-change rule (U6)
  ```
  `load()` keeps the previous list while a new language loads (`loading` true) so the step never flashes empty; a language switch clears `selectedId` (U6) and announces through the `LiveAnnouncer` with `series.voice.clearedByLanguage`.

**No speed control.** The step renders no rate/`<input type=range>`/speed select. `series.voice.rateFixed` is a hint line under the list (fact from 04 CR-11), not a control.

**Copy keys (scope `series`, vi + en).** `series.field.voice`, `series.voice.preview`, `series.voice.previewUnavailable`, `series.voice.rateFixed`, `series.voice.clearedByLanguage`, `series.voice.gender.<male|female|neutral>` [OPEN: the gender vocabulary is owned by 04/09 and is not enumerated in the files read — if the API returns another value the picker falls back to the raw value in the gender chip and the key set is amended in 10.2.5-T1's check], plus the verbatim `voices.tag.<tag>` keys (11) and `errors.*` for the codes below.

**Errors.** `validation_failed` with `errors.language` (400) → the store maps it to a field error, keeps the last good list and shows `errors.validation_failed` on the language control (this can only happen after a client bug or a language the API does not accept); `network_error` → `ErrorState` with Retry inside the step (the rest of the form stays usable); `rate_limited` → `RetryCountdown` and the Retry action disabled until 0; 401 → `SessionEnded` through the interceptor (D6), no local handling.

**Performance.** One request per language per page visit (the store caches the last language in memory; the HTTP cache + `ETag`/304 handles a revisit), no request while the step is not visible (`@defer` on the step is **not** used — the step is cheap and the form must know its voices — but the *audio* is deferred), `track voice.id`, tag chips are text nodes (no per-chip request), and no `setInterval` anywhere.

**Reuse.** Produces `VoicePicker` + `AudioPreviewButton` + `CatalogRepository` + `FakeCatalogRepository`; reuses `EmptyState` (empty catalog), `ErrorState`, `RetryCountdown`, `CharCounter` is **not** used here.

**Approved design handoff (2026-10-02).** Use [`03-dashboard-series.html`](../../../../design/ui/screens/03-dashboard-series.html), frames `f-new-step3`, `f-new-step3-empty`, `f-new-errors`. They cover picker/list/empty/error only. Active playback and preview-load failure have no distinct frame in the approved deck — implement them from the locked contract and flag to the owner only if a new visual state is needed (does not reopen the approval or block the task). Runtime audio/keyboard semantics are not proven by static frames. Screen-03 balance is S-only and omitted in P.

`VoiceStepStore` is page-scoped composition; `VoicePicker` and `AudioPreviewButton` receive immutable `VoicePickerViewModel`/`AudioPreviewViewModel` and emit select/start/stop/retry intents. The unpaged voice endpoint is mapped exactly from `{items}`; it is not wrapped in `CursorPage`. Full response handling retains the previous representation on 304. Language/request generation and session generation gate late responses; route/session destruction stops audio, releases object/media references and clears listeners. The typed parent form observes async load/error/disabled changes through the shared zoneless bridge. No ETag is exposed to presentation and no idempotency key applies to catalog reads.

The voice catalog endpoint is present; preview-file production remains the soft `04.2.3-T1` prerequisite. Shared ownership is linked from [implementation-roadmap.md §2](../implementation-roadmap.md), readiness from [integration-readiness.md §1](../integration-readiness.md).

**Task-local acceptance delta:** take the playing/preview-failed visual states from the locked contract and flag to the owner only if new visual states are needed (does not reopen the approval or block the task); then prove `{items}`/304 behavior, zero media request before activation, one active player, late-language result rejection and teardown on route/session exit.

## Failure handling and edge cases

| Case | Handling |
|---|---|
| `previewUrl` is `null` (key absent, base URL empty, unsafe key — 09.4.2-T1:144-146) | Disabled button + `series.voice.previewUnavailable`; no `<audio>`, no request. The step is fully usable. |
| Empty catalog (fresh DB before the seeder) | `EmptyState` `series.voice.empty` + a link back to the language step; never a 404 error state. |
| Media origin missing from `NTS_CSP_MEDIA_ORIGINS` | The `<audio>` fails to load; the button shows an inline error (`series.voice.previewFailed`) and does not retry in a loop. |
| Preview URL is absolute to another host and CSP blocks it | Same as above — the button must not bypass CSP with a `bypassSecurityTrust*` (D2/D4). Worse case is a missing preview, never a broken policy. |
| Language changed while a load is in flight | The store keeps the request's language tag and discards a response whose language is no longer current (no flicker of the wrong list). |
| 304 from `If-None-Match` | The store reuses the last list; no loading flash. |
| `voice_language_mismatch` returned later by `POST/PATCH /series` (09.4.1-T1:47) | Out of scope here: the editor (10.4.2-T1) maps it to `errors.voice_language_mismatch` and clears the voice; the picker is stateless about it. |
| Voice de-activated server-side between two visits | It simply disappears from the list; an already-saved series keeps its `voice_id` (backend rule, `09.4.2-T1:147`) and the editor shows the stored id as a fallback row with `series.voice.inactive` [OPEN: the exact DTO for an inactive-but-referenced voice is not defined in the files read — the fallback row renders the id and the message, never a crash]. |
| Rollback | Delete the step's provider registration and the component files: the editor turns off the voice step and the store contract becomes unused (no data migration client-side). |

## Notes

**Shared components produced vs reused (D11).** Produces `VoicePicker`, `AudioPreviewButton` (WR4 — the shared preview control), `CatalogRepository`/`FakeCatalogRepository` (reused by 10.4.2-T1 for its own `styleTemplates(topic)` half and by any later voice surface). Reuses `EmptyState`, `ErrorState`, `LoadingState` (row skeletons), `RetryCountdown`, `LiveAnnouncer` (Angular CDK, re-export of Material's `LiveAnnouncer`), Material radio primitives and chips — no new visual pattern is invented, and the picker's layout matches the style grid of 10.4.2-T1 (same row/card rhythm).

**Cross-plan keys used verbatim (do not re-author).** `voices.tag.<tag>` × 11 (04 README L213, CR-11) and `errors.<code>` for every code listed above (D9). `series.voice.gender.*` is this task's own key family — [OPEN] the gender vocabulary is not enumerated anywhere readable; if 04 does not publish one, the picker renders the raw value and 10.2.5-T1's key check is amended at implementation time.

**Performance.** One HTTP request per language per visit; audio deferred to the interaction; `track voice.id`; no N+1 and no timer. gzip contribution ≈ 3–4 kB in the lazy `series` chunk.

**Security.** The token stays in `SessionStore` (D6); no storage writes; `previewUrl` is used exactly as returned and loaded as media under the D4 CSP (`media-src`), never with `bypassSecurityTrust*`; no voice id/URL in logs; the picker is read-only over a public catalog, so no `If-Match`/idempotency concern exists on this screen.
