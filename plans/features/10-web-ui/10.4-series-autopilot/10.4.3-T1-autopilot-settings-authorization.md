## Goal

The series' Autopilot tab lets the owner set on/off, cadence (weekdays, publish time, IANA time zone), daily cap, ready-buffer, publish privacy, veto window, pre-audit mode and (advanced) the gate-threshold profile; turning autopilot **on** requires a fresh re-auth and accepting a **versioned authorization text** bound by its hash; a change to any covered field revokes the authorization and forces a re-accept; the topic is locked while it is on; pause/resume work through their own routes with the pause reason visible and Resume blocked while the reason still holds. True-crime series show the hold notice. The run log and the veto list are 10.4.3-T2.

- `web/src/app/features/series/ui/authorization-dialog.ts` — as specified in `plan.md` §6.1: `@Input() text: AuthorizationText`, `@Input() locale`, `@Output() accept = output<{textVersion: string; textHash: string}>()`, `@Output() cancelled`. It renders the text with `white-space: pre-wrap` **interpolation only** inside a focusable region (`role="region"`, `tabindex="0"`, `aria-labelledby` = the heading) so a keyboard user can scroll it. The scroll gate is `scrolledToEnd = signal(false)`: it becomes true when `scrollTop + clientHeight >= scrollHeight - 8` **or when there is nothing to scroll** (`scrollHeight <= clientHeight + 1`) — evaluated in `afterNextRender` and on every `ResizeObserver` callback of the region (resize/zoom/font change), because a short rendered text that fits entirely must not dead-end the enable flow (no acceptance would ever be recorded). While the gate is false the accept button is disabled with the polite `autopilot.authorization.scrollHint`; once true it stays true for that open. It traps focus, closes on Esc as a cancel, and never allows submitting via an accidental Enter before the gate is met. The emitted pair is taken verbatim from the input (never recomputed).

**Covered-field hint.** After a successful save, if `coveredFieldsPending()` is non-empty the form shows the `autopilot.authorization.required` banner and the switch reads "authorization required"; the strings come from the server (`requiredAuthorization`) so the client hint can never contradict it.

**Reauth + retry budget.** One retry only, for exactly one action at a time (`setEnabled`, `acceptAuthorization`); the store never repeats a `PUT` on its own after a 412/409.

**Performance.** One `GET` per tab open; no requests while the user types (the form is local, saved explicitly); the settings form is a single component with `track` over chips/reasons; `@defer (on viewport)` on the "Advanced" panel and the next-slots block; no timers on this screen.

**Security (this task is marked `FE + Security`).** (1) The access token never leaves `SessionStore`; the re-auth goes through 10.3.3-T3's dialog (no client-side "recently re-authenticated" cache — the server's 5-minute window is the only authority). (2) The accepted pair `{textVersion, textHash}` always comes from the rendered response; the UI cannot accept a text it never displayed, and a mismatch surfaces `autopilot.authorization.stale_text` with a reload. (3) The authorization text is rendered with interpolation and `pre-wrap` — no `innerHTML`, no Markdown, no link injection (D2/D4 CSP + Trusted Types). (4) Every mutating request uses the ETag that came from the server; a 412 opens `ConflictDialog` and the entered settings stay in memory. (5) Pause/resume/enable/accept are single-flight in the store (button disabled while in flight); no route here requires a client idempotency key (they are state-guarded server-side, B11/B15). (6) `featureHidden` on 404 `feature_disabled` hides the settings block, refetches `/me` and never shows a raw error. (7) No series title, authorization text or hash is logged; the hash is displayed nowhere (only the version number is shown to the user).

**A11y (D16).** Weekday chips `fieldset`/`role="group"`; the time-zone select is searchable and labelled with both a visible label and `aria-describedby`; the on/off switch is a labelled `mat-slide-toggle` with `aria-describedby` to the topic-lock/true-crime hints when relevant; the dialog traps focus, `aria-labelledby` = its heading, the text region is a focusable `role="region"` (`tabindex="0"`), accept is disabled until scroll-to-end (announced politely) **or immediately enabled when the text fits without scrolling**, Esc cancels, focus returns to the switch; the pause banner is `role="status"`; the covered-field banner uses `aria-live="polite"`; every error is linked with `aria-describedby`; advanced controls are ≥ 24 px; 360 px stacks the two columns.

## Failure handling and edge cases

| Case | Handling |
|---|---|
| 401 `reauth_required` | `ReauthDialog` once, then one retry of the same action; a second 401 ends the flow with the re-auth message (no loop). |
| 409 `autopilot_authorization_required` on enable | Open the dialog with the freshly fetched text; if the GET is stale the accept returns `stale_text` and the form reloads. |
| `errors["textHash"] = "stale_text"` | Dialog closes, the settings are refetched, the banner says the text changed (and, when the audit status moved, the `autopilot.authorization.changedByAudit` variant from `02.8.3-T2:183`). |
| Two tabs open, both accepting | The second accept is compared against the **stored** settings server-side, so only one matches; the other gets `stale_text` and reloads (server rule, `02.8.3-T2:167`). |
| 412 on `PUT` | `ConflictDialog`; unsaved settings preserved; "Reload latest" replaces the form, "Save mine as new version" re-submits with the fresh ETag. |
| 400 `autopilot_settings_invalid` with JSON-path keys (`plan.md` §2 B11) | `bindFieldErrors` maps each path (`cadence.daysOfWeek`, `dailyCap`, …) onto the matching control; unmapped keys go to a form-level alert. |
| 409 `channel_reauth_required` | Banner with a link to the channel settings; the switch stays off. |
| 409 `autopilot_pause_reason_active` with `errors.reasons` | Banner lists the reasons (each translated through `autopilot.pause.<reason>`), Resume stays disabled until the next `GET` no longer reports them. |
| Settings invalid **and** the authorization would change | The server answers 400 first (it cannot render the text from invalid settings); the UI shows the field errors only. |
| YouTube audit status flips pending → approved | The rendered text changes → the covered-field diff revokes → the tab shows `autopilot.authorization.required` plus the audit-change banner; the owner re-accepts (intended, `02.8.3-T2:170`). |
| Series archived while enabled | The next `GET` shows the archived state; the tab disables every control and shows `errors.series_archived`; the server already disabled + revoked. |
| 404 `feature_disabled` (flag off mid-session) | Hide the block, refetch `/me` (D14); no error state, no retry loop. |
| Network loss while saving | `errors.network_error` with a Retry that re-sends the same form with the **stored** ETag (a 412 on the retry opens the conflict dialog). |
