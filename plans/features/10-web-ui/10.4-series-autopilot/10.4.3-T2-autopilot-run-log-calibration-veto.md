## Goal

Below the autopilot settings, the owner reads what the machine did: per run the slot, state, outcome, the idea picked (with the rejected ideas and their similarity), the gate verdicts (`gates.v1`, failing checks first, `dry_run` badge), the render/publication state and the pause reason; above the table a calibration panel summarises the dry-run data once the series has dry-run verdicts; beside it a veto-window list shows the publications waiting for the owner with the time left, Edit, Cancel and Approve now. The run log refreshes on `EpisodeUpdated` and by a 30 s poll while the tab is open (D17) because P has no `AutopilotRunUpdated` event.

**Polling (D17) and realtime (D8).** `visible-poll.ts` with `intervalMs: 30_000` runs while the run-log tab is visible **and** `isActive()`; on return to visible/active it runs immediately; a failed poll keeps the last good table and shows a soft hint (`autopilot.run.staleData`), never a full-page error. `RunLogStore.subscribe(episodeIds)` registers **`RealtimeService.subscribeEpisode(id, handler)`** (WR7) for the episodes on the current page and calls the coalesced `refresh()`; the same `refresh()` runs on `resync` (reconnect/visibility) when the tab is live. `RenderProgress` is not used here. Every subscription is torn down in `DestroyRef`. Poll and tick specs advance the clock with Playwright **`page.clock`** (never a 90 s wall-clock wait) and the idle gate is asserted in unit tests through a **fake `ActivityTracker` port** — there is no in-app test hook (WR14).

**Copy keys.** Verbatim: `autopilot.run.state.*` (9 states), `autopilot.gate.failed.<checkId>`, `autopilot.ideas.picked|rejected|reason.*|none|requiresResearch|similarity`, `autopilot.pause.*` (15), `autopilot.pause.banner`. Own keys: `autopilot.run.tableCaption`, `autopilot.run.loadMore`, `autopilot.run.openEpisode`, `autopilot.run.empty`, `autopilot.run.staleData`, `autopilot.run.col.slot|state|outcome|idea|gates|artifact|reason`, `autopilot.run.gatesNone`, `autopilot.run.dryRunBadge`, `autopilot.calibration.title|ready|unavailable|falseBlockRate|falseApproveRate|evaluated|recommendation|histogramCaption`, `autopilot.veto.title|empty|timeLeft|edit|cancel|approveNow|preview|privacy.<public|unlisted|private>`, `autopilot.veto.maxRows` (the note shown when the per-episode hydration cap is reached), plus `errors.*` for the codes below.

**A11y (D16).** The log is a `<table>` with `<caption>`, `<th scope="col">` per column and a `<th scope="row">` slot cell; state/gate cells carry icon + text; the poll announces "updated" once per refresh via a polite live region (never per row); rejected-idea details use `<details>`/`<summary>`; histograms have text alternatives; veto countdowns are silent (`aria-live="off"`) but readable as `<time>`; actions per row are labelled with the episode title; the Edit form traps focus and restores it; at 360 px the table switches to a per-run card layout (a CSS media query with the same semantics, `role="table"` not needed — the rows remain a real table with `overflow-x: auto` replaced by the card layout).

**Security.** No token in storage; the run log is read-only (`If-Match` is not sent by `GET`); the three publication mutations use the `If-Match` from the entity they display and are single-flight per row (`busyIds`); no `innerHTML` for idea titles/loglines/recommendation lines (interpolation only — recommendation lines are server-authored English text and are shown as returned [OPEN: they are not localised; the UI shows them verbatim with `autopilot.calibration.recommendation` as the heading — recorded here as a known limitation]); no story text, idea title, publication title or URL in `console.*`; the calibration payload is never persisted client-side; `feature_disabled` hides the block + refetches `/me`; the veto list renders only the owner's own publications.

**Performance.** First page + one hydration call per distinct episode in the veto window (≤ daily cap); `loadMore` single-flight; poll ≤ 1 request / 30 s while visible **and** active (0 while hidden or idle — D7); `EpisodeUpdated` coalesced to ≤ 1 page request / 250 ms; `track run.id`; histograms deferred; the model helpers are pure so the table needs no recomputation per row beyond `computed`.

## Failure handling and edge cases

| Case | Handling |
|---|---|
| `calibrationReport` omitted (ground-truth query failed — `02.8.2-T3:203`) | `calibrationUnavailable` message; the run table still renders (never a failed page). |
| `gates = null` on an old run (`02.8.3-T2:173`) | `autopilot.run.gatesNone`; no error, no retry. |
| Unknown `state`/`step`/`outcome`/`waiting_for` from the wire | Ignored for the chip/label (D8 rule for unknown stage values); the row renders with the raw value in a details popover. |
| Unknown `pauseReason` | Rendered with the generic `autopilot.pause.unknown` own key (the 15-value union covers the server enum; a future value must not break the table). |
| Poll failure | Keep the last good table + `autopilot.run.staleData` hint; the next successful poll clears it; a 401 goes through the interceptor (session end) and stops the poll. |
| Event burst (`EpisodeUpdated` × 20) | Coalesced to one refetch per 250 ms window. |
| `nextCursor` points to a deleted/changed run | The server returns a consistent page; if a page fails, the hint appears and the cursor is unchanged so Retry can repeat it. |
| Veto hydration: many episodes in the window | `Promise.all` bounded by the daily cap; if more than the UI cap (20, `autopilot.veto.maxRows`) is reached, the list shows the first 20 with the note and a link to the episode list ([OPEN-1] series-level route removes the cap). |
| Publication leaves the veto window while the user looks at it (consent written by the scheduler after the window) | The next poll/`EpisodeUpdated` removes the row; the action buttons answer `409` with `errors.<code>` and the row refetches. |
| `PATCH` on a publication in `uploading`/`processing` | Server refuses (only `awaiting_consent`/`scheduled` before upload — `00-overview.md:362`); the UI hides the Edit action for any status other than those two. |
| Flag turned off mid-session | 404 `feature_disabled` on the next request → hide both blocks + refetch `/me` (D14); no error state. |
| Session revoked while polling | The interceptor ends the session (D6); the poll's `DestroyRef` cleanup stops the timer on navigation. |
| Rollback | The whole feature sits behind `youtube_publish`: turning the flag off removes the log and the veto list without a deploy; a client rollback re-deploys the previous container. |
