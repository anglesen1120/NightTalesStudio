## Goal

`/episodes` lists the caller's episodes with a cursor-paginated "load more", a status filter and a series filter, shows a status chip plus a "Continue" action per row, and is reusable by the dashboard (10.4.1-T1 consumes the same component and store). One request per page, no duplicate requests, and an honest empty/error state.

```ts
// domain/episodes.repository.ts
export abstract class EpisodesRepository {
  abstract list(q: { status?: EpisodeStatus; seriesId?: string; cursor?: string; limit?: number }):
    Promise<CursorPage<EpisodeListItem>>;
  abstract get(id: string): Promise<EpisodeDetail>;                 // used from 10.5.2-T1 on
}
// domain/episode.model.ts
export const nextActionFor = (s: EpisodeStatus): { labelKey: string; segment: 'detail' } =>
  ({ labelKey: 'episodes.list.continue', segment: 'detail' });      // detail page owns the real actions (plan §10 O5)
```

```ts
// application/episode-list.store.ts
@Injectable()
export class EpisodeListStore {
  private readonly repo = inject(EpisodesRepository);
  private readonly destroyRef = inject(DestroyRef);
  readonly statusFilter = signal<EpisodeStatus | null>(null);
  readonly seriesFilter = signal<string | null>(null);
  readonly seriesOptions = signal<readonly { id: string; title: string }[]>([]);   // GET /series, loaded once per page open
  readonly loading = signal(false);
  readonly loadingMore = signal(false);
  readonly error = signal<AppError | null>(null);
  readonly items = signal<readonly EpisodeListItem[]>([]);
  readonly nextCursor = signal<string | null>(null);
  readonly hasMore = computed(() => this.nextCursor() !== null);
  readonly isEmpty = computed(() => !this.loading() && this.error() === null && this.items().length === 0);
  readonly page = cursorList({ limit: 20, fetch: (cursor) => this.fetch(cursor) });  // D5 primitive
  load(direction: 'reset' | 'more' = 'reset'): Promise<void>;   // every list call is user-initiated → carries `USER_ACTION` (WR11)
  setStatus(value: EpisodeStatus | null): void;                      // resets the cursor and reloads
  setSeries(value: string | null): void;                             // resets the cursor and reloads
  retry(): Promise<void>;
}
```

- `load('more')` is a no-op while `loadingMore()` is true or `nextCursor()` is null (the in-flight guard comes from `cursor-list`; the store must not open a second request).
- Errors: `AppErrorMapper` output goes to `error()`; a 400 with `fieldErrors.cursor` is treated as a terminal list error (the list restarts on the next filter change), never retried in a loop.
- Query-param contract: `/episodes?status=story_review&series=<uuid>` — the page writes the filters with `router.navigate([], { queryParams, replaceUrl: true })` and reads them once at construction, so a deep link and the browser Back button both work. `status` values are the `EpisodeStatus` literals; an unknown value is ignored.
- `SeriesOptionsRepository` exposes `list()` (this task) and `get(id)` → `{ id, title, topic }`, added by 10.5.2-T1 for the true-crime first step (`GET /api/v1/series/{id}`, 09.4.1-crud/plan.md:74) — one adapter, two calls, no third repository and no `@features/series` dependency.
- The series filter is a `mat-select` fed by `SeriesOptionsRepository.list()` (`GET /api/v1/series?limit=100`, mapped to `{ id, title }`) and loaded **once** when the page opens — it is never re-issued per filter change and it adds no dependency on `@features/series`. Archived series are not offered (`includeArchived` omitted). A `?series=<uuid>` deep link is resolved against the loaded options; when the id is not in the options (a series created in another tab) the filter still applies, the chip shows the id, and the next options load fills the title in. The exact `SeriesListItemDto` field names are verified against the generated client at implementation — plan §10 O7.
- `EpisodeListComponent` is presentational: `inputs: items, loading, loadingMore, hasMore, error`; `outputs: loadMore, retry, open(id)`. It injects no store and no `HttpClient` (D2).
- `@for (item of items(); track item.id)`; a skeleton (`LoadingState`) on the first load; `EmptyState` with an action to `/series` when the list is empty (copy `episodes.list.empty`); an older-row footer button labelled `episodes.list.loadMore` with `aria-busy` while `loadingMore`.

**Performance.** The route is lazy (`loadComponent`), every component is `OnPush`, `@for (item of items(); track item.id)` keeps row identity across "load more", the page size is fixed at 20 (one request per page, so the list never issues a request per row — no N+1), the first load renders the shared skeleton instead of a spinner per row, `Intl.DateTimeFormat` instances are created once per language rather than per row, and the only concurrency control is `cursor-list`'s in-flight guard (no timer, no polling — D13/D17). The feature adds no dependency to the initial chunk beyond the shared UI that `10-W1-foundation` already ships.

**Security.** The list renders ids, series id, title, status and dates only — no story content, no brief; none of it is logged or written to `localStorage`/`sessionStorage` (D6/D19). Row links are built from `item.id` to a literal internal route (no user-controlled URL, no open-redirect surface). The access token stays in `SessionStore` memory and the HTTP interceptor owns the `Authorization` header; the per-row `etag` is used as a cache validator for the detail request and is never persisted.

**Approved design handoff (2026-10-02).** Use [`04-episode-editor.html`](../../../../design/ui/screens/04-episode-editor.html), frames `f-list-loading`, `f-list-rows`, `f-list-empty`, `f-list-filters`, `f-list-filter-unavailable`, `f-list-filter-empty`, `f-list-paging`, `f-list-error`. These are observed static states; cursor/query synchronization and single-flight behavior remain runtime acceptance. Any shell balance in the artifact is S-only and absent in P.

`EpisodesListPage` is the route container. `EpisodeListViewModel`, `EpisodeRowViewModel` and `EpisodeFiltersViewModel` are immutable; presentational components emit filter/load/open/retry intents and never inject a store/repository. Route/session/request generation rejects obsolete list and series-option responses. The component-provided store and its query-param listener are destroyed together with the page component — `Route.providers` would live in the route's cached `EnvironmentInjector`, so page-scoped stores are provided on the component. The episode list is cursor-paged. The separate series endpoint is also cursor-paged; voice/style `{items}` catalogs elsewhere are unpaged and must not be used as a generic precedent.

The approved design has no paging/search state for a series filter beyond the first 100. The implementation loads only the first page (`limit=100`), preserves a deep-linked unknown id, and labels the option set as bounded; it must not claim all series or silently drain unbounded pages. Episode list/basic detail are present on the pinned backend snapshot. No ETag mutation or idempotency key applies to this read-only route. Shared ownership/lifecycle rules are linked from [implementation-roadmap.md §2–§3](../implementation-roadmap.md), readiness from [integration-readiness.md §1](../integration-readiness.md).

**Task-local acceptance delta:** prove scalar filter/query serialization, opaque cursor single-flight, late-result rejection after filter/route/session change — including a param-only change on a reused component and leaving to a public route without logout — and the explicitly bounded first-page series options (no >100-series claim).

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| 400 field `cursor` (expired/opaque cursor) | terminal error state + retry; retry restarts from page 1 rather than re-sending the bad cursor |
| 400 field `limit` | impossible from the UI (limit is fixed at 20) — logged as a client bug in dev, generic message shown |
| 401 during paging | handled by the interceptor under **WR9**: it refreshes + retries once only for a 401 with no code, `unauthenticated` or an expired-token challenge on a non-`/auth` route; `session_revoked`, `reauth_required`, `invalid_mfa_code`, `hub_ticket_invalid`, `refresh_token_reused` pass straight through to the caller (never replayed). A refresh failure ends the session and the router goes to `/login?returnUrl=/episodes…` (D6). A background request would instead refresh only while `isActive()` (WR11) — the list has none. |
| Empty page but `nextCursor` present | keep the button; the list must not claim "no episodes" while a cursor remains |
| `Cancelled`/unknown episode opened | the detail route answers 404 → `errors.not_found` + a back action (10.5.2-T1/U2) |
| Two filters changed within one tick | one request: filter setters debounce to the microtask queue and the last state wins |
| `?status=` with an unknown value | ignored (no request with an invalid value); the filter shows "Tất cả" |
| `GET /series` fails while the episodes list works | the select is disabled with `episodes.list.seriesFilterUnavailable` and the list keeps working; the options are retried on the next page open — never a blocking error |
| `?series=<uuid>` for a series missing from the options (created in another tab) | the filter still applies (the API decides) and the chip shows the id until the options reload with the title |
