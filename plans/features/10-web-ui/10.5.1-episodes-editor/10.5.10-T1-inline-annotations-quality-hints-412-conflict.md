## Goal

Every piece of server feedback about the draft lands **next to the text it is about**: quality hints from `qualityHints[]`, blocking vs advisory, objective vs taste, grouped in a summary panel and inline on the paragraph, hook, ending or keyword chip they address; `409 keywords_flagged` turns the exact chip red and keeps "Make video" disabled until it changes; and a `412 story_version_conflict` opens a dialog that never loses the user's text and never overwrites a colleague's version silently.

```ts
// shared/ui/inline-annotation/inline-annotation.component.ts   (inputs/outputs only, OnPush, no injections)
@Component({ selector: 'nts-inline-annotation', changeDetection: ChangeDetectionStrategy.OnPush, ... })
export class InlineAnnotationComponent {
  readonly annotation = input.required<SegmentAnnotation>();
  readonly compact = input(false);
  readonly dismissed = output<SegmentAnnotation>();
  readonly focusRequested = output<SegmentAnnotation>();
  // renders: severity icon + severity label, messageKey copy, evidence (interpolation), repair direction,
  //          optional "go to segment" action; role="note"; id derived from address + ruleId for aria-describedby
  //          a11y: focusable "go to" button, no focus stealing, no aria-live (the panel owns the live region)
}
```

- **Merge is pure and deterministic** (`annotation-merge.ts`): input = hints (`QualityHint[]`), keyword flags and (from 10.5.3-T2) similarity segments. Review issues are **not** an input: they already arrive flattened inside `qualityHints` (`02.3.4-T2:42`), and merging them again would render every one twice; output sorted by `kind` (objective first), then `severity` (blocking first), then `compareAddresses(segment)`, then `ruleId`. The same order feeds the panel and the inline slots, so a user reading top-to-bottom sees must-fix items first. Duplicate `(address, ruleId)` pairs collapse, and there is deliberately **no** `review` source: a `model_review` issue reaches the client as an ordinary hint (severity/kind/segment/evidence/repairDirection all present), so it renders once, inline, like any other objective or taste hint.
- **Keys are bound verbatim (D10).** `messageKey` from the payload is passed straight to Transloco — no `episodes.hints.<ruleId>` mirror and no `quality.<ruleId>` fallback, so the 02.3.4-T1 bundles stay the single source for hint copy. Only a genuinely missing key falls back to `episodes.annotations.unknown`, with one dev-console warning per session and never the raw key or server prose (D9).
- **Placing an annotation:** `segment-address.parse` turns `p:3` into paragraph index 3, `hook`/`title`/`ending` into their single-segment editors, and `meta` into the metadata block; an address that no longer exists after a reorder is re-anchored by the store's `remapAfterReorder` (10.5.9-T1) before rendering, and a truly unresolvable address is shown in the panel only (never dropped silently).
- **`409 keywords_flagged` — the one write path into `keywordFlags` (WR6).** `EpisodesHttpRepository` maps the ProblemDetails `errors[]` to `KeywordFlag { address, index, rule }` and 10.5.6-T1 (approve/render) hands them to the editor store through **`setKeywordFlags(errors)`** — the store is the single owner of `keywordFlags` and of `videoBlocked = computed(() => keywordFlags().length > 0)`; 10.5.6-T1 keeps no copy of its own. `SegmentChips` renders a flagged chip with an error icon, the accessible name `episodes.editor.keywordFlagged`, and `aria-describedby` pointing at the annotation's id. Flags clear only when the *next* save's response recomputes the checker (the server is the authority; a local edit never clears them).
- **Advisory scene hints:** `scenes_trimmed` / `scenes_sparse` arrive as advisory `QualityHint`s with segment `meta`; they render in the panel (not inline) with their verbatim `quality.scenes_sparse` copy.
- **412 conflict flow (completes the wiring of the `ConflictDialog` owned by 10.2.2-T1, WR4):**
  1. the draft, the scroll position and the focus are kept; `conflict` state records the server ETag/version and the segments that differ between my draft and the server's current story (a pure `diffSegmentAddresses(myDraft, serverStory)` — same address, different text/keywords);
  2. the dialog shows `episodes.conflict.title` / `.body`, the differing addresses ("Đoạn 3, Mở đầu") and `errors.story_version_conflict`;
  3. *Reload latest* → refetch the detail, adopt the server content as the new baseline, discard the draft (**only after an explicit second confirm inside the dialog**, because it is destructive);
  4. *Save mine as new version* → refetch the detail once, take the **fresh** `currentStory.etag`, PUT the draft again; one automatic re-attempt only — a second 412 keeps the dialog open and shows the "someone is editing too" variant instead of looping;
  5. *Cancel / Escape* → the dialog closes, the draft stays dirty, focus returns to the Save button;
- **Changed elsewhere, before a 412 (shared with 10.5.3-T1; WR7/WR11).** The invalidation arrives through `RealtimeService.subscribeEpisode(episodeId, handler)` (WR7) or `resync`, and the refetch it triggers is **background** — it carries no `USER_ACTION` flag, so a 401 there refreshes only while `isActive()` (D7) instead of waking an idle tab. 10.5.3-T1 owns that refetch; this task owns the notice it produces:
- **Copy keys** (scope `episodes`, vi + en): `episodes.annotations.heading` (Gợi ý cải thiện / Suggestions), `episodes.annotations.objective` (Khách quan / Objective), `episodes.annotations.taste` (Cảm nhận / Taste), `episodes.annotations.blocking` (Cần sửa / Must fix), `episodes.annotations.advisory` (Nên xem / Worth a look), `episodes.annotations.evidence` (Bằng chứng / Evidence), `episodes.annotations.repair` (Cách sửa / How to fix), `episodes.annotations.goTo` (Tới đoạn / Go to), `episodes.annotations.none` (Không có gợi ý / No suggestions), `episodes.annotations.unknown` (Có một gợi ý chưa dịch / A suggestion is not translated yet), `episodes.editor.keywordFlagged` (Cảnh cần sửa / Scene needs a change), `episodes.editor.keywordFlaggedHint` (Sửa cảnh này trước khi làm video / Fix this scene before making the video), `episodes.conflict.title` (Kịch bản đã thay đổi / The story changed), `episodes.conflict.body` (…đã được lưu ở nơi khác… / …was saved somewhere else…), `episodes.conflict.changed` (Khác với bản trên máy chủ / Differs from the server version), `episodes.conflict.reload` (Tải bản mới nhất / Reload latest), `episodes.conflict.reloadConfirm` (Bản bạn đang sửa sẽ bị thay thế / Your edits will be replaced), `episodes.conflict.saveMine` (Lưu bản của tôi thành phiên bản mới / Save mine as new version), `episodes.conflict.cancel` (Huỷ / Cancel), `episodes.conflict.busy` (Ai đó cũng đang sửa. Hãy tải bản mới nhất. / Someone else is editing too. Reload the latest.). Reused verbatim: `quality.*` (every `messageKey` from 02.3.4-T1), `quality.scenes_sparse`, `errors.keywords_flagged`, `errors.story_version_conflict`.
- **Performance.** `annotations` is a single `computed` over the hint/keyword signals (no re-merge per keystroke: it depends on the *saved* hint set and the flag set, not on the draft text, except for the flagged-chip binding). Inline annotations are per-segment `computed` slices; the summary panel is behind `@defer (on viewport)` (D13) so the editor's first paint is unaffected; `@for (a of annotations(); track a.address + a.ruleId + a.source)`; no per-keystroke DOM work for annotations. No timer, interval or new subscription is added by this task — the merge is pure, the live-region counter is a signal, and the dialog's own listeners are cleaned up through its component's `DestroyRef` when 10.5.3-T1's dialog is destroyed (D13).
- **Security.** Evidence strings are ≤ 200 chars of **our own** draft and are rendered through interpolation only (no `[innerHTML]`, no Markdown, D2/D18); `ruleId`/`messageKey` from the server are validated against a shape guard (`/^[A-Za-z0-9._:-]+$/`) before being used as a CSS class or an i18n key, so a hostile value cannot inject a class name or a Transloco path; nothing is logged with content (D19).
- **a11y (D16/WR12).** Severity is conveyed by an inline-`<svg>` icon component from 10.1.3-T1 **and** text (no `MatIconRegistry` SVG sets — WR12, since they would need `bypassSecurityTrustResourceUrl`)

They cover annotation present/empty and conflict base visuals. A distinct flagged editable keyword state follows the locked contract; do not infer it from the superseded scene-chip composition, and flag to the owner only if a new visual state is needed (does not reopen the approval or block the task).

`StoryReviewPage` owns conflict/dialog composition; the single `StoryEditorStore` owns hint/flag/conflict state. `InlineAnnotationViewModel`, `AnnotationPanelViewModel`, `ConflictViewModel` and typed focus/dismiss/reload/saveMine/cancel intents keep API shapes out of `ui/`. Immutable annotations are keyed by validated segment/rule identities. Route/episode/session generation rejects late invalidation/conflict responses; dialog/focus registrations are destroyed with the route and a late response cannot reopen the dialog.

The 412 flow always uses the exact current-story ETag, with one user-authorized save-mine attempt after a fresh GET; it has no idempotency key and never loops. Quality/currentStory/keyword payloads remain blocked on `02.3.4-T1/T2` and their existing 03/09 owners; do not synthesize `errors[]` or flags from the static artifact. See [implementation-roadmap.md §2–§3](../implementation-roadmap.md) and [integration-readiness.md §2–§3](../integration-readiness.md).

**Task-local acceptance delta:** implementation of the flagged control follows the locked contract; then prove no duplicate annotation, one-retry 412 safety, draft byte preservation, and no late dialog/state after route or session teardown.

## Acceptance checks

- [ ] After a save that returns hints, each hint appears inline next to its segment (or its chip) and once in the summary panel; the panel lists objective items before taste items and blocking before advisory.
- [ ] The panel and the inline copies show the **server's** copy from `quality.*`; no hint text is hard-coded in the client and no server prose is shown (D9).
- [ ] A hint whose `messageKey` is unknown renders the generic sentence and logs one dev warning — never the raw key.
- [ ] A `409 keywords_flagged` with `errors[{segment:"p:3",index:1,rule:"keyword_name_detected"}]` flags exactly that chip on paragraph 3 with an icon + text, and "Make video" is disabled while any flag exists.
- [ ] Editing the flagged chip does not clear the flag by itself; the flag set is replaced by the next save's recomputed hints.
- [ ] `scenes_sparse` / `scenes_trimmed` render as advisory notes in the panel with the verbatim 03 copy keys.
- [ ] Approve/Make-video is disabled **only** by the four WR6 conditions: (a) the draft is dirty or a save is in flight, (b) `auditReport.moderation` carries a blocking category (the 409 `story_moderated` condition), (c) an unmet true-crime precondition (attestation, `EPISODE_GATE`), or (d) `keywordFlags()` is non-empty. `qualityHints` **never** disable anything (C11, `02.3.4/plan.md:177`; WR6 supersedes `02.3.4-T1:85`, 10 CR-11) — the keyword flags disable because they are a server 409 `errors[]` (03.2.2-T2), not a hint.
- [ ] When another tab saves, the page raises the "changed elsewhere" notice from the refetch **before** the user presses Save, and the typed segments are byte-identical to before the notice appeared.
- [ ] A second consecutive 412 does not loop: the dialog switches to the busy variant and waits for the user (one automatic re-attempt maximum).
- [ ] E2E (vi and en): two browser contexts save the same episode; the loser sees the dialog and both actions are exercised; axe-clean; the dialog traps focus and restores it; no CSP/Trusted Types console error.
- [ ] Screen reader path: the annotation count is announced once after a save (one polite live region), each annotation is `role="note"` and linked with `aria-describedby` from its control; severity is never colour-only (verified with a contrast-off/a11y-tree assertion).
- [ ] At 360 px the inline annotations wrap under their textarea without horizontal scroll, and the `@defer`ed panel does not shift the layout when it loads.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Hint addresses a segment that no longer exists (stale response after a reorder) | re-anchored via `remapAfterReorder`; if it still cannot be resolved it stays in the panel with its address text, never silently dropped |
| Two hints share `(address, ruleId)` | deduplicated; the first (blocking/objective) wins |
| `errors[]` present but with an unknown `rule` | the chip is flagged and the tooltip falls back to `episodes.editor.keywordFlaggedHint`; the raw rule string is never rendered |
| `errors[]` with `segment: "meta"` (rule `no_scenes`) | announced in the panel only; no chip to flag |
| Hint payload present while the editor is read-only (`story_approved`) | annotations still render (they are informational); the save button stays disabled by state, not by hints |
| 412 while the dialog is already open | coalesced into the same state; no second dialog |
| `Save mine as new version` fails with 400 | the field errors are bound and the dialog closes with the draft intact |
| Network failure during `Reload latest` | the dialog stays open with an inline retry; the draft is untouched |
| A hint set changes while the user is typing | the panel updates; the live region announces the new count once (debounced by the save event, not by keystrokes) |
