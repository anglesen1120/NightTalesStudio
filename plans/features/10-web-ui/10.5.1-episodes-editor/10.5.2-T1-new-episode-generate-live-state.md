## Goal

`/series/:id/episodes/new` collects a brief (≤ 1,000 chars) and a length tier, creates the episode, starts story generation with an `Idempotency-Key`, shows the run's live stage from `EpisodeUpdated`, resolves a failure to its `errors.<code>` message, and hands off to the editor the moment the episode reaches `story_review`.

```ts
// application/new-episode.store.ts
@Injectable()
export class NewEpisodeStore {
  private readonly repo = inject(EpisodesRepository);
  private readonly realtime = inject(RealtimeService);
  private readonly router = inject(Router);
  readonly form = new FormGroup({ title: new FormControl('', { validators: [Validators.maxLength(120)] }),
                                  brief: new FormControl('', { nonNullable: true, validators: [Validators.required, Validators.maxLength(1000)] }),
                                  lengthTier: new FormControl<LengthTier>('standard', { nonNullable: true }) });
  readonly briefLength = toSignal(this.form.controls.brief.valueChanges.pipe(startWith('')), { initialValue: '' });
  readonly submitting = signal(false);
  readonly error = signal<AppError | null>(null);
  readonly episodeId = signal<string | null>(null);
  readonly generation = signal<EpisodeGeneration | null>(null);
  readonly stageKey = computed(() => stageKey(this.generation()?.stage));     // unknown stage → null → nothing rendered
  readonly failure = computed(() => failureKey(this.generation()?.errorCode)); // null while running/succeeded
  private attemptKey: string | null = null;
  async create(seriesId: string): Promise<void>;      // POST episodes → subscribe(id) → fiction: generate(id, fresh:true) | true_crime: navigate to /episodes/:id/research
  async generate(id: string, fresh: boolean): Promise<void>;
  subscribe(id: string): void;                         // RealtimeService.subscribeEpisode(id, handler) (WR7) — subscribe BEFORE generate; payload ignored
  retry(): Promise<void>;                             // new attemptKey only after a terminal failure
}
```

- **Idempotency discipline.** `attemptKey = IdempotencyKeys.new()` is created when the user starts a generation and **kept** while the outcome is unknown (network error, 5xx, timeout) so the retry replays the same logical command and cannot create a second run (02.2.2-T2). After a **terminal** failure the retry button calls `generate(id, fresh: true)` which mints a new key — a new intent must not replay the old run. `422 idempotency_key_reused` (a key reused on another episode) is surfaced as a client bug in dev and `errors.unknown_error` with `traceId` to the user. **Create has no idempotency key** (09.5.1-T1 Notes), so the create request is **never auto-retried**: a lost response leaves the button idle with `errors.network_error` and asks the user to check the episode list before pressing again — a fresh press is an explicit new submit, never a background retry.
- **Live state — invalidation only (plan §10 O11 / WR7).** `subscribe(id)` calls `RealtimeService.subscribeEpisode(id, handler)`
- **Errors.** `validation_failed`/`story_invalid_content` → `bindFieldErrors(form, error)` on `title`/`brief`, unmapped keys to a form-level alert; 429 → `RetryCountdown` from `Retry-After` with the submit disabled until 0; 409 `episode_invalid_state` → refetch the detail and re-render from `nextActions`; `fact_sheet_required` (true crime, 10.5.5) → message + link to `/episodes/:id/research`.
- **Copy keys.** Reused verbatim from 02 (F8): `story.generation.stage.writing|checking|reviewing|revising|scoring|saving`, `story.generation.error.story_invalid_output|story_generation_failed|story_generation_limit|spend_cap_reached`, `story.generation.paused.provider_funds_exhausted`, `story.generation.moderation.*`, `story.generation.action.retry|generate`. Owned here (plan §10 O3, the 02 namespace stays untouched): `episodes.generation.stage.queued` (Đang xếp hàng / Queued), `episodes.generation.stage.done` (Xong / Done), `episodes.generation.heading` (Đang tạo kịch bản / Generating your story), `episodes.generation.retrying` (Đang thử lại / Retrying). Form keys: `episodes.new.title` (Tập phim mới / New episode), `episodes.new.briefLabel` (Ý tưởng / Your idea), `episodes.new.briefHint` (…1.000 ký tự / …1,000 characters), `episodes.new.titleOptional` (Tiêu đề (không bắt buộc) / Title (optional)), `episodes.new.lengthTier` (Độ dài / Length), `episodes.new.tier.short|standard|long` (Ngắn|Tiêu chuẩn|Dài / Short|Standard|Long).
- **P (D14).** No "up to N credits" text and no `GET /billing/quote` call; the submit label is `story.generation.action.generate` and the reserved cost-line slot stays empty (plan §10 O2).
- **True-crime first step (a new episode has no fact sheet, so generate would always 409).** The page reads the series once; when `topic = 'true_crime'` the submit **creates the episode and navigates to `/episodes/:id/research` without calling generate** (the fact sheet and ≥ 2 cited sources must exist first, 02.2.2-T2 step 4 / 10.5.5-T1), and the button reads `episodes.new.trueCrimeNext` with the notice `episodes.new.trueCrimeNotice`. Every other topic keeps `create → generate` unchanged. `EPISODE_GATE` cannot help on this route — it is episode-scoped and no episode exists yet (W10Research, 2026-09-24) — so the topic check is the only pre-check here and the server's 409 `fact_sheet_required` stays the authority for every other path.
- **Write-story gate (soft integration, no canonical-cell change).** The generate action injects the token **optionally** (`inject(EPISODE_GATE, { optional: true })`, default `'open'`): when 10.5.5-T1 supplies it and the state is not `'open'`, the button is disabled with `episodes.research.gate.writeStoryBlocked` and a link to `/episodes/:id/research`; when the token is absent (10.5.5-T1 not merged yet) the button stays enabled and the server remains the authority through 409 `fact_sheet_required`, which the page already maps. The F13 rule is **never** re-implemented in this feature.
- **Request classification (WR11).** `create()` and `generate()` are called from UI events and therefore carry the `HttpContext` flag `USER_ACTION` (a 401 there may refresh unconditionally). The seeding `GET /episodes/{id}` after the 202 and every event/`resync` refetch run **without** it, so a generating tab nobody is looking at pauses instead of refreshing (D7).
- **Performance.** `OnPush` everywhere; the route is lazy; the form uses typed Reactive Forms (no template-driven); `CharCounter` is bound to a `computed` length, not to a `valueChanges` subscription per keystroke; exactly one create request and one generate request per attempt; the progress component renders a `@switch` over five stage keys, never a per-token DOM update.

**Security.** The brief and the title are user content: they go only to `POST /series/{id}/episodes`, are never logged, are rendered by interpolation only (no `[innerHTML]`), and are never persisted in the browser (D18/D19). The access token stays in `SessionStore` memory and the interceptor attaches it (D6); the `Idempotency-Key` is a client-generated UUID that never appears in a URL or in the hub ticket. A failure shows `errors.<code>` copy plus the `traceId` — never the raw `detail` and never generated text (D9); the hub ticket is never logged (D8); the D4 CSP/Trusted Types policy is untouched, and a `413 payload_too_large` is reported as a validation problem instead of being retried.

**Approved design handoff (2026-10-02).** Use [`04-episode-editor.html`](../../../../design/ui/screens/04-episode-editor.html), frames `f-new-form`, `f-new-form-limit`, `f-new-true-crime`, `f-new-submitting`, `f-new-generating`, `f-new-failed`. The first five are observed base states. `f-new-failed` is only a composite reference: terminal failure (alert + retry), 429 (countdown) and `processingPaused` (status, no error/retry) follow the locked contract; flag to the owner only if distinct visual states are needed (does not reopen the approval or block the task). Static frames do not prove subscription order or idempotency.

`NewEpisodePage` owns `NewEpisodeStore` and the typed form; `StoryBriefFormViewModel`/`GenerationProgressViewModel` feed presentational components, which emit create/generate/retry/open/research intents. Programmatic errors, submit disablement and server-driven progress use the zoneless notification bridge. Subscribe-before-generate is route-scoped; `DestroyRef` removes it, and route/episode/session generation rejects late create/detail events.

The create adapter must decode the 201 body as a JSON UUID **scalar**, then combine it with `Location`/`ETag` into `{id, etag}` for the domain port; it must reject an object-shaped assumption. Create has no idempotency key and never auto-retries. Generate alone uses `IdempotencyKeys`: same key while one intent's outcome is unknown, new key only for an explicit new attempt. Episode create/basic detail are present; generation/currentStory acceptance waits for `02.2.2-T2`, `02.3.4-T2` and `09.5.3-T1`. No story API is invented before them. See [implementation-roadmap.md §2–§3](../implementation-roadmap.md) and [integration-readiness.md §1–§3](../integration-readiness.md).

**Task-local acceptance delta:** mapper tests assert scalar UUID + headers; runtime proof distinguishes the three failure/paused states, ignores a late event after teardown/session change, and verifies create has no key while generation retries preserve or rotate the intent key exactly as specified.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Generate requested while a run is already active | 409 `story_generation_in_progress` → the page switches to the live state from `GET /episodes/{id}` instead of showing an error |
| True-crime episode without an approved fact sheet | cannot be reached from this page for a true-crime series (the first step navigates to research instead); if the topic changed between the read and the submit, the defensive path is 409 `fact_sheet_required` → message + link to `/episodes/:id/research` (10.5.5-T1), no retry loop |
| The hub is offline while generating | the page still shows `GET /episodes/{id}`'s `generation`; `resync` on reconnect refreshes it; the run continues server-side |
| A stage change happens between the 202 and the subscription | impossible by construction: the subscription exists before `generate` is sent, and the seeding `GET` after the 202 covers a run that already advanced |
| Duplicate submit (double click / Enter) | the submit button is disabled while `submitting()` and `create()` is guarded by a single in-flight promise |
| The create response is lost to a network error | `errors.network_error` + a note to check the episode list before retrying; **no automatic retry** (create has no idempotency key, 09.5.1-T1) |
| The episode is created but generate fails permanently | the page keeps the episode id and offers "Thử lại" plus "Mở tập phim" (the episode exists in `draft`) |
| `Idempotency-Key` > 128 chars | impossible (helper generates a UUID); a rejected key surfaces as `errors.validation_failed` |
| User navigates away mid-run | the run continues server-side; the subscription is torn down with the page |
