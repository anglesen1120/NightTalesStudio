- **Draft model (D18).** `StoryDraft` mirrors `story.v1` exactly — `title`, `hook { text, keywords, fact_refs }`, `paragraphs[] { beat, text, keywords, fact_refs }`, `ending { … }`, `description`, `tags`, `content_warnings`, `structure`. They are `StorySegment`s with `segKey`. `toContent()` drops `segKey` and emits the wire shape; `fromContent()` mints a fresh `crypto.randomUUID()` per segment. `structure` is carried opaquely and never rendered or edited (plan §10 O4).
- **Not a Reactive Form.** D13's typed-Reactive-Forms rule governs the simple forms (the brief form of 10.5.2-T1, the series/metadata forms of 10.4.x); the story editor is the documented exception because **D18** mandates one `WritableSignal` per segment plus a `serialize()`-based dirty check. Recording this once keeps the two rules from being read as contradictory.
- **Token rule (D4/D18).** `countTokens(text) = text.normalize('NFC').split(/\s+/u).filter(Boolean).length` — the same normalisation the backend uses, so the counters agree with `QualityHint` thresholds closely enough to be useful as a hint, and the UI never claims authority over the server's numbers (`wordCount` from the response wins after a save).
- **412 (D9/D18).** No silent overwrite: the store keeps the draft untouched, sets `conflict`, and `ConflictDialog` offers three actions — *Reload latest* (adopt the server content as the new baseline after an explicit confirm, discarding the local draft), *Save mine as new version* (refetch `GET /episodes/{id}`, take the fresh `currentStory.etag`, and PUT the draft again, so the other writer's version stays immutable in history), *Cancel* (stay dirty, keep the draft). 10.5.10-T1 owns the polish of this flow (copy, focus, repeated-412 guard, two-tab e2e).
- **Changed elsewhere, before a 412 (shared with 10.5.10-T1; WR7/WR11).** `subscribeEpisode` invalidations (and `resync`, background, **no** `USER_ACTION`) reach the detail;
- **Save uses the synchronous check.** `saveVersion()` calls `hasUnsavedChanges()` first, so a save pressed inside the 150 ms debounce window is not dropped (the debounced `isDirty` drives the "có thay đổi chưa lưu" indicator and the guards' hint only).
- **Copy keys** (scope `episodes`, vi + en): `episodes.editor.saveVersion` (Lưu phiên bản / Save version), `episodes.editor.saving` (Đang lưu… / Saving…), `episodes.editor.saved` (Đã lưu / Saved), `episodes.editor.unsaved` (Có thay đổi chưa lưu / Unsaved changes), `episodes.editor.segment.title|hook|paragraph|ending` (Tiêu đề|Mở đầu|Đoạn|Kết / Title|Hook|Paragraph|Ending), `episodes.editor.beat` (Nhịp / Beat), `episodes.editor.keywords` (Cảnh / Scenes), `episodes.editor.addKeyword` (Thêm cảnh / Add scene), `episodes.editor.removeKeyword` (Xoá cảnh / Remove scene), `episodes.editor.tokens` ({{count}} từ / {{count}} words), `episodes.editor.description` (Mô tả / Description), `episodes.editor.tags` (Thẻ / Tags), `episodes.editor.keywordLimit` (Mỗi đoạn cần 1–2 cảnh / Each paragraph needs 1–2 scenes). Reused verbatim from other plans: `errors.<code>`, `quality.*` (rendered by 10.5.10-T1).
- **Request classification (WR11).** `saveVersion()`, `resolveConflict('reload'|'saveAsNew')` and the explicit user reload carry the `HttpContext` flag `USER_ACTION`; the invalidation/`resync` refetch does **not**, so a 401 on it refreshes only while `isActive()` (D7).
- **Performance.** Lazy route; `OnPush`;

**Security.** Story text is the most sensitive payload this app holds: it is rendered by interpolation only (no `[innerHTML]`, no Markdown, no `bypassSecurityTrust*` — D2/D18), never logged, never written to `localStorage`/`sessionStorage`, never echoed into a URL, and sent only to the story routes. The access token lives in `SessionStore` memory and only the interceptor attaches it (D6). The save is `If-Match`-guarded so a stale tab cannot overwrite a newer version, and the 412 path never resolves silently (D9). `structure` and `fact_refs` are round-tripped untouched and never interpreted. An error response contributes only `code`, `fieldErrors` and `traceId` to the UI — never the raw `detail` (D9).

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| `currentStory` is `null` (episode never generated) | the page shows `EmptyState` with the generate action from `nextActions`; the editor never renders an empty draft |
| Episode in `story_approved`/`rendering` | `edit_story` is absent from `nextActions` → the editor renders read-only with `errors.episode_invalid_state` and a reopen action (10.5.6-T1 owns approve/reopen) |
| `If-Match` missing (428) | only reachable if the client has no ETag; the store refuses to save without one and logs the code + `traceId` in dev, showing `errors.unknown_error` to the user |
| Two saves in flight | the second is blocked by `saving()` (the button is disabled) |
| Another tab saves between `GET` and `PUT` | 412 → the conflict dialog (documented above), never a silent overwrite |
| The 412 body repeats on "Save mine as new version" | the dialog stays open with the same draft; the loop safety and copy are completed in 10.5.10-T1 |
| Very long text | plain textareas with the panel scroll; no `maxlength` truncation of the user's own story (the server validator reports real violations instead) |
| Clipboard / IME input | the write-back reads `event.target.value` on `input` (not `keyup`), so Vietnamese IME composition is not dropped |
| Reload with unsaved edits | the draft is intentionally lost (D18 forbids `localStorage`); the dirty guard warns first (10.5.9-T1) |
