## Goal

Surface the model's self-review in the same inline vocabulary the quality hints already use: blocking vs advisory issues with their evidence and repair direction, the rubric scores with a stale marker, the "Automatically corrected once" badge for a version the pipeline revised, and similarity `warn`/`block` highlights on exactly the segments the server says overlap a source.

## Design

Files:

```
features/episodes/domain/story.model.ts                    + AuditReport, ReviewCounts, RevisionInfo, SimilaritySection
features/episodes/domain/audit.model.ts                    ReviewIssue, RevisionInfo, countBySeverity(hints), whyIssues(auditReport), highlightMap(similarity, hints)
features/episodes/application/annotation-merge.ts          + similarity shares ONLY (review issues already arrive inside `qualityHints`)
features/episodes/application/story-editor.store.ts        + audit, reviewBlock, reviewCounts, revision, similarity, whyIssues, revisedBadge, driftNote, similarityHighlights, similarityUnavailable
features/episodes/ui/review-panel.component.ts             scores, counts, stale marker, drift note (@defer on viewport)
features/episodes/ui/revised-badge.component.ts            "Automatically corrected once"
features/episodes/ui/segment-editor.component.ts           + similarity highlight class per address
```

```ts
// application/story-editor.store.ts (additions — still the one editor store)
readonly audit = computed(() => this.snapshot()?.auditReport ?? null);                 // audit.v1 verbatim (02.3.4-T2:34)
readonly reviewBlock = computed(() => this.audit()?.modelReview ?? null);              // scores, stale, raw issues
readonly revision = computed(() => this.audit()?.revision ?? null);
readonly similarity = computed(() => this.audit()?.similarity ?? null);
readonly reviewCounts = computed<ReviewCounts>(() => countBySeverity(this.hints()));   // from qualityHints only
readonly revisedBadge = computed(() => this.snapshot()?.source === 'revised' || this.revision()?.applied === true);
readonly driftNote = computed(() => this.whyIssues().some(i => i.type === 'revision_drift') === true);
readonly whyIssues = computed(() => this.reviewBlock()?.issues ?? []);                 // expanded "why" panel ONLY
readonly similarityHighlights = computed(() => highlightMap(this.similarity(), this.hints())); // address → warn|block
readonly similarityUnavailable = computed(() =>
  this.snapshot()?.similarityScore === null && this.sourcesExist() === true);
```

- **One vocabulary, no double render.** A `model_review` issue **already** reaches the client as a `QualityHint` — `02.3.4-T2:42` flattens `local.issues ++ model_review.issues` into `qualityHints` — so the inline annotations come **only** from `qualityHints` through 10.5.10-T1's merge. This task must **not** merge `auditReport.modelReview.issues` a second time, or every review issue would render twice. The raw `modelReview.issues` are used only in the expanded "why" panel (impact / repair direction / evidence), which is exactly the panel `02.3.4-T2:134` reserves for `auditReport`. No second annotation UI is built, and `InlineAnnotation`'s signature stays stable for 10.5.4/10.5.5.
- **Counts and scores.** `reviewCounts` counts the `qualityHints` by severity (`blocking` / `advisory`) — CR-7 has no `issueCounts` field and none is invented. The seven 1–5 `scores` and `stale` come from `auditReport.modelReview`; `stale` renders `quality.model_review_stale` next to the scores. The drift note is read from a `revision_drift` advisory issue in `modelReview.issues` (or `revision.drift`) and renders `episodes.audit.drift`. A taste issue is always shown as advisory even if a payload claimed otherwise (`kind` respected, severity clamped — the same rule 02.6.1-T1:99 applies server-side).
- **"Automatically corrected once".** `revisedBadge()` reads the version `source` (authoritative) with `revision.applied` as the fallback; the badge uses **`story.generation.revised.badge`** verbatim ("Automatically corrected once" / "Đã tự sửa một lần"). The diff link is added by 10.5.4-T1 together with the versions route — this task ships the badge text only, so no task links to a route it does not depend on.
- **Similarity highlights.** `similarityHighlights()` maps every `segments[].segment` (a D22 address) to `warn` or `block` using the **server's** verdict as it arrives in the hint set (`Q-SIM-01` / `Q-SIM-02`); the client never re-derives thresholds from `Similarity:WarnAbove` (it does not know them and must not guess). The affected paragraph, hook or ending gets a quiet outline plus the shared `quality.similarity_warn` / `quality.similarity_blocked` copy in its annotation; `share` is shown as a percentage in the panel (`episodes.similarity.segmentShare`), never as a bar that implies precision the score does not have. The **panel** carries the copy owned by 02.5.6 (`story.similarity.warn` / `story.similarity.block` / `story.similarity.unavailable`, `02.5.6 plan.md` §6) and lists the overlapping addresses with their `share`; the inline rows keep the hint keys `quality.similarity_warn` / `quality.similarity_blocked` (02.3.4-T1).
- **Degrade, never break (soft 02.6.2-T1):** when `revision` is missing (`applied` absent/false) there is no badge and no drift note; when `auditReport` or `modelReview` is `null` the panel renders an empty state and shows "no checks recorded" (`02.3.4-T2:125`), never an error; when the story is not scorable, `similarityScore = null` with sources shows `story.similarity.unavailable` (verbatim 02.5.6-T1 copy) and **no** highlights; with no sources nothing similarity-related is rendered at all.
- **Addresses survive structure edits:** highlights and review annotations are keyed by `SegmentAddress` and remapped by the store's `remapAfterReorder` after a move/delete (10.5.9-T1), so a highlight never jumps to the wrong paragraph.
- **Copy keys** (scope `episodes`, vi + en): `episodes.audit.heading` (Tự đánh giá / Self-review), `episodes.audit.blocking` (Cần sửa / Must fix), `episodes.audit.advisory` (Nên xem / Worth a look), `episodes.audit.scores` (Điểm đánh giá / Scores), `episodes.audit.score.hook|pacing|atmosphere|natural_language|originality|factual_care|length_fit` (seven dimension labels, vi + en), `episodes.audit.drift` (Bản tự sửa có thể đã lệch — hãy xem lại các đoạn được sửa / The automatic fix may have drifted — review the fixed paragraphs), `episodes.audit.impact` (Ảnh hưởng / Impact), `episodes.similarity.heading` (Giống nguồn / Similar to a source), `episodes.similarity.segmentShare` (Đoạn {{segment}} — {{percent}}% / Segment {{segment}} — {{percent}}%), `episodes.similarity.note` (Đây là gợi ý, bạn vẫn có thể duyệt nếu không bị chặn / This is a hint; you can still approve unless it is blocked). Reused verbatim: `story.generation.revised.badge`, `quality.similarity_warn`, `quality.similarity_blocked`, `quality.model_review_stale`, `story.similarity.unavailable`, `errors.story_too_similar_to_source` (approve path, 10.5.6-T1).
- **Performance.** The review/similarity signals are read from the same `currentStory` payload as the hints — **no extra request** (10.5.3-T1's page already loads the detail once). `review-panel` sits behind `@defer (on viewport)` (D13); `@for` over `scores` uses a literal key list (7 items) with `track key`; the highlight class is derived from a `computed` map, not per-paragraph function calls in the template, so a keystroke does not recompute the whole map. No timer, interval or new long-lived subscription is introduced, so nothing extra needs tearing down beyond the store's own `DestroyRef` lifecycle (D13/D17).
- **Security.** `evidence`, `impact` and `repair_direction` are server strings derived from our own draft (≤ 200 chars) and are rendered by interpolation only — no `[innerHTML]`, no Markdown (D2/D18); `issue.id`/`ruleId` are shape-validated before being used as i18n keys or class names; no review text or source text is logged (D19).
- **a11y (D16).** Scores are announced as a real table (`<table>` with `<th scope="row">`) rather than a grid of divs; stale and drift are textual, not colour-only; the similarity highlight is accompanied by text in the annotation (the outline is decoration); the panel's live region is the single one owned by 10.5.10-T1, so this task adds no second `aria-live`; the badge carries an explanatory `aria-describedby` pointing at the drift/stale note when present.

**Approved design handoff (2026-10-02).** Use [`04-episode-editor.html`](../../../../design/ui/screens/04-episode-editor.html), frames `f-editor-self-review`, `f-editor-annotations`, `f-editor-annotations-none`. They establish the base panel/inline states only; no-double-render, stale markers, similarity address mapping and remap after structure changes are runtime acceptance.

The existing story route/store remains the only container/writer. `ReviewPanelViewModel`, `RevisedBadgeViewModel` and `SimilarityHighlightViewModel` are immutable presentation contracts with only open/focus intents; no component recomputes server verdicts or injects data access. Audit signals derive from the current server snapshot, are replaced immutably, and disappear on route/session teardown. Late detail results for another episode/session are rejected. There is no mutation, ETag or idempotency key in this task.

All review/revision/similarity payloads are planned under `02.6.1-T1`, soft `02.6.2-T1`, `02.5.6-T1` and the currentStory owner `02.3.4-T2`; basic detail and the static frame do not establish those fields. Shared seams remain `InlineAnnotation`/`SegmentAddress`; no new shared component is proposed. See [implementation-roadmap.md §2](../implementation-roadmap.md) and [integration-readiness.md §2–§3](../integration-readiness.md).

**Task-local acceptance delta:** real merged payload proof must show one inline row per flattened hint, no invented verdict/count, no extra request, and no stale panel/highlight after route, episode or session changes.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| The hint set and `auditReport.modelReview.issues` disagree (a hint added/removed by a later checker version) | the header counts stay the ones derived from `qualityHints` — what the user sees inline — and the expanded panel lists the audit document as recorded, with the `episodes.audit.partial` note instead of a silent recalculation |
| An issue address no longer exists after a reorder | remapped by address; if it still does not resolve it appears in the panel with its address text |
| `revision.applied = false` with `reason = revision_invalid_output` | no badge; nothing else changes (the run still succeeded, 02.6.2-T1) |
| `review_after` present but `revision` absent | panel renders only what exists; no invented badge |
| `similarity.corpus = 'past_episodes'` | the *sources* corpus verdict is the only one the hint set carries; a past-episode share is displayed as informational text without a warn/block claim |
| Similarity score > 0 but every `segments[]` share is 0 | the panel shows the score alone and marks nothing (no fabricated paragraph) |
| Payload grows (03.4.2-T1 adds `renderJob.images`) | untouched: this task reads only `currentStory` |
| `modelReview` present while `qualityHints` is empty (should not happen — the hints flatten the issues) | the inline list stays empty and the expanded "why" panel shows the audit document; no synthetic annotation is invented from `modelReview.issues` |
