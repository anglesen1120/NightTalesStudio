## Goal

Shape the story without losing work: each paragraph moves by pointer or keyboard, its keyword values and read-only `beat` travel with it, deletion is undoable for 10 seconds, and dirty navigation asks first. The keyword control and 360 px active-segment navigation follow the locked contract, not an inferred return to the old scene-chip composition.

## Design

Files:

```
features/episodes/application/story-editor.store.ts        + moveUp/moveDown/moveTo/removeParagraph/undoRemove, address remap
features/episodes/application/paragraph-structure.ts       pure: applyMove(paragraphs, from, to), applyRemove(...) (immutable)
features/episodes/guards/dirty-story.guard.ts              canDeactivate<StoryReviewPageComponent>
features/episodes/ui/paragraph-list.component.ts           cdkDropList + handle + up/down buttons
features/episodes/ui/paragraph-card.component.ts           beat label, textarea, chips, move/delete buttons

```

```ts
// application/story-editor.store.ts (additions — same store, no second writer, D18)
readonly removed = signal<{ paragraph: ParagraphState; index: number } | null>(null);   // the undo buffer
moveUp(index: number): void;                       // no-op at index 0
moveDown(index: number): void;                     // no-op at the last index
moveTo(from: number, to: number): void;            // CDK drop end
removeParagraph(index: number): void;              // pushes to `removed`, clears after 10 s
undoRemove(): void;                                // re-inserts at the original index with the SAME segKey
readonly canMoveUp = (index: number) => boolean;   // template helpers bound to `computed` arrays
readonly canMoveDown = (index: number) => boolean;
private remapAddresses(): void;   // rebuilds every `p:<i>`-keyed address after a move, a delete OR an undo
```

- **Immutable moves.** `applyMove` returns a new array (the store's `paragraphs` is a signal holding a frozen array), so `@for (p of paragraphs(); track p.segKey)` reuses every untouched textarea (D18). `moveTo` clamps the target index to `[0, length - 1]` and ignores a move to the same index (a CDK drop on itself must not create a dirty state).
- **Keyboard path is first-class.** Each card has `↑`/`↓` icon buttons with accessible names that include the position (`episodes.editor.moveUp` / `moveDown` + the 1-based index), `aria-disabled` at the ends (never `disabled`, so screen-reader users keep the item in the reading order), and every move calls `LiveAnnouncer.announce(...)` with `episodes.editor.reorderAnnounce` (`Đã chuyển đoạn {{n}} tới vị trí {{m}}` / `Moved paragraph {{n}} to position {{m}}`). The CDK drag handle is an additional affordance for pointers only — no reorder path depends on it (D18/F11).
- **Focus after a move.** After a successful move the moved textarea regains focus (`viewChild` by `segKey`), and after an undo the restored paragraph's textarea regains focus; the announcement happens after the DOM update (`LiveAnnouncer` post-render), so the order the screen reader hears matches what it sees.
- **Delete + undo.** `removeParagraph` stores `{ paragraph, index }` in `removed`, removes it from the array, and starts a 10 s timer (`DestroyRef`-cleared). The snackbar (`MatSnackBar`) shows `episodes.editor.deleted` with an action `episodes.editor.undo`; `undoRemove()` re-inserts with the original `segKey` (so `track` reuses the node) and clears `removed`. A second delete within the window replaces the buffer and **commits** the first deletion semantics-wise (the draft simply no longer contains it) — the buffer holds one paragraph at a time, documented in the UI copy. Nothing is durable until "Lưu phiên bản": not saving still leaves the paragraph recoverable in the last server version (D18).
- **Address remapping — on every structural change.** A **move**, a **delete** and an **undo** all shift later `p:<i>` values, so the annotation/keyword-flag/similarity maps are rebuilt from the pre-change paragraph list through `segment-address.remapAfterReorder`: after deleting `p:2`, the hint that belonged to the old `p:3` stays on the same text (now `p:2`) instead of sliding onto a neighbour. While a paragraph sits in the undo buffer its own hints are hidden (its text is not in the draft) and they return with the undo. `meta`/`title`/`hook`/`ending` addresses are unaffected.
- **Dirty guard.** `dirtyStoryGuard` (`CanDeactivateFn`) reads the **synchronous** `StoryEditorStore.hasUnsavedChanges()` (never the 150 ms debounced `isDirty`, which would let the user leave inside the debounce window); when dirty it opens the shared `ConfirmDialog` with `episodes.dirty.title` / `episodes.dirty.body` and the actions `episodes.dirty.stay` / `episodes.dirty.leave`, returning the user's answer as a `Promise<boolean>`. The page registers a `beforeunload` handler while `hasUnsavedChanges()` is true (`effect` + `DestroyRef`), removed as soon as the draft is clean. The guard covers **user-initiated** navigation and logout only; a terminal `SessionEnded` (`session_revoked`, `refresh_token_reused`, a refresh-family failure) is not deferred by the prompt — scoped stores reset, realtime stops and the session ends immediately, so a "Stay" answer can never keep a draft or route alive after the session is already invalid (D6).
- **Copy keys** (scope `episodes`, vi + en): `episodes.editor.moveUp` (Lên / Move up), `episodes.editor.moveDown` (Xuống / Move down), `episodes.editor.moveHandle` (Kéo để di chuyển / Drag to move), `episodes.editor.delete` (Xoá đoạn / Delete paragraph), `episodes.editor.deleted` (Đã xoá một đoạn / Paragraph deleted), `episodes.editor.undo` (Hoàn tác / Undo), `episodes.editor.reorderAnnounce` (Đã chuyển đoạn {{n}} tới vị trí {{m}} / Moved paragraph {{n}} to position {{m}}), `episodes.editor.structureWarning` (Cấu trúc có thể không còn đúng hạng độ dài / The structure may no longer fit this tier), `episodes.dirty.title` (Bạn có thay đổi chưa lưu / You have unsaved changes), `episodes.dirty.body` (Rời trang sẽ mất các thay đổi này / Leaving will discard them), `episodes.dirty.stay` (Ở lại / Stay), `episodes.dirty.leave` (Rời trang / Leave).
- **Performance.** The route is lazy and every component is `OnPush`; the move/delete operations are pure array copies over a `readonly` array (no deep clone of text); the snackbar timer and the `beforeunload` listener are the only timers and both are `DestroyRef`-cleared; the drag preview is `@angular/cdk` only and adds no `@defer` boundary; CDK is already a dependency (D1) — no new package.
- **a11y (D16).** Move/delete buttons ≥ 24 px with visible focus; the drag handle is `aria-hidden`-free but documented as optional and carries `episodes.editor.moveHandle` as its accessible name; the snackbar action is keyboard reachable and the snackbar is announced; `prefers-reduced-motion` disables the drag-drop animation (`cdkDropList` transition) and the snackbar slide; screen-reader users get the same result through the buttons and the announcements.
- The client does **not** block a structure that violates the tier's segment range: after the next save the server's validator and the hint `quality.segment_count_out_of_range` report it. The editor only shows the sticky advisory `episodes.editor.structureWarning` while `paragraphs().length` is outside the tier band that C9 documents, and never disables Save for it (hints never gate, D9/D18).

**Security.** Reorder and delete are purely local operations: no request, no persistence, nothing written to `localStorage`/`sessionStorage` (D18) and no story text shown in the snackbar beyond a generic sentence. The dirty guard protects the user's work rather than exposing it — the in-app confirmation uses the shared `ConfirmDialog` (focus-trapped) and the tab-close path uses the browser's own dialog, never a spoofable custom one. The guard never mutates the store, so a cancelled navigation cannot leak an intermediate order into a later save, and all paragraph text stays interpolated (`[innerHTML]` is banned by the lint rule, D2).

**Approved design handoff (2026-10-02).** Use [`04-episode-editor.html`](../../../../design/ui/screens/04-episode-editor.html), frames `f-editor-structure`, `f-editor-undo`, `f-dirty-guard`. `StoryReviewPage` remains the container and `StoryEditorStore` the single writer. `ParagraphListViewModel`/`ParagraphRowViewModel` feed presentational rows and emit move/delete/undo/focus intents. Existing shared ownership is linked from [implementation-roadmap.md §2–§3](../implementation-roadmap.md), readiness from [integration-readiness.md §2](../integration-readiness.md).

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Drag dropped outside the list / on itself | ignored; no dirty flag, no request |
| Delete while only one paragraph remains | allowed (the server owns the tier minimum and reports `quality.segment_count_out_of_range` after the save); `episodes.editor.structureWarning` is visible meanwhile |
| Delete then undo after a further edit | the restored paragraph keeps its text **as removed** (an edit made after the delete is not re-applied to it) — stated in the undo behaviour and covered by a test |
| Two deletes within 10 s | the buffer holds the last one; the snackbar action restores only that paragraph |
| Save in flight while reordering | the save serialises the array as it was when `saveVersion()` was called; the later reorder leaves the draft dirty again (no lost keystrokes, no partial write) |
| Route deactivation caused by a session end | the guard runs first; a "leave" answer lets the logout proceed and discards the draft |
| Browser blocks the `beforeunload` dialog | expected (browsers ignore custom copy); the in-app guard carries the real message |
| Annotation address remap when a paragraph moves twice quickly | computed from the pre-move address list each time; the result is idempotent per move |
| Screen reader + CDK drag | irrelevant: the buttons are the accessible path and the drag handle is optional |
