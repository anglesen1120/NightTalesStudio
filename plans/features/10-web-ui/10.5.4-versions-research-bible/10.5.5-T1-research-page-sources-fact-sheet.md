## Goal

`/episodes/:id/research` lets the owner add up to 10 sources (a pasted link or a personal note), watch each fetch result, retry or remove one, then build, edit and **approve** the episode fact sheet (facts with source chips and a confidence badge). For a true-crime episode the page also owns the visible gate: story writing stays blocked until the fact sheet is approved with ≥ 2 fetched url sources each cited by ≥ 1 fact. For a true-crime series this route is also the **post-creation landing page** (10.5.2-T1 creates the episode and navigates here instead of calling generate, owner ack 2026-09-24), so the zero-source state must render as a normal empty state — no error, no redirect, add form focused.

**`ResearchStore`** (provided by the research route; the editor route provides a second instance only for the read-only gate — the two never write):

```ts
readonly sources = signal<ResearchSource[]>([]);
readonly limits = signal<SourceLimits | null>(null);
readonly factSheet = signal<FactSheet | null>(null);
readonly generation = computed(() => this.episode.generation());          // from 10.5.3-T1's EpisodeStore
readonly kind = computed(() => this.generation()?.kind ?? null);          // 'fact_sheet' | 'find_sources' | …
readonly running = computed(() => this.kind() !== null && ['queued','running'].includes(this.generation()!.status));
readonly pendingCount = computed(() => this.sources().filter(s => s.status === 'pending').length);
readonly urlCount = computed(() => this.sources().filter(s => s.kind === 'url').length);
readonly canAddUrl = computed(() => this.urlCount() < (this.limits()?.maxPerEpisode ?? 10));
readonly loaded = signal(false);                                           // set true by the first successful load()
readonly gate = computed<GateState>(() => {
  if (!this.loaded()) return 'open';                                       // an unloaded instance must NEVER pre-disable
  const fs = this.factSheet();
  if (!this.isTrueCrime()) return 'not_applicable';
  if (!fs || fs.status !== 'approved') return 'sheet_not_approved';
  const cited = new Set(fs.facts.flatMap(f => f.sourceIds));
  const fetched = this.sources().filter(s => s.kind === 'url' && s.status === 'fetched' && cited.has(s.id));
  return fetched.length >= 2 ? 'open' : 'sources_insufficient';           // mirrors 02 F13 for copy only
});
readonly savingFactSheet = signal(false); readonly approvingFactSheet = signal(false);
readonly error = signal<AppError | null>(null); readonly formError = signal<AppError | null>(null);
readonly conflict = signal<{ etag: string } | null>(null);
load(episodeId: string): Promise<void>;                                    // GET sources + GET fact-sheet, in parallel
addUrl(episodeId: string, url: string): Promise<Result<void>>;
addNote(episodeId: string, note: string): Promise<Result<void>>;
remove(episodeId: string, sourceId: string): Promise<Result<void>>;
retry(episodeId: string, sourceId: string): Promise<Result<void>>;
refresh(episodeId: string): Promise<void>;                                 // "Refresh status"
generate(episodeId: string): Promise<Result<void>>;                        // IdempotencyKeys.next('fact_sheet', episodeId)
editFact(factId: string, patch: Partial<Pick<Fact,'statement'|'confidence'|'sourceIds'>>): void;  // local draft only
addFact(): void;                                                           // id '' + user origin, confidence 'high'
removeFact(factId: string): void;
save(episodeId: string): Promise<Result<void>>;                            // PUT { content } + If-Match: factSheet().etag
approve(episodeId: string): Promise<Result<void>>;                         // POST approve + If-Match
dirty = computed(() => serialize(this.draft()) !== serialize(this.factSheet()));   // 150 ms debounce (D18)
reset(): void;
```

Wire bodies: `PUT` sends `{ content: { facts: FactItemInputDto[] } }` built from the draft (`id` omitted for a new fact, `confidence` sent only when the user changed it — otherwise preserved server-side, F2/T53); `POST …/fact-sheet/generate` sends the `Idempotency-Key` header; `POST …/fact-sheet/approve` sends only `If-Match`.

**Missing sheet = a normal state, not an error**: `GET /api/v1/episodes/{id}/fact-sheet` answers **200 with a null body** (its only error is 403 — 02.5.3 `plan.md:122`), so `loadFactSheet()` sets `factSheet = null` and the page renders `factSheet.empty` with the generate button enabled once ≥ 1 source is fetched; `save`/`approve` are disabled because there is no `fs-<id>` ETag to send. No error state, no retry loop, no toast. This is the state the page always starts in on the true-crime post-creation landing (see Goal), so the empty state must be the first-class default.

**Gate exposure to 10.5.2-T1 (cross-folder contract, accepted by its owner 2026-09-24)**: this task provides `EPISODE_GATE` (`InjectionToken<Signal<GateState>>`) from **route-level `providers`** on `/episodes/:id` in `features/episodes/episodes.routes.ts` (next to the editor and research children) so the editor and the research page resolve the same instance. The consumer injects it **optionally** (`inject(EPISODE_GATE, { optional: true })`, default `'open'`) and disables "Write story" with `episodes.research.gate.writeStoryBlocked` + a link to `/episodes/:id/research`; a missing provider degrades to the server's 409 `fact_sheet_required`, which stays the authority (10.5.2-T1 maps it). The editor route reads `gate` from the provided store and calls `load()` once on activation (two coalesced GETs), so the pre-emptive disable is real without duplicating the F13 rule (D18); `research-page` provides the same token when it owns the store. **Unloaded state**: `gate` returns `'open'` until the first successful `load()` (`loaded()` false), so an instance that has not fetched yet can never pre-disable the button — the same behaviour as the peer's absent-provider default, which means no new enum value and no change on their side. The gate is **episode-scoped**, so `/series/:id/episodes/new` (the create+generate path) intentionally resolves no token: no episode exists yet and therefore no fact sheet to check; that route keeps the server's 409 `fact_sheet_required` as its authority. Recorded in `plan.md` §10 item 5.

## Steps

1. Model + port + `HttpResearchRepository` (all 9 calls; `readEtag` for the fact sheet; `appErrorMapper` everywhere; no body logging).
2. Fake repository + `ResearchStore` + store tests (gate matrix, ETag flows, idempotency, coalesced refetch).
3. `SourceAddForm` (url/note tabs, one field active at a time, note `CharCounter` 3,000; inline `aria-describedby` errors), `SourceRow` (status chip with icon + text; `title` as the primary line when present, else the domain; retry only for `failed`; remove with a confirm dialog when `isCited`).
4. `FactSheetPanel` + `FactRow`: statement textarea (`CharCounter` 600), confidence `mat-select` (`high|medium|low`, `low` shown as advisory, never hidden — F2), source chips (`alias` + title, tooltip = url, `user_note` chip uses `factSheet.userNoteLabel`), delete (`aria-label` with the fact index), add-fact (requires ≥ 1 source: `episodes.research.facts.requiresSource`), overlap chip when `sourceOverlap !== null` (see Notes).
5. Panel states: `empty`, `generating` (driven by `generation.kind === 'fact_sheet'` + `running`), `draft`, `approved` (read-only + "Edit" → next draft), `error` (`fact_sheet_sources_insufficient`, `fact_sheet_generation_in_progress`, `spend_cap_reached` → banner only, no quote in P).
6. Route + navigation: restore key `research`; the editor gets a tab/link "Research"; the page loads both `GET`s in parallel on entry.
7. Realtime: subscribe `EpisodeUpdated` for this episode id + `resync`; refetch `sources` + `fact-sheet` when `change === 'factSheet'` or `generation.kind` changes to/from `find_sources`; coalesce within 250 ms; unsubscribe in `DestroyRef`. Add the manual "Refresh status" button (D17 — no polling).
8. Error routing: 412 `fact_sheet_conflict` → `ConflictDialog` (Reload latest = refetch sheet; Save mine as new version = PUT again with the fresh ETag, which creates the next draft by design, 02.5.4-T1:26); 400 `fact_sheet_invalid_content` → `bindFieldErrors` (unknown/duplicate id, unknown source, empty statement); 409 F13 → the two-clause copy; 429 → `RetryCountdown`.
9. i18n keys both files; e2e spec; wire the gate token.

- [ ] `/episodes/:id/research` loads sources and the fact sheet in two parallel calls; the counter shows `{used}/{max}` from `limits`; at the episode cap (10) "Add source" is disabled with the reason.
- [ ] Adding a link POSTs `{ url }` and the new row shows `pending`; adding a note POSTs `{ noteText }` and the row is immediately `fetched` with the `factSheet.userNoteLabel`-style note chip (02.5.1:208).
- [ ] A blocked domain shows `errors.source_domain_not_allowed` inline on the input; a bad URL shows `errors.source_url_invalid`; a duplicate points at the existing row; the 24 h cap shows `RetryCountdown` from `Retry-After`.
- [ ] A note longer than 3,000 characters is blocked client-side with the counter in the error state (server cap mirrored for UX only).
- [ ] Landing on the page with no fact sheet (a fresh true-crime episode) shows `factSheet.empty` — **not** an error, no retry, no toast — with "Build fact sheet" enabled once ≥ 1 source is `fetched` and `Save`/`Approve` disabled (no `fs-<id>` to send); a 403 on that GET is the only error path and renders `ErrorState`.
- [ ] Each source row shows its status (pending spinner / fetched with title / failed with the mapped reason from `errorCode`, e.g. `errors.source_blocked_by_robots` / blocked domain as `rejected`) with an icon **and** text; `failed` rows offer Retry; removing a `cited` source asks for confirmation; removing any source is blocked in `story_approved` with `errors.episode_invalid_state`.
- [ ] Fetch status updates without polling: after an `EpisodeUpdated` for this episode the list refetches once (two events within 250 ms produce one request); "Refresh status" always works.
- [ ] "Build fact sheet" sends a single `Idempotency-Key` and shows the generating state; a 422 on retry sends a **new** key.
- [ ] In the draft state a fact's statement, confidence and sources are editable; deleting and adding facts works; saving sends `If-Match` and the new ETag is adopted; a fact whose only source was deleted is rejected with `errors.fact_sheet_invalid_content` and the UI offers to remove it (02.5.4-T1:73).
- [ ] `confidence: 'low'` is visible as an advisory badge (`episodes.research.confidence.low`) and the fact is neither hidden nor blocking (T53).
- [ ] In the approved state the list is read-only and "Edit" creates the next draft version (a PUT), leaving the approved row intact; approving again while nothing changed is impossible (the button only exists on a draft).
- [ ] Approving with fewer than 2 distinct fetched cited url sources is refused with `errors.story_sources_required` and the two-clause copy; after two cited fetched sources the approve succeeds and the editor's "Write story" button unlocks.
- [ ] The gate block on the research page announces its reason in a `role="status"` region in both languages; axe clean; the page works keyboard-only at 360 px.
- [ ] An editor-route gate instance that has **not** loaded yet reports `'open'` (no false "Write story" disable); after its one-shot load it reports the real state, and a true-crime episode with an approved sheet + 2 cited fetched sources reports `'open'`.

## Failure handling and edge cases

- **Generate while a run is active** → `fact_sheet_generation_in_progress` (409): the button is disabled while `running`; on a stale tab the banner appears and the run state comes from `generation`.
- **`spend_cap_reached` (429)** → banner only (the user asks support/autopilot settings elsewhere); no credit amount, no quote in P (D14).
- **Approve on a sheet whose sources changed** (a source removed after generation) → `story_sources_required` + the F13 copy; the fix is adding/citing a second fetched source, not re-approving blindly.
- **Approve a draft while a generate run is in flight** → allowed by the server and documented in 02.5.4-T1:72; the UI shows `factSheet.reopenStoryHint` so the user knows the new version will be a fresh draft needing re-approval.
- **Two tabs editing the same draft** → the second save gets 412 → `ConflictDialog`; "Save mine as new version" re-PUTs with the reloaded ETag (creating the next draft, which is the server's own semantics — never a silent overwrite).
- **Source removed between load and save** → `fact_sheet_invalid_content` naming the field → the UI offers to drop that fact's source chip.
- **Network loss mid-add** → the row is not created (no optimistic row); a retry re-POSTs, and a duplicate response points at the existing row instead of erroring confusingly.
- **`input_truncated` set by the run** (02.5.3:135) → `episodes.research.sources.truncated` chip on the affected source; the fact list still renders.
- **No fact sheet yet** (200 + null body, the normal state after creating a true-crime episode): `factSheet.empty`, generate enabled once a source is `fetched`, `save`/`approve` disabled; the store must not treat the null body as a failed load and must not clear the sources list.
- **Empty states**: no sources → `episodes.research.sources.empty` with the add form focused; sources but no sheet → `factSheet.empty`; sheet with zero facts → the panel warns and approve is refused (`fact_sheet_sources_insufficient`).
- **Hub reconnect** → `resync` refetches once (D8); the page never polls (D17).
- **Very long source text** is never rendered (only title/domain/chars), so no risk of rendering 300,000 characters.

## Notes

- **Reuse**: `CharCounter`, `StatusChip`, `EmptyState`, `ErrorState`, `LoadingState`, `PageHeader`, `ConfirmDialog`, `ConflictDialog`, `RetryCountdown` (D11); `AppErrorMapper` + `bindFieldErrors` (D9); `IdempotencyKeys` (10.2.3-T1); `visible-poll` is deliberately **not** used (D17); `SegmentChips` is not needed here (fact chips are source chips, a local component).
- **Performance**: two parallel GETs on entry; `@defer (on viewport)` for the fact panel; `@for … track source.id / fact.id`; a note counter is O(n) on ≤ 3,000 chars; no `computed` walks over all facts on every keystroke beyond the focused fact; refetches coalesced per 250 ms; no timers except `RetryCountdown` (`DestroyRef`, D13).
- **Security**: `If-Match` on the two writes, `Idempotency-Key` on generate; source titles/URLs and fact statements are untrusted and rendered by interpolation only (no `innerHTML`, no `bypassSecurityTrust*`); external links use `rel="noopener noreferrer" target="_blank"`; nothing persisted (memory store + `SESSION_SCOPED.reset()`, D6); no source URLs or fact text in logs, telemetry or the URL bar (D2/NFR-10-5).
- **a11y (D16)**: labelled inputs, status chips with icon + text, `aria-describedby` for field errors, `role="status"` for the gate and the saved indicator, delete buttons with `aria-label` (fact index / source domain), ≥ 24 px targets, contrast in both themes, keyboard-only flow add → edit → save → approve.
- **[OPEN] (07) — overlap chip threshold**: `FactItem.sourceOverlap` is a score (null when unscored, F2); the DTO does not carry the block threshold, so the chip is rendered whenever `sourceOverlap !== null` with the percentage in a tooltip and the copy `factSheet.overlapWarning`. A strict client-side gate would need the threshold in the DTO (02 CR) — recorded in `plan.md` §10 item 7.
- **[OPEN] (03) — source-fetch completion event**: the page relies on `EpisodeUpdated` + `resync` + the manual refresh. If 02.5.1 does not outbox an event when a fetch task finishes, the "pending" chip only changes on refresh; the copy stays neutral ("Refresh to update" is part of `episodes.research.refresh`) — recorded in `plan.md` §10 item 3.

### Angular implementation amendment (2026-10-02)

- Frame evidence is the `05-versions-research.html#f-research-*` family in `plan.md` §12; 200+null empty, fetch/access error, generating, conflict and gate-closed remain distinct.
- `research-page` is the routed container; source/fact rows are UI-only; the route-scoped store exposes immutable readonly arrays/models. Repository mappers preserve the nullable fact-sheet body, optional confidence, root field-error arrays, ETag/`If-Match` and `Retry-After`. Typed source/fact forms serialize through explicit command mappers rather than casts.
- Async source errors, fact-sheet patching and disabled controls use the zoneless form bridge; namespaced server errors preserve local validation and clear on edit/resubmit. Episode/session/request generations reject late parallel loads, stale hub refreshes and obsolete saves; all debounce/retry/defer work is destroyed. The current basic episode detail is not story/research readiness, so real acceptance waits for the named `02.5.*` owners.
