## Goal

The owner approves the reviewed script — or reopens an approved one — from the episode editor. Approve opens a confirm dialog that states what happens next (in P: the "edits need reopening" note; the credit line is an S-only slot per D14), and for a **true-crime** episode it renders the server-owned attestation text and requires an explicit tick before the confirm button enables. Reopen asks once and puts the episode back in `story_review`.

**`ApprovalStore`** (provided on the editor route next to the story store):

```ts
readonly attestation = computed<Attestation | null>(() => this.episode.currentStory()?.attestation ?? null);
readonly attestationAccepted = signal(false);
readonly approving = signal(false); readonly reopening = signal(false);
readonly error = signal<AppError | null>(null);
readonly canApprove = computed(() => this.storyStatus() === 'story_review' && (!this.attestation()?.required || this.attestationAccepted()));
readonly hintCount = computed(() => this.episode.currentStory()?.qualityHints.length ?? 0);   // advisory only
approve(episodeId: string): Promise<Result<void>>;   // body { accepted: true, textVersion } only when the block is rendered
reopen(episodeId: string): Promise<Result<void>>;
reset(): void;                                        // SESSION_SCOPED (D6)
```

`approve` sends `If-Match: currentStory.etag`; on 200 it writes the returned `{ status, currentStory }` into the episode store (status becomes `story_approved`), toggles the dialog closed and emits `episodes.approve.done` through the shell's snackbar/`aria-live`; it never mutates the local draft.

`reopen` sends the same `If-Match`; 200 `{ status, currentStory }` → status `story_review`, editor becomes editable again, snackbar `episodes.reopen.done`.

**`ApproveDialog` API** (inputs/outputs only for the presentational part, the store is injected by the container `EpisodeEditorComponent` — D2 forbids stores in `ui/`):

```ts
readonly attestation = input<Attestation | null>(null);
readonly hintCount = input<number>(0);
readonly busy = input<boolean>(false);
readonly blocked = input<AppError | null>(null);
readonly acceptedChange = output<boolean>();
readonly approved = output<void>();
readonly cancelled = output<void>();
```

Composition: `ConfirmDialog` with `cost-line` left **empty** (D14 — the S task 10.8.x fills it; a unit test asserts no credit/cost text is rendered), a body paragraph `episodes.approve.body`, an advisory line when `hintCount > 0` (quality hints never disable approve — C11), the `AttestationBlock` when `attestation?.required`, and a `blocked` region that renders the mapped `AppError` for the five gate 409 codes (`episode_invalid_state` / `story_fact_sheet_outdated` / `story_sources_required` / `story_too_similar_to_source` / `story_moderated`) plus `keywords_flagged` (below). The reopen path reuses `ConfirmDialog` with `episodes.reopen.*`.

**409 `keywords_flagged` (the sixth approve failure)**: the body is `{ code: "keywords_flagged", errors: [ { segment: "p:3", index: 1, rule: "keyword_name_detected" }, … ] }` with 02 D22 segment addresses (03.2.2-T2:29-32). This is **not** a `validation_failed` field-error map, so it does not go through `bindFieldErrors`; the store records only `blocked` and forwards the array once to the editor store — `editorStore.setKeywordFlags(error.problem?.errors ?? Approve is disabled **only** by the four WR6 conditions: a dirty/saving draft, a blocking moderation category in `auditReport.moderation`, an unmet true-crime precondition (attestation tick, `EPISODE_GATE`), or a present `keywordFlags` (server-enforced by 03.2.2-T2); `qualityHints` never disable it (C11). 02.3.4-T1's older line "the UI disables the approve button while a blocking hint is visible" is **superseded** (10 CR-11). ## Failure handling and edge cases

- **Two tabs**: A approves, B still shows `story_review` → B's approve gets 412 (stale ETag) → `ConflictDialog`; B's reopen on an already-reopened episode gets 409 → refetch, no message beyond the mapped one.
- **Approve while a save is in flight**: the editor's save must finish first — the approve button is disabled while `storyStore.saving()`; if a save lands after the dialog opened, the ETag in the request is re-read at call time (never a cached copy), so it is the freshest value.
- **Attestation text version changed** (an edit saved between opening the dialog and confirming) → 400 `story_attestation_required` → refetch + re-tick (no auto-retry, the user must re-confirm).
- **`attestation` absent/null** (non-true-crime, or a draft with no story) → no block; approve disabled when `currentStory` is null.
- **Reopen not applicable** (episode not `story_approved`) → the button is hidden; a stale tab that calls anyway gets 409 → refetch.
- **409 `keywords_flagged` while the episode was already reopened** (a stale tab approving after an edit): the flags come from the response and are forwarded to the editor store (WR6), not held locally, so the stale tab shows the current reasons and cannot approve until the server agrees.
- **429 `rate_limited`** → `RetryCountdown` from `Retry-After`, button disabled until 0.
- **428 `if_match_required`** = client bug → dev console warning, generic message (D9).
- **Network drop after sending approve** (response lost): the user retries; a second approve of an already-approved episode returns 409 → the UI refetches, shows `story_approved` and does not double-approve [INFERENCE: the API rejects the second call in the new state]; no client-side dedupe beyond the disabled button.
- **Long attestation text**: the dialog body scrolls; the confirm button stays reachable on a 360 px viewport.
