## Goal

On the research page, when the `source_finder` flag is on, the owner can ask the system to search for candidate links. The block shows the run state, lists candidates with their title and site, opens one in a new tab, and adds or dismisses it explicitly — **nothing is ever added automatically**. When the flag is off (or the API answers 404 `feature_disabled`) the block is invisible.

**`SourceFinderStore`** (provided by the research route):

```ts
readonly hasFeature = computed(() => this.session.hasFeature('source_finder'));
readonly candidates = signal<SourceCandidate[]>([]);
readonly generation = computed(() => this.episode.generation());
readonly running = computed(() => this.generation()?.kind === 'find_sources'
  && ['queued', 'running'].includes(this.generation()!.status));            // survives a page reload
readonly busyId = signal<string | null>(null);
readonly error = signal<AppError | null>(null);
readonly loading = signal(false);
readonly visible = computed(() => this.hasFeature());                        // hides on 404 feature_disabled too
find(episodeId: string, query?: string): Promise<Result<void>>;              // IdempotencyKeys.next('find_sources', episodeId)
load(episodeId: string): Promise<void>;                                      // GET candidates (only when visible)
add(episodeId: string, candidateId: string): Promise<Result<void>>;          // POST add → researchStore.load(episodeId)
dismiss(episodeId: string, candidateId: string): Promise<Result<void>>;      // POST dismiss → row status updated
reset(): void;
```

`find` sends `{ query }` only when non-empty (≤ 300 chars, mirroring the server validator for UX only); on 202 it keeps the minted key so a network retry of the *same* intent reuses it, and mints a new one after 422 `idempotency_key_reused`. On 404 `feature_disabled` it sets `visible=false`, refetches `GET /me` (D14/O1) and shows nothing — never an error.

**Panel states**: hidden (`visible() === false`) · idle ("Find sources" + optional focus field) · running (`sources.find.running`, driven by `EpisodeDetail.generation`) · results (rows: title or URL, site name, "Open" link, Add, Dismiss) · empty (`sources.find.empty`) · error (mapped `AppError`, `RetryCountdown` on 429).

Row behaviour follows 02.7 §6 literally: one **Add** and one **Dismiss** button per row, "Open" is an `<a>` with `rel="noopener noreferrer" target="_blank"`, and **no checkbox is pre-ticked** — the high-level wording "the user ticks the ones to add" is satisfied by the explicit per-row Add, which is the only contract the API offers (`POST …/candidates/{candidateId}/add`; there is no batch route) [DECISION]. Adds are issued one at a time (a single click = a single request); on a per-row failure the error shows on that row and the others remain untouched.

**Copy keys** — `sources.find.button`, `sources.find.running`, `sources.find.empty`, `sources.find.note`, `error.find_sources_in_progress`, `error.find_sources_generation_failed` are used **verbatim** from 02.7 §6 (vi/en pairs in `plan.md` §6); new keys: `sources.find.title`, `sources.find.queryLabel`, `sources.find.queryPlaceholder`, `sources.find.add`, `sources.find.dismiss`, `sources.find.open`, `sources.find.added`, `sources.find.dismissed`, `sources.find.refresh`, `sources.find.run`; the two error keys are additionally registered in the D9 shape (`errors.find_sources_in_progress`, `errors.find_sources_generation_failed`) with identical text (⚠️ shape discrepancy recorded in `plan.md` §10 item 2).

## Steps

1. Model + port + `HttpSourceFinderRepository`: `find` (202, `Location` ignored), `candidates`, `add` (201), `dismiss` (204); `AppErrorMapper` on all failures; no URL/title logging.
2. Fake repository + `SourceFinderStore` + store tests (flag off, 202 → running, 409, 422 re-key, 404 mid-session, add/dismiss, refresh on `EpisodeUpdated`).
3. `SourceFinderPanel` + mounting into the research page (below the sources list, above the fact sheet); the run state also shows in the sources list area as `sources.find.running` so a reloaded page is coherent.
4. Realtime: subscribe `EpisodeUpdated` for this episode + `resync`; refetch candidates when the `find_sources` run transitions to a terminal state (or on any event for this episode, coalesced within 250 ms). **No polling** (D17).
5. Error routing: 409 `find_sources_in_progress` → the running copy and the button disabled; 404 `feature_disabled` → hide + `/me` refetch; 429 `spend_cap_reached` → banner without any amount (D14) and `RetryCountdown` when `Retry-After` exists; 429 `source_fetch_limit_reached` on add → `RetryCountdown` + the 02.5.1 copy; 409 `source_duplicate` / `source_limit_reached` / `source_candidate_not_proposed` → per-row mapped messages.
6. i18n keys in both scopes and both languages; e2e spec.
7. Empty/legacy `features` array (10 CR-10 not yet merged): `hasFeature` returns false → the block stays hidden with no error (see Notes).

## Acceptance checks

- [ ] With the flag on, the research page shows the block; with the flag off (or `features` absent) the block is absent and **no** request to `/sources/find` or `/sources/candidates` is made.
- [ ] "Find sources" sends `POST …/sources/find` with an `Idempotency-Key` header (and `{ query }` only when the focus field is filled, ≤ 300 chars); the state becomes `sources.find.running`; the button is disabled while a run is active.
- [ ] After the run finishes, candidates render in the order returned, each with title (or URL when the title is null), site name, an "Open" link that opens a new tab with `rel="noopener noreferrer"`, and Add / Dismiss buttons; `sources.find.note` states they are suggestions only.
- [ ] **No** checkbox or row is pre-selected and no candidate is ever added without an explicit click on that row's Add.
- [ ] Add calls `POST …/candidates/{id}/add` once and the new source appears in the sources list above (a research-store reload follows the 201); a 409 `source_duplicate` shows on that row and points out that the link is already in the list.
- [ ] Dismiss calls `POST …/candidates/{id}/dismiss` and the row becomes dismissed (or disappears) without touching the sources list.
- [ ] Zero candidates after a successful run shows `sources.find.empty` (a run with no results is not an error).
- [ ] A second run request while one is active (e.g. from another tab) shows `error.find_sources_in_progress` and does not double-run.
- [ ] 404 `feature_disabled` mid-session hides the block and refetches `GET /me` without showing an error; a 429 `spend_cap_reached` shows a banner with **no** credit, price or balance numbers (D14).
- [ ] A reload during a run still shows "Searching…" (the state comes from `EpisodeDetail.generation.kind = 'find_sources'`), and the candidate list refreshes on `EpisodeUpdated`/`resync` without polling.
- [ ] Both languages render; axe clean with the block visible and visible; keyboard-only flow run → open → add → dismiss works and each row's buttons are labelled.

## Tests

- **Vitest store** (`source-finder.store.spec.ts`, fake repository): `hasFeature` false → `visible` false and no repository call; 202 → key sent once and `running` true from the episode generation signal; network failure on `find` → the same key is reused on the retry; 422 → the next attempt sends a **different** key (fake asserts inequality); 409 `find_sources_in_progress`; 404 `feature_disabled` → `visible` false + `/me` refetch requested (session fake); `load` maps candidates and preserves server order; `add` success → research-store reload requested; `dismiss` success → row status `dismissed`; 429 exposes `retryAfterSec`; `EpisodeUpdated` coalescing (2 events within 250 ms → 1 candidate refetch); `reset()` clears candidates, `error`, `busyId`.
- **Vitest component**: `SourceFinderPanel` (hidden when the flag is off — no DOM; running copy; rows with title/site/open/Add/Dismiss; no pre-ticked control in the template; per-row busy state; empty state; error rendering).
- **Playwright** `web/e2e/episodes-find-sources.spec.ts` (owner project, per-file UI login, D15/F08): flag on → run → wait for results → assert the suggestions-only note and that the source list is unchanged until Add is clicked → Add one (appears in the sources list) → Dismiss one (does not); flag off (env/config variant) → the block is absent and no finder request is issued; axe on both states.
- No test asserts incidental copy or the internal idempotency key format; assertions are on request shape, mapped keys and observable row state.

## Failure handling and edge cases

- **Run started in another tab** → own `find` gets 409 → copy + the block stays in the running state (`generation.kind`).
- **Run finishes with 0 candidates** (`Ok` with no results, 02.7 §7) → `sources.find.empty`, no error, no retry loop.
- **`find_sources_generation_failed`** (a job outcome, 02.7 §7) → `error.find_sources_generation_failed` (and its `errors.*` twin) with a retry action; the button re-enables after a fresh idempotency key.
- **Candidate of another episode / unknown id** → 404 on that row only; the list reloads.
- **`source_candidate_not_proposed`** (already added or dismissed elsewhere) → the row refreshes to the server state instead of erroring twice.
- **Add while the episode is at the 10-source cap** → 409 `source_limit_reached` on the row + a pointer to the sources list; no retry loop.
- **Add while the 24 h url-source cap is reached** → 429 `source_fetch_limit_reached` + `RetryCountdown` (the same rule as 02.5.1).
- **`features` missing from `GET /me`** (10 CR-10 not merged yet) → treated as flag off; the block is hidden and the page is fully usable without it. Recorded as `plan.md` §10 item 4.
- **Slow or stuck run** → no polling and no client timeout in P; the state is the episode's `generation`, so a user who returns later sees the real state after the detail refetch.
- **URL in a candidate can be long** → displayed truncated with a `title` tooltip; the anchor target is the raw URL (Angular's URL sanitizer still applies).
- **Duplicate candidates between two runs** → the server dedupes against existing candidates and `story_sources` (02.7 §7); the UI just renders what it gets.

- **Performance**: at most one `find` request per user click, one `candidates` GET per run completion (coalesced 250 ms), no polling, no timers except `RetryCountdown` (`DestroyRef`, D13); `@for … track candidate.id`; the candidate list renders behind `@defer (on viewport)`, and the panel is behind the already-lazy research route (`loadComponent`), so the initial bundle is unchanged.
- **Security**: the run is started with an `Idempotency-Key` (no accidental double spend); candidate URLs and titles are untrusted third-party content rendered by interpolation only (no `innerHTML`); external links use `rel="noopener noreferrer" target="_blank"`; no candidate URL or title in logs, telemetry or the URL bar; no credit/price text (D14); the block hides itself on 404 `feature_disabled` instead of exposing a broken action.
- **a11y (D16)**: the block is a labelled `<section aria-labelledby>`; the run state is `aria-live="polite"`; per-row Add/Dismiss carry accessible names including the site name (e.g. "Add suggestion from vnexpress.net"); the "Open" link announces that it opens a new tab; `busyId` disables only that row's buttons while keeping focus; suggestions-only note is plain text, not a colour cue.
