## Goal

While a render runs (or has just failed) the owner sees exactly where the work is: the three **guaranteed** stages `queued → running → ingesting` with `percent` as a progress bar, the **finer** node sub-step under Rendering when the adapter reports one, how long it has been running, a distinct "waiting for a free studio slot" state instead of a false error while the job sits queued, and — if the render failed — the failure in the owner's language with the scenes the image pipeline dropped or blocked and the action that fixes them. The view is the `rendering` (and failed) branch of the existing `/episodes/:id` page; leaving the page is safe and coming back re-derives everything from one `GET /episodes/{id}` plus the live `RenderProgress` signal.

## Design

All paths are `web/src/app/features/episodes/`.

```ts
// domain/render.model.ts  (this task owns the render half of the file)
export type RenderStatus = 'queued' | 'submitted' | 'running' | 'ingesting' | 'succeeded' | 'failed' | 'cancelled';
export type GuaranteedStage = 'queued' | 'running' | 'ingesting';
export type SubStage = 'voice' | 'subtitles' | 'images' | 'assembling' | 'checking';
export interface RenderJob {
  renderJobId: string; status: RenderStatus; stage: string;        // stored verbatim; unknown values are never rendered raw
  percent: number; attempt: number; imagesNeeded: number;
  submittedAt: string | null; finishedAt: string | null;
  errorCode: string | null; hints: readonly string[]; images: RenderImages | null;
}
export interface RenderImages { needed: number; succeeded: number; skipped: readonly SkippedScene[]; }
export interface SkippedScene { segment: string; reason: string; }
export interface RenderTimelineStep { key: GuaranteedStage; state: 'done' | 'active' | 'todo' | 'failed'; percent: number | null; subStepKey: SubStage | null; }
export interface RenderFailure { code: string; scenes: readonly SkippedScene[]; detailCode: string | null; }
```

```ts
// application/render-stage.ts   — THE single stage mapping (pure, no Angular import)
export const GUARANTEED: readonly GuaranteedStage[] = ['queued', 'running', 'ingesting'];
export const SUB_STAGES: readonly SubStage[] = ['voice', 'subtitles', 'images', 'assembling', 'checking'];
export function isGuaranteedStage(v: string): v is GuaranteedStage;
export function isSubStage(v: string): v is SubStage;
export function clampPercent(v: number | null | undefined): number;          // NaN/undefined → 0, −5 → 0, 250 → 100
export function subStepKeyOf(stage: string): SubStage | null;                // '' / 'queued ' / 'RENDERING' / 'v2' → null
export function renderTimeline(job: Pick<RenderJob, 'status' | 'stage' | 'percent' | 'errorCode'>): RenderTimelineStep[];
// renderTimeline: `ingesting` marks queued+running done; a `failed` job marks the stage it reached as 'failed' and later stages 'todo';
// `succeeded` marks queued/running/ingesting done; `cancelled` marks the reached stage 'todo' (never 'failed' — render_cancelled is a state, 05 README:228-242).

// application/render-failure.ts — pure copy resolution (never prose from the server)
export interface FailureCopy { titleKey: string; bodyKeys: readonly string[]; actionKeys: readonly FailureAction[]; }
export type FailureAction = 'editScenes' | 'retry';
export function failureCopy(code: string, scenes: readonly SkippedScene[]): FailureCopy;
```

`failureCopy` table (F7): every code → `render.failure.code.<code>` when a key exists for it (`images_incomplete`, `provider_funds_exhausted`, `upstream_error`) plus the code's own `errors.<code>` title; `image_moderated` / `image_generation_failed` with a `moderated` scene → `editScenes`; `tts_failed`, `render_node_error`, `render_assembly_failed`, `render_lost`, `render_timeout`, `render_output_invalid`, `render_quality_failed` → `retry` when `nextActions` offers `retry_render`; an unknown code → generic title, **no** action. Scene addresses are only rendered when `segment-address.parse` succeeds.

```ts
// application/render-timeline.store.ts — `@Injectable()`, provided by the episode page (component `providers`, beside EpisodeDetailStore)
@Injectable()
export class RenderTimelineStore {
  private readonly detail = inject(EpisodeDetailStore);       // owns GET /episodes/{id}
  private readonly realtime = inject(RealtimeService);        // owns the RenderProgress map (WR7/D8)
  readonly now = signal(Date.now());                          // the 1 s tick (visibility-gated)
  readonly job = computed<RenderJob | null>(() => {           // detail wins for status/submittedAt/errorCode/images; live progress wins for stage/percent
    const detailJob = this.detail.episode()?.renderJob ?? null;
    if (!detailJob) return null;
    const live = this.realtime.progress().get(this.detail.episode()!.id);
    return live && live.renderJobId === detailJob.renderJobId       // a stale entry from an older job is ignored
      ? { ...detailJob, stage: live.stage, percent: live.percent }
      : detailJob;
  });
  readonly steps = computed(() => renderTimeline(this.job() ?? EMPTY_JOB));
  readonly percent = computed(() => clampPercent(this.job()?.percent));
  readonly subStepKey = computed(() => subStepKeyOf(this.job()?.stage ?? ''));
  readonly queuedSince = signal<number | null>(null);   // client-only, non-persisted: stamped when this store FIRST sees status='queued'
  readonly elapsedSec = computed(() => elapsedSeconds(this.job()?.submittedAt ?? this.queuedSince(), this.now()));
  readonly waitingForSlot = computed(() => this.job()?.status === 'queued' && !this.job()?.submittedAt && this.elapsedSec() >= 30);
  readonly failure = computed<RenderFailure | null>(() => this.job()?.errorCode
    ? { code: this.job()!.errorCode!, scenes: this.job()!.images?.skipped ?? [], detailCode: imageDetailCode(this.job()) } : null);
  readonly active = computed(() => ['queued', 'submitted', 'running', 'ingesting'].includes(this.job()?.status ?? ''));
  start(episodeId: string): void;   // subscribeEpisode(id, () => {}) FIRST, then detail.load(id) (never USER_ACTION), then arm the tick
  refresh(): void;                  // detail.refetch() (no USER_ACTION — WR11)
}
```

`start()` subscribes **before** the first read so no `RenderProgress` is lost between the read and the subscription (the 10.5.2-T1 discipline); the subscription and the tick are released through `takeUntilDestroyed(this.destroyRef)` — `destroyRef` resolves to the page component's injector because the store is component-provided, so it does fire on page destroy (it would not if the store lived in `Route.providers`). The tick is a `setInterval(1_000)` armed only while `active()` **and** `document.visibilityState === 'visible'` (a `visibilitychange` listener starts/stops it, D7/D13) and cleared at the first terminal status; there is **no** HTTP in the tick.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| `renderJob` is `null` on a `rendering` episode (a race between the status change and the job row) | The view renders `LoadingState` and calls `detail.refetch()` once via the event/`resync` path — never a fatal error, never a spinner forever: after the refetch the status is re-read, so a `story_approved` episode leaves the branch |
| Progress event arrives before the detail is loaded | The store merges on the next `computed` evaluation; the timeline renders from the detail alone until then, and no stage is invented |
| Progress event says `running` while the detail still says `queued` | Live progress wins for stage/percent (Design) — the server's own `queued` is shown until the first event |
| Detail says `ingesting` while the last progress event said `assembling` | Detail wins for `status`, so the stage list shows `ingesting` active and no sub-step (tested) |
| The job ends `failed` while the page shows a stale progress percent | The failure alert is rendered from `errorCode`; the bar is hidden once `failure()` is non-null so a completed-looking bar is never shown next to a failure |
| `Hints`/`images` absent (10 CR-12 / 03.4.2-T1 not merged, O-2) | `failureCopy` still resolves a title; the scene list is omitted with the generic body; no extra request is made and no client-side guess about scenes is attempted |
| The edit-scenes action is not provided (10.5.6-T1 not merged) | The scene list and `render.failure.editScenesHint` render, the button is absent (soft integration, the same pattern as 10.5.2-T1:73's optional `EPISODE_GATE`); the server stays the authority and a 409 from the editor flow is mapped by wave 1 |
| A `RenderProgress` for another episode | Ignored by the keyed map; the store also guards on `renderJobId` |
| A hidden tab while rendering | The tick stops; the hub itself follows D7 (pause + `realtime.paused` bar) and `resync` refetches on return, so the displayed stage/percent are reconciled within 250 ms of the tab becoming visible |
| A stale tab whose job already finished | The next `EpisodeUpdated`/`resync` refetch replaces the view; a manual reload re-derives everything from one `GET /episodes/{id}` |
| Cancelled job | The status is `cancelled` and the episode returns to `story_approved` (F2); `render_cancelled` is **never** rendered as an error title (05 README:228-242) |
| Rollback | Delete the `@case` branch + the task's files; the wave-1 editor page and the server state are untouched (no migration, no route) |

## Notes

- **Reuse (D11/WR4):** `EpisodeDetailStore` (10.5.3-T1/10.5.2-T1) is the only owner of `GET /episodes/{id}` — this task never calls it directly; `RealtimeService` (10.2.4-T1) is the only owner of the socket and of the progress map; `LoadingState`/`ErrorState`/`EmptyState`/`StatusChip`/icon components (10.1.3-T1); `AppErrorMapper` + `RetryCountdown` (10.2.2-T1); `segment-address` (10.5.3-T1). Nothing in `render-stage.ts`/`render-failure.ts` is duplicated in a component: the lists live only there.
- **`queuedSince` is a client-side elapsed baseline only** (never sent anywhere, never persisted, discarded with the store): `submittedAt` is `null` exactly while the job waits for a node, so without it the waiting state could never reach its 30 s threshold and the timeline would show no elapsed time during the wait (WB2/WD2).
- **Performance:** one signal read per rendered region (`OnPush` + signals, no `subscribe()` in a component); the progress bar is the only element that changes per event; the tick runs at 1 Hz only while a job is active **and** the tab is visible; `@for` tracks `step.key` (three items) and the scene list tracks `segment`. No refetch on a progress event, no timers without `DestroyRef`, no polling added beyond D17.
- **Security:** the scene list, stage names and failure codes are our own i18n keys rendered by interpolation; the server's `detail` is never displayed (F20/D9); no content from `renderJob.params` is read or shown (never content-bearing, 09.6.1-T1:202); nothing is persisted; the view adds no script and no CSP/TT allowance.
- **a11y (D16):** labelled progressbar with an `aria-valuetext` stage name; `aria-current="step"` on the active stage; status changes announced once per stage through one polite live region; the waiting state is text, not colour; every failure is an alert with a heading and text-paired icons; 360 px layout without horizontal scroll; `prefers-reduced-motion` disables any bar animation.
- **Soft edges (recorded, not silently assumed):** 03.4.2-T1 (`images`) and 10 CR-12 (`errorCode`/`hints`) are soft — the acceptance run needs the real fields, the component/store tests use the contract-true fake (O-2).
