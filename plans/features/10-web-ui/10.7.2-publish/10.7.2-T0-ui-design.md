## Goal

Produce the approved UI design for every screen and state this folder ships: the publish panel and consent step on the episode page, the publication status widgets, and the two veto-email landing pages (`/publications/cancel` public, `/publications/approve` owner). The deliverable is a design link recorded in `plan.md` §6 plus the owner's approval record; it is a **hard gate** — no implementation task in this folder starts before it (D19, owner rule 2026-09-25, `../README.md` §10 O5; wave 2 equivalent WD11).

## Inputs

- `plan.md` §6 (screen × state inventory, copy keys, a11y) — the authoritative list this design must cover row by row; §2 facts and the CR/`[OPEN]` items that change a screen.
- `../README.md` D11 (Angular Material M3, dark default + light option, tokens once in `shared/ui/theme/`, Be Vietnam Pro self-hosted weights 400/500/600, subsets latin + latin-ext + vietnamese) and D16 (a11y baseline); D13 (OnPush, `@defer` for heavy parts); D9 (`errors.<code>` copy) where the folder shows failures.
- The theme + UI kit must exist first: **10.1.3-T1** owns the shared components below and the icon components (WR4). This design never invents a second component set.
- - Screens: §6.1 publish panel (episode page, `ready`), §6.2 publication status (episode page + dashboard row), §6.3 `/publications/cancel` (public, fragment token), §6.4 `/publications/approve` (authenticated, fragment `#p=&e=`).
- Contract: `POST /episodes/{id}/publications` → `PublicationDto` (+ `preAudit`, `requestedPrivacy`); `POST /publications/{id}/consent { consentTextVersion }` + `If-Match "pu-<xmin>"`; `GET /publishing/youtube/eta` → `{ available, nextSlotAt }`; `POST /publications/cancel-by-link { publicationId, token }`; consent text `pc.v1` vi/en served by the API and sent back as displayed.
- Copy: new scope `publishing` (`web/src/assets/i18n/publishing/{vi,en}.json`), including `publication.error.<code>` for `publication_invalid_state`, `publication_conflict`, `consent_text_outdated`, `cancel_token_invalid`, `channel_not_active`, `episode_invalid_state`, `feature_disabled`.

## Design

Artifacts in the project design tool (Figma or equivalent), one page per screen, plus a screen × state matrix page:

- Screen count: 4 screens (publish panel, status widgets, cancel page, approve page) → **M (1.0)** per the rule.

Annotations required per screen: breakpoints **360 / 768 / 1280**; both themes (dark default + light); vi + en copy at real lengths (vi is default, D10); focus order and the full keyboard path; `aria-live` regions and what they announce and when; target size >= 24 px; contrast pairs >= 4.5:1 text and >= 3:1 focus ring in both themes; `prefers-reduced-motion` behaviour; the D11 components and tokens used.

| Screen | States to design |
|---|---|
| §6.1 publish panel | loading · no-channel (connect CTA) · existing publication (status view) · form (empty, field errors, byte counter at limit) · consent (`pc.v1` text, version line) · quota_wait (`nextSlotAt` + zone) · done · hidden (flag off) · error (network) |

## Steps

1. Confirm 10.1.3-T1's theme, tokens and UI kit exist; open the design library from it.
2. Draft lo-fi wireframes for every screen above in all of its state families, then walk the folder's use cases (`plan.md` §4) on the wireframes.
3. Build hi-fi mockups from the D11 tokens/components at 360/768/1280, dark + light, vi + en.
4. Annotate focus order, keyboard path, `aria-live` regions, target sizes, contrast, reduced-motion behaviour and the loading/empty/error/success affordances per state.
5. Fill the screen × state matrix: one row per screen, one column per state family, each cell linked to a frame; mark "n/a" with a reason where a state cannot exist.
6. Write the design link and the matrix into `plan.md` §6 (the `Design (owner rule 2026-09-25)` paragraph) and record the approval.
7. Present to the owner; record approval (name + date + link) in `plan.md` §6 and in `## Outputs` below.
- Privacy group is a real `radiogroup` with a legend; it is **disabled while `preAudit`** and the reason is text, never a tooltip.
- Description `CharCounter` is byte-based (5,000 UTF-8 bytes) and announces only on blur / at the limit; every field error is linked with `aria-describedby` and focus moves to the error summary on a failed submit.
- The consent text block is focusable and keyboard-scrollable; the step indicator announces the step change; the quota wait is a polite status region updated once per state change, not per tick.
- The cancel page has a single `h1` and one primary button; its result is `role="status" aria-live="assertive"`, focus moves to the result heading, and there is no auto-focus on a destructive control.
- Approval is never disabled by `vetoEndsAt` (F10); the approve page shows the preview plus the same scrollable consent block as §6.1.
- Every schedule/ETA value is labelled with its zone (`America/Los_Angeles` for quota, browser zone for user input).

## Acceptance checks

- **Given** the design file, **When** the reviewer walks the folder's routes/screens in `plan.md` §6, **Then** every screen and every state named there has a frame at 360, 768 and 1280.
- **Given** the mockups, **When** checked, **Then** each screen exists in dark **and** light and in vi **and** en with real-length copy (longest vi string included).
- **Given** the matrix, **When** checked, **Then** loading / empty / error / success (plus the folder's special states listed above) each link to a frame, and every "n/a" carries a reason.
- **Given** the annotations, **When** checked, **Then** focus order, keyboard path, `aria-live` regions, target sizes, contrast pairs and `prefers-reduced-motion` are recorded per screen.
- **Given** the design, **When** audited, **Then** it uses only D11 tokens/components and requests no third-party asset (D4/D12).
- **Given** approval is absent, **When** any implementation task in this folder is attempted, **Then** it is blocked (hard dependency, `Depends on` = 10.7.2-T0).

## Tests

No code tests (design task). Verification is the checklist above plus:
- a frame-per-row coverage check against the `plan.md` §6 inventory;
- a breakpoint × theme × language matrix check on every row;
- a token/component conformance check against the 10.1.3-T1 UI kit;
- a focus-order walk-through on the hi-fi frames (annotations, not a build).

## Failure handling and edge cases

| Case | Handling |
|---|---|
| 10.1.3-T1 theme/kit not ready | Design waits (hard dependency); never invent a parallel component set |
| An upstream contract in the folder's `[OPEN]`/CR list changes a screen (e.g. a new `error_code` or field) | Re-annotate that screen and re-approve; the implementing task keeps its own `[OPEN]` fallback |
| Owner requests changes | Re-approve and update the link + record; implementation stays blocked until then |
| A state cannot exist for a screen (e.g. no server call in a prerendered page) | Record "n/a" with the reason in the matrix rather than inventing a frame |
| Copy is not final in one language | Design with real-length vi/en text; placeholders only for text another plan owns (legal, consent, pricing) |
| Scope creep into a peer folder's screen | Stop at this folder's screens; the peer folder has its own `-T0` |
