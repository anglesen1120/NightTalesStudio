## Goal

On a `ready` episode the owner publishes the approved video to their YouTube channel without leaving the Studio: a form with the YouTube metadata (title, description with a live UTF-8 byte counter, tags, visibility, optional schedule, read-only synthetic-content declaration), a validation pass that mirrors the server's `YouTubeMetadataRules` in one client implementation, then a **consent step** showing the `pc.v1` text the API will check (version sent = version displayed), then — when the daily quota is spent — a wait state driven by `GET /publishing/youtube/eta` that says when the upload will actually happen. Under the hood the flow is one signal store with explicit steps (`form → consent → quota_wait → done`), one repository port, and a single-flight submit that recovers a lost response through `409 publication_invalid_state` + refetch. The form is the entry point of the whole 10.7 publishing story (10.7.4-T1 renders what it creates). Owner value: no silent quota failures, no mismatched consent text, no half-created duplicate publications.

## Design

**Files produced** (all under `web/src/app/features/publishing/`, WD1/D2).

1. `domain/publication-detail.model.ts` — **no duplicate `Publication` (D2/WR4)**: re-export `PublicationStatus` from `@features/series` (one union only — F17) and **extend** wave-1's `Publication` with the fields the wave-2 wire carries and wave 1 lacks, plus `QuotaEta`, `ConsentText`, `CreatePublicationInput`, `PublishPrivacy`, `TERMINAL` and the pure helpers `canCancel` (`awaiting_consent|scheduled`, 06.2.6-T1:30), `canApprove`, `quotaWait`, `studioUrl` (plan §3.1; the local extension is CR-W7's subject). No token, no `platform_payload` key, no authorization id ever reaches a model (F4).
2. `domain/youtube-metadata-rules.ts` — the single client mirror of the server rules (WD6):
   ```ts
   export const PUBLISH_LEAD_MINUTES = 120;                 // O-W9: source of truth is YouTube:PublishLeadMinutes (06 D11)
   export const TITLE_MAX = 100, DESCRIPTION_MAX_BYTES = 5_000,
                TAGS_MAX = 15, TAG_MAX = 30, TAGS_LENGTH_MAX = 500;
   export function utf8Bytes(value: string): number;        // TextEncoder, NFC first (same rule as D18's token count)
   export function validateMetadata(value: CreatePublicationInput,
     ctx: { preAudit: boolean; now: Date }): { fieldErrors: Record<string, string>; scheduleAllowed: boolean };
   ```
   `scheduleAllowed = !ctx.preAudit && value.privacy === 'public'` — a **client-side rule of the manual form only** (WD6; CR-W4 withdrawn by TL ruling 2026-09-25): the server keeps accepting `publishAt` with non-public privacy because autopilot pre-audit rows carry `publish_at = slot` (06 YR2/YR20, `06.2.4-T1-lead-time-publish-at-pre-audit.md:121`), and its own validation (`YouTubeMetadataRules` at create, `PlanUpload` at upload) is the backstop. When `scheduleAllowed` is false the control is disabled **and** `validateMetadata` reports the field error `publishAt`, so a stale form cannot POST a schedule the upload job would drop (`private`) or fail on (`unlisted`). `fieldErrors` keys are the server's (`title`, `description`, `tags`, `privacy`, `publishAt`) so `bindFieldErrors` maps both sources identically.
3. `domain/publishing.repository.ts` — the new port holds **only the four calls wave 1 does not have** (`create`, `cancelByLink`, `consentText`, `quotaEta`; plan §3.2); `listForEpisode`/`consent`/`cancel` are wave-1's `PublicationRepository` (`@features/series`, `10.4-series-autopilot/plan.md:166-172`) and are injected here for the list, the duplicate-create recovery and the consent call (10 CR-20 already landed `consent(id, ifMatch, consentTextVersion)`/`cancel(id, ifMatch)` on it, `10.4-series-autopilot/plan.md:191-192`). `cancelByLink` lives in this port so 10.7.4-T2 reuses one HTTP layer; it is never reachable from an authenticated-only page (WD10).
4. `data-access/publishing.http-repository.ts` — implements the four new calls over the generated `@shared/api` client (the only file importing it, D2): `create` reads the 201 `ETag` header with `readEtag`, `cancelByLink` posts the token body, `consentText`/`quotaEta` are plain reads; pure `mapPublication`/`mapQuotaEta`/`mapConsentText`; unknown `errorCode` values fall back to `errors.unknown_error` (D9). `consent`/`cancel` are **not** here — they are wave-1's `PublicationRepository` with 10 CR-20's signatures. A 404 `feature_disabled` becomes an `AppError` with that code and no retry (D14).
5. `tests`-facing fake: `testing/fake-publishing.repository.ts` — hand-written (D15): settable rows/ETA, canned `AppError`s (`validation_failed` with `fieldErrors`, `publication_invalid_state`, `consent_text_outdated`, `publication_conflict`, `channel_not_active`, `feature_disabled`, `rate_limited`), an `If-Match` recorder, and a call log so tests assert the ETag and the consent version actually sent.
6. `application/publish-form.store.ts` — `PublishFormStore` (provided by the panel component):
   ```ts
   readonly episodeId = signal<string | null>(null);
   readonly step = signal<'form' | 'consent' | 'quota_wait' | 'done'>('form');
   readonly publications = signal<readonly PublicationDetail[]>([]);
   readonly channels = signal<readonly Channel[]>([]);        // 10.7.1-T1's Channel model
   readonly eta = signal<QuotaEta | null>(null);
   readonly created = signal<{ publication: PublicationDetail; etag: string } | null>(null);
   readonly consentText = signal<ConsentText | null>(null);
   readonly submitting = signal(false); readonly etaLoading = signal(false);
   readonly error = signal<AppError | null>(null);
   readonly fieldErrors = signal<Record<string, string>>({});
   readonly conflictOpen = signal(false); readonly hidden = signal(false);
   readonly activeChannel = computed(() => this.channels().find(c => c.status === 'active') ?? null);
   readonly quotaBlocked = computed(() => quotaWait(this.eta()));
   readonly existing = computed(() => this.publications().find(p => !TERMINAL.includes(p.status)) ?? null);
   readonly scheduleAllowed = computed(() => !!this.created() === false && /* form-time gate, see validateMetadata */ true);
   open(episodeId: string): Promise<void>;        // parallel: publications + eta + channels (Promise.all)
   refreshEta(): Promise<void>;
   submit(value: CreatePublicationInput): Promise<void>;   // USER_ACTION; single-flight
   loadConsentText(locale: 'vi' | 'en'): Promise<void>;
   confirmConsent(): Promise<void>;                        // USER_ACTION; If-Match = created().etag
   recoverFrom409(): Promise<void>;                        // refetch → adopt the awaiting_consent row
   backToForm(): void; reset(): void;
   subscribe(): void; unsubscribe(): void;                 // subscribeEpisode via DestroyRef (D8/D13)
   ```
   `open()` runs the three reads with `Promise.all` (WD9: per-episode, no N+1); an ETA failure degrades to `eta = null` (the form stays usable, the quota wait is simply not shown) while a publications failure is a real error. `submit()` sets `USER_ACTION` (WR11), disables the button while `submitting` (no `Idempotency-Key` exists on the route, F1) and on success stores `{ publication, etag }` from the 201 body/header and moves to `consent`. `confirmConsent()` sends `{ consentTextVersion: consentText().version }` with `If-Match: created().etag`, and moves to `quota_wait` when the returned row is `scheduled` with `errorCode === 'youtube_quota_exhausted'` (F15), otherwise to `done`. `confirmConsent()` on an already-`scheduled` row is a 200 no-op (F7) and is treated as success. `subscribe()` refreshes the row list on `PublicationUpdated` for this episode and abandons a stale `quota_wait` when the row leaves `awaiting_consent`.
7. `application/publish-panel.component.ts` (+ `ui/` templates) — `PublishPanelComponent`, selector `nts-publish-panel`, `input.required<string>('episodeId')`, `output<void>('published')` (emitted on `done` so the episode page can react); a typed Reactive Form (D13) with `track`-free `@if` branches per step; `OnPush`; no store is injected by any `ui/` component (D2). It renders the channel pick (single `active` channel auto-selected; none → connect CTA to `/channels`), the metadata form, the consent step (`pc.v1` text as **preformatted text**, plan §8/O-W6), the quota-wait panel, and the error surfaces.
8. `index.ts` re-export of the models/port above (the feature barrel exists from 10.7.1-T1; this task appends its exports).

**Routes.** No new route: the panel is rendered on the episode page by 10.7.4-T1's additive `@case` branches (`features/episodes/feature/story-review.page.ts`, WT-W10). The only route this task needs is 10.7.1-T1's `/channels` for the connect CTA.

**i18n** (scope `publishing`, D10): the `publication.create.*`, `publication.consent.*`, `publishing.quota.*`, `publishing.eta.estimated` and `publication.error.<code>` keys of `plan.md` §6.1 with both `vi` and `en` values in `web/src/assets/i18n/publishing/{vi,en}.json`; the `pc.v1` text itself is never in the catalogue (it comes from the API). Time values go through `Intl` for `vi-VN`/`en-US` and always carry a zone label (`America/Los_Angeles` for the quota reset).

**Security (WD10).** No token in this task's flows (the cancel token is 10.7.4-T2's); the consent text is bound as text (no `innerHTML`, no `bypassSecurityTrust*`, D2/D4); nothing about a publication is written to `localStorage`/`sessionStorage` (D6); the OAuth navigation is not here (10.7.1-T1); no third-party script; the client logs ids and codes only.

**A11y (D16, plan §6.1).** Labelled controls, `CharCounter` linked with `aria-describedby`, a fieldset/`role="radiogroup"` for privacy, the schedule hint in `aria-describedby`, `FormErrorAlert` + focus move on a failed submit, the quota-wait block as `role="status"` `aria-live="polite"` (one announcement per state change, never per tick), the consent text block keyboard-scrollable with `aria-labelledby`, ≥ 24 px targets, 360 px layout, reduced-motion honoured, no information by colour alone.

**Performance (WD9).** One `GET /episodes/{id}/publications` + one ETA + one `GET /channels` per open (`Promise.all`); the consent text is fetched once per consent step and cached in the store; the panel is part of the lazily loaded `publishing` chunk; **no timer at all** — state changes arrive through `RealtimeService.subscribeEpisode`/`resync` and through the action that just ran (plan §7; TL ruling: D17's `visible-poll` stays the autopilot run log's).

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Lost response after a successful create | retry → `409 publication_invalid_state` → `recoverFrom409()` adopts the existing row and continues at the consent step (F5) — the form never creates a second publication (partial unique `(episode_id, platform)`, F5) |
| Two tabs submit at once | the second gets 409 and adopts; the first owns the consent step (no optimistic state anywhere) |
| `400 consent_text_outdated` right after a deploy changed `pc.v1` | text is reloaded and shown again; the user must confirm once more; the version sent always equals the version displayed (WC9) |
| ETA endpoint down / flag off | `eta = null` → no quota block; the form still submits and the server decides; a `429`/quota reply from consent falls back to `quota_wait` with `nextAttemptAt` |
| `available = 0` while the user is filling the form | the wait is informational until submit; the submit then goes through the consent step and ends in `quota_wait` (the server is the authority, the ETA only explains) |
| `publishAt` in the past (clock skew) | validation error on the field (F13); the server's catch-up branch is never reached from this form |
| `preAudit` row | privacy is disabled and shown as `private`, `requestedPrivacy` is displayed as the owner's original ask, the schedule is disabled, `publication.create.preAuditBanner` explains why (F14) |
| No active channel / connection revoked between open and submit | connect CTA before submit; `409 channel_not_active` after it |
| `429 rate_limited` on any write | `RetryCountdown` from `Retry-After`; the action stays disabled until zero (D9) |
| Network error | `network_error` copy + retry, the form keeps its values in memory (nothing is persisted, D6) |
| Session ends mid-flow (401, refresh failure) | the interceptor ends the session (D6/WR9); the panel's state is discarded with the route; nothing publication-specific is cached |
