## Goal

Ship the R2 composer at `/episodes/:id/publish/tiktok`: the caption is the publication `title` (≤ 2200 UTF-16 code units with a live counter), every option comes from the creator info (`privacy = SELF_ONLY` is the only privacy, interactions forced off where the creator info says so, the persistent "private until the TikTok audit passes" notice), the disclosure variant (`music`/`branded`) fetches and displays the server's consent text **before** the Post button, creating the publication goes to `POST /episodes/{id}/publications` with `description`/`tags`/`publishAt` null and the `tiktok{…}` settings object, consent is `POST /publications/{id}/consent { consentTextVersion }` + `If-Match`, and the upload status is followed through `PublicationUpdated` → refetch. **The browser uploads nothing and shows no progress UI** — 07 transfers with `PULL_FROM_URL` (FC13/K7). Design: `10.7.3-T0` + the connection surface of `10.7.3-T1` (both hard dependencies).

**Route.** `/episodes/:id/publish/tiktok` (SD1 `:654`, SD10 `:673`), registered in `publishing.routes.ts` as a **child of the existing `/episodes/:id` route** so the wave-1 `EpisodeDetailStore` provider (`10.5.1-episodes-editor/plan.md:212`) is inherited and the episode is **not** fetched twice — route entry: `{ path: 'publish/tiktok', canMatch: [tiktokEnabledGuard], loadComponent: () => import('./feature/tiktok-composer.page').then(m => m.TikTokComposerPage), data: { titleKey: 'tiktok.composer.title' } }`. Registering the child requires one additive line in the episodes route tree (outside this folder) — recorded as the task's single cross-folder edit, owner notified (WT-W10 precedent) and flagged as `plan.md` §10 [OPEN] 5; the documented fallback if the TL forbids it is 10.7.2-T1's mount pattern (an additive `@case` branch on `features/episodes/feature/story-review.page.ts`) with this route redirecting to the episode page. `tiktokEnabledGuard` comes from `10.7.3-T1`; an absent/empty `features[]` means the area is **off**.

**Composer store** (signals + `OnPush`/zoneless, D13; per `plan.md` §3):

```ts
readonly caption = signal('');                    // seeded once from EpisodeDetailStore.episode().title
readonly variant = signal<DisclosureVariant>('music');
readonly consent = signal<{ version: string; text: string } | null>(null);
readonly consentState = signal<'idle' | 'loading' | 'ready' | 'error'>('idle');
readonly settings = signal<TikTokPostSettings>({ disableComment: false, disableDuet: false,
  disableStitch: false, disclosureEnabled: false, brandOrganic: false, brandedContent: false });
readonly creator = signal<TikTokCreatorInfo | null>(null);
readonly submitState = signal<'idle' | 'submitting' | 'created' | 'consenting' | 'done'>('idle');
readonly publication = signal<PublicationDetail | null>(null);
readonly error = signal<AppError | null>(null); readonly fieldErrors = signal<FieldError[]>([]);
readonly validation = computed(() => validateTikTokPost(this.caption(), this.settings(), this.creator()));
readonly canSubmit = computed(() => this.validation().ok && this.submitState() === 'idle');
load(episodeId: string): Promise<Result<void>>;   // creator info + consent text (music) in parallel; adopts an existing row
setVariant(v: DisclosureVariant): Promise<Result<void>>;   // refetches the consent text (never reuses the other variant's)
submit(): Promise<Result<void>>;                  // create (Idempotency-Key) → consent (If-Match) → done
```

**Caption.** `title` **is** the caption (07 D8): seeded from the episode title, editable, `1…2200` UTF-16 code units counted with `text.length` semantics on the raw string (offset-based counter, `CharCounter`), never code points; `String.prototype.length` of an emoji-heavy sample is `2` per astral character. Over the limit → `validation().caption = 'tooLong'`, Post disabled and the counter turns into an `aria-live="polite"` error; `description`, `tags` and `publishAt` are sent **null** and no schedule/date control exists (07 D3).

**Options matrix (server-owned, 07 D5).** Rendered from `TikTokCreatorInfo`: `privacy` is displayed as a fixed, non-editable `SELF_ONLY` value with the persistent notice (`nts-tiktok-private-notice`, `role="note"`, referenced by `aria-describedby` from Post); `disableDuet`/`disableStitch` switches are `disabled` + checked with an explanation when `creator.duetDisabled`/`creator.stitchDisabled` are true; `disclosureEnabled = false` forces `brandOrganic = brandedContent = false` (the switches are disabled); `brandedContent = true` forces the `branded` variant and is impossible with `privacy = SELF_ONLY` for an unaudited client — the switch is **not offered** in R2 (privacy is always `SELF_ONLY`, FC13), so the R2 variant set is `music` for "no commercial / Your brand" and `branded` only when the client is audit-approved (`privacyLevelOptions` contains more than `SELF_ONLY`); a `privacyLevelOptions` list with a single `SELF_ONLY` renders the variant radios with `branded` disabled and the reason. `is_aigc` and `video_cover_timestamp_ms` are server concerns; no UI control exists for them.

**Consent flow (K5).** `setVariant(v)` → `GET /publications/consent-text?locale=<vi|en>&variant=<music|branded>` (`locale` = the current Transloco language, so the letter matches the account's `uiLocale`), rendered as **plain text** (`{{ }}`, never `[innerHTML]`) in a `<section aria-labelledby>`; `consentTextVersion` is taken from the response **verbatim** (`tt.v1.music` / `tt.v1.branded`) and is never constructed client-side. `submit()`: create (with the `Idempotency-Key` from `IdempotencyKeys.begin('tiktok.create')`) → `201 PublicationDto + ETag` → store `readEtag(response)` → `POST /publications/{id}/consent { consentTextVersion }` with `withIfMatch(etag)` → `204` → `submitState = 'done'` and the status panel mounts. `400 consent_text_outdated` → refetch the text for the current variant, clear the stored version, show `tiktok.consent.outdated`, and **require a new explicit click** (no auto-retry — the consent must be a fresh user act); `412` stale ETag → refetch the publication row and re-derive the ETag before retrying once; `409 publication_invalid_state` → refetch and render the row's real state instead of an error.

**No-upload rule (FC13, K7).** The task ships **no** file input, no uploader, no progress bar, no percentage, no chunk/resumable code. The created state states the truth: "TikTok downloads the video from our storage — you can close this page; the status below updates when it is published". An e2e negative assertion enforces the absence of any `input[type=file]` and of any `progress`/`role="progressbar"` element on the page.

**Status follow (K8).** `submitState = 'done'` mounts 10.7.4-T1's `<nts-publication-status [episodeId]="id">` unchanged; that component owns `PublicationsStore`, the `PublicationUpdated` subscription and the refetch of `GET /episodes/{id}/publications`, so this task adds no realtime code, no poll and no timer (SD16). A `tiktok_reauth_required` `error_code` or a `status = 'expired'` connection shows this task's reconnect card (shared with 10.7.3-T1's `nts-tiktok-connect-card`), whose `Reconnect` action re-runs the connect flow and then **refetches** the publication list; no retry loop, no auto-consent.

**Lost-response / double-submit (UC-T8).** The create route **requires** an `Idempotency-Key` (07.2.2-T1:20,50,89; missing → 400 `idempotency_key_required`), so the store keeps the key while the outcome is unknown (network error, 5xx, timeout) and the next click replays the **same** logical command — the server answers with the same `201` + `ETag` and writes no second row; a new click after a terminal answer mints a fresh key via `IdempotencyKeys.begin('tiktok.create')` and `settle()`s the old intent (10.2.3-T1, 10.5.2-T1:67). The Post button is `disabled` + `aria-busy` while `submitState = 'submitting'`. Additionally, on a transport failure the store refetches `GET /episodes/{id}/publications` and adopts an existing non-terminal TikTok publication (`publication` signal, `submitState = 'created'`, consent step continues) so the UI state matches the server even if the replay is answered from the server's idempotency record. A `422 idempotency_key_reused` or `409 idempotency_conflict` (same key, different body) is treated as a client bug (dev console + `errors.unknown_error` with `traceId`), never silently retried.

**Performance.** One `GET /channels` (connection pick) + one `GET /channels/{id}/tiktok/creator-info` (via 10.7.3-T1's cached `TikTokStore` where the user came from `/channels`, otherwise one call) + one consent-text call per variant change + one create + one consent; the episode comes from the inherited `EpisodeDetailStore` (no second fetch). The page is in the lazy `publishing` chunk (FC8); the status panel is a sibling component of the same chunk (no `@defer` needed — it is below the fold but cheap); no polling; everything is `track`-ed by id.

**Security.** Bearer via the wave-1 interceptor; the consent text is server text rendered as plain text; `privacy` is not user-selectable and is always sent as `SELF_ONLY`; `description`/`tags`/`publishAt` are sent as explicit `null`s (never omitted, so a stray server default cannot leak a schedule); no `bypassSecurityTrust*`, no CDN, no third-party script; the create carries the required `Idempotency-Key` (one key per Post intent, kept across a lost response — 07.2.2-T1:89), consent carries `If-Match` and no key, and no credit copy exists because posting spends no credits (07 D16); the caption, consent text and `blockReason` are never logged and never put in a URL; `If-Match` is required for consent so a concurrent change cannot be consented to blindly; a foreign publication id is `404` server-side (tenant filter) and is rendered as "not found", never as an authorization hint.

**Accessibility (SD12/WCAG 2.2 AA, states B1–B12).** Form labels tied to controls (`<label for>`), `aria-invalid` + `bindFieldErrors` for the caption and the variant group, the counter `aria-live="polite"` and not the only error signal (a text message accompanies it); the private notice is a `role="note"` referenced by `aria-describedby` from Post; the variant radios are a `fieldset`/`legend`; the consent section has a heading and is fully readable before Post at 360 px; while submitting, `aria-busy` + disabled + a static "posting…" text under `prefers-reduced-motion`; after consent, focus moves to the status panel heading and its own live region announces changes (10.7.4-T1); every target ≥ 24 px; visible focus at both themes and 200 % zoom; no colour-only signal for the blocked/expired states.

## Acceptance checks

- **Given** the composer route with `tiktok_publish` off, **when** the URL is opened, **then** `tiktokEnabledGuard` blocks it and the user sees the flag-off state (not an empty form), and no composer request is issued.
- **Given** an episode whose title is 300 characters, **when** the composer loads, **then** the caption field is seeded with that title, the counter shows the UTF-16 unit count against `2200`, and an emoji sample counts 2 units per astral character.
- **Given** a caption of 2201 UTF-16 units, **when** the user tries to submit, **then** Post is disabled, the counter shows the error text (not colour alone) in an `aria-live="polite"` region, and **no** `POST /episodes/{id}/publications` is sent.
- **Given** creator info with `duetDisabled = true` and `stitchDisabled = false`, **when** the form renders, **then** the duet switch is checked + disabled with its explanation, the stitch switch is enabled, and the submitted `tiktok.disableDuet` wire value is `true`.
- **Given** `disclosureEnabled = false`, **when** the settings are submitted, **then** `brandOrganic` and `brandedContent` are both `false` in the request body (and their switches are disabled in the UI).
- **Given** the variant `music`, **when** the user switches to `branded`, **then** exactly one `GET /publications/consent-text?locale=<current>&variant=branded` is sent, the displayed text is replaced, and `consentTextVersion` becomes the returned `version` verbatim.
- **Given** a ready composer, **when** the consent text has not been displayed yet, **then** Post is disabled and the notice + consent region are reachable before it in the tab order.
- **Given** a Post click, **when** the create request is sent, **then** it carries exactly one `Idempotency-Key` (UUID v4); a replay after a timeout/5xx carries the **same** key (and the server returns the same `201` + `ETag` without a second row), while a new click after a terminal answer carries a **new** key.
- **Given** a successful create, **when** the `201 PublicationDto + ETag` arrives, **then** the store keeps the ETag, immediately sends `POST /publications/{id}/consent { consentTextVersion }` with `If-Match: "pu-<xmin>"` and **no** `Idempotency-Key`, and only after `204` mounts the status panel with `submitState = 'done'`; the request body contains `privacy = 'SELF_ONLY'`, `description = null`, `tags = null`, `publishAt = null` and the six `tiktok` switch values.
- **Given** a `409 idempotency_conflict` or `422 idempotency_key_reused`, **when** the response is handled, **then** it is surfaced as a client bug (dev console error + `errors.unknown_error` with `traceId`), not as a user error and not as a silent retry.
- **Given** a `428 if_match_required` on consent, **when** the response is handled, **then** the store refetches the publication row, re-derives the ETag and retries **once**.
- **Given** a `400 consent_text_outdated`, **when** the response is handled, **then** the consent text is refetched, the previous version is discarded, the copy `tiktok.consent.outdated` is shown, and **no** automatic consent is retried — a new click is required.
- **Given** a `400 tiktok_invalid_post_settings` (or `tiktok_video_too_long`), **when** the response is handled, **then** the mapped `errors.tiktok.*` copy is shown, the form keeps the user's input, and Post returns to an enabled state; **given** `409 tiktok_cannot_post_now`/`channel_already_connected` or `429 tiktok_creator_cap`/`tiktok_rate_limited`, then the mapped banner is shown and no automatic retry happens.
- **Given** the publication's `error_code` is `tiktok_reauth_required` (or its connection is `expired`), **when** the composer or the status panel renders it, **then** the reconnect card appears with its own copy, `Reconnect` restarts the connect flow, and the publication list is refetched afterwards.
- **Given** a create request that fails at the transport level, **when** the store recovers, **then** it refetches `GET /episodes/{id}/publications` and adopts an existing non-terminal TikTok publication (continuing to the consent step) instead of sending a second create; a second create is sent only when the refetch proves none exists.
- **Given** the rendered page, **when** the DOM is inspected, **then** there is no `input[type=file]`, no progress bar, no percentage and no chunked-upload code — and the created state's copy says TikTok downloads the video from our storage.
- **Given** axe with tags `wcag2a`,`wcag2aa`,`wcag21a`,`wcag21aa`,`wcag22aa`, **when** each state B1–B12 is rendered in vi and en, dark and light, **then** there are zero violations and zero `securitypolicyviolation` events.

## Failure handling and edge cases

| Situation | Handling |
|---|---|
| Caption exactly at the limit with astral characters | UTF-16 counting; the boundary test keeps `2200` valid and `2201` invalid |
| Creator info says `canPost = false` | blocked card with `blockReason` verbatim; Post disabled and `aria-describedby`-linked; a retry refetches the creator info (`force`) |
| `privacyLevelOptions` only `SELF_ONLY` (audit not approved) | variant `branded` is disabled with the reason; the persistent notice is present; nothing offers public posting |
| Consent text request fails | `consentState = 'error'` + `ErrorState` with retry; Post stays disabled (a consent without text cannot be given) |
| The variant is changed after a successful consent | the consent is already recorded server-side; the form shows the recorded variant read-only and links to the status panel instead of re-consenting |
| `consent_text_outdated` twice in a row | the second click re-submits the newly fetched version; no loop — each attempt needs a click, and two consecutive failures surface the error banner with a support hint |
| `409 idempotency_conflict` (same key, different body) / `422 idempotency_key_reused` | client bug: dev-only console error + `errors.unknown_error` with `traceId`; the form state is kept and a fresh Post click mints a new key (the old intent is `settle()`d) |
| Consent answered with `428 if_match_required` | refetch the publication row, re-derive the ETag, retry once, then show `errors.unknown_error` with the `traceId` |
| Create timed out but the server created the row | refetch → adopt the non-terminal TikTok publication → continue with consent (no duplicate) |
| Create succeeded but consent never got an answer | the status panel renders `awaiting_consent`; the consent action is offered again from the panel/row (with a fresh ETag) |
| `tiktok_video_too_long` | mapped copy with the server's `maxVideoPostDurationSec` context; the user re-renders a shorter video (no client-side duration truncation is attempted) |
| `429 tiktok_creator_cap` / `tiktok_rate_limited` | mapped copy; `tiktok_rate_limited` may be retried after a backoff by an explicit user click, `tiktok_creator_cap` is a next-day/quota explanation (07 D10) |
| `429` from our own inbound policy | same rate-limit copy; no automatic retry |
| Episode not render-ready / no `active` TikTok connection | B2 state with the reason + a link to `/channels`; the composer never fabricates a connection |
| Flag turned off mid-session | the next call returns `404 feature_disabled` → flag-off state, form state preserved in memory only (never persisted) |
