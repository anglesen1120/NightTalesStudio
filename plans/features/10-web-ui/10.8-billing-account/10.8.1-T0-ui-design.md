## Design

**Screen × state inventory (the design must cover each cell).** From `plan.md` §6, unchanged: `/billing/packages` [DECISION] (loading, empty, error, success, flag-off); the checkout dialog (idle, submitting, promo applied, promo rejected, invoice expanded, redirecting, bank-QR alternative, `payment_invalid_state`, `rate_limited`); `/billing/return` (confirming/poll, paid, `pending_approval`, `needs_review`, failed, expired, missing `paymentId`); `/billing/ledger` [DECISION] (loading, empty, error, success = one line per reservation, `@defer` row detail); `/billing/wallet` (loading, error, balance card, low-balance banner, `nextExpiry` present/absent); `/billing/payments` (loading, empty, filtered-empty, error, success); `/billing/payments/:id` (loading, 404, success, receipt available/absent, refund eligible/not eligible/pending, refund dialog states); `/account` (loading, error, form, saving, field errors, locale changed, export pending/ready/expired-link/rate-limited, deletion pending/requested, legal re-acceptance required); `/account/export` + `/account/deletion` [DECISION] (pending, ready, expired link, failed, requested); `/account/activity` (loading, empty, filtered-empty, error, success, row detail); the episode **History tab** component (same four states); `/account/security` (loading, empty, error, success ≤ 20 rows, revoking, revoke-all confirm/done, `isCurrent` marked); the `header-end` balance chip (hidden, loading, value, silent error); the `cost-line` slot (hidden, quote loading, quoted, quote failed/silent).

**Breakpoints.** 360 — one column, dialogs full-screen, the QR card ≥ 240 px wide so nothing is zoom-clipped, chips wrap, no horizontal table scroll without a scroll affordance; 768 — package cards 2-up, balance card + low-balance banner side by side, ledger as a card list; 1280 — 3-up package grid, table-style ledger/payments/activity with sticky headers and a visible row-action column.

**Themes and languages.** Dark (default) + light, every state designed in both, contrast checked on `StatusChip` variants (no colour-only status; the chip always carries a text label — SD12). vi (default, usually longer: price suffixes, "khoản giữ chỗ" for a reservation line) + en; the design shows the longer language in the tightest cell (package card CTA, `header-end` chip, `StatusChip`).

**Focus order and a11y annotations (per screen).** Documented as a numbered path: skip-link → `PageHeader` → primary action → content → secondary actions; dialogs trap focus, restore it to the opener, close on Esc, and expose `aria-labelledby`; poll transitions announce through `aria-live="polite"`, errors through `role="alert"`; tables/rows expose `aria-sort`-ready headers and 24 px minimum targets; the receipt is a link opening a new tab, so the design annotates `rel="noopener"` and an external-link icon; the QR card annotates a text alternative (bank name + account number as copyable text, not the image alone). **No `[innerHTML]`** anywhere in the design's text boxes (D4).

**Component usage (D11, no new primitives unless listed).** Reused: `PageHeader`, `LoadingState`, `EmptyState`, `ErrorState`, `StatusChip`, `ConfirmDialog` (+`cost-line`), `RetryCountdown`, `CopyableCode`, `CharCounter`, `FormErrorAlert`, and — as content slots, not new visuals — `LegalAcceptanceDialog`/`ReauthDialog` entry points. New folder-local components the design must draw: `BalanceCard`, `LowBalanceBanner`, `BankQrCard`, `CheckoutDialog`, `LedgerRowDetail`, `ReceiptButton`, `RefundRequestDialog`, `BalanceChip`, `CostLine`, `ActivityTimeline`, `EpisodeHistoryTab`, `RevokeAllDialog`. Every new component is drawn from D11 tokens (spacing/typography/colour/elevation), so 10.1.3-T1 needs no new token; if a token is missing, the gap is reported in the design notes instead of inventing one.

**Copy rules.** All strings are shown in both languages and mapped to proposed Transloco keys in the `billing`/`account`/`errors` scopes (SD13 style `scope.area.item`); no price, refund window or bonus figure is invented (**ST-1**, S-O4) — the design uses explicit placeholders where the owner must supply numbers, and the packages/pricing pages state credit expiry and refund rules (12 D18). Server-emitted text (receipt HTML, consent texts, error `detail`) is drawn as a frame/mock, never as a key.

## Steps

1. Restate the inventory from `plan.md` §6 as a checklist; add any state found while drawing and flag it back to `plan.md` §6.
2. Low-fi wireframes: every screen at 360, 768, 1280 (one artboard per breakpoint per screen family) — layout, hierarchy, action placement, table/list behaviour, dialog shells.
3. Hi-fi mockups: dark and light for every screen × state, built from the D11 tokens/components with the slots (`header-end`, `cost-line`) drawn in place.
4. Copy sheet: vi + en for every state, mapped to proposed keys; placeholders for owner-supplied figures (ST-1).
5. Focus order + keyboard path + a11y annotation layer on each screen (focus rings, `aria-live` regions, Esc/trap/restore, 24 px targets, contrast pairs, 200 % zoom and 360 px checks noted).
6. Design review with the owner; apply notes; record the **design link** and the **owner approval (name + date)** in `plan.md` §6, replacing the `[OPEN]` line.

## Failure handling and edge cases

| Situation | Handling |
|---|---|
| A screen/state is discovered while drawing that `plan.md` §6 does not list | Add it to the design **and** to `plan.md` §6 in the same change; notify the owning implementation task; the design gate is re-approved rather than partially applied |
| The owner rejects a screen or a whole direction | Iterate and re-record approval; implementation tasks stay blocked (`Blocks` is hard) |
| A D11 token/component is missing for a money-specific affordance | Report the gap in the design notes; do not invent a parallel token (the fix belongs to 10.1.3-T1 / D11) |
| Owner-supplied figures (prices, refund window copy) are not available | Keep ST-1 placeholders; the design is approvable with placeholders, and the numbers are a content change, not a design re-do |
| vi copy does not fit the tightest cell | Redesign the cell (shorten the vi string in the copy sheet); never truncate a money label or a state label |
| A state depends on 13's DTO shape, still being written (`GET /me/exports/{id}`, `GET /me/deletion-requests`) | Draw the frame generically with the fields listed in SC24 and note the dependency; the exact field names land with 13.3.3-T1/13.3.2-T1 |
