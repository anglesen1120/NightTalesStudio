## Goal

Ship `/account` — profile (`GET/PATCH /me`), UI language, legal re-acceptance entry, and the entry points + status routes for the data export (DSAR) and the account deletion flow — consuming 13's engine deliverables (`13.3.3-T1`, `13.3.2-T1`, `13.2.1-T1`) and 09's `/me` wire, plus the `Account` shell nav entry. The screens must never re-implement the export/deletion engine, never show a stale pre-signed link, and never leak the export content into the app DOM.

## Design

**Routes (`features/account/account.routes.ts`).** `/account` → `AccountPage`; `/account/export` [DECISION] → `AccountExportPage`; `/account/deletion` [DECISION] → `AccountDeletionPage`; `/account/activity` and `/account/security` are 10.8.5-T1's (same feature folder, added by that task). Lazy `loadComponent`, authenticated shell, no prerender (D12). `/billing`-style guard reuse (authenticated only — **no** admin/MFA requirement here).

**`/account` — profile.** Loads `GET /me`; the form is dirty-tracked and `PATCH /me` sends **only** changed fields. Validation mirrors the server: 400 `validation_failed` → `bindFieldErrors` binds each `fieldErrors` entry to its control; `breached_password` (if a password change is offered through a link) binds to the password control and never echoes the value. Save state: idle → saving → saved (announcement via `aria-live="polite"`) or error (`FormErrorAlert` + `traceId` for `unknown_error`). The e-mail field is read-only (changes go through 09's verify flow, not this screen).

**Language.** A selector writing `uiLocale` (D10): the choice is applied to Transloco immediately (optimistic, local) and persisted by the `PATCH /me` that follows; a failed PATCH reverts the selector and announces the error, leaving the session language as the server has it. `PreferencesStore` stays the only browser-storage site (D6) — this screen adds no key.

**Legal re-acceptance entry.** When `GET /me/legal` reports a stale version (or the login response carries `pendingAcceptance`, SC24), `/account` shows a banner with an action that opens `LegalAcceptanceDialog` (13.2.1-T1, imported); acceptance posts `POST /me/legal/accept { tos, privacy }` through that dialog's own flow — this task only mounts it and refreshes the status on success. No consent text is embedded here (13's content).

**Export (DSAR).** Action button → `POST /me/export` once per intent via `withIdempotency(IdempotencyKeys, …)` (FC7, SC24); responses: 202 → navigate to `/account/export`; 429 (repeat within 24 h) → the rate-limit copy with the remaining-window hint if the API provides it [INFERENCE], no retry storm. `/account/export` reads `GET /me/exports/{id}` (status + links) and, while pending, polls through `visible-poll` capped at **10 min** (SD16); when ready it shows the pre-signed links and their expiry, and **refreshes them at expiry (≤ 15 min)** by re-reading `GET /me/exports/{id}` (13.3.3-T1) — an expired link is never shown as usable. Links are opened with `rel="noopener"` and offered as downloads with `safe-filename.ts` names; the archive is never fetched into the SPA DOM.

**Deletion.** `/account` shows the danger zone; the request runs 13.3.2-T1's flow (its confirmation component/dialog, imported) and the status page `/account/deletion` reads `GET /me/deletion-requests` (13 CR-8, SC24) with the same pending/ready/expired-state discipline; a cancellation option exists only if 13's API exposes one (⚠️ not in the plan → not designed as a button; flagged as [OPEN]).

**Ownership boundary (folder-local [DECISION], consistent with SC24 + 10 CR-27).** 13 owns the engine and its flow components; this task owns the `/account` routes, the entry points and the status pages that render 13's components. If 13 ships the engine without mounted flow components, this task renders the status pages itself against the same routes/DTOs (`POST /me/export`, `GET /me/exports/{id}`, `GET /me/deletion-requests`) — the contract names do not change; the component ownership is the only variable, and it is recorded in `## Notes`.

**Nav + i18n.** Append `Account` to the shell `NAV_ITEMS` (path `/account`, `nav.account`) — WT-W6 precedent, matching 10.8.1-T1's `Billing` entry. New Transloco scope `account` (`account.profile.*`, `account.language.*`, `account.export.*`, `account.deletion.*`, `account.legal.*`) and `errors.*` keys (`validation_failed`, `rate_limited`, `forbidden`, `unknown_error`), vi + en.

## Acceptance checks

- **Given** an unchanged profile, **when** the form is submitted, **then** no `PATCH /me` is issued; **given** one changed field, **then** the body carries exactly that field.
- **Given** a 400 `validation_failed` with `fieldErrors`, **when** the save fails, **then** each message is bound to its control and focus moves to the first invalid control.
- **Given** a language change that the server rejects, **when** the `PATCH /me` fails, **then** the selector reverts, the announcement explains the failure, and no local preference is persisted beyond `nts.prefs.v1`.
- **Given** an export request, **when** the user submits twice quickly, **then** exactly one `POST /me/export` is issued; **given** the API answers 429, the rate-limit copy shows with no automatic retry.
- **Given** an export in progress, **when** `/account/export` is open, **then** it polls `GET /me/exports/{id}` only while visible, stops at 10 min, shows ready links with their expiry, and re-reads the status at expiry so an expired link is never presented as usable.
- **Given** a deletion request, **when** the flow completes, **then** `/account/deletion` shows the status from `GET /me/deletion-requests` and the account stays usable until the server state says otherwise.
- **Given** a stale legal version, **when** `/account` loads, **then** the banner appears and its action opens 13.2.1-T1's `LegalAcceptanceDialog` (imported, not re-implemented), and the banner clears after a successful acceptance.
- **Given** axe (`wcag2a, wcag2aa, wcag21a, wcag21aa, wcag22aa`) on `/account`, `/account/export`, `/account/deletion`, **then** zero violations; the danger zone is not colour-only, the destructive action has an explicit confirm, and focus is trapped/restored in the dialogs.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| `PATCH /me` 401 `reauth_required` | Route the user through `ReauthDialog` (10.3.3-T3) and retry the same call **once** (SD7's step-up helper), then show the error |
| Export request 429 (already requested < 24 h) | Show the rate-limit copy; no automatic retry; the existing request's status page is linked |
| Export link expires while the page is open | Re-read `GET /me/exports/{id}` on the expiry boundary; show a "link refreshed" inline notice; never open a dead link |
| Export fails server-side | Render the failed state from the status endpoint (not a client timeout) with the retry availability the API signals |
| `GET /me/exports/{id}` 404 (unknown/expired request) | Neutral state + a new-request action; no detail leak |
| Deletion cancelled by the server/user | The status endpoint is authoritative; the page renders its status, never a client-side "deleted" claim |
| Language change with an active draft in the profile form | Apply the language immediately (copy only); the form data is untouched |
| Offline / network error | D11 error state + retry; the form keeps the typed values; no silent loss |
| Unknown field in `GET /me` | Ignored (no dynamic form rendering); the form binds only the fields it knows |

## Notes

This task exists to give the account route its owner without duplicating 13's DSAR/deletion engine (SC24: "13 owns and 10 only consumes"). Two contract details are deliberately not invented: an export **cancellation** or a deletion **cancel** action — neither is in the plan's route list, so no button is designed (⚠️ [OPEN] if 13 adds one). `GET /me/deletion-requests` is a 13 CR-8 **new route**, so the deletion status page is pinned to 13.3.2-T1's DTO once 13's Part C is on disk; until then it renders the states above against a contract-true fake (the dependency is hard, so the acceptance run needs the real endpoint). The export poll is the only polling here and it uses `core/state/visible-poll.ts` with the 10-minute cap (SD16) — no ad-hoc timer anywhere (D13's no-timer rule). `LegalAcceptanceDialog` is imported from 13's feature (exported from `@features/compliance` or `@features/account` per 13.2.1-T1's final location — the import path is taken from that task, not re-created).
