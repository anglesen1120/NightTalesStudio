## Goal

Ship the account's history and device surfaces: `/account/activity` (the `GET /me/activity` cursor timeline with category/date filters and deep links), the episode **History** tab reusing `GET /episodes/{id}/activity`, and `/account/security` (session list, per-session revoke, "This wasn't me" → revoke-all + password reset). The screens render only the user-visible projection 09 provides, never ask for admin visibility, and treat device trust as dying with the session it belongs to.

## Design

**`/account/activity` (`activity.page.ts` + `activity-timeline.ts`).** `cursor-list` over `GET /me/activity`; only user-visible rows are ever requested — the request carries `category`/`from`/`to`/`cursor`/`limit` and **never** a visibility or admin parameter (FC11). Filters: a category selector fed by the categories the projection exposes, plus `from`/`to` date inputs (server-side filtering, so the list re-pages from the first page on each filter change). Label = `activity.<messageKey>` with `activity.unknown` fallback (`messageKey` is server-emitted and never a key by itself, SD13); `params` are interpolated as text, never rendered as HTML (D4). Each row shows `occurredAt` (locale-formatted), the label, `actorLabel` and — in the `@defer` detail — `reason`, `ip`, `device`, `targetType`/`targetId`. Deep links: `targetType` decides the route (`episode` → `/episodes/{targetId}`, `series` → `/series/{targetId}`, `publication`/`payment` → their detail routes where the user owns them), and an unmapped `targetType` renders without a link rather than guessing. States: loading, empty, **filtered-empty** (distinct copy + a clear-filters action), error + retry; paging ends at `nextCursor == null`.

**Episode History tab (`episode-history-tab.ts`, exported from `@features/account`).** The same timeline component with `GET /episodes/{id}/activity` as its source and a fixed `episode` scope (no category filter; date filter kept). Mount point: the episode detail page `/episodes/:id` belongs to wave 1 (`10.5.3-T1`); this task owns the component and the tab registration, and the two-line change to that page's tab list is part of this task's Outputs. If wave 1's page exposes no tab/extension point, the mount is requested from `10.5.3-T1` and the gap is recorded in `plan.md` §11 (open item) — the component ships regardless, and its acceptance is proven on the standalone route/Storybook-equivalent harness until mounted.

**`/account/security` (`sessions.page.ts` + `revoke-all-dialog.ts`).** Renders `GET /me/sessions` verbatim: `deviceLabel` (with a "trusted device" badge driven by the DTO's trust state for the family — the badge is informational and disappears with the row), `lastUsedAt`, `createdAt`, `expiresAt`, `ip`, `userAgent`, and an `isCurrent` marker on the caller's own session (`StatusChip`, text label — never colour-only). Actions: per-row `DELETE /me/sessions/{id}` → 204 removes the row (optimistic with rollback on error) and that device's **trust dies with the session** (README:312 contract, FC11); a 404 is treated as already-gone (row removed, no error). "This wasn't me" opens `RevokeAllDialog` (`ConfirmDialog`): `POST /me/sessions/revoke-all` → 204 keeps the current family, then the list refetches and a link to the password-reset flow (`/auth/forgot-password`) is shown as the next step. The list is ≤ 20 rows with no cursor, so the page states it explicitly ("newest 20; older sessions can be removed with 'revoke all'"). No raw `audit_logs.data`, no extra formatting of `ip`/`userAgent` beyond what the DTO gives.

**Realtime/privacy.** No hub subscription here (SD16: ids-only `CreditBalanceChanged` is billing's); the list refetches on navigation and after any action. No admin-visibility route is called anywhere in this task, and no screen displays another user's data (the fake repository in tests throws if an admin route is requested, FC11).

**i18n.** `account.activity.*` (title, filters, `activity.<messageKey>` labels, `activity.unknown`, filtered-empty copy), `account.sessions.*` (title, columns, trusted badge, revoke, revoke-all confirm, "this wasn't me", post-revoke-all instructions) and `activity.*` labels for the catalogue 09.3.6-T2 publishes; vi + en, with the CI key-set equality check (SD13) failing if a server-emittable `messageKey` has no key.

## Acceptance checks

- **Given** `GET /me/activity` returns `items` with `nextCursor`, **when** the timeline loads, **then** rows render newest first, paging continues until `nextCursor == null`, and no request carries any visibility/admin parameter (asserted against the fake repository, which fails on an admin route).
- **Given** a row with `messageKey` present in the catalogue, **when** it renders, **then** the label is `activity.<messageKey>` in the current language; **given** an unknown `messageKey`, then `activity.unknown` renders and no raw key leaks to the UI.
- **Given** filters produce no rows, **when** the result arrives, **then** the **filtered-empty** state renders with a clear-filters action, distinct from the true empty state.
- **Given** a row with `targetType`/`targetId` in the mapped set, **when** the row is activated, **then** it navigates to that entity's route; **given** an unmapped `targetType`, then the row renders without a link.
- **Given** the episode History tab on `/episodes/:id`, **when** it loads, **then** it calls `GET /episodes/{id}/activity` and renders the same states as the timeline.
- **Given** `GET /me/sessions` returns ≤ 20 rows, **when** `/account/security` renders, **then** every DTO field is shown as received, `isCurrent` is marked with a text label, and the trusted-device badge is tied to its row.
- **Given** a revoke on a non-current session, **when** the call returns 204, **then** the row disappears and stays gone after a refetch (the device's trust is gone with it); **given** a failure, the row is restored with the mapped copy.
- **Given** "This wasn't me" confirmed, **when** `POST /me/sessions/revoke-all` returns 204, **then** the list refetches, the current session remains, and the copy offers the password-reset link.
- **Given** axe (`wcag2a, wcag2aa, wcag21a, wcag21aa, wcag22aa`) on the three screens, **then** zero violations; the timeline is a semantic list with an accessible row structure, filters are labelled, dialogs trap and restore focus, and no status is colour-only.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| `GET /me/activity` 401 `session_revoked` (this session was revoked) | Standard session handling: the app returns to login; the page never renders a partial timeline |
| A `messageKey` arrives that is not in the catalogue | `activity.unknown` renders; the CI key check flags it at build time rather than at runtime |
| `params` contain a URL or HTML-looking string | Rendered as text via interpolation — never `[innerHTML]`, never a link built from server data other than `targetType`/`targetId` |
| Session list changed elsewhere between render and action | `DELETE` answers 404 → treated as already gone (row removed, no error); `revoke-all` refetches |
| Revoking the session that is making the request | Not offered for `isCurrent` (the API keeps the current family on revoke-all); if the server revokes it anyway, the app falls back to login |
| `ip`/`userAgent` absent or empty | Row renders with the remaining fields; no placeholder text invented for a security field |
| More than 20 sessions | Page shows the newest 20 and explains the revoke-all path (no cursor exists on that route) |
| Activity filters with `from > to` | Client-side guard: show the validation copy, do not send the request |
| History tab opened for an episode with no activity | Empty state (not filtered-empty) with a link back to the episode |

## Notes

The episode-page tab mount is the one coordination point in this folder: `/episodes/:id` is wave 1's (`10.5.3-T1`), the component is this task's, and the registration is the two-line change listed in `## Outputs` — if the page exposes no extension point, `10.5.3-T1` is asked for it and `plan.md` §11 records the gap; the component's behavior is verified independently until then. `session_new_device` e-mails link to `/account/security` **without** a token (09 D12), so the page needs no token handling and must be reachable by any authenticated session — the e-mail link is a plain route. Device trust is a server fact: this task renders the badge and removes it with its session; it never keeps a local "trusted" flag (FC11). The timeline uses `cursor-page.ts` (D5) and refetches on navigation — no polling (SD16) and no hub subscription. The `activity.*` label keys are the only place server-emitted identifiers are translated, and CI enforces catalogue coverage (SD13).
