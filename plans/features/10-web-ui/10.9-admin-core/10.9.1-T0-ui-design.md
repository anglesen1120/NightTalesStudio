## Goal

Produce the approved UI design for the whole S admin surface **before** any implementation task starts (owner rule 2026-09-25, SD11/ST-3; hard gate). The design covers the admin shell, the nine admin routes owned by this folder, the `setting_change` section of `/admin/approvals`, and the shell/nav shape used by `10.9-admin-ops/` (this folder is also that folder's design owner, §C8) — as wireframes plus hi-fi mockups for every state, at 360/768/1280, vi+en, dark+light, with focus order and a11y annotations, built from the D11 component inventory. Output is a design file link plus a screen × state inventory; the approval record is appended to `plan.md` §6.

**Breakpoints.** 360 px: nav as a drawer, tables as stacked cards (label/value pairs, no horizontal scroll for the primary fields), dialogs full-height sheets, 24 px minimum target size. 768 px: two-column form/dialog layout, tables scroll horizontally inside their container with a sticky first column. 1280 px: full table, side panel for filters (or a filter bar), dialogs ≤ 560 px wide. Motion: `prefers-reduced-motion` disables the skeleton shimmer and the toast slide.

**Languages.** vi + en text length checked for every nav label, table header, button and dialog title (German-length stress not required; the longest vi/en string governs the column width); all copy keys are the `admin` Transloco scope (SD13/FC10) with the error keys `forbidden`, `reauth_required`, `setting_change_pending`, `owner_action_pending`, `owner_action_disputed`, `grant_requires_approval`, `grant_request_not_pending`, `payment_already_resolved`, `payment_expired`, `payment_invalid_state`, `self_grant_forbidden`, `grant_target_forbidden`, `rate_limited`.

**Themes.** dark + light from the M3 tokens of `10.1.3-T1`; status chips (`StatusChip`) use token pairs verified for ≥ 4.5:1 text contrast in both themes (WCAG 2.2 AA, CR-23).

**Focus order and a11y annotations (per screen).** Documented in the design: skip-link → nav → page header actions → filter bar → table (header cells focusable only when sortable, `aria-sort` announced) → row actions → paging; dialogs trap focus and return it to the invoking button; destructive confirms put the cancel action first in DOM order; every async region has an `aria-live="polite"` loading/empty announcement; `feature_disabled` and 404 states are announced as the page's main content; the reason input is `aria-required`, with the error text bound to it (`bindFieldErrors`); the top-20 quota table marks the override state with an accessible label, not colour alone. Annotate the 24 px target size on every icon button and toggle.

**D11 components used.** `PageHeader`, `EmptyState`, `ErrorState`, `LoadingState`, `StatusChip`, `ConfirmDialog`, `ConflictDialog`, `FormErrorAlert`, `bindFieldErrors`, Material table + sort header (10.1.3-T1), `ReauthDialog` (10.3.3-T3), `CopyableCode` (ids/order codes), `RetryCountdown` is **not** used (no polling in this folder, SD16).

1. Given the design file, When the TL walks the screen × state inventory, Then every screen has loading/empty/error/success plus its role/privacy states, at all three breakpoints, in both themes and both languages, and no state in the inventory is missing.

4. Given the approvals mockups, When an owner views them, Then the approve button is drawn in a disabled variant for the requester when another owner exists (UC-7/UC-8).

6. Given `plan.md` §6, When the design is signed, Then the approval record is present and dated, and no implementation task in this folder or `10.9-admin-ops/` started before it.

## Failure handling and edge cases

| Case | Handling in the design |
|---|---|
| An admin (not owner) opens an owner-only URL | The chunk is not loaded; the design draws the generic 404 `not_found` page, never a "no permission" page (the API answers 404 too) |
| Owner views another owner | Buttons rendered in their owner-on-owner variant with the "Needs a third owner or a 24 h time-lock" copy slot and the apply time |
| Actor is the target of a grant | The grant button is absent from the mockup (no disabled hint that reveals the self rule) |
| `pending_approval` payments render on both this folder and `10.9.2-T1`'s queue | One shared row component spec is drawn once (approve/reject here; `needs_review` resolve belongs to 10.9.2-T1) so the two screens cannot drift |
| Very long `reason` / `note` inputs | Max length 500 chars shown as a counter (`CharCounter`); overflow scrolls inside the field, never resizes the dialog |
| Empty top-20 quota table | Designed empty state with the "no uploads today" copy, not a blank card |
| Disputed owner-action badge | Colour + text + icon (never colour alone) |
| Design unavailable before implementation | The gate holds: no implementation task starts; the TL escalates to the owner (§C7 design gate) |
