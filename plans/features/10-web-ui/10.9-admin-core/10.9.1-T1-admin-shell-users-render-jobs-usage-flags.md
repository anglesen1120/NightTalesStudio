## Design

**Routes (`web/src/app/features/admin/admin.routes.ts`).**

```ts
export const ADMIN_ROUTES: Routes = [{
  path: 'admin',
  canMatch: [adminGuard],                    // role admin|owner AND mfaEnabled

  loadChildren: () => import('./admin.routes.children').then(m => m.ADMIN_CHILD_ROUTES),
}];

export const ADMIN_CHILD_ROUTES: Routes = [
  { path: '', pathMatch: 'full', redirectTo: 'users' },

  { path: 'users',            loadComponent: () => import('./feature/users/admin-users.page').then(m => m.AdminUsersPage) },
  // 10.9.4-T1 adds: { path: 'users/:id', loadComponent: … AdminUserDetailPage }; the list links to it with [routerLink]
  { path: 'render-jobs',      loadComponent: () => import('./feature/render-jobs/admin-render-jobs.page').then(m => m.AdminRenderJobsPage) },
  { path: 'usage',            loadComponent: () => import('./feature/usage/admin-usage.page').then(m => m.AdminUsagePage) },
  { path: 'flags',            loadComponent: () => import('./feature/flags/admin-flags.page').then(m => m.AdminFlagsPage) },
  { path: 'moderation' | 'quota' | 'reports' | 'deletion-requests', loadComponent: () => import('./feature/…') }, // registered by 10.9.1-T2
  {
    path: '', canMatchChild: [ownerGuard],   // separate lazy chunk: settings + approvals, never downloaded by an admin
    loadChildren: () => import('./owner/owner.routes').then(m => m.OWNER_ROUTES),
  },
];

```

`adminGuard: CanMatchFn` — `inject(SessionStore).role()` ∈ {`admin`,`owner`} **and** `mfaEnabled` true, else `router.createUrlTree(['/'])` (an admin without MFA → the 10.3.3-T3 enrolment route); it reads the session store only, never fires an HTTP call in the guard. `ownerGuard: CanMatchFn` — role `owner`, else `router.createUrlTree(['/admin/users'])`. Both guards are pure functions of the session store so the chunk is not requested when they fail (asserted in e2e by the absence of the chunk request).

**Step-up helper (`web/src/app/core/security/step-up.ts`).**

```ts
@Injectable({ providedIn: 'root' })
export class StepUp {
  private readonly dialogs = inject(MatDialog);          // ReauthDialog from 10.3.3-T3
  private readonly errors = inject(AppErrorMapper);       // 10.2.2-T1 — .from(unknown): AppError
  async run<T>(call: () => Promise<T>): Promise<T> {     // retries the SAME call at most once
    try { return await call(); }
    catch (e) {
      if (this.errors.from(e).code !== 'reauth_required') throw e;   // 401 with a 5-minute window (09:426)
      const ok = await firstValueFrom(this.dialogs.open(ReauthDialog).afterClosed());
      if (!ok) throw e;
      return await call();                                // a second 401 is surfaced, never looped
    }
  }
}
```

**Users screen (`admin-users.page.ts` + `application/admin-users.store.ts`).** Query params in the URL (`query`, `status`, `role`, `verified`, `hasPayments`, `cursor`) so a reload restores the filter; `GET /admin/users` → `AdminPageDto<AdminUserListItemDto>`; columns `email`, `displayName`, `role`, `status`, `emailConfirmed`, `mfaEnabled`, `createdAt`, `lastLoginAt`, `creditBalance` — all rendered verbatim, `creditBalance` never recomputed; sortable columns announce `aria-sort`; row click → `/admin/users/:id`. Store shape: `{ items: AdminUserListItemDto[]; nextCursor: string | null; loading: boolean; error: AppError | null }` with `setFilter()` resetting `nextCursor` and `loadMore()` guarded by a single in-flight flag (`core/state/cursor-list.ts`).

**Render jobs screen.** `GET /admin/render-jobs?status=&cursor=&limit=` → `AdminPageDto<AdminRenderJobDto>`; columns `id`, `episodeId`, `userId`, `status`, `stage`, `percent`, `attempt`, `errorCode`, `workerNodeId`, `startedAt`, `finishedAt`; ids only (no script/scene/episode title content, no extra fetch — FC15 construction); retry/cancel behind `ConfirmDialog` → `POST /admin/render-jobs/{id}/retry|cancel`, 202/204 → refetch the row set (no optimistic status), 409 `episode_invalid_state` → `ConflictDialog` with the state copy + refetch.

**Usage screen.** `GET /admin/usage?from=&to=&groupBy=user|operation|model` (ISO dates in the query); segmented control for `groupBy`; the table renders exactly the rows the API returns — no client-side sum/average/margin arithmetic (A10 asserts absence of array aggregation in the feature); wide-table overflow handled per design at 360 px.

**Flags screen.** `AdminFlagsStore` loads the list (`[OPEN]` route, see Inputs) and toggles with `PATCH /admin/feature-flags/{key}` body `{ enabled, rules }` — `rules` is sent back unchanged for a plain on/off toggle (the rollout editor is not in this task; 06.5.2-T1 validates the schema and `percent`/`list`/`all` rollouts). Optimistic UI: the switch flips immediately, the call runs through `StepUp`, success → refetch the row (server is the source of truth), failure → revert the switch + `FormErrorAlert` with `AppError.code`/`traceId` (`validation_failed`, `not_found`, `reauth_required`, `forbidden`).

## Acceptance checks

1. Given role `user`, When the browser navigates to `/admin/users`, Then the SPA redirects to `/` and the network log contains **no** request for the admin chunk; Given role `admin` with `mfaEnabled = false`, Then it redirects to the enrolment route ✅.
2. Given role `admin`, When `/admin/settings` is requested directly, Then `ownerGuard` redirects to `/admin/users` and the owner chunk is never fetched; Given a direct `/admin/users` API call with a non-admin token, Then the API answers 404 `not_found` and the screen renders its not-found state (no permission page) ✅.
3. Given `/admin/users?status=suspended&cursor=…`, When the page reloads, Then the same filtered result set is restored from the URL and `nextCursor` drives "load more" with a single in-flight request ✅.
4. Given a render job in a retryable state, When the admin confirms retry, Then `POST /admin/render-jobs/{id}/retry` is sent once, and the row's state comes back from a refetch (never from an optimistic write) ✅.
5. Given a `409 episode_invalid_state`, Then `ConflictDialog` shows the state conflict copy and the list refetches; no retry loop starts ✅.
6. Given the flags screen, When a toggle posts `PATCH /admin/feature-flags/{key}` `{ enabled, rules }`, Then the switch flips optimistically, success refetches the row, and a failure reverts the switch and shows `AppError.code` + `traceId` ✅.
7. Given a mutation that first returns 401 `reauth_required`, When the admin passes password + TOTP, Then the same request is retried **once** and succeeds; a second 401 is shown as an error with no further retry ✅.
8. Given `/admin/usage?from=&to=&groupBy=model`, Then the rendered rows equal the API payload with no client aggregation, and the grouped totals shown are the server's ✅.
9. Given axe on `/admin/users`, `/admin/render-jobs`, `/admin/usage`, `/admin/flags`, Then zero violations with tags `wcag2a`,`wcag2aa`,`wcag21a`,`wcag21aa`,`wcag22aa` ✅.

## Failure handling and edge cases

| Case | Handling |
|---|---|
| Session expires mid-screen (401 with refresh failure) | The session interceptor ends the session (`session-end.ts`); the admin screen shows the session-ended banner, never a half-rendered table |
| `mfaEnabled` flips to false while in the area | Next navigation re-runs `adminGuard` and redirects to enrolment; the current screen's calls fail closed with 404/401 |
| `[OPEN]` `GET /admin/feature-flags` absent | The flags screen renders `ErrorState` with the `not_found` copy and a note; the toggle stays disabled (no write without a known current value) |
| Toggle races (two admins) | Server is authoritative: the response/refetch overwrites the optimistic value; a `validation_failed` on `rules` reverts and shows the code |
| `nextCursor` loop / duplicate rows | `cursor-list.ts` ignores a page whose `nextCursor` equals the previous one and de-duplicates by `id` |
| Empty usage range | Empty state with the range echoed; no "0" row is invented |
| Very large `limit` | Client always sends `limit ≤ 100` (09 paging rule) |
| Chrome-only back/forward through filters | Filters live in query params, so history navigation restores them deterministically |
