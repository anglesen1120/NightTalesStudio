## Goal

## Design

**Moderation (`feature/moderation/admin-moderation.page.ts`).** `GET /admin/moderation?cursor=&limit=` → paged `moderation_events` rows `[INFERENCE]` (member names not frozen — the table binds only what the deployed API returns; recorded as 10.9 CR-2 in Notes). Read-only list: no action buttons; row click opens a `@defer`ed detail drawer that shows only the fields the payload carries — the screen never fetches episode/scene/script content from a second endpoint (FC15 privacy rule: "the user's content is not shown here").

**Quota (`feature/quota/admin-quota.page.ts`).** `AdminQuotaStore.load()` → `GET /admin/quota` → `AdminQuotaDto`; cards for `used`/`limit`/`available` plus `quotaDay`, `nextResetAt`, `queueLength`, and a top-20 table from `users[]` (`displayName`, `uploadsToday`, `uploadsLimit`, `overridden`, `earliestScheduledAt`) — counts and display name only, no titles/episode/channel ids (06 D25 §Privacy). Row action "Set daily cap" → dialog with `uploadsPerDay` (`1..100`) + `reason` (3–500 chars) → `PUT /api/v1/admin/users/{userId}/quota-limit` body `{ uploadsPerDay, reason }` → 204 then refetch; "Clear cap" → `ConfirmDialog` → `DELETE /api/v1/admin/users/{userId}/quota-limit` → 204 then refetch. `409 oauth_client_in_use` (from 06's client-card flows) renders as a **blocking** dialog (no dismissal that implies success). `404 feature_disabled` — the whole screen is replaced by the "YouTube publishing is disabled (`youtube_publish`)" explanation with no retry button that would loop; the nav entry stays visible (ST-9).

**Reports (`feature/reports/admin-reports.page.ts`).** `GET /admin/reports?status=&cursor=` → `AdminPageDto<AdminReportDto>`; columns `createdAt`, `targetType`, `targetId`, `reason`, `status`, `reporterEmail` (masked `a***@domain`), `resolvedAt`, `handledBy`. `reporterEmail` is rendered exactly as received; the client never requests or displays the raw address (owner-only server-side). Resolve dialog → `PATCH /admin/reports/{id}` body `{ status, note }` → `AdminReportDto` in the response updates the row (server-authoritative); the note is required when the chosen status closes the case; 409 renders `ConflictDialog` + refetch, 404 renders the not-found state.

**Deletion requests (`feature/deletion/admin-deletion-requests.page.ts`).** `GET /admin/deletion-requests?status=&cursor=` → `AdminPageDto<AdminDeletionRequestDto>`; read-only columns `id`, `userId`, `scope`, `reason`, `requestedAt`, `dueAt`, `status`, `attempts` — **no** action button, no per-row fetch (13.3.2-T1 owns the flow; the admin list only observes it).

**Shared pieces.** All four stores reuse `AdminPageDto<T>` + `cursor-list.ts`, are constructed with the repositories below, and use `PageHeader`/`EmptyState`/`ErrorState`/`LoadingState`/`StatusChip`/`ConfirmDialog`/`ConflictDialog`/`FormErrorAlert`. Every mutation runs through `StepUp.run()` (retry once on 401 `reauth_required`). No polling and no hub subscription (SD16). Filter state lives in the URL query params for moderation/reports/deletion request status filters, and in component state for the usage-range-free quota screen (no filters there).

**Files.** New: `features/admin/data-access/{admin-moderation.repository.ts, admin-quota.repository.ts, admin-reports.repository.ts, admin-deletion-requests.repository.ts}`, `features/admin/application/{admin-moderation.store.ts, admin-quota.store.ts, admin-reports.store.ts, admin-deletion-requests.store.ts}`, `features/admin/feature/{moderation/admin-moderation.page.ts, quota/admin-quota.page.ts, quota/quota-limit-dialog.ts, reports/admin-reports.page.ts, reports/resolve-report-dialog.ts, deletion/admin-deletion-requests.page.ts}`, `features/admin/testing/fake-admin-{moderation,quota,reports,deletion-requests}.repository.ts`, `web/src/assets/i18n/admin/{vi,en}.json` (added keys). Changed: `features/admin/nav/admin-nav.ts` (four appended `AdminNavItem` entries; the quota entry carries `feature: 'youtube_publish'`), `features/admin/admin.routes.ts` (four child routes: `moderation`, `quota`, `reports`, `deletion-requests`).

## Failure handling and edge cases

| Case | Handling |
|---|---|
| `404 feature_disabled` on `/admin/quota` | Dedicated explanatory state; the override dialog is unreachable; no retry loop |
| `409 oauth_client_in_use` | Blocking dialog with the reconnect copy; the dialog cannot be dismissed into a success-looking screen |
| Override on a user that disappeared | 404 `not_found` → dialog closes with the error text and the list refetches (the row disappears) |
| `uploadsPerDay` out of `1..100` | Client-side validation blocks submit; a server `validation_failed` is shown through `bindFieldErrors` on the field |
| Empty moderation/reports/deletion table | Distinct empty state per screen (no cases / no events / nothing awaiting deletion), never a blank card |
| Masked `reporterEmail` missing (`null`) | Cell renders the "not provided" copy; no request for the raw value |
| Long `reason`/`note` | Counter at the 500-character limit; the dialog scrolls instead of growing |
| Resolve conflict (case already closed) | 409 → `ConflictDialog` + refetch; the operator sees the final state from the server |
| Slow list response | `LoadingState` skeleton; the nav stays interactive; no request cancellation cascade |
| Admin session loses role | Next call returns 404/403 per policy; the screen renders the not-found state (no role disclosure) |

## Notes

- `[INFERENCE]` Moderation row member names are not frozen in the contract (plan.md A17); the table binds only the deployed payload's fields and this is recorded as 10.9 CR-2 alongside the usage/owner-action DTO gap.
- `[OPEN]` The quota override route is documented as `PUT|DELETE /api/v1/admin/users/{userId}/quota-limit` (06 CR-19 handover / 06.3.2-T1); the screen uses that path and body verbatim.
- The quota screen and the 06.3.3-T1 endpoint read the same `platform_quota_usage` view; this task adds no second quota mechanism (06 ST8) and no polling — a manual refresh button refetches.
- `ADMIN_NAV_ITEMS` entries are appended here (WT-W6 precedent); the sidebar itself is owned by 10.9.1-T1.
- No third-party asset, no new CSP origin, no client telemetry: diagnostics are `AppError.code` + `traceId` and the server `audit_logs` (FC15).
