## Goal

Deliver support and abuse handling for one account: `/admin/users` (filterable, cursor-paged list) and `/admin/users/:id` (six `@defer`ed tabs from `AdminUserDetailDto`) plus every user-management action as a dialog with a **required** reason, hiding owner-only actions for admins and never showing a self grant. Content is not shown here; the moderation/report tabs link to the case view instead (10-web-ui.md:239-244).

## Design

**List (`feature/users/admin-users.page.ts` + `application/admin-users.store.ts`).** Query-param-bound filters `query`, `status`, `role`, `verified`, `hasPayments` + `cursor`; `GET /admin/users` (`limit ≤ 100`) → `AdminPageDto<AdminUserListItemDto>`; columns rendered verbatim, `creditBalance` displayed as the server's number (no client arithmetic); row → `/admin/users/:id`. Empty state ("no users match"), filtered-empty state, error state with `AppError.code`/`traceId`, loading skeleton.

**Detail (`feature/users/admin-user-detail.page.ts`).** One call `GET /admin/users/{id}` feeds six tabs: **Overview** (profile, verification, MFA on/off, last login, series/episode counts), **Sessions** (count, last IP, user agent — verbatim DTO fields only), **Channels** (platform + status; no tokens), **Credits & payments** (balance + recent ledger rows + payments + refunds as returned), **Moderation & reports** (event/report summaries with links to the case view — the case view logs the access; this screen embeds no content), **Audit** (the admin trail for that user). Each tab body is `@defer (on idle)` inside the routed page so the initial admin bundle never carries the tab panels; a tab whose slice is absent renders its own empty state. `404 not_found` (role-above-target or missing user) renders the shared not-found state, **never** a permission page — the API deliberately hides the difference.

**Action model (`feature/users/user-action-dialog.ts` + `application/user-actions.ts`).** A declarative list drives button rendering, so role rules live in one place:

```ts
type UserAction =
  | 'suspend' | 'unsuspend' | 'sessions/revoke' | 'resend-verification'
  | 'force-password-reset' | 'credits' | 'delete' | 'mfa/reset' | 'role';

interface UserActionSpec {
  action: UserAction; labelKey: string; ownerOnly: boolean; destructive: boolean;
  endpoint: (id: string) => string; method: 'POST' | 'PATCH';
  body: (form: UserActionForm) => unknown;      // always includes a non-empty reason
  requiresAmount?: boolean;                     // credits only
}
```

Every dialog enforces a non-empty `reason` (≤ 500 chars) before enabling submit; `credits` additionally requires `amount ≠ 0` and warns above the cap. `mfa/reset`, `role` and `delete` are `ownerOnly: true` and are **not rendered** for an admin actor (10-web-ui.md:239-244); "grant credits" is never rendered for the actor's own row (no disabled hint that reveals the self rule). Submit → `StepUp.run(() => repo.action(...))`; results: 204/200 → close + refetch `GET /admin/users/{id}` (server state is authoritative, no optimistic UI); **202** → the dialog stays open in its pending variant with the apply time when returned (`owner_action_pending` / `owner_action_disputed` "Needs a third owner or a 24 h time-lock") or the "waiting for owner approval" copy (`grant_requires_approval`); 403 `self_grant_forbidden` / `grant_target_forbidden` → bound to the credits dialog; 404 → not-found state; 409 → `ConflictDialog` + refetch.

**Approved design handoff.** Frames in [`08-admin.html`](../../../../design/ui/screens/08-admin.html): list `f-users-loading|empty|filtered|error|rows|404`; detail `f-user-loading|overview|sessions|channels|credits|moderation|audit|hierarchy|self|404`; actions `f-dialog-idle|invalid|submitting|success|reauth|owner-pending|owner-disputed|forbidden|grant-approval|conflict`. One common detail loading frame and six loaded tabs do not cover per-tab `loading|empty|ready|error`; `f-dialog-forbidden` does not prove distinct self-grant/target-forbidden copy; bounded dialog cards do not resolve the 360 px sheet mismatch.

**Container/presentation and state.** `AdminUsersPage` owns URL filter/cursor state; `AdminUserDetailPage` owns route id, one detail request and `activeTab: UserDetailTab`; each tab component is presentational over a typed slice and emits link/action intent only. Use explicit `TabLoadState<T> = idle|loading|empty|ready|error` per tab even if all slices derive from one response, so deferred placeholders and announcements are deterministic without extra endpoints. `UserActionDialog` maps a typed `UserActionCommand` to the frozen path/body; reason/amount form mapping is explicit and never serialized from raw `FormGroup.value`. Route id/session generation/destroy invalidate late detail/action results and clear reason state.

**Authority and races.** `canActOn`/button hiding are UX projection only. The API decides hierarchy, self and target rules; 404 remains non-disclosing, 403 codes remain distinct, 401 reauth retries one identical command, 202 remains pending, and 409 refetches before another attempt. Double-submit prevention is not authorization or server-idempotency proof.

## Acceptance checks

1. Given an admin actor viewing another admin or an owner, Then the action buttons are hidden entirely (no disabled variants) and no `role`/`mfa/reset`/`delete` request is reachable from the UI ✅ (10-web-ui.md:243).
2. Given the actor's own row, Then the "grant credits" action is absent ✅.
3. Given the credits dialog with `amount` above the per-admin 24 h cap, When submitted, Then the API's 202 `grant_requires_approval` (with `creditGrantRequestId`) keeps the dialog open in the "waiting for owner approval" state and the detail refetches, showing no granted credits ✅ (12 D12).
4. Given an owner acting on another owner (`suspend`, `demote`/`role`, `mfa/reset`), Then a 202 `owner_action_pending` renders "Needs a third owner or a 24 h time-lock" with the apply time (when returned); a 202 `owner_action_disputed` renders the Disputed copy ✅ (09 D8).
5. Given any action dialog, When the reason is empty, Then submit stays disabled; a whitespace-only reason (`trim().length < 1`, server allows 1–500) is rejected client-side ✅.
6. Given `GET /admin/users/{id}` returns 404 for a role-above-target, Then the page renders the not-found state with no hint about roles ✅.
7. Given the detail page, Then only one request to `/admin/users/{id}` is made for the initial render and the tab panels load on `@defer (on idle)` — no per-tab endpoint is called ✅ (FC12: no N+1, no client aggregation).
8. Given a suspended user, Then the suspend action flips to "unsuspend", and the row state comes from the refetch, never from an optimistic write ✅.
9. Given a mutation that first answers 401 `reauth_required`, Then `ReauthDialog` opens once and the same request is retried once ✅.
10. Given axe on `/admin/users` and `/admin/users/:id` (each tab), Then zero violations with tags `wcag2a`,`wcag2aa`,`wcag21a`,`wcag21aa`,`wcag22aa` ✅.

## Failure handling and edge cases

| Case | Handling |
|---|---|
| Role-above-target | 404 `not_found` → not-found state; buttons hidden so the UI never invites the call |
| Actor is the target | Owner-on-owner/self rules: no delete, no self grant; the owner-on-owner paths go to the pending flows |
| `Reason` too long | Hard cap at 500 chars with the counter; the field never truncates silently |
| Double submit | Submit disabled while in flight; the API's idempotent state codes (202 with the request id, 409 conflicts) prevent a second effect |
| Detail fetch fails after a successful action | The dialog closes with a success notice and the page shows the error state with a retry — the action is not repeated |
| Sessions tab shows a device the user revoked elsewhere | Values come from the server on the next load; the UI never caches session rows across visits |
| MFA not enrolled on the target | The `mfa/reset` action still renders for an owner; the API's code is surfaced if it refuses |
| Suspended user's detail | A banner with `status` renders from the DTO; actions remain available per role (unsuspend/should be visible) |
| Very long `email`/`displayName` in the table | Truncation with `title`/accessible full text; no layout break at 360 px |
| 404 on an action (user deleted concurrently) | Dialog closes with the not-found copy; the list detail refetches |

## Notes

- `[INFERENCE]` `AdminUserDetailDto`'s nested member names are not enumerated in the contract (09 README `:1048` lists the sections, not the fields); the tabs bind only the fields the deployed payload returns, and this is recorded as 10.9 CR-2 next to the usage/owner-action/moderation gap.
- The suspend side effects (family revocation, stamp rotation, SignalR abort, job cancellation with refund) are server-side (09.10.5-T1); the screen must not attempt any of them and must not claim them in copy beyond the server's returned state.
- Self-service MFA enrolment lives in `10.3.3-T3` / `/account/security`; this task only resets a user's MFA for an owner.
- The `grant_requires_approval` approval queue, the owner-action pending list and the role-hierarchy helper used by these buttons are completed in 10.9.4-T2 on top of this task's repository surface.
- No third-party asset, no client telemetry, no polling: refreshes happen on navigation and after mutations (FC15, SD16).
- Frame coverage is design evidence, not runtime a11y proof. Per-tab states, code-specific forbidden copy, mobile dialog behavior and focus trap/return follow the locked contract; flag to the owner only if a new visual state is needed (does not reopen the approval or block the task).
