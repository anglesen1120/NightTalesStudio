## 1. Scope

**In.** Six tasks: `10.9.1-T0` (M, UX design, SD11), `10.9.1-T1` (M, admin shell + `ADMIN_NAV_ITEMS` + users + render-jobs + usage + feature flags), `10.9.1-T2` (M, moderation + quota + reports resolve + deletion-requests), `10.9.4-T1` (M, admin user list + detail tabs + action dialogs), `10.9.4-T2` (M, role-hierarchy action hiding + owner-action pending list + credit-grant approval queue + payment `pending_approval` approve/reject), `10.9.5-T1` (XS, MFA disable for users + admin/owner redirect to enrolment before `/admin`, 10 CR-40). Total **5.25 d raw / 6.3 buffered** (part of §C9's 10.9 Admin 7.75 d; the remaining 2.5 d is `10.9-admin-ops/`).

Implements the wave-3 contracts that belong to this folder: SD1 (`admin` feature placement, `/admin` route table, `ADMIN_NAV_ITEMS`), SD7 (two `canMatch` guards, owner-only lazy chunk, `StepUp` re-auth retry), ST-4 (the L task splits as shell+users+render-jobs+usage+flags vs moderation+quota+reports+deletion-requests), ST-9 (06's D25/D26/D27 names rendered verbatim; `feature_disabled` hides `/admin/quota`), SD12/FC8 (per-lazy-route budget), SD13/FC10 (`admin` Transloco scope + error keys), FC15 (no client telemetry; `traceId` on `unknown_error`), FC16 (admin table a11y for 10.10.1-T2's manual matrix).

**Out.** `10.9.2-T1`, `10.9.3-T1`, `10.9.3-T2` → `10.9-admin-ops/` (same design owner); `10.9.5-T1`'s P parts (`ReauthDialog`, MFA enrolment/login step) → `10.3.3-T3` (10 CR-4); every API handler, policy, index, migration, job and outbox event (09/12/13/06 own them); `/admin/kpis` (08.1.1-T2 mounts into this shell); the accessibility audit + per-route budget enforcement (10.10.1-T1/T2); `10.1.3-T1` theme/UI kit, `10.2.6-T1` shell + `NAV_ITEMS`, `10.3.3-T3` `ReauthDialog` (all already detailed prerequisites, SC29).

**Area** FE + Security · **Phase** S · M2 · **Flag** none on this folder (no route here is feature-gated except `/admin/quota`, which is gated **server-side** by `youtube_publish`).

## 3. Domain and data

The SPA owns **no schema, no migration, no job and no outbox event** in this folder; it reads and mutates through the routes in §5 and renders server state verbatim. There is **no client-side aggregation** (A10) and **no client-side credit arithmetic** (12 README FC7): credit balances arrive as `creditBalance` (list) / "balance + recent ledger" (`AdminUserDetailDto`).

**Wire models (TS interfaces, one file `web/src/app/features/admin/data-access/admin.models.ts`, field names exactly as the JSON above):** `AdminPageDto<T> { items: T[]; nextCursor: string | null }`; `AdminUserListItemDto`, `AdminUserDetailDto`, `AdminRenderJobDto`, `AdminQuotaDto`, `AdminQuotaUserDto`, `AdminReportDto`, `AdminDeletionRequestDto`, `CreditGrantRequestDto`, `AdminPaymentDto`, `OwnerActionDto` `[INFERENCE]` (09 A4 freezes the three routes and the `status=pending` filter but not the row members; the screen renders `id`, `action`-equivalent status, the apply time and the target from the fields the deployed API returns, and the task's Notes record the gap as 10.9 CR-2), plus `[OPEN]` `FeatureFlagDto { key, enabled, rules }` (A16).

**Stores (signal-based, one per screen, `application/*.store.ts`):** `AdminUsersStore` (list + filters + cursor), `AdminUserDetailStore` (tabs, `@defer`-driven per-tab fetch), `AdminRenderJobsStore`, `AdminUsageStore`, `AdminFlagsStore` (optimistic toggle → refetch on success, revert + `AppError` on failure), `AdminModerationStore`, `AdminQuotaStore`, `AdminReportsStore`, `AdminDeletionRequestsStore`, `AdminOwnerActionsStore`, `AdminGrantRequestsStore`, `AdminPaymentApprovalsStore`. Every list store uses `core/state/cursor-list.ts` + `shared/util/cursor-page.ts` (A15) with `limit ≤ 100`, a single in-flight guard and `nextCursor`-driven "load more"; filters reset the cursor.

**Repositories (`data-access/*.repository.ts`, `Promise<T>`, `HttpClient` only here, never in components):** `AdminUsersRepository` (`list(query)`, `detail(id)`, `action(id, action, reason)`, `changeRole(id, role, reason)`, `grantCredits(id, amount, reason)`), `AdminRenderJobsRepository`, `AdminUsageRepository`, `AdminFlagsRepository` (`list()`, `patch(key, { enabled, rules })`), `AdminModerationRepository`, `AdminQuotaRepository` (`today()`, `setUserLimit(userId, uploadsPerDay, reason)`, `clearUserLimit(userId)`), `AdminReportsRepository`, `AdminDeletionRequestsRepository`, `AdminOwnerActionsRepository`, `AdminGrantRequestsRepository`, `AdminPaymentApprovalsRepository`. Fakes are hand-written (`testing/fake-admin-*.repository.ts`) — no mocking library (D15).

**Angular ownership and lifetime.** Routed page containers live in `features/admin/feature/**`, inject one task-owned application store and own URL/filter/tab/cursor synchronization plus request-generation teardown. Presentational leaves stay in `features/admin/ui/**`, accept immutable typed view contracts and emit intents; they never import generated DTOs, repositories or permission policy. Admin-local helpers are introduced only for two named semantic consumers with a named owner and input/output contract (for example the approvals and report decision dialogs), and are not promoted into a universal table/form/CRUD DSL. Stores are route-scoped unless a task explicitly names a parent route composition owner; destroy/navigation/session-generation changes invalidate late responses and clear sensitive form state.

**Server data touched (read-only from the client's point of view):** `users`, `sessions`, `channel_connections`, `series`, `episodes`, `credit_accounts`/`credit_ledger` (via `AdminUserDetailDto`), `payments`, `refunds`, `moderation_events`, `reports`, `audit_logs` (admin trail for a user), `usage_records`, `render_jobs`, `feature_flags`, `platform_quota_usage`, `platform_user_quota_usage`/`platform_user_quota_limits`, `data_deletion_requests`, `owner_action_requests`, `credit_grant_requests`. Paging relies on the API's keyset queries and indexes (09 §C3.1 keyset `?cursor=&limit=`, `OwnerActionApplyJob` over `(status, apply_after) WHERE status = 'pending'`) — the SPA never issues SQL and asserts no server-side index.

## 8. Security and privacy

- **Authorization is server-side.** The client guards (`adminGuard`, `ownerGuard`) only avoid downloading the chunk; `AdminPolicy`/`OwnerPolicy` re-check every call and a wrong role gets 404 `not_found` (A3). The screens render the 404 as "not found" and never treat it as a permission hint.
- **Step-up re-auth.** A 401 `reauth_required` on any admin mutation opens `ReauthDialog` (password + TOTP, 10.3.3-T3) and retries the **same** request exactly once inside the 5-minute window (A9); a second 401 is surfaced, never looped.
- **Role hierarchy.** Owner-only buttons (`mfa/reset`, `role`, `delete`, approvals approve/reject) are hidden unless the actor's role is strictly higher (UC-5); `self_grant_forbidden`/`grant_target_forbidden` are rendered as copy, and the approve button is disabled for the requester when another owner exists (UC-7/UC-8).
- **No content, no secrets.** Render jobs show ids/status only; reports mask `reporter_email` (`a***@domain`, raw owner-only); deletion requests are read-only; the moderation/report tabs link to the case view (which logs the access) instead of embedding content; no token, IP, user agent, receipt or QR payload is logged or put in a URL — the trusted-device/IP/UA fields come verbatim from `AdminUserDetailDto` (A1, A14).
- **Sensitive browser evidence.** Admin/billing/owner Playwright projects keep trace and video capture off, including retain-on-failure, unless a separately reviewed redacted diagnostic artifact is named. Screens and tests never attach raw request/response bodies, provider events, IP/UA values, secrets, cancel tokens or unmasked PII; only allowlisted codes and sanitized `traceId` references may appear.
- **Audit.** Every mutation is `[Audited]` server-side; the client shows the post-refetch state and never claims success optimistically (A14).
- **Tenant filter.** The admin group bypasses `IUserOwned` filters explicitly inside the API (09.9.1-T1 owns the allow-list entry); the SPA sends no tenant/user scope header and must not be relied on for scoping.
- **CSP/Trusted Types.** Unchanged: the admin chunk adds no inline script, no `bypassSecurityTrust*` and no new origin (D4; the CAPTCHA delta of CR-28 does not touch this folder).
- **Budgets.** `/admin/**` must never be referenced by the initial bundle; the per-lazy-route budget table asserts it (A12).
