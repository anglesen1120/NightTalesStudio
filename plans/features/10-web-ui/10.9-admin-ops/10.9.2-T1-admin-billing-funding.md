## Goal

The owner can run the money side of the service without a deploy or a SQL prompt: the credit-package catalogue and promo codes (list/create/edit/deactivate, create+edit owner-only), the payments that the provider could not settle automatically (`status = needs_review`) with a resolve dialog whose note is mandatory, the pending refund requests, and the funding page that answers "will the API still work tomorrow" — estimated balance, 7-day burn, runway (coloured at 7/3 days), outstanding liability, weekly set-aside vs actual top-ups — with forms to record a balance snapshot and a top-up and one "Resume processing" button while `provider_funds_exhausted` is open. Every figure and every state is rendered from a server payload; the screen performs no arithmetic of its own and claims nothing the server has not returned.

## Design

**Placement.** All screens sit in `features/admin/billing/` and are mounted under the already-existing `/admin/**` route subtree (`10.9.1-T1` owns the shell and `ADMIN_NAV_ITEMS`); this task only appends its five child routes (`billing/packages`, `billing/promos`, `billing/payments`, `billing/refunds`, `billing/funding`) — no second admin route group, no new `canMatch` (the `adminGuard` from 10.9.1-T1 already gates them).

**Ports (one per area, `HttpClient` + auth interceptor, return `Promise<T>`).**

```ts
export interface CreditPackagesRepository {
  list(): Promise<CreditPackageInput[] & { id: string; active: boolean }[]>; // server-paged payload, verbatim
  create(input: CreditPackageInput): Promise<void>;
  update(id: string, input: CreditPackageInput, etag: string): Promise<void>;   // withIfMatch
  deactivate(id: string, etag: string): Promise<void>;                          // active = false
}
export interface PromoCodesRepository { list(); create(input: PromoCodeInput); update(id, input, etag); deactivate(id, etag); }
export interface AdminPaymentsRepository {
  needsReview(cursor?: string): Promise<{ items: AdminPaymentDto[]; nextCursor: string | null }>;
  resolve(id: string, action: 'grant_expected' | 'grant_partial' | 'mark_failed', note: string): Promise<AdminPaymentDto | { creditGrantRequestId: string }>;
}
export interface RefundRequestsRepository { list(cursor?); approve(id: string, reason: string); reject(id: string, reason: string); }
export interface FundingRepository {
  overview(): Promise<FundingOverviewDto>;
  recordSnapshot(input: BalanceSnapshotInput): Promise<void>;
  recordTopUp(input: TopUpInput): Promise<void>;
  resume(): Promise<{ flag: string; textProbe: boolean; imageProbe: boolean; reason?: string }>;
}
```

Types are the frozen ones verbatim (`CreditPackageInput`, `PromoCodeInput`, `AdminPaymentDto`, `RefundRequestDto`, `FundingOverviewDto`, `BalanceSnapshotInput`, `TopUpInput`) — no `*Vm` aliases and no added fields; where a field is not in the frozen list the writer reads `12-billing-credits/12.8-funding/plan.md` first and must not invent one (see `./plan.md` §2 A12 ⚠️).

**Stores.** Signal stores per area with an explicit state union `{ status: 'idle'|'loading'|'ready'|'empty'|'error'; items; nextCursor; error?: AppError }`; `load()`, `loadMore()` (through `cursor-page.ts`/`cursor-list.ts`), `resync()` after every mutation. **No client aggregation and no derived money** (FC12, A13): the tables render rows, the funding cards render `FundingOverviewDto` field-for-field, `marginPct` renders "—" when `null` (never 0, never a division).

**Key behaviours.**
- Owner-only affordances: create/edit for packages and promos are hidden for role `admin`; the server still decides (403 `forbidden`) and a forced call renders the mapped copy.
- Resolve dialog: fields shown are `expectedAmount`, `receivedAmount`, `currency`, `method`, `orderCode`, `providerPaymentId`, `providerEvents[]` (`type`, `receivedAt`, `signatureValid`); `note` is required (`CharCounter`, max length from the API's validation error, not a client guess); actions are the three frozen enum members; a **200** renders the returned `AdminPaymentDto` (row updated by refetch) and a **202** renders "waiting for owner approval" with `creditGrantRequestId` — the row stays in the queue and no balance is claimed.
- `grant_partial` rounds **down** (12.3.5 brief:33) — the dialog says so; the client does not compute the number.
- Funding: runway chip `>= 7 d` neutral, `< 7 d` warn, `< 3 d` critical (12 D15); "Resume processing" is enabled only while the flag `provider_funds_exhausted` is open, requires re-auth, and renders `{ textProbe, imageProbe, reason }`; `reason = node_image_project_unfunded` renders the explanation ("the node's image project is unfunded; a text-only pass keeps processing paused") instead of a success state.
- Every mutation goes through the 10.3.3-T3 `StepUp` helper: 401 `reauth_required` → `ReauthDialog` → retry **once** (SD7).
- Refetch triggers only navigation, `resync` and user action — no polling, no new hub event (SD16, A23).

**Layout.** D11 components only: `LoadingState`/`EmptyState`/`ErrorState` per table, `StatusChip` for payment/refund state (label + icon, never colour alone, 12 D18), `ConfirmDialog` for deactivate/approve/reject, `RetryCountdown` for 429 `rate_limited`, `bindFieldErrors` for field-level 400s. Tables are server-paged with an `aria-sort` header and an `aria-live` region for empty/loading/error (FC16).

## Acceptance checks

- **Given** role `admin`, **When** `/admin/billing/packages` loads, **Then** rows come from `GET /admin/credit-packages` (server-paged, `cursor-page.ts`), create/edit affordances are absent, deactivate is present, and a forced `POST` renders 403 `forbidden` copy.
- **Given** a package form, **When** the price is below the floor and the API returns 400 `package_below_cost`, **Then** the error binds to the price control (no toast-only) and the form keeps its values.
- **Given** a stale `If-Match` on a package/promo save, **When** the API returns 412, **Then** the reload dialog appears and the row is refetched.
- **Given** a payment with `status = needs_review`, **When** the operator resolves with `grant_expected` + note, **Then** a 200 renders the returned `AdminPaymentDto` and the row leaves the queue after refetch; **When** the API returns 202, **Then** the dialog shows "waiting for owner approval" with `creditGrantRequestId` and the row **stays** in the queue with its state unchanged.
- **Given** the resolve dialog, **When** the note is empty, **Then** submit is blocked client-side and no request is sent.
- **Given** a payment already resolved elsewhere, **When** resolve is submitted, **Then** 409 `payment_already_resolved` shows the current state instead of a generic error.
- **Given** a refund request, **When** approve is confirmed with a reason, **Then** the row is refetched and the state shown is the server's; a 409 `refund_request_not_pending` shows the new state.
- **Given** `/admin/funding`, **When** it loads, **Then** every card value equals the `FundingOverviewDto` field with no arithmetic, `runwayDays < 7` renders the warn chip, `< 3` the critical chip, and `marginPct = null` renders "—".
- **Given** the flag `provider_funds_exhausted` is closed, **When** `/admin/funding` loads, **Then** "Resume processing" is disabled with the reason shown; **Given** it is open, **When** Resume is confirmed, **Then** re-auth is required and the probe result is rendered, with `node_image_project_unfunded` shown as "still paused".
- **Given** any mutation, **When** the API returns 401 `reauth_required`, **Then** `ReauthDialog` opens and the same call is retried exactly once (asserted by request count in the spec).
- **Given** the built app, **Then** no `/admin/**` chunk is referenced by the initial bundle and the axe spec passes with tags `wcag2a, wcag2aa, wcag21a, wcag21aa, wcag22aa`.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| `GET` fails (network/5xx) | `ErrorState` with `RetryCountdown` on 429 and `traceId` on `unknown_error` (FC15); no partial table, no stale money shown as current |
| 404 `not_found` (role changed server-side) | Permission-denied state, the chunk is not re-requested, no 403 branch rendered |
| 409 `payment_already_resolved` / `payment_invalid_state` | Refetch the row and show the server state; the dialog closes |
| 409 `refund_request_not_pending` | Refetch; the decide buttons disappear |
| 202 `grant_requires_approval` (resolve above the threshold) | "waiting for owner approval" with the request id; no balance claimed (10.9.4-T2 renders the approval) |
| 401 `reauth_required` | `ReauthDialog`; one retry; a second 401 surfaces the error and stops (no loop) |
| Resume with a text-only probe | Renders `reason = node_image_project_unfunded`; the button stays available; the flag stays open |
| `provider_funds_exhausted` flips between load and click | Resume returns the current flag in the probe result; the card re-renders from it |
| Empty catalogue / empty queue / empty refunds | `EmptyState` with the action-appropriate copy (no "0" cards, no invented totals) |
| `billing_enabled = false` (12 CR-3/BR17) | These admin screens stay fully usable — the flag gates order creation only; no screen hides itself |
| Long `providerEvents[]` | Rendered in a `@defer`ed detail panel; the table row shows a count only |
