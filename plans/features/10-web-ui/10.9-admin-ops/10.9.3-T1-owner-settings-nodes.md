## Goal

The owner changes API keys, base URLs and worker-node capacity in one screen, without a deploy: one card per integration of the 09 §5.6 catalogue, a secret model that never shows or pre-fills a real secret, a "Test connection" that separates connectivity failure from validation failure, per-integration version history with a rollback that always demands the secrets back, a read-only row for the node-managed image key, and a worker-nodes tab with add/drain/activate/rotate-key. The screen is owner-only, lives in its own lazy chunk, and treats every 401 as a chance to prove identity again — never as a dead end.

## Design

**Placement and guard.** `features/admin/settings/` mounted as its **own lazy chunk**, separate from the rest of `/admin/**` (SD7, `plans/10-web-ui.md:313-314`): `ownerGuard` (`RequireRole` owner, checked client-side for UX only — the server is authoritative and returns 404 `not_found` for `admin`/other roles, never 403). The route `canMatch` guard prevents an `admin`-role session from ever fetching this chunk (FC8/network assertion in tests).

**Secret model (A24, never relaxed).**

```ts
export interface SettingFieldView {
  key: string;
  kind: 'text' | 'secret' | 'readonly';
  value?: string;       // non-secret only; readonly rows show server-supplied display text
  secretHint?: string;  // last 4, secret kind only — never the value
}
export type SecretEdit = { action: 'keep' } | { action: 'replace'; value: string } | { action: 'clear' };
```

A secret field renders `••••{secretHint}` with "Replace" (opens an input, cleared on cancel) and "Clear"; it is **never** pre-filled and never echoed back after submit. `PUT /admin/settings/{integration}` sends `SecretEdit` only for touched secret fields; an untouched secret is omitted from the body entirely (not sent as `null`, not sent as the masked string). Changing `base_url` flips the form to require a `replace` on the integration's secret (409/400 `setting_secret_required` from the server is the fallback validator, but the client disables submit first).

**Catalogue rendering (data-driven, A8).** One card per row of `GET /admin/settings` (§C7 flags this as [OPEN]: the card list is **not** hard-coded, so a new integration — e.g. 09 W3 CR-2's `captcha` — appears without a client change). Special cases:
- `mpt node image key`: `kind = 'readonly'`, rendered as one line "Node-managed — rotate via runbook" with no edit, no test, no reveal action (`plans/10-web-ui.md:232`).
- `youtube`: after the standard card fields, an embedded **OAuth clients** panel fed by `GET /admin/youtube/clients` (`YouTubeClientSettingsDto`): a table of `YouTubeClientDto` (`clientId`, `displayName`, `active`, `connections`, `activeConnections`, `lastConnectedAt`, `inUse`) with "Set active" and "Remove"; removing a client pinned by a connection renders the **409 `oauth_client_in_use`** payload (`{ clientId, connections }`) as a blocking `ConfirmDialog` that names the connection count and refuses the action — this is not a soft warning.
- Environment lock: a card whose settings are environment-pinned shows a "Locked by environment" `StatusChip` and disables edit/test (server truth; the client trusts the flag the payload carries, it does not infer it).

**Test connection.** Disabled when `base_url` is dirty and unsaved **and** a stored secret would be used (the high-level rule, `plans/10-web-ui.md:231`); on submit, 200 renders "Connected", 502 `setting_test_failed` renders the error text as data (never a key) with a retry.

**Save flow (UC-7).** `PUT` with `withIfMatch`; branches: 200 → refetch + toast; 202 `setting_change_pending` → hand off to `10.9.3-T2`'s banner (do not duplicate its rendering here — this task only triggers the refetch that makes the banner appear); 400 `setting_invalid`/`setting_secret_required` → `bindFieldErrors`; 401 `reauth_required` → `StepUp` (10.3.3-T3) → retry **once**, a second 401 surfaces the error; 409 `setting_change_pending` → show the **existing** pending change (fetched via the same `GET /admin/settings/changes?status=pending` call `10.9.3-T2` uses) instead of a generic conflict; 412 `setting_conflict` → reload dialog (discard local edits, refetch, no silent merge).

**History and rollback (UC-8).** `GET /admin/settings/{integration}/versions` → a list (who, when, reason, hints — `hints` is server text, not a key); "Roll back" opens a `ConfirmDialog` that **always** requires re-entering every secret field of that integration before the rollback call is enabled (old secrets are never restored, per the high-level rule and A24); the rollback POST carries `If-Match` and can itself return 202 `setting_change_pending` (critical integrations) — same banner hand-off as above.

**Worker nodes tab.** `GET/POST /admin/worker-nodes`, `PATCH /admin/worker-nodes/{id}` — list (state, capacity, active tasks, last health pull, key hint), add form, drain/activate actions, "Rotate key" opens a checklist dialog rendering the 09 §5.6 rotation steps as static copy (not fetched — it is procedural text shipped with the client, sourced from the design).

**Layout.** D11 `ErrorState`/`EmptyState`/`LoadingState`, `StatusChip` (locked/active/draining), `ConfirmDialog` (rollback, remove client, drain), `ReauthDialog` via `StepUp`, `bindFieldErrors`. No `[innerHTML]`, no `bypassSecurityTrust*` — the "Locked by environment" and rotation-checklist copy are static template text or Transloco keys, never raw HTML from the API.

**Approved design handoff.** Frames in [`08-admin.html`](../../../../design/ui/screens/08-admin.html): settings `f-set-cards|secret|locked|node-managed|test|pending-requester|pending-second|history|rollback|reauth|conflict`; nodes `f-nodes-rows|add|drain|rotate`. Missing acceptance-level frames: settings/nodes loading, empty, error and 404; YouTube clients and blocking `oauth_client_in_use`; connected test success; node activate; and proof that an admin session never loads the owner chunk. These follow the locked contract; flag to the owner only if a new visual state is needed (does not reopen the approval or block the task).

**Container/presentation, typed catalogue and lifetime.** `AdminSettingsPage` and `WorkerNodesPage` are separate lazy page containers with route-scoped private stores. `SettingsCard`, `SecretFieldEditor`, `SettingsHistoryDrawer`, `RollbackDialog`, `YouTubeClientsPanel` and node leaves receive readonly typed view contracts and emit typed intents; they do not call repositories or infer locks/roles. The catalogue renderer accepts a closed `SettingFieldDescriptor` union (`text|number|enum|secret|readonly`) and rejects unknown kinds into a safe unsupported state; integration-specific rules remain typed adapters rather than a dynamic global form engine. Explicit `SaveSettingsCommand`, `TestConnectionCommand`, `RollbackSettingsCommand`, `AddNodeCommand`, `ChangeNodeStateCommand` and `RotateNodeKeyIntent` own form-to-wire mapping. Destroy/navigation/session generation clears secret inputs and rejects late test/save/history results.

**Lazy and authority contract.** The guarded owner route-config is not imported by the admin route-config until `ownerGuard` matches; settings and approvals remain separate dynamic page entries, and settings-local barrels do not re-export either page to the initial/admin graph. Client lock badges, owner-only controls and hidden node actions are UX only; backend `OwnerPolicy`, reauth, 404/401/409/412 remain authoritative. Test unauthorized deep links and request-conflict races against the real API.

**Integration prerequisite.** Settings/nodes/governance are planned-only at `00e7d5d…`. Pin merged OpenAPI artifacts from exact header owners `09.10.2-T1` and `06.1.2-T3` before generation, including catalogue descriptors, secret edit semantics, ETag/header variants, YouTube client mutation paths (not just the GET), worker-node activate/drain bodies, roles and every 200/202/204/400/401/404/409/412/502 branch. If a mutation owner/path is absent, keep that control blocked; do not infer it from the mockup.

## Acceptance checks

- **Given** role `owner`, **When** `/admin/settings` loads, **Then** one card renders per row of `GET /admin/settings` with no hard-coded integration list.
- **Given** role `admin`, **When** the settings chunk route is matched, **Then** the client `canMatch` guard blocks navigation **and** the network trace shows the chunk was never requested (the server would return 404 `not_found` if reached).
- **Given** a secret field, **Then** it renders `••••{hint}` only, is never pre-filled, and an untouched secret is **omitted** from the `PUT` body (asserted on the request payload in the spec).
- **Given** `base_url` is edited, **Then** the secret field becomes required before submit is enabled.
- **Given** the render-node card, **Then** the image-key row shows "Node-managed — rotate via runbook" with no edit, test or reveal action.
- **Given** the `youtube` card, **When** removing a client pinned by an active connection, **Then** the API's 409 `oauth_client_in_use` renders a blocking dialog naming the connection count, and the removal does not proceed client-side either way.
- **Given** save returns 401 `reauth_required`, **Then** `ReauthDialog` opens and the same `PUT` is retried exactly once; a second 401 shows the error and does not loop.
- **Given** save returns 412 `setting_conflict`, **Then** local edits are discarded and the card refetches; no silent merge is attempted.
- **Given** save returns 202 `setting_change_pending`, **Then** this task triggers a refetch of `GET /admin/settings/changes?status=pending` (rendered by `10.9.3-T2`) and does not draw its own competing banner.
- **Given** "History" on a card, **When** "Roll back" is chosen, **Then** the confirm action stays disabled until every secret field of that integration has a re-entered value.
- **Given** the worker-nodes tab, **Then** add/drain/activate/rotate-key all require `owner` + re-auth per the API and render the 09 §5.6 rotation checklist as static copy on "Rotate key".
- **Given** the built app, **Then** the settings chunk is absent from the initial bundle and the axe spec passes with tags `wcag2a, wcag2aa, wcag21a, wcag21aa, wcag22aa`.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| `GET /admin/settings` fails | `ErrorState`, no partial catalogue rendered as if complete |
| Secret field left untouched on save | Omitted from the request body entirely — never sent as the masked string or `null` |
| `base_url` changed, secret left untouched | Submit disabled client-side; server's 400 `setting_secret_required` is the fallback if bypassed |
| 502 `setting_test_failed` | Rendered as the returned error text (data, not a key); retry offered; never confused with a save failure |
| Rollback attempted with a secret older than 7 days (server-purged) | Server-side concern (09 F12); the client's mandatory re-entry already covers every case — no special client branch needed |
| Removing the **active** `youtube` client id | Server rejects (D27); client shows the 409/400 mapped copy, no optimistic removal |
| 409 `setting_change_pending` on save | Existing pending change is fetched and shown instead of an error toast |
| 401 on the second attempt after `StepUp` retry | Error surfaced, no further automatic retry (avoids a re-auth loop) |
| Worker node drain while it has active tasks | Server-side business rule; client shows the server's response, no client-side task-count gate |
| A new integration appears in `GET /admin/settings` (e.g. `captcha`, 09 W3 CR-2) | Renders automatically from the catalogue-driven card list — no client deploy needed |
