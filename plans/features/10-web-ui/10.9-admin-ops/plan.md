## 4. Use cases

- **UC-1 Packages** — Given role admin\|owner, When `/admin/billing/packages` loads, Then rows render server-paged from `GET /admin/credit-packages`; create/edit is offered only to owners (`POST`/`PATCH`), a save below the floor shows 400 `package_below_cost` on the price field, a stale `If-Match` shows the reload dialog (412), and deactivate is offered to admins too.
- **UC-2 Promo codes** — Given role admin, When the promos table loads, Then only "deactivate" (`active = false`) is offered; create/edit is hidden (403 `forbidden` if forced) — owner-only per 12.
- **UC-3 Review queue** — Given rows with `status = needs_review`, When the operator opens the resolve dialog, Then they see `expectedAmount` vs `receivedAmount`, `currency`, `method`, `orderCode`, `providerPaymentId` and `providerEvents[]` (`signatureValid`), must type a `note` (required), and choose `grant_expected` / `grant_partial` / `mark_failed`; a 200 renders the returned `AdminPaymentDto` after a refetch, a 202 renders "waiting for owner approval" with `creditGrantRequestId` and does **not** claim the payment was granted, and 409 `payment_already_resolved` shows the row's current state instead.
- **UC-4 Refunds** — Given a pending refund request, When approve/reject is confirmed with a reason, Then the row is refetched and the state shown comes from the server; a 409 `refund_request_not_pending` shows the new state.
- **UC-5 Funding** — Given `/admin/funding`, When it loads, Then the cards render `FundingOverviewDto` verbatim, runway is coloured at < 7 d (warn) and < 3 d (critical), and the "Resume processing" button is enabled only while the `provider_funds_exhausted` flag is open; recording a balance snapshot (`BalanceSnapshotInput`) or a top-up (`TopUpInput`) refetches; Resume needs re-auth, shows the probe result `{ flag, textProbe, imageProbe, reason? }`, and a text-only pass renders the `node_image_project_unfunded` explanation instead of success.
- **UC-6 Settings cards** — Given role owner, When `/admin/settings` loads, Then one card per catalogue integration (A8) renders: non-secret fields editable, secret fields show `••••1234` (`secret_hint`) with "Replace"/"Clear" and are never pre-filled or revealed, changing `base_url` makes the secret required, "Test connection" shows ok or the error code and is disabled for an unsaved base URL while a stored secret would be used, an env-locked integration shows "Locked by environment", the render-node image key row is read-only ("Node-managed — rotate via runbook"), and the `youtube` card additionally lists the OAuth clients from `GET /admin/youtube/clients` with the removal guard (409 `oauth_client_in_use` blocking dialog).
- **UC-7 Save, step-up, conflict** — Given a save, When the API returns 401 `reauth_required`, Then `ReauthDialog` opens and the same request is retried **once**; 412 `setting_conflict` shows the reload dialog; 202 `setting_change_pending` hands over to UC-9's banner; 400 `setting_secret_required`/`setting_invalid` binds to the field; 502 `setting_test_failed` shows the test error, not a save error.
- **UC-8 History, rollback, nodes** — Given a card's "History", When it loads, Then `GET /admin/settings/{integration}/versions` lists who/when/reason/hints; "Roll back" opens a confirm dialog that requires re-entering **every** secret of that integration (old secrets are never restored) and sends the rollback with `If-Match`; the nodes tab lists `GET /admin/worker-nodes` (state, capacity, active tasks, last health pull, key hint) with add, drain, activate and "Rotate key" showing 09 §5.6's rotation steps as a checklist.
- **UC-9 Pending change** — Given a 202 or a page load with `GET /admin/settings/changes?status=pending`, Then the card shows a banner with who requested it, the apply time (24 h time-lock) or "waiting for a second owner", plus "Cancel"; another owner additionally sees "Approve" (`POST …/approve` / `…/cancel`, both re-auth); 409 `setting_change_pending` shows the **existing** pending change instead of an error.
- **UC-10 Public cancel page** — Given a logged-out phone browser opening `/cancel-request#kind=…&id=…&token=…`, When the user confirms once, Then the page posts `{ token }` to `/security/cancel-links/{kind}/{id}`, shows "cancelled", "already applied" or one generic "link invalid or expired", never logs or echoes the token, sends no `Bearer` and no refresh, sets `Referrer-Policy: no-referrer`, ships no third-party asset, and renders the 429 copy under rate limiting.

## 8. Security and privacy

- **Route guards (client) + server policy (real).** `adminGuard` (admin\|owner **and** MFA enrolled) on `/admin/billing/*`; `ownerGuard` on the `/admin/settings` subtree, which lives in its **own lazy chunk** never referenced by the initial bundle (FC8 asserted by 10.10.1-T2); a non-owner hitting `/admin/settings` gets 404 `not_found` from the API — the client renders "permission denied" without ever asking for a 403 (A9, A19).
- **Step-up.** Every mutation on `/admin/settings*`, `/admin/worker-nodes*`, `/admin/funding/resume`, `/admin/settings/changes/*` can return 401 `reauth_required`; the `StepUp` helper opens `ReauthDialog` (password + TOTP, 5-minute window) and retries **once** (SD7, A25). No client-side "assume it worked": every mutation refetches.
- **Secrets.** Write-only, end to end (A24): the UI renders `secret_hint` only, never pre-fills a secret, sends `null`/omits it when untouched, requires a new secret when `base_url` changes, and the rollback dialog demands re-entry of every secret of that integration. No secret, token or hint is written to `console`, telemetry, a URL or an error message; `safe-filename.ts` is used for any download name (SD14).
- **Cancel-link token.** Fragment-only, read once then `history.replaceState`, never logged/echoed/put in a query string, no `Authorization` header and **no refresh** for that call, `Referrer-Policy: no-referrer`, no third-party asset, one confirm, generic copy for unknown/used/expired, 429 copy under the `anon` 60 req/min/IP policy (A4, A5, ST-5, WT-W12 rules).
- **Tenant isolation.** `/admin/*` is the only tenant-bypass site and it is **server-side** (09.2.3-T2's cross-tenant table enumerates every admin route, 09 README §C6:1191); the client never filters another tenant's data and never calls `IgnoreQueryFilters`-shaped endpoints without the admin policy.
- **PII.** `AdminPaymentDto.user` exposes `{ id, email }` only; provider events expose `{ id, type, receivedAt, signatureValid }` — no raw webhook body, no bank account name beyond the DTO; 12 F11 forbids raw bodies in logs and this UI adds none (FC15: `traceId` on `unknown_error`, never tokens/QR payloads/receipt bodies).
- **Audit.** Every mutation here is audited server-side (`[Audited]`, 09.3.6-T1) — the UI shows the resulting state after a refetch and adds no client logging as a substitute (FC15).
- **CSP unchanged.** No third-party origin, no new script, no `bypassSecurityTrust*`; the cancel page and the admin screens are `'self'`-only (D4 as amended by CR-28 for the CAPTCHA, which is not on these pages).
