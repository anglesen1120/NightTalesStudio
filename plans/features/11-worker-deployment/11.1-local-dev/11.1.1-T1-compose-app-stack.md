## Goal

## Design

Append to the existing `docker-compose.yml` (one file, one `name: nighttales`; no `docker-compose.override.yml` is committed):

```yaml
x-app-env: &app-env
  ASPNETCORE_ENVIRONMENT: ${ASPNETCORE_ENVIRONMENT:-Development}
  ConnectionStrings__Postgres: Host=postgres;Port=5432;Database=${POSTGRES_DB:-nighttales};Username=${POSTGRES_USER:-nighttales};Password=${POSTGRES_PASSWORD:?set POSTGRES_PASSWORD in .env}

services:
  api:
    build: { context: ., dockerfile: src/NightTales.Api/Dockerfile }
    image: nighttales-api:dev
    environment:
      <<: *app-env
      ASPNETCORE_HTTP_PORTS: "8080;8081"   # public 8080 + internal 8081 (02 D10) [RULED — README §10 T10]
      # mail/storage settings are appended by 11.1.1-T2
    ports: ["127.0.0.1:5000:8080"]        # only the public listener is published; 8081 stays on the compose network (T10)
    depends_on:
      postgres: { condition: service_healthy }
    healthcheck:
      test: ["CMD-SHELL", "curl -fsS http://127.0.0.1:8080/health/live || exit 1"]
      interval: 5s
      timeout: 3s
      retries: 20
      start_period: 20s
  worker:
    build: { context: ., dockerfile: src/NightTales.Worker/Dockerfile }
    image: nighttales-worker:dev
    environment:
      <<: *app-env
      Worker__HealthPort: "8082"
    ports: ["127.0.0.1:8082:8082"]        # 09.2.6 Worker health port
    depends_on:
      postgres: { condition: service_healthy }
    healthcheck:
      test: ["CMD-SHELL", "curl -fsS http://127.0.0.1:8082/health/ready || exit 1"]
      interval: 10s
      timeout: 5s
      retries: 12
      start_period: 30s
  web:
    profiles: ["web"]                      # image defined by 10.1.1-T2 (10 CR-2)
    build: { context: ./web, dockerfile: Dockerfile }
    image: nighttales-web:dev
    ports: ["127.0.0.1:4200:8080"]         # nginx-unprivileged listens on 8080 (10 D3)
    environment:
      NTS_CSP_MEDIA_ORIGINS: "http://localhost:8333"   # presigned media host = Storage:PublicServiceUrl (10 CR-21)
      NTS_API_UPSTREAM: http://api:8080    # dev-only proxy of /api, /hubs, /health to the api service (10.1.1-T2) (api container port 8080, never the internal 8081)
    depends_on:
      api: { condition: service_healthy }
    healthcheck:
      test: ["CMD-SHELL", "wget -qO- http://127.0.0.1:8080/healthz || exit 1"]   # 10 CR-2
      interval: 10s
      timeout: 5s
      retries: 12
```

Rules the file must keep:

1. **One published port per service, always `127.0.0.1:<host>:<container>`.** No `0.0.0.0`, no bare `ports: ["5000:5000"]`.
2. **Health check on every service, including the ones 11.1.1-T2 and 02.5.2-T3 add.** `depends_on` uses `condition: service_healthy` wherever the dependency has one.
3. **No secret in the compose file.** Every value comes from `.env` (or the service's env file); the file contains `${VAR:?message}` guards for the values that must exist.
4. **No volume for `api`/`worker`.** Both are stateless in dev; `pgdata` (09.1.1-T2) stays the only committed volume, plus the emulator volumes 11.1.1-T2 adds.
5. **No `restart: always`.** A crash-looping Api in dev is a signal to read the log, not to hide.

`.env.example` (committed) grows the app rows, each with a safe dev value and a one-line comment: `ASPNETCORE_ENVIRONMENT=Development`, `POSTGRES_*` (from 09.1.1-T2), and the placeholder rows 11.1.1-T2 fills (`STORAGE_*`, `SMTP_*`) so a developer copies one file. `.env` stays git-ignored (D14).

`docs/dev-setup.md` gains a "Full stack" section: copy `.env.example`, `docker compose up -d --wait`, the service→URL table (Api `http://127.0.0.1:5000`, Worker health `http://127.0.0.1:8082/health/ready`, web `http://127.0.0.1:4200` under profile `web`), and `docker compose down` / `down -v`.

## Steps

1. Read the current `docker-compose.yml` and `.env.example` on disk (09.1.1-T2's output) and keep their style (`name:`, env defaults, healthcheck shape).
2. Add the `api`, `worker` and `web` services with the `x-app-env` anchor; do not touch `postgres`.
3. Extend `.env.example` and append the "Full stack" section to `docs/dev-setup.md`.
4. `docker compose config` → exit 0; then `docker compose config --quiet` with `POSTGRES_PASSWORD` unset → non-zero with the guard message.
5. `docker compose up -d --wait` on a machine with a clean `.env` → `api` and `worker` healthy within their `start_period`; `docker compose --profile web up -d --wait` only when 10.1.1's image exists (skip otherwise, record why).
6. `docker compose ps --format '{{.Service}} {{.Ports}}'` → every published port starts with `127.0.0.1:`.

## Acceptance checks

- [ ] `docker compose config` → exit 0; with `POSTGRES_PASSWORD` unset it fails with `set POSTGRES_PASSWORD in .env`.
- [ ] `docker compose up -d --wait` → `postgres`, `api`, `worker` all `healthy`; `docker compose ps` shows no `unhealthy` or `exited` service.
- [ ] `curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:5000/health/live` → `200`; `curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:8082/health/ready` → `200`.
- [ ] `docker compose ps --format '{{.Ports}}'` → every published entry begins with `127.0.0.1:`; `docker compose port api 8080` → `127.0.0.1:5000`; `docker compose port api 8081` → nothing published.
- [ ] From another host on the LAN, ports 5000 and 8082 refuse the connection.
- [ ] `docker compose --profile web config --services` → includes `web`; `docker compose config --services` → does **not** (the profile is off by default).
- [ ] `git grep -nE '(PASSWORD|SECRET|API_KEY)=[^$]' -- docker-compose.yml` → 0 hits (every value is `${…}`).
- [ ] `git status --porcelain` after `docker compose up -d` → no new tracked-file change (`.env` ignored).
- [ ] 09.1.1-T2's own checks still pass (`docker compose up -d postgres` → healthy; `psql "host=127.0.0.1 user=nighttales dbname=nighttales" -c 'select version()'` → 17.x).

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Host port already used (5000, 8082, 5432, or MPT's 8080 on the M0 trial machine) | the developer sets the host side in a git-ignored `docker-compose.override.yml` and updates the matching client URL; `docs/dev-setup.md` lists this case per service |
| `.env` missing | `docker compose up` fails on the `:?` guard with the message from 09.1.1-T2; nothing starts half-configured |
| `api` starts before `postgres` accepts connections | `depends_on: service_healthy` + `start_period: 20s`; a slow first migration is retried by the Api's own retry policy (09), not by `restart:` |
| Worker health endpoint absent (09.2.6-T1 not landed yet) | the check is temporarily `CMD-SHELL pgrep -f NightTales.Worker` and is upgraded to `/health/ready` in the same PR that lands 09.2.6-T1 — recorded as a note in the compose file, never silently |
| `web` image missing (10.1.1 not landed) | the profile keeps it out of `up`; `docker compose config` still validates the service definition |
| Dockerfiles missing | this task writes them (T24); `docker compose build` fails fast if a path is wrong |
| Compose v2 not installed | the file uses no v1-only key; `docker compose version` is documented as a prerequisite in `docs/dev-setup.md` |
| Rollback | `git checkout docker-compose.yml .env.example docs/dev-setup.md` + `docker compose down`; no data is affected (the emulator volumes belong to 11.1.1-T2) |
