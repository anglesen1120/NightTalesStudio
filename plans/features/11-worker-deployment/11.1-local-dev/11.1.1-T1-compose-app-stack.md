## Goal

`cp .env.example .env && tools/dev/up.sh` on a fresh clone starts the whole platform on one machine **without Docker** — the Homebrew `postgresql@17` service plus `seaweedfs` and `mailpit` processes on `127.0.0.1`, then Api, Worker and `mock-mpt` through `dotnet run` (plus `ng serve` behind `--web`) — with every listener on `127.0.0.1` and every health endpoint green; `tools/dev/down.sh` stops it again. The same services also exist as **optional** Compose services in the file 09.1.1-T2 created, used by 11.5.1-T1's `e2e.yml` (CI only) and image smoke — never required for daily development (D14, F10, 11 CR-1/09 CR-6, 11 CR-16).

## Design

**A. Native path (primary, no Docker).**

**`tools/dev/up.sh`** — Bash 3.2 (`#!/usr/bin/env bash`, no `mapfile`, no associative arrays), `set -euo pipefail`, idempotent, 01 D9 style:

1. `--help`, `--web` (also start `ng serve`), `--skip-storage-init`, and exit 0 ok / 1 check failed / 2 usage-environment. Unknown flag → exit 2.
2. Load `.env` (never echo a value); `.env` missing → exit 2 naming `cp .env.example .env`; a required variable missing → exit 2 naming only the variable.
3. Start/verify, idempotently: the `postgresql@17` brew service (`brew services list` first, `brew services start` only when not started; `listen_addresses = '127.0.0.1'` set by 09.1.1-T2's `db-init.sh`), then `seaweedfs` and `mailpit` as `up.sh`-owned background processes with the loopback command lines of 11.1.1-T2 (pid + log under `.nts/dev/`; skipped when the pid file names a live process of that binary) — never `brew services` for these two, whose stock services bind every interface (11 CR-16). Then run 09.1.1-T2's `tools/dev/db-init.sh` (idempotent role/database) and wait for readiness, each with a timeout and a named failure message: `pg_isready -h 127.0.0.1 -p 5432`; `curl -fsS http://127.0.0.1:9333/cluster/status`; `curl -fsS http://127.0.0.1:8025/api/v1/info` (fallback `nc -z 127.0.0.1 8025`).
4. `tools/dev/storage-init.sh` (11.1.1-T2) once SeaweedFS is ready (skip with `--skip-storage-init`).
5. Start the app hosts in the background with `dotnet run` (SDK 10.0.401), each with its pid and log under the git-ignored `.nts/dev/` (`NTS_HOME` convention, 01 DEC-5), and never start a second copy when the pid is alive:
   - `src/NightTales.Api` with `ASPNETCORE_URLS=http://127.0.0.1:5000`, `Fetcher__Internal__ListenAddress=127.0.0.1` (the 8081 internal listener is code-configured, 02.5.2-T2) and `ConnectionStrings__Postgres` from `.env` (T10);
   - `src/NightTales.Worker` with `Worker__HealthPort=8082`, `ASPNETCORE_ENVIRONMENT=Development`, `RenderNodes:Nodes` = node `mock` → `http://127.0.0.1:8090` + `RENDER_NODE_MOCK_API_KEY` (D13/F26);
   - `tools/mock-mpt` with `ASPNETCORE_URLS=http://127.0.0.1:8090` and the `MOCK_*` rows of `.env`;
   - with `--web`: `ng serve` (plan 10) on `127.0.0.1:4200`.
6. Health loop (timeout `DEV_HEALTH_TIMEOUT`, default 90 s): `curl -fsS http://127.0.0.1:5000/health/live`, `http://127.0.0.1:8082/health/ready`, `http://127.0.0.1:8090/v1/health` with the header fed through stdin (`printf 'x-api-key: %s\n' "$MOCK_API_KEY" | curl -fsS -H @- …`, D9: no key in argv); any failure → exit 1 naming the service and pointing at its log file (never a silent half-up stack).
7. Print the service→URL table (Api `http://127.0.0.1:5000`, Worker health `http://127.0.0.1:8082/health/ready`, mock `http://127.0.0.1:8090`, Mailpit UI `http://127.0.0.1:8025`, storage `http://127.0.0.1:8333`, web `http://127.0.0.1:4200` with `--web`).

**`tools/dev/down.sh`** — same conventions: `--help`, `--services` (also `brew services stop postgresql@17`; the `seaweedfs`/`mailpit` processes are always stopped with the rest), `--volumes` (the only flag that discards dev data: natively it deletes `.nts/dev/seaweedfs` and drops + recreates only the `.env` database (`DROP DATABASE … WITH (FORCE)`, then `db-init.sh`) — it never touches the shared Homebrew data directory, which also holds the `NTS_TEST_PG` databases; in the compose variant the `seaweedfs`/`pgdata` volumes), default = stop only the processes `up.sh` started (pid files under `.nts/dev/`), then exit 0; a pid that is not ours is never killed.

**B. Optional Compose variant (e2e / image smoke; CI).**

Append to the existing `docker-compose.yml` (one file, one `name: nighttales`; no `docker-compose.override.yml` is committed):

```yaml
x-app-env: &app-env
  ASPNETCORE_ENVIRONMENT: ${ASPNETCORE_ENVIRONMENT:-Development}
  ConnectionStrings__Postgres: Host=postgres;Port=5432;Database=${POSTGRES_DB:-nighttales};Username=${POSTGRES_USER:-nighttales};Password=${POSTGRES_PASSWORD:?set POSTGRES_PASSWORD in .env}

services:
  api:
    build: { context: ., dockerfile: src/NightTales.Api/Dockerfile }
    image: nighttales-api:dev
    environment:
      <<: *app-env
      ASPNETCORE_HTTP_PORTS: "8080;8081"   # public 8080 + internal 8081 (02 D10) [RULED — README §10 T10]
      # mail/storage settings are appended by 11.1.1-T2
    ports: ["127.0.0.1:5000:8080"]        # only the public listener is published; 8081 stays on the compose network (T10)
    depends_on:
      postgres: { condition: service_healthy }
    healthcheck:
      test: ["CMD-SHELL", "curl -fsS http://127.0.0.1:8080/health/live || exit 1"]
      interval: 5s
      timeout: 3s
      retries: 20
      start_period: 20s
  worker:
    build: { context: ., dockerfile: src/NightTales.Worker/Dockerfile }
    image: nighttales-worker:dev
    environment:
      <<: *app-env
      Worker__HealthPort: "8082"
    ports: ["127.0.0.1:8082:8082"]        # 09.2.6 Worker health port
    depends_on:
      postgres: { condition: service_healthy }
    healthcheck:
      test: ["CMD-SHELL", "curl -fsS http://127.0.0.1:8082/health/ready || exit 1"]
      interval: 10s
      timeout: 5s
      retries: 12
      start_period: 30s
  web:
    profiles: ["web"]                      # image defined by 10.1.1-T2 (10 CR-2)
    build: { context: ./web, dockerfile: Dockerfile }
    image: nighttales-web:dev
    ports: ["127.0.0.1:4200:8080"]         # nginx-unprivileged listens on 8080 (10 D3)
    environment:
      NTS_CSP_MEDIA_ORIGINS: "http://localhost:8333"   # presigned media host = Storage:PublicServiceUrl (10 CR-21)
      NTS_API_UPSTREAM: http://api:8080    # dev-only proxy of /api, /hubs, /health to the api service (10.1.1-T2) (api container port 8080, never the internal 8081)
    depends_on:
      api: { condition: service_healthy }
    healthcheck:
      test: ["CMD-SHELL", "wget -qO- http://127.0.0.1:8080/healthz || exit 1"]   # 10 CR-2
      interval: 10s
      timeout: 5s
      retries: 12
```

Rules the file must keep:

1. **One published port per service, always `127.0.0.1:<host>:<container>`.** No `0.0.0.0`, no bare `ports: ["5000:5000"]`.
2. **Health check on every service, including the ones 11.1.1-T2 and 02.5.2-T3 add.** `depends_on` uses `condition: service_healthy` wherever the dependency has one.
3. **No secret in the compose file.** Every value comes from `.env` (or the service's env file); the file contains `${VAR:?message}` guards for the values that must exist.
4. **No volume for `api`/`worker`.** Both are stateless in dev; `pgdata` (09.1.1-T2) stays the only committed volume, plus the emulator volumes 11.1.1-T2 adds.
5. **No `restart: always`.** A crash-looping Api in dev is a signal to read the log, not to hide.

**C. Docs and env.**

`.env.example` (committed, created by 09.1.1-T2) grows the app rows, each with a safe dev value and a one-line comment: `ASPNETCORE_ENVIRONMENT=Development`, `POSTGRES_*` (from 09.1.1-T2), `MOCK_*`, and the placeholder rows 11.1.1-T2 fills (`STORAGE_*`, `SMTP_*`) so a developer copies one file. `.env` stays git-ignored (D14).

`docs/dev-setup.md` gains a "Native stack (default)" section — `cp .env.example .env`, `brew install postgresql@17 seaweedfs mailpit awscli`, `tools/dev/up.sh`, `tools/dev/down.sh`, the service→URL table above — and an "Optional Compose stack" section — `docker compose up -d --wait`, `docker compose --profile web up -d --wait`, `docker compose down` / `down -v` — stating that the compose path is for e2e / image smoke and is never required for daily development (11 CR-16).

## Steps

1. Read the current `.env.example`, `docker-compose.yml`, `tools/dev/db-init.sh` and `docs/dev-setup.md` on disk (09.1.1-T2's output) and keep their style.
2. Write `tools/dev/up.sh` and `tools/dev/down.sh` (executable bit set); `shellcheck` and `bash -n` clean under bash 3.2.
3. Add the `api`, `worker` and `web` services to the optional compose file with the `x-app-env` anchor; do not touch `postgres`.
4. Extend `.env.example` and append the two sections to `docs/dev-setup.md`.
5. Native smoke: `tools/dev/up.sh` twice (second run idempotent) → all endpoints 200, loopback-only audit; `tools/dev/down.sh` → no leftover process.
6. Compose variant (where Docker is present): `docker compose config` → exit 0; then `docker compose config --quiet` with `POSTGRES_PASSWORD` unset → non-zero with the guard message; `docker compose up -d --wait` on a clean `.env` → `api` and `worker` healthy; `docker compose --profile web up -d --wait` only when 10.1.1's image exists (skip otherwise, record why); `docker compose ps --format '{{.Service}} {{.Ports}}'` → every published port starts with `127.0.0.1:`.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| A brew formula is missing | `up.sh` exits 1 naming the formula and the `brew install <formula>` hint; it never installs anything silently |
| Host port already used natively (5000, 8081, 8082, 8090, 5432, 8333, 1025, 8025, or MPT's 8080 on the M0 trial machine) | `up.sh` exits 1 naming the port; the port is overridable per service through `.env` (`DEV_API_PORT`, `MOCK_PORT`, …) and the client URLs follow the same rows |
| Compose variant started next to the native services | 5432/8333/1025 collide → run one path at a time; the override file (git-ignored) can move the host side, as 09.1.1-T2 records for `postgres` |
| Docker absent or the daemon down | only the compose variant is affected; the native path is unaffected and `up.sh` never calls Docker (11 CR-16) |
| `.env` missing | exit 2 naming `cp .env.example .env`; nothing starts half-configured |
| `api` starts before PostgreSQL accepts connections | `up.sh` waits on `pg_isready` before `dotnet run`; the Api's own retry policy (09) covers a slow first migration — never `restart:` |
| Worker health endpoint absent (09.2.6-T1 not landed yet) | `up.sh` reports the Worker as unhealthy with its log path (the health check cannot be faked); the compose variant uses `CMD-SHELL pgrep -f NightTales.Worker` temporarily and is upgraded in the same PR that lands 09.2.6-T1 — recorded as a note in the compose file, never silently |
| `web` missing (10.1.1 not landed) | `--web` / the `web` profile is opt-in; `docker compose config` still validates the service definition |
| Dockerfiles missing | this task writes them (T24); the compose variant's `docker compose build` fails fast if a path is wrong |
| Rollback | `git checkout docker-compose.yml .env.example docs/dev-setup.md` + remove `tools/dev/{up,down}.sh`; `tools/dev/down.sh` (or `docker compose down`) stops the stack; no data is affected unless `--volumes` |
