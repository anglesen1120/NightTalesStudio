## Goal

A developer has a real SMTP sink and a real S3-compatible endpoint on the laptop: mail sent by the Api is readable in Mailpit's UI, and the storage client used by music sync, assets and the image-relay fixtures finds the three dev buckets after one idempotent command (D14, D2, F16).

## Design

**Compose additions** (append to `docker-compose.yml`; nothing above changes):

```yaml
  storage:
    image: chrislusf/seaweedfs@sha256:<digest filled at implementation>   # D14: digest-pinned
    command: ["server", "-dir=/data", "-s3", "-s3.port=8333"]
    ports: ["127.0.0.1:8333:8333"]      # S3 API
    volumes: ["seaweedfs:/data"]
    healthcheck:
      test: ["CMD-SHELL", "curl -fsS http://127.0.0.1:9333/cluster/status || exit 1"]
      interval: 5s
      timeout: 3s
      retries: 30
      start_period: 15s
  mail:
    image: axllent/mailpit@sha256:<digest filled at implementation>       # D14: digest-pinned
    environment:
      MP_SMTP_AUTH_ACCEPT_ANY: "1"        # dev only: any credentials accepted
      MP_SMTP_AUTH_ALLOW_INSECURE: "1"
    ports:
      - "127.0.0.1:1025:1025"             # SMTP
      - "127.0.0.1:8025:8025"             # UI + API
    healthcheck:
      test: ["CMD-SHELL", "wget -qO- http://127.0.0.1:8025/api/v1/info >/dev/null || exit 1"]
      interval: 5s
      timeout: 3s
      retries: 20
```

Ports 8333 (SeaweedFS S3), 9333 (its master status API), 1025/8025 (Mailpit SMTP/UI) are the projects' documented defaults ⚠️ — confirmed at implementation, then recorded in `.env.example` and `docs/dev-setup.md`.

**`tools/dev/storage-init.sh`** (new, Bash, 01 D9):

- Inputs: `STORAGE_ENDPOINT` (default `http://127.0.0.1:8333`), `STORAGE_ACCESS_KEY`, `STORAGE_SECRET_KEY`, `STORAGE_REGION` (default `us-east-1`) from the environment or `.env`. Missing required variable → exit 2 with a named message; never a credential on the command line.
- Creates `nt-media-dev`, `nt-public-dev`, `nt-music-dev` with `s3api create-bucket` (idempotent: an existing bucket is success, not an error), then the D15 prefixes `music/` and `music-evidence/` inside `nt-music-dev` as zero-byte marker objects.
- Runs the S3 calls through a **pinned `amazon/aws-cli` image** (`docker run --rm --env-file .env --network host` on Linux, `host.docker.internal` on macOS) so no host `aws` installation is required and no credential ever appears in `argv` [INFERENCE: helper container, see Notes].
- Verifies at the end with `s3api head-bucket` for each of the three names; any failure → exit 1 naming the bucket.
- Re-running after `docker compose down -v` recreates everything; the script never deletes a bucket or an object.

**`.env.example` additions** (safe dev values, no real secret): `STORAGE_ENDPOINT=http://127.0.0.1:8333`, `STORAGE_ACCESS_KEY=dev`, `STORAGE_SECRET_KEY=dev-secret-local`, `STORAGE_REGION=us-east-1`, `STORAGE_BUCKET_MEDIA=nt-media-dev`, `STORAGE_BUCKET_PUBLIC=nt-public-dev`, `STORAGE_BUCKET_MUSIC=nt-music-dev`, `SMTP_HOST=127.0.0.1`, `SMTP_PORT=1025`, `SMTP_USER=dev`, `SMTP_PASSWORD=dev-secret-local`, `SMTP_FROM=dev@nighttales.local`.

**Wiring.** `api` and `worker` gain `STORAGE__ENDPOINT=http://storage:8333`, `SMTP__HOST=mail`, `SMTP__PORT=1025` (compose service names; the loopback `STORAGE_ENDPOINT`/`SMTP_HOST` values above are for host-side tools such as `tools/dev/storage-init.sh` and curl checks, T41) plus the other `STORAGE__*` / `SMTP__*` rows (from `.env`, `__` separators) and `depends_on: storage: {condition: service_healthy}` where the Api actually needs storage at startup; `mail` needs no `depends_on`. SeaweedFS in dev runs with its own credentials (`-s3` reads `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY` from the environment) — set them in the `storage` service from the same `.env` rows so client and server agree.

## Steps

1. Append the `storage` and `mail` services with digests pinned and loopback ports.
2. Add the `STORAGE_*`/`SMTP_*` rows to `.env.example` and reference them from `api`/`worker`; document the Mailpit UI URL in `docs/dev-setup.md`.
3. Write `tools/dev/storage-init.sh` (01 D9 style, `--help`, exit 0/1/2) and `shellcheck` it.
4. `docker compose up -d storage mail --wait` → both healthy; `docker compose exec storage sh -c 'ls /data'` shows data.
5. Run `tools/dev/storage-init.sh` twice; the second run is a no-op with exit 0.
6. Send one mail through the Api's local sign-up/reset path (or `swaks`/`curl` to 1025) and read it in the Mailpit UI at `http://127.0.0.1:8025`.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Port 8333/1025/8025 busy | host side moves in a git-ignored `docker-compose.override.yml`; the script's `STORAGE_ENDPOINT` and `SMTP_PORT` follow (both are `.env` values, not literals) |
| SeaweedFS volume from an older layout | `docker compose down -v` (dev data is disposable); the script recreates the buckets |
| `storage-init.sh` runs before `storage` is healthy | the script waits on `docker compose ps --format json` for up to 60 s, then exits 1 naming the service (never a silent partial run) |
| A bucket already exists with a different region | `create-bucket` returns `BucketAlreadyOwnedByYou` → treated as success; a real error (403) exits 1 with the S3 code |
| Mailpit image has no shell for the healthcheck | the check falls back to a TCP probe (`nc -z 127.0.0.1 8025`) and the deviation is recorded in the compose comment ⚠️ |
| Emulator image rebuilt by the vendor | digests are pinned, so nothing changes until a human updates the pin; the update is one line + a re-run of the checks |
| Rollback | remove the two services and the script; `docker compose down -v`; the Api/Worker storage+SMTP env rows revert with the file (git) |

## Notes

- [INFERENCE] The script needs an S3 client. The host may not have `aws`, and MinIO's `mc` is AGPL (E12) → a pinned `amazon/aws-cli` helper container run with `--env-file` keeps credentials out of `argv` and adds no dependency. If the TL prefers a stdlib-only Python helper, it must implement SigV4 by hand — not recommended for three `create-bucket` calls.
- [OPEN] Mailpit's `/api/v1/info` path and the SeaweedFS `/cluster/status` path are ⚠️ docs-based, not repo facts; the digests are deliberately left as `<digest filled at implementation>` because no plan asserts one.
- Do not add MinIO, Grafana, Redis, Elasticsearch or a second S3 emulator: F16/D14 fix the choice (SeaweedFS, Apache-2.0).
- The dev bucket names are the `<env> = dev` case of D15; nothing here may rename them, or 05.3.2-T2 and 09.7.2 diverge between local and cloud.
