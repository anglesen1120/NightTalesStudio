## Goal

A developer has a real SMTP sink and a real S3-compatible endpoint on the laptop **without Docker**: mail sent by the Api is readable in Mailpit's UI at `127.0.0.1:8025`, and the storage client used by music sync, assets and the image-relay fixtures finds the three dev buckets after one idempotent command (D14, D2, F16, 11 CR-16).

## Design

**Native services (primary path — no Docker).** `tools/dev/up.sh` (11.1.1-T1) starts and verifies the Homebrew binaries as its own processes (pid files under `.nts/dev/`), **not** through `brew services`: the stock formula services cannot take flags, `weed server` would bind every interface and put its volume server on 8080 (MPT, 01 D4), and Mailpit's defaults are `[::]:1025` / `[::]:8025` (11 CR-16):

- `seaweedfs` — `weed server -ip=127.0.0.1 -ip.bind=127.0.0.1 -dir=.nts/dev/seaweedfs -volume.port=8084 -master.volumeSizeLimitMB=64 -s3 -s3.port=8333` (volume server moved off 8080; filer on its default 8888, master on 9333, gRPC ports +10000, all loopback; `volumeSizeLimitMB=64` because the default size leaves no free volume slot for a new bucket, 04.2.3-T1 rehearsal). S3 API on `127.0.0.1:8333`, master status on `127.0.0.1:9333`; flag names and the pinned formula version are recorded in `docs/dev-setup.md` (⚠️ confirmed at implementation, T12).
- `mailpit` — `mailpit --smtp 127.0.0.1:1025 --listen 127.0.0.1:8025 --smtp-auth-accept-any --smtp-auth-allow-insecure` (the same SMTP auth behaviour as the compose `MP_SMTP_AUTH_ACCEPT_ANY`/`MP_SMTP_AUTH_ALLOW_INSECURE`, so `.env`'s `SMTP_USER`/`SMTP_PASSWORD` work); flag names ⚠️, T12.
- Health: `curl -fsS http://127.0.0.1:9333/cluster/status`, `curl -fsS http://127.0.0.1:8025/api/v1/info`, `nc -z 127.0.0.1 1025`.

**Optional Compose variant** (append to `docker-compose.yml`; nothing above changes; used by `e2e.yml` in CI and image smoke only — 11 CR-16):

```yaml
  storage:
    image: chrislusf/seaweedfs@sha256:<digest filled at implementation>   # D14: digest-pinned
    command: ["server", "-dir=/data", "-s3", "-s3.port=8333"]
    ports: ["127.0.0.1:8333:8333"]      # S3 API
    volumes: ["seaweedfs:/data"]
    healthcheck:
      test: ["CMD-SHELL", "curl -fsS http://127.0.0.1:9333/cluster/status || exit 1"]
      interval: 5s
      timeout: 3s
      retries: 30
      start_period: 15s
  mail:
    image: axllent/mailpit@sha256:<digest filled at implementation>       # D14: digest-pinned
    environment:
      MP_SMTP_AUTH_ACCEPT_ANY: "1"        # dev only: any credentials accepted
      MP_SMTP_AUTH_ALLOW_INSECURE: "1"
    ports:
      - "127.0.0.1:1025:1025"             # SMTP
      - "127.0.0.1:8025:8025"             # UI + API
    healthcheck:
      test: ["CMD-SHELL", "wget -qO- http://127.0.0.1:8025/api/v1/info >/dev/null || exit 1"]
      interval: 5s
      timeout: 3s
      retries: 20
```

Ports 8333 (SeaweedFS S3), 9333 (its master status API), 1025/8025 (Mailpit SMTP/UI) are the projects' documented default ports ⚠️ — set explicitly with loopback binds natively (8084 = SeaweedFS volume server, moved off MPT's 8080) — confirmed at implementation, then recorded in `.env.example` and `docs/dev-setup.md` (T12).

**`tools/dev/storage-init.sh`** (new, Bash, 01 D9):

- Inputs: `STORAGE_ENDPOINT` (default `http://127.0.0.1:8333`, the native service; the compose variant leaves it as-is for host-side tools, T41), `STORAGE_ACCESS_KEY`, `STORAGE_SECRET_KEY`, `STORAGE_REGION` (default `us-east-1`) from the environment or `.env`. Missing required variable → exit 2 with a named message; never a credential on the command line.
- S3 client: the host `aws` CLI (Homebrew `awscli`, Apache-2.0 ✅ — or `uvx --from awscli`, the form 11.4.1-T1 records) by default — the native path must not need Docker (11 CR-16, T11); the pinned `amazon/aws-cli` image (`docker run --rm --env-file …`) remains the fallback when `docker` is present but `aws` is not, so CI keeps working. Credentials reach the client through the environment/`--env-file`, never `argv`. The container branch alone rewrites a loopback `STORAGE_ENDPOINT` (`127.0.0.1`/`localhost`) to `host.docker.internal`, since a loopback address is the helper container's own namespace; macOS Docker/colima resolve that name to the host, and the host clients and readiness probe keep the endpoint as written.
- Creates `nt-media-dev`, `nt-public-dev`, `nt-music-dev` with `s3api create-bucket` (idempotent: an existing bucket is success, not an error), then the D15 prefixes `music/` and `music-evidence/` inside `nt-music-dev` as zero-byte marker objects.
- Verifies at the end with `s3api head-bucket` for each of the three names; any failure → exit 1 naming the bucket.
- Re-running after a dev data reset (`tools/dev/down.sh --volumes` natively, `docker compose down -v` for the variant) recreates everything; the script never deletes a bucket or an object.

**`.env.example` additions** (safe dev values, no real secret): `STORAGE_ENDPOINT=http://127.0.0.1:8333`, `STORAGE_ACCESS_KEY=dev`, `STORAGE_SECRET_KEY=dev-secret-local`, `STORAGE_REGION=us-east-1`, `STORAGE_BUCKET_MEDIA=nt-media-dev`, `STORAGE_BUCKET_PUBLIC=nt-public-dev`, `STORAGE_BUCKET_MUSIC=nt-music-dev`, `SMTP_HOST=127.0.0.1`, `SMTP_PORT=1025`, `SMTP_USER=dev`, `SMTP_PASSWORD=dev-secret-local`, `SMTP_FROM=dev@nighttales.local`.

**Wiring.** Native: `api` and `worker` (started by `up.sh`) read the flat `.env` storage rows exported under the canonical `StorageSettings` property names — `STORAGE_ENDPOINT` → `Storage__ServiceUrl=http://127.0.0.1:8333`, `STORAGE_ACCESS_KEY` → `Storage__AccessKey`, `STORAGE_SECRET_KEY` → `Storage__SecretKey`, `STORAGE_REGION` → `Storage__Region` and `STORAGE_BUCKET_MEDIA`/`__PUBLIC`/`__MUSIC` → `Storage__Buckets__Media`/`__Public`/`__Music` (the flat rows are shell input only, never .NET config; `Storage__ENDPOINT`/`Storage__BUCKET_MEDIA` would bind as `Storage:Endpoint`/`Storage:BucketMedia`, neither is supported by `AddStorage` after the canonical-only cutover) — and the mail rows as the canonical `Email__Smtp__Host=127.0.0.1`, `Email__Smtp__Port=1025`, `Email__Smtp__Username`/`__Password` and `Email__From__Address` (the flat `.env` names stay `SMTP_*`; exporting them as `SMTP__*` would lose to the `Email:Smtp:*` defaults both hosts commit, 09.2.6-T3) — the loopback values are the default for both the app hosts and host-side tools (T41). Compose variant: the `api` and `worker` services override the storage host to `http://storage:8333` and the mail host to `mail:1025` (service names) and add `depends_on: storage: {condition: service_healthy}` where the Api actually needs storage at startup; `mail` needs no `depends_on`. SeaweedFS in dev runs with its own credentials (`-s3` reads `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY` from the environment) — set them from the same `.env` rows on both paths so client and server agree.

## Steps

1. Document and pin the `seaweedfs`/`mailpit` command lines (flags above), data dir and formula versions in `docs/dev-setup.md`; wire the `seaweedfs` credentials from `.env` (T12).
2. Append the `storage` and `mail` services to the optional compose file with digests pinned and loopback ports.
3. Add the `STORAGE_*`/`SMTP_*` rows to `.env.example` and reference them from `api`/`worker` (both paths); document the Mailpit UI URL.
4. Write `tools/dev/storage-init.sh` (01 D9 style, `--help`, exit 0/1/2, host `aws` first with the container fallback) and `shellcheck` it.
5. Native: `tools/dev/up.sh` → both services reachable; run `tools/dev/storage-init.sh` twice (second run is a no-op with exit 0).
6. Compose variant (where Docker is present): `docker compose up -d storage mail --wait` → both healthy; `docker compose exec storage sh -c 'ls /data'` shows data.
7. Send one mail through the Api's local sign-up/reset path (or `swaks`/`curl` to 1025) and read it in the Mailpit UI at `http://127.0.0.1:8025`.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Port 8333/1025/8025 busy | the port is overridable per service through `.env` (`DEV_STORAGE_PORT`, `SMTP_PORT`, …) on the native path, or the host side moves in a git-ignored `docker-compose.override.yml` for the variant; `STORAGE_ENDPOINT`/`SMTP_PORT` follow (both are `.env` values, not literals) |
| The `seaweedfs` process is not running when `storage-init.sh` starts | the script waits for `http://127.0.0.1:9333/cluster/status` for up to 60 s, then exits 1 naming the service (never a silent partial run) |
| SeaweedFS data dir from an older layout | `tools/dev/down.sh --volumes` (native) or `docker compose down -v` (variant); dev data is disposable and the script recreates the buckets |
| No `aws` CLI on the host | the script falls back to the pinned `amazon/aws-cli` container when Docker is available, else exits 2 naming the missing client (`brew install awscli`, or `uvx --from awscli`) |
| A bucket already exists with a different region | `create-bucket` returns `BucketAlreadyOwnedByYou` → treated as success; a real error (403) exits 1 with the S3 code |
| Mailpit's `/api/v1/info` unavailable | the health check falls back to a TCP probe (`nc -z 127.0.0.1 8025`) and the deviation is recorded in the docs ⚠️ |
| An emulator upgrade | native: the pinned formula version in `docs/dev-setup.md` is bumped by hand; compose: the pinned digest is bumped; both are explicit human actions (T12) |
| Rollback | remove `tools/dev/storage-init.sh` and the two compose services; `tools/dev/down.sh` (or `docker compose down -v`) stops the stack; the Api/Worker storage+SMTP env rows revert with the file (git) |
