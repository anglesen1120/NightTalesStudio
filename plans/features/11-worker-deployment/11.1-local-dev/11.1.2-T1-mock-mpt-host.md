## Goal

`tools/mock-mpt` serves the real `render-node.v1` surface (`NightTales.RenderNode.Server`, D5) over an in-memory backend: seven routes, a task walking `queued → running → checking → succeeded` over `MOCK_RENDER_SECONDS`, canned per-aspect media, an SRT derived from the submitted `video_script`, valid `render-status.v1`/`render-node-health.v1`, and the 05 D14 fixtures — no MPT, GPU, OpenAI or egress (D2, D3, D14; 05 D4/D14). In local development it runs **natively** with `dotnet run` on `127.0.0.1:8090` (started by `tools/dev/up.sh`, 11 CR-16); the same project is also the optional compose service (`expose`-only) used by `e2e.yml` in CI.

## Design

**Project.** `tools/mock-mpt/NightTales.MockMpt.csproj` — `Microsoft.NET.Sdk.Web`, in `NightTales.ci.slnf`, referencing **only** `NightTales.RenderNode.Server` + `NightTales.RenderNode.Contract` (the architecture test fails otherwise); .NET 10, `sealed`, nullable, warnings-as-errors (00 §5.4). `Program.cs` binds `RenderNodeServer:*`, registers the four seams and calls `app.MapRenderNodeV1(options)`. `Backend/FakeRenderBackend.cs` implements `IRenderBackend` (submit starts the clock; cancel/delete semantics; `OpenOutputAsync` streams the canned file); `Backend/ProgressClock.cs` maps elapsed ÷ `MOCK_RENDER_SECONDS` to `state`/`stage`/`percent`; `Backend/FakePostProcessor.cs` fills `output`, `check` (from the `render-check.v1.*` fixtures) and `images` at the terminal tick; `Health/MockNodeHealthSource.cs` builds `render-node-health.v1` from in-process values (no shell-out — Q1); `Fixtures/FixtureLoader.cs`; `Media/` resolves the canned file and writes the SRT; `README.md` documents the env table, the keywords and the "canned file is always 10 s while `MOCK_VIDEO_SECONDS` only changes the reported duration" rule.

**Envelope and auth** come from the core: one `x-api-key` constant-time compared to `RenderNodeServer:ApiKey` (= `MOCK_API_KEY`), the 2,097,152-byte cap, `RenderNodeJson.Strict`, `SubmitValidator` order, `adapter_route_not_found` fallback. The mock adds **no route, field or code**.

**Progress** (05 D4): 0 → `queued`/0 %; then `voice` 5–29, `subtitles` 30–39, `images` 40–49, `assembling` 50–99; at the terminal tick `checking` → terminal, 100 only when terminal, `percent` never decreasing. `MOCK_RENDER_SECONDS` default 20 (D14), accepted range ≥ 1 s, validated at start (invalid → exit 2 with a named message).

**Fixtures.** Loaded once at start from the fixtures directory (read-only bind mount in compose, `COPY` in the image). A submit carrying `__fixture_<name>__` replays that fixture's state; `MOCK_FIXTURE=<name>` makes every task replay it. The body is served verbatim except the contract-generated fields (`task_id`, `render_job_id`, timestamps); the per-fixture ignore list lives in the tests.

**Canned media (F25).** Multi-stage `Dockerfile`: `dotnet publish -r linux-x64 --self-contained` (D3/E8) → a media stage running `ffmpeg -f lavfi -i testsrc2=size=1920x1080:rate=30 -f lavfi -i sine=frequency=440 -t 10 -c:v libx264 -c:a aac -movflags +faststart landscape.mp4` (and the same at `1080x1920`) → final stage with the output, `/media/*.mp4` and the fixtures. Nothing is committed; the tests use the same recipe. The SRT splits `video_script` into sentences (the boundary rule the 05 contract pins) and spreads one cue per sentence over the canned duration.

**Compose service** (appended by this task; `expose`, never `ports`; the **optional variant** used by `e2e.yml` in CI and image smoke — the daily path is native, 11 CR-16):

```yaml
  mock-mpt:
    build: { context: ., dockerfile: tools/mock-mpt/Dockerfile }
    environment:
      # [DECISION — the fallback is ≥ 32 bytes because the core rejects a shorter `RenderNodeServer:ApiKey`
      #  (05 D15 S3): the earlier 12-byte `dev-mock-key` made a fresh checkout (no .env) exit 2, so the
      #  container could never be healthy. Same value as .env.example / tools/dev/up.sh.]
      RenderNodeServer__ApiKey: ${MOCK_API_KEY:-dev-mock-api-key-local-0123456789}
      RenderNodeServer__MaxConcurrentTasks: ${MOCK_MAX_CONCURRENT:-2}
      MOCK_RENDER_SECONDS: ${MOCK_RENDER_SECONDS:-20}
      MOCK_VIDEO_SECONDS: ${MOCK_VIDEO_SECONDS:-10}
      MOCK_FAIL_RATE: ${MOCK_FAIL_RATE:-0}
      MOCK_FAIL_MODE: ${MOCK_FAIL_MODE:-}
      MOCK_IMAGE_REPORT: ${MOCK_IMAGE_REPORT:-ok}
    volumes: ["./worker-node/contract/fixtures:/fixtures:ro"]
    expose: ["8090"]
    healthcheck:
      test: ["CMD-SHELL", "curl -fsS -H \"x-api-key: $${MOCK_API_KEY:-dev-mock-api-key-local-0123456789}\" http://127.0.0.1:8090/v1/health || exit 1"]
      interval: 5s
      timeout: 3s
      retries: 20
```

**Dev host (native, primary).** `tools/dev/up.sh` (11.1.1-T1, 11 CR-16) runs `dotnet run --project tools/mock-mpt` with `ASPNETCORE_URLS=http://127.0.0.1:8090`, `RenderNodeServer__ApiKey` = `MOCK_API_KEY`, the other `MOCK_*` rows and `ASPNETCORE_ENVIRONMENT=Development`; the fixtures are read from `worker-node/contract/fixtures/` in the working tree (no mount needed) and the canned media comes from the same build recipe. Bound loopback-only, per T10.

Reachable as `http://127.0.0.1:8090` natively (loopback only) and `http://mock-mpt:8090` from the compose network only (D14) in Development; in staging the same image runs `ASPNETCORE_ENVIRONMENT=Staging` (never Development) and serves HTTPS on 8090 with its own self-signed certificate, pinned in the staging `RenderNodes:Nodes` config like a real node [RULED — README §10 T44] (D20 H2). Kestrel inside a container binds all interfaces because a container cannot bind the host's `127.0.0.1`; the adapter's `ListenAddress` guard (D6) does not apply to a container that publishes nothing, and the mock's README says so, so nobody copies this onto a node.

**Dev Worker wiring** (executed by 11.3.3-T1's seeder path): `RenderNodes:Nodes:[{ Name: "mock", BaseUrl: "http://127.0.0.1:8090", TlsCertSha256: null, Capacity: ${MOCK_MAX_CONCURRENT:-2} }]` natively (`http://mock-mpt:8090` in the compose variant), `RENDER_NODE_MOCK_API_KEY=${MOCK_API_KEY}`, `ASPNETCORE_ENVIRONMENT=Development` — the only configuration where `RenderNodeConnectionFactory` accepts `http://` (D13, F26, 11 CR-16).

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| `MOCK_RENDER_SECONDS` invalid or `MOCK_MAX_CONCURRENT` < 1 | exit 2 at start with a named message; no listener opens |
| Fixtures directory missing/empty | exit 2 naming the path; never a silent empty fixture set |
| Canned media missing | the image build asserts both files → a build failure, not a runtime 500 |
| An aspect with no canned file | 400 `adapter_contract_violation` at submit (the validator owns the enum), never a 500 at download |
| Worker restarts while the mock keeps running | tasks are gone → polls 404 → the Worker's `render_lost` path; intended (D5) |
| Someone publishes 8090 to the host (compose) or binds it beyond loopback (native) | the compose service uses `expose` and the native run is started with `ASPNETCORE_URLS=http://127.0.0.1:8090`; this file's port audit (`lsof` natively, `docker compose ps` in the variant) fails on a change; the mock must not be reachable from the LAN |
| Staging uses the mock as a render node (D1) | allowed: it is a real node to the Worker; staging runs `ASPNETCORE_ENVIRONMENT=Staging` (never Development) and serves HTTPS on 8090 with its own self-signed certificate pinned in `RenderNodes:Nodes`, so `http://` stays Development-only [RULED — README §10 T44] (D20 H2) |
| Rollback | remove the service and the project; no state to migrate |

## Notes

- [RULED — README §10 T33, amended by CR-16] Fixture delivery: the native run reads `worker-node/contract/fixtures/` in the working tree (edits need no rebuild); the compose variant uses a read-only bind mount; `COPY` in CI/staging.
- [RULED — README §10 T44] (D20 H2) Staging never sets `ASPNETCORE_ENVIRONMENT=Development`: the staging deployment mounts the mock's own self-signed certificate and puts its SHA-256 fingerprint in the staging `RenderNodes:Nodes[i]:TlsCertSha256`, exactly like a real node; `http://127.0.0.1:8090` (native) and `http://mock-mpt:8090` (compose) are the Development-only values.
- [INFERENCE] `MOCK_FIXTURE` is introduced here: D14 lists the other `MOCK_*` names but no fixture selector, while 05 D14 requires the mock to serve the fixtures.
- Ownership boundary: `IImagePlanSink` is **bound** here and its default `ok` report keeps a render succeeding; the generator `tools/mock-mpt/Images/MockImageReport.cs` and every `MOCK_IMAGE_REPORT` value belong to 03.4.3-T2, the mode wiring/tests to 11.1.2-T2. No file is written by two tasks. The mock never runs ffmpeg at request time, reads a task directory or probes a GPU — a test needing MPT's real failure text belongs to 11.3.5-T2's `FakeMptServer` (D18).
