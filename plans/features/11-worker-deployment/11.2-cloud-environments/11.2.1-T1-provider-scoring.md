## Goal

Produce one evidence-backed, reproducible decision: which cloud provider, which region, which GPU type, at which dated prices, with which managed services — recorded in `DECISIONS.md` so that 11.2.2-T1 can write IaC against real resource names. The output is a decision record plus a scoring harness, not cloud resources.

Hard gates (a provider that fails any of these is not scored further):
GPU VRAM ≥ 16 GB with 24 GB preferred, one GPU per node (F28, D9); managed PostgreSQL 17 with base backup + continuous WAL archive (E10); **block volumes attachable to a VM with encryption at rest, snapshots and a published GB-month price, in two availability zones (or locations) for `storage-backup-<env>`**; **a published internet egress price for `media.<domain>` downloads** (T74); private networking between services; a provider-native secret manager; a container registry; a telemetry backend option that is not self-hosted AGPL (E12, F16, O6). **No object-storage product is scored and no managed-storage hard gate exists** (11 CR-15: SeaweedFS is self-hosted in every env — D21 — and `weed filer.backup` replaces H9's replication path, 11.4.1-T2).

Scored criteria (weights in `criteria.json`, sum 1.0): GPU price per hour (billing granularity: per-second/per-minute/per-hour), stop/start of GPU nodes, monthly price at the expected duty cycle, region latency to Vietnam and to `api.openai.com` / the YouTube Data API, block-volume GB-month price + volume snapshot price + internet egress price for `media.<domain>` (T74, 11 CR-15), PostgreSQL price (PITR included?), data-processing terms and region/VN data rules ⚠️, VPN/bastion support, FQDN egress-rule support ⚠️ (F14), container-registry price, telemetry option, an internal/private CA option for `storage-<env>.internal` ⚠️ (11 CR-15; object lock ✅ and conditional put ✅ are SeaweedFS features per D21, not provider criteria), support and VN payment options (`11 §5.6` as amended by 11 CR-15).

## Design

Deliverables live in `infra/scoring/` (this folder's code home until 11.2.2-T1 creates `infra/modules/`):

- `infra/scoring/criteria.json` — the machine-readable checklist: `{ "hard_gates": [...], "criteria": [{ "id", "weight", "direction", "unit" }] }`. Every criterion id matches a heading in `11 §5.6`; `hard_gates` is the T74 set (11 CR-15) — **no object-storage product appears anywhere in the file**.
- `infra/scoring/captures/<provider>-<yyyy-mm-dd>.json` — one immutable capture per provider: per criterion `{ "value", "unit", "source_url", "captured_on", "captured_by", "quote" }`. A capture without `source_url` + `captured_on` is invalid.
- `infra/scoring/score.py` — Python stdlib only; reads `criteria.json` + all captures, applies the hard gates, normalises each criterion across providers (0–1 by min/max or by the declared `scale`), multiplies by the weight, prints a ranked table and a per-criterion diff; exit 0 = scored, 1 = a hard gate failed for the top provider or a capture is invalid, 2 = usage/environment error. Arguments are paths only; no secret is needed, and any provider API token used to fetch prices comes from an env var (never argv).
- `infra/scoring/latency.md` — the measurement method and the raw numbers: `ping`/`curl -w '%{time_connect}'` from a temporary instance **in the candidate region** to `api.openai.com`, `www.googleapis.com` and the owner's VN vantage point (or a provider-published latency tool if it exists). Until a region is rented the numbers are ⚠️ and the file carries the exact command to re-run. This is the only allowed ⚠️ in the exit artefact besides the flagged provider features (F14 FQDN egress, the private CA for `storage-<env>.internal`, T74's two-zone snapshot support).
- The decision text itself: a dated block appended to `DECISIONS.md` §10.4 [INFERENCE: §10.4 is the hardware/cost section CR-8 already touched; a new §10.x sub-entry is equally acceptable and changes nothing here] containing provider, region, GPU type + VRAM, prices with units, billing granularity, stop/start, the latency evidence, PG17 PITR confirmation, the block-volume price with encryption + snapshot support + snapshot retention, the two-zone/location answer for `storage-backup-<env>`, the `media.<domain>` internet egress price, the private-CA answer for `storage-<env>.internal`, private networking, FQDN egress support yes/no, VPN/bastion, secret manager, registry, telemetry backend, data terms (11 CR-15), and a "revisit triggers" list.

Cost model (not a price assertion — a formula): `cost/video = (GPU price per hour × node hours) ÷ videos per hour`; the map 11.6.3-T1 fills the denominator; this task supplies the numerator. Duty-cycle sensitivity (how many hours/day the GPU must run) is computed for the expected render volume, and the result feeds 11.2.2-T4's decision to keep staging GPU-free (F08).

## Steps

1. Copy the `11 §5.6` checklist into `infra/scoring/README.md` and derive `criteria.json`; set weights so the sum is exactly 1.0 and document why each weight is what it is.
2. Pick 2–3 providers that plausibly satisfy the hard gates; `python3 infra/scoring/score.py --check-criteria` validates the file and exits 0.
3. For each provider, open the official pricing page and the managed-PostgreSQL page, capture numbers + the URL + the date into a capture file, with the quoted line where a number could be misread (per GPU-hour vs per node-hour; egress per GB; storage per GB-month).
4. Determine stop/start and billing granularity from the official docs, not from a forum; a "quoted only" price is recorded as `"value": null, "note": "quote required"` and the provider is dropped if the missing criterion is a hard gate.
5. Rent one smallest instance in each finalist region for < 1 hour (⚠️ the only spend in this task), run the latency commands from `latency.md`, and record raw numbers with timestamps; then destroy the instance.
6. Confirm PG17 PITR wording (base backup + WAL archive, E10), the block-volume gates (encryption at rest, snapshots, GB-month price, snapshot pricing, two zones/locations — T74), the `media.<domain>` internet egress price, the private-CA option (T81: provider private CA preferred; when absent the fallback is an owner-generated offline root, never client cert pinning) and the FQDN-egress answer (F14 ⚠️) in writing (doc quote or support reply) per finalist (11 CR-15).
7. Run `score.py` over all captures; review the ranked table and the per-criterion diff. Two criteria that are within noise must not decide the outcome — say so explicitly in the record.
8. Write the decision block into `DECISIONS.md` §10.4, tag it `(11 11.2.1-T1)`, and fix the provider-native resource names that `plan.md` §3 currently leaves generic — including the storage VMs, their block volumes, the snapshot policy and the private CA for `storage-<env>.internal`/`storage-backup-<env>.internal` (T81, 11 CR-15); the TL applies those names.
9. Re-run `score.py` from a clean checkout of `infra/scoring/` (no network) and confirm the record's ranking is reproducible from the captures alone.

## Tests

- `python3 -m unittest infra.scoring.test_score` — class `TestScore` with `test_weights_must_sum_to_one`, `test_hard_gate_vram_15gb_rejects_provider`, `test_missing_source_url_is_invalid_capture`, `test_missing_captured_on_is_invalid_capture`, `test_ranking_is_stable_across_runs`, `test_exit_2_on_no_arguments`, `test_exit_1_when_top_provider_fails_a_hard_gate`.
- `python3 infra/scoring/score.py --check-criteria` and `python3 infra/scoring/score.py captures/*.json` run in CI in 11.5.1-T2's `node.yml` shellcheck/self-test job (the harness is shell/Python only, no cloud credentials).
- Manual, recorded in `latency.md`: `curl -w '%{time_connect} %{time_total}\n' -o /dev/null -s https://api.openai.com/v1/models` and `ping -c 20 <region endpoint>` from the rented instance.
- No unit test asserts a price value (prices are data, not behaviour) — the test doubles live in the test file as fixtures with obviously fake numbers.

## Failure handling and edge cases

- **Price page requires a login or a quote**: record `"value": null, "note": "quote required"`; a provider whose hard-gate criterion is quote-only is dropped and the reason is written in the record. Never estimate a price.
- **Two finalists within noise**: the tie-break order is documented (latency to OpenAI first, then GPU price, then egress price) and applied by the script, not by prose.
- **Latency cannot be measured before the region exists**: `latency.md` stays ⚠️ and the numbers become a mandatory pre-apply check in 11.2.2-T1 step 1; the decision is provisional on that check only.
- **FQDN egress unsupported** (likely, F14 ⚠️): the record says so explicitly, so 11.3.2-T1 keeps the IP/port allow-list design and no FQDN rule is written into IaC.
- **A hard gate fails only after real provisioning** (e.g. VRAM smaller than advertised): the revisit-trigger list is the rollback path — the affected tasks are not started, and the second-ranked provider is applied from the same captures.
- **Capture drift** (page changed after capture): captures are immutable and dated; a later page is a *new* capture with a new date, never an edit of the old one.
- **No account/payment method available for a finalist**: recorded as a hard-gate failure with the reason ("VN payment options", `11 §5.6`), not silently skipped.
- **Rollback**: this task creates no cloud resource except the < 1-hour latency instances, which are destroyed in step 5; destroying them is the only cleanup. Nothing else must be reverted if the decision is later revised (the captures stay as evidence).
