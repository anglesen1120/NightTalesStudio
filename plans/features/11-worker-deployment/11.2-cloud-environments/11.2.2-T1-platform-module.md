# 11.2.2-T1 — `platform` and `render-node` modules and the `staging` environment

| Story | Size | Area | Depends on | Blocks | Phase / flag |

## Goal

One OpenTofu codebase produces the whole D15 resource list for an environment — including the two self-hosted storage hosts of D21 (11 CR-15) — with `staging` as the first instantiation and `gpu_node_count = 0` (F08). After this task, `staging` exists from code, is re-appliable without drift, exposes only non-secret outputs, and hands 11.3.3-T1 the node tuple (`BaseUrl`, `GpuModel`, `Name`) it needs for `RenderNodes:Nodes[i]`.

## Inputs

- `11.2.1-T1` decision record: provider-native resource names, region, GPU type, dated prices, FQDN-egress answer (F14 ⚠️), telemetry backend.
- `../README.md` D15 (resource list + secret paths), **D21** (storage hosts in their own `storage` subnet, volumes, `storage-sg`/`storage-backup-sg`, DNS, sizing, snapshots, LB media host — 11 CR-15), §10 **T74-T94**, D11, D13, D16, D17, F08, E10, E11, E13; `plan.md` §3 (module interface), §8, §9.
- `infra/bootstrap` (T76) must exist first: the PostgreSQL instance + the `nts_tofu` database for the `pg` state backend, its local state encrypted (⚠️ OpenTofu state encryption, verified in step 1 here) and kept offline by the owner (11 CR-15).
- `../../../11-worker-deployment.md` §5.1 (topology, subnets, egress), §5.5 (release flow the LB and registry must support).
- OpenTofu ≥ the release 11.2.1-T1 records as current, pinned in `infra/envs/<env>/versions.tf` (MPL-2.0, E11) — exact version chosen at implementation ⚠️, never floating `latest`.
- Nothing is inherited from upstream tasks: the provider account, DNS zone and payment method must exist (owner setup, part of 11.2.1-T1's payment-options answer).

## Design

**Layout** (module vs environment; no copy-paste of resources into envs):

```
infra/
  bootstrap/               # T76/T83 (11 CR-15): the PostgreSQL instance + nts_tofu, local encrypted state, kept offline
  modules/platform/        # network, subnets app/render/fetcher/storage (T77), PG (R from bootstrap), storage hosts + volumes + storage-sg/storage-backup-sg (D21), internal CA (T81), registry, hosts, LB, DNS, TLS, bastion, secret containers
  modules/render-node/      # one GPU node: instance, boot disk, render-subnet attachment, node security group (8090 from app CIDR only)
  envs/staging/             # provider+backend, module calls, variables, outputs, terraform.tfvars.example
  envs/prod/                # 11.2.2-T4 — same modules, prod values
  checks/{assert-plan.sh,check-ws.sh,check-egress.sh}
  README.md
```

**`platform` contract** — inputs: `env`, `region`, `domain`, `gpu_node_count`, `nodes` (list of `{ name, gpu_type }`), CIDR plan, `image_tags`, `telemetry_backend_*`, `dns_zone_id`, `bastion_ssh_public_key`. Outputs (non-secret only): `lb_address`, `app_base_url`, `staging_base_url`, `db_host`, `db_port`, `db_name`, `bucket_names` (env-derived constants — 11.4.1-T1 creates the buckets over the S3 API, D21), `storage_hosts` (list of `{ name, private_ip }`), `storage_endpoint` (`https://storage-<env>.internal`, gateway published on TCP 443, T77), `storage_public_url` (`https://media.<domain>` prod / `https://media.staging.<domain>` staging, T83), `registry_url`, `subnet_ids`, `bastion_endpoint`, `otel_collector_endpoint`, `secret_path_prefix`, `render_nodes` (list of `{ name, private_ip, gpu_model }`) (11 CR-15).

**Invariants the code must hold**

- No secret value is ever a resource attribute, variable default, output or tag; outputs carry the *path prefix* only.
- No resource in the `app` or `storage` subnet has a public IP; only the LB and the bastion are internet-facing, and only the LB has an ingress rule from `0.0.0.0/0` on 443/80.
- Tags on every resource: `env`, `project = nts`, `managed-by = opentofu` — so cost reports and the 11.6.3-T1 cost/video number can be attributed.
- `render-node` is instantiated per node from `nodes`, never with a hard-coded IP; the node security group allows TCP 8090 from `worker-sg` only (D20 H3; D11).
- `staging` runs `ASPNETCORE_ENVIRONMENT=Staging` (never Development); its render node is mock-mpt over HTTPS on 8090 with its own self-signed certificate, pinned in the staging `RenderNodes:Nodes` config like a real node (D20 H2).
- Remote state per env is the `pg` backend (T76, 11 CR-15): database `nts_tofu`, which locks (T15's object-storage locking scheme is superseded), on the PostgreSQL instance `infra/bootstrap` creates (T83); bootstrap holds only the instance + `nts_tofu`, with its local state encrypted by OpenTofu state encryption ⚠️ (feature verified in step 1) and kept offline by the owner.
- Buckets are **not** IaC resources (D21): the module exposes the four env-derived names and the two storage hosts; 11.4.1-T1 owns creation, policies, CORS and lifecycle through the S3 API (D20 H20 as amended).
- The S3 gateway is the only storage service reachable off a storage host, on TCP 443 (T77/T78): `storage-sg` opens 443 from `api-sg`, `worker-sg`, the render subnet, the LB and the VPN/bastion range (22/443 operator access, T86), 8888/18888 from `storage-backup-sg` only (`filer.backup -filerProxy`), 9327 from `worker-sg` only (metrics) — never `fetcher-sg` (02 CR-1); `storage-backup-sg` opens only 22/443 from the VPN/bastion range and 9327 from `worker-sg` (T86); `worker-sg` adds inbound 4318 from `storage-backup-sg` for the `nts_backup_lag_seconds` push (T85); 9333/8080/18080 and gRPC stay host-local; both volumes are provider-encrypted and carry `prevent_destroy`, and only the primary volume has daily snapshots, retained 7 days (T87) (D21, 11 CR-15).
- Everything the module creates is idempotent: a second `apply` on a converged env changes nothing.

## Steps

1. Create `infra/modules/platform` and `infra/modules/render-node` skeletons with the variables/outputs above and `versions.tf` pinning the provider and OpenTofu versions (11.2.1-T1's record); create `infra/bootstrap` (T76/T83, 11 CR-15) — the PostgreSQL 17 instance + the `nts_tofu` database, PITR and `prevent_destroy` on — and verify the `pg` backend locks and that OpenTofu state encryption works on the bootstrap state (⚠️ feature check; the local state stays offline).
2. Implement the network: network, four subnets (`app`, `render`, `fetcher`, `storage` — T77) with route tables, NAT for `app`, no route for `fetcher` into `app`/`render`/`storage`, security groups `api-sg`, `worker-sg` and `storage-backup-sg` enumerated rule by rule (deny-by-default; node 8090 from `worker-sg` only; `storage-backup-sg` opens only 22/443 from the VPN/bastion range and 9327 from `worker-sg` — T86; `worker-sg` adds inbound 4318 from `storage-backup-sg` — T85; `fetcher-sg` is 11.2.2-T2's and never a `storage-sg` source, D20 H3, T77, 11 CR-15); assert the CIDR plan does not overlap with the operator's VPN range.
3. Reference the managed PostgreSQL 17 `infra/bootstrap` created (T83 — private endpoint, PITR + daily snapshots already on); create the app database and the app role; store nothing but the connection *path* in the secret container.
4. Create the registry with its six repositories, and the two storage hosts of D21 (11 CR-15): `storage-<env>` and `storage-backup-<env>` (each a VM in its own `storage` subnet, T77, the backup in another zone/location; encrypted block volumes at `/var/lib/nts/seaweedfs` with `prevent_destroy`), `storage-sg` (443 from `api-sg`/`worker-sg`/the render subnet/the LB and 22/443 from the VPN/bastion range — never `fetcher-sg`; 8888/18888 from `storage-backup-sg` only for `filer.backup -filerProxy`; 9327 from `worker-sg` only for the metrics scrape; 9333/8080/18080 stay host-local — T78/T86, 11 CR-15), the internal root CA and the trust-store install on every host (T81), DNS `storage-<env>.internal` + `storage-backup-<env>.internal` and daily volume snapshots retained 7 days on the primary volume only — the backup volume is not snapshotted (T87). Implement DNS records and the bastion/VPN endpoint; wire the certificate validation wait into the outputs (`lb_address` not exported before the cert is issued) so a caller never gets a half-ready endpoint. Create the env-scoped OIDC role whose trust pins `job_workflow_ref = <owner>/<repo>/.github/workflows/deploy.yml@refs/heads/main` and the environment claim (D20 H7).
8. Create the D15 secret containers (empty) at the per-service paths `nts/<env>/{api,worker,fetcher,shared}/<NAME>` and `nts/<env>/node/<name>/<NAME>` (D20 H3/T51), plus `nts/<env>/storage/<NAME>` (the T91/T95 identity names incl. `NTS_BACKUP_PROBE`) readable only by the two storage hosts' role, together with its T94 exact-name reads (`shared/STORAGE_ACCESS_KEY`/`STORAGE_SECRET_KEY`, `NTS_MUSIC_WRITE_KEY`/`_SECRET`, `NTS_MUSIC_READ_KEY`/`_SECRET`, `NTS_PREVIEW_WRITE_KEY`/`_SECRET`) — no api/worker/fetcher/node role grants `storage/*` (T91/T94, 11 CR-15); no value is written anywhere in this task.

- No unit test asserts provider resource attributes (they are configuration); the harness tests the assertion script, which is the behaviour that can break.

## Failure handling and edge cases

- **Quota/capacity**: GPU or instance capacity unavailable in the region → re-apply after the provider's capacity frees, or switch the region variable (11.2.1-T1's record lists the fallback region); a GPU-capacity failure for staging is acceptable because `gpu_node_count = 0`.
- **DNS zone not delegated**: the owner must add the NS records at the registrar; until then the ACME/managed-certificate validation stalls. The task exports `lb_address` and records the pending record in `infra/README.md`; no resource is faked.
- **Certificate still validating**: outputs wait for the certificate; a second `apply` is the recovery. Never export `lb_address` before validation (that would hand a 11.5.1-T1 smoke step a false failure).
- **State lock stuck after an interrupted apply**: the `pg` backend holds the lock row (T76, 11 CR-15); release it with the backend's documented procedure — or `tofu force-unlock <lock-id>` only after confirming no apply is running — then re-apply; never `tofu state` surgery without a state backup.
- **Partial apply** (a networking or quota error mid-run): re-run `apply` — the configuration is convergent, and no resource is created outside the module.
- **PG major-version drift**: the module pins PostgreSQL **17**; an offering that only has 16 is a hard-gate failure recorded in 11.2.1-T1, not a version bump here (E10's PITR wording is version-specific).
- **Volume/database destroy attempt**: `prevent_destroy` aborts the run by design (11 CR-15); bucket data removal is 11.4.1-T1/13's job, not a plan side effect.
- **Storage host or volume lost**: recreate the host from IaC and reattach the volume (or its latest snapshot); a lost volume is restored from `nt-backup-<env>` by 11.4.1-T3/11.6.1-T1 (D21, T80); after a backup-volume loss, rebuild or rollback, `filer.backup` is started once with `-initialSnapshot` to re-seed `nt-backup-<env>`, then restarted without it (T89, 11 CR-15).
- **A secret accidentally referenced as a value**: `assert-plan.sh` fails the plan; the fix is to reference the secret *container*, never its value.
- **Rollback**: `tofu destroy -chdir=infra/envs/staging` after lifting the `prevent_destroy` guard from the disposable staging storage volumes — the env state guards only the volumes; the database guard lives in `infra/bootstrap` (T90; the guard aborts the run by design, 11 CR-15); prod is untouched because it has a separate state. Nothing in this task is a one-way door except the DNS zone delegation, which is a registrar-level record the owner controls.

## Notes

- `prod`'s directory exists here as a stub so both envs share the modules from day one (F08's point); 11.2.2-T4 completes it.
- Creating empty secret containers here keeps secrets out of OpenTofu while giving 11.5.2-T1 a stable, reviewable path list (`nts/<env>/<NAME>`).
- Cost control: staging runs the smallest available instances and no GPU; the staging GPU node exists only during rehearsals (D1) and is destroyed after (`tofu apply -var gpu_node_count=1` → `nts-node provision --env staging` → `tofu destroy` of that node or the whole env's node resources).
- [RULED — README §10 T76, 11 CR-15] State is the `pg` backend in `nts_tofu`, which locks, so no `plan.sh`/`apply.sh` stale-lock wrapper is needed; `infra/bootstrap` owns the instance + database and its local state stays encrypted and offline.
- [RULED — README D21, T74-T94, 11 CR-15] `infra/bootstrap` is a prerequisite of this task (it creates the PG instance + `nts_tofu` the platform module references, T83); the two storage hosts are IaC, the buckets are not (11.4.1-T1 over the S3 API), and 11.4.1-T2 runs SeaweedFS on the hosts this task creates. Internal TLS trusts a root CA (T81), never a pinned or self-signed cert; clients use `https://storage-<env>.internal` on 443.
