# 11.2.2-T1 — `platform` and `render-node` modules and the `staging` environment

| Story | Size | Area | Depends on | Blocks | Phase / flag |
|---|---|---|---|---|---|

## Goal

One OpenTofu codebase produces the whole D15 resource list for an environment, with `staging` as the first instantiation and `gpu_node_count = 0` (F08). After this task, `staging` exists from code, is re-appliable without drift, exposes only non-secret outputs, and hands 11.3.3-T1 the node tuple (`BaseUrl`, `GpuModel`, `Name`) it needs for `RenderNodes:Nodes[i]`.

## Inputs

- `11.2.1-T1` decision record: provider-native resource names, region, GPU type, dated prices, FQDN-egress answer (F14 ⚠️), telemetry backend.
- `../README.md` D15 (resource list + secret paths), D11, D13, D16, D17, F08, E10, E11, E13; `plan.md` §3 (module interface), §8, §9.
- `../../../11-worker-deployment.md` §5.1 (topology, subnets, egress), §5.5 (release flow the LB and registry must support).
- OpenTofu ≥ the release 11.2.1-T1 records as current, pinned in `infra/envs/<env>/versions.tf` (MPL-2.0, E11) — exact version chosen at implementation ⚠️, never floating `latest`.
- Nothing is inherited from upstream tasks: the provider account, DNS zone and payment method must exist (owner setup, part of 11.2.1-T1's payment-options answer).

## Design

**Layout** (module vs environment; no copy-paste of resources into envs):

```
infra/
  modules/platform/        # network, subnets app/render/fetcher, PG, buckets, registry, hosts, LB, DNS, TLS, bastion, secret containers
  modules/render-node/      # one GPU node: instance, boot disk, render-subnet attachment, node security group (8090 from app CIDR only)
  envs/staging/             # provider+backend, module calls, variables, outputs, terraform.tfvars.example
  envs/prod/                # 11.2.2-T4 — same modules, prod values
  checks/{assert-plan.sh,check-ws.sh,check-egress.sh}
  README.md
```

**`platform` contract** — inputs: `env`, `region`, `domain`, `gpu_node_count`, `nodes` (list of `{ name, gpu_type }`), CIDR plan, `image_tags`, `telemetry_backend_*`, `dns_zone_id`, `bastion_ssh_public_key`. Outputs (non-secret only): `lb_address`, `app_base_url`, `staging_base_url`, `db_host`, `db_port`, `db_name`, `bucket_names`, `registry_url`, `subnet_ids`, `bastion_endpoint`, `otel_collector_endpoint`, `secret_path_prefix`, `render_nodes` (list of `{ name, private_ip, gpu_model }`).

**Resources** (names per 11.2.1-T1; `C` = created by IaC, `R` = referenced):

| Item | Kind | Notes |
|---|---|---|

| NAT for app-subnet egress (registry pulls, OTLP) | C | egress 443/53/123 only; no inbound |
| Managed PostgreSQL 17 | C | private only, storage encrypted, PITR on (base backup + WAL archive, E10), automated daily snapshots; app role without superuser; `prevent_destroy` |
| Buckets `nt-media-<env>`, `nt-public-<env>`, `nt-music-<env>`, `nt-backup-<env>` | C | private + SSE on creation; `prevent_destroy`; 11.4.1-T1 applies its policies through these storage resources (D20 H20) |
| Container registry (+ per-image repositories) | C | `api`, `worker`, `fetcher`, `web`, `mock-mpt`, `nts-migrate` (D16) |
| `app` host ×3 (API ×2, Worker ×1) | C | no public IP; container runtime only; per-service instance roles (registry pull + their own `nts/<env>/{api,worker}/*` + `nts/<env>/shared/*`; the API role cannot read `worker/*` or `node/*`); IMDS disabled or IMDSv2 hop limit 1 where the provider needs it at boot (D20 H3, H10); the fetcher host ×1 is 11.2.2-T2's |

| LB access logs | C | enabled to the log bucket; the query string is dropped for `/api/v1/channels/*/callback` and `/hubs/*` (OAuth `code`/`state`, hub `ticket`) (06 CR-10) |
| `web` target group + path rules (10 CR-1) | C | the `web` container on the two API hosts, port 8080, health `GET /healthz`; listener rules `/api/*`, `/hubs/*`, `/health/*` → API target group, default → `web`; one origin per env (`app.<domain>`, `staging.<domain>`) so the SPA never needs CORS (`../../10-web-ui/README.md` D3) |
| DNS zone records `app.<domain>`, `staging.<domain>` | C | zone `R` or `C` per 11.2.1-T1 |
| Bastion + VPN endpoint | C | operator SSH and `nts-node deploy` transport (D11, O5); no operator key in state |
| Secret containers at `nts/<env>/{api,worker,fetcher,shared}/<NAME>` and `nts/<env>/node/<name>/<NAME>` | C | D15 names as **empty** secrets, split per service (D20 H3/T51): `shared` = `DB_CONNECTION`, `DP_KEK`, `STORAGE_ACCESS_KEY`/`_SECRET`; `api` = `JWT_SIGNING_KEY`, `OPENAI_API_KEY`, `SMTP_PASSWORD`, `YOUTUBE_CLIENT_SECRET`; `worker` = `RENDER_NODE_<NAME>_API_KEY`; `fetcher` = `FETCHER_API_TOKEN` (the container path is created here; the fetcher host and its role are 11.2.2-T2's, D20 H3); values are 11.5.2-T1's |
| OTel Collector container (on the Worker host [INFERENCE], D15 lists no collector host) | C | Apache-2.0 (E11); serves `otel_collector_endpoint` in the `app` subnet; exports OTLP to the backend chosen in 11.2.1-T1 (D17) |
| GPU nodes | C via `render-node` | `count = gpu_node_count`; `staging` passes 0 |
| Monitoring/alerts backend | R | never self-hosted AGPL (E12, F16, O6) |

**Invariants the code must hold**

- No secret value is ever a resource attribute, variable default, output or tag; outputs carry the *path prefix* only.
- No resource in the `app` subnet has a public IP; only the LB and the bastion are internet-facing, and only the LB has an ingress rule from `0.0.0.0/0` on 443/80.
- Tags on every resource: `env`, `project = nts`, `managed-by = opentofu` — so cost reports and the 11.6.3-T1 cost/video number can be attributed.
- `render-node` is instantiated per node from `nodes`, never with a hard-coded IP; the node security group allows TCP 8090 from `worker-sg` only (D20 H3; D11).
- `staging` runs `ASPNETCORE_ENVIRONMENT=Staging` (never Development); its render node is mock-mpt over HTTPS on 8090 with its own self-signed certificate, pinned in the staging `RenderNodes:Nodes` config like a real node (D20 H2).
- Remote state per env in the provider's object storage with locking (⚠️ D15); if locking is unsupported, a lease object + a `tofu` pre-flight check inside `apply.sh` [INFERENCE, `plan.md` §10 item 4].
- Everything the module creates is idempotent: a second `apply` on a converged env changes nothing.

## Steps

1. Create `infra/modules/platform` and `infra/modules/render-node` skeletons with the variables/outputs above and `versions.tf` pinning the provider and OpenTofu versions (11.2.1-T1's record).
2. Implement the network: network, three subnets with route tables, NAT for `app`, no route for `fetcher` into `app`/`render`/storage, security groups `api-sg` and `worker-sg` enumerated rule by rule (deny-by-default; 8090 from `worker-sg` only, `fetcher-sg` is 11.2.2-T2's, D20 H3); assert the CIDR plan does not overlap with the operator's VPN range.
3. Implement managed PostgreSQL 17 with PITR + daily snapshots + a private endpoint; create the database and the app role; store nothing but the connection *path* in the secret container.
4. Create the four buckets with SSE and `prevent_destroy`, and the registry with the six repositories.
5. Implement the three `app` hosts (API ×2, Worker ×1; no public IP, IMDS disabled or IMDSv2 hop limit 1, D20 H10) with per-service instance roles (registry pull + their own `nts/<env>/{api,worker}/*` + `nts/<env>/shared/*`; the API role cannot read `worker/*` or `node/*`, D20 H3) and the OTel Collector as a container on the Worker host, serving `otel_collector_endpoint`.
6. Implement the LB: listener 443 with the managed certificate, 80 → 301, health check against the API readiness path used by D16 (`/health/ready`), `preserve_host` on; leave `/hubs/*` routing to 11.2.2-T3.
7. Implement DNS records and the bastion/VPN endpoint; wire the certificate validation wait into the outputs (`lb_address` not exported before the cert is issued) so a caller never gets a half-ready endpoint. Create the env-scoped OIDC role whose trust pins `job_workflow_ref = <owner>/<repo>/.github/workflows/deploy.yml@refs/heads/main` and the environment claim (D20 H7).
8. Create the D15 secret containers (empty) at the per-service paths `nts/<env>/{api,worker,fetcher,shared}/<NAME>` and `nts/<env>/node/<name>/<NAME>` (D20 H3/T51); no value is written anywhere in this task.
9. Write `infra/envs/staging` (module calls + `terraform.tfvars.example`) and `infra/envs/prod` as a stub that 11.2.2-T4 completes, both with the remote backend block.
10. Write `infra/checks/assert-plan.sh` (exit 0/1/2, `set -euo pipefail`, shellcheck clean) asserting the §9 checklist against `tofu show -json`: subnet names, `gpu_node_count`, 4 buckets, LB 443/TLS ≥ 1.2/WebSockets, no `0.0.0.0/0` ingress except LB 443/80, no public IP on app hosts, security groups `api-sg`/`worker-sg` with 8090 from `worker-sg` only, no secret value.
11. Write `infra/README.md`: apply order, `TF_VAR_*` file location, the tuple hand-over to `RenderNodes:Nodes[i]`, the staging-GPU-on-demand recipe (D1: `-var gpu_node_count=1` then `nts-node provision --env staging`, destroyed after the rehearsal).
12. `fmt`/`validate`/`plan` both envs, run the positive and negative `assert-plan.sh` cases, then apply staging and re-plan (must be empty).

## Outputs

- `infra/modules/platform/`, `infra/modules/render-node/`, `infra/envs/staging/`, `infra/envs/prod/` (stub), `infra/checks/assert-plan.sh`, `infra/README.md`.
- A live `staging` with: network + 3 subnets, PG 17 with PITR, 4 buckets, registry, 3 app hosts + the OTel Collector container, LB with a valid TLS certificate and DNS records, bastion/VPN, the D15 secret containers (empty, per-service paths), `gpu_node_count = 0`, `ASPNETCORE_ENVIRONMENT=Staging` with mock-mpt as an HTTPS pinned node (D20 H2/H3).
- The non-secret outputs other tasks consume: `registry_url`, `lb_address`, `staging_base_url`, `db_*`, `bucket_names`, `subnet_ids`, `bastion_endpoint`, `otel_collector_endpoint`, `secret_path_prefix`, `render_nodes`.
- The provider-native name table 11.2.2-T2/T4, 11.3.2-T1, 11.4.1-T1, 11.5.1-T1 and 11.5.2-T1 build on.

- [ ] `curl -sS -o /dev/null -w '%{http_code}' https://staging.<domain>/health/live` returns 502/503 (the LB is up, no API container deployed yet — 200 becomes the expectation after 11.5.1-T1); no connection or TLS error.

## Tests

- `infra/checks/assert-plan.sh staging plan.json` (positive) and the same script against a mutated plan (negative) — both run in CI in 11.5.1-T2's `node.yml` shellcheck/self-test job with no cloud credentials.
- `tofu -chdir=infra/envs/staging validate` and `tofu -chdir=infra/envs/prod validate` as separate CI steps.
- Live, operator-run and recorded in `infra/README.md`'s verification log: `dig`, `curl -sSI`, `openssl s_client` (TLS 1.2 pass / TLS 1.1 fail), `apply` then `plan -detailed-exitcode`, and `tofu destroy` on staging followed by `tofu plan` on prod still empty.
- Manual check (recorded): create a test file in `nt-backup-<env>` and confirm `tofu destroy` on staging refuses while the bucket exists (the `prevent_destroy` guard).
- No unit test asserts provider resource attributes (they are configuration); the harness tests the assertion script, which is the behaviour that can break.

## Failure handling and edge cases

- **Quota/capacity**: GPU or instance capacity unavailable in the region → re-apply after the provider's capacity frees, or switch the region variable (11.2.1-T1's record lists the fallback region); a GPU-capacity failure for staging is acceptable because `gpu_node_count = 0`.
- **DNS zone not delegated**: the owner must add the NS records at the registrar; until then the ACME/managed-certificate validation stalls. The task exports `lb_address` and records the pending record in `infra/README.md`; no resource is faked.
- **Certificate still validating**: outputs wait for the certificate; a second `apply` is the recovery. Never export `lb_address` before validation (that would hand a 11.5.1-T1 smoke step a false failure).
- **State lock stuck after an interrupted apply** (⚠️ provider feature): unlock via the provider's documented procedure and re-apply; never `tofu state` surgery without a state backup.
- **Partial apply** (a networking or quota error mid-run): re-run `apply` — the configuration is convergent, and no resource is created outside the module.
- **PG major-version drift**: the module pins PostgreSQL **17**; an offering that only has 16 is a hard-gate failure recorded in 11.2.1-T1, not a version bump here (E10's PITR wording is version-specific).
- **Bucket destroy attempt**: `prevent_destroy` aborts the run by design; data removal is 11.4.1-T1/13's job, not a plan side effect.
- **A secret accidentally referenced as a value**: `assert-plan.sh` fails the plan; the fix is to reference the secret *container*, never its value.
- **Rollback**: `tofu destroy -chdir=infra/envs/staging` (own state); prod is untouched because it has a separate state. Nothing in this task is a one-way door except the DNS zone delegation, which is a registrar-level record the owner controls.

## Notes

- `prod`'s directory exists here as a stub so both envs share the modules from day one (F08's point); 11.2.2-T4 completes it.
- Creating empty secret containers here keeps secrets out of OpenTofu while giving 11.5.2-T1 a stable, reviewable path list (`nts/<env>/<NAME>`).
- Cost control: staging runs the smallest available instances and no GPU; the staging GPU node exists only during rehearsals (D1) and is destroyed after (`tofu apply -var gpu_node_count=1` → `nts-node provision --env staging` → `tofu destroy` of that node or the whole env's node resources).
- [INFERENCE] `plan.sh`/`apply.sh` wrappers with a stale-lock pre-flight are proposed only if the provider's backend lacks locking (`plan.md` §10 item 4).
