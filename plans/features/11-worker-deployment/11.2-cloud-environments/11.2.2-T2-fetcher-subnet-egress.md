# 11.2.2-T2 — Fetcher subnet with internet-only egress

| Story | Size | Area | Depends on | Blocks | Phase / flag |
|---|---|---|---|---|---|
| 11.2.2 | S (0.5) | Ops | 11.2.2-T1, 02.5.2-T3 | — | P · phase 2 (deploy, 11 CR-18) |

## Goal

Make the `fetcher` subnet real and prove it: the `NightTales.Fetcher` container runs in a subnet whose only way out is 80/443 to the internet (plus DNS), whose only way into the app network is the API internal listener `:8081`, and which cannot reach PostgreSQL, object storage, the `render` subnet or the metadata endpoint. The requirement table is 02.5.2-T3's (P11); this task implements and tests it — it does not change it.

## Inputs

- `02.5.2-T3-fetcher-host-container-network.md:118-135` — the container/network table, verbatim the acceptance spec (egress allowed: `0.0.0.0/0:80`, `0.0.0.0/0:443`, `api:8081`, the configured DNS resolver; egress denied: PostgreSQL, the storage endpoint, the render subnet, the `mpt-adapter` port, `169.254.0.0/16`; ingress: none; secrets: `FETCHER_API_TOKEN` only; no ports; resource limits CPU 0.5 / memory 512 MiB / pids 128; 1 replica).
- `../README.md` D15 (the subnet is part of the env), D11, P11; `plan.md` §3, §8, §9 check 15.
- `11.2.2-T1` outputs: `subnet_ids`, `db_host`, `bucket_names`, `secret_path_prefix`, `bastion_endpoint`.
- `../../../11-worker-deployment.md` §5.1 — "internet-only egress, no route to PostgreSQL, storage, the render network or the metadata endpoint, and no DB/storage credentials".

## Design

**Network (in `infra/modules/platform`).**
- Subnet `fetcher`: no NAT, one route `0.0.0.0/0` → the internet gateway; no peering, no route to the `app`/`render` CIDRs, no VPC endpoint for object storage.
- Security group `fetcher-sg`: **no ingress rule at all**; egress allow-listed to `0.0.0.0/0:80`, `0.0.0.0/0:443`, the provider resolver `:53`, and the `app` CIDR on `:8081` only. `fetcher-sg` is created by this task (D20 H3). Everything else is denied by default, which is exactly the table's "the app subnet except `api:8081`". The metadata endpoint is **not** excluded by the `0.0.0.0/0:80`/`:443` rules (`169.254.169.254` lies inside `0.0.0.0/0`), so the fetcher host runs with IMDS disabled, or IMDSv2 with hop limit 1 where the provider needs it at boot, and adds a `DOCKER-USER` drop to `169.254.169.254` (D20 H10).
- Host `fetcher ×1` in that subnet (created by this task only, D20 H3), no public IP, IMDS disabled or IMDSv2 hop limit 1 (D20 H10), instance role that can read **only** `nts/<env>/fetcher/FETCHER_API_TOKEN`; no DB, storage or OpenAI credential is attached.
- Private DNS: `api` resolves to the API hosts' private addresses from the `app` subnet (`Fetcher:Internal:BaseUrl` points at `http://api:8081`), so no public name is used and the egress rule stays CIDR/port based.
- Container-level flags (read-only root filesystem, `/tmp` tmpfs 64 MiB, pids 128, CPU 0.5, memory 512 MiB, no published port) are handed to the deploy workflow as a fetcher service fragment [INFERENCE: a small `fetcher-service.json`/compose fragment under `infra/` — the runtime owner is 11.5.1-T1]; this task only has to guarantee they are applied in cloud, not in the local dev stack — 02.5.2-T3 adds the service to the optional compose variant only (CR-10, 11 CR-16).

**Proof (the deliverable 02.5.2-T3 named).** `infra/checks/check-egress.sh` — Bash, `set -euo pipefail`, shellcheck clean, exit 0 all as expected / 1 any deviation / 2 usage-environment. It runs a fixed probe set and prints one `PASS|FAIL <target>` line each:

| Target | Expect |
|---|---|
| `http://api:8081/<internal health route>` | reachable |
| `https://example.com/` | reachable (301/200) |
| `<db_host>:5432` | connection refused/timeout |
| `<storage endpoint>:443` | timeout |
| a `render` node address on 8090 | timeout |
| `169.254.169.254` (IMDS) | timeout |
| `<app host private IP>:5000` (any non-8081 port) | timeout |
| DNS resolution of `api` and `example.com` | works (proves 53) |

The shipped fetcher image has no shell/curl (02.5.2-T3), so the probe runs from a **probe sidecar** on the fetcher host with `--network container:<fetcher>` (D20 H13), launched for the test and removed afterwards [probe image choice is the implementation's, it is never part of the fetcher image].

## Steps

1. In `infra/modules/platform`, add the `fetcher` subnet, its route table (internet gateway only) and `fetcher-sg` with the enumerated rules above; assert in code that no deny-listed CIDR is routed. IMDS is disabled on the host (or IMDSv2 hop limit 1 where the provider needs it at boot) and a `DOCKER-USER` drop to `169.254.169.254` is installed (D20 H10).
2. Add the `api:8081` reachability path: the private DNS name plus the SG rule to the `app` CIDR on port 8081 only.
3. Create the fetcher host (no public IP, IMDS off or IMDSv2 hop limit 1) and its least-privilege instance role (read `nts/<env>/fetcher/FETCHER_API_TOKEN` only; the API role must not read it, D20 H3).
4. Export the container flags/limits for the deploy workflow as the fetcher service fragment.
5. Write `infra/checks/check-egress.sh` with the probe table and exit codes; run it in the local negative harness first (all targets unreachable → exit 1).
6. Extend `infra/checks/assert-plan.sh` with a `fetcher` section: subnet present, route table has no route to `app`/`render`/storage CIDRs, `fetcher-sg` has zero ingress rules, egress = 80/443/53 + `app:8081` and nothing else.
7. Apply, then run the probe from the sidecar with `--network container:<fetcher>` (D20 H13); record the output in `infra/README.md`'s verification log.
8. Remove the sidecar and re-run `tofu plan` on staging (must stay empty — the sidecar is not in IaC).

## Failure handling and edge cases

- **Provider has no SG-reference rules** ⚠️: fall back to a CIDR+port egress rule for `api:8081` (still allow-by-default-deny, so the guarantee holds); record which mechanism was used.
- **Private DNS for `api` not offered**: use the API hosts' private IPs from the module output and rewrite the SG rule per host; `Fetcher:Internal:BaseUrl` then points at the private IP (02.5.2-T3's config key is unchanged, only the value differs) — flagged as a drift risk when API hosts are replaced, and 11.5.1-T1's rollout must update the value.
- **Metadata endpoint reachable on this provider through a non-169.254 address** ⚠️: IMDS is disabled (or IMDSv2 hop limit 1) and the `DOCKER-USER` drop blocks `169.254.169.254` (D20 H10), but the probe must be extended to the provider's documented metadata address; if it answers, an explicit deny rule is added.
- **DNS to a strict resolver only**: some providers drop 53 to the internet — the resolver is provided by the platform and the probe only asserts the platform resolver answers.
- **Debug sidecar leaks into IaC**: forbidden by step 8; the empty post-removal plan is the guard.
- **The fetcher needs a new outbound host later** (02.7 changes): the change is one egress rule plus a new probe row, reviewed together — never a blanket `0.0.0.0/0` allow.
- **Rollback**: revert the module additions and re-apply; the subnet and host are disposable, the fetcher holds no state (02.5.2-T3: no volumes, no DB).
