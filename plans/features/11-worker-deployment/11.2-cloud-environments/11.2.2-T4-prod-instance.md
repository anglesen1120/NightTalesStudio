# 11.2.2-T4 — `prod` from the same module, GPU node count 1

| Story | Size | Area | Depends on | Blocks | Phase / flag |
|---|---|---|---|---|---|
| 11.2.2 | S (0.5) | Ops | 11.2.2-T1, 11.5.2-T1 | 11.5.1-T1, 11.6.1-T1, 11.2.3-T1, 11.4.1-T2 (11 CR-15) | P · M1 |

## Goal

`prod` exists in P, in the same account, from the **same modules** as staging, with `gpu_node_count = 1` (F08) and staging still at 0. Prod is the environment 11.5.1-T1 deploys to behind the `production` environment and 11.6.1-T1 backs up; 11.2.3-T1 later moves it to its own account. No new resource type is introduced here — only prod values and the prod-only assertions (one GPU node, `app.<domain>`, its own secret path and OpenAI projects).

## Inputs

- `11.2.2-T1` — `infra/modules/platform`, `infra/modules/render-node`, `infra/envs/prod` stub, `assert-plan.sh`, the provider-native name table, the staging GPU-on-demand recipe.
- `11.5.2-T1` — values in the D15 secret containers under `nts/prod/` (this task's dependency per `../README.md` §8.1); without them the env applies but the API cannot start.
- `11.2.1-T1` — region, GPU type (≥ 16 GB VRAM, 24 GB preferred, F28), prices, stop/start ability.
- `../README.md` D1 (staging GPU 0 / prod GPU 1; staging node on demand for upgrades), D15, D16, F08, F28, P8; `plan.md` §3, §9 check 6, §11; `../../../DECISIONS.md` §10.5, §10.11 (separate projects, hard budgets).

## Design

- `infra/envs/prod/`: the same two module calls with prod values — `env = "prod"`, `gpu_node_count = 1`, the node list from D13's `RenderNodes:Nodes[i].Name`, prod CIDRs, its own `pg`-backend state in `nts_tofu` on the prod `infra/bootstrap` instance (T76/T83), its own `secret_path_prefix = nts/prod/`, DNS `app.<domain>` and `media.<domain>` (T83), and the prod OIDC role ARN for 11.5.1-T1 (its trust pins `job_workflow_ref = <owner>/<repo>/.github/workflows/deploy.yml@refs/heads/main` and the `production` environment claim, D20 H7). **No module code is copied or forked**: the check is a directory diff that must show value-only differences.
- Buckets `nt-media-prod`, `nt-public-prod`, `nt-music-prod`, `nt-backup-prod` are **not** created here — 11.4.1-T1 creates them over the S3 API (D21); the env only exports `bucket_names` constants. The registry is the same account's with prod repositories; PG is the prod `infra/bootstrap` instance referenced (`R`, T83) with PITR.
- OpenAI projects (P8) are created by the owner in the OpenAI console, **not** by IaC, and only referenced: `nts-text-prod` (text models, the story pipeline) and `nts-images-prod` (node image models only, hard budget). Their ids/keys land in `nts/prod/OPENAI_API_KEY` and the node-side `NODE_OPENAI_IMAGE_KEY` (D11/D15). The image project's hard budget must be set before the node is activated; the value is not asserted here beyond "set", because prices are P8/`DECISIONS` §10.11 territory.
- Staging keeps `gpu_node_count = 0` and `ASPNETCORE_ENVIRONMENT=Staging` with mock-mpt as an HTTPS node pinned like a real one (D20 H2); prod's hosts use the same `api-sg`/`worker-sg`/`fetcher-sg` groups (D20 H3) and IMDS disabled or IMDSv2 hop limit 1 (D20 H10); a staging GPU node is `tofu apply -var gpu_node_count=1` + `nts-node provision --env staging`, destroyed after the rehearsal (D1). Prod's node count is a variable too, so the node can be detached (`0`) without touching data [INFERENCE: an operator lever, not a P requirement].
- Prod-only assertions in `assert-plan.sh prod plan.json`: exactly one `render-node` instance; DNS `app.<domain>` and `media.<domain>`; `storage-prod`, `storage-backup-prod`, their volumes and `storage-sg`/`storage-backup-sg` with the T78/T86 rules (storage-sg 443 from `api-sg`/`worker-sg`/the render subnet/the LB + 22/443 from the VPN/bastion range, 8888/18888 from `storage-backup-sg` only, 9327 from `worker-sg` only, never `fetcher-sg`; storage-backup-sg only 22/443 from the VPN/bastion range + 9327 from `worker-sg`; `worker-sg` inbound 4318 from `storage-backup-sg`, T85) and the 7-day snapshot retention on the primary volume only — the backup volume is not snapshotted (T87), DNS `storage-prod.internal`/`storage-backup-prod.internal` and the prod CA in place; separate state/secret names and `bucket_names` outputs; `nts/prod/storage/*` containers (incl. `NTS_BACKUP_PROBE`/`_SECRET`, T95) readable only by the storage hosts' role + its T94 exact-name reads (`shared/STORAGE_ACCESS_KEY`/`STORAGE_SECRET_KEY`, `NTS_MUSIC_WRITE_KEY`/`_SECRET`, `NTS_MUSIC_READ_KEY`/`_SECRET`, `NTS_PREVIEW_WRITE_KEY`/`_SECRET`) (T91/T92/T94/T95); no staging-named resource referenced by a prod resource (a cross-env id would be a plan-visible mistake) (11 CR-15).
- The render node's tuple (`private_ip`, `gpu_model`, `name`) is the hand-over to 11.3.3-T1's `RenderNodes:Nodes[i]`; the TLS fingerprint comes from the node (11.3.2-T2) and is written after provisioning, not by this task.

## Steps

1. Fill `infra/envs/prod` from the staging env: same module calls, prod values, its own `pg` backend in `nts_tofu` on the prod `infra/bootstrap` instance (T76/T83), prod OIDC role and DNS records; delete nothing from the shared modules.
2. Add the prod-only assertions to `assert-plan.sh` (one render node; `app.<domain>` + `media.<domain>`; the prod storage hosts/DNS/CA per the Design above; no cross-env ids; `gpu_node_count` 1 in prod and 0 in staging).
3. Confirm by diff that `infra/envs/staging` and `infra/envs/prod` differ only in values (a scripted check: strip `terraform.tfvars*`/backend blocks and compare the module call shapes).
4. Record in `infra/README.md`: the prod env, its state location, the required OpenAI projects and where their values live, and that the node's hard budget is set before activation.
5. `validate` both envs, `plan` prod, run the prod assertions; then apply prod.
6. Hand the prod node tuple to 11.3.3-T1's config and the `RENDER_NODE_<NAME>_API_KEY` container path to 11.5.2-T1's runbook.
7. Verify isolation: the prod OIDC role reads `nts/prod/*` and is **denied** `nts/staging/*` (recorded denied call); the staging role is denied `nts/prod/*`; the API role is denied `nts/prod/worker/*` and `nts/prod/node/*` (D20 H3).
8. Record the operator cost lever: the prod GPU node is the largest fixed cost (F08); the node is detached (`-var gpu_node_count=0`) only when prod is intentionally idle [INFERENCE].

## Tests

- `tofu -chdir=infra/envs/prod validate`, `assert-plan.sh prod plan.json`, the value-only-diff script, and `shellcheck infra/checks/*.sh` — all runnable in CI without cloud credentials.
- Negative: a copy of the prod env with `gpu_node_count = 0` must fail the prod-only assertion (exit 1), and a copy that references a staging bucket name must fail the cross-env assertion.
- Live: `dig`, `curl -sSI`, `openssl s_client` (1.2 pass / 1.1 fail), the VRAM query on the node, the role read/deny pair, and `plan -detailed-exitcode` after apply.
- Not re-tested here: GPU driver/whisper/ffmpeg correctness (11.3.1-T1/T2, `gpu-smoke.sh`) and the render path (11.3.5-T1…T4) — this task proves the node exists and is reachable-looking; the `11-node` gate is theirs.

## Failure handling and edge cases

- **GPU capacity unavailable in the region/time** ⚠️: retry, or apply the fallback GPU type from 11.2.1-T1's record (≥ 16 GB VRAM still holds, F28); a prod node with a smaller card is not acceptable (F28 is a hard requirement).
- **Secrets not yet filled** (11.5.2-T1 not done): the env applies but the API containers fail readiness; this is why the dependency exists. Do not inline a secret to "make it work" — the temporary value is a blocker to escalate.
- **Image-project budget not set**: node activation is forbidden until the hard budget exists (P8, `DECISIONS` §10.11); record the setting in `infra/README.md`.
- **Cross-env reference** by accident (a prod plan that reuses a staging id): caught by the assertion; the fix is the prod value, never a shared resource.
- **Accidental staging change**: prod and staging have separate states, so a prod apply cannot mutate staging; the reverse is also true. A shared module change is still a two-env change — apply staging first, then prod, in the same change set.
- **Cost surprise**: the prod GPU node runs continuously by design (F08 decided that over doubling it); the detach lever and the 11.6.3-T1 cost/video number are the monitoring tools. Alert thresholds are 11.6.2-T1's.
- **DNS/`app.<domain>` collision with staging**: only one record per name; staging uses `staging.<domain>`.
- **Rollback**: `-var gpu_node_count=0` detaches the GPU node without touching data; a full prod rollback is a reviewed plan diff; the storage volumes carry `prevent_destroy` here — `infra/envs/prod` guards the volumes only — and the prod PG instance carries its guard in the `infra/bootstrap` state (T90; buckets are not IaC resources, D21, 11 CR-15). 11.2.3-T1 owns the later account move.

## Notes

- The prod env deliberately shares the account with staging in P (F08): one account, two environments, separate states, separate secret prefixes, separate storage hosts/volumes (D21), separate PG. Isolation in P is by naming and IAM, not by account boundary — that boundary is S (11.2.3-T1).
- `prod` also becomes the second consumer of 11.2.2-T3's `/hubs/*` rule and 11.2.2-T2's fetcher subnet; both are module-level, so prod inherits them with no extra work (a reason to keep the envs value-only).
