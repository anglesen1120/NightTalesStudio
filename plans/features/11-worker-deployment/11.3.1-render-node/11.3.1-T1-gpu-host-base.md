## Goal

A bare Ubuntu 24.04 LTS x86_64 host (D8) becomes a node that runs whisper and VieNeu on CUDA from pinned inputs only: driver ≥ `NVIDIA_DRIVER` (E3), one ffmpeg at `FFMPEG_APT` (K3, F06), cuBLAS 12 + cuDNN 9 from the locked `worker-node/cuda-libs/` project exposed to MPT only through `LD_LIBRARY_PATH` (F04, E1, K2), venvs synced from each upstream's own lock with `UV_PROJECT_ENVIRONMENT` (D9, K6/K7/K9), whisper `large-v3-turbo` at the path MPT reads offline (F05, K4), the D8 users/layout, and `gpu-smoke.sh` proving all of it with exit 0.

## Design

- **Layout (D8, F07).** `/opt/nts/releases/<version>/{mpt,vieneu,proxy,adapter,worker-node,seed,venvs/{mpt,vieneu,proxy,cuda-libs}}` root-owned read-only; `/opt/nts/current` → active release; state `/var/lib/nts/{mpt/storage,mpt/config.toml,music/songs,models,hf,adapter,relay}`. Users `nts-mpt`, `nts-vieneu`, `nts-proxy`, `nts-adapter`, `nts-music` (`/usr/sbin/nologin`) [RULED — README §10 T48 (D20 H5)], group `nts-render = {nts-mpt, nts-adapter}`; `mpt/storage/tasks` = `nts-mpt:nts-render 2770` setgid so the adapter writes `final-1.norm.mp4` without being `nts-mpt`. Release symlinks are 11.3.1-T2's; this task publishes targets and modes.
- **Driver (F04, E3).** `nvidia-driver-<N>-server` from the Ubuntu archive (D9's concrete floor name is `nvidia-driver-570-server`), `N` recorded in `NVIDIA_DRIVER`; no CUDA toolkit on the host; `apt-mark hold` on it and on `ffmpeg`. A kernel upgrade rebuilds DKMS → smoke must pass again.
- **CUDA libs (F04, E1, K2).** `worker-node/cuda-libs/pyproject.toml` (`requires-python = ">=3.11"`) depends only on `nvidia-cublas-cu12` and the `nvidia-cudnn-cu12` 9 series; `uv lock` records the resolved versions and hashes (no version literal elsewhere). Synced with MPT's interpreter — `UV_PROJECT_ENVIRONMENT=<release>/venvs/cuda-libs uv sync --frozen --project worker-node/cuda-libs --python "$MPT_PYTHON"` — so D9's `lib/python3.11/site-packages/nvidia/...` path holds. `mpt.service` sets `LD_LIBRARY_PATH=<cuda-libs>/lib/python3.11/site-packages/nvidia/{cublas,cudnn}/lib`, rendered per release into `/etc/nts/mpt.env` (README §10 item 3). MPT's venv stays exactly MPT's lock.
- **Venvs (D9).** `uv python install "$MPT_PYTHON" "$VIENEU_PYTHON"`; per release with `UV_PROJECT_ENVIRONMENT=<release>/venvs/<name>`: mpt `uv sync --frozen --project <release>/mpt`; vieneu `uv sync --frozen --no-dev --extra cuda`; proxy `uv sync --frozen`. No `.venv` inside a release. `install-release.sh` (T2) calls this same script for later releases.
- **Weights (F05, K4).** `fetch-whisper-model.sh --verify` writes `/var/lib/nts/models` at the pinned repo/revision; files checked against `whisper-large-v3-turbo.sha256` and CARRY-OVER §2. `HF_HUB_OFFLINE=1` + per-service `HF_HOME=/var/lib/nts/hf/<service>` in both Python units (T2) [RULED — README §10 T64 (D20 H17)] → no download at render time.
- **`worker-node/host/gpu-smoke.sh`** (0 ok / 1 check failed / 2 usage-env; flags `--libs`, `--models`, `--mpt-venv`, `--vieneu-venv`, `--require-driver`, `--help`; no secret). Checks: `nvidia-smi` driver ≥ floor; VieNeu `torch.cuda.is_available()`; `ctranslate2.get_cuda_device_count()` ≥ 1 **with** `LD_LIBRARY_PATH` and the same command recorded **without** it; `WhisperModel("<models>/whisper-large-v3-turbo", device="cuda", compute_type=<NTS_WHISPER_COMPUTE>)` under `HF_HUB_OFFLINE=1`; `ffmpeg -hide_banner -encoders` contains `NTS_MPT_VIDEO_CODEC`; D8 paths/modes; prints VRAM used. It is the 11-node gate item and the deploy smoke.
- **Tracked artifacts.** `worker-node/host/{provision-host.sh,sync-venvs.sh,gpu-smoke.sh,tests/host-layout.test.sh,pins.env}`, `worker-node/cuda-libs/{pyproject.toml,uv.lock}`. The first four names are [INFERENCE] (D2 fixes only `worker-node/host/`, `cuda-libs/`, `gpu-smoke.sh`).

## Steps

1. Record `lsb_release -ds`, `uname -r`, `dpkg --print-architecture`, `free -g`, `df -h /var/lib/nts` (≥ 40 GB). Exit 2 if not Ubuntu 24.04 `amd64`.
2. Write `provision-host.sh` + `host/pins.env`; resolve `NVIDIA_DRIVER` (provider image notes) and `FFMPEG_APT` (`apt-cache policy ffmpeg`) — record, never guess.
3. Install `ffmpeg=$FFMPEG_APT`, `nvidia-driver-<N>-server`, `python3.12`, `curl`, `ca-certificates`, `nftables`, `zstd`; `apt-mark hold ffmpeg nvidia-driver-<N>-server`; reboot if `nvidia-smi` fails.
4. `uv python install "$MPT_PYTHON" "$VIENEU_PYTHON"`; verify both with `uv run --no-project --python <X> python -V`.
5. Create users/group (including `nts-music`), `/opt/nts/{releases,current}`, the `/var/lib/nts/…` tree with the §Design modes — `/var/lib/nts/music/songs` = `nts-music:nts-render 2750` [RULED — README §10 T48 (D20 H5)]; idempotent (`getent`, `install -d`).
6. Write `cuda-libs/pyproject.toml`, run `uv lock --project worker-node/cuda-libs`, commit `pyproject.toml` + `uv.lock`.
7. Write `sync-venvs.sh` (list arguments, `--help`, exit 0/2), `chmod +x`, `bash -n`, `shellcheck`; run it against a prepared release (MPT at `MPT_COMMIT`, VieNeu at `VIENEU_COMMIT`, proxy source, this repo's `worker-node/`).
8. Prove after step 7: device count ≥ 1, VieNeu torch 2.8.0 CUDA `True`, `test ! -d <release>/{mpt,vieneu,proxy}/.venv`.
9. `fetch-whisper-model.sh --verify` into `/var/lib/nts/models`; verify hashes against the checksum list and CARRY-OVER §2; record bytes.
10. Write `gpu-smoke.sh`, `chmod +x`, `bash -n`, `shellcheck`, run on the GPU → exit 0; record the VRAM line.
11. Write and run `worker-node/host/tests/host-layout.test.sh` (§Tests).
12. Record the 11-node evidence: commands, outputs, exit codes, driver/ffmpeg versions, whisper bytes + sha256.

## Failure handling and edge cases

| Case | Handling |
|---|---|
| Driver missing after reboot | Stop (2); check `dkms status` vs `uname -r`; never install a CUDA toolkit as a workaround. |
| Kernel upgraded later | DKMS rebuilds; smoke must pass again before activation (11.3.1-T3 runbook). |
| A held package gets a security update | Pin is a decision: record the candidate, re-run smoke, change `FFMPEG_APT`/`NVIDIA_DRIVER` in `worker-node/host/pins.env` in its own commit (T21). |
| Device count still 0 with `LD_LIBRARY_PATH` | Check cuDNN major (9.x only, E1) and the `lib/python3.11` path; never install the libs into MPT's venv (D9). |
| Whisper sha mismatch | Stop; do not overwrite the checksum list; re-check the revision in `pins.env` vs CARRY-OVER (pin drift, not a file bug). |
| Smoke passes but subtitle jobs fail later | K4's silent failure: only `gpu-smoke.sh` loads the model, on every deploy and activation, and the adapter never warms it up [RULED — README §10 T20]; a passing smoke therefore does prove the model loads, so a later subtitle failure is an adapter finding, not a model-load one. |
| Disk below the floor | Exit 1 with the `df` line; the node is not activated. |
| `UV_PROJECT_ENVIRONMENT` unset | `sync-venvs.sh` exits 2 naming the variable; a `.venv` inside a release is a hard failure (the release is read-only after install). |
| Rollback | Decommission only: remove users/group and `/opt/nts`. A bad release rolls back via `nts-node rollback` (11.3.1-T3), never touching host packages. |
