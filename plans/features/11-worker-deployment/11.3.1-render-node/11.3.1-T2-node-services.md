## Goal

The four D10 services become startable, hardened systemd units on the node, each reading only its own `0640` `/etc/nts/<file>.env`, with `mpt.service` running the D6a-relevant pre-flight chain (config render → `--check --profile node` → `check-fonts.sh` → `check-music.sh`) and the adapter reachable on HTTPS 8090. A single `worker-node/bin/install-release.sh` turns an extracted bundle into a read-only release dir with the D8 symlinks and swaps `/opt/nts/current`; journald keeps 7 days and ships nothing.

## Design

- **Units in `worker-node/systemd/`** (`vieneu.service`, `mpt.service`, `mpt-adapter.service`, `nts-cleanup.service`, `nts-cleanup.timer`, `nts-music-sync.service`); `vieneu-proxy.service` stays 04.1.5-T1's file. Every unit: `User=`/`Group=` per D10, `Restart=on-failure`, `NoNewPrivileges=yes`, `ProtectSystem=strict`, `ProtectHome=yes`, `PrivateTmp=yes`, `EnvironmentFile=/etc/nts/<file>.env`, `ReadWritePaths=` exactly its own D8 state dir, `StandardOutput=journal`, `StandardError=journal`.
- **Networking per unit.** `vieneu`, `vieneu-proxy`, `mpt`: `IPAddressDeny=any` + `IPAddressAllow=127.0.0.1 ::1` — never `localhost`, which also admits the resolver stub `127.0.0.53` [RULED — README §10 T47 (D20 H4)] (S2, proven in 11.3.2-T2). `mpt-adapter`: loopback + the Worker CIDR on 8090, outbound per D11. `nts-cleanup`: no network. `nts-music-sync`: runs as `nts-music`, 443 to the storage endpoint's IP set only [RULED — README §10 T48/T73 (D20 H5)].
- **`mpt.service`.** `ExecStartPre=` in order: (1) `/usr/bin/python3.12 <release>/worker-node/bin/render-mpt-config.py --profile node --env-file /etc/nts/mpt.env --out /var/lib/nts/mpt/config.toml`; (2) the same with `--check --profile node`; (3) `<release>/worker-node/bin/check-fonts.sh`; (4) `<release>/worker-node/bin/check-music.sh`. A non-zero exit from any stop the start (fail closed, F06). Environment: `IMAGEIO_FFMPEG_EXE=/usr/bin/ffmpeg` (K3), `LD_LIBRARY_PATH=/opt/nts/current/venvs/cuda-libs/lib/python3.11/site-packages/nvidia/cublas/lib:/opt/nts/current/venvs/cuda-libs/lib/python3.11/site-packages/nvidia/cudnn/lib` set in the unit (through `current`, so a rollback also rolls back the libraries) [RULED — README §10 T22], `HF_HUB_OFFLINE=1`, `HF_HOME=/var/lib/nts/hf/mpt`, `ReadWritePaths=/var/lib/nts/mpt /var/lib/nts/hf/mpt`, `ReadOnlyPaths=/var/lib/nts/music/songs /var/lib/nts/models` [RULED — README §10 T64 (D20 H17)], `NTS_MPT_VIDEO_CODEC=libx264`, and the MPT venv on `PATH`. `After=vieneu-proxy.service`.
- **`vieneu.service`.** Binds `127.0.0.1:8000`, `HF_HUB_OFFLINE=1`, `HF_HOME=/var/lib/nts/hf/vieneu`, `ReadWritePaths=/var/lib/nts/hf/vieneu` [RULED — README §10 T64 (D20 H17)], `VIENEU_MAX_STREAMS` ≥ `NTS_MPT_MAX_CONCURRENT` (04 D5); `vieneu-proxy.service` keeps its own env file and `After=vieneu.service`.
- **`mpt-adapter.service`.** `After=mpt.service`; runs the self-contained binary from `<release>/adapter`; `EnvironmentFile=/etc/nts/adapter.env` (README §10 item 3) carrying the D6 `Adapter__*`/`RenderNodeServer__*` keys and `ADAPTER_API_KEY`/`ADAPTER_API_KEY_NEXT`; `ReadWritePaths=/var/lib/nts/adapter /var/lib/nts/relay /var/lib/nts/mpt/storage/tasks`; binds the node's private address only (Kestrel refuses `0.0.0.0`).
- **`nts-music-sync.service`.** `Type=oneshot`, `User=nts-music`, runs `<release>/worker-node/bin/sync-music.sh` with the catalog from the release, then `check-music.sh`; credential only from `/etc/nts/music-sync.env` (`0640 root:nts-music`); started by `nts-node deploy` and on a catalog revision change (05.3.2-T2) — never on a timer [RULED — README §10 T48/T73 (D20 H5)].
- **Env examples `worker-node/env/{mpt,vieneu,vieneu-proxy,adapter,music-sync}.env.example`.** Tracked, no secret values: every key with a safe placeholder or empty value plus a comment naming its secret-manager path (`nts/<env>/node/<name>/<NAME>` for node keys; `nts/<env>/shared/<NAME>` only for `DB_CONNECTION`/`DP_KEK`/`STORAGE_*`, D15) [RULED — README §10 T51 (D20 H3)]. Real files are written by `nts-node provision|deploy` into `/etc/nts/` mode `0640 root:<service user>` (D8) — this task writes the examples and documents the mapping; 11.3.1-T3 writes the real file.
- **`worker-node/bin/install-release.sh`** (`--root DIR` default `/opt/nts` so it is testable in a temp tree; `--bundle-dir DIR`, `--version V`, `--keep 3`, `--swap`, `--help`; exit 0/1/2). Steps: verify the bundle's `SHA256SUMS` again; refuse if `releases/<version>` exists; `rsync -a`/`tar` the tree into `releases/<version>`; call `sync-venvs.sh`, which reuses a venv from the previous release unchanged when that venv's lock sha256 is identical (`cp -al`) and syncs only the changed locks [RULED — README §10 T43 (D20 H1)]; create the D8 symlinks (`mpt/storage → /var/lib/nts/mpt/storage`, `mpt/resource/songs → /var/lib/nts/music/songs`, `mpt/models → /var/lib/nts/models`, `mpt/config.toml → /var/lib/nts/mpt/config.toml`); `chmod -R a-w` the release; `ln -sfn` + `mv -T` to swap `current` atomically; keep the last `--keep` releases and delete older ones only after the swap succeeded. Never writes into a finished release; idempotent when the version is already `current`. Every install and every rollback also copies the release's `worker-node/systemd/*.service` and `*.timer` into `/etc/systemd/system/`, runs `systemd-analyze verify` on each and then `daemon-reload`, so units are never stale [RULED — README §10 T65 (D20 H18)].
- **journald.** Drop-in `worker-node/systemd/journald-nts.conf` installed as `/etc/systemd/journald.conf.d/nts.conf` with `MaxRetentionSec=7day` (D8/03 D12) and `SystemMaxUse` recorded; `systemctl restart systemd-journald`; no shipping, no remote target.
- **Tracked artifacts.** The five env examples, the six unit/timer files, `journald-nts.conf`, `worker-node/bin/install-release.sh`, `worker-node/bin/tests/install-release.test.sh` [INFERENCE], `worker-node/bin/tests/units.test.sh` [INFERENCE].

## Steps

1. Write the five env examples; enumerate every key: mpt (`NTS_MPT_API_KEY`, `NTS_MPT_MAX_CONCURRENT`, `NTS_MPT_VIDEO_CODEC`, `NTS_WHISPER_COMPUTE`, `NTS_MPT_PORT`; `IMAGEIO_FFMPEG_EXE`, `LD_LIBRARY_PATH`, `HF_HUB_OFFLINE`, `HF_HOME` are fixed `Environment=` lines in the unit, not env-file keys, T22), vieneu (`VIENEU_API_KEY`, `VIENEU_MAX_STREAMS`, `HF_*`), vieneu-proxy (04 D13 keys), adapter (D6 `Adapter__*` + `RenderNodeServer__*` + `ADAPTER_API_KEY`, `ADAPTER_API_KEY_NEXT`, `NODE_OPENAI_IMAGE_KEY`), music-sync (`NTS_MUSIC_READ_KEY`, `NTS_MUSIC_READ_SECRET`).
2. Write the six systemd files with the §Design hardening; `systemd-analyze verify` each one.
3. Write the journald drop-in; `systemd-analyze cat-config systemd/journald.conf` shows `MaxRetentionSec=7day`.
4. Write `install-release.sh` with `--root` support; `chmod +x`, `bash -n`, `shellcheck`.
5. Write `worker-node/bin/tests/install-release.test.sh` (temp root, fake bundle: a directory with `SHA256SUMS` and the D8 subdirs) and run it.
6. Install a real release on the node via `install-release.sh` against a bundle built by 11.5.1-T2 (or a locally packed equivalent) and confirm `current`, the symlinks, the modes and the venvs.
7. Install the units and the journald drop-in; `daemon-reload`; start the chain `vieneu → vieneu-proxy → mpt → mpt-adapter` and confirm each unit is `active` and its `ExecStartPre` chain printed nothing to stderr.
8. Prove the negative paths: a `config.toml` rendered with a wrong `font_name` makes `check-fonts.sh` fail → `mpt.service` start fails (exit ≠ 0); a missing catalog file makes `check-music.sh` fail likewise.
9. Record evidence: `systemd-analyze security <unit>` score per unit, `systemd-analyze verify` output, the `journalctl -u` lines of the four units, and `ls -l /etc/nts/*.env`.

## Failure handling and edge cases

| Case | Handling |
|---|---|
| `ExecStartPre` fails on the node | The unit stays `failed`; `nts-node deploy` (11.3.1-T3) treats a failed restart as a deploy failure and rolls back. Never convert the checks to warnings. |
| `config.toml` missing at first start | The render step creates it; `RenderNodes`/env must be complete first, so rendering before the env file exists is the expected first-run error. |
| Env file has a value with spaces/quotes | The examples document plain `KEY=value`; a quoted value is a defect (systemd does not strip shell quotes) — the installer validates the shape and exits 2. |
| A unit needs a path outside its `ReadWritePaths` | Add it to that unit only, and record why; never widen `ProtectSystem`. |
| `install-release.sh` interrupted mid-copy | The release dir is left without a `current` swap; re-running installs it again (the version dir is removed first only if `MANIFEST.json` is absent). |
| Old release still referenced by a running unit | Never delete a release while `/opt/nts/current` or a running unit points at it; `--keep` counts only unreferenced, older releases. |
| journald retention vs available disk | `SystemMaxUse` is set from `df` at provisioning; if `journalctl --disk-usage` exceeds it, retention wins (logs are not content, S7). |
| Rollback | `nts-node rollback` runs `install-release.sh --swap` for the previous version; the units are restarted by the same script's caller (11.3.1-T3), never by hand. |
