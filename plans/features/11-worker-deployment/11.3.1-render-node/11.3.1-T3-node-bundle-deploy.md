# 11.3.1-T3 — Node bundle layout and `nts-node` provision / deploy / rollback / drain / activate

| Story | Size | Area | Depends on | Blocks | Phase / flag |
|---|---|---|---|---|---|
| 11.3.1 | M (1.0) | Ops | 11.3.1-T2, 11.5.1-T2, 11.3.3-T1 | 11.6.3-T1, 11.5.3-T2 | P · M1 |

## Goal

A new adapter/MPT/proxy version reaches a node only through a CI-built, hash-verified bundle installed by `worker-node/bin/nts-node` over the VPN/bastion (F18, O5): drain → verify → copy → install release → swap `current` → restart → smoke → activate, with automatic rollback and a runbook. The node accepts no connections from the app network and CI holds no SSH into the render network.

## Inputs

- README D8, D10, D12, D19; F18, F07, F27; P5.
- 11.3.1-T2: `install-release.sh` (`--root`, `--bundle-dir`, `--version`, `--swap`, `--keep`), the units, `/etc/nts/*.env`.
- 11.5.1-T2 (`node.yml`): the bundle artifact and the GitHub release asset; this task defines the layout and consumes it, never builds it.
- 11.3.3-T1: `nts-worker nodes set-state <name> active|draining` and `nodes list` (audited as `system:operator`).
- 11.3.1-T1: `worker-node/host/{provision-host.sh,gpu-smoke.sh}`. 05.1.1-T1: `worker-node/bin/mpt-upgrade-diff.py`. 05.3.2-T2: `sync-music.sh`.
- Reused, never forked: 01 D9 conventions; `install-release.sh` owns extraction, venvs, symlinks and the `current` swap.

## Design

- **Bundle `nts-node-<version>.tar.zst`**, `<version>` = `<yyyymmdd>-<git sha 7>` (D12): `mpt/` (checkout at `MPT_COMMIT`, no `.git`), `vieneu/`, `proxy/`, `adapter/` (self-contained publish, E8), `worker-node/`, `seed/`, each venv's lock, `MANIFEST.json` (`version`, `ref`, `git_sha`, `run_id`, `mpt_commit`, `vieneu_commit`, `built_at`, `files[]` with sha256) and `SHA256SUMS`; release assets are published only by `node.yml` runs on `refs/heads/main` — no tag releases [RULED — README §10 T49 (D20 H6)]. Never contains env files, keys or models (D12, S4).
- **`nts-node` preflight** (every verb): the caller must be root on the node, `MANIFEST.json` + `SHA256SUMS` verify, `MPT_COMMIT`/`VIENEU_COMMIT` equal `pins.env` unless `--allow-pin-drift` (pin drift is a decision, not a deploy), `MANIFEST.json:ref` is `refs/heads/main` and the tarball's sha256 equals the digest of the GitHub release asset fetched over HTTPS (never only the bundle's own `SHA256SUMS`) [RULED — README §10 T49 (D20 H6)], free disk ≥ 2× the bundle size before extraction, and `zstd`/`tar` present.
- **`deploy --env <env> --node <name> --bundle <file> [--dry-run] [--no-drain] [--timeout-min 90]`**: (1) preflight; (2) `nts-worker nodes set-state <name> draining`; (3) poll `nts-worker nodes list` until `active_tasks = 0`, timeout `--timeout-min` → abort exit 1 (never force); (4) extract to `/var/lib/nts/tmp/<version>` and, when `mpt_commit` changed, run `mpt-upgrade-diff.py` on the **extracted** tree *before* installing (05.1.1-T1, exit ≠ 0 aborts) [RULED — README §10 T65 (D20 H18)]; (5) when a venv lock changed, open the deploy egress window — a temporary nftables set letting root reach TCP 443 of `pypi.org`, `files.pythonhosted.org`, `download.pytorch.org`, `github.com`, `objects.githubusercontent.com` (resolved at deploy start), removed by a `trap` at exit and recorded in the deploy evidence; services never get it [RULED — README §10 T43 (D20 H1)]; (6) `install-release.sh --bundle-dir … --version … --swap`, which also syncs the release's unit files, `systemd-analyze verify`s them and `daemon-reload`s [RULED — README §10 T65 (D20 H18)]; (7) `nts-node sync-env --node <name>`, then assert every `/etc/nts/*.env` equals the secret manager's rendered value by sha256 (values never printed) [RULED — README §10 T52 (D20 H8)]; (8) run `sync-music.sh` for the release; (9) restart units in order `vieneu → vieneu-proxy → mpt → mpt-adapter`; (10) `gpu-smoke.sh` (exit ≠ 0 → fail); (11) adapter `GET /v1/health` on the private address with the pinned certificate until HTTP 200 (60 s) → fail otherwise; (12) `nts-worker nodes set-state <name> active`. Any failure in 4–11 → `rollback` automatically and exit 1.
- **`rollback --node <name>`**: restore the previous `current` via `install-release.sh --swap` — again installing the release's unit files, `systemd-analyze verify` and `daemon-reload` [RULED — README §10 T65 (D20 H18)] — restart, smoke, health, activate. Releases kept: 3 (D12).
- **`drain` / `activate --node <name>`**: thin wrappers over `nts-worker nodes set-state` (no local logic).
- **`provision --env <env> --node <name> --bundle <file>`**: `provision-host.sh` (T1) then `deploy`. The script itself is run from an extracted bundle or a checkout at the same commit (README §10 item 4) — it is not installed before the first deploy.
- **Secrets.** `nts-node` never takes a key on the command line: env files are written from the secret manager (`nts/<env>/node/<name>/<NAME>`, D15/T51) into `/etc/nts/` mode `0640 root:<service user>` — `music-sync.env` is `0640 root:nts-music` [RULED — README §10 T51 (D20 H3), T48 (D20 H5)] — by `nts-node sync-env --node <name>`, one key at a time, and no value is echoed [RULED — README §10 T52 (D20 H8)]. Nobody edits an env file by hand, and `deploy` asserts the on-disk content equals the secret manager by sha256 [RULED — README §10 T52 (D20 H8)]. `--secrets-from <file>` (a mode-0600 file produced by the operator from the secret manager) is the only non-interactive path.
- **`nts-worker` reachability.** `--worker-cmd` (default `nts-worker`) is the operator's way to reach the platform CLI (the Worker binary in the app network); if it is unreachable, `--no-drain` requires an explicit confirmation and records a `⚠️ not drained` line in the evidence [INFERENCE].
- **Runbook `docs/runbooks/node-deploy.md`** (D2): prerequisites (VPN/bastion, secret-manager access, the bundle's `SHA256SUMS` from the release page), first provisioning, routine deploy, MPT bump (cross-ref 05.1.1-T1), rollback, adapter key rotation (→ 11.3.2-T2), certificate rotation (→ 11.3.2-T1), node replacement/decommission, the evidence to record per deploy, and the time budget.
- **Tracked artifacts.** `worker-node/bin/nts-node`, `worker-node/bin/tests/nts-node.test.sh` [INFERENCE], `docs/runbooks/node-deploy.md`, `worker-node/bundle/README.md` describing the layout [INFERENCE].

## Steps

1. Write the bundle layout document (`worker-node/bundle/README.md`) and the `MANIFEST.json`/`SHA256SUMS` field list; hand it to 11.5.1-T2 as the contract (no code in this task builds the bundle).
2. Write `nts-node` with the five verbs, `--help`, exit 0/1/2, `set -euo pipefail`, list arguments only, and a `log`/`die` from `lib.sh` style.
3. Implement the preflight (manifest + sums + pin drift + disk) and the extraction into `/var/lib/nts/tmp/<version>` with a `trap` cleanup.
4. Implement `deploy` steps 2–10 with the drain poll, the `mpt-upgrade-diff.py` gate, the unit restart order, the smoke gate and the health gate; make `--dry-run` print the plan and change nothing.
5. Implement `rollback`, `drain`, `activate` and the automatic rollback path on any deploy failure.
6. Implement the env-file writer (`/etc/nts/<file>.env`, `0640`, from `--secrets-from` or prompts) and assert no value appears in stdout/stderr.
7. Write `worker-node/bin/tests/nts-node.test.sh` with stubs for `systemctl`, `nts-worker` and `gpu-smoke.sh` on `PATH` and a fake bundle; run it.
8. Write `docs/runbooks/node-deploy.md` with the sections of §Design and the exact commands per step.
9. Rehearse on a staging node (D1/O2: created on demand, destroyed after): a real bundle, a real deploy, a deliberate smoke failure (rename the model dir) to prove the automatic rollback, then destroy the node.
10. Record evidence: the deploy log (drain, install, restart, smoke, health, activate), the rollback log, the timings per step, and the bundle sha256.

## Acceptance checks

- [ ] `bash -n` and `shellcheck` exit 0 for `nts-node`; `nts-node --help` lists the five verbs and exits 0; `nts-node bogus` exits 2.
- [ ] `bash worker-node/bin/tests/nts-node.test.sh` exits 0 with every named case passing.
- [ ] `nts-node deploy --dry-run` on a healthy node prints the plan (drain, install, restart, smoke, health, activate) and changes nothing: `readlink /opt/nts/current` unchanged, `systemctl is-active mpt-adapter.service` unchanged.
- [ ] A bundle whose `SHA256SUMS` was tampered with → `deploy` exits 1 before extraction and `readlink /opt/nts/current` is unchanged.
- [ ] A bundle whose `MANIFEST.json` `mpt_commit` differs from `pins.env` → exit 1 naming the drift; with `--allow-pin-drift` it proceeds (recorded).
- [ ] A drained node (`active_tasks > 0` simulated by the stub) → `deploy` waits, then aborts at `--timeout-min 1` with exit 1 and no changes.
- [ ] A deliberate smoke failure after the swap (model dir renamed) → `deploy` exits 1, `current` points back at the previous release, the units are restarted, and `gpu-smoke.sh` passes again.
- [ ] `nts-node rollback` on a node with two releases moves `current` to the older one and leaves the units `active`.
- [ ] `nts-node drain` then `nts-node activate` produce exactly one `nodes set-state` call each (visible in the stub log) and change nothing else.
- [ ] Secret hygiene: with a marker secret in the secret-manager stub, `grep -F "$MARKER"` over stdout, stderr and every file the run wrote → no hit; `nts-node deploy --bundle x --api-key abc` → exit 2 (unknown flag).
- [ ] `stat -c '%a %U %G' /etc/nts/mpt.env` → `640 root:nts-mpt`; `ls /var/lib/nts/tmp` is empty after a successful deploy (the `trap` cleaned up).
- [ ] `docs/runbooks/node-deploy.md` exists and every command in it is copy-pasteable (no placeholders other than the documented variables) — checked by a reviewer read of the file.

## Failure handling and edge cases

| Case | Handling |
|---|---|
| Drain never reaches 0 | Abort with the last `nodes list` line; never kill a running render; the node stays `draining` until the operator decides (D12). |
| `install-release.sh` fails mid-way | No `current` swap happened; the partial release dir is removed by the `trap` if `MANIFEST.json` is absent. |
| Restart order matters | `mpt-adapter` must start after `mpt` (`After=`, T2); a failed unit stops the sequence and triggers rollback. |
| Health gate times out | Treat as a failed deploy: the adapter may be up but unhealthy (`assets`, `gpu`); roll back and keep the journal for the diagnosis. |
| Bundle extracted twice | `install-release.sh` refuses an existing version; `nts-node` re-extracts only after removing a version dir with no `MANIFEST.json`. |
| Operator runs `deploy` without VPN | Preflight fails on the `nts-worker` call; with `--no-drain` it proceeds and records `⚠️ not drained` — an explicit, auditable choice. |
| MPT bump needs the pin changed | `pins.env` is edited in its own commit first (01 D2); the bundle must then carry the same commit, else preflight aborts. |
| Rollback of a bad certificate/key | Not this task's: 11.3.2-T1/T2 own certificate and key rotation; `rollback` never touches `/etc/nts/tls` or the env files. |
| Node destroyed / replaced | Disks are rebuilt, never restored (F27): a new node is `provision`ed and deployed from the same bundle. |
