# 11.3.2-T1 — Node firewall, adapter certificate and exposure proof

| Story | Size | Area | Depends on | Blocks | Phase / flag |

## Goal

The node is unreachable from the internet: the provider firewall and an nftables ruleset on the node allow only SSH from the VPN/bastion range and TCP 8090 from the Worker subnet (S1, F14), and the adapter presents a self-signed ECDSA P-256 certificate whose SHA-256 fingerprint is handed to the Worker's `RenderNodes:Nodes[i]:TlsCertSha256` (S3, F15, E6). Proven by an external port scan, bind assertions and a fingerprint comparison.

- 11.2.2-T1: the network, subnets `app`/`render`/`fetcher`, the bastion and the provider firewall rules. 11.2.2-T2: the fetcher subnet (must be denied from the node).

- Reused, never forked: 01 D9 script conventions and `lib.sh`.

## Design

- **Two layers, one policy.** The provider firewall (IaC, 11.2.2-T1) and `worker-node/net/nftables.conf` express the same rule set; the node ruleset is the last line of defence and is what the audit reads. Any divergence is a finding, so both are checked in the same step.
- **`worker-node/net/nftables.conf`** (`table inet nts`): sets `worker4`/`worker6` (the Worker subnet) and `admin4` (the VPN/bastion range); `chain input { type filter hook input priority 0; policy drop; }` with: `iif lo accept`; `ct state established,related accept`; `ct state invalid drop`; ICMP echo-request from `admin4` only; `tcp dport 22 ip saddr @admin4 accept` (and v6 if the provider uses it); `tcp dport 8090 ip saddr @worker4 accept` — the Worker's `worker-sg` security group is the only source, never the app or fetcher host [RULED — README §10 T45/T51 (D20 H3)]; explicit `drop` for the app subnet, the fetcher subnet and `169.254.0.0/16`, which stays, with IMDS disabled on the host (or IMDSv2 with hop limit 1 where the provider needs it at boot) [RULED — README §10 T55 (D20 H10)]; `chain forward { policy drop; }`; no NAT. Ports 8000/8001/8080/8091 are never opened (they are loopback-only per D10) — the ruleset must not contain them.
- **Application.** `nft -c -f worker-node/net/nftables.conf` (syntax check) then `nft -f`; persist by installing the file as `/etc/nftables.conf` (or an `include` line) and `systemctl enable --now nftables.service`; idempotent (re-applying yields the same `nft list ruleset`).
- **`worker-node/net/make-adapter-cert.sh`** (`--node <name>`, `--ip <private ip>`, `--out-dir /etc/nts/tls`, `--days 397`, `--force`, `--print-fingerprint`, `--help`; exit 0/1/2). Uses `openssl req -x509 -newkey ec -pkeyopt ec_paramgen_curve:P-256 -nodes -days 397 -subj "/CN=<node>" -addext "subjectAltName=IP:<ip>"`; writes `adapter.key` mode `0600` owned `nts-adapter` and `adapter.crt` mode `0644`; refuses to overwrite an existing pair without `--force`; prints exactly one line `sha256=<HEX uppercase, no colons>` computed from the DER certificate (`openssl x509 -outform DER | sha256sum`), which is the same value `GetCertHashString(HashAlgorithmName.SHA256)` returns (E6). No secret, no network.
- **Handover.** The operator copies the printed fingerprint into the Worker's configuration (`RenderNodes:Nodes[i]:TlsCertSha256`, stored via the secret manager, 11.5.2-T1); the node stores only the key and the certificate. The Worker compares case-insensitively (D11).
- **Rotation (D11, F15).** `nts-node drain` → run the script (new pair) → update `TlsCertSha256` → restart the Worker → `nts-node activate`. Never rotate while renders run. The Worker's pin callback also checks the certificate's `NotAfter`, exports `render_node_cert_expiry_days{node}` and alerts at 30 days; 11.6.2-T1 owns that alert rule [RULED — README §10 T57 (D20 H12)].
- **Evidence to record.** `nmap -Pn -p- <public ip>` output from outside the network; `ss -ltn` output; `openssl s_client -connect <private ip>:8090 -showcerts` fingerprint; `nft list ruleset` hash; the provider firewall rule list.
- **Tracked artifacts.** `worker-node/net/nftables.conf`, `worker-node/net/make-adapter-cert.sh`, `worker-node/net/tests/make-adapter-cert.test.sh` [INFERENCE], `worker-node/net/tests/nftables-shape.test.sh` [INFERENCE], and a section in `docs/runbooks/node-deploy.md` (11.3.1-T3's file — this task supplies the text).

## Steps

1. Read the provider's rule list from 11.2.2-T1 and write the equivalent `worker-node/net/nftables.conf` with the two source sets; record both side by side in the evidence.
2. `nft -c -f worker-node/net/nftables.conf`; then install and apply; `systemctl enable --now nftables.service`; re-apply and confirm `nft list ruleset` is unchanged (idempotent).
3. Write `make-adapter-cert.sh`; `chmod +x`, `bash -n`, `shellcheck`; run `--print-fingerprint` on a temporary pair first.
4. Generate the real pair on the node (`--node <name> --ip <private ip>`), record the fingerprint, install the key owner/mode (`chown nts-adapter`, `chmod 600`).
5. Write `worker-node/net/tests/make-adapter-cert.test.sh` and `nftables-shape.test.sh`; run both (no root needed for the shape test; the certificate test uses a temp `--out-dir`).
6. Restart `mpt-adapter.service` and confirm it serves TLS on the private address with the new certificate.
7. From outside the network run `nmap -Pn -p- <public ip>`; from the app network run the port probes of §Acceptance; record every result.
8. Add the certificate-rotation section to `docs/runbooks/node-deploy.md` and hand the fingerprint to the Worker config (11.3.3-T1's key).
9. Record evidence: the scan output, `ss -ltn`, the `openssl s_client` fingerprint, `nft list ruleset`, and the provider firewall list.

## Acceptance checks

- [ ] `nft -c -f worker-node/net/nftables.conf` exits 0 and `bash -n`/`shellcheck` exit 0 for `make-adapter-cert.sh`.
- [ ] `nft list ruleset` contains exactly one `dport 22` rule restricted to the admin set, one `dport 8090` rule restricted to the `worker-sg` set (nothing else — not the app host, not the fetcher host), and no rule opening 8000/8001/8080/8091; the input policy is `drop`; the `169.254.0.0/16` drop is present and the host's IMDS is disabled (or IMDSv2 hop limit 1) [RULED — README §10 T45/T51 (D20 H3), T55 (D20 H10)].
- [ ] Re-applying the ruleset changes nothing: `nft list ruleset | sha256sum` is identical before and after.
- [ ] `nmap -Pn -p- <public ip>` from outside the network reports every port closed/filtered except the bastion path (22) — recorded verbatim.
- [ ] From the app network: `nc -z -w3 <private ip> 8090` succeeds; `nc -z -w3 <private ip> 8000|8001|8080|8091` all fail; from a host in the fetcher subnet, 8090 fails.
- [ ] `ss -ltn` shows `8090` bound to the private address only and `8000`, `8001`, `8080`, `8091` bound to `127.0.0.1` only.
- [ ] `openssl x509 -in /etc/nts/tls/adapter.crt -noout -text` shows `id-ecPublicKey` with `prime256v1`, `Not After` ≈ 397 days out, `CN=<node name>` and `IP Address:<private ip>`; the Worker reports `render_node_cert_expiry_days{node}` for it and the 30-day alert rule is owned by 11.6.2-T1 [RULED — README §10 T57 (D20 H12)].
- [ ] `stat -c '%a %U' /etc/nts/tls/adapter.key /etc/nts/tls/adapter.crt` → `600 nts-adapter` and `644 …`.
- [ ] `openssl s_client -connect <private ip>:8090 -showcerts` fingerprint equals the line `make-adapter-cert.sh` printed and the value in `RenderNodes:Nodes[i]:TlsCertSha256` (compared case-insensitively).
- [ ] `make-adapter-cert.sh` on an existing pair exits 1 naming the file; with `--force` it replaces both files and prints a different fingerprint.
- [ ] `bash worker-node/net/tests/make-adapter-cert.test.sh` and `nftables-shape.test.sh` exit 0.
- [ ] The `ss -ltn`/scan/`s_client` outputs and the fingerprint are recorded in the 11-node evidence.

## Failure handling and edge cases

| Case | Handling |
|---|---|
| Provider firewall and nftables disagree | The stricter rule wins until fixed; record the divergence and raise it to 11.2.2-T1 (IaC is the source of truth for the provider side). |
| Locking yourself out over SSH | Apply with `nft -f` inside a `systemd-run`-style timeout and keep the current session open; if the bastion range is wrong, roll back with the previously recorded ruleset file. |
| Ruleset lost after reboot | `nftables.service` must be enabled and the file persisted; a reboot test is part of the evidence. |
| Certificate expired (397 days) | The Worker's pin comparison fails → node `down` in the registry; rotate per §Design (drain first). |
| Fingerprint copied with colons or lowercase | The Worker compares case-insensitively and without colons only if the value matches `GetCertHashString(SHA256)` (E6); the script's format is the contract, and a mismatch is a config error, not a code change. |
| IPv6 present but unruled | Either the provider gives no public v6 (recorded) or the same two sets are added for v6; never leave the input policy v4-only by accident. |
| `--force` used during renders | Forbidden: drain first; a certificate swap under a running render breaks the Worker's in-flight calls. |
| Rollback | Restore the previous ruleset file with `nft -f`; for the certificate, re-run the script and restore the previous `TlsCertSha256` value. |
