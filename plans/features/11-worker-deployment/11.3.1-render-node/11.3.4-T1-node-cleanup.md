# 11.3.4-T1 — Node cleanup: `nts-cleanup` timer and `cleanup-orphans.py`

| Story | Size | Area | Depends on | Blocks | Phase / flag |
|---|---|---|---|---|---|
| 11.3.4 | S (0.5) | Ops | 11.3.1-T2, 11.3.5-T2 | — | P · M1 |

## Goal

An hourly, network-less `nts-cleanup.timer` removes what the adapter can no longer account for: task directories and relay JSONL files that the adapter's durable store does not reference and that are older than 24 h (05 D15 P4 backstop), so a crashed adapter, a deleted row or a rolled-back release cannot fill the node's disk. The run deletes nothing when the store cannot be read, logs ids only, and feeds the disk metric (`render_node_disk_used_pct`, D13) whose alert fires at 80 % (D17).

- Reused, never forked: Python stdlib only (`sqlite3`, `os`, `json`, `argparse`, `shutil`), 01 D9 conventions (list arguments, no shell, exit 0/1/2).

## Design

- **`worker-node/systemd/nts-cleanup.service`**: `Type=oneshot`, `User=nts-adapter`, `ExecStart=/usr/bin/python3.12 /opt/nts/current/worker-node/bin/cleanup-orphans.py --apply --older-than 24h --json`, `IPAddressDeny=any`, `NoNewPrivileges=yes`, `ProtectSystem=strict`, `ProtectHome=yes`, `PrivateTmp=yes`, `ReadWritePaths=/var/lib/nts/mpt/storage/tasks /var/lib/nts/relay`, no `EnvironmentFile` (README §10 item 3), `TimeoutStartSec=900`.
- **`worker-node/systemd/nts-cleanup.timer`**: `OnCalendar=hourly`, `Persistent=true`, `RandomizedDelaySec=120`, `Unit=nts-cleanup.service`. Hourly is a decision, not a business rule: the adapter deletes a `succeeded` task dir at `DELETE` and a `cancelled` one at once (D6), so the timer is the backstop.
- **`worker-node/bin/cleanup-orphans.py`** (stdlib only; list arguments; exit 0 ok / 1 check failed / 2 usage-environment):
  `--tasks-dir /var/lib/nts/mpt/storage/tasks` · `--relay-dir /var/lib/nts/relay` · `--store /var/lib/nts/adapter/tasks.db` · `--older-than 24h` · `--max-entries 20000` · `--apply` (default is dry run) · `--json` · `--self-test` · `--help`.
- **Reference set.** Read the store read-only (`sqlite3.connect("file:<path>?mode=ro", uri=True)`) and build the set of referenced task ids; if the schema does not match what the script expects, or the store is missing/locked, it prints why and exits **1 without deleting anything** (fail safe, S8). Rows that are still non-terminal (`state` not terminal, `cleaned_at` null) are always references.
- **Deletion rules.** (a) A directory directly under `--tasks-dir` whose name is a UUID the store does not reference and whose mtime is older than `--older-than` → remove. (b) A file under `--relay-dir` whose name contains a UUID the store does not reference and whose mtime is older than `--older-than` → remove. (c) Anything older than `--older-than` under `--tasks-dir` that is a regular file, not a dir, and not referenced → remove. Nothing else, ever.
- **Safety (S8).** `os.lstat` only; refuse if `os.path.realpath(target)` escapes the given root; never follow a symlink; never delete a root itself; ignore names that are not UUIDs (log as `skipped_non_uuid`); `--max-entries` bounds the scan (Q1) and a larger tree stops with exit 1 `scan_limit` rather than running unbounded. Every deletion logs the id and the kind only — never a path that contains content, never a file's bytes (S7).
- **Reporting.** Human: `cleanup: removed <n> task dirs, <m> relay files, freed <bytes>`; `--json`: one object `{ok, scanned, removed:{task_dirs,relay_files,files}, freed_bytes, skipped_non_uuid, store, store_readable, duration_ms}`. `freed_bytes` comes from summing `st_size`/directory sizes before removal; it is journal-only evidence, not a metric.
- **Disk signal.** The `disk` block of `render-node-health.v1` is the adapter's (11.3.5-T4/D7: `statvfs` on `/var/lib/nts/mpt/storage`); this task fixes the semantics it must carry — every disk figure (`used_pct`, `task_dir_free_bytes`, `disk_low`, `render_node_disk_used_pct`) comes from **one** `statvfs` on `/var/lib/nts/mpt/storage`, with `used_pct` = `1 - f_bavail/f_blocks` of that call, sampled every 15 s and cached [RULED — README §10 T63 (D20 H16)] — and the alert wiring: the Worker exports `render_node_disk_used_pct{node}` (D13) and D17 raises a warning at 80 % and `disk_low` at 85 %. A cleanup run that fails must be visible: `systemctl --failed` plus the journal line, and the disk alert remains the backstop.
- **Tracked artifacts.** `worker-node/systemd/nts-cleanup.{service,timer}` (the file names are D10's), `worker-node/bin/cleanup-orphans.py`, `worker-node/bin/tests/cleanup-orphans.test.sh` [INFERENCE], plus the additions to `worker-node/bin/tests/units.test.sh` (11.3.1-T2) and the cleanup section of `docs/runbooks/node-deploy.md` (11.3.1-T3).

## Steps

1. Write `cleanup-orphans.py`: argument parsing (exit 2 on usage/unknown flag), the read-only store reader with the fail-safe branch, the bounded scan, the three deletion rules, the safety checks of §Design, the two output shapes and `--self-test`.
2. Implement `--self-test` with a temporary tree and a temporary SQLite store it creates itself (the same fixture shape the unit tests use), covering every `- [ ]` case below; it must not need root or network, so `node.yml` (11.5.1-T2, D18) can run it.
3. Write `worker-node/systemd/nts-cleanup.service` and `.timer`; `systemd-analyze verify`; extend `worker-node/bin/tests/units.test.sh` with this unit's assertions (hardening, no `EnvironmentFile`, `ReadWritePaths` restricted to the two roots, timer `OnCalendar=hourly`).
4. Write `worker-node/bin/tests/cleanup-orphans.test.sh` (temp tree, `trap` cleanup) with the named cases; run it and `--self-test`.
5. On the node: install the unit and timer in the release, `systemctl daemon-reload`, `systemctl enable --now nts-cleanup.timer`; `systemctl list-timers nts-cleanup.timer` shows the next hourly run; `systemctl start nts-cleanup.service` exits 0 with `removed 0`.
6. Plant a fake orphan (a UUID dir under `tasks/` with an old mtime and a fake relay file) plus a referenced dir; run the service; prove the orphan is gone and the referenced dir is untouched; run again → `removed 0` (idempotent).
7. Fill a test file under `/var/lib/nts/mpt/storage` until it crosses 80 % [RULED — README §10 T63 (D20 H16)]; confirm the Worker's `render_node_disk_used_pct` reflects it and the D17 warning fires; remove the file and confirm the metric returns (record both readings).
8. Record evidence: the `--json` output of a dry run and of an apply run, the planted-orphan transcript, the second-run `removed 0`, the disk readings before/after the fill, and `systemd-analyze verify` output.

## Failure handling and edge cases

| Case | Handling |
|---|---|
| Store missing, locked or unreadable | Exit 1, delete nothing (S8). The adapter may be restarting; the next hourly run fixes it. |
| Adapter writes a task dir while the scan runs | Only paths older than 24 h are candidates, so an active task dir is never in scope; a dir created during the scan is skipped by the mtime test. |
| Store schema changes with a future adapter version | The script fails closed and says which columns it expected; the fix ships in the same bundle as the adapter change (D12 `nts-node deploy` verifies with `gpu-smoke.sh` and health). |
| Relay layout changes (03.4.3-T1) | The rule is "file whose name contains an unknown UUID"; a layout without ids in names simply removes nothing and reports `removed 0` — never a wildcard delete. |
| Disk still full after cleanup | The alert path (D17 80 %/85 %) and the capacity numbers (11.6.3-T1) decide; never delete a referenced task dir to free space. |
| Cleanup unit fails repeatedly | `systemctl --failed` plus the journal; the timer has no retry (an hourly backstop does not need one) and `Restart=on-failure` is not set on `Type=oneshot`. |
| Someone runs the script by hand with `--apply` | Allowed (it is the same code path); the dry run is the default so a mistyped command deletes nothing. |
| Rollback | The timer and the script ship in the release: `nts-node rollback` + `daemon-reload` restores the previous behaviour. Nothing the script deleted can be restored — which is exactly why it deletes only unreferenced, older-than-24 h paths. |
