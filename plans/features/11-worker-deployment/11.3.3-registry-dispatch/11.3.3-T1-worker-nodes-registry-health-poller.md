## Goal

Make render nodes a first-class, queryable registry: one migration + entity for `worker_nodes` (00 §6 L311), a config seeder that needs no settings UI (F09/P4), one shared pinned-TLS `HttpClient` factory (F13/D13, reused by 09.6.2-T1), a `BackgroundService` health poller with hysteresis under an advisory lock (F10/F12, P9), an in-memory health cache, and the operator CLI verbs that drain/activate a node and write `audit_logs`.

**Binding.** `RenderNodesOptions`: `HealthPollSeconds = 30`, `DownAfterSeconds = 120`, `HealthStaleSeconds = 90` [INFERENCE: key name, plan §10 open item 3], `Nodes: List<RenderNodeOptions { Name, BaseUrl, Capacity, TlsCertSha256, GpuModel }>`. 4. 5. Implement `NodeHealthCache` (singleton) and register it.
6. Implement `WorkerNodeSeeder` + startup hook: bind `RenderNodes:Nodes`, upsert by `name` (`ApplyConfig`, state untouched), `MarkDown` config-absent rows (never delete), verify each node's key. Run it from the Worker startup path and once before the first CLI verb.
7. Implement `NodeHealthPoller` per `plan.md` §7 steps 1–8: advisory lock, bounded concurrent pulls with a 5 s timeout, valid-answer classification (200 **or** 503 with a parseable body), heartbeat + cache update, 2-good-pull recovery, 120 s down, `draining` untouched, `render_node_up` + `render_node_health_reasons_total` emission, drift warning after 3 pulls. Register it after the seeder; leave the existing `OutboxDispatcher` registration untouched.
8. Implement `NodesCommand` and the Worker argument dispatch (`args[0] == "nodes"`, no web listener): `list` table and `set-state <name> active|draining` with its `audit_logs` row in the same transaction, exit codes 0/1/2 (`plan.md` §5). No key, hint or ciphertext on stdout.
9. Security sweep of the new path: no node `HttpClient` outside the factory; no secret in a log, exception message or `audit_logs.data`; exception messages must not echo URL userinfo [INFERENCE].
10. Run the `plan.md` §9 suites that this task owns (`dotnet test`), plus a build, and report the raw output.

## Failure handling and edge cases

- **Poller throws** (DB down, bad config): catch per tick, log `{tick, error}`, keep the loop alive — the Worker's Hangfire/outbox must keep running.
- **Advisory-lock connection drops**: the lock dies with the connection and the next tick re-acquires; a lost lock never flips a node state.
- **Node answers 401** (wrong/rotated key): "no answer" → row `down` after 120 s; if the 401 body parses, its `mpt_unauthorized` reason is recorded, otherwise the local `node_unreachable` [INFERENCE]. One pull per interval — no retry storm.
- **200 with an unparseable body** (missing `capacity`): treated as no answer; log the node name and the parse-error class, never the body.
- **Clock skew**: hysteresis uses the Worker's `IClock` UTC only; node timestamps are display data (09 D3).
- **Config change while running**: the seeder runs at startup only [INFERENCE: D13 says "at Worker start"] — document in 11.3.1-T3's runbook line.
- **Two Workers during a rolling deploy**: polling is serialised by the lock; the non-holder still serves `nodes list`.
- **Rollback**: revert the Worker image (poller/seeder gone, table inert); if needed, run the migration down — rows re-seed from `RenderNodes:Nodes`; a `draining` row left by a failed deploy is cleared with `nodes set-state <name> active` (D12).
- **Secrets**: a missing key fails fast at startup instead of degrading to unauthenticated polls; no fallback to `http://` or unvalidated TLS outside Development.
