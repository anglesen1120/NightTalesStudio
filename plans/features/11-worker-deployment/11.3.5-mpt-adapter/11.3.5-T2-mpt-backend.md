## Goal

Implement the adapter's MPT side behind T1's `IRenderBackend`/`ITaskStore`: `MptClient` (submit/status/delete on `127.0.0.1:8080` with `x-api-key` and `x-task-id`), `SqliteTaskStore` (the durable store D6 fixes), and `MptTaskPoller` (2 s per non-terminal task, the only MPT reader, F19) with the D4 stage mapping, the D6 lost rule, the 05 D5 failure mapping, cancel and delete — so a Worker poll always answers from the store and MPT restarts or disappearances become `render_lost` instead of a stuck job.

## Design

| Component | Responsibility |
|---|---|
| `MptClient` | `POST /api/v1/videos` (body = the D3 `mpt` set + `n_threads`), `GET /api/v1/tasks/{id}`, `DELETE /api/v1/tasks/{id}`, `GET /ping`; header `x-api-key: NTS_MPT_API_KEY` and `x-task-id: <adapter task_id>` on submit (05 C3); connect 2 s, read 30 s; no redirects; JSON via `RenderNodeJson.Tolerant` |
| `SqliteTaskStore : ITaskStore` | one writer connection, `SemaphoreSlim(1)`, WAL; JSON columns for `outcome/output/check/images/mpt`; `PurgeCleanedAsync(now − 7 d)` |
| `MptTaskPoller : BackgroundService` | every `Adapter:PollSeconds` = 2 over `ListNonTerminalAsync`; stage/percent mapping; lost rule; terminal transitions; drives T3's post-processor |
| `MptProcessStartReader` | `systemctl show mpt.service -p ExecMainStartTimestamp` (list args, no shell); read at start and after every MPT connection error; `null` → the restart rule is disabled and logged once (the 404 rule stays) |
| `OutcomeMapper` | `failed_stage` → 05 D5 code + `detail`; `OutcomeMessages` supplies `message`; MPT's raw `error` goes to the journal only (S4) |
| `TaskDirCleaner` | removes the MPT task dir, `/var/lib/nts/relay/<task_id>.jsonl`, `/var/lib/nts/relay/plans/<task_id>.json` and `tasks/<task_id>/` per the D6/05 D15 P4 rules |

```csharp
public sealed class MptClient : IRenderBackend
{
    public MptClient(HttpClient http, IOptions<AdapterOptions> options, ILogger<MptClient> log);
    // SubmitAsync → POST /api/v1/videos, records BackendAccepted(mptTaskId, mptStartedAt = MptProcessStartReader.Read())
    // CancelAsync → marks only: MPT has no cancel route and DELETE refuses a running task (05 D4), the poller finalises
    // DeleteAsync → ErrorOr.Fail(adapter_task_busy) while non-terminal, else DELETE + TaskDirCleaner
    // OpenOutputAsync → ErrorOr.NotFound until T3 has stored the outputs
}
public sealed class SqliteTaskStore : ITaskStore { public SqliteTaskStore(SqliteStoreOptions options); public Task MigrateAsync(CancellationToken ct); }
public sealed class MptTaskPoller : BackgroundService { protected override Task ExecuteAsync(CancellationToken ct); }
```

Store DDL and columns: `plan.md` §3.1 (authoritative); `MigrateAsync` runs it inside one transaction and writes `schema_meta['version']`.

**Stage mapping** (`MptTaskPoller`, MPT → adapter, 05 D4):

| MPT `state` | MPT `progress` | adapter `state` | adapter `stage` | adapter `percent` |
|---|---|---|---|---|
| — (no `backend_task_id`) | — | `queued` | `queued` | 0 |
| 4 | 5, 10, 20 | `running` | `voice` | as reported |
| 4 | 30 | `running` | `subtitles` | 30 |
| 4 | 40 | `running` | `images` | 40 |
| 4 | 50 … 99 | `running` | `assembling` | as reported |
| 1 | 100 | `checking` → `succeeded` | `checking` → `done` | 100 once succeeded |
| -1 | any | `failed` (+ mapped code) | last stage | as reported |

`percent = max(previous, reported)` (never decreases, D5); 100 is written only with a terminal state.

**Failure mapping** (`OutcomeMapper`, 05 D5):

| MPT `failed_stage` | adapter outcome `code` | `detail` | Retry (00 §7) |
|---|---|---|---|
| `audio` | `tts_failed` | `audio` | yes |
| `materials` | `image_generation_failed` (the Worker's `03.4.2-T1` reclassifies to `image_moderated` from `images.v1`) | `materials` | per 03 D7 |
| `video` | `render_assembly_failed` | `video` | yes |
| `preflight`, `script`, `terms`, `pipeline` | `render_node_error` | the stage | yes, on another node + ops alert |
| any other value | `render_node_error` | the raw stage, truncated to 64 chars | yes + ops alert |
| lost: MPT 404 for a submitted task | `render_lost` | `mpt_task_missing` | yes |
| lost: MPT process start newer than `backend_started_at` | `render_lost` | `mpt_restarted` | yes |
| no `failed_stage` present | `render_node_error` | `unknown_stage` | yes + ops alert |

A cancelled task never becomes `succeeded`: on MPT's terminal state it is set to `cancelled` (no `outcome`) and `TaskDirCleaner` removes the task dir at once (05 D4).

- [ ] `percent` never decreases even when MPT reports a lower value; 100 appears only with a terminal state.
- [ ] `GET /v1/renders/{id}` performs **zero** MPT calls while the poller is stopped (asserted on `FakeMptServer` request count).
- [ ] A fake MPT that returns 404 for a submitted task, and a fake whose process start jumps after `backend_started_at`, both produce `failed` + `render_lost` (`detail` `mpt_task_missing` / `mpt_restarted`).
- [ ] A failed task reports only a 05 D5 code and a fixed message; the fake MPT's exception text appears in the log sink and **not** in `outcome.message` (S4).
- [ ] The store survives an adapter restart: a task submitted before the restart is still polled and reaches a terminal state; a task whose store row was deleted → 404 → Worker-side `render_lost` (ruling T2, asserted in T1's route test with this store).
- [ ] `DELETE` on a running task → 409 `adapter_task_busy` and no MPT delete; after success → 204 with the MPT task, the task dir and both relay files gone, `cleaned_at` set, and a second delete → 204.
- [ ] Cancel: `cancel_requested = true` immediately, no MPT call, the image plan released, and on MPT's terminal state `state = cancelled` with the task dir removed.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| MPT unreachable while polling | task stays non-terminal, `attempts++`, exponential log back-off (2 s → 30 s cap); `attempts` > 900 (30 min at 2 s) logs an ops alert line; never marked failed by the poller (the Worker raises `render_timeout`, 05 D5) |
| MPT 401/403 | log once, health source reports `mpt_unauthorized`, no state change |
| MPT progress goes backwards | ignored for `percent`; `mpt_json` keeps the raw values |
| MPT returns a state the mapping does not know | `failed` `render_node_error` detail `unknown_state` |
| Adapter restart mid-task | polling resumes from `backend_task_id`; a missing store row is the Worker's problem (T2 ruling) |
| Deleting a task whose dir is already gone | `DeleteAsync` treats `DirectoryNotFoundException`/`FileNotFoundException` as success (idempotent) |
| Relay files missing at cleanup | ignored (03.4.3-T1 owns their lifecycle) |
| `mpt_json` snapshot lacks `warnings` | stored as `[]` |
| Rollback | the store is additive; reverting the release dir keeps `tasks.db` (schema v1 forward-compatible) |

## Notes

- `MptClient` is the only place `NTS_MPT_API_KEY` is read (S3/S6); it is never logged and never leaves the adapter.
- `mpt.warnings` comes from MPT's task dict, which is `extra="allow"` and documented to carry `warnings` (05 C6, `05 README:33`); when a snapshot lacks it the adapter stores `[]`.
- `FakeMptServer` is the only MPT in tests; the real MPT is exercised on the node by `11-node` (D18).
