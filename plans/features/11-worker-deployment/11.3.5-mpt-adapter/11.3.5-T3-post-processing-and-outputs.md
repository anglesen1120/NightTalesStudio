## Goal

Turn an MPT-completed task into a served output: run `render_check.py run --normalize` (D6a) under `Adapter:CheckConcurrency` and `Adapter:CheckTimeoutSeconds`, store the report as the status `check`, publish `RenderOutputV1` from the report, stream `final-1.norm.mp4` and `subtitle.srt` with `X-Content-SHA256` taken from the check (never re-hashed, 05 D15 P3), and enforce the 05 D15 P4 disk rules for cancelled, succeeded and failed tasks.

## Design

| Component | Responsibility |
|---|---|
| `PostProcessor : BackgroundService` | consumes finished tasks from T2's seam; one worker per `Adapter:CheckConcurrency`; sets `stage = checking`, runs the check, publishes the result, moves to `succeeded`/`failed` |
| `CheckRunner` | builds the argument list, starts the process with `UseShellExecute = false`, `RedirectStandardOutput/Error`, no stdin; kills on timeout (SIGTERM, then SIGKILL after 10 s); returns exit code + report path |
| `CheckReportReader` | reads `<task dir>/render-check.json` via `RenderNodeJson.Tolerant` into `RenderCheckV1`; copies it to `/var/lib/nts/adapter/tasks/<task_id>/render-check.json` (survives the MPT dir being removed) |
| `OutputPublisher` | builds `RenderOutputV1` and stores it: video from `check.output`, subtitles from `subtitle.srt` (streamed sha256 + `cues` from `check.subtitles.cues`), `narration_seconds` from `check.narration.duration_s` |
| `FileOutputSource : IRenderBackend` (output half) | `OpenOutputAsync` → `FileStream(…, SequentialScan)` with `Length` + stored sha256 + content type; never reads the whole file, never re-hashes |
| `DiskRuleEnforcer` | cancel → remove the task dir + root norm file at once; delete → remove after ingest; other failures → keep 24 h (then `TaskDirCleaner`/`11.3.4-T1`) |

Exact command (D6a; one argument per list element, no shell):

```
/usr/bin/python3.12 /opt/nts/current/worker-node/checks/render_check.py
  run --task-dir <task dir> --aspect landscape|portrait --subtitles on|off --normalize
      --out <task dir>/render-check.json
```

Environment: `PATH=/usr/bin:/bin`, `Adapter__FfmpegPath` passed as `FFMPEG_PATH` only if the tool reads it, no MPT key, no adapter key (S6); working directory `/opt/nts/current`; stdout/stderr captured to the journal, truncated to 8 KiB each. Timeout: `Adapter:CheckTimeoutSeconds` (900) measured from process start; on expiry → kill, `stage = checking` → `failed` `render_node_error` `detail = check_timeout`.

Exit handling (D6a, D9): exit 0 → report is authoritative for `output`/`check` (a non-empty `errors[]` is **not** a failure here — the Worker's `RenderQualityEvaluator` decides, 05 D10); exit 1 → `failed` `render_node_error` `detail = check_failed` with the report attached when it exists; exit 2 → the same plus an ops-alert line naming the environment problem; a missing report with exit 0 → `check_failed`.

`RenderOutputV1` publication:

| Field | Source |
|---|---|
| `video.bytes` / `video.sha256` | `check.output.bytes` / `check.output.sha256` (`final-1.norm.mp4`) |
| `video.cues` | `null` |
| `subtitles.bytes` / `subtitles.sha256` | `subtitle.srt` size and a 1 MiB-chunk sha256 computed once here (P3) |
| `subtitles.cues` | `check.subtitles.cues` |
| `narration_seconds` | `check.narration.duration_s` |

`output.subtitles` is `null` when `--subtitles off` was submitted or the SRT is absent → `/subtitles` answers 404 `adapter_output_absent`. `check.output` missing or `normalized = false` (no `--normalize` effect) → `failed` `render_node_error` `check_failed`, because the served file must be the measured normalised one (P2).

Serving: `GET /v1/renders/{id}/video` → `200`, `Content-Type: video/mp4`, `Content-Length` = `output.video.bytes`, `X-Content-SHA256` = `output.video.sha256`, body streamed; a non-terminal task → 409 `adapter_output_not_ready`; cleaned/`succeeded`-without-file → 404. `subtitles` → `application/x-subrip; charset=utf-8`. Both resolve paths from the stored `backend_task_id`, never from the request (S8).

## Acceptance checks

- [ ] A fake MPT that completes produces exactly one `render_check.py run --normalize` process with the argument list of D6a, `--aspect` from the submit body and `--out <task dir>/render-check.json`.
- [ ] After a successful run the status shows `state = succeeded`, `stage = done`, `percent = 100`, `check` equal to the report file and `output.video.bytes/sha256` equal to the report's `output` values.
- [ ] `GET .../video` sends `X-Content-SHA256` equal to `check.output.sha256` and `Content-Length` equal to `check.output.bytes`; no code path reads the whole file (asserted via a stream that fails if fully buffered / a `ReadAllBytes` guard test).
- [ ] `GET .../subtitles` answers `200 application/x-subrip; charset=utf-8` with `cues` = `check.subtitles.cues`, and `404 adapter_output_absent` when the submit had `--subtitles off`.
- [ ] A check that exceeds `CheckTimeoutSeconds` (fake clock / 2 s override) → `failed`, `outcome.code = render_node_error`, `detail = check_timeout`, and the process is killed.
- [ ] Exit 1 and exit 2 both → `failed` `check_failed`; exit 2 also writes one ops-alert line; exit 0 with a non-empty `errors[]` stays `succeeded` and keeps the report as `check`.
- [ ] With `CheckConcurrency = 1`, two tasks finishing together run their checks strictly one after the other (a fake runner records overlapping intervals).
- [ ] Disk rules: a cancelled task's `final-1.norm.mp4` and task dir are gone immediately; a succeeded task's files survive until `DELETE`; a failed task's files survive and `TaskDirCleaner` is invoked for them after 24 h.
- [ ] Cancel arriving while `stage = checking` ends the task as `cancelled` (never `succeeded`) and removes the task dir once the running process has exited.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Timeout | kill (SIGTERM → 10 s → SIGKILL), `failed` `check_timeout`, no re-submit to MPT (the Worker's retry policy applies) |
| Report present but unparseable | `failed` `check_failed`, the raw bytes copied to the adapter dir and logged as a hash only |
| `subtitle.srt` changed after the check | the stored sha is served; the Worker's `render_output_invalid` catches the mismatch (05 D5) — the adapter never re-hashes |
| Disk full while writing `final-1.norm.mp4` | the tool exits non-zero → `check_failed`; health `disk_low` blocks new dispatch |
| MPT task dir removed under us | `failed` `check_failed`; cleanup is idempotent |
| Adapter restart while a check is running | the child process dies with the host; on restart the task is re-checked once if `stage = checking` (idempotent: the tool overwrites its report) |
| Concurrent cancel + delete | cancel wins for `state`; delete returns 409 until terminal, then removes |
| Rollback | `Adapter:CheckTimeoutSeconds`/`CheckConcurrency` are config-only; reverting the release restores the previous arguments, the store keeps already published outputs |

## Notes

- `render-check.v1` has no `output` entry for the **subtitles** file while 05 D4 requires `bytes`/`sha256`/`cues` in `output.subtitles`; this task hashes the SRT once after the check and takes `cues` from the report (`[INFERENCE]`, `plan.md` §10 Open items).
- The adapter never decides pass/fail (05 D9/D10): it stores `check` verbatim and publishes `output`; `render_quality_failed` is raised by the Worker.
- Norm file ownership: the tool writes `final-1.norm.mp4` inside MPT's task dir, which D8 makes group-writable (`2770 nts-mpt:nts-render`).
