## Goal

Four buckets per environment with the names other plans already use — `nt-media-<env>`, `nt-public-<env>`, `nt-music-<env>`, `nt-backup-<env>` — with pinned prefixes, visibility, SSE, lifecycle and CORS, plus one least-privilege credential per consumer: the node music key reads `music/` and nothing else, the app key cannot touch the music or backup buckets and cannot write `nt-public-<env>`. This task also owns the `nt-media-<env>` → `nt-backup-<env>` replication (provider replication, else a provider-run scheduled copy) with a put-only replication credential and object lock where available (D20 H9). These names, prefixes and cache headers are the contract consumed by `04.2.3-T1` (`voice-previews/`), `03.1.2-T1` (`style-previews/`) and `05.3.2-T2` (`music/`, `music-evidence/`).

## Design

| Bucket | Visibility | Versioning | SSE | Lifecycle |
|---|---|---|---|---|
| `nt-media-<env>` | private | off | on | `tmp/`: expire **1 day** |
| `nt-public-<env>` | public-read on `voice-previews/` + `style-previews/` only | off | on | none |
| `nt-music-<env>` | private | off | on | none |
| `nt-backup-<env>` | private | off | on | expire **30 days** |

- **Policies as data:** `worker-node/storage/policies/{media,public,music,backup,lifecycle,cors}.json` [INFERENCE: paths] are the single source; **this task applies them through `infra/modules/platform`'s storage resources** (it depends on `11.2.2-T1`), not through `11.2.2-T2` (D20 H20), and `tools/dev/storage-init.sh` (`11.1.1-T2`) must read the same files (CR requested). Public read is a prefix-scoped bucket policy on `<bucket>/voice-previews/*` and `<bucket>/style-previews/*` — never bucket-wide.
- **Credentials:**

| Consumer | Path | Scope |
|---|---|---|
| Api + Worker | `nts/<env>/STORAGE_ACCESS_KEY`, `…/STORAGE_SECRET_KEY` (✅ D15) | rw `nt-media-<env>` + read on the two preview prefixes; **no write** on `nt-public-<env>`; deny `nt-music-*`, `nt-backup-*` (D20 H9) |
| Operator `upload_music.py` | `nts/<env>/NTS_MUSIC_WRITE_KEY`, `…_SECRET` [INFERENCE] | write `music/` + `music-evidence/` |
| Node `sync-music.sh` | `nts/<env>/NTS_MUSIC_READ_KEY`, `…_SECRET` (✅ D11) | read `music/` only; writes and `music-evidence/` denied |
| Backup job `11.6.1-T1` | `nts/<env>/BACKUP_ACCESS_KEY`, `…_SECRET` [INFERENCE] | read `nt-media-<env>`, write `nt-backup-<env>`; the replication path uses a **put-only** credential into `nt-backup-<env>` with object lock where the provider has it (D20 H9) |
| Operator preview upload | `nts/<env>/NTS_PREVIEW_WRITE_KEY`, `…_SECRET` (Keychain `nts.preview.write`) (D20 H9) | **put only** on `voice-previews/` + `style-previews/`; no read, no other prefix | `04.2.3-T1`, `03.1.2-T1` |

- **CORS** (only for presigned GET of private objects): origins = the web origin from `nts/<env>/APP_ORIGIN` = `App:PublicOrigin` (one origin per env, `../../10-web-ui/README.md` D3; 10 CR-3), never `*`; methods `GET`/`HEAD`/`OPTIONS`; allowed header `Range`; exposed `Content-Length`, `Content-Range`, `ETag`, `X-Content-SHA256`; max age 3000. On `nt-media-<env>` and `nt-public-<env>`.
- **Uploads:** preview PUTs use a conditional put (`If-None-Match: *`) where supported ⚠️, else HEAD-before-put, so an existing key is never overwritten (D20 H9).
- **No client-side key:** provider default SSE; versioning off on purpose — object recovery is `11.6.1-T1`'s copies.
- **One script:** `worker-node/storage/check-buckets.sh [--env <env>] [--self-test]`, idempotent, one line per assertion.

## Steps

1. Read the `11.2.1-T1` decision; record provider, CLI name/version and its credential mechanism in `worker-node/storage/README.md`. If the CLI cannot take credentials off argv, stop and escalate (the CLI choice is part of this task).
2. Write the six policy JSONs with the exact names/prefixes/cache headers from Inputs.
3. Apply the policy JSONs through `infra/modules/platform`'s storage resources (this task, D20 H20); request the CR to `11.1.1-T2` so the dev init script reads the same JSON.
4. Create the credentials per env at the D15/D11 paths plus the preview operator key `nts/<env>/NTS_PREVIEW_WRITE_KEY`/`_SECRET` (`11.5.2-T1` owns the secret manager); the replication credential is put-only on `nt-backup-<env>` (D20 H9).
5. Write `check-buckets.sh` with the checks in §Tests; run it against `dev`; fix failures (`nt-backup-dev` may legitimately be absent — warn, do not create).
6. Prove the preview contract on dev (HEAD 404 → PUT with the immutable cache header → HEAD 200 equal length; a second PUT is refused by the conditional put, D20 H9) and run the negative credential tests plus one positive control; paste commands (never values) into `worker-node/storage/README.md`.
7. Record the CDN decision (public-read implemented; CDN is a later provider choice) for `11.2.1-T1`.

## Acceptance checks

- [ ] The four buckets exist per environment with exact names; `nt-media-<env>` has versioning off and SSE on; lifecycle is `tmp/` = 1 day and `nt-backup-<env>` = 30 days with no other rule.
- [ ] Public read is prefix-scoped (anonymous HEAD of a `voice-previews/` and a `style-previews/` object → 200, any other key in `nt-public-<env>` → 403) and CORS preflight from the web origin returns that origin with `Range` allowed, while another origin gets no allow header.
- [ ] Denied, each with the reason recorded: node key `PUT music/<key>` and `PUT nt-media/<env>/<key>`; node key `GET music-evidence/…`; app key `GET` any object in `nt-music-<env>`; app key `PUT` into `nt-backup-<env>`; app key `PUT nt-public-<env>/voice-previews/<key>` (no write, D20 H9). Positive control: node key `GET music/<key>` → 200; operator preview key `PUT voice-previews/<new>.mp3` → 200 while `GET` with it → 403.
- [ ] Preview PUT returns 200 with `audio/mpeg`, `Cache-Control: public, max-age=31536000, immutable`, matching `Content-Length`; overwriting an existing key is refused by the conditional put `If-None-Match: *` (or HEAD-before-put where unsupported, D20 H9).
- [ ] `shellcheck worker-node/storage/check-buckets.sh` silent; no `--env` → exit 2; second run → exit 0 with no provider change; `grep -c 'set -x' …` → 0 and no credential value in any argv or in the script's output.
- [ ] The `nt-media-<env>` → `nt-backup-<env>` replication exists (provider replication, else the provider-run scheduled copy) with a put-only credential and object lock where available; a write into `nt-media-<env>` appears in `nt-backup-<env>` (D20 H9).

## Failure handling and edge cases

| Case | Handling |
|---|---|
| No provider CORS support (or CORS is CDN-only) | Escalate: the serving proxy or CDN becomes mandatory; never ship an unusable presigned GET |
| A preview object 403s after a policy edit | Policy regression; re-apply the JSON and re-run the checker. Never widen to bucket-wide public read |
| The 1-day lifecycle removes an object still needed | Wrong prefix at the writer (`09.7.x`); fix the writer, never extend the lifecycle (11 §4 = 1 day) |
| Dev script and policy JSON drift; `nt-backup-dev` missing in dev | CR to `11.1.1-T2` (and `check-buckets.sh --env dev` as detector); warn only for the backup bucket (prod/staging, `11.6.1-T1`) |
| A credential value reaches a log or argv | Treat as leaked: rotate per `docs/runbooks/secrets-rotation.md`, then fix the caller |
| Rollback | Re-apply the previous policy JSONs via the IaC module; a policy rollback deletes no object (lifecycle is the only deletion path) |
