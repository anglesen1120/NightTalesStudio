## Goal

Four buckets per environment with the names other plans already use — `nt-media-<env>`, `nt-public-<env>`, `nt-music-<env>`, `nt-backup-<env>` — with pinned prefixes, visibility, SSE, lifecycle and CORS, plus one least-privilege credential per consumer: the node music key reads `music/` and nothing else, the app key cannot touch the music or backup buckets and cannot write `nt-public-<env>`. Buckets live on the self-hosted SeaweedFS of `11.4.1-T2` (D21, 11 CR-15); this task creates `nt-backup-<env>` on `storage-backup-<env>` with versioning + object lock (GOVERNANCE 29 d at creation, T87), the `Write`-only backup key (no `BypassGovernanceRetention`/`Admin`, T88) and the `NTS_CANARY_WRITE` put-only `_canary/` identity (T85), while the `nt-media-<env>` → `nt-backup-<env>` copy itself (`weed filer.backup`) is `11.4.1-T3`'s (T80, D20 H9, T74). These names, prefixes and cache headers are the contract consumed by `04.2.3-T1` (`voice-previews/`), `03.1.2-T1` (`style-previews/`) and `05.3.2-T2` (`music/`, `music-evidence/`); `apply-buckets.sh`/`head-bucket`/`list-buckets` run with the apply-window `NTS_OPS_ADMIN` identity (T92).

## Design

| Bucket | Visibility | Versioning | SSE | Lifecycle |
|---|---|---|---|---|
| `nt-media-<env>` | private | off | on | `tmp/`: expire **1 day** |
| `nt-public-<env>` | public-read on `voice-previews/` + `style-previews/` only | off | on | none |
| `nt-music-<env>` | private | off | on | none |
| `nt-backup-<env>` | private | on (object lock GOVERNANCE 29 d at creation, T87, 11 CR-15) | on | `NoncurrentVersionExpiration` **29 days**, no current-version `Expiration` (T87) |

- **Policies as data:** `worker-node/storage/policies/{media,public,music,backup,lifecycle,cors}.json` [INFERENCE: paths] plus `identities.template.json` (the `s3.json` actions per identity, no secrets — **owned by this task**, consumed by `11.4.1-T2`'s `sync-identities.sh`, T82; `NTS_OPS_ADMIN`'s actions are rendered only by `--with-admin`, T92) are the single source; **this task applies them through the S3 API with `worker-node/storage/apply-buckets.sh --env <env>`** (idempotent: `create-bucket`, `put-bucket-policy`, `put-bucket-cors`, `put-bucket-encryption` SSE-S3, `put-bucket-lifecycle-configuration`), run by the operator over the VPN (443 to the gateway, T86) with `NTS_OPS_ADMIN` during an apply window (T92); not IaC resources (D21, supersedes D20 H20 for buckets). `tools/dev/storage-init.sh` (`11.1.1-T2`) calls the same script with `--env dev` (CR requested). Public read is anonymous `Read` scoped to `<bucket>/voice-previews/*` and `<bucket>/style-previews/*` — never bucket-wide. `nt-backup-<env>` lives on `storage-backup-<env>` and is created there with versioning + object lock with default retention GOVERNANCE 29 days (object lock can only be enabled at creation ✅ SeaweedFS, T87).
- **Credentials:**

| Consumer | Path | Scope |
|---|---|---|
| Api + Worker | `nts/<env>/STORAGE_ACCESS_KEY`, `…/STORAGE_SECRET_KEY` (✅ D15) | rw `nt-media-<env>` + read on the two preview prefixes; **no write** on `nt-public-<env>`; deny `nt-music-*`, `nt-backup-*` (D20 H9) |
| Operator `upload_music.py` | `nts/<env>/NTS_MUSIC_WRITE_KEY`, `…_SECRET` [INFERENCE] | write `music/` + `music-evidence/` |
| Node `sync-music.sh` | `nts/<env>/NTS_MUSIC_READ_KEY`, `…_SECRET` (✅ D11) | read `music/` only; writes and `music-evidence/` denied |
| Backup `filer.backup` (`11.4.1-T3`, T80, 11 CR-15) | `nts/<env>/storage/BACKUP_ACCESS_KEY`, `…/BACKUP_ACCESS_KEY_SECRET` (T91, T94) | identity on `storage-backup-<env>`: `Write` on `nt-backup-<env>` only — SeaweedFS has no `DeleteObjectVersion` action (`Write` covers all deletes), so the object lock is the guard; never `BypassGovernanceRetention`/`Admin` (T88); `filer.backup` reads the primary through the filer port, not through an S3 identity (D21, D20 H9) |
| Backup lag canary (`11.4.1-T3`, T85) | `nts/<env>/storage/NTS_CANARY_WRITE`, `…_SECRET` (T91) | put only on `nt-media-<env>/_canary/` (the `heartbeat` object); no read, no other prefix |
| Restore leg (`11.6.1-T1`, `11.4.1-T3` restore test) | `nts/<env>/storage/NTS_OPS_READ`, `…_SECRET` (T91) | `Read`/`List` on `nt-backup-<env>` only, no write — the named read identity used to fetch objects/noncurrent versions over the VPN, never `BACKUP_ACCESS_KEY` (T88/T91) |
| Backup lag gauge (`11.4.1-T3` `--metrics` timer) | `nts/<env>/storage/NTS_BACKUP_PROBE`, `…_SECRET` (T95) | `Read` on `nt-backup-<env>/nt-media-<env>/_canary/*` only — no `List`, no write; the continuously-held key on `storage-backup-<env>`, same prefix-scoped pattern as `NTS_CANARY_WRITE` (T85/T95, 11 CR-15) |
| Operator preview upload (`04.2.3-T1`, `03.1.2-T1`) | `nts/<env>/NTS_PREVIEW_WRITE_KEY`, `…_SECRET` (Keychain `nts.preview.write`) (D20 H9) | **put only** on `voice-previews/` + `style-previews/`; no read, no other prefix |
| `apply-buckets.sh`, `head-bucket`, `list-buckets` (apply window) | `nts/<env>/storage/NTS_OPS_ADMIN`, `…_SECRET` (T92) | `Admin` — rendered into `s3.json` only by `sync-identities.sh --with-admin` for the window, removed by the next plain run; `check-storage-host.sh` fails while it lingers; the sole exception to T88's "no `Admin`" |

- **CORS** (only for presigned GET of private objects): origins = the web origin from `nts/<env>/APP_ORIGIN` = `App:PublicOrigin` (one origin per env, `../../10-web-ui/README.md` D3; 10 CR-3), never `*`; methods `GET`/`HEAD`/`OPTIONS`; allowed header `Range`; exposed `Content-Length`, `Content-Range`, `ETag`, `X-Content-SHA256`; max age 3000. On `nt-media-<env>` and `nt-public-<env>`.
- **Uploads:** preview PUTs use a conditional put (`If-None-Match: *`, ✅ SeaweedFS atomic compare-and-create, 412 on an existing key), so an existing key is never overwritten (D20 H9). HEAD-before-put stays as the client-side guard already in `make_previews.py`.
- **No client-side key:** SSE-S3 bucket default (SeaweedFS-managed keys ✅) on top of the provider-encrypted volume; versioning off on the primary on purpose — object recovery is the `nt-backup-<env>` copy (`11.4.1-T3`, T80) and volume snapshots.
- **One script:** `worker-node/storage/check-buckets.sh [--env <env>] [--self-test]`, idempotent, one line per assertion.

## Steps

1. On dev compose, verify SeaweedFS honours `NoncurrentVersionExpiration` and object lock (GOVERNANCE retention) at the pinned digest: create a versioned, object-locked scratch bucket, apply the rule, write + delete an object, confirm the noncurrent version is governed (T87 ⚠️ → ruling); in the same scratch setup check whether a **bucket policy** can deny version deletes to a `Write`-only identity (T88 ⚠️ → ruling — no `DeleteObjectVersion` action exists in `s3.json`); if either is unsupported, escalate to the TL before `11.4.1-T3` starts. Record the CLI (`aws` via `uvx --from awscli`, version), the endpoint per env (`https://storage-<env>.internal`, 443, T77, 11 CR-15), path-style addressing and the credential mechanism (environment only, never argv) in `worker-node/storage/README.md`.
2. Write the six policy JSONs and `identities.template.json` (the `s3.json` actions per identity, no secrets — handed to `11.4.1-T2`'s `sync-identities.sh`, T82) with the exact names/prefixes/cache headers from Inputs.
3. Write `apply-buckets.sh` and apply the JSONs to dev, then staging and prod over the VPN; request the CR to `11.1.1-T2` so the dev init script calls the same script.
4. Create the credentials per env at the D15/D11 paths plus the preview operator key `nts/<env>/NTS_PREVIEW_WRITE_KEY`/`_SECRET` (`11.5.2-T1` owns the secret manager); the backup credential is `Write` on `nt-backup-<env>` only, never `BypassGovernanceRetention`/`Admin` (T88); the `s3.json` identity keys live under `nts/<env>/storage/` (T91), each pair `<NAME>` + `<NAME>_SECRET` (T94): `nts/<env>/storage/BACKUP_ACCESS_KEY`/`BACKUP_ACCESS_KEY_SECRET`, `nts/<env>/storage/NTS_CANARY_WRITE`/`_SECRET` (put-only on `nt-media-<env>/_canary/`, T85), `nts/<env>/storage/NTS_OPS_READ`/`_SECRET` (`Read`/`List` on `nt-backup-<env>` for the restore leg, T91), `nts/<env>/storage/NTS_BACKUP_PROBE`/`_SECRET` (`Read` on `nt-backup-<env>/nt-media-<env>/_canary/*` only for the T85 lag gauge — no `List`, no write, T95) and `nts/<env>/storage/NTS_OPS_ADMIN`/`_SECRET` (apply window only, T92); add the `NTS_OPS_READ` + `NTS_BACKUP_PROBE` + `NTS_OPS_ADMIN` rows to `identities.template.json`; ask `11.4.1-T2` to re-run `sync-identities.sh` with the full template (T82, 11 CR-15).
5. Write `check-buckets.sh` with the checks in §Tests; run it against `dev`; fix failures (`nt-backup-dev` may legitimately be absent — warn, do not create).
6. Prove the preview contract on dev (HEAD 404 → PUT with the immutable cache header → HEAD 200 equal length; a second PUT is refused by the conditional put, D20 H9), PUT the permanent probe object `voice-previews/_probe.v1.mp3` to `nt-public-staging` with the `NTS_PREVIEW_WRITE_*` key (immutable header, never overwritten) so the anonymous GET in §Acceptance checks has a known object, and run the negative credential tests plus one positive control; paste commands (never values) into `worker-node/storage/README.md`.
7. Record the public-read decision (anonymous `Read` on the two preview prefixes, served through `https://media.<domain>` / `media.staging.<domain>`; no CDN in P, T75, 11 CR-15) for `11.2.1-T1`.

## Failure handling and edge cases

| Case | Handling |
|---|---|
| A CORS rule is not honoured by the pinned SeaweedFS gateway | Escalate: CORS is added at the LB for `media.<domain>` (D21) and recorded as a README ruling; never ship an unusable presigned GET |
| A preview object 403s after a policy edit | Policy regression; re-apply the JSON and re-run the checker. Never widen to bucket-wide public read |
| The 1-day lifecycle removes an object still needed | Wrong prefix at the writer (`09.7.x`); fix the writer, never extend the lifecycle (11 §4 = 1 day) |
| Dev script and policy JSON drift; `nt-backup-dev` missing in dev | CR to `11.1.1-T2` (and `check-buckets.sh --env dev` as detector); warn only for the backup bucket (prod/staging, `11.6.1-T1`) |
| A credential value reaches a log or argv | Treat as leaked: rotate per `docs/runbooks/secrets-rotation.md`, then fix the caller |
| Rollback | Re-apply the previous policy JSONs with `apply-buckets.sh`; a policy rollback deletes no object (lifecycle is the only deletion path) |
