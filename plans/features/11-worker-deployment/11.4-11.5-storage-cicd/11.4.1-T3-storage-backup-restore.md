## Design

- **Backup service.** On `storage-backup-<env>` the compose `backup` service runs `weed filer.backup -filer=storage-<env>.internal:8888 -filerPath=/buckets/nt-media-<env> -filerProxy -doDeleteFiles=true` (T79), under the same `nts-storage.service`; `replication.toml` `[sink.s3]` points at `https://storage-backup-<env>.internal` (T81), bucket `nt-backup-<env>`, directory `/nt-media-<env>`, `is_incremental = false` (`true` drops deletes and date-prefixes keys, T85), with `BACKUP_ACCESS_KEY`/`_SECRET` rendered by `sync-identities.sh`. The filer gRPC and volume ports are never exposed beyond `storage-backup-sg` (8888/18888, T78).
- **Delete semantics.** Deletes propagate as delete markers (`-doDeleteFiles=true`); versioning + object lock keeps the noncurrent version for 29 d and `NoncurrentVersionExpiration` 29 d + daily detection removes it within 30 days of the delete (T87). The backup identity is `Write` only — SeaweedFS has no `DeleteObjectVersion` action, so the object lock is the guard: a locked version (< 29 d) cannot be removed and no identity gets `BypassGovernanceRetention`/`Admin` (T88).
- **Lag canary + gauge (T85).** `filer.backup` has no `-metricsPort` (✅ pin). This task ships `worker-node/storage/host/nts-storage-canary.{service,timer}` on `storage-<env>`: every 5 min it puts `nt-media-<env>/_canary/heartbeat` with `NTS_CANARY_WRITE`/`_SECRET` (a `0600` env file rendered alongside `s3.json` by `sync-identities.sh`, T82). A 5-min timer on `storage-backup-<env>` runs `check-storage-host.sh --metrics` (added in this task), which pushes the gauge `nts_backup_lag_seconds` = now − `LastModified` of the backup copy over OTLP/HTTP 4318 to the collector on the Worker host (`worker-sg` allows 4318 from `storage-backup-sg`, T86). `11.6.2-T1` alerts at `nts_backup_lag_seconds > 900`.
- **Checker assertions (backup side).** Copy present, `nts_backup_lag_seconds` ≤ 900, delete propagated as a marker, backup identity cannot `GET` and cannot delete a locked version (T88), lifecycle executed, restore sha256 equal — one line each.

## Failure handling and edge cases

| Case | Handling |
|---|---|
| `NoncurrentVersionExpiration` unsupported at the pin | The T87 ⚠️ fails open in `11.4.1-T1` step 1 → the TL rules before this task starts; never substitute a current-version `Expiration` (it would expire live objects) |
| `filer.backup` stops or lags | It resumes from its offset on restart; never delete the offset to "catch up"; alert is `11.6.2-T1`'s (`nts_backup_lag_seconds > 900`) |
| Primary filer unreachable from the backup host | `storage-sg` rule for 8888/18888 from `storage-backup-sg` is missing or wrong — fix in `11.2.2-T1`'s module, never widen to other sources |
| Backup host lost | Recreate from IaC; if the volume survives, reattach it and `filer.backup` resumes from its offset; if the volume is lost/rebuilt (wiped destination), start `filer.backup` **once with `-initialSnapshot`** to re-seed `nt-backup-<env>`, then restart without it — the checkpoint lives on the source filer, so a resume alone would silently leave the backup empty (T89) |
| Restore sha256 mismatch | Treat as corruption: keep the object, copy the version explicitly (`--version-id`), alert `11.6.2-T1`; drill retargeted to a second object in `11.6.1-T1` |
| Rollback | Stop the `backup` service; objects already in `nt-backup-<env>` stay (lock); restart resumes from the offset — if the rollback wiped the destination, one `-initialSnapshot` start first (T89) |
