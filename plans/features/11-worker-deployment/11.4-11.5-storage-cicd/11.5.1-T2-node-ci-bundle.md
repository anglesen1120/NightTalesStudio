# 11.5.1-T2 — Node CI: `node.yml`, adapter publish and the node bundle

## Goal

One workflow runs everything node-side that can run without a GPU — proxy pytest, `render_check.py --self-test`, `check_fixtures.py`, shellcheck of the node scripts — and produces the versioned node bundle `nts-node-<version>.tar.zst` with `MANIFEST.json` and `SHA256SUMS`, published as a workflow artifact on every run and as a GitHub release asset **only from `refs/heads/main` runs (no tag releases, D20 H6)**, so `nts-node deploy` (11.3.1-T3) has one verifiable input. An always-running `node-gate` job aggregates the jobs and is the required status check (D20 H19).

## Design

| Job | Runs | Gate |
|---|---|---|
| `proxy` | `uv sync --frozen` in each `worker-node/*` project, then pytest over `worker-node/proxy/tests` and the 04 suites | — |
| `checks` | `python3 worker-node/checks/render_check.py --self-test`; `python3 worker-node/checks/check_fixtures.py` over `worker-node/contract/fixtures/*.json`; `python3 infra/scoring/score.py --self-test`; `python3 worker-node/checks/capacity_run.py --self-test` (D20 H19) | — |
| `shellcheck` | `shellcheck --severity=warning` over `worker-node/{bin,host,net,storage}/*.sh`, `infra/checks/*.sh`, `tools/ops/*.sh` (the proxy unit file is not a shell script; D20 H19) | — |
| `adapter` | `dotnet restore --locked-mode` → `dotnet publish src/NightTales.MptAdapter -c Release -r linux-x64 --self-contained -o artifacts/adapter` (E8) | — |
| `bundle` | assemble the D12 layout, write `MANIFEST.json` (versions from `worker-node/pins.env`, `ref`, `git_sha`, `run_id`, file list with sha256 — D20 H6) and `SHA256SUMS`, `tar --zstd -cf nts-node-<version>.tar.zst` | `proxy`, `checks`, `shellcheck`, `adapter` |
| `release` | upload the artifact always; **only on `refs/heads/main`** attach the three files to the GitHub release for `<version>` (no tag releases, D20 H6) | `bundle` |
| `node-gate` | always runs (`if: always()`), fails unless every job above succeeded; the single required status check (D20 H19) | `proxy`, `checks`, `shellcheck`, `adapter`, `bundle`, `release` |

- **Triggers (D20 H19):** `pull_request` + push to `main` + `workflow_dispatch`, with path filters `worker-node/**`, `src/NightTales.RenderNode.*/**`, `src/NightTales.MptAdapter/**`, `tools/mock-mpt/**`, `tests/NightTales.{RenderNode,MptAdapter,MockMpt}.Tests/**`, `infra/**`, `tools/ops/**`, `seed/**`; an always-running `node-gate` job is the required status check.
- **CI vs node split (D18):** no whisper model load, no nvidia-smi, no ffmpeg codec probe, no `gpu-smoke.sh` in CI. Anything needing the GPU is verified by `worker-node/host/gpu-smoke.sh` on the node (11.3.1-T1) and during `nts-node deploy`.
- **Bundle content is permissive-by-allow-list:** `bundle` copies only the D12 paths and fails on any file matching `*.env`, `*.key`, `*.pem`, `id_*`, `config.toml`, `model.bin`, `**/weights/**` — a deny-list grep alone is not proof.
- **`MANIFEST.json`** carries `version`, `ref`, `git_sha`, `run_id`, `built_at`, `mpt_commit`, `vieneu_commit`, `whisper_model_revision`, `mpt_python`, `vieneu_python`, `nvidia_driver` (from `pins.env`) and `files: [{path, sha256, bytes}]`; `SHA256SUMS` is the same list in `sha256sum -c` format. `ref`/`git_sha`/`run_id` are the provenance `nts-node deploy` checks (D20 H6).
- **Caching:** NuGet via the SDK action's cache; `uv` cache keyed on the lock files. No secret is needed or available to this workflow.

## Steps

1. Confirm the exact check entry points and their CLI (`render_check.py --self-test`, `check_fixtures.py`) with `05`, and the proxy test directories with `04`; record the paths in the workflow comments.
2. Write `node.yml` with the seven jobs above (incl. `node-gate`) and the H19 path filters; pin every action by SHA; add `concurrency` per ref with cancel (a PR run is disposable, a `main` run is not — keep cancel off on `main`).
3. Write the bundle assembly step (allow-list copy, `MANIFEST.json`, `SHA256SUMS`) and the negative check for forbidden file patterns.
4. Add the fixture replay and self-test to the same job as the adapter build so a contract regression fails before the bundle is assembled.
5. Run it on a PR that touches `worker-node/**`; then on `main`; verify the artifact and, on `main`, the release asset with all three files.
6. Run `nts-node deploy --bundle` from `11.3.1-T3` against a staging node with this bundle (the real end-to-end acceptance of the artefact) and record the result.

## Outputs

- New (tracked): `.github/workflows/node.yml`.
- Produced per run: `nts-node-<version>.tar.zst`, `MANIFEST.json`, `SHA256SUMS` (workflow artifact), plus a GitHub release asset only on `refs/heads/main` runs (no tag releases, D20 H6).
- Hand-over: the bundle consumed by `11.3.1-T3`; the publish step reused by `11.5.3-T2` for signing and SBOM.

## Acceptance checks

- [ ] A PR touching any H19 path runs `proxy`, `checks`, `shellcheck`, `adapter`, `bundle` and the always-running `node-gate`, all green on the current tree; a deliberately failing proxy test and a broken fixture each turn their own job red and `node-gate` red (D20 H19).
- [ ] `grep -n 'uses:' .github/workflows/node.yml` → every `uses:` is a 40-char SHA; no `secrets.` reference; `permissions: contents: read` (plus `contents: write` only in `release`).
- [ ] The bundle for a known commit contains exactly the D12 top-level entries; `tar --zstd -tf` lists no `*.env`, key/PEM file or model binary; `sha256sum -c SHA256SUMS` passes and every `MANIFEST.json` `files[]` entry matches the archive (none missing, none extra).
- [ ] `MANIFEST.json` pins equal `worker-node/pins.env` for every key both files carry.
- [ ] On `refs/heads/main`, the release for `<version>` has the three assets and no release asset is produced for a PR or a tag; `MANIFEST.json` carries `ref = refs/heads/main`, `git_sha` and `run_id` (D20 H6); a re-run for the same commit produces an identical `SHA256SUMS` (`built_at` excluded from the hash list); `nts-node deploy` accepts the bundle on a staging node (`SHA256SUMS` verified, `gpu-smoke.sh` exit 0, adapter health 200).
- [ ] No job loads a whisper model or calls `nvidia-smi` — GPU verification stays on the node (D18).

## Tests

- `node.yml` on a PR (paths filter) → green; then the two deliberate-failure proofs.
- Local rehearsal of the bundle step on the Mac with the same script the job uses (`--version <yyyymmdd>-<sha7> --out /tmp`), then `tar --zstd -tf` and `sha256sum -c`.
- `python3 worker-node/checks/render_check.py --self-test` and `check_fixtures.py` run by hand once with the CI working directory to catch path assumptions (both are also run by the job).
- `shellcheck --severity=warning` over the target set locally before the first CI run, so the job starts green.
- End-to-end: `nts-node deploy` on the staging node with the produced bundle.

## Failure handling and edge cases

| Case | Handling |
|---|---|
| A check needs ffmpeg or the GPU | Move it to `gpu-smoke.sh`/the deploy path (D18); never install CUDA in CI to make it pass |
| `uv sync --frozen` fails because an upstream lock changed | Fail closed: the pin + lock pair is the contract; update `pins.env` and the lock in one reviewed commit |
| Fixture check fails after a contract change | Expected signal: the contract library and the fixtures move together (`11.3.5-T1`) |
| A forbidden file appears in the bundle staging dir | `bundle` fails; remove it from the layout logic — no exception without a TL ruling |
| Bundle exceeds the artifact/release limit, or `<version>` collides | Trim non-runtime files (or split the bundle only with a TL decision); the same commit ⇒ same version, a re-run updates the assets idempotently |
| Runner lacks `zstd`/`shellcheck` | Install pinned versions in the job; never rely on the image |
| Rollback | Re-run `node.yml` for the previous commit and deploy that bundle (the node keeps 3 releases, D12) |
