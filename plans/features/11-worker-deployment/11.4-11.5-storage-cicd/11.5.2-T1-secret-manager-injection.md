## Goal

Every runtime secret lives in the provider's secret manager at a per-service path — `nts/<env>/{api,worker,fetcher,shared}/<NAME>` and `nts/<env>/node/<name>/<NAME>` (D20 H3/T51) — and reaches its consumer at runtime only: containers read it from the injected environment, node services from `/etc/nts/*.env` written by `nts-node`, and nothing in a workflow, bundle, SBOM or log ever contains a value (a value fetched in CI is `::add-mask::`-ed at once and passed through the environment, never argv, D20 H11). Rotation is a written procedure per family, including the adapter `ADAPTER_API_KEY_NEXT` window (no drain), `FETCHER_API_TOKEN`, and the one-time offline `DP_KEK` copy. Secret scanning is enabled where the plan allows and replaced by a local scanner where it does not.

## Design

| Surface | Mechanism | Never |
|---|---|---|
| Containers (api, worker, fetcher, web) | provider secret manager → environment at deploy (`11.2.2-T2`/`T4`), from per-service paths so the API role cannot read `worker/*` or `node/*` (D20 H3) | build arg, committed `.env`, CI secret |
| Node services | `nts-node` reads `nts/<env>/<NAME>` → writes `/etc/nts/<unit>.env` (D8) | inside `nts-node-<version>.tar.zst` (D12) |
| Workflows / Mac operator tools | only `GITHUB_TOKEN` + OIDC in CI; a fetched value is `::add-mask::`-ed and passed via the environment (D20 H11); Keychain (`nts.music.write`, `nts.preview.write`) on the Mac | `secrets.*` in a `pull_request` job; values in argv or history |

- **Rotation, three shapes.** (a) *Overlap-free restart* (`DB_CONNECTION`, `STORAGE_*`, `SMTP_PASSWORD`, `OPENAI_API_KEY`, `YOUTUBE_CLIENT_SECRET`, `RENDER_NODE_<NAME>_API_KEY`): new value → rolling restart of the consumers; keep the old value at a sibling path until the drill passes. (b) *Overlap window* (`ADAPTER_API_KEY` → NEXT per F24; `FETCHER_API_TOKEN` → fetcher restarted after the Api). (c) *JWT_SIGNING_KEY*: restart the Api; existing sessions are invalidated, recorded as accepted in P. `DP_KEK` is never rotated in P — losing it is unrecoverable for encrypted settings (D17).
- **Path map (D20 H3/T51):** `shared` = `DB_CONNECTION`, `DP_KEK`, `STORAGE_ACCESS_KEY`/`_SECRET` (read by api and worker); `api` = `JWT_SIGNING_KEY`, `OPENAI_API_KEY`, `SMTP_PASSWORD`, `YOUTUBE_CLIENT_SECRET`; `worker` = `RENDER_NODE_<NAME>_API_KEY`; `fetcher` = `FETCHER_API_TOKEN`; `node/<name>` = the D11 node keys. The API role cannot read `worker/*` or `node/*`.
- **Verification:** `worker-node/bin/check-secrets.sh --env <env> [--node <name>] [--list]` [INFERENCE: path] prints names and presence only (never values or lengths); exit 0 all present / 1 missing or empty / 2 usage-environment; `--node` also asserts `/etc/nts/*.env` mode `0640` and owner.
- **Scanning:** enable the repository's secret scanning + push protection if E17 allows; otherwise a CI job runs the installed gitleaks build over the full diff (`gitleaks git --redact`, fail closed) and is the only scan in P, gated on the MIT licence check (plan 01 U1).

## Steps

1. Read the `11.2.1-T1` decision for the secret-manager product; record its CLI and path-level access control in `docs/runbooks/secrets-rotation.md` §Tooling.
2. Create the D15 bootstrap paths per environment at the per-service split (`shared`/`api`/`worker`/`fetcher`, D20 H3/T51) and the D11 node paths under `nts/<env>/node/<name>/`.
3. Hand the injection steps to `11.2.2-T2`/`T4` and `11.3.1-T3`; the runbook is the single name list — neither duplicates it.
4. Write `check-secrets.sh` and `docs/runbooks/secrets-rotation.md` (one section per family: steps, verification, rollback, blast radius; `DP_KEK` export once with date and location, not the value).
5. Enable scanning or add the gitleaks fallback job; record which path was taken and why.
6. Drill on staging: rotate `ADAPTER_API_KEY` through the NEXT window during a live render, then rotate `FETCHER_API_TOKEN`; record step numbers, timings and any 401/403.

## Failure handling and edge cases

| Case | Handling |
|---|---|
| Path name differs by case/environment so a consumer gets an empty value | `check-secrets.sh` fails; fix the path — never add a default in code |
| Adapter rotation opens a 401 window | Promote NEXT only after the Worker holds the new current key; else restore the previous value (kept until the drill passes) |
| E17 blocks scanning and the gitleaks licence is not permissive | Stop that step, record it, escalate (a different scanner is a new decision) |
| The provider CLI cannot read a value without printing it | Provider integration must inject directly; the script then checks presence only, never the value |
| A value reached a commit or a log | Rotate first, then remove; history rewriting never replaces revocation |
| Rollback | Sibling previous path kept for the drill length, then deleted in two steps so no consumer is left pointing at a deleted value |
