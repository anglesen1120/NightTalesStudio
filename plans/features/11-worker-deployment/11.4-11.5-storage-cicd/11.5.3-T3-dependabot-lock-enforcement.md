# 11.5.3-T3 — Dependabot and lock enforcement

| Story | Size | Area | Depends on | Blocks | Phase / flag |
|---|---|---|---|---|---|

## Goal

Dependency updates arrive as grouped, reviewable PRs (`nuget`, `npm`, `uv` per `worker-node/*` project, `docker`, `github-actions`) and every CI job fails when a manifest and its lock disagree, so a dependency cannot change without its lock in the same commit. This is the P half of the split high-level 11.5.3-T2 (README §2 F23); signing and SBOM are `11.5.3-T2` (S).

## Inputs

- ✅ README §3 **D16** — ecosystems, weekly, grouped; lock flags `dotnet restore --locked-mode`, `npm ci`, `uv sync --frozen` in every job; §1 **E16** (ecosystems), **E12** (Renovate AGPL → Dependabot).
- ✅ README §2 **F23** — weight/`uv.lock` content hashes are verified in `11.3.1-T1`, not here.
- ✅ `09.1.5-T1:34-37,76` — `backend.yml` already uses `--locked-mode` and creates `.github/dependabot.yml` (nuget + github-actions), which this task extends (T23).
- ⚠️ Unverified: which directories contain a Dockerfile (a `docker` entry without one makes Dependabot error).

## Design

| Ecosystem | Directory | Grouping |
|---|---|---|
| `nuget` | `/` | patches/minors; `Microsoft.*`; test packages |
| `npm` | the web app directory (`10.1.5`) | one group, majors excluded |
| `uv` | each `worker-node/*` project with `pyproject.toml` + `uv.lock` | one group per project |
| `docker` | each directory holding a Dockerfile (five images) | one group (digest bumps) |
| `github-actions` | `/` | one group — the only mechanism that changes `11.5.3-T1`'s SHA pins |

- Weekly, `open-pull-requests-limit: 5`, labels `dependencies` + ecosystem, commit prefix `chore(deps):`.
- Lock enforcement lives in the jobs, not in the bot: a manifest-only hand edit fails its own CI run.
- Out of scope here: weight hashes (`11.3.1-T1`), action pins by hand (`11.5.3-T1`), licence checks (E11/E12 already cover every configured ecosystem).

## Steps

1. List directories that actually contain a manifest, lock file or Dockerfile; omit any without one.
2. Extend `.github/dependabot.yml` (created by 09.1.5-T1 with `nuget` + `github-actions`) with `npm`, `uv` (one entry per `worker-node/*` project) and `docker`, plus schedule, grouping and PR limits [RULED — README §10 T23].
3. Confirm every existing workflow uses its ecosystem's lock-enforcing command; hand any missing step to that file's owner (`09.1.5-T1`, `10.1.5`) rather than editing it silently.
4. Open one deliberate low-risk `github-actions` PR and check: no secrets in the run, the lock-enforcement line in the log, merge possible only with green checks.

## Outputs

- Changed (tracked): `.github/dependabot.yml` (owner of the file: 09.1.5-T1; this task adds three ecosystems, T23).
- Evidence: the first Dependabot PR run URL + lock-enforcement log line, and the list of skipped directories with reasons, in the review PR body.

## Acceptance checks

- [ ] Exactly `nuget`, `npm`, `uv`, `docker`, `github-actions` are configured, weekly, grouped, with PR limits; no directory lacking a manifest.
- [ ] Every `uv` entry points at a `worker-node/*` project that has both `pyproject.toml` and `uv.lock`.
- [ ] `backend.yml`, `web.yml`, `node.yml` and `deploy.yml` each run their lock-enforcing command (grep evidence in the PR).
- [ ] A manifest edited without its lock turns that job red (negative proof on a scratch branch, then reverted).
- [ ] One Dependabot PR exists, is green, and its diff contains manifest + lock; the `github-actions` group is present.

## Tests

- Dependabot PR rehearsal (step 4) — the only real test of the config (a syntax error surfaces as a bot error comment).
- Negative lock test per ecosystem: edit the manifest, keep the lock → job red; restore.
- `grep -n 'locked-mode\\|npm ci\\|uv sync --frozen' .github/workflows/*.yml` → one hit per ecosystem job set.

## Failure handling and edge cases

| Case | Handling |
|---|---|
| "No files found" for a directory | Remove the entry; re-add once the manifest lands |
| A major bump breaks the build | Close it and open an issue; majors are planned work, never merged to quiet the bot |
| Lock enforcement fails on a legitimate lock regeneration | Commit manifest + lock together; never bypass with `--no-restore`/`--force` |
| Two owners write the file | Blocked on the TL ruling (`plan.md` Open items); until then this task writes the whole file |
| Rollback | Revert the config commit (the bot stops opening PRs); merged dependency commits revert normally |
