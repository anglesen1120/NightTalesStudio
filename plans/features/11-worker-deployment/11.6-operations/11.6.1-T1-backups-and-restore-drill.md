## Goal

Configure and prove recovery for `prod`: PITR with WAL 7 d and daily snapshots 30 d; the `nt-media-<env>` → `nt-backup-<env>` copy (noncurrent versions 29 d, T87) **owned by 11.4.1-T3** (`weed filer.backup` on `storage-backup-<env>`; asserted here, never re-implemented) [RULED — README §10 T74/T80] (D21, D20 H9) (11 CR-15); `DP_KEK` exported once offline; then a monthly **timed** drill into a **scratch** DB that re-applies every `data_deletion_requests` row completed after the backup timestamp before the restored system serves data, plus the two storage legs — one object restored out of `nt-backup-<env>` on `storage-backup-<env>` (sha256 compared; a deleted object is fetched as a noncurrent version, T79) and one volume snapshot restored into a scratch volume (D21) (11 CR-15). Targets **RPO 15 min / RTO 4 h** (plan.md §10 Open items). Runbook: `docs/runbooks/restore-drill.md`.

## Design

Tiers (D17): WAL 7 d → PITR to any instant; daily snapshots 30 d → provider restore into a new instance; the `nt-media-<env>` → `nt-backup-<env>` copy — media blobs held as versions, `NoncurrentVersionExpiration` 29 d — **applied by 11.4.1-T3's `weed filer.backup`** on `storage-backup-<env>` (resumable continuous replication through `sink.s3` with `BACKUP_ACCESS_KEY`; a primary delete propagates as a delete marker and the noncurrent version's data is purged within 30 days of the delete, T87) and only asserted here [RULED — README §10 T79/T80] (D21, D20 H9) (11 CR-15); daily provider snapshots of the `storage-<env>` volume only 7 d (backup volume not snapshotted, T87); `DP_KEK` offline, indefinite. Deliberately **not** backed up: adapter durable store (lost-task rule, F27), node disks/releases (rebuilt by `nts-node deploy`, D12/F27), logs (journald, 7 d, D8).

- `DP_KEK` is never in a backup: not in the DB, not in a bucket, not in the repo, not reproduced in the runbook. Without it Data Protection payloads cannot be decrypted — the accepted boundary.
- Deleted data ages out of every tier within 30 days (13's promise), so the retention values are asserted, never adjusted ad hoc.

**Drill contract**, in order on the scratch instance: (1) refuse any host that is not the declared scratch instance → **exit 2**; (2) record `now`, read archive lag, fail if > 15 min; (3) restore to `--target-time`; (4) re-apply each `data_deletion_requests` row with `completed_at > --target-time`, ordered by `completed_at`, idempotently, via 13's path; (5) smoke read — aggregate counts, one live object readable, one deleted object still absent; (6) storage legs — download one object out of `nt-backup-<env>` on `storage-backup-<env>` to the operator Mac (scratch dir, deleted after — nothing is written to any bucket or prefix, T93) — read over the S3 gateway `https://storage-backup-<env>.internal` via the VPN/bastion range on 443 (T86) with the `NTS_OPS_READ` identity (`Read`/`List` on `nt-backup-<env>` only, never `BACKUP_ACCESS_KEY`, T88/T91) — and compare its sha256 (if the source object was deleted on the primary, fetch its noncurrent version by version id — the delete marker's data survives until `NoncurrentVersionExpiration` at 29 d, T87), then restore one daily snapshot of the `storage-<env>` volume into a scratch volume and read one object from it (D21) (11 CR-15); (7) print the elapsed time (measured RTO) and append the runbook's timed row; (8) exit 0 all checks pass / 1 any check failed.

**Scripts** (Bash, 01 D9, idempotent): `tools/ops/restore-drill.sh` [INFERENCE: path] (`--env`, `--target-time`, `--scratch-host`, `--self-test`, `--dry-run`; secrets via `--env-file`/stdin) and `tools/ops/verify-backups.sh` [INFERENCE: path] (retention values, archive lag, `nts_backup_lag_seconds` ≤ 900 (canary gauge, T85), snapshot freshness ≤ 24 h, `DP_KEK` absence).

## Failure handling and edge cases

- **Archive stopped / lag above RPO** → exit 1 before restoring; the runbook's first fix step is "confirm the archive is running", because a restore from a broken archive silently loses the tail.
- **Target time older than the oldest base backup** → exit 2 with the supported window printed.
- **Deletion completed after the target time but before now** is in scope: the enumeration's upper bound is `now`.
- **Re-application fails halfway** → the failing request id is reported, exit 1, the scratch instance is kept for inspection and recreated on the next (idempotent) run.
- **Missing/empty declared scratch name** → usage error (exit 2); the guard is never skipped.
- **`DP_KEK` unreadable at restore time** → recorded as a runbook-step failure; encrypted payloads are then not asserted.
- **Scratch cost/space** → created from the snapshot, destroyed after the drill, never grown from prod; a failed destroy is a reported cost leak.
- **`filer.backup` stopped or `nts_backup_lag_seconds` > 900 / no daily snapshot** → the storage legs exit 1 before the object restore; the copy resumes from its offset on restart — never delete the offset to "catch up" (D21); after a backup-volume loss/rebuild it is started once with `-initialSnapshot` and then without it (T89).
