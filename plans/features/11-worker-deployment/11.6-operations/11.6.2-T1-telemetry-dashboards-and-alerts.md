## Goal

Make the platform observable and prove it: an OpenTelemetry Collector in the app network takes OTLP from Api/Worker (09.9.3), the backend chosen in 11.2.1-T1 stores it, three dashboards answer the operator's questions (API latency/errors, Hangfire queue depth, outbox lag, render success rate, node GPU/disk, OpenAI cost/day, YouTube quota, relay metrics, storage gateway/backup/volume health), all D17 alert rules plus D21's four storage rules exist with their thresholds, and one alert is provoked end to end in a drill.

## Design

**Pipeline.** Api + Worker export OTLP (gRPC) to one collector in the **app subnet** (Apache-2.0, E11); it batches under a memory limiter and exports to the 11.2.1-T1 backend. No node connects to it (D17: node metrics come only through the Worker).

```
Api/Worker --OTLP--> otel-collector (app subnet) --export--> backend (11.2.1-T1)
Worker health pull (30 s) --> node metrics (D13) --OTLP--> same collector
Worker: relay metrics derived from terminal images.v1 reports + health --> same collector   [RULED — README §10 T27]
```

**Boards.** Platform: API latency p50/p95/p99 and 5xx ratio, Hangfire queue depth, `outbox_lag_seconds`, render success share (24 h) and `render_duration_seconds` by stage/outcome, `openai_cost_usd_total` per day vs the budget line, `youtube_quota_used` %, `render_dispatch_unavailable_total`. Node: the seven D13 names, GPU temp (85 °C line), the active-tasks drift counter and the certificate-expiry gauge [RULED — README §10 T70/T72] (D20 H21), relay `image_calls_total{status,error_code}`, `image_relay_rejections_total{code}`, `image_relay_tokens_available{node}` (`image_relay_wait_seconds` stays node-local, T27). Billing panel (12 CR-8, F21): `billing_openai_runway_days`, `billing_webhook_signature_invalid_total`, `billing_credits_minted_total`, `billing_payments_needs_review_total`, `billing_reservation_missing_total`, `billing_spend_cap_hits_total{scope}`, `billing_credit_cap_reached_total`, `billing_held_jobs_cancelled_total`. Storage panel (D21) (11 CR-15): S3 gateway request/error ratio (5xx % over 5 min), `nts_backup_lag_seconds` on `storage-backup-<env>` (T85), writable volume slots and volume disk used % per host (`storage-<env>`, `storage-backup-<env>`).

**Alert rules** (initial values D17; thresholds owned by 08 §5.2; `condition → severity · source metric`):

1. API 5xx > 2 %/5 min → page · HTTP server metrics
2. outbox lag > 30 s → page · `outbox_lag_seconds` [RULED — README §10 T72] (D20 H21; 09 §8 owns the metric)
3. any node `down` > 5 min → page · `render_node_up`
4. `render_dispatch_unavailable_total` rising 15 min → warn · same
5. render failure share > 20 %/24 h → page · render outcomes / `render_duration_seconds`
6. disk ≥ 80 % → warn / ≥ 85 % `disk_low` → page · `render_node_disk_used_pct`, `render_node_health_reasons_total`
7. GPU temp > 85 °C → warn · `render_node_gpu_temp_celsius{node}` (from health `gpu.temp_c`, D13) [RULED — README §10 T28]
8. relay `invalid_api_key` or quota codes → page · `image_relay_rejections_total{code}`, `image_calls_total{error_code}`
9. OpenAI cost/day above the budget line → page · `openai_cost_usd_total`
10. YouTube quota > 80 % → warn · `youtube_quota_used`
11. `autopilot_gate_total{result="fail"}` > 50 % of verdicts/24 h → warn · 02.8.2
12. any `autopilot_pause_total` increment or `autopilot_run_stuck_total` > 60 min → page · 02.8.3
13. `render_node_active_tasks_drift_total{node}` rising over 3 consecutive pulls (the poller's drift check) → warn · drift counter, 11.3.3-T1 [RULED — README §10 T70] (D20 H21)
14. `render_node_cert_expiry_days{node}` < 30 → warn · 11.3.3-T1's pin callback [RULED — README §10 T57] (H12; D20 H21)
15. a render job `queued` longer than `Render:QueueAlertMinutes` (360) → page · `render_jobs` queued age, 09.6.3 [RULED — README §10 T60] (D20 H14/H21)
16. `platform_incident_open{platform,oauth_client_id}` > 0 for 5 min → page · 06.2.3-T3 (broken OAuth client; 06 CR-10)
17. any open `data_deletion_requests` with `due_at − now < 24 h` → page · `deletion_requests_due_soon` from 13.3.1-T1 (13 CR / 06 CR-10)
18. any package below 50 % margin for 7 days → warn · `billing_price_review_required` (12 CR-8, 12 F21)
19. an open `provider_funds_exhausted` circuit → page (P1) · 12.8.3-T2's breaker flag (12 CR-8, 12 F21)
20. `billing_held_jobs_cancelled_total` rising in a 12 h window → warn · the held-job cancel e-mail counter (12 CR-8, 12 F21)
21. `tiktok_active_user_cap_hit_total` > 0 → warn (P2) · 07's unaudited-cap counter (07 CR-10); `platform_incident_open{platform="tiktok"}` already covers `url_ownership_unverified` (07 CR-10)
22. storage S3 gateway 5xx > 1 %/5 min → page · the SeaweedFS gateway metrics from `-metricsPort` on `storage-<env>` (T16, D21) (11 CR-15)
23. `nts_backup_lag_seconds` > 900 → page · the canary gauge pushed by `check-storage-host.sh --metrics` on `storage-backup-<env>` over OTLP/HTTP 4318 (`filer.backup` has no metrics port; `worker-sg` opens 4318 to `storage-backup-sg`, T85/T86) (11 CR-15)
24. no writable volumes on a storage host (`No writable volumes`) → page · the volume server's slot gauge on `storage-<env>` (D21) (11 CR-15)
25. storage volume disk ≥ 80 % → warn / ≥ 85 % → page · the disk gauge of the attached volume on `storage-<env>` / `storage-backup-<env>` (rule 6 is the render node's disk, D21) (11 CR-15)

Rules live in the repository (backend rule file or API payload) so a threshold change is a reviewed diff, not a console edit.

## Steps

1. Record the 11.2.1-T1 backend choice and its ingest endpoint/credential path (`nts/<env>/<NAME>`, D15); an unavailable choice blocks this task — the collector cannot target "TBD".
2. Deploy the collector via IaC (the 11.2.2 module consumes a config file owned here): `otel-collector/config.yml` [INFERENCE: path] with the OTLP receiver, memory limiter, batch processor and backend exporter; no per-node receiver.
3. Point Api/Worker exporters at the collector (09.9.3 owns the wiring; this task adds only the endpoint/credential reference).
4. Verify the D13 node metrics arrive **including `gpu`** plus `render_node_gpu_temp_celsius`, `render_node_active_tasks_drift_total` and `render_node_cert_expiry_days` [RULED — README §10 T70/T72] (D20 H21) — a missing `gpu` block is a hard failure here (F21 would be silently unmet) — the relay metrics derived by the Worker (T27), and the four storage signals — gateway 5xx, writable volume slots and volume disk used % scraped from the SeaweedFS hosts' `-metricsPort` 9327 (`worker-sg` → 9327 only, T78/T86), plus `nts_backup_lag_seconds` pushed over OTLP/HTTP 4318 by `check-storage-host.sh --metrics` on `storage-backup-<env>` (`filer.backup` has no metrics port, T85; D21) (11 CR-15).
5. Import the three dashboards (platform, node, storage; D21) (11 CR-15) from repository JSON, load the 25 rules (incl. the drift, cert-expiry, queued-too-long, billing, TikTok-cap and the four storage ones; 12 CR-8, 07 CR-10, 11 CR-15) [RULED — README §10 T70/T72] (D20 H21), and assert every threshold against D17/D21.
6. Run the alert drill on staging (a 5xx burst or a node set `down`), record the detection latency and the clearing step in the ops runbook, and leave the rule enabled.
7. Scan captured payloads for a seeded story sentence, a token and a node path → absent (09.9.3 owns the redaction; this verifies it).

## Tests

- Config validation: the collector's own validate command over `otel-collector/config.yml` in CI.
- `tools/ops/check_metrics_contract.sh` — positive on the shipped config, negative with one metric name deleted (exit 1).
- Rule tests: table-driven validation of the rule file (25 rules) plus a per-rule assertion that the threshold string equals the D17/D21 value; the outbox-lag threshold is 30 s [RULED — README §10 T72] (D20 H21) and the four storage rules carry the D21 thresholds (lag rule = `nts_backup_lag_seconds` > 900, T85) (11 CR-15).
- Dashboard import against staging (in `deploy.yml`'s staging step or as a runbook command).
- Redaction check: seed a story sentence and a token in a staging request, scan exported payloads through a debug exporter → absent.
- Manual (acceptance): the alert drill with the recorded detection latency.

## Failure handling and edge cases

- **Backend not chosen or unreachable** → the task blocks rather than targeting a placeholder; telemetry buffers then drops, and alerts cannot be enabled before a channel exists.
- **`gpu` block missing (F21 unmet)** → GPU panels stay empty and rule 7 can never fire: a wiring failure, not an accepted gap.
- **Relay metrics route absent** [RULED — README §10 T27: derived by the Worker] → panels and rule 8 fall back to the health payload; a rule must never be enabled against a metric that will not be exported.
- **Storage metrics absent** → rules 22-25 must not be enabled against a metric that is not exported (the D21 wiring is 11.4.1-T2's `-metricsPort` 9327 to `worker-sg` (T78/T86) plus this task's scrape job, and the `nts_backup_lag_seconds` canary push over OTLP/HTTP 4318 from `storage-backup-<env>` (T85/T86) — `filer.backup` has no metrics port; the job itself is 11.4.1-T3's, T80); fix the scrape first (11 CR-15).
- **Cardinality blow-up** → `node` is a bounded label from `RenderNodes:Nodes`; user, episode and task ids stay in traces/logs (09.9.3).
- **Alert storm on first load** → rules are enabled after the drill; a wrong unit or a duplicate is caught by the threshold test.
- **Collector restart** → no disk queue in P, buffered data is lost; `for:` windows prevent paging on the gaps.
- **Credential exposure** → collector credentials come from an env file or the secret manager, never argv or the committed config.
