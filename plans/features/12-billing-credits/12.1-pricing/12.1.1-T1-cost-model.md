# 12.1.1-T1 — Cost model from measurements

| Story | Size | Area | Depends on | Blocks | Phase / flag |
|---|---|---|---|---|---|
| 12.1.1 | M (1.0) | BA | 01, 03.3.1-T2, 11.6.3-T1 | 12.1.2-T1 (soft), 12.7.1-T1 (soft), 12.8.4-T1 (soft) | S · M2 |

## Goal

Produce the owner-signed cost model that turns the platform's measured usage into money, and hand over the exact parameter set that 12.1.2-T1 seeds into `price_versions`. After this task the numbers exist and are traceable: cost per priced operation × tier (`story_generate`, `fact_sheet`, `render`), the parameters `credit_usd`, `margin`, `fee_rate`, `fx_buffer`, `gpu_s_per_video_min`, `rates.gpu` and `floors`, the worst-case reserve each tier produces, and the margin check. Deliverable is **documentation + read-only SQL**: no code, no migration, no route, no config key, no job. Gate `12-measure` (README §7) is what this task opens: no public price is shown before the document is signed (plan 12 B1).

## Inputs

- **01** (environment + cost capture, P): the usage-tap schema v2 columns (`image_count`, `image_tokens_per_image_avg`, `image_cost_per_image_usd`, …) that make 03.3.1-T1/T2 measurable; the machine/GPU machine facts.
- **03.3.1-T2** (P, M0 exit): the image-quality decision and the measured `tokens_per_image` / `tokens_per_image_p95` per `aspect:quality` that seed `price_versions.rates.image[model]` (03 D8, 03 CR-4); until it lands the seed is the 6,000-token placeholder ⚠️ and this task must be re-run.
- **03.2.1-T1** (P): `RenderImagePlanner` — `ClipSeconds = 10`, `SpareShare = 0.15`, `TierMaxMinutes` 1/8/15 ⇒ image caps **6 / 48 / 90**, `MaxTerms = min(ceil(NeededImages × 1.15), ceil(TierMaxMinutes × 60 ÷ 10))`. Read the cap from the planner, **never recompute it** (03 CR-4).
- **11.6.3-T1** (P): GPU seconds per finished-video minute (`gpu_s_per_video_min`) and the node cost per hour + `NTS_MPT_MAX_CONCURRENT`, from the 20-render capacity run (`price from the dated 11.2.1 page`) ⇒ `r_gpu = node cost/hour ÷ 3600 ÷ render concurrency`.
- **02 CR-6 / 02.2.4-T1**: `story_generate` worst case = writer + review + one revision + **review #2**, each at its `max_output_tokens`; the P subset of `price_versions` (`rates`, `limits`) that this task's parameters extend.
- **12.3.1-T1** (soft): the payment `fee_rate` and settlement facts, ⚠️ unknown until a provider is chosen — the document states the placeholder it used (0.03) and its source line says "placeholder, re-run after 12.3.1-T1".
- **`../../12-billing-credits.md` §5.7** (steps 1–5) and `../README.md` D3/D4/D5/D10, rulings BR20/BR25/BR31/BR32, gate §7 `12-measure`.

## Design

**1. `docs/ops/pricing/cost-model.md`** — internal (never published; 13 owns user-facing pricing), fixed sections:

| § | Content |
|---|---|
| §1 Sources | one row per input: what, value, source (file+line or URL+date), owner task, read date |
| §2 Measured inputs | text tokens in/out per step (mean, p95, max); cached share; `tokens_per_image` and `_p95` per `aspect:quality`; GPU seconds per output minute; node cost/hour; concurrency; provider fee rate |
| §3 Cost per operation × tier | `cost_usd` per `story_generate` (short/standard/long), `fact_sheet`, `render` (short/standard/long) with the per-item breakdown (`Cost` per plan §5.7 step 1) and the `C_max` (bound) row next to it |
| §4 Parameters | `credit_usd = 0.01` [DECISION O-2], `margin`, `fee_rate`, `fx_buffer`, `gpu_s_per_video_min`, `rates.gpu.perSecondUsd`, `floors` per operation × tier, and `k = (1+fx_buffer)/((1−margin)(1−fee_rate))` with the arithmetic shown |
| §5 Bounds and worst-case reserve | the four bound rules of §5.7 step 5 with their numeric values per tier (text bytes, `max_output_tokens` per step, 6/48/90 images, `TierMaxMinutes × 60 × gpu_s_per_video_min × 1.5`) and `reserve = max(floor, credits(C_max))` |
| §6 Margin check | package price per credit vs measured cost per credit; margin % must be ≥ 60 % on measured costs before public prices (README gate `12-payments-sandbox`); it also states the **cost floor** of BR32 — `MinimumPricePerCreditVnd(priceVersion, fxRate)`, the per-credit minimum in VND for that parameter version at the effective rate of `IFxRateProvider.CurrentAsync()` (declared by 12.1.2-T1, options-backed; DB-backed implementation 12.8.2-T1) — and every package must satisfy `priceVnd ÷ (credits + bonusCredits) ≥ MinimumPricePerCreditVnd(priceVersion, fxRate)` |
| §7 Sign-off | date, signer, version of the parameter set (`2026-10-01.1`-style string that 12.1.2-T1 will use as `price_versions.version`) |

**2. `docs/ops/pricing/queries.sql`** — read-only snippets, each with a one-line comment naming what it produces and its bind parameters (`:from`, `:to`, `:tier`, `:operation`). Column names come from 00 §6; **a name that drifted is fixed at run time and the correction recorded in the header comment — never invented** (the 08.4.3-T1 precedent):

- `Q1` text tokens per step from `usage_records` (`operation IN ('story','story_review','story_revision','fact_sheet')`): n, mean, p95, max of `input_tokens`/`cached_input_tokens`/`output_tokens`.
- `Q2` image tokens per billed call from `usage_records` (`operation = 'image'`), grouped by `model`.
- `Q3` `tokens_per_image` per `aspect:quality` (usage rows joined to the episode/render context) ⇒ the 03 D8 placeholders.
- `Q4` GPU seconds per output minute: `usage_records` (`operation = 'render'`, `gpu_seconds`) ÷ the ingested video duration ⇒ `gpu_s_per_video_min`.
- `Q5` the distribution of per-job `cost_usd` per operation × tier (p50/p95/max) — the sanity check that `credits(C) ≤ reserve`.
- `Q6` estimated-vs-real share per operation (`usage_records.estimated`) — how much of the cost model rests on estimates.
- `Q7` rows-per-operation counts, so a p95 built on 3 rows is visibly unusable.

**3. Parameter hand-off table** — one row per parameter, the value, its source §, and the `price_versions` field it becomes (`credit_usd`, `margin`, `fee_rate`, `fx_buffer`, `gpu_s_per_video_min`, `floors`, `rates.image[…].tokens_per_image*`, `rates.gpu`). This table is the input of 12.1.2-T1's `Credit:Pricing` seed block, row for row.

## Steps

1. Confirm the three measurement inputs exist and are finished (01, 03.3.1-T2, 11.6.3-T1); record each one's artefact and date in §1. If 11.6.3-T1 has not run, stop — a `gpu_s_per_video_min = 0` version must never be signed.
2. Write `docs/ops/pricing/queries.sql` with Q1–Q7 and run each against staging data (or a staging copy) with its binds; paste the command and the row count into the file header.
3. Fill §2 from Q1–Q4 and Q6 (values with their row counts); mark every cell that came from fewer than 20 rows or from an `estimated = true` row.
4. Compute §3 with the plan §5.7 step 1 formulas: text `(input − cached) × r_in + cached × r_cached + output × r_out`; image `text_tokens × r_text_in + image_tokens × r_image_in + output_tokens × r_image_out`; render `gpu_s_per_video_min × output_minutes × r_gpu`.
5. Compute §4: `k`, the `credit_usd` of 0.01 [DECISION], and `floors` per operation × tier from the measured cost plus the fixed costs the floor must absorb (moderation, storage, support) — state the reasoning per cell.
6. Compute §5 with the planner's caps (6/48/90) and the GPU headroom ×1.5; record `reserve` per operation × tier and confirm `credits(C_max) ≥ credits(C_p95)` for every cell.
7. Run the §6 margin check against 12.7.1-T1's package shapes; if any package is below 60 %, adjust the package price or the floor and record the iteration (never silently loosen `margin`). The same pass computes `MinimumPricePerCreditVnd(priceVersion, fxRate)` (BR32) and asserts `priceVnd ÷ (credits + bonusCredits) ≥ MinimumPricePerCreditVnd(priceVersion, fxRate)` for every package shape, so a save below the floor is a 400 `package_below_cost` (12.7.1-T1) instead of a surprise.
8. Sign §7 (date + signer + version string) and copy the parameter table into the hand-off (it is the diff 12.1.2-T1 implements).
9. Re-run the whole document once after 12.3.1-T1 names a provider (`fee_rate`) and after 03.3.1-T2/11.6.3-T1 land their measurements; each re-run is a new §7 sign-off line, not an edit of the old numbers.

## Outputs

- `docs/ops/pricing/cost-model.md` (new; §1–§7 filled and signed for one parameter version).
- `docs/ops/pricing/queries.sql` (new; Q1–Q7, each executed once with its command and row count recorded).
- The parameter hand-off table (in §4/§5 of the same document; consumed row-for-row by 12.1.2-T1 and by 12.7.1-T1's `package_below_cost`), plus §6's `MinimumPricePerCreditVnd(priceVersion, fxRate)` floor and the `priceVnd ÷ (credits + bonusCredits)` comparison per package (BR32).
- No code, no migration, no route, no config file, no job, no metric; nothing outside `docs/ops/pricing/`.

## Tests

This task ships no code, so its "tests" are reproducible checks recorded in the document:

- **Recompute check:** §3/§4/§5's numbers are re-derived once by hand from §2's inputs and the §5.7 formulas; the second pass's result is written next to the first (a mismatch is a defect, not a rounding note).
- **Bound check:** for each cell, `credits(C_p95) ≤ reserve` and `reserve = max(floor, credits(C_max))` are asserted in §5 as explicit inequalities.
- **Margin check:** §6 shows the package price per credit, the measured cost per credit and the resulting margin %, per package.
- **Repeatability:** re-running `queries.sql` with the same binds against the same data returns the same §2 values (the row counts are recorded so a later reader knows when the data changed).
- **Worked-example cross-check:** the mid-value cells are compared with the §5.7 illustrative table (story ⇒ floor 5; Standard render ⇒ `charged 192`, `returned 11` — a derived DTO value, never a ledger row, BR18) so a formula error shows up immediately.

## Failure handling and edge cases

| Case | Handling |
|---|---|
| 11.6.3-T1's capacity run has not happened | Stop. Signing `gpu_s_per_video_min = 0` would price every render at zero and violate I1; the document's §7 stays empty and 12.1.2-T1 cannot seed an active version |
| 03.3.1-T2 has not landed (image tokens still the 6,000 placeholder) | The document marks §2's image cells `placeholder ⚠️`, §6's margin is reported as provisional, and the re-run is scheduled; the placeholder is never presented as measured |
| 12.3.1-T1 has no provider yet | `fee_rate` is the stated placeholder 0.03 with a source line naming 12.3.1-T1; §6 records that a provider change re-opens the margin check |
| A `Q` snippet returns fewer than 20 rows for a cell | The cell is marked "insufficient sample"; the value used is the p95 with the row count shown, or the value is deferred to a re-run — never a rounded-up guess |
| Measured margin < 60 % | Raise the floor or the package price and record the iteration; do not lower `margin` (it protects the platform, not the price) |
| A column name in `queries.sql` no longer exists | Fix the snippet to the real column, record the correction in the header, re-run; never invent a replacement column |
| Cost per render varies more than 2× between the M0 trial renders | Report the spread in §2 and use the p95 (not the mean) for `C_max`; the bound rules of §5.7 step 5 stay the authority for the reserve |
