# 12.1.2-T1 — `price_versions` credit columns, loader and seeder

| Story | Size | Area | Depends on | Blocks | Phase / flag |
|---|---|---|---|---|---|
| 12.1.2 | S (0.5) | BE | 12.1.1-T1 (soft), 09.2.2-T1, 02.2.4-T1 | 12.1.3-T1, 12.1.4-T1, 12.7.1-T1, 12.3.2-T1 | S · M2 |

## Goal

Extend the P `price_versions` table (created by 02.2.4-T1) with the credit parameters of D4 — `credit_usd`, `margin`, `fee_rate`, `fx_buffer`, `gpu_s_per_video_min`, `floors` — and give the platform one loader that hands the active version's pure value types to the calculator, quote, ledger and package checks. The table stays append-only (a price change is a new row with a new `active_from`), `IPriceCatalog` grows two members and never forks, and an invalid or missing active version **fails startup** instead of pricing at a default. No route is added: the version is seeded from config and flipped by its own `active_from`.

## Inputs

- **02.2.4-T1** (P): `price_versions` with `version`, `active_from`, `rates`, `limits`; `IPriceCatalog.GetActive(at)`; the seed blocks `OpenAi:Pricing` / `OpenAi:Pricing:Limits`; `TextCostCalculator` (02 D14) stays the text-cost owner inside `Cost`.
- **09.2.2-T1** (P): the core schema + migration bundle and its naming convention (`<ts>_<NN>_<Name>`, e.g. `_09_RenderJobs`); 09.2.5-T1's `StyleTemplateSeeder` is the seeder pattern.
- **12.1.1-T1** (soft): the signed parameter table (values for §4/§5 of the cost model) — the seed's only source of real numbers; until it lands the seed carries the documented placeholders and the active version is rejected.
- **03.3.1-T2 / 03 D8 / 03 CR-4**: the `rates.image[model]` shape (`text_in_per_1m`, `image_in_per_1m`, `image_out_per_1m`, `tokens_per_image{aspect:quality}`, `tokens_per_image_p95{…}`) and the 6,000-token placeholder.
- **11.6.3-T1**: `gpu_s_per_video_min` and the per-second GPU rate derived from node cost/hour ÷ 3600 ÷ concurrency.
- **`../README.md`** D1 (extend, never duplicate), D3 (the calculator signatures this loader feeds), D4, D10 (`Credit` section keys), D16/D17 (indexes), BR15 (frozen names), BR20 (migration ownership), BR25 (`version` is text), BR31 (`IFxRateProvider`), BR32 (`MinimumPricePerCreditVnd`).

## Design

**1. Migration `<ts>_12_PriceVersionsCreditColumns`** (BR20 — this task owns the name, and only this task writes it) — additive, forward-only:

```sql
ALTER TABLE price_versions
  ADD COLUMN credit_usd          numeric(12,6) NOT NULL DEFAULT 0.010000,
  ADD COLUMN margin              numeric(12,6) NOT NULL DEFAULT 0.600000,
  ADD COLUMN fee_rate            numeric(12,6) NOT NULL DEFAULT 0.030000,   -- ⚠️ placeholder until 12.3.1-T1
  ADD COLUMN fx_buffer           numeric(12,6) NOT NULL DEFAULT 0.050000,
  ADD COLUMN gpu_s_per_video_min numeric(12,6) NOT NULL DEFAULT 0,
  ADD COLUMN floors              jsonb         NOT NULL DEFAULT '{}';
ALTER TABLE price_versions
  ADD CONSTRAINT ck_price_versions_credit_usd CHECK (credit_usd > 0),
  ADD CONSTRAINT ck_price_versions_margin     CHECK (margin >= 0 AND margin < 1),
  ADD CONSTRAINT ck_price_versions_fee_rate   CHECK (fee_rate >= 0 AND fee_rate < 1),
  ADD CONSTRAINT ck_price_versions_fx_buffer  CHECK (fx_buffer >= 0),
  ADD CONSTRAINT ck_price_versions_gpu_rate   CHECK (gpu_s_per_video_min >= 0);
CREATE INDEX ix_price_versions_active_from ON price_versions (active_from DESC);
```

`price_versions.id`/`created_at`/`updated_at` come from 00 §6's preamble (never re-added); `version` keeps the P uniqueness constraint if 02.2.4-T1 already declares it (the task checks before adding a second one).

**2. Loader and port (extends 02's, per D1/BR15).**

```csharp
// Application/Abstractions/Pricing/IPriceCatalog.cs — 02.2.4-T1 owns the file; this task ADDS two members only
PriceVersion GetActive(DateTimeOffset at);                                                            // existing (02)
Task<PriceVersionParameters> GetParametersAsync(PriceVersionVersion version, CancellationToken ct);   // NEW
Task<PriceVersionParameters> GetActiveParametersAsync(DateTimeOffset at, CancellationToken ct);       // NEW
```

- `GetActive(at)` semantics (I1): the row with the greatest `active_from <= at`; `at == active_from` selects that row. A new version therefore activates by timestamp with no write and no restart.
- `PriceVersionCache` (Infrastructure, `IMemoryCache`, 60 s TTL + invalidation called by the seeder) caches the active row and its parameters; the parameter object is a pure Domain type, so the cache never leaks EF entities.
- `PriceVersionVersion` is the `readonly record struct` over `price_versions.version` (D2/D4), which is **text** (00 §6:320) — as is `usage_records.price_version` (BR25). 02's `RunContext.PriceVersion` int therefore becomes **string**, filed as **12 CR-17** against `features/02-story-writing/` 02.2.4-T1 + 02.6's `RunContext` DTO (no other 02 change); the loader records that mapping in its doc comment, never renames the column and never adds a second catalog interface — and this folder never edits 02.

**3. `PriceVersionValidator` (start-up, fail closed).** Runs on the active version at boot and rejects: missing/blank `version`; `credit_usd <= 0`; `margin` outside `[0,1)`; `fee_rate` outside `[0,1)`; `fx_buffer < 0`; `gpu_s_per_video_min <= 0`; a `floors` cell missing for any priced operation × tier (`story_generate`, `fact_sheet`, `render` × short/standard/long); an incomplete `rates.image[model].tokens_per_image` set for any `aspect:quality` the render path can produce; a `limits.max_output_tokens` missing for a step the story path calls. Failure is a **named configuration error at startup** (`service_unavailable` at runtime if the cache is somehow empty), never a default price.

**4. `PriceVersionSeeder`** (Infrastructure, the 09.2.5-T1 pattern): reads the `Credit:Pricing` block (D10's `Credit` section) plus 02's rate blocks, builds one row per version, inserts with `ON CONFLICT (version) DO NOTHING`, is idempotent, never updates an existing row (I6), and invalidates `PriceVersionCache` after inserting. `Credit:Pricing` shape (this folder's key names, [DECISION]; the section name is D10's):

```jsonc
"Credit": { "Pricing": { "ActiveVersion": "2026-10-01.1",
  "Versions": { "2026-10-01.1": { "activeFrom": "2026-10-01T00:00:00Z", "creditUsd": 0.01, "margin": 0.60,
    "feeRate": 0.03, "fxBuffer": 0.05, "gpuSecondsPerVideoMinute": 0, "gpuNodeCostUsdPerHour": 0.50,
    "gpuRenderConcurrency": 1,
    "floors": { "story_generate": { "short": 5, "standard": 5, "long": 8 },
                "fact_sheet":     { "short": 2, "standard": 2, "long": 3 },
                "render":         { "short": 20, "standard": 50, "long": 90 } } } } } }
```

`rates.gpu.perSecondUsd` is derived by the seeder (`gpuNodeCostUsdPerHour ÷ 3600 ÷ gpuRenderConcurrency`) and stored inside `rates`, so the calculator never divides by 3600 at runtime.

**5. Domain value types** (`Domain/Pricing/`) are declared by 12.1.4-T1 (`PriceVersionRates`, `ImageRates`, `PriceVersionParameters`, `OperationFloor`, `OperationTier`, `PriceVersionVersion`); this task only maps rows/config into them, so the two tasks share one set of names (BR15).

**6. FX port (BR31) and the package credit floor (BR32).**

- `IFxRateProvider.CurrentAsync()` is **declared by this task** (BR31) as an Application port in the Pricing abstractions, together with an **options-backed** implementation that reads the fallback option `Credit:FxUsdVndFallback` (D10/D16) — enough for a working rate before any real top-up exists. The **DB-backed** implementation (latest `provider_topups.fx_rate`, D16) is **12.8.2-T1** and replaces that registration at M2: **no new dependency edge**, hence no cycle. **12.8.4-T1**'s margin alert reads the same port; a second FX port is forbidden.
- `MinimumPricePerCreditVnd(priceVersion, fxRate)` is declared here for the active parameters (12.1.1's cost model is its value source, BR32) and consumed by **12.7.1-T1**: a package save is rejected 400 `package_below_cost` unless `priceVnd ÷ (credits + bonusCredits) ≥ MinimumPricePerCreditVnd(priceVersion, fxRate)`, where `priceVersion` is the active version and `fxRate` the value from `IFxRateProvider.CurrentAsync()`.

## Steps

1. Confirm 02.2.4-T1 has landed (`price_versions`, `IPriceCatalog`, the seed blocks) and read its existing constraints/indexes so the migration adds only what is missing (no duplicate unique on `version`).
2. Add the migration `<ts>_12_PriceVersionsCreditColumns` exactly as Design 1, with a `Down` that drops the five constraints, the index and the six columns in reverse order.
3. Add the pure value types' EF mapping — `price_versions` owns the columns; `floors` and `rates`/`limits` are `jsonb` mapped to the Domain records through a converter that rejects unknown enum keys with a named error (never a silent skip).
4. Extend `IPriceCatalog` with the two members and implement them in the existing catalog implementation + `PriceVersionCache` (60 s TTL, seeder-invalidation hook).
5. Write `PriceVersionValidator` with one named failure per rule (§Design 3) and wire it into the boot check that validates the active version; make the failure path a hard startup error.
6. Write `PriceVersionSeeder` reading `Credit:Pricing` + 02's rate blocks, computing `rates.gpu.perSecondUsd`, inserting idempotently, and invalidating the cache.
7. Add the config block with the 12.1.1-T1 values (or the documented placeholders with `gpuSecondsPerVideoMinute = 0`, which the validator rejects for an **active** version — the seeding task must not activate an unmeasured GPU rate).
8. Run the migration against a DB that already holds the P subset (one P-only row) and against an empty DB; both must apply and leave the CHECKs and the index in place.
9. Hand the resulting `PriceVersionParameters` shape to 12.1.4-T1 (Domain names) and 12.1.3-T1 (which reads `priceVersion` for the quote).
10. Declare `IFxRateProvider.CurrentAsync()` (Application port) with its options-backed implementation reading `Credit:FxUsdVndFallback`, and declare `MinimumPricePerCreditVnd(priceVersion, fxRate)` next to the catalog/validator (BR31/BR32); hand both names to 12.7.1-T1 and 12.8.4-T1 and never fork either.

## Acceptance checks

- [ ] The migration applies on an empty DB and on a DB seeded with the P subset; both leave `credit_usd`, `margin`, `fee_rate`, `fx_buffer`, `gpu_s_per_video_min`, `floors` and the five CHECKs present, and `ix_price_versions_active_from` exists.
- [ ] The `Down` migration removes exactly the five constraints, the index and the six columns and leaves the P subset intact.
- [ ] `GetActive(at)` returns the row with the greatest `active_from <= at`; with two versions, `at == active_from` of the newer one selects the newer one, and `at` one tick earlier selects the older one.
- [ ] `PriceVersionSeeder` run twice inserts one row per version (second run inserts nothing and changes no row); a manually edited row is never updated by the seeder.
- [ ] `PriceVersionValidator` fails startup with the named failure for each of: `credit_usd = 0`, `margin = 1`, `fee_rate = 1`, `fx_buffer = -1`, `gpu_s_per_video_min = 0`, a missing `floors` cell, an incomplete `tokens_per_image` set, a missing step limit — and passes a complete version.
- [ ] `rates.gpu.perSecondUsd` stored by the seeder equals `gpuNodeCostUsdPerHour ÷ 3600 ÷ gpuRenderConcurrency` for the seeded inputs.
- [ ] `IPriceCatalog` has exactly `GetActive`, `GetParametersAsync`, `GetActiveParametersAsync` (plus members 02.2.4-T1 already declared); no second catalog interface exists (architecture test).
- [ ] `GetParametersAsync(someVersion)` for an **older** version returns that version's parameters, not the active one's, so a job reserved under an old version is charged with it.
- [ ] `PriceVersionCache` serves the second call without a DB round trip and re-reads after the seeder's invalidation (asserted with a counting fake/DbContext hook).
- [ ] `IFxRateProvider.CurrentAsync()` is declared here as an Application port with an options-backed implementation that returns the `Credit:FxUsdVndFallback` rate when no top-up row exists; the DB-backed implementation is 12.8.2-T1's (no dependency edge is added) and no second FX port exists (architecture test).
- [ ] `MinimumPricePerCreditVnd(priceVersion, fxRate)` is declared by this task (value source: 12.1.1's cost model) and `priceVnd ÷ (credits + bonusCredits) ≥ MinimumPricePerCreditVnd(priceVersion, fxRate)` is the predicate 12.7.1-T1 applies for `package_below_cost` (BR32).

## Failure handling and edge cases

| Case | Handling |
|---|---|
| No active version at boot | Hard startup failure naming the config key; the API never starts with a default price (fail closed) |
| Active version invalid (any §Design 3 rule) | Hard startup failure with the rule name and the offending value; the previous version is not silently used |
| `gpu_s_per_video_min = 0` on the active version | Explicit rejection: renders are not priced before 11.6.3-T1's measurement (a zero would make every render free) |
| Two versions activated at the same instant | `active_from` is unique per version and `GetActive` orders by `active_from DESC`; a tie is resolved deterministically by `created_at DESC, id DESC` and reported as a configuration warning |
| A row holds a `version` string a job stored but the row was later deleted | Rows are never deleted (I6); if one is missing anyway, `GetParametersAsync` returns a domain error and the settle path alerts (12.2.1-T1) instead of charging a wrong price |
| `activeFrom` in the new `Credit:Pricing` block is in the past | Accepted: it activates on the next read; the seeder logs the activation instant |
| A new version changes `floors` while jobs are open | Safe by design: each reservation stores its version (D4) and is charged with it; the new floors apply to new reserves only |
| 02.2.4-T1's `RunContext.PriceVersion` is still `int` while the version is text (BR25) | The mapping is recorded in the loader's doc comment; the change to 02 is **12 CR-17** (filed, not applied from this folder) — no rename, no fork, and this folder never edits 02 |

## Notes

- **No UI task here and none added** (owner rule 2026-09-25); the admin surface that would edit prices does not exist in 00 §8, so at M2 a version is added by config + deploy. 10.9's admin shell consumes `GET /admin/usage` (12.5.2-T1) and shows the *effect* of a version, never an editor.
- `price_versions` rows are immutable and append-only (I6): no `UPDATE`/`DELETE` path exists anywhere in the codebase, which is what makes "running reserves keep their version" true rather than aspirational.
- `fee_rate` carries the placeholder 0.03 until 12.3.1-T1 chooses a provider; the re-seed is a **new version**, never an in-place edit (which the immutable rule forbids).
- The migration is additive so the M2 deploy can run before the seeder: the columns exist with defaults, the seeder fills the real version, and the boot validation is what refuses an unusable state.
- BR20: `<ts>_12_PriceVersionsCreditColumns` is written by 12.1.2-T1 only; the CR-13 index set belongs to the tasks CR-13 names and none of it is added in this folder.
- BR25: `price_versions.version` and `usage_records.price_version` are **text**; 02's `RunContext.PriceVersion` int → string is **12 CR-17** (filed against 02.2.4-T1; 02 is never edited here).
- BR31: `IFxRateProvider.CurrentAsync()` is declared in this task (options-backed, `Credit:FxUsdVndFallback`); the DB-backed implementation is 12.8.2-T1 (12.8.4-T1's margin alert reads the same port) — no new edge, no cycle.
- BR32: `MinimumPricePerCreditVnd(priceVersion, fxRate)` is declared by 12.1.1/12.1.2 and consumed by 12.7.1-T1 for `package_below_cost` — `priceVnd ÷ (credits + bonusCredits) ≥ MinimumPricePerCreditVnd(priceVersion, fxRate)`.
