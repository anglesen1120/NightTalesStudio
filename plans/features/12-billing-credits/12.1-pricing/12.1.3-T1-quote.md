# 12.1.3-T1 — Quote endpoint (`maxCredits`, `typicalCredits`)

| Story | Size | Area | Depends on | Blocks | Phase / flag |
|---|---|---|---|---|---|
| 12.1.3 | S (0.5) | BE | 12.1.2-T1, 12.1.4-T1 | 10.8.1-T1 (10/08 CR-hand-off) | S · M2 |

## Goal

Ship the one read-only route this folder owns: `GET /billing/quote` returns the number the reserve will actually take (`maxCredits`), what the same operation has usually cost (`typicalCredits`, the median charge of the last 50 settled jobs of that operation and tier), the balance after the worst case, the tier and the price version. The quote must be the same number the ledger moves — it calls `CreditCalculator.Reserve` with the same bounds the reserve path uses, so a "usually about M" that disagrees with the settled charge is a defect, not a rounding difference. Reading only: no credit moves, no event, no job.

## Inputs

- **12.1.4-T1**: `CreditCalculator.Reserve(bound, parameters, floor)` → `maxCredits`; `PriceVersionParameters`/`OperationFloor` shapes.
- **12.1.2-T1**: `IPriceCatalog.GetActiveParametersAsync(at, ct)` and `GetActive(at).Version` → `priceVersion`; `floors[operation][tier]`.
- **03.2.1-T1** (`RenderImagePlanner`): `MaxTerms` for the render bound — read from the planner, never recomputed (03 CR-4). **02 D14/D4**: `limits.max_output_tokens` per step and the `story_generate` worst case (writer + review + revision + review #2, 02 CR-6).
- **02's episode aggregate**: `length_tier` (short/standard/long) and the tenant-owned episode lookup, so a foreign episode is `404 not_found`.
- **09 D14/D15** (README C11): `validation_failed` 400 + `errors` keyed by camelCase field; `[AllowAnonymousRequest]`/`[Audited]`/`[NotAudited]` — one and only one per handler; `UnitOfWorkBehavior` is the only `SaveChangesAsync` caller (this handler never saves).
- **README §3.1** (the frozen route and `QuoteDto`) and §5 (the formula), `../../12-billing-credits.md` §12.1.3 (the endpoint's user story and the two rejected operations).

## Design

**1. Contract (frozen names).**

```
GET /api/v1/billing/quote?operation={story_generate|fact_sheet|render}&episodeId={uuid}

200 QuoteDto {
  operation: string, tier: string, maxCredits: number, typicalCredits: number|null,
  balanceAfter: number, priceVersion: string
}
400 validation_failed   — operation missing/unknown, or operation ∈ {story_review, story_revision} (no own price),
                          or episodeId missing/invalid for render
404 not_found           — the episode does not exist or is not visible to the caller (tenant filter)
503 service_unavailable — no active, valid price version (fail closed; the API never quotes a default price)
```

- `maxCredits` = `CreditCalculator.Reserve(bound, parameters, floors[operation][tier])` — the **same** call and the same bound construction the reserve path uses (12.2.4-T1 builds the bound from the same helper).
- `typicalCredits` = median of the charged credits of the last 50 **settled** reservations for that `(operation, tier)`, `null` when fewer than 50 samples exist (BR25). It is an aggregate read: no `user_id` is selected, nothing per-user is returned (index pinned by D17/F20; the read is bounded to the last 30 days).
- `balanceAfter` = current derived balance − `maxCredits` (**may be negative**: the UI compares it to 0 to disable the action and to show the shortfall) [DECISION].
- `tier`: from the episode for all three operations; for `story_generate`/`fact_sheet` with no `episodeId`, `standard` (the tier a new episode gets by default) and the response says so via `tier` [DECISION]. `render` **requires** `episodeId`.
- Not behind `billing_enabled` (the quote is read-only; CR-3 flags only money-mutating routes); policy `All` (authenticated), rate policy `auth`; `[NotAudited]`.

**2. Handler.** `GetQuoteQuery(QuoteOperation Operation, Guid? EpisodeId) → ErrorOr<QuoteDto>` in `Application/Features/Billing/Quote/`, through `ISender`; `GetQuoteValidator` (FluentValidation) mirrors the 400 cases above; the handler:

1. resolves the active parameters and the version (`IPriceCatalog`), failing `service_unavailable` when none is valid;
2. resolves the episode (tenant-filtered) and its `length_tier`; for `render`, builds the image bound from `RenderImagePlanner.Plan(…)` and the GPU bound from the tier's maximum minutes;
3. builds the `UsageBound` with the §5.7 step 5 rules (prompt UTF-8 bytes, per-step `max_output_tokens` ×4 for `story_generate`, image cap, GPU ×1.5) — the same helper the reserve path calls;
4. `Reserve(...)` → `maxCredits`;
5. reads `typicalCredits` from `ICreditQuoteReadModel` (60 s cached, 30-day window, `LIMIT 500` recent settle rows grouped in SQL to the last 50 per `(operation, tier)`);
6. reads the balance and computes `balanceAfter`.

**3. Read model.** `ICreditQuoteReadModel.TypicalCreditsAsync(CreditOperation, LengthTier, ct) → ErrorOr<long?>` implemented in Infrastructure over `credit_ledger` (`kind = 'settle'` rows carry the charged amount; the reservation link is `reference_id`), grouped by the reservation's operation and the reservation's episode tier. One set-based statement, bounded window, `percentile_cont(0.5)`; no per-row loop (F20's rule). [OPEN] if the 30-day bounded scan ever exceeds the budget, the candidate index `credit_ledger (kind, created_at DESC)` is raised as a CR to README D17/F20 — it is **not** added here.

**4. Same-number guarantee.** A single `UsageBoundFactory.ForOperation(operation, tier, episode, plan, limits)` (Application, `[INFERENCE]` name) is used by both the quote and the reserve path; the test asserts the quote's `maxCredits` equals what `ICreditLedger.ReserveAsync` stores for the same request (integration test with a real reserve).

## Steps

1. Add `GetQuoteQuery` + validator + handler in `Application/Features/Billing/Quote/` and register the route on the existing `/api/v1` group (no new group, no new policy).
2. Implement `UsageBoundFactory.ForOperation` for the three operations (text bytes, per-step output limits ×4 for `story_generate` per 02 CR-6, image cap via `RenderImagePlanner`, GPU ×1.5 capped by the render timeout) and hand it to 12.2.4-T1 so the reserve path uses the identical bound.
3. Implement `ICreditQuoteReadModel` + its Infrastructure query (one statement, 30-day window, `percentile_cont(0.5)`, `LIMIT 500` inner scan, 60 s cache) and the "fewer than 50 samples ⇒ null" rule (BR25).
4. Wire the episode lookup through the tenant-filtered query (no `IgnoreQueryFilters`; that is allowed only in the admin handlers) and map a missing/foreign episode to `not_found`.
5. Return `QuoteDto` with field names exactly as §Design 1 — with no USD rate, margin or `k` in the payload (I5), asserted on the raw JSON body.
6. Write the tests of §Tests: unit (handler + validator with hand-written fakes), integration (endpoint, 400/404/503, the same-number assertion against a stored reservation), and the raw-body key check.
7. Record the i18n hand-off: the API returns numbers only; the "up to N, usually about M" copy keys (`billing.quote.*`) and their vi/en strings are 10.8's, not this task's (README D18's `billing.*` set on 12's side covers errors and the receipt, not this surface).

## Acceptance checks

- [ ] `GET /billing/quote?operation=story_generate&episodeId=<own episode>` returns 200 with exactly the six `QuoteDto` fields and `tier` equal to the episode's `length_tier`.
- [ ] `maxCredits` equals the credits a real reserve stores for the same request (integration assertion against `credit_ledger`, the same-number contract).
- [ ] `operation=story_review` and `operation=story_revision` return 400 `validation_failed` with `errors.operation` non-empty; an unknown or missing `operation` does the same.
- [ ] `operation=render` without `episodeId` returns 400 `validation_failed` (field `episodeId`); with an `episodeId` of another user the response is 404 `not_found` and no field of that episode leaks.
- [ ] `typicalCredits` is `null` below 50 settled samples for the pair (BR25) and a non-null median (not mean) once the samples exist; seeding 50 rows with a known distribution returns the median value.
- [ ] `balanceAfter` equals the current balance minus `maxCredits` (a negative value is returned verbatim, not clamped).
- [ ] `priceVersion` equals `price_versions.version` of the row `GetActive(now)` selects; after a second version's `active_from` passes, the returned string changes without a restart.
- [ ] The raw response body contains no `usd`, `margin`, `feeRate`, `fxBuffer` or `k` key (asserted on the string body, per invariant I5).
- [ ] With no valid active version (validation disabled in a test fixture), the route returns 503 `service_unavailable` and never a default or zero price.
- [ ] The handler performs no write: the test asserts no `credit_ledger`/`price_versions`/`usage_records` row is added and no outbox row appears after a 200.

## Failure handling and edge cases

| Case | Handling |
|---|---|
| No active valid price version | 503 `service_unavailable` + the boot validation already failed in practice; never a default price and never zero |
| Episode not found / not owned | 404 `not_found` (the tenant filter does the work; no `IgnoreQueryFilters` outside the admin handlers) |
| `story_review` / `story_revision` | 400 `validation_failed` — these are included in `story_generate` (12.1.1) and have no own price |
| `render` without `episodeId` | 400: the tier, the image plan and the duration cap all come from the episode |
| `episodeId` given for `story_generate`/`fact_sheet` on an episode whose tier is not yet set | Falls back to `standard` and the response's `tier` states it |
| Fewer than 50 settled samples | `typicalCredits = null` (BR25); the UI shows only the "up to N" half (10.8's copy) |
| Median read slow (large ledger) | The read is bounded (30 days, `LIMIT 500` inner scan) and cached 60 s; a slow plan is a CR to D17's index list, not a new index added here |
| The bound helper and the reserve path drift apart | Prevented structurally (one `UsageBoundFactory` for both) and caught by the same-number integration assertion |
| A quote is asked for while the funding pause is open | Answered normally: the credits are still reserved (README D15), so the quote stays true; the pause is surfaced by `processingPaused` on the episode, not by the quote |
