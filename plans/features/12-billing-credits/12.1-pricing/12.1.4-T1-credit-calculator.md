# 12.1.4-T1 — `CreditCalculator` (pure Domain cost → credits)

| Story | Size | Area | Depends on | Blocks | Phase / flag |
|---|---|---|---|---|---|
| 12.1.4 | S (0.5) | BE | 12.1.2-T1, 02.2.4-T1 | 12.1.3-T1, 12.2.1-T1, 12.2.4-T1, 12.5.2-T1 | S · M2 |

## Goal

Write the one pure function that turns metered usage into credits, so that the quote, the reserve, the charge and the margin report cannot disagree. `CreditCalculator` takes a `PriceVersionRates` + `PriceVersionParameters` and answers exactly four questions: what did this usage cost in USD (`Cost`), what is the worst case of an upper bound (`CostBoundUsd`), how many credits is that (`Credits`), and what does a job reserve/charge (`Reserve`/`Charge`). It is Domain code with no I/O, no clock and no config; rounding happens once per job; the render GPU item is `gpu_s_per_video_min × actual output minutes` and **never** wall time. The task also lands the Domain value types the loader (12.1.2-T1) maps rows into, and the `usage_records` reservation link contract with 02's metering writer (no write path here).

## Inputs

- **12.1.2-T1**: the `PriceVersionParameters` values that come from `price_versions` (`credit_usd`, `margin`, `fee_rate`, `fx_buffer`, `gpu_s_per_video_min`, `floors`) and `PriceVersionRates` (text/image/GPU/web-search rates) — this task declares those types.
- **02 D1 / D14 / CR-4**: `UsageBound` and `CostBound` (02's types), `UsageItem` (02's `usage_records` row shape: `operation`, input/cached/output tokens, `imageCount`, `gpuSeconds`, `estimated`), `IUsageMeter` as the **only** writer of those rows, and `CreditOperation` (`StoryGenerate`, `FactSheet`, `Render` are the priced members; `StoryReview`/`StoryRevision` are not separately priced).
- **03 D8 / 03 CR-4**: the image cost formula, `tokens_per_image[aspect:quality]` fallback for a call with no `usage`, and `RenderImagePlanner.MaxTerms` as the image **bound** (read, never recomputed).
- **05 / 11.6.3-T1**: `output_minutes` = the ingested video's real duration (ffprobe) and the measured `gpu_s_per_video_min`; wall time from dispatch to done is never charged.
- **`../../12-billing-credits.md` §5.7** (steps 1–5, including the bound rules and the illustrative worked example) and `../README.md` D3 (the frozen signatures), D4, D5.

## Design

**1. Domain value types** (`src/NightTales.Domain/Pricing/`), pure:

```csharp
public sealed record PriceVersionRates(
    IReadOnlyDictionary<string, TextRates> Text, IReadOnlyDictionary<string, ImageRates> Image,
    decimal GpuPerSecondUsd, decimal WebSearchCallUsd);
public sealed record TextRates(decimal InputPer1M, decimal CachedInputPer1M, decimal OutputPer1M);
public sealed record ImageRates(decimal TextInPer1M, decimal ImageInPer1M, decimal ImageOutPer1M,
    IReadOnlyDictionary<ImageCell, long> TokensPerImage, IReadOnlyDictionary<ImageCell, long> TokensPerImageP95);
public readonly record struct ImageCell(Aspect Aspect, ImageQuality Quality);
public sealed record PriceVersionParameters(PriceVersionVersion Version, decimal CreditUsd, decimal Margin,
    decimal FeeRate, decimal FxBuffer, decimal GpuSecondsPerVideoMinute, IReadOnlyDictionary<OperationTier, long> Floors);
public readonly record struct OperationTier(CreditOperation Operation, LengthTier Tier);
public readonly record struct OperationFloor(long Credits);
public readonly record struct PriceVersionVersion(string Value);   // "2026-10-01.1" (README D2/D4)
```

**2. The calculator** (`src/NightTales.Domain/Pricing/CreditCalculator.cs`) — static, pure, exactly the D3 signatures:

```csharp
public static decimal Cost(IReadOnlyList<UsageItem> actual, PriceVersionRates rates);
public static decimal CostBoundUsd(UsageBound bound, PriceVersionRates rates);
public static long    Credits(decimal usd, PriceVersionParameters p);
public static long    Reserve(UsageBound bound, PriceVersionParameters p, OperationFloor floor);
public static long    Charge(long reserve, IReadOnlyList<UsageItem> actual, PriceVersionParameters p, OperationFloor floor);
public static decimal K(PriceVersionParameters p);   // (1 + fxBuffer) / ((1 − margin) × (1 − feeRate))
```

- `Cost`: per item — text `(input − cached) × r_in + cached × r_cached + output × r_out`; image `textTokens × r_text_in + imageTokens × r_image_in + outputTokens × r_image_out`, or `tokens_per_image[aspect:quality] × r_image_out` when the item carries no provider usage (the caller has already set `UsageItem.estimated = true`); render `GpuSecondsPerVideoMinute × outputMinutes × GpuPerSecondUsd`, using the **actual** duration the render path reports, never a wall-clock delta. Per-1M rates are divided by 1,000,000 inside `Cost`/`CostBoundUsd`.
- `CostBoundUsd`: the same arithmetic over the bound's upper values: text input ≤ the assembled prompt's UTF-8 byte count, output ≤ `limits.max_output_tokens` per step (02 CR-6: `story_generate` = writer + review + revision + **review #2**, each at its own limit), images ≤ `RenderImagePlanner.MaxTerms` (6/48/90), GPU seconds ≤ `TierMaxMinutes × 60 × gpu_s_per_video_min × 1.5` capped by the render timeout.
- `Credits`: `(long)Math.Ceiling(usd × K(p) ÷ p.CreditUsd)` — `decimal` throughout, the **only** ceiling in the pricing code, computed after the full multiplication (never on `K` alone).
- `Reserve`: `Math.Max(floor.Credits, Credits(CostBoundUsd(bound, rates), p))`.
- `Charge`: `Math.Min(reserve, Math.Max(floor.Credits, Credits(Cost(actual, rates), p)))` — the clamp that makes `charge ≤ reserve` structural (invariant I2) and the floor structural (I3). `Charge` returns the **charged** number only and never writes ledger rows; the ledger row shapes (`settle = −charged`, `release = +reserve`, written together in the same transaction) are 12.2.1-T1's (BR18).
- Guards (domain errors, never silent zeros): negative `usd`, `CreditUsd <= 0`, `Margin` outside `[0,1)`, `FeeRate` outside `[0,1)`, `FxBuffer < 0`, a missing rate for a model/aspect in the usage, a negative bound, `Reserve` overflow (`long.MaxValue` guard on the ceiling conversion ⇒ domain error, alerted by 12.2.1-T1 as a rate/limit bug).
- No `DateTimeOffset.Now`, no `decimal.Round`, no `double` (the arch test asserts purity; I4 asserts the single ceiling).

**3. `usage_records` reservation link (contract only — 02's writer owns it).** The settle path reads `usage_records` rows by `reservation_id`; 12.2.1-T1's `SettleAsync` passes `IReadOnlyList<UsageItem>` built from those rows. This task records and tests the mapping (`usage_records` row → `UsageItem`) as a pure function `UsageItemMapper.FromRow(UsageRecordRow)` so a change in one place cannot desynchronise the two call sites (`Cost` for the settled amount, `CostBoundUsd` for the reserve):

| `usage_records` field | `UsageItem` member | Note |
|---|---|---|
| `operation` | `Operation` | snake_case values → `CreditOperation` |
| `input_tokens`, `cached_input_tokens`, `output_tokens` | same | `output` includes reasoning tokens ⚠️ (02.2.4-T1 confirms field names) |
| `image_count` | `ImageCount` | 1 per billed image (03 D8) |
| `gpu_seconds` | `GpuSeconds` | measured node seconds; the **cost** uses `gpu_s_per_video_min × output_minutes`, this field is recorded for re-measuring (plan §5.7 step 1) |
| `estimated` | `Estimated` | true ⇒ the item used a counted quantity × measured rate |
| `model`, `price_version` | not in `UsageItem` | the version comes from the reservation, not from the row (D4); `usage_records.price_version` is **text** (BR25/00 §6:294) |

**4. Margin/report reuse.** `Cost` is the only cost function; 12.5.2-T1's margin report calls it over `usage_records` rows (never a second implementation), and 12.7.1-T1's `package_below_cost` compares a package's price per credit with `Credits` of the package's credit amount at the current version.

## Steps

1. Add the Domain value types of §Design 1 (`Domain/Pricing/`), including the two `IReadOnlyDictionary` shapes with the `ImageCell` key and the `OperationTier`/`OperationFloor` helpers.
2. Implement `K`, `Credits`, `Cost` (three item kinds), `CostBoundUsd`, `Reserve`, `Charge` with the guards of §Design 2; keep money in `decimal` and the single ceiling in `Credits`.
3. Document each arithmetic step against plan §5.7's step numbers in the XML doc comment (so a reviewer can diff code ↔ formula).
4. Implement `UsageItemMapper.FromRow` (§Design 3) and use it in the settle path contract; hand the same mapper to 12.2.1-T1/12.2.4-T1.
5. Reproduce the §5.7 worked examples as unit tests: story (floor 5 dominates), Standard render (`cost $0.708`, `credits 192`, `reserve 203`, `charged 192`, `returned 11` with the illustrative parameters $0.013/image and 75 GPU s/min at $0.00014/s).
6. Add the bounds tests with the planner's real caps (6/48/90) and `TierMaxMinutes` (1/8/15).
7. Add the architecture tests: `Domain/Pricing/` has no EF/HTTP/`IConfiguration`/`IClock` reference; `Math.Ceiling` appears once in the namespace.
8. Expose the types to 12.1.2-T1 (mapping) and 12.1.3-T1 (`Reserve` for `maxCredits`) and record the member set in the PR description so siblings pin the same names.

## Failure handling and edge cases

| Case | Handling |
|---|---|
| Metered `actual` exceeds the bound (`credits(C) > reserve`) | `Charge` clamps to `reserve` (I2) and the caller (12.2.1-T1) alerts: a bound or rate is wrong — the user is never charged above the reserve they were quoted |
| A usage row arrives after the reservation was refunded (late `usage_records`) | Not this task's path: it is platform loss and is never charged again (README §0 F24/F25 note; 12.2.1-T1 owns the state machine). The calculator only sees the rows given to it |
| An `estimated` usage row | Costed with the counted quantity × measured rate; the row keeps `estimated = true` and the margin report shows the sub-total (12.5.2-T1) |
| Render with no report (no `gpuSeconds`, no duration) | The bound path is used (`TierMaxMinutes × 60 × gpu_s_per_video_min × 1.5`); a missing duration in the settle path is a domain error for 12.2.1-T1 to alert, never a zero charge |
| A model or `aspect:quality` cell missing from the version | Domain error naming the cell; `PriceVersionValidator` already refuses to activate such a version (12.1.2-T1), so this is a defence-in-depth path |
| `Margin = 0`, `FeeRate = 0`, `FxBuffer = 0` | Legal: `K = 1`; covered by a test so a "cheap" configuration cannot divide by zero (`(1−1) = 0` in the denominator is rejected by the guard) |
| Very large bound | The ceiling conversion is guarded (`long.MaxValue`); the overflow path returns a domain error rather than a negative or wrapped value |
| Wall time ≫ GPU time (queue + image waits) | Never charged: `Cost` reads `gpu_s_per_video_min × output_minutes`; the measured `gpu_seconds` stays in `usage_records` for the next re-measurement of the rate |
