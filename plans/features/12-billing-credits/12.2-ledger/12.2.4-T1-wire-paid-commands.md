# 12.2.4-T1 — Wire credits into paid commands and the [PaidOperation] architecture test

| Story | Size | Area | Depends on | Blocks | Phase / flag |
|---|---|---|---|---|---|
| 12.2.4-T1 | S (0.5) | BE | 12.2.1-T1, 12.1.4-T1, 02.2.2-T3, 09.6.1-T1 | 12.8.3-T2 | S · M2 |

## Goal

Make "no path spends provider money for free" structural: every paid command reserves credits **inside its own command transaction** before any provider call, and every terminal transition of a paid job settles the actual (`usage_records` by `reservation_id`) or refunds the reserve. Enforce it with a `[PaidOperation]` marker plus an architecture test that fails when a marked handler has no `ICreditLedger.ReserveAsync` call. Define the reserve-then-dispatch order and the paused 202 shape that 12.8.3-T2's circuit breaker flips on; nothing else may call a provider before the reserve succeeds.

- 12.2.1-T1: `ReserveAsync`/`SettleAsync`/`RefundAsync`/`GetOpenReservationAsync`, the lot-scoped `reserve:{referenceId}:{lotId}` keys (BR19), `reservation_missing` semantics; BR18 (sign convention), F25 (settle snapshots usage; a later row is `platform_loss`, never re-charged), F26 (the render hold is derived — no `render_jobs` column).
- 12.1.4-T1: the `UsageBound` per operation and `OperationFloor`; 02 CR-6: the story reserve covers writer + review + revision + **review #2**.

## Design

**Paid operations (wire exactly these).** `[PaidOperation]` goes on the command handler whose operation is quoted at the route:

| Handler | `CreditOperation` | Wire value | Owning plan |
|---|---|---|---|
| `GenerateStoryCommand` handler | `StoryGenerate` | `story_generate` | 02 (00 §8 route) |
| `GenerateFactSheetCommand` handler | `FactSheet` | `fact_sheet` | 02 |
| the render command behind `POST /episodes/{id}/render` | `Render` | `render` | 09.6.1-T1 |
| 02's handlers for the `bible_proposal`, `idea`, `source_find` operations | `BibleProposal`, `Idea`, `SourceFind` | `bible_proposal`, `idea`, `source_find` | 02 (02 CR-4 operations) |

`story_review` and `story_revision` are **not** paid operations: they are inside the story reservation (02 CR-6) and `GET /billing/quote?operation=story_review|story_revision` returns 400 (README §3.1) — no `[PaidOperation]` may be placed on those handlers.

**Order inside a paid command (transaction boundary = the command's own `UnitOfWorkBehavior` commit):**

```text
1. IBudgetGuard.CheckAsync(CostBound, ct)            // 02's platform-USD caps, unchanged (C6)
2. per-user credit cap (12.4.1-T1, runs before the reserve; 429 spend_cap_reached)
3. ICreditLedger.ReserveAsync(userId, op, referenceId = <owning entity id>, bound, ct)
      -> insufficient_credits 402 (nothing was created, no provider call)
4. persist the owning row (generation_runs / render_jobs) with reservation_id = <ReservationId>
5. if the platform flag provider_funds_exhausted is open (12.8.3-T2):
      status = queued, pause_reason = provider_funds_exhausted, return 202, dispatch nothing
   else: dispatch to OpenAI / MPT after the commit
```

- The reserve is a hard precondition: a paid command that cannot reserve must fail **before** creating a job or calling a provider, and `insufficient_credits` (402) is the answer on all of them.
- The rate policy on every paid route is `paid` (09's policy list); the reserve failure must not consume the rate-limit budget differently from today.
- 02's `IBudgetGuard` platform caps and `spend_cap_reached` (429) keep their `pg_advisory_xact_lock(hashtext('budget_guard'))` — this task must not add a second platform-budget lock (02 T61/F02).

**Settle/refund sites (job/outbox handlers, never the UI — plan 12 §5.1 L203).** Each terminal transition of a paid job dispatches exactly one command through `ISender` in its own scope:

| Terminal event | Call | Command |
|---|---|---|
| provider work succeeded | `ICreditLedger.SettleAsync(reservationId, ct)` | `SettleReservationCommand` ([NotAudited], one per reservation) |
| provider work failed/cancelled, or the episode moves back per 00 §7 | `ICreditLedger.RefundAsync(reservationId, reason, ct)` | `RefundReservationCommand` ([NotAudited]) — reason `job_failed` / `job_cancelled` |
| platform paused > 12 h (12.8.3-T2 cancels the queued job) | `RefundAsync` once | same command, reason `held_timeout` |
| resume dispatch finds no open reservation | cancel instead of dispatch | `GetOpenReservationAsync` gate = 12.8.3-T2 (F08) |

Settle reads `usage_records` by `reservation_id` and snapshots them at `settled_at` (F25); a row landing later is a `credit_ledger (reference_type = 'platform_loss')` row reported as `platformLossUsd` (BR30) and is never re-charged. Row amounts follow BR18: `settle` `−C` per lot, `release` `+R` per lot (the whole hold, written only together with `settle` in the same transaction), `refund` `+R` with no `settle` row; the DTO’s `quoted`/`charged`/`released` are derived per reservation group.

Both commands re-check the reservation is open inside the transaction (the account lock makes the check authoritative) and end `reservation_missing` — metric + alert, **no** movement — when it is already closed (BR4).

**`[PaidOperation]` contract (12 CR-11).** `NightTales.Application` declares `[AttributeUsage(AttributeTargets.Class)] sealed class PaidOperationAttribute : Attribute` carrying the `CreditOperation`. The architecture test (below) reads it via Roslyn: for every `IRequestHandler<,>` whose type carries the attribute, the handler must contain a call to `ICreditLedger.ReserveAsync` (directly or through a private method in the same type); the webhook endpoint stays the only `[AllowAnonymousRequest]` route that writes money state.

**Paused shape (boundary with 12.8.3-T2).** This task owns the reserve-then-dispatch order, the guarantee that a paused system **keeps** the reserve (never releases it), and the 202 response contract with a `reservationId`; 12.8.3-T2 owns the flag store read, the trips, the probes, the ordered dispatch on resume and the 12 h cancel. `GET /episodes/{id}` and `EpisodeUpdated` carry `processingPaused = provider_funds_exhausted` (00 §8/C3) — emitted by 09.6/12.8.3-T2, consumed by 10.8.4 with the copy "Processing is paused. Your credits are reserved, not charged yet".

**i18n:** the 202 response carries no user string; the paused banner keys (`billing.errors.processing_paused` = vi "Hệ thống đang tạm dừng xử lý, credit đã được giữ chỗ và chưa bị trừ" / en "Processing is paused. Your credits are reserved, not charged yet") and `billing.errors.insufficient_credits` are 10.8.x's keys (D18).

## Steps

1. Declare `[PaidOperation(typeof(CreditOperation))]` in `Application/Common` and annotate the five handlers of the table (edits land in 02/09 files coordinated with their owners — this task owns the attribute + the call, not their business logic).
2. Insert the reserve call as the first write in each handler, before the owning row and before dispatch, with `referenceId` = the owning entity id (generated up front so the lot-scoped `reserve:{referenceId}:{lotId}` keys are stable on retries, BR19).
3. Persist `reservation_id` on the owning row (`render_jobs.reservation_id` exists per 00 §6; the generation-run equivalent as 02 defines it).
4. Replace every ad-hoc credit touch in those handlers' completion paths with `SettleReservationCommand` / `RefundReservationCommand` dispatched through `ISender`.
5. Add the paused short-circuit hook (flag read + `queued`/`pause_reason` + 202) that 12.8.3-T2 completes.
6. Write the architecture tests (Roslyn-based) and the integration walk-through test.
7. Confirm no handler calls a provider before the reserve by ordering assertions in the integration test (a fake provider that records call order).

## Acceptance checks

1. **Given** a user with enough credits, **When** any paid command runs, **Then** a `reserve` row exists **before** the owning row is created and before any provider call (fake provider records order: reserve → dispatch).
2. **Given** a user with insufficient credits, **When** a paid command runs, **Then** it returns 402 `insufficient_credits`, creates no `generation_runs`/`render_jobs` row and makes no provider call.
3. **Given** a paid command whose handler lacks a reserve call, **When** `PaidOperationArchTests` runs, **Then** it fails naming the handler type and the missing `ICreditLedger.ReserveAsync` call.
4. **Given** a paid job that succeeded, **When** its job handler completes, **Then** exactly one `settle:{reservationId}:{lotId}` family exists (one row per lot, BR19) and the charge equals `Charge(reserve, actual, p, floor)` with the rows sized per BR18.
5. **Given** a paid job that failed or was cancelled, **When** the handler completes, **Then** the reserve is fully refunded and the episode status moves per 00 §7 (`story_generating → draft | story_review`, `rendering → story_approved`).
6. **Given** the platform flag `provider_funds_exhausted` open, **When** a paid command runs, **Then** it returns **202** with a `reservationId`, the job row is `queued` with `pause_reason = provider_funds_exhausted`, nothing is dispatched to OpenAI/MPT, and the reserve is **not** released.
7. **Given** a settle and a refund racing for one reservation, **When** both run, **Then** exactly one wins and the loser reports `reservation_missing` (metric + alert, no second movement).
8. **Given** the same paid command replayed by the client, **When** it runs twice with the same `referenceId`, **Then** the lot-scoped `reserve:{referenceId}:{lotId}` keys make the second a no-op returning the same reservation (no double reserve, no double provider call).
9. **Given** `GET /episodes/{id}` after a paused paid command, **When** it is read, **Then** `processingPaused = provider_funds_exhausted` is present and `EpisodeUpdated` carried it.
10. **Given** a handler for `story_review`/`story_revision`, **When** the architecture test enumerates `[PaidOperation]` handlers, **Then** neither is marked and `GET /billing/quote?operation=story_review` still returns 400 (the review/revision cost rides the story reservation, 02 CR-6).

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Reserve succeeded, process dies before the job row is committed | the transaction rolls back both (single command transaction) — no orphan reserve; if the job row committed and the process died before dispatch, the reservation is open and the sweep/job lifecycle recovers it (F09) |
| Provider call fails immediately after the reserve | refund via `RefundReservationCommand` (`job_failed`); the episode moves per 00 §7 |
| Double dispatch (retry of the job) | the lot-scoped `settle:{reservationId}:{lotId}`/`refund:{reservationId}:{lotId}` keys (BR19) make the second a no-op; a settle after refund ⇒ `reservation_missing` + alert |
| Paused > 12 h | 12.8.3-T2 cancels + refunds once with reason `held_timeout`; the resume path cancels instead of dispatching when `GetOpenReservationAsync` finds nothing |
| Cap (`spend_cap_reached` 429) reached | no reserve, no job, no provider call; `retryAfterSeconds` to the next UTC midnight (12.4.1-T1) |
| Platform-USD budget exhausted (02's `IBudgetGuard`) | unchanged 429 `spend_cap_reached` from 02's check; the credit reserve is not reached |
| Handler wrapped in a decorator/mediator | the Roslyn test walks the handler type's own methods; a delegated call through another type fails the test on purpose (keep the reserve in the handler) |
| `story_review`/`story_revision` handler accidentally marked | test 10 above fails; the quote route's 400 contract is asserted too |

## Notes

- This task must not change 02's/09.6's business logic beyond inserting the reserve/settle/refund calls and the paused short-circuit hook; the ownership of those handlers stays with their plans (report any conflict instead of rewriting).
- `[PaidOperation]` is a **marker + test contract**, not a runtime interceptor: a runtime decorator would hide the reserve from ordering assertions and from the arch test.
- The reserve-then-dispatch order is the whole point of the paused flow staying fair: the user is not charged while paused and the platform never spends provider money for a reservation that no longer exists.
- Keep `CreditOperation` wire values in one place (the enum→string map used by `reference_type`, the quote route and the history DTO) so `story_generate`, `fact_sheet`, `render`, `bible_proposal`, `idea`, `source_find` cannot drift (BR15).
