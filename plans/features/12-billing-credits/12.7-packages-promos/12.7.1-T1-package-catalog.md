## Goal

## Design

**Domain.** `CreditPackage(Id, Code, NameVi, NameEn, Credits, BonusCredits, PriceVnd, PriceUsd?, Active, SortOrder)` in `NightTales.Domain.Billing.Catalog`; guards in the constructor: `Credits >= 1`, `BonusCredits >= 0`, `BonusCredits <= Credits` (BR13), `PriceVnd > 0`, `PriceUsd is null or > 0`, `SortOrder >= 0`, `nameVi`/`nameEn` non-empty and ≤ 200 chars, `code` matching `^[a-z0-9][a-z0-9_-]{1,31}$` and immutable after creation (payments snapshot `package_id`, so a rename must never silently re-meaning a historic code).

**Application.** `UpsertCreditPackageCommand(CreditPackageInput Input, byte[]? ExpectedRowVersion)` → `ErrorOr<CreditPackageDto>`; `GetAdminCreditPackagesQuery` → `IReadOnlyList<CreditPackageDto>`; `GetCreditPackagesQuery` (public read model) → `IReadOnlyList<CreditPackageDto>` filtering `Active` and ordering `sort_order ASC, code ASC`. Every handler is `[Audited]` (09.3.6-T1 ✅: exactly one of `[Audited]`/`[NotAudited]`/`[AllowAnonymousRequest]`); the public read is `[NotAudited]` + `IUserOwned`-free (it is global catalogue data — the auth policy, not a tenant filter, protects the admin routes).

**The floor check (D4 ✅, BR32).** The package's price per credit — over `credits + bonusCredits` — must be ≥ the minimum price per credit of the **current** version and FX rate (BR32):

```
fx             = (await IFxRateProvider.CurrentAsync(ct)).UsdVnd     // latest provider_topups.fx_rate, fallback Credit:FxUsdVndFallback
pricePerCredit = input.PriceVnd / (input.Credits + input.BonusCredits)
minimum        = MinimumPricePerCreditVnd(priceVersion, fxRate)      // declared by 12.1.1/12.1.2 (BR32)
if (pricePerCredit < minimum) => Error("package_below_cost")
```

`MinimumPricePerCreditVnd(priceVersion, fxRate)` is the value **declared by `12.1.1-T1`/`12.1.2-T1`** (BR32 ✅); the current `price_versions` row is read via `IPriceCatalog` (C7 ✅) and `fxRate` via `IFxRateProvider.CurrentAsync()` (D16/BR7 ✅). All arithmetic is `decimal` with `MidpointRounding.ToZero` on the comparison (never `double`); the failure returns the frozen 400 `package_below_cost` with `Extensions { minimumPricePerCreditVnd, packagePricePerCreditVnd }` (README §3.1 ✅ says only "400 `package_below_cost`"; renamed from the earlier `floorCredits`/`packageCreditsPerUsd` to match the BR32 VND-only formula — the extension names are this task's).

**Persistence.** EF configuration on `credit_packages`: `code` unique index; `price_vnd bigint`, `price_usd numeric(12,6) NULL`, `credits`/`bonus_credits bigint` (C2 ✅); `xmin` mapped as the concurrency token (C2 ✅). PATCH uses `If-Match: "cp-<xmin>"` → load with the token, compare, 412 on mismatch; the response carries the new `"cp-<xmin>"`. The read model is projected straight to the DTO (`AsNoTracking`, `Select`) — no entity leaks to the API.

**Config/DI.** No new options; the FX fallback is `Credit:FxUsdVndFallback` (D10 ✅). DI: the handlers are auto-registered (09.2.1-T1's assembly scan ✅).

## Acceptance checks

- **Given** a package whose effective price per credit is below the floor, **When** `POST /admin/credit-packages`, **Then** 400 `package_below_cost`, no row is written, no `audit_logs` entry exists, and the transaction is rolled back.
- **Given** `bonusCredits > credits`, **When** saving, **Then** a 400 validation failure naming `bonusCredits` and no row (BR13 ✅).
- **Given** an existing package and a stale `If-Match`, **When** `PATCH`, **Then** 412 and the row is unchanged; **Given** the current token, **Then** 200 + the new `"cp-<xmin>"` and an `audit_logs` row with `category = 'billing'`.
- **Given** three active packages with different `sortOrder` and one inactive, **When** `GET /billing/packages`, **Then** exactly the three active ones, ordered by `sortOrder`, with `priceVnd` as an integer and `priceUsd` null where unset.
- **Given** `billing_enabled` false, **When** `GET /billing/packages`, **Then** 200 (the read model is never gated ✅ BR17).

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| No `price_versions` row yet (M2 start) | Boot validation fails fast (`IPriceCatalog` requires an active version) — never a silent pass; the seed ships `2026-10-01.1` |
| No `provider_topups` row (no FX yet) | `IFxRateProvider.CurrentAsync()` falls back to `Credit:FxUsdVndFallback` (D16 ✅); log the source once |
| `priceUsd` supplied that disagrees with `priceVnd ÷ fx` by > 5 % | Save succeeds; a warning is logged and the margin alert path (12.8.4-T1 ✅) owns the audit trail — no silent correction |
| Duplicate `code` | 409 from the unique index mapped to `ValidationProblemDetails` with the field |
| Concurrent PATCH of the same row | `xmin` token ⇒ one wins, the other 412 (`UnitOfWorkBehavior` per-command commit ✅) |
| Package deactivated while it is in a live checkout | The `payments` row keeps its snapshot (`package_id`, `credits`, `bonus_credits` ✅ 12.3.2-T1) — deactivation never rewrites history |
| Zero active packages | `GET /billing/packages` returns `{ items: [] }`; buy UI must show its empty state (`10.8.1-T0` design, 10 CR-24 ✅) — no fallback row is invented |
