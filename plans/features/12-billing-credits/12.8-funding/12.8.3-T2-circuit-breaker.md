# 12.8.3-T2 — Circuit breaker: classifier, MPT mapping, held rows, dispatch gate, 12 h cancel

| Story | Size | Area | Depends on | Blocks | Phase / flag |
|---|---|---|---|---|---|
| 12.8.3-T2 | M (1.0) | BE | 12.8.3-T1, 12.2.1-T1, 12.2.4-T1, 09.6.3-T1, 05.4.1-T2 (soft) | — | S · M2 |

## Goal

Stop the platform from spending money the provider no longer has. One latch (`provider_funds_exhausted`), three trip detectors, one dispatch gate, one hold rule and one deadline: while the latch is open nothing is dispatched to OpenAI or MPT, a paid command still succeeds with its credits **reserved** (202, job `queued`, `pause_reason = provider_funds_exhausted`), `GET /episodes/{id}` / `EpisodeUpdated` carry `processingPaused = provider_funds_exhausted`, and a row held longer than 12 h is cancelled, refunded exactly once and the user e-mailed. The dangerous half of this task is the interaction with the sweeps (F08): a held reservation must never be expired by `CreditReconciliationJob`, and a resumed dispatch must re-check that its reservation is still open — otherwise the platform spends provider money for free or refuses a job whose credits were already taken.

## Design

### Classifier (pure, Domain)

```csharp
public enum ProviderFundsSignal { FundsExhausted, Unrelated }                 // [INFERENCE] member names
public enum FundsMatchSource { OpenAiCode, MptErrorText }                     // [INFERENCE] member names
public sealed class OpenAiErrorClassifier
{
    public ProviderFundsSignal Classify(string? providerCode, string? providerMessage, out FundsMatchSource source);
}
```

- Matches the OpenAI code `credit_balance_exhausted` and `*_spend_limit_exceeded` (02's existing mapping, F-C) and an error **text** containing `credit_balance_exhausted` (the MPT path, ⚠️ F-K — the 05 spike must confirm MPT keeps the text; until then this branch is covered by unit tests over recorded samples and the third detector below is the safety net).
- No I/O, no logging of the raw provider text beyond an id to keep PII out of logs.
- The signal must reach the retry policy as **non-retryable** (D15: "Polly must not retry it"); 02's policy already maps the 429 spend-limit case that way — this task asserts it with a test rather than adding a second policy.

### Trip

```csharp
public sealed record OpenProviderFundsLatchCommand(FundsMatchSource Source, DateTimeOffset OpenedAt)
    : IRequest<ErrorOr<LatchState>>;                                          // [Audited(Category.Billing, Visibility.Internal)]
```

Detectors, all landing in the same idempotent command:

1. **OpenAI path** — `OpenAiTextClient`/image client surfaces `ProviderFundsExhausted` (F-C) → `Source = OpenAiCode`.
2. **MPT path** — `PollRenderJob` maps a task failure whose `error_message` carries the code → `Source = MptErrorText` (soft on 05.4.1-T2 for the exact text/view).
3. **Image-failure storm** — ≥ 3 render jobs failing at the image stage within 10 minutes → a **1-token paid probe** (`IProviderFundsProbe.ProbeTextAsync`, 12.8.3-T1) confirms → `Source = image` (the P value raised by 03.4.2-T1).

Command behaviour: if the flag row is already `enabled` → no-op (no second alert, no second outbox event, and the original `openedAt` stands). Otherwise: `IFeatureFlagWriter.SetAsync("provider_funds_exhausted", true, ct)` (writes `feature_flags` + `feature_flags_changed.v1` + evicts the 30 s cache), outbox `provider_funds_exhausted.v1 { source, openedAt }`, P1 alert through 11.6.2-T1.

### Gate, held rows and the deadline

```csharp
public sealed class ProviderFundsDispatchGate(IFeatureFlags flags, ICreditLedger ledger)
{
    public async Task<DispatchDecision> CheckAsync(Guid referenceId, CancellationToken ct);
}
public enum DispatchDecision { Dispatch, Hold, Cancel }                        // [INFERENCE] member names
```

- `CheckAsync`: flag off → `Dispatch`; flag on → `Hold`. On resume, the ordering loop (12.8.3-T1) calls it again; a **closed/missing reservation** ⇒ `Cancel` (never dispatch), which is the free-spend guard (F08/BR5).
- Three call sites, each a one-line change at the top of its dispatch path: 02's paid generation job, 09.6.3-T1's render submit, `PollRenderJob`'s resume-poll. The gate is the only reader of the flag on those paths — no path reads the flag itself.
- **Held-row predicate** (one helper, used by the gate, the cancel stage and the sweep):

```csharp
// generation_runs: status = 'queued' AND pause_reason = 'provider_funds_exhausted' AND reservation_id IS NOT NULL
// render_jobs:     status = 'queued' AND reservation_id IS NOT NULL AND adapter_task_id IS NULL AND worker_node_id IS NULL
//                  (render_jobs has no pause_reason column — the episode carries processingPaused)
```

  **Why `adapter_task_id IS NULL AND worker_node_id IS NULL` is safe, not over-narrowing (BR29/F26 define the hold as `queued` ∧ flag open ∧ open reservation only):** 09.6.3-T1's state machine makes those two columns structurally NULL for every genuinely `queued` row — `SubmitRenderJob` is the **only** writer of `adapter_task_id`/`worker_node_id` and it runs only when the dispatch gate returns `Dispatch` (never while held); a retry does not revert a row's status in place, it creates a **new** `render_jobs` row per attempt (09.6.3-T1: "new RenderJob(attempt + 1) … state Queued", one row per attempt) — so no `queued` row can ever carry a stale non-null value from an earlier attempt. The two clauses are therefore a redundant, always-true restatement for readability/defence-in-depth, not an exclusion that could strand a held row; if 09.6.3-T1's invariant ever changes (e.g. a row is reused across attempts), this predicate must drop them and rely on `status = 'queued' AND reservation_id IS NOT NULL` alone, matching BR29 exactly.


- **Sweep co-signature.** `CreditReconciliationJob` (12.2.3-T1) excludes a row matching that predicate **only while the `provider_funds_exhausted` latch is open** (the sweep re-reads the flag once per run; 12 CR-26 — without the flag check the exemption would match every pre-dispatch `queued` row forever and silently disable F09's 72 h stale-reserve sweep). While the latch is open a held reservation is never "stale", whatever its age (BR5/BR14). The stale margins stay per-operation (24 h story/fact sheet, 72 h render — F09) for rows that are **not** held.
- **`Credit:HoldCancelHours` cancel** (`HeldJobCancelStage`, contributed to `FundingRunwayJob`): a held row whose own age (`generation_runs.queued_at`, otherwise `created_at`) exceeds the frozen option `Credit:HoldCancelHours` (12, BR29 — never a literal in code) → `RefundAsync(reservationId, "provider_funds_exhausted", ct)` (idempotency `refund:{reservationId}` — exactly once even if two Workers run), row `cancelled`, `finished_at` set, `EpisodeUpdated` published, user e-mailed; the episode moves per 00 §7. A row created *after* the trip is cancelled `Credit:HoldCancelHours` after **its own** queue time, never earlier — D15's "12 h after the trip" is honoured for every row that was already queued when the latch opened, and no row is cancelled before it has waited that long (see Notes).
- Running rows that fail while the latch is open take the existing 02/03/05 failure mapping (`ProviderFundsExhausted` → fail + `pause_reason`), refund through `RefundAsync` and the episode transitions of 00 §7 (`story_generating → draft | story_review`, `rendering → story_approved`). This task does not invent a second failure path.
- Locks: none. The latch is a flag row written by the 09 writer; the cancel/refund path uses the ledger's own `credit_accounts` row lock, and **no** session-scoped advisory lock exists anywhere in 12 (BR2). Batch size for the cancel sweep: 200 rows per run, ids read through a pinned, one-member port declared here — `IHeldReservationCandidateQuery.PendingAsync(ct) → IReadOnlyList<HeldReservationCandidate>` (`HeldReservationCandidate(Guid ReservationId, Guid UserId, string OwnerTable)` — house pattern, matching `ITrialGrantCandidateQuery`/`ISystemWorkQuery.PendingAsyncT`, never extended) — then one command per row (per-row isolation, F-E); a row that fails does not roll back the batch.
- Metrics/alerts: `billing_reservation_missing_total` on a `Cancel` decision, `billing_openai_runway_days` unchanged, P1 on latch open, and the ratified rule key `billing_held_jobs_cancelled_total` (CR-8) on every `Credit:HoldCancelHours` cancel + user e-mail (F21/CR-8).

## Steps

1. `OpenAiErrorClassifier` + `ProviderFundsSignal` in Domain, with the three match cases and their unit tests (including recorded MPT samples).
2. `OpenProviderFundsLatchCommand` + handler: idempotent latch write, outbox event, P1 alert; `[Audited(Category.Billing, Visibility.Internal)]`.
3. Wire detector 1 (the paid client's `ProviderFundsExhausted`), detector 2 (`PollRenderJob`'s MPT text mapping, soft on 05.4.1-T2) and detector 3 (the ≥ 3-in-10-min counter + 1-token confirm; the counter state is process-local per Worker with the metric as the durable signal).
4. `ProviderFundsDispatchGate` + the `IFeatureFlags` read; insert the gate at the three dispatch paths.
5. Held-row predicate helper + `IHeldReservationCandidateQuery` (Application port) + Infrastructure implementation (raw SQL over `generation_runs`/`render_jobs`, no user filter) + the co-signed exclusion in 12.2.3-T1's sweep (one shared helper, two callers) + the regression test.
6. `HeldJobCancelStage` (200-row batches, ordered by `queued_at`/`created_at`) + refund-once + e-mail + `EpisodeUpdated`; register the stage with `FundingRunwayJob`.
7. Tests for the resume path with a closed reservation (the free-spend regression, F08) and for the sweep skip.

## Outputs

- `OpenAiErrorClassifier` with three trip detectors feeding one idempotent latch command; `provider_funds_exhausted.v1 { source, openedAt }` + P1 alert on the first trip only.
- `ProviderFundsDispatchGate` at the three dispatch paths; a paid command while open returns 202 with the reservation kept and the row `queued` + `pause_reason`.
- Held rows survive the daily sweep; a row held longer than the frozen option `Credit:HoldCancelHours` (12) is cancelled, refunded once — one `refund:{reservationId}:{lotId}` row per consumed lot (12 CR-27) — and the user e-mailed.
- `engineering metrics`: `billing_reservation_missing_total`, P1 alert, no second alert pipeline.

## Acceptance checks

1. **Given** an OpenAI 429 carrying `credit_balance_exhausted`, **When** the classifier runs, **Then** `FundsExhausted` with `Source = OpenAiCode`, the call is **not** retried by Polly, and `OpenProviderFundsLatchCommand` opens the latch once.
2. **Given** an MPT task failure whose `error_message` contains `credit_balance_exhausted`, **When** `PollRenderJob` maps it, **Then** the latch opens with `Source = MptErrorText` and the failing job is failed + refunded, not retried.
3. **Given** 3 render jobs failing at the image stage within 10 minutes and a **failed** 1-token probe, **When** detector 3 runs, **Then** the latch stays closed and a warn alert records the anomaly (a failing probe does not open a latch).
4. **Given** the same storm with a **passing** probe, **When** detector 3 runs, **Then** the latch opens with `Source = image`.
5. **Given** the latch already open, **When** a second detector fires, **Then** no second `provider_funds_exhausted.v1` is emitted, no second P1, and `openedAt` is unchanged (idempotent `feature_flags` write through `IFeatureFlagWriter`).
6. **Given** the latch open, **When** a user starts a paid action, **Then** the command returns 202, the credits are reserved (one `reserve:{referenceId}` ledger row), the row is `queued` with `pause_reason = provider_funds_exhausted`, nothing is sent to OpenAI or MPT, and `GET /episodes/{id}` + `EpisodeUpdated` carry `processingPaused = provider_funds_exhausted`.
7. **Given** a held `generation_runs` row and a held `render_jobs` row older than the 24 h/72 h margins, **When** `CreditReconciliationJob` runs, **Then** neither reservation is refunded and both remain `open` (F08/BR5 regression).
8. **Given** a held row whose age exceeds 12 h, **When** `HeldJobCancelStage` runs, **Then** it is `cancelled`, exactly one `refund:{reservationId}:{lotId}` row per consumed lot exists, the episode moved per 00 §7, `EpisodeUpdated` was published and the user was e-mailed; a second run performs nothing.
9. **Given** a held row 11 h 59 m old, **When** the stage runs, **Then** nothing is cancelled.
10. **Given** a resume ordered dispatch where one job's reservation was already closed, **When** the gate runs for that job, **Then** `Cancel` is returned, the job is cancelled (not dispatched), `billing_reservation_missing_total` is incremented, and **no** provider call happens.
11. **Given** a running job that fails while the latch is open, **When** the failure is mapped, **Then** it is refunded and the episode follows 00 §7 (`story_generating → draft | story_review` / `rendering → story_approved`).
12. **Given** the whole flow, **When** any part fails, **Then** no session-scoped `pg_advisory_lock` was taken and every job argument remained ids-only.

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Two Workers trip simultaneously | the flag write is idempotent (`enabled` already true) and the outbox event is guarded by the same check inside one transaction; at most one P1 |
| Storm counter across Worker restarts | process-local, reset on restart; the metric + the 1-token probe make a missed storm detectable (the probe is the authoritative confirmation) |
| Probe itself fails during a storm | treated as "not confirmed" → latch stays closed, warn alert (fail-open here is deliberate: an unconfirmed storm must not freeze all paying users) |
| Reservation closed but the row is still `queued` | gate returns `Cancel`; the row is cancelled via the standard cancel command, `billing_reservation_missing_total`++ |
| Latch closes while the cancel stage is running | the stage re-reads the flag per batch; already-cancelled rows are skipped by `status = 'cancelled'`; a refund is never doubled (`refund:{reservationId}:{lotId}` per lot) |
| Held row whose `queued_at` is NULL (legacy/edge) | fall back to `created_at` (every table has it, C2 preamble); if both are NULL the row is skipped and alerted, never refunded blindly |
| Episode already terminal when the cancel lands | refund still happens (money first), `EpisodeUpdated` is emitted only if the state actually changed |
| 12 h boundary race with a settle arriving | the ledger's reservation lifecycle decides: a settle after refund ends `reservation_missing` (BR4, metric + alert, no movement) — money is never moved twice |
