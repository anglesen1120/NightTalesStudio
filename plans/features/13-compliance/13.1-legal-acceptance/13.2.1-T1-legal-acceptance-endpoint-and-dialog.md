**Gate contract (UC1).** `EnsureCurrentAsync` returns `Error.Conflict(ErrorCodes.LegalAcceptanceRequired, "Legal acceptance required.")`
with metadata `documents` = the missing documents in wire spelling, alphabetical (`["privacy","tos"]`), which the ProblemDetails
writer serialises into the envelope's `errors` map (`errors: { documents: [...] }`) — exactly the shape 13 README D3 fixes and the
shape the FE reads as `fieldErrors` ([OPEN] O-2 tracks the confirmation with 09.1.4-T1's writer). Callers: 06.1.2-T1 before starting
the OAuth flow, 02.8.3-T2 before enabling autopilot (13 CR-2); both surface it unchanged. The gate never writes, never allocates a
tracking entity, and adds exactly one indexed query per connect/autopilot attempt.

**Accept command (UC3).** All-or-nothing: if either submitted version differs from the current one, nothing is written and the
handler returns `Error.Conflict(ErrorCodes.LegalVersionOutdated, …)` with `documents` naming the mismatching ones. On success the
handler records **the server's current version** for each document via `IConsentWriter.RecordAsync(user.Id, document,
currentVersion, ip, ct)` — the client's values are only proof that it rendered the same version. Rows are appended (history, no
unique index, I4) and commit with the ambient transaction; the response body is the fresh projection, so the client never has to
re-fetch after accepting. Repeated acceptance is safe and needs no idempotency key ([OPEN] O-1 records the rationale for the TL:
append-only, non-pecuniary, no `RequireIdempotencyKey()`).

**Routes.**

| Method | Route | Auth | Success | Errors |
|---|---|---|---|---|
| GET | `/api/v1/me/legal` | session | 200 `LegalAcceptanceDto` | 401 `unauthenticated` (existing), 500 |
| POST | `/api/v1/me/legal/accept` | session + `Origin` check (cookie-authenticated POST) | 200 `LegalAcceptanceDto` | 400 `validation_failed`, 401 `unauthenticated`, 409 `legal_version_outdated`, 500 |

No outbox event, no SignalR message, no e-mail: acceptance changes no publication/channel state (plan §5). No ETag/`If-Match` — the
resource is append-only history, not a versioned mutable aggregate ([DECISION], recorded in §8 of the plan so a reviewer does not
ask for one).

## Failure handling and edge cases

- **Stale client** (page cached before a version bump): 409 `legal_version_outdated`, nothing written; the dialog refreshes and shows
  the new version — never auto-accept on the user's behalf.
- **Configuration drift** (`LegalDocuments:Current:*` ≠ manifest): CI red (I1); at runtime the gate keeps working with the configured
  version, so the CI step is the only guard and must be wired before the gate is called met.
- **Missing/oversized version at startup**: fail fast through `ValidateOnStart()` — never a default `1.0.0`.
- **Concurrent accepts** (two tabs): append-only, so both succeed; the last response wins in the UI; no unique index to violate.
- **Database down during the gate**: the caller fails closed (500 with `traceId`, the connect/autopilot action does not proceed) —
  deliberately preferred over "allow when unsure".
- **User deleted between the gate and the write**: the `user_consents` FK violation maps to 400 `validation_failed`, never a raw 500.
- **`errors.documents` shape** ([OPEN] O-2): the list is always the offending documents in the sorted wire spelling
  (`["privacy","tos"]`); if 09.1.4-T1's writer does not surface an arbitrary `errors` key, the dialog falls back
  to refreshing `GET /me/legal` and computing the missing set itself — the endpoint is authoritative either way; record the outcome
  rather than inventing a second metadata key.
- **`unauthenticated`** ([OPEN] O-4): the 401 code is not in 09's §5.4 catalogue; the client relies on the session interceptor and
  this task does not invent the constant.
- **Nothing sensitive in logs or problem bodies**: the version strings are public; the IP goes to the DB column only.
- **Rollback**: the two codes are additive; reverting the app leaves the codes harmless in the catalogue and `user_consents` intact
  (no migration in this task). Reverting `LegalDocuments:Current:*` without reverting the content breaks I1 by design (loud CI
  failure, not silent drift).
- **Scope creep guard**: no per-document accept endpoint, no consent-change realtime event, no consent cache, no second e-mail/
  audit/flag mechanism — all rejected explicitly in the plan (§5, §8).
