## Goal

Deliver the **lawyer-reviewed privacy policy as the published version**: run the external review of 13.1.1-T1's draft, apply the clause-by-clause dispositions to **both** locales, decide the version with the materiality checklist (folder `plan.md` §3.3), keep `manifest.json` in step, and publish through 13.2.2-T1's operator verb (`D6`) so the page `/vi/privacy` + `/en/privacy` and the `legal_documents` row (`kind = 'privacy'`) show **one** version — the version `user_consents.version` records can then never differ from the served page (`K1`). This task owns the review, the version decision and the publish call; it does not own the verb (13.2.2-T1), the page renderer (10.3.1-T1) or the acceptance gate (Part A `13.2.1-T1`). External lawyer time is a **cost** line, not a dev-day line (`O4`, README §B9).

## Design

**Review protocol.** One clause matrix per document (one engagement covers this task and 13.1.2-T2, `O4`):

`| checklist item | source (§5.1 / III.A.2 / 00 §11) | draft paragraph | disposition accepted|reworded|rejected | reason (required for reworded/rejected) | anchor in the new text |`

A row whose check item has no disposition, or a `reworded` row with an empty reason, fails the review-log check (`tests/ci/test_check_compliance_docs.py`).

**Materiality → version (§3.3, [INFERENCE] on the patch/minor split).** Five rows: obligation / right / retention window / price-credit rule / data category. All `unchanged` → the text may stay `1.0.0` (no publish) or become a **patch** (`1.0.1`) when wording changed; **any** `changed` → **minor** (`1.1.0`), which re-opens re-acceptance through 13.2.1-T2/D7. A published version is never overwritten or deleted.

**Files.** `privacy.<version>.vi.md` + `privacy.<version>.en.md` are added; the `1.0.0` files stay in the tree as history (`K1`: the old acceptance must remain reconstructible). The manifest points at the current version only. Locale parity is mandatory: one locale alone is **not** publishable (`D17`).

**Publish sequence (`D6`, verbatim verb).**
1. The web artifact is deployed and the file is served (`content_url` is a path under the deployed static site, never an external URL — `T6`).
2. `nts-worker legal publish --doc privacy --version <v> --locale vi --effective-at <ISO> --content-url /content/legal/privacy.<v>.vi.md`
3. Repeat with `--locale en`.
4. Verify: audit `legal.document_published` (`support`, `internal`) per call, and max `legal_documents.version` per (kind `privacy`, locale) equals the manifest entry (`D6b`). A failure prints **409 `legal_content_missing`** and writes **no** row → deploy, then retry. The row's `checksum` (CR-7, sha256 of the served file) and `published_by` are produced by the verb; this task never inserts the row by hand.
5. `effective_at`: immediate in the single-user case; a scheduled instant only with the owner's decision (a row may exist before its instant; acceptance for it starts at `effective_at`, D7).

**Content obligations the review must confirm (⚠️ = the lawyer decides the wording).** Retention/deletion table (7-day and 30-day windows by trigger) and the 30-day backup window; the per-video consent model plus the autopilot veto window (`D2`); the sub-processor list (OpenAI and the rest); 18+ / children (`D8`); user rights (access, correction, deletion, export); staff access and its logging; the exact required links ⚠️.

**Hand-off, not an edit here.** After a version change the seed value `LegalDocuments:Current:Privacy` must equal the new max row (`D6b`); the startup check asserts it. This task **reports** the published version; it does not edit `appsettings` — resolved (folder `plan.md` §10 O-6/T15): the config is seed-only, no task updates it, and the startup check compares `manifest.json` to the max row instead.

## Steps

1. Build the clause matrix from `docs/compliance/privacy-checklist-1.0.0.md`, plan §5.1 and III.A.2; send the draft, the matrix and the link list to the lawyer.
2. Record every disposition in `docs/compliance/privacy-review-<yyyy-mm-dd>.md` (reviewer identity/credentials, date, scope, fee agreed).
3. Apply the accepted rewordings to **both** locales in one pass (translate, do not transliterate; the vi text stays idiomatic, the en text keeps the Google-facing statements exact).
4. Fill the five-row materiality checklist; mint the version per §3.3 and record the justification.
5. Rename/add the files at the new version, update the `privacy` manifest key, run `tools/ci/check-legal-content.py` and `tools/ci/check-legal-versions.py` locally.
6. Deploy (11's pipeline), then publish both locales with the verb; capture the two audit rows, the row's version/checksum and the timestamps.
7. Close the review log with the publish evidence and the list of ⚠️ items that stay open for 13.4.1-T1's filing notes.
8. When the bump is material, notify 13.2.1-T2's owner (re-acceptance) and the owner (next-login dialog); when the review demands a product change, open a backlog row in the owning plan — the text must not promise what the product does not do (the P slice's "no registration acceptance in P" rule).

## Outputs

- Reviewed `web/src/content/legal/privacy.<v>.vi.md` + `.en.md` and the updated `manifest.json` `privacy` entry (or an unchanged `1.0.0` when the review changes nothing).
- `docs/compliance/privacy-review-<yyyy-mm-dd>.md`: clause matrix, materiality checklist, version decision, publish evidence, ⚠️ remainder.
- One `legal_documents` row per locale set as produced by the verb (kind `privacy`, version, locale, `effective_at`, `content_url`, `published_by`, `checksum`) plus the `legal.document_published` audit rows — or **zero** rows when nothing changed.
- Hand-offs: the published version + URL for 13.4.1-T1's verification filing (`D12`) and 13.5.1-T1's evidence index.

## Acceptance checks

- **Given** the reviewed draft and the reviewer's dispositions, **when** the review log is complete, **then** every §5.1/III.A.2 item has a disposition, no `reworded` row lacks a reason, and the reviewer's identity and date are recorded.
- **Given** a text change in the retention table, **when** the materiality checklist is filled, **then** the retention row reads `changed`, the version is `1.1.0` (not `1.0.1`) and the log names the re-acceptance consequence.
- **Given** a deployed `privacy.1.1.0.vi.md` + `.en.md` and the manifest at `1.1.0`, **when** `nts-worker legal publish --doc privacy --version 1.1.0 --locale vi --effective-at <ISO> --content-url /content/legal/privacy.1.1.0.vi.md` runs (then `--locale en`), **then** it exits 0, two rows exist and the audit has two `legal.document_published` entries.
- **Given** a version whose file is not deployed, **when** the same command runs, **then** it exits non-zero with **409 `legal_content_missing`** and writes no row (the 13-S-legal fail-closed walkthrough, README §B7).
- **Given** the published state, **when** the startup/CI equality check runs, **then** the manifest version equals the max row per (kind `privacy`, locale) and `/vi/privacy` shows that version (`K1`).
- **Given** a reviewed text that differs from what the product does (e.g. a promised export window), **when** the log is closed, **then** a backlog row exists in the owning plan and the sentence is removed or softened — the policy states only what is true that day.

## Tests

- `tools/ci/check-legal-content.py` + `tests/ci/test_check_legal_content.py` (pytest, mirroring `tests/ci/test_check_legal_versions.py`): a missing `en` file, a manifest/file version mismatch, a dropped clause anchor or raw HTML → exit 1 naming file and line; consistent tree → exit 0; `--selftest` green.
- `tools/ci/check-legal-versions.py` (13.2.2-T1's script, run locally here): manifest ⇄ `legal_documents` ⇄ `LegalDocuments:Current:Privacy` equality.
- `NightTales.Architecture.Tests/Legal/LegalContentCoverageTests.cs`: every §5.1 clause anchor present in **both** locales; per-doc manifest entries resolve to existing files at the manifest version.
- Manual (recorded): the lawyer's clause matrix (evidence for 13.5.1-T1); a staging publish rehearsal for both locales completing the 13-S-legal walkthrough.
- No fake or mock is needed: the readers are file reads; no new domain behaviour is introduced here. Nothing asserts English prose beyond the anchors — a test over sentences would test prose, not a contract.

## Failure handling and edge cases

| Case | Handling |
|---|---|
| Lawyer unavailable / engagement slips | the owner-only personal-version draft stays live (`O1`); no publish, no version change; nothing user-facing claims a review |
| The review touches only one locale | not allowed — both locales are re-issued at the same version (`K1`, `D17`) |
| Served file 404 / not deployed | verb fails with 409 `legal_content_missing`, no row; deploy and retry — never insert the row by hand |
| Manifest or config left stale | CI red at `check-legal-versions.py`; fix the value, never the check |
| Review demands a product change | backlog row in the owning plan; the text must not promise it |
| An item stays ⚠️ (exact link wording, governing law) | recorded ⚠️ in the log and carried into 13.4.1-T1's filing notes; never promoted to ✅ on this evidence |
| Version bump is material | 13.2.1-T2 shows `pendingAcceptance`; the previous acceptance does not satisfy the new version (`D7`) |
| Wrong text was published | publish a superseding version (patch if the materiality checklist is all `unchanged`, otherwise minor); published rows are never deleted — there is no delete verb (`D6`) |
| `effective_at` scheduled | allowed; the page shows the version only after the web deploy and re-acceptance starts at the instant, not at row creation (`D6b`) |
