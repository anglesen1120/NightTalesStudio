## Goal

Ship the **public, versioned Content Policy** the P slice deferred (`K14`): `web/src/content/legal/content_policy.1.0.0.vi.md` + `.en.md` (the files 10.3.1-T1 prerenders, `K1`), the `content_policy` entry in `manifest.json`, and the **prohibited/restricted ↔ report-reason map** that makes this policy the single source of the reason taxonomy the report form shows (`D11`). The policy lists prohibited and restricted content with synthetic examples (plan 13 §5.3), states how the platform enforces it, and links to the report path — it does **not** restate plan 02's attestation or 09's suspension rules, it points at them. Publishing happens through 13.2.2-T1's verb with `--doc content_policy` (`D6`). No code, no screen, no migration; the form itself and its endpoints are 13.3.4-T1's.

## Design

**Files.** `content_policy.1.0.0.vi.md` / `content_policy.1.0.0.en.md` at the manifest `content_policy` key (`K1`); later versions follow the same semver-like rule as the other texts (folder `plan.md` §3.3). Because no consent row exists for this document, a new version needs no re-acceptance (`D7` applies to `tos`/`privacy` only) — it still gets a new version, an `effectiveDate` and a `legal_documents` row, so a takedown decision can always cite the policy text in force on the date of the content.

**Document structure (identical section order in both locales).**
1. Purpose and scope (what the policy governs, who it binds, relationship to the ToS).
2. Prohibited content — one bullet per §5.3 prohibited item, each with a synthetic example and a one-line rationale.
3. Restricted content — the §5.3 restricted items, each with the condition under which it is allowed (sources cited, respectful tone, no group targeting).
4. Enforcement — linked, not restated: generation-time rules and the attestation (02.3.3), the review checkpoints in the episode flow (10.7/06), suspension and account actions (09.9.1, 08.2), and uploads going private/blocked.
5. How to report — `/vi/report` + `/en/report` (owned by 13.3.4-T1, route fixed by 10 CR-24), the e-mail channel, and the 72 h **response target** worded as a target (`T9`).
6. Changes to this policy — version + effective date, and the statement that the policy in force on the publication date governs.

**The reason map (`D11`).** A table in the plan/task deliverables and a section in the policy:

| Wire value (fixed) | Policy section that justifies it |
|---|---|
| `copyright` | Prohibited: copyrighted text/music/footage |
| `privacy` | Prohibited: identifiable real people (realistic depiction), private information |
| `defamation` | Prohibited: accusations not supported by cited sources; Restricted: real historical cases |
| `abuse` | Prohibited: content sexualising anyone; harm to minors; glorifying violence or self-harm; hate/harassment; impersonation |
| `other` | Anything not covered above — the catch-all the form offers, explicitly not a sixth category |

Every prohibited/restricted section must appear in the right column at least once (no orphan section), and every wire value must have at least one section (no orphan value). Both directions are asserted by `ReportReasonMappingTests`.

**Labels for the form (hand-off).** `legal.contentPolicy.reason.copyright|privacy|defamation|abuse|other` (vi + en), one short noun per value, worded identically to the policy headings so the form and the policy read as one document. 13.3.4-T1 renders them; this task supplies them and does not touch the form.

**Examples rule `[DECISION]`.** Examples are synthetic and unlinkable (no real person, case, channel, video title or URL); where a category needs an illustration, it is written generically ("a video that names a private individual as a perpetrator without any cited source").

## Steps

1. Draft the vi text from §5.3 (vi is the authoring language), then produce the en text with the same section order and the same legal meaning.
2. Add the prohibited/restricted → reason table; verify each of the five values and every section appears (both directions).
3. Write the six section headings in both locales; keep the section order identical.
4. Add the `content_policy` key to `manifest.json` with `version` `1.0.0` and an `effectiveDate`; run `tools/ci/check-legal-content.py` locally.
5. After 13.2.2-T1's verb is available and the web artifact is deployed, publish both locales:
`nts-worker legal publish --doc content_policy --version 1.0.0 --locale vi --effective-at <ISO> --content-url /content/legal/content_policy.1.0.0.vi.md`, then `--locale en`.
6. Hand the five i18n labels + the map to 13.3.4-T1 (the form's reason list) and record the hand-off in the plan's §7 integration edge.
7. Record in the task's evidence: the section list, the map, the audit rows `legal.document_published` (`support`, `internal`) and the published URL for 13.5.1-T1's index.

- **Given** the report form's reason list, **when** `ReportReasonMappingTests` runs, **then** the list equals `copyright`, `privacy`, `defamation`, `abuse`, `other` and nothing else, each value maps to at least one section, and every section maps to at least one value.
- **Given** a new prohibited category added in a later version with no matching wire value, **when** the mapping test runs, **then** it fails — the fix is a CR to 13.3.4-T1/00 §6, never an extra enum value added here.
- **Given** the deployed files and 13.2.2-T1's verb, **when** the two publish calls run, **then** they exit 0, two `legal_documents` rows exist with kind `content_policy` (`vi`, `en`, version `1.0.0`, `content_url` under the deployed static site) and the manifest `content_policy` version equals the max row per locale (`D6b`); **given** an undeployed version, **then** 409 `legal_content_missing` with no row. No **page** is asserted here: 10 README D12 / 10.3.1-T1 pin only the `/vi|en/privacy` and `/vi|en/terms` routes, so the Content Policy's public route was folder `plan.md` **O-8** — resolved via **13 CR-27** (`10.3.1-T1`'s prerender list gains `/vi|en/content-policy`) — this task's evidence stops at the file, the manifest entry and the row.

## Failure handling and edge cases

| Case | Handling |
|---|---|
| A §5.3 item cannot be expressed in one bullet without a second rule set | fold it into the closest §5.3 item and record the merge in the evidence; do not create a new category that 13.3.4-T1 cannot report on |
| A prohibited category has no wire value | CR to 13.3.4-T1 + 00 §6 (`reports.reason`); never add a sixth value in this folder |
| The policy contradicts 02.3.3's attestation or 09.9.1's suspension rule | the owning plan's rule wins; fix the policy, and record the mismatch as a finding rather than editing the other plan |
| A restricted condition is unverifiable in practice (no sources required in the flow) | word it as a requirement the flow enforces, or move the item to prohibited; a policy rule the product cannot check is a promise, not a rule |
| Copyright section drifts into inventing a legal process (statutory notice/counter-notice steps) | the section names the report path and the contact; the statutory position stays ⚠️ for the lawyer (13.6.1-T1 scope) |
| A takedown/response time is stated as a guarantee | reword to the 72 h **target** (`T9`); the page must not promise what the job queue cannot meet |
| The mapping test would need a new value for a real requirement (e.g. `impersonation` separately) | the wire enum is fixed by `D11`; `abuse` covers it — record the mapping rationale in the evidence |
| Version bump after a category change | new version (patch/minor by the §3.3 materiality test), republished through `D6`, new `legal_documents` row; no acceptance row exists for this document (`[DECISION]` above) |
