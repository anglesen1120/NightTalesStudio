## Goal

Make the cookie claim **verifiable** (`F15`): `docs/compliance/cookies.md` becomes the single inventory (name, host, purpose, category `essential`|`analytics`|`marketing`, lifetime, set by whom — `D13`), the SPA reads a generated constant derived from it, the vi + en notice copy lists the same rows and links to `/vi/privacy`, and **two assertions fail CI the moment a cookie is set outside the inventory** — the API enumerates every `Set-Cookie` name it emits, the SPA enumerates every name its helpers write. While every row is `essential` the platform shows a dismissible **notice** (no wall); the first non-essential row may only land together with a consent banner obtained **before** that cookie is set (`D13`). This task ships the inventory, the generated constant, the copy, the generator and the tests — **not** the mounted notice: that component and its visual design are 10.2.6-T1's (CR-13, owner rule 2026-09-25).

## Design

**Inventory file `docs/compliance/cookies.md`.** One table, columns exactly `name | host | purpose | category | lifetime | set by whom`; rows sorted by (category, name); a header paragraph stating that the file is the single inventory, that the notice renders from it, and that the generated constant is derived from it (never hand-edited). Every row's `set by whom` names the concrete origin (`API: auth refresh cookie`, `SPA: language preference`, …) so a reader can find the code.

**Generator `tools/ci/generate-cookie-inventory.py`** (repo tooling, sibling of the contracted `tools/ci/check-legal-versions.py`):
- parses the table, validates the schema (six columns, `category` in the allowed set, `lifetime` non-empty, name matches `^[A-Za-z0-9_.-]+$`),
- writes `web/src/app/core/legal/cookie-inventory.generated.ts`: `export const COOKIE_INVENTORY: readonly CookieInventoryRow[] = [...]` plus `export const COOKIE_INVENTORY_MODE: 'notice' | 'consent'` (computed from the categories present) and a `GENERATED — do not edit` header,
- `--check` mode rewrites to a temp buffer and fails when the committed constant differs (a stale constant is red in CI);
- a non-essential row without the `consentBanner` companion flag (see below) fails the generator with a message naming the row.

**Copy (i18n, this task).** `legal.cookieNotice.title`, `.intro`, `.row.name`, `.row.purpose`, `.row.lifetime`, `.row.category.essential|analytics|marketing`, `.dismiss`, `.privacyLink`, `legal.cookieNotice.consentBanner.*` (present but unused while `MODE === 'notice'`) — vi + en, plain language, ≤ 2 sentences per row, no legal-advice framing, and the link targets the existing `/vi/privacy` / `/en/privacy` pages (`K1`, `D13`).

**The two closure assertions.**
1. **API side** — `CookieInventoryTests` drives the real pipeline (Testcontainers) through `POST /auth/login`, `POST /auth/refresh`, `POST /auth/logout` and the CSRF/state surface, collects every `Set-Cookie` name from the responses, and asserts the set is a subset of the inventory parsed by the C# reader. `[DECISION]` the C# reader and the pytest parser are exercised against the same fixture table so the two cannot disagree about what the document says.
2. **SPA side** — a Vitest spec exercises every cookie helper and the language switcher, collecting written names, and asserts the subset relation against `COOKIE_INVENTORY`.

**The first non-essential cookie (`D13`).** While every row is `essential`, `COOKIE_INVENTORY_MODE === 'notice'` and the notice is a notice. Adding an `analytics`/`marketing` row flips the constant to `'consent'`; the generator then requires the `consentBanner` copy to be present for every new row, and the SPA test asserts that in `'consent'` mode the banner path is taken **before** any non-essential write. The change is a Gate 2+ owner decision (it changes what is collected), so the row is never added by a developer alone — the inventory diff is reviewed as a privacy change, and the test is the tripwire that makes a forgotten banner impossible.

**Hand-off to 10.2.6-T1 (no component here).** The notice component, its placement and its design are 10.2.6-T1's; this task delivers `COOKIE_INVENTORY`, `COOKIE_INVENTORY_MODE`, the i18n keys and the a11y requirements (keyboard reachable, dismissible by button and `Escape`, AA contrast, focus not trapped, notice does not block the page). Folder `plan.md` §10 **O-2** (resolved: no dedicated page, CR-13/T16) — a page instead of the shell notice would need an approved `<story>-T0 — UI design` task first (owner rule); this plan deliberately ships no screen.

## Steps

1. Read 09's cookie table (BD3) and enumerate, in the running SPA/API as they exist, the cookies actually set (auth refresh, CSRF/state, language); write them into `docs/compliance/cookies.md` with `set by whom` pointing at the code. **No name is invented** (`D13`).
2. Write the generator and the generated constant; commit both; run `--check` locally.
3. Write the vi + en copy keys (both locales in the same change, `D17`).
4. Write `CookieInventoryTests` (API) with a deliberate failing-before fixture (a test-only cookie emitted in a test-double middleware) and confirm the test is red, then green with the row documented.
5. Write the SPA spec over the cookie helpers + the language switcher; same red/green discipline.
6. Write `tests/ci/test_check_cookie_inventory.py` covering: valid inventory green; unknown category red; stale generated constant red; non-essential row without banner copy red; `--selftest` green.
7. Hand the constant, the keys and the a11y list to 10.2.6-T1 and record the hand-off; ask 13.5.1-T1's owner to include the notice screenshot (both locales) in the evidence pack.
8. If any real cookie is found that the owner may not want (a marketing/analytics cookie already present), stop and raise it: document it, and land the consent banner before it is set — never silence the test or delete the row (D13's rule).

## Acceptance checks

- **Given** the running system, **when** login, refresh, logout and the CSRF surface are exercised, **then** every emitted `Set-Cookie` name is a row of `docs/compliance/cookies.md`.
- **Given** a code change that sets a new cookie without a row, **when** CI runs, **then** `CookieInventoryTests` (API) or the SPA spec fails naming the cookie; **given** the row is added, **then** both are green (the failing-before/passing-after case of UC-4).
- **Given** the committed constant, **when** `generate-cookie-inventory.py --check` runs, **then** exit 0; **given** a hand-edited constant, **then** non-zero.
- **Given** every row is `essential`, **when** the notice renders, **then** it is dismissible (button and `Escape`), keyboard reachable, links to `/vi/privacy` / `/en/privacy`, and `COOKIE_INVENTORY_MODE === 'notice'` — no wall, no focus trap (`D13`).
- **Given** an `analytics` row added alone, **when** the generator runs, **then** it fails for the missing `consentBanner` copy and the SPA spec fails for a non-essential write before consent.
- **Given** the copy in both locales, **when** the specs run, **then** every key resolves in `vi` and `en` and each row's purpose/lifetime text is non-empty.
- **Given** the inventory, **when** a reader checks the notice, **then** the notice's rows and lifetimes equal the document's rows (the notice is generated, not typed twice).

## Failure handling and edge cases

| Case | Handling |
|---|---|
| A cookie appears in production but not in the repo code paths read here | document it as a row and record the origin; the inventory describes the running system, not the intended one |
| A cookie is set by a third party (payment provider, e-mail link host) | it is still a row (with `set by whom` naming the issuer) if our page can set it; if the platform never sets it, it is not part of this inventory — record the decision in the file's preamble |
| The auth cookie is renamed by another plan's change | CI red at the API test; the row is updated in the same change as the rename, and the notice copy follows (both locales) |
| A non-essential cookie already exists and someone wants it kept | the banner is mandatory **before** it is set (`D13`) — a Gate 2+ owner decision; the test must not be skipped, and "temporarily" is not an option |
| `Host`-prefix / `__Host-` cookies | listed by their literal name, prefix included (`set by whom` notes the constraint); the generator's name regex accepts `_` and `-` |
| The generated constant is edited by hand | `--check` fails in CI; the fix is to re-run the generator |
| An inventory row has no matching cookie in code | the SPA/API tests do **not** fail on extra rows (the inventory may lead the code by one change), but the owner is asked to remove dead rows in the next version — a stale row is a maintenance signal, not a security failure |
| The notice would be a wall by accident (e.g. a modal) | rejected at the 13-S-trust walkthrough (`D13`: notice, not wall); the requirement is in the hand-off list for 10.2.6-T1 |
