# 13.3.3-T1 — DSAR export job: allow-listed archive, status endpoint, cleanup job

| Story | Size | Area | Depends on | Blocks | Phase / flag |
|---|---|---|---|---|---|

## Goal

Make FR-13-3 real: an authenticated user asks once, gets one machine-readable archive of **their own** data inside the 7-day promise, downloads it through a short-lived link, and the platform deletes the object on schedule without ever leaking a token, a secret, a staff-only audit row or another tenant's data. `POST /me/export` (202 + `Idempotency-Key`, ≤ 1 per user per 24 h) writes `data_export_requests` + outbox `export_requested.v1`; the Worker's `ExportRequestedHandler` schedules `DataExportJob(exportId)`, which streams the allow-listed members into `exports/{userId}/{exportId}.zip` in `nt-media-<env>`; `GET /me/exports/{id}` reports status and mints a fresh pre-signed link; `ExportCleanupJob` removes objects 7 days after creation (T3).

## Design

**Domain** (`src/NightTales.Domain/Compliance/Export/`): `ExportRequest : AggregateRoot, IUserOwned` + `ExportStatus { Queued, Running, Ready, Failed, Expired }`, with unit-tested invariants: `ExpiresAt == RequestedAt + ExportRetentionDays(7)`; `CompletedAt is not null ⇒ Status is Ready|Failed`; `Status` only moves `Queued → Running → Ready|Failed`, `Ready|Failed → Expired` (via cleanup or account deletion); `StorageKey == $"exports/{UserId}/{Id}.zip"`.

**Table** (CR-19, applied): `data_export_requests` — `id uuid PK` (UUIDv7), `user_id`, `status` (`queued`/`running`/`ready`/`failed`/`expired`), `requested_at`, `claimed_at`, `completed_at`, `expires_at`, `deleted_at`, `storage_key`, `error_code`, `attempts`, `last_attempt_at`; `IUserOwned`; indexes `(user_id, requested_at DESC)` and `(status, expires_at)` — the exact CR-19 column and index list, no additions.

**Application** (`src/NightTales.Application/Compliance/Export/`, one file triple per command/query):

```csharp
[Audited] public sealed record RequestExportCommand : ICommand<RequestExportResult>, IIdempotentCommand;
public sealed record RequestExportResult(Guid ExportId);

[NotAudited] public sealed record GetExportStatusQuery(Guid ExportId) : IQuery<ExportStatusDto>;
public sealed record ExportStatusDto(string Status, DateTimeOffset RequestedAt, DateTimeOffset ExpiresAt,
    string? DownloadUrl, IReadOnlyList<MediaLinkDto> MediaLinks, string? ErrorCode);   // CR-19/D9/T12 exact shape
public sealed record MediaLinkDto(Guid Id, string Kind, string Url, long SizeBytes);
```

`RequestExportCommandHandler`: ⓪ `pg_try_advisory_xact_lock(hashtext('nts:dsar_export:' || @userId))` inside the command transaction — the 12 D13 pattern; `false` → 429 `rate_limited` with `Retry-After: 5` (the cap check is now race-safe: a bare read-then-insert, or an `INSERT … WHERE NOT EXISTS`, lets two concurrent requests both pass under READ COMMITTED — **13 CR-32**); ① resolve the newest row for the user (any status — the cap is on `requested_at`, not on "active"); if `requested_at > now - 24 h` → 429 `rate_limited` with `Retry-After` = seconds remaining (policy `Compliance:Exports:MaxPerDay = 1`) and **no** row; ② create the row (`queued`) and an outbox `export_requested.v1 { exportId, userId }`; ③ return 202 `{ exportId }`. The Api never enqueues a Hangfire job (house rule); audit is written for the request ([INFERENCE] action `account.data_exported`, category `support`, visibility `user` — D9 names no export audit row; reported as a gap).

`GetExportStatusQueryHandler`: tenant-filtered read; `not found` → 404 (never 403); when `status = ready` and not expired/deleted → `downloadUrl = IBlobStore.CreateReadUrl(bucket, storage_key, TimeSpan.FromMinutes(DownloadUrlTtlMinutes))` **and** `mediaLinks` freshly minted per request from the archived `media.json` keys — read the archive's central-directory entry for `media.json` only (no need to unzip the whole file), parse the key list, and mint one `CreateReadUrl` per key (≤ 100/page via `?cursor=`, same TTL) — this is T12's "keys in the archive, links only from the status endpoint" and satisfies `00 §8:360`'s "fresh short-lived media links" (CR-19); when `expires_at <= now()` or `deleted_at` is set → `expired` with no URL and an empty `mediaLinks`.

**Worker** (`src/NightTales.Worker/Jobs/`):

- `ExportRequestedHandler` (outbox consumer): opens `ISystemContext.For(userId)` from the event payload, re-reads the row in that scope, ignores a cancelled/expired row, then `IJobScheduler.Enqueue<DataExportJob>((exportId, ct))`. No ambient user ⇒ nothing is read outside a system scope.
- `DataExportJob(Guid exportId)`, `IBackgroundJob`, `[JobPolicy(Queue = JobQueue.Default, Retries = 2)]`: claim `queued|failed → running` (`claimed_at`, `attempts+1`, atomic `UPDATE … WHERE id = @id AND status IN ('queued','failed') RETURNING id`), then in **one** `IServiceScopeFactory` scope with one `ISystemContext.For(userId)`:
  1. create `<temp>/export-<id>.zip`, open `ZipArchive(Create)`;
  2. write the nine members — `profile.json`, `series-episodes.json`, `story-versions.json`, `publications.json`, `consents.json`, `audit-activity.json`, `usage-ledger.json`, `media.json`, `README.txt` — each from an `AsNoTracking()` keyset query (page 1 000, ordered by `id`) serialised with the API's JSON options; `audit-activity.json` includes only `visibility = user` rows;
  3. `media.json` carries `{ id, kind, objectKey, sizeBytes, createdAt }` — **keys, not URLs** (a link inside a stored archive would be dead on arrival; see Notes);
  4. `IBlobStore.PutAsync(bucket, objectKey, fileStream, "application/zip", ct)`; the archive is never buffered in memory (D9);
  5. `ready` + `completed_at`; queue the "ready" e-mail through `IEmailSender` whose body is **only** "sign in to download" (T3/D9: no link, no attachment);
  6. on failure: `attempts < MaxAttempts(3)` → `IJobScheduler.Schedule<DataExportJob>((exportId, ct), 5 min)` outside the retry budget (transport errors do not consume Hangfire retries); else `failed` + `error_code` + `dsar_export_failed_total`.
- Concurrency ≤ 2 (D9): a Worker-local `SemaphoreSlim(2)` [INFERENCE]; when full the job reschedules itself (~30 s) instead of blocking a Hangfire thread; correct for the single-Worker MVP.
- `ExportCleanupJob`, `IRecurringJobRegistration` id `export_cleanup`, cron `0 3 * * *`, `[JobPolicy(Queue = JobQueue.Default, Retries = 2)]`: ① `IBlobStore.DeleteAsync` for rows with `expires_at <= now()` and `deleted_at IS NULL` (≤ `CleanupBatchSize = 50` per run, missing key = success) → set `deleted_at`; ② lease recovery: the candidate query is the **pinned** `ISystemWorkQuery.PendingAsync<ExportRequest>(predicate, batch, ct)` member (never extended toward a second member; it takes **no `ORDER BY` and no lock hint** — `06.2.2-T3:53`, 06 `[OPEN]` O-9), driven by the **bounded sweep loop** copied from `06.2.3-T3:83-96` (`MaxBatches` × `batch`, plus a run-local `failedIds`/exclusion set so a daily run cannot re-claim the same unordered page forever and still terminates). Every candidate is re-read by id inside `ISystemContext.For(userId)` before any write — a by-id re-read under the payload's system scope needs no pinned member at all (that is why the outbox handler above does not use one). Rows stuck in `queued|running` with `claimed_at` (or `created_at`) older than `LeaseMinutes(15)` and `attempts < MaxAttempts` are re-enqueued; beyond that they become `failed` + metric. The expiry sweep is the only cross-user scan and its `IgnoreQueryFilters(["tenant"])` call site lives lexically in **this** class (09.1.2-T1:43; CR-20 allow-list entry).

**Config:** `Compliance:Exports:MaxPerDay` (1), `ExportRetentionDays` (7), `DownloadUrlTtlMinutes` (15), `MaxConcurrentExports` (2), `CleanupBatchSize` (50), `LeaseMinutes` (15), `MaxAttempts` (3), `MaxBatches` (50) / `LeaseBatchSize` (200) for the bounded lease loop.

**i18n** (D17): `account.export.*` in `web/src/assets/i18n/account/{vi,en}.json` — request, "you can ask again in X hours" (429 copy), queued/running/ready/failed/expired, download-ready, and the note that the link expires in ≤ 15 min; handed to 10.8.2-T1 (no page here).

## Acceptance checks

- **Given** a signed-in user with no export in 24 h, **When** `POST /me/export` with `Idempotency-Key`, **Then** 202 `{ exportId }`, one `data_export_requests` row (`queued`, `storage_key = exports/{userId}/{exportId}.zip`, `expires_at = requested_at + 7 d`), one `export_requested.v1` outbox row, and **no** Hangfire job created by the API.
- **Given** that row, **When** the handler + `DataExportJob` run, **Then** exactly one object exists in `nt-media-<env>` and it contains exactly the nine allow-listed members and **no** other entry (asserted by listing archive entries).
- **Given** the archive, **When** its contents are scanned, **Then** no refresh token / resumable session URI / `data_protection_keys` value / `system_settings` value / `platform_payload` body / other-user id / `visibility = internal` audit row appears in any member.
- **Given** a `ready` export, **When** `GET /me/exports/{id}`, **Then** `{ status: "ready", requestedAt, expiresAt, downloadUrl, mediaLinks: [...], errorCode: null }`, `downloadUrl` and every `mediaLinks[].url` expire in ≤ 15 min, and a second call returns **fresh** URLs for both (T12).
- **Given** a second `POST /me/export` inside 24 h, **Then** 429 `rate_limited` with `Retry-After` and no new row; **Given** one 24 h later, **Then** a new row.
- **Given** two concurrent `POST /me/export` with different `Idempotency-Key`s, **Then** exactly one `data_export_requests` row exists and the loser is 429 — the per-user advisory lock serialises the cap check (13 CR-32).
- **Given** a fake clock advanced 7 days, **When** `ExportCleanupJob` runs, **Then** the object is gone, `deleted_at` is set, and `GET /me/exports/{id}` returns `expired` with no URL.
- **Given** another user's `exportId`, **Then** 404 `not_found` (never a 403 oracle) and no object read.
- **Given** the account-scope deletion from 13.3.2-T1, **Then** the user's exports (rows + objects) are gone immediately, irrespective of `expires_at`.
- **Given** a transport failure on `PutAsync`, **Then** the job retries (3 attempts, 5-minute backoff), and after the last attempt the row is `failed` with `error_code` and `dsar_export_failed_total` incremented once.
- **Given** a stuck `running` row past the 15-minute lease, **When** the cleanup job runs, **Then** it is re-enqueued once (not two jobs at once).

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Two `POST /me/export` racing on the same key | `IIdempotentCommand` returns the first response; the per-user advisory lock is the backstop — a loser that slipped past idempotency gets 429 `rate_limited` (`Retry-After: 5`), and its retry hits the idempotency store and returns the original 202 (13 CR-32) |
| Two different keys, same second | the per-user advisory lock serialises the 24 h check + insert inside one transaction ⇒ one row, the loser gets 429 (CR-19 names no unique index for this — none is relied on) |
| `ISystemContext.For` called twice in the job | throws by contract — the job opens exactly one scope and never nests; asserted by test |
| Row deleted between outbox event and job (account deletion) | handler/job see no row in the system scope ⇒ no-op, exit cleanly, no metric noise |
| Storage bucket missing/renamed | `PutAsync` error → retry → `failed` + metric; the user sees `failed` with an `errorCode` and can ask again after 24 h |
| Huge account (100 k+ rows per table) | keyset paging, one member at a time, temp file on disk; never a whole-table `ToList()`; the 7-day window is the SLA, not a synchronous request |
| E-mail delivery fails | `SendEmailJob` retries 5×; the export stays `ready` and downloadable regardless (no link in the mail, so a lost mail is recoverable by signing in) |
| Clock skew on `expires_at` | all comparisons use `IClock.UtcNow` (FakeClock-testable), never `DateTime.Now` |
| Formulaire abuse | the 24 h cap + auth requirement are the only brakes; `dsar_export_failed_total` catches a retry storm |
