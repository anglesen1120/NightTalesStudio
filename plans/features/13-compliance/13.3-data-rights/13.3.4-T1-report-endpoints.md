## Goal

Give a third party one public, rate-limited, CAPTCHA-protected way to report harmful content, and give the owner the triage surface behind it — without ever confirming whether a target exists. `POST /reports` answers **202 `{ reportId }` for every well-formed request** (T1: any `targetId`, even a well-formed but unknown uuid), and its only effects are one `reports` row, one outbox `report_received.v1`, exactly one owner e-mail and one `abuse.report_received` audit row. `GET /admin/reports?status=` + `PATCH /admin/reports/{id}` let an admin resolve a report with a note and measure the 72-hour target on `created_at` (F8, FR-13-5). The page content and its vi+en copy are authored here; the page host, the CAPTCHA widget and the admin screens belong to 10.

## Design

**Domain** (`src/NightTales.Domain/Compliance/Reports/`): `Report : AggregateRoot` + `ReportTargetType {Episode,User,Publication}`, `ReportReason {Copyright,Privacy,Defamation,Abuse,Other}`, `ReportStatus {Open,InReview,Resolved,Rejected}` exactly as declared in `plan.md` §3. `Report.Create(...)` **never** takes a resolved target — existence is not part of the model; `Resolve(to, handledBy, note, now)` allows only `Open|InReview → Resolved|Rejected` and sets `ResolvedAt` once. `reports` is **not** `IUserOwned` (public input), so it has no tenant filter; the admin group is the only reader.

**Table** (CR-7/CR-16; `plan.md` §3): `reports` + `ix_reports_status_created_at (status, created_at)`. Migration owned here, 09.2.2-T1 conventions, expand-only.

**Application** (`src/NightTales.Application/Compliance/Reports/`):

```csharp
[AllowAnonymousRequest] public sealed record SubmitReportCommand(string? ReporterEmail, ReportTargetType TargetType,
    Guid TargetId, ReportReason Reason, string? Details, string Locale, string? CaptchaToken)
    : ICommand<SubmitReportResult>;
public sealed record SubmitReportResult(Guid ReportId);

[NotAudited] public sealed record GetAdminReportsQuery(string? Status, string? Cursor)
    : IQuery<AdminPageDto<AdminReportDto>>;                     // 09's envelope, ≤ 100/page, keyset (created_at DESC, id DESC), one projection query
public sealed record AdminReportDto(Guid Id, string? ReporterEmail, string TargetType, Guid TargetId, string Reason,
    string? Details, string Status, DateTimeOffset CreatedAt, DateTimeOffset? ResolvedAt, Guid? HandledBy, string? ResolutionNote);

[Audited] public sealed record ResolveReportCommand(Guid ReportId, ReportStatus Status, string? ResolutionNote)
    : ICommand<AdminReportDto>;   // wire body is 09.9.1-T1's `{ status, note }`; `note` maps onto `reports.resolution_note` (CR-26)
```

`SubmitReportCommandHandler` (order matters): ① verify CAPTCHA through 09.3.3-T2's verifier (`captchaToken` + resolved client address); a failure is the 09 code and **no** row — the verifier is fail-closed (a verifier outage → 503, never an unverified accept); ② FluentValidation over shape only (`TargetId != Guid.Empty`, enums parsed, `Locale ∈ {vi,en}`, `Details ≤ 2 000`, `ReporterEmail` valid when present, `reporterEmail` never logged); ③ `ip_hash = SHA256(salt + resolvedIp)` using 09.3.5-T1's IP-hash helper (same one the limiter partitions with — no second hashing scheme, no new secret); ④ insert one `Report` (`open`) + one outbox `report_received.v1 { reportId }`; ⑤ return 202 `{ reportId }`. **No target lookup anywhere in the path** — a random uuid, an existing episode of another tenant and a deleted publication all take the same branch (T1).

`ReportReceivedHandler` (outbox consumer, Worker): audit `abuse.report_received` (`support`, `internal`) and queue exactly one e-mail through `IEmailSender` to the `report-to` setting (D11) — subject/body carry the report id, target type and reason but **not** `reporter_email`; the mail is best-effort (the row is the record of truth). `ResolveReportCommandHandler`: load, `Resolve(...)`, save; `resolved_at` + `handled_by` set; audit `abuse.report_resolved`; a refused transition → 409.

**API.** `POST /reports` — anonymous, `.RequireRateLimiting("anon")` (CR-10's policy name, T4: no limiter registered here) and 202 for every well-formed request; `report_target_invalid` (400) is emitted **only** for a malformed uuid/enum, never for an unknown target. The **handler/query side** of `GET /admin/reports?status=&cursor=` and `PATCH /admin/reports/{id}` is ours, but the **routes are not**: both are pre-existing rows of the single `/api/v1/admin` group registered by **09.9.1-T1** under `AdminPolicy` (`09-backend-api/README.md:1053`; 09 D20 forbids a second group/policy at `:1032`). So: no route group, no policy, no pagination envelope of our own — return 09's `AdminPageDto<AdminReportDto>{ items, nextCursor }` (`?status=&cursor=`, ≤ 100/page, one projection query), wrong role/unauthenticated → 404 `not_found` (never 403), the list masks `reporter_email` as `a***@domain` while the raw address and `ip_hash` stay owner-only, and the PATCH body is 09's `{ status, note }` (13 D11 writes `resolutionNote`; the wire name is 09's — CR-26). The 72-hour target is derived from `created_at` (never stored as a promise on the page, T9).

**Page + copy** (FE part; owner rule): `/vi/report` + `/en/report`, prerendered, **no** API call at build time (K11; route fix is 10 CR-24). Fields: target type, target id (an opaque string field — no autocomplete, no validation against the API), reason (select generated from the Content Policy's prohibited/restricted sections, 13.1.3-T1), details (optional, `maxlength` 2 000), optional reporter e-mail (labelled "only if you want a reply"), the `CaptchaWidget` from 10's `features/public`, and a submit button. On success show one neutral confirmation ("we received your report") — never the target's name. i18n keys `public.report.*` in `web/src/assets/i18n/public/{vi,en}.json` (⚠️ folder name confirmed with 10's `features/public`), both languages in the same change (D17). a11y (D17/WCAG 2.1 AA): real `<form>`, `<label>` per field, `aria-describedby` for hints/errors, an error summary that takes focus, keyboard-reachable CAPTCHA with an accessible alternative, and no colour-only states. **Design gate (owner rule 2026-09-25, D19/T14):** `10.3.1-T0 UI design (public marketing + auth)` is a **hard** dependency of this task (its scope covers the report page per CR-24) — the header row above already carries it; the FE part may not start before that design is owner-approved.

## Acceptance checks

- **Given** an anonymous caller with a solved CAPTCHA inside the `anon` limit, **When** `POST /reports` with `targetId = <random uuid>`, **Then** 202 `{ reportId }`, one `reports` row (`open`), one `report_received.v1`, exactly one owner e-mail, one `abuse.report_received` audit row — and the response contains nothing about the target.
- **Given** the same call with a `targetId` that names a real episode belonging to another user, **Then** the response is **byte-identical** to the unknown-uuid case (same status, same body shape), and no episode data is read.
- **Given** a malformed target (`targetId` not a uuid, unknown `targetType`/`reason`, `locale = "fr"`), **Then** 400 `report_target_invalid` / `validation_failed` and no row.
- **Given** a missing/invalid CAPTCHA token, **Then** the 09.3.3-T2 failure code and no row; **Given** the verifier is unreachable, **Then** 503 and no row (fail closed).
- **Given** more than 60 requests from one resolved IP in a minute, **Then** 429 `rate_limited` with `Retry-After`, emitted by the shared `anon` policy (no limiter code in this folder).
- **Given** an admin/owner, **When** `GET /admin/reports?status=open`, **Then** ≤ 100 rows/page with a working keyset cursor, one SQL query (no N+1), and `created_at` present so the 72 h target is measurable.
- **Given** a `PATCH` with 09's body `{ status: "resolved", note: "…" }`, **Then** 200, `resolved_at` + `handled_by` set, `resolution_note` stored, one `abuse.report_resolved` audit row; **Given** a `PATCH` on an already resolved row, **Then** 409 (transition refused); **Given** an unauthenticated caller or a wrong role on either admin row, **Then** 404 `not_found` (`AdminPolicy`, never 403); **Given** the list response, **Then** `reporter_email` is masked `a***@domain`.
- **Given** the public page, **Then** `/vi/report` and `/en/report` render in both languages, the reason list matches the Content Policy sections, the form passes an axe check and prerenders without an API call; **Given** the design `10.3.1-T0` is not approved, **Then** the FE part has not started (gate).

## Failure handling and edge cases

| Case | Behaviour |
|---|---|
| Target id unknown / deleted | 202, identical body (T1) — the only difference exists in the admin screen, never in the response |
| Report about the reporter themselves / self-report | accepted; triage decides (no special case) |
| Duplicate submissions of the same target+reason | separate rows **by design** (D11 has no dedupe rule); the `anon` limit + CAPTCHA are the only brakes — flagged `[OPEN]` if abuse appears |
| CAPTCHA outage | 503, no row, metric counter; the page shows a retry message, never a silent fake success |
| E-mail delivery fails | `SendEmailJob` retries 5×; the row and the admin list are unaffected (T9) |
| Admin resolves without a note | allowed (`resolutionNote?`); the audit row records the transition anyway |
| Report arrives for a target in another tenant | never read, never joined; the admin screen decides by target id |
| Details field used to smuggle PII | length-capped and stored as-is; never rendered as HTML (Angular `{{ }}` interpolation only, no `innerHTML`), and `Details` is excluded from the owner e-mail body |
| 72 h target missed | visible as the oldest open report age (D15/13.5.2-T1) — **not** a user-facing promise (T9) |
