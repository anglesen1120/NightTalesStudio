# 13.4.1-T1 — Google OAuth sensitive-scope verification filing + `saas_registration` launch gate

## Goal

File Google's OAuth **sensitive-scope verification** for `youtube.upload` on the production API project, from the narrowest scope set `06.1.1-T1` actually uses, with every D12 pre-condition proven at filing time — and keep registration closed behind `RequireFeature("saas_registration")` until the verification is **granted**, because until then every external user sees the unverified-app warning screen and an app left in Testing is capped at 100 users (README K17/F9/O9).

Deliverable = **documents and filing only** (`docs/compliance/google-oauth-verification-<yyyy-mm-dd>.md`, the calendar row handed to 13.5.2-T1, and a flag paragraph for the 08.3 runbook). Per D18 this task adds **no route, no DTO, no table/column/index, no migration, no job, no CLI verb, no `tools/` script, no config key**; the single runtime action is the existing operator verb `nts-worker flags set saas_registration on`.

## Design

**Repo artifact (text only).**

```
docs/compliance/google-oauth-verification-<yyyy-mm-dd>.md    # <yyyy-mm-dd> = filing date, ISO
  ## 0. Header            filing date · production project (redacted label + external artefact id) ·
                          brand-verification status · pre-condition table below · form URL · sign-off
  ## 1. Pre-conditions    verified domain · live homepage / privacy / ToS URLs + versions · app in production ·
                          multi-user connect works · narrowest scope set
  ## 2. Scope table       | scope | code path that needs it | Google bucket (sensitive/restricted/basic) | kept? |
  ## 3. Demo video        id · visibility = Unlisted · language = en · what it shows (consent grant) · recapture steps
  ## 4. Submission        questions verbatim as presented · answers · link/artefact refs · sent at
  ## 5. Launch gate        flag key `saas_registration` · verb · who flips · condition · 100-user cap note
  ## 6. Calendar rows      filing date · expected reply (range/unknown ⚠️) · appeal path · re-file cadence
  ## 7. Follow-up log      appended per exchange (info requested, granted, denied + reason); earlier sections unchanged
```

**Schema details.**

- **§1 pre-condition rows:** `| Pre-condition | Proof | Where | Checked at | Verdict |` with `Verdict ∈ {proven, provisional, gap}`; a `gap` **blocks the filing** (the same rule as the YouTube audit walkthrough). `provisional` = the proof exists but only on staging or a screen is not shipped — the label is explicit.
- **§2 scope rows:** scope names are copied from `06.1.1-T1`'s client config, never typed from memory; each row's `code path` is a real call site (e.g. the upload path that needs `youtube.upload`); a scope with no call site is removed from the client *before* filing (its removal is a CR to 06, not an edit here).
- **§3 demo video:** Unlisted, English, shows the consent grant (K15). No real account, e-mail, token or API key appears in frame (D14); the recorded tenant is `demo+<n>@invalid`. `Unlisted` is recorded as a field (id + visibility) in this artifact **and** in the pack index (D14).
- **§5 launch gate:** `flag key = saas_registration`; flip = `nts-worker flags set saas_registration on`; the condition is "verification granted", recorded in §7; while off, an external registration gets 404 `feature_disabled`. The 100-user Testing cap and the 7-day refresh-token expiry of Testing (K17) are the reasons the default is closed.
- **Status vocabulary** used in the calendar row: `not_filed | filed | info_requested | granted | denied`. No other status word.

## Steps

1. Read `06.1.1-T1`'s config and build §2: list every scope the app requests, the call site that needs it, and the Google bucket; mark any scope with no call site for removal (raise it as a 06 CR; do not file with it).
2. Prove §1: brand verification status first (K15 — brand verification **precedes** data-access verification), the domain's verified state, and the three URLs live with their versions. Cross-check the served versions against `legal_documents` max per (kind, locale) and run `tools/ci/check-legal-versions.py` (13.2.2-T1). Record the served `privacy`/`tos` versions verbatim — the filing's version claim is only valid with this green.
3. Confirm the app is in **production** in the console and that multi-user connect runs (06.1.1-T1), i.e. the flow the demo video will show exists.
4. Record the demo video: create it Unlisted + English showing the consent grant, cite its id/visibility in §3, and add its artefacts to the 13.5.1-T1 pack (`video id + visibility` row). No real user data in frame.
5. Capture the form's questions **verbatim** as presented (they are not published in the plans) and answer each in ≤ 3 sentences, every claim traceable to a §1/§2 row or a pack artefact id; no claim outside those.
6. File the submission; record `sent at` and the console/ticket reference in §0/§7.
7. Fill the calendar values (§6) and hand the row to 13.5.2-T1: filing date, expected reply (range/unknown ⚠️ — never a fabricated date), re-file cadence, appeal path `https://support.google.com/youtube/contact/yt_api_appeals`.
8. Keep `saas_registration` **off**; draft the 08.3 runbook paragraph (flag key, verb, flip condition, what the user sees while off) and hand it to 08's owner.
9. On the outcome: `granted` → run step 10; `info_requested` → answer, append to §7, re-submit; `denied` → record the reason, use the appeal path, keep the flag off.
10. On `granted`: record the grant + its evidence, run `nts-worker flags set saas_registration on`, update the calendar row status, and re-run the D6 equality check on the deployed environment before announcing open registration.

## Acceptance checks

- Given the app is unverified and the flag is off, When an external address submits the registration form, Then the API answers **404 `feature_disabled`** and no account is created (the check itself belongs to 09.9.2-T2; this task records the observed result).
- Given the verification is granted, When the owner runs `nts-worker flags set saas_registration on`, Then a new external registration succeeds, the unverified-app warning screen no longer appears, and §5/§7 record the flip with its date.
- Given the filing artifact, When a reviewer reads §2, Then **every** scope row names a code path that needs it and no scope without a call site remains in the client; and When they read §1, Then every pre-condition row has a dated proof and a verdict, and no `gap` row exists at filing time.
- Given the filing claim "privacy policy vX.Y.Z is live", When the page, `legal_documents` max for the locale and `tools/ci/check-legal-versions.py` are compared, Then all three agree (D6/CR-12).
- Given §3, Then the demo video is recorded as **Unlisted** and **English**, shows the consent grant, and contains no real e-mail, token or API key (D14; redaction grep clean).
- Given §5 and the calendar row, Then they name the same flag key `saas_registration` and the same verb spelling; Given the 08.3 runbook paragraph is handed over, Then it repeats the same pair.
- Given the filing is `filed` or `info_requested`, Then registration is still closed; only a recorded `granted` precedes the flip (O9/F9).

## Failure handling and edge cases

| Case | Handling |
|---|---|
| Brand verification still pending | Do **not** file data-access verification (K15 order). Calendar row status stays `not_filed` with a reminder cadence; §1's brand row reads `provisional`. |
| The served page version ≠ `legal_documents` max | Blocked until 13.2.2-T1's equality check is green; if the drift is real, the fix is in 13.2.2-T1 (publish/redeploy), not a note in the filing. |
| A requested scope has no code path | Remove it from `06.1.1-T1`'s client config first (CR to 06); filing with an unused sensitive scope invites a rejection. |
| Google asks a question the doc cannot answer | Answer only from §1/§2 + pack artefacts; append the exchange to §7; never invent a capability. |
| Filing denied | Record reason in §7, use `https://support.google.com/youtube/contact/yt_api_appeals`, keep registration closed (never flip the flag to "test" the grant). |
| Flag flipped by mistake | Flip back with `nts-worker flags set saas_registration off`, record it in §7; the flag change is audited by 09.9.2-T2's path. |
| Demo video shows real data | Delete it, recapture with `demo+<n>@invalid`; the old id is removed from §3 and the pack index. |
| Reply time unknown (⚠️, 13 §2 C7) | Calendar stores an expected range/unknown with a check cadence — never a made-up date. |
| A 10 wave-2 screen (channel connect) is not shipped when the video is due | §1 row goes `provisional`, the video uses the shipped subset (consent grant is the required element, K15), and the pack marks the artefact `provisional` with the blocking task id. |
