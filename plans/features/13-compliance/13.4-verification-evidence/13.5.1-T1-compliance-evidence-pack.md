# 13.5.1-T1 — Reusable compliance evidence pack (in-repo index + out-of-repo binaries)

| Story | Size | Area | Depends on | Blocks | Phase / flag |

## Goal

Capture the seven compliance flows once, on staging, as a **reusable** pack: `docs/compliance/evidence-<yyyy-mm-dd>/index.md` in the repo (what each artefact proves, when it was captured, the app version, the file's sha256, its redaction check) and the binaries in `~/.nts/compliance/evidence-<yyyy-mm-dd>/` on the FileVault disk — never the repo, never `/Volumes/Project` (D14 :246, O7 :400, T5 :406, CR-15 :283).

Deliverable = one index file plus the binary set; **no code, no route, no DTO, no table/column/index, no migration, no job, no CLI verb, no `tools/` script, no config key** (D18 :262). Dependent filings cite artefact ids instead of retaking screens: 13.4.1-T1's demo video and submission doc, 13.4.2-T1's re-file, 13.4.3-T1's required-UX matrix, and 13.6.1-T1's memo when it needs a behaviour reference.

## Design

**Repo artifact (text only).**

```
docs/compliance/evidence-<yyyy-mm-dd>/index.md     # <yyyy-mm-dd> = capture date, ISO
```
**Binaries (external, FileVault disk).**

```
~/.nts/compliance/evidence-<yyyy-mm-dd>/EV<n>-<slug>.png | .mp4 | .json
```
**Index schema** — one row per artefact, this pack's local numbering `EV1…EVn` (the same discipline as 06.5.1-T1's `A1–A16`):

```
| Id | Flow | What it proves | Captured at | App version | Binary | sha256 | Redaction checked | Owning task | Verdict |
```
- `Flow` is one of the seven names above (verbatim, no synonyms).
- `What it proves` = one sentence, in terms of a policy clause or a required UX item (so a filing can cite it directly).
- `App version` = git sha + build id of the environment captured; a stale pack is visible.
- `Redaction checked` = the grep run + who ran it + date; `Verdict ∈ {proven, provisional, gap}` where `provisional` = staging-only or a screen not yet shipped (**[OPEN]** 10 wave 2), `gap` = missing, and a `gap` artefact must be listed (never silently omitted).
- The index stores **paths and hashes**, never the binary bytes and never a base64 blob.

**Repo header section** (above the table): pack date, environment, app version, capture operator, tenant convention (`demo+<n>@invalid`), the exact redaction command run, and the retention note (kept until the next successful re-audit, ≥ 24 months — D14 :248).

**Additional artefacts rule.** Only two sources may add rows: (a) a task citing the pack that states which artefact it needs (13.4.1-T1 §3's demo video, 13.4.3-T1 §2's required-UX matrix, 13.6.1-T1's memo), and (b) the seven flows above. The pack must not grow into a general screenshot dump — mirroring the boundary rule between 06.5.1-T1 and 13.4.2-T1 (`06.5.1-T1-audit-evidence-pack.md:136`).

**Capture rules.** vi + en where the surface is bilingual (D17); the recorded tenant is synthetic; no real e-mail, IP, token, API key or real user's story text in frame (D14); Google demo videos are **Unlisted** and their id + visibility are recorded here **and** in the D12 submission doc; a screencast's narration is English for Google's submission (K15).

**Reproduction column.** Every row carries enough steps (route, tenant, click path, expected observable) that a second person can retake the artefact after a UI change — that is what makes the pack *reusable*.

## Steps

1. Freeze the pack date and the app version; create `docs/compliance/evidence-<yyyy-mm-dd>/` and `~/.nts/compliance/evidence-<yyyy-mm-dd>/`; record both in the header.
2. Prepare the synthetic tenant (`demo+<n>@invalid`) on staging with a channel connection, one series, one episode and one publication, so the publish form, per-video consent and disconnect flows have real state to show.
3. Capture the seven flows in order (registration consent → connect → publish form → per-video consent → disconnect + revoke explanation → deletion request → export); for each, record at capture time: id, flow, what it proves, timestamp, app version, file name.
4. Capture the artefacts the citing tasks ask for (demo-video flow set for 13.4.1-T1; the required-UX screens for 13.4.3-T1; the cookie notice and report form when 13.1.4-T1/13.3.4-T1 land) — same schema, same rules.
5. Redact and verify: re-shoot when anything real is in frame; run the VP7 grep over every **text** artifact in `docs/compliance/**`; record the command, the runner and the date in `Redaction checked` for each row.
6. Hash: `shasum -a 256` every binary; put the digest in the index (a mismatch makes the artefact unusable for a filing).
7. Write `index.md` (header + table with no empty cells); confirm the repo copy contains no binaries (`git status --porcelain docs/compliance` shows only `.md`).
8. Hand the pack path/date to 13.4.1-T1 (§0/§3) and 13.4.3-T1 (§0/§2), and note the pack date in 13.4.2-T1's re-file inputs if a re-file happens while this pack is current.
9. Record the retention decision and the recapture trigger (any change to a captured screen, or a new filing that needs a flow the pack lacks).

## Outputs

- `docs/compliance/evidence-<yyyy-mm-dd>/index.md` — header section + one row per artefact, all columns filled.
- The binary set under `~/.nts/compliance/evidence-<yyyy-mm-dd>/` with matching sha256 digests.
- The redaction evidence (command + date) recorded in the index, and the retention note (≥ 24 months, D14).
- Artefact ids cited by 13.4.1-T1 and 13.4.3-T1; no code, no configuration, no route, no migration (D18).

## Acceptance checks

- Given staging with a synthetic tenant, When the seven flows are captured, Then the index has exactly one row per flow (ids `EV1…EVn`), each with non-empty `What it proves`, `Captured at`, `App version`, `Binary`, `sha256`, `Redaction checked`, `Owning task` and `Verdict`, and each `sha256` matches `shasum -a 256` of its binary.
- Given the repo, When `git status --porcelain docs/compliance` is read, Then it lists only markdown; When `grep -RIn` with the VP7 pattern runs over `docs/compliance/**`, Then there is no token, real e-mail, IP or real video-id match (D14).
- Given an artefact row, When a second person follows its reproduction steps, Then they reach the same observable state without exposing real user data (TS-9 of `plan.md` §9).
- Given a screen in the pack is not yet shipped, Then its row's `Verdict` is `provisional` and its `Owning task` names the blocking 10/13 task (never a false `proven`).
- Given the index header, Then it states the pack date, environment, app version, tenant convention, the redaction command and the ≥ 24-month retention (D14 :248).
- Given a Google demo video artefact, Then its visibility is recorded as **Unlisted** here and in the D12 submission doc (K15).
- Given a citing task, When it references the pack, Then it references the artefact id and the pack date — not a bare screenshot path (so a re-capture invalidates citations visibly).

## Tests

No test file or script is added (D18). Evidence run:

- **Hash consistency (TS-3):** `shasum -a 256 ~/.nts/compliance/evidence-<date>/*` against the index column; every digest matches.
- **Redaction (TS-2):** the VP7 grep over `docs/compliance/**` (`06.5.1-T1-audit-evidence-pack.md:117`) + `git status --porcelain` shows no media.
- **Index completeness (TS-6):** read the table; no empty cell; every `Flow` value is one of the seven flow names verbatim; every `Verdict` is `proven|provisional|gap`.
- **Reproducibility (TS-9):** one artefact retaken by a second person from the index alone.
- **Gate use (README :325, `13-S-trust`):** the pack is the evidence behind the consent/deletion/export claims of the filing gates; a `gap` artefact is a visible blocker rather than a silent pass.
- **Manual environment check:** the recorded app version equals the running environment's git sha + build at capture time.

## Failure handling and edge cases

| Case | Handling |
|---|---|
| A screen is not shipped yet (10 wave 2 **[OPEN]**) | Row `provisional` with the blocking task id; capture whatever the shipped subset shows (the consent grant is the element Google requires, K15). |
| Real data in frame (e-mail, IP, token, story text) | Delete the artefact, recapture with `demo+<n>@invalid`; the old hash never appears in the index. |
| sha256 mismatch after a recapture | Re-hash and update the row, and re-point the citing tasks — a stale digest invalidates their evidence claim. |
| Redaction grep flags a pattern | Treat as a real finding: inspect, recapture or redact the text file; never widen the pattern to make it pass. |
| A citing task asks for a flow outside the seven | Add the row only if the citing task is named; record the requester in `Owning task` (keeps the pack bounded). |
| Binary accidentally copied into the repo | Remove it from the working tree **and** from history if it was committed; the repo copy stays markdown-only (D14/O7). |
| App version changed mid-capture | Split the pack by version (two dated folders) or restart the capture; the index never mixes versions silently. |
| Export/deletion flow needs a completed request | Use the synthetic tenant's request; if the `due_at` window has not elapsed, capture the states that exist (`queued\|running\|ready`, `open`) and mark the completed-state artefact as a later addition — never fake a completion. |
| Retention/expiry | Pack kept until the next successful re-audit, ≥ 24 months; recapture trigger = any captured screen change or a new filing need. |
