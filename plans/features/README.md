# Detailed feature plans

The plans in `plans/00`–`13` are **high-level and not final**. Planning continues here, one feature at a time:

1. Review the high-level sections the feature touches (Tech Lead; plus a security review for auth, admin, billing or data features).
2. Write the detailed plan in this folder, using the template in `../00-overview.md` §10.1. Layout: one folder per high-level plan (`<plan-no>-<slug>/`) with a `README.md` (review, shared decisions, index, re-estimate); inside it one folder per feature (`<story-id>-<slug>/`) holding `plan.md` and **one file per task** (`<task-id>-<slug>.md`, task template in the plan folder's README).
3. Review the detailed plan (Definition of Ready, `../00-overview.md` §10). Web/UI features: design first — a `<story>-T0 — UI design` task per UI folder, approved design linked from `plan.md` §6 before any implementation task starts (owner rule 2026-09-25).
4. Implement. Keep the feature plan in sync with what was built; contract changes go to `../00-overview.md` first.

No feature is built from a high-level plan alone.
